# プラットフォームのウィンドウとタイトルバー

[English](../../ux/platform-windows.md) | [简体中文](../../zh-CN/ux/platform-windows.md) | [繁體中文](../../zh-TW/ux/platform-windows.md) | 日本語 | [한국어](../../ko-KR/ux/platform-windows.md) | [Français](../../fr-FR/ux/platform-windows.md) | [Deutsch](../../de-DE/ux/platform-windows.md) | [Español](../../es-ES/ux/platform-windows.md) | [Português (Brasil)](../../pt-BR/ux/platform-windows.md) | [Русский](../../ru-RU/ux/platform-windows.md)

xdzip の操作画面は独立した最上位ウィンドウを使い、メインウィンドウに付属するシートや内部に描画する重ね合わせパネルを使いません。独立したウィンドウは別プロセスや、補助ウィンドウごとのタスクバー項目を意味しません。ドロップダウンメニューとツールチップは軽量な Popup のままで、操作ウィンドウには含みません。

<a name="xdzip-window-contract"></a>

## ウィンドウの契約

| ウィンドウ | メインウィンドウとの関係 | 閉じる / Escape | 最小化 / 最大化 |
| --- | --- | --- | --- |
| 展開または作成フォーム | 参照画面から開く場合は一時的な所有者を持つ非モーダルの `OperationWindow` | 新規タスクを送信せず、下書きまたは確認を閉じる | 無効 / 無効 |
| タスクの競合確認 | 操作ウィンドウのホストが所有する非モーダルの確認画面。タスクは判断を待機 | 確認画面を閉じる。タスクから再度開くか、そこでタスクを明示的にキャンセルする | 無効 / 無効 |
| パスワード、終了、再起動の確認 | アプリケーションモーダル。ネイティブのファイル選択画面もアプリケーションモーダルで、一時的な呼び出し元を持つ | パスワード、終了、再起動にはそれぞれ明示的な閉じる操作または確認操作がある | ネイティブダイアログの機能による |
| タスクの進捗と結果 | 非モーダルの `TaskWindow`。他のモーダル画面がなければ参照を続行可能 | 詳細を閉じてタスク項目から再度開く。独立した操作でも実行中のタスクへのアクセスを維持 | 最小化 / 無効 |
| 設定とバージョン情報 | 非モーダル。トレイ項目から参照画面の所有者なしで開く場合がある | 画面を閉じる。保存済み設定は有効のまま | 無効 / 無効 |

タスクのキャンセルは進捗ウィンドウを閉じる操作とは独立した明示的なコマンドです。バックグラウンドでの完了は前面のフォーカスを奪わず、開いている詳細かタスク項目を更新します。アプリケーションの終了には引き続きタスク終了方針が適用され、メインウィンドウの終了を補助ウィンドウの終了に直接対応させることはできません。

<a name="xdzip-platform-appearance"></a>

## プラットフォームの外観

- macOS：システム装飾のタイトルバーを使い、左上に赤、黄、緑のコントロールを配置します。ネイティブコントロールを独自の色付き点で置き換えません。固定サイズの操作ウィンドウは赤い閉じるボタンを保持し、使用できない最小化とズームを無効にします。進捗ウィンドウは最小化できます。実際のボタンの使用可否は AppKit/Qt のウィンドウ機能に依存し、実機で受け入れます。メインウィンドウは通常のサイズ変更、最小化、全画面表示を維持します。
- Windows のメインタイトルバーはクライアント領域に拡張し、QML のキャプションボタン、サイズ変更可能なネイティブ枠、DWM の影を使います。ドラッグ、端でのサイズ変更、システムのスナップはプラットフォーム機能を使います。独立した操作ウィンドウはネイティブ装飾を使います。Windows と Ubuntu のメイン画面デザインを参照してください。
- Ubuntu X11 は右側の統合コントロールを使い、通常状態では角丸の輪郭を表示します。合成と入力領域の形状指定を備えたセッションでは、クリックを透過する柔らかい影も表示します。最大化と全画面のウィンドウは角が直角になり、利用可能領域を埋めます。移動とサイズ変更はウィンドウシステムが処理します。独立した操作ウィンドウはシステム装飾を保持します。独自 X11 経路以外のバックエンドは通常の装飾を使います。Wayland はサポート範囲外です。Ubuntu のメイン画面デザインを参照してください。

各操作ウィンドウは独自のタイトル、枠、影、ドラッグ可能なタイトルバーを持ちます。背後のメインウィンドウはウェブページのように暗くしたりぼかしたりしません。初回表示時は所有者のディスプレイの利用可能領域内で中央に配置します。復元位置は表示可能な画面内に収めます。ツールバーや内容でタイトルバーを覆ってはいけません。

<a name="xdzip-qt-quick-implementation-constraints"></a>

## Qt Quick 実装の制約

`OperationWindow` は独立した `Window` を使い、任意の `transientParent` を指定できます。既定値は `Qt.NonModal` です。`PasswordWindow` と `OperationConfirmationWindow` は明示的に `Qt.ApplicationModal` を使います。ネイティブ選択画面は実際の呼び出し元を一時的な所有者とし、その画面が表示中の場合に限りアクティブ状態を復元します。[ウィンドウ登録](../../../specs/visual/window-registry.json)と[タスクウィンドウ](task-windows.md)を参照してください。

Windows/Linux の独自タイトルバーには、プラットフォームによる実際のウィンドウ移動、サイズ変更、システムメニューが必要です。QML の位置を手動で変更してシステムのドラッグを模擬しません。`WindowController` はウィンドウのライフサイクル、所有関係、閉じる要求、タスク画面の再表示を管理します。タスクはコアが所有し、画面の破棄によって実行中のタスクを破棄してはいけません。スレッド間のウィンドウ状態更新は定義済みのブリッジイベントだけを使います。

<a name="xdzip-prototype-evidence-and-limits"></a>

## プロトタイプの証拠と制限

HTML プロトタイプは独立ウィンドウの外観、タイトルバーのドラッグ、ブロックする操作としない操作、閉じる動作を模擬します。上部の「Platform」選択は macOS、Windows、Linux の比較用で、製品設定ではありません。ブラウザーの `dialog` は一つのページ内にあり、実際のネイティブウィンドウ、システムボタン、システムの最小化、タスクバー、複数ディスプレイの動作を提供できません。タスクウィンドウの最小化は詳細を隠して模擬します。

プロトタイプのメインウィンドウにあるプラットフォームコントロールは外観の例示です。上書き確認から作成に戻るとサンプルフォームはまだリセットされますが、製品実装は下書きを保持する必要があります。これらの制限をネイティブ受け入れ完了の証拠にはできません。

<a name="xdzip-real-device-acceptance-criteria"></a>

## 実機受け入れ基準

1. 各操作ウィンドウは独立したプラットフォームウィンドウで、メインウィンドウに正しく関連付けられ、シートやウェブページ風の重ね合わせはありません。
2. 信号色または右側のボタンの順序、無効状態、閉じる要求がプラットフォームとウィンドウの機能に合い、異なる文字サイズと倍率でタイトルとシステムボタンが重なりません。
3. ウィンドウのドラッグ、画面境界、複数ディスプレイ、125%/150%/200% の倍率、明暗テーマが正しく動作します。
4. タスク詳細を閉じてもタスクは続行し、タスク項目から詳細を再表示できます。競合ウィンドウを閉じると、確認を再表示するか明示的にタスクをキャンセルするまで待機します。
5. 所有者のモーダル制御、フォーカス復元、キーボード操作、スクリーンリーダー向けタイトル、システムショートカットが動作し、無関係なアーカイブウィンドウを不必要にブロックしません。
6. Windows のシステムメニューとスナップ、および Linux X11 を別々に確認します。Wayland は初期サポート範囲外です。既存の Qt 実機検証結果は [WP-12 #5](https://github.com/xiaodaozhi/xdzip/issues/5) にあります。この一覧は後から影響箇所を再確認するためのもので、完了した受け入れをやり直すものではありません。
