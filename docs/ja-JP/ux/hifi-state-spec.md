# 高忠実度状態と実装契約

[English](../../ux/hifi-state-spec.md) | [简体中文](../../zh-CN/ux/hifi-state-spec.md) | [繁體中文](../../zh-TW/ux/hifi-state-spec.md) | 日本語 | [한국어](../../ko-KR/ux/hifi-state-spec.md) | [Français](../../fr-FR/ux/hifi-state-spec.md) | [Deutsch](../../de-DE/ux/hifi-state-spec.md) | [Español](../../es-ES/ux/hifi-state-spec.md) | [Português (Brasil)](../../pt-BR/ux/hifi-state-spec.md) | [Русский](../../ru-RU/ux/hifi-state-spec.md)

このガイドは作成、展開、タスクの各ウィンドウの動作、フォーカス、閉じる操作を説明し、[操作状態の原稿](../../../design/hifi/README.md)と[共有アセットライブラリー](../../../design/assets/README.md)にリンクします。表の識別子はデザインのアートボードを指し、タスクプロトコルを変更しません。

<a name="xdzip-screens-and-task-semantics"></a>

## 画面とタスクの意味

| 状態 / アートボード | 開始条件 | 既定のフォーカスと操作 | 閉じる操作と復帰 |
| --- | --- | --- | --- |
| C01 / 01 | 作成、実行中のタスクなし | 最初の入力ボタンまたはファイル名。作成前に入力、名前、保存先、機能を検証 | このウィンドウの下書きを破棄。書き込みなし |
| E02 / 02 | タスクのスナップショットに有効な競合確認がある | スキップ、名前の変更、上書きは明示的な判断。名前の変更が主操作。以降の競合に適用は初期状態で未選択 | 閉じると確認画面が消え、タスクは待機したまま。タスクから再表示するか、タスクのキャンセル操作で停止 |
| T01 / 03, 08 | プランを受け入れ、実行イベントを受信 | 閲覧に戻る、キャンセルは通常のボタン。存在しない一時停止は表示しない | 表示のみ隠す。タスク項目から再表示可能。バックグラウンド完了はフォーカスを奪わない |
| T01 / 整合性検査 | タスク進捗と同じコンポーネント、読み取り専用アーカイブと検証段階 | 閲覧に戻る、検査のキャンセル、実際のタスク結果。HTML デモと Qt コンポーネントのプレビューは別々に明示 | 閉じてもキャンセルしない。実際の検査はツールバーからバックグラウンドキューに入る |
| R01 / 04 | タスクに公開済み項目と未完了項目がある | 再試行は未完了項目のみを選び、プラン確認に戻る | 表示を閉じても確定済みファイルは削除しない |
| S01 / 05 | 設定を開き、六つのタブの一つを選択 | すべての編集はキーボードで操作可能。変更は成功後すぐに反映され、アドレスは検証が必要 | 閉じても適用済み設定を保持。失敗時は以前の値を保持 |
| R02 / 06 上 | 一意の成功終端を受信 | 展開では明示的な選択で保存先フォルダーを開ける。作成では対応結果をアプリ内でのみ開き、システムフォルダーは自動で開かない。失敗ゼロは中立状態 | 詳細を閉じても完了通知を繰り返さない |
| T02 / 06 中 | キャンセルを受理、クリーンアップ未完了 | 重複キャンセルは無効。閲覧には戻れる | 隠すことは可能。「キャンセル済み」を早まって表示しない |
| R03 / 06 下 | キャンセル終端を受信 | 公開済み項目を保持。再試行可能なら未完了範囲を再計画 | 閉じても公開済み項目をロールバックしない |
| C02 / 07 | アートボードが既存の出力アーカイブを示す | 実際の作成競合は稼働中タスクの安全な名前と公開の規則に従う | 確認を閉じるとタスクは待機したまま。名前の変更、置換、キャンセルの明示的な選択はタスク結果に従う |

「新しい名前を使う」は名前の提案のみで、実際の開始時にも保存先の存在を確認します。ファイル名の確認は最終的な書き込み許可ではありません。置換を伴う作成では、一時アーカイブを完全に生成・検証してから公開先の条件を再確認する必要があります。線形化されたコミット点の後にキャンセルが到着した場合、成功をキャンセルに書き換えず、コアの結果に従って完了を表示します。

<a name="xdzip-creation-capabilities-and-field-errors"></a>

## 作成機能とフィールドエラー

- ZIP の 4 段階は Store/Deflate 1/6/9 に対応し、既定は 2 の通常です。TAR と TAR.GZ を作成でき、形式の切り替えで拡張子を同期し、パスワードと分割設定を消去します。TAR ではレベルを無効にし、TAR.GZ のレベル 0/1/2/3 は GZIP 0/1/6/9 に対応します。形式変更は拡張子を同期しますが、対象を無断で上書きできません。
- 入力なし、名前が空、保存先が無効、権限不足の場合は作成を無効にし、フィールドの横に理由を表示します。エラーは枠線の色だけでなく、スクリーンリーダーが読めるテキストでも示します。
- 重複入力とディレクトリ展開はコアが処理し、UI は選択の概要のみ表示します。作成画面の画像アイコンは種類の表示であり、画像プレビューではありません。
- ZIP と 7z はそれぞれ対応するパスワードと分割設定を表示します。7z はファイル名の暗号化にも対応します。実際の書き込み機能は形式レジストリを参照してください。[ZIP の作成](../engineering/zip-creation.md)、[形式レジストリ](../engineering/format-registry.md)

<a name="xdzip-task-data-and-exceptions"></a>

## タスクデータと例外

例 A は 3 ファイル、8.4 + 6.2 + 12.8 = 27.4 MB です。2 件が成功すると 14.6 MB が保存され、残る PDF は 12.8 MB です。成功、スキップ、未完了の件数を混同してはなりません。例 B は 30 ファイル、77.5 MB のアーカイブ全体で、46.5 MB は 60% です。例 A と同じ時点ではありません。

割合は既知の総バイト数と実際の計測から求めます。総量が不明な場合は残り時間を作らず不確定な進捗を使います。段階が変われば速度を再推定します。図の 6.2 MB/s と約 5 秒は安定した段階の例にすぎません。ファイル数は完了と処理中を区別し、現在の項目の順番を成功数として使いません。

ディスク満杯: 停止して公開済み項目を保持し、空き容量の確保または保存先の変更後に再計画します。ソース変更: 再試行ではアーカイブを開き直し、古いインデックスは再利用できません。キャンセルのみ: 未完了は琥珀色または中立色とし、破損と報告しません。エラーコードは詳細に表示し、通常の画面にはコールスタックや内部ブリッジの用語を表示しません。

<a name="xdzip-immediately-applied-settings"></a>

## 即時適用される設定

テーマ、文字サイズ、密度、言語、開き方、プライバシー切り替えは変更が成功すると直ちに保存・適用されます。最近の履歴の消去は直ちに実行され、元ファイルは削除しません。失敗時は以前の設定を保持してメッセージを表示します。アプリ情報と更新は設定のアプリ情報ページにあります。ファイルの関連付けには OS の確認が必要で、実際の結果を反映します。ネットワークページは検証済みのプロキシとミラーのアドレスを保存します。[設定契約](settings-localization.md)を参照してください。

既存ホストの既定の出力予算はファイルごとに 8 GiB、タスクごとに 20 GiB です。現在の設定画面では上限を編集できません。将来上限を追加する場合は正の整数とオーバーフローを検証し、ファイルごとの上限がタスク上限以下になるようにし、新しいプランのみに適用します。実行中のタスクの不変の許可を変更したり、空き容量の確認を回避したりしてはなりません。

<a name="xdzip-window-layout-and-asset-mapping"></a>

## ウィンドウ、レイアウト、アセットの対応

すべての操作ウィンドウは[プラットフォーム別ウィンドウ仕様](platform-windows.md)に従います。macOS のネイティブタイトルバーでは切り出した信号ボタンを使いません。Windows/Linux のタイトルボタンの位置、無効状態、システムメニュー、移動はプラットフォーム層で検証します。比較画像にある Linux の右側コントロールは、すべてのデスクトップ環境への固定された約束ではありません。

現在の寸法は [layout-scale.json](../../../specs/visual/layout-scale.json)、[ウィンドウ登録簿](../../../specs/visual/window-registry.json)、[デザイン規範](../visual/design-standard.md)に従い、初期の大きすぎる提案に代わります。作成、展開、競合、進捗、結果は幅 491 を共有し、設定は用途別の登録済みの差として 612 を使います。タイトル 20、本文 13、フッターボタン 13、補足テキスト 12 です。高さは内容と各ウィンドウの上限に従い、本文はスクロールします。フッター付きの操作ウィンドウはフッターを固定して操作可能に保ち、設定にはフッターがありません。設定では文字サイズ 100%/125%/150% を選べます。全体スケーリングやスクリーンショットの物理ピクセルからコンポーネント寸法を導いてはなりません。

| 用途 | 追加アセット | 共有 / 動的な部分 |
| --- | --- | --- |
| 作成タイトル、入力の追加 | archive-add, image-file, remove | folder, file-pdf, new |
| 競合、部分失敗 | document-warning, status-warning, info | file-pdf。比較カードとテキストは QML で描画 |
| 実行中の進捗 | document-download, image-file, info | 進捗バーと数値は動的に描画 |
| 成功、スキップ、キャンセル、停止 | status-success, status-skipped, status-stopped, spinner, clock | Qt コントロールが spinner を回転 |
| 設定 | settings-tile, theme-system | テーマプレビュー、スイッチ、数値入力はコンポーネント。settings は小さいアイコン |

アセットは `design/assets/` にあります。`reference/` は外観比較用に元のピクセルで切り出した画像を保持します。`svg/` と `png/` は透明な実行用アセットで、元のレイヤーと呼んではなりません。すべての SVG は 24×24 のキャンバスを使い、PNG は 24×24、48×48、72×72 で書き出し、同じ論理表示サイズを保ちます。HTML のファイル一覧は元座標で 48×48 の枠を使い、Qt は約 31.75×39.69 論理ピクセルを使います。PDF、テキスト、コード、Markdown のアイコンは中心と可視高さ 22 ピクセルを共有し、輪郭幅はそれぞれ異なります。フォルダーも同じキャンバスの中央に配置します。ダーク SVG はアセットの調整であり、完全なダーク表示には実際の Qt とコントラストの確認が必要です。

<a name="xdzip-directory-tree-addition"></a>

## ディレクトリツリーの追加

B01 の閲覧には[ディレクトリツリー B 仕様](directory-tree.md)が追加され、正式なアートボード 3 点と共有切り出し画像 26 点があります。ノードの矢印はサブディレクトリの有無に依存し、展開、現在のディレクトリ、キーボードフォーカスは独立しています。読み込み、空のアーカイブ、ルートのファイル、ナビゲーション制限、失敗、隠れた現在パスは別々に規定され、既存の読み取り専用ドメイン契約は変わりません。HTML と Qt は基本ナビゲーション、接続線、隠れた現在の枝の表示を統合しています。スケルトンと専用の境界アイコンはデザインアセットのままです。統合範囲はディレクトリツリー仕様を参照してください。

<a name="xdzip-changes-and-revalidation"></a>

## 変更と再検証

主要な状態は HTML と Qt で使用されています。後続の変更でも原稿と改訂パラメーター、コントロールと機能の対応、共有コンポーネント、ウィンドウ契約を確認し、影響を受けるプラットフォームを検証します。デザインや静的検査だけではネイティブ機能とアクセシビリティを証明できません。実際の結論を対応する issue に記録します。この一覧によって過去の受け入れをやり直すものではありません。
