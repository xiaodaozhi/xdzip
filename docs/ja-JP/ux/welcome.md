# メインウィンドウのウェルカムページ

[English](../../ux/welcome.md) | [简体中文](../../zh-CN/ux/welcome.md) | [繁體中文（台灣）](../../zh-TW/ux/welcome.md) | 日本語 | [한국어](../../ko-KR/ux/welcome.md) | [Français](../../fr-FR/ux/welcome.md) | [Deutsch](../../de-DE/ux/welcome.md) | [Español](../../es-ES/ux/welcome.md) | [Português (Brasil)](../../pt-BR/ux/welcome.md) | [Русский](../../ru-RU/ux/welcome.md)

高忠実度デザインは確認済みで、[公式 HTML レビュー入口](../../../design/html/index.html?view=welcome&zoom=1)に統合されています。Qt は実際のオープンと作成を実装し、デスクトップの手動受け入れは別途記録します。[ウェルカムページの状態デザイン](../../../design/hifi/sources/welcome.html)と [welcome-reference.json](../../../specs/visual/welcome-reference.json)を参照してください。色とメインウィンドウの密度は既存のトークンと layout-scale を維持し、全体の規格は変更しません。四つの PNG はコードで描いたデザイン原稿の書き出しであり、実行中の製品のスクリーンショットではありません。

<a name="xdzip-information-and-layout"></a>

## 情報とレイアウト

スタートページの見出しは中国語で「打包与解压，都简单一点。」、英語で「Pack and unpack, a little simpler」、日本語カタログでは「圧縮と展開を、もっと手軽に」です。補足文は最初に閲覧し、必要に応じて展開し、共有のために圧縮することを説明します。

既定のクライアント領域は 1024×622、最小は 832×544、タイトル領域 48、カプセル 32、下部バー 32 です。内容グループは幅 608 で水平方向のみ中央揃えし、使用可能な本文上端から固定の 28 論理ピクセル下で始まり、垂直中央揃えはしません。見出しサイズは 30、狭いウィンドウでは 28、説明 13、アクションタイトル 16、カード説明 12 です。二つのアクションカードは幅 296、高さ 124、間隔 16、内側余白 20、半径 8 です。これはウェルカムページの入口カードであり、共有操作ウィンドウボタンの代替ではありません。

タイトルバーはメインウィンドウの既存コンポーネントを全面的に再利用し、ブランド、スタートタブ、タブ追加、外観設定を保持します。ウェルカムページは配置、寸法、フォント、アイコンを変更しません。本文には空のファイルツリー、表ヘッダー、検索欄、展開ツールバーを表示せず、アーカイブを開いた後に閲覧レイアウトが現れます。主操作は「アーカイブを開く」、副操作は「アーカイブを作成」で、ドロップ領域の後に対応ファイル形式を表示します。各カテゴリは登録済み拡張子数を示し、最初は「アーカイブ」が開いています。別カテゴリを有効にするとプレビューが切り替わり、同じカテゴリを再度有効にすると折りたたみます。アクセント文字とウェイトで選択中カテゴリを示します。プレビューは通常の UI フォントで、薄く塗られ枠のあるタグを一行に並べます。あふれは省略記号で示し、行にホバーすると選択カテゴリの拡張子を表示します。「ファイルの関連付け」は設定内の既存コントロールを開きます。下部バーのローカル処理に関する文言は処理場所の説明であり、安全性の保証ではありません。タスク数は実際の履歴を使い、デザインのゼロは初回利用の空の履歴を表します。

架空の最近使ったファイル、サンプルサイズ、製品にない形式機能は表示しません。タイトル領域の信号ボタンは macOS 装飾の位置だけを示し、実装はプラットフォームのウィンドウ機能を使います。Windows と Linux は信号ボタンをコピーせず、それぞれの装飾を維持します。

<a name="xdzip-interaction-design"></a>

## インタラクションデザイン

- ウェルカムページは初回起動時、最後のアーカイブタブを閉じた後、または閲覧可能なアーカイブがない状態でオープンに失敗した後に現れる場合があります。バックグラウンドタスクは継続し、リセットされません。
- 開く操作はシステムのファイル選択画面を呼び出し、キャンセルするとウェルカムページに留まります。成功時は実際のアーカイブタブに切り替え、失敗時は回復可能なエラーを表示して成功した一覧を捏造しません。
- 作成は既存の作成ウィンドウを開き、キャンセルするとウェルカムページを維持します。候補ショートカットは macOS で ⌘O/⌘N、Windows/Linux で Ctrl+O/Ctrl+N です。実装前に実際の割り当てを確認し、このデザインは統合済みとは主張しません。
- 受け入れ可能な選択をドラッグすると、2 論理ピクセルのアクセント枠と選択色の塗りでドロップ領域を強調し、離れると通常状態に戻ります。デスクトップと HTML レビューは別々の受け入れ規則を持ちます。実際のファイルオープンは[実際の Qt 統合](#xdzip-real-qt-integration)を参照してください。
- カード全体をクリックできます。タイトルバーの後のキーボード順序は開く、作成、タスクです。キーボードフォーカスは追加の枠を描かず、ウィンドウ全体のフォーカス喪失規則に従います。ホバーと押下は不透明度だけでなく共有の accentHover と accentPressed を使います。
- オープン中はカードのタイトルをビジーインジケーターと「開いています…」に置き換え、繰り返しのオープンとドロップを一時的に防ぎます。無効表示には accentDisabled と accentDisabledText を使います。作成ウィンドウが同時に実行できるかはホスト規則に従い、ウェルカムページはタスクの意味を変えません。ビジー、無効、エラーは四つの静的原稿に描かれていない実装契約です。
- 設定とタスクのポップアップは幅 240、フォント 13、最小行高 32 を維持し、本文フォント 13 との比率は 1:1 です。ウェルカムページは独自のメニュースタイルを導入しません。カードのフォント 16 は入口見出しであり、メニュー密度の比較基準ではありません。

<a name="xdzip-verification-and-boundaries"></a>

## 検証と制約

ライト・ダーク、最小ウィンドウ、ドラッグ状態、メニューとタイトルバーの比率を対象にし、DPR 1、1.25、2 と実際のブラウザーページズームを確認します。縮小スクリーンショットでレイアウトを代用せず、CSS スケーリングでブラウザーページズームを代用しません。結果、画像、形状レポートはローカルまたは CI の成果物だけに置き、状態は対応 issue に記録します。

HTML 操作検査は `scripts/check-html-welcome.py`、Qt はウェルカムページとブラウザーの回帰検査を使います。HTML へのドラッグは例を選ぶだけでユーザーファイルを読みません。Qt は実際の製品入口からファイルを開きます。ウェルカムページのダーク版が完成しても他の全ページのダーク原稿の完成を意味せず、自動検査はネイティブのドラッグ＆ドロップ、スクリーンリーダー、IME の検証に代わりません。

<a name="xdzip-real-qt-integration"></a>

## 実際の Qt 統合

WelcomePage と WelcomeAction はレイアウトと意図だけを表します。ウェルカムページは起動時とアーカイブを閉じた後に現れ、オープン成功時は適切なセッションに入ります。空のアーカイブも有効な閲覧状態です。初期読み込み中は繰り返しのオープンと作成を無効にし、「開いています…」を表示して読み込みのキャンセルを可能にします。失敗時はウェルカムページと実際のエラーを残し、再選択できます。作成ドラフトを閉じてもタスクは作られません。バックグラウンドタスク一覧はリセットしません。

開く操作とシステムショートカットは chooseArchive、作成は CreateWindow を再利用します。ネイティブファイル選択画面はシステムウィンドウのままで、キャンセルしてもセッションは作られません。Qt は保存されたタブ・ウィンドウモードに従って振り分け、空のスタートページを優先して再利用し、重複アーカイブでは既存セッションを有効にします。

デスクトップセッションマネージャーでは、一回のドロップから最大 128 個のローカルファイルを開けます。各項目は生成されたドラッグ＆ドロップ用拡張子、または対応する分割ボリュームの名前パターンに一致する必要があります。単一セッションの開発入口は一項目を受け付けます。ディレクトリと非ローカル URL は拒否します。これらの検査はオープン経路を選ぶもので、Rust ランタイムは実際の形式を識別しソースを検証します。明示的なオープン入口のみの形式は **アーカイブを開く** を使います。[形式レジストリ](../engineering/format-registry.md)を参照してください。

寸法は welcome-reference.json から generate-qml-theme.py を通じて Theme に入ります。文字を大きくするとカードと本文も拡大し、本文はスクロールしてキーボードフォーカス項目を自動的に表示範囲へ移します。ステータス領域とタイトル領域は Item.scale を使わず独立して拡大します。Qt は共有 PNG アイコンを使い、主操作には既存の暗色・明色の図形を使います。実行時素材は原稿から切り出しません。

自動化入口は tst_welcome.qml、browser_test.cpp の welcomeOpensRealArchivesAndReturns、scripts/check-qt-welcome.py です。必要時の三プラットフォーム Qt ワークフローは、実際のオープン、クローズ、失敗からの回復、DPR 1、1.25、2 での 36 個の形状項目と、メニュー幅 240、フォント 13 を検査します。ネイティブのドロップ、ファイル選択、スクリーンリーダー、IME は必要に応じて確認します。オフスクリーンの結果を未実施のデスクトップ操作として提示しません。

タイトルバーの改訂：初期版のウェルカム専用タイトルバースタイルを削除しました。Qt ArchiveTabs は統合前のコンポーネントに変更なく戻し、HTML はメインウィンドウの既存ソースキャンバスと倍率を再利用します。ウェルカムページが変更するのは本文だけです。古い PNG とハッシュは過去の記録として残し、改訂版は design/hifi/sources/welcome.html をソースとする `screens/welcome-titlebar-*.png` です。回帰検査はアーカイブのオープン前後のタイトルバー、タブ、外観ボタンの形状を比較し、空状態でアプリ枠が再び変わらないようにします。

読み込み状態：初期オープンのキャンセル入口は本文の浮動オーバーレイに移動しました。進捗不明時は模擬した割合を使わずアクティブな進捗バーを使います。[読み込みオーバーレイ契約](welcome-opening.md)を参照してください。元のウェルカムビットマップを保持し、動的デザインは `opening=1` を提供します。

エラー・警告は形式ヒントの下に、共有の危険色と状態警告アイコンを使って表示します。エラーの表示、折り返し、消去、置き換えによって見出しと入口カードの上端座標は変わらず、長い内容は本文内でスクロールします。トレイへ閉じた後にメインウィンドウを再表示してもスタートページは一つだけで、バックグラウンドタスクをキャンセルしません。編集可能なソースには `error=1` 状態を追加しています。古いウェルカム PNG は過去のバイト列を保持し、その以前の中央配置で上端位置の契約を置き換えてはいけません。
