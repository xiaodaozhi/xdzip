# タスクウィンドウと整合性検査

[English](../../ux/task-windows.md) | [简体中文](../../zh-CN/ux/task-windows.md) | [繁體中文](../../zh-TW/ux/task-windows.md) | 日本語 | [한국어](../../ko-KR/ux/task-windows.md) | [Français](../../fr-FR/ux/task-windows.md) | [Deutsch](../../de-DE/ux/task-windows.md) | [Español](../../es-ES/ux/task-windows.md) | [Português (Brasil)](../../pt-BR/ux/task-windows.md) | [Русский](../../ru-RU/ux/task-windows.md)

アプリのタスク入口はすべてのセッションを集約し、セッション UUID とバックエンドのタスク ID を使って進捗、パスワード、競合、結果を振り分けます。ページを閉じてもコントローラーは保持され、明示的な終了時はすべての非同期 join を待ちます。[アプリケーションセッション契約](../engineering/application-sessions.md)を参照してください。

タスクメニューの行には操作アイコン、アーカイブのファイル名、連番タグ、状態タグを表示します。アイコンは作成、展開、検査、追加、移動、エクスポートの共有アセットを使い、操作種別を表すテキストの接頭辞は付けません。両タグは同じコンポーネントを使用し、連番はバックエンドの番号を維持し、セッション間の内部識別情報も変わりません。長いファイル名は省略しますが、アクセシブル名には操作、番号、ファイル名、状態を含めます。

`ExtractWindow` と `CreateWindow` はタスクの進捗とは別に下書きを表示します。各アーカイブセッションは `TaskWindow` を持つ `OperationTasks` プレゼンターを備えます。タスクを選択するとスナップショットをバインドし、同じ画面に終端結果を表示します。画面を閉じてもタスクは実行を続けます。ファイルマネージャーからの独立タスクが唯一の入口を失う場合はウィンドウを再表示できます。システムが一時ファイルを開く要求を受け入れるとタスクウィンドウは隠れ、受け渡しが拒否された場合は結果から再試行できます。[一時的なオープン](../engineering/archive-opening.md)を参照してください。

[組み込みレジストリ](../engineering/format-registry.md)が作成形式とレベルを決めます。単一ファイルストリーム、ISO データイメージ、Windows x64 の ZIP 自己解凍ファイルも含みます。7z の既定は通常の LZMA2 で、ソリッドモード、内容の暗号化、ファイル名の暗号化、分割は別々のオプションです。ファイル名の暗号化には内容の暗号化が必要です。形式を切り替えると旧形式のオプションを消去し、コントロールはスクロールする本文に残ります。

整合性検査は同じ TaskWindow レイアウトを使用します。実際のツールバーの「検証」はアーカイブ全体に対する読み取り専用のバックグラウンドタスクを送信し、読み取り、パスワード待ち、キャンセル、終端状態を `kind=check` として表示します。現在の選択とは無関係で、最初のエラーで停止し、検証済み件数と未検査件数を別々に表示します。展開や作成で確定した件数は検査件数ではありません。形式と安全性の範囲は[検査契約](../engineering/archive-checking.md)を参照してください。コンポーネント開発用プレビューでは、別の IntegrityWindow を「インターフェースのプレビューです。実際の検査は行いません。」と明示して提供します。

完了とキャンセルは同じ構造とフッターを使用します。対象パス、読み取りバイト数、ファイル数、速度、残り時間の推定、段階、現在の項目はデータ欄であり、UI はファイルを走査、読み取り、展開しません。

ウィンドウ幅、密度、フォント、角丸、枠線、進捗バー、アイコン枠、説明の位置合わせは[視覚規範](../visual/design-standard.md)と[固定された原稿](../../../specs/visual/integrity-reference.json)に従います。総量が不明なら確定した割合を表示せず、大きい文字ではフッターを操作可能に保ちながら本文をスクロールできます。閉じる操作はキャンセルを発行せず、キャンセル操作は明示的に要求します。検査の終端に保存済みファイルを表示したり、保存先フォルダーを開いたりしてはなりません。

高忠実度原稿は[整合性検査の進捗](../../../design/hifi/screens/integrity-progress.png)で、実行時のアイコンは共有アセットの document-check です。原稿の切り出しは参考のみで、動的 UI は共有コンポーネントを使用します。

## 通常寸法とタスクの表示

アイコン、タイトル、副題を持つ作成、追加、展開、タスク・結果、競合、設定、アプリ情報のウィンドウは OperationHeader を共有します。基準はアイコン枠 48 論理単位、タイトル 20、副題 13、通常高さ 96 です。長い文や大きな文字では共有フォントメトリクスに従って高さが増え、本文はスクロールを続け、フッターは固定されます。テキストのみのパスワード、事前確認、終了・再起動の確認に、架空の装飾アイコンを追加しません。パラメーター、独立状態、登録は[視覚規範](../visual/design-standard.md)を参照してください。

タスクボタンの右側には対になった山形を残します。アプリ内のタスクメニューは最大 360 論理ピクセルかつ現在のウィンドウの利用可能な高さに制限し、履歴は内部でスクロールし、消去ボタンは固定して操作可能にします。消去は完了、失敗、キャンセル済みの履歴のみを隠し、実行中、待機列、パスワード・競合待ち、キャンセル中、クリーンアップ中のタスクは残します。消去できる履歴がないときはボタンを無効にします。この操作はタスクをキャンセルせず、元のアーカイブやユーザーの出力を削除せず、元のコントローラーや終了バリアも変更しません。消去により隠された結果ウィンドウは空のスナップショットを表示せず閉じます。

消去ボタンは装飾的な背景ではなく、メニューの操作可能な内容に属します。ポインター、キーボード、ネイティブアクセシビリティは同じ消去操作を呼び出します。区切り線の両側に 4 論理単位を残し、ボタンの下は共有メニューのパディングだけを使い、追加のフッター余白を設けません。タスク行の水平・垂直パディングは同じにし、状態バッジは利用可能な内容の右端に揃え、スクロールバーの幅は実際にあふれる場合のみ確保します。ラベルはスナップショットの種別から検査、展開、作成、追加、移動、エクスポートを区別し、作成以外をすべて展開とは呼びません。起動時は完全なタスク識別情報と元のコントローラーを保持し、検査タスクを展開に振り分けません。

2026-10-15 の改訂: 作成、展開、共有タスクウィンドウの幅は 491 論理ピクセルです。進捗と結果は内容に合わせて最大 600 まで高さを調整します。詳細を折りたたんだ状態では展開用の余白を予約せず、展開リストは最大 168 です。タスク ID を変更すると詳細の展開状態を消去し、同じタスクの更新ではユーザーの選択を保持します。ファイルが存在する場合のウィンドウも同幅で最大高さ 560、通常密度と共有フッターを使用します。この寸法はネイティブの独立ウィンドウやキャンセルの意味を変更しません。

タスクの実行中、「現在のファイル」は 1 行で中央を省略し、パスの先頭とファイル名の末尾を残します。完全なプレーンテキストのパスはデータとアクセシブル名に残ります。同じ状態と文字サイズでは、パスの長さだけでカードやウィンドウの高さを変えてはなりません。他のパスカードと終端の説明は折り返します。通常の展開結果には「N 件のファイルを処理しました」のみを表示し、制限付き詳細リストではなく committedFiles を使用します。ゼロは明示し、スキップまたは未完了のファイルは含めません。バッチ作成を含む作成結果には「ファイル N 件」のみを表示します。outputParts は通常作成では分割ボリュームを含む生成ファイル数、バッチでは成功したタスク数を数えます。バッチ展開も「ファイル N 件」のみを表示し、制限付き詳細リストのファイル名ではなく成功した展開タスク数を数えます。名前とサイズは省略します。バッチ統計は 3 列で、初めに完了、未完了、キャンセルの件数を 1 行に表示します。中央の下向き矢印で残りの件数を表示し、上向き矢印で折りたたみます。ボタンにはツールチップと読みやすいアクセシブル名を保持します。別タスクでは展開状態をリセットし、同じタスクの更新では保持します。バッチ作成結果にはボリュームグループの重複排除件数を表示しません。バッチ展開では、選択された別ファイルが同じボリュームグループに属するためにスキップしたファイルを「スキップ（同一グループ）」と表示します。作成と展開は未完了ファイルとその理由を展開可能な詳細に列挙し、タスク単位のエラーは別に表示します。

ステータスバーのボタンはアプリ全体で保持されるタスク行を数えます。アクティブ数は別で、ツールチップと終了方針に使います。コントローラーごとの履歴は 64 を超えると対象となる終端記録を削除して整理します。タスクを再表示するときは、閲覧ページが閉じられた後もセッション UUID とタスク ID を使用します。

タスク一覧はタスク ID によって項目の識別情報を保持します。進捗と状態は一覧を再構築せずにその場で更新し、ホバー、強調表示、キーボードフォーカスを妨げません。新規タスクと履歴の削除では対象項目だけを挿入または削除し、他の項目の識別情報と選択を保持します。並び順はタスク ID の降順のままで、マウスやキーボードによる操作は常に対応する ID を再表示します。QML データモデルはタスク履歴の UI 表示にすぎず、スナップショット、キャンセル、コミット、終端、終了バリアの意味を変更しません。

この更新は既存のウィンドウやメニューのレイアウト、論理単位、視覚状態を変更しません。実行時検証では静止したホバー、キーボード操作、その場での状態更新、タスク追加、履歴の削除を引き続き確認します。

## ネイティブ選択画面とドラッグ時のアクティブ化

アーカイブを開く操作、ファイルやディレクトリの追加、展開先や作成先の変更は、実際に呼び出した Quick ウィンドウを共有 NativeDialogPolicy に渡します。選択画面はアプリケーションモーダルな独立ネイティブダイアログのままで、呼び出し元を一時的な所有者とします。ネストされたイベントループを抜けた後、呼び出し元が存在し表示されている場合に限り、そのアクティブ化の復元をキューに入れます。常にメインウィンドウを復元してはなりません。閉じた呼び出し元を復活させてはなりません。システム選択画面の文言は引き続きシステム言語に従います。

ウェルカムページが有効なローカルアーカイブのドロップを受け入れた後、受信ウィンドウは次のイベントループでアクティブ化を要求します。拒否されたドロップや通常のタスク完了は前面へのアクティブ化を要求しません。有効な選択は[ウェルカムページのドロップ受理](welcome.md#xdzip-real-qt-integration)を参照してください。

## 終了と再起動の確認

QuitWindow と RestartWindow は OperationConfirmationWindow を継承し、アプリケーションモーダル、通常密度、適応的な高さ、スクロール可能な本文、固定フッターを使用します。ボタンは戻る、待機、終了のキャンセル、後で、再起動の各操作を維持し、ファイルの公開とタスクのクリーンアップは既存のコントローラーが処理します。停止中は判断操作と Escape による終了を無効にし、タイトルや説明の変更によって以前の寸法を復元しません。

以前は確認ウィンドウの視覚面を確認せずにタスク終了の成功を検証していたため、機能と視覚の証拠は別々に記録します。ウィンドウの整合性、基底クラス、寸法の検査は[必須ワークフロー](../visual/design-workflow.md)、デザインは確認状態を参照してください。

パスワード付き展開は独自の `waiting_password` 状態と要求識別情報を使用します。TaskWindow はパスワード待ちを表示して再表示を提供し、アプリケーションモーダルな PasswordWindow が入力とキャンセルを処理します。競合の `promptId` は使用しません。ライフサイクルは[パスワード展開の操作](password-extraction.md)を参照してください。
