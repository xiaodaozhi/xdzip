# パスワードが必要な展開操作

[English](../../ux/password-extraction.md) | [简体中文](../../zh-CN/ux/password-extraction.md) | [繁體中文](../../zh-TW/ux/password-extraction.md) | 日本語 | [한국어](../../ko-KR/ux/password-extraction.md) | [Français](../../fr-FR/ux/password-extraction.md) | [Deutsch](../../de-DE/ux/password-extraction.md) | [Español](../../es-ES/ux/password-extraction.md) | [Português (Brasil)](../../pt-BR/ux/password-extraction.md) | [Русский](../../ru-RU/ux/password-extraction.md)

対応する ZIP、7z、RAR のタスクは、パスワードが必要な項目に達すると `waiting_password` に移行します。ランタイムはタスク ID と要求 ID を含む要求を公開します。QML は入力とキャンセルの意図を伝え、復号、認証、ファイルの確定はコアが担当します。パスワード要求と名前の競合は別の状態です。パスワード要求を競合ウィンドウに送ってはいけません。形式、認証、再試行、出力の範囲は[技術契約](../engineering/password-extraction.md)に従います。

7z または RAR のファイル名が暗号化されている場合は、開くときに PasswordWindow でパスワードを要求します。「アーカイブのパスワード」と「開く処理を続ける」を表示し、ウィンドウを閉じると今回の開く操作だけがキャンセルされ、展開や検査のタスクは作成されません。開く操作には独立した `open` 識別情報と増加する要求 ID を使います。古い要求から新しい開く操作へパスワードを送ることはできません。全件の走査が終わるまで部分的なファイル一覧は表示しません。開くためのパスワードと内容のパスワードは保存しません。

7z が `password_or_integrity` を返したときは、同じウィンドウに中国語で「密码不匹配或加密数据损坏，请重试。」、英語で「The password does not match or the encrypted data is damaged. Try again.」と表示します。これだけではパスワードの誤りを断定できず、再入力で破損が直る保証もありません。ユーザーはキャンセルできます。タスクの再試行は既存の上限に従い、上限到達時も原因不明の分類を維持し、パスワード誤りが確定したかのようには表示しません。

PasswordWindow はアプリケーションモーダルで、既存のシステムタイトルバーを使います。クライアント領域の幅は 491、高さは最大 600 で、画面の利用可能な高さにも制限されます。タイトルは 20、本文は 13、補助文は 12 のサイズです。本文は内容に応じて拡大または独立してスクロールし、下部のボタンを操作できます。寸法は [password-reference.json](../../../specs/visual/password-reference.json)、高忠実度の基準は P02 の独立ウィンドウ設計です。対応言語、ライト／ダークテーマ、100%／125%／150% の文字サイズに同じ寸法規則を適用します。

ウィンドウには暗号化された項目名、パスワード欄、表示／非表示操作、タスクでの使用範囲を示します。表示操作には明確な文字とアクセシブル名を付け、パスワードを含むツールチップは設けません。入力は初期状態でマスクします。送信、キャンセル、ウィンドウ終了、要求 ID の変更時には欄を消去してマスクを戻します。パスワードは設定、クリップボード、ログ、タスクスナップショット、レポートに書き込みません。UI の文字列消去は Qt メモリ内の過去の全コピーの消去を保証しません。秘密情報を格納するコンテナーの寿命はランタイム契約に従います。

外部アーカイブのパスワードは空でも制御文字を含んでも構いません。前後の空白を取り除かず、作成時の 1～128 バイトの制限を適用しません。展開用パスワードの上限は UTF-8 で 1,024 バイトです。欄は最大 1,024 個の UTF-16 単位を受け付け、送信前に UTF-8 バイト数を確認します。バックエンドも再確認します。上限を超えた場合は実際のエラーを表示し、修正できるよう入力を保持します。再試行の要求には新しい要求 ID を使い、古い入力を消去して「パスワードが一致しないか、暗号化データが破損しています。もう一度試してください。」と表示します。

展開の続行では正確なタスク ID、要求 ID、元のパスワードをコントローラーへ送ります。受け付けられたら直ちに欄を消去し、マスクを戻して重複送信を防ぎます。タスクスナップショットがその要求を離れたことを確認してからウィンドウを閉じます。期限切れ、キャンセル済み、重複の要求を別のタスクへ送ることはできません。即座に拒否された場合は有効な要求と入力を保持し、再試行できます。並行タスクの要求はコントローラーが順番に表示し、後の要求が未処理の要求を黙って置き換えることはありません。

「タスクをキャンセル」またはネイティブウィンドウの終了は、そのウィンドウに対応するタスクをキャンセルし、見つけられない待機状態を残しません。Escape は共通のフォーカス規則に従い、まず現在のコントロールからフォーカスを外し、次にウィンドウを閉じてタスクをキャンセルします。パスワード欄で Return／Enter を押すと、同じ要求 ID、長さ、送信待ちの条件で送信します。ボタンは既存のキーボード操作を維持します。タスクウィンドウの「パスワードの入力待ち」は実際の進捗を保持し、要求を再表示できます。タスク終了時は関連する要求を消去します。

デザインデモは空の入力欄と管理下のサンプル名だけを使い、実際のアーカイブの読み取りやパスワードの検証は行いません。自動検査ではマスク、空パスワード、非 ASCII のバイト境界、拒否と重複送信、要求の切り替え、キャンセルと終了、小画面でのスクロール、固定された下部ボタンを確認します。機能の結果とネイティブの視覚受け入れは別々に記録します。
