# ディレクトリツリー B：デザイン、素材、統合

[English](../../ux/directory-tree.md) | [简体中文](../../zh-CN/ux/directory-tree.md) | [繁體中文](../../zh-TW/ux/directory-tree.md) | 日本語 | [한국어](../../ko-KR/ux/directory-tree.md) | [Français](../../fr-FR/ux/directory-tree.md) | [Deutsch](../../de-DE/ux/directory-tree.md) | [Español](../../es-ES/ux/directory-tree.md) | [Português (Brasil)](../../pt-BR/ux/directory-tree.md) | [Русский](../../ru-RU/ux/directory-tree.md)

状態：**ディレクトリの基本操作は Qt の読み取り専用ブラウザーに統合済みです。境界状態の素材は統合待ちです**。操作は[読み取り専用ブラウザー契約](../engineering/readonly-browser.md)に従います。通常のディレクトリ閲覧は直下の項目を対象とし、検索は現在の範囲を再帰的に対象とします。出力の認可は読み取り専用操作とは別です。

現在の三つのアートボードは、[多階層の展開](../../../design/hifi/screens/directory-tree-capsule.png)、[ノードと操作の状態](../../../design/hifi/screens/directory-tree-states.png)、[空状態とナビゲーションの境界](../../../design/hifi/screens/directory-tree-boundaries.png)です。[素材ライブラリ](../../../design/assets/index.html#directory-tree)に個別の切り出しがあります。多階層展開のタイトルバーは現在のカプセル型タブと同期しています。ボード上部と中央のリストは文脈を示すだけで、タイトルバー、ツールバー、ファイル表を再定義しません。[過去の多階層原稿](../../../design/hifi/screens/directory-tree.png)は 26 枚の切り出しの元データと独立した測定基準として変更せず保持します。

アートボードは拡大表示され、各カードの倍率は異なります。画像中の文字、角丸、ピクセル寸法をそのままコントロールの寸法に使うことはできません。[コンポーネントパラメーター](../../../specs/visual/directory-tree.json)には実装の論理寸法を明記し、素材マニフェストには物理的な切り出し座標を別に記録します。実装は論理幅 1024 と共有の原稿キャンバス変換を使用します。新しいコンポーネント全体をさらに拡大しないでください。

Qt は以下の論理値を直接使用します。1548 ピクセルの参照は layout-scale.json に従い 1024 論理ピクセルに対応します。DPR はサンプリング密度と線の位置合わせだけを決め、論理寸法の変換には入りません。

## ツリー構造と件数

完全なインデックスは明示的および暗黙的なディレクトリを提供します。リーフとは**サブディレクトリがない**ことであり、ファイルがないことではありません。Glacier Lake にサブディレクトリがある場合、親の矢印とは別に独自の展開矢印があります。

```text
Root                               ← current directory
▼ 01 Photos                     12
  ▼ Glacier Lake                 6
    ▸ Lakeside Trail             3  ← deeper directory, not expanded
      Snow Mountain View          3  ← files only, retains empty arrow slot
  ▸ Mountain Sunrise             4
    Other Photos                 2  ← no subdirectories
▸ 02 Documents                   8
  03 Maps                        4  ← no subdirectories
```

例のアーカイブには写真 12 件、文書 8 件、地図 4 件、ルート直下のファイル 6 件があります。ルートのリストは直下の三つのディレクトリと六つのファイルを表示し、子孫を展開しません。閉じた枝の子孫もパラメーターファイルにすべて記載し、リーフに偽の矢印を付けないようにします。別のボードにある明示的な空ディレクトリは独立した状態例であり、この 30 件の例には追加しません。

ディレクトリの数値は、重複名を含み、ディレクトリの接頭辞と完全に一致するレコードを除いた、接頭辞下のすべての**物理アーカイブレコード**を表します。サブディレクトリの数ではなく、名前検索によって変わりません。ツリーの行に件数は表示しません。アーカイブの概要は全物理レコード数を保持し、リストのタイトル右側は現在のディレクトリの行数を表示します。両者は定義が異なります。通常のリストは最終名を、検索結果はアーカイブ内の完全なパスを表示します。

矢印は既知のサブディレクトリの有無だけで決まり、親が閉じていれば右、展開されていれば下を向きます。ファイルだけを含むノードや空ノードには矢印がありませんが、同じ階層では矢印枠、アイコン枠、テキスト開始位置を揃えます。完全なインデックスの読み込み中は、ノードごとの矢印、件数、構造を推測せず、ノード単位の非同期読み込み状態を追加しません。

## レイアウト、文字、動的な形状

| 項目 | 通常の論理寸法と動作 |
| --- | --- |
| サイドバーの既定幅 | 193.16。メインウィンドウの構造境界では 193 に丸める |
| 行の高さ | 最小 32。大きい文字ではパラメーターの式に従って増加 |
| 階層ごとのインデント | 12.8。ノードの種類に依存しない |
| 矢印の操作領域／画像枠 | 最小 19.2×19.2／14.4×14.4。リーフも同じ枠を保持 |
| フォルダーアイコン枠 | 16×16。共有の 24 単位 SVG を比例縮小し、現在のツリーの 18 枠を置換 |
| アイコンと文字の間隔／末尾余白 | 6.4／16。件数は表示しない |
| 本文 | 11.2。Qt では 11 に丸め、同一原稿のフォントを使用 |
| レコード件数 | データとアクセシビリティの意味情報に保持。行には表示せず、件数列も確保しない |
| 現在のディレクトリ | 淡い青の背景、右側の角丸 6.4、左端は直線、全高で幅 2.4 のインジケーター |
| キーボードフォーカス | 追加の枠やフォーカスバーを描かず行の占有範囲も変えない。現在のディレクトリのインジケーターは保持 |
| 階層線 | 幅 1。背景に対して控えめに階層を示す |
| 隠れた現在のディレクトリの印 | 透明な 19.2 単位の枠内に 4.8 単位の点。名前と行の中心を共有 |

接続線は表示中の祖先チェーンと最後の兄弟フラグから動的に描画します。親の縦線は展開されたサブツリーを通り最後の兄弟の中心まで続き、最後の接続は L 字で終わって次の最上位グループに延びません。各縦線の中心 X は親の下向き矢印の先端 X と揃え、アクセシビリティ用の大きな文字でも維持します。内側の線はそれぞれ独立して終わるため、汎用の線画像を全行にわたって使うことはできません。線分は対象 DPR に合わせ、文字、矢印、フォルダーは行の縦中心を共有します。

階層領域は水平方向にスクロールします。幅は展開されて現在見えるノードの実際の名前、インデント、末尾余白 16 のみから求めます。名前は件数を重ねず完全に表示します。折りたたんだ後は幅を再計算し、隠れた深いノードのために空白を残しません。左のインジケーターは表示領域の端に固定します。行をホバーしてもフローティングツールチップは表示せず、完全なパスはアクセシビリティ説明と詳細で確認できます。垂直スクロールはディレクトリの表示領域内だけで行い、スクロールバーはメインウィンドウの枠を囲みません。

すべてのディレクトリで同じフォルダー素材を使用します。枝の点、塗りつぶしの情報／警告アイコン、分割型スピナーにはライト／ダーク SVG と 1×／2×／3× PNG があります。線、フォーカス枠、背景、スケルトン、文字、案内は動的コンポーネントです。ダークのパラメーターは全体テーマを再利用し、線とマーカーの色を追加します。**完全なダークのディレクトリツリー原稿は未完成**であり、ダークアイコンの書き出しはアートボード全体の代わりにはなりません。既存の描画とデスクトップ受け入れの結論は、対応する issue と成果物に別途記録されています。

Qt の操作の一貫性は[検証方法](../../../developers/qa/README.md)に従って記録します。アートボードと切り出しは元のデザイン履歴を保持し、現在の行数、フォーカス、角はこのページと論理仕様に従います。

## 操作と独立した状態

展開、現在のディレクトリ、ホバー、キーボードフォーカスは独立して保存され、同時に存在できます。現在のディレクトリは、右側のファイルのチェック選択とも異なります。

ルートは別途移動できる項目で、常に展開され、通常のノードの展開／折りたたみに参加しません。右クリック、Menu キー、Shift+F10 でメニューを開いたとき、「サブディレクトリを折りたたむ」は無効のままで、画面上の説明行やツールチップは表示しません。アクセシビリティ説明は「根目录始终展开」／「Root is always expanded」です。通常のツリー行がないことはサブディレクトリがないことを意味しません。通常の親ノードの展開／折りたたみは実際のサブディレクトリの有無によって決まります。通常のリーフはアクセシビリティ説明「This node has no subdirectories」を保持します。理由はアクセシビリティ情報としてのみ提供し、画面上には表示しません。メニューを開いたり無効な項目をクリックしたりしても、ディレクトリ、ファイル選択、ツリーの展開状態は変わりません。

| 操作 | 結果 |
| --- | --- |
| 矢印をクリック | そのノードだけを展開／折りたたむ。ディレクトリの問い合わせ、ファイル選択、詳細は変わらない |
| 名前をクリックまたは Enter | 現在のセッションのディレクトリ ID で移動する。問い合わせの置換に成功した後、既存契約に従って現在のディレクトリの問い合わせ、ファイル選択、詳細をリセット |
| 上／下 | 表示中のディレクトリ行間でフォーカスを移動し、ファイルリストは自動で切り替えない |
| 右 | 閉じた親を展開し、既に展開済みなら最初の子に移動。リーフでは移動しない |
| 左 | 展開された親を折りたたみ、それ以外は親へ移動。最上位ノードでは移動しない |
| 現在のディレクトリの祖先を折りたたむ | 現在のディレクトリとファイルリストを保持。隠れたフォーカスは最も近い表示中の祖先に戻す |
| 新しいアーカイブセッション | 古いノード ID、展開、フォーカス、枝の点を消去。他のアーカイブの状態を再利用しない |

例えばパスが `01 Photos / Glacier Lake` のとき、`01 Photos` を折りたたんでも右側には Glacier Lake が表示されたままです。Photos 行には青い末尾の点だけを表示し、Glacier Lake の現在ディレクトリ背景は付けません。ルートも現在のディレクトリにはなりません。青い点は**最も近い表示中の折りたたまれた祖先**に付きます。隠れた現在のディレクトリ一つにつき枝マーカーは一つです。再展開すると Glacier Lake の現在背景が復元されます。

ツリー全体はキーボードナビゲーションの一つの入口です。ノードは安定した ID、名前、階層、展開状態、位置、レコード件数のアクセシビリティ意味情報を保持します。リーフを展開可能と表現せず、装飾用のフォルダー、線、点を重複して読み上げません。隠れた現在のパスにはアクセシビリティ説明を付け、青色だけに依存しません。矢印キーと矢印のクリックは行のアクティブ化に伝播させません。

## 状態の網羅と復旧

| 状態 | ディレクトリツリー | ファイルリストと復旧 |
| --- | --- | --- |
| 読み込み中 | 読み込みメッセージ、件数不明。スケルトンは将来用のデザイン素材。ナビゲーションは無効 | 全体の読み込み状態に従い、完全なインデックスの公開後にツリーを一度置換 |
| 空のアーカイブ | ルート行に数値なし。「このアーカイブは空です」 | 空のリスト。他のアーカイブは引き続き開ける |
| ルート直下のファイルのみ | ルート行に数値なし。「サブディレクトリはありません」 | 六つのファイルを通常どおり表示し、ページ全体を空状態にしない |
| ディレクトリインデックスの上限超過 | 不完全なツリーを公開せず「ディレクトリが表示上限を超えています」を表示 | 現在の機能範囲でルート、検索、対象の明示的ディレクトリの閲覧を継続 |
| 読み込み失敗 | ナビゲーションを減光し明確なエラーを表示 | アーカイブを開き直す。失敗を件数ゼロや空ディレクトリと解釈しない |
| サブディレクトリのあるノード | 各階層に独立した矢印 | 展開はそのディレクトリへの移動ではない |
| 非空／空のリーフ | 件数はデータに保持。どちらも行数や矢印を表示しない | 名前はアクティブ化可能。空ディレクトリも閲覧できる |
| 長い名前／深い階層 | 完全な名前、アクセシブルなパス、水平スクロール、表示ノードに基づく幅 | パスのフィルタリングは一貫性を保つ |
| 文字サイズ 150%（200% は過去の負荷試験のみ） | 枠と行が拡大し、線を行の中心に再配置 | 名前、矢印、フォーカスを切り取らない |
| 隠れた現在のディレクトリ | 最も近い表示中の祖先に枝の点を表示 | リストは現在のパスを保持し、再展開で現在の行を復元 |

ナビゲーションの上限と全体の読み込み失敗は異なる状態です。理由、可能な操作、件数の出所を「空ディレクトリ」のテンプレートに共用できません。既存の 32,768 ノード、64 階層、ディレクトリ名 4 MiB の上限は読み取り専用契約によるものであり、デザインによって引き上げたり回避したりしません。

## 素材の提供と実際の統合

元のピクセル単位の 26 枚の切り出しは `design/assets/reference/tree-*.png` にあり、それぞれに出典、SHA-256、`x,y,width,height`、用途を記録します。`component_reference_coverage` は共有ベクターまたは動的コンポーネントを個別に指します。静的な行全体の画像を対話型コントロールと説明したり、切り出しから白い背景を消して透明素材を捏造したりしないでください。

| 部分 | 素材／描画 | 現在の統合 |
| --- | --- | --- |
| フォルダー、右／下矢印 | 共有素材の `folder`、`chevron-right`、`chevron-down` | 既存の共有リソースが利用可能。Qt デリゲートで B のアイコンと寸法を使用 |
| 読み込み、情報、警告 | 新しい `tree-spinner`、`tree-info`、`tree-warning` | ライト／ダークの SVG 8 枚と透明 PNG 24 枚の一部。既存の輪郭アイコンに置き換えず、ボードの塗りつぶしと分割表現を保持 |
| 隠れた現在の枝 | 新しい `tree-active-branch` | 二つのテーマ用に透明 PNG 6 枚を提供。Qt が最も近い表示中の折りたたまれた祖先の印として使用 |
| 線、現在背景、フォーカス、スケルトン、案内 | パラメーターファイルの寸法とテーマで動的に描画 | スタイルとロジックを規定。別のビットマップコントロール群は提供しない |
| 正式なアートボード | `hifi/screens/directory-tree*.png` | デザイン比較のため確定済み原稿のバイトを保持 |

Qt は接続線、枝の点、16 単位のフォルダー枠、ディレクトリのコンテキストメニューを統合しています。Qt は実際の制限付きインデックスを使います。現在の祖先を折りたたんでも問い合わせは送信しません。読み込みスケルトンと専用の情報／エラーアイコンはデザイン素材のままで、完全なダークのアートボードは未完成です。アイコンの統合は各プラットフォームのスクリーンリーダーや高 DPI の受け入れを証明しません。既存の手動検証の結論は [WP-12 #5](https://github.com/xiaodaozhi/xdzip/issues/5) に従います。

## 統合後の受け入れ

1. 論理幅 1024、フォント設定、DPR、状態データを揃えて実際のディレクトリ領域を撮影し、対応する確定済みアートボードの領域と仕様を比較します。倍率の関係を記録し、視覚的判断と構造のアサーションを別々に保持します。
2. 各階層の矢印、アイコン、名前の開始位置を揃えます。数値の行列は設けません。アイコン、文字、点、矢印は行の中心を共有します。目標となる形状の差は最大で物理 1 ピクセルとし、フォント差異のプラットフォームと実際のフォールバックを記録します。
3. 深い階層の折りたたまれた枝と非空リーフを含め、少なくとも三階層を展開します。最後の兄弟と展開されたサブツリーを通る接続線の連続性と終端を確認します。
4. 現在、ホバー、フォーカスを個別および同時に確認します。矢印のクリックはディレクトリ問い合わせを送信せず、ファイル選択を消しません。Enter のアクティブ化は問い合わせ成功時のリセット規則に従います。
5. Glacier Lake を現在のディレクトリにして Photos を折りたたみます。リストのパスは保持され、ルートは選択されず、Photos には枝の点だけが表示されます。再展開で現在の行を復元します。フォーカスが隠れた場合もキーボード操作が可能であることを確認します。
6. 実際の制限付きインデックスで、空アーカイブ、ルートのファイル、明示的な空ディレクトリ、読み込み失敗、ディレクトリ上限を確認します。件数、無効化、復旧操作をそれぞれ確認します。
7. 長い名前、100%／125%／150% の文字サイズと過去の 200% 負荷試験、最小ウィンドウ、許可された最大インデックス深度で、名前が完全に見え、水平スクロールが階層だけに作用し、完全なパスがアクセシブルであることを確認します。ツリーのスクロールはアーカイブ概要や下部の統計を動かしません。
8. 実際のライト／ダーク描画、通常／Retina／Windows 高 DPI、キーボード、スクリーンリーダーの受け入れを完了します。画像チェックや素材生成の成功はこれらの実行時検査の代わりにはなりません。

[検証方法](../../../developers/qa/README.md)に従い、原稿、切り出し、素材と、実際のマウス、キーボード、メニュー、ツリー操作を別々に確認します。未検証のアクセシビリティとプラットフォーム差を明記します。
