# XDZip の製品要件

[English](../../design/product-requirements.md) | [简体中文](../../zh-CN/design/product-requirements.md) | [繁體中文（台灣）](../../zh-TW/design/product-requirements.md) | 日本語 | [한국어](../../ko-KR/design/product-requirements.md) | [Français](../../fr-FR/design/product-requirements.md) | [Deutsch](../../de-DE/design/product-requirements.md) | [Español](../../es-ES/design/product-requirements.md) | [Português (Brasil)](../../pt-BR/design/product-requirements.md) | [Русский](../../ru-RU/design/product-requirements.md)

XDZip ではアーカイブをフォルダーのように閲覧し、選択した内容を扱えます。形式が対応する場合は作成や変更もできます。デスクトップと[独立 CLI](../engineering/command-line.md) は同じアーカイブランタイムを使います。現在の機能と配布方法は[プロジェクト README](../../../README.ja-JP.md)を参照してください。以下は維持・検証する動作です。

<a name="xdzip-requirements-and-implementation"></a>

## 要件と実装

| ID | 要件 | 現在の動作と範囲 |
| --- | --- | --- |
| P01 | 展開せずに閲覧 | 入力元を判定し、上限付き走査を終えてから最初のページを公開します。項目内容のデコードには別の操作が必要です。 |
| P02 | 移動、検索、並べ替え、選択 | 安定した物理 ID、独立したナビゲーション ID、ページ単位の検索、上限付き選択を実装しています。通常の単一ファイル ZIP/ZIP64 はより大きなメタデータ索引を持ち、タスク上限は別です。 |
| P03 | 指定範囲を展開 | ランタイムは対象範囲を固定し、名前を検証して出力先を許可します。競合の判断を扱い、実際の確定、スキップ、エラー、キャンセルを報告します。 |
| P04 | ファイルとフォルダーからアーカイブを作成 | 作成レジストリでオプションを検証し、一時領域に出力してから検証・確定します。対応形式とオプションはレジストリに従います。 |
| P05 | 形式ごとの機能を尊重 | UI は形式の説明と現在のセッション状態を組み合わせます。各要求はランタイムでも検証します。読み取り、プレビュー、検査、作成、パスワード、分割の各プロファイルには別々の制限があります。 |
| P06 | タスクを制限しキャンセルを可能にする | メタデータと重いタスクは別の待ち行列を使います。デスクトップの重い操作は一度に一つ実行し、受理済みのタスクはタブを閉じても継続できます。 |
| P07 | 検証済みの権限と制限の範囲内で書き込む | ホストが名前、リンク、ファイルの識別、一時準備、実出力、確定を管理します。形式の検査は該当する構造と整合性を検証します。 |
| P08 | 一貫性がありアクセシブルなデスクトップ操作を提供 | QML と C++ は共通コントロール、キーボード操作、フォーカス、アクセシビリティを提供します。ネイティブ IME、スクリーンリーダー、表示動作には個別の検証が必要です。 |
| P09 | リソースを制限し計測 | コードは独立した予算を適用します。性能目標と実測結果は別々に管理します。 |
| P10 | 形式ロジックから Qt を分離 | Rust トレイト、明示的なレジストリの振り分け、専用プロセスのインターフェースで組み込み実装を支えます。デスクトップと CLI は同じコアを使います。 |
| P11 | 秘密情報とデータを保護 | アーカイブ操作はオフラインで動きます。パスワードは用途を限定し、ゼロ消去可能な領域に保持します。プライバシー、診断、明示的な更新アクセスにはそれぞれ契約があります。 |
| P12 | 配布物を監査 | 定められた配布経路、固定入力、マニフェスト、チェックサム、ライセンス資料、プラットフォーム検査を使用します。結果は実際に検証したビルドと配布物に適用します。 |
| P13 | 信頼性と権限を検証した第三者拡張のみを許可 | 読み取り専用 XDP1 試験は別に実装しています。製品での拡張のインストールと有効化は設計段階です。 |
| P14 | プレビューと開く操作を制限 | プロパティパネルが見えているとき、対応ファイルを一つ選ぶと上限付きのテキストまたは画像プレビューを開始します。対象となる通常ファイルを明示的に開くと、検証済みの非公開コピーをシステム関連付けに渡します。 |
| P15 | 失敗と不確実な結果を正確に報告 | 安定したエラーと上限付きの結果で、入力元の変更、ディスク障害、スキップ、後処理を報告します。再起動後の自動復旧は設計案です。 |

<a name="xdzip-workflows-and-scope"></a>

## 操作と範囲

- **開いて確認。** ファイルを開く要求はデスクトップのセッション管理へ送られます。走査に成功するとセッションを公開し、検索と並べ替えは新しい照会を作ります。ダブルクリックでフォルダーに入り、対応するファイルは一時コピーを介して開きます。プロパティパネルが見えているときは、対応ファイルを一つ選ぶとプレビューが始まります。[閲覧とプレビュー](../user-guide/browse.md)、[一時的に開く](../engineering/archive-opening.md)
- **展開。**「すべて展開」はアーカイブ全体を対象とします。一致項目だけを展開するには、検索結果から選び、対象範囲を確認します。メタデータの事前検査は書き込み許可の前に問題を報告します。ファイルごとに確定するため、後の失敗やキャンセル後も完了済みファイルは残ります。[展開](../engineering/zip-safe-extraction.md)、[タスクのスケジュール](task-scheduling.md)
- **作成、変更、検査。** 作成と対応する変更は一時出力を検証してから確定します。検査は対応アーカイブを形式に従って調べ、出力の権限は得ません。操作の可否は形式、項目、入力元のプロファイルによります。[形式レジストリ](../engineering/format-registry.md)、[アーカイブ転送](../engineering/archive-transfers.md)、[アーカイブ検査](../engineering/archive-checking.md)

<a name="xdzip-planned-scope-and-verification"></a>

## 計画範囲と検証

外部拡張の管理、永続的なタスク復旧、追加の形式プロファイルには個別の設計、実装、検証が必要です。バージョン番号だけでは形式やプラットフォームの対応範囲を確定できません。クラウド同期、ディスクイメージのマウント、マルウェア検査サービスは製品の対象外です。[追跡マトリクス](requirements-traceability.md)に要件と検証の対応を示します。[サポート方針](../engineering/support-policy.md)とリリースノートに配布ビルドを記載します。
