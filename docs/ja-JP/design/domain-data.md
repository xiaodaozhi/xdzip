# ドメインモデルとアーカイブデータ

ランタイムはアーカイブのセッション、完成した索引、そのセッションの最新クエリーを所有します。Qt は結果のビューを保持し、CLI は別のカタログコマンドで物理レコードを読めます。両方とも同じ Rust サービスに操作を送信します。[システム構成](system-architecture.md)、[Qt/Rust ブリッジ](qt-rust-bridge.md)

<a name="xdzip-identity-and-source-version"></a>

## 識別とソースバージョン

| 識別情報またはデータ | 現在の表現と範囲 |
| --- | --- |
| `SessionId` | 開いたアーカイブのゼロでないランタイム識別子。新たに開く操作が成功するたびに新しいセッションを作成する。ファイルパスは入力と UI のルーティングに使う。 |
| `SourceVersion` | ランタイムは受理した各部分の通常ファイルの識別情報、長さ、利用可能なタイムスタンプを記録する。関連する読み書きの境界で、開いたオブジェクトと対応するパスを再確認する。変更の検出はベストエフォートである。 |
| `EntryId` | セッション内の物理アーカイブレコードを識別する。同名のレコードも異なる ID を保持する。 |
| 移動用の識別情報 | 索引付きディレクトリーを表す。子孫から合成した仮想ディレクトリーは、物理項目 ID がなくてもツリーや一覧に表示できる。 |
| `QueryKey` | セッション、クエリー ID、世代、スナップショットのリビジョンを組み合わせる。オフセットはこの結果内の位置を指す。 |
| 要求、タスク、確認画面の識別情報 | サービスは接続内で要求番号とタスク番号を割り当てる。確認画面は特定のタスクに属する。共通デスクトップのタスク項目はコントローラーのセッション識別情報とタスク番号を組み合わせる。 |

ドメイン型はアーカイブとクエリーの識別子がゼロでないことを保証します。ネイティブブリッジでは型付き Rust 値を生成された CXX データで表現します。64 ビットすべてを必要とする ID は不透明な文字列として QML に渡します。行番号は特定のクエリー内の位置にすぎません。[ドメインの識別子](../../../crates/xdzip-domain/src/identity.rs)、[ソース実装](../../../crates/xdzip-runtime/src/source.rs)、[アプリケーションセッション](../engineering/application-sessions.md)

<a name="xdzip-physical-entries-and-output-names"></a>

## 物理項目と出力名

`xdzip-codec-api::Entry` は形式、物理的識別情報、名前の表現、サイズ情報、ファイル種類のフラグ、更新情報、形式固有の方式と暗号化フィールドを含みます。名前の生バイト、省略可能なデコード済み UTF-8 表記、エンコーディングの判定、エスケープ済み表示文字列は別々に保存します。出力時にはランタイムが実効名を移植可能パスの方針と許可された出力先に照らして検証します。未解決の名前は表示したままにできますが、そのレコードまたはディレクトリーの展開は拒否されます。

元のサイズには独立した `size_known` フラグがあり、サイズがゼロと判明しているファイルと不明なサイズを区別します。圧縮コンテナーによっては項目ごとの圧縮サイズがありません。方式の値は形式に応じて解釈します。時刻データも ZIP のローカル DOS 時刻など形式固有の規則を保持し、時刻が欠けている場合は不明のままです。`payload_supported()` は現在のレコードがデコード可能かを判定します。出力はさらに選択した操作、ソースの状態、名前、ファイルシステムの規則に依存します。[項目のフィールド](../../../crates/xdzip-codec-api/src/lib.rs)、[ファイル名の処理](../engineering/filename-encoding.md)、[ファイルの認可](file-security.md)

<a name="xdzip-index-query-and-page-lifecycle"></a>

## 索引、クエリー、ページのライフサイクル

ランタイムはソースを開き、上限付きの走査を完了してからアーカイブと最初のページを公開します。走査はキャンセルできます。末尾の破損、パスワード不足、ソースの変更があれば部分的な索引は公開しません。移動には別の予算があります。ディレクトリーツリーがそれを超えても、ルート参照と物理検索は引き続きサポートできます。通常の単一ファイル ZIP/ZIP64 は非公開ディスク経路により最大 100 万レコードを保持できます。他の形式と分割経路はそれぞれの上限を維持します。

`Archive::query_page` はディレクトリー、テキスト、並べ替え方式、オフセット、期待するクエリー識別子を受け取ります。新しいクエリーは新しい世代でオフセットゼロから始まります。ランタイムは結果全体の順序を構築し、各アーカイブにつき一つの現在の不変クエリーを保持します。ページはその順序から行の識別情報を解決します。検索と並べ替えはアーカイブレコードの元の識別情報を維持します。どの方式でもディレクトリーをファイルより先にまとめ、同順位を識別情報で決定的に処理し、同じグループ内ではサイズ不明を既知の値の後に置きます。

汎用ドメイン型の `PageRequest` は最大 256 行を検証します。デスクトップランタイムの転送は最大 128 行を要求し、名前の予算は 64 KiB です。Qt は小さな結果を全件確定し、大きな結果では最大 1,024 行を常駐させます。セッション、クエリー、世代、リビジョン、オフセットが一致しない応答は現在のデータを置き換えられません。[クエリー実装](../../../crates/xdzip-runtime/src/query.rs)、[一覧と並べ替え](../../../crates/xdzip-runtime/src/listing.rs)、[大規模アーカイブの索引](../engineering/large-index.md)

<a name="xdzip-selections-and-operation-input"></a>

## 選択と操作入力

Qt モデルは読み込み済み結果の選択を ID で保存し、大きな結果では現在の結果内の上限付き範囲として保存します。すべて選択はその結果全体を対象とします。タスクはアーカイブ全体と、検索結果から明示的に選択した集合を区別できます。展開の確認時、Rust は `FreezeSelection` で完全なクエリーキーに照らしてページをまたぐ選択を解決します。ディレクトリーの展開では実際の子孫を解決して物理 ID の重複を除きます。操作の上限を超えるとエラーを返します。CLI は `SelectMembers` でメンバーパスと物理 ID を解決します。

展開、検査、編集は必要なソースと保持済みメタデータを使って操作固有のジョブを準備します。作成ではオプションを受け取ってから別の `InputTree` を走査し検証します。メタデータの事前確認は潜在的な問題を説明できますが、タスクに出力権限を与えません。ランタイムは書き込み前に入力を再確認し、対応する許可を取得します。ジョブが選択を所有した後は、UI の変更でその範囲が変わることはありません。[デスクトップモデル](../../../apps/desktop/BrowserController.cpp)、[ランタイムコマンド](../../../crates/xdzip-runtime/src/service.rs)、[タスクスケジューリング](task-scheduling.md)

<a name="xdzip-results-and-data-lifetime"></a>

## 結果とデータの寿命

| データ | 寿命 |
| --- | --- |
| 現在のアーカイブ、クエリー、ディスク索引 | サービスセッションに属する。クエリーの置換またはセッションの終了で関連する非公開データを解放するが、ジョブが独立して保持するリソースは別。ディスクメタデータ索引はアーカイブの再オープン時に再構築する。 |
| タスクのスナップショット | ランタイムは実際の状態、バイト数と項目数、クリーンアップ状態、上限付き詳細一覧を含む上限付きスナップショットを公開する。デスクトップは所有コントローラーを通じてアプリケーションセッション中に結果を利用可能に保つ。 |
| ユーザー設定 | アーカイブ索引とタスク結果とは別に管理する。データ保持とプライバシーは設定とプライバシーの契約に記載する。 |
| 作業領域とジャーナル | 非公開の出力準備と相対的な公開記録がクリーンアップと検査を支える。再起動しても未完了のアーカイブ書き込みを再実行しない。 |

<a name="xdzip-design-options-outside-the-current-implementation"></a>

## 現在の実装外の設計案

検索可能な索引の段階的公開、独自のリビジョンと開始トークンを持つ再利用可能な計画、永続的なページ分割タスク履歴は設計案です。現在のコマンドはそれぞれ上限付きジョブを準備してキューに入れ、一つの現在のクエリーを保持し、上限付きタスクスナップショットを返します。永続的な復旧には、ソースと出力の検証を別途設計する必要もあります。
