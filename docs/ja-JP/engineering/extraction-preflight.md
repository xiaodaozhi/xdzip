# 展開前チェック：メタデータ段階

[English](../../engineering/extraction-preflight.md) | [简体中文](../../zh-CN/engineering/extraction-preflight.md) | [繁體中文（台灣）](../../zh-TW/engineering/extraction-preflight.md) | 日本語 | [한국어](../../ko-KR/engineering/extraction-preflight.md) | [Français](../../fr-FR/engineering/extraction-preflight.md) | [Deutsch](../../de-DE/engineering/extraction-preflight.md) | [Español](../../es-ES/engineering/extraction-preflight.md) | [Português (Brasil)](../../pt-BR/engineering/extraction-preflight.md) | [Русский](../../ru-RU/engineering/extraction-preflight.md)

このモジュールはメタデータ事前チェックの規則を提供します。出力先の承認、デコード、書き込み、一時準備、コミットの能力はありません。

<a name="xdzip-implementation-and-boundaries"></a>

## 実装と境界

`xdzip-extract-plan` はドメインとメタデータのインターフェースだけに依存し、Qt、形式パーサー、追加の第三者依存関係を持ちません。入力はセッションスナップショット、物理 EntryId の集合、キャンセルです。出力は制限されたレポートだけであり、書き込み可能なパスや安全承認フラグではありません。`xdzip-runtime` がスナップショットを保持し、Qt はワーカースレッドのブリッジを通じて呼び出します。

選択は空でなく、最大 128 個の物理 ID に制限され、すべて現在のスナップショットに属する必要があります。ディレクトリーの選択は元の名前のスラッシュ境界を使って全子孫を展開し、検索、ページ分割、現在のディレクトリー範囲には左右されません。ディレクトリーと子を両方選んでも子は 1 回だけ数えます。同名の物理レコードはパスで統合しません。ディレクトリー統計は明示レコードだけを数え、ディレクトリーオブジェクトを生成しません。

事前チェックは制限された受け入れと独立したキャンセルを持つコマンド、イベントサービスで実行します。ランタイムは検査前後に開いたソースの ID を確認します。ディスクインデックス付き ZIP では、選択した物理レコードと必要な子孫をインデックスから読み込みます。選択、クエリー、セッションが変わるとレポートを消去します。結果は記録されたメタデータからの推定です。事前チェックはメンバー内容のデコード、出力先パスの予約、書き込み承認を一切行いません。

<a name="xdzip-rules-performed"></a>

## 実行する規則

- 名前は UTF-8 に解決でき、最大 4 KiB、64 コンポーネント、各コンポーネント最大 255 バイトです。元の名前は修復、書き換えしません。
- 絶対パス、空のコンポーネント、`.`、`..`、バックスラッシュ、コロン、制御文字と双方向制御文字、Windows の無効文字、コンポーネント末尾の空白やドットを拒否します。
- 拡張子付きや上付き COM/LPT 数字を含む一般的な Windows デバイス名を拒否し、クロスプラットフォームの可搬名サブセットを保守的に適用します。
- 既存のメタデータ警告を報告し、レコードのデータとパスワードの能力フラグを使用します。暗号化レコードは対応するパスワード要求または未対応の暗号化を報告できます。既知サイズでデータが未対応のレコードは方式の問題も報告します。事前チェックはリーダーが投影したメタデータと能力を使用し、データの復号、認証、デコードは行いません。
- 完全に重複する名前、Unicode 小文字比較による衝突、大文字小文字だけが異なる親ディレクトリー別名、両方の挿入順におけるファイルとディレクトリーの競合を確認します。暗黙の親ディレクトリーは同名の明示ディレクトリーで補えますが、明示ディレクトリーレコードの重複は競合します。
- 宣言されたファイルサイズが 8 GiB を超える場合、合計が 20 GiB を超える場合、整数オーバーフローを報告します。ZIP レコードの宣言された圧縮率が 1000:1 を超える場合は確認を促します。ディレクトリーサイズは出力バイトに含めません。

Unicode 小文字比較は完全なケースフォールディングでも、ファイルシステムの NFC/NFD 等価性でもありません。非 ASCII コンポーネントがある場合、出力先ファイルシステムで名前の等価性と衝突をさらに確認する必要がある旨を通知します。問題のないレポートでも出力を承認しません。

<a name="xdzip-resources-and-failures"></a>

## リソースと失敗

最大 100,000 件のスナップショットレコードを確認し、選択または展開した名前の合計は最大 4 MiB です。衝突インデックスに保存する比較キーと元の表記の合計は、コンテナーのオーバーヘッドを除いて最大 8 MiB です。コンポーネントの走査深度は制限され、外側の各レコードでキャンセルを確認します。レポートは全問題を数えますが、ブリッジを通す代表的な問題は最大 64 件で、物理レコード ID と安定した理由だけを含み、任意のアーカイブエラー文は含みません。

空の選択、別の ID、インデックス制限、キャンセルは部分成功レポートではなくエラーを返します。合計がオーバーフローした場合、ゼロに切り捨てず「利用不可」と表示します。基本的な問題は報告するだけで、自動的に上書き、名前変更、無視、スキップしません。

非圧縮サイズが不明な場合は安定した理由 `unknown_size` を報告します。`declared_bytes=None` は合計不明を意味し、既知の空ファイルを示す `Some(0)` とは異なります。不明な値から合計サイズ超過や未知方式の問題を作り出しません。実際の整数オーバーフローは引き続き合計上限の問題になります。出力タスクは別途、デコード、一時準備、パスワード操作の前にサイズ不明のレコードを拒否します。

<a name="xdzip-desktop-entry-point"></a>

## デスクトップ入口

項目を選択して「展開前にメタデータを確認…」をクリックします。結果は独立した非モーダルのトップレベル `OperationWindow` に表示し、メインウィンドウを一時的な所有者としてネイティブタイトルバーを保持します。macOS の信号ボタンをアプリが描画することはありません。結果を閉じてもそのウィンドウだけが閉じます。メインウィンドウを閉じる場合は協調的キャンセルを使い、GUI スレッドでワーカーを待ちません。

<a name="xdzip-boundary-with-actual-extraction"></a>

## 実際の展開との境界

[実際の安全な展開](zip-safe-extraction.md)は出力計量、CRC と構造検証、出力先承認、プラットフォームのパス再確認、競合、一時準備、ファイルコミットを独立して実装します。事前チェックの 128 件の選択制限は受けず、100,000 件の物理レコードの計画と仮想ディレクトリー選択をサポートします。事前チェックのレポートを書き込み許可として再利用しません。タスク開始時には[ファイルセキュリティ仕様](../design/file-security.md)に従い出力先承認を再取得し、ソースを再検証し、実際の内容を確認する必要があります。ネイティブの失敗動作と既知の欠陥は関連する契約と issue で追跡します。

<a name="xdzip-window-and-result-presentation"></a>

## ウィンドウと結果の表示

事前チェックは幅 491 論理ピクセルの共通操作ウィンドウを使用し、内容に応じた本文、最大クライアント領域高 600、スクロール可能な長い問題一覧、アクセス可能な固定フッターを備えます。データ段階とメタデータ段階の承認境界は変わりません。パラメーターと設計ソースは[事前チェックパラメーター](../../../specs/visual/preflight-reference.json)を参照してください。

事前チェックの説明位置は 2026-10-15 に変更されました。「このレポートではメタデータだけを検査します…」をスクロール可能な本文の末尾に 12 ポイントの説明文として移します。フッターにはこの説明を置かず、戻る操作だけを残します。高さはレポートの長さに関係なく、同じ文字サイズの共通アクション専用フッターと一致します。
