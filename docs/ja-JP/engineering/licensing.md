# ライセンスの決定と第三者資料

状態：採用済み。プロジェクトは 2026-10-11 に、別途明示されたものを除くプロジェクト独自のコード、文書、その他の独自コンテンツに **Apache-2.0** を採用しました。以前の実験文書にあった MIT OR Apache-2.0 の選択肢は、このリポジトリーには適用されません。

ルートの [LICENSE](../../../LICENSE) には Apache License 2.0 の標準全文があり、SPDX 識別子は `Apache-2.0` です。貢献ガイドとリリース設計も更新されています。ライセンスの選択はリポジトリーの公開範囲を変更しません。2026-10-19 の読み取り専用チェックで公開状態が確認されました。リリースの受け入れには実際の資料の別途レビューが必要です。

Qt の動的リンクでは各モジュールの LGPL/GPL/商用条件を確認する必要があります。バックエンド、アイコン、フォント、ツール、静的な Rust 依存関係は別々にレビューします。ライセンス互換性はコードにセキュリティ上の欠陥がないことを意味しません。必要な通知、ソースと再リンクの資料、インストール情報をリリース成果物に添付します。

7z、RAR、CAB、ISO/UDF は[独立した Rust 実装](independent-rust-codecs.md)を使用し、公式 UnRAR と 7-Zip のソースは現在の製品ビルドやデプロイに入りません。固定ルーティングと制御された I/O については[分離バックエンド契約](native-codecs.md)を参照してください。分析用ソース、開発用参照ツール、過去の公式バックエンド配布はそれぞれ元のライセンスを保持します。独立実装は厳格なクリーンルームや法的リスクがゼロであることを主張するものではありません。公式 7-Zip または UnRAR を含む過去の配布には元の条件、通知、変更資料の義務が引き続き適用され、現在の依存関係を削除したからといって Apache-2.0 に付け替えることはできません。現在の製品ソース一覧が空でも、過去の配布や独立参照ツールの義務は免除されません。実験ビルドは正式なライセンスレビューの代わりにはなりません。

RAR の有限なワイヤー形式マッピングと公開テストデータは、それぞれ出所、元の通知、ライセンス記録を保持します。[RAR 実装の根拠](rar-format-sources.md)を参照してください。製品エンジンを削除しても、これらの資料がプロジェクト独自コードとして再ライセンスされることはありません。

有限なマッピングは[固定された元の参照文書と出所](../../../third_party/rar-wire-mappings/README.md)も保持します。これには上流内部バージョン UnRAR 7.30 beta1 の元のライセンス全文、ダウンロードアーカイブ `unrarsrc-7.3.1.tar.gz`、原文の SHA-256 が含まれます。通知収集ツールはこれらの限定資料を実際の通知ハッシュに含め、対応ソース配布も別のコピーを保持します。これは公式エンジンを再導入したりランタイム依存関係と宣言したりするものではなく、条件の適用性を自動判定したり候補のリリースを承認したりするものでもありません。

固定された原文は空白を正規化した後、SPDX の `UnRAR` ライセンス文と一語一句一致します。参照マッピングを保守的に扱うため、RAR crate とそのソース SBOM は `Apache-2.0 AND UnRAR` と宣言し、選択可能な二重ライセンスではなく両方を要求します。この crate は crates.io に公開しません。`UnRAR` は SPDX 3.28 以降で OSI 未承認の識別子であり、古いツールでは認識されない場合があります。元のライセンスと制限を資料とともに保持します。この宣言はマッピングの著作権上の状態を決定せず、元の alpha.8 一覧を変更しません。

プラットフォームのランタイム通知、供給元の入力、ライセンス資格は[ネイティブランタイムの出所と通知](native-runtime-materials.md)に従います。一般的なライセンス文は供給元の著作権通知の代わりにはなりません。

自分の開発環境が必要な Windows 保守担当者は、条件を満たす場合、無料の Visual Studio Community を利用できます。GitHub 標準ホストランナーにプリインストールされた Enterprise には別のホスト利用権限があり、CI でのビルドと配布にローカルの Community IDE を追加する必要はありません。適用条件、Microsoft CRT/SDK の再配布条件、下流向け説明は [Windows 開発ツールとランタイムのライセンス](windows-licensing.md)を参照してください。これらの Microsoft コンポーネントはプロジェクトの Apache-2.0 の対象ではなく、通常の利用者が Visual Studio をインストールする必要はありません。

[実際のコンポーネント帰属プロセス](runtime-attribution.md)は固定 SDK の SPDX からモジュール、第三者、著作権、上流のライセンス式を抽出し、固定ソースのライセンス文を Windows/Linux ランタイムディレクトリーとともに配布します。上流の licenseConcluded は、プロジェクトがそのライセンス分岐を選択または承認したことを意味しません。各候補では実際のコンポーネントのソース、通知、対応ソース、置換資料を確認する必要があります。特定された適用義務または必要資料が未解決なら、その候補のリリースは阻止されます。上流の NOASSERTION や機械レポートの incomplete 表示だけでは、ライセンス衝突も免除も成立しません。

3 枚の視覚画像は生成デザインツールで作成され、Bandizip のスクリーンショットではありません。参照リンクは研究上の根拠を記録するだけです。生成素材の独占性は保証しません。リリース用アイコン、サンプル画像、フォントには別々の出所記録が必要であり、デザイン画像から切り抜くだけでは素材監査は完了しません。

最初の ZIP メタデータバックエンドは MIT ライセンスの rawzip を使用しました。バージョンと通知は[過去の採用記録](zip-metadata-admission.md)を参照してください。現在の ZIP、TAR、GZIP/Deflate は[独立した Rust 実装](independent-rust-codecs.md)を使用し、形式参照ライブラリーは開発テストだけに使用します。過去の配布とテスト参照のライセンス義務は残ります。汎用暗号基盤の通知は[依存関係契約](../engineering/dependencies.md)に従って収集します。プロジェクト独自のライセンスは引き続き Apache-2.0 です。

HTML デザインは公式 Noto Sans SC の派生サブセットを使用します。Qt の固定 UI テキストは、言語に応じて Noto Sans TC、JP、KR と Noto Sans の派生サブセットも使用します。これらのフォントは OFL-1.1 であり、プロジェクトの Apache-2.0 は適用されません。ファミリー名、固定ソース、バージョン、ハッシュは[フォント一覧](../../../specs/dependencies/ui-font.json)と[ネイティブ TTF 出力](../../../design/assets/fonts/README.en.md)を参照してください。元のライセンス全文は [CJK OFL](../../../design/assets/fonts/OFL.txt) と [Noto Sans OFL](../../../design/assets/fonts/NotoSans-OFL.txt) です。オフライン HTML はそのフォントバイナリーと完全な通知を含み、Qt 配布通知は対応するフォントライセンス文を含みます。製品には上流の完全な CJK フォントは含まれません。
