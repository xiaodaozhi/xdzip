# ZIP 作成の実装契約

[English](../../engineering/zip-creation.md) | [简体中文](../../zh-CN/engineering/zip-creation.md) | [繁體中文](../../zh-TW/engineering/zip-creation.md) | 日本語

明示的に選択したファイルとディレクトリから新しい ZIP アーカイブを作成します。既定はレベル 2 の通常圧縮で、Deflate 6 を使います。Store、Deflate 1/6/9、WinZip AES-256 による内容の暗号化、番号付き分割ボリュームに対応します。作成と展開は [TAR/GZIP](tar-gzip.md)、AES-256 の読み取りは[パスワード付き展開](password-extraction.md)、分割読み取りは[分割ボリューム契約](archive-opening.md)を参照してください。通常の単一ファイルアーカイブへの明示的な追加は[ドラッグ＆ドロップと変更の契約](../../engineering/archive-transfers.md)を使い、新規アーカイブ向けのソース保護例外を再利用しません。ホストは入力の認可、準備、検証、競合の判断と最終保存を所有します。フォーマット層が受け取るのはエントリー、読み取り可能な入力、書き込み可能な出力だけです。

## 入力ツリーと制限

選択対象は通常ファイルまたはディレクトリの絶対パスでなければなりません。同じパスと、選択済みディレクトリ内にある選択対象は重複排除します。再帰時もルートディレクトリ名を保持し、空ディレクトリは明示的なレコードを作ります。リンク、再解析ポイント、デバイスなどの特殊オブジェクト、移植性のない名前、大文字小文字の衝突は拒否します。共通の親ごとにルートディレクトリハンドルをまとめ、最大 128 個とします。上限は 100,000 エントリー、64 階層、名前の合計 16 MiB、ファイルごとに 8 GiB、入力合計 20 GiB です。エントリーごとにファイル記述子を持たず、限られたルートハンドルと現在の入力ファイルだけを保持します。

最初に入力の親に対するシステム上の別名を同じ場所に正規化し、選択された末端リンクはたどりません。ルートを開いた後にディレクトリの識別情報を結び付けて再確認します。ディレクトリの探索はルートハンドルの下をリンクをたどらずに走査し、ディレクトリ識別情報とフィルター後の子一覧、ファイルの識別情報、長さと更新時刻を保持します。エンコード前後と保存前に再確認し、各ファイルはオープン時と EOF でもバージョンを確認します。追加、削除、名前変更、リンクの置換と観測可能な内容変更はソース変更として失敗します。識別情報とタイムスタンプの検査は最善努力であり、原子的な内容スナップショットではなく、同じアカウントが意図的にメタデータを戻した編集の検出は保証しません。

後述の macOS メタデータを除き、作成は選択されたすべての通常入力を保持します。既存の出力先アーカイブ、古いボリューム、別ディレクトリの同名ファイルは通常の入力であり、対象パスと一致することを理由に早期拒否したり無言で除外したりできません。入力ツリーは、この操作が作成した非公開の準備作業ディレクトリについて、識別情報が一致した場合に限り別途除外します。`.xdzip-*` や出力先ファイル名をワイルドカードで除外しません。ディレクトリの別名を正規化し、保持ハンドルの識別情報を検証します。非公開作業ディレクトリまたはその別名の明示的な選択は引き続き拒否します。

エンコードは非公開の準備ファイルだけに書き、完全な検証後に最終競合ガードに進みます。出力先が入力にも含まれる場合は通常の競合確認を表示し、その入力の上書きを禁止して、新しい名前またはキャンセルを許可します。古い対象ファイルだけを選択した場合も同じ流れで、その元のバイトを別名の新しいアーカイブに含めます。UI を迂回する直接の上書きパラメーターや上書き応答は `protected_source` を返し、元データを保護します。アーカイブ作成中に追加されたファイルを再帰的に再探索しません。最終アーカイブは保存時にのみ公開し、増加中の準備ファイル自身をアーカイブに入れません。

名前競合ウィンドウは既定の論理幅と共有フッターを維持します。タイトルと保護の説明は利用可能な本文幅内で折り返し、アクセシビリティ用の大きな文字でもレイアウトの最小幅を広げて横方向の切れを生じさせません。本文が高すぎる場合は本文をスクロールし、判断ボタンには引き続きアクセスできます。

## macOS メタデータ入力のフィルタリング

ZIP、AES-256 ZIP、番号付き ZIP ボリューム、TAR、TAR.GZ の作成と通常アーカイブへの追加は、Rust の `InputTree::scan_for_archive` ポリシーを共有します。すべてのホストプラットフォームで、大文字小文字を区別した末端名の完全一致により、通常ファイル `.DS_Store` とディレクトリ `__MACOSX`、`_MACOSX` のツリー全体を、明示選択のルートや再帰走査を含む全階層で除外します。`._*`、隠しファイルや接頭辞ワイルドカードには拡張しません。`_MACOSX`/`__MACOSX` という名前の通常ファイルは入力に残ります。明示選択して除外されたディレクトリの子孫を、重複選択によって再追加することはありません。選択または検出されたリンク、再解析ポイント、特殊オブジェクトには既存の no-follow 拒否が適用され、フィルタリングによって読み取り権限は生まれません。

フィルタリングはこのアーカイブの入力にのみ適用し、ホスト上の元データは削除も変更もせず、既存アーカイブのレコードも掃除しません。メタデータ除外だけで空になったディレクトリとその空の祖先は書き込みません。本当に空のディレクトリと 0 バイトの通常ファイルは保持します。有効なエントリーが残らない場合はエンコードや競合確認の前に `empty_input` で失敗します。既存の結果ウィンドウには「macOS のメタデータを除外した結果、アーカイブに含めるファイルやフォルダーがありません。」と表示します。新しいアーカイブは公開せず、既存アーカイブも変更しません。選択の要約は制限付きメタデータプレビューのままで、最終的な有効内容は GUI の再帰走査ではなくバックグラウンドタスクのスキャンが決定します。

固定した構成と保存前の再検証には同じフィルタリングを使います。メタデータの内容や有無の変更では有効な入力を失敗させませんが、通常エントリーや枝刈りされたディレクトリの通常の子の変更は引き続きソース変更になります。スキャン制限は最終的に枝刈りされる通常ディレクトリにも適用し、フィルタリングでエントリーや名前の制限を回避できません。展開、一時的なオープン、内部移動、macOS のファイルプロミス公開には新規入力のフィルターを適用しません。通常の `InputTree::scan` はすべての内容を保持します。

## フォーマットインターフェースと検証

エンコードインターフェースは Qt とファイルパスから独立しています。ホストは順序付きの不変エントリー一覧と、順序番号で開く読み取り専用ストリームを提供します。フォーマット層はホストのストリームに書き込み、実際に処理したバイトを報告します。ZIP は独立した Rust レコードライターと共有 Deflate バックエンドを使い、固定 UTF-8 名と通常ファイル・ディレクトリ権限を使用し、特権ビットは付けません。大きなエントリーと中央ディレクトリには自動的に ZIP64 を使います。ソースサイズは固定値と一致しなければならず、失敗した準備ストリームは公開できません。

データと圧縮ストリームの完了および中央ディレクトリの書き込み後、ホストは準備された ZIP を再スキャンし、すべてのエントリーをデコードしてヘッダー、サイズ、CRC、ストリーム終端を検査します。エントリーの名前、種類とサイズは固定した入力ツリーと一致しなければなりません。アーカイブ全体の保存は検証とソース再検証の後にのみ許可されます。ディレクトリの一覧表示だけではアーカイブの整合性は証明されません。読み取り、圧縮、書き込み、検証はバックグラウンドの重いタスク用スレッドで実行し、定期的にキャンセルを確認します。

## 準備、競合とアーカイブ全体の保存

M3 で検証されたディレクトリ認可、同一ボリューム上の非公開準備領域、ファイル全体のコミット機構を使います。名前競合は既定で確認し、新しい名前または確認済みの通常ファイルの置換を許可します。ディレクトリ、リンク、特殊オブジェクト、入力に含まれるファイル識別情報は上書きしません。競合判断はタスクと確認 ID に結び付け、コミット前に既存対象を再確認します。必要な機構がないファイルシステムでは、コピーと削除で原子的保存を模倣せず失敗します。

macOS の作成出力は [M3 の拡張 ACL 境界](zip-safe-extraction.md#macos-扩展-acl-控制)を再利用し、外部への変更権限を与えない拒否・読み取り専用 ACL を許容しつつ、外部の実効または継承専用の変更権限を拒否します。出力先ルート、準備ディレクトリ、新しい親、既存出力を共有ルールで確認します。ユーザー ACL を書き換えず、既存の読み取り専用共有アカウントから内容を隠すとも約束しません。

分割しない場合、作成タスクは一つの ZIP を全体として保存します。検証や保存前のキャンセルは既知の準備ファイルを削除し、既存アーカイブを保護します。書き込み済みの入力エントリーを保存済みファイルとして数えることはできません。キャンセルと最終コミットは既存のゲートを共有します。コミット許可前はキャンセルが勝ち、許可後はコミット全体の結果が優先されます。コミット成功後のキャンセルは成功をキャンセル済みに変えません。クリーンアップに失敗した場合は復旧可能な資料を警告付きで保持し、見知らぬ準備ディレクトリを削除しません。

## タスクとインターフェース

作成と展開は制限付きバックグラウンドタスクのチャネル、制御と終了機構を共有します。タスクスナップショットは作成と展開、合計が既知かどうかを区別します。スキャン中は合計不明を表示し、完了後は固定したファイル数とサイズを使います。書き込み中は実際の入力読み取り、出力書き込み、現在のファイルを表示します。検証は別に示し、検証バイトを入力読み取りに再計上しません。

作成ウィンドウは高忠実度原稿と HTML のレイアウトに従い、パス欄、組み込みドロップダウン、チェックボックス、ボタン、フッターを再利用します。ファイル追加、ディレクトリ追加、削除、名前、出力先、Store/Deflate、レベル、完了結果のオープンを操作できます。レベルは 0 が無圧縮、1 が高速、2 が通常、3 が最大で、既定は 2、それぞれ Store/Deflate 1/6/9 に対応します。別個のアルゴリズムコントロールはありません。分割ボリュームとパスワードは実際の作成パラメーターです。TAR/TAR.GZ は [WP-11](tar-gzip.md) の安全な作成フローを再利用し、フォーマット固有の能力はその契約で制御します。タスクウィンドウは修正済みの通常密度を使います。ウィンドウを閉じてもタスクは続き、ステータスバーから再表示、キャンセル、競合解決ができます。

## 選択要約と共有コントロール

通常ファイルを選択した後、既存の Rust メタデータワーカーが現在のファイル長を読み取り、GUI はディスクの読み取りやディレクトリの再帰走査を行いません。InspectInputs は最大 256 パスを受け付け、固定した入力順で返し、サイズを 10 進バイト文字列としてブリッジします。symlink_metadata は選択された末端リンクをたどりません。要約は 10 進 MB を使います。0 バイトファイルのサイズは既知ですが、ディレクトリと失敗はゼロではなく不明です。256 件を超える場合は未確認項目の説明を残し、実際の作成には既存の制限が引き続き適用されます。素早い編集は最新のパス集合にまとめ、古い結果で新しい選択を置き換えません。対象検査が優先され、通常のクエリーは既存のキャンセル機構を使います。要約は事前認可ではなく、タスク開始後に入力ツリーを再構築します。

対象検査と入力要約はバックグラウンド準備です。追加・削除コントロールの有効な外観を変更せず、ウェルカムページに検査中のヒントを公開しません。実際のリクエストは引き続き直列で、現在のパスの作成検査が成功した場合にのみ作成を有効にします。展開は独立した検査状態を持ち、同じパスの作成検査では代用できません。[展開契約](zip-safe-extraction.md)を参照してください。

6 種類の操作ウィンドウはフッターボタンを共有し、フィールド、本文の操作、円形の削除、セグメントグループの選択肢は対応する役割コンポーネントを再利用します。外観と文字サイズは layout-scale.json から生成し、各ウィンドウで上書きしません。実際の要約、コントロールの測定値とスクリーンショットは[検証方法](../../../developers/qa/README.md)に従い build/ または CI アーティファクトに保存します。

## 受け入れ

メタデータのルートエントリー、入れ子のディレクトリ、混合選択、複数階層のメタデータのみのディレクトリ、本当に空のディレクトリ、暗号化と番号付きボリュームを対象とし、フィルタリング後に何も残らない場合は新たな出力がなく古い出力が保持されることを確認します。実際の Store/Deflate、Unicode 名、空ファイルと空ディレクトリ、書き込み、再オープン、展開の相互運用性を確認し、Python zipfile で内容、CRC、ディレクトリを独立して検証します。ソース変更、名前衝突、リンクと特殊オブジェクト、入力ツリー内の出力、明示選択またはディレクトリで検出された元の出力先バイトの収録、親パスと大文字小文字・Unicode の別名、別ディレクトリの同名入力、古い対象だけを選んだ場合の通常の名前変更、入力識別情報による上書き保護、検証失敗、競合の変化、古いアーカイブを保護するキャンセルを確認します。コア、ブリッジと Qt をビルドし、3 プラットフォームのバックグラウンドのライフサイクルと、通常密度および高 DPR での実際のキャプチャーを確認します。実際の入力サイズ、所要時間、リソースと検証コストを記録し、レベルだけから圧縮率を推測しません。

## AES-256 による内容の暗号化

「パスワードを入力」が有効なとき、パスワードは空にできず UTF-8 で 1〜128 バイトです。先頭や末尾の空白は削除せず、制御文字と不正な Unicode は拒否します。独立した WinZip AE-2 AES-256 ラッピング、OS のランダムソルト、許可済みの汎用 AES/PBKDF2/HMAC ライブラリを使います。暗号プリミティブを独自実装せず ZipCrypto にフォールバックしません。空ファイルを含むすべての通常ファイルを暗号化し、CRC フィールドをゼロ、認証コードを最後に書きます。通常のディレクトリレコードとファイル名は見えるままであり、ファイル名の暗号化を主張しません。パラメーターは[自前フォーマット契約](../../engineering/independent-rust-codecs.md)を参照してください。

ソースのエンコードインターフェースはパスワードを借用するだけで、ファイルパスやコミットの権限を持ちません。Rust のパスワードコンテナーは Debug で常に `[REDACTED]` を表示し、スコープ終了時にゼロ化します。キュー中のキャンセル、拒否、終了時もゼロ化されます。パスワードはスナップショット、ログ、設定、コマンドライン、復旧ログに入りません。Qt/HTML のパスワード欄は閉じる、キャンセル、送信時に消去します。Qt/ブラウザーやシステムメモリーに過去に作られたコピーをすべて消去できる保証はなく、Rust コンテナーのゼロ化はプロセス全体の安全な消去ではありません。

書き込み後の検証は各エントリーを制限付き破棄シンクへ復号し、EOF まで読んで認証とストリーム終端を確認し、固定した入力名、種類とサイズを検査します。誤ったパスワード、破損やキャンセルでは公開しません。独立した 7-Zip のデコードは相互運用性のゲートです。対応する AES-256 の結果は通常の ZIP と同様にアプリ内で自動的に開き、実際のパスワード付き展開へ進めます。番号付きボリュームは最初の部分をアプリ内で自動的に開きます。どちらもシステムのフォルダーを自動的に開きません。

## 分割ボリュームのパラメーターと公開

ドロップダウンの選択肢は、分割なし、3MB、4MB、5MB、10MB、20MB、25MB（Gmail）、100MB、300MB、650MB（CD）、700MB（CD）、4GB（FAT32）、4.7GB（DVE）、カスタムです。MB/GB は 10 進バイトです。カスタムでは共通ドロップダウンが bytes、KB、MB、GB 単位の正の整数入力になります。空、ゼロ、数値以外、24 GiB 超は無効です。最大 1,024 ボリュームで、実際の圧縮出力がボリューム数の制限を超えた場合は公開しません。

バイト分割の名前は `.zip.001`、`.zip.002` などで、最後のボリュームは小さくなることがあります。これは 7-Zip と互換の番号付き分割であり、複数ディスクヘッダーの `.z01` ではありません。まず完全な ZIP を仕上げて検証し、固定 64 KiB バッファーで非公開ファイルへ分割し、各ボリュームを同期して閉じます。メモリーと開いた通常ファイルの数はボリューム数に比例して増加しません。準備領域には完全な ZIP と各ボリュームの両方が必要になる場合があります。完全な ZIP 出力は 24 GiB が上限で、ボリュームのコピーにも最大同量が必要なため、最悪の場合の準備領域は約 48 GiB です。タスクの書き込み数は分割コピーをアーカイブサイズとして二重計上しません。

分割作成はユーザーが選んだ古いボリューム、基本 `.zip`、`.zip.1025` などの通常入力を保持し、同じ macOS メタデータ除外を適用し、識別情報が一致する非公開準備ディレクトリを除外します。既存の出力ボリュームは最終保存時にグループ全体の競合名前変更またはキャンセルを使い、古いボリュームが入力に含まれるという理由だけで早期失敗しません。古いボリュームや入力ファイルの識別情報は上書きしません。

グループ内のすべての出力先を事前確認します。古いボリュームがある場合はグループ全体の名前変更またはキャンセルを提供し、上書きは無効です。コミット許可を得た後、各ボリュームを置換なしで個別に公開します。複数ファイルには共通の原子的可視化点がないため、複数ファイルの原子的トランザクションを主張しません。後続の失敗では、このタスクが公開し識別情報がまだ一致するボリュームだけをロールバックします。同時に作られた古いファイルは変更しません。ロールバックに失敗した場合は復旧警告と不確実な結果を明示します。コミット許可前はキャンセルが勝ち、その後は部分的なボリューム集合を成功と偽装せず、グループ全体のコミットまたはロールバック結果に従います。

## 結果レコードとインターフェース

結果ウィンドウは[結果デザインパラメーター](../../../specs/visual/result-reference.json)に従い、タイトル、3 列の統計、未完了カード、出力先を保持します。展開された詳細には補助原稿と共有アイコンを使います。本文はスクロールし、フッターは固定します。コントロールの論理寸法は DPR やブラウザーのズームに影響されません。

完了、明示的なスキップ、失敗となった実ファイルごとに状態を記録し、進行率から成功を推測しません。スナップショットは最新 128 項目を保持する共有の制限付きレコード一覧を使い、各名前は最大 1,024 UTF-8 バイト、さらに省略数を保持します。統計は常に全ファイルを対象とします。作成レコードは実際に公開したアーカイブやボリュームを表し、失敗時は読み取った入力を保存済みとして数えません。レコードは現在のメモリー内タスクにのみ存在し、既定では起動をまたいで保存されません。

対応アーカイブの作成後、タスク ID に対する最初の成功した終端状態で、Qt は最終コミット済みパスを直列オープンキューに入れます。現在の読み取りや受付が終わった後、アプリ内で自動的に開きます。失敗、キャンセル、重複した終端状態では開きません。ユーザーが同じファイルを明示的に開いた場合、Qt の正規パスをネイティブ区切りで正規化して比較し、Windows では大文字小文字を区別せず、保留中の自動オープン意図を消費します。この比較は UI 意図の重複排除だけを行い、出力権限を与えません。重複排除は別のオープンが新規セッションや展開の意図を無効化するのを防ぎます。番号付きボリュームも最初の部分を開き、[分割ボリュームホスト](archive-opening.md)が完全な集合を検証して読み取り、欠落を明示的に報告します。結果ウィンドウは実際の出力ファイルとボリューム数を保持し、外部リーダーを必要としません。

完了時の動作は 2026-10-16 に改訂されました。作成時にシステムのファイルマネージャーを自動起動せず、作成ウィンドウからディレクトリ自動オープンのオプションを削除しています。古い startCreation の openAfter パラメーターは無視します。タスクの受付と終端経路の双方で、作成タスクがシステムディレクトリを自動的に開くことを禁止します。成功結果は既存の暗号化・番号付き読み取りを使い、アプリ内オープンキューへ進みます。結果統計のラベルは「保存済み」です。[UI 契約](../ux/welcome-opening.md)を参照してください。

[システムコンテキストメニュー](shell-actions.md)からの作成タスクは別の完了ポリシーを持ちます。成功結果はアプリ内自動オープンキューに入りません。単一作成と複数作成はそれぞれ実際の独立した結果を表示し、ユーザーが結果のディレクトリ操作を明示的にクリックした場合にのみシステムのファイルマネージャーを呼び出します。

## ISO と専用 SFX のプロファイル

[ISO9660/Joliet 作成](iso-creation.md)と [Windows ZIP SFX 作成](sfx-creation.md)は、この入力ツリー、出力認可、キャンセル、競合、最終公開の契約を再利用します。それぞれのより狭い名前、サイズ、方式、プラットフォームの制限を公開前に適用します。SFX のラッピングは作成中に実行ファイルを起動しません。
