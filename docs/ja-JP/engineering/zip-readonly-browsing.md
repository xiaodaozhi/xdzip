# 読み取り専用 ZIP 閲覧の仕様

[English](../../engineering/zip-readonly-browsing.md) | [简体中文](../../zh-CN/engineering/zip-readonly-browsing.md) | [繁體中文](../../zh-TW/engineering/zip-readonly-browsing.md) | 日本語 | [한국어](../../ko-KR/engineering/zip-readonly-browsing.md) | [Français](../../fr-FR/engineering/zip-readonly-browsing.md) | [Deutsch](../../de-DE/engineering/zip-readonly-browsing.md) | [Español](../../es-ES/engineering/zip-readonly-browsing.md) | [Português (Brasil)](../../pt-BR/engineering/zip-readonly-browsing.md) | [Русский](../../ru-RU/engineering/zip-readonly-browsing.md)

ルート直下の項目、配下の検索、安定した物理識別子、フォルダー優先の並べ替えを定めます。ZIP の閲覧ではメタデータだけを読み取り、項目の内容のデコードや CRC の検証、ファイルの展開は行いません。大きな通常の ZIP では、非公開の[ディスク上のメタデータ索引](large-index.md)を使用できます。

現在の大きな通常 ZIP の索引とオンデマンドの Qt モデルについては、[大規模アーカイブの索引](large-index.md)を参照してください。このページには、当初の 100,000 項目の基準とクエリー識別子の要件を記録します。上限の拡張後も、エラー、キャンセル、識別子の回帰を確認します。

<a name="xdzip-browsing-scope-and-limits"></a>

## 閲覧の対象と上限

- ZIP/ZIP64 のメタデータは物理レコードで最大 100,000 件です。分割ボリュームは[分割ボリュームホスト](archive-opening.md)で変換してから読み取ります。コーデックは未変換のマルチディスクのメタデータを引き続き拒否します。
- 名前ごとに 4 KiB、元の名前の合計 16 MiB、デコードとエスケープ後の表示名の合計 16 MiB、総読み取り量 64 MiB、スキャンバッファー 256 KiB です。宣言された 64 ビットのサイズは正確な整数のまま保持します。
- ディレクトリー索引は最大 32,768 ノード、64 階層で、名前と接頭辞の合計は最大 4 MiB です。上限を超えたらナビゲーション索引全体を破棄し、制限された動作を説明します。不完全なツリーは表示しません。
- 直下の項目の索引とクエリー結果を再利用します。同じクエリーの転送バッチでフィルター処理や並べ替えを繰り返しません。名前は各バッチで別々に 64 KiB に制限します。UI はページ切り替えボタンなしで現在のディレクトリー全体を表示します。
- ページごとにセッション、クエリー ID、GUI の世代、スナップショットのリビジョン、オフセットを検証します。クエリーの変更時は従来の処理をキャンセルし、最新の要求にまとめます。古い応答は新しい結果を置き換えません。
- スキャン前後、クエリー時、事前確認時に、ソースの長さ、変更時刻、Unix のデバイスと inode、Windows のボリューム番号とファイルインデックスを確認します。`source_changed` が発生すると、Qt のクエリーと事前確認で無効になった一覧、選択、ディレクトリーツリー、詳細を消去します。開き直すと新しいセッションが作成されます。可能な範囲で変更を検出しますが、ファイルシステムのアトミックなスナップショットや安全な書き込みの権限は提供しません。

<a name="xdzip-acceptance-exit-criteria"></a>

## 受け入れ基準

実際に生成した 100,000 項目の ZIP64 で、スキャン、全結果の並べ替え、取得、ディレクトリー移動、Qt の全件表示、選択が完了することを確認します。すべてのバッチでクエリー識別子が一致します。壊れた ZIP64、分割ボリューム、名前、表示、読み取りの上限、キャンセル、古い応答、ソースの変更と置き換えを検証します。実際の所要時間、リソース、イベントキュー、デリゲート数を記録します。3 プラットフォームのビルドや Apple Silicon 用開発パッケージをオンデマンドで検証する場合は、実際の結果を個別に記録します。

CI はリポジトリーのワークフロー実行一覧を head_sha と実際のイベントで絞り込みます。通常のチェックはプッシュまたは PR で実行し、Foundation と Qt の全項目は必要に応じて手動で実行します。実行結果と未実行の範囲を関連する Issue に記録します。別のイベントで該当結果がなくても、対象チェックの状態は確定しません。
