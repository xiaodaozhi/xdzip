# 分割ボリュームの読み取りと一時的なオープン

[English](../../engineering/archive-opening.md) | [简体中文](../../zh-CN/engineering/archive-opening.md) | [繁體中文](../../zh-TW/engineering/archive-opening.md) | 日本語 | [한국어](../../ko-KR/engineering/archive-opening.md) | [Français](../../fr-FR/engineering/archive-opening.md) | [Deutsch](../../de-DE/engineering/archive-opening.md) | [Español](../../es-ES/engineering/archive-opening.md) | [Português (Brasil)](../../pt-BR/engineering/archive-opening.md) | [Русский](../../ru-RU/engineering/archive-opening.md)

デスクトップでのファイル選択、ファイルマネージャーからの要求、CLI は、同じ Rust のソースオープン規則を使います。ホストは許可されたボリューム集合を解決し、ソースの識別情報を記録して許可範囲のバイト列を調べます。選択されたバックエンドが、場合により[分離された形式ワーカー](native-codecs.md)を通して[閲覧用メタデータ](readonly-browser.md)を提供します。項目を明示的に開くと、関連付けられたアプリ用に検証済みの一時コピーが作成されます。アーカイブ全体を検証するには別途[整合性検査](archive-checking.md)を使います。

TAR らしいヘッダーが完全な構造検査に通らなかった場合、形式が未特定の入力と同じ候補順序と共通の読み取り上限で検査します。TAR ヘッダーも有効な自己解凍 ZIP も確認できなかった場合に限り、最後に単独の LZMA を試します。

<a name="xdzip-split-zip"></a>

Windows では、展開と一時的なファイルのオープン時に、元のアーカイブの Windows ゾーン情報（Mark of the Web）を保持します。分割アーカイブでは、許可されたすべてのボリュームのうち最も高いゾーンが適用されます。XDZip は公開前に非公開の一時ファイルへゾーンを書き込みます。出力先が必要なマークを保存できない場合、そのファイルは公開されません。

## 分割 ZIP

読み取り層は `name.zip.001`、`.002` のような連続する番号付きバイトストリームと、`name.z01`、`.z02`、最後の `name.zip` のような PKZIP ボリュームに対応します。どのボリュームからでも開けます。同じディレクトリ内に連番の名前で配置し、最大 1,024 ボリュームまでです。欠落ボリューム、リンク、特殊ファイルは拒否されます。拡張子は隣接するボリューム集合の探索にのみ使用します。実際のコンテナーはソースのバイト列から判定し、バックエンドが全体を走査します。

ZIP64 の従来のディスク番号が 0xFFFF の場合、隣接する locator の上限付き総ボリューム数から実際の集合を先に探索します。このプレースホルダーを 65,535 個の欠落ボリュームと誤認しません。この探索は終了レコードとディレクトリの完全な検証に代わるものではありません。

Rust ホストは各ボリュームの識別情報、長さ、更新時刻を保持します。論理入力はアーカイブ全体を結合せず、必要に応じてボリュームをまたいで読みます。PKZIP のディスク相対オフセットは単一ボリューム上の上限付き中央ディレクトリビューに変換されます。既存のコーデックは引き続きディレクトリ、ローカルヘッダー、CRC、パスワード認証、展開クォータを検査します。すべてのソースボリュームを使用のたびと確定前に再検証し、変化があればタスクを停止します。すべてのソースボリュームの識別情報は出力による上書きから保護されます。

PKZIP の正規化は受理済みの中央レコードだけを処理し、中央ディレクトリの電子署名終了レコードには対応しません。この拒否は署名検証の失敗を意味しません。通常の単一ボリュームアーカイブはそのレコードを範囲内で読み取れますが、暗号署名は検証せず、移動時に未知のメタデータを失ったり壊したりしないよう変更を拒否します。

受け入れ範囲には、番号付きボリューム、PKZIP、ZIP64、ボリュームをまたぐヘッダーとデータ、欠落または不連続なボリューム、ソースの置き換え、不正なディスク番号、中国語名、通常の単一ボリュームに対する回帰が含まれます。

<a name="xdzip-7z-and-rar-volumes"></a>

## 7z と RAR のボリューム

番号付き 7z ボリュームは name.7z.001、.002 のような連続バイトストリームです。RAR は name.partN.rar または name.rar、name.r00 のような旧形式名を使い、分離された Rust RAR リーダーへ渡す際に各物理ボリュームの境界を維持します。どちらも既存の任意の一部から同じディレクトリ内の集合を特定できます。上限は 1,024 ボリューム、ディレクトリ探索 100,000 エントリーです。欠落ボリューム、名前の番号の衝突、リンク、再解析ポイントは明示的に拒否します。

Rust は各ボリュームのハンドルの識別情報、長さ、タイムスタンプを保持し、ReadSource::volume_lengths() でネイティブアダプターに許可範囲を伝えます。ネイティブプロセスは許可された範囲の読み取りだけをホストに要求でき、ボリューム切り替え時にアーカイブから任意のホストパスを受け入れません。すべてのボリュームはソースの再検証と出力による上書き防止の対象です。最初または後続のどのボリュームが変化してもタスクを停止します。

7z と RAR のファイル名暗号化では、オープン時にパスワードが必要なことがあります。通常の Open が password_required を返した場合、インデックスは公開されません。Qt は既存のパスワードウィンドウを再利用し、最初に選択されたファイルと上限付きの秘密情報を OpenWithPassword で再送します。検証値が間違っている場合は wrong_password を返します。成功後、パスワードを保持するのはセッションとその受理済みタスクだけです。セッション終了時にそのコピーを解放し、設定や復旧記録には書き込みません。

<a name="xdzip-cab-volumes"></a>

## CAB のボリューム

CAB のボリューム名はヘッダーから得られ、有効な任意のファイル名を使えます。番号付きボリュームのバイト連結規則は適用されません。次のボリュームへの参照は一つずつ進みます。論理的な前ボリュームへの参照は直前ではなく、継続ファイルが最初に現れたさらに前のボリュームを指す場合があります。既存のサンプルには直前を指すものもあります。選択されたボリュームから Rust は前への論理参照を逆向きにたどり、その後、同じディレクトリ内の完全な集合を順方向に探索します。集合の識別情報、連続した順序、各識別情報を検証してから、各ボリュームの長さと元の名前を固定します。デコーダーはすべてのファイル断片を検証し、隣接しない前ボリュームは継続ファイルが実際に始まったボリュームでなければなりません。上限は 1,024 ボリューム、同一ディレクトリの探索 100,000 エントリーです。欠落、不正、循環、識別情報の重複、絶対パス、ディレクトリ区切り、親ディレクトリへの脱出、リンク、再解析ポイントを拒否します。開いた部分集合を完全なアーカイブとして公開しません。

ワーカーのボリューム変更コールバックは許可された集合内の名前だけを選べます。各ボリュームは独自の上限付きストリームを提供します。タスクとファイル確定の前のソース再検証、および出力による上書き防止には、すべてのボリュームが参加します。ネイティブハンドラーの警告やボリューム欠落の結果を成功したインデックスに変換することはできません。単一・分割 CAB は読み取り専用です。

<a name="xdzip-double-clicking-regular-files"></a>

## 通常ファイルのダブルクリック

ディレクトリをダブルクリックすると従来どおりその中に入ります。通常ファイルでは、その物理項目だけを含むバックグラウンド展開タスクを送り、ユーザーのプライベートキャッシュ内のランダム名のディレクトリに出力します。この経路ではリンクや特殊オブジェクトを開けません。パスワード、CRC、認証、キャンセル、およびアプリケーション全体での重いタスクの逐次受け入れは引き続き適用され、展開先の選択は不要です。

出力に成功すると、コマンドインタープリターを介さずローカルファイル URL でシステムの関連付けを呼び出します。システムがオープン要求を受理した場合だけ、対応する進捗ウィンドウを自動的に隠します。展開失敗、キャンセル、システムによる拒否の場合は、読み取れるエラーとともに表示を維持します。システムの受理は外部アプリが読み終えたことを意味しないため、要求送信時に一時ファイルを削除できません。

一時ディレクトリには予測不能な 128 ビットのランダム名を使い、出力データと識別マーカーを分離します。出力先には現在のユーザーと信頼されたシステム主体のみがアクセスできます。Windows では、この操作のためだけに新規作成した空ディレクトリに限り、保持中のハンドルを通じて保護された DACL を設定し、平文を書き込む前に再検査します。ユーザーが選んだディレクトリの共有権限は変更しません。POSIX は 0700 を使い、macOS の継承 ACL を確認します。権限を保証できない場合は出力を拒否します。[Win32 DACL API](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-setsecurityinfo)を参照してください。

ロックが保持されている間はクリーンアップしません。完了した出力は少なくとも 7 日間保持し、その後の一時オープン時に期限切れでロックされていないディレクトリを削除します。キャッシュは最大 256 エントリーを保持し、上限では明示的に拒否します。各走査は 4,096 エントリーに制限されます。クリーンアップはプライベート権限、マーカー、名前を検証し、リンクをたどりません。一時コピーの変更はアーカイブに書き戻しません。

一時ファイルのクリーンアップはアプリが作成したプライベートキャッシュに限られ、ユーザーの展開ディレクトリを走査または削除しません。受け入れ範囲には成功時の自動非表示、失敗時のウィンドウ維持、キャンセル、パスワード再試行、重複ファイル名、Unicode と特殊文字、ページを閉じた後のタスク振り分け、一時ディレクトリの安全性、終了時クリーンアップ方針が含まれます。

読み取り専用の [Brotli/TAR.BR](brotli-streams.md) の受け入れでは、行を公開する前にヘッダーなし候補を完全に検証し、Brotli/LZMA 候補の読み取り台帳を共有します。強いソースと有効な TAR/ZIP の検出を優先し、デコード後に破損した TAR を通常ストリームに格下げしません。

[LHA/LZH](lha-containers.md) の候補は公開前にヘッダーと名前の完全な上限付き検証を必要とし、ゼロ一つだけの空アーカイブも対象です。弱い LHA、Brotli、LZMA 候補は実際の読み取り台帳を共有します。強く有効なコンテナーの検出が優先され、完全な LHA 受け入れにより無効な生 TAR マーカーの曖昧さを解消できます。パスワード、分割、修復のプロファイルは受け入れません。

[PMA](pma-streams.md) は同じ弱い検査の共有台帳と完全なメタデータ受け入れを使い、正確なゼロ終端と任意の上限付き CP/M 埋め草に対応します。レベル 0 の PM0/PM1/PM2 データをサポートし、未知の方式は表示されますが未対応です。埋め草付きの空 CP/M コンテナーは PMA と判定し、区別できない 1 バイトのゼロ終端は従来の LZH 選択を維持します。作成、パスワード、分割、変更、修復のプロファイルは受け入れません。
