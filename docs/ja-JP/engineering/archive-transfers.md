# ファイルリストからの開く操作、双方向ドラッグ＆ドロップ、アーカイブの変更

[English](../../engineering/archive-transfers.md) | [简体中文](../../zh-CN/engineering/archive-transfers.md) | [繁體中文](../../zh-TW/engineering/archive-transfers.md) | 日本語

コンテキストメニューの「開く」は複数選択を変更せず、右クリックした項目に対して実行され、ダブルクリックと Enter の入口を再利用します。ディレクトリには移動し、通常ファイルには[一時的に開く](archive-opening.md)ためのプライベートキャッシュ、パスワード、関連アプリケーションの規則を適用します。セッションや問い合わせが変わるとメニューを閉じ、実行時にも安定した項目の識別情報を検証します。

## 外部へのドラッグ

リストまたはグリッドのドラッグがシステムのしきい値に達したら、選択とアーカイブのディレクトリを固定します。未選択項目をドラッグすると先にその項目だけを選択し、選択済み項目をドラッグすると選択を保持します。ディレクトリの子孫を展開し、親子の重複選択を除き、現在のディレクトリ以下の相対階層と空ディレクトリを保持し、アーカイブの内容を削除しません。リンクはドラッグで公開しません。マニフェストは 100,000 項目と名前／構造 4 MiB に制限され、安全な展開のバイト数、パス、パスワード、クォータ制約も適用されます。

外部ドラッグ用マニフェストの作成は転送メタデータの準備であり、ディレクトリの読み込みではありません。準備とネイティブへの引き渡し中は確定済みのリスト／グリッド、選択、ディレクトリを保持し、メインページの「読み込み中」オーバーレイを表示しません。要求は処理中とキャンセルの意味を維持します。実際の開く操作、ディレクトリの問い合わせ、アーカイブの変更にはそれぞれの待機表示を引き続き使います。

Windows は OLE の `IDataObject` FILEDESCRIPTOR/FILECONTENTS と非同期機能を通じてコンテンツを提供します。バックグラウンド準備は送り先が受け入れた後に始まり、受信側はプライベートコピーの検証完了後にだけ読み取れます。同期受信側によって GUI がタスクを待つことはできず、未対応の送り先は明示的に失敗します。最終位置と名前の衝突は Explorer が決定します。FILEDESCRIPTORW のパスは UTF-16 単位で 260 未満でなければなりません。コンテンツストリームは読み取り専用で、キャンセル後は後続データの提供を停止します。終了時は非同期受信側が終わるまでネイティブ転送を待ちます。

macOS は NSFilePromiseProvider により最上位のファイルまたはディレクトリのプロミスを Finder に提供します。プライベートコピーの準備後、Finder のローカルファイル URL は別の Rust PublishExport タスクで認可されます。ファイルは個別に準備領域へ置き、ソースを検証し、既存の通常ファイルを上書きせず公開します。POSIX の通常ファイルは安全な展開の `0600 | (mode & 0155)` 権限方針を維持し、実行ビットを残しつつ特権ビットと外部書き込みビットを除きます。ディレクトリの結合と部分的な完了は安全な展開の出力境界に従い、転送全体のロールバックは約束しません。ファイルプロミスのコールバックはバックグラウンドで待ち、ファイル書き込みは常に制限付きタスクキューと終了バリアを通ります。

Linux の対応基準は X11 を使う Ubuntu 24.04 x86_64 です。先にプライベートコピーを準備し、準備完了時もマウスが押されていればファイル URL のドラッグ＆ドロップを開始します。先に放された場合は再ドラッグを依頼し、コピーを再利用します。最終的なコピーと名前の衝突はファイルマネージャーが決定します。アプリケーションは最終送り先や保存成功を推測しません。Wayland はこの対応範囲外です。

エクスポートと一時的なオープンのキャッシュは分離します。ランダムなディレクトリ、識別マーカー、使用中ロックを使い、準備失敗時は URL を公開しません。項目を 7 日間保持し、後で制限付きのクリーンアップを行います。受信側がまだ必要とする可能性がある場合、ドラッグの戻り時にファイルを削除しません。ページを閉じてもタスクのコントローラーを保持します。明示的な終了は準備をキャンセルし、Rust ワーカーとネイティブ受信側の完了を待ちます。

Linux では、グループ書き込み可能な umask で作成されたディレクトリを含め、アプリ所有のキャッシュルートを使用前に現在のユーザーだけに制限します。リンクされたキャッシュルート、他の所有者のディレクトリ、権限変更の失敗は準備を停止します。

外部ドラッグの準備では通常の展開結果ウィンドウを開きません。エクスポートとコピーのタスクは、ドラッグ後に Explorer、Finder、送り先ディレクトリを自動で開きません。通常の展開の「完了時にフォルダーを開く」はその明示的な展開要求だけに属し、後続のエクスポートや一時オープンに引き継ぎません。結果ウィンドウでユーザーが明示的に「開く」を選んだ場合は既存の動作を維持します。

X11 では、準備済みコピーをネイティブドラッグに渡す前に実際の左ボタン状態を確認します。準備中にボタンが放されていれば新しいドラッグを開始しません。ネイティブドラッグオブジェクトの寿命は Qt が管理します。受信アプリがドラッグループの戻り後にデータを要求する場合があるため、その時点でアプリケーションはオブジェクトを破棄してはなりません。

## 外部からのドロップと確認

既存の CAB、ISO、UDF、RAR アーカイブは追加、置換、内部移動、名前変更、削除に対応しません。インターフェースと Rust の実行入口の両方でこの制限を強制します。対応するレコードは同じ保護された読み取り経路で外部ドラッグ、一時オープン、展開が可能です。[新しい ISO イメージの作成](iso-creation.md)は別の操作です。

開いているアーカイブのファイルリスト本体は実在するローカルファイルとディレクトリをコピーのみで受け付けます。ドロップしたアーカイブファイルは通常の入力として追加し、開始ページへのドロップは引き続き開く操作になります。リモート URL、仮想添付、リンク、特殊オブジェクトは拒否します。ドロップ時にセッション、現在のディレクトリ、入力を固定し、検索ページでは先にディレクトリへ入る必要があります。

追加前に Rust は[作成時の入力フィルター](zip-creation.md#macos-元数据输入过滤)を適用し、すべての階層の `.DS_Store` ファイルと `__MACOSX`／`_MACOSX` ディレクトリを除外します。有効な項目が残らなければ結果ウィンドウに明確な失敗を表示し、元アーカイブのバイトは変えません。ホストの元ファイルやアーカイブ内の既存メタデータを削除しません。

UpdateWindow は作成画面のデザインに従い、アイコン付きタイトルと、追加ファイル、送り先、オプションの三つのカードを備えます。ファイル領域は CreateWindow と ArchiveInputPanel を共有します。ユーザーはファイル／ディレクトリの選択を続け、重複を除き、マウス、キーボード、アクセシビリティで項目を削除できます。通常ファイルのサイズは最大 256 項目のバックグラウンド集計を再利用し、ディレクトリの合計は不明です。集計はプレビューでありタスク入力の固定に代わりません。ウィンドウの下書きは独立し、非表示のウィンドウがメタデータ要求を引き継ぎません。対象アーカイブと内部ディレクトリは読み取り専用で、ドロップ時に固定したセッションとディレクトリから取得し、確認時に安定した識別情報を再検証します。確認、スキップ、名前変更、置換の方針を提供し、既定は確認です。同名ディレクトリは元の表記で結合し、ファイルとディレクトリの衝突は拒否します。置換はアーカイブ内の通常ファイルに適用し、ホストの入力ファイルを上書きする権限を与えません。確認前にアーカイブは変更されません。外観は作成ウィンドウと同じ論理幅 491、三つのカード、共有コントロールを使います。[独立したデザイン](../../../design/hifi/sources/archive-add.html)を参照してください。

アーカイブ編集が受け付けられた後、メインページのキャンセル操作は元セッションの実際のタスク識別情報を使ってタスクをキャンセルします。名前の衝突プロンプトが閉じてもタスクが判断待ちの場合も同様です。既に完了したタスク登録要求だけをキャンセルしてはなりません。キャンセル後もタスクの終端状態、クリーンアップ、元アーカイブの再オープンを待ってからディレクトリ問い合わせと選択を復元し、古い項目識別情報の固定を早期に解除しません。

変更中は確定済みのファイルページを表示し続けますが、古い問い合わせと選択の識別情報は操作できません。ページの待機オーバーレイは更新完了まで実際の追加、移動、名前変更または削除コマンドを示します。ランタイムがキャンセルを受け付けたら直ちに表示し、衝突とパスワードのプロンプトは判断を受け付けなくなり、進行ウィンドウは実際の終端状態を追いながらキャンセルを表示します。衝突ウィンドウはタスクとプロンプトのトークンに結び付きます。ユーザーが閉じたプロンプトは別のタスク更新で自動再表示せず、タスク入口から明示的に再表示できます。タスク変更、プロンプトトークンの交換、終端状態、終了時には古いプロンプトを閉じ、ボタンが古い判断を新しいタスクへ送らないようにします。

## 内部ドラッグ＆ドロップによる移動

ファイルリストまたはグリッドのドラッグがシステムのしきい値に達したら、まず内部移動として扱い、現在のセッション、問い合わせ世代、選択バージョン、元のアーカイブディレクトリ、安定した項目 ID を固定します。未選択項目をドラッグすると先にその項目だけを選択し、選択済み項目では複数選択を保持します。元項目は元の位置に描画したままにします。送り先フォルダーはリスト、グリッド、ディレクトリツリーで既存の選択色を使います。操作案内はツールチップの文字サイズ、最大幅、余白を再利用し、最大四行で現在のクライアント領域内に収めます。これは即時のドラッグ状態であり、通常のホバーツールチップのタイマーではありません。

現在のディレクトリ内のフォルダーと左ツリーでインデックスされた任意のディレクトリは、サブディレクトリからルートへの移動を含め、ドロップを受け付けられます。このセッションのプライベートドラッグ識別情報だけを受け付け、外部 URL や別セッションの項目を移動と解釈しません。リスト、グリッド、左ツリーは同じ送り先制限を使用します。選択されたフォルダー、その任意の深さの子孫、元ディレクトリを送り先にすることはできません。対象フォルダーだけでなく混合選択全体を拒否します。検索ページ、古い選択、現在変更できないアーカイブも拒否します。拒否された送り先は即時の説明とドロップ不可状態を保持し、放してもタスクを開始しません。暗号化、分割ボリューム、その組み合わせにはそれぞれ異なる説明があります。外部からの追加拒否もホバー時に表示し、実際のドロップを拒否します。

有効な送り先で放すと独立した移動タスクを直ちに開始し、進行、名前衝突、結果ウィンドウを再利用します。通常ファイルの衝突は既定で確認し、スキップ、新しい名前を使う、置換と、後続の衝突への適用をサポートします。フォルダーは結合し、ファイル／フォルダーの種類衝突は失敗します。スキップした元ファイルは元の位置に残り、必要な明示的な元ディレクトリを保持します。完全に移動した元項目は消え、空および暗黙的ディレクトリも移動できます。現在の暗黙的な元ディレクトリが空になるよう移動する場合は、閲覧位置を保つ空ディレクトリレコードを追加します。成功または失敗後は元アーカイブを開き直し、元ディレクトリとソート順を保持し、古い物理 ID の選択を消去します。編集の受付、実行、再オープン中はリストのスナップショットを保持し、ディレクトリ問い合わせを固定し、古い識別情報から閲覧を開始できないようにします。

MoveOptions は制限付きの元ディレクトリ、対象ディレクトリ、選択識別情報だけを保持し、ホストパスは持ちません。コアは直下の元項目を再解決し、循環、元の位置、古い識別情報を拒否します。移動と追加は名前空間、衝突判断、完全なコンテンツ検証、同一ボリュームでの原子的置換を共有します。ZIP は圧縮済みデータを変更せずコピーし、名前を書き直します。TAR は通常レコードのヘッダーとパス以外の対応 PAX 属性を保持し、パスを UTF-8 PAX で書き込み、GNU 長名を PAX に変換します。圧縮 TAR は外側のストリームを再構築します。安全に保持できない拡張は明示的に失敗します。コミット前の失敗やキャンセルは元アーカイブのバイトを保持します。

ポインターが元ウィンドウのクライアント領域を離れるか、元ウィンドウが非アクティブになったら、固定した選択を既存のプラットフォーム外部コピー処理へ渡し、内部ドラッグを終了します。システムの外部ドラッグに移行した後、アプリに戻されたエクスポートデータを内部移動や新しい入力として扱いません。これによりプライベートな準備済みコンテンツの再追加を防ぎ、プラットフォームの外部ドラッグ規則は変えません。

`Move`、`Update`、`EditEntries` コマンドは制限付きタスクキューを使用して現在のセッションを検証します。タスク受付時にコマンドスレッドはアーカイブのスナップショットを退役させます。コントローラーは終端状態と再オープンを待つ間、最後に描画したページを保持できます。ページの `edit_restriction` ビット 0 は暗号化、ビット 1 は分割ボリューム、ビット 2 は書き換え非対応の形式、ディスクインデックス ZIP、危険なレコード、未対応メソッドなどのその他の制限を示します。`update_allowed` はすべてのビットがクリアな場合にのみ true です。ランタイムはソース全体のスナップショットから可否を計算し、タスクは書き込み前に入力を引き続き検証します。

## アーカイブ内の名前変更と削除

項目のコンテキストメニューは内部移動と同じアーカイブ全体の編集要件を使用し、通常のディレクトリ表示で利用できます。右クリックはその行を含む選択を保持し、含まれなければクリックした行だけを選択します。名前変更には項目がちょうど一つ必要です。削除では一つの名前または選択項目数を確認し、フォルダーを再帰的に削除することを説明します。ダイアログは元のセッション、問い合わせ、ディレクトリ、選択に結び付き、変更があれば無効になります。ワーカーは不変の現在のアーカイブに対してセレクターを再解決し、選択された各ルートが指定ディレクトリの直下であることを確認します。

名前変更は移植可能な一つの名前構成要素を受け付け、選択項目とその子孫のパスを書き換えます。同じ項目の表記だけの変更は許可します。正規化された送り先名を持つ既存ファイル、明示的または暗黙的ディレクトリがある場合は失敗します。削除は選択したディレクトリ以下の全レコードと選択ファイルを一つのトランザクションで削除します。最後の子を削除した場合も現在のフォルダーを保持し、必要なら暗黙的フォルダーを空ディレクトリとして実体化します。空のルートは項目ゼロのアーカイブとして残ります。空に書き換えた TAR.GZ には固定の GZIP コメントを付け、一般的な `.gz` 名でも TAR として開けるようにします。[GZIP の認識](single-file-streams.md)

## 通常アーカイブの変更トランザクション

Update は[形式レジストリ](format-registry.md)の条件を満たす単一ファイルの ZIP/ZIPX、7z、レベル 2 の LHA/LZH、TAR、圧縮 TAR プロファイルに対応します。暗号化、分割ボリューム、リンク、特殊レコード、安全に保持できない名前は書き換えません。可否は現在のページだけでなくソース全体のスナップショットから決定します。タスクを受け付けたらメタデータセッションを解放し、古い項目 ID に新しい操作を受け付けません。タスクはソースハンドルと識別情報を保持します。

名前は[エンコード契約](filename-encoding.md)の固定結果を使います。解決済みの旧来名は書き換え時に明示的な UTF-8 で書き込み、アーカイブ名前空間と Unicode／大文字小文字の衝突を再確認します。ソースのバージョンとリンクをたどらない InputTree を固定した後、元アーカイブと同じボリュームのプライベート作業領域に完全な新アーカイブを作成します。独立した ZIP レコード層は元の圧縮データをコピーして許容されたメタデータを保持し、新規項目は Deflate 6 を使用します。保持する ZIP/ZIPX レコードは Store、Deflate、Deflate64、BZip2、LZMA、XZ を使えます。独立した Rust 7z バックエンドはアーカイブを再構築し、通常レベルの LZMA2 で内容を追加します。TAR は元のレコードグループを保持し、圧縮 TAR は外側のストリームを再エンコードします。LHA/LZH は条件を満たすレベル 2 メンバーの圧縮データをコピーし、変更名を UTF-8 で出力し、新しいファイルを LH5 でエンコードします。保持した ZIP、TAR、LHA、対応 7z レコードは元の物理順に処理し、新しい項目を末尾に追加します。7z の保持と再構築の境界は[独自仕様](../../engineering/independent-rust-codecs.md#7z读写规格)を参照してください。新アーカイブは項目の種類、サイズ、完全なデータを欠落、重複、異物混入なしで検証する必要があります。重複または曖昧なレコード、ZIP 自己解凍プレフィックス、書き換え不能な拡張は黙って捨てず明示的に失敗します。現在 TAR グローバル PAX レコードは書き換えません。圧縮 TAR の最後のレコードを削除するとき、単独ストリームの拡張子によって通常の圧縮ファイルとして再オープンされる場合はコミット前に失敗します。マーク付き TAR.GZ は既存の例外を使用します。

アーカイブ名前空間には暗黙的な親ディレクトリを含め、100,000 ノードに制限します。深いパスによる無制限のインデックスを防ぐため、名前と正規化インデックスは 16 MiB の予算を共有します。新アーカイブを再走査し、各ファイルを制限付きの検証先にデコードしてから、入力、元アーカイブ、送り先の識別情報を再検証します。元ファイルのバージョンに結び付いた ArchiveUpdate 権限だけが全体を置換でき、通常の作成／展開のソース保護は変わりません。元アーカイブを追加入力に使うことは明示的に拒否します。必要な原子的ファイルシステムプリミティブが利用できなければ、先に削除や切り詰めを行わず、コピー／削除で置換を模倣せずに失敗します。バージョン検査は最善の努力であり、同一アカウントによる悪意ある同時書き込みに対するコンテンツ CAS や停電時の耐久性を約束しません。

コミット前のキャンセルまたは失敗は元アーカイブのバイトを保持します。コミット許可の取得後は公開成功が優先され、クリーンアップ失敗は別に記録します。成功または失敗後は同じソースを開き直し、無効な物理項目の選択を消去します。タスクは update、move、rename、delete、export、export-copy の各種類を区別し、プライベートな準備をシステムコピーの成功とは扱いません。

7z の変更も同じ名前空間、衝突、ソース再検証、原子的置換の契約に従います。ソリッド内容はデコードして再構築する必要があります。再構築入力は明示的に制限されたバッファーを使用します。元と追加内容の合計はネイティブアダプターのキャッシュ上限 512 MiB を超えられず、バックエンドのプロセスメモリ予算 1 GiB も適用されます。上限超過は明示的にリソースエラーを返し、ディスクキャッシュ権限を与えず、元アーカイブを変更しません。成功した出力は通常圧縮と非ソリッド構造を使う場合があり、元の圧縮ストリーム、アルゴリズムの組み合わせ、ソリッドブロック、物理レコード順の維持は約束しません。暗号化された名前、暗号化された内容、任意の分割 7z ボリュームを持つアーカイブは、空の暗号化ディレクトリを含め変更を拒否します。

RAR は独立した読み取り専用 Rust バックエンドを使い、追加、置換、内部移動を提供しません。アーカイブ全体のその他の未対応レコードを示す `edit_restriction` ビットは常に設定され、現在のページに未対応項目がなくても回避できません。7z/RAR のリンクと特殊オブジェクトは出力しません。外部コピーと一時オープンは引き続き既存の事前検査と安全な出力タスクを使用します。

## 受け入れの境界

リストとグリッドの完全名ツールチップは、内部移動、ネイティブコピーの準備、実際のネイティブドラッグの間ずっと抑制し、古い静止タイマーをキャンセルします。内部／外部の引き渡しで元のツールチップを一時的にも再有効化しません。ジェスチャー状態は Windows では OLE の戻り、macOS ではネイティブのドラッグ終了コールバック、Qt の準備済みドラッグでは exec の戻りで終了します。非同期コピーは継続する場合があり、コピータスクの完了はマウスジェスチャーの終了ではありません。その後は新しいポインター位置を取得してから静止状態を再度 1,200 ms 待ち、キャッシュされた元のホバーでツールチップが復活しないようにします。

ドラッグプレビューは固定された元の名前、アイコン、選択数のみを表し、内容の読み取りや展開をせず、送り先への書き込み権限も与えません。内部プレビューは有効なドラッグトークンから値を取得します。ウィンドウを離れたら内部オーバーレイを消し、ネイティブコピーのフィードバックへ引き渡します。Windows の IDataObject は Shell イメージ用の制限付きでスレッドセーフなプライベート HGLOBAL 形式を保持し、別途、固有の DragContext ストリームへの COM 参照を内容の読み取りやコピーなしに保持します。GetData は独立した参照を返します。ファイル記述子、コンテンツストリーム、優先アクションを上書きしてはなりません。失敗しても既存の安全な出力とキャンセルの意味は変わりません。ネイティブ画像は Shell 用の非乗算済み BGRA を使い、ビットマップの所有権は初期化時に移ります。COM/GDI の準備に失敗した場合はシステムカーソルを維持します。スタイルは[ドラッグ仕様](../../../specs/visual/drag-preview.json)を参照してください。

コアの検証は三つの形式、現在のディレクトリ、元の内容と空ディレクトリ、衝突方針、ソース変更、保護された入力、キャンセルをカバーします。Qt は実際のコンテキストメニューの開く操作と追加確認、両言語、ライト／ダークテーマ、複数の文字サイズ、固定セッションをカバーします。Windows のネイティブプロトコルテストは非同期データオブジェクトと実際のコンテンツストリームを検証します。移動の回帰はリスト／グリッド、ディレクトリツリー、拒否された送り先、混合選択、ディレクトリ結合、メタデータ保持、境界の引き渡しをカバーし、三つの形式を Python リーダーで独立に再確認します。実際の Explorer、Finder、Ubuntu Files とデスクトップへのドロップは必要に応じて確認し、実行時に別途記録します。オフスクリーンやプロトコル受信側は未実行のデスクトップ操作の代わりにはなりません。段階の証拠は関連 issue とローカル／CI の成果物に記録します。
