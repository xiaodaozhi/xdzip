# 大規模アーカイブの索引とオンデマンド参照

[English](../../engineering/large-index.md) | [简体中文](../../zh-CN/engineering/large-index.md) | [繁體中文](../../zh-TW/engineering/large-index.md) | 日本語 | [한국어](../../ko-KR/engineering/large-index.md) | [Français](../../fr-FR/engineering/large-index.md) | [Deutsch](../../de-DE/engineering/large-index.md) | [Español](../../es-ES/engineering/large-index.md) | [Português (Brasil)](../../pt-BR/engineering/large-index.md) | [Русский](../../ru-RU/engineering/large-index.md)

通常の単一ファイル ZIP/ZIP64 に対するソースコードの機能上限は物理レコード 100 万件です。他の形式と分割ボリュームの経路は従来の 100,000 項目の受け入れ上限を維持します。形式名だけで、すべての組み合わせの上限が拡張されたとは限りません。ディレクトリー、重複名、要確認レコードはいずれも物理項目に数え、暗黙の移動用ディレクトリーは表示行だけを増やします。

<a name="xdzip-scanning-and-storage"></a>

## 走査と保存

ZIP は通常の ZIP パーサーでレコードを個別に走査します。最初にアーカイブ全体の旧来のエンコーディング名を上限付きでサンプリングし、同じ判定で二度目を走査します。二度の読み取りは合計最大 512 MiB、中央ディレクトリーは最大 256 MiB、生の名前の合計は最大 128 MiB、デコード名と表示名の合計も最大 128 MiB です。生またはデコード済みの各名前は引き続き 4 KiB 以下です。末尾の破損、キャンセル、ソースの変更は結果全体を失敗させ、部分的な索引は公開しません。

使用中のメタデータが 64 MiB に達するか項目が 100,000 件を超えると、レコードを個別に非公開ディスク保存へ移し、既存の名前とレコードを解放します。完全な索引を二つ同時に保持しません。物理位置表には最大 100 万個の u64 オフセットが入ります。ディスク上のメタデータは最大 512 MiB で、診断文字列にファイル名や内容を含めません。ディレクトリーツリーは最大 32,768 ノード、64 階層、名前の予算 4 MiB に制限されます。超過時はツリーを公開せず、ルート参照と物理検索は引き続き使用できます。

一時ファイルはホストの一時ディレクトリー配下のランダム名 `xdzip-index-*` に置き、現在のユーザーだけが読み書きできます。保持したディレクトリーと通常ファイルのハンドルで操作します。通常終了、クエリーの置換、失敗、キャンセル時には既知ファイルと、同一性を確認した空ディレクトリーを削除します。クラッシュの残留物は、ディレクトリーのランダムな識別情報に一致する 16 バイトのマーカーと排他的リースで識別します。後の作成時は上限付きで走査し、7 日より古く未使用の既知ファイルだけを削除します。リンク、識別情報の不一致、未知のオブジェクトは保持します。見知らぬ内容を再帰削除せず、起動をまたいで索引を復元または再利用しません。

Windows では新規ディレクトリーの所有者と変更権限に関する通常の検査を先に通過させ、その後で機密保存のため DACL を保護します。無関係な主体に継承された変更権限は、リースやメタデータファイルの書き込み前に拒否します。ランタイムは秘密性の低い場所へ黙って切り替えません。分離検証ではテストプロセスの `TMP` と `TEMP` だけを、現在のユーザー、SYSTEM、Administrators にのみ変更を許す ACL を持つ新しい所有ディレクトリーへ向けます。実際のユーザーディレクトリーの ACL を変更せず、権限検査を緩めません。割り当て、実際のディスク検索とマージ、稼働中のリース、既知ファイルの削除、無関係な変更権限の拒否をそれぞれ検証します。

<a name="xdzip-queries-and-selection"></a>

## クエリーと選択

検索と並べ替えは完全で不変の行順序を生成します。ソートキーはそれぞれ最大 8 MiB の非公開マージランに書き込み、最大 128 ラン、ソート用一時保存最大 512 MiB とします。最終クエリーは行トークンだけを保存し、名前全体をもう一度コピーしません。比較は元の整数、既存の名前と種類の規則、安定した物理的同一性を維持します。すべての並べ替えで明示的および暗黙のディレクトリーをファイルより先に置き、昇降順は各グループ内に適用します。不明なサイズは各ディレクトリーまたはファイルのグループ内で既知の値の後に置き、降順でも重複項目の同一性の順序を変えません。キャンセルは走査、ソートラン、マージの前後で確認し、比較器内の順序関係は変更しません。

ブリッジは一回につき最大 128 行と 64 KiB の名前を転送します。最大 1,024 行のクエリーは既存の全件確定方式を維持します。より大きな Qt モデルは論理行数全体を維持して表示位置だけを読み込み、常駐キャッシュは最大 1,024 行です。未読み込みの行は項目操作を送信できません。遅延ページはセッション、クエリー、世代、リビジョン、要求オフセットに結び付けられ、古いページが新しい結果に入ることはありません。

ページをまたぐ選択は現在の不変クエリー内の上限付き範囲で表し、最大 4,096 範囲です。すべて選択は現在のクエリー全体を対象とし、キャッシュから外れても選択は変わりません。展開確認前に Rust が範囲を物理または移動用の識別情報に固定し、クエリー変更後もそれを使います。タスクの 100,000 項目上限を超えた選択は明示的に拒否し、黙って縮小しません。非常駐選択の合計サイズは現在表示しません。常駐内容を超える一括クリップボードコピーは、不完全な一覧を黙ってコピーせずリソース上限エラーを返します。

<a name="xdzip-task-boundaries"></a>

## タスクの境界

ディスク索引から選択した通常ファイルは、ソース全体の再検証、安全な計画、項目全体の検証、既存の許可済み確定を経て展開できます。固定された計画は引き続き 100,000 項目とメタデータ 64 MiB 以下です。ファイルと実際にデコードしたバイトの上限は[展開契約](../../engineering/zip-safe-extraction.md)に従います。ディレクトリー展開時に未解決の名前を飛ばすことはできず、この索引構成では選択されたリンクを拒否します。ZIP リーダーは中央ディレクトリー全体の物理オフセットを再確認し、選択されたデータの位置だけを保持して、領域の重なり、ローカルヘッダー、サイズ、CRC、認証、キャンセルの検査を維持します。

ディスク索引を使うアーカイブは現在、アーカイブ全体の変更や検査に対応しません。空のメモリー上の投影を完全なアーカイブとして扱えません。作成、他の形式、分割ボリューム、書き換えの既存上限は変わりません。[内容のプレビュー](content-preview.md)も参照してください。CLI の物理一覧と選択は同じ索引を再利用し、[明示的なページ分割](command-line.md#xdzip-archive-behavior)で大規模アーカイブの完全な物理範囲を取得します。ページ分割しない応答は 100,000 項目とシリアル化データまたはテキスト 16 MiB の予算を維持し、超過時は全体が失敗します。

<a name="xdzip-verification"></a>

## 検証

`scripts/probe-large-index.py` は中国語名、重複、入れ子のディレクトリーを持つ実際の ZIP64 を `build/` に生成し、実際の `xdzip-m2-probe` を呼び出します。プローブはすべてのクエリーバッチを読み、走査、並べ替え、取得、ディスクバイト、プラットフォームで利用できるメモリー指標を別々に記録します。サンプル生成器は 100 万件のファイル名配列をメモリー内に作りません。対象範囲、失敗、キャンセル、クリーンアップ、古いページ、選択ファイルの実出力は[受け入れ要件](../../../developers/qa/acceptance.md)に従い、結果は issue、ローカル、CI 成果物に保存します。測定値は実際の機器と負荷に対する証拠であり、普遍的な性能を保証しません。
