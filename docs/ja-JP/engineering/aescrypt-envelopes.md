# AES Crypt の読み取り専用封装

[English](../../engineering/aescrypt-envelopes.md) | [简体中文](../../zh-CN/engineering/aescrypt-envelopes.md) | [繁體中文（台灣）](../../zh-TW/engineering/aescrypt-envelopes.md) | 日本語 | [한국어](../../ko-KR/engineering/aescrypt-envelopes.md) | [Français](../../fr-FR/engineering/aescrypt-envelopes.md) | [Deutsch](../../de-DE/engineering/aescrypt-envelopes.md) | [Español](../../es-ES/engineering/aescrypt-envelopes.md) | [Português (Brasil)](../../pt-BR/engineering/aescrypt-envelopes.md) | [Русский](../../ru-RU/engineering/aescrypt-envelopes.md)

独立した Rust バックエンド `xdzip-codec-aescrypt` は AES Crypt ストリームバージョン 0、1、2、3 を読み取ります。アプリケーションのバージョン番号は別です。通常の仮想ファイルを 1 つ公開し、作成、変更、ボリューム、外部拡張の取得は提供しません。この形式は圧縮せずにデータを暗号化するため、行の方式は Store、暗号化フラグは true です。圧縮サイズは物理封装全体です。バックエンドは `.aes` ではなく内容検出によって選択されます。

<a name="xdzip-admission-and-authentication"></a>

## 受け入れと認証

4 バージョンすべてでオープン時にパスワードが必要です。空ファイルを含め、正確なサイズのメタデータを表示する前に暗号文全体を認証します。不変のアーカイブセッションは、検査、プレビュー、展開のために制限されたオープン認証情報を既存のホスト秘密スロットに保持し、項目ごとの新しいパスワード機構は導入しません。2 回目の完全な認証によってタスクリーダーを受け入れます。エクスポートパスは実際に復号する暗号文そのものを認証し、最終 MAC とサイズの検査後にのみ成功します。ホストはコーデックの成功とソース検査後にのみ一時出力を公開します。未検証のチャンクは最終公開を承認しません。

バージョン 0–2 は UTF-16LE パスワードバイトを使用する指定の 8192 ラウンド SHA-256 ACKDF を使用します。バージョン 0 はデータ鍵を直接導出し、パスワード誤りと暗号文の破損を区別できず、`password_or_integrity` を報告します。バージョン 1–2 は CBC 復号前にラップされたセッション IV と鍵を HMAC-SHA-256 で認証します。検証失敗は `wrong_password` を報告しますが、ラップされたデータの破損でも発生し得ます。バージョン 3 は UTF-8 の PBKDF2-HMAC-SHA-512 を使い、ラップされたセッションバイトとバージョンバイト `03` を認証し、データには PKCS#7 パディング付き AES-256-CBC を使います。メタデータ受け入れ時とエクスポート後のどちらも、実際の暗号文を認証してからパディングを検証します。パディングをパスワード検証には使用しません。MAC 比較は固定幅で、採用済みの定数時間プリミティブを使用します。

すべてのバージョンが暗号文の HMAC-SHA-256 を検証します。ただしバージョン 0–2 は最終平文長の 16 による剰余を認証範囲外に保存します。このフィールドを変更すると、MAC を無効にせずに報告およびエクスポートされる長さが変わる場合があります。バージョン 2–3 の拡張も暗号化、認証されていません。したがって `format_declared_checks` は形式が宣言したすべての検査に合格したことを意味し、封装の全フィールド、送信者 ID、ファイル出所を認証するものではありません。バージョン 3 の暗号化されたパディングは平文長を認証します。旧版の検査成功を、平文長が完全に認証されたと説明してはいけません。

<a name="xdzip-names-limits-and-failures"></a>

## 名前、制限、失敗

仮想ベース名はホストが承認したベース名から `.aes` を大小文字を区別せず除去したものだけに由来します。危険、空、ドット、ドット 2 つのベース名は `content` になります。認証されていない `FILENAME`、`URI`、`CREATED_BY` とコンテナー拡張値は、パス、ネットワーク、プロセス、実行の権限を与えません。タイムスタンプや実行権限は復元しません。最初のメンバーが文字どおり `AES` という通常の TAR は、制限されたフレーミング判別後も TAR です。拡張に TAR マーカーを含む有効な暗号化封装も AES Crypt のままです。AES Crypt として受け入れた後、認証失敗時に TAR、ZIP、他形式へフォールバックしません。

バージョン 1–3 は予約バイトがゼロであることを要求し、拡張レコードには NUL 区切りの識別子が必要です。受け入れ上限は拡張レコード 256 件、ヘッダー 1 MiB、バージョン 3 の反復回数 1～2,000,000 です。ゼロ回、形式不正、切断、ブロックに整列しないデータは KDF 作業前に拒否します。未知のバージョンは未対応です。旧版の剰余は 0–15 で、長さゼロの暗号文は剰余ゼロが必要です。バージョン 3 は少なくとも 1 つのパディングブロックが必要です。破損データの修復はありません。

リーダー専用の累積割り当てにはそれぞれ厳格な 24 GiB 上限があります。対象は実入力、実際のハッシュ圧縮ブロック作業、実際の AES ブロック作業、配信された平文です。メタデータ認証、KDF、後続読み取りを含み、失敗後の返却はありません。呼び出し元のメタデータ入力と名前の制限は受け入れを厳しくすることだけができます。ハッシュ作業は KDF、HMAC パッド、最終処理を計上し、CBC はラップされたセッション資料を含む実際の全ブロックを計上します。追加の受け入れ作業と KDF 作業はデータ配信前にホスト出力先へ課金されます。通常のデコードは既存のホストソース、出力、タスク予算の対象であり、平文はファイルごとに 8 GiB、タスクごとに 20 GiB が上限です。汎用コーデックインターフェースは最大 4096 UTF-8 パスワードバイトを受け入れ、製品共通の認証情報上限は 1024 バイトのままです。反復上限はアプリケーションのリソース方針であり、形式の最大値ではありません。

KDF 中、各読み取り、各制限付き CBC バッチでキャンセルを確認します。パスワード由来ハッシュ、中間 KDF ブロック、鍵、IV チェーン、平文バッファーには消去可能な状態を使用します。採用された AES プリミティブはゼロ化機能を有効にします。コーデックは導出鍵を保持し、平文パスワードを追加で保持しません。協調的キャンセルではブロック中の OS 読み取りを中断できません。ソース、キャンセル、割り当て、出力エラーは型を保持し、単純な中断読み取りだけを再試行します。リーダーエラーは終端的です。ホストのソース ID、サイズ、時刻の検査は変更をベストエフォートで検出するもので、原子的なソーススナップショットではありません。

<a name="xdzip-sources-and-regression-inputs"></a>

## ソースと回帰入力

フレーミングと暗号の主な規則は、作者の [AES Crypt ストリーム仕様](https://www.aescrypt.com/aes_stream_format.html)と[エンジンのストリーム説明](https://github.com/terrapane/aescrypt_engine/blob/master/stream_format.md)です。独立バックエンドは採用された汎用 AES と SHA-2 プリミティブを使用し、AES Crypt ランタイムや公式アプリケーションは使用しません。暗号化ファイルを実行せず、アプリケーションのライセンスも回避しません。共有秘密の SHA-512/HMAC 状態は RFC 2104 と [RFC 4231](https://www.rfc-editor.org/rfc/rfc4231) に従います。

[プロジェクト所有のテストデータ](../../../tests/fixtures/aescrypt/README.md)は独立してエンコードされたバージョン 0–3 を含み、別の Python 暗号デコーダーで交差確認しています。固定の公開テスト鍵と IV は決定的なテスト入力専用です。参照実装は `build/toolchain/`、生成証拠は `build/` または CI に保管します。受け入れ項目は[検証要件](../../../developers/qa/acceptance.md)の `FORMAT-AESCRYPT` です。[パスワード処理](password-extraction.md)、[検査](archive-checking.md)、[安全な展開](zip-safe-extraction.md)も参照してください。
