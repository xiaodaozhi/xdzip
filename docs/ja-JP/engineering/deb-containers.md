# DEB コンテナー契約

[English](../../engineering/deb-containers.md) | [简体中文](../../zh-CN/engineering/deb-containers.md) | [繁體中文（台灣）](../../zh-TW/engineering/deb-containers.md) | 日本語 | [한국어](../../ko-KR/engineering/deb-containers.md) | [Français](../../fr-FR/engineering/deb-containers.md) | [Deutsch](../../de-DE/engineering/deb-containers.md) | [Español](../../es-ES/engineering/deb-containers.md) | [Português (Brasil)](../../pt-BR/engineering/deb-containers.md) | [Русский](../../ru-RU/engineering/deb-containers.md)

パッケージの外側は Debian の [deb(5)](https://manpages.debian.org/unstable/dpkg-dev/deb.5.en.html)、共通の ar フィールドは [ar(5)](https://man.netbsd.org/ar.5) に従います。通常の `!<arch>\n` レイアウトのみを受け入れます。各 60 バイトのヘッダーには、長さが制限された ASCII の名前、時刻、所有者、モード、サイズの各フィールドと必須の終端マーカーがあります。10 進フィールド、8 進モード、正確なデータ範囲、奇数長メンバーの改行パディング、物理 EOF を検証します。thin アーカイブ、過去の形式、長い名前の拡張はサポートせず、外部ファイルへのアクセス権限も与えません。

`debian-binary` が先頭です。メジャーバージョン 2、制限された 10 進のマイナーバージョン、制限された追加バージョン行を受け入れ、互換性のないメジャーバージョンは拒否します。control と data のメンバーはこの順序で現れます。アンダースコアで始まる拡張を間に挟むことができ、後続の追加メンバーも保持します。control は非圧縮 TAR、GZIP、XZ、Zstandard を受け入れ、data はさらに BZip2 と LZMA Alone を受け入れます。選択した各メンバーは実際の TAR とフィルターの実装が検証し、拡張子だけでは判断しません。必須メンバーの未対応プロファイルは明示的に失敗します。Deb822 フィールド、メタデータ内のチェックサム、署名、インストール可能性はコンテナー検証の対象外です。

<a name="xdzip-views-and-physical-identities"></a>

## ビューと物理 ID

既存のディレクトリーモデルは重複しない 3 つのプレフィックスを公開します。`members/` にはバージョンと圧縮 TAR メンバーを含む、すべての生 ar メンバーがあります。`control/` と `data/` には対応する TAR レコードがあります。これらはエクスポートビューです。すべてを展開すると、生メンバーと展開済みレコードの両方が出力されます。`control/` または `data/` のみを選択すると、そのビューだけが出力されます。パッケージのインストールやスクリプトの実行は行いません。

生レコードには ar の順序で安定した ID を与え、続いて各 TAR の物理レコード順に control と data の ID を与えます。重複、生の名前と解決済みの名前、警告と特殊項目のフラグ、タイムスタンプの意味を保持します。表示名がソースや出力に対する権限になることはありません。子項目の生の名前と解決済みの名前の両方にプレフィックスを付けますが、危険な構成要素を正規化で消去しません。プレフィックスを付ける前に元の危険な表記をマークし、絶対パスが安全そうな相対子項目になることを防ぎます。既存の TAR パーサーは無害な空の `.` ルートマーカーを省略します。プレフィックスから推定されたディレクトリーノードは仮想のままで、物理項目を作り出しません。リンクと特殊オブジェクトは TAR の未対応フラグを保持します。ホストの汎用パス検査は引き続き危険な出力を拒否します。メタデータのオープン時は、行を公開する前に両方の内側の走査と宣言された検査を完了します。

<a name="xdzip-source-ownership-work-and-payload-verification"></a>

## ソースの所有、作業量、データ検証

内側のリーダーには、既存の承認済みソースの制限されたビューだけを渡します。相対シークと読み取りはメンバーの物理範囲から出たり別のファイルを開いたりできません。共有ビューはルートソースへの実際のアクセスを直列化し、それぞれ独立した論理カーソルを保持します。unsafe ポインターや自己参照ポインターは導入しません。型付きのキャンセル、制限エラーは保持し、通常のホスト読み取り失敗は I/O エラーのままにします。借用の衝突と不可能な読み取り数は、パニックを起こしたり終端エラーを再試行したりせず拒否します。

既存の制御されたストリームと TAR リーダーを所有型ソース入力に対応させ、借用する呼び出し元と同じ初期化、受け入れ規則を維持します。物理順の要求中は各内側データリーダーを保持し、多数のレコードを展開するときにファイルごとに TAR を再走査しないようにします。データを使用する前に外側の構造と両方の TAR インデックスを再解析し、それらのリーダーを保持して、新しい完全なインデックスを投影し、不変の親スナップショットと比較します。呼び出し元が指定した名前、ID、型、方式、サイズで別のレコードを置き換えることはできません。パディングとメンバー範囲も再検証します。リーダーは失敗後に再開できません。ホストのソース検査、一時準備、ファイル単位の検証、最終公開が引き続き優先されます。既存のソース ID 検査による変更検出はベストエフォートです。ar に内容のチェックサムはなく、これらの検査で原子的または認証済みのソーススナップショットが作られるわけではありません。解析した ar の所有者とモードのフィールドは権限復元を許可しません。

メンバー数と行数、生、解決済み、表示名のバイト数、物理ソース範囲、メタデータのデコード作業量にはパッケージ全体の共通制限を適用します。control と data にそれぞれ新しい累積デコード割り当ては与えません。入力 I/O は準備または配信の各段階内で共有ビュー全体にわたり計上します。既存の TAR インデックス作成とデータの再オープンと同様、準備と配信は別です。準備時にキャッシュしたバイトは追加のソースアクセスを許可しません。配信では、生メンバーのエクスポートと実際の内部デコードを、配信したファイルのバイト数とは別に計上します。次の読み取り、書き込み、割り当ての前に超過を拒否し、レコード境界とソース読み取り時にキャンセルを確認します。

このプロファイルは読み取り専用で、パスワード、分割ボリューム、パッケージの作成や書き換えを提供しません。生 ar メンバーの圧縮サイズは既知ですが、圧縮 TAR の子レコードのサイズは不明です。検査には `format_declared_checks` を使用し、コンテナー構造、読み取り可能性、採用された内部フィルターが実際に宣言する検査を検証します。これはパッケージの認証ではありません。自動受け入れには、内容が既知の独立した参照、採用された全フィルター系統、入れ子の境界、重複 ID、不正な外側構造と内部検査、正確な予算、ソース変更、キャンセルに加え、実際の CLI/Qt での閲覧、検査、展開が含まれます。生成した証拠は `build/` または CI に保管し、プラットフォームおよびリリースの承認とは分けます。
