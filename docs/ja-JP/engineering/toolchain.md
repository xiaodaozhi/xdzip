# ツールチェーンとプラットフォームの固定

[English](../../engineering/toolchain.md) | [简体中文](../../zh-CN/engineering/toolchain.md) | [繁體中文](../../zh-TW/engineering/toolchain.md) | 日本語 | [한국어](../../ko-KR/engineering/toolchain.md) | [Français](../../fr-FR/engineering/toolchain.md) | [Deutsch](../../de-DE/engineering/toolchain.md) | [Español](../../es-ES/engineering/toolchain.md) | [Português (Brasil)](../../pt-BR/engineering/toolchain.md) | [Русский](../../ru-RU/engineering/toolchain.md)

開発ツールのバージョンは rust-toolchain.toml、Cargo.lock、CMake、CI で固定し、サポート範囲は[サポート方針](support-policy.md)に従います。この表は更新とリリース時の検証を定めます。具体的な観察結果は issue や Actions に記録し、一台のツール一覧をリリースの依存関係ロックとはしません。

| 項目 | 現在の方針 | 固定に必要な証拠 |
| --- | --- | --- |
| Rust | rust-toolchain.toml で 1.99.0、edition 2024、rust-version 1.99 を固定 | 更新時に依存関係の MSRV、三つのターゲットのテスト、Clippy を確認し、ツールチェーンと Cargo 設定を一致させる |
| Qt | SDK 6.8.2 を固定。QtNetwork は公式セキュリティ修正から派生した `6.8.2-xdzip-network.1` を使用。ローカル SDK は `build/toolchain/Qt/6.8.2/<platform-subdirectory>`、動的配置 | 固定した由来とハッシュ、モジュールのライセンス、三平台の基本動作確認。各リリース前にセキュリティ保守を確認し、更新時はソースと置換を再検証 |
| C++ | C++17 と Qt に対応するコンパイラー | macOS の clang、Windows の MSVC、Linux コンパイラーのバージョン |
| CMake | ルートで 3.24 以降を要求し Ninja を使用 | 実際のビルドバージョン、生成ヘッダーの依存関係、クリーンな設定を確認。CI ツールのバージョンはワークフローで固定 |
| Python | 共通デスクトップ入口は 3.10+ を要求。パッケージ検証ツールは分離環境を使用 | 後続の Python スクリプトで同じインタープリターを使い、段階ごとに固定済みツール依存を確認。ブラウザー設計ツールは製品ビルドの依存関係にしない |
| cxx | 1.0.205。ブリッジはビルド時に生成し、安定したバイナリー ABI はない | crate と生成器のバージョン一致、終了時の競合と例外境界の回帰検証 |
| システム | macOS 14+ arm64、保守中の Windows 11 x64、Ubuntu 24.04 X11 x64 | 承認された方針に従って実際の環境を確認し、CI ホストの証拠をすべてのシステムバージョンの保証に拡張しない |

Windows ではデスクトップ、Qt ソース、提供ソースの再ビルドが MSVC/Ninja 用に一時的に UTF-8 コンソールコードページを使用し、終了後に元に戻します。コンソールがない場合はプロセスと子プロセス用に一時的な非表示コンソールを作成し、外部プロセスは接続してはいけません。既存コンソールを共有する保護対象ビルドは接続プロセス一覧を使って直列化し、独立したコンソールは並列にビルドできます。保護中はプロセスを接続したままにします。無効な一覧ではビルドを停止し、30 秒の待機後は再試行を求めます。ウィンドウハンドルを持たない古いスクリプトのロックとは互換性がなく、他プログラムによるコンソール設定変更も防げません。ビルド前後にはコンパイル済みオブジェクトの Ninja 依存記録を検査します。直接の引用符付き include または同一ディレクトリーの山括弧 include を持つソースに依存記録がない場合は停止し、古いディレクトリーを保持して新しいビルドディレクトリーを求めます。オブジェクトを自動削除または再利用しません。Ninja はシステムヘッダーを意図的に省略する場合があり、システムヘッダーだけを使うソースの依存数がゼロでも構いません。他の検索パスで解決される山括弧 include やすべての暗黙のコンパイラー入力は対象外で、プリプロセッサー条件も評価しないため、無効な include を保守的に拒否する場合があります。CMake/Ninja の直接実行はこれらの入口保護を迂回します。コンパイラー出力を Ninja の接頭辞に一致させ、コードページやツールチェーンの変更後に実際のヘッダー変更で再コンパイルされることを確認します。

GitHub ホストの Apple Silicon ジョブは macOS 15 ランナーを使いますが、製品の配置ターゲットは macOS 14.0 のままです。ランナー更新は macOS 14 実機での検証を意味せず、プラットフォーム互換性と手動受け入れを別々に記録します。

日常の準備、確認、実行は[開発者向けビルドガイド](../../engineering/developer-build.md)を参照してください。`scripts/desktop.py doctor` は既定で build を検査し、`doctor --for-stage package` はパッケージ全体のチェーンを事前に検査します。prepare の `--install-rust`、`--install-qt`、`--packaging` はそれぞれ対応するツールと固定材料を明示的に準備します。システムのコンパイラーと SDK は引き続き開発者がインストールし、事前検査は暗黙のインストーラーではありません。

固定されたローカルツールチェーンは `build/toolchain/` にあります。Qt SDK、`qmllint`、`qmake` は `build/toolchain/Qt/6.8.2/<platform-subdirectory>`、`aqtinstall` と共通 Python ツールは `build/toolchain/desktop-tools`、Qt ダウンロードの一時配置は `build/toolchain/qt-install-tool` を使います。共通入口はビルド、テスト、パッケージ、個別 Qt 検査ごとに別のキャッシュを作らず、これらを共有します。CI がランナーの一時ディレクトリーを使う場合は明示的な引数を渡し、ローカル既定の配置は変えません。

事前検査は PATH 上で実際に使用される Rust/Cargo を実行し、固定バージョンとネイティブホスト、CMake、Ninja、Qt プレフィックス、プラットフォームツールを確認します。インストール済みでも現在のシェルで使えないコンパイラーは不足とみなします。パッケージ時はさらに固定された Rust 依存メタデータ、Qt SPDX とライセンス資料、スキーマキャッシュを確認します。後続プロセスは同じ検査済み環境を使用し、ビルド成功後にライセンス収集で rustc/cargo が見つからない事態を防ぎます。Docker または Inno Setup の不足は必要とする段階だけに影響し、通常の開発ビルドを妨げません。

各記録にはバージョン、ダウンロード元、SHA-256、ライセンス、ターゲット、担当者、検証コミット、日付を含めます。Rust/Qt のセキュリティ更新は再検証を伴い、保守終了したパッチを無期限に維持しません。最小システムの候補は正式なサポートの約束ではありません。

システム保守、Qt のセキュリティ更新経路、更新検証の責任は[サポート方針](support-policy.md)に従います。由来とライセンスの結論は[リリース審査手順](../../../developers/qa/release-review.md)に従って記録します。

Windows のメインウィンドウのクライアント領域拡張は WindowsFrame が公開 Qt ウィンドウインターフェースと Win32 で実装し、GuiPrivate にリンクしません。通常ウィンドウへの初回バインド時には現在の QWindow クライアント領域の論理寸法、DPR、ネイティブ枠の測定値から枠を決め、その後のテーマまたは DPI 再適用では枠だけを更新します。ローカルなスケール上書きがなく Qt PassThrough 丸めを使う通常の PMv2 ウィンドウでは、WM_GETDPISCALEDSIZE が保留中 SIZE のスケーリング前の調整量を保持し、クライアント領域を拡大縮小して対象 DPI の実際の枠を加えます。無効な測定値、オーバーフロー、その他の状態では SIZE を変更せず Qt に制御を返します。借用したネイティブメッセージと書き込み可能な構造体は同期コールバック中だけ使用します。Qt 更新または SDK 置換時には影響するクライアント領域、枠、ウィンドウ状態を再検証します。物理的な二画面間ドラッグと外観は必要に応じて確認し、プログラム上の結果で未実施の物理検証を代替しません。

日次 CI は rust-toolchain.toml で固定された Rust、rustfmt、clippy をランナーの一時ディレクトリーに独立してインストールし、実際のコンパイラーがそこにあることを確認してから Rust のフォーマットを検査します。これによりホストの不完全な rustup ツールチェーンを避けます。完全な Rust テストと署名ツールのテストは変更に応じてローカルまたは対応するオンデマンドワークフローで実行します。
