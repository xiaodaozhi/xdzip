# ディスクイメージとその他のアーカイブ形式のソースとライセンス

[English](../../engineering/disk-image-archive-format-sources.md) | [简体中文](../../zh-CN/engineering/disk-image-archive-format-sources.md) | [繁體中文](../../zh-TW/engineering/disk-image-archive-format-sources.md) | 日本語 | [한국어](../../ko-KR/engineering/disk-image-archive-format-sources.md) | [Français](../../fr-FR/engineering/disk-image-archive-format-sources.md) | [Deutsch](../../de-DE/engineering/disk-image-archive-format-sources.md) | [Español](../../es-ES/engineering/disk-image-archive-format-sources.md) | [Português (Brasil)](../../pt-BR/engineering/disk-image-archive-format-sources.md) | [Русский](../../ru-RU/engineering/disk-image-archive-format-sources.md)

このページは DAA、ISZ、ZPAQ、PEA、BOND、J2J と関連形式について、公開技術資料、ライセンス上の制限、対応要件を説明します。形式が公開されていてもデコーダーの配布許可を意味せず、参照実装が必ずしも再配布可能な製品依存関係とは限りません。以下の参照はどれも xdzip にリンクされません。形式を製品レジストリに追加する前に、ソースリビジョン、ライセンス文、完全なテストデータ、リソース制限、失敗時の動作を確定する必要があります。

<a name="xdzip-daa-10"></a>

## DAA 1.0

- **公開仕様:** ベンダーが公開した DAA 1.0 仕様は見つかっていません。公開資料は DAA を PowerISO の独自ディスク/アーカイブイメージとし、ヘッダー、チャンク長テーブル、独立圧縮された ISO チャンクを記述しています。zlib と LZMA の変種、および 110 など後の内部バージョンは公開記録にありますが、安定した 1.0 契約は定義されていません。
- **参照実装:** `daa2iso` 0.1.7e、Debian/Fedora の GPL-2.0-or-later パッケージ。ソースは過去の調査にのみ有用です。現在、権威ある公開リポジトリから upstream Git コミットやベンダー仕様を固定できません。
- **ライセンスと再配布:** 実装は GPL-2.0-or-later です。このライセンスは独自の DAA 技術に対する権利を与えず、プロジェクトには xdzip でデコーダーを配布する独立した許可記録もありません。
- **完全なサンプル:** 公開サンプルは出所とバージョンが固定されていないディスクイメージや複数部アーカイブであることが多く、旧ヘッダー、バージョン 110、複数部の順序、zlib、LZMA、難読化、チェックサム、不正チャンクを網羅する再配布可能なコーパスは現在受理されていません。
- **クリーンルームの実現可能性:** 安定した形式記録と法的判断を得た後なら、制限付き ISO 再構築は技術的に可能かもしれません。GPL デコーダーだけからのリバースエンジニアリングは製品実装の証拠として不十分です。
- **機能範囲:** 製品判断により永久に非対応です。DAA の検出器、codec、レジストリ、MIME、関連付け、リーダー、ライターを追加しません。過去の調査は将来の受理を許可するものではありません。
- **結論:** **製品判断により永久に対象外。** xdzip は DAA 対応を追求しません。上記のソース、ライセンス、サンプルに関する結果は過去の調査であり、配布待ちの条件ではありません。

<a name="xdzip-isz"></a>

## ISZ

- **公開仕様:** EZB Systems の *ISZ File Format Specification* バージョン 1.00、2006-07-03 改訂は、`IsZ!` シグネチャ、固定ヘッダー、任意のセグメント定義テーブル、チャンク定義テーブル、データブロックを記載します。ヘッダーフィールドにはセクターサイズと総数、パスワードモード、セグメントサイズ、ブロック数とサイズ、ポインター長、セグメント番号、テーブルとデータのオフセットがあります。チャンクフラグはゼロ、格納、zlib、BZip2 ブロックを識別します。仕様は [ImgBurn フォーラムのコピー](https://forum.imgburn.com/topic/14260-isz-images-supporting/#comment-115553)に転載されています。
- **参照実装:** CDEmu `libmirage` の ISZ フィルター、コミット `39fcffe09739e1dc40bef4781646f9ffb8b7dc4e` と、Play- の `IszImageStream`、コミット `5bb010f27d8e2309f37b1f8eba0f74ecd546b29b`。どちらも参照分析資料に限定します。`Helias/isz-tool` は Python リーダーですが、この環境では権威ある不変コミットとライセンス記録を取得できませんでした。
- **ライセンスと再配布:** EZB 仕様の第 8 節は、製品に ISZ 技術を組み込むには EZB に連絡し、条件付きの無料ライセンスを取得する必要があるとしています。公開文書や寛容なライセンスの独立リーダーが存在しても、この製品ライセンス条件は免除されません。CDEmu と Play- は xdzip の依存関係ではありません。
- **完全なサンプル:** 公開ツールで有効な Store、zlib、BZip2 ブロックを生成できますが、完全な再配布可能マトリクスには単一ボリュームと分割イメージ、ゼロブロック、すべてのポインター長、正確な末尾ブロック、パスワードモード、テーブル難読化、切り詰め、オフセット、ソース変更のケースも必要です。そのような自前コーパスは現在リポジトリに記録されていません。
- **クリーンルームの実現可能性:** 非暗号化、単一ボリューム、読み取り専用のサブセットは技術的に ISO 閲覧から分離できます。最初の実装では文書化された 4 種類のブロックを一つの仮想 `image.iso` にデコードでき、マウントや起動実行は行いません。ただし、実装前に法的許可、不変の参照固定、完全なテストデータが必要です。
- **機能範囲:** 条件を満たすまでは `.isz` を登録せず、`IsZ!` から対応を推測せず、パスワード、AES、分割、書き込み、直接の光学イメージ閲覧を公開しません。後に受理する場合、デコーダーはヘッダー/バージョン、ポインターとセグメントテーブル、XOR/難読化解除規則、ブロックとデータの境界、論理サイズ計算、完全なブロック終端、キャンセル、入力/処理/出力の制限を検証する必要があります。
- **結論:** **製品判断により対象外。** xdzip はこの作業パッケージで ISZ 対応を進めず、製品ライセンスのため EZB に連絡もしません。判断を見直さない限り `.isz` 検出器やレジストリ項目を追加できません。

<a name="xdzip-zpaq"></a>

## ZPAQ

- **公開仕様:** Matt Mahoney の *The ZPAQ Open Standard Format for Highly Compressed Data* バージョン 2.03 と 2.06。形式は ZPAQL バイトコードに展開プログラムを保存し、ソリッドブロック、ジャーナリング、重複排除、SHA-1 レコード、後のレベルでの暗号化、複数部アーカイブをサポートします。
- **参照実装:** `zpaq/zpaq` のタグ `6.22` と対応する `libzpaq` ソース。このタグは本評価で固定した調査参照ですが、実装作業前にコミットハッシュとライセンス文のハッシュを取得する必要があります。
- **ライセンスと再配布:** 参照実装と設定ファイルは GPLv3 です。第三者アーカイブランタイムを使わない方針のもと、現在の製品にはリンクできません。公開標準はクリーンルーム分析を可能にしますが、デコーダー VM と設定コーパスには別途実装とレビューが必要です。
- **完全なサンプル:** 有用なコーパスにはレベル 1 と 2 のブロック、任意の ZPAQL プログラム、ジャーナル更新、重複排除、暗号化・複数部レコード、SHA-1 検証、不正な VM またはブロック境界が必要です。リポジトリにそのような自前コーパスはありません。
- **クリーンルームの実現可能性:** 理論上可能ですが、小さなコンテナー解析ではなく、仮想マシンとリソース計量のプロジェクトです。安全な制限はバイトコード解釈、モデルメモリー、展開出力、履歴、重複排除状態を計上する必要があります。
- **機能範囲:** 将来の最初の範囲は読み取り専用、非暗号化、非複数部、非ジャーナルで、VM サブセットを宣言します。作成、更新、パスワード、無制限のソリッド展開を意味しません。
- **結論:** **製品判断により対象外。** xdzip は ZPAQL 仮想マシンを実装せず、それに依存する ZPAQ プロファイルを受け入れません。判断を見直さない限り `.zpaq` 検出器やレジストリ項目を追加できません。

<a name="xdzip-pea"></a>

## PEA

- **公開仕様:** PeaZip の *Pack, Encrypt, Authenticate* 仕様は PEA 1.x と提案段階の PEA 2.0、ストリーム、ボリュームとオブジェクトの制御、終端マーカー、PCOMPRESS レベルを扱います。仕様は [`pea_help.pdf`](https://peazip.github.io/pea_help.pdf) として公開され、[pea-file-format.html](https://peazip.github.io/pea-file-format.html) に概要があります。現在の公式ページは PEA と PCOMPRESS の仕様を明示的にパブリックドメインとしています。
- **参照実装:** `peazip/PeaZip`、コミット `81b31f7e487b462980a52ac0f2e0b3cf700fe799`。`peazip-sources/dev/pea_utils.pas` と `unit_pea.pas` を含みます。実装は LGPLv3 で、同梱の Wolfgang Ehrhardt 暗号ユニットは zlib/libpng ライセンスです。ソースの公開 URL は [peazip-11.4.0.src.zip](https://github.com/peazip/PeaZip/releases/download/11.4.0/peazip-11.4.0.src.zip) です。固定ソースは参照分析にのみ使用します。
- **ライセンスと再配布:** 形式仕様自体には製品ライセンス上の障害はありませんが、LGPLv3 エンジンと暗号依存関係を現在の製品に既定でコピーやリンクすることはできません。クリーンルームの Rust 実装はパブリックドメインの形式記録と独立して選択したアルゴリズムを使用し、参照バイナリはテスト専用にします。
- **完全なサンプル:** 受理済みプロファイルには、ファイル、ディレクトリ、有効な UTF-8 名、空/非空データ、切り詰め、末尾バイト、ソース変更、上限を対象とする自作の完全な Store テストデータがあります。より広いコーパスには PEA 1.x と 2.0、複数ストリーム、ボリューム境界、PCOMP レベル、認証失敗、暗号化ヘッダー、不正な終端マーカー、大きな宣言サイズが必要で、これらは製品範囲外のままです。
- **クリーンルームの実現可能性:** 非暗号化、単一ストリームの Store/Deflate リーダーは技術的に可能ですが、認証と暗号化は別のセキュリティ作業として扱う必要があります。形式の整合性設計上、構造解析だけを内容検証として宣伝できません。
- **機能範囲:** 将来の受理はまず読み取り専用とし、パスワード、暗号化、複数ボリューム、作成、変更を提供しません。抽出ストリームごとに公開前の宣言ダイジェストと終端認証の検査が必要です。
- **結論:** **保守的な読み取り専用プロファイルとして受理済み。** xdzip は現在 PEA 1.x、物理ボリューム一つ、UTF-8 名、PCOMPRESS0 格納ファイル/ディレクトリを受理し、オブジェクト、ストリーム、ボリュームのチェックは行いません。パスワード、認証/暗号化ストリーム、チェックサムアルゴリズム、PCOMPRESS1–3、分割、PEA 2.0、作成、変更は未対応です。LGPL 参照はテスト専用で製品にリンクしません。

<a name="xdzip-bond"></a>

## BOND

- **公開仕様:** Bandizip BOND アーカイブの仕様、シグネチャ、バージョン、圧縮契約は見つかっていません。最近の Bandizip リリースノートは「一部の BOND ファイル」の脆弱性に言及しますが、形式定義ではありません。公開 `.bond` 拡張子データベースは主に Microsoft Bond のスキーマ化データを説明し、別のシリアライズ形式です。
- **参照実装:** 権威あるアーカイブ形式の識別、固定リビジョン、再配布可能ライセンスを持つ実装は見つかっていません。
- **ライセンスと再配布:** 不明です。形式の所有者、技術的権利、参照条件が不明な間は製品やデコーダーを受理できません。
- **完全なサンプル:** 信頼できるバージョン付きソースからのサンプルはありません。拡張子だけでは許容可能なテストデータの識別になりません。
- **クリーンルームの実現可能性:** シグネチャと、アーカイブを Microsoft Bond データや他のバイナリペイロードと区別できる十分な完全サンプルがなければ評価できません。
- **機能範囲:** 検出、拡張子登録、閲覧、展開、検査、作成、パスワード、分割には対応しません。
- **結論:** **製品判断で対象外であり、Bandizip アーカイブ形式として未確認。** この作業パッケージでは `.bond` 検出器やレジストリ項目を追加しません。

<a name="xdzip-j2j"></a>

## J2J

- **公開仕様:** J2J アーカイブの仕様、シグネチャ、バージョン、開発者記録は見つかっていません。過去の Bandizip 機能一覧は J2J を展開専用として挙げますが、現在の公式形式ページに技術的定義はありません。他の J2J 検索結果は無関係な job-to-job データセットや JPEG-to-JPEG ツールを指します。
- **参照実装:** 固定リビジョンとライセンスを持ち、Bandizip のアーカイブリーダーと結び付けられる実装はありません。
- **ライセンスと再配布:** 不明です。第三者の拡張子ページや古いソフトウェア一覧はライセンス許可ではありません。
- **完全なサンプル:** 信頼できる再配布可能なサンプルマトリクスはリポジトリにありません。`.j2j` という名前だけではコンテナーの識別を確定できません。
- **クリーンルームの実現可能性:** シグネチャ、レコードモデル、圧縮/暗号化動作が文書化され、完全なコーパスが利用可能になるまで評価できません。
- **機能範囲:** 検出、拡張子登録、閲覧、展開、検査、作成、パスワード、分割には対応しません。
- **結論:** **製品判断で対象外であり、Bandizip アーカイブ形式として未確認。** この作業パッケージでは `.j2j` 検出器やレジストリ項目を追加しません。

<a name="xdzip-requirements-for-format-support"></a>

## 形式対応の要件

1. 権威ある仕様または法的レビュー済みのクリーンルームプロトコルを記録します。ブログ、拡張子データベース、単一のデコーダーソースだけでは不十分です。
2. 各調査ソースを不変コミットまたは内容ハッシュに固定し、適用されるライセンス文を記録します。
3. 対応を主張する各方式、バージョン、ボリュームモード、暗号化状態、終端条件の完全で再配布可能なテストデータマトリクスを作ります。ヘッダーのみや Store のみのサンプルでは相互運用性を証明できません。
4. 入力読み取り、メタデータ、展開作業、メモリー、論理出力、履歴、暗号状態、キャンセルの制限付きリソースモデルを定義します。不正なオフセット、循環、オーバーフロー、ソース変更は公開前に拒否します。
5. 各デコーダーを Qt、マウント、起動、インストーラー、スクリプト、レジストリ、任意のプロセス実行 API から独立させます。
6. codec、スナップショット識別、正確なペイロード動作、失敗分類が対象を絞った自動検証に合格してから、runtime、CLI、関連付け、ユーザー文書を接続します。
7. 保留中の候補は評価上も保留のまま表示します。Bandizip や第三者の一覧に名前があるだけで拡張子、MIME 項目、製品機能を与えてはなりません。

リポジトリの `python scripts/test-m10-source-gates.py` は、6 つの二言語セクションが必要な証拠フィールドを保持し、各結論が保留、対象外、受理済みのいずれかに明示され、保留または対象外の候補が `specs/engineering/archive-formats.json` に入っていないことを検査します。
