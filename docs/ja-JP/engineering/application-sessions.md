# アプリケーションセッションと終了の契約

[English](../../engineering/application-sessions.md) | [简体中文](../../zh-CN/engineering/application-sessions.md) | [繁體中文](../../zh-TW/engineering/application-sessions.md) | 日本語 | [한국어](../../ko-KR/engineering/application-sessions.md)

タブのコンテキストメニューには「閉じる」「他のタブを閉じる」「右側のタブを閉じる」があります。Shift+F10 またはメニューキーはフォーカスされたタブに作用します。右クリックでは現在のページを切り替えません。コマンドはタブの安定した識別情報を固定し、所有ウィンドウ内の現在の表示順にのみ作用し、他のウィンドウに影響してはなりません。並べ替え、ウィンドウのリサイズ、対象の消失、モーダル操作への移行時にメニューを閉じます。対象がない一括操作は無効にします。一括クローズは一度だけ送信します。現在のページが残る場合は維持し、閉じる場合は基準タブに切り替えてページの繰り返しの点滅を避けます。最後のページを閉じるとウェルカムページが復帰し、タスクと結果はグローバルなタスク入口に残ります。

同じユーザーログインセッション内では、通常のインストール版とポータブル版のプロセスは単一インスタンス、トレイ、アプリケーションメニューを共有します。Windows のパッケージ版は別の単一インスタンス名前空間を使い、通常のインストール版へリクエストを転送しないため、Store からの起動が通常版の更新インターフェースに到達することを防ぎます。両プロセスが共存する場合はそれぞれがトレイを所有します。既存のインストール・更新ゲートは両者を保守的に制約します。共存、設定、関連付けには実際のインストール環境での検証が必要です。バージョン照会は GUI を作る前に返ります。スモークテスト、デスクトッププローブとテストは分離されたパスを使い、実ユーザーのインスタンスには接続しません。

`SingleInstance` はメインウィンドウの作成前に QLockFile で所有者を選出し、クラッシュ後に残ったローカルサーバーを削除できるのはロック所有者だけです。QLocalServer は UserAccessOption を使います。構造化 JSON プロトコルはバージョン 1 で、メッセージごとに 256 KiB、絶対パス 128 個、接続 32 個までに制限します。後続プロセスはプライマリーの準備を待ち、リクエスト ID の確認応答を受けて終了します。15 秒以内の通信失敗は明示的に報告し、通常の UI を二重に作りません。Windows では起動側プロセスがサーバーハンドシェイク内の PID を使い、今回のユーザー操作に対するフォアグラウンド起動権限を引き渡します。永続的な最前面化は行いません。IPC はコマンドインタープリターを通さず、ユーザーのパスをログに記録しません。

`ApplicationSessions` は Qt のアプリケーション層コーディネーターであり、フォーマットの解釈、ディレクトリの認可、ファイルのコミットは行いません。各セッションは独立した SessionPage、BrowserController、Rust RuntimeConnection を所有します。開いているページはクエリー、選択、ディレクトリ、閲覧状態を保持します。ウィンドウがページを収容し、タブはアーカイブごとに隠れたネイティブメインウィンドウを作りません。ファイル関連付け、コマンドライン、ネイティブのファイルオープンイベント、開く操作、最近使った項目、ドラッグ＆ドロップ、作成結果はすべてオープン意図を送信します。アーカイブやタスクのない待機中のウェルカムページの再利用を優先します。重複パスは、まだ開いているセッションのみをアクティブにします。複数ファイルのリクエストは順に受け付け、最後のものをアクティブにします。パスの正規化は UI の重複排除専用で、書き込み権限を与えません。

`desktop/openMode=tabs|windows` の既定は tabs で、スキーマバージョン 1 と不明なフィールドを保持します。設定変更の成功は既存ページを移動せず、今後のオープンに直ちに反映されます。タイトルバーのプラスはこの設定に従ってページまたはウィンドウを開きます。

タブの並べ替えは安定したセッション識別情報と、そのウィンドウ内の対象インデックスを送信します。変更するのはそのウィンドウの開いているセッションの表示順だけで、タスク受付に使うコントローラー集合は変えません。ドラッグ終了またはキーボードでの並べ替え後も、アクティブなページ、アーカイブ、コントローラー、選択、タスク識別情報を保持し、他ウィンドウと閉じたバックグラウンドセッションの相対順は変えません。非アクティブなタブを閉じてもページは切り替わりません。アクティブなタブを閉じた場合は表示上の右隣、右隣がなければ左隣を選びます。不正な識別情報、閉じたセッション、範囲外インデックス、終了中の並べ替え要求は無視し、Rust 接続を生成または破棄しません。現在は同一ウィンドウ内の並べ替えのみ対応し、ウィンドウ間のドラッグ、ウィンドウへの分離、起動をまたぐ順序復元は未対応です。タブバーのオーバーフローは表示領域だけを変更し、セッションを破棄してはなりません。メニューやキーボードによる有効化では、アクティブなタブを見えるようにします。

保持できる生存セッションは最大 32 個で、上限時には明示的に通知します。バックグラウンドタスクがすべての枠を占有している場合、最後の閲覧ページを閉じると、そのシェルを再利用してウェルカムページとグローバルタスク入口を表示し、新しいランタイムを作りません。タブやメインウィンドウを閉じると、そのページのディレクトリ、検索、並べ替え、選択、スクロール、表示状態を消去しますが、バックグラウンドタスクはキャンセルしません。タスクや完了結果のあるページはコントローラーとタスクに必要なデータを保持します。統一タスクメニューは「セッション UUID／バックエンドタスク ID」を使い、別接続の同じ数値 ID は同じタスクではありません。パスワード、競合、結果ウィンドウは元のセッションのコントローラーが引き続き処理します。タスクのない閉じたページはまず非同期終了を要求し、受信スレッドの join 後にセッション集合から除去します。

セッションを閉じた後、遅れて到着した開始、事前検査、パスワード、競合のイベントは自動的にウィンドウを開いたりフォーカスを奪ったりしません。タスクとリクエストのトークンは残ります。ユーザーがグローバルなタスク入口から明示的にタスクを開いたときに、元セッションの進捗と保留中の要求を表示します。ページを閉じても要求はキャンセルされません。

グローバルタスク入口は複合識別情報で元のコントローラーのタスクウィンドウを表示します。まず呼び出し元のメニューを閉じ、現在のアーカイブタブを切り替えず、閉じたアーカイブページやメインウィンドウを復元しません。パスワード、競合、キャンセル操作は引き続き元のコントローラーに送ります。不正または期限切れのタスク識別情報は無視します。閲覧ページを閉じることとタスクを明示的に見ることは別のユーザー意図です。

タスクメニューの内容が変わった後、表示領域に収まる短い一覧は先頭項目から始まります。古いスクロール位置でタスク行を切ってはなりません。高さ制限を超える一覧はスクロール可能なままにし、消去領域は固定します。

タスク履歴の消去はアプリケーション層の表示意図です。コントローラーは正とするバックエンドスナップショットと遅れて届く確認応答を保持し、制限付き履歴内で終端項目だけを非表示にします。同じ終端状態の重複更新で再表示してはなりません。アクティブ数、準備プレースホルダー、パスワード、競合、キャンセル、join は非表示マーカーを使いません。完了履歴がない場合は変更を通知しません。履歴からの追い出しは非表示マーカーも除去します。表示可能なタスクがなくなった閉じたコントローラーは、既存の非同期終了フローで回収します。セッション間の消去はコントローラー識別情報で行い、数値 ID が同じという理由で別セッションのアクティブタスクを消去してはなりません。

作成、展開、整合性検査は、準備、パスワード・競合待ち、コミット、クリーンアップを含めてアプリケーション層で直列に受け付けます。受付待ちのコントローラーは制限付きコマンドを一つだけ保持し、キャンセル可能で GUI スレッドを占有しません。各 Rust 接続のタスク順序と安全性の意味も引き続き適用します。明示的な終了では全セッションを対象に確認します。待機を選ぶと全タスク完了後に終了し、キャンセルを選ぶと全接続のキャンセル、クリーンアップ、join を待ちます。終了完了状態の確認だけを行い、その確認から終了処理を再度開始しません。

重いタスクのスナップショットは、`TaskAccepted` より前またはそのリクエストの `Finished` より後に届いても、元のタスク作成リクエスト ID を保持します。コントローラーはリクエスト、元のセッション、タスクの識別情報が一致した場合にのみ、準備プレースホルダーを実際のタスクに結び付けます。他のリクエストやセッションのスナップショットがプレースホルダーを消費してはなりません。タスクとプレースホルダーは一度だけ数え、終端タスクはアクティブではありません。この結び付けは実際の受付応答を置き換えず、タスクウィンドウを早期に開かず、直列受付、キャンセル、全接続の join バリアを迂回しません。

すべてのタスクの終了待ちはアプリケーション層のタスク数と join バリアだけに収束します。一つのページが先に完了したとき、以前の単一ページ自動クローズ動作を実行したり、そのページの終了を理由に最後のウィンドウを隠したり、終了確認を再表示したりしません。

終了確認を表示する前にアプリケーション層の `quitDecisionPending` を設定します。この判断中は全セッションとウィンドウで、キューに入ったパスワード質問とその明示的な再表示要求を一時停止し、終了確認を覆えないようにします。戻るまたは待機を選んだ場合は、まだ有効なタスクと質問トークンだけを再開します。キャンセル、クリーンアップ、join 中は表示を停止したままにし、パスワードウィンドウを再び開きません。この状態は既存要求を隠したりキャンセルしたりせず、セッションを閉じた後の明示的なタスクアクセスも変更しません。

システムの終了、アプリケーションメニューとトレイの明示終了は同じデスクトップ経路を使います。管理セッションが所有するパスワードや競合の質問は、グローバルな終了確認に置き換えられる場合があります。戻る操作はタスクと要求トークンを保持し、キャンセルして終了する場合もすべての接続のクリーンアップと join を待ちます。ネイティブファイル選択、他のモーダルコントロール、管理対象ウィンドウ外の質問は引き続き終了を阻止し、前面に残ります。汎用的なモーダル検査でパスワード待ち中の終了を握りつぶしたり、確認を迂回してタスクをキャンセルしたりしてはなりません。

トレイの設定とバージョン情報は共有設定ウィンドウを直接表示します。メインウィンドウが非表示、最小化、または存在しない場合は、メインウィンドウを作成・復元せず独立したインスタンスを使います。トレイの終了は直接グローバル終了に進み、タスク待機中は共有確認を使います。「メインウィンドウを表示」は閲覧ウィンドウを明示的に復元または作成します。

トレイを無効にするかトレイのホストを失っても、閉じたダイアログや完了結果を再び開きません。表示中または最小化されたメインウィンドウはグローバルタスク入口を提供します。その入口がない場合は、元のパスワードと競合トークンを維持しながら、非表示のアクティブタスクだけを復元します。この自動復旧のためにメインウィンドウを作成または復元しません。開いている設定ウィンドウは引き続き利用できます。トレイ、アクセス可能なウィンドウ、アクティブタスクがいずれも残らない場合、隠れたメインウィンドウオブジェクトが保持されていても、全接続の join を待ってから終了します。

トレイを再び有効にした後も、既存のコマンドと現在のタスク状態を備えたコンテキストメニューを使えるようにします。Windows での即時のオフ・オン変更や、ホスト可用性の繰り返しの変更も含み、アイコンの復元だけでは不十分です。

メインウィンドウが表示中なら、「表示してアクティブにする」は前面に上げてアクティブ化を要求するだけです。非表示または最小化されている場合は、最初に通常表示してから最大化することなく、以前の通常・最大化・全画面状態に復元します。阻止しているモーダルウィンドウのアクティブ化を優先します。ポップアップの transientParent は実際の呼び出し元ウィンドウです。最後のメインウィンドウを閉じる動作は引き続きトレイ設定に従います。設定とバージョン情報は統一入口を使い、まず既存ウィンドウをアクティブにし、バージョン情報操作ではそのページに切り替えます。

`showMinimized()` は元の状態ビットを置き換えます。復元時は最小化されたまま保存済みの最大化または全画面フラグを追加し、その後で最小化フラグだけを除去します。最初に通常ウィンドウを表示してはいけません。ネイティブ回帰は Qt への要求をウィンドウマネージャーの完了状態とみなさず、ウィンドウが実際に露出してアクティブになり、最終状態が確認されるまで待ちます。

Cocoa 経路は所有する NSWindow の最小化と全画面遷移通知を監視します。遷移中は復元要求を保留し、ネイティブの確認後に続行します。同じネイティブウィンドウが表示・露出したままで遷移中でもないのに Qt が最小化を報告する場合、到着しないネイティブ確認を待たず、効果のなかった Qt 状態要求を取り消して保存状態に復元します。ネイティブウィンドウが破棄されたらオブザーバーを除去します。ウィンドウを取得できない場合は要求を保留したままにし、固定遅延を完了の証拠にしません。

全画面への移行中や完了コールバック内の最小化要求は、後の Qt 状態に上書きされたり、AppKit に受理されないまま Qt に記録されたりすることがあります。同じネイティブウィンドウへの要求を記録します。移行後も表示中で遷移がなければ、次のイベントループターンで Qt 状態をネイティブ全画面に合わせ、最小化を再試行します。より新しい復元、通常、最大化の要求を優先します。ウィンドウが破棄済みまたは利用不可なら再試行しません。状態合わせ中に届いた復元も優先し、古い最小化要求を取り消します。

パスワードと終了の順序回帰は、実際の AES 待機を使用します。タスク通知で要求が確立した後、遅延ウィンドウ表示より前の同期的な終了を、同じページ、別セッション、別ウィンドウから検査し、待機を選ぶ場合も含めます。ウィンドウ表示後に実際に投稿された終了は配信の対照です。通知と配信の実際の状態を記録します。キューにあるパスワードウィンドウが終了判断を覆わず、戻る・待機で同じトークンを保持し、キャンセルですべての join が完了することを検証します。制御された同期通知順は、過去のプラットフォームイベント順の証拠ではありません。

受け入れは、実際のネイティブウィンドウ状態の変化、同時起動とクラッシュ後の残留物、Unicode と一括ルーティング、両オープンモード、保存・キャンセルと再起動、セッション間 ID の衝突、バックグラウンドタスク、パスワードと競合、グローバル終了、受信スレッドの回収を対象とします。オフスクリーンテストが示すのは状態契約のみであり、ネイティブの視覚、アクセシビリティ、手動デスクトップ受け入れの代わりにはなりません。証拠は build/ または CI アーティファクトに保管します。

終了が実際のキャンセルと join に入った後、IPC は新しい意図を明示的に拒否します。選出ロックはチャネルを閉じた後にのみ解放し、再起動プロセスは全接続が終了した後にのみ起動します。旧インスタンスによる繰り返しのクリーンアップが新しいエンドポイントを削除してはなりません。Windows の再起動も今回のユーザー操作に対するフォアグラウンド権限を引き渡します。

阻止するダイアログ中に外部オープンを受けた場合は、最後のアクティブ化意図を保持し、まず阻止中のウィンドウをアクティブにして、その終了後に対応する新しいウィンドウを表示します。これにより隠れた新規ウィンドウが入口を失うことを防ぎます。設定ウィンドウは実際の呼び出し元を保持し、別のメインウィンドウにフォーカスが移っても所有者は変わりません。

ネイティブ回帰の入口は `python3 scripts/check-native-sessions.py --tests <browser-tests> --output build/review/native-sessions.json` です。Linux は Xvfb と Openbox を使った実際の X11 ウィンドウ管理経路を使用し、Windows と macOS はシステムのウィンドウマネージャーを使います。スクリプトは自ら起動した検証プロセスだけを管理します。オンデマンドの Qt ワークフローと Release はこの入口を共有します。ネイティブログと JSON は build/ または CI アーティファクトに保管し、未実施の手動視覚、GPU、IME、スクリーンリーダー検査の証拠にはできません。

Linux では Openbox の `--startup` コールバック後にのみ Qt テストプロセスを作成します。`_NET_SUPPORTING_WM_CHECK` が示すのはウィンドウマネージャーの識別情報のみで、テーマやイベント処理の準備完了は証明しません。`scripts/check-x11-startup.py` と `scripts/test-x11-startup-supervision.py` はそれぞれコールドスタートの準備とタイムアウト時のクリーンアップを確認し、自身のプロセスログを保持します。追加の待機や再試行は元の最初のウィンドウに対するアサーションの代わりにはなりません。

メインウィンドウを閉じることは最小化とは異なります。トレイがある状態で最後のウィンドウを閉じると、そのすべての閲覧タブを消去し、設定とバージョン情報を含む所有ダイアログを閉じ、未保存の外観プレビューをキャンセルし、適用済み設定を保持し、ネイティブウィンドウリソースを破棄してからメインウィンドウを非表示にします。トレイ、Dock、またはファイル引数のない二度目の起動から復元すると、ウェルカムページだけを一つ表示し、古いタブや所有ダイアログは復元しません。最後ではないウィンドウも、自身の閲覧タブと所有ダイアログを閉じてクリーンアップし、他のウィンドウには影響しません。バックグラウンドタスクと質問トークンは元のコントローラーに残し、対応するネイティブウィンドウはユーザーが明示的にタスクを開いたときだけ再作成します。モーダルウィンドウが阻止している場合はそれを先にアクティブにし、メインウィンドウのクローズを受け付けません。

ウィンドウを閉じても実際のバックグラウンドタスクはキャンセルされず、所有セッションは複合識別情報とともに残ります。通常は新しい空セッションがウェルカムページを収容します。生存セッション 32 個の上限では、閉じたページのアーカイブを持たないシェルを一時的に使用し、古いタイトル、読み込み、エラー表示を隠します。非同期 join で枠が空いた後、上限を超えずに空セッションを作ります。この置換は隠れたウィンドウを表示せず、他ウィンドウからフォーカスを奪いません。グローバルタスク入口はタスクウィンドウだけを表示します。ファイルオープン要求は閉じた閲覧ページを復元せず、新しいセッションで再読込します。バックグラウンドタスクが同じファイルをまだ変更している場合、新しいページはキャンセル可能な待機を表示し、タスク終了後に再読込します。その待機のキャンセルは元のタスクに影響しません。

オープンが失敗またはキャンセルされた後、読み取り中でなく、アクティブタスクもパスワード質問もないウェルカムページは別のオープンに再利用できます。古いパスは正常に開いたアーカイブの識別情報として扱いません。タスクによって保持された閉じたアーカイブを再び開く場合は、現在の待機中ウェルカムページを優先して新しいセッションで読み、元タスクの独立した識別情報を保持します。ユーザーが明示的に作った他のページや他ウィンドウには影響しません。待機のキャンセルや待機ページのクローズによって、タスク完了後にオープン要求を復活させてはなりません。

オープンの進行中表示中にユーザーがキャンセルした場合、バックグラウンドの完了応答が既にキューにあっても、結果をコミットしたりパスワード質問を表示したりしません。コントローラーは元の要求完了を待ち、確立された可能性のあるランタイムアーカイブセッションを問い合わせて閉じます。クリーンアップ中は busy を維持し、繰り返しのキャンセルでクリーンアップを止めません。キャンセル後のクリーンアップに成功したと装わず、実際の失敗を報告します。受理済みの他のバックグラウンドタスクは独自のライフサイクルを保持します。

メインウィンドウのクローズを受け付けるとき、アクティブ化世代を進め、モーダル待機の接続を切ります。すでにキューに入った古い起床コールバックも世代を確認し、モーダルが閉じた直後にメインウィンドウを再表示したり古いタブを復元したりできません。この無効化は通常のオープン入口と共有され、バックグラウンドタスクをキャンセルしません。

更新の引き渡しは即時再起動ではなく、別の `prepareForUpdate` バリアを使います。タスク、タスク開始、モーダル操作がある間は引き渡しを拒否します。ダウンロードは続行でき、待機はキャンセル可能です。受付後は新しい意図の入口を閉じ、すべての Rust 接続をクリーンアップします。全 join 完了後にのみ `readyForUpdate` を送出し、早期に終了しません。更新プロバイダーはインストールのコミットを解放する前に終了バリアを通知し、その後にのみメインアプリケーションが通常の終了介入を解除します。インストールのコミットが失敗した場合はバージョン情報に復旧入口を残し、通常のユーザー終了を許可し、旧バージョンを自動再起動しません。[ソフトウェア更新](../../engineering/software-update.md)を参照してください。

## ファイルマネージャー操作セッション

[ファイルマネージャーのコンテキスト操作](shell-actions.md)は閲覧ページやメインウィンドウを持たない操作セッションを使います。既存の複合タスク識別情報、直列受付、終了時の join バリアを共有します。コールドスタートでは独立した操作ホストだけをロードし、既に実行中のインスタンスはタブを切り替えずメインウィンドウも復元しません。一括準備と入力待ちはグローバルな活動として数え、作成成功は閲覧用のオープンキューに入りません。閲覧ウィンドウを作るのはメインウィンドウが明示的に表示されたときだけです。
