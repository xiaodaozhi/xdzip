# 製品ランタイムと Qt のライフサイクル

[English](../../engineering/product-runtime.md) | [简体中文](../../zh-CN/engineering/product-runtime.md) | [繁體中文](../../zh-TW/engineering/product-runtime.md) | 日本語 | [한국어](../../ko-KR/engineering/product-runtime.md) | [Français](../../fr-FR/engineering/product-runtime.md) | [Deutsch](../../de-DE/engineering/product-runtime.md) | [Español](../../es-ES/engineering/product-runtime.md) | [Português (Brasil)](../../pt-BR/engineering/product-runtime.md) | [Русский](../../ru-RU/engineering/product-runtime.md)

このガイドは、デスクトップアプリがコマンドとイベントで Rust ランタイムに接続する仕組みを、キューのバックプレッシャー、シャットダウン、プラットフォーム別ビルドを含めて説明します。各機能の範囲は[読み取り専用の閲覧](../../engineering/readonly-browser.md)と[安全な展開](../../engineering/zip-safe-extraction.md)を参照してください。

<a name="xdzip-implemented-services"></a>

## 実装済みサービス

`xdzip-runtime::service` が製品サービスを実装します。GUI は `CommandClient` を一度だけ取得し、専用の Qt 受信スレッドは `EventReceiver` を一度だけ取得します。Rust のコマンドスレッドは接続のオープン中アーカイブと閲覧スナップショットを所有します。別の Rust タスクスレッドは必要なソースと設定を伴う準備済み作業を受け取り、タスク更新を公開します。アーカイブハンドルと同期走査の入口は Rust に残ります。ABI は [Qt/Rust ブリッジ](../design/qt-rust-bridge.md)、所有と受け入れは[タスクスケジューリング](../design/task-scheduling.md)を参照してください。

主要コマンドには Open、Browse、Preflight、CloseSession、Snapshot があり、既存の実際の閲覧と事前確認はすべてこれらを使います。受理された通常要求には再利用されない ID が割り当てられ、上限付きデータイベントを最大一つ返した後、Finished を必ず一つ返します。エラーは直接 Finished を返します。ページにはセッション、要求、オフセットの識別情報が付きます。各 RuntimeConnection は一つのセッションと逐次処理される GUI 保留要求を持ちます。クエリーには完全なクエリー ID、GUI 世代、スナップショット改訂も含まれます。[ZIP 閲覧契約](zip-readonly-browsing.md)を参照してください。セッションをまたぐ要求は stale_session を返します。

GUI の通常受け入れはキューの空きを待たず try_lock を使い、パス 4 KiB、検索 1 KiB、選択項目 128 件、ディレクトリ ID 21 バイト、ソートコード 0–12 を検証します。拒否時は ID を消費せず、Busy は再試行できます。キャンセルは最大 128 件の独立した制御チャネルと専用の Finished 確認応答を持ちます。確認応答は対象がすでに終了していないことを保証しません。シャットダウンは独立した冪等な RequestId を保持し、最後の使用可能な ID を予約するため、通常 ID の枯渇時やキュー満杯時にも動作します。

Qt コントローラーが受け入れ待ちとして保持するコマンドは一つだけです。一時的な Busy はイベントループ内の 1 ms の単発タイマーで最大 32 回再試行し、継続的な飽和の場合だけ再試行を促します。これは完了期限ではありません。キャンセル、シャットダウン、切断時には未受理のコマンドを直ちに取り下げ、アイドル時には再試行タイマーを動かしません。不正な引数や ID 枯渇は busy に偽装せず別々に報告します。切断後は Open が無効になります。

<a name="xdzip-bounded-transport"></a>

## 上限付き転送

- 未完了の通常要求は最大 128 件で、受信側が Finished を取り出したときに初めて容量が解放されます。要求ごとに二つのイベント枠を予約し、データが終端状態を押し出さないようにします。
- Rust のデータイベントには累積 32 MiB の内容予算があり、最大 16 MiB の画像とそのコンテナーを含みます。予算超過時は公開を待機し、キャンセルまたはシャットダウンで待機を起こしてキャンセル済み終端状態を出せます。単一イベントが大きすぎる場合は resource_limit を返します。
- Rust コマンドの累積内容上限は 8 MiB のままで、超過は受け入れ時に拒否します。画像イベントの大きい予算はこれに影響しません。
- Qt メールボックスは最大 256 イベント、内容 32 MiB です。通常データは最大 128 枠で、残りは終端・制御イベント用です。Rust イベントごとに Qt コールバックを作りません。
- 一つの通知チェーンは一回につき最大 32 イベントまたは約 4 ms を処理し、残りがあれば次の処理を投稿します。単一イベントの処理は途中で中断できません。キューが空になると予約を止め、受信側は条件変数で待機します。
- Open の Page には完全な上限付きディレクトリインデックスも含まれます。最大 32,768 ノード、名前・接頭辞合計 4 MiB で、`replace_directories` により置き換え対象と示します。空のインデックスも明示的に置き換えます。Browse はインデックスを再送せず、`navigation_limited` は縮小されたインデックスを明示します。Rust は名前と接頭辞のバイト数を計上し、Qt メールボックスはブリッジ生成のノード ID と親 ID 文字列も計上します。ノードコンテナーと深さには別の上限があります。対応する要求の Finished が成功してから、新しいページとディレクトリモデルを一緒に適用します。
- Page の `total` は現在の一覧行数、`archive_total` はアーカイブの物理レコード数を独立して保持します。通常閲覧は現在のディレクトリ直下のファイルとディレクトリを一覧し、検索は物理的な一致を再帰的に返します。明示レコードのないディレクトリは `navigation_id` と `physical=false` を使います。Qt 行キーは `dN`、元の物理 ID は別に保持され、仮想ノードは Preflight を送信できません。行メタデータには完全パスを保持し、通常閲覧では末尾名、検索では完全パスを表示します。
- 文字列予算は RSS ではありません。コンテナー、スナップショット、変換中の一イベントに追加領域が必要ですが、項目とページは引き続き制限されます。ブリッジのバッチは最大 128 項目です。元の 100,000 項目走査基準は [ZIP 閲覧契約](zip-readonly-browsing.md)、通常の単一ファイル ZIP に対する後の拡張は[大規模アーカイブのインデックス](large-index.md)を参照してください。

制御イベントと通常イベントは交互に取り出し、キャンセル確認応答が続いても通常の終端状態が処理されなくならないようにします。配信時に単調増加するシーケンス番号を付与します。Qt は古いシーケンスを破棄し、制御確認応答と古い request_id は現在の表示を変更しません。

独立したタスクチャネルの `Task`/`TaskUpdate` エンベロープは、元のタスク作成 request_id を保持します。相関レコードは上限付きタスク制御枠に保持され、タスクの終端状態の配信時に解放されます。受け入れデータより先にも、要求の Finished より後にも到着し得ます。二つ目の通常データ枠を消費せず、通常要求を再び解放・完了することもありません。準備中の仮表示を実際の TaskId と元セッションに正しく結び付けます。この ID はキャンセル要求 ID ではなく、タスク制御には引き続き TaskId を使います。

<a name="xdzip-shutdown-destruction-and-failure"></a>

## シャットダウン、破棄、障害

個別のアーカイブを閉じたりウィンドウを閉じたりしても、アプリとタスクがトレイで動作し続ける場合があります。アプリ終了・再起動時、コーディネーターは受け入れを止め、キャンセルを要求し、Rust がセッションを解放する間イベントを取り出します。受信側は Rust の両スレッドの終了を待ってから `ShutdownReady` を返します。デスクトップは終了前に Qt 受信側の終了とメールボックスの排出を待ちます。GUI スレッドはファイル作業やイベント配信を待つスレッドの終了を待ちません。

キャンセルとシャットダウンの制御はデータキュー容量に依存せず、上限付き状態操作を含む短いクリティカルセクションを使います。協調キャンセルでは OS によってブロックされた読み取りを中断できず、厳密なリアルタイム終了は保証しません。ここでの読み取り専用要求は出力トランザクションを生成しません。作成・展開の確定、一時領域のクリーンアップ、終了結果は[作成](../../engineering/zip-creation.md)と[安全な展開](../../engineering/zip-safe-extraction.md)の契約にそれぞれ従います。

QObject が早期に破棄された場合、メールボックスを閉じ、受信側を起こし、サービスを停止します。バックグラウンド作業が保持するのは共有キューと Rust 受信側ハンドルのみで、コントローラーへのポインターは持ちません。Qt は破棄されたオブジェクトへの通知を自動的にキャンセルします。イベント消費コールバックが接続を同期的に破棄する場合も QPointer が寿命を保護します。受信を放棄するときデストラクターでスレッド終了を待たず、作業は協調的に終了します。正常な ShutdownReady のみがスレッド待機の完了を示します。

読み取り専用ワーカーハンドラーで巻き戻し可能な panic が発生した場合、境界で捕捉し、サービス全体を破棄して RuntimeFault を送り、未完了要求を runtime_unavailable で終了します。セッションは再利用しません。これは読み取り専用の失敗のみを定義し、途中までの作成・展開トランザクションの回復を保証しません。確定済み項目、不確実な結果、書き込みのクリーンアップは各契約に従います。回復不能なメモリー確保失敗、プロセス中断、破損状態の内部ロックでは終端イベントの配信を保証しません。予期しない EOF や接続障害では、Qt は保留状態を一律に終了して永続的なビジー状態を防ぎます。

<a name="xdzip-verification-and-build"></a>

## 検証とビルド

[共通の検証方法](../../../developers/qa/README.md)を参照してください。Rust コアテストに Qt は不要です。Qt のウィンドウ、モデル、負荷、シャットダウンのケースは三つのプラットフォームでネイティブにビルド・実行されます。macOS CI はアプリを配備・アップロードせず、arm64 と SDK 環境での Cocoa 起動を検証します。明示的な要求によりローカル開発 DMG を作成できます。Windows/Linux は同梱 Qt を配備し、SDK なしでの実行を検証します。[ビルドガイド](../../engineering/developer-build.md)を参照してください。これらの検査は正式リリースの承認を意味しません。

最初のクエリーは不変の結果識別情報を割り当て、後続バッチはすべての QueryKey フィールドとパラメーターに一致しなければなりません。Qt は古い要求をキャンセルして最新の意図をまとめ、シーケンスと要求 ID の検査を維持します。バッチの名前は合計 64 KiB 以下で、再フィルタリングや再ソートはしません。過去の受け入れは当時利用可能だった機能に限られます。

アプリケーション層は複数の独立した接続を作成でき、ドメインランタイムは接続ごとにセッションを分離します。グローバルなタスク識別と重いタスクの逐次受け入れは[アプリケーションセッション契約](../../engineering/application-sessions.md)を参照してください。
