# ISO9660 と Joliet の作成

[English](../../engineering/iso-creation.md) | [简体中文](../../zh-CN/engineering/iso-creation.md) | [繁體中文](../../zh-TW/engineering/iso-creation.md) | 日本語 | [한국어](../../ko-KR/engineering/iso-creation.md) | [Français](../../fr-FR/engineering/iso-creation.md) | [Deutsch](../../de-DE/engineering/iso-creation.md) | [Español](../../es-ES/engineering/iso-creation.md) | [Português (Brasil)](../../pt-BR/engineering/iso-creation.md) | [Русский](../../ru-RU/engineering/iso-creation.md)

最初の書き込みモジュールは、2048 バイトのセクター、ISO9660 の主名前空間、Joliet の補助名前空間を持つ、起動用ではない単一のデータイメージを作成します。[ECMA-119 第 5 版](https://ecma-international.org/wp-content/uploads/ECMA-119_5th_edition_december_2024.pdf)と、付属書 C に掲載されている Joliet の仕様に従います。外部のイメージ作成エンジンをリンクしたり起動したりしません。

通常ファイルと明示されたディレクトリのみを受け付けます。Joliet はビッグエンディアンの UCS-2 で名前をそのまま保存し、各構成要素につき最大 64 文字まで対応します。ファイルバージョンのバイトと親ディレクトリ数を含むエンコード済み Joliet パス全体の上限は 240 バイトです。補助面の文字、`*`、`?`、`;`、安全条件を満たさない相対パス、重複パス、親の欠落、ファイルとディレクトリの競合は書き込み前に拒否します。主識別子には一意で決定的な ASCII の別名を使います。Joliet に表示する元の名前は維持します。ディレクトリ階層はルートを含めて 8 レベル、ディレクトリ数はルートを含めて 65535、ファイルサイズは 4 GiB 未満、イメージ全体は 20 GiB、計画するメタデータは 64 MiB が上限です。タイムスタンプは UTC を使い、ディスク上で表現できる範囲に制限します。

ファイルの内容をストリームで書き込む前に、両方のディレクトリツリーとリトルエンディアンおよびビッグエンディアンのパステーブルを計画します。ディレクトリレコードはセクターをまたぎません。各セクターはゼロで埋め、両方の数値表現を一致させます。固定した入力インデックスでストリームにアクセスし、ファイルシステムのパスにはアクセスしません。キャンセル、短すぎる入力や途中で増える入力、出力エラー、リソース上限の超過でエンコードを停止します。一時ファイルを確定できるのはホストだけです。

確定前に完成したイメージを開き直し、列挙順によらずデコード済み Joliet 名でレコードを照合し、デコードしたファイルのバイト列を固定したソースと比較します。任意の ISO イメージの構造検証は、このソース比較とは別です。ISO は通常ファイルのチェックサムを提供しません。独立した読み取り実装で、主名前空間の別名、正確な Joliet 名、ファイルのバイト列を確認する必要があります。

UDF、Rock Ridge の書き込み、El Torito と起動用イメージ、圧縮、パスワード、分割ボリューム、既存イメージの変更には対応していません。CLI とデスクトップは同じ作成レジストリーとタスク経路を使用します。
