# RAR 独立実装の根拠と互換性の境界

[English](../../engineering/rar-format-sources.md) | [简体中文](../../zh-CN/engineering/rar-format-sources.md) | [繁體中文](../../zh-TW/engineering/rar-format-sources.md) | 日本語 | [한국어](../../ko-KR/engineering/rar-format-sources.md) | [Français](../../fr-FR/engineering/rar-format-sources.md) | [Deutsch](../../de-DE/engineering/rar-format-sources.md) | [Español](../../es-ES/engineering/rar-format-sources.md) | [Português (Brasil)](../../pt-BR/engineering/rar-format-sources.md) | [Русский](../../ru-RU/engineering/rar-format-sources.md)

自社 RAR 移行では、旧形式、RAR5、RAR7、パスワード、ヘッダー暗号化、ソリッドアーカイブ、認可されたボリュームを含む読み取り専用の全範囲を維持し、RAR エンコーダーは開発しません。機能の置換と公式依存関係の除去は引き続き[移行タスク #51](https://github.com/xiaodaozhi/xdzip/issues/51)に従います。コンテナーコードや Store の読み取りだけでは完全移行を証明できません。現在のルーティングとソースは[分離バックエンド契約](native-codecs.md)を参照してください。

## ソースと役割

現行コンテナーフィールドは RARLAB の [RAR 5.0 形式技術説明](https://www.rarlab.com/technote.htm)に従い、RAR7 アルゴリズムの識別は [UnRAR7 説明](https://www.rarlab.com/unrar7notes.htm)を参照します。技術説明は圧縮、旧パスワード、VM、チェックサム調整アルゴリズムを完全には公開しておらず、欠落した状態機械を方式名から推測できません。オンライン説明には独立した版番号や署名がなく、保存した HTML を上流の署名付きリリースとして扱いません。

公式説明にない旧コンテナーと受け入れ動作について、独立した解析者が固定した UnRAR ソースから事実のみの引き継ぎを作成しました。参照元の上流内部バージョンは 7.30 beta1 です。ダウンロードアーカイブの名前は `unrarsrc-7.3.1.tar.gz` ですが、それによって別の上流リリースバージョンが証明されるわけではありません。アーカイブの SHA-256 は `634900842a3737d9cc15bbcc71d4c74cc713437e0bca296a573424fe5f2660ab` です。UnRAR ライセンスが適用され、正確な元のライセンスと来歴は[有限マッピング資料](../../../third_party/rar-wire-mappings/README.md)を参照してください。コンテナー、現行 LZ とフィルター、ソリッド処理、パスワードの引き継ぎは別々です。一つの文書で他のアルゴリズムの解析完了を証明することはできません。

最初のコンテナー実装者は参照コアを読まず、公式文書と、参照コードの表現を含まない数学的引き継ぎ `RAR-CONTAINER-2026-10-26-v1` を使いました。固定したコンテナー事実の SHA-256 は `116ed2926619ea3009f00a6b6991f5d939581bca30a2060df2c77c51724f9839`、Unicode 補助境界は `b456b85b59e97c96c78c1936df6d46c893a9f9b26cc61511cfc411dec20a2750`、来歴は `b68b0def40ca7b7f3220fa6caf928f239113366bf9a1969372c52063ce240827` です。その後の旧サービス互換性補足では、元のコンテナー作者がコード固定後に範囲を限定したヘッダー解析とバイト読み取りを読み、事実解析者となってそのコンテナーの変更を停止しました。別の未閲覧の実装者が数値事実から最終的なサービス受理を独立して完成しました。旧サービス補足の本文 SHA-256 は `2554d6752cd5c8e0f59f97c5a90a9291ba2d8908960a65f50e1c5b54301bad08`、固定済み一覧は `39cad28299020679ab1a8e98e723c3eb8310008861bcea9c6ba76aa80f8fc853` です。生成した事実、ソース範囲、検証報告はローカルまたは CI の工件として保持し、参照コード、構造、コメント、逐行翻訳をコピーしません。これは厳密なクリーンルーム開発やライセンス上の結論ではありません。参照ツールと過去の提供物には引き続きライセンス義務があります。

後のエントリーコメント補足では、実装者が形式上の事実を確認するため、公開された [UnRAR のヘッダー宣言](https://chromium.googlesource.com/chromium/src/+/refs/tags/117.0.5865.1/third_party/unrar/src/headers.hpp)とヘッダー・コメント解析を参照しました。参照コードはコピーしておらず、この補足について以前の実装者分離を主張しません。

現行 LZ は事実のみの `RAR5-RAR7-LZ-FACTS-2026-10-26-v1` を使い、一覧の SHA-256 は `b86978fb63c90c38b4dc0fa0831a27598fff12407f561d25fef8d923d83f8ea5` です。LZ コアは `02e31d56e5a1538d5b0d72222908e2dcc626259e68ec00e6d32e11b5cb92df13`、受け入れ境界の補足は `7fdef948fdd8ab82376ed1aa8f1a3bba6016569fb1c036f5e0ec53f8f37d0e49`、フィルターは `09933ca42c68676a63092a3de9fecb38dda4086cac13a1b7a63f9bc0f818fb30`、RAR7 の差異は `43ada71358a7df4f2c6ed84f0e7661dfeb16169e7f6d1bee3cebe46f6243139c` です。Store とウィンドウの補足 `RAR-SOLID-STORE-WINDOW-2026-10-26-v1` は `37de8e2d60a96ba92c0e4b400c77556d15a0adc448bc94e4328144979d0713f4` です。実装者は対応する参照コアを読まず、RAR 圧縮エンコーダーも開発しません。固定した宣言型の数学ビットベクターはテストデータであり、独立した作者圧縮サンプルではありません。

プロジェクトは独自の予算、順次書き込み、ソリッドの不変条件を使い、大きな論理辞書向けの Constant/Raw ストレージを独立して設計しました。実装者が読んだのはプロジェクトの設計と数値事実であり、対応する第三者デコーダーではありません。実際の RAR7 テストデータ解析者が実装者に渡したのは、固定したアーカイブ識別、ヘッダー数値、既知の全ゼロ生成手順、ツール記録のみです。テスト入口がダウンロードするのは圧縮データと元の通知であり、上流実装や README ではありません。スクリプトで生成した資料記録はテストデータの来歴とライセンスの境界を保持しますが、法的結論を示すものではありません。

現行暗号バージョン 0 は事実のみの `RAR5-CRYPTO-FREEZE-2026-10-26-v1` を使います。パスワードとラッピング本文は `029f03e1cf7dff2ae804fb99f7dbacb8ac0306498476119a4d851cbe9a52e9fb`、BLAKE2sp プロファイルは `1574159e24c956a2287d605501dff63f1ee67d0028cfd9fe3dadcdbbeee8f795`、来歴は `e13a21f12cc3df777d8d1d2332e38d9e525aceed02ddb0ce93a54c4cf8a2577a` です。共通 `xdzip-crypto` が独自の SHA256 状態ラッピング、RFC2104 HMAC、BLAKE2s/sp 構成を提供します。AES と SHA2 圧縮プリミティブは汎用依存関係の採用規則に従い、参照のラウンド関数や表を書き換えません。

RAR29 PPM は事実のみの `RAR29-PPM-2026-10-26-v1` を使い、本文 SHA-256 は `9425e386ee75acac31f843d61480b02dbba7ed56ae6ef550e45e54fd8ee32114`、来歴は `4de014dc4cf1de581d32e10c6b166bc2e14542c04ca1cc6cf46cee1dced39482` です。ファイル再入、圧縮末尾、エスケープの補足 `RAR29-PPM-BOUNDARIES-2026-10-26-v1` は本文 `540795a89e33a2bbf43b3317f30b8c0f0550884740f0230594f33cf949a9aa92`、独立固定物 `e3b6e475bd2c7438de3c366c19d2f156bcaec6ca7426c250aff1e61eb04ae8e5` です。実装者は対応する第三者のモデル、レンジ、アロケーター実装を読んだり翻訳したりせず、プロジェクト独自の PPMd H 統計モデルと数学的補足を再利用しました。元の PPMd のパブリックドメイン宣言は RAR ラッピングや他の変更を自動的に再ライセンスしません。参照ツールと公開フィクスチャーはそれぞれのソースとライセンスを保持します。

RAR29 LZ と 6 種の標準フィルターは事実のみの本文 `e375c541e106d43a3e58a2fe8aab79f60ffc71beff08b76c2a66f26d0fd355cb` と `eeecbd9a247d4a8c98e3d1cd11371106c16fbb5bd565406731908241e7432d8a` に従い、旧パスワード本文は `9650bce5affb20ea4d616e1e68c25d52e5fa703bd0b7c56b3915fad825abdcb4` です。最古コンテナーの補足 `RAR14-CONTAINER-2026-10-26-v1` の本文は `d3a86f3cad6e1893959d40cc691e7c7d4ddfec4b96abc9f4ba12ea98fd7f484c`、独立した固定一覧は `e6adcbf16ad688c82ad5bd39ae7cdd4379003ae82dd19b30b4dd53ce52223f9c` です。これらは数値、境界、受け入れ動作のみを引き継ぎます。各実装者は担当モジュールの初回実装時に対応する UnRAR コアを読んでいません。固定した公開アーカイブと公式ツールは引き続き独立したブラックボックス参照専用です。

13/15 系列は旧アルゴリズムの事実本文 `d4cd5d61ee4b16fa7202cb6840d0e9592d67205c4fdbfd02f3e515320ebf96ef` に従います。有限プレフィックスと Short のマッピングは独立したデータ表の引き継ぎであり、SHA-256 はそれぞれ `2e50aa5c3c9f97609cf7b7c91676b7266de9ca65ee977f9184c42ec104c9edeb` と `31d4186b3dbf06bdbf5aabd5f08cfa800bc810709cfd042fe6f32ef22c9cad1b` です。ソースは引き続き固定した UnRAR 参照です。有限ワイヤーマッピング、独立した CSV、独自の Rust 構成は著作権や再ライセンスを決定しません。

旧コンテナーの例外と Windows ホストの文字投影には追加固定物 `RAR-COMPATIBILITY-GAPS-2026-10-26-v1` を使い、事実本文は `142e47f9a3c2920e0e0c674555df669ecde0bc29549a9a45f03133d11957a4ef` です。Unix/macOS の追加事実 `RAR-COMPATIBILITY-GAPS-UNIX-2026-10-26-v2` は `3853684c35ee672956ccaadb3efc1f1fffb58e0a7fa472d41c261fbacd69a479`、時刻投影の事実は `2ea490c2304c8fe5188af371d77fe9013b23ae66e6ff4fe05cf489cb7c914a20` です。純粋なシステムサービスはローカル文字と暦の変換のみを行い、形式選択、制限、切り詰め、DOS 演算は Rust に残ります。システム失敗を検査しない参照動作は未初期化データを返す許可にはなりません。

ソースの分離は実際の閲覧状況に従って記録します。現行 ARM の実装と数学テストの完了後、テストデータの検索結果要約に別の第三者デコーダーの ARM 式が偶然表示されました。既存の ARM 実装をその時点で固定し、その実装者は以後アルゴリズムを変更しません。修正が必要な場合は未閲覧の実装者が事実の引き継ぎから行います。伸長コアを未閲覧という説明は、第三者の断片を一度も見ていないという意味ではなく、上記の後日の範囲限定サービスコンテナー閲覧も含みません。正確な検索、閲覧範囲、時系列はローカル工件に保持します。

## コンテナー候補契約

`xdzip-codec-rar` はプロジェクトの codec API とドメイン、共通圧縮と暗号、および採用された汎用 AES、SHA2 圧縮プリミティブ、ゼロ化に依存します。CRC32 は共通実装を再利用し、第三者の RAR、アーカイブ、圧縮形式ライブラリーを導入しません。`MetadataCodec`/`PayloadCodec` を実装し、既存の分離ワーカー内で共通 CXX ブリッジを経由して動作します。失敗時の公式フォールバックはありません。接続だけでは完全な互換性受け入れの代わりにならず、製品経路の切替は[移行契約](independent-rust-codecs.md#实现边界)に従います。

- ホストは順序付きの認可ストリームと各物理ボリュームの長さを最大 1,024 個供給します。絶対位置への変換前にボリューム内の範囲を確認します。アーカイブ名はパスアクセス権を与えません。各ボリュームヘッダーを再識別し、形式世代、ボリューム番号、ヘッダー暗号化状態、継続関係を確認します。明示された前後分割のみを統合し、通常の重複名は別の識別を保持します。通常ファイルとサービスの継続チェーンは別々に保持し、サービスは通常の EntryId を消費しません。
- 通常の 1.5..4 ヘッダー検査には通常 CRC32 の下位 16 ビットを使い、現行ヘッダーは完全な CRC32 を格納します。それ以前の 1.4 コンテナーにはヘッダー CRC がなく、別の内容チェックサムと混同できません。制限付きフィールドや追加データを解釈する前に、通常の平文ヘッダー検査を行います。現行 vint は最大 10 バイトで、最終バイトは有効な 0/1 ビットのみです。数学的な値が正しければ最短でない表現も許可します。head-size 自体は最大 3 バイト、平文ヘッダー全体は最大 2 MiB です。未知でもスキップ可能な追加データは範囲内で飛ばし、未知の必須デコード機能を通常内容の成功に見せかけません。
- 非公開インデックスは各断片の元ヘッダー、ボリューム／ヘッダー／圧縮範囲、既知または未知のサイズ、生の名前、デコードバージョン、圧縮強度、宣言および実効アルゴリズム、辞書、ソリッド状態、時刻、種別、CRC／ハッシュ、パスワード記述を保持します。公開 method は 50 や 70 などの UnpVer を保持し、公開 packed_size は最初に見える断片の圧縮サイズであって合計ではありません。EntryId は最初に見える通常レコードの順に 1 から連続して割り当てます。
- 宣言された旧 Unicode はまず数学的コマンドで解決し、それ以外は共通のアーカイブ単位の旧文字コード検出を使います。生の名前領域を保持し、マルチバイト内の `0x5c` を分割しないよう旧区切りを文字デコード後に変換します。Unicode サロゲートは完全に対になる必要があり、切れたコマンド、埋め込み NUL、範囲外コピーを拒否します。RAR5 は宣言された UTF-8 を厳密に検証します。Unix の名前マッピングとリダイレクトは警告を保持し、リンクや特殊オブジェクトを通常出力できません。
- メタデータ読み取りは最大 64 MiB、物理ヘッダーは最大 100,000、名前はそれぞれ最大 4,096 バイト、生名前合計とデコード／表示テキスト合計はそれぞれ最大 16 MiB です。呼び出し元のより低い制限が優先します。ペイロード再スキャンは元の入力許容量を累積し続け、実入力とデコード作業はそれぞれ最大 20 GiB、ファイルは最大 8 GiB です。アルゴリズムの作業領域は実行前に既定 1 GiB のメモリー上限内で受理します。
- 注入されるアルゴリズムが受け取るのは制限付き平文圧縮ストリーム、借用した制御、ホストシンクのみです。コンテナーは断片の圧縮データ検査、復号、入力全体の消費、正確なファイルサイズ、最終的な内容全体の検証を扱います。アルゴリズムは状態、圧縮ストリーム終端、メモリー事前検査を担当します。候補は Store、13/15、20/26、RAR29 LZ/PPM、現行 LZ を実行し、ファイル全体を蓄積せず最大 8 KiB のブロックを出力します。ディレクトリーはサイズと圧縮サイズがゼロであること、元ヘッダーの再検証、必要な空内容検査を終えた後にのみ完了します。名前の警告、リンク、特殊レコードは先に拒否し、公開エントリーの受理を回避できません。
- 識別済みのドメイン I/O エラー分類を優先して保持します。ラップされたエラーのない単独の Interrupted のみ再試行できます。キャンセル、クォータ、ソース変更、I/O、出力失敗、検証失敗はインスタンスを失敗状態にします。失敗は EOF、entry_done、公開資格ではありません。ホストはソース識別、パス検査、非公開一時配置、最終コミットを保持します。公開 DecodeError には現在独立した SourceChanged バリアントがなく SourceIo に対応付けますが、ソースホストは具体的な原因を保持します。

## 現行 LZ 候補仕様

- 実効アルゴリズム 0 は 64 個、アルゴリズム 1 は 80 個の距離シンボルを使います。宣言されたバージョン 1 の互換性ビットがあっても実効アルゴリズム 0 が選ばれます。ツールのバージョンや拡張子でツリーを選んではいけません。独立した MSB ビット読み取りと正準 Huffman ツリーは宣言された有効ビットを消費し、Deflate の LSB 順序は使いません。新しい表が対象とするコード長はそれぞれ 430/446 個です。未使用ツリーは空でも構いませんが、存在しないコードの消費、過剰な符号割り当て、範囲外の繰り返しは明示的に失敗します。
- ブロックヘッダー検証、最終バイトの有効ビット、最終ブロックフラグが共同でビットストリームの終端を決定します。既知の出力サイズ、最終内容 CRC、圧縮データの完全消費は別々に検査します。宣言サイズを出力しても早期成功にはなりません。空ブロックで符号なし演算をアンダーフローさせず、有効な表なしに内容をデコードできません。候補は範囲外の繰り返し、未完了のフィルター範囲、圧縮データ末尾に厳格な方針を適用します。健全なサンプルは過去の全復旧動作との等価性を証明しません。
- 非ソリッド圧縮ファイルでは有効な辞書履歴、直近距離、最後の長さ、表をリセットします。ソリッド圧縮ファイルではこれらを保持し、入力ブロック、フィルター、ファイルオフセットはファイルごとにリセットします。最初の圧縮ファイルで決まる実効ウィンドウを使い、作業ウィンドウの最小値は 256 KiB です。2 の累乗でないウィンドウは実際の剰余で循環します。後続の小さい宣言や 2 の累乗でない宣言は剰余を変えません。ストリーム途中の拡大は、旧割り当てキャッシュに依存した不正チェーンの例外を再現せず Unsupported を返します。非ソリッドの置換前に旧ウィンドウを解放し、大きなウィンドウが二つ共存することを避けます。
- Store はソリッドビットの有無を問わずファイルをコピーして検証し、LZ 履歴には追加せず、表、直近距離、最後の長さも消去しません。ディレクトリーとサービスは新しい圧縮初期化地点ではありません。ソリッドファイルを任意選択すると、直前の非ソリッド圧縮ファイルから復元し、物理順にプレフィックスを実際にデコードします。Store は再開始地点ではなく、スキップと繰り返し再生は実作業として計上します。
- Delta、x86 E8、x86 E8/E9、ARM フィルターはそれぞれ完全で独立した論理範囲を処理します。フィルター前のバイトは常に LZ 履歴を形成し、変換したコピーをファイル CRC とシンクに渡します。範囲はブロックや物理ボリュームをまたげますが、ファイルはまたげません。開始位置とファイルオフセットをリングインデックスと混同してはいけません。範囲は最大 4 MiB、保留項目は最大 8,192 個です。重複、逆順、未知の変換、未完了範囲を拒否します。これらは候補のリソース方針であり、形式上の極限を主張するものではありません。
- 命令バッチは最大 8 KiB の出力または 256 命令を計画します。実行前は残り作業をローカルにのみ予約し、未実行の進捗を公開シンクに報告しません。実行後、部分失敗やキャンセル前に完了したバイトも含め、実際の WORK のみを精算して一度限りの前払い許容量に変換します。未実行の予約は出力に充てられず、失敗後に再利用しません。完全なフィルター範囲を一時配置する間も実作業を累積します。前払い配送前にコンテナー内の非公開クレジットを差し引き、最終サイズ、CRC、キャンセル、書き込み失敗の検査を維持します。既定シンクは保守的に再計上する場合があります。Store は通常の出力計上を使います。ワーカーは計上済み RAR 内容を PRECHARGED_DATA で送り、Native 受信側とランタイムはホストクレジット、正確なサイズ、クォータを独立して検査します。再開始、完了、失敗後に旧ワーカークレジットは再利用できません。
- 上限付きメタデータ、フィルターコピー、キュー、その他の状態のために LZ 辞書の外側に 288 MiB を予約し、ワーカー上限 1 GiB に対して一括受理します。これは保守的なメモリー方針であり、ワイヤー形式の最大辞書ではありません。宣言サイズは割り当てを許可しません。キャンセルやエラーはペイロード状態全体を失敗状態にし、部分的な辞書を保持したまま別エントリーへ進めません。

### 大きな論理辞書の正確な保存

現行の実効アルゴリズム 1 の圧縮ファイルで、辞書全体が密な保存方式の受理範囲を超える場合は、最大 1 TiB の論理ウィンドウを持つ正確な Constant/Raw ページ履歴を使います。ページは 64 KiB で、一定の 1 バイト値または専有する Raw バッファーを保持します。読み書きと距離は元の論理ウィンドウの実際の剰余を使います。未生成の履歴は読めず、重複する一致は 1 バイトずつ実行します。履歴はフィルター前の内容を保存し、最終出力バッファーを共有しません。他のアルゴリズム、Store、未知の方式、サービスレコードには大辞書の例外を与えません。

ページディレクトリー、スロット表、空きプール、保持する全容量、一時的ピーク、非公開状態、アロケーター許容量 16 MiB の合計は最大 512 MiB です。外側の 288 MiB とパスワード状態は別で、ワーカー上限 1 GiB は維持します。すべての割り当て前に予算を確認し、論理ウィンドウのサイズに応じて巨大なアドレス空間を予約したりディスク履歴に切り替えたりしません。定数ページに異なる値を書き込む前に Raw ページを完全に初期化します。有効なページ長全体が同じ新しいバイトで順次上書きされた場合にのみ定数へまとめます。部分ページのソリッド継続では元の末尾と候補状態を保持し、非ソリッド置換では先に旧ストレージを解放します。プールに戻したバッファーも実容量で計上し続けます。

ディレクトリー、スロット表、Raw ページの実際の初期化は別の補助作業チャネルを使い、キャンセルを確認しながら最大 8 KiB のブロックで精算します。ファイル進捗や配送クレジットは増やしません。出力バイトを受け入れる前に失敗し得るストレージ準備を完了し、その後は割り当てなしに履歴をコミットします。出力の拒否は履歴バイトもカーソルも変更しません。完了した初期化は返金されず、エラーはペイロードを失敗状態にします。定数ページを効率よく扱えますが、任意の低エントロピーストリームや大辞書が収まる保証はありません。過大な Raw 作業セットは明示的に Limit を返します。

実際のアルゴリズム 1 の相互運用検査では、固定した圧縮テストデータと通知のみを build または CI に取得し、大きな平文や第三者実装を保存せず、元ヘッダー識別、平文全体の SHA-256、CRC、サイズ、WORK、AUX、保持容量を検査します。数学的ページテストと独立した健全な圧縮ストリームは別々に記録します。一つの成功ストリームは、すべての拡張距離や暗号化、ソリッド、ボリューム横断の組み合わせの受け入れを証明しません。

独立して既知の現行 x86 平文は[管理された PE データ生成手順](../../../crates/xdzip-codec-rar/tests/fixtures/modern-x86-owned/README.md)で検査できます。公式作者によって通常生成されたストリームが実際に E8 または E8/E9 を選択し、直接 LZ、Payload、実際のワーカーを通る完全な内容検査に合格する必要があります。PE 名、ツールバージョン、記述子数だけでは不十分です。テスト入力は実行せず、PE ファイルや生成アーカイブはリポジトリーに保存しません。他のソリッド、暗号化、ボリューム横断の組み合わせは別々に受け入れます。

## RAR29 PPM 候補仕様

- `xdzip-compression` は順序付き統計コンテキスト、二値確率、SEE、除外、後続状態の実体化、名目容量台帳を共有します。RAR29 と 7z は統計を重複実装せず、異なるレンジアダプターを通じ同じモデルを使います。RAR は 4 バイトのキャリーなし初期値、独立した正規化、両分岐で除算余りを捨てる二値区間を使います。7z は 5 バイトの初期値、余り、終端規則を維持します。
- モードヘッダーは完全に整列した F バイトから始まります。リセットビットがモデル全体を再構築するか決め、メモリーフィールドは名目容量 1..256 MiB を表し、order はヘッダーフィールドを符号化可能な 2..64 に対応付けます。任意のエスケープは宣言時のみ変更し、リセット時に自動復元しません。保持要求には、継続性が確立された有効な既存モデルが必要です。各モード初期化は 4 バイトのレンジを再構築し、ヘッダーなしのファイル横断継続で代用できません。以前のモデルがない独立した任意開始点は明示的に失敗します。
- 名目 12 バイト単位と決定的なクラス、断片化、結合、借用の規則が、形式で指定されたモデル再開始を制御します。Rust オブジェクト、履歴、インデックス、走査用一時領域、固定状態、その他のデコード状態は実ストレージに基づいて別々に受理します。リセットでは大きな割り当てが二つ共存しないよう、先に旧 arena を解放します。容量による再開始は、すでにデコードした現在のシンボルとレンジを保持します。実際の OOM、クォータ、キャンセル、ソース I/O、モデル不変条件エラーは終端失敗であり、容量再開始に見せかけられません。
- 新 arena の初期化と容量再開始では、まず補助作業予算を受理します。実際の充填と消去は最大 64 KiB のストレージチャンクと制限付き確率表の行で実行し、キャンセルを確認して完了した初期化バイトを累積します。その後のレンジ読み取り失敗、キャンセル、`clear` は完了作業を返金しません。外側は成功時と失敗時に実際の差分を制御／パラメーターシンボルの補助作業とともに累積 20 GiB の上限に対して精算します。別の AUX は前払いファイル配送クレジットを与えず、将来の予約は実進捗ではありません。
- PPM は統計更新と正規化を完了した後にモデルバイトを一つ渡します。エスケープ、フィルターパラメーター、一致パラメーターはいずれも通常どおりモデルを更新します。RLE または LZ コピーで生成したファイルバイトは PPM にフィードバックしません。外側はファイル終端、モード切替、出力サイズ、内容 CRC、宣言された圧縮境界を検証します。RAR はルートからのエスケープを 7z END として受理せず、7z の最終コードゼロ条件も課しません。失敗したモデルは外側の復旧で明示的に消去するまで失敗状態を保ちます。
- 実際の PPM EOF 後は、入力クォータ、キャンセル、断片検査を続けながら、宣言された完全な圧縮範囲内でのみ残り入力を読み尽くします。PPM 算術末尾には現行 CBC の 0..15 バイト整列上限を適用しません。実 EOF 欠落やサイズ／CRC 不一致を末尾方針で成功にできません。後続のソリッドファイルはモードヘッダーと新しいレンジを読み直し、リセットビットがモデル保持を独立して決めます。固定した参照はエスケープ後の制御 1 と 6..255 に対しリテラルエスケープを出力します。候補が 6..255 を厳格に拒否する場合は受け入れ差を別途記録し、参照も拒否すると主張してはいけません。

## RAR29 LZ と標準フィルター候補仕様

- RAR29 は MSB ビットストリームを独立して読み、404 個の差分コード長で 299/60/17/28 シンボルのツリーを構成します。以前のコード長基準、下位 4 ビット距離の繰り返し、直近 4 距離、最後の一致長は圧縮状態に残ります。この旧アルゴリズムに現行の 64/80 距離表を適用しません。ファイル終端は次のソリッドファイルがモードを読み直すかも制御します。未初期化状態の再利用、空ツリーの消費、範囲外の繰り返し／出力、履歴より前の距離は失敗します。
- 外側の PPM エスケープはファイル終端、モード切替、リテラルエスケープ、フィルター、2 種のコピーを制御します。パラメーターバイトは引き続きモデルを通じてデコードし、一致出力は LZ 履歴と最終ファイルストリームにのみ入り、統計モデルにはフィードバックしません。PPM EOF 後の残り圧縮データ読み尽くしと、純粋な LZ ビットストリーム終端は別の方針です。
- 標準フィルタープログラムはまず制限付きパケット、プログラム長、XOR、固定 CRC／長さの識別を確認します。製品基準として確立した E8、E8/E9、Itanium、Delta、RGB、Audio の 6 変換のみを受理します。候補はアーカイブ内の任意 VM を実行しません。定義、キャッシュ長、最後の選択はソリッド状態を保持し、オフセットはファイルごとに再計算します。未完了範囲をリセットによって捨てられません。
- フィルター前のバイトは LZ 履歴に残ります。開始位置と長さが同じ標準変換は連結できますが、その他の重複、逆順、未完了範囲を拒否します。範囲は 1..262,143 バイト、定義と保留項目は最大 8,192 個です。これらは候補のリソース方針です。Delta は最大 1,024 チャンネル、Audio は 128 チャンネルで、先にワイヤーパラメーターと初期化バッファーを受理します。
- 旧 E8 PC は現行の 16 MiB 剰余ではなく、完全な 32 ビットファイル位置を使います。Itanium は元のバンドル／テンプレートと命令フィールドを変換し、RGB と Audio は別々の予測状態を持ちます。Audio は最初のサンプルでの適応と -17 までの負係数を含みます。現行 Delta や E8 の数学ベクターは代用品ではありません。
- 実際に変換した各バイト、PPM パラメーター、実際のモデル初期化は補助作業予算を消費します。補助作業は最大 64 KiB の非ゼロ `charge_auxiliary` メッセージで別途精算します。これによって decoded_bytes、展開率の分子、配送クレジットは増えず、ソリッドプレフィックスをスキップしても転送します。ワーカー、Native 受信側、ランタイムはそれぞれ[補助作業契約](auxiliary-decoding-work.md)を強制します。補助量を WORK に通した以前の候補は契約を満たしません。処理ループはチャンクごとにキャンセルを確認し、失敗前に完了した補助作業は返金しません。

## 最古コンテナーと旧パスワード候補仕様

- 1.4 メインヘッダーは `RE~^` を含む最低 7 バイトです。ファイルヘッダーは固定 21 バイトの後に制限付き名前とスキップ可能な追加素材を持ちます。ペイロードは宣言された headSize の末尾から始まります。メインの 0x01/0x08 はボリューム／全体ソリッドを示し、元の 0x80 は後世のヘッダー暗号化ビットではありません。ファイルは 0x01/0x02/0x04 のみを前分割／後分割／暗号化に使います。ディレクトリーは DOS 属性から判断し、後世のファイルウィンドウやソリッドビットを再利用しません。辞書は 64 KiB 固定です。
- 最古の方式値は 0..5 を直接使います。セレクター 2 は公開 UnpVer13、その他は 10 に対応します。圧縮の受理は基準化した 13/15 のみで、10 は Store のみをサポートします。全体ソリッドは 2 番目の論理ファイルから継続し、物理的な継続断片は同じ論理ファイル状態を継承します。新しいファイルはビット読み取りと内容チェックサムをリセットし、Store は圧縮履歴に内容を注入しません。
- 最古形式の各論理ファイルは 16 ビットの c=0 から始まり、実際の最終出力の各バイト x について `c=ROTL16((c+x) mod65536,1)` を計算します。最終 XOR なしに最終ヘッダーの u16 と直接比較します。中間断片の u16 値は圧縮 CRC とみなさず保持します。内容チェックサム全体は断片を横断し、ソリッドの先行ファイルのチェックサムを次のファイルに持ち越しません。同世代アルゴリズムを使う後世コンテナーは通常 CRC32 を使います。
- 最古形式の暗号化は常に salt/IV なしの old13 バイトパスワード系列を使い、selector10 はこれを変えません。後世の 13/15 はそれぞれのバイト系列、20/26 は旧ブロック系列、RAR3 は独自の SHA1 導出構成と AES128-CBC を使います。各論理ファイルに新しい暗号状態があり、物理的な分割断片は連続します。パスワード状態は圧縮のソリッド状態とともにファイルを越えません。old13/15 はブロック整列末尾を受理せず、旧ブロック暗号の Store は実サイズで切り詰めます。RAR29 PPM の宣言末尾方針は別に適用します。
- RAR3 の暗号化ヘッダーはヘッダーごとに 8 バイトの salt を読み直し、最初のブロックを復号して実ヘッダー長を得た後、そのボリューム内の整列済み全範囲と通常ヘッダー CRC を検証します。ペイロード再検証用に元の salt／暗号文を保持します。外側はまず UTF-8 で 4,096 バイトの制限を検査します。旧経路はさらに最初の NUL 後の入力を含め、ネイティブコールバックの入力全体についてローカル wide 511 単位の上限を維持します。その後に初回 NUL 前の内容を取り、暗号処理の 127 単位境界を適用します。これは過去のホスト入口の動作であり、形式のパスワード長仕様ではありません。現行 KDF 入口方針は別です。
- Windows は最古形式でないコンテナーの HostDOS 旧ファイルに限り、ゼロ埋めした 512 UTF-16 単位全体に OEM から ANSI への wide 投影を適用し、wide インデックス 127 で切り詰めます。旧 13/15/20 は次に 512 バイトバッファーで ANSI にエンコードし、生バイト 127 で切り詰めるため DBCS が分割される場合があります。RAR3 は投影した wide 単位の下位 16 ビットを直接使います。最古形式の内容には後世の DOS 補正を適用しません。変換は同期的に借用したホストサービスを使います。OS 失敗は明示的に Unsupported とし、型付きソースエラーとキャンセルは分類を保持します。サービスがない場合は等価性を証明できる ASCII 経路のみを使います。
- macOS の旧 narrow パスワードは最初に Unicode スカラー 127 個を取り、明示的に UTF-8 にエンコードした後、生バイト 127 で切り詰めます。末尾に不完全なシーケンスが残る場合があります。通常の Linux は現在のスレッドロケールの状態付き変換を使い、EILSEQ 再試行後の実際のプレフィックスを保持します。このプロジェクトの独立ワーカーはそのためにプロセスロケールを変更しません。Linux の U+FFFE マーカー付き復旧経路は Rust でマーカーを取り除き、U+E080..E0FF の元バイトを復元し、通常単位をホスト変換に渡します。Apple やマーカーのない文字列には適用しません。Windows 以外の RAR3 wide 投影は元のスカラープレフィックスを保持し、単位の下位 16 ビットを使います。下位 16 ビットがゼロでも元の NUL と誤認しません。中間 wide、narrow、単一文字、鍵のバッファーはゼロ化し、固定投影用一時領域には別に 4 KiB の予算があります。
- 信頼できる独立検証器がない場合、ヘッダー Invalid または内容 Integrity はホストが安全に再試行できるよう PasswordOrIntegrity を返します。SourceChanged/SourceIo、Limit、Cancelled、Output、Unsupported はパスワードの曖昧さに包みません。検証済みの現行チェック不一致は WrongPassword のままであり、検証済み鍵の下での破損は整合性エラーです。再検証時の物理的な元ヘッダー変更はソースエラーであり、暗号文の変更から推測したパスワードエラーではありません。

## 旧補助ヘッダーとプレフィックスの候補仕様

- 埋め込みの旧コメントでは、メイン親の CRC は固定 13 バイトのみを対象にします。ファイル親の CRC は実際に消費した固定フィールド、LARGE、名前、salt、解釈した最初の 3 個の拡張時刻を対象とし、アーカイブ時刻スロットは消費しません。type75 の子は親の HeadSize 内で固定 13 バイトのヘッダー CRC を独立して検証します。コメント内容は範囲内でスキップできますが、内容 CRC の検証を主張したり、参照の後続の全読み取り／BrokenHeader 復旧フローを形式規則にしたりしません。
- AV76 と SIGN79 は common7、LONG の場合の追加 dataSize4、宣言されたデータ範囲のみを使ってスキップします。UO が一般 CRC を迂回するのは正確に type77+subtype0x0101 の場合のみで、共通 14 バイトと宣言範囲から位置を求めます。他のサブタイプと通常ファイルは引き続き通常ヘッダー CRC を検査し、NUL を走査して旧文字列の終端を推測しません。
- END は任意の archiveCRC／ボリューム番号の後、宣言された不透明な末尾をスキップします。厳密な旧例外は、通常の END+REVSPACE CRC が失敗し、この読み取りの終わりより前の物理的な元の 7 バイトがすべてゼロの場合にのみ適用します。これは現在の物理ヘッダー末尾からの相対位置であり、ボリューム EOF からではありません。暗号化ヘッダーでは復号済み論理末尾や END 消費後のトレーラーではなく、物理的な salt／暗号範囲の最後の 7 バイトを検査します。暗号化 REV には引き続き独立した実サンプルがありません。
- 最古形式の SFX はオフセット 1 の特別な受け入れ経路を維持します。オフセットが 2 以上で実スキャン長が 31 バイトを超える場合、絶対 byte28..31 は RSFX である必要があります。完全に認可された検索における最古マーカーの最大開始位置は 4 MiB−19 です。候補は、旧ネイティブの 64 KiB 単一読み取りが返した狭い検索範囲をコピーせず、認可された短い読み取りを範囲内で補完します。プレフィックスは決して実行しません。
- Windows の旧 Unicode で未修正の高ビット連続部分には、検証済みの signed-char から 16 ビット単位への拡張を使います。修正済み連続部分は下位バイト演算を維持し、両者を混同できません。Windows 以外ではローカル ABI と wide 変換の実サンプルを待ち、未修正の高ビット連続部分を Unsupported のままにします。公開文字列は引き続き有効なスカラーであり、共通の名前セキュリティーを通過する必要があります。

## 13/15 系列候補仕様

- 13 と 15 はそれぞれの公開 UnpVer を維持しながら一つの独立した適応デコーダーに入ります。ウィンドウは 64 KiB 固定です。有限の正準コード表、リテラル順位、距離順位、フラグモデル、Short の変種、特殊モードは別々に表現し、後世の差分コード長表を再利用したり別の Deflate/PPM 実装をコピーしたりしません。
- 最初の非ソリッド圧縮ファイルは履歴と統計をリセットし、後続のソリッド圧縮ファイルは辞書、順位、一致状態を保持します。各ファイルはビットカーソルとフラグ／繰り返し／特殊状態を再初期化し、前の残余制御ビットや特殊モードをファイル間で持ち越せません。Store は圧縮初期化を呼ばず、圧縮履歴を充填したり消去したりしません。
- 実出力前に宣言された残りサイズと有効な履歴距離を確認し、一致がファイル末尾を越えないようにします。実際の展開サイズに達した後は、通常の入力クォータとキャンセルを維持してホストが認可した残り圧縮入力をすべて消費します。この世代に存在しない現行の最終ブロックフラグを作りません。実ビットが足りなければ失敗し、ゼロバイトで埋めません。
- 制限付き一致と最大 8 KiB の出力バッチにローカル予算を予約します。成功経路と失敗経路で実行済みバイトを精算し、実際に生成した元のバイトだけが一度限りの配送クレジットを作ります。エラーは圧縮インスタンスを失敗状態にし、新しい独立状態を使えるのは明示的なリセット後のみです。先行状態のないソリッド開始点では復旧できると仮定しません。

## 現行パスワードと整合性の候補仕様

- 平文のアーカイブ暗号レコードは、そのボリュームのメインヘッダー前に一度だけ現れる場合があります。後続の各ヘッダーは自身の IV で AES256-CBC を再開始し、最初のブロックを復号して実ヘッダー長を得て、そのボリューム内の IV 全体と整列済み暗号文範囲を検査します。ヘッダー CRC は実際のフィールドのみを対象とし、整列末尾を追加データとして解析しません。非公開の物理断片はペイロード再スキャン時のバイト単位検証のため元の IV と暗号文ヘッダーを保持します。同等の復号済みメタデータはソース識別の代わりになりません。
- 同じ PBKDF2-HMAC-SHA256 チェーンは `2^L` 回、さらに 16 回、さらに 16 回の反復で AES 鍵、ハッシュ鍵、折り畳みチェックを生成し、`L<=24` です。タスク専用の 16 スロットキャッシュと累積予算はメタデータスキャンからペイロードオブジェクトまで継続し、ファイルやボリュームごとにリセットしません。既定上限は実 HMAC 最大 `2^26` 回、導出ハッシュ入力 4 GiB です。キャッシュヒットでは再導出せず、キャンセル前に行った作業は返金しません。保守的なキャッシュ／一時領域 16 KiB の予算もアルゴリズムメモリーの事前検査に別途含めます。
- 外側のパスワードは UTF-8 で最大 4,096 バイトです。最初の U+0000 で切り詰める前に制限を検査します。ネイティブ互換プロファイルは Windows で最初の UTF-16 127 単位、Unix で最初の Unicode スカラー 127 個を取り、導出バイトを生成します。Windows の切り詰め境界にある単独サロゲートは非公開の互換バイトにのみ存在し、公開 str や名前には入りません。これは参照互換動作であり、形式全般の規則ではありません。パスワード、導出中間値、鍵はゼロ化する寿命を持ちますが、OS の過去のコピーすべての消去は保証しません。
- 不一致時に WrongPassword を返すのは、チェック自体の SHA256 チェックサムが有効で、信頼できない全ゼロの旧サービス値でない場合のみです。不正なチェックサムでは高速検査を無効にしますが、正しい鍵なら構造／内容検証で成功できます。信頼できる検証器なしの Invalid/Integrity は公開 PasswordOrIntegrity による曖昧さを維持し、確実なパスワード誤りとは呼べません。
- 内容 CBC はファイルごとに再開始し、認可された分割断片を通じて継続します。ブロックは一つの断片の末尾と次の断片の先頭を組み合わせる場合があります。各断片の圧縮 CRC/BLAKE2sp は常に復号前の物理暗号文を対象とし、最終内容検査はフィルター後の平文全体を対象とします。現在の候補は断片チェーン全体で完全な暗号パラメーターの一致を厳格に要求し、健全なサンプルでも過去の全分割エンコードの等価性は証明できません。
- Store は展開サイズで実内容を選び、LZ は完全な最終ブロックと有効ビットで終端します。後続には最小限の 0..15 バイトの整列末尾のみを許し、値を制限せず PKCS7 と解釈しません。LZ の先読みバッファーも末尾長に含め、外側 CBC の消費だけでは不十分です。宣言された暗号文全体を消費し、入力として計上する必要があります。参照の復旧が追加の不正な完全ブロックを受け入れる場合は候補の成功範囲外です。
- 共通のストリーミング BLAKE2sp32 状態を再利用します。既知の BLAKE2sp 追加フィールドがあれば、その全幅チェックを選び、基本 CRC フィールドは保持しますが両方を要求しません。これは固定参照の選択セマンティクスと一致します。flag2 が鍵付き調整を宣言する場合は通常 CRC の LE4 に HMAC を適用して 8 個の LE32 値を XOR し、通常 BLAKE2sp32 は完全な HMAC32 を使います。flag2 がなければ暗号化されていても調整しません。未知のハッシュは Unsupported のままで、CRC やチェックはソースの真正性を証明しません。

## RAR20/26 LZ と Audio 候補

20/26 系列は事実のみの引き継ぎ `RAR20-26-2026-10-26-v1` に従い、本文 SHA-256 は `d240cac882e8120eb5f20c7894395732b9798bd133479604ae79d5bde24b04d5` です。実装者は対応する UnRAR、Junrar、その他の第三者 LZ/Audio アルゴリズム実装を読んでおらず、RAR 圧縮エンコーダーを提供しません。元のテストアーカイブ、既知の WAV、アサーション、ライセンスは独立したデータ参照専用です。ソース検索で第三者の汎用アーカイブ識別コードの要約が偶然返されましたが、この世代の LZ/Audio アルゴリズムは含まれず、その実装にも使われませんでした。これは厳密なクリーンルーム開発の証明ではありません。

20 と 26 は独自のエントロピーと Audio 状態機械を共有し、制限付きの共通 MSB 入力、最大 1 MiB のリング履歴、実出力ヘルパーを通じてデコードします。新しいコード長表はバイト境界に整列せず、完全に構築されたときのみ確定し、1,028 項目の旧基準内の未変更値を保持します。範囲外の不正な繰り返しは厳格に拒否します。直近 4 個の一致は重複距離を時系列で保持します。Audio は実 PCM 履歴を書き込む予測モードで、1..4 チャンネル、チャンネル間の差分、32 番目のサンプル後のチャンネルごとの適応、係数 -17..16 をサポートします。モード／表の切替では予測状態を消去せず、非ソリッドのリセット時のみ消去します。

コンテナーの既知展開サイズが内容境界を決め、一致は残りサイズを超えられません。この世代には追加の必須 EOF シンボルがありません。サイズに達した後、候補は現在の物理バイトから少なくとも 5 実バイトが残ることを要求する安定した規則に基づき、1 シンボルを観察します。次表の制御を識別した場合は後続のソリッドファイルのために完全に解析し、他のシンボルは追加内容や PCM 更新を生成しません。その後、入力エラー、キャンセル、コンテナー検証を保持しながら、認可された圧縮範囲全体を読み尽くします。これは明示的な旧末尾受け入れ方針であり、バッファリングに影響されるすべての参照復旧動作との等価性を主張せず、任意の末尾を有効内容とも解釈しません。失敗後、インスタンスは失敗状態を保持し、形式リセットでも失敗状態を解除しません。

旧初期化と表制御は先に補助作業を予約し、実際に完了した操作を出力クレジットなしで精算します。実際に生成された内容のみが一度限りの配送クレジットを生みます。候補のメモリー事前検査は保守的な外側の 288 MiB と保持した履歴容量を含み、ワーカーの 1 GiB 実装予算内で行います。これはリソース方針であり、形式上限ではありません。

固定した Junrar `v8.1.0` の RAR2.06 暗号化圧縮サンプル、コミット `57091f9ccd43661cf8f12c389917cc24950df707` は、独立して完全に既知の 87 バイトのペイロードを提供します。元の RAR20 Boat アーカイブ 2 個は[legacy20 フィクスチャー](../../../crates/xdzip-codec-rar/tests/fixtures/legacy20/sources.json)の小さなソース一覧とともに保持し、実際の 2 チャンネル Audio と通常 LZ 対照を含む公開 WAV 内容の完全なサイズ、SHA-256、CRC を記録します。元のアーカイブバイトは変更せず、CC BY-SA 4.0 の内容表示と上流の元ライセンスは別々に保持します。宣言型ビットベクターと独立した Python PCM の数学検証は、モード切替、1..4 チャンネル、適応境界、ソリッド状態、距離、エラー、クォータ、出力失敗を別々に検証し、作者が作成したサンプルの代わりにはなりません。

固定した公式 RAR 2.90 作者ソフトウェアは、プロジェクト所有の数学的平文から通常、ソリッド、強制 Audio ソリッドの 3 個の元アーカイブも生成しました。[自社 RAR20 フィクスチャー](../../../crates/xdzip-codec-rar/tests/fixtures/legacy20-owned/README.md)を参照してください。各アーカイブには実際の UnpVer20 メンバーが 3 個あり、ソリッドの後続メンバーには実際のソリッドフラグがあります。通常の回帰では作者ソフトウェアやネットワークなしに、新しいリーダーによる先行内容の再生を含め、合計 591,561 バイトの完全出力 9 個の全バイトを比較します。公式 2.90 がネイティブ生成した [RAR26 大容量ファイルサンプル](../../../crates/xdzip-codec-rar/tests/fixtures/legacy26-owned/README.md)は実際の UnpVer26、method1、LARGE を持ち、既知の平文は 2 GiB と 1 バイト、アーカイブは約 1 MiB です。明示的なリリース回帰は制限付きシンクと増分 SHA のみを使い、大きな平文を保存せず完全な CRC、バイト数、一度限りの配送クレジットを検査します。通常のデバッグテストは既定でこの重い処理を除外します。すべての旧末尾表遷移、他の実 Audio チャンネル数、他の分割／ソリッド／暗号化の組み合わせは別途カバーが必要です。バージョンフィールドを変更した数学ベクターは作者バージョン 26 の相互運用には数えません。

元の公式作者ソフトウェアは[自社 7 ボリューム RAR20](../../../crates/xdzip-codec-rar/tests/fixtures/legacy20-split-owned/README.md)と[自社 17 ボリューム RAR26](../../../crates/xdzip-codec-rar/tests/fixtures/legacy26-split-owned/README.md)も生成しました。各ボリュームのダイジェストと実際の split/LARGE フィールドを独立して固定します。通常のバージョン 20 回帰は数学的平文 589,826 バイトすべてを比較します。明示的なバージョン 26 リリース回帰は単一ボリューム用の制限付きシンクを再利用し、同じ 2 GiB と 1 バイトについて完全な SHA、CRC、一度限りの配送クレジットを再検査します。公開 packed_size は常に最初の断片のサイズを保持します。テストに作者実行ファイルは不要で、大きな平文も生成しません。この二つの非暗号化、非ソリッドの正常例は、他の分割の組み合わせを証明せず、実際の Store 混在サンプルの代わりにもなりません。

## 未解決の互換条件

13/15、20/26、RAR29 LZ/PPM と標準フィルター、旧パスワード、初期チェックサムには候補実装があります。過去の各組み合わせには引き続き個別の実サンプルと完全経路の受け入れが必要です。一つのコンポーネントや作者アーカイブの合格は完全移行の代わりになりません。RAR7 実効アルゴリズム 1 の独立した正常な圧縮サンプルは [#43](https://github.com/xiaodaozhi/xdzip/issues/43) で追跡し、固定したソース、平文全体、ワーカー／ランタイムの業務経路を別々に検証します。Store、数学ビットベクター、互換性のあるアルゴリズム 0 サンプルは代用品ではありません。各フィルターの独立した実サンプルの範囲を別々に記録します。フィルターコードの存在は受け入れを証明しません。固定した既存 UnRAR 基準が実行するのは旧標準フィルター 6 種のみで、過去の VM という名称によって任意のアーカイブプログラムを実行するインタープリターへ範囲が広がるわけではありません。

公開 `Entry.size_known` は未知サイズと既知の空ファイルを区別します。完全な断片チェーンの既知サイズが一致する場合はサイズを復元します。完全に未知のエントリーは `size_known=false,size=0` で閲覧、公開できますが、旧内部センチネル `0x7fffffff7fffffff` は公開しません。Native ROW の `0x40` は RAR の未知サイズ用に予約され、size=0 とともに使う必要があります。Native ROW の `0x80` は、制限付きで必要時に取得できる RAR エントリーのコメントを示します。CAB の `0x20` の意味は保持し、RAR 専用フラグは他の形式では拒否します。ランタイムと Qt はマーカーを保持します。未知サイズを含む元サイズと選択合計は `—` と明示的な未知状態を表示します。サイズの昇順と降順はいずれも未知エントリーを既知エントリーの後に置き、同値は物理識別で安定的に並べます。事前検査は `unknown_size` と未知の合計を報告します。アーカイブ全体の検査、展開、一時オープン、エクスポートは内容取得前に拒否します。未知は空ファイルではなく、デコード／出力クォータも提供しません。

現行 Unix/FILETIME タイムスタンプは非公開の完全な値を保持します。公開 DOS 時刻は[ホスト暦サービス](host-platform-services.md)を通じて投影し、直接 API は既定で UTC、製品ワーカーは日付に応じたローカル規則を使います。Rust は過去の剰余演算、128 年の折り返し、偶数秒への切り詰め、異常な小数部分の無視を維持します。OS 投影の失敗は明示的に 0 であり、参照で未検査のシステム失敗による未定義結果とは異なります。3 プラットフォームの完全な製品証拠は別途受け入れます。

旧サービスの LARGE／拡張時刻は、完全なヘッダー CRC、必要な 32/40 バイト基部、名前、64 ビット圧縮範囲、予算の検査に合格した後、範囲内でスキップできます。元の末尾は未解釈データとして保持します。salt／時刻の区分を推測せず、ゼロ埋めパスワードパラメーターを作らず、通常ファイルの時刻を変更せず、サービス出力やサービス内容の認証も提供しません。数学的メタデータの正負対照と独立した健全な作者アーカイブは別々に記録し、健全な大容量サービス内容サンプルの欠如は証拠上の境界として残ります。既知平文の作者サンプルは最古形式の圧縮分割アーカイブ、RAR20 の通常および Audio ソリッド、RAR20/RAR26 の圧縮分割ボリューム、実際の UnpVer26 で 2 GiB と 1 バイトのファイルを含みます。これらの限定的な正常例は全ボリューム、チャンネル、末尾表遷移の受け入れを証明しません。Windows 以外の旧 Unicode 未修正高ビット連続部分、過去の非 ASCII パスワード暗号文、旧圧縮と Store の交互配置は別々に追跡します。数学的コンテナー、OS 変換のみ、宣言バージョンの変更を健全な作者相互運用に見せかけません。

現行アーカイブに終端レコードがなければ現在は安全側に失敗し、旧形式はレコード境界ちょうどの EOF を許可します。SFX 検索は最初の 4 MiB に制限し、最古形式の境界は上記に従います。重複するセキュリティー追加フィールドの厳格な拒否やその他の不正入力方針が公式形式の必須条件だとは主張しません。スキップしたサービス内容に完全な内容整合性の保証は与えません。ホストのソース識別検査は引き続きベストエフォートであり、メタデータ再スキャンは原子的な入力内容スナップショットではありません。
