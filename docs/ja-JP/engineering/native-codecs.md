# 分離された形式ワーカーの契約

[English](../../engineering/native-codecs.md) | [简体中文](../../zh-CN/engineering/native-codecs.md) | [繁體中文](../../zh-TW/engineering/native-codecs.md) | 日本語 | [한국어](../../ko-KR/engineering/native-codecs.md) | [Français](../../fr-FR/engineering/native-codecs.md) | [Deutsch](../../de-DE/engineering/native-codecs.md) | [Español](../../es-ES/engineering/native-codecs.md) | [Português (Brasil)](../../pt-BR/engineering/native-codecs.md) | [Русский](../../ru-RU/engineering/native-codecs.md)

7z、RAR、CAB、ISO/UDF の読み取りは、分離ワーカー内の共有 CXX 境界を介した[組み込み Rust codec](../../engineering/independent-rust-codecs.md)を使用します。同じワーカーはホストが制御するタスク内で 7z の書き込みも扱います。Rust ホストは ZIP、TAR、圧縮ストリーム、DEB、[新しい ISO9660/Joliet イメージ](iso-creation.md)をプロセス内で処理します。形式の選択には組み込み経路を使用し、どの経路も PATH からコマンドラインデコーダーを探しません。

製品の CAB は常に独立した Rust 経路を使用し、テストスイッチ、公式ハンドラー、失敗時フォールバックはありません。完全なフレーム、共有アルゴリズム、リソース範囲は[自前の契約](../../engineering/independent-rust-codecs.md#cab-read-only-specification)、出所と参照分析の役割は[CAB ソース](../../engineering/cab-format-sources.md)を参照してください。

ホストは runtime 起動前に検証済みの絶対ワーカーパスを一つ登録できます。同じ登録の繰り返しは成功し、競合するパスや相対パスは選択を変更せず拒否します。明示的な開発者オーバーライドが優先され、次に登録済みパスを使用し、登録がない場合のみ実行ファイルに隣接するワーカーを使います。デスクトップ CLI バンドルはこの登録でデスクトップワーカーを共有します。独立パッケージはローカルワーカーを持ち、近くのディレクトリから他のデスクトップインストールを推測しません。

<a name="xdzip-build-and-sources"></a>

## ビルドとソース

統一準備入口は `scripts/prepare-native-codecs.py` を実行します。[製品ソースマニフェスト](../../../scripts/native-codec-sources.json)は現在空で、準備時に公式形式ソースをダウンロードしたり展開したりせず、オフラインビルドにも UnRAR や 7-Zip アーカイブは不要です。一般的なソースツールは明示宣言された資料に対する制限付き展開とダイジェスト検証を保持し、キャッシュ内容は自動的に製品へ入りません。

製品は公式 UnRAR/7-Zip のコンテナー、アルゴリズム、共通ユーティリティ、ファイルアダプター、形式レジストリをコンパイルまたはリンクしません。7z、RAR、CAB、ISO、UDF は実行時失敗からのフォールバックなしに Rust を使用します。内部 CMake の `XDZIP_7Z_BACKEND=rust`、`XDZIP_RAR_BACKEND=rust`、`XDZIP_CAB_BACKEND=rust` は固定識別を記録します。生成された `native-codec-source-list.txt` はプロジェクト所有の接続ファイル 7 個を完全に記録します。検査はパスと集合を確認し、公式ソースや廃止された `host_file.cpp` の再導入を拒否します。`platform_time.cpp` と `platform_encoding.cpp` は OS のローカル暦と文字セット対応のみを Rust に返し、アーカイブの時刻形式やパスワードバイト規則を解釈しません。共有 Zstandard/FSE/Huffman/XXH64、LZ4/XXH32、Deflate/Deflate64、LZMA、BZip2、PPMd、LZX、Quantum は実際の形式に応じて再利用し、形式ライブラリーを重複させません。

対応するソース資料は実際にデプロイされたバージョンに添付し、ダウンロードリンクだけでは不十分です。過去のビルドと独立した公式参照ツールはそれぞれ元の条件に従います。現在の製品ソースマニフェストが空でも既存配布の義務は変わりません。

<a name="xdzip-authority-and-lifecycle"></a>

## 権限とライフサイクル

Rust コアはソース許可、分割ボリュームの識別、保存先許可、一時領域、コミット権限を保持します。Rust の 7z/RAR/CAB/光学バックエンドは別ワーカーで動作し、許可されたストリームを読み取り、現在承認された項目データを制限付きプロトコルで出力します。ユーザーの保存先パスや任意のファイルアクセスインターフェースは受け取りません。CXX を通じて同期的に借用する文字列とスライスは呼び出し中のみ有効で、ポインターを保持しません。C++ 例外と Rust の unwind は安定したエラーに変換します。OOM/abort はワーカーを失敗させ、ホストは未完成の一時出力を破棄します。

ホストによる最初のソースシーク、ワーカーのランダム読み取り、作成入力、EOF プローブは、クォータ、キャンセル、未対応、ソース変更の型付きエラーを一貫して保持します。外側の I/O 種別が Interrupted でも型付き原因を消しません。型付き原因のない Interrupted のみ、キャンセルを確認してから再試行でき、先払い済みのソース作業は返還しません。Scan は SourceChanged を保持し、内容読み取りは既存のソースエラー意味論を使い、作成はソースエラー時のコミットを拒否します。

ワーカーはコマンドラインでパスワードを受け取らず、アーカイブが提供する任意の診断を出力せず、アプリケーションの認証情報やプロキシ環境を継承しません。エラーは安定したコードに対応付けます。暗号化ディレクトリを開くパスワードは現在のセッションと関連タスクのゼロ消去コンテナーにのみ保持し、起動をまたいで永続化しません。セッション終了とタスク終端はそれぞれのコンテナーを解放します。キャンセルは読み取りと出力を止め、タイムアウト時はワーカーを終了・回収します。ワーカー失敗を成功にはできません。プロセス分離は OS サンドボックスではなく、侵害されたプロセスによる同一ユーザーのすべてのリソースへのアクセスを防げるとは主張しません。

ワーカーの UTF-8/ワイド文字変換は Unicode スカラー値を厳格に検証します。Windows は UTF-16 サロゲートペア、macOS と Linux は 32 ビットのワイド文字を使用します。不正な UTF-8、孤立サロゲート、範囲外スカラーは `std::range_error` を送出し、ワーカー境界でプロトコルエラー 2 に変換され、成功終端を出しません。変換は埋め込み NUL を保持します。安全でない名前の拒否はホストの名前・パス安全検査の責任です。

7z 作成は EncodeOutput::write_at により制限されたオフセットとブロックをホストの非公開一時領域に書き込みます。ネイティブプロセスはストリーム位置のみを保持し、出力アーカイブ全体をメモリーに蓄積しません。ホストは実際の書き込みバイトとアーカイブ長の最大到達値を別々に計量し、ヘッダーの書き直しは分割ボリューム内容長を増やしません。ホスト側の検査はオフセット、ブロックサイズ、累積出力、キャンセルを再検証します。ランダム書き込みができない出力は明示的に拒否します。

タスクはホストの項目、パス、メタデータ、実バイトの予算を保持し、既定のネイティブ予算は 1 GiB です。Windows は Job Object のコミットメモリー上限、Linux は絶対仮想アドレス空間上限、macOS は起動時の仮想アドレス基準に予算を加え、dyld 予約を除いた値を使用します。Unix のアドレス空間制限は RSS 計測ではありません。辞書とソリッド作業領域は割り当て前に受理し、予算に収まらない操作は制限なしのディスク一時領域へ黙って移らず明示的に失敗します。再試行とソリッドスキップは実際の作業量を累積します。

RAR の実効的な現代アルゴリズム 1 は[制限付きの正確なページ化履歴](../../engineering/rar-format-sources.md#exact-storage-for-large-logical-dictionaries)で大きな論理辞書を表現できます。論理宣言は割り当て許可ではありません。ディレクトリ、保持ページ、一時ピークには独立した上限があり、元のワーカー予算と動的失敗動作を維持します。

実際のアルゴリズム初期化・制御の補助作業は別の `AUX_WORK=24` を使用し、現在は RAR ペイロードのみが対象です。ホストと runtime は補助予算を独立に累積し、ファイルデコード、展開率、公開進捗、前払いクレジットには計上しません。プロトコル、再試行のライフサイクル、必要な受け入れは[補助デコード作業の計量](auxiliary-decoding-work.md)を参照してください。

<a name="xdzip-capability-boundaries"></a>

## 機能の範囲

7z の閲覧、展開、整合性検査、作成は別々に宣言します。作成は既定で LZMA2、通常レベル、非ソリッド、非暗号化、非分割です。ソリッド、内容暗号化、ファイル名暗号化、番号付き分割は独立した機能として検証します。ファイル名暗号化にはパスワードが必要です。暗号化された名前はメタデータを開く際にパスワードを要求し、未完了の走査は部分インデックスを公開できません。

暗号化されず分割されておらず、すべての項目を安全に保持できる 7z アーカイブは、追加、置換、内部移動を再利用できます。ソリッド内容は制限付き再構築を使用します。暗号化、分割、リンク、未対応の特殊レコードの変更は引き続き拒否します。ソースの再確認と完全な検証を経て、同一ボリューム上で原子的に置換します。独立した削除・名前変更の入口はこの拡張の範囲外です。

RAR は常に `xdzip-codec-rar` を使用し、公式フォールバックなしの読み取り専用です。旧形式、RAR5、RAR 7 拡張、パスワード、ヘッダー暗号化、ソリッドアーカイブ、分割は別々に検証し、アルゴリズムと互換性の制限は[自前の仕様](../../engineering/independent-rust-codecs.md#rar-read-only-specification)に従います。作成、変更、修復、パスワード回復は提供しません。RAR の初期化・制御作業は補助チャネルを使い、実際のデコード出力は WORK と前払い配信を使用し、モデル初期化をファイルサイズや展開率に含めません。

CAB は Store、MSZip、Quantum、LZX に対応し、単一および同じディレクトリ内の分割ボリュームは読み取り専用です。Rust はヘッダー関係から許可済みボリューム集合を検証・固定した後、元のボリューム名と境界をワーカーへ送ります。ボリュームの欠落や不一致で部分インデックスは公開できません。[分割ボリューム契約](archive-opening.md)を参照してください。CAB の生名と UTF-8 宣言を保持し、旧形式の名前には[共有ファイル名解決](filename-encoding.md)を使用し、出力パスをホストコードページから推測しません。

`xdzip-codec-optical` は公式 Iso/Udf ハンドラーをリンクせず ISO9660、Joliet、Rock Ridge、UDF を解析します。ハイブリッドイメージは UDF 名前空間を優先し、認識された UDF の破損時に ISO へ黙ってフォールバックしません。拡張子ではなく内容で検出します。ISO/UDF リーダーはマウントや起動イメージの実行なしに閲覧、展開、一時オープン、エクスポート、検査をサポートします。プロセス内の [ISO9660/Joliet ライター](iso-creation.md)は通常のデータイメージを作成し、UDF の作成と更新は未対応です。起動イメージレコードは読み取り可能なファイルのみで、リンクと特殊オブジェクトは出力できません。イメージ検査は構造、範囲、実際の読み取り可能性を検証し、通常ファイルに内容チェックサムがあるとは主張しません。パーティションマップと未対応拡張の明示的な範囲は[自前の仕様](../../engineering/independent-rust-codecs.md#iso-and-udf-read-only-specification)を参照してください。

<a name="xdzip-verification-and-delivery"></a>

## 検証と配布

実際の対応を主張するには公式ツールとの相互運用、既知の出力バイト、破損とリソース上限のサンプルが必要です。マジック検出、呼び出しの成功、一つのバックエンドによる自己読み書きだけでは相互運用性を独立に証明できません。3 プラットフォームのコア/Qt 検査、デプロイ検証、ネイティブ視覚検査、デスクトップのドラッグ/ドロップは別々に記録し、段階の証拠は issue とローカルまたは CI 成果物に残します。

CTest `native_unicode_conversion` はワーカーの変換実装を直接コンパイルし、UTF-8 長の境界、非 BMP、埋め込み NUL、不正シーケンス、プラットフォームのワイド文字境界を検証します。`native_unicode_protocol` は不正な作成名を実際のワーカーに送り、エラー応答と失敗終了を確認します。Windows、macOS、Linux で実行し、一つのプラットフォームで両方のワイド文字幅の検証を代用できません。

RAR 経路の受け入れは実際のワーカーを通じた走査、検査、安全な展開を対象とし、小ファイル、PPM 初期化、パスワード、許可済み分割を含みます。小ファイルや PPM 初期化だけで高い展開率による拒否を発生させてはならず、補助作業は公開バイト数を増やしてはなりません。失敗時にファイルを公開してはなりません。ソース検査は空の製品マニフェスト、固定 Rust 識別、完全なコンパイルソース一覧、薄い RAR 入口を合わせて検査し、シンボルや成功出力だけで公式コードが除外されたとは証明できません。

Foundation は `scripts/check-rar-rust-interop.py --worker <built-worker> --output build/<evidence>` を使い、元の完全な明示的 `native_backend_tests` バッチを実行します。入口はまず `scripts/rar-rust-fixtures.json` で URL、サイズ、SHA-256 を固定した公開の小 PPM、大 PPM、旧パスワードサンプルを準備し、元の圧縮ストリームだけを含む単一メンバー部分集合、自前の数学的なサイズ不明および既知の空ヘッダー、プロジェクト所有の 20/26 テストデータに必要な環境を作ります。各ネットワーク応答は最大 512 KiB です。準備ファイルと証拠は build 内に置き、2 GiB の平文を生成せず、作者のツールも実行しません。入力が欠けるか一致しなければ失敗する必要があり、スキップしたテストは環境準備の代わりになりません。ラッパーは悪意ある補助作業ワーカー、サイズ不明プロトコル検査、ネイティブ小ファイル計量、ソリッド再読み取り、自前の E8E9 全バイトダイジェスト、実際の OS 文字対応プローブも実行する必要があります。プローブは現在のワーカーの隣にある固定 Rust 出力ディレクトリの CXX ヘッダーと厳密に一意な Release 静的ライブラリーのみを使用し、ヘッダー、ライブラリー、プローブのダイジェストを記録します。入力が欠けるか曖昧なら失敗します。別のコンポーネント検査が大きなバージョン 26 の完全 SHA を検証し、runtime バッチは実際のワーカーで大ファイル全体の件数、CRC、ゼロ一時出力を一度検査します。明示的な `--large-digest` はワーカーによる完全 SHA 検査を追加します。

相互運用には製品ワーカーとは別の固定された公式 26.05 参照ツールを使用します。Windows では同じ公式リリースから 7zr.exe をダウンロードしてダイジェストを検証し、検証済み 7z2605-extra.7z から x64/7za.exe だけを展開してそのメンバーの独立 SHA-256 を再検証します。システム tar の LZMA 対応に依存せず、インストーラーを実行せず、固定されていない PATH ツールも使用しません。Linux と macOS は検証済み tar.xz から指定された 7zz メンバーだけを読み取ります。ダウンロード、キャッシュ、展開のいずれかのダイジェストが一致しなければ停止します。参照ツールは build/ のテストディレクトリに置き、製品デプロイには含めません。

開発パッケージは実験的なままです。コンポーネントライセンス、対応するソース、再リンクの要件は実際のビルドごとに別途レビューし、この機能の完了だけで正式リリースは承認されません。

[runtime ワーカー検証入口](../../../developers/qa/runtime-worker-tests.md)が宣言された完全な統合一覧と固定入力を自動的に準備します。準備していない `native_backend_tests --ignored` バッチを直接呼び出さず、この入口を使用します。任意の完全ライブラリーモードは無視された結果がゼロである必要があります。
