## 外部 SDK 試行

独立した試行ホストは固定済みの serde 1.0.229、serde_json 1.0.154、sha2 0.10.9、getrandom 0.4.2、libc 0.2.190、tempfile 3.27.0 を再利用し、第三者の新バージョンやフォーマット／CBOR ライブラリーを追加しません。プロトコルクレートは std のみを使用し、プロジェクト所有の上限付き CBOR は RFC 8949 に従って独立した Python 標準ライブラリーの相手と相互運用します。ホストは Qt とリンクせず、デスクトップや CLI の実行時依存集合に入らず、正式リリースの資料を変更しません。

tempfile は汎用一時ディレクトリー実装を維持せず、検証済みの非公開実行ファイルコピーを保持するため、既存ロックファイルから試行の直接依存関係に昇格します。安全な出力には引き続き xdzip-io を使用し、tempfile はコミットを認可しません。ソースは [Stebalien/tempfile](https://github.com/Stebalien/tempfile)、ライセンスは MIT または Apache-2.0 です。既定機能と fastrand、getrandom、once_cell、rustix/windows-sys を含む実際のターゲット依存集合は Cargo.lock／metadata に従って固定バージョンを再利用し、ビルドスクリプトのダウンロードや C ライブラリーの追加はありません。既存の基盤ライブラリーの用途、ソース、ライセンスも引き続き適用し、過去のアドバイザリー照会を新たな安全性の結論として扱いません。テストとゲートは [SDK 試行](sdk-trial.md)を参照してください。Windows は AppContainer 実装がなければ実行を明示的に拒否します。

パッケージ内メンバーへのアクセスは、採用済みの cap-std/cap-fs-ext 4.0.3 の厳密なバージョンと既存機能を再利用し、保持したディレクトリーから各構成要素をリンク追跡なしで相対的に開きます。これにより文字列検査と環境パスを介した再オープンの間の競合を防ぎます。両者は既存の安全 I/O の来歴、MIT または Apache-2.0 ライセンス、推移依存のバージョン、ネイティブ動作を維持し、第三者の新バージョンを追加しません。

## CLI フロントエンドと HTTPS

CLI はロック済み clap 4.6.7 を実際の製品フロントエンド依存関係に昇格し、std、help、usage、error-context、suggestions、string のみを有効にして derive や端末色は使いません。ureq 3.5.1 は既定機能を無効にして追加し、native-tls-no-default と socks-proxy のみを有効にし、NativeTls とシステム信頼ルートを明示的に選択します。既定の GZIP デコード、Cookie、JSON ヘルパー、外部 curl、Qt ネットワークの実行時依存関係は導入しません。serde、serde_json、zeroize、sha2、getrandom、プラットフォームバインディングは固定バージョンを再利用します。

ureq と ureq-proto のソースは [algesten/ureq](https://github.com/algesten/ureq) で、MIT ライセンスを選択します。主な推移入力は native-tls 0.2.18、ureq-proto 0.7.1、http 1.5.0、httparse 1.10.1 です。完全なバージョン、機能、ターゲット依存集合は Cargo.lock とホストでフィルターした Cargo メタデータに従います。Windows は schannel 0.1.30、macOS は security-framework 3.7.0 とシステムフレームワーク、Linux は openssl 0.10.82／openssl-sys 0.9.118 とシステム OpenSSL 3 を使用します。RustCrypto の der／PKI 型は汎用 TLS ラッピングのみを支援し、アーカイブ形式を解釈しません。

Linux の Native TLS ビルドは pkg-config でシステム OpenSSL を探し、専用 OpenSSL を同梱、ダウンロード、コンパイルしません。Mac／Windows はシステム TLS を使用します。必要な Cargo ビルドスクリプト、ネイティブリンク、ターゲット条件、既知のアドバイザリーを実際の固定バージョンについて確認します。照会記録はローカル／CI 成果物に残し、要約を CLI の issue に記録します。一度の該当なしという結果は恒久的な安全保証ではありません。プロジェクト所有の CLI 端末、シグナル、OS 照会 FFI はプラットフォームアダプターに限定し、失敗時は操作を拒否します。パスワードコンテナーには引き続きゼロ化要件が適用されます。

パッケージ通知は CLI とワーカーの通常依存集合からそれぞれ収集し、ビルド／開発／proc-macro 依存関係を実行時帰属の証拠から除外します。デスクトップの実行時帰属には CLI ルートを追加します。公開 Windows ランチャーだけがコンパイラー CRT を静的リンクし、バージョン付きのアプリローカル DLL を読み込む前に入口を起動できるようにします。実際のペイロードとワーカーには引き続き固定 VC++ ランタイムと元のライセンスを同梱し、SDK グラフィックスライブラリーは含めません。実際のリリース資料では依存関係の来歴、保持する静的／動的機械コード、ライセンス義務を引き続き審査します。

依存関係を初めて追加するときは、目的、代替案、バージョン、ソース、ライセンス、推移依存関係、機能、ネイティブビルド動作、既知の脆弱性、保守状況を記録します。クレート名だけでは採用審査は完了せず、架空の監査済みバージョンを記載してはいけません。

| 候補の方向 | 必要な検証 |
| --- | --- |
| Rust ZIP 実装 | Store／Deflate、ZIP64、CRC、重複、生の名前バイト、キャンセル、ホスト出力先 |
| Rust TAR + GZIP 実装 | ストリーミングインデックス、PAX／GNU メタデータ、リンク・デバイスの拒否、未知サイズ、破損ストリーム |
| cxx | 所有権、ジェネレーターの一貫性、クロスプラットフォーム静的コアリンク、例外が境界を越えないこと |
| Qt モジュール | 実際の実行時・推移依存関係、置換可能な配置、ライセンス、セキュリティ更新チャンネル |
| アイコンセット | 明示的な再頒布ライセンス、一貫した線幅、アクセシビリティ、アセット一覧 |

検証順序は、最小限の相互運用 → 悪意ある入力・切り詰め入力 → キャンセル・リソース制限 → ライセンス／SBOM → クリーンビルド → 判断の記録です。ライブラリーの汎用 unpack でホストのパス保護を迂回してはいけません。

アプリケーションの Rust ワークスペースでは Cargo.lock をコミットします。新しいネイティブライブラリーやネットワークからダウンロードするビルドスクリプトには専用審査が必要で、未使用の機能は無効にします。依存関係が放棄された場合や脆弱性の修正がない場合は、実際の到達可能性に基づいて更新、置換、機能の無効化を判断し、理由を記録します。

## 更新メタデータと発行者署名の検証

`xdzip-update` はマニフェスト、チャンネル、署名検証のための Qt 非依存コアで、製品は別の cxx 境界を通じて呼び出します。リリースツールとインストールヘルパーも同じ規則を使用します。`ed25519-dalek = 2.2.0` の安全な `VerifyingKey::verify_strict` を使い、弱い公開鍵を拒否して正確な生バイトを検証します。署名演算を独自実装したり、TLS や SHA-256 を発行者署名とみなしたりしてはいけません。上流の fast、std、zeroize は既定で有効、batch、hazmat、legacy_compatibility、rand_core、PKCS#8 は無効です。リリースツールは所有者が設定した 32 バイトのシードのみを取り込み、本番秘密鍵を生成しません。

| 直接依存または主要な推移依存 | 厳密なバージョン | ソース、ライセンス、目的 |
| --- | --- | --- |
| ed25519-dalek、curve25519-dalek | 2.2.0、4.1.3 | [dalek-cryptography](https://github.com/dalek-cryptography/curve25519-dalek)、BSD-3-Clause、Ed25519 と曲線演算 |
| base64ct | 1.8.3、alloc | [RustCrypto/formats](https://github.com/RustCrypto/formats)、Apache-2.0 または MIT、Sparkle 互換署名エンコード |
| sha2 | 0.10.9 | [RustCrypto/hashes](https://github.com/RustCrypto/hashes)、MIT または Apache-2.0、パッケージダイジェスト |
| semver | 1.0.28 | [dtolnay/semver](https://github.com/dtolnay/semver)、MIT または Apache-2.0、上限付き製品バージョン解析 |
| subtle | 2.6.1 | [dalek-cryptography/subtle](https://github.com/dalek-cryptography/subtle)、BSD-3-Clause、上流の定数時間演算サポート |
| zeroize | 1.9.1 | [RustCrypto/utils](https://github.com/RustCrypto/utils)、Apache-2.0 または MIT、リリース処理中の一時秘密鍵コンテナーのゼロ化 |

serde 1.0.229 と serde_json 1.0.154 はロック済みバージョンを再利用します。digest、block-buffer、crypto-common、generic-array、typenum、cpufeatures、derive マクロを含むその他の推移依存関係は Cargo.lock と実際の機能ツリーに従います。curve25519-dalek のビルドスクリプトはローカルコンパイラーの能力のみを検出し、実行時には上流の CPU 固有実装を選択する場合があります。外部ソースをダウンロードせず、C/C++ 暗号ライブラリーや OpenSSL の実行時依存関係も追加しません。既存の通知とベンダー収集は Cargo メタデータを使ってこれらのパッケージを含めます。実際のパッケージ帰属とライセンスはリリース資料での審査が必要です。

システム暗号 API を使うと 3 プラットフォームで検証規則が分かれ、外部 OpenSSL CLI は実行時依存関係と引数の境界を広げるため、一つの Rust コアを使用します。過去の [RUSTSEC-2022-0093](https://rustsec.org/advisories/RUSTSEC-2022-0093.html) の旧 Keypair API は使用しません。[RUSTSEC-2024-0344](https://rustsec.org/advisories/RUSTSEC-2024-0344.html) が要求する修正済み curve25519-dalek の境界は 4.1.3 で、固定バージョンはこれを満たします。これらの確認はすべての依存関係に脆弱性がないことを証明しません。更新時には引き続き保守状況とアドバイザリーを確認します。

回帰では正確なバイトの変更、無効な署名、未知／重複／弱い公開鍵、空の本番信頼セット、チャンネルフォールバック、バージョンとビルドの結合、6 パッケージの完全性、署名付きフィードを検証します。一時テスト鍵はテストコードと分離された成果物にのみ存在し、製品の信頼リソースには入りません。ネイティブインストールとクロスプラットフォームの結果は別々に記録し、1 プラットフォームのコアテストはインストール受け入れの代わりになりません。

## Windows ソース識別

M2 は Windows 実行時に厳密な `winapi-util = 0.1.11` の安全な `file::information(&File)` ラッパーを直接使い、ボリュームシリアル番号とファイルインデックスを比較します。長さと更新／作成時刻だけでは、同名で置き換えられた NTFS ファイルを確実に検出できません。標準ライブラリーの対応するファイルインデックス API はまだ安定しておらず、手書きの Win32 unsafe は審査範囲を広げます。既存のロック済みライブラリーを再利用し、パッケージバージョンを追加しません。

ソースは crates.io／[BurntSushi/winapi-util](https://github.com/BurntSushi/winapi-util) で、上流の MIT または Unlicense の二重ライセンスから MIT を選択します。Windows の推移依存関係は固定された windows-sys 0.61.2 と windows-link 0.2.1 で、どちらも MIT または Apache-2.0 です。上流が宣言する Win32 モジュールのみを有効にし、既定機能は無効で、ビルドスクリプト、外部ネイティブビルド、ネットワークダウンロードはありません。Windows 以外のターゲットではこの実行時依存関係をコンパイルしません。上流の安全なラッパーは有効な File ハンドルを借用し、システム呼び出しが失敗した場合は旧ソースを無効とします。ハンドルは FFI を越えず、識別確認は安全な書き込みの認可ではありません。

バージョンの来歴、機能、ネイティブコンパイル動作を確認し、Windows GNU ターゲットの型チェックに合格しました。ネイティブ Windows の回帰では、更新時刻を維持した同名・同サイズの置換を対象にする必要があります。上流は小さな安全な Win32 ラッパーであり、更新はロックファイルとネイティブ回帰に制約されます。2026-10-13 の 3 パッケージの厳密なバージョンに対する OSV 照会では既知のアドバイザリーはありませんでした。過去の応答は元の実行成果物に保持し、新たな照会では実際の応答を[検証](../../../developers/qa/README.md)に従って記録します。これは脆弱性がないことの証明ではありません。開発パッケージは引き続きすべての上流ライセンスを収集します。

## Rust フォーマットバックエンドと共有ワーカーブリッジ

`xdzip-codec-7z` はプロジェクト API／ドメイン、第三者の製品用依存関係を持たない共通圧縮アルゴリズム、汎用暗号プリミティブを使います。AES 0.9.3 は zeroize を有効にし、getrandom 0.4.2 と zeroize 1.9.1 は ZIP のバージョンを再利用します。ゼロ化可能な SHA-256 はフォーマット非依存の `xdzip-crypto` に抽出し、形式ごとにラッパーを複製せず、採用済み sha2 0.10.9 の compress プリミティブ上でプロジェクト所有の増分状態を管理します。共有クレートは公開された数学仕様から HMAC-SHA256 と BLAKE2s／BLAKE2sp も実装します。ソースと境界はその [README](../../../crates/xdzip-crypto/README.md)を参照してください。これはアーカイブや公開の権限を与えず、第三者暗号バージョンを更新しません。フォーマット属性、CBC 構成、KDF、作成、書き換えは独立した実装であり、基盤ライブラリーが提供するアーカイブ処理ではありません。ソース、解析上の役割、ライセンスの違いは [7z の根拠](sevenzip-format-sources.md)を参照してください。

`xdzip-codec-optical` のフォーマットロジックは標準ライブラリーとプロジェクトの codec API／ドメインのみを使用し、ISO/UDF や汎用アーカイブライブラリーを使用しません。仕様、範囲、エラーは[独立実装契約](../../engineering/independent-rust-codecs.md#iso与udf只读规格)を参照してください。`xdzip-codec-bridge` はロック済み cxx／cxx-build のバージョンと生成処理を再利用し、新しい外部バージョン、ダウンロードするビルドスクリプト、フォーマットアルゴリズムライブラリーを追加しません。インプロセスのルーティングに置き換えると既存の光ディスクタスクのプロセス管理が失われるため、ワーカーと制御ストリームプロトコルを維持します。

`xdzip-codec-cab` はプロジェクト API、ドメイン、第三者の製品用依存関係を持たない `xdzip-compression` のみに依存します。MSZIP は ZIP／GZIP の Deflate を再利用し、LZX と Quantum は追加の Deflate や汎用アーカイブライブラリーを使わない独立アルゴリズムモジュールです。7z、CAB、光ディスクバックエンドは `xdzip-codec-bridge` とホストが認可したストリームを共有します。作成時は汎用境界を複製せず、制御入力とランダム一時配置のコールバックのみを追加します。製品は Rust を使い、公式 Cab と CAB 固有の LZX／Quantum はビルドに入りません。リソースと形式は[自社実装契約](../../engineering/independent-rust-codecs.md#cab只读规格)、参照解析の範囲とライセンスは [CAB ソース](cab-format-sources.md)を参照してください。

`xdzip-codec-rar` は RAR やその他のアーカイブライブラリーを導入せず、同じ codec API、共通圧縮アルゴリズム、暗号プリミティブを再利用します。PPMd H 統計モデルは 7z と RAR で共有し、各形式が独自の range、reset、termination を定義します。特殊な旧パスワード互換の組み合わせは RAR モジュール内に留めます。システムカレンダーと OEM／ANSI／ローカルエンコーディングには薄いワーカーコールバックを使い、Rust がフォーマットフィールド、パスワードの切り詰め、検証を担当します。Qt はフォーマットロジックに入りません。

製品依存関係方針では、フォーマットとブリッジの各クレートについて通常／ビルド依存集合を確認します。公式 7-Zip と UnRAR のコンテナー、アルゴリズム、汎用ユーティリティーはすべて製品 CMake マニフェストから除外され、製品ソース準備一覧は空で、失敗時のフォールバックもありません。過去に提供したもののライセンス義務は残ります。独立した pycdlib、Microsoft IMAPI、mkudffs／udfclient フィクスチャー、公式参照ワーカー、仕様ベクターはテスト専用です。それぞれのソースとライセンスを別管理し、アプリの実行時依存関係には入りません。小さな固定済みプロジェクト所有入力とジェネレーターはテストディレクトリーでバージョン管理し、展開済みイメージと実行証拠は build/ に保持します。

## HTML レビュー用フォントとツール

レビュー端末のシステムフォントへのフォールバックに代えて、公式 Noto Sans SC 2.004-H2 のオフライン可変サブセットを使用します。固定された Google Fonts のコミット、元ソースのハッシュ、生成手順、著作権、OFL-1.1 ライセンスは[資料一覧](../../../specs/dependencies/ui-font.json)を参照してください。ビルド時に太さ 400–750 の WOFF2 と同じソースのネイティブ TTF をビルドディレクトリーに生成します。ソースリポジトリーには生成フォントバイナリーを保持せず、外部サービス、推移的な実行時依存関係、ネイティブコンパイルも必要ありません。システムフォントではクロスプラットフォームのテキストメトリクスが異なるため、レビューデザインにはフォントを同梱します。各ビルドで現在のテキストの文字網羅を確認しますが、未知の生成デザインフォントが一致すると仮定することはできません。上流は引き続き保守されており、保守状況の変化に応じて固定バージョンを再評価します。

デスクトップリソースの静的チェックでは Pillow（HPND）、FontTools（MIT）、Brotli（MIT）、ワークフローチェック用の PyYAML（MIT）を使用します。バージョンは[デスクトップアセットツールの要件](../../../scripts/desktop-asset-requirements.txt)で固定し、別の仮想環境にインストールします。Playwright（Apache-2.0）と Chromium は必要時のローカル HTML デザインレビューにのみ使用し、バージョンは[ローカルデザインツールの要件](../../../scripts/html-design-requirements.txt)に記載します。これらは既定 CI、アプリケーション、オフラインデザインの提供物に入りません。いずれのツールも製品ランタイムコードには入りません。

## 自社 ZIP 実装と汎用暗号プリミティブ

ZIP コンテナー、ストリーミング作成、通常の書き換え、AES ラッピングには[独立した Rust 実装](../../engineering/independent-rust-codecs.md)を使い、Deflate／CRC-32 は `xdzip-compression` を再利用します。`rawzip = 0.5.2`、`zip = 9.0.3`、`flate2 = 1.1.10` は開発テストの参照専用で、ZIP 製品またはビルド依存集合には入りません。汎用 unpack を呼び出さず、任意のパスを認可しません。過去にこれらを使用した提供物のライセンス義務は残ります。

暗号プリミティブは、既存の推移依存関係から直接依存関係に昇格した厳密なバージョンを再利用します。RustCrypto の `aes = 0.9.3`、`hmac = 0.13.0`、`sha1 = 0.11.0`、`pbkdf2 = 0.13.0` と、`getrandom = 0.4.2`、`constant_time_eq = 0.6.1` です。PBKDF2 は hmac のみを有効にします。SHA1 は既定の alloc／oid を無効にし、zeroize のみを有効にします。AES／HMAC でも zeroize を有効にします。フォーマットライブラリー、ネイティブ圧縮ライブラリー、実行時ダウンロードは追加しません。CTR、ランダムソルトによるラッピング、導出結果の分割、パスワード検証値、認証済み EOF はプロジェクトで実装します。汎用プリミティブによって ZIP パーサーを再導入してはいけません。

これらのパッケージと推移的な cipher／digest 依存関係は Cargo.lock で固定し、crates.io と上流から取得します。AES／HMAC／SHA1／PBKDF2／zeroize／getrandom は MIT または Apache-2.0、constant_time_eq は CC0-1.0 または MIT-0 または Apache-2.0 で、実際に固定したパッケージのテキストに従います。SHA-1／PBKDF2 のパラメーターは WinZip AES に由来し、別途選択したユーザーパスワード保存方式には使用しません。ビルドスクリプトはプラットフォーム設定のみを行い、ネットワークダウンロードや C デコーダーのコンパイルはありません。

`zeroize` は AES 0.9.3 の鍵消去機能を満たすため 1.9.1 に統一して固定します。ホスト、ネイティブアダプター、更新、プローブのパスワードコンテナーは、同じメジャーバージョンを 2 つ持たず一つのバージョンを維持します。秘密情報の Debug は引き続き伏せ字にし、導出バッファーと展開済み鍵はライブラリーがサポートするゼロ化ライフタイムを使用します。過去のすべてのメモリーコピーを消去できるとは主張しません。採用審査にはロックファイル、ライセンス、実際の機能ツリー、失敗テスト、独立した 7-Zip 相互運用を含めます。脆弱性照会の元応答はビルド成果物に残し、アドバイザリーなしの成功した照会も脆弱性がないことの保証ではありません。

## WP-11 TAR/GZIP

[tar 0.4.46](https://docs.rs/tar/0.4.46/tar/) を厳密に固定し（crates.io、[上流ソース](https://github.com/alexcrichton/tar-rs)、MIT または Apache-2.0）、既定の xattr 機能を無効にします。これは独立した開発テストの読み書き参照にのみ使います。製品の TAR ヘッダー、PAX、作成、書き換えには第三者 TAR パーサーや Builder、汎用 unpack、所有者／権限の復元ではなく、[独立した Rust レコード層](../../engineering/independent-rust-codecs.md)を使います。製品依存集合への tar と filetime の再導入は禁止し、テストと過去の提供物のライセンスは残ります。クロスプラットフォームの名前の相互運用のため、エンコード時に PAX UTF-8 パスと範囲外の数値を明示的に書き込みます。

GZIP は第三者の製品用依存関係を持たない独立した `xdzip-compression` 実装を使用し、RFC 1951 Deflate、RFC 1952 フレーミング、CRC-32 を含みます。圧縮入力とデコード出力にはホストのキャンセルとバイト予算が適用されます。完全なデコードでは各メンバーの CRC と ISIZE を検証します。`flate2` 1.1.10 は開発テストの参照です。ZIP と GZIP は同じ自社 Deflate アルゴリズムを使用します。実行時ルーティングは一つの論理ファイルを公開する[単独 GZIP](single-file-streams.md)と、TAR ディレクトリーツリーを公開する [TAR.GZ](tar-gzip.md)を区別します。

tar のテスト用推移依存関係には filetime 0.2.29（MIT または Apache-2.0）が含まれ、cfg-if と libc を再利用します。filetime は codec の製品依存集合には入りません。新しいダウンロード型ビルドスクリプト、実行時ネットワーク要求、外部プロセスのフォーマットバックエンドはありません。既存の collect-notices.py はロックファイルからライセンスを収集します。テストパッケージがロックファイルにあることは製品にリンクされていることを意味しません。システム tar と Python tarfile はテスト専用で、実行時依存関係には入りません。

2026-10-15 の tar 0.4.46、filetime 0.2.29、flate2 1.1.10 に対する厳密なバージョンの OSV 照会ではアドバイザリーはありませんでした。元の応答は build/review/wp11 にのみ保持します。これは脆弱性がないことの保証ではありません。双方向の相互運用、不正入力、クォータ、キャンセル、3 プラットフォームの検証は実際に実行する必要があります。証拠は [WP-11 契約](tar-gzip.md)からリンクします。

Mac 更新統合では Sparkle 2.10.0 と `xdzip-proxy.2` プロキシ拡張を固定します。SDK、ソースアーカイブ、パッチ、完全なライセンステキストのハッシュは[依存関係設定](../../../scripts/sparkle-dependency.json)にあります。これはアプリケーションの更新のみを扱い、アーカイブのデコードは行いません。公式 SDK 元来のライセンステキストには MIT、BSD-2-Clause、Zlib が含まれ、Mac の通知に保持します。ローカルの対応ソース収集器はオフライン準備と動的フレームワークの再リンクのため固定ソースと公式 SDK アーカイブを保持します。リリースプロトコルにより、このアーカイブは Release または Actions のダウンロード資産として提供しません。

必要時の Qt ワークフローの Mac ジョブは SDK を外部リンクし、フレームワークを配置しません。専用パッケージ化では一時コピーに組み込み、非サンドボックスアプリで有効にしない XPC サービスを削除し、必要なインストールヘルパーを保持します。削減と移動の後、ヘルパー、フレームワーク、アプリケーションの順に ad-hoc 完全性署名を行います。ヘルパーには必要な Hardened Runtime と特定のエンタイトルメントを保持し、汎用ネイティブライブラリー再署名コマンドを適用してはいけません。配置の帰属、SBOM、ライセンス、ソース資料をバージョンとともに記録します。

## 実験的なインストーラーツール

Windows ビルドはプロジェクトのランタイムディレクトリー向けユーザー単位インストーラーをコンパイルするためだけに Inno Setup 6.7.3 を導入します。ソースは [jrsoftware/issrc 公式リリース](https://github.com/jrsoftware/issrc/releases/tag/is-6_7_3)で、不変のソースコミットと公式バイナリー、中文言語リソース、ライセンステキストの SHA-256 は [installer-toolchain.json](../../../scripts/installer-toolchain.json)に固定しています。ユーザー単位モードと累積アンインストールログを使用します。NSIS と WiX/MSI は代替案です。この作業では独自のクリーンアップデータベースや企業向け配置規則を維持しません。

コンパイラーを変更せず、固定ソースの Inno Setup License を使用し、著作権、元の来歴、エンジン UI を保持します。テキストは Windows の通知に含めます。推移コードは公式コンパイラー／インストーラースタブの Pascal Script、圧縮、プラットフォームコンポーネントを使用し、ここではエンジンを再ビルドしません。同梱コンポーネントのソースとライセンスは実際の提供物に照らして確認します。コンパイラーは CI の build/ にインストールし、Qt ランタイムディレクトリーには入りません。インストーラースタブは最終インストーラーに入り、回執はそのバージョンとインストーラーのハッシュを記録します。ランタイムディレクトリーの SBOM をインストーラースタブ全体の SBOM として扱いません。

標準的なファイルコピー、ユーザー単位レジストリー、プロジェクトショートカット、ミューテックス保護のみを有効にし、アプリケーションの自動終了／再起動は無効にします。インストール時のネットワークダウンロード、独自ネイティブプラグイン、新しい Rust ビルドスクリプトはありません。Linux .deb は Ubuntu の dpkg-deb とシステム保守ツールを使い、アプリケーションの codec を追加しません。Qt ダウンロードツールの作業ディレクトリーは build/ 内に固定し、aqtinstall.log がソース識別を汚染しないようにします。

公式リポジトリーの公開セキュリティアドバイザリー API は 2026-10-16 に空の一覧を返し、元の応答は build/review/installer-tool-advisories.json に保持しています。これは脆弱性がないことの証明でも完全な NVD 検索でもありません。[公式バージョン履歴](https://jrsoftware.org/files/is6-whatsnew.htm)は後のセキュリティ保守審査に利用できます。6.7.3 の固定は、そのバージョンが最新または長期サポート対象であるとの主張ではありません。ハッシュ検証は署名者の識別やエンジン全体のライセンス／セキュリティ採用審査の代わりにはなりません。実際のコンパイル、インストール、システムでのオープン、更新／ロールバック／アンインストール、失敗は[インストール契約](installers-associations.md)と実際の CI に記録します。

## 旧ファイル名エンコーディングの検出とデコード

[chardetng 1.0.0](https://docs.rs/chardetng/1.0.0/chardetng/) と [encoding_rs 0.8.42](https://docs.rs/encoding_rs/0.8.42/encoding_rs/) を厳密に固定し、どちらも crates.io と hsivonen の上流から取得します。前者は MIT または Apache-2.0、後者のコードは MIT または Apache-2.0 で、WHATWG マッピングデータには追加で BSD-3-Clause が適用されます。LICENSE-WHATWG と COPYRIGHT を保持します。通知収集器は完全なライセンステキストだけでなく COPYRIGHT も含めます。

両方の既定機能を無効にします。encoding_rs は直接には alloc のみを有効にし、検出器のマルチスレッド／rayon は無効にします。新たに固定する推移パッケージは core_detect 1.0.0、multiversion_no_op 1.0.0、scopeguard 1.2.0、simdutf8 0.1.5 で、すべて MIT または Apache-2.0 です。cfg-if 1.0.5、memchr 2.8.3、ビルドマクロ rustversion 1.0.23 は固定済みバージョンを再利用します。core_detect はローカル CPU の能力を検出し、simdutf8 は上流の SIMD UTF-8 検証、multiversion_no_op はコンパイル時の no-op マクロです。新しい C/C++ ネイティブライブラリー、ネットワークビルドスクリプト、実行時ダウンロードは追加しません。encoding_rs のビルドスクリプトはコンパイラーバージョンに応じたローカル設定のみを選択します。CPU 固有の unsafe は保守されている上流コードに残り、ホストは unsafe／FFI を追加しません。

一つの Rust 検出器を使うことで、Qt、システム iconv、Windows コードページの規則が分岐することを避けます。CJK 統計モデルの保守や外部解凍プログラムの呼び出しは、実装と配置の境界を広げます。chardetng の上流は受動的な保守とされており、バージョン／モデルの変更には独立したファイル名サンプルの再実行が必要です。ZIP CP437 はプラットフォーム API を使わず [Unicode CP437 テーブル](https://www.unicode.org/Public/MAPPINGS/VENDORS/MICSFT/PC/CP437.TXT)に基づく固定シングルバイトマッピングです。Python 標準ライブラリーが別途テスト用の生バイトを生成します。検出はヒューリスティックであり、パスの認可や内容検証の証拠ではありません。

新たに固定した 6 パッケージについて 2026-10-24 に厳密なバージョンの OSV 照会を行い、アドバイザリーはありませんでした。生の応答はローカル成果物にのみ保持します。これは対象を絞った確認であり、脆弱性がないことの保証ではありません。採用時には実際の Cargo 機能、ソース、完全なライセンステキストも確認します。回帰範囲、リソース、失敗規則は[ファイル名エンコーディング契約](filename-encoding.md)を参照してください。3 プラットフォームのビルド、内容の相互運用、実際の結果は関連 issue／CI で追跡します。
