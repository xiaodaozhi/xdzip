# TAR/GZIP 実装契約

[English](../../engineering/tar-gzip.md) | [简体中文](../../zh-CN/engineering/tar-gzip.md) | [繁體中文](../../zh-TW/engineering/tar-gzip.md) | 日本語 | [한국어](../../ko-KR/engineering/tar-gzip.md) | [Français](../../fr-FR/engineering/tar-gzip.md) | [Deutsch](../../de-DE/engineering/tar-gzip.md) | [Español](../../es-ES/engineering/tar-gzip.md) | [Português (Brasil)](../../pt-BR/engineering/tar-gzip.md) | [Русский](../../ru-RU/engineering/tar-gzip.md)

この契約は TAR/TAR.GZ の閲覧、作成、安全な展開の境界を定義します。プラットフォームの結果と手動受け入れは issue または CI 成果物に記録します。[安全な展開](zip-safe-extraction.md)と [ZIP 作成](zip-creation.md)の入力承認、一時準備、競合、キャンセル、アーカイブ全体のコミットを維持します。

<a name="xdzip-scope-and-capabilities"></a>

## 範囲と機能

TAR と TAR.GZ の閲覧、作成、安全な展開をサポートします。TAR はコンテナー、GZIP は圧縮フィルターです。読み取り時は拡張子でバックエンドを選ばず内容を検出します。ZIP の動作は互換性を維持します。ネストした自動展開、暗号化、分割 TAR は有効にしません。通常の単一ファイル GZIP は別の[ストリーム契約](single-file-streams.md)を使用します。

TAR ヘッダー、数値、PAX、ストリーミングエンコード、書き換えには独立した Rust レコード層を使用します。GZIP フレーミング、CRC-32、Deflate の LZ77/Huffman は共通の `xdzip-compression` を使用します。`tar` と `flate2` は開発テストの参照用であり、これらの crate の製品依存関係の閉包には入りません。仕様、ソース、制限は[独自形式契約](../../engineering/independent-rust-codecs.md)を参照してください。

TAR は通常ファイルとディレクトリーを受け入れ、PAX パスと GNU 長い名前を解析します。シンボリックリンク、ハードリンク、デバイス、FIFO、スパースファイル、未知の型は展開できません。すべての出力名は引き続き PortablePath とホストの競合事前検査を通り、形式ライブラリーにはファイルパスや展開権限を与えません。ディレクトリー権限、所有者、特殊モードは復元しません。日付は表示用メタデータであり、復元は保証しません。

<a name="xdzip-bounded-streaming"></a>

## 制限されたストリーミング

従来のファイル名エンコード、GNU 長い名前、PAX UTF-8/BINARY 宣言は[エンコード契約](filename-encoding.md)に従って統一的に解決します。インデックスは全走査後にのみ公開し、走査中は項目数と合計が不明です。メタデータには 100,000 項目、名前ごとに 4,096 バイト、名前の累積予算を維持します。ストリーミングソースのエンコード入力とデコード作業はそれぞれ最大 24 GiB、GNU/PAX 拡張ヘッダーは 1 つ最大 64 KiB、項目ごとに最大 4 つです。グローバル PAX は git archive との互換性のため、ファイルの意味を持たないコメントだけを受け入れます。宣言されたレコード長に対して完全に検査し、項目へ継承せず破棄します。グローバル path、size、mtime、linkpath、スパース、未知のフィールドは明示的に拒否し、GNU 長リンクとスパース変種は対象外です。グローバルコメントも項目ごとの 4 ヘッダーとストリームバイトの予算に計上し、未完成のローカル拡張を有効にはしません。TAR 名の一般的な先頭 `./` は正規化し、ルートマーカーは出力項目にしません。順次読み取りとスキップもキャンセルとバイト予算を確認し、シークで破損ストリームの検査を回避できません。GZIP は EOF に達して CRC と ISIZE を検証する必要があります。複数メンバーは一続きの TAR バイトストリームだけを構成します。末尾の非ゼロの余分なデータ、切断、破損は失敗します。未検証の部分インデックスは拒否します。

TAR.GZ には項目ごとの圧縮サイズがありません。高圧縮率の受け入れでは、選択された宣言合計と固定したソース全体のサイズを比較します。1000:1 と 1 MiB を超える場合は明示的な許可が必要であり、その許可でも走査作業や出力の割り当てを回避できません。メタデータ事前検査は項目ごとの圧縮率を作り出しません。

展開では選択項目を物理順に処理します。未選択の内容のスキップも計量され、キャンセル可能です。ランダム読み取りは保証しません。PayloadReader が受け取るのはソースとホストの出力先だけです。ホストは走査、デコード、コミットの境界で引き続きソースバージョンを検証します。項目ごとのコミットと作成全体の失敗の意味は既存の安全な I/O 契約に従います。

<a name="xdzip-creation-and-interface"></a>

## 作成とインターフェース

作成ウィンドウは密度を変えずに既存の TAR と TAR.GZ のセグメントを有効にします。形式切り替えで拡張子を更新します。TAR は圧縮レベルを無効にし、両 TAR 形式はパスワードと分割ボリュームの値を無効化して消去します。TAR.GZ は GZIP レベル 0/1/6/9 を使用します。項目ごとの圧縮サイズは不明で、0 バイトではなくダッシュで表示します。Rust はソース名からアーカイブ名の対象フォルダーを統一的に導出し、制限されたブリッジを通じてプレビューに提供します。TAR.GZ は大小文字を区別せず複合拡張子全体を除去し、基底名が空なら archive にフォールバックします。UI は別の対象を導出せず、PortablePath と承認されたルートが再検証します。メインウィンドウの形式タグは実際の形式と文字幅に合わせます。TAR の日付は UTC で表示し、既存の表示範囲外では不明のままにします。作成時は Unicode または長い名前に PAX UTF-8 パス、大きなファイルに PAX サイズを明示的に書き、参照リーダーによるローカルエンコードの推測を避けます。入力ツリーを固定し、出力をストリーミングし、TAR/GZIP を終了して再走査し、各項目をデコードして検証します。すべて成功後に全体を公開します。競合による名前変更では複合拡張子全体を保持します。

<a name="xdzip-verification-and-limits"></a>

## 検証と制限

システム tar/Python tarfile との双方向相互運用、長いパス、Unicode、空ディレクトリー、重複、PAX/GNU、特殊項目、パス脱出、切断、CRC、リソース制限、キャンセル、既存ファイルの保護を対象にします。実際の Qt 作成、再オープン、展開は既存のタスクと競合ウィンドウを再利用します。実際の証拠は build/ または CI 成果物にのみ生成します。

影響するデスクトップとアクセシビリティの再検証は[共通検証](../../../developers/qa/README.md)に従って選択します。ネイティブ自動化とオフスクリーンチェックは手動チェックの代わりにはなりません。実際の結果と制限は対応する issue に記録します。既存のデスクトップ受け入れは [WP-12 #5](https://github.com/xiaodaozhi/xdzip/issues/5) にあり、一時的な権限や環境の阻害要因はこの契約に残しません。`v0.1.0` の過去のリリースライセンスレビューは [#4](https://github.com/xiaodaozhi/xdzip/issues/4) と [#53](https://github.com/xiaodaozhi/xdzip/issues/53) にあり、今後の候補には新しいリリース issue が必要です。

CLI 作成入口は .tgz を .tar.gz と同形式の別名として受け入れ、同じ GZIP エンコード、検証、コミットを使用します。通常の非 TAR GZIP は別の単一ファイルコーデックを使用します。
