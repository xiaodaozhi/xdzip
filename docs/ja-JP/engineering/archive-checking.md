# アーカイブの整合性検査

[English](../../engineering/archive-checking.md) | [简体中文](../../zh-CN/engineering/archive-checking.md) | [繁體中文](../../zh-TW/engineering/archive-checking.md) | 日本語 | [한국어](../../ko-KR/engineering/archive-checking.md) | [Français](../../fr-FR/engineering/archive-checking.md) | [Deutsch](../../de-DE/engineering/archive-checking.md) | [Español](../../es-ES/engineering/archive-checking.md) | [Português (Brasil)](../../pt-BR/engineering/archive-checking.md) | [Русский](../../ru-RU/engineering/archive-checking.md)

ツールバーの「テスト」は、対象となる現在のアーカイブに対して実際のバックグラウンド検査を一回実行します。現在のディレクトリ、検索、選択に関係なく、重複名、ディレクトリ、空ファイルを含むすべての物理レコードが対象です。ディスクインデックスを使うアーカイブ全体の検査は現在未対応です。[大規模アーカイブのインデックス](large-index.md)を参照してください。検査が保持するのは固定された入力ソースとメタデータのみで、出力先の認可を取得せず、ステージングや出力ファイルを作らず、展開パスの対応付けやリンクの公開を使いません。

UU/UUE と XXE は空ファイルや重複名を含むテキストエンベロープの物理メンバーすべてを検査し、カウント付き行または受理された Base64 パディングと正確な終端マーカーを検証します。チェックサムや認証はなく、有効なアルファベットの文字を置換するとエラーなしにバイトが変化することがあります。ヘッダーのパスとモードは出力や実行の権限を与えません。[テキストエンベロープ契約](text-envelopes.md)を参照してください。

Z と TAR.Z は Unix compress LZW コード、辞書の境界、CLEAR・幅のアラインメント、物理 EOF を検証し、TAR.Z は TAR のレコードと末尾も完全に検査します。内容チェックサム、デコードサイズ欄、認証がないため、構造検査に成功しても内容を保つすべての置換や有効コードの末尾を検出できません。制御されたソースとタスクの同じ上限が適用されます。[compress 契約](compress-streams.md)を参照してください。

<a name="xdzip-formats-and-results"></a>

## 形式と結果

通常の GZIP、BZip2、LZMA Alone、Lzip v1 は同じ上限付き破棄先にデコードし、正確なストリーム終端と観測サイズを検証します。GZIP は各メンバーの CRC/ISIZE、BZip2 はブロックと結合 CRC、Lzip は CRC、データサイズ、メンバーサイズを検査します。LZMA Alone は内容チェックサムがないため、成功で確認できるのは構造と可読性です。フィルター付き TAR の組み合わせは圧縮 EOF を含むコンテナー全体を再走査し、ペイロードの二回目の処理は行いません。検査の強度は[組み込みレジストリ](format-registry.md)、上限とプロファイルは[ストリーム契約](single-file-streams.md)に従います。

ZIP は対応する番号付き分割と PKZIP 分割を含む対象の ZIP/ZIP64 アーカイブを検査します。デコーダーは対応メンバーのデータを上限付き破棄先で検査し、中央ディレクトリとローカルヘッダー、デスクリプター、正確な終端、宣言サイズ、CRC、受理された AES-256 認証を検証します。暗号化されていない Deflate64、BZip2、LZMA、XZ 項目には後述の追加制限が適用されます。安全な名前の ZIP シンボリックリンクはターゲットを解決せずリンクを作らずにペイロードを検査します。未知の方式、未対応の暗号化、危険な名前、その他の未受理レコードは検査を失敗させます。

7z と RAR は分離ワーカー内の独立した Rust バックエンドを使い、各物理項目を同じ上限付き破棄先へデコードして、デコード終端、宣言サイズ、コンテナーが実際に提供する検査を検証します。選択項目に到達するためソリッドブロック内でデコードした他のデータは作業量としてのみ計上し、現在のファイルの検証済み数には加えません。ディレクトリ、空ファイル、暗号化項目を飛ばして全体成功とは報告できません。旧 RAR、RAR5、新しい RAR 7 のアルゴリズムは独立した内容既知のサンプルで受け入れており、マジックが同じだけではバージョン互換性を証明しません。

CAB は分離ワーカー内の自社 Rust コンテナーと共有アルゴリズムを使い、ボリューム集合、実際のデコードサイズ、完全なデータフレームが提供する検査を検証します。ISO/UDF は記述子、ディレクトリ、データ範囲、宣言サイズを検査し、対応する通常ファイルをすべて実際に読みます。一般にファイルごとの内容チェックサムがなく、構造を保つ任意の改ざんを検出できません。イメージ内のリンク、デバイス、その他の未対応レコードを飛ばして全体成功とは宣言できません。ハイブリッドイメージは固定された UDF 名前空間を使い、失敗後に ISO へフォールバックしません。

TAR と TAR.GZ は検査タスク内で完全なストリームを順次再走査し、固定された物理レコードのメタデータと照合してヘッダーチェックサム、長さ、二つの終了ブロック、末尾を検査します。TAR.GZ は EOF まで進んで GZIP CRC/ISIZE を検証し、完全走査後に内容をもう一度すべて展開しません。TAR はファイル内容チェックサムを持たず、確認できるのは形式構造と可読性だけで、構造を保つ任意の内容改ざんは検出できません。TAR のリンク、特殊オブジェクト、スパースファイルは未対応です。この機能はソースの信頼性を証明せず、マルウェアも検査しません。

Compound File (MSI) はコンテナー構造と生ストリームの可読性を検査しますが、内容チェックサムはありません。NSIS が公開するのは静的なインストーラーメタデータのみです。制限は [MSI と NSIS の形式対応](wim-msi-installer-format-sources.md)を参照してください。

最初の構造、ペイロード、ソース、リソース、未対応項目のエラーでタスクを終了します。結果は成功、失敗、キャンセルを区別し、検証済みと未検査のファイル数を示し、失敗項目と安定したエラーコードを保持します。全物理レコードを検査しますが、`files`/`verified_files` は空ファイルを含むディレクトリ以外のファイルだけを数えます。ディレクトリとディレクトリだけのアーカイブも、成功前に構造検証を完了する必要があります。検査中または以前に読み取りが完了しても、アーカイブ全体が合格したことにはなりません。

<a name="xdzip-scheduling-source-and-resources"></a>

## スケジューリング、ソース、リソース

`Check { session }` は `Source::fork()` でソースを固定し、形式、メタデータ、元セッションの識別情報も固定して、作成・展開と同じ上限付きの重いタスクキューとアプリ全体の逐次受け入れに入ります。開始時、読み取り後、成功した終端状態の前に、ソースハンドルと各ボリュームパスの識別情報、サイズ、時刻を再検査します。ソース変更は `source_changed` を返し、対応する元セッションだけを無効にします。これはベストエフォートの検出であり、入力内容のアトミックなスナップショットではなく、識別情報と時刻を保つ同時のインプレース変更の検出を保証しません。

実際のデコードはファイルごとに 8 GiB、タスクごとに 20 GiB 以下です。誤ったパスワードの再試行でも累積作業量はリセットしません。ZIP は位置メタデータ用の独立した 64 MiB 予算と実際の入力読み取り用の共有 20 GiB 予算を維持します。TAR/GZIP は既存の完全ストリーム読み取り 24 GiB 上限を維持します。7z/RAR/CAB/ISO/UDF はさらにネイティブワーカーに 1 GiB のメモリー上限を使います。入力読み取りとソリッドスキップにも上限があり、超過はリソースエラーであって整合性合格ではありません。タスク・イベント数、スナップショット詳細、保持メモリーは既存のキュー上限に従います。成功した終端状態は書き込み、確定、保存ディレクトリ、出力パスのカウントを設定しません。

タスク種別は `kind=check` として Qt に明示的に送られます。`read_bytes` はヘッダーと再試行を含む実際のソース読み取り、`decoded_bytes` は実際のデコード作業、`verified_bytes`/`verified_files` は必要な検査の完了後にのみ増加します。TAR/GZIP の完全走査中にファイル単位の割合を捏造せず、実際の読み取りバイトと速度は表示し続けます。完全ストリームのファイルは成功後にのみ検証済みとして数えます。

AES パスワードは[パスワードプロトコル](password-extraction.md)を再利用します。独立した制御枠、一回限りのプロンプト ID、タスク内キャッシュ、項目ごとに最大十回の誤検証値応答、認証破損時の即時失敗、秘密のゼロ化です。キャンセルとシャットダウンは通常コマンドキューの容量に関係なくパスワード待機を起こします。閲覧ページや進捗ウィンドウを閉じても受理済みタスクはキャンセルされず、グローバルなタスク入口から結果を開き直せます。明示的な終了ではキャンセルと非同期のスレッド待機を引き続き待ちます。

<a name="xdzip-verification-boundaries"></a>

## 検証の境界

コア回帰は対応形式、空ファイル、ディレクトリ、重複名、ZIP リンクのペイロード、パスワード再試行・キャンセル、破損データ、ソース変更、実際のカウント、出力がないことを対象とします。ブリッジと Qt の検証はツールバーからバックグラウンドタスクと結果までの実際の流れを対象とし、パスワードの振り分け、過去タスク、セッション間の受け入れ、終了は別々に検査します。二言語・複数字号、ライト・ダーク、ネイティブデスクトップの視覚受け入れは issue に別途記録します。生成された証拠は build/ または CI 成果物にのみ置きます。

旧 RAR の暗号化項目には、誤ったパスワードと内容破損を確実に区別できる検証値がありません。暗号化項目をデコードする前にそれぞれパスワードを要求し、別の秘密を使う可能性のある後続項目に前項目のパスワードを自動適用しません。RAR5 と他の対応形式はタスク内の再利用を続けます。信頼できるパスワード検証値がない暗号化デコードまたは暗号化ヘッダー整合性の失敗は `password_or_integrity` と報告し、誤パスワードと破損の曖昧さを維持します。平文ヘッダー検査、ソース変更、キャンセル、上限、出力 I/O をパスワード問題と誤分類しません。

非圧縮サイズが不明なアーカイブも閲覧できます。全体検査は合計を不明とし、ペイロードを開く前またはパスワードを要求する前に `unsupported_feature` で失敗し、実際の検証済み数とデコード数を保持します。不明サイズを空ファイルとして検査せず、内部センチネルを進捗の分母に使いません。

XZ と TAR.XZ は `format_declared_checks` を使い、宣言された CRC32/CRC64/SHA-256 と構造フィールドをすべて検証します。None を宣言するストリームには内容チェックサムがありません。インターフェースはすべての入力にチェックサムがあると約束せず、この違いを示します。暗号化されていない新しい ZIP 方式 9/12/14/95 も正確なデコードサイズと外側 ZIP CRC が必要で、LZMA データデスクリプターには EOS が必要です。未知の方式は表示されますが検証済み内容には数えません。

AES Crypt は `format_declared_checks` と保持されたオープンパスワードを使います。完全な暗号文 HMAC はメタデータ受け入れ前と実際のタスクデコード後に合格する必要があります。バージョン 0–2 は末尾の長さの剰余を認証せず、拡張も認証されません。成功は[AES Crypt 契約](aescrypt-envelopes.md)に記載された形式宣言の検査に限定されます。

Brotli と TAR.BR は `structure_and_readability` を使います。完全なストリーム終端、宣言されたメタブロックサイズ、受理されたすべての辞書・履歴変換に合格する必要がありますが、Brotli には内容チェックサムがありません。[Brotli 契約](brotli-streams.md)を参照してください。

LHA/LZH は `format_declared_checks` を使い、対応する通常ファイルをすべて実際にデコードし、正確な長さと存在するすべてのヘッダー・ペイロード CRC-16 を検証します。古いレベル 0 メンバーは CRC を省略でき、その場合は構造、サイズ、可読性だけを検査します。LH2 は CRC に結び付いた有限バリアントの受け入れが必要です。未知の方式、疑わしい名前、リンク、特殊オブジェクトは全体成功を妨げます。[LHA 契約](../../engineering/lha-containers.md)を参照してください。

PMA は `format_declared_checks` を使い、受理された PM0/PM1/PM2 メンバーを完全にデコードして正確なサイズと存在するすべてのペイロード CRC-16 を検証します。CRC がないメンバーは構造、サイズ、可読性だけを確認できます。未知の方式と他の未対応項目は全体成功を妨げます。CP/M パディングは圧縮メンバー範囲外の物理コンテナー構造として検証します。[PMA 契約](pma-streams.md)を参照してください。

ARJ は `supported_content` を使います。完全なメタデータ受け入れはメイン、ファイル、拡張ヘッダーの CRC-32 を検証し、検査は受理された通常メンバーを Store または方式 1–4 で完全にデコードし、正確なサイズと必須ペイロード CRC-32 を検証します。CRC 対象の旧テキストバイトは改行を変換せず保持します。未知または未対応のレコードは全体成功を妨げます。[ARJ 契約](arj-streams.md)を参照してください。

ARC は `supported_content` を使い、完全な物理受け入れ、旧・新 Store または方式 3–9 による実際のデコード、正確なデコードサイズ、必須 CRC-16/IBM を検証します。未知の方式、疑わしい名前、未対応プロファイルを飛ばして全体成功とは宣言できません。ヘッダーの SHA 結合はスナップショット検査であり、認証ではありません。[ARC 契約](arc-streams.md)を参照してください。

BH は `supported_content` を使い、完全な `BH 05 07` メンバー構造、方式 8 の生 Deflate 終端、正確なデコードサイズ、必須 CRC-32 を検証します。未知の方式、不正な定数、疑わしい名前、未対応プロファイルは表示されますが全体成功を妨げます。[BH 契約](bh-containers.md)を参照してください。

ALZ は `supported_content` を使い、完全な単一ボリューム構造、Store または生 Deflate のペイロード終端、正確なデコードサイズ、必須 CRC-32 を検証します。暗号化、デスクリプター、改変 BZip2、分割、未知方式のレコードは表示されますが全体成功を妨げます。[ACE、ALZ、EGG のソース条件](ace-alz-egg-format-sources.md)を参照してください。

EGG は `supported_content` を使い、暗号化なし・非ソリッドの完全な単一ボリューム構造、Store または生 Deflate ブロックの終端、正確なブロックサイズ、必須 CRC-32 を検証します。AZO、BZip2、LZMA、暗号化、分割、ソリッド、未知方式のレコードは表示されますが全体成功を妨げます。[ACE、ALZ、EGG のソース条件](ace-alz-egg-format-sources.md)を参照してください。
