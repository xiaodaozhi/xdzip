# ユーザーが開始する更新の契約

[English](../../engineering/software-update.md) | [简体中文](../../zh-CN/engineering/software-update.md) | [繁體中文](../../zh-TW/engineering/software-update.md) | 日本語

Windows の MSIX パッケージ識別情報がある場合、「xdzip について」にアプリ内更新を表示せず、更新コントローラーは既存の GitHub 更新確認を拒否します。Store 版の更新は Microsoft Store が管理し、サイドロードされたパッケージにはアプリ内自動更新を保証しません。識別情報の問い合わせエラーは、インストーラー更新の誤使用を防ぐためパッケージ化された識別情報として扱います。通常のインストールとその他のプラットフォームは変更しません。

スタンドアロン CLI とデスクトップパッケージ内の CLI は、[コマンドライン契約](command-line.md)に従ってそれぞれのインストールを更新します。スタンドアロン CLI は別の署名付きマニフェストと管理対象バージョンディレクトリを使います。バンドル CLI は同一ユーザーの単一インスタンス IPC に候補意図を渡し、デスクトップ側のコントローラーが独立して検証します。受理は handed_off を意味するだけで、実際の成功には受領記録と実行中の識別情報が必要です。Windows/Linux のインストール使用中保護には CLI タスクも含まれます。macOS は共有使用ロック、コミットゲート、永続状態で CLI を保護します。既存タスクは暗黙にキャンセルされません。ヘッドレス CLI の識別情報問い合わせは QApplication を作成せず、インストール受領記録を読み取ったり消去したりしません。

アプリケーションの `UpdateController` は「xdzip について」から公開リリースを確認します。この画面を閉じても確認やダウンロードはキャンセルされず、再度開くと同じ状態を表示します。確認はユーザーが開始し、起動時のポーリングや自動インストールは行いません。製品のウィンドウは「xdzip について」と共有操作コントロールを引き続き使用します。

## 選択、ネットワーク、プライバシー

Qt 更新クライアントはメタデータ、チェックサム、パッケージのダウンロードに HTTP/1.1 を使います。これは固定した Qt リリース向けに公開された緩和策を適用するものです。macOS の Sparkle 更新通信は別です。[Qt のセキュリティ勧告](https://www.qt.io/blog/security-advisory-cve-2026-96432)

クライアントは固定リポジトリ `xiaodaozhi/xdzip` の公開 [Releases API](https://docs.github.com/en/rest/releases/releases) のみを読み取り、認証情報を使わず、ファイル名、アーカイブの内容、パスワード、最近の記録、設定を送信しません。GitHub とダウンロード CDN は接続情報とアプリケーションバージョンを含む User-Agent を受け取ります。リリースページとダウンロードフォルダーはシステムのインターフェースで開きます。

各ページは最大 100 件、最大 10 ページです。各応答は最大 8 MiB、マニフェストは 256 KiB、署名は 4 KiB です。元の要求は HTTPS と明示的に登録された GitHub/CDN ホストのみを許可します。ユーザーがミラーを設定した場合、その HTTPS サイトを転送先として許可し、リダイレクトは最大 5 回です。メタデータはアイドル 15 秒、合計 30 秒、ダウンロードはアイドル 30 秒、合計 1 時間が上限です。メモリ内 ETag キャッシュは最大 24 件で、304 は以前の成功応答のみを再利用します。オフライン、TLS、タイムアウト、レート制限、切断、不足パッケージ、マニフェストエラーは「最新」ではなく失敗です。繰り返しクリックしても更新は並列に開始しません。

更新は、設定されたシステム、直接接続、認証情報なしのカスタム HTTP/SOCKS5 プロキシを使います。任意のミラーは HTTPS を使い、認証情報、クエリ、フラグメントを含めず、そのベースに元の GitHub HTTPS URL 全体を続けます。元の URL は引き続き固定ホスト許可リストを通過する必要があります。ミラーやリダイレクトは署名付きマニフェストの内容、検証、候補の識別情報、インストールゲートを変更しません。設定変更は現在の更新終了後、次の更新に適用します。macOS のネイティブ Sparkle は、システム、直接、認証情報なしのカスタム HTTP CONNECT/SOCKS5 モードをサポートします。各ネイティブインスタンスは開始前に検証済みモードとプロキシアドレスをコピーし、フィードとアーカイブに同じセッションポリシーを使用します。カスタムプロキシが失敗しても直接接続へフォールバックしてはいけません。直接モードは URLSession のプロキシ辞書で HTTP、HTTPS、SOCKS、FTP、PAC、検出の各フラグを数値 0 に明示設定します。nil の辞書や空の新しいプロキシ配列は依然としてシステム既定を意味します。TLS 信頼、リリース署名、独立したインストールゲートは変わりません。

HTTP 429 はレート制限です。HTTP 403 は残りクォータがゼロ、有効な秒単位の Retry-After がある、または GitHub JSON メッセージがレート制限を明示する場合に限ってレート制限と分類します。それ以外の 403 はネットワーク障害とし、クォータ枯渇を推測しません。製品は自動再試行せず、GitHub 認証情報を読み取りません。匿名クォータは送信元 IP で共有され、CI のリポジトリ権限では増やせません。

Qt に依存しない Rust コアはセマンティックバージョン、チャネル、単調増加するビルド番号で候補を選び、固定リポジトリ、6 種すべてのパッケージクラス、アーキテクチャ、パッケージ種別、最小システム契約、一致する候補識別情報を検証します。stable は stable のみ、alpha は alpha、beta、rc、stable、beta は alpha を除外し、rc は rc と stable を受け入れます。dev は公開リリースを確認できます。セマンティックバージョンとビルド番号の両方が増加する必要があり、公開時刻で代用しません。クライアントは現在のシステムの対応状況と Releases アセットのバイト数も確認します。

## 信頼とダウンロード

`release.json.sig` はマニフェストの正確なバイト列を検証します。信頼ルートはクライアントとインストーラーヘルパーに組み込まれ、ダウンロードや要求から追加できません。JSON メタデータは文字列 FFI に渡す前に UTF-8 として検証し、不正なエンコーディングは置換文字で認証済みバイトを変更せず明示的に失敗させます。署名形式、独立した Sparkle 鍵、配信順序、不変アセットは[リリースプロトコル](release-protocol.md)を参照してください。署名がない場合や公開鍵が不明な場合は公式リリースページからの手動ダウンロードのみを案内し、署名不正は明示的に失敗します。本番公開鍵が設定されるまで自動置換は無効です。

Windows/Linux は最大 2 GiB のパッケージを非公開更新キャッシュにストリーミングし、長さと SHA-256 を確認します。正常に公開された場合のみヘルパーへ引き渡します。キャンセルや検証失敗時にはインストール可能な状態を作りません。ポータブル、変更済み、開発・ソース由来、または識別情報不明のビルドは確認とダウンロードのみを提供します。自動置換には Release 構成と有効なコミット識別情報も必要です。Git 識別情報のないソースアーカイブからのビルドはインストール済みとみなしません。インストール識別情報はシステムのインストール記録、実行中パス、パッケージマーカーと一致する必要があります。

macOS は固定された Sparkle 2.10.0 と制限付き `xdzip-proxy.2` プロキシ拡張を使用し、薄い Objective-C++ ユーザードライバーが統合された「xdzip について」に状態を渡します。フレームワークライブラリと Ed25519 は固定されたソースとパッチから Apple Silicon 上でネイティブにビルドし、リソース、インストーラーヘルパー、署名ツールは固定された公式 SDK の由来を保持します。生成フレームワークが上流 SDK とバイト単位で同一とは主張しません。Sparkle はフィードとアーカイブをネイティブに検証し、フィードには同じ選択済み候補のみを含めます。Sparkle が追加の SHA-256 検証を行うとは主張しません。読み取り専用 DMG、App Translocation、未登録の .app、更新公開鍵の欠如では手動インストールを案内します。通常 CI は Sparkle を使うという理由だけで Mac アプリパッケージのデプロイ、署名、アップロードを行いません。

手動フォールバックは、インストール識別情報、セッション、自動更新フィードの欠如、無効なネットワーク設定のうち最初に満たされない条件を表示します。識別情報エラーは一連の確認が失敗したことだけを意味し、どの項目かを推測しません。複数の未充足条件は順に解決する必要があります。「xdzip について」は対応するリリースと DMG の案内へリンクし、app.zip の展開、旧バージョンの終了、アプリの置換を説明します。ダウンロード成功はインストール成功ではありません。

## インストールの引き渡しと復旧

ダウンロード中も既存タスクは続行します。ダウンロードとインストールを選択した後にタスクが実行中なら待機します。ユーザーは待機をキャンセルして更新を延期でき、タスクやパスワード要求を暗黙にキャンセルしません。ヘルパーの準備後、`prepareForUpdate` は実行中タスク、タスク開始、モーダル操作を拒否します。引き渡し開始後は新しいセッションやタスクを受け付けず、インストールコミットを送る前にすべての Rust 接続をクリーンアップして終了待ちする必要があります。引き渡しは「旧プログラムを直ちに再起動する」経路を使いません。

Windows は登録された現在のユーザーのインストールルートからのみ、Qt 不要の独立したヘルパーを非公開キャッシュへコピーします。ヘルパーは署名、サイズ、ハッシュを独立して再検証し、捕捉したメインプロセスの終了を待ってから、対話式のライセンス同意を伴う既存の Inno インストーラーを起動します。インストールゲートは置換中の再起動を阻止します。

インストールルートが安全性検査に失敗した場合、「xdzip について」はネットワーク障害と分類せず、インストールフォルダーの権限またはリリースページからの手動インストールを案内します。既存のディレクトリと識別情報のチェックは緩和しません。

Ubuntu のインストールは固定の `/usr/libexec/xdzip-update-helper` を使用します。一般ユーザーのコーディネーターは固定引数でのみ polkit を呼び出します。root ヘルパーはパッケージを非公開 root ステージングへコピーし、署名と xdzip パッケージ名、アーキテクチャ、バージョンを再検証し、固定 APT 操作だけを許可します。コマンド、任意のパッケージ名、出力先ディレクトリを受け付けず、sudo シェルも使いません。認証のキャンセルと認証エージェントの欠如は別の状態です。未設定の dpkg を成功と報告せず、自動ロールバックや旧プログラムの再起動も行いません。元のユーザーとして新バージョンを再起動する際、許可リストに基づく限定された XDG 設定、データ、キャッシュ、状態ディレクトリとデスクトップ言語は保持しますが、動的ローダー、Qt SDK、テスト環境の上書きは保持しません。これらの変数は root のインストールコマンドに渡しません。

macOS ではすべての終了待ちが完了した後にのみ Sparkle のインストールコールバックを解放します。メインプログラムは、プロバイダーが実際のインストールをコミット済みと示してから SDK のインストール応答を呼び出すまでの間に、終了インターセプターを同期的に解除します。終了待ちバリアだけで最後のウィンドウの早期自動終了を許してはいけません。引き渡しが失敗またはキャンセルされた後の通常終了も、ネイティブヘルパーの監視ゲートを待ちます。実際のアーカイブ置換と再起動は Sparkle が行います。キャンセル後に次の終了時のインストール予定は残りません。フレームワーク、XPC、ヘルパーはそれぞれ必要な署名パラメーターとエンタイトルメントを保持し、共通の再署名規則を一律に適用できません。

Sparkle のキャンセル応答は非同期更新サイクルで処理され、サイクルの完了は別のインストーラープロセスの終了を意味しません。未コミットのインストールでは、通常終了時にキャンセルを要求してサイクルを待ち、システムの `/bin/ps` を読み取り専用で使用して、このアプリの正確なフレームワークパスに一致する Autoupdate プロセスを監視します。それらの終了後にのみ終了インターセプターを解除します。準備完了時に一致するインストーラーを記録します。検査失敗は終了許可ではありません。ヘルパーを強制終了したり無関係なプロセス情報を記録したりしません。準備失敗後の再試行でも、更新ドライバーを置換する前に旧ヘルパーの終了を待ちます。コミット済みインストールは Sparkle 本来の終了と再起動を使用します。

Windows/Linux のトランザクションはランダム ID と固定の ready/proceed/cancel/result ファイル名を使用します。終了前、クライアントはトランザクション、対象識別情報、キャッシュディレクトリを設定内容の内部ではなく、設定の隣にある別の `update-state.ini` に保存します。ヘルパーはゲートを解放し再起動する前に、成功結果をアトミックに書き込みます。次回起動時は受領記録のパスとサイズを制限し、トランザクションと現在のバージョン、ビルド、インストール識別情報を検証します。失敗、受領記録の欠如、不一致では自動再インストールせず復旧を表示します。有効な候補 URL がない復旧記録からも固定の公式リリース一覧を開けます。キャッシュ資料はユーザーの修復用に保持し、公開証拠に完全な非公開パスを含めません。

Sparkle のインストールを解放する前に、macOS は対象バージョンとビルドのローカル試行記録を保存します。再起動後、実際の実行中識別情報と信頼できるインストールマーカーにより完了または復旧を判断します。この記録はインストール権限を与えず、Sparkle の署名検証を代替しません。

## 検証の範囲

Mac のみの診断では製品の完全な一連の処理のみを実行できます。全プラットフォーム検証では、6 件の Sparkle シナリオと製品の完全な一連の処理を常に実行し、6 件を省略する診断オプションは無視します。

ネイティブダウンローダーのシステム競合チェックは、明示的に分離された使い捨てホスト型 Apple Silicon ランナーでのみ、専用の静的プロキシと PAC を一時的に有効にします。最初にシステムモードのフィードとアーカイブが実際にプロキシへ到達し、直接モードでは到達がゼロであることを確認します。HTTPS の対照では接続先を検証し、信頼できない証明書の拒否を維持します。限定されたヘルパーはサービスの完全なプロキシ設定と固定テストドメインの hosts 内容を保存、復元、検証し、EOF とタイムアウト時にも対応します。ローカル実行ではプロキシ、DNS、証明書の信頼設定を変更しません。別の製品全体の一連の処理では、制御された PAC 下での直接インストール、通常再起動、実行中の更新設定スナップショットを検証します。ダウンローダーのチェックはインストール証拠の代わりにはなりません。

Mac の SDK なし HTTPS 受け入れでは、同じデプロイ済みプローブと匿名の実際の更新要求を使用します。記録に含めるのはステータスコード、Qt エラー、許可リスト内のレート制限応答ヘッダーのみで、生のエラー本文、送信元 IP、認証情報は含めません。レート制限を確認後、受け入れドライバーは最大 3 回プローブを開始し、Retry-After とクォータリセットの遅い方まで待ちます。使用可能な主要クォータのリセット時刻がない場合、早期再試行を拒否します。その他の確認済み制限では少なくとも 60 秒から増加する待機を使用します。合計待機時間は 3700 秒を上限とし、超過時は各結果と実際の待機時間を保持して明示的に失敗します。既存の要求ごとのタイムアウト、TLS、応答制限、成功ステータス、SDK 分離は引き続き必要です。再試行を一つの成功にまとめません。この待機は専用受け入れドライバーにのみ属し、製品にバックグラウンド再試行を追加せず、最後の専用チェックの省略も許しません。

コアのフィクスチャはチャネル、dev、順序の異なるページ、パッケージ欠如、不正署名、最小システム、識別情報の競合を対象とします。ネットワークフィクスチャはキャンセル、繰り返しクリック、レート制限、TLS、応答制限、ETag、破損ダウンロードを対象とします。セッション回帰ではタスク保持と全終了待ち後の引き渡しを確認します。3 プラットフォームの実際の旧版から新版への更新、認証キャンセル、再起動、インストール失敗と復旧、設定・関連付け保持、SDK なし HTTPS には分離されたプラットフォーム証拠が必要です。単体テストや CI のコンパイルでは代替できません。Mac の完全な更新にはネイティブ Apple Silicon が必要です。実際の完了と証拠は issue で追跡します。

[専用ネイティブ更新回帰](../../../.github/workflows/update-regression.yml)は手動実行のみで、本番シークレットを持たず、アプリパッケージをアップロードしません。既定は全プラットフォームで、診断用に単一プラットフォームを選択でき、それぞれ独立したキューを持ちます。最終受け入れには同一コミットの全プラットフォーム結果が必要です。使い捨て GitHub ランナーの Windows と専用コンテナの Linux では、まず自前の C プロトコル製品と実際の Inno/APT でヘルパーのキャンセル、失敗、復旧を検証します。別の非公開 Qt 更新チェーンでは、2 つの実際の `browser_main`/QML バージョンをビルドし、「xdzip について」で実際のマウス入力を使い、マニフェストとパッケージ、終了待ち、Inno/APT、一般ユーザーの単一インスタンス再起動と受領記録の復旧を検証します。設定、未知の設定キー、既存の既定値、無関係なインストールディレクトリ内ファイルの保持も確認します。Linux はビルド SDK とランタイムのコンテナを分け、ランタイムにはコンパイラーや Qt SDK がなく、カスタム XDG ディレクトリを使用します。Windows Server CI は非公開マクロ下でのみ最小システム判定を代替し、ネイティブ Windows 11 の受け入れを代替しません。このチェーンは公開 GitHub URL のネットワーク通信を代替し、本番 HTTPS/TLS は SDK なしで別途検証します。

別途認可された[本番署名受け入れ](../../../.github/workflows/production-update-acceptance.yml)は、コミット済み本番公開ルートを保持したまま既存の保護環境の鍵を使い、実際の Qt 更新・復旧チェーンを実行します。準備段階では署名しません。独立した署名ステップがまず公開信頼ルートとの厳密な一致を確認し、その後この固定候補を検証します。実行はシークレットを含む環境を拒否します。任意のアセット署名や公開のインターフェースはありません。署名済み候補は使い捨てランナー内に留まり、公開アーティファクトには限定された診断と要約のみを含めます。テスト鍵による回帰と分けて記録し、実際の実行のみを合格とします。鍵の一致はインストール成功ではありません。[リリースプロトコル](release-protocol.md)を参照してください。

拡張シナリオではパッケージのダウンロード完了を遅延させ、実際の AES チェックをパスワード待ちまで開始して、更新がタスクを待つことを検証します。パスワードダイアログはネイティブなアプリケーションモーダルのままで、フィクスチャはコントローラーから更新待機をキャンセルし、この段階では「xdzip について」のマウス入力を使用しなかったことを明示的に記録します。キャンセル後も同じタスクとパスワードトークンが残り、入力メソッドの確定イベントとパスワード確認ボタンでチェックを完了した後、「xdzip について」からインストールを再開します。別の実行では、更新とパスワード待ちが共存する間にシステムの終了を実際のメインプログラムへ送信し、実際の「戻る」と「キャンセルして終了」をクリックして、同じタスクとトークン、全終了待ち、インストール引き渡しゼロ、更新前の同じ旧インストールでの通常再起動を確認します。物理デスクトップと人間による入力は必要に応じて別途確認・記録し、ライセンス審査とリリース認可も分離します。

2 セッションのコンポーネント回帰は AppQuitGuard、DesktopIntegration、全セッションのルーティングを通じて同じ終了ウィンドウに入り、AES 待機タスクの「戻る」・キャンセルと終了待ちを確認します。終了確認で覆えるのは管理対象セッション自身のパスワードまたは競合のモーダルだけで、ネイティブ QWidget モーダルは引き続き終了を阻止します。このコンポーネントチェックは、更新待機中の完全なメインプログラムのシステム終了およびネイティブインストール回帰とは分けて記録します。

完全な Mac 製品フィクスチャは最初のシステム終了の前に、同じ作業セッションのパスワードウィンドウが可視で公開され、そのメインウィンドウに所有され、現在のアプリケーションモーダルであり、タスクとパスワードトークンが変わっていないことを実際に観察する必要があります。Rust のパスワード要求だけでは遅延表示の準備完了を証明できません。これらの前提を満たした後に終了を一度だけ送信し、実際の「戻る」、モーダル復元、キャンセル、すべての終了待ちを検証します。タイムアウト時はクリーンアップ前に進行を固定し、後のクリーンアップ中に生成された終了結果で失敗を上書きできません。

非公開 Windows インストール回帰は実際の Inno が新しい `xdzip.exe` をコピーした後、ほかのファイルをコピーする前に一時停止し、新しい識別情報を確認して実際の Qt プログラムを再起動します。ウィンドウ表示や新規セッションなしで起動ゲートが終了コード 11 を返すことを要求し、その後コピーを再開して既存の更新受け入れを完了します。監視ハンドルは直ちに閉じ、テストがインストーラーのゲートを長引かせないようにします。旧版と新版はいずれも Qt 6.8.2 を使用し、アプリパッケージの原子的置換や Qt バージョン間の移行を証明するものではありません。本番インストーラーテンプレートにはこの一時停止はありません。

別名の非公開 Mac Qt アプリは実際の「xdzip について」、2 セッションの終了待ち、Sparkle、署名済み app.zip、新ビルドへの再起動を使用し、フィードやアーカイブの改ざんとキャンセルを対象とします。候補の検出のみループバックの代替手段を使用し、公開 GitHub マニフェストとチャネルは更新コアとネットワーク回帰で別途チェックします。テスト鍵は非公開コピーにのみ注入し、本番リソースは変更しません。実際の実行による証拠のみ合格として記録できます。

Windows ヘルパーの専門テストでは、実際の Inno ライセンスページのキャンセルボタンと非公開の InitializeSetup 失敗注入も操作します。インストーラーログでその経路を確認し、旧識別情報が残り、再起動せず、インストールゲートが解放される必要があります。Linux は実際の pkexec でポリシー拒否、認証エージェント不在、Cancelled を返す標準 D-Bus エージェントを別々に検証します。キャンセルエージェントは固定のテスト UID、アクション、要求のみを扱い、パスワードを受け取らず権限を与えません。成功した更新では既存の ZIP、TAR、GZip の既定の関連付けも確認します。ライセンスボタンの自動操作やテストエージェントは、手動のライセンス確認やシステムデスクトップ認証エージェントの受け入れを意味しません。

完全な Windows/Linux Qt 回帰は、実際に失敗する Inno 初期化パッケージまたは一度だけ失敗する postinst を送信し、実際の要求、トランザクション、失敗受領記録、ゲート解放を記録し、失敗後の自動再起動を禁止します。復旧では通常のメインプログラムを起動します。非公開ネットワークファクトリーが null を返すことで、既定のコントローラーコンストラクターが実際の既定キャッシュから受領記録を読み取ります。復旧状態、同じ実際のインストール識別情報、新規タスク・インストール引き渡し・自動再試行がないこと、設定と ZIP/TAR/GZip の既定値保持を要求します。Linux の postinst 失敗時は新ファイルが既にインストールされている場合があるため、旧版が保持されたと呼ばず、実際の新バージョンと dpkg の半設定状態を確認します。APT 設定の修復と別の成功シナリオへのリセットはフィクスチャだけが明示的に行い、このテスト操作を製品のロールバックと説明しません。

完全な Mac 製品回帰では、テスト所有の旧アプリルートに可逆的な UF_IMMUTABLE を適用し、終了待ち・コミット境界でのキャンセルと実際のコミット後のファイルシステム拒否を区別します。後者では実際のインストールコミット、該当ヘルパー PID の自発的終了、そのヘルパーの権限失敗ログを正確に記録する必要があります。引き渡しキャンセルはインストール失敗の代わりになりません。所有範囲、UID、dev/inode、元のフラグを確認してからフラグを復元します。sudo、インストーラーの強制終了、結果の捏造は行いません。両復旧ケースとも旧版を通常起動して永続試行記録を読み取ります。実際の Apple Silicon アーティファクトが合否を示します。

別の完全な Mac 製品チェーンは、正式なバンドル ID、インストールマーカー、Alternate ドキュメントタイプを保持した 2 つのクリーンな Release ソース識別情報から実際のメインプログラムをビルドし、使い捨てランナーの専用 Applications パスにインストールします。旧版は実際の「xdzip について」と UpdateController を使用してマニフェスト認証、Sparkle インストール、終了待ち後の引き渡しを行います。新版の通常起動で、インストール識別情報、更新受領記録、既定の設定ディレクトリ、設定と未知のキー、単一インスタンス動作、LaunchServices の ZIP 既定ハンドラーを検証します。非公開通信は固定メタデータ URL、認証済みフィード URL、正確なアーカイブ URL のみを対応付けます。署名は実際に検証し、SDK なし HTTPS は別途検証します。回帰では元のユーザーの HOME と既定設定パスを使い、再起動後の復旧をテストパス注入で置き換えません。
