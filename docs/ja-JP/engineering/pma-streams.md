# PMA コンテナーと PMarc メソッド

[English](../../engineering/pma-streams.md) | [简体中文](../../zh-CN/engineering/pma-streams.md) | [繁體中文](../../zh-TW/engineering/pma-streams.md) | 日本語 | [한국어](../../ko-KR/engineering/pma-streams.md) | [Français](../../fr-FR/engineering/pma-streams.md) | [Deutsch](../../de-DE/engineering/pma-streams.md) | [Español](../../es-ES/engineering/pma-streams.md) | [Português (Brasil)](../../pt-BR/engineering/pma-streams.md) | [Русский](../../ru-RU/engineering/pma-streams.md)

PMarc は `-pm0-`、`-pm1-`、`-pm2-` メソッドを持つ LHA に似た逐次ヘッダーを使用します。これらは異なるアルゴリズムを識別し、名前が似た LH メソッドの別名ではありません。読み取り専用の PMA プロファイルは、レベル 0 ヘッダーの PM0、PM1、PM2 メンバーについて閲覧、検査、選択抽出を認めます。不明なメソッドは内容が未対応である警告とともに表示されます。作成、変更、暗号化、分割、修復は認められず、形式レジストリが正式な基準です。

<a name="xdzip-sources-and-reference-boundary"></a>

## 情報源と参照の範囲

美濃吉彦氏の[元のソフトウェアページ](https://www.asahi-net.or.jp/~am9y-mn/fswlist.htm)、[PMarc 2.00 マニュアル](https://www.asahi-net.or.jp/~am9y-mn/doc/pmarc2.doc)、[元のツールパッケージ](https://www.asahi-net.or.jp/~am9y-mn/arc/pmarc200.pma)には、PM2、バイナリ／テキストモード、CP/M の 128 バイトのファイルレコードが記されています。マニュアルは拡張子にかかわらず CP932 のプレーンテキストです。ツールと文書の識別情報、コンパイラー、エミュレーター、独自に作成した入力は[テストデータ](../../../tests/fixtures/pma/README.md)とともに記録しています。元のツールにはそれぞれの条件が適用され、再配布も製品の依存関係への取り込みも行いません。

マニュアルは圧縮ビットストリームの完全な仕様ではありません。限定的な形式の観察には、Simon Howard 氏の [PM2 デコーダー](https://github.com/fragglet/lhasa/blob/v0.6.0/lib/pm2_decoder.c)、Git blob `b711988f2ac8a21ea4081e06020ecbd3fb83c49c`、および [PMA 共通情報](https://github.com/fragglet/lhasa/blob/v0.6.0/lib/pma_common.c)、blob `7433c3b6fcbd742963a7a63a03d21d858e798631` を Lhasa の ISC ライセンスに従って用います。厳密なクリーンルーム実装を主張するものではありません。Rust ではプロジェクトの制限付きビットリーダー、汎用の完全な正準プレフィックス実装、独自に表現したフラットなバイト置換を使い、参照実装の連結リストや木構造はコピーしません。参照アルゴリズムのソースやバイナリは製品にコンパイルされません。

元の PMarc 2.00 はハッシュで固定しソースを検証した CP/M エミュレーション内で実行し、すべての入出力を管理下のテストディレクトリに限定してバイナリ I/O を明示的に選択します。Lhasa 0.6.0 と、文書化された IBM-PC 移植版の元の PMext 2.22 が、それぞれ出力全体のバイトを独立に比較します。元のエンコーダーは長さゼロの入力をスキップして空のアーカイブを作るため、空メンバーが符号化された証拠にはなりません。独自に形式を記述したケースで、28 ビットのリテラルプレフィックスと許容される先頭ビットの変種を別々に検証します。ソース観察、生成データ、実際の参照比較の出所は区別します。

<a name="xdzip-container-requirements"></a>

## コンテナーの要件

PMA のヘッダーとペイロード範囲には、算術、チェックサム、名前、重複、固定されたソース、特殊オブジェクトについて [LHA](lha-containers.md) と同じ規則が必要です。PM0 は Store で、圧縮サイズと元のサイズは等しくなります。PM1 と PM2 を LH デコーダーに渡してはなりません。存在するペイロードの CRC-16 は完全なデコード後に検証する必要があり、メソッドを開いたり一覧表示したりするだけでは内容の有効性は証明されません。

元の CP/M アーカイブはゼロバイトで終わり、次の 128 バイトレコード境界まで `0x1a` で埋められます。許容されるパディング付き形式は正確に整列し、パディングは最大 127 バイトですべてその値でなければなりません。パディングのないコンテナーも、正確なゼロ終端子で区切ることができます。これらは明確なフレーミング要件であり、任意の末尾バイトを無視したり、欠けた終端子を作ったり、デコードされた EOF バイトを追加したりする許可ではありません。コンテナーのパディングはメンバーの圧縮範囲に含まれません。ソースの固定にはパディングを含む物理ファイル全体が必要です。

8 バイトの候補だけでは形式は公開されません。ホストが行を公開する前に、完全なメタデータ連鎖、正確なゼロ終端子、任意の物理パディングを検証する必要があります。弱い形式群のすべての検出は一つの入力計量を共有します。CP/M の空アーカイブは制限付きパディングによって PMA と識別し、区別できない 1 バイトのゼロ終端子は従来の LZH の選択を維持します。強いコンテナーは弱い検出より優先され、生の TAR マーカーとの衝突には完全なコンテナー受理が必要です。ホスト由来の型付き不正入力値を含め、ソース I/O エラーは終端エラーのままです。

ペイロード出力前に物理行 ID、元およびデコード済みの名前、フラグ、サイズ、メソッドを再比較します。PMA メソッド 2 は LHA の LH2 変種を試さず、直接 PM2 に進みます。CRC エラー、未対応メソッド、ソース変更時も、ホストの非公開の一時領域と既存ファイルの保護を維持します。`.pma` は対応プラットフォームでシェルおよびドロップの候補です。専用 MIME タイプは宣言しないため、Linux で PMA の既定の関連付けを追加するという主張ではありません。

レベル 0 基本ヘッダーの長さ 31 バイトとそのチェックサムは、GZIP の `1f 8b` または Unix Z の `1f 9d` と偶然一致することがあります。後続バイトが完全な `-lh`、`-lz`、`-pm` ファミリーマーカーであれば、検出は偶然一致した 2 バイトのストリーム候補を理由に拒否せず、ファミリー全体の受理検証を続けます。マーカーの `-` は受理される GZIP メソッド 8 でも有効な Unix Z フラグでもありません。これは制限付きのヘッダー判別であり、デコードに失敗したペイロードを再試行しません。有効なストリーム形式とホストエラーは通常どおり扱います。

<a name="xdzip-pm1-wire-profile"></a>

## PM1 の形式プロファイル

`Pm1Reader` は PMA アダプターが共有する生の基本処理です。PMA メソッド 1 は固定されたメタデータの比較後、LHA メソッドとは独立に直接ここへ入ります。形式の観察には ISC ライセンスの Lhasa の [PM1 参照実装](https://github.com/fragglet/lhasa/blob/v0.6.0/lib/pm1_decoder.c)、Git blob `bb2937e382c8c8a8f5783b94a96b9b59e2c4e74b` を使用します。Rust は参照の圧縮された相対オフセット木とは独立して固定コードワードを直接表現し、共有の制限付きフラットな最近使用順の置換を使います。厳密なクリーンルームも参照実装への実行時依存も主張しません。

5 ビットのセレクターは 32 種の固定リテラルカテゴリーアルファベットから一つを選びます。カテゴリーは 0/16/32/64/128/192 から始まる順位を、それぞれ 4/4/5/6/6/6 の下位ビットで選択します。セレクター 17 はカテゴリー 3/4 の分岐を繰り返し、カテゴリー 0/1/5 を省略します。重複する両分岐は観察された意味を保ちます。セレクター 31 にはカテゴリービットがなく、順位 0–15 のみを認めます。各リテラルまたはコピーされたバイトが最近使用順を更新します。独立した生成器は製品のコードワード表ではなく、展開された記号アルファベットを使います。

コマンドは明示的な履歴コピーか 1–216 バイトのリテラルブロックです。短いリテラルブロックは、デコード出力が残っていれば後続コピーを意味し、216 バイトのブロックは明示的なコマンド選択に戻ります。宣言された最後のリテラルは、架空のコピーを読まずにメンバーを終了できます。コピークラス 0/1 は長さ 2、その他は 3–244 を符号化します。距離プレフィックスはデコード済み 64/576/2624 バイトで拡大します。クラス 3/4/5 の下位フィールドはそれぞれ 320、832/1088/1600、2880/3136/3648/4672/6720 バイトで拡大します。距離はオフセットに 1 を加えた値で、出力済みの内容を参照する必要があり、重なりと周回を伴う 16 KiB のリングを使います。PM2 の初期空白は PM1 の履歴にはなりません。

リテラルとコピーの長さは宣言済みの残り出力に収まる必要があり、余分な完全な圧縮バイトは拒否します。最後の 1 バイト未満のパディングは無視しますが、欠けたバイトをゼロで補うことはありません。参照実装の歴史的な EOF 修復はこのプロファイルの対象外です。メモリーの許容量は履歴 16 KiB に加え、入力、状態、一時領域に 32 KiB です。圧縮とデコードの各上限は 24 GiB、処理量の上限は 96 GiB で、呼び出し元のより小さい予算も適用します。ソース読み取り、プレフィックス比較、順位移動、ソースに依存しないコピーは、協調的なキャンセルと型付き終端エラーを維持します。

<a name="xdzip-pm2-wire-model"></a>

## PM2 の形式モデル

ストリームは上位ビットから読み、先頭ビットの両方の値を、デコード結果が変わらないことを独立に検証します。コード表は 5 ビットの数 1–29 と 3 ビットの最小長を宣言します。最小長がゼロなら定数記号 `count - 1` を選び、それ以外は 3 ビットのフィールドで各長さの値を読む幅を宣言します。値がゼロなら不在、それ以外なら `minimum + value - 1` です。完全な正準木が必要です。最大 29 葉なら有効な深さは最大 28 で、`Prefix<29>` は既存の Brotli/LZH の `Canonical = Prefix<17>` インスタンスを拡大せずに対応します。不正な数、過剰割り当てまたは不完全な木、過大な深さは使用前に失敗します。

コード 0–7 はバイトの最近使用順位を選び、基数は 0/8/16/32/64/96/128/192、追加幅は 3/3/4/5/5/5/6/6 です。初期順位は 16 進数で `20–7f, 00–1f, a0–df, 80–9f, e0–ff` です。履歴コピーを含むすべての出力バイトを先頭へ移動します。Rust 実装は制限付きのフラットな置換を検索・回転し、実際の比較と移動を計量します。

コード 8–28 はコピーです。クラス 0–14 は長さ 2–16 を生成します。クラス 15–20 は基数 17/25/33/65/129/256 と幅 3/3/5/6/7/0 を使います。クラス 0 は 6 ビットのオフセットを直接読み、クラス 1–19 は位置表を使います。位置ゼロは下位 6 ビットを読み、それ以外の位置 1–7 は下位 `position + 5` ビットを読み、対応する 2 の累乗の基数を加えます。クラス 20 は常にオフセットゼロです。実際の距離はオフセットに 1 を加えた値です。履歴は空白で埋めた 8192 バイトのリングで、重なりや初期履歴への参照はバイト単位の意味を保ちます。

必要な場合、位置表は最初に 3 ビット長を 5 個持ち、出力 1024 バイトで 6 個、2048 で 7 個、4096 で 8 個になります。4096 では明示的なビットがコード表の置換を制御し、その後に 8 位置の表が続きます。8192 以降は 4096 バイトごとに明示的なビットが両表の置換を制御します。イベントは出力バイトの正確な位置で発生し、コピーの途中や出力のちょうど終わりも含みます。元の境界サンプルには最終制御フィールドがあり、省略したり部分出力の成功で代用したりできません。

存在する記号が一つの位置表は定数です。全ゼロの表は不在として表現し、最終制御イベントを含め、使わずに済む場合があります。実際にそれを必要とするコマンドは失敗します。全ゼロ表を架空の記号に修復することはありません。位置表が必要かはコード表の選択で決まります。最後の 1 バイト未満のパディングは無視しますが、論理上の圧縮バイトは正確に終わる必要があり、余分な完全バイトは拒否します。

<a name="xdzip-limits-and-failure"></a>

## 制限と失敗

PM2 は 8192 バイトの履歴に加え、バッファー入力、プレフィックス表、最近使用状態、制限付き一時領域に 32 KiB を認めます。圧縮サイズとデコードサイズはそれぞれ 24 GiB、アルゴリズムの処理量は 96 GiB が厳格な上限です。呼び出し元のより小さい予算も適用されます。構築、表の読み取り、最近使用操作、コピー、ビットを計量し、`work_remaining()` はメンバー間で実際の処理量を保持します。読み取りは最大 8192 バイトを返し、追加のソース読み取りがなくても協調的に確認します。

再試行するのは追加情報のない `Interrupted` I/O のみです。型付き中断はその情報を保持して終了し、ソース、不正データ、キャンセル、リソースのエラーはインスタンスを以後使用不能にします。ホストは正常に最後まで読み、宣言サイズと CRC を検証し、成功するまで出力を非公開に保つ必要があります。生のリーダーにはファイル名、プロセス、権限、ファイルシステムへの公開権限を渡しません。生のテスト、完全なコンテナーテスト、runtime/CLI/Qt のタスク、別プラットフォーム、リリース許可は別々の証拠です。
