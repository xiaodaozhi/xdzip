# ASAR コンテナーの契約

[English](../../engineering/asar-containers.md) | [简体中文](../../zh-CN/engineering/asar-containers.md) | [繁體中文](../../zh-TW/engineering/asar-containers.md) | 日本語 | [한국어](../../ko-KR/engineering/asar-containers.md) | [Français](../../fr-FR/engineering/asar-containers.md) | [Deutsch](../../de-DE/engineering/asar-containers.md) | [Español](../../es-ES/engineering/asar-containers.md) | [Português (Brasil)](../../pt-BR/engineering/asar-containers.md) | [Русский](../../ru-RU/engineering/asar-containers.md)

形式は Electron の [ASAR の説明](https://github.com/electron/asar#format)と Chromium の [Pickle の契約](https://chromium.googlesource.com/chromium/src/+/main/base/pickle.h)に従います。サイズを格納する八バイトの Pickle の後に、JSON ディレクトリーツリーを格納する Pickle 文字列が続きます。ファイルのオフセットはデータ領域からの相対位置を表す十進文字列です。同じ記録バイトを複数のファイルで共有する場合も、各エントリーは固有の識別子を保持します。任意の整合性情報はファイル全体と各固定長ブロックの SHA-256 を宣言します。この情報はデータ破損の検出に使い、パッケージやアプリの認証には使用できません。

<a name="xdzip-admission-and-identity"></a>

## 受け入れ条件と識別

ツリーを解析する前に、リトルエンディアンの四つの長さフィールド、四バイト境界への整列、文字列の正確な長さ、ゼロパディング、入力元の範囲を検査します。ヘッダーは 8 MiB、入れ子は 64 個のパス要素までとし、ノード数と保持する名前のバイト数には共通の走査上限を適用します。一般的な JSON を上限付きで解析し、重複キーを拒否し、オブジェクトの順序を保持します。不正な UTF-8、誤ったフィールド型、整数でない値や安全な範囲外のサイズ、桁あふれする十進オフセット、未知の必須プロファイルを拒否します。名前の要素は接頭部分とは独立に検査します。安全でない元の名前は警告と非対応の印を付けて表示に残し、ホストが出力を拒否できるようにします。

明示的なディレクトリーと空ファイルを含め、JSON ツリー順で物理識別子を割り当てます。ルートオブジェクトは構造用です。同じデータ範囲を使うエントリーは個別に保持します。一部だけ重なる範囲、許可された入力元の範囲外、参照されない末尾データを拒否します。整合性宣言がないファイルは、構造と読み取り可能性だけを確認します。宣言がある場合は、ダイジェスト長、アルゴリズム、ブロックのサイズと数、空ファイルの規則をすべて検査します。非対応の宣言は明示的に報告します。

<a name="xdzip-read-only-export-and-verification"></a>

## 読み取り専用の書き出しと検証

バックエンドは許可済みのシーク可能なストリームとホストの出力先を受け取ります。他のパスを開いたり、リンクをたどったり、アプリを実行したりしません。`unpacked` レコードは表示しますが、処理は非対応です。隣接する `.asar.unpacked` ディレクトリーは入力の許可対象外です。宣言されたリンクの識別子は保持しますが、リンク操作には対応しません。実行可能フラグはモード復元や実行を許可しません。パスワード、分割ボリューム、作成、書き換えはこのプロファイルの対象外です。

データを使う前にヘッダー全体を再解析し、得られたインデックスを変更不能なホストのスナップショットと比較します。上限内のオフセットと任意のダイジェストを内部で保持します。累積入力とデコード済みバイトの上限およびキャンセルの制約に従って、格納範囲を順次読み取ります。成功を報告する前にファイル全体とブロックの SHA-256 を検査します。空ファイルも対象です。検査中のデータは専用の一時作業領域に書けますが、検証済みファイルを確定できるのはホストだけです。SHA-256 の処理量にはパディングを含めて実際に処理した 64 バイトの圧縮ブロックを数えます。入力、出力済みバイト、ハッシュ処理量にはそれぞれ専用の 24 GiB 上限があります。ホストのタスク上限はさらに厳しい場合があります。共有範囲を再読しても許容量は戻りません。エラー後は開いたリーダーを使い続けられません。入力元の識別検査は可能な範囲で変更を検出するもので、アトミックなスナップショットや認証済みのスナップショットは保証しません。

形式の登録には、バージョンを固定した参照ツールが生成した、または同ツールで独立に読み取った管理下の入力が必要です。ディレクトリー、空ファイルと UTF-8 名のファイル、共有データ、複数ブロックの整合性宣言の有無、外部レコード、実行可能宣言を含めます。回帰検査では、JSON の重複キー、算術、整列、切り詰め、重なり、不正なダイジェスト、安全でない名前、入力元の変更、厳密な割り当て、キャンセル、出力失敗を確認します。ランタイム、CLI、Qt の実タスクと、影響する候補表示、読み取り専用動作、検査結果の注記、レイアウトの確認を自動化します。参照ツールと生成した検証記録は `build/` に置き、テスト入力と生成コードはバージョン管理します。進捗と実際の受け入れ結果は該当する issue に記録します。
