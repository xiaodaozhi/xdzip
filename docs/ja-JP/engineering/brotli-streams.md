# 通常の Brotli ストリーム契約

[English](../../engineering/brotli-streams.md) | [简体中文](../../zh-CN/engineering/brotli-streams.md) | [繁體中文](../../zh-TW/engineering/brotli-streams.md) | 日本語 | [한국어](../../ko-KR/engineering/brotli-streams.md) | [Français](../../fr-FR/engineering/brotli-streams.md) | [Deutsch](../../de-DE/engineering/brotli-streams.md) | [Español](../../es-ES/engineering/brotli-streams.md) | [Português (Brasil)](../../pt-BR/engineering/brotli-streams.md) | [Русский](../../ru-RU/engineering/brotli-streams.md)

`xdzip-compression::BrotliReader` は RFC 7932 の通常 Brotli ストリームを一つ独立してデコードします。呼び出し元が所有する `Read` 能力と受理済み圧縮範囲を受け取り、ファイル名、ファイルシステム、ネットワーク、プロセス、出力の公開に対する権限は持ちません。製品は[形式レジストリー](format-registry.md)で Brotli（`.br`）と TAR.BR（`.tar.br`）を登録します。両形式は共通のホストのソース、タスク、クォータ、一時準備、公開の規則に従って参照、プレビュー、検査、選択した項目の展開をサポートします。条件を満たす既存 TAR.BR は標準の非圧縮メタブロックで書き直して編集できます。どちらのプロファイルも新規アーカイブの作成や分割ボリュームには対応しません。[圧縮 TAR アーカイブの書き換え](single-file-streams.md#xdzip-rewriting-compressed-tar-archives)を参照してください。

<a name="xdzip-wire-profile"></a>

## ストリームのプロファイル

リーダーは標準のウィンドウ宣言 10–24、圧縮、非圧縮、メタデータのメタブロック、単純および複雑な正準プレフィックスコード、連鎖したコード長の反復、三種類すべてのブロック切り替え、四種類すべてのリテラルコンテキスト、RLE と逆 MTF のコンテキストマップ、明示、直近、直接、後置の距離、重なりのある履歴コピーを受け入れます。辞書コピーは規範の単語長 4–24 と 121 種類すべてのバイト変換を適用し、ゼロバイトを生成する変換も含みます。直近距離はメタブロック間で保持し、対象となる履歴参照の場合だけ更新します。生バイト、辞書バイト、履歴コピーはいずれもリテラルコンテキストを更新します。

出典は [RFC 7932](https://www.rfc-editor.org/rfc/rfc7932.txt)、SHA-256 `394abd1879e016f4eac89512c2acaf92f7b2d67feb8ab58b6b118c213be07146` です。確認済みの[正誤表 5948](https://www.rfc-editor.org/errata/eid5948)は 3.5 節の編集上の誤記を修正します。[RFC 9841](https://www.rfc-editor.org/rfc/rfc9841.html) は共有辞書、大きなウィンドウ、別のコンテナーを追加しますが、これらの拡張は通常ストリームのプロファイル外です。予約済みの拡張ウィンドウパターンは非対応として報告します。外部辞書を検索または取得することはありません。

一つの厳密なストリームは合法なゼロ埋めで終わり、受理したバイト範囲を消費しなければなりません。非正準の長さフィールド、メタデータの予約ビット、無効、過剰割り当て、不完全な木、重複記号、マップや種類の欠落、無効な距離や変換、ブロック外への出力は失敗します。このプロファイルは連結、余分な末尾バイト、途中で切れたストリームを拒否します。Brotli には内容チェックサム、ストリーム全体のデコード後サイズ宣言、暗号化、メンバーのパス名、タイムスタンプがありません。デコードの成功が示すのは受理された構造、宣言されたメタブロックサイズ、読み取り可能性であり、変更後も有効なストリームであれば破損として検出できません。

<a name="xdzip-product-discovery-and-presentation"></a>

## 製品での検出と表示

Brotli には固定のマジックがありません。強いソースシグネチャー、有効な通常 TAR メタデータ、ZIP/SFX の検出が優先されます。残るヘッダーなしの経路では、上限付き Brotli プレフィックスが通常ファイルまたは TAR の組み合わせを候補にします。形式や行を公開する前に、メタデータの完全走査でストリーム全体を検証しなければなりません。通常ファイルの推測が失敗した場合、既存の LZMA Alone 候補へ進めます。Brotli のデコード後に認識した TAR ヘッダーは決定的であり、TAR 解析の失敗を通常ファイルや LZMA の成功に変えてはいけません。圧縮バイト内の未検証の生 TAR マーカーは、完全に有効な Brotli 受理によってのみ曖昧さを解消できます。推測が無効なら元の TAR エラーを保持します。ソース、キャンセル、リソースのエラーは終端です。

Brotli/LZMA 候補の調査と繰り返されるメタデータ読み取りには、実際の読み取り 24 GiB の単一台帳を使い、候補間で返却しません。他の強い形式やテキスト封筒の検出は既存の独立した上限を維持します。1 バイトの空 Brotli ストリームは受理しますが、空の物理ファイルは無効です。ファイル名の拡張子は候補を検証しません。完全な検証後に、同じフィルターの `.br` または `.tar.br` のヒントだけが、1024 バイト以上の全ゼロ出力の曖昧さを解消します。無関係なヒントでは空 TAR の既定値を維持します。実際の TAR ヘッダーは通常ファイルの拡張子より優先します。

通常 Brotli は、ホスト由来の安全なベース名、既知のデコード後サイズ、物理的な圧縮サイズ全体を持つ通常の仮想ファイル一つとして表示します。TAR.BR は TAR の物理項目の同一性を維持し、子項目の圧縮サイズは不明です。両方とも実際の Brotli 方式と構造検査の注記を表示し、チェックサムがあるようには示しません。汎用のアーカイブ画像を再利用し、既存の MIME 宣言 `application/x-brotli` は通常のシェル候補を提供します。

<a name="xdzip-resource-and-control-rules"></a>

## リソースと制御

履歴の確保前に `(1 << window_bits) + 2 MiB` を受け入れます。後者は上限付きプレフィックス記号、ブロックとコンテキストのベクター、入力バッファー、固定状態を保守的にカバーし、宣言された各数も個別に制限します。各カテゴリーのブロック種類またはコンテキスト木は最大 256 です。リテラルマップは最大 16384 項目、距離マップは 1024 項目、プレフィックスのアルファベットは最大 704 記号です。静的な規範データは外部 I/O を許可しません。

圧縮入力と累積出力にはそれぞれ 24 GiB の厳格な上限があり、呼び出し元はさらに制限できます。実際のビット解析、プレフィックス構築、記号と反復の展開、コンテキスト MTF の移動、出力は、最大 96 GiB 単位の単一累積作業台帳を消費し、失敗しても返却しません。メタブロックの出力宣言はデコード前に受理され、呼び出し元のクォータを拡大しません。一回の読み取りは最大 8192 デコード済みバイトを返します。`with_poll` はヘッダー処理や出力のない作業も含めて上限付きの作業間隔で権限を持たない協調コールバックを呼び出すため、キャンセルは追加のソースバイトが必要かどうかに依存しません。コールバック、ソース、クォータのエラーは終端です。再試行するのは単純な中断読み取りだけで、型付き中断はエラーオブジェクトを保持し、便利メソッドで再試行しません。

呼び出し元は EOF まで読み、成功するまで出力を非公開に保つ必要があります。後のエラーはそれ以前のチャンクを無効にし、プリミティブは公開しません。失敗したリーダーは再開できません。協調制御ではブロック中の基盤 OS 読み取りを中断できません。ソースの固定と最終公開はホストの責任です。

<a name="xdzip-normative-data-and-validation"></a>

## 規範データと検証

静的辞書と三つのコンテキスト表は固定された RFC から直接抽出し、すべての規範長と CRC を確認します。単語の深さと変換識別子も検証します。[データの由来とライセンス](../../../third_party/brotli-rfc7932/README.md)はこれらの標準定数を対象とし、Brotli の参照実装はリンクしません。ソースと配布する通知に IETF Revised BSD 通知を保持します。デスクトップと CLI の通知収集入口は Cargo 依存関係や参照ランタイムとは別に収集します。

[自作のテストデータ](../../../tests/fixtures/brotli/README.md)は生成または独立して構築し、固定された作者のデコーダーでバイト単位に照合します。品質、ウィンドウ、コンテキストに依存する実出力、ブロック切り替え、距離パラメーター、すべての規範変換、メタデータと生ブロックを網羅します。正確なクォータ、切断、埋め、短い入力、型付きエラー、作業ポーリング、決定的な変更で相互運用ケースを補います。参照ツールは `build/toolchain/`、証拠は `build/` または CI に保持します。[受け入れ要件](../../../developers/qa/acceptance.md)の `FORMAT-BROTLI` はプリミティブテストとは別に製品統合を規定します。
