## 調査の根拠と適用

1. [公式 Bandizip Windows UI](https://www.bandisoft.com/bandizip/screenshots/)：ディレクトリーツリー、ファイル表、明確な解凍入口とステータスバーを維持し、大きくカラフルなツールバーを文字と細線アイコンに簡略化し、主要操作を 1 つ強調します。
2. [公式 Bandizip macOS UI](https://www.bandisoft.com/bandizip.mac/screenshots/)：公式のファイル閲覧デモとアーカイブ作成パネルを調べ、内容と解凍先を選ぶ前に閲覧する流れを維持します。
3. [Bandizip の解凍手順](https://www.bandisoft.com/bandizip/help/how-to-unzip/)：ファイルを開いても自動的には解凍しません。ユーザーが出力先、範囲と競合処理を確認してからタスクを開始します。
4. [公式 Transmit UI](https://panic.com/transmit/)：ファイルマネージャーの情報密度、パスナビゲーションと控えめな区切りを参考にします。
5. [Linear の 2026 年デザイン刷新](https://linear.app/now/behind-the-latest-design-refresh)：中央の内容を強調する落ち着いたサイドバー、コンパクトなナビゲーション、柔らかい境界と中立的な背景を参考にします。

調査は 2026-10-11 に公開された公式スクリーンショット、デモと記事を用いて行いました。各製品の現在インストールされる最新版を示すと主張するものではありません。第三者の調査資料は別の実験用ワークスペースにあり、このリポジトリーには含まれません。

## ビジュアルシステム

暖かみのあるグレーの背景、コバルト色の主要操作、グラファイト色のダークテーマを使用します。大きなグラデーションやすりガラス風背景で情報階層を置き換えません。通常のファイル一覧は明確なフラット構造を保ち、影はオーバーレイに限定します。左は「どこか」、中央は「何があるか」、右は「何が選択されているか」に答えます。

HTML と Qt は [Xdzip Design Sans SC](../../../design/assets/fonts/README.en.md) の字形とメトリクスを共有します。Qt は同じソースの TTF を使用し、サブセット外のアーカイブ名にはプラットフォームのフォールバックを使います。メイン一覧の文字は 13、ヘッダーとツールバーは 12、ペインタイトルは 13 論理ピクセルで、Qt フォントピクセルの整数に丸めます。ファイル名は完全なアクセシブル名を保持し、視覚上の省略には省略記号とフルネームのホバーヒントを使います。ファイルアイコンは約 31.75 論理ピクセルの共通スロットを使用し、種類ごとのサイズ補正はしません。

メインウィンドウの初期サイズは 1024 × 622、最小サイズは 832 × 544 論理ピクセルです。サイドバーとプレビューの元測定値は約 193.16 / 257.98 で、Qt の構造境界では 193 / 258 に丸めます。ディレクトリー行は約 43、ファイル行は 44.65 です。ペインタイトルの高さは 46、表ヘッダーは 34、検索と主要ボタンは約 33.74 です。ディレクトリーツリー B は独立して高さ 32、アイコンスロット 16 を維持します。幅 928 未満ではプレビューを折りたたみ、ボタンから独立したネイティブウィンドウで開きます。設定はフォントサイズ 100%/125%/150% を提供し、過去の 200% は 150% として読み取ります。大きなフォントでは、あふれを隠す全体拡大ではなく、実際のレイアウト、スクロールと独立した詳細ウィンドウを使います。ペインのドラッグと幅の永続化は未実装です。

## メインウィンドウの操作

- Qt は独立したアーカイブセッションをサポートし、保存されたオープン方式に応じてカプセル型タブまたはメインウィンドウを作成します。再度開くと既存セッションをアクティブにします。ページはパス、選択、並び順とスクロール状態を保持し、ページを閉じてもタスクは続行します。[アプリケーションセッション契約](../engineering/application-sessions.md)を参照してください。HTML の複数タブ動作はデザインの検証に限ります。
- 選択がない場合、主要ボタンは「すべて解凍」、選択がある場合は「選択した項目を解凍」です。ドロップダウンは常にもう一方の範囲を提供します。
- ファイル表は並べ替え、複数選択、範囲選択とキーボード操作をサポートします。フォルダーをダブルクリックすると入り、通常ファイルをダブルクリックすると一時コピーを解凍してシステムで開きます。プロパティカードは対応する単一ファイルを自動的にプレビューします。範囲と安全性は[プレビュー契約](../engineering/content-preview.md)を参照してください。HTML のサンプル写真は実際のデコード結果ではありません。
- 検索は現在のディレクトリーと子孫を再帰的に対象とし、ルート検索は全内容を対象とします。結果にはアーカイブ内の完全なパスを表示し、通常のディレクトリー一覧には末尾の名前を表示します。
- 詳細は閉じたり再度開いたりできます。プレビューには非同期読み取りとリソース制限が必要です。非対応項目にはプロパティと解凍入口を表示します。タスクキャンセル後に遅れて届いたプレビュー結果は破棄します。
- ステータスバーには選択数と元サイズ、インデックス状態、再表示できるタスク履歴の件数を表示します。実行中タスク数はヒントと終了保護を別に制御します。未完了インデックスは完全な件数を作り出さず「読み取り中」と表示します。

## 解凍パネルの操作

パネルはアーカイブ、出力先、選択範囲、競合ポリシーと完了時の動作をまとめます。サンプルの選択は 8.4 + 6.2 + 12.8 = 27.4 MB です。ファイル一覧は要約で、大きな一覧には「すべて表示」を提供します。

出力先の既定値は前回のディレクトリーです。「アーカイブ名のフォルダーを作成」は不要な入れ子を避けるため最終パスのプレビューを直ちに更新します。パス権限、空き容量とアーカイブ読み取りの失敗をテキストで表示します。確認中は別の状態とし、確認できない空き容量は「不明」とします。

競合の既定値は確認です。スキップ、自動名前変更、上書きも選べます。上書きの結果を明確に示します。実行中は実際の段階、処理ファイル数、バイト進捗と計算可能な場合の速度を表示し、合計が不明なら不確定進捗を使います。キャンセル後はバックグラウンドが停止を確認するまで「停止中」と表示します。

## コンポーネント状態とアクセシビリティ

| コンポーネント | 必要な状態とフィードバック |
| --- | --- |
| 主要ボタン | 通常、ホバー、押下、キーボードフォーカス、無効、送信中。重複開始を防ぐ |
| ファイル行 | 通常、ホバー、選択、ウィンドウ非フォーカス時の選択、キーボードフォーカス。選択では文字色以外も変える |
| 検索 | 空、入力中、検索中、結果なし、クリア。Escape はテキストを残してフォーカスを離れる |
| プレビュー | 選択なし、読み込み中、読み込み済み、非対応、エラー、キャンセル |
| タスク | 待機中、実行中、パスワード・競合判断待ち、停止中、完了、一部失敗、失敗 |
| モーダルパネル | フォーカスの制限、未送信パネルを Escape で閉じる、起点ボタンへのフォーカス復帰 |

Qt 実装後にテーマ色の本文コントラストが WCAG AA を満たすか検証します。追加のフォーカスリングを描かず、現在のデザイン基準に従ってフォーカスの見た目と離脱を扱います。スクリーンリーダー向けの名前と状態通知を提供し、システムの視差効果を抑える設定を尊重します。通常の遷移の推奨値は 120–160 ms です。装飾用のファイル一覧効果を継続的にアニメーションさせません。

## Qt Quick の実装制約

Qt は共有 `Theme` と生成された寸法を使用します。`ArchiveTabs`、`ArchiveToolbar` と `SessionPage` 内の一覧、グリッド、ディレクトリー各部分はメインレイアウトを共有します。`InspectorPanel`、`ExtractWindow`、`CreateWindow`、`TaskWindow` はそれぞれ固有のデータとレイアウトの境界を維持します。QML は状態とユーザーの意図を表現し、Rust ランタイムがインデックス、アーカイブの読み書きと形式検証を担当します。

macOS、Windows、Linux は内容のレイアウトと操作モデルを共有し、ウィンドウコントロール、メニューとショートカットは各プラットフォームの慣例に従います。ここに描いた macOS のフレームは、他プラットフォームに信号機型ボタンの模倣を要求しません。大きなリアルタイムぼかしは実装要件ではありません。静的マスクでスクリーンショットの背景を抑えた表現を再現できます。

メインウィンドウを[ライト](../../../design/hifi/sources/main.html?theme=light)または[ダーク](../../../design/hifi/sources/main.html?theme=dark)で確認し、[タスク状態](../../../design/hifi/sources/task-windows.html)、[設定](../../../design/hifi/sources/settings.html)、[デスクトップ統合](../../../design/hifi/sources/desktop-integration.html)も確認します。その他の状態やサイズ例外は[ウィンドウレジストリ](../../../specs/visual/window-registry.json)から探します。デザインページはネイティブウィンドウやメニューの内容を示す場合があります。実際の装飾、アクティブ化、スケーリングとメニュー動作には該当プラットフォームが必要です。

## プラットフォームウィンドウの改訂

操作パネルはすべて[独立したプラットフォームウィンドウ](../ux/platform-windows.md)になります。以前の解凍原稿の内容領域内の閉じるボタン、丸いパネルとマスクは独立タイトルバーとプラットフォーム装飾に置き換え、色、タイポグラフィと内容構造は維持します。現在のファイル種別アイコン、一覧の整列と 3 プラットフォームのタイトルバーには、補助レビュー資料としてインタラクティブなプロトタイプがあります。

## 原稿と共有アセットライブラリ

[完全な原稿](../../../design/hifi/README.md)は `design/hifi/screens/` にあり、メインウィンドウ、解凍確認と 8 枚の操作状態ボードを含みます。機能と復旧は[状態契約](../ux/hifi-state-spec.md)を参照してください。原稿のバイトを保持し、実装に合わせて原稿やスライスを変更してはいけません。

[共有アセットライブラリ](../../../design/assets/README.md)は、納品バッチごとに分けず、メインウィンドウと操作状態のアセットをまとめています。透明なランタイムアイコンの画像ソースは SVG のみで、HTML に直接埋め込み、Qt では同じソースから複数解像度の PNG として描画します。`reference/` の元ピクセル比較用スライス 45 点は元の画像、切り抜きと背景を保持し、HTML 用サンプル写真 3 点は `demo/` にあります。単一のマニフェストが用途を識別し、背景付きスライスを透明レイヤーと誤認しないようにします。

すべての透明アイコンは 24×24 キャンバスを共有します。PDF、テキスト、コード、Markdown アイコンは中心と可視高さ 22 ピクセルを共有し、シルエットの幅と内部スタイルはそれぞれ維持します。フォルダーは中央揃えの水平な可視シルエット 22×約 18.86 を使います。この高さ制約はランタイムアイコンに適用し、元のスライスには適用しません。1×/2×/3× PNG は 24×24、48×48、72×72 で、倍率は論理サイズを変更しません。HTML のファイル一覧はソース空間で 48×48 のスロット、Qt は同等換算後の約 31.75×39.69 論理ピクセルを使います。種類別 CSS の拡大、移動と線幅補正を削除します。

ファイル一覧のパンくずと右側プレビュー・詳細のタイトルはバーの高さ、フォントサイズと文字の垂直中心を共有します。HTML は共通タイトルバー変数、Qt は `PaneHeader` と `Theme.mainPaneTitleSize` を使用します。タイトルはスクロール内容の上に残り、大きなフォントでは両方のペインの高さを一緒に増やします。実測値は[検証方法](../../../developers/qa/README.md)に従い実行アーティファクトに保持します。

HTML の写真プレビューはペインタイトル直下から始まり、上端をファイル一覧ヘッダーに合わせ、追加の上余白を設けません。検索ヒントが表示された場合は実際に占める領域に従って整列します。既存画像の高さと下部間隔は維持します。写真整列の再確認はサンプル画像 2 点、ライト・ダークテーマ、3 種のウィンドウ装飾と検索変更を対象とします。

ファイル一覧の元サイズと圧縮サイズのヘッダー・値は右揃え、種類のヘッダー・内容は左揃えにし、各列で共通の内容パディングを使います。HTML は元の列幅と行高を維持し、サイズ列の右パディングはソース空間で 26 と 22 ピクセル、種類列の左パディングは 28 ピクセルです。再検証では表示される全行の文字レイアウト端を記録します。

アイコンのシルエット、元ピクセルスライスの寸法とランタイムキャンバスの寸法を別々に記録します。フォルダーを紙の形に引き伸ばす必要はなく、スロットを埋めるために SVG を変形してはいけません。ビジュアル変更は画像ソースで行い、アセットギャラリーで確認して両実装へ同期します。

## ディレクトリーツリー B の改訂（2026-10-12）

3 枚の正式ボードが多階層展開、ノード操作とナビゲーション境界を定義します。[ディレクトリーツリー仕様](../ux/directory-tree.md)を参照してください。元ピクセルスライス 26 点が共有 `assets/reference` に入り、分岐点、塗りつぶし状態アイコンと分割スピナーは 2 テーマの SVG と 3 解像度の PNG を使用します。接続線、状態背景、フォーカスとテキストは[コンポーネントパラメーター](../../../specs/visual/directory-tree.json)から動的に描画し、これらはグローバルトークンを自動的に上書きしません。ボードは拡大した視覚説明で、正確な論理寸法とソースピクセル矩形は別に記録します。HTML と Qt は再帰ディレクトリー、接続線と隠れた現在ブランチのマーカーを統合しています。専用境界アイコン・スケルトンはデザイン資源のままで、完全なダークボードは未完成です。

## 現行メインデザインのツールバー改訂（2026-10-12）

上記の以前の一般的なコントロール提案は、メインツールバーには適用されません。現在の原稿測定値は高さ 51 ソースピクセル、フォント 18 ソースピクセル、アイコン 32 ソースピクセルで、1024/1548 の換算後は高さ約 33.74、整数フォント 12、アイコンキャンバス 21.17 です。ツールバー領域の高さは 53 です。以前の幅 1280 に基づく 42.17/15/26.46 の換算は通常密度に置き換えられ、通常の操作ウィンドウは登録された対応を維持します。

通常の左右ツールバー操作と検索・主要操作はそれぞれグループを形成します。大きなフォントでは高さを増やし、最小ウィンドウサイズで右側の操作全体が見えるよう検索欄を縮めることがあります。無効な文字にグループ全体の不透明度を適用せず、主要ボタンには独自の無効背景を使います。解凍の主要ボタンは無効な区切り線と矢印の見た目を維持し、実際の解凍と範囲メニューはランタイムの能力に従います。選択がない場合は選択範囲とメタデータの事前検査が無効で、整合性検査はアーカイブの能力に従います。再検証は[共通の検証方法](../../../developers/qa/README.md)に従って記録します。

## アプリのブランドとプラットフォームアイコン

各形式のシステム文書アイコンは[ファイル関連付けアイコン仕様](file-association-icons.md)と[高忠実度レビューページ](../../../design/hifi/sources/file-association-icons.html)に従います。この系列は後の形式別統合用デザインアセットとして、下記ブランド形状を再利用しながら、形式ラベル、アクセントと小サイズでの簡略化を区別します。

ブランドは 4 本の織り合わさった帯と下部の開いた U 字を使い、形状は `scripts/brand_assets.py` で管理します。独立マーク、アプリアイコンと ZIP 文書マスターは `design/assets/brand/` にあります。UI の `app-mark`、`archive`、`archive-grey` はそれぞれアプリ、青いアーカイブ、灰色のアーカイブを表し、すべて同じブランド形状から生成されます。アプリは青い角丸の外枠、文書は折り返し角のある紙を使用し、識別要素を共有しながら枠の役割を分けます。

現在のマークは細い 2:3 の縦横比を維持し、旧マークの幅に引き伸ばしません。ベースは 4 隅すべてに回転対称の連続曲率曲線を使用し、直線端のゼロから対角中点へ曲率を滑らかに増やして、途中が面取りのようになることを避けます。光とベースは一つのパスを共有し、半径の異なる線や開いたハイライト線を重ねません。文書バッジも同じ輪郭定義を使用します。

これは古い高忠実度原稿の ZIP ジッパーアイコンを見分けがつかないほど再現したものではなく、明示的な新しいブランド改訂です。完全な原稿 10 点、元ピクセルアイコン参照 45 点、サンプル写真 3 点は元のバイトを保持します。新しく生成された `brand/identity-reference.png` は現在のブランド方向のレビュー参照であり、ランタイムアセットではありません。メインアセットマニフェストは参照の網羅範囲を記録し、旧ブランド参照を過去のデザイン役割として明示します。

小さな UI アイコンは 24×24 キャンバスを維持します。プラットフォームアイコンは 16/24/32/48/64/128/256/512/1024 ピクセルの透明 PNG を出力します。16/24/32 サイズでは読めない文字と大画像用の光を簡略化しつつ、織り合わさった帯と U 字の認識構造を保持します。アプリと ZIP 文書の各アイコンは 7 サイズの ICO と 11 種の密度表現の ICNS を提供します。24 単位の UI アイコンをシステム用途で無限に拡大したり、大きな影を縮小して小サイズのノイズにしたりしません。

システムアプリアイコンは Qt ウィンドウ、macOS アプリバンドル、Windows 実行ファイルリソース、Linux デスクトップランチャーと hicolor ディレクトリーに統合されます。ZIP 文書のプラットフォーム形式はインストーラーとファイル関連付けに使い、システムのオープン要求は統一ルーティングを通じて実際の閲覧へ送ります。[インストールと関連付けの契約](../engineering/installers-associations.md)を参照してください。オープン候補のみを登録し、ユーザーの既定値を変更しません。プラットフォーム検証は[共通の方法](../../../developers/qa/README.md)に従って記録します。

不足していたテーマ、成功、キャンセル、競合、進捗の画像は元ピクセル参照から意味の異なるアセットとして補完します。大きなキャンセル画像は四角い停止記号を使い、システムテーマは完全なウィンドウ構造を保持します。HTML はネイティブのラジオ入力を使い、Qt は IntentRadioButton でマウス、キーボードとアクセシビリティ操作を一つの選択モデルへ送ります。アセットは外観だけを担当します。生成チェック、対象プラットフォームの表示と原稿との差異を別々に記録し、既存の受け入れをこの改訂の結果の代わりにはできません。

## インタラクティブコントロール仕様

[controls.json](../../../specs/visual/controls.json) はメニュー列、行高、角丸、色、フォーカスとヒントのタイミングを定義し、[directory-tree.json](../../../specs/visual/directory-tree.json) はディレクトリー階層を定義します。どちらも HTML コントロールパラメーターと QML Theme を生成し、検査により寸法やテーマの手動重複を避けます。メインデザインの論理・ソースピクセル比は `display-spec.js` に由来します。[コンポーネントレビューページ](../../../design/html/components.html)は 1:1 の論理寸法を使い、メインキャンバスはソース座標を使います。機能一覧と入力契約は[メインウィンドウコンポーネントの説明](../ux/main-window-components.md)、実際の描画と動作は[検証方法](../../../developers/qa/README.md)に従って該当 issue とアーティファクトに記録します。
