# HTML の視覚的忠実度レビュー

[English](../../visual/html-fidelity.md) | [简体中文](../../zh-CN/visual/html-fidelity.md) | [繁體中文（台灣）](../../zh-TW/visual/html-fidelity.md) | 日本語 | [한국어](../../ko-KR/visual/html-fidelity.md) | [Français](../../fr-FR/visual/html-fidelity.md) | [Deutsch](../../de-DE/visual/html-fidelity.md) | [Español](../../es-ES/visual/html-fidelity.md) | [Português (Brasil)](../../pt-BR/visual/html-fidelity.md) | [Русский](../../ru-RU/visual/html-fidelity.md)

高忠実度画像を視覚的な基準とし、HTML を編集可能な実装とします。ツールバーの上下の寸法は、現在の CSS から逆算せず、[固定された初期メインウィンドウ](../../../design/hifi/screens/main-light.png)から別々に測定します。現在の表示には[ライトのカプセルタブデザイン](../../../design/hifi/screens/main-capsule-light.png)と[ダークデザイン](../../../design/hifi/screens/main-capsule-dark.png)を使い、[編集可能なソース](../../../design/hifi/sources/main.html)から書き出します。これらは独立した測定に代わりません。タイトルバーは layout-scale.json の明示された改訂に照らして受け入れます。元画像には柔らかい輪郭と生成されたグリフがあり、テスト件数だけではページ全体のピクセル単位の完全一致を証明できません。

<a name="xdzip-fixed-reproducible-conditions"></a>

## 再現可能な固定条件

- ソースキャンバスは 1586×992 の PNG と一致し、ウィンドウは原点 `(20,30)` で 1548×940 です。元画像のアンカー検査は引き続きデバイスピクセル比 1、ブラウザービューポート 1588×1000 を使います。元画像を引き伸ばさず、上部を `(20,30)-(1568,167)`、内容を `(20,167)-(1568,970)` で切り出します。
- 元画像の SHA-256 は [header-reference.json](../../../design/html/header-reference.json) と [body-reference.json](../../../design/html/body-reference.json) に固定されています。元画像の変更には再測定が必要で、黙って置き換えてはいけません。
- 同梱のオフラインフォント [Xdzip Design Sans SC](../../../design/assets/fonts/README.md) は `document.fonts.ready` の後に測定します。プラットフォームの代替フォントによる幅の変化を減らすため、実際のウェイト 400–750 を固定します。
- 生成画像から元のフォントファミリーを確定することはできません。グリフの輪郭とシステムのアンチエイリアスには差が残り得ます。差を別途記録し、元フォントを復元したと主張しません。

<a name="xdzip-display-size-and-source-pixels"></a>

## 表示サイズとソースピクセル

通常のデザイン表示は[幅 1024 論理ピクセルのウィンドウ](README.md)を使い、ソース座標を `1024 / 1548` で一様に変換します。メインウィンドウは 1024 × 約 621.81 CSS ピクセルで表示し、元画像にも同じ倍率を使います。この比率は明示的なデザイン上の取り決めであり、PNG から Retina や DPI を推定したものではありません。

`display-spec.js` はすべてのアートボード寸法と表示倍率の唯一のソースです。デスクトップは通常サイズ、モバイルはフィットを既定とし、広い画面で自動拡大しないようフィット倍率を通常サイズ以下に制限します。元ピクセルモードは `scale=1` を使い、元のピクセル寸法を保ち、HTML 側と画像側の両方でスクロールします。デバイスピクセル比はラスタライズ密度のみに影響し、CSS の論理幅は変えません。

元画像と HTML をそれぞれのコンテナーに独立してフィットさせてはいけません。ヘッダーと本文のアンカーはソースピクセル座標で測定し続け、表示倍率によって調整済みの間隔やフォントサイズを変更しません。サイズの一貫性では、実際の画面境界、元画像の自然サイズ、モバイルのスクロール、独立プレビュー、オフライン単一ファイル出力を別々に確認します。証拠は[検証方法](../../../developers/qa/README.md)に従って保管します。

<a name="xdzip-canvas-and-content-scrolling"></a>

## キャンバスと内容のスクロール

レビューツール内の HTML は固定サイズのアートボードで、ルート文書に `overflow:hidden` を指定します。これにより通常のスクロールバーがキャンバス寸法を消費して互いに発生させ合うことを防ぎます。レビューページは縦にスクロールし、外側のキャンバスは幅不足時だけ横に移動します。`scrollbar-gutter:stable` は通常スクロールバーの幅を予約し、境界の高さでフィット倍率が繰り返し変化するのを防ぎます。独立プレビューは `auto` を使います。ファイル一覧、長いプロパティ、操作ウィンドウは内容コンテナー内のスクロールを保持し、直接開いた非埋め込みソースキャンバスはページスクロールを保持します。ソースキャンバス、ウィンドウ、コンポーネントの寸法は変わりません。

Playwright は既定で `--hide-scrollbars` を使うため、過去のスクリーンショットとサイズのマトリクスは実際の通常スクロールバーを対象としていませんでした。現在のサイズとプレビュー検査ではこの引数を明示的に除去し、ルートのスクロールバー領域の予約、ウィンドウの四辺の可視性、外側の横移動、長いプロパティの最後のボタンへの到達を確認します。1 px 小さすぎるキャンバスと、埋め込み規則を除去した否定ケースで、スクロールバー領域の競合を再現して検出します。再現と修正のスクリーンショットは[検証方法](../../../developers/qa/README.md)に従い実行成果物に保管します。これはすべてのブラウザーやシステムでのスクロールバーの外観を証明するものではありません。

## ヘッダーの修正

| 領域 | 修正前 | 元画像に照らした修正 |
| --- | --- | --- |
| アクティブタブ | 開始 x299、幅 244 | x293、幅 246 |
| 非アクティブタブ | x557、幅 244 | x542、幅 262 |
| タブ間隔 | 14 px | 3 px。柔らかい輪郭のため約 1 px の不確実性を許容 |
| 追加と閉じるボタン | 別々の縦配置で中心が 5 px 離れる | 同じタブ行に配置し、元画像から約 1 px の光学的オフセットを設定 |
| 閉じるコントロール | ボタン一つと素の span 一つ | 同じアイコン・名前・閉じる操作の構造と明示的な枠 |
| 設定アイコン | 見える図形が小さく左上にずれている | 中心 `(1532,61)`。SVG コンテナーだけでなく実際の図形を確認 |
| アクティブタブの下枠 | タイトルバーの線と重なる | 白いツールバー面につなぎ、左肩の遷移は別途定義 |
| 検索と展開 | 横と縦の境界がずれている | それぞれ `(906,101,449,51)` と `(1368,101,183,51)` に比較 |
| ツールバー左のアイコン | 汎用ボタンのサイズと間隔で配置 | 元画像の図形アンカーに合わせて配置・検査 |

ヘッダーのコンポーネント枠と文字組みは `hifi.css` のタイトルバー、タブ、ツールバーの各節に集約し、汎用 `.icon-button` 寸法や継承行高に依存しません。ライトとダークは同じ形状を共有します。Windows/Linux のタイトル装飾はブラウザー上のデモであり、製品のネイティブウィンドウは別途受け入れます。

<a name="xdzip-content-below-the-toolbar"></a>

## ツールバー下の内容

本文にはアーカイブカード、ディレクトリツリー、パスバー、表の見出しと行、選択、ファイルプレビュー、下部ステータスバーが含まれます。列境界、行高、内側余白、アイコン中心と見える描画領域を記録し、[独立した基準](../../../design/html/body-reference.json)と比較します。厳密な形状と孤立アイコンの描画領域の許容差は 2 px です。文字輪郭は手動レビュー用に記録するだけです。フォルダーの光学サイズは明示的なデザイン改訂で、新しい輪郭を共有素材で一様に約 25.7% 拡大しています。古いフォルダー描画例五つを比較用に残し、独立して記録した新しいデザイン境界で検査します。他の元アンカーは変更しません。

本文レビューは同じサイズの内容切り出しを使い、サイドバー、一覧、プレビュー、ステータスバーの領域別比較を残します。前後のスクリーンショット、コミット、測定値は対応する issue または Actions の成果物だけに置き、特定実行の結果を仕様に書き込みません。モバイルレビューは領域ごとに行い、差を隠すためにデスクトップ配置を変えません。

元画像は一項目を選択しながら「すべて選択」を空のままにし、節約率 26% と表示しながらバーを約 56% 塗っています。これらは矛盾する静的状態です。HTML は文書化された意味上の例外として、それぞれ部分選択の `indeterminate` と実際の 26% 塗りを維持します。プレビュー専用検査は通常のあふれと長い内容のスクロールを対象とし、既存の操作検査は選択、ナビゲーション、ソート、検索、サンプル操作を対象とします。形状検査は機能検証に代わりません。

本文レビュー、同サイズの領域比較、測定証拠は[検証方法](../../../developers/qa/README.md)に従って別々に保存します。不明な元フォント、生成された柔らかい輪郭、照明、アンチエイリアスの差の説明を残します。この HTML の証拠は Qt 製品の対応する調整を証明しません。

<a name="xdzip-checks-and-delivery"></a>

## 検査と納品

実行：

```sh
python scripts/build-html-design.py
python scripts/check-html-header.py
python scripts/check-html-body.py
python scripts/check-html-preview.py
python scripts/check-html-references.py
python scripts/check-html-scale.py
python scripts/check-html-design.py
python scripts/build-html-header-review.py
python scripts/build-html-body-review.py
```

ヘッダー検査は独立した元アンカーを使い、DOM 境界・中心のずれは最大 1 px、孤立領域の実際のアイコン描画境界は最大 2 px です。白いドロップダウン矢印の許容差は 1 px、タブ右肩は元の白い面と曲線をサンプリングし、柔らかさに対する単一チャネル許容差を 10/255 とします。グリフ輪郭は測定・記録するだけです。重ね合わせと差分画像にはアンチエイリアス、照明、グリフの差が含まれ、総ピクセル差を架空の類似度に変換してはいけません。

オフラインのヘッダーファイルは `dist/xdzip-header-review.html`、本文ファイルは `dist/xdzip-body-review.html` です。どちらも元画像、修正前、修正後、透明な重ね合わせ、ピクセル差分を切り替えられ、本文レビューにはモバイル領域の選択もあります。単一ファイル UI は `dist/xdzip-hifi-design.html` です。

これらの HTML 検査とオフラインレビューは必要に応じてローカルで実行し、デスクトップ製品 CI の既定には含めません。形状が合格した後もアンカーの失敗を調べ、重ね合わせの証拠を確認します。メインウィンドウの HTML 検査は他ページや Qt 製品の調整、ネイティブデスクトップの受け入れに代わりません。

通常のメインウィンドウとメニューの密度は [UI 規格](design-standard.md)に従います。Qt のメニューと一覧のフォントサイズ比は一緒に確認します。ローカルの HTML レビューでは[検証方法](../../../developers/qa/README.md)に従って実際のページズームを確認し、古いソース画像の座標との一致で代用しません。
