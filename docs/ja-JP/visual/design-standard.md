# UI デザイン標準

[English](../../visual/design-standard.md) | [简体中文](../../zh-CN/visual/design-standard.md) | [繁體中文](../../zh-TW/visual/design-standard.md) | 日本語 | [Français](../../fr-FR/visual/design-standard.md) | [Español](../../es-ES/visual/design-standard.md) | [Português (Brasil)](../../pt-BR/visual/design-standard.md)

この標準は UI の作成、HTML デザインの提供、Qt 実装に適用します。寸法変換は [layout-scale.json](../../../specs/visual/layout-scale.json)、色、共通コントロール、ディレクトリーツリーはそれぞれ [tokens.json](../../../specs/visual/tokens.json)、[controls.json](../../../specs/visual/controls.json)、[directory-tree.json](../../../specs/visual/directory-tree.json)に従います。原稿の測定値は [qt-main-reference.json](../../../specs/visual/qt-main-reference.json)にあり、実装結果から逆算して原稿を書き換えてはいけません。

## 内容プレビュー

[内容状態](../../../design/hifi/sources/content-preview.html)は既存のプロパティーカードの幅、高さ、角丸、メインウィンドウの密度、テキストの役割を維持します。内側余白、間隔、アイコン、読み込み表示のパラメーターは layout-scale.json の main.content_preview から生成します。単一ファイルを選択すると、表示中のプロパティーカードで自動的にプレビューを開始します。読み込み、パスワード待ち、プレーンテキスト、画像、エラー、複数選択はカードを共有し、読み取り中またはパスワード待ちにキャンセルできます。複数選択メッセージの上では 2 個のファイル種別アイコンが既存のプレビューアイコンサイズを使い、横 16 ピクセル、縦 8 ピクセルずらして重なります。カードは利用可能なメタデータの中からリスト順の選択項目を使い、メタデータがなければ汎用ファイルアイコンを使います。ポインターのホバーまたはキーボードフォーカス時には、右上にフローティング ArchiveAction が表示されます。正方形は 28 論理ピクセル、角丸 3、内側余白 6、更新アイコン 16 ピクセルです。テキストは選択可能なプレーンテキストです。選択には共通のアクセント背景と accentText 前景を使います。画像は縦横比を保持し、ラスターと制限付き静的 SVG はブラウザー、HTML、外部リンクの実行を導入せず同じ画像領域を使います。SVG は制限付きワーカーでラスター化し、ソースを QML に渡しません。メインウィンドウと独立プロパティービューアーは InspectorPanel を再利用し、プレビューを閉じるか項目を変更すると直ちに内容を消去します。パスワードウィンドウは[パスワード要求](../ux/password-extraction.md)のレイアウトと共通フッターを維持し、プレビュータスクの文言のみを変更します。メインウィンドウとメニューの比率は引き続き同時に再検証する必要があります。

## インターフェースフォントとユーザーデータ

Qt の起動時、固定 UI テキスト用の同梱 Noto Sans SC 派生サブセットをインストールする前に、システム既定のフォントファミリーを取得します。ファイル名、アーカイブ名、ディレクトリー名、パス、それらを含むメッセージやフィールドは取得したファミリーを優先し、不足字形には Qt／プラットフォームのフォールバックを使います。ファイル名を含む複合メッセージは全体にシステムフォントを使えます。静的なプレースホルダーと操作テキストは UI フォントを維持します。表示、ディレクトリーツリーの幅、ドラッグプレビューの測定には対応する同じフォントを使います。フォントサイズは引き続き論理寸法とアクセシビリティ拡大に従い、システム DPI はコンポーネントの論理寸法を変えません。HTML レビュー例は同梱サブセットを使います。ユーザーデータの実際の字形と幅は実行プラットフォームに依存し、構造寸法は同じ論理仕様に従います。

## 単位と密度

1. すべての寸法を論理ピクセル、すなわち HTML の CSS px と Qt のデバイス非依存ピクセルで提供します。スクリーンショットの物理ピクセルは DPR で割ってからデザイン値と比較します。アセットの 1×/2×/3× はサンプリングの鮮明さにのみ影響し、アイコン領域には影響しません。
2. 以前の幅 1280 のメインウィンドウ基準を 125% とみなし、`1 / 1.25 = 0.8` で 100% に変換します。新しい既定クライアント領域は 1024×622、最小は 832×544、プレビュー折りたたみ閾値は 928 です。この密度補正をタイトル、ツールバー、ペイン、ファイル一覧、ディレクトリーツリー、ステータスバーとそれらのフォントに適用します。
3. ポップアップメニューとヒントはメインウィンドウとともに縮小せず、通常密度を使います。メニューの既定値は幅 240、最小行高 32、フォント 13、アイコン領域 18 です。メイン一覧の目標フォントは約 12.57、Qt では 13 に丸めます。メニュー／一覧のフォント比は 0.95–1.10 とし、個別パラメーターと比率の両方を検査します。
4. 元のメインクライアント領域 1548×940 は測定座標です。HTML メインキャンバスは `1024 / 1548` で変換し、メニュー原稿の CSS 座標は上記の論理寸法を保つよう逆変換します。通常の操作ウィンドウは `1280 / 1548` を維持します。展開原稿は別の `819.2 / 1548` マッピングと約 491 のウィンドウ幅を使います。これは以前、独立入口が埋め込み入口より 25% 大きかったことへの明示的な密度補正です。すべての入口は最終論理サイズを共有し、埋め込みと独立表示でコンポーネントのフォントを変えてはいけません。
5. ブラウザーのレビュースケール、ページズーム、システム拡大、DPR をコンポーネントのサイズパラメーターに入れてはいけません。Qt は密度補正の実装に `Item.scale`、縮小スクリーンショット、追加の 1.25 倍を使わず、仕様パラメーターから実際のレイアウトと整数 pixelSize を生成します。
6. 1 論理ピクセルの区切り線とフォーカス線は指定値を維持し、ネイティブウィンドウ装飾は OS が管理します。空間寸法の小数を保持し、構造境界とウィンドウサイズは最も近い整数に丸めます。Qt のフォントサイズは密度変換後、アクセシビリティ拡大前に丸めます。

新しいコンパクトなバッジとタグは角丸 3 論理ピクセルを使います。大きい角丸は明示的に承認されたコンポーネント形状に限り、コンパクトタグをカプセル形にしません。標準ボタン、フィールド、ウィンドウには共通の形状を使います。

## タイトル領域の改訂

メインタイトルバーの高さは 48 論理ピクセルです。タブは高さ 32、角丸 16 の浮いたカプセル形で、上下にそれぞれ 8 の余白があります。アクティブタブは完全な枠線を持ち、ツールバーに接続しません。タブを閉じる操作、追加、設定はタイトルバーの縦中心を共有します。文字が大きい場合はまずカプセルを高くし、上下の余白を等しく保ちます。これは保管された原稿の下端接続タブに代わります。

アクティブタブのウェイトは 600、非アクティブは 400 で、アクティブ枠線を付けずホバー時のみ共通の塗りを使います。タブは既存の推奨幅と最小 112 の間で利用可能幅を分配し、文字拡大時は上限と下限を増やします。あふれた場合は可視スクロールバーのない水平ビューポートを使い、設定やシステムボタンを圧迫せず、新規作成、双方向スクロール、タブ一覧の入口を保持します。ホイール、トラックパッド、キーボード切替、メニュー操作、ドラッグ端のスクロールは一つの制限付きビューポートを共有します。開く、切替、閉じる、サイズ変更後はアクティブタブを全体表示し、ユーザーが明示的にスクロールした場合は引き戻しません。ウィンドウ内ドラッグでは浮いたカプセルと挿入マーカーを示し、リリース時に安定したセッション識別で並べ替え、Escape または入力キャンセルで破棄します。パラメーターはスクリーンショットのピクセルではなく layout-scale.json の titlebar から取得します。

タブの閉じる操作は正方形のヒット領域と中央位置を維持し、ホバー／押下時は円形背景を使います。エラーのない通常の待機中ウェルカムページが一つだけなら非表示とし、読み込み、エラー、複数タブ、アーカイブタブでは既存の表示条件を維持します。非表示ボタンはキーボードフォーカスを受けたり、可視のアクセシビリティ操作として現れたりしません。

ウェルカム読み込みカードの本文はスクロールし、「読み込みをキャンセル」は右下の固定操作領域で共通 OperationFooterButton を使います。読み込みは展開ではなく、「展開をキャンセル」を再利用しません。キャンセル後はキャンセル中を表示して重複送信を無効にし、読み込み終了後にウェルカムのフォーカスを復元します。カードの論理幅は 360、余白は 24 で、半透明オーバーレイと共通ボタン寸法を維持し、フッターの外観を上書きしません。

開いたアーカイブを待つ変更処理は、カードパラメーターと layout-scale.json の operation_overlay 透明度を再利用します。重複操作をブロックしつつ元のファイルページを表示したままにします。タイトル、説明、進捗のアクセシブル名、キャンセルは実際の追加、移動、名前変更、削除の操作を示し、タスクのクリーンアップとディレクトリー更新後に操作を復元します。キャンセルが受理されると無効になった競合とパスワードの要求を直ちに閉じ、進捗はキャンセル中を示して実際の終端に従います。競合ウィンドウは特定のタスクと要求トークンに結び付け、タスク変更時またはトークン失効時に閉じます。

現在の[ライトのメインウィンドウ](../../../design/hifi/screens/main-capsule-light.png)、[ダークのメインウィンドウ](../../../design/hifi/screens/main-capsule-dark.png)、[多階層ディレクトリーデザイン](../../../design/hifi/screens/directory-tree-capsule.png)はこのタイトル領域を使い、[編集可能なソース](../../../design/hifi/sources/main.html)から生成します。旧メインとディレクトリーの原稿はギャラリー履歴に残し、独立した測定値、SHA-256、スライスの来歴を変更しません。現在の書き出しは独立した形状受け入れの代わりにはなりません。

リストとグリッドの項目メニューは[アーカイブ項目編集デザイン](../../../design/hifi/sources/archive-entry-edit.html)と標準ポップアップ密度を共有します。名前変更と削除は共通の幅 491 論理ピクセルの確認ウィンドウを使い、本文はスクロールし、フッターは固定します。ファイル名にはユーザーデータ用システムフォントを使います。名前変更は共通フィールドにフォーカスし、ファイルの場合は拡張子を除く名前を選択します。削除は開いたときにキャンセルへフォーカスします。

## コンポーネント規則

### 設定ウィンドウのカテゴリー改訂

所有者のないトレイの設定とアプリ情報は、現在のディスプレイの作業領域と完全なネイティブフレームに対して共通の画面中央配置を再利用します。右下の通知領域のポインター位置を維持せず、ネイティブ作成と高さ調整の後に再配置します。設定の寸法、書体、密度は変えません。

Windows MSIX 識別の場合、アプリ情報は更新タイトル、区切り線、更新セクション全体を省き、バージョン情報には後続の既存の共通グループ間隔を使います。ウィンドウの寸法、フォント、その他の内容は維持し、配布経路ごとの拡大や密度を設けません。

設定とアプリ情報は幅 612 論理単位、推奨クライアント高さ 532 の非モーダルウィンドウを共有し、高さは使用可能な画面に制限します。共通 OperationHeader の下の 1 単位の区切り線に続き、サイドバーのナビゲーションと独立してスクロールする右ページを配置します。サイドバーの基準幅は 144、通常行高は 40、アイコン領域は 18、アイコン左位置は 15 です。先頭行は上端に接し、選択表示は右側の区切り線に接します。文字拡大時は実際に最も広い単語とアイコン間隔に合わせてサイドバーを広げ、英語は単語間で折り返し、行は拡大またはスクロールします。未選択行のホバーは両テーマでサイドバーと区別できる共通 controlHover を使います。ページ余白は 20、グループ間隔は 16 です。パラメーターはスクリーンショット、DPR、レビュースケールではなく layout-scale.json の operation.settings に従います。

ページは外観、一般、プライバシー、ファイル関連付け、ネットワーク、アプリ情報です。設定にはフッターや保存、キャンセル、完了ボタンがありません。成功した変更は直ちに適用し、失敗時は適用済みの値を維持して理由を表示します。アプリ情報はバージョン、ライセンス、ユーザーが開始する更新を保持し、すべてのアプリ情報入口は独立ウィンドウではなくこのページを開きます。テーマカード、設定アイコン、ブランド、既存状態アセットを再利用し、変更のないスライスを再生成しません。

設定の選択行では、説明と右寄せセレクターが横に収まらない場合、説明をセレクターの上に配置します。MSIX のファイル関連付けページでは、共通の既定アプリボタンを内容幅内に保ちます。長い翻訳は使用可能幅で折り返し、文字を大きくしても読めるようにします。

ページ本文にサイドバーのタイトルやその区切り線を繰り返さず、実際のセクションタイトルと区切り線は維持します。アプリ情報の主要更新操作は状態行を共有して右寄せします。確認中は確認をキャンセル、利用可能時はダウンロード、ダウンロードしてインストール、またはリリースページ、ダウンロード中はダウンロードをキャンセル、完了後はインストールまたはダウンロード先を開く操作です。確認と確認キャンセルは同じ位置とサイズを保ち、その下に進捗を表示します。補助的なダウンロード先操作は右寄せします。

各コンポーネントは寸法、フォント、アイコン領域、余白、整列端、ヒット領域、状態、データソースを指定します。既定状態だけでは不十分です。ボタンは通常、ホバー、押下、フォーカス、無効、処理中を扱います。メニューはキーボード選択、サブメニュー、チェック済み、無効、画面端での反転、スクロールを扱います。ツリーは階層、末端、折りたたまれた現在パス、深いスクロール、長い名前を扱います。一覧はヘッダー／内容の端の整列、並べ替え、複数選択、空、未知の状態を扱います。

数値列は共通の端で右揃えし、種別列は左揃えします。パンくずとプレビュータイトルの高さ、フォント、ベースラインを合わせ、プレビュー上端をファイルヘッダー上端に揃えます。アイコンは領域内で中央に置き、テキストはフォントメトリクスで揃えます。背景を含むスクリーンショットからの一時スライスではなく、共通アセットを使います。

ファイル一覧のチェックボックス右端からアイコン領域までの間隔は 12 論理ピクセルで、layout-scale.json の fileSelectionGap に従います。元の約 21.17 の間隔を縮め、アイコン領域、アイコンとテキストの間隔、他の列境界を維持しながらファイルアイコン、ファイル名、名前ヘッダーを一緒に左へ移動します。固定した原稿と測定値は変更しません。

メインウィンドウの通常密度補正とアクセシビリティフォント拡大は別の手順です。現在の選択肢は 100%/125%/150% で、旧 200% 設定は 150% として読み込みます。文字が大きい場合は高さの増加、スクロール、独立詳細表示を許可し、選択を打ち消すために文字を縮小しません。200% を直接注入するテストは過去の負荷検査を表し、現在の製品選択肢ではありません。すべての視覚例外について理由と検証範囲を記録します。

## 受け入れ条件

HTML と Qt は同じ論理幅で比較し、原稿の外側背景のみを切り取り、明示したスケールで表示します。形状の最大誤差は 1 論理ピクセル、テキスト／アイコンの縦中心誤差は 0.5、整列したペイン上端の誤差は 0.01 です。スクリーンショット報告にはコミット、プラットフォーム、レンダラー、ブラウザーズーム、レビュースケール、DPR、論理ウィンドウ寸法を記載します。

任意の HTML 比較では実際のブラウザーページズーム 100%/125% と DPR 1/1.25/2 を確認します。対応する Qt 測定は高 DPR 下で同じ論理ウィンドウ、フォント、メニューパラメーターを検証します。ツールは CSS ズームを実際のブラウザーページズームと偽ったり、オフスクリーンのスクリーンショットをネイティブデスクトップ受け入れと偽ったりできません。検査数は視覚忠実度のパーセンテージではありません。

[UI デザイン手順](design-workflow.md)に従います。仕様、生成出力、実座標、スクリーンショット、操作証拠が欠ける場合は完全な受け入れと記録しません。

## メインウィンドウ操作の改訂

メインツールバーのアイコン／テキスト間隔は 6 固定とし、独立アイコンは内容ボックス内で中央に置きます。リスト／グリッド／並べ替えボタンは 28×28 の角丸正方形で固定し、ヘッダー間隔は 6.4、パンくずが残りの幅を吸収します。パンくずボタンは通常高さ 28 で上下余白を持ちます。メニューは呼び出しボタンから 4 単位離し、下端のメニューは上向きに開きます。ツリー行はファイル数を表示せず、選択された左端は直線で全高のインジケーターを持ち、子ノードには四辺の枠を付けません。ツリー幅は展開ノードの実際のテキストメトリクスを使います。改訂した操作と測定は[検証方法](../../../developers/qa/README.md)に従って記録します。

## 操作ウィンドウとタスク状態のアセット

### 共通アイコンヘッダー

作成、追加、展開、タスク／結果、競合、設定ウィンドウは OperationHeader を共有します。アプリ情報は設定内にあり、整合性検査は TaskWindow を通じて継承します。アイコン領域は 48×48、タイトル 20、サブタイトル 13、水平余白 24、垂直余白 20、アイコン／テキスト間隔 16、タイトル／サブタイトル間隔 6、通常高さの基準は 96 です。アイコンはウィンドウ固有のキャンバスやアートワークの上書きなしに縦横比を保って中央に配置します。タイトルとサブタイトルはライト／ダークテーマの text/textSecondary を使うプレーンテキストで、フォントサイズはアプリのアクセシビリティ設定によってのみ変わります。長いテキストや大きいフォントでは共通フォントメトリクスでヘッダーを拡大し、文字を縮小したり本文／フッターを覆ったりしません。

[operation.header](../../../specs/visual/layout-scale.json)が唯一のパラメーターソースです。独立状態のデザインは [operation-headers.html](../../../design/hifi/sources/operation-headers.html)、ウィンドウ対応は [window-registry.json](../../../specs/visual/window-registry.json)にあります。これはウィンドウ別アイコン領域、中央に置いた 24 単位のアプリ情報ブランド、ウィンドウ固有のヘッダー高さに代わります。過去の画像、ハッシュ、測定値は変更しません。テキストのみのパスワード、事前検査、終了／再起動のヘッダーに架空の装飾アイコンを追加せず、安全な操作を維持します。メインウィンドウとメニューの密度は別々に測定します。

操作ウィンドウのジッパーイラストは scripts/zipper_assets.py の形状と一覧を共有します。かみ合う 2 列の丸い歯、低コントラストのテープ、独立したスライダー、開いた引き手で構成します。歯と金属のハイライトを控えめにし、ドキュメントのシルエット、アイコン領域、UI 密度を変えずアセット内で比例拡大し、背景に合わせた色を選びます。新しい利用箇所は ZIPPER_ICONS に登録し、アセット検査でライト／ダークの完全性と互換性のあるインライングラデーション ID を検証します。

形状は 24 単位の共通ベクターキャンバスを使い、ヘッダーは共通の 48 論理ピクセル領域を維持します。ライト／ダーク SVG と 1×/2×/3× PNG は一つの定義を共有し、archive-add と file-archive は 9× 書き出しも維持します。ブランドと関連付けアイコンはブランド定義を保持し、過去のアートワークとスライスは変更しません。

すべてのフッターボタンは layout-scale.json から生成したテキスト 13、補助テキスト 12、アイコン領域 16 論理ピクセルを使います。本文は独立してスクロールし、フッターは操作可能な位置に保ちます。フォント、色、1 論理ピクセルの線は埋め込み／独立入口によって変えません。実際の比較を[検証方法](../../../developers/qa/README.md)に従って記録します。

タスク結果の円形アイコンは [status-icons.json](../../../specs/visual/status-icons.json)の単色塗りと白い意味別マークを使い、キャンバス 24 単位、可視直径 20 で、グラデーション、ハイライト、細い枠、影を付けません。ライト／ダーク SVG と 1×/2×/3× PNG を一緒に書き出します。既存の原稿とスライスは過去のピクセルを保持し、新しいスタイルに書き換えません。実際の検証は[共通方法](../../../developers/qa/README.md)に従って記録します。

## ルートとファイル項目の操作

ディレクトリーツリー上部の「アーカイブ」はパンくずタイトルと縦中心を共有します。通常のディレクトリー閲覧は直下のファイルとフォルダーのみを表示し、ツリー入口は「ルートフォルダー」です。アーカイブ内の完全パスはデータに残し、通常一覧は末尾の名前、検索結果は完全パスを表示します。ツリーのホバーに浮動ヒントは付けず、完全パスはアクセシブルな説明として残します。親の縦線中心 X は親の展開矢印の中心 X に揃えます。

リストのホバーは行の全列を覆い、選択の塗りを優先します。グリッドの水平余白は 16、カード領域は 144×124、領域間隔は 12、アイコン領域は 40 です。チェックボックスはカード左上から 8×8 に置き、ホバー時に表示し、選択中は表示したままにします。アクセシビリティフォントでは実メトリクスに従って領域を拡大します。プレビュー再表示ボタンも 28×28 です。メニューの影は半径 12、垂直オフセット 4 です。Qt はソフトウェア／GPU レンダリングに対応する共通 9 スライス PNG、HTML は同じパラメーターの CSS ぼかしを使います。最初の完全なメニューフレームで本文と影が同時に現れることを確認し、ライト／ダーク状態の実ピクセルを検査します。ダークの分割ボタンの区切り線はダークの枠線色を使います。

ZIP 作成は C01 原稿の 3 部構成と白い内側パネルを使います。通常幅 491、タイトル 20、本文 13、補助テキスト 12、フィールド／本文ボタンの高さ 28、入力行 38、フッターボタンの高さ 32、フォント 13 です。クライアント領域は最大 736 で、小さなデスクトップでは本文のみをスクロールし、フッターを操作可能に保ちます。Qt と HTML は同じ論理パラメーターを使います。TAR/TAR.GZ は既存の形式セグメントを使い、TAR はレベルを無効にし、両方ともパスワードとボリュームを無効にします。切替時には適用されないオプションを消去して拡張子を同期します。ディレクトリー合計はバックグラウンドスキャンを待ち、サンプル値を実際の事前検査の代わりにしません。実際の機能と比較を[検証方法](../../../developers/qa/README.md)に従って記録します。

## 共通操作コントロールと作成ウィンドウの改訂

[create-reference.json](../../../specs/visual/create-reference.json)は C01 原稿のハッシュ、コントロールの切り取り座標、現在の改訂を固定します。操作ボタン、入力、ドロップダウン、フッターボタンは角丸 5、ライト枠 #DCE2EC、ダーク枠 #485469、通常の中立ボタン塗り #FAFBFD を共有します。本文操作は高さ 28、フッター操作は 32、フッターテキストは 13、補助テキストは 12 です。個別ウィンドウは形状、線、フォント、色、密度を上書きしません。危険操作は意味に応じた危険色を維持し、フォーカスで追加の線を付けません。

作成一覧は共通アセットの円形マイナスを使い、ヒット領域 28、アイコン領域 24 とし、ファイルサイズを右揃えします。圧縮形式は等幅、隙間なし、外枠一つの連続したセグメント型ラジオグループです。無効な形式はマウスでもキーボードでも選択できません。ファイル概要は通常ファイルのメタデータをバックグラウンドで読み取り、元の同名フィクスチャー 3 個は実際に 8.4、6.2、12.8 MB で「3 ファイル、27.4 MB」と表示します。ディレクトリー合計は不明のままにし、開始時に入力ツリーを再び固定します。

情報は中点ではなく、カンマ、句点、改行、明示的なラベルで区切ります。これは現在の UI と保守文書に適用し、既存の高忠実度ビットマップには適用しません。過去のスクリーンショットと取得 JSON は現在のソースツリーに入れません。scripts/check-operation-components.py は共通コントロールを強制し、実際の測定、操作、制限を[検証方法](../../../developers/qa/README.md)に従って記録します。

## 整合性検査とシステムウィンドウ

整合性検査はタスク進捗の幅 491、最大 600 の可変クライアント高さ、タイトル 20、本文 13、共通フッター、通常密度を維持します。高忠実度原稿は screens/integrity-progress.png、固定した参照は integrity-reference.json です。ヘッダー、対象パス、グラデーション進捗、読み取りバイト／ファイル、3 個の指標、現在のファイル、説明、フッターのレイアウトを維持し、操作名、青いドキュメント検査イラスト、対象、平均読み取り、読み取りと検証、検査キャンセルのみを置き換えます。別のブラウザーネイティブ進捗バーや異なるサイズの検査カードを使いません。

HTML は taskProgressBody、taskProgressFooter、進捗スタイルを再利用し、Qt の IntegrityWindow は TaskWindow を継承します。検査は読み取り専用で、終端に保存済み出力の統計や出力フォルダーを開く操作を表示しません。コンポーネント開発プレビューは実際の検証を行わないことを明示し、実際のツールバーコマンドは[検査契約](../engineering/archive-checking.md)に従います。ライト／ダーク、未知の合計、長いパス、アクセシビリティフォント、閉じる、キャンセルは共通契約を使います。

固定 Qt 行高はレイアウトの行領域の高さでもある必要があり、固定領域にフォントの追加行間を加えません。割合行の領域は 24、バイト／ファイル数行の領域は 18 です。パスカードのタイトルと指標は規定の行高を維持し、複数行の指標は実際の行数に応じて拡大します。既定フォントサイズでは進捗ウィンドウ本文の説明 3 個をすべて表示し、小画面や大きい文字では本文をスクロールしつつフッターを固定して操作可能に保ちます。

現在、各メインウィンドウは ExtractWindow、CreateWindow、TaskWindow を一つずつ所有し、いずれも独立した OS ウィンドウです。展開、作成、実際の整合性検査の進捗／結果は TaskWindow を再利用し、別タスクを選ぶと状態ごとにウィンドウを作らず同じウィンドウを更新します。コンポーネントプレビューは別に IntegrityWindow を使い、実際の検査は行いません。[タスクウィンドウ契約](../ux/task-windows.md)を参照してください。

## 2026-10-15 操作と選択の改訂

この節は過去の進捗、結果、名前競合ウィンドウの寸法に代わります。元の PNG、ハッシュ、切り取り参照は維持し、寸法を変えるためにスクリーンショットを拡大縮小しません。[操作ウィンドウとボタン状態](../../../design/hifi/operation-revisions.html)を参照してください。

- 展開、作成、進捗、結果、ファイル存在ウィンドウは幅 491 論理ピクセルを共有します。タスク本文とフッターが最大 600 までの高さを決め、詳細一覧は最大 168 の高さとし、折りたたみ時は実際の内容高さに戻します。競合本文は通常密度 0.8、タイトル 20、本文 13、補助 12、最大高さ 560 と、固定して操作可能な共通フッターを使います。文字が大きい場合は内容が拡大またはスクロールします。
- 圧縮形式は連続したセグメント型ラジオグループを構成します。最初の選択肢のみ左側の 2 角、最後のみ右側の 2 角を丸くし、選択、ホバー、押下、フォーカスのすべての状態で内側の角は直角にします。
- 共通トークンは青いボタンの通常、ホバー、押下、無効状態をすべて区別します。押下は accentPressed、無効は accentDisabled/accentDisabledText を使い、グループの不透明度や灰青の混合を使いません。キーボードとマウスの押下は同じ状態を共有します。
- 外側クリック、Escape、Return、テンキー Enter は展開を開始せず、展開先編集のフォーカスを離れます。最初の Escape はウィンドウを維持し、次の Escape はウィンドウ規則に従って閉じます。範囲タイトルと補助件数は別の列に置きつつ、行は一つのラジオヒット領域を維持します。
- すべて選択と個別選択はフォーカスされた詳細の意味を共有します。すべて選択では現在の一覧の最後の項目にフォーカスし、選択解除では詳細を消去します。選択がない場合は 4 個のプロパティーとプレビューの展開操作を非表示にします。プレビュー展開はホバー、押下、フォーカス、無効を維持します。
- ステータスバーのボタンはセッションをまたいで再表示可能なタスクを数えます。別の実行中件数はヒントと終了を制御します。タスクメニューは文字サイズ 100% で共通の幅 240 単位、フォント 13 単位、最小行高 32 単位を使います。操作アイコンはファイル名、連番、状態の前に置きます。`CommandMenuTag` は共通余白と角丸を使い、連番に中立色、状態に意味別の色を使います。タグの場所を確保するためファイル名を省略し、アクセシブル名には操作、番号、ファイル名、状態を保持します。履歴が多い場合はメニュー高さの上限内でスクロールします。削除とタスク識別は[タスクウィンドウ](../ux/task-windows.md)を参照してください。

ウェルカムページとアーカイブページはタスクボタンの内部配置と、layout-scale.json の右側内余白 14 論理ピクセルを共有します。ボタン、アイコン、開閉表示、メニューアンカーはフォント倍率や DPR にかかわらずページ切替時も水平に揃います。

タグのテキスト幅と高さは現在のフォントの暗黙メトリクスに直接結び付け、タグとテキストの寸法から位置を計算します。これによりメニュー表示またはフォント変更後の最初の描画フレームから中央に保ちます。最初のフレームの検査は後のレイアウト補正を待たず、文字サイズ、共通内余白、中心を検証します。利用できないメニュー操作は理由行、ヒント、ツールチップを表示せず無効のままとし、正確な理由はアクセシブルな説明にのみ記載します。選択がない場合の「選択項目を展開」と「展開前のメタデータ検査」もこの規則に従います。実際の操作エラーと安全性エラーは引き続きタスクまたはフィールドに明示します。

正規パラメーターは layout-scale.json の operation.adding で、既存の作成および共通コントロールパラメーターを再利用します。独立した対応付けは [add-reference.json](../../../specs/visual/add-reference.json)にあります。[編集可能なデザイン](../../../design/hifi/sources/archive-add.html)は中国語／英語、ライト／ダーク、100%/125%/150%、長い名前、空の選択に対応します。HTML と Qt はカード、コントロール、スクロール、フッターを別々に検査し、メインウィンドウ／メニューの比率も別途測定します。オフスクリーンの成功はネイティブデスクトップ受け入れの代わりにはなりません。

## アーカイブ内移動の状態

内部ドラッグはメインウィンドウ、メニュー、行高の比率を変えません。対象は既存の一覧選択と treeSelectionColor を使います。フィードバックは tooltipSurface/tooltipText、tooltipMaxWidth、tooltipPadding、mainBodySize を使い、最大 4 行とし、固定操作ウィンドウを使わずクライアント領域内で反転または制約します。無効な対象には具体的な理由を示し、元の行は選択色を維持します。進捗と競合ウィンドウの寸法を再利用し、ファイル競合ではスキップ、名前変更、置換、後続の競合への適用を提供します。[archive-move.html](../../../design/hifi/sources/archive-move.html)を参照してください。

ファイルドラッグがシステム閾値を超えたら、対象ディレクトリーを待たずにポインターに追従するアイコン／名前カードを直ちに表示します。単一項目は種別アイコンと名前、複数項目は選択数も表示します。名前はプレーンテキストで中央を省略し、対象説明は最大 4 行です。カードは入力を扱わず、ドロップ検出を妨げません。対象カーソルと具体的なテキストは引き続き許可／拒否を表します。右下に 16 ずらしてクライアント境界内に収め、キャンセルまたは完了時に直ちに消去します。最大幅 280、アイコン 24、余白 10、間隔 8、角丸 8 です。共通ヒント色とメニューテキストを使い、アクセシビリティフォントではテキストと最大幅を拡大します。[drag-preview.json](../../../specs/visual/drag-preview.json)と [archive-drag.html](../../../design/hifi/sources/archive-drag.html)を参照してください。

外部コピーはプラットフォームのドラッグセッションを使います。Windows Shell と Linux QDrag は透明な 64 論理単位のプレビュー、48 単位のアイコン、複数選択数バッジを使い、99 を超える件数は 99+ と表示します。ウィンドウ DPR でサンプリングするのはビットマップの保存のみで、論理寸法は変わりません。Mac は AppKit のネイティブファイル約束画像とシステムフィードバックを維持します。ネイティブカーソルはコピーまたは拒否を示します。外部コピーをアーカイブ内移動として描いたり、成功前に完了を示したりしません。ネイティブ画像の準備に失敗しても、安全な転送と既定のシステムカーソルを維持し、内容検証を弱めません。[Windows Shell ドラッグフィードバック](https://learn.microsoft.com/en-us/windows/win32/shell/dataobject)と [Qt 6.8 QDrag](https://doc.qt.io/qt-6.8/qdrag.html)を参照してください。

展開確認のネイティブタイトルと本文タイトルは「解压文件」／「Extract files」です。ツールバーの展開操作は別の翻訳 ID を維持します。タイトル改訂はウィンドウ寸法、本文、フッターを変えません。

最初の本文グループは共通ヘッダーの後に operation.header.bodyGap を置き、現在は 0 論理ピクセルです。ヘッダー余白がすでに間隔を提供するため、旧ヒーロー間隔を追加しません。カード余白、本文段落、設定セクションの間隔は本文コンテナー内に維持します。Qt と HTML はヘッダー下端から最初のグループまでの境界を測定し、実行中と 3 種すべての終端タスク表示を対象にします。

## 操作ウィンドウの動的な高さ

[タスクパスと結果の改訂](../../../design/hifi/sources/task-windows.html)は、実行中の現在ファイル領域を中央省略付きの 1 行に保ち、アクセシブル名に完全なプレーンテキストを保持します。パスの長さだけではカードやウィンドウのサイズを変更しません。通常の展開結果の説明は保持した詳細レコードにかかわらず、コミットされたファイル数のみを含みます。作成の説明は名前やサイズを含まない「N ファイル」のみを表示し、通常出力には outputParts、一括作成には成功タスク数を使います。一括作成結果はボリュームグループの重複排除数を省き、一括展開結果はそれを維持します。展開可能な詳細は既存動作を保持します。既存の論理寸法、密度、大きいフォントへの適応を正規の基準とします。

各操作ウィンドウは内容、フォント、使用可能な画面に基づく既存の目標クライアント高さを維持します。調整時はまず目標方向に制約を広げ、目標高さを設定してから両方の境界を目標値に戻し、古い制約によるプラットフォームの拒否を避けます。その後、クライアント高さは固定のままです。再表示、内容変更、遅れて届くプラットフォームの形状コールバックは、画面倍率や新しいサイズパラメーターを加えず同じ論理単位を使います。実行時の形状検査はネイティブデスクトップの視覚受け入れの代わりにはなりません。
