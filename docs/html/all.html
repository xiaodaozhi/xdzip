核心决定#

  1. 双击压缩包先浏览内容；解压、压缩、覆盖及执行外部程序都由明确操作触发。
  2. UI 不实现归档业务。Rust 核心不依赖 Qt，预留测试驱动和未来 CLI 接入。
  3. 正式 Qt/Rust 边界使用 cxx 生成的构建期类型桥接，不承诺跨版本二进制 ABI。原型的 JSON/C ABI 仅用于迁移验证。
  4. 格式以能力声明驱动。源码级 Rust 扩展和进程级第三方扩展是不同契约；不加载任意 Rust 动态库。
  5. 文件授权、路径校验、输出事务和配额集中在宿主。编解码器不能自行挑选真实输出路径。
  6. 先完成 ZIP 和 TAR/GZIP 的真实闭环，再扩大格式范围。7z、RAR、加密、分卷、第三方沙箱均有独立验证门槛。
  7. UI、索引、任务、插件均有有界队列和缓存；任务终态不能被进度事件淹没。
  8. 把“小、快、低占用”转化为机器配置和工作负载明确的预算，不把原型二进制大小当安装体积。

xdzip：01 产品与需求

1. 产品定位#

xdzip 是面向 macOS、Windows、Linux 的桌面归档管理器。主要价值是像普通文件管理器一样查看压缩包，并可靠地完成选定内容解压和新建归档。用户不必先把整个归档展开到磁盘，也不必理解插件和编解码实现。

优先体验为 macOS 桌面，包括中文输入法、⌘ 快捷键、Retina、系统文件选择和 Finder 打开方式；三个平台共享信息结构、任务行为和安全语义，遵循各平台键盘、窗口和文件系统习惯。

3. 操作流程#

打开和浏览#

文件关联、拖入或“打开”均获得一个用户授权的源文件句柄。按文件魔数和格式探测确定后端，后缀仅提供提示。会话先显示归档标题和探测状态，再增量显示内容。ZIP 可读取目录；TAR 等流式格式显示“正在扫描”，扫描期间总条目数可未知。部分索引不能伪装成完整搜索结果。

遇到密码先说明是读取目录还是读取内容需要密码。用户取消密码输入后，会话保留可用元数据或返回可操作错误，不静默尝试空密码或无限重试。文件缺失、格式不支持、损坏和权限拒绝使用不同提示。

解压#

工具栏提供“解压选中项”和“全部解压”。有选择时默认使用选中项；没有选择时默认所有条目，不把当前搜索结果悄悄当成全部归档。搜索页可通过单独菜单“解压搜索结果”生成明确快照，并在确认区显示数量及“当前结果”的范围。

用户选择目标目录，可选“创建同名子目录”。核心生成计划：去重递归目录选择、路径可映射性、能力检查、预计大小、已知冲突及风险。对尚未完成的索引，全部解压计划等待扫描完成；大型计划异步构建，有进度和取消。

默认不覆盖现有文件，遇冲突进入等待决策。对话框提供跳过、改名、覆盖，以及“对本次任务后续同类冲突应用”。决定绑定任务及冲突 ID；任务在实际提交时重新检查磁盘。完成摘要显示成功、跳过、失败、取消前已完成项，并提供“在系统中显示目标目录”。

创建归档#

添加文件/目录 → 选择格式与目标 → 按后端能力选择压缩级别 → 预检 → 后台写入同目录临时归档 → 校验/关闭 → 原子发布。默认 ZIP/Deflate，压缩级别显示“快速/均衡/更小”并展示对应后端参数，不能承诺各格式同等级同结果。目标在输入树内时排除目标和本次临时文件，拒绝会无限递归的输入。

预览和临时打开#

MVP 不提供自动预览。后续版本只内置有限文本/图像预览，格式和大小由白名单控制；外部打开先完整解码到受控临时目录，说明将调用系统应用。禁止自动执行归档内程序、脚本、宏或 HTML。可执行文件不会因“预览”自动启动。

xdzip：02 系统架构

1. 架构目标#

Rust 负责所有归档语义、任务、格式选择和文件安全。QML 负责视图与轻量交互，C++ 负责 Qt 对象、模型、系统桌面接口和 Rust 类型适配。更换 UI 时保留核心和格式适配器；增加格式时不改列表视图和任务状态机。

MVP 采用一个应用进程、一个 Rust 核心运行时及可选格式工作进程。内置纯 Rust 后端可进程内运行；使用大规模原生解析库的适配器优先放在官方工作进程。第三方扩展一定经过受约束工作进程，不能以“进程隔离”代替沙箱。

箭头表示调用方向。格式适配器通过 SDK 的受限读取/输出对象请求 I/O；图中未画出的受限端口不构成任意文件系统访问。

3. 进程与线程#

执行位置 工作 生命周期
Qt GUI 线程 QML、控制器属性、模型更新、文件对话框 应用主线程；不能等待扫描或解压
Qt 事件接收线程 等待 Rust 事件，转换成批量 Qt 值对象，发送 queued signal 启动时创建；关闭通过独立控制通道唤醒
Rust 调度线程 轻量命令、会话/任务状态、资源准入 核心运行时；不执行长时间 codec 调用
Rust 有界工作池 扫描、查询、解压、压缩、校验、文件提交 队列有上限，工作项检查取消
格式工作进程 特定后端、官方原生库或第三方扩展 按任务/会话复用，限制并发与内存

没有为每个文件创建线程。压缩后端自带并行线程必须纳入任务 CPU 额度，不能在外层四线程任务里再启动四个无限线程池。任务状态变化集中到调度器，工作线程只发送结果/进度。

UI 提交接口只完成校验和非阻塞入队。结果采用事件推送；空闲时事件接收线程阻塞等待，不常驻 100ms 状态轮询。计时和指标采样只在诊断或运行任务时启用。

4. 服务和所有权#

ApplicationRuntime 持有会话管理、任务调度、能力注册表及事件通道。每个 ArchiveSession 持有源文件授权、格式后端、索引状态、源版本和生命周期计数。查询产生不可变 QuerySnapshot，计划产生不可变 OperationPlan。

任务不依赖某个标签页存活。关闭标签页释放浏览订阅；有关任务持有其源快照和文件授权，继续运行或根据用户选择取消。关闭整个应用则进入统一 shutdown：停止新命令、请求取消、等待提交安全点、收尾工作进程，再回收模型与运行时。

一条归档会话允许多个读取任务，但具体并发由后端声明限制。禁止原位修改源；创建新归档或“另存为”使用新输出事务。因此读取任务不会与产品自身的原地写入竞争。

5. 配置与持久化#

小型用户设置使用 Qt 设置适配器：主题、窗口、上次目录、快捷键选项。Rust 只接受验证后的策略快照，不直接读取 GUI 设置。设置分 schema 版本，有迁移和备份；读取异常恢复默认，并显示一次非阻塞提示。

归档索引先采用内存紧凑结构，达到预算阈值后迁移到临时磁盘索引。每会话独立 SQLite 候选后端仅用于产品自己的元数据，不保存密码或文件内容；是否采用 SQLite 由内存阶段实测决定，但 IndexStore 接口从首版提供。默认不跨启动持久缓存归档索引，避免源身份和隐私问题。

输出事务日志保存在授权目标内的随机私有工作目录。全局应用数据只保存用户设置、扩展清单和低敏诊断；不能因为打不开一个用户路径就把原始内容搬入全局缓存。

6. 可替换性和边界检查#

单元测试使用内存源、故障注入文件端口、假后端和无 Qt 的事件客户端。界面集成测试使用同一个应用服务，不重复实现“假核心业务”。未来 CLI 是另一个适配器，可复用 xdzip-runtime，不通过 GUI 或 cxx 间接调用。

架构检查在 CI 禁止核心 crate 依赖 Qt/桥接，禁止格式 crate 依赖桌面应用，检查 Cargo features 不拉入未使用后端。代码审查关注调用方向和资源所有权，不能只以目录拆分作为解耦证据。

7. 故障边界#

工作进程崩溃使相关任务失败，宿主回收未提交文件；既已提交的文件留在结果摘要中。格式错误成为领域错误。Rust 内部不变量崩溃和无法恢复的内存错误是进程级故障，不能声明一切 panic 都可捕获继续。桥接入口禁止 panic 越过 FFI；发行 panic 策略在桥接验证阶段确定，并配合输出恢复日志处理异常终止。

Qt 渲染故障不允许触发重复提交。GUI 断开订阅后核心仍按状态机收尾。关闭等待超过软期限时提供“继续等待/强制退出”；强制退出不承诺零遗留，由下次启动恢复流程处理。

xdzip：03 领域模型与数据设计

1. 身份和版本#

类型 含义 规则
SessionId 当前运行时归档会话 运行时生成，不按路径推导
SourceRevision 打开源的版本 绑定已打开句柄、文件身份、大小、修改信息及可用变化标记
EntryId 一个物理归档记录 会话内稳定；重复路径仍有不同 ID
QueryId / QueryGeneration 查询快照与 UI 请求代次 代次用于丢弃旧响应；QueryId 绑定实际结果版本
PlanId / PlanRevision 已准备操作计划 修改目标/策略/源需新修订，旧计划不能启动
TaskId / RequestId 后台任务和调用关联 不复用，日志可匿名引用
ConflictId / PromptId 等待的用户决定 仅对应任务当前决策点，可超时/失效

ID 为不可解释整数或不透明值，桥接中以 64 位数传递；QML 不直接用浮点表示 64 位 ID，由 C++ 提供不透明字符串/值包装，避免 JavaScript 精度截断。行号是视图位置，不是身份。

源版本检测属于尽力一致性保护，不等同于持有文件句柄就获得静态快照。读取前、读取中关键点和提交前检测变化；不支持可靠检测或用户要求强一致时先做受配额的源快照。检测到变化停止任务，保留已提交项，要求重新打开和规划。

2. 条目模型#

ArchiveEntry 包含：ID、父节点 ID、归档记录序号、原始路径字节、展示路径、类型、已知/未知压缩大小与解压大小、时间及精度、校验类型、加密标志、属性、扫描序号和安全标记。符号链接目标单独保存，不能当普通文件内容自动恢复。

大小用 Option<u64> 表示未知，不使用 0 表示未知。时间附带来源和时区/精度；无法确定时显示“未知”。支持常规文件、显式目录、合成目录、符号链接及特殊记录；MVP 只输出常规文件和目录，其余显示原因并拒绝恢复。

路径原始字节保留。展示优先遵从格式编码规则；UTF-8 标志、Unicode 扩展和编码选择按后端能力处理。非法字节在 UI 中安全替换/转义，不能用替换后的名称直接写出，否则两个不同原始名可能合并。用户可选择会话级旧编码，重新生成展示/输出候选并使旧计划失效。

同名记录不去重；合成目录使用独立身份，包含实际后代集合。归档内部安全标记如 absolute_path、parent_escape、unsupported_special 不因展示规范化而消失。EntryId -> raw_record 映射保存在核心，扩展必须用该 ID/记录令牌读内容。

3. 索引状态#

状态为 Detecting -> Scanning -> Ready，任何阶段可进入 Failed 或 Closed。扫描可产生增量批次及 ScanProgress；已发现行数不等于总数。查询结果具有 complete: bool 和 indexed_count，总匹配数在未完成时为下界。

部分结果默认按发现/路径显示，可以查询已扫描内容；最终排序和完整计数在扫描结束后建立新快照。UI 明示“已扫描内容”，不能把部分结果用于默认“全部解压”。流式后端必须保留扫描错误位置，不能以提前 EOF 标记 Ready。

索引字段分为常用列和详情。列表页不复制原始路径、注释或所有扩展属性；点击详情才读取完整记录。超长名称、超多条目、注释和额外字段各自有预算，见 常量。

4. 查询与分页#

QuerySpec 含目录范围、普通文本搜索、排序字段、方向和隐藏项选项。首版无正则，避免非预期复杂度。默认搜索展示路径，大小/类型筛选是独立显式字段。匹配采用 Unicode 规范化后的大小写折叠副本，原始名不改变；本地排序以确定性比较器加 EntryId 作为终级 tie-breaker。

建立查询快照可能耗时，因此异步返回。PageRequest {query_id, generation, offset, limit} 中 offset 为 64 位，limit 最大 256。页包含 QueryId、generation、snapshot revision、行数据和完整性。Qt 内部单个模型行数受 int 限制，超过上限时采用分段视图；不能窄化转换或使总数溢出。

数据更新不就地改变已创建 QuerySnapshot 的行身份。新扫描批次、编码变化、筛选或排序产生新版本。相同查询可共享只读索引，最多保留当前及正在使用的旧版本；旧快照在引用释放后回收。缓存页键为 QueryId+revision+offset，不是 offset 单独。

5. 选择#

SelectionState 属于会话，核心保存选择表达式而不是每次下载所有行。支持显式 ID 集、QuerySnapshot 范围，以及“全部结果减去排除项”。大型范围保存区间/位图并提供统计，避免 UI 持有百万个 ID。

Ctrl/⌘ 切换单项；Shift 范围基于当前 QueryId 的锚点。查询变化清除锚点，保留已选身份；被筛选隐藏的选择在工具栏显示“已选 N 项，其中 M 项在当前视图”。目录选择在生成计划时展开后代并去重物理 EntryId，不重复解压。

UI 可先显示轻量本地选中态，核心返回 SelectionRevision 后确认。任何选择命令都带当前 QueryId，过期范围命令返回 stale_query，不能按新行号误选。

6. 操作计划#

OperationPlan 固定：操作类型、源版本、选择快照、后端版本/能力、授权目标引用、输出映射、冲突策略、配额、压缩参数、预计工作量和风险摘要。计划不保存明文密码；秘密使用单独短生命周期令牌传入。

计划构建可延迟存储大量条目，但启动后输入集合不得随 UI 选择变化。启动检查源、目标授权、计划修订和后端版本；过期返回 stale_plan。同一 PlanRevision 默认只允许启动一个任务；有重复 RequestId 时返回已创建 TaskId，而不是再写一遍。

“压缩输入”不是归档条目：使用 InputSourceId 和预扫描树，记录句柄授权及文件版本。扫描文件树不跟随链接，检测输入变化，排除输出和暂存目录。恢复权限只允许普通读写位，不恢复 setuid、setgid、设备节点或不受信任扩展属性。

7. 结果和持久化#

TaskResult 含状态、完成/跳过/失败数、实际字节、已提交列表或分页结果句柄、清理状态、完整性状态和有限错误样例。成功指所有要求项已完成并通过声明校验；允许跳过的策略产生成功但摘要显示跳过。任何未被用户策略允许的失败使任务为 Failed，摘要仍可含已完成文件。

事务日志只记录恢复所需的相对映射、随机工作目录、文件身份、临时文件状态和提交状态。日志格式版本化、长度有界，并视为不可信输入。重启不会自动续写或删除陌生文件；恢复流程见 07。

用户设置、归档索引、事务日志和扩展清单采用不同 schema；不能用一个 SQLite 数据库承载所有生命周期。密码永不进入它们。

未启动计划默认最多保留 8 个，重新规划释放旧计划；计划映射和分页结果共用独立 64MiB 热数据预算。v0.1 超额明确返回资源错误，M6 将大型映射/结果迁入磁盘后端。任务完成历史默认保留最近 100 个轻量摘要，完整结果在用户关闭/过期时回收；活动任务引用的数据不能提前清理。所有缓存包含选择区间和查询快照，不能只计列表页而漏掉计划内存。

6. 无障碍和输入#

验收包括中文拼音/五笔候选、组合文本、RTL 名称、emoji、200% 字体缩放、125%/150% DPI、深浅色和减少动态效果。原型里的程序化中文搜索不算输入法验收。

7. 密码与错误#

密码框禁用自动完成、剪贴板建议和日志。提交后 QML 属性尽快清空，C++ 转移到短生命周期秘密对象；Qt/系统输入法内部复制无法保证全部擦除，因此不宣称绝对零残留。默认不持久记住密码。

错误码由核心给出，Qt 使用翻译目录形成文案；插件不能直接提供富文本错误页。允许复制脱敏诊断：软件版本、格式、错误码、匿名 TaskId，不带密码、内容或完整路径。

独立操作窗口#

解压、新建、冲突、任务、结果和设置均使用独立顶层窗口，不使用主窗口内遮罩或 macOS sheet。macOS 使用原生左上角系统按钮，Windows/Linux 可自定义标题栏并保留系统窗口行为。所有权、模态范围、关闭与取消语义、原型边界及实机验收以平台窗口规范为准。

xdzip：05 Qt/Rust 类型桥接与应用服务协议

1. 决策和版本#

正式产品使用 cxx 生成 Rust/C++ 构建期桥接。应用、Rust 静态库和生成头必须来自同一提交和工具链组合；不允许替换为任意版本动态库。此接口面向产品内部，不是第三方二进制 SDK，也不是 06 的进程协议。

原型 lab_engine_new/lab_request/lab_string_free/lab_engine_free 及 JSON 请求继续作为实验代码保存；产品不能逐步往实验接口塞入密码、输出路径和插件操作后声称它已冻结。

以下表格定义概念类型与语义，不是可直接编译的 cxx::bridge 声明。实施阶段根据 cxx 允许的共享类型拆分结构，生成代码纳入构建而非手工编辑。禁止为性能方便引入未定义生命周期的裸指针。

M1 已落地独立双句柄、Open/Browse/Preflight/CloseSession/Snapshot、取消/关闭控制通道和 Qt mailbox。当前单会话、串行 GUI 请求；完整查询代际、TaskId、输出授权与扩展协议仍是后续目标。已实现签名、资源预算与故障语义见 M1 运行时契约，测试和开发包见 M1 验收入口。

2. 客户端和事件接收#

桥接创建两个独占句柄：CommandClient 和 EventReceiver。内部通过 Arc/有界通道引用同一个 Rust Runtime；C++ 以 RAII 包装拥有它们。

  • GUI 线程使用 CommandClient 提交短命令；入口不等待工作完成，不操作 QObject。
  • Qt 接收线程独占 EventReceiver，调用可阻塞 next_event()。运行时关闭/接收器关闭能立即唤醒，不靠长轮询。
  • 接收线程把事件转换成值对象，放入容量 256 的 C++ mailbox；对 GUI 最多保持一个使用明确 QueuedConnection 的“待处理事件”通知，不为每个 Rust 事件各排一个 Qt callback。GUI 在一轮中按批次/时间预算 drain，仍有数据时再安排一轮。QObject 销毁会取消对应通知，不用捕获悬空 this 的 lambda。
  • GUI 命令句柄和接收句柄不跨线程并发调用；Rust 内部共享状态经过类型和锁/通道保护。接口文档必须说明哪些对象 Send，不能只因底层用了 Arc 就推断全部线程安全。
  • 关闭时保留一个不受普通队列容量影响的控制信号；关闭接收器前明确是否继续 drain 终态，防止工作线程因满事件队列阻塞而无法 join。

3. 统一包络#

命令包络：RequestId、可选 SessionId/TaskId、命令种类和类型化参数。提交立即返回 Accepted 或 Rejected(Error)；Accepted 表示已入队，不表示操作成功。

被接受的普通请求最终产生一次 RequestFinished {request_id, outcome}。异步任务启动的 outcome 是 TaskId，任务终态另由 TaskUpdated 给出。取消/关闭控制具有独立准入通道，但仍带 RequestId。运行时崩溃时无法保证最终响应，Qt 连接断开会完成所有 pending 请求为 runtime_unavailable。

FetchPage 的内容只由 PageReady 携带一次，RequestFinished 引用页身份并结束 pending 请求；丢弃过期页面仍须结束对应请求。状态事件和请求完成不能重复创建任务或重复应用数据。

事件带 event_sequence；任务事件另有单调 task_sequence。页结果带完整查询身份。传输顺序不作为跨任务排序依据。一个 TaskId 收到终态后，不接纳更旧的 running/progress 事件。

普通请求入口最多 128 个 outstanding；page 请求重复合并，满时返回 busy。事件使用容量 256 的必达队列及按对象合并的进度槽。接收端慢时停止接纳普通请求、丢弃过期页/低优先级进度；工作任务不能在文件提交锁内等待 GUI。等待中的任务数量受任务队列限额约束，因此提示和终态占用也有上界。

C++ mailbox 同样合并进度并为控制/等待/终态保留容量；满时接收线程暂停读取普通事件，背压传回 Rust。仅限制 Rust 队列不能限制 Qt 的 queued-event 内存。调度器处理 cancel/shutdown 不阻塞在普通事件入队上，必要时停止新工作并保留有界 pending 控制结果；shutdown 期间 GUI 继续 drain，不能在 GUI 线程 join 一个仍等 mailbox 空位的接收线程。

6. 数据和所有权#

小 DTO 复制按值交付，字符串 UTF-8；原始非 Unicode 路径字节不直通 QML。页面条目仅有展示字段和 ID，完整属性另查。跨线程结果拥有自己的数据，不借用仍可能变化的索引缓冲。

大内容不通过桥接送到 QML；预览最多按配额获得有限缓冲或受控临时授权。cxx 的 Rust/C++ 容器由其对应类型正确析构，禁止使用 free/delete 处理 Rust 分配内存。秘密对象与普通 String DTO 分离，显式销毁/失效，尽可能使用零化容器。

Rust Result 在边界转换为结构化 Error，C++ 异常不跨回 Rust。入口校验所有数值窄化、枚举值、对象状态、长度和 handle 归属。无法恢复的 panic 按发行策略终止/报告，不用捕获 panic 来维护半完成事务。

8. 构建和迁移验证#

CMake 构建 Qt 应用，Cargo 构建 Rust 静态库和 cxx 生成产物。使用一个构建编排入口，明确目标 triple、Qt 架构、编译器、C++ 标准和生成头目录。不能用系统中碰巧存在的另一个 generated header。

首阶段验证 macOS arm64、Windows MSVC、Linux x86_64 的最小往返、Unicode、所有权、队列满、关闭过程中 pending 页、取消优先通道和 RuntimeFault。通过后再迁移原型分页模型。cxx 依赖版本锁定在验证提交；暂不在设计中虚构一个已通过测试的版本号。

WP-10 当前创建切片#

内部桥接增加 Create：输入路径数组、目标目录、ZIP 名称、Store／Deflate、1／6／9 级和重名策略。Qt 在 UTF-16→UTF-8 与整数窄化前拒绝非法值，Rust 再检查单路径 4 KiB、选择路径总量 4 MiB、条目数与便携文件名。CheckTarget 的 session=0 表示独立创建目标检查；非零会话仍绑定解压来源。

创建与解压共用后台任务身份、取消、提示 ID、事件预算与异步退出。TaskSnapshot 增加 creating、total_known，扫描未知总量不能伪装为零字节任务；Verifying 阶段不把再次读取的校验量计入已处理输入。创建只保存完整归档一次，输入条目不能提前计为已保存。字段、错误及整体提交语义见 WP-10 契约。

xdzip：06 格式适配与扩展 SDK

1. 两类扩展#

内置源码级扩展实现 Rust SDK，随产品构建，使用 Cargo feature 挑选后端。Rust 编译器 ABI 不稳定，不将它们做成任意版本可加载的 .so/.dylib/.dll。

进程级扩展实现版本化线协议，由 xdzip-plugin-host 适配为同一格式接口。外部扩展可以用 Rust、C++、Go 等语言编写，独立发布。线协议与 Qt 的 cxx 接口没有关系；外部进程永远不能创建 Qt 对象或弹出自己的密码窗口。

官方原生后端也可使用工作进程协议，以隔离内存错误；“官方”不免除输入检查。第三方发布在沙箱验证阶段前默认不可执行。

4. Rust SDK 契约#

概念接口：

CodecFactory.probe(ProbeSource, ProbeBudget) -> Detection
CodecFactory.open(ReadSource, OpenOptions, OperationContext) -> CodecSession
CodecSession.scan(MetadataSink, OperationContext) -> ScanReport
CodecSession.read_entry(EntryToken, OutputSink, OperationContext) -> ReadReport
CodecFactory.create(InputCatalog, ArchiveSink, WriteOptions, OperationContext) -> WriteReport

这是职责示意，不是已编译签名。实现阶段 trait 返回类型保留 Result，并显式标明 Send/并发要求。OperationContext 含取消、预算、进度和短期秘密访问，不能把全局应用服务/文件系统放进去。

ReadSource 只暴露读取、有限 seek 和已授权卷；OutputSink 只能写当前批准条目，不暴露目标路径。ArchiveSink 只能写新归档临时对象。适配器主动每个安全点检查取消；宿主计量实际字节并返回限额错误。适配器不能捕获错误后继续偷偷写。

普通解压 OutputSink 为顺序写；ArchiveSink 如需修订头部，可协商受限 seek/write，所有偏移及加法检查溢出，高水位文件长度和累计写入均受额度限制，不能以 seek 制造超额稀疏文件。无需 seek 的后端优先流式写。

扫描向 MetadataSink 输出原始路径、record token、大小、类型和属性；Sink 有批次和字段限额。后端声明的大小不作为配额可信输入。结束时返回完整性和扫描计数，不能只返回一个 bool。

如格式需再次 seek，同一个授权源仍受 SourceRevision 检测；如 TAR/固实块只能顺序解码，计划按物理顺序处理已选项并跳过无关内容，同时计量解码工作，不能承诺 O(1) 任意条目读取。

5. 插件包与 manifest#

当前源码编码切片已编译实现于 xdzip-codec-api::encode：CreationCodec::encode 接收 EncodeInput、EncodeOutput、EncodeSettings、取消令牌和处理字节回调。算法使用后端定义的 store／deflate 标识，ZIP 头的数值不成为通用格式接口。输入只提供不可变条目和按序号打开的读取流，输出只提供顺序 Write；没有目标路径、目录句柄或提交能力。ZIP 写入器与 Qt 无依赖关系。预算和写后逐项校验由 WP-10 宿主契约约束，外部进程协议仍未启用。

独立包包含 manifest、目标平台 executable、许可证、校验和、可选签名及能力 schema。manifest 至少包含 plugin_id、版本、作者、支持平台/架构、协议主版本范围、格式能力、入口、资源请求和来源。

入口是包内相对路径；禁止 ..、绝对路径、链接逃逸及 shell 命令字符串。宿主使用绝对可验证可执行文件及参数数组启动，不使用 sh -c。清理环境变量，不传应用凭据、代理密码、用户 PATH 扩展等。

6. 线协议 v1 草案#

传输为私有继承 IPC 管道；不监听 TCP，不创建公开端口。双向帧是 u32 little-endian 长度 + CBOR 对象。在分配前检查长度；每帧最大 1MiB，数据消息中 bytes 最大 256KiB。CBOR 深度最大 16，不允许无界长度、重复关键字段或未知必需消息种类。

包络为 {kind, request_id, operation_id, sequence, payload}。CBOR 使用固定字段键和类型；字段 schema 随协议包发布。首帧只允许 Hello，后端在 2 秒握手预算内声明版本，宿主选择共同主版本和协商能力。相同主版本新增可选字段允许忽略；未知枚举/必需字段不忽略；不兼容变化升级主版本。

交互 NeedSecret、NeedVolume、SupplySecret、SupplyVolume UI 由宿主呈现；秘密仅限对应操作
控制 Cancel、CancelAck、Ping/Pong、Shutdown 控制优先；收到 Ack 不等于任务已清理
结果 Progress、OperationFinished、Error sequence 单调；一次终态，不信任声称的字节/CRC

每个数据方向默认最多 4 个 256KiB 未确认块，信用耗尽时停止发送；控制消息不被数据信用阻塞。宿主验证 operation、句柄、范围和当前状态。超额/乱序/重复终态/非法状态转移关闭工作进程并令任务失败。

关键 payload 约束如下；整数使用无符号有界类型，字节字段使用 CBOR bytes，而非把原始路径强行转 UTF-8：

消息 必需字段及约束
Open source_token、options；token 绑定当前 operation 的授权源
EntryBatch session_token、entries；记录含 entry_token/raw_path/type/optional sizes，单批最多 128 且帧不超 1MiB
ReadEntry session_token、entry_token、approved_sink_token；不在当前计划内的条目不能获得 Sink
ReadAt source_token、offset:u64、length:u32；length ≤256KiB，范围不越授权源，EOF可短读
WriteData sink_token、block_sequence、bytes；只能按批准顺序/seek能力写，重复块拒绝
FinishOutput sink_token、reported_size、checksum_info；宿主使用实测字节和自身计量决定是否提交
OperationFinished outcome、counts、integrity_info；操作只允许一次终态，存在未完成 Sink 时不能声明成功

令牌不可复用到另一会话、任务或工作进程；取消撤销后不能继续 BeginOutput。Create 的输入目录只包含用户已授权输入的相对归档名和读取令牌，不允许扩展按本机路径自行增添文件。

宿主需要独立 stdout/stdin IPC 和有界 stderr 诊断；插件日志不能混入协议通道。诊断默认不记录秘密及完整路径，并对总量限流。宿主不能假定未知插件会自觉遵守日志隐私，因此插件启用说明必须涵盖其对用户内容和密码的接触。

宿主重新计量实际写入并计算可验证的校验值，但如果预期 CRC/摘要及解析结果也完全来自不可信插件，这不能独立证明内容忠实于原归档。沙箱保障的是权限边界，内容正确性仍依赖后端信任和互操作；需要更强保证时使用独立受信解析/校验，不宣称恶意插件可以被通用 broker 自动验证正确。

7. 文件权力与沙箱#

所有源、卷和输出由 broker 以操作令牌提供。默认不给第三方原始源路径或广泛目录句柄；只授权受限读范围和某个当前输出 Sink。密码算法需要明文秘密时，插件不可避免会接触该秘密；不能宣称宿主能让恶意解密插件永远看不到密码。

Windows 评估受限令牌/AppContainer、Job 对象和句柄白名单；Linux 评估 namespaces、seccomp、Landlock/挂载限制、cgroups；macOS 评估可支持发行方式下的沙箱 helper、entitlements 和 broker。每个平台都需实证禁止任意写、联网、派生逃逸和访问未授权文件。具体 API 可用性不由本设计假定。

无法实现/验证沙箱的构建禁用第三方执行；官方受信工作进程可以按发行政策单独允许，但界面不能标为“沙箱安全”。沙箱不保护同一授权归档的机密免受用户主动选择的恶意格式扩展读取，因此来源、权限与信任仍是必要条件。

8. 生命周期与失败#

每后端默认最多一个工作进程；每进程默认一个活动重任务。宿主监督内存、协议大小、响应和 CPU/无进展预算。无进展预算不能简单把“60 秒未完成”当崩溃；读取复杂块时结合心跳、字节/进度和用户取消判断。

取消后给后端 2 秒合作期限；未退出可终止工作进程。终止只释放未提交输出，不撤回已提交条目。后端崩溃不自动无限重试，同一输入连续崩溃隔离后端并提示。更新等待所有关联任务结束，旧包保留至引用归零。

9. 开源扩展开发流程#

开发者实现参考骨架 → 声明真实能力 → 运行 SDK conformance → 提交最小及对抗性样本 → 独立参考工具互操作 → 检查取消/配额/损坏 → 许可证/SBOM → 平台包验证。提供源码级 ZIP/TAR 样例和进程级只读示例，文档按接口定义生成。

Rust SDK 使用 SemVer，破坏 trait 变更升级 major；线协议另有 major/minor。协议冻结前须由两个独立实现完成互通，不能只测宿主与自己生成的同一份代码。支持窗口至少覆盖当前及上一受支持协议主版本，具体撤销周期在 v1.0 发布政策确定。

xdzip：07 文件安全、权限和输出事务

1. 威胁模型#

归档、文件名、大小、CRC、压缩数据、扩展元数据、恢复日志和第三方扩展均不可信。主要威胁包括路径逃逸、覆盖重要文件、链接攻击、解压炸弹、解析器内存错误、错误名称映射、部分写入伪装成功、密码泄漏及扩展越权。

可信边界是签名宿主、经过审查的平台文件层和用户授权。第三方代码不属于可信计算基。此设计不承诺抵御已控制同一用户账户或内核的攻击者；一个拥有同等权限并持续移动目录/读取内存的进程，不受普通文件权限防御。对不可信多人可写目标，默认要求改用用户私有子目录或拒绝安全覆盖模式。

2. 源和目标授权#

用户选择源/目标后由平台层打开并保存文件身份和句柄。授权绑定文件/目录对象，不只绑定展示字符串。SourceRef/TargetRef 仅在宿主内使用；扩展获得操作令牌。源只读，不自动请求全盘访问。读取其他分卷需先识别和获得用户授权，不能按归档提供的绝对路径寻找文件。

目标目录必须存在且有足够权限，或由宿主在已授权父目录内创建。工作目录使用安全随机名、排他创建和最小权限，不从归档名称生成可预测临时文件。所有输出和日志工作目录位于授权目标内，方便同卷提交；跨卷输出不能称为原子 rename。

3. 路径处理流水线#

  1. 保存原始路径与编码来源；去掉展示歧义不等于接受输出路径。
  2. 按格式规则解析分隔符，拒绝绝对路径、驱动器前缀、UNC、设备路径、NUL 和父级逃逸。
  3. 形成组件列表，拒绝空/非法组件和平台保留名；. 可按定义规范化，但不能先盲目删除 .. 再宣称安全。
  4. 建立平台候选输出名，检查组件长度、总路径、大小写和 Unicode 文件系统等价性。
  5. 检查同一计划内部的重复路径、文件/目录冲突及现有磁盘冲突。
  6. 用户决策后，在真正打开/提交时重新验证对象身份和类型，执行句柄相对 I/O。

Windows 特别处理 CON/NUL/COM1 等保留名、尾随空格/点、冒号 ADS、\\?\\/设备前缀和大小写碰撞。POSIX 允许的反斜杠/冒号也不能用一条通用字符串规则假设 Windows 可写。长路径支持按平台能力显式启用并测试。

规范化只用于碰撞分析和展示，不随意改变原始名。A.txt/a.txt、NFC/NFD 等价名、重复 ZIP 记录等生成冲突组。默认等待决定或跳过，不能以“最后一个覆盖前一个”为默认。改名策略保留可追踪映射，扩展不能修改映射。

4. 防链接和竞态#

POSIX 以目录句柄和 openat 类调用逐组件遍历，拒绝跟随符号链接；Linux 可在可用时使用 openat2 的 beneath/no-symlink 约束，但仍需其他平台后端。Windows 使用句柄相对/可验证打开、reparse point 检查及 file ID；不把 canonicalize + string starts_with 当安全算法。

输出不恢复符号链接、硬链接、junction、设备、FIFO、socket 或 setuid/setgid。已有目标若为链接/特殊对象则拒绝普通覆盖。所有暂存文件排他创建，句柄保留至提交；扫描与提交间的目标变化重新走冲突决策。

仅目录句柄不能保证其路径永远不被有权限者移动。平台层需定义“授权对象下”的语义，检测目标/父节点身份变化；普通多人可写树不满足安全覆盖要求时拒绝或转到私有新子目录。不得声称 O_NOFOLLOW 能单独消除全部目录移动竞态。

平台安全实现须以原生对抗测试验收：在检查和打开间置换链接、目录、大小写别名与 reparse point；不能用内存 mock 代替全部验证。

5. 按文件事务解压#

计划与授权检查
  -> 受控暂存文件
  -> 解码并计量实际字节
  -> 校验内容/认证/预期结构
  -> 检查取消及目标冲突
  -> 更新事务日志
  -> 原子发布单文件
  -> 记录已提交项
  -> 清理暂存

后端写入受限 Sink，宿主掌握暂存句柄；CRC/认证失败、配额、磁盘满和取消都不把当前半文件发布。缺少格式校验的文件可按后端能力完成，但摘要不声称已做不存在的 CRC。模式为普通安全读写位，时间戳在提交后尽力恢复，失败作为警告。

默认不覆盖：使用平台“目标不存在才发布”原语，不能先 exists 再普通 rename。用户允许覆盖时，重新检查目标是预期普通文件，使用同卷替换原语；不先删除旧文件。Windows 被其他程序打开或防病毒占用时可失败，提示重试，不转为非原子截断。平台不提供所需原语时返回能力/安全错误。

覆盖授权针对该映射路径，原子替换保证新内容整体出现，不天然提供“仅当目标 inode/内容从检查时完全不变才替换”的比较交换语义。普通平台原语无法排除检查后另一个程序的修改；对需要严格避免此类覆盖的场景，采用不覆盖/改名/新私有目录模式，或仅在平台确有可验证条件替换能力时开放。路径安全与并发编辑保护是两项不同保证。

目录和多个文件不是一次整体事务。失败/取消保留已提交项，并精确报告；清理不会删除这些项。首版不提供假想的一键回滚。未来“新目录整体发布”只能在不存在目标、同卷和支持目录原子 rename 的条件下作为独立模式。

6. 新建归档事务#

临时归档位于最终目标同目录，写完 footer/目录、flush、关闭及必要校验后，再执行目标不存在发布或用户批准替换。失败/取消保留原有归档；未发布临时归档删除或登记可恢复遗留。不能把“写完最后一个文件”当归档已经可用。

发布可见原子性和断电持久性不同。启用 durable 模式时按平台能力同步文件与目录/事务记录；默认至少保证不发布半成品，不宣称所有磁盘/网络文件系统都能抵御断电。网络盘和不支持原语的文件系统明确降级或拒绝相应模式，并纳入测试。

7. 配额和归档炸弹#

宿主在实际写入处计量，不相信归档声明。初始限额见 常量：单文件 8GiB、任务 20GiB、扫描条目 100 万、单字段 64KiB、格式组合 4 层。超限在当前文件发布前停止；用户提高限额需重新规划并检查剩余空间，不用一个对话框无限自动放行。

压缩比大于 1000:1 产生风险提示，但绝对实际字节、索引数量、解码内存和工作预算才是硬保护。零压缩长度、未知大小和格式欺骗不能绕过计量。高压缩比合法内容可以经用户明确提高相应策略处理。

固实/流式归档即使只选一个小项也可能解码大量前置内容，计量“解码字节”和“输出字节”分别显示。CPU/时间限制以取消和工作进程监督实施；原生阻塞解析无法合作取消时需要隔离，不能靠 UI 进度停止表示工作已停止。

8. 预览和外部打开#

预览仅显式触发：文本上限 1MiB，图像压缩内容上限 20MiB且解码像素上限 40MP，须在读取头后、分配像素前检查。图像解码库也处理不可信数据，应审计并考虑隔离。外部临时打开上限默认 100MiB；超出需明确操作，不自动全包展开。

私有临时目录排他创建；文件不赋执行位，不跟随链接，不继承危险 xattr/ADS。用户确认后调用系统关联应用，不执行 shell。不渲染活动 HTML/SVG 脚本/宏。macOS 不主动剥离已有 quarantine，Windows 不主动清除已有下载标记；新的标记传播由平台验证，不声称同一规则适用于全部格式。

临时文件可能被外部应用占用，无法删除时登记期限并下次清理。只清理本应用创建且身份验证通过的工作目录，不用一个宽泛路径通配符递归删除。

9. 密码、内容和日志#

秘密限会话/任务阶段生存，默认不写磁盘；使用可零化缓冲，减少字符串复制，不通过普通事件/错误/trace 传递。操作系统输入法、GUI 内部缓存和后端复制可能留下残留，因此只承诺合理的最小化和清理策略。

日志默认含版本、匿名 ID、错误码、阶段、计数和耗时。不含文件内容、密码、完整路径、归档注释或任意插件原文。用户导出详细诊断时预览内容并本地保存，上传需另行显式行为；产品不自带默认遥测。

10. 异常终止与恢复#

启动时发现工作目录，先验证目录所属、随机任务标识、文件身份、日志版本和授权可用性。日志视为不可信：路径仍要通过相同安全验证。状态无法确定时显示待处理遗留，不自动重新解压/覆盖。

prepared 但未发布文件可安全删除；发布已发生而日志终态未写入时检查目标身份/校验记录，标为“可能已完成，请确认”，不能简单删目标。旧文件替换后的恢复不承诺还原旧内容。清理权限不足产生可操作提示。

11. 安全测试门槛#

路径逃逸、链接/reparse 竞态、目录别名碰撞、重复记录、ZIP64、未知大小、CRC/认证错误、磁盘满、无空间日志、目标变化、进程 kill、恢复日志损坏、插件超长帧和拒绝取消均为发布阻断用例。所有安全失败要验证目标外文件无变化和当前半文件未发布，而非仅断言返回了错误码。

xdzip：08 任务状态、资源准入和并发

1. 状态机#

Task 在 StartPlan 接受后创建。操作计划不是任务；准备计划本身作为可取消后台请求处理。

终态不可逆，终态事件只发一次；内部状态转换和 outcome 在调度器串行决定。CleaningUp 可由成功、失败或取消进入，它保存最终意图，不自行改成成功。清理失败附带遗留警告；如果数据已全部正确提交，不把“临时目录未删”混同为内容损坏。

TaskPhase 进一步表示扫描/准备输入/解码/写入/校验/发布/清理。状态和阶段不同：Running+Verifying 不需要额外制造几十个顶级状态。

2. 进度#

记录已处理输入、实际解码字节、实际输出字节、完成/跳过/失败项、当前阶段及总量可信度。未知总量显示不定进度和已处理数量，不把估算百分比宣传成精确完成度。校验、固实块跳读和发布均可能改变耗时分布。

任务对外进度合并频率初始为 10Hz，后台高频计数用原子/局部累加；等待用户、取消反馈和终态即时投递。剩余时间在至少数秒稳定吞吐后才估算，阶段变化时重置；默认不展示高波动数字。

单文件之间高频 Running/Committing 转换可与进度合并，不要求每个瞬态都穿过 GUI；等待用户、取消反馈和终态即时。核心仍逐次维护完整状态机，合并只影响展示，不能省略提交许可或终态判断。

3. 准入和线程预算#

预算为资源准入及监控政策，进程内库的内存估算不是 OS 硬限额。不能审计并限制分配的原生/第三方后端必须使用工作进程，再加平台硬限制。用户可选择更低资源模式；高字典后端需声明预计内存并在启动前检查。

任务根据 CPU、内存、源读取模式和目标范围联合准入，不能先拿 CPU 再永久等待目标锁。按统一顺序获取 lease，无法获得全部就退回队列。读取查询/GUI请求单独保留轻量执行容量，避免两个压缩任务占满后搜索完全停顿。

4. 公平和优先级#

取消/关闭 > 交互页与提示决定 > 当前会话查询 > 任务调度 > 扫描与预取。优先级不允许长期饿死后台任务，使用有限 burst 和队列等待加权。预取可丢弃，用户已经明确请求的操作应给出结果或取消。

对同源 ZIP 的读并发取后端限制与全局预算较小者；TAR/固实块通常顺序处理。SSD/NVMe 可不同于机械盘和网络盘，但首版不自动猜测硬件后开无限并发。性能数据决定是否增加块级流水线。

5. 取消线性化#

CancelTask 是请求停止，不是函数返回时已停止。调度器登记取消 token 并立即回报 accepted；工作项在读取块、写入块、条目切换、等待用户和发布前检查。等待 I/O 使用可取消/有超时策略；无法打断的系统调用要在 UI 中明确显示正在收尾。

取消和提交并发时以一个提交许可/状态门控制：取得提交许可后，短原子发布完成再响应取消；未取得许可的当前临时文件清理。已发布项不可无条件删除。最后一项提交及成功终态已线性化后收到取消，返回“已完成”，不把任务改为 Cancelled。

工作进程 2 秒合作期限后允许终止；先撤销新写信用和后续授权，终止后回收未提交 Sink。进程内不可合作的库不能依靠 kill 一个线程解决；应隔离或不宣称满足取消预算。

取消终态需等待工作停止、提交许可释放和清理结果确定。UI 不得仅收到 CancelAck 就显示“取消完成”。取消后重新启动创建新 TaskId 和新的有效计划。

6. 等待用户和暂停#

冲突/秘密/卷/配额触发 WaitingForUser。释放不必要 CPU token，不持有文件系统互斥锁等待对话框；保留受限临时对象及必要资源，并计入等待预算。用户决定携带 PromptId，过期重复决定无效。

配额提示只用于准备阶段的风险/估算决策。运行中达到硬输出配额时丢弃当前暂存项并停止为 Failed；提高限额需生成新计划/任务，不能在原不可变计划内静默扩额后继续。

MVP 不提供通用暂停按钮。可靠暂停需要后端可检查点、源版本和持久化状态，不能用“暂停界面计时”假装暂停 codec。后续只对声明 safe-point pause 的后端开放，且暂停仍占用的资源必须说明。

7. 失败策略#

默认遇内容/结构、安全、权限或配额错误停止任务。用户可在计划中选择“跳过允许的单项错误继续”，限于明确错误类别；路径逃逸、协议错误、源变化和全局磁盘满不被宽泛忽略。

失败摘要保存分页结果和有限错误样例。“重试失败项”重新获取授权、检查源版本并生成新计划，不复用可能过期的写句柄。插件连续崩溃有熔断，无自动无限重试。

8. 应用关闭#

关闭窗口与退出应用分开。任务运行时，退出对话框列出继续等待/取消并退出；后台驻留不是首版默认行为。用户选择取消后停止新命令，唤醒等待提示，取消任务，回收工作进程和事件接收线程。

软等待期限初始 5 秒。超过后保留“正在安全收尾”信息，可继续等待或强制退出。强制退出说明可能保留暂存和部分结果，下次启动执行恢复检查。shutdown 控制不能被满队列或阻塞 GUI join 卡死。

9. 并发验证#

模型化验证状态转移、cancel/commit 竞争、关标签页/任务独立生存、事件乱序、满队列 shutdown、重复启动、资源回收和两任务重叠目标。测试通过同步屏障和故障点驱动，避免只依赖任意 sleep。必要时对小范围共享状态采用 Loom 等工具，不能把整个 Qt 应用塞进并发模型测试。

WP-10 创建任务#

创建任务沿用单重任务线程和有界任务 mailbox，不在 GUI 递归扫描输入。冻结输入树后报告已知总量，顺序编码并写入私有暂存，完成后逐条重新解码校验，再取得整体提交许可。普通状态快照合并至约 100 ms，冲突和终态保留；取消与关闭沿用现有控制通道。整体保存后的输入文件数与源字节数才进入 committed 计数；written 表示实际 ZIP 输出字节。阶段、预算与失败行为见 实现契约。

xdzip：09 性能设计与基准

1. 指标边界#

性能目标是用户可感知的打开/查询延迟、真实吞吐、低空闲开销、可控任务峰值和完整分发体积。Rust 并不自动保证这些指标，Qt 也不能由一台 Linux 云环境推出所有 Mac 表现。

现有证据：Qt 6.8.2 Linux 软件渲染原型启动准备标记 P50 158ms、峰值 PSS 中位数 81.9MiB、预热 Home/End 参考像素匹配 P50 15.3ms；只含 C++ 程序和 Rust 库的 0.80MiB 不含 Qt。该原型使用十万条固定数据及模拟任务。既不是生产基线，也不是冷缓存、真实解压或物理显示器延迟。

3. 内存模型#

总占用 = Qt/字体/GPU + 热元数据 + 查询索引 + 页缓存 + 活跃任务(字典+流缓冲) + 工作进程 + 暂存管理。

优化优先级：不要创建十万个 GUI 对象；不要重复复制路径；不要一次传所有条目；限制 query snapshot 和结果页；减少后端内部线程/字典；最后才考虑不必要的 unsafe 或自定义 allocator。

元数据使用紧凑记录和字符串池/共享缓冲；原始路径和展示路径按需分开。索引热数据预算默认 128MiB，64MiB 时准备转入磁盘后端；迁移本身有峰值预算，不先复制完整索引两份。大型搜索/排序外部化或给出明确资源错误，不能 OOM 后才提示。

面向未来大索引的 Qt 页缓存目标为最多 1024 行，传输页默认 128。当前只读 ZIP 的扫描上限为 10,000 条，采用有界完整查询模型以支持无分页浏览；128 条批次按序传输后原子提交，delegate 数仍按 viewport 实测。提高扫描上限前必须改为保留完整逻辑行数的按需模型，不能直接扩大 GUI 缓存。查询最多保留当前快照及已被计划/任务引用的必要旧快照；用户连续搜索有取消和回收。失败结果写有界分页结果存储，不把所有错误字符串堆进 UI。

4. 吞吐和 I/O#

先选高质量成熟 codec，避免为“快”自写 ZIP/Deflate。流缓冲初始 256KiB，测试 64/256/1024KiB；复用缓冲但不能把含秘密缓冲放回普通池。文件读取、解码和输出校验可流水线，但 credit/队列有上限。

ZIP 按独立项并行需要评估源 seek 和目标文件数；TAR/固实 7z 通常顺序解码。小文件工作负载瓶颈可能是创建/同步/日志，不是压缩算法。durable 模式、磁盘缓存及安全校验成本在报告中单独标注，不为了好看关闭默认安全。

后端内部线程参与全局预算。创建模式的“更小”可能更慢/高内存，UI 显示提示。第三方 broker 复制的额外成本先实测；只有受控共享内存的所有权、边界和复用证明齐全后，才替换普通块传输。

常规 CI 跑功能和粗资源上限；每夜/发布前参考机跑全套。优化 PR 附原始数据和适用范围，说明是否改变算法、压缩结果或磁盘持久性。

xdzip：10 编码规范、注释和质量工程

1. 总原则#

以明确的数据所有权、小而有语义的接口、可预测资源使用和可验证行为为主。可读性不等于把所有代码抽象成框架；性能不等于默认 unsafe。优化有测量证据，复杂边界有测试与注释。

业务状态只在一个位置决定，错误不吞掉，外部输入不使用 panic 处理。跨语言、文件、并发、加密和解析边界比普通 UI 文案需要更严格审查。格式贡献者不能通过新增一个适配器改变默认安全政策。

2. Rust 规范#

  • workspace 统一 edition、工具链、lints 和依赖；发行版锁 Cargo.lock。新增 crate 明确职责和依赖方向。
  • 使用 rustfmt，Clippy 按发布验证目标无警告。allow 必须局部且说明原因，不能全局关闭索引/错误相关 lint。
  • 公共 API 有 rustdoc，说明参数、返回、错误、资源所有权、线程要求和重要复杂度。内部明显 getter 不写重复注释。
  • 外部数量/偏移使用 checked arithmetic 和 checked conversion；ID 使用 newtype，不让 SessionId 和 TaskId 混用。
  • 生产关键路径禁止无依据的 unwrap/expect；不变量可以局部 expect，但需解释不变量来源并覆盖测试。测试代码可用 unwrap 使失败直接可读。
  • Option 表示未知，Result 表示失败；不以空列表、0 或空字符串掩盖损坏。领域错误不依赖 UI 文案。
  • 默认禁止 unsafe；平台 I/O/FFI 的必要 unsafe 放在小模块，逐块写 SAFETY，注明指针、长度、别名、生命周期和线程前提。
  • 不跨 await/阻塞 I/O 持有普通锁；关键区短且顺序一致。公共类型不盲目实现 Clone/Send/Sync。
  • 用借用、Arc 不可变数据和批处理减少复制；普通循环通常优于难读的多层 iterator 组合。数据大小明确后才考虑结构布局和缓存优化。

注释示例（接口示意，尚未实现）：

/// 将已校验的暂存文件发布为计划中的目标。
///
/// 调用者必须持有提交许可；取消只能在发布前或发布后生效。
/// 目标变化返回 Conflict，不删除原目标，也不重试成截断写入。
/// 成功后所有权转为已提交项，清理流程不得再次删除它。
fn publish_verified_file(/* typed parameters */) -> Result<CommitReceipt, CommitError>;

有意义的内部注释解释“为什么需要提交许可”或“为什么不能根据归档大小分配缓冲”，不写“这里增加计数器”这类复述。

3. C++/Qt 规范#

C++17、RAII、clang-format、显式 ownership。Qt QObject 父子管理和智能指针只能选定一致的所有权方案，避免一个对象同时被 parent 和 unique_ptr 删除。模型对象只在 GUI 线程更新，工作结果用值对象跨线程。

Qt connect 明确接收 context 和连接类型，避免捕获可能失效的裸 this；QPointer 只辅助生存检测，不作为跨线程竞态的万能锁。析构不执行无限 join，shutdown 协议先唤醒接收线程。

不在 C++ 中复制 Rust 的路径、配额和格式逻辑。不把所有请求挤进一个处理任意 JSON 的巨型函数。窄化到 int/qsizetype 前验证长度，原始字节不通过 QString 有损转换后再当文件名使用。

使用 clang-tidy 的选定规则集，并对 FFI 生成代码排除自动修复。异常边界、Qt 非异常路径与 Rust Result 在桥接处统一，异常不穿越 Rust。

4. QML 规范#

组件按职责和语义命名；必须属性使用 required property，明确角色类型。视觉 token 集中，状态使用声明式绑定。禁止在 onChanged 中形成循环写属性，禁止每帧调用业务接口。

列表 delegate 不读取磁盘、不解析归档、不拼 HTML、不在 component completed 中为每行启动 timer。业务动作通过控制器，长计算离开 GUI 线程。使用 qmllint、格式化工具和 QML 测试；Qt 版本不同可能影响 lint，工具与运行库一起锁定。

所有可见字符串走翻译，含数量的字符串使用复数规则。字段、时间、字节按用户 locale 显示；原始协议值不随 locale 改变。

ADR-001：Qt Quick 作为唯一产品界面#

状态：Accepted。

背景：产品要求现代桌面 UI、统一体验和低占用；已完成 Slint、Tauri、Qt Quick 的同核心原型。结合界面能力、统一体验与现有 Linux 软件渲染数据，项目选定 Qt Quick 进入产品阶段；其他平台表现仍需验证。

决定：Qt Quick/QML + Qt Quick Controls 2，C++ 薄适配。Slint/Tauri 作为历史实验保留，不打包进产品。

代价：承担 Qt 运行库、QML 模块、跨语言构建和许可工作；Mac/Windows 输入、无障碍、GPU 和部署必须补测。不能把 0.80MiB 原型程序当 Qt 完整安装包。

重新评估触发：Qt 目标平台无法满足必要功能/许可/安全维护，且经过实际优化仍无法达到核心产品预算。普通性能波动不触发重复框架选型。

ADR-002：Rust 持有全部归档业务#

状态：Accepted。

决定：领域、索引、计划、任务、配额、路径策略和格式注册表在 Rust；Qt 只表示状态、授权系统文件选择和用户决定。业务测试不需 Qt。

替代方案：把 libarchive/7zip 直接接到 C++/QML，或在每个 UI 中重复控制逻辑。代价是核心与平台 UI 耦合，无法一致验证安全/取消。Rust 也不免除原生库安全风险，相关库可工作进程隔离。

重新评估触发：某个平台 API 无法在 Rust 可靠实现时，允许小型平台 C++ port，不改变业务所有权。

ADR-003：构建期 cxx 桥接#

状态：Accepted，集成需 M1 验证。

决定：产品内部用 cxx 生成的类型安全桥接，同提交构建；不维护长期手写 C ABI，不在热点路径 JSON 序列化。桥接不含 Qt 业务。

替代方案：沿用实验 C ABI、使用 CXX-Qt 自动生成 QObject、通过本地 IPC 连接 GUI 和整个核心。cxx 保留明确的 Qt 模型和线程边界，避免首阶段依赖额外 QObject 生成框架；代价是自行维护薄 QObject 层和 CMake/Cargo 编排。

不承诺：cxx 不提供跨任意 Rust/Qt 版本的动态二进制兼容，也不生成第三方格式协议。

重新评估触发：M1 三平台构建/生命周期验证失败，或适配层明显膨胀。届时以 ADR 评估 CXX-Qt 或显式版本化 C ABI，不默默切换。

ADR-004：内置源码 SDK 与外部进程协议分离#

状态：Accepted，线协议为草案。

决定：内置格式使用 Rust trait 和 Cargo features；外部插件使用有界 CBOR IPC。两者由宿主统一能力和 I/O 端口。

原因：Rust 动态库 ABI 不稳定；任意进程内原生插件破坏崩溃隔离和资源治理。采用 Wasm 作为通用格式运行时暂不优先，原因是现有原生 codec 迁移、线程、seek 和性能验证成本，不否认其未来用途。

代价：协议、broker、沙箱和 IPC 开销。协议需两个独立实现互通后冻结。

ADR-005：宿主集中控制真实文件写入#

状态：Accepted。

决定：后端只写被批准的 OutputSink，真实路径、冲突、暂存和提交由宿主控制。禁止直接调用库的通用 unpack 到任意目录，除非完整验证其端口已受宿主约束。

原因：各格式重复实现路径保护很容易出现差异；仅检查字符串无法阻止链接/竞态。代价是自己实现三个平台文件安全层和故障测试。

不承诺：宿主能证明恶意插件输出内容语义正确，或阻止同用户已被控制的恶意进程。插件信任和权限仍需明确。

ADR-006：按文件提交解压，整体提交新建归档#

状态：Accepted。

决定：解压各文件先暂存校验再发布，任务失败可保留部分完成；新归档整体写完再发布。默认不覆盖。

原因：合并进现有目录无法跨平台简单提供真正全目录原子事务；假装全任务回滚会误删用户后续修改。代价是详细结果和恢复日志，取消语义需要讲清。

重新评估触发：新增“全新目录整体发布”模式，可在受限条件下独立实现，不改变已有目录合并语义。

ADR-007：有界 actor/工作池和事件推送#

状态：Accepted。

决定：轻量调度器决定状态，有界池执行工作；Qt 独立事件接收线程，进度合并、终态必达；取消和 shutdown 有独立控制准入。

替代方案：GUI 同步调用、每文件一个线程、无限 Tokio/spawn_blocking、常驻轮询。归档主要是同步 CPU/I/O，不因“异步”字样引入无限任务；未来真正网络 I/O 可局部使用异步运行时。

代价：明确背压、关闭和资源 lease；收益是空闲低占用、不会被任务淹没 GUI。

ADR-008：能力驱动，首版限制格式#

状态：Accepted。

决定：v0.1 ZIP Store/Deflate 和 TAR/GZIP；加密、分卷、RAR、7z 与额外算法逐项验证。UI 不按后缀推断完整支持。

原因：格式名称不能描述所有实际特性。代价是首版格式表较短，收益是对用户诚实且可验证。

ADR-009：小型产品数据与用户内容分离#

状态：Accepted。

决定：设置、临时索引、事务日志和扩展清单分生命周期管理。默认无遥测、不持久密码、不跨启动缓存归档索引。

代价：多种 schema 和清理规则。重新评估跨启动索引时需新增源身份、失效、隐私与容量设计。

ADR-010：完整分发和许可进入架构门槛#

状态：Accepted。

决定：Qt 默认动态部署，准确模块许可审查；安装体积包含运行库；签名、SBOM、替换/源码义务进入发布检查。

替代方案：只比较 executable 或发布前才补 LICENSE。它们不能证明产品小或可合法分发。

代价：部署和许可持续维护。Qt 静态构建或商店发行需单独 ADR 与许可审查，不能由 size 优化 PR 顺手改变。

3. 代表性端到端场景#

  1. 普通 ZIP：拖入 → 显示目录 → 中文查询 → 范围多选 → 选新目录 → 解压 → 内容与参考一致。
  2. 搜索范围：过滤后无选择 → “全部解压”仍是整个归档；“解压搜索结果”单独显示范围并固定快照。
  3. 重复/碰撞名：两个记录映射同名 → 宿主提示 → 改名/跳过后结果可追踪，没有最后一项偷偷覆盖。
  4. 取消提交：提交屏障前取消不发布当前项；屏障后取消保留已提交项；终态只出现一次。
  5. 恶意路径：包含 ../、绝对名、ADS、链接和 reparse 替换 → 全部按平台政策拒绝，授权目录外无变化。
  6. 源变化：索引后修改源文件 → 启动/读取检测失效 → 停止并说明需重开，没有“成功”摘要。
  7. 新建覆盖旧归档：写入中磁盘满/取消 → 旧归档校验不变，临时遗留可定位清理。
  8. 工作进程失控：乱序帧、超长帧、拒绝取消或越权读写 → 终止扩展，宿主可继续处理其他会话。
  9. 异常终止：发布前/后注入 kill → 下次恢复不自动覆盖或删用户文件，状态不确定时明确提示。

1. 术语#

术语 定义

编解码器/Codec 识别、扫描、读取或创建格式的实现

计划/OperationPlan 已固定范围、目标、能力、参数和策略的操作描述
任务/Task 执行一个计划的生命周期和结果
授权/Grant 宿主持有的文件/目录访问权，不是路径字符串
Sink 受计量、限额和事务控制的写接口
工作进程/Worker 独立进程；只有实施了权限限制才能称受沙箱约束
提交/Commit 将已校验暂存内容发布为最终文件的安全点

2. 单位和数值#

内存/文件量使用二进制 KiB/MiB/GiB，1MiB=1024² bytes；传输和计量保留整数 bytes。时间使用 ms 或 s，事件时间来自单调时钟，用户文件时间使用携带精度/来源的日历时间。吞吐统一 MiB/s 并说明压缩输入、解码或输出哪一种字节。

单核计 CPU 100% 表示占满一个逻辑核心，进程树可超过 100%。PSS/RSS/USS/physical footprint 不互相等同。下载压缩体积、安装体积、executable 大小分别记录。

4. 状态标准名称#

5. 版本规则#
