# 平台窗口与标题栏规范

[English](../../ux/platform-windows.md) | 简体中文 | [繁體中文（台灣）](../../zh-TW/ux/platform-windows.md) | [日本語](../../ja-JP/ux/platform-windows.md) | [한국어](../../ko-KR/ux/platform-windows.md) | [Français](../../fr-FR/ux/platform-windows.md) | [Deutsch](../../de-DE/ux/platform-windows.md) | [Español](../../es-ES/ux/platform-windows.md) | [Português (Brasil)](../../pt-BR/ux/platform-windows.md) | [Русский](../../ru-RU/ux/platform-windows.md)

xdzip 的操作界面使用独立顶层窗口，不使用附着主窗口的 sheet 或在主窗口内部绘制的遮罩面板。独立窗口不等于独立进程，也不要求每个辅助窗口占一个任务栏入口。下拉菜单、工具提示保持轻量 Popup，不属于操作窗口。

## 窗口契约

| 窗口 | 与主窗口的关系 | 关闭 / Escape | 最小化 / 最大化 |
| --- | --- | --- | --- |
| 解压或创建表单 | 非模态 `OperationWindow`，从浏览入口打开时从属于调用窗口 | 关闭草稿或确认窗口，不提交新任务 | 禁用／禁用 |
| 任务重名提示 | 从属于操作宿主的非模态提示，任务等待决定 | 关闭提示后可从任务入口重开，也可在任务窗口明确取消任务 | 禁用／禁用 |
| 密码、退出或重启提示 | 应用模态，原生文件选择器同样为应用模态并从属于调用窗口 | 密码、退出和重启各有明确的关闭或确认动作 | 由原生对话框能力决定 |
| 任务进度和结果 | 非模态 `TaskWindow`，无其他模态窗口时可继续浏览 | 关闭详情后可从任务入口重开。独立操作会保留活动任务的入口 | 允许最小化／禁用最大化 |
| 设置和关于 | 非模态，从托盘打开时可以没有浏览窗口所有者 | 关闭视图，已保存的设置继续生效 | 禁用／禁用 |

取消任务是明确的任务命令，独立于关闭进度窗口。任务在后台结束时，不抢夺前台焦点；详情已打开时更新结果，否则更新任务入口。应用退出仍按任务退出策略处理，不能把主窗口关闭直接映射为辅助窗口关闭。

## 平台外观

- macOS：使用系统装饰标题栏，红黄绿控件位于左上角；不以自绘彩色圆点替代原生控件。固定尺寸操作窗保留红色关闭，禁用不可用的最小化、缩放按钮；进度窗允许收起。实际按钮可用状态由 AppKit/Qt 的窗口能力共同决定，并在真机验收。主窗口保持正常缩放、最小化及全屏能力。
- Windows 主窗口将标题区延伸进客户区，窗口按钮由 QML 绘制，保留可缩放的原生边框和 DWM 阴影。拖动、边缘缩放和系统贴靠由平台处理。独立操作窗保留系统装饰。见 [Windows 主窗口稿](../../../design/hifi/sources/main.html?platform=windows)。
- Ubuntu X11 主窗口使用右侧内嵌按钮，普通状态显示圆角边框。开启合成且支持输入区域整形时，还会显示可点击穿透的柔和阴影。最大化和全屏使用直角，铺满可用区域。移动和缩放由窗口系统处理。独立操作窗保留系统装饰，非自绘 X11 路径使用普通装饰。Wayland 不在支持范围内。见 [Ubuntu 主窗口稿](../../../design/hifi/sources/main.html?platform=linux)。

操作窗口各自有标题、边框、阴影和可拖动标题栏；背后的主窗口不加网页式变暗或模糊。初次打开居中于所属窗口所在显示器的可用区域；恢复位置必须夹取到可见屏幕内。标题栏不能被工具栏或内容覆盖。

## Qt Quick 实现约束

`OperationWindow` 是独立的 `Window`，可指定 `transientParent`，默认使用 `Qt.NonModal`。`PasswordWindow` 和 `OperationConfirmationWindow` 显式使用 `Qt.ApplicationModal`。原生选择器以实际调用窗口为所有者，只在该窗口仍可见时恢复其激活状态。见[窗口登记](../../../specs/visual/window-registry.json)与[任务窗口](task-windows.md)。

Windows/Linux 自绘标题栏需要真正的平台窗口移动、调整尺寸和系统菜单支持，不以 QML 手动修改位置模拟系统拖动。`WindowController` 负责窗口生命周期、所有权、关闭请求和任务视图重开；任务由核心持有，销毁视图不能销毁正在执行的任务。窗口状态跨线程只通过已定义桥接事件更新。

## 原型证据与限制

HTML 原型模拟独立窗口外观、标题栏拖动、阻塞或非阻塞交互及关闭语义。顶部“平台”选择器用于对照 macOS、Windows、Linux；不属于产品设置。浏览器 `dialog` 仍在同一浏览器页面内，不能提供真正的原生窗口、系统按钮、系统最小化、任务栏或多显示器行为。收起任务窗口通过隐藏详情模拟。

原型主窗口的平台控制区为外观示意；覆盖确认返回新建时仍重置示例表单，正式实现必须保留草稿。这些限制不能作为完成原生验收的证据。

## 实机验收门槛

1. 各操作窗是独立平台窗口，正确关联主窗口；不生成 sheet，无网页式遮罩。
2. 红绿灯/右侧按钮的顺序、禁用状态、关闭请求符合平台和窗口能力；标题与系统按钮在不同字体、缩放下不重叠。
3. 窗口拖动、屏幕边界、多显示器、125%/150%/200% 缩放，以及深浅主题正常。
4. 关闭任务详情后任务继续，任务入口可以重开。关闭重名窗口后任务继续等待，直到用户重开提示作出决定或明确取消任务。
5. 所属窗口的模态限制、焦点恢复、键盘导航、读屏标题与系统快捷键有效；其他压缩包窗口不被无故阻塞。
6. Windows 系统菜单／贴靠和 Linux X11 分别验证；Wayland 不在首批支持范围。既有 Qt 实机结论见 [WP-12 #5](https://github.com/xiaodaozhi/xdzip/issues/5)，本清单用于后续受影响项复验，不重置已完成验收。
