# 按需桌面验证

桌面验证按本次变更选择，不要求每次提交、合并或生成候选时填写固定的三平台人工验收表。执行者优先运行相关自动测试，并在可用环境中操作实际应用、检查实际窗口或截图。无对应设备、系统或桌面权限时，记录未执行的范围和原因；不能把离屏、合成输入或虚拟屏幕的结果写成真人或物理设备通过。

按[验收范围、证据和收口](README.md#验收范围证据和收口)先确定必要场景。实际窗口检查、截图、事件断言和录像各有证据边界，不互相冒充；录像不是桌面验收的默认步骤。足以验证已要求的场景并记录限制后停止，不因历史评论或执行者个人偏好追加固定人工矩阵。用户或适用规范明确要求的场景仍须执行，不以缩短流程为由跳过。

## 选择检查

| 改动涉及 | 可按需检查的实际场景 |
| --- | --- |
| 界面布局和样式 | 实际窗口和菜单、浅深主题、双语与字号，窗口装饰及系统缩放。QML 窗口的自动契约、共享控件和双语多字号布局检查仍在提交前执行。 |
| 系统交互 | 文件选择器的确认与取消、文件管理器拖放、窗口归属及文件关联。 |
| 输入与辅助功能 | 输入法预编辑、键盘焦点和真实读屏。单选、复选控件的 Qt 辅助功能动作和选择模型使用自动回归核对。 |
| 安装、更新与性能 | 使用自有测试数据按改动范围检查安装或更新；性能问题使用可复现工作负载和实际测量。完整安装生命周期及三平台检查可使用按需工作流。 |

仅观察应用自有窗口和自有测试文件；不上传密码、用户归档或完整私人路径。实际结果和限制记录在对应 issue，截图与日志放在 `build/`、`dist/` 或临时 Actions 工件，不提交源码。

## 可选工具

- [Windows 原生视觉诊断](../../../.github/workflows/windows-native-visual.yml)在一次性 hosted runner 自动采集自有窗口；它不需要维护者逐项点击，也不代表物理显示器验证。
- 原生菜单诊断可在合适的 Windows 桌面运行 `scripts/check-windows-menu-launcher.ps1`；采样细节和阈值见 [menu-qa-contract.json](../../../tests/fixtures/native/menu-qa-contract.json)。无需为无关修改重复完整采样。
- `scripts/prepare-private-test.py` 和 `scripts/private-test-matrix.json` 保留为自愿使用的历史记录工具；普通 CI、按需 Qt 检查和发行构建均不自动生成或要求填写该表。

既有已完成的桌面验收保留在对应 issue，不因工作流调整而重新执行。发布时按[发布协议](../engineering/release-protocol.md)说明实际验证和已知限制，许可复核与发行决定仍分别处理。
