## 从原型到产品

早期试验用模拟归档列表与任务比较界面框架，最终选择 Qt Quick。正式应用使用类型化的 cxx 桥接，执行实际归档操作和文件读写。原型使用的 JSON/C ABI 与夹具有助于理解当时的选型，未作为对外集成接口。[架构决策](architecture-decisions.md)

产品沿用有限的模型缓存、查询代次检查及无障碍控件等设计原则，并加入真实条目身份、格式能力判断、安全文件授权及经校验的输出提交。[系统架构](system-architecture.md)说明这些能力在当前代码中的位置。

## 当前能力和实验边界

| 领域 | 当前边界 |
| --- | --- |
| 桌面与命令行 | Qt Quick 桌面和独立 Rust CLI 共用运行时行为。 |
| 大归档 | 内存和磁盘索引位于运行时，大型 ZIP 索引的选择解压与整包操作有各自限制。 |
| 格式 | 内置路由以[格式注册表](../engineering/format-registry.md)为准。支持某格式需要实际实现及验证依据。 |
| 扩展 | [只读 SDK 试验](../engineering/sdk-trial.md)使用单独协议与宿主。当前产品构建禁用第三方扩展。 |

当前源码能力见[格式支持表](../../../README.zh-CN.md#格式支持)。发布包可查阅对应版本的发布说明。
