# 文件授权与安全写出

[English](../../design/file-security.md) | 简体中文 | [繁體中文（台灣）](../../zh-TW/design/file-security.md)

由宿主决定可打开哪些文件，以及验证后的内容可写到哪里。格式后端只能使用有界的读取器和输出接收器，独立归档工作进程也遵循这一边界。归档名称、声明大小、校验和及内容都属于输入数据。宿主文件检查与格式校验分别生效。[系统架构](system-architecture.md)、[归档工作进程协议](../engineering/native-codecs.md)

## 来源与目标授权

- **归档来源。** `Source::open` 通过 `xdzip-io::open_regular_readonly` 打开选定路径，并核对实际打开的文件类型。Unix 以非阻塞方式打开对象后再判断类型，避免打开命名管道时卡住。用户选定的路径可以经链接指向普通文件。分卷发现依格式执行并受限额约束。宿主冻结允许读取的相邻分卷，核对其文件身份和版本。编解码器只能定位宿主提供的数据流。[来源实现](https://github.com/xiaodaozhi/xdzip/blob/main/crates/xdzip-runtime/src/source.rs)、[分卷处理](../engineering/archive-opening.md)
- **创建输入。** `InputTree` 在元数据与文件身份限制内遍历选定输入。读取时从目录树打开对应成员并校验版本。扫描时排除本次创建的私有暂存目录，检测到来源变化就停止作业。文件身份、大小与时间信息用于尽力检测变化，无法据此获得完整的内容快照。[输入目录树](https://github.com/xiaodaozhi/xdzip/blob/main/crates/xdzip-io/src/input.rs)、[归档创建](../engineering/zip-creation.md)
- **写出目标。** `Grant` 持有选定目录对象及其身份。解压把所有源分卷身份一并列为受保护文件。创建和修改分别通过自己的任务路径核对冻结输入或原归档的身份。子目录与暂存均通过已有目录句柄访问，提交前会重新核对父目录身份。`CheckTarget` 和解压预检可以在任务开始前提供检查结果，实际操作仍须重新校验写出授权。[目标授权](https://github.com/xiaodaozhi/xdzip/blob/main/crates/xdzip-io/src/target.rs)、[解压预检](../engineering/extraction-preflight.md)

## 名称映射、平台保护与链接

1. **校验归档相对名称。** 运行时解析冻结的选区，按需去掉所选子树的前缀，并使用 `PortablePath` 接受相对 UTF-8 路径组件。绝对路径、盘符路径、控制字符、有歧义的分隔符、父目录组件、设备保留名及结尾空格或点都会被拒绝。通过语法检查的名称只作为目标授权的输入。
2. **提前规划名称冲突。** 解压计划以小写 NFD 键比较常见的大小写和 Unicode 等价名称。目录拼写歧义及文件与目录冲突会在准备时失败。普通文件的等价名称映射到同一拼写，由运行时执行重名策略。实际文件系统上的名称仍须通过原生排他发布确认。显示名称与物理条目身份分开保留。
3. **沿已授权目录树访问。** 输出从持有的目录能力出发，逐层打开子目录时拒绝跟随链接。提交前重新检查授权根、父目录身份以及预期覆盖的末级对象。目标被替换或遇到不安全链接时会拒绝。同卷重命名前的最后检查能缩小竞态范围，普通重命名无法对同账号进程提供内容级的比较交换保证。

| 平台 | 对输出对象的检查 |
| --- | --- |
| Linux 与 macOS | 对象必须归当前有效用户所有，拒绝组或其他用户的写权限，已有普通文件必须只有一个硬链接。macOS 还检查原生 ACL，包括可能继承的修改权限。 |
| Windows | 通过已持有对象检查重解析点、所有者、文件 ID、普通文件硬链接数和 DACL。有效或仅继承的访问规则必须将修改权限限定在受信任主体内。已有只读共享可以保留。 |
| 私有明文或临时工作数据 | 额外执行保密检查，排除无关读取者。Windows 上可为排他创建的私有缓存目录设置受保护的 DACL。用户选定的一般解压目标保留自己的只读共享策略。 |

ZIP 符号链接的输出仅适用于通过校验的 Unix 链接图。运行时先验证选区内的链接关系和要求不存在的末级对象，提交普通目标文件后才发布链接。任务写出时不会跟随归档创建的链接。其他不受支持的链接或特殊文件会明确失败。POSIX 普通文件可在暂存时恢复安全的读与执行位，并保留所有者读写权限，排除特权位与其他主体的写权限。解压路径不会在提交后恢复时间戳。

## 暂存、验证与提交

宿主使用目标授权在同一卷内排他创建私有工作区，按限额把后端输出写入暂存文件。发布前须完成解码、核对预期大小，并通过格式提供的完整性或认证检查。`Stage::finish` 刷新并同步文件，保留已校验的版本。提交时宿主再次检查暂存对象与目标。同步文件数据以及单个文件的原子可见性，无法保证断电后目录元数据一定持久化。

| 操作 | 发布语义 |
| --- | --- |
| 解压或发布文件承诺 | 每个符合条件的文件验证后单独发布。无覆盖时排他创建同卷硬链接，再清理私有暂存链接。允许覆盖时，解压须匹配预期且安全的普通文件，通过同卷重命名替换，避免先截断。文件承诺发布始终禁止覆盖。文件系统缺少所需原语或目标发生变化时，相关写入失败。已提交文件与已创建目录不执行整单回滚。 |
| 创建单文件归档 | 编码到暂存后重新打开，按照创建配置验证预期条目及内容，再一次发布整个归档。名称冲突可以选择新名称或允许符合条件的替换。受保护的输入不能成为覆盖目标。 |
| 创建分卷 | 验证暂存归档内容，将每一卷暂存后发布为同一目录下的新卷组，禁止覆盖已有分卷。每卷分别变为可见。部分失败时，回滚只尝试移除身份仍匹配的本次新发布对象。回滚失败可能使结果不确定。 |
| 修改已有归档 | `ArchiveUpdate` 绑定授权父目录与预期的原归档版本。重新打开并验证已重写的暂存归档后，通过这一授权一次替换原归档。普通解压不能使用这种专用替换方式覆盖自己的来源。 |

在取得提交许可前取消，当前提交不会开始。已经在执行的发布可以完成并报告实际结果。先前提交的解压文件仍可见，最终快照可能在带有提交记录的同时报告 `cancelled`、`failed` 或清理警告。整包成功发布后，迟到的取消不会改写成功结果。[任务取消](task-scheduling.md)、[归档修改](../engineering/archive-transfers.md)、[安全解压](../engineering/zip-safe-extraction.md)

## 输出预算与完整性范围

解压分别限制声明输出与实际输出，普通文件上限为 8 GiB，任务上限为 20 GiB。支持的格式会在准入时检查高压缩比。ZIP 中超过 1 MiB 且声明压缩比超过 1,000 比 1 的条目需要显式允许，但硬性额度仍然有效。固实或流式后端可能需要处理未选中的数据。相关工作量、重复读取或重试以及辅助解码消耗，与发布字节数分别计量。

元数据浏览、任务准入、工作进程内存和预览各自有预算。较大的 ZIP 磁盘索引不会提高解压或写入限额。完整性检查的范围取决于格式。例如，ISO/UDF 的结构与可读性检查无法补足格式没有提供的逐文件校验和。[大型归档索引](../engineering/large-index.md)、[完整性检查](../engineering/archive-checking.md)、[辅助解码计量](../engineering/auxiliary-decoding-work.md)

## 预览、临时打开与密码

- **预览。** 用户主动请求预览受支持的条目。Rust 在限额内完整读取并验证条目。文本上限为 256 KiB，编码图片上限为 16 MiB，原图尺寸和像素数另有限制。专用图片进程接收字节并返回受限缩略图，接收的数据中没有归档名称、密码或目标句柄。当前格式及限制见[预览契约](../engineering/content-preview.md)。
- **临时打开。** 普通条目按任务的常规验证规则解压到私有缓存。桌面以本地 URL 将验证后的文件交给系统关联应用。系统接受交接请求并不表示外部程序已读完文件。保留期满后，后续操作会核对缓存身份与锁并清理。编辑临时副本与原归档的内容相互独立。[临时打开](../engineering/archive-opening.md)、[归档传输](../engineering/archive-transfers.md)
- **密码。** 打开和解压密码在会话或任务存续期间保存在对应操作的可清零容器中，不进入任务快照或暂存日志。用户数据的本地存放、保留与披露规则见[隐私工程契约](../engineering/privacy.md)和[密码契约](../engineering/password-extraction.md)。

## 日志、遗留文件与验证

暂存日志在准备与提交时记录任务上下文和相对输出名称。正常清理核对所有权与身份，只删除已知的暂存对象。异常终止后，私有日志与遗留对象可用于判断实际情况。运行时检查目标时会统计可能存在的遗留工作区，不根据发现的日志重放写入或删除未知内容。私有临时输出的过期清理另有身份和锁检查。

修改这一边界时，要核对实际提交及清理结果和错误码。[I/O 测试](https://github.com/xiaodaozhi/xdzip/blob/main/crates/xdzip-io/src/tests.rs)、[解压测试](https://github.com/xiaodaozhi/xdzip/blob/main/crates/xdzip-runtime/src/extraction/tests.rs)和[安全解压契约](../engineering/zip-safe-extraction.md)分别覆盖不同层级。改动涉及原生平台行为时，需要对应平台的验证证据。
