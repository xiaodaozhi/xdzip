# 性能设计与测量

[English](../../design/performance.md) | 简体中文 | [繁體中文（台灣）](../../zh-TW/design/performance.md)

XDZip 分别约束索引、传输、任务执行和图片预览的内存与工作量。下面的代码限额属于实现规则。耗时、内存和吞吐数据取决于构建和工作负载，后文的参考指标是设计目标。

## 当前代码中的限额与机制

| 范围 | 当前行为与资源开销 |
| --- | --- |
| 普通单文件 ZIP/ZIP64 | 流式扫描最多接收一百万条物理记录，还受名称、中央目录和读取预算限制。热元数据超过 64 MiB，或新增记录会使常驻条目超过十万条时，将记录迁入私有磁盘存储。元数据文件上限为 512 MiB，另有位置表。浏览扫描元数据。 |
| 内存和磁盘查询 | 运行时一次建立当前不可变结果的顺序。磁盘路径生成每段最多 8 MiB 的排序段，再归并为条目令牌顺序。名称与排序存储均受限。缓存保存当前查询，界面的渲染结果及查询历史另有生命周期。 |
| 导航与 Qt 传输 | 目录树限制为 32,768 个节点、64 层与 4 MiB 名称数据。目录树超额时仍可保留根目录浏览和搜索。桥接每页最多传 128 行及 64 KiB 名称数据。大结果最多常驻 1,024 行，逻辑行数覆盖完整结果。 |
| 命令、任务与写出 | 元数据线程与任务线程分别使用有界队列。桌面重任务逐个准入。解码工作量、输出字节数、文件提交和工作进程资源分别计量。固实或流式格式在到达选中项前可能要读取或解码前置数据。 |
| 预览与原生工作进程 | 文本与图片编码数据有各自的字节上限。图片尺寸、像素数、解码进程执行和缩略图大小独立受限。格式工作进程遵守自己的协议及进程限额。 |

[磁盘索引实现](https://github.com/xiaodaozhi/xdzip/blob/main/crates/xdzip-runtime/src/disk_index.rs)、[大型归档索引](../engineering/large-index.md)、[Qt/Rust 桥接限额](qt-rust-bridge.md)、[任务准入](task-scheduling.md)、[输出预算](file-security.md)、[预览限额](../engineering/content-preview.md)

内存开销包含 Qt、字体、渲染与模型、归档元数据、位置表和查询缓冲、解码器状态、子进程及 I/O 缓冲。64 MiB 是元数据迁移阈值，进程树内存还包含索引以外的开销。扩大的元数据准入不会提高解压配额，使用磁盘索引的会话也无法执行整包测试或修改。私有索引写入和解压暂存分别产生磁盘开销。

## 测量当前实现

| 入口 | 测量或验证的范围 |
| --- | --- |
| `scripts/probe-large-index.py` 与 `xdzip-m2-probe` | 生成项目自有 ZIP64，执行真实扫描、排序和分页查询，分别报告各阶段与存储。场景包含重复名称、长名称和目录结构，并记录是否进入磁盘路径。 |
| `scripts/measure-desktop.py` 与 `xdzip-process-metrics` | 测量桌面进程树、启动和浏览。启用解压选项时驱动真实解压，并独立验证输出字节。记录渲染后端、构建身份和实际负载。 |
| `scripts/run-performance-suite.py` | 收集 Release 构建的启动、稳定空闲与浏览观测，并使用自有样本与锁定的核心探针比较解压。报告记录构建及样本身份。这是一项观测性比较，参考机器验收是独立条件。 |
| `scripts/check-runtime-resources.py` | 检查探针返回的运行时资源及字体回执，说明本次探针的资源身份和覆盖范围。交互耗时由独立测量入口获取。 |

[大索引探针](https://github.com/xiaodaozhi/xdzip/blob/main/scripts/probe-large-index.py)、[桌面测量](https://github.com/xiaodaozhi/xdzip/blob/main/scripts/measure-desktop.py)、[性能套件](https://github.com/xiaodaozhi/xdzip/blob/main/scripts/run-performance-suite.py)、[运行时资源探针](https://github.com/xiaodaozhi/xdzip/blob/main/scripts/check-runtime-resources.py)、[证据采集](../../../developers/zh-CN/engineering/candidate-verification.md#性能与资源证据)

比较时记录提交与构建配置、系统与架构、渲染后端、硬件、轮次、样本、设备和缓存条件，区分冷启动和重复启动。测量条件允许时，分别报告首次交互、归档扫描、查询排序、页面传输及界面可见的时间。区分取消反馈与实际停止及清理。吞吐报告分别说明输入、解码和已提交的字节数。

进程树工具分别标注 Linux PSS、macOS 物理内存占用和 Windows 私有已提交内存，并在可用时报告 RSS 或工作集。比较时采用相同指标及相近条件。真实安装包的下载大小和安装后大小分别记录。离屏和原型测量只说明各自环境下的观测。

## 对比测试负载

| 负载 | 测量内容 |
| --- | --- |
| B01/B08 空窗口、空闲和主题切换 | 启动与帧耗时、空闲 CPU、保留内存与渲染后端。 |
| B02 十万与一百万条 ZIP 记录 | 元数据扫描、迁移、排序、分页获取，并分别记录内存与磁盘开销。 |
| B03/B04 一个大型普通文件或大量小文件 | 吞吐、取消、目标文件操作、同步及清理。小文件耗时可能主要来自文件操作。 |
| B05/B06 高压缩比内容或长流末端的条目 | 配额处理与到达所选条目之前额外消耗的解码工作。 |
| B07 有重任务排队时浏览 | 一个重操作执行、另一个等待期间的搜索与分页耗时。 |
| B09 随包工作进程及完整安装包 | 进程树开销、协议成本、下载体积与安装体积。 |

这些是对比场景。选用与变更对应的负载，使用项目自有样本，并记录大小和哈希。

## 参考目标与后续研究

既有设计以配备 16 GiB 内存、本地 SSD、60 Hz 显示器的 Apple Silicon 为参考，使用系统字体、实际 GPU 和 Release 构建。下列目标用于可比条件下的测量。最新版本与其他平台的实际表现需要各自的观测。

| 场景 | 设计目标 |
| --- | --- |
| 空窗口重复启动 | 至少 30 轮后，到可交互帧的 P95 不超过 500 毫秒 |
| 打开并查询缓存中的十万条 ZIP 记录 | 元数据准备 P95 不超过 1 秒，已有索引的查询到可见 P95 不超过 80 毫秒 |
| 热页跳转与界面调度 | 页面跳转到可见的 P95 不超过 50 毫秒，界面线程连续阻塞的 P95 不超过 8 毫秒 |
| 内存 | 进程树空窗口目标不超过 150 MiB，浏览十万条记录且无预览和解码字典时不超过 256 MiB |
| 空闲 CPU | 稳定后平均不超过单个逻辑核心的 0.5% |
| 取消 | 分别测量反馈和本地流式协作停止，P95 目标依次为 50 和 250 毫秒 |
| 解压与分发 | 以相同负载和 I/O 设置比较桌面与核心，吞吐损耗目标不超过 10%。Mac 单架构包的下载和安装体积目标分别为 100 MiB 与 250 MiB。 |

按块并行解压、跨会话持久化复用索引，以及共享 CPU 令牌调度仍是设计选项。调整并发或存储前，先分析当前串行任务及内存、磁盘路径。比较时保持相同的字节验证、取消和安全提交条件。[架构演进](architecture-evolution.md)、[文件提交](file-security.md)
