## 代码与所有权

- **Rust。** 遵循工作区工具链、检查规则与锁文件。校验外部长度、偏移和整数转换，保留未知大小与类型化错误。记录 unsafe 与 FFI 的前提、所有权、生命周期和失败行为。缩短同步临界区，将归档 I/O 留在临界区之外。
- **C++ 与 Qt。** 使用 C++17、RAII 和明确的 QObject 所有权。在界面线程修改模型，跨线程传递自有数据的值，并将排队通知绑定到存活的接收方。接收线程仍需界面取走事件时，以异步方式关闭。归档和文件规则仍由 Rust 负责。[Qt/Rust 桥接](qt-rust-bridge.md)
- **QML。** 通过控制器表达状态和操作意图。复用共享控件及生成的视觉和文字资源。列表委托无需访问磁盘或解释归档。窗口变动遵循登记、原生行为及视觉规范。[Qt Quick 界面](qt-quick-ui.md)、[视觉流程](../visual/design-workflow.md)

记录不变量及失败后留下的状态。例如，文件代码应说明提交许可保护什么、校验哪些身份，以及出错时哪些内容可能已经可见。[文件提交](file-security.md)

## 验证层次

| 改动 | 对应证据 |
| --- | --- |
| 领域、查询与服务 | 用 Rust 测试身份、限额、同名记录、排序、过期响应、有界交付与取消。 |
| 格式操作 | 使用项目自有样本，在适用时进行独立往返核验，同时覆盖拒绝、损坏、不支持的配置和额度。 |
| 原生文件与任务 | 在受影响平台核对文件身份和实际字节、取消与提交竞态、已有输出保护和清理结果。 |
| 桌面、Qt 与辅助功能 | 覆盖模型和控制器、QML 与共享控件，按影响范围执行原生交互，验证实际视觉或辅助技术行为。 |
| 性能与分发 | 记录绑定提交的负载、渲染及资源指标，或对应发行渠道的构建身份、安装更新结果和依赖回执。 |

[验收指南](../../../developers/zh-CN/qa/README.md)用于确定本次改动所需的检查。协议一致性、夹具或离屏验证、原生自动化和桌面人工观察各有证据范围。现有回归入口与交付边界见[开发构建指南](../engineering/developer-build.md)和[追踪矩阵](requirements-traceability.md)。

## 现有 CI 与补充验证方法

常规 [CI 工作流](https://github.com/xiaodaozhi/xdzip/blob/main/.github/workflows/docs.yml)检查文档、生成资源、布局契约、格式和工作流结构。更重的原生 Rust、格式及 Qt 检查分别手动调度 Foundation 和 Qt 工作流。发行工件由专用发行任务处理。[CI 策略](../../../developers/zh-CN/engineering/ci-policy.md)描述触发条件和门槛。需要执行哪些本地或手动调度的测试，取决于本次受影响的代码路径和平台。

模糊测试、运行时检查工具（Sanitizer）、模型检查与性能基准是按覆盖需要选用的方法。使用有界且可再分发的样本，单独记录实际证据。敏感安全报告遵循[安全政策](../../../SECURITY.zh-CN.md)。设计中的计划检查或方法示例本身不表示已有定时流水线，也不表示已经验收。

## 维护设计

实现改动涉及身份、命令、能力、任务或文件写出边界时，同步更新对应设计、工程参考及验收引用，并保持双语一致。[架构决策](architecture-decisions.md)记录取舍，[性能设计](performance.md)定义测量规则。实际结果及限制另行记录到对应变更。
