# xdzip：架构决策记录

[English](../../design/architecture-decisions.md) | 简体中文 | [繁體中文（台灣）](../../zh-TW/design/architecture-decisions.md)

早期记录日期为 2026-10-11，后续记录各自注明日期。已采用表示架构决策生效。各段的当前实现说明将决策关联到维护中的契约及能力依据。替代旧决策时，保留原记录并追加新记录。

## ADR-001：Qt Quick 作为唯一产品界面

**状态：Accepted。**

**当前实现。** 桌面已采用 Qt Quick/QML 与薄 C++ 适配层。Windows SFX 的系统对话框宿主属于 ADR-013 中的有限例外。[桌面界面](qt-quick-ui.md)

背景：产品要求现代桌面 UI、统一体验和低占用；已完成 Slint、Tauri、Qt Quick 的同核心原型。结合界面能力、统一体验与现有 Linux 软件渲染数据，项目选定 Qt Quick 进入产品阶段；其他平台表现仍需验证。

决定：Qt Quick/QML + Qt Quick Controls 2，C++ 薄适配。Slint/Tauri 作为历史实验保留，不打包进产品。

代价：承担 Qt 运行库、QML 模块、跨语言构建和许可工作；Mac/Windows 输入、无障碍、GPU 和部署必须补测。不能把 0.80MiB 原型程序当 Qt 完整安装包。

重新评估触发：Qt 目标平台无法满足必要功能/许可/安全维护，且经过实际优化仍无法达到核心产品预算。普通性能波动不触发重复框架选型。

## ADR-002：Rust 持有全部归档业务

**状态：Accepted。**

**当前实现。** Rust 运行时持有归档状态与任务。文件选择属于桌面意图，由宿主 I/O 层执行文件系统授权。[系统架构](system-architecture.md)

决定：领域、索引、计划、任务、配额、路径策略和格式注册表在 Rust；Qt 只表示状态、授权系统文件选择和用户决定。业务测试不需 Qt。

替代方案：把 libarchive/7zip 直接接到 C++/QML，或在每个 UI 中重复控制逻辑。代价是核心与平台 UI 耦合，无法一致验证安全/取消。Rust 也不免除原生库安全风险，相关库可工作进程隔离。

重新评估触发：某个平台 API 无法在 Rust 可靠实现时，允许小型平台 C++ port，不改变业务所有权。

## ADR-003：构建期 cxx 桥接

**状态：已采用。**

**当前实现。** 产品已构建并使用类型化桥接，命令和事件使用独立句柄。事件接收器及关闭生命周期见[桥接契约](qt-rust-bridge.md)。

决定：产品内部用 cxx 生成的类型安全桥接，同提交构建；不维护长期手写 C ABI，不在热点路径 JSON 序列化。桥接不含 Qt 业务。

替代方案：沿用实验 C ABI、使用 CXX-Qt 自动生成 QObject、通过本地 IPC 连接 GUI 和整个核心。cxx 保留明确的 Qt 模型和线程边界，避免首阶段依赖额外 QObject 生成框架；代价是自行维护薄 QObject 层和 CMake/Cargo 编排。

不承诺：cxx 不提供跨任意 Rust/Qt 版本的动态二进制兼容，也不生成第三方格式协议。

重新评估触发：受支持平台的桌面构建或生命周期验证失败，或适配层明显膨胀。届时以 ADR 评估 CXX-Qt 或显式版本化 C ABI，不默默切换。

## ADR-004：内置源码 SDK 与外部进程协议分离

**状态：已采用该设计边界，外部协议仍为试验。**

**当前实现。** 产品格式通过显式注册内置。随包格式工作进程使用自己的协议，外部 CBOR 实现是独立的只读试验。[格式适配器与扩展试验](codec-extension-sdk.md)

决定：内置格式采用 Rust 源码接口，外部扩展采用独立且有界的进程协议。I/O 授权仍由宿主持有。

原因：Rust 动态库 ABI 不稳定；任意进程内原生插件破坏崩溃隔离和资源治理。采用 Wasm 作为通用格式运行时暂不优先，原因是现有原生 codec 迁移、线程、seek 和性能验证成本，不否认其未来用途。

代价：协议、broker、沙箱和 IPC 开销。协议需两个独立实现互通后冻结。

## ADR-005：宿主集中控制真实文件写入

**状态：Accepted。**

**当前实现。** 运行时准备操作，`xdzip-io` 持有授权、暂存和提交，格式适配器使用读取器和接收器。[文件授权](file-security.md)

决定：后端只写被批准的 OutputSink，真实路径、冲突、暂存和提交由宿主控制。禁止直接调用库的通用 unpack 到任意目录，除非完整验证其端口已受宿主约束。

原因：各格式重复实现路径保护很容易出现差异；仅检查字符串无法阻止链接/竞态。代价是自己实现三个平台文件安全层和故障测试。

不承诺：宿主能证明恶意插件输出内容语义正确，或阻止同用户已被控制的恶意进程。插件信任和权限仍需明确。

## ADR-006：按文件提交解压，整体提交新建归档

**状态：Accepted。**

**当前实现。** 解压逐文件发布。创建和修改在发布或替换前验证暂存归档。分卷创建验证后逐个发布，部分失败时执行受限回滚。[提交语义](file-security.md)

决定：解压各文件先暂存校验再发布，任务失败可保留部分完成；新归档整体写完再发布。默认不覆盖。

原因：合并进现有目录无法跨平台简单提供真正全目录原子事务；假装全任务回滚会误删用户后续修改。代价是详细结果和恢复日志，取消语义需要讲清。

重新评估触发：新增“全新目录整体发布”模式，可在受限条件下独立实现，不改变已有目录合并语义。

## ADR-007：有界 actor/工作池和事件推送

**状态：Accepted。**

**当前实现。** 当前每个连接使用独立的命令和任务线程，桌面串行准入重任务，Rust 队列与 Qt 邮箱均有界。通用资源令牌池仍是设计选项。[任务调度](task-scheduling.md)、[Qt/Rust 桥接](qt-rust-bridge.md)

决定：轻量调度器决定状态，有界池执行工作；Qt 独立事件接收线程，进度合并、终态必达；取消和 shutdown 有独立控制准入。

替代方案：GUI 同步调用、每文件一个线程、无限 Tokio/spawn_blocking、常驻轮询。归档主要是同步 CPU/I/O，不因“异步”字样引入无限任务；未来真正网络 I/O 可局部使用异步运行时。

代价：明确背压、关闭和资源 lease；收益是空闲低占用、不会被任务淹没 GUI。

## ADR-008：能力驱动，首版限制格式

**状态：Accepted。**

**当前实现。** 首批格式是历史背景。当前源码能力由维护中的注册表与运行时准入决定，包含后续扩展的读取与创建配置，以及各操作自己的限制。[格式注册表](../engineering/format-registry.md)

决定：v0.1 ZIP Store/Deflate 和 TAR/GZIP；加密、分卷、RAR、7z 与额外算法逐项验证。UI 不按后缀推断完整支持。

原因：格式名称不能描述所有实际特性。代价是首版格式表较短，收益是对用户诚实且可验证。

## ADR-009：小型产品数据与用户内容分离

**状态：Accepted。**

**当前实现。** 设置、索引和暂存日志有独立生命周期。磁盘索引是会话私有数据。持久复用索引及重放未完成作业仍是设计选项。[领域模型](domain-data.md)、[文件提交](file-security.md)

决定：设置、临时索引、事务日志和扩展清单分生命周期管理。默认无遥测、不持久密码、不跨启动缓存归档索引。

代价：多种 schema 和清理规则。重新评估跨启动索引时需新增源身份、失效、隐私与容量设计。

## ADR-010：完整分发和许可进入架构门槛

**状态：Accepted。**

**当前实现。** GitHub 二进制包与 Microsoft Store MSIX 现已使用各自文档中的打包渠道，按渠道核对实际部署依赖、工件完整性和许可材料。[构建与发行](build-release.md)

决定：Qt 默认动态部署，准确模块许可审查；安装体积包含运行库；签名、SBOM、替换/源码义务进入发布检查。

替代方案：只比较 executable 或发布前才补 LICENSE。它们不能证明产品小或可合法分发。

代价：部署和许可持续维护。Qt 静态构建或商店发行需单独 ADR 与许可审查，不能由 size 优化 PR 顺手改变。

## ADR-011：首批支持范围与个人项目维护政策

**状态：Accepted，2026-10-19，由项目所有者明确批准。**

**当前实现。** 当前支持范围及更新行为见[支持政策](../engineering/support-policy.md)和[更新契约](../engineering/software-update.md)。手动更新条款描述 v0.1。

决定：首批支持 macOS 14 及以上 Apple Silicon arm64、仍受维护的 Windows 11 x86_64，以及 Ubuntu 24.04 LTS x86_64、X11、glibc 2.39 及以上。只优先维护最新公开版本，尽力处理反馈，不承诺固定响应时限；v0.1 手动下载更新，开发预览保持实验性。详见[支持政策](../engineering/support-policy.md)。

原因：以现有原生构建、安装器和运行依赖为边界，收窄旧设计未验证的系统与架构承诺，符合个人开源项目的维护能力。代价是不承诺 Intel Mac、Windows 10、ARM64 Windows/Linux、其他发行版或 Wayland。扩大范围须先补充实现与实测。

边界：个人 GitHub 开源发行不要求付费开发者账号、签名证书、Developer ID 或公证，macOS 保留必需的 ad-hoc 完整性；该政策不代替许可来源与包验证，也不推断所有未来系统版本兼容。

## ADR-012：逐格式迁移至独立 Rust 格式与压缩算法实现

**状态：Accepted，2026-10-25，由项目所有者明确批准实施。替代第三方格式引擎的长期选型，不表示迁移已经完成。**

**当前实现。** 当前产品路由使用 Rust 格式实现。适用的 7z、RAR、CAB 和光盘镜像读取走随包工作进程，目前也有进程内 ISO 写入器。具体操作见[格式注册表](../engineering/format-registry.md)和[适配器设计](codec-extension-sdk.md)。

决定：格式解析及压缩、解压算法采用独立 Rust 实现，允许通用密码学、字符编码和系统基础库。依据官方规范先定义行为规格，再独立实现，参考源码不逐行转换或改名复制。已经接触源码的开发者不宣称严格洁净室开发；来源不足及许可限制需单独审查，尤其不开发 RAR 编码器。

迁移方案按当时的能力逐个验收并替换 ZIP、TAR、TAR.GZ、7z、RAR、CAB、ISO 和 UDF。未达标格式保留当前实现，不静默回退，不扩大 RAR/CAB/ISO/UDF 的只读范围。共享压缩算法复用，名称、身份、授权 I/O、资源、取消和提交继续由 Rust 宿主管理；工作进程隔离不因改为 Rust 而取消。

代价：独立承担兼容性、安全、性能、模糊测试及长期算法维护。第三方参照可用于测试，但完成迁移的格式须从产品依赖和交付文件中移除对应引擎。来源与接口规则见[自研后端契约](../engineering/independent-rust-codecs.md)，进展与实际验收在 [#45](https://github.com/xiaodaozhi/xdzip/issues/45)登记。

## ADR-013: 独立 Windows SFX 宿主

**状态：按所有者授权的首版 SFX 范围采用，2026-11-16。**

**当前实现。** [SFX 契约](../engineering/sfx-creation.md)说明 Windows 配置与独立的 Rust 和系统对话框入口。

背景：生成的 Windows x64 自解压包必须无需安装 xdzip 或 Qt 即可工作。每个归档附带另一套完整 Qt 应用会增加独立的部署运行时。

决定：桌面继续使用 Qt Quick 并复用现有创建窗口。自有独立 SFX 程序仅使用 Windows 系统目录和任务对话框，字体、DPI、尺寸及辅助功能由系统控制。ZIP、校验、输出授权、冲突、进度、取消和清理继续使用现有 Rust 核心。这是 ADR-001 的有限发行宿主例外，不是另一套桌面框架或自定义控件库。

成本：维护并自动化验证一个额外的 Windows 可执行程序、版本化封装、静态 CRT 链接、无 Qt 依赖审计和原生对话框宿主。绝不运行解压内容。为生成文件签名与为固定解压程序签名分开处理。

重新评估触发条件：安装器、自动运行载荷、其他可执行平台或自定义 SFX 界面须另行确定范围并评审架构。
