# 普通 Brotli 流契约

[English](../../engineering/brotli-streams.md) | 简体中文

`xdzip-compression::BrotliReader` 独立解码一个普通 RFC 7932 Brotli 流，只接收调用者持有的 `Read` 能力和已准入压缩跨度，没有文件名、文件系统、网络、进程或输出发布权限。产品入口与 TAR 组合另由[格式登记](format-registry.md)声明，原语本身不声明浏览、创建或关联能力。

## 数据范围

读取器接受标准 10–24 位窗口、压缩/未压缩/元数据元块、简单和复杂规范前缀码、连续重复码长、三类块切换、四类字面量上下文、零游程和逆 MTF 上下文表，以及显式、近期、直接、后缀距离和重叠历史复制。词典复制接受 4–24 字节原始词和全部 121 种字节变换，包括产生零字节的变换。近期距离跨元块保留，仅合格的历史回溯更新缓存。未压缩、词典和历史复制字节都更新字面量上下文。

依据 [RFC 7932](https://www.rfc-editor.org/rfc/rfc7932.txt)，SHA-256 为 `394abd1879e016f4eac89512c2acaf92f7b2d67feb8ab58b6b118c213be07146`。已确认的[勘误 5948](https://www.rfc-editor.org/errata/eid5948)修正 3.5 节的文字笔误。[RFC 9841](https://www.rfc-editor.org/rfc/rfc9841.html)新增共享词典、大窗口和单独容器，不在普通流范围内。扩展窗口保留模式返回不支持，不发现或下载外部词典。

一个流必须以合法零填充结束，并精确消费已准入字节跨度。非规范长度、元数据保留位、无效/过满/不完整码树、重复符号、上下文表或类型缺口、无效距离/变换、超出元块输出都会失败。拒绝拼接、额外尾字节和截断。Brotli 没有内容校验和、完整流解码大小声明、加密、成员路径或时间字段。成功只证明准入结构、声明的元块大小和可读性，仍能形成合法流的字节变动无法被识别为损坏。

## 资源与控制

分配历史前须准入 `(1 << window_bits) + 2 MiB`。后一项保守覆盖有界前缀符号、块/上下文向量、输入缓冲和固定状态，每个声明的数量也独立受限。每类最多 256 个块类型或上下文树，字面量表最多 16384 项，距离表 1024 项，前缀字母表最多 704 个符号。静态标准数据不授予外部 I/O。

压缩输入和累计输出各有 24 GiB 硬上限，调用者只能收紧。实际位读取、前缀构建、符号/重复展开、上下文 MTF 移动和输出消费同一份累计工作预算，最多 96 GiB 工作单位，失败不退还。元块输出声明在解码前准入，不能扩大调用者配额。每次读取最多返回 8192 个解码字节。`with_poll` 按有界工作间隔调用无文件权限的协作控制回调，头部和零输出计算也覆盖，因此取消不依赖继续读取源字节。回调、源和配额错误都是终止错误。仅重试无附加错误的中断读取，类型化中断保留原错误对象，不被便利方法自动重试。

调用者必须读到 EOF，并在成功前私有保留输出。后续失败使先前数据块整体无效，原语不发布文件，失败读取器不能恢复使用。协作控制不能中断阻塞的底层系统读取，冻结源和最终提交由主机负责。

## 标准数据与验证

静态词典和三张上下文表直接从固定 RFC 提取，核对全部规范长度与 CRC，同时验证词长位深和变换编号。[数据来源与许可](../../../third_party/brotli-rfc7932/README.md)仅覆盖这些标准常量，不链接 Brotli 参考实现。源码和分发材料保留 IETF 修订 BSD 声明，桌面与 CLI 的声明收集入口独立于 Cargo 依赖和参考运行时收集该材料。

[项目构造样本](../../../tests/fixtures/brotli/README.md)经编码或独立构造后，由固定作者解码器逐字节核对，覆盖等级、窗口、实际影响输出的上下文、块切换、距离参数、全部标准变换、元数据及未压缩块。精确配额、截断、填充、短输入、类型化错误、工作轮询和确定性变异补充互操作样本。参考工具仅在 `build/toolchain/`，生成证据仅在 `build/` 或 CI。[验收要求](../qa/acceptance.md)中的 `FORMAT-BROTLI` 另行约束产品接入，原语测试不代替产品验收。
