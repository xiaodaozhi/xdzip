# ASAR 容器契约

格式依据 Electron 的 [ASAR 说明](https://github.com/electron/asar#format)和 Chromium 的 [Pickle 契约](https://chromium.googlesource.com/chromium/src/+/main/base/pickle.h)。八字节尺寸 Pickle 后跟包含 JSON 目录树的字符串 Pickle，文件偏移以十进制字符串表示，相对于载荷区起点。即使多个文件共享同一段存储字节，每个树条目仍保留独立身份。可选完整性声明包含整个文件及各固定尺寸块的 SHA-256，这些是损坏检查，不代表软件包或应用认证。

## 准入与身份

解析目录树前验证四个小端长度字段、四字节对齐、精确字符串长度、零填充及源边界。头部上限为 8 MiB，路径深度最多 64 个组件，节点数和名称分配受共同扫描上限限制。通用 JSON 解析必须有界，拒绝重复键并保留对象顺序。拒绝非法 UTF-8、字段类型、非整数或不安全尺寸、十进制偏移溢出及未知必需配置。名称组件不能通过拼接前缀变得安全，原本不安全的名称保留可见警告和不支持标志，由宿主拒绝输出。

按 JSON 树顺序分配物理身份，包括显式目录和空文件，根对象仅为结构。精确共享载荷区间的文件保留各自身份，拒绝部分重叠、授权源之外的范围及未引用尾部数据。无完整性声明的文件只提供结构和可读性检查；存在声明时须完整校验摘要长度、算法、块尺寸与数量及空文件规则，不忽略不支持的声明。

## 只读导出与复核

后端只接收已授权可定位流和宿主输出接口，不打开其他路径、不跟随链接、不运行应用。`unpacked` 条目可见但不支持输出，相邻 `.asar.unpacked` 目录不构成输入授权。声明的链接保留身份，但不支持输出。可执行标志不授予权限恢复或执行能力。本配置不提供密码、分卷、创建或重写。

载荷使用前重新解析完整头部，将投影索引与不可变宿主快照比较，并私下保留有界偏移与可选摘要。累计限制实际输入与解码字节，分块读取存储区间并检查取消。报告载荷成功前验证整文件和块 SHA-256，包括空文件。校验期间内容只能进入私有暂存，最终发布由宿主控制。读取器发生错误后不可继续。源身份检查仍是尽力变化检测，不构成原子或已认证快照。

登记前须以固定作者工具生成或独立读取自有样本，覆盖目录、空文件、UTF-8、共享载荷、无摘要和多块摘要、外置记录及可执行声明。回归覆盖重复 JSON 键、算术、对齐、截断、重叠、错误摘要、不安全名称、源变化、精确配额、取消及输出失败。实际 runtime、CLI、Qt 任务和受影响的候选、只读边界、检查说明与布局采用自动化验证。参考工具和生成证据留在 `build/`，测试输入及生成器源码纳入版本管理，进度与实际验收登记在交付 issue。
