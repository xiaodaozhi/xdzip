# UU、UUE 与 XXE 文本封装

[English](../../engineering/text-envelopes.md) | 简体中文

传统 UU 字段与位序依据 [NetBSD uuencode(5)](https://man.netbsd.org/uuencode.5)。Base64 模式参见 [uuencode(1)](https://man.netbsd.org/uuencode.1) 与 [GNU Sharutils](https://www.gnu.org/software/sharutils/manual/sharutils.html)。XX 字母表为 `+-0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz`，已与 [UUDeview](https://github.com/hannob/uudeview) 的公共编码器核对。Rust 读取器依据这些字段与位规则独立编写，参考 C 实现仅为测试工具，不成为运行时依赖。

## 准入配置与边界

接受 `begin`、一个空格、一至四位八进制权限、一个空格及非空原始文件名。头部权限只验证语法，不恢复。UU 与 XX 使用相同头部，根据完整有效的计数正文行识别实际字母表，空成员也以零长度行识别。每行首个六位值声明 0–63 个解码字节，字符数必须恰为 `1 + 4 * ceil(count / 3)`。UU 的零值接受空格或反引号。按高位优先将四个六位值还原为三个字节，丢弃末组未使用字节，不要求历史填充位全为零。零长度行后必须立即出现独占一行的 `end`，不修复缩短或损坏的行。

`begin-base64` 变体接受 4–76 字符的普通 Base64 行，每行为四的倍数，填充位必须为零。带填充的行结束正文，之后只允许独占一行的 `====` 结束标记，正文可为空。裸 Base64、MIME 组装、GNU `begin-encoded` 文件名扩展、多段修复、yEnc 和 BinHex 不属于此配置。`.uu`、`.uue` 是 UU 候选，`.xxe` 是 XXE 候选，后缀不决定实际字母表。

接受 LF、CRLF 和末尾无换行的完整结束标记。成员前、成员间及成员后可有受限的传输文本。形似头部但损坏或不支持的行必须报错，不能忽略而隐藏成员。首个头部起点必须在前 64 KiB 内，传输与头部单行最多 8192 字节。强容器签名、光盘描述符和有效 TAR 头部优先于文本候选探测。完整验证后才准入，不能依赖后缀或单词 `begin`。全 XX 成员封装标记为 XXE，普通 UU、Base64 及混合成员封装标记为 UU。每个物理成员保留序列化顺序身份、原始名称和实际编码，包括同名成员。

## 宿主权限、配额与检查

后端只接收已授权可寻址源与宿主接收器。头部文件名经过共享的归档级名称解析、显示转义和危险路径检查，不打开输入，也不授予输出路径。读取器不恢复权限、不访问外部文件、不执行命令、不创建目录，不提供创建、修改、加密或分卷权限。正文与结束标记的编码区间作为已知压缩大小，有效行计数用于计算载荷大小。

元数据阶段在共享扫描限额内验证整个封装，通常最多实际读取 64 MiB、100,000 条记录、单个原始名称 4096 字节，原始名称和显示名称各受 16 MiB 累计预算限制。只保留受限成员区间，不保留解码内容。载荷使用前重新扫描，与宿主不可变快照比较完整投影索引；随后保留定位信息，按物理记录任意选择，不为每个文件重扫前序成员。元数据和重复正文读取共享私有 24 GiB 累计输入上限，交付字节另受 24 GiB 上限，宿主任务和单文件更严格限额继续生效。在读取、逐行工作、接收器写入及独立取消令牌处协作检查。保留源适配器的类型化错误，不重试已经终止的 `Interrupted` 失败。任何源、结构、配额、取消或接收器错误都使当前读取器终止，重试不返还预算。

检查只验证结构与可读性，**不提供校验和或认证**。修改有效六位字符可能改变输出而不触发检查失败。暂存与最终提交仍由宿主负责，源身份检查尽力发现变化，不构成已认证快照。即使只提取选中成员，也验证整个封装；不支持的头部扩展或后续损坏成员不能被静默跳过。

## 自动化验收

自有参考输入覆盖全部字节值、空文件、行尾余数、UU 零值别名、CRLF、XX、Base64、传输文本，以及包含同名记录的混合成员。固定独立参考源码版本，只调用公共编码器；UU 另用 Python `binascii` 核对，Base64 用独立标准解码器核对。补充覆盖 0–63 的所有行计数、危险和 Unicode 名称、精确输入/名称/解码预算、短读取、类型化错误、快照不一致、取消、终止后拒绝继续，以及已有输出保持不变。实际 runtime、CLI 和 Qt 任务覆盖浏览、检查、提取、物理选择、只读说明、检查强度提示和登记候选。受影响双语、主题、字号布局及主窗口与菜单比例通过自动化检查。参考程序和生成证据保留在 `build/`，进展与实际结果记录在交付 issue。
