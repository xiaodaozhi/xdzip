# LHA 数据与算法契约

[English](../../engineering/lha-containers.md) | 简体中文

LHA/LZH 与历史 LArc 是按成员顺序排列的容器家族。后缀、可识别的方法字符串或成功的 Store 成员，都不能证明另一方法可解码。`xdzip-compression` 原语只接收已准入的压缩跨度和经容器独立验证的解码大小，没有文件系统、进程、文件名或输出发布权限。产品登记和容器准入另按下述条件验收。

## 容器结构要求

`xdzip-codec-lha::inspect` 实现下述 0、1、2、3 级结构，`LhaCodec` 投影物理条目，`Reader` 独立于 Qt 执行有界载荷解码。runtime、CLI 和 Qt 提供 `LZH` 格式，`.lha`、`.lzh` 作为打开及文件关联候选。后缀或方法族标记只提出候选，完整元数据通过后才发布。有效 TAR、ZIP、光盘和自解压归档的强识别仍优先，只有未经验证的原始 TAR 标记才可由完整 LHA 验证消歧。创建准入 LH5 1/6/9 级及 2 级头部，仍不支持修改。元数据读取最多 64 MiB，物理记录最多 100000 条，单成员扩展最多 256 条，1、3 级累计头部最多 1 MiB，调用者的名称及条目限制仍有效。0 级缺少 CRC 时显式表示，不把未知系统基头尾部、扩展类型或头级别解释为普通受支持数据。

每条物理成员由头部及其精确压缩区间构成，零终止字节结束归档。多余尾部、缺少结束标记、越界区间和后续损坏成员，都不能发布部分索引。0、1 级保留基头字节和校验及 DOS 形状时间；1 级跳过大小包含扩展头链，载荷准入前必须减去其精确总长度；2 级小端头部总长限制全部扩展，时间使用 Unix 秒。算术、分配和跳转前验证字段及扩展链接。声明的扩展头 CRC 在其自身 CRC 字段置零后计算，与载荷 CRC 分开。扩展和注释不授予邻接文件、权限或执行能力。

3 级在偏移 0 保存固定为 4 的小端长度字段宽度，基头为 32 字节，偏移 24 保存头部总长，偏移 28 保存首个 32 位扩展大小，每个扩展以 32 位下一扩展大小结束。压缩及原始文件大小仍为 32 位，时间为 Unix 秒，宽头部不自动授予 64 位文件大小。分配前以 1 MiB 准入总长，扩展最多 256 条，拒绝不足的最小大小、溢出或越出头部的链接及额外尾字节。字段依据原作者[3 级头部注释](https://github.com/jca02266/lha/blob/16619b066b189ef289bb8b07b37d1c38d550da99/src/header.c)，Git blob `df8ae5e3f9dece45325d499cf63c34fc2bb0ec99`。其 README 提醒历史 3 级规范尚未固定，当前常见扩展由 jLHA、Lhasa 分别演示，不声称覆盖全部历史扩展。

2 级头长若恰为 256 字节的倍数，首字节零会与终止标记冲突。原作者文档规定，此时可补且仅补一个零字节，并计入总长和头部 CRC；其他头部尾字节及非零填充应拒绝。独立编码的 222 字节文件名验证该规则，不为了参考工具的旧路径上限而截短成员名称。

归档名称解析独立于输出授权，保留物理顺序、同名项及原始名称。先解析旧编码，再解释反斜杠分隔符，避免多字节尾字节凭空生成目录。扩展文件名和目录名有明确唯一性和组合规则，歧义重复声明应失败，不挑选方便的拼写。目录、特殊对象和链接不能作为普通文件处理，原始 Unix 模式仅为元数据，不恢复权限。冻结源、可移植路径预检、选中条目身份、私有暂存和最终发布仍由主机负责。

原始名称保留目录字段、其中的 `0xff` 分隔符、文件名字段及两者准确边界。整包有界旧编码检测分别采样完整目录分量和文件名，分隔字节不能污染检测，也不能跨字段拼成多字节字符。逐字段严格解码后，才规范化实际解码所得的反斜杠并组合 `/` 分隔符；分别检查各分量和最终名称的异常路径。原始名称、有效名称和转义显示保留共享限额与取消点。目录展开、选中提取、预览和导出使用同一冻结有效名称。未知方法、无法解码或异常名称、链接、特殊类型及相互矛盾的目录声明保持可见并标记警告，不能输出载荷，Unix 模式不授予权限恢复能力。

产品准入 Store（`-lh0-`、`-lz4-`）、LH1–LH7、LZS 和 LZ5，PMA 方法尚未准入产品。条目方法编号只在 LZH 内有效，不等于 ZIP 方法编号。检查类型为 `format_declared_checks`：存在的头部及载荷 CRC 必须通过，但没有 CRC 的古老 0 级成员只提供结构、尺寸与可读性检查。LH2 的有限变体准入必须有载荷 CRC。暂不支持密码、分卷或修复配置。单个零字节表示空归档，后续记录损坏不能得到成功的部分清单。打开时扫描名称和结构，检查或提取时才实际解码并验证声明校验。

Store 标识 `-lh0-` 和 `-lz4-` 要求压缩及解码大小相等，历史 `-lz4-` 与现代 LZ4 无关，`-lhd-` 表示目录。LH1–LH3、PMarc、扩展头、密码和分卷均须有各自验证范围与独立样本，不能由后缀或通用 Huffman/LZW 实现自动获得。未知方法须与可解码普通文件区分，容器结构有效不代表载荷内容有效。

## 静态 LH4–LH7 原语

`LzhReader` 处理高位在先、每块 1–65535 条字面量或匹配命令的位流。LH4、LH5 的位置字母表均为 14，树数量字段 4 位；LH6 为 16 和 5 位，LH7 为 17 和 5 位。四种字典地址位数分别为 12、13、15、16。字典容量与可编码的位置字母表不同，超过字典容量的距离必须失败。

19 符号码长树描述 510 符号的字面量/长度树，两类数量字段分别为 5 位、9 位。短树码长由 3 位及有界一元扩展表示，长度树接受规定的三种零游程。数量为零时选择已检查范围的单符号，不再读取符号位。普通规范码树须完整、非空、不过满，深度不超过 16。0–255 为字面量，256–509 为 3–256 字节匹配；位置零表示距离一，其他位置使用二的幂前缀及低位。重叠复制和跨块历史保持连续。

初始字典按原始普通 LHa 行为填充空格，不回退到全零的损坏归档修复模式。声明的解码大小须精确结束于命令和块边界，读取器须消费整个压缩字节跨度；忽略最后字节未用位，但拒绝额外完整字节、截断、零命令数和输出超限。空解码成员要求空压缩跨度，CRC-16 由容器负责验证。

## LH1–LH3 原语与 LH2 变体

`LhDynamicReader` 实现 LH1 的 314 符号动态模型、4096 字节字典、3–60 字节匹配和固定规范码表示的减一距离高位，其低六位直接保存。LH2 使用 286 个初始符号，285 加 8 位扩展表示较长匹配，字典 8192 字节，位置字母表在跨过每个 64 字节输出边界后增长，超范围长度应失败。两者保留空格历史和精确大小、跨度。`LzhReader` 另接受 LH3 的逐块 286 符号树、可选传入或固定的 128 符号位置树、前三码长单符号哨兵及相同的 8 位长度扩展，拒绝零命令块、无效哨兵和不完整或过满码树。

通用兄弟性质更新独立表达为稳定节点身份、显式排序及子树交换。重建时正叶权重向上折半，保持当前叶顺序，用两个有序队列合并，并从合并结果取得新根，不依赖增长前的根身份，实际比较、交换、重建及初始化都扣工作量。理论依据为 [Vitter 对 FGK 的分析](https://www.ittc.ku.edu/~jsv/Papers/Vit87.jacm.pdf)第 2 节，数据专用字母表、固定位置和阈值补充参考固定 [dhuf.c](https://github.com/jca02266/lha/blob/16619b066b189ef289bb8b07b37d1c38d550da99/src/dhuf.c)，Git blob `bcb08bdccf6c6396938e3b2d9b6b032a991aa26e`，及 [shuf.c](https://github.com/jca02266/lha/blob/16619b066b189ef289bb8b07b37d1c38d550da99/src/shuf.c)，blob `2c18ed6a909cfa7fd1d591af1e7f0bd90e269fd7`。这是对前述源码观察范围的补充，不移植其实现结构。

原始 Unix LH2 不更新初始单符号位置叶的权重，位置更新次数单独累计；jLHA 通过通用模型更新该叶。两者在相同 `-lh2-` 标识下产生不兼容的真实位流。原语提供显式 `Lh2Variant` 选择入口，通用方法 2 构造器默认使用 jLHA 的计数约定。容器要求 LH2 声明 CRC，把两个有限候选完整解码至不输出的接收端。结构或 CRC 无效可排除候选，源、取消、预算及主机错误立即终止，所有探测保留实际输入、解码及辅助工作消耗。成功候选的大小与 SHA-256 摘要须一致，否则为歧义、不支持；唯一有效或完全一致的结果再解码输出，并复核选定摘要和 CRC。摘要仅约束探测与交付字节，不证明归档真实性；不发布候选数据，也不将其变为输出抵扣额度。

原始 C 文件保持未修改并固定摘要，仅在 `build/toolchain/` 通过项目自有有界主机工具编译为测试参考。边界样本仅在参考构建中调用原始编码及增长状态，不移植到产品；两种变体都用实际变化的距离跨过字符与位置模型重建阈值。一份自有 LH2 流通过公开通用码树 API 按原始单符号约定生成，并由原作者解码器完整读取。原始 Unix 不能正确读取 jLHA 的长数据及空格配置等差异单独记录，不修复或计为通过。

## 容器创建与发布

创建采用 `lh5` 方法、1/6/9 级及 2 级头部，接受 `.lzh`、`.lha`，桌面默认后缀为 `.lzh`。主机创建方法编号为 259，与 LZH 条目内的方法编号 5 区分，不支持 Store、密码、固实分组、分卷或修改。输入最多 100000 条冻结记录，名称合计 16 MiB，实际读取最多 24 GiB，头部合计最多 64 MiB。单成员原始及压缩长度都须能由无符号 32 位表示，Unix 修改秒数也须能由无符号 32 位表示，不截断。输出最多 24 GiB，普通文件跨成员共用累计原始编码工作账本。CRC 只处理实际准入源字节，受输入及头部上限约束；读取预算完全耗尽时，可在最终 EOF 探测前保守失败。

只接受可移植普通文件和目录。目录用 `-lhd-`、零尺寸及零载荷 CRC，普通文件即使很小或不可压缩而膨胀，仍使用 LH5。名称以 UTF-8 分别放入文件名扩展和 `0xff` 分隔的目录扩展，始终输出共同头部 CRC 与逐文件 CRC-16。2 级头部恰好对齐时保留规定的单个填充字节。验证时读取已验证目录可成功返回，但不输出字节，也不授予目录操作或权限恢复能力。

此处 UTF-8 是未声明的名称约定，不是通用 Unicode 标记。自有 jLHA 公共 API 测试宿主显式选择 UTF-8，并把完整路径与载荷分别核对。旧 Windows 读取器可能使用 OEM 代码页，即使所有字节和 CRC 通过，也显示不同名称。所查原作者 7-Zip [LZH 名称投影](https://github.com/ip7z/7zip/blob/main/CPP/7zip/Archive/LzhHandler.cpp)，Git blob `1b6e3b9d9905abe28b53e39b1267465fe2fc7f03`，选择 `CP_OEMCP`；该源码观察解释参考工具限制，不把其实现加入产品，不宣称名称普遍互通。

编码器只接收冻结源索引和空的私有可随机写暂存输出。先验证全部记录边界，再流式处理内容及 CRC，完成原始编码后回填压缩尺寸和 CRC，并在下一成员前恢复顺序写入终点。不支持随机写或任何源、输出、预算及取消失败都会终止，不写成功终止标记；最终路径和提交权限不进入编码器。主机复核把 LHA 冻结有效名称与输入名称比较，其他容器保留原始名称比较，并在冻结源复核和原子发布前实际解码全部内容。验证失败、源变化或取消保留旧目标并清理私有暂存。

`scripts/check-lzh-creation.py` 独立解析并验证生成的 2 级字段、边界、UTF-8 名称、时间戳及两类 CRC，再以固定身份 jLHA、Lhasa、7-Zip 比较完整多成员内容，分别记录目录、名称与载荷结果。runtime、CLI、Qt 的创建、重开、检查和提取另由自动化覆盖，原始编码往返不能代替这些入口。

## LH5 原始编码器

`LzhWriter` 是有界原始编码器，独立于产品创建准入。它跨 32768 字节输入块保留 8192 字节历史，通过共享四字节哈希链输出真实的 4–256 字节匹配。1、6、9 级分别搜索 1、16、64 个候选，距离以 LH5 字典上限约束，不沿用匹配器更宽的容量。输出完整规范码树：C 符号 0、1 码长 8，其余 508 个码长 9，实际使用的两个码长符号各占 1 位，位置符号 0、1 码长 3，其余十二个码长 4。这是明确有界的固定树策略，不宣称最优熵编码，也不回退 Store。命令数量准确，中间块不按字节对齐，仅最终不足一字节的部分补零，空输入不输出压缩字节。

实际哈希链、输入与历史、最多 32768 个四字节命令、输出缓冲和控制状态按 1 MiB 准入。实际哈希初始化、播种、查找、候选比较、复制、位操作和输出尝试消耗累计 96 GiB 工作账本，输入与压缩字节分别最多 24 GiB。每最多 8192 工作单位回调，单次写入最多接收 8192 字节；`finish_with_work()` 可把剩余账本交给后续成员。短写和无附加错误的中断重试不重复字节，类型化中断、取消、输出及资源失败终止该实例，不暴露输出路径或发布权限。非最终 `flush()` 保留连续位流，成功结束仍须调用 `finish()`。

显式执行 `scripts/check-lzh-writer.py` 会导出原始编码器结果，以独立构造的测试专用 0 级头包装，再用固定身份 jLHA、Lhasa 和 7-Zip 完整比较字节，包括 7-Zip 的 CRC 测试。每级覆盖空、单字节、全部字节、空格、确定性随机、长内容和准确窗口重复。这只证明原语互操作，产品容器写入、名称元数据和主机原子发布仍须分别验证。

## LArc 原语

`LarcReader` 分别选择 LZS、LZ5。LZS 使用 2048 字节空格环，初始写位置 2031，高位在先的字面量标志，随后为 8 位字面量，或 11 位绝对位置及减二的 4 位长度，匹配长 2–17。LZ5 使用 4096 字节环，初始写位置 4078，每个标志字节低位在先处理八条命令，字面量和双字节绝对引用按字节对齐，匹配长 3–18。绝对位置不能解释为相对距离，两者均不复用 Stac LZS 结构。

LZ5 初始环依次包含每个字节重复十三次、递增字节、递减字节、128 个零和 110 个空格。其余十八个未写位置存在不兼容的历史默认值，实际写入前读取这些位置应拒绝，不擅自选择修复变体。源与目标重叠、环绕都保持逐字节复制语义。忽略最后已消费字节中的剩余标志或位填充，拒绝额外完整字节。容器仍须检查声明的输出大小和 CRC。

## 资源、失败和验收

原语分别限制压缩及解码大小为 24 GiB，累计工作为 96 GiB 单位。LH4–LH7 准入字典加 64 KiB，LArc 为字典加 32 KiB，覆盖历史初始化标志、输入缓冲和控制状态，调用者只能收紧。位字段、码树构造、重复展开、字典初始化及输出先扣工作量；容器可通过 `work_remaining()` 跨成员及失败保留同一份实际工作预算。分配前准入内存及字段数量，每次读取最多返回 8192 字节。

LH3 准入字典加 64 KiB，动态 LH1/LH2 保守准入 192 KiB。一个载荷实例跨成员、重复请求和 LH2 探测，共用 24 GiB 实际输入、24 GiB 解码工作、96 GiB 算法工作硬预算，元数据重扫也计入输入。LH2 另准入最多 24 GiB 实际 SHA 压缩块字节，包含结束填充，并通过辅助工作接口上报。丢弃候选以 `charge_skipped` 扣解码工作，最终交付仍普通写入，不授予预付额度。任何载荷前比较完整源和扫描快照，最终失败使实例终止。

协作回调覆盖无需新源读取的有界计算，仅重试无附加错误的 `Interrupted`，类型化中断保留原错误对象并终止。源、预算、取消、损坏和接收端错误不授予回退或继续使用部分状态的权限。调用者须读到 EOF，验证声明的载荷 CRC，并在成功前私有保留输出。CRC-16 用于意外损坏检测，不能证明真实性或密码正确，反射多项式为 `0xa001`，初始值零，无最终异或。

[验收要求](../qa/acceptance.md)中的 `FORMAT-LHA` 分别约束原语互操作、容器和实际 runtime/CLI/Qt 接入。原语测试不能证明产品入口、写入、密码、分卷、其他平台或发行许可。参考结果与工作包进度记录在 issue，生成证据只放 `build/` 或 CI。
