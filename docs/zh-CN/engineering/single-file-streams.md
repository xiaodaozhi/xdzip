# 单文件压缩流与 ZIP 衍生包

[内置能力表](format-registry.md)将普通 GZIP 与 TAR.GZ 分开登记。`xdzip-codec-stream` 将独立 `xdzip-compression` 中的 [RFC 1952](https://www.rfc-editor.org/rfc/rfc1952) 实现接入元数据、内容解码和创建契约，生产依赖闭包不引入参考压缩库。

## 探测与读取边界

GZIP 探测最多读取 256 KiB 压缩输入和 512 字节解码前缀。有效的传统 TAR 头或明确的 `ustar` 标识选择 TAR.GZ，已识别的 TAR 损坏时直接失败，不降级为普通文件。其他内容先完整扫描 GZIP，再发布一个普通文件条目。完整解码流全零且至少 1024 字节时，优先解释为空 TAR；只有零前缀、随后出现非零普通数据时仍为 GZIP。这种内容歧义无法仅靠字节完全消除，规则固定且不依赖文件名。

扫描时，物理输入长度和实际解码字节分别限制为 24 GiB。`ControlledStream` 在读取前检查取消并保留第一个明确类型的错误。解码量恰好到达边界时，可在内部检查额外一个解码字节以区分 EOF 和超限，该字节不会交给调用方。TAR 使用同一受控流，选择原样读取或 GZIP 过滤。必须完整到达 EOF，逐成员校验 CRC32 与 ISIZE，包括空成员；串联成员形成一个逻辑文件。头标志、有界可选字段、头校验、截断及非成员尾随字节继续由独立 GZIP 解码器检查。

条目尺寸使用完整解码后观察到的字节数，不使用 32 位 ISIZE 代替。宿主可通过 `ReadSource::source_name_hint` 提供文件基本名，格式层忽略 ASCII 大小写移除结尾 `.gz`，拒绝分隔符、控制字符和特殊名称，否则使用 `content`。忽略头部 FNAME，展示文本另行转义，最终名称仍通过宿主的可移植路径和目标检查。名称提示不授予文件系统权限。内容解码绑定不可变条目、压缩长度和观察尺寸，成功前再次校验 EOF，失败或完成后不得继续解码。任务仍限制每个文件 8 GiB、整个任务 20 GiB。

## 创建与提交

普通 `.gz` 创建只接受一个普通文件，使用 Deflate 0/1/6/9 级别。拒绝目录、多个文件、密码、分卷、固实和文件名加密。编码器通过 EOF 读取冻结输入，检查精确尺寸和取消，并在宿主私有暂存中完成 GZIP 尾部。宿主校验暂存压缩流、源版本和输出事务后才发布。GZIP 不保留输入文件名，重新打开的虚拟名称取自归档基本名，因此创建校验要求普通文件身份和尺寸一致，不强求与原输入名称相同。普通 GZIP 不提供归档修改能力，TAR.GZ 的创建与重写沿用独立容器契约。

桌面创建选项、欢迎页标签和关联候选从稳定格式标识生成，共享格式下拉框使用既有控件尺寸参数。CLI 创建读取同一后缀登记，优先匹配最长后缀，保证 `.tar.gz` 不被 `.gz` 遮蔽。冲突改名保留实际登记后缀，包括 `.tgz`。

## ZIP 衍生入口

`.xpi`、`.apk`、`.ipa` 和 `.cbz` 接入既有 ZIP 读取链路，继续遵守 ZIP 的内容校验、Store/Deflate、已准入 WinZip AES-256 组合、路径处理和资源边界。扩展名不授予新算法或加密能力，这些操作不解释包清单、安装行为或包签名。别名不增加创建后缀。Windows 复用 ZIP 图标，macOS 登记扩展名并查询该扩展名实际分配的类型，不修改所有 ZIP 的默认处理程序；Linux 使用对应可用 MIME 候选，IPA 沿用通用 ZIP 关联。

## 自动化验收

流格式测试使用独立参考读写器验证成员校验、截断、尾随字节、输入变化、取消、精确预算和虚拟名称。运行时测试覆盖分类、空 TAR 优先级、单文件创建、检查、解压和拒绝时不发布。真实 CLI 回归覆盖四档级别和 ZIP 别名。Qt 测试覆盖稳定标识选择、单文件准入、实际创建与重新打开、原生辅助功能元数据、键盘选择及中英文 100/125/150% 字号布局。生成声明、安装映射、窗口和共享控件契约分别自动检查。实际执行结果写入工作 issue，不将这些检查扩大为未执行平台或发行许可的通过结论。
