# 单文件压缩流与 ZIP 衍生包

[English](../../engineering/single-file-streams.md) | 简体中文 | [繁體中文（台灣）](../../zh-TW/engineering/single-file-streams.md)

[内置能力表](format-registry.md)将普通 GZIP 与 TAR.GZ 分开登记。`xdzip-codec-stream` 将独立 `xdzip-compression` 中的 [RFC 1952](https://www.rfc-editor.org/rfc/rfc1952) 实现接入元数据、内容解码和创建契约，生产依赖闭包不引入参考压缩库。

## 探测与读取边界

GZIP 探测最多读取 256 KiB 压缩输入和 512 字节解码前缀。有效的传统 TAR 头或明确的 `ustar` 标识选择 TAR.GZ，已识别的 TAR 损坏时直接失败，不降级为普通文件。其他内容先完整扫描 GZIP，再发布一个普通文件条目。完整解码流全零且至少 1024 字节时，空 TAR 与全零普通文件存在字节歧义。只有完整验证压缩流后，才用同一外层过滤器下最长已登记后缀选择视图：明确普通后缀保留文件，TAR 后缀保留容器，未知或缺失名称继续空 TAR 优先级。只有零前缀、随后出现非零普通数据时仍为 GZIP。提示不能覆盖 TAR 强识别、坏压缩、校验、配额或源权限。

扫描时，物理输入长度和实际解码字节分别限制为 24 GiB。`ControlledStream` 在读取前检查取消并保留第一个明确类型的错误。解码量恰好到达边界时，可在内部检查额外一个解码字节以区分 EOF 和超限，该字节不会交给调用方。TAR 使用同一受控流，选择原样读取或 GZIP 过滤。必须完整到达 EOF，逐成员校验 CRC32 与 ISIZE，包括空成员；串联成员形成一个逻辑文件。头标志、有界可选字段、头校验、截断及非成员尾随字节继续由独立 GZIP 解码器检查。

条目尺寸使用完整解码后观察到的字节数，不使用 32 位 ISIZE 代替。宿主可通过 `ReadSource::source_name_hint` 提供文件基本名，格式层忽略 ASCII 大小写移除结尾 `.gz`，拒绝分隔符、控制字符和特殊名称，否则使用 `content`。忽略头部 FNAME，展示文本另行转义，最终名称仍通过宿主的可移植路径和目标检查。名称提示不授予文件系统权限。内容解码绑定不可变条目、压缩长度和观察尺寸，成功前再次校验 EOF，失败或完成后不得继续解码。任务仍限制每个文件 8 GiB、整个任务 20 GiB。

## 创建与提交

普通 `.gz` 创建只接受一个普通文件，使用 Deflate 0/1/6/9 级别。拒绝目录、多个文件、密码、分卷、固实和文件名加密。编码器通过 EOF 读取冻结输入，检查精确尺寸和取消，并在宿主私有暂存中完成 GZIP 尾部。宿主校验暂存压缩流、源版本和输出事务后才发布。GZIP 不保留输入文件名，重新打开的虚拟名称取自归档基本名，因此创建校验要求普通文件身份和尺寸一致，不强求与原输入名称相同。普通 GZIP 不提供归档修改能力，TAR.GZ 的创建与重写沿用独立容器契约。

桌面创建选项、欢迎页标签和关联候选从稳定格式标识生成，共享格式下拉框使用既有控件尺寸参数。CLI 创建读取同一后缀登记，优先匹配最长后缀，保证 `.tar.gz` 不被 `.gz` 遮蔽。冲突改名保留实际登记后缀，包括 `.tgz`。

## ZIP 衍生入口

`.xpi`、`.apk`、`.ipa` 和 `.cbz` 接入既有 ZIP 读取链路，继续遵守 ZIP 的内容校验、Store/Deflate、已准入 WinZip AES-256 组合、路径处理和资源边界。扩展名不授予新算法或加密能力，这些操作不解释包清单、安装行为或包签名。别名不增加创建后缀。Windows 复用 ZIP 图标，macOS 登记扩展名并查询该扩展名实际分配的类型，不修改所有 ZIP 的默认处理程序；Linux 使用对应可用 MIME 候选，IPA 沿用通用 ZIP 关联。

## XZ 准入与线格式契约

XZ 能力须遵循 [Tukaani 格式 1.2.1](https://tukaani.org/xz/xz-file-format-1.2.1.txt)。分配解码器前验证流标志和头部 CRC，拒绝保留位、非规范或溢出的九字节变长整数、不支持的过滤器和超预算字典。块头为 8–1024 字节，包含已验证 CRC、可选非零压缩尺寸、可选解码尺寸、最多三个保持尺寸的 Delta/BCJ 过滤器后接 LZMA2，以及全零头部填充。LZMA2 结束标记决定精确压缩边界，可选尺寸须与实际处理量一致。原有 7z 严格构造器与未知尺寸成员解码分开，仅验证结束后允许交还未消费的输入。

验证块填充、声明的内容校验（None、CRC32、CRC64 或 SHA-256）、索引各记录与实际未填充尺寸和解码尺寸、索引填充和 CRC、流尾反向尺寸、标志、CRC 和魔数，以及串联流和四字节全零流填充。None 没有内容校验和，不得展示为内容校验保证。流数和每流块数分别限制为十万，固定解析和过滤缓冲计入 128 MiB 工作内存准入，并保留取消及独立输入输出预算。失败后流不可继续，完整验证及源检查前解码内容只能保留在宿主暂存区。创建须执行真实 LZMA2 压缩，使用有界且独立重置的块并声明内容校验和；独立工具解码并核对输出后才能认定编码器验收通过。

ZIPX 沿用 ZIP 记录语法与物理身份。按 [APPNOTE 6.3.10](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT) 分方法准入，包括 BZip2 12、LZMA 14、XZ 95。LZMA 属性头与独立 LZMA 不同，通用标志第 1 位控制 EOS 要求。已准入的数据描述符配置必须使用 EOS，本地记录已知尺寸时可省略。仍须验证精确负载范围、本地与中央记录一致性、描述符、解码尺寸和 ZIP CRC。没有已验证实现的方法保持逐记录不支持，后缀不能启用其他算法或加密配置。

XZ（`.xz`）和 TAR.XZ（`.tar.xz`、`.txz`）按上述配置提供浏览、检查和提取。创建使用 CRC64、不超过 16 MiB 的独立块以及 LZMA2 1/6/9 级，拒绝级别 0、密码和分卷。普通 XZ 仅接受一个普通输入文件，虚拟输出名称来自宿主文件名；TAR.XZ 通过既有 TAR 写入器接受普通文件和目录，两者均不支持修改。ZIPX 将 `.zipx` 登记为 ZIP 候选，在既有 Store/Deflate 之外读取未加密方法 9、12、14、95。新增方法不能启用修改，也不扩展既有 AES-256 Store/Deflate 组合。PPMd I、JPEG 和 WavPack 仍明确不支持。

## 新增只读过滤器的准入契约

BZip2（`.bz2`、`.bz`）、LZMA Alone（`.lzma`）和 Lzip v1（`.lz`）当前只读，TAR 组合接受 `.tar.bz2`、`.tar.bz`、`.tbz`、`.tbz2`、`.tar.lzma`、`.tlz` 和 `.tar.lz`。后缀只提供入口，歧义缩写由实际字节决定。适配复用独立算法，在分配前准入算法工作内存，限制为 128 MiB，沿用既有流字节预算，串联成员最多 100,000 个。BZip2 校验逐块和组合 CRC，允许串联完整流。LZMA Alone 遵守 [13 字节格式](https://github.com/tukaani-project/xz/blob/master/doc/lzma-file-format.txt)，前五字节为属性和字典，后八字节为小端原始尺寸。全一尺寸必须有 EOS，已知尺寸允许合法 range 终止或 EOS，拒绝尾随数据。此格式只提供结构和可读性校验，不提供内容校验和。Lzip v1 遵守[格式规范](https://datatracker.ietf.org/doc/draft-diaz-lzip/02/)，检查固定 LZMA 属性、编码字典边界、EOS 以及尾部 CRC32、解码尺寸和完整成员尺寸，其他版本明确拒绝。串联 Lzip 成员组成一个逻辑文件。

算法的成员读取器只有在 EOF 验证成功后，才可交还未消费输入，不得吞掉后续容器字节。独立构造入口必须保留既有 7z 读取器对完整压缩范围和已知尺寸的严格约束，并用前缀发现及畸形输入测试证明两种入口隔离。TAR 复用这些过滤器作为只读组合，压缩 TAR 解析失败不得降级为普通文件成功。LZMA Alone 没有强魔数，不得抢占有效 TAR 头、ZIP SFX 或其他强容器识别。能力表及产品入口声明须有对应实现与自动化验收，并登记检查强度与压缩尺寸未知状态，为 CLI 和界面生成一致信息。弱识别排除已知原始尺寸达到 256 GiB 的 LZMA，实际工作预算仍采用更小的既有边界。Windows 和 macOS 为新增只读候选复用既有无格式字样的通用归档图标。

## 自动化验收

流格式测试使用独立参考读写器验证成员校验、截断、尾随字节、输入变化、取消、精确预算和虚拟名称。运行时测试覆盖分类、空 TAR 优先级、单文件创建、检查、解压和拒绝时不发布。真实 CLI 回归覆盖四档级别和 ZIP 别名。Qt 测试覆盖稳定标识选择、单文件准入、实际创建与重新打开、原生辅助功能元数据、键盘选择及中英文 100/125/150% 字号布局。生成声明、安装映射、窗口和共享控件契约分别自动检查。实际执行结果写入工作 issue，不将这些检查扩大为未执行平台或发行许可的通过结论。

LZ4 与 TAR.LZ4 遵循[标准帧契约](lz4-streams.md)，读取独立块、关联块、声明的校验、串联和 skippable 帧。创建使用真实 LZ4 压缩，输出 256 KiB 独立块、块与内容 XXH32，提供 1/6/9 级。普通 LZ4 只接受一个普通文件，TAR.LZ4 复用共享 TAR 写入器；均不支持修改、密码或分卷。检查仅验证流声明的校验和，旧式帧和外部字典尚不支持。

Zstandard（`.zst`）与 TAR.ZST（`.tar.zst`、`.tzst`）遵循 [Zstandard 压缩流契约](zstandard-streams.md)。读取准入有界标准帧原始/RLE/压缩块、Huffman/FSE、重复偏移、窗口历史、声明的校验、串联和 skippable 帧。创建使用真实 LZ/FSE，提供 1/6/9 级、128 KiB 窗口和必需 XXH64，普通 Zstandard 仅接受一个普通输入文件。两者均不支持修改、密码或分卷。非零字典编号、不可用外部历史和超预算窗口明确拒绝，检查仅验证声明的校验，不承诺格式中缺失的校验保证。
