# Settings window and UI language

When no main window is visible, ownerless Settings and About windows opened from the tray center their complete native frame in the work area of the screen containing the pointer. They reuse OperationWindow screen placement and recenter after native creation and height determination. The height cap uses the selected QScreen actual available height and existing margin, rather than the combined virtual desktop, without restoring hidden or minimized main windows. Owned entry points retain their caller placement, dimensions and density.

Settings uses a nonmodal standalone system window. The title bar, application menu and tray reuse the same visible window. The sidebar contains Appearance, General, Privacy, File Associations, Network and About in that order; all About entries open the About page of the same settings window. Logical width is 612 and client height 532, constrained when screen space is insufficient. Sidebar and body scroll independently, meet without extra space at the top, and have no footer, Save or Cancel button. See [settings designs](../../design/hifi/sources/settings.html) and [layout tokens](../../specs/visual/layout-scale.json).

Theme, font size, list density, language, opening mode, tray and recent-history switches persist and apply on interaction; closing does not undo successful changes. Language immediately refreshes product text, application-owned native menus and tray menus without affecting running tasks; system-owned menu items follow system language. Opening mode affects subsequent open entries and the title-bar plus button without migrating existing sessions. Clearing recent history acts immediately without deleting original files. Clear and settings-write failures appear on the page, preserving existing data and actual settings. Checkboxes use IntentCheckBox; theme and proxy radio buttons use IntentRadioButton. Mouse, keyboard and native accessibility press/toggle must submit the same selection intent and verify the model, not merely change graphics. Dropdowns continue using OperationSelect, submitting once after selection confirmation.

Settings persistence uses schema 1, preserves unknown keys, includes network proxy and mirror addresses and stores no passwords. Saving holds a separate configuration lock, stages a complete INI in the same directory and atomically updates backup and primary files. Read failures, sizes above 1 MiB, invalid or newer schemas, symlinks, backup failures and commit failures reject overwriting the original. Application failures restore runtime state. Recent paths are separately stored in recent.json in the same directory, deduplicated, limited to 20 records and 64 KiB reads, and readable/writable only by the user. Disabling recording stops additions; Clear deletes existing records.

Staging retains original bytes as an immutable input snapshot, copies all keys into a separate new candidate INI and then applies changes, without rewriting the freshly created snapshot. Schema validation and unknown-key preservation remain; backups retain original bytes.

On Windows, atomic replacement rename failures due to transient contention such as read handles without delete sharing receive at most four retries with 75 ms total backoff, excluding I/O. The configuration lock remains held; each attempt stages the same bytes into a new file without processing GUI events or falling back to direct overwrite. Persistent contention or other errors preserve the original file and applied settings and report failure.

File associations show the current system default app. macOS requests changes through the system default-app interface and requeries after cancellation or failure rather than assuming consent; when disabling, the user chooses another app. CAB preferentially queries supported types recognized by the system to avoid displaying a default different from actual files. Development copies do not register optional handlers and therefore cannot change them. Windows opens system Default Apps settings for the user to confirm, without writing protected UserChoice. Linux uses desktop MIME settings; disabling lets the user choose another installed desktop app. `.tar.gz` and `.tgz` can share a system type, so a change may affect both; Windows associates by the final `.gz` extension. On refusal, missing installation or cancellation, the actual queried result governs the UI. Installation and uninstall do not independently change default choices; see [installation and associations](../engineering/installers-associations.md).

Windows installed per-format association descriptions follow the application's Chinese or English selection after successful language changes, and Setup reads the saved language on installation or upgrade. The application updates only nine verified ProgID descriptions belonging to its current installation, without changing default handlers. System or other applications' type descriptions, caches and other platforms' displays are not directly controlled by this setting. See [installation and file associations](../engineering/installers-associations.md) for prerequisites and failure boundaries.

Network offers no proxy, system proxy, custom HTTP or SOCKS5 proxy, and an optional HTTPS GitHub mirror. Custom proxies require a host and port and do not accept credentials; save addresses after input and validation. An empty mirror uses official addresses directly. A nonempty mirror changes update transport addresses only, without changing checksum or signature boundaries. In-progress updates retain their network configuration; the next operation uses new settings. macOS Sparkle can use only the system proxy; other selections offer verified manual downloads without claiming automatic installation used that proxy. See [software updates](../engineering/software-update.md) for trust and redirect policy.

The six page bodies do not repeat sidebar page names or retain separators beneath old titles. About reserves scrollable space for update status and actions according to current language, font size and available width. The primary update action remains right of status: “Cancel check” while checking; “Download update”, “Download and install update” or “Go to releases” after discovery according to trust and installation capability; “Cancel download” during download with progress below; and “Open download location” or “Install update” after download, retaining open-folder as a secondary action when installable. Other cancellable phases retain cancellation; installation handoff does not. Recovery retains release-page and available download-location entries. Clicking check, download or cancel and switching states preserves scroll position unless the user scrolls; total scroll height and thumb height also stay stable. Keyboard focus on offscreen controls still scrolls them into view, and bottom content such as licenses remains reachable.

About exposes its update-status text as a native accessible name, synchronizing it with displayed checking, downloading, installing, success or failure state and language.

macOS manual-update guidance shows the first unmet installation condition and retains release-page and download-location actions. Several conditions can be unmet; identity failure does not identify the particular underlying cause. Guidance covers the matching DMG and manual app.zip replacement and makes clear that download is not installation.

The settings body's vertical scrollbar sits at the right edge and spans the viewport; its thumb follows scrolling and can be dragged to scroll. The About version-information grid sizes its label column to actual text and font size. Values use remaining width and may wrap; new fields use the same layout.

All static product text uses stable IDs in `resources/i18n/zh-CN.json` and `en-US.json`; QML uses `qsTrId`, C++ `qtTrId`. Protocol codes, filenames, paths and user content are not translated. Language options are “自动识别”, “中文 (简体)” and “English (US)” in that order, defaulting to auto-detect. Persisted `locale/language` is `auto`, `zh-CN` or `en-US`; effective language is resolved separately. Automatic mode reads the preferred `QLocale::system().uiLanguages()` entry: all Chinese regions use Simplified Chinese, all English regions English (US), and other languages or an empty list fall back to English (US). Application numeric locale set via `QLocale::setDefault()` does not affect detection. Auto resolves again on every launch; switching back to auto or choosing manually applies immediately. Failed saves restore prior effective language and selection mode. Future languages extend the shared supported list and both UI option sets; no historical settings migration is added here.

Font sizes are 100%, 125% and 150%; historical 200% reads as 150%. System file pickers follow system language independently of application language. macOS bundles declare zh-Hans and en and allow mixed localization. Qt standard controls load available translations for the system locale without modifying the user's AppleLanguages.

Acceptance covers six tabs, no footer, all entries and cross-session About, immediate save and reopen, rollback on save failure, immediate language change, theme and font sizes, system confirmation and refresh for nine associations, proxy/mirror inputs, all update states, both languages and 150% text. Use QAccessibleActionInterface to actually operate radio buttons and switches and check model, mutual exclusion and events. Check real desktop and system-default-app behavior on each platform as needed; HTML and component tests do not stand in for unperformed desktop operations. Screenshots and evidence go only to build/ or CI artifacts.
