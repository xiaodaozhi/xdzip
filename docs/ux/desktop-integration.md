# System menus and tray

Multi-session, single-instance, window state and global exit follow the [application session contract](../engineering/application-sessions.md). Closing a non-last main window retains tasks; the last window follows tray settings. Exit confirmation covers all sessions.

Explicit system, menu and tray Quit can open global confirmation over an owned task password or conflict prompt; Return preserves the task and prompt. On macOS the application-menu Quit item and Command-Q remain available for these prompts. File selectors and other modal controls must first complete or be cancelled; Quit triggered while blocked must not execute later after the modal closes.

The macOS menu bar and tray on all three platforms use native OS menus while retaining the existing main-window title bar. See [desktop integration parameters](../../specs/visual/desktop-integration.json), the [interaction design](../../design/html/desktop-integration.html) and [high-fidelity entry](../../design/hifi/sources/desktop-integration.html). Native fonts, row heights, menu widths and system highlights do not use in-app CommandMenu density parameters; HTML explains interaction and is not native pixel acceptance.

macOS menus are xdzip, File, Edit, View, Actions, Window and Help. Help offers “User guide” and “Report issue”, opening the project README and Issues in the default browser without submitting feedback; after a separator, “About xdzip” opens the About page of the same settings window used by application and tray menus. Help's About uses NoRole and stays in place; the application menu uses AboutRole, PreferencesRole and QuitRole, while the system supplies Services, Hide and Show All. File includes Open, New, Recent, Close Archive and Close Window. Edit offers Undo, Redo, Cut, Copy, Paste, Select All and Find according to current text focus. View includes list, grid and preview. Actions includes extract all, extract selected and metadata preflight. Window includes minimize, zoom, main window, tasks and visible product windows.

Menus and existing UI use a unified command entry and recheck capability on opening and before activation. ⌘W closes the current window; ⇧⌘W closes the archive. Text editing must not accidentally affect file selection. Modal windows block main-window commands; disabled items have no appended explanation line. Recent files appear only when recording is permitted and paths are not additionally copied or uploaded. Copy uses zh-CN/en-US resources; system-owned items follow system language.

After successful language save, the existing menu bar, application-owned About/Settings/Quit items, tray menu, task submenu and tray tooltip switch immediately. A failed save retains the previous language. Commands, shortcuts, task identities and running tasks remain unchanged. System-owned macOS items such as Services and Hide and native file pickers continue to follow system language.

Tray is enabled by default and settings changes take effect immediately after successful save. Schema 1 adds desktop/trayEnabled, defaults old configurations to true, preserves unknown fields and uses atomic saving. The menu offers show main window, open, create, tasks, settings, about and quit. Tasks use real controller data and agree with task details. On macOS click opens the menu; on Windows/Linux ordinary activation restores the window and right-click opens the menu. Task completion does not automatically notify or steal focus.

When the tray is available, closing the last main window clears that window's browsing tabs and operation-window drafts, then hides it; showing it again retains only one start page. Background tasks and their session identities continue and can be explicitly opened from the global task entry. Minimizing does not clear tabs. When a modal or file picker exists, activate the blocking window first. Explicit quit, system quit and restart bypass hiding and continue existing task confirmation and asynchronous joins; cancelling exit restores residency policy. Disabling the tray first restores a hidden main window. Without a tray, normal closing resumes; if the tray disappears while running and the window is hidden, restore the main window. The macOS Dock remains; clicking it or reopening through a file association can restore the app. Test probes finish using explicit exit semantics rather than depending on residency settings.

Tray glyphs derive from the existing brand mark. macOS uses a template icon; Windows and Linux use white fill with a dark outline and multiple bitmap sizes for light, dark and colored system panels. Windows does not depend on application theme or registry theme readings and retains contrast when system theme information is unavailable. Icons do not blink or animate continuously.

The View menu retains a non-collapsible separator after “File Preview and Properties” to separate AppKit's automatically appended fullscreen command, preventing the system fullscreen icon from reserving an extra icon column for preview. Preview text aligns with list and grid; the system still draws checkmarks. Do not compensate with spaces, fixed widths or custom menus. HTML/high-fidelity interactions express application commands only; native desktop verification covers system-appended items.

## Verification

When an application-owned Qt Quick window hides or minimizes, synchronously end pointer hover and clear old positions in buttons, MouseArea, HoverHandler and tooltips. Before first restored-frame synchronization, reconcile against the actual system pointer position rather than reusing old hover colors or coordinates. Late native enter events are normalized against actual position until real mouse movement or a press supplies current coordinates. This applies to main and operation windows without changing focus, button bindings or native file pickers.

On Windows, tray hiding retains the native window, state, QML objects, controllers and background tasks. While hidden, opacity is masked until the first newly submitted frame after restoration, preventing DWM from briefly revealing the previous frame. Clearing hovered alone cannot prevent this. A new hide invalidates old frame callbacks. This policy applies only to tray hiding, not minimizing or visible windows, and uses no screenshot readback, fixed delay or system-animation override.

Backends without a global system pointer treat injected events as authoritative rather than overriding them with physical cursor queries. Offscreen/minimal component checks remain separate from actual native DWM, Cocoa and X11 window acceptance.

Automation covers menu structure and roles, state synchronization, command and edit routing, configuration compatibility and cancellation, residency and exit policies, no-tray fallback, task menus, modal blocking and restart. Native desktop checks separately verify the macOS menu bar and Dock restore, Windows notification area and Linux StatusNotifier/XEmbed, light/dark appearance, high DPR, keyboard and screen readers. Offscreen verification is not native desktop acceptance; screenshots and reports go only to build/ or dist/.

Native edit roles use the application's language catalog only in `QCocoaMenuItem` Cut, Copy, Paste and Select All translation contexts. `QCocoaMenuBar/Edit` uses the same title so Qt text-role detection and Edit-menu recognition do not depend on system language. System file pickers and other Qt controls continue using qtbase translations for the system locale. Verify both a Chinese app with an English system and an English app with a Chinese system without modifying the user's global AppleLanguages.

The tray tooltip is `xdzip (活动中的任务: %1)` in Chinese and `xdzip (Active tasks: %1)` in English; the task menu is `任务 (活动中的任务: %1)` and `Tasks (Active tasks: %1)` respectively. Counts come from real application-wide active tasks, including tasks still running after their browser page closes; completed results do not count as active.
