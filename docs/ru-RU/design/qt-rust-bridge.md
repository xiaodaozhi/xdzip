# Мост Qt/Rust и служба приложения

[English](../../design/qt-rust-bridge.md) | [简体中文](../../zh-CN/design/qt-rust-bridge.md) | [繁體中文](../../zh-TW/design/qt-rust-bridge.md) | [日本語](../../ja-JP/design/qt-rust-bridge.md) | [한국어](../../ko-KR/design/qt-rust-bridge.md) | [Français](../../fr-FR/design/qt-rust-bridge.md) | [Deutsch](../../de-DE/design/qt-rust-bridge.md) | [Español](../../es-ES/design/qt-rust-bridge.md) | [Português (Brasil)](../../pt-BR/design/qt-rust-bridge.md) | Русский

Настольное приложение Qt вызывает среду Rust через скомпонованный мост `cxx`. Каждый `BrowserController` владеет `RuntimeConnection` с отдельным экземпляром службы. Мост передаёт типизированные команды и результаты с передачей владения внутри процесса приложения. CLI напрямую использует ту же службу Rust. [Архитектура системы](../../design/system-architecture.md), [Сеансы приложения](../../engineering/application-sessions.md)

<a name="xdzip-handles-threads-and-ownership"></a>

## Дескрипторы, потоки и владение

`new_runtime()` запускает потоки команд и задач Rust. Временный `Runtime` выдаёт по одному `CommandClient` и `EventReceiver`. Поток интерфейса использует дескриптор команд. Выделенный поток приёма Qt владеет дескриптором событий и блокируется в `next_event()`. Поток команд Rust владеет текущим архивом и его индексом. Отдельный поток задач владеет подготовленной работой во время её выполнения.

CXX передаёт типы значений и владеющие контейнеры Rust. Принимающий код Qt хранит или преобразует значения, пока владеет ими. Дескрипторы архивов и нативных файлов в Qt не переходят. При передаче ID и точного числа байтов в QML контроллер использует строки для значений, которым нужно сохранить все 64 бита. Созданные заголовки и статическая библиотека собираются вместе с хостом. Этот интерфейс принадлежит сборке продукта. Входящий в комплект рабочий процесс использует отдельный [протокол процесса](../engineering/native-codecs.md).

[Объявления и преобразования моста](https://github.com/xiaodaozhi/xdzip/blob/main/crates/xdzip-qt-bridge/src/lib.rs), [Соединение Qt](https://github.com/xiaodaozhi/xdzip/blob/main/apps/desktop/RuntimeConnection.cpp), [Служба Rust](https://github.com/xiaodaozhi/xdzip/blob/main/crates/xdzip-runtime/src/service.rs)

## Идентичность запросов, выборок и задач

| Идентичность | Назначение |
| --- | --- |
| ID запроса | Служба Rust назначает ID при допуске в пределах соединения. `Submission` возвращает `Accepted`, `Busy`, `Closed`, `Invalid` или `Exhausted`. При отказе возвращается нулевой ID. |
| ID сеанса | Определяет снимок открытого архива. Команды, действующие на этот архив, должны ему соответствовать. При новом открытии назначается новый ID сеанса. |
| Идентичность и смещение выборки | Страница связана с сеансом, ID выборки, поколением интерфейса, ревизией и смещением. Контроллер проверяет их до приёма строк. |
| ID физической записи или навигации | Физическая запись сохраняет идентичность при сортировке и переходе по страницам. Синтезированные каталоги имеют собственные идентичности. Индекс строки, отображаемое имя или диапазон выборки никогда не дают доступа к пути файловой системы. |
| ID задачи и запроса ответа | ID задачи принадлежит её соединению. Запрос ответа определяет ожидающее решение конфликта или пароль внутри задачи. Запись задачи приложения также знает владеющий контроллер. |
| Последовательность событий | Получатель назначает монотонно возрастающую последовательность для каждого соединения при извлечении событий. Qt отбрасывает события, последовательность которых не новее последней обработанной. Обновления задач используют ту же последовательность и исходный ID запроса для корреляции. |

<a name="xdzip-commands-in-the-current-bridge"></a>

## Команды текущего моста

| Команда или метод | Назначение и обычный результат |
| --- | --- |
| `Open`, `OpenWithPassword` | Открыть и просканировать выбранный источник. Успешный ответ содержит первую `Page` и ограниченные данные навигации. Зашифрованный каталог может потребовать пароль до открытия сеанса. |
| `Browse` | Начать выборку или продолжить её с совпадающими идентичностью и смещением. Каждая команда возвращает не более одной `Page`, ограниченной 128 строками и 64 KiB имён. |
| `FreezeSelection`, `Preflight` | Разрешить текущие селекторы во владеющие физические или навигационные ID в `Selected` либо свести результаты проверки метаданных в `Preflight`. Снимок и выбранный объём повторно проверяются для фактической операции. |
| `Preview` | Разрешить одну физическую запись. При успехе вернуть ограниченные байты `Preview` с владением вместе с идентичностью записи и сеанса. |
| `CheckTarget`, `InspectInputs` | Вернуть число остатков в `TargetChecked` после открытия и очистки проверочного рабочего пространства средой выполнения. Проверка создания использует нулевой сеанс. `Inputs` сообщает поверхностные метаданные в порядке входов без рекурсивного сканирования каталогов. Ни один ответ не даёт права на фиксацию. |
| `Extract`, `Create`, `Check`, `OpenEntry` | Проверить намерение и поставить задачу в очередь. `TaskAccepted` содержит назначенный ID задачи. Авторизацию цели и фиксацию выполняют среда и слой ввода-вывода. |
| `Update`, `Move`, `Export`, `PublishExport`, `ExportManifest` | Изменения архива и публикация данных поступают в очередь тяжёлых задач. После допуска `Update` или `Move` служба отбрасывает текущий снимок, чтобы следующие запросы не использовали старые ID записей. `ExportManifest` возвращает относительные метаданные передачи как обычный ответ. |
| `Snapshot`, `CloseSession` | Вернуть ID сеанса текущего архива или ноль. Закрытие указанного сеанса отбрасывает его снимок просмотра, а отдельно удерживаемые входы задач могут оставаться активными. |
| `cancel`, `cancel_task`, `decide_task`, `respond_password`, `release_export`, `shutdown` | Методы управления вне обычной очереди команд. Отмена запроса имеет собственный ID и `Finished`; управление задачей действует на существующую задачу. |

Служба Rust предоставляет дополнительные операции CLI, например `Catalog` и `SelectMembers`. Мост проверяет размер входа и значения перечислений до отправки. Например, пути создания ограничены 4 KiB каждый и 4 MiB в сумме. Среда проверяет сеанс и семантику операции, а слой ввода-вывода открывает файлы и получает полномочия на вывод. [Контракт службы среды](../engineering/product-runtime.md), [Контракт CLI](../engineering/command-line.md), [Авторизация файлов](file-security.md)

<a name="xdzip-event-delivery-and-backpressure"></a>

## Доставка событий и противодавление

При обычной доставке допущенный запрос создаёт не более одного результата данных, за которым следует один `Finished`. Ошибка представлена `Finished` с кодом ошибки. Контроллер ждёт успешного завершения перед публикацией соответствующей страницы или предпросмотра. Устаревший результат отбрасывается, но его запрос всё равно завершается. Путь больших индексов кэширует в Qt до 1 024 строк и запрашивает недостающие страницы. Перед подтверждением извлечения он фиксирует выбор между страницами. [Индексирование больших архивов](../engineering/large-index.md), [Предпросмотр содержимого](../engineering/content-preview.md)

`TaskAccepted` и `Finished` относятся к обычной доставке запросов. `TaskUpdate` использует отдельные ожидающие слоты каждой задачи и несёт исходный ID запроса, ID задачи и ID исходного сеанса. Обновление может прийти раньше `TaskAccepted` или позже `Finished`. Контроллер связывает раннюю задачу с исходным запросом и направляет последующие обновления этой задаче. Позднее обновление задачи никогда не завершает обычный запрос повторно. Слоты хранят последний снимок задачи. Ход может объединяться, а конечный снимок сохраняется до извлечения получателем. Запросы ответа присутствуют в снимках, пока задача ждёт ответа. [Состояние задач и отмена](task-scheduling.md)

- **Rust.** Для каждого соединения обычный допуск разрешает 128 ожидающих запросов и бюджет 8 MiB на байты команд в очереди. Бюджет полезных данных обычных событий — 32 MiB. Принятые запросы резервируют место для результата и завершения. Подтверждения отмены запросов имеют собственную ограниченную очередь, а завершению место в ней не требуется.
- **Qt.** Ящик содержит до 256 событий, до 128 событий с полезными данными и 32 MiB учтённых данных. При исчерпании ёмкости получатель ждёт, пока интерфейс освободит место. Одна поставленная в очередь цепочка уведомлений обрабатывает до 32 событий или 4 ms за проход. Уведомление поступает потоку интерфейса, а события в очереди сохраняют собственные данные.

<a name="xdzip-prompts-failures-and-shutdown"></a>

## Запросы ответа, ошибки и завершение

- Решения конфликтов используют `decide_task`. Пароли задач используют `respond_password` и отдельный ID запроса пароля. Оба проверяют текущий запрос без ответа. Ответ с паролем попадает в хранилище Rust, обнуляемое при освобождении, и никогда не появляется в результате или событии хода. `OpenWithPassword`, `Preview` и создание с шифрованием несут входные секреты конкретной операции, которые мост перемещает в соответствующие типы паролей Rust. [Обработка паролей](../engineering/password-extraction.md)
- Стабильные коды описывают результаты допуска, запроса и задачи. Например, `stale_session`, `stale_query`, `source_changed`, `unsafe_target`, `target_changed`, `disk_full` и `password_required`. Контроллер переводит коды для отображения. Изменение источника делает соответствующий снимок просмотра недействительным. `RuntimeFault` и неожиданные разъединения делают ожидающую работу интерфейса недействительной с `runtime_unavailable`; потеря соединения может помешать доставке исходных конечных событий.
- `shutdown` закрывает допуск и отменяет принятую работу, включая задачи, ожидающие ввода. Получатель Qt продолжает извлекать события во время завершения потоков Rust. Получатель Rust ожидает потоки перед выдачей `ShutdownReady`, затем мост выдаёт `End`. Qt сообщает о чистом разъединении после опустошения ящика. При раннем уничтожении соединения оно закрывает ящик и пробуждает получателя, не ожидая его в потоке интерфейса. [Завершение задач](task-scheduling.md), [Жизненный цикл среды](../engineering/product-runtime.md)

При изменениях этой границы [проверка моста](https://github.com/xiaodaozhi/xdzip/blob/main/tools/bridge-probe/README.md), тесты службы Rust и [тесты контроллера приложения](https://github.com/xiaodaozhi/xdzip/blob/main/apps/desktop/tests/browser_test.cpp) охватывают разные уровни. Нужные цели указаны в [руководстве по сборке](../../engineering/developer-build.md).
