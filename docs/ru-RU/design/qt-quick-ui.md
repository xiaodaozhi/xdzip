# Настольный интерфейс Qt Quick

[English](../../design/qt-quick-ui.md) | [简体中文](../../zh-CN/design/qt-quick-ui.md) | [繁體中文](../../zh-TW/design/qt-quick-ui.md) | [日本語](../../ja-JP/design/qt-quick-ui.md) | [한국어](../../ko-KR/design/qt-quick-ui.md) | [Français](../../fr-FR/design/qt-quick-ui.md) | [Deutsch](../../de-DE/design/qt-quick-ui.md) | [Español](../../es-ES/design/qt-quick-ui.md) | [Português (Brasil)](../../pt-BR/design/qt-quick-ui.md) | Русский

Настольное приложение использует Qt Quick для отображения и взаимодействия. Контроллеры C++ преобразуют действия пользователя в запросы и поддерживают состояние представления. Среда выполнения Rust отвечает за интерпретацию архивов, правила задач и полномочия на файлы. Вызовы описаны в [архитектуре системы](system-architecture.md) и [контракте моста](qt-rust-bridge.md).

<a name="xdzip-windows-sessions-and-models"></a>

## Окна, сеансы и модели

| Компонент | Текущая ответственность |
| --- | --- |
| `Browser.qml` и `SessionPage.qml` | Начальная страница, вкладки архивов, путь и поиск, навигация по каталогам, список или сетка, свойства и команды. Страница показывает текущее состояние контроллера и вызывает команды. |
| `ApplicationSessions` | Направляет запросы открытия в независимые сеансы просмотра. Координирует вкладки или окна, общий раздел задач и завершение приложения. Режим открытия действует на последующие запросы. При закрытии страницы представление освобождается, а контроллер задачи может продолжать работу. |
| `BrowserController` и `ArchiveTableModel` | Хранят выбор, состояние списка и идентификатор результата. Небольшие результаты применяются как полная модель. Для больших результатов доступно логическое число строк, при этом одновременно хранится не более 1 024 строк. Недостающие страницы загружаются по запросу. Действия по незагруженным строкам недоступны. |
| `TaskListModel` и окна операций | Представляют ограниченные снимки задач, прогресс, результаты и ожидаемое решение. Составной идентификатор настольного приложения направляет команду задачи ответственному контроллеру. |
| Настройки и адаптеры платформы | Управляют оформлением, языком, размером текста и поведением приложения. Нативные адаптеры отвечают за область уведомлений, активацию, файловые диалоги, ассоциации и передачу данных в зависимости от ОС. |

## Просмотр и выполнение операций

Открытие публикует полный снимок метаданных. У каждого нового запроса поиска, сортировки или навигации свой идентификатор результата. Устаревшая страница не заменит текущую модель. Пока ожидается новый запрос, представление показывает уже применённый результат, если контроллер считает его действительным. Транспорт ядра передаёт не более 128 строк и 64 KiB имён за одну порцию. [Данные предметной области](domain-data.md), [Индексирование больших архивов](../engineering/large-index.md)

Открытие каталога переходит внутрь него. Двойной щелчок по допустимой записи обычного файла или соответствующая команда запускает задачу временного открытия. В свойствах есть отдельное действие предпросмотра. Запросы решения о конфликте и ввода пароля сохраняют идентификатор текущей операции. Ход и результаты доступны через раздел задач, даже когда страница просмотра закрыта. [Просмотр архива](../user-guide/browse.md), [Временное открытие](../engineering/archive-opening.md), [Предпросмотр содержимого](../engineering/content-preview.md), [Окна задач](../ux/task-windows.md)

При перетаскивании в приложение архив открывается или файл становится входом для создания в зависимости от области сброса. Допустимые перемещения внутри архива и перетаскивание из него используют подготовку задачи и передачу, специфичную для платформы. Платформа определяет возможности передачи, включая асинхронное содержимое и запись по месту назначения. [Перенос данных архивов](../engineering/archive-transfers.md)

## Общие элементы управления и нативные границы

Экраны операций используют `OperationButton`, `OperationFooterButton`, `OperationFrame`, `OperationSelect` и `OperationSegmentedGroup`. Общие компоненты определяют размеры и взаимодействие. Общие элементы выбора передают действия мыши, клавиатуры и специальных возможностей в одну модель состояния. Тексты интерфейса и файловые данные следуют правилам шрифтов и локализации из [стандарта дизайна](../visual/design-standard.md). Имена внутри архива остаются данными и отображаются безопасно.

Самостоятельные окна операций следуют реестру окон и собственным правилам модальности и закрытия. macOS использует нативные элементы заголовка окна. Windows и Linux используют свои системные адаптеры. [Контракт окон платформы](../ux/platform-windows.md) определяет приёмку реальных окон, а [контракт интеграции с рабочим столом](../ux/desktop-integration.md) описывает область уведомлений и активацию.
