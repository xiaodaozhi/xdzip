# Модель предметной области и данные архива

[English](../../design/domain-data.md) | [简体中文](../../zh-CN/design/domain-data.md) | [繁體中文（台灣）](../../zh-TW/design/domain-data.md) | [日本語](../../ja-JP/design/domain-data.md) | [한국어](../../ko-KR/design/domain-data.md) | [Français](../../fr-FR/design/domain-data.md) | [Deutsch](../../de-DE/design/domain-data.md) | [Español](../../es-ES/design/domain-data.md) | [Português (Brasil)](../../pt-BR/design/domain-data.md) | Русский

Среда выполнения владеет сеансом архива, готовым индексом и последним запросом этого сеанса. Qt хранит представление результата, а CLI может читать физические записи отдельной командой каталога. Оба передают операции одному сервису Rust. [Архитектура системы](system-architecture.md), [Мост Qt/Rust](qt-rust-bridge.md)

<a name="xdzip-identity-and-source-version"></a>

## Идентичность и версия источника

| Идентичность или данные | Текущее представление и область |
| --- | --- |
| `SessionId` | Ненулевая идентичность времени выполнения для открытого архива. Каждое успешное новое открытие создает новый сеанс. Пути файлов используются для ввода и маршрутизации интерфейса. |
| `SourceVersion` | Среда записывает идентичность, длину и доступные временные метки обычного файла каждой допущенной части. На соответствующих границах чтения и записи она повторно проверяет открытый объект и соответствующий путь. Изменения обнаруживаются по возможности. |
| `EntryId` | Определяет физическую запись архива в сеансе. Записи с одинаковыми именами сохраняют разные идентификаторы. |
| Навигационная идентичность | Представляет индексированный каталог. Виртуальный каталог, созданный по потомкам, может появиться в дереве или списке без идентификатора физической записи. |
| `QueryKey` | Объединяет сеанс, идентификатор запроса, поколение и ревизию снимка. Смещение указывает позицию в этом результате. |
| Идентичность запроса, задачи и приглашения | Сервис назначает номера запросов и задач в пределах соединения. Приглашение принадлежит конкретной задаче. Общий пункт задач desktop использует идентичность сеанса контроллера вместе с номером задачи. |

Типы предметной области обеспечивают ненулевые идентичности архива и запроса. В системном мосте типизированные значения Rust представлены в сгенерированных данных CXX. QML получает непрозрачные строки для идентификаторов, которым нужны все 64 бита. Номер строки — только позиция в конкретном запросе. <a name="xdzip-physical-entries-and-output-names"></a>

## Физические записи и имена вывода

`xdzip-codec-api::Entry` содержит формат, физическую идентичность, представления имени, сведения о размерах, признаки вида файла, сведения об изменении и специфичные для формата поля метода и шифрования. Исходные байты имени, необязательное декодированное написание UTF-8, решение о кодировке и экранированный отображаемый текст хранятся отдельно. Для вывода среда проверяет действующее имя по политике переносимых путей и разрешенному назначению. Неразрешенное имя может оставаться видимым, но извлечение этой записи или каталога отклоняется.

Поле исходного размера имеет отдельный флаг `size_known`, отличающий файл с известным нулевым размером от неизвестного размера. У некоторых сжатых контейнеров нет сжатого размера отдельной записи. Значения метода интерпретируются по формату. Данные времени также сохраняют соглашения формата, например локальное время DOS в ZIP; отсутствующее время остается неизвестным. `payload_supported()` определяет, можно ли декодировать текущую запись. Вывод дополнительно зависит от выбранной операции, состояния источника, имени и правил файловой системы. [Поля записи](../../../crates/xdzip-codec-api/src/lib.rs), [Обработка имен](../engineering/filename-encoding.md), [Разрешения файлов](file-security.md)

<a name="xdzip-index-query-and-page-lifecycle"></a>

## Жизненный цикл индекса, запроса и страницы

Среда открывает источник и завершает ограниченное сканирование до публикации архива и первой страницы. Сканирование можно отменить. Поврежденный конец, отсутствие пароля или изменение источника оставляют операцию без опубликованного частичного индекса. У навигации отдельный бюджет. При его превышении деревом каталогов просмотр корня и физический поиск могут оставаться доступны. Обычный однофайловый ZIP/ZIP64 может хранить до миллиона записей через закрытый дисковый путь. Другие форматы и многотомные пути сохраняют свои пределы.

`Archive::query_page` принимает каталог, текст, режим сортировки, смещение и ожидаемую идентичность запроса. Новый запрос начинается со смещения ноль с новым поколением. Среда строит полный порядок результата и сохраняет один текущий неизменяемый запрос на архив. Страницы разрешают идентичности строк из этого порядка. Поиск и сортировка сохраняют исходные идентичности записей архива. Каждый режим группирует каталоги перед файлами, детерминированно разрешает равенства по идентичности и ставит неизвестные размеры после известных внутри группы.

Общий тип домена `PageRequest` проверяет до 256 строк. Транспорт desktop запрашивает до 128 строк с бюджетом имен 64 KiB. Qt полностью фиксирует небольшие результаты и держит не более 1 024 резидентных строк для больших. Ответы с несовпадающим сеансом, запросом, поколением, ревизией или смещением не могут заменить текущие данные. [Реализация запросов](../../../crates/xdzip-runtime/src/query.rs), [Список и сортировка](../../../crates/xdzip-runtime/src/listing.rs), [Индекс больших архивов](../engineering/large-index.md)

<a name="xdzip-selections-and-operation-input"></a>

## Выбор и вход операций

Модель Qt хранит выбор загруженных результатов по ID, а выбор больших результатов — ограниченными диапазонами текущего результата. Выбрать все охватывает этот результат. Задача может различать весь архив и явно выбранный набор результатов поиска. Rust разрешает межстраничные селекторы по полному ключу запроса через `FreezeSelection` для подтверждения извлечения. Развертывание каталогов разрешает реальных потомков и удаляет повторные физические ID. Превышение предела операции возвращает ошибку. CLI разрешает пути участников и физические ID через `SelectMembers`.

Извлечение, проверка и редактирование готовят задания конкретных операций с необходимыми источником и сохраненными метаданными. Создание получает параметры, затем сканирует и проверяет отдельное `InputTree`. Предварительная проверка метаданных может описать возможные проблемы без предоставления задаче полномочий на вывод. Перед записью среда повторно проверяет входы и получает соответствующее разрешение. После передачи выбора заданию изменения интерфейса не меняют его область. <a name="xdzip-results-and-data-lifetime"></a>

## Результаты и время жизни данных

| Данные | Время жизни |
| --- | --- |
| Текущие архив, запрос и дисковый индекс | Принадлежат сеансу сервиса. Замена запроса или закрытие сеанса освобождает связанные закрытые данные с учетом ресурсов, независимо удерживаемых заданиями. Дисковый индекс метаданных перестраивается при повторном открытии архива. |
| Снимки задач | Среда публикует ограниченные снимки с фактическим состоянием, числами байтов и элементов, состоянием очистки и ограниченным списком подробностей. Desktop сохраняет результаты задач доступными через контроллер-владелец в течение сеанса приложения. |
| Пользовательские настройки | Управляются отдельно от индексов и результатов задач. Хранение и конфиденциальность описаны в контрактах настроек и конфиденциальности. |
| Рабочие области и журналы | Закрытая подготовка вывода и относительные записи публикации поддерживают очистку и проверку. Перезапуск не повторяет незавершенную запись архива. |

<a name="xdzip-design-options-outside-the-current-implementation"></a>

## Варианты дизайна вне текущей реализации

Постепенная публикация поисковых индексов, повторно используемый план с собственной ревизией и токеном запуска и постоянная постраничная история задач являются вариантами дизайна. Текущие команды готовят и ставят в очередь собственные ограниченные задания, держат один текущий запрос и возвращают ограниченные снимки задач. Для постоянного восстановления также потребовался бы отдельный дизайн проверки источника и вывода.
