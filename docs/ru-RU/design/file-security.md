# Авторизация файлов и безопасная публикация

[English](../../design/file-security.md) | [简体中文](../../zh-CN/design/file-security.md) | [繁體中文](../../zh-TW/design/file-security.md) | [日本語](../../ja-JP/design/file-security.md) | [한국어](../../ko-KR/design/file-security.md) | [Français](../../fr-FR/design/file-security.md) | [Deutsch](../../de-DE/design/file-security.md) | [Español](../../es-ES/design/file-security.md) | [Português (Brasil)](../../pt-BR/design/file-security.md) | Русский

Хост контролирует, какие файлы можно открыть и где разрешено опубликовать проверенный результат. Обработчик получает ограниченные устройства чтения и приёмники, в том числе при работе в изолированном процессе архива. Имена, заявленные размеры, контрольные суммы и данные архива являются входными данными. Проверки файлов хостом применяются независимо от проверок формата. [Архитектура системы](system-architecture.md), [Протокол процесса архива](../engineering/native-codecs.md)

<a name="xdzip-authorizing-the-source-and-destination"></a>

## Авторизация источника и места назначения

- **Источник архива.** `Source::open` открывает выбранный путь через `xdzip-io::open_regular_readonly` и проверяет тип открытого файла. В Unix открытие для классификации неблокирующее, поэтому FIFO не может его заблокировать. Выбранный пользователем путь может разрешаться через ссылку к обычному файлу. Поиск разделённых томов ограничен и зависит от формата. Хост фиксирует допущенные соседние части и проверяет их идентичности и версии. Кодек может обращаться только к предоставленным потокам. [Реализация источника](https://github.com/xiaodaozhi/xdzip/blob/main/crates/xdzip-runtime/src/source.rs), [Работа с томами](../engineering/archive-opening.md)
- **Входы создания.** `InputTree` обходит выбранные входы с ограниченными метаданными и идентичностями файлов. При чтении элементы открываются из этого дерева с проверкой версий. Текущий частный каталог подготовки исключается из собственного сканирования входа. Обнаруженное изменение источника останавливает работу. Проверки идентичности, размера и времени обнаруживают изменения по мере возможностей, но не являются полным снимком содержимого. [Дерево входа](https://github.com/xiaodaozhi/xdzip/blob/main/crates/xdzip-io/src/input.rs), [Создание архива](../../engineering/zip-creation.md)
- **Место назначения.** `Grant` удерживает выбранный объект каталога и его идентичность. Извлечение также передаёт идентичности всех исходных томов как защищённые файлы. Создание и редактирование проверяют зафиксированные идентичности входов или исходного архива в своих путях задачи. Подкаталоги и подготовка доступны через удерживаемый каталог; идентичности родителей повторно проверяются перед публикацией. `CheckTarget` и предварительная проверка извлечения могут сообщить полезные сведения до начала задачи. Право записи повторно проверяется во время операции. [Разрешения назначения](https://github.com/xiaodaozhi/xdzip/blob/main/crates/xdzip-io/src/target.rs), [Предварительная проверка извлечения](../engineering/extraction-preflight.md)

## Сопоставление имён, защита платформы и ссылки

1. **Проверить относительное написание внутри архива.** Среда разрешает зафиксированный выбор, при необходимости удаляет префикс выбранного поддерева и с помощью `PortablePath` принимает относительные компоненты UTF-8. Абсолютные пути и пути дисков, управляющие символы, неоднозначные разделители, родительские компоненты, зарезервированные имена устройств и конечные пробелы или точки отклоняются. Проверенное написание — только вход для полномочия назначения.
2. **Спланировать столкновения до создания вывода.** Извлечение сравнивает распространённые варианты регистра и Unicode по ключам NFD в нижнем регистре. Неоднозначные написания каталогов и столкновения файла с каталогом приводят к ошибке подготовки. Варианты обычных файлов приводятся к общему написанию для применения политики конфликта имён. Нативная исключительная публикация по-прежнему решает, доступно ли имя в реальной файловой системе. Отображаемое написание и идентичность физической записи остаются раздельными.
3. **Обойти разрешённое дерево.** Вывод спускается от удерживаемого полномочия каталога, открывая дочерние каталоги без перехода по ссылкам. Корень разрешения, идентичности родителей и ожидаемый конечный объект для перезаписи проверяются повторно. Подменённая цель или небезопасная ссылка отклоняется. Последняя проверка перед переименованием в пределах тома уменьшает гонки. Обычное переименование не гарантирует атомарное сравнение и замену содержимого относительно процесса с правами той же учётной записи.

| Платформа | Проверки объектов вывода |
| --- | --- |
| Linux и macOS | Владельцем должен быть текущий эффективный пользователь. Права записи группы и остальных отклоняются; существующий обычный файл должен иметь одну жёсткую ссылку. macOS также проверяет нативную ACL, включая унаследованные права изменения. |
| Windows | Проверяются точки повторной обработки, владелец, ID файла, число жёстких ссылок обычных файлов и DACL удерживаемых объектов. Эффективные и предназначенные только для наследования правила доступа должны ограничивать изменение доверенными субъектами. Существующее совместное чтение можно сохранить. |
| Частный открытый текст или временная рабочая область | Дополнительные проверки конфиденциальности исключают посторонних читателей. В Windows исключительно созданный частный каталог кэша может получить защищённую DACL. Обычные выбранные пользователем каталоги извлечения сохраняют собственную политику совместного чтения. |

Вывод символических ссылок ZIP ограничен допущенным графом ссылок Unix. Среда проверяет выбранный граф и конечные объекты, которые должны отсутствовать, до публикации ссылок; обычные цели фиксируются первыми. Задача никогда не следует по созданной архивом ссылке для записи содержимого. Другие неподдерживаемые профили ссылок и специальных файлов явно завершаются ошибкой. Обычные режимы файлов POSIX могут восстанавливать безопасные биты чтения и выполнения в подготовке наряду с чтением и записью владельца. Биты привилегий и внешней записи исключены. Путь извлечения не восстанавливает временные метки после фиксации.

## Подготовка, проверка и фиксация

Разрешение назначения создаёт исключительное частное рабочее пространство на том же томе. Хост учитывает вывод кодека в подготовительном файле. До публикации должны успешно завершиться декодирование, проверка ожидаемого размера и предоставляемые форматом проверки целостности или аутентификации. `Stage::finish` сбрасывает и синхронизирует файл и сохраняет его проверенную версию. При фиксации хост повторно проверяет подготовку и место назначения. Синхронизация данных и атомарная видимость одного файла не доказывают сохранность метаданных каталога при потере питания.

| Операция | Семантика публикации |
| --- | --- |
| Извлечь или опубликовать обещанный файл | Публиковать каждый подходящий файл после проверки. Без перезаписи исключительно создать жёсткую ссылку на том же томе, затем удалить частную подготовительную ссылку. При перезаписи извлечение требует ожидаемый безопасный обычный файл и заменяет его переименованием на том же томе без предварительного усечения. Обещанный файл всегда публикуется без перезаписи. Отсутствие нужной операции файловой системы или изменение цели приводит к ошибке соответствующей записи. Общего отката уже опубликованных файлов или созданных каталогов для всей задачи нет. |
| Создать единый архив | Закодировать в подготовке, вновь открыть и проверить ожидаемые записи и содержимое профиля создания, затем один раз опубликовать архив целиком. При конфликте можно выбрать новое имя или разрешить допустимую замену. Защищённый вход не может стать целью перезаписи. |
| Создать разделённые тома | Проверить содержимое подготовленного архива, подготовить каждую часть и опубликовать новый плоский набор без перезаписи существующих томов. Части становятся видимыми по отдельности. При частичной ошибке откат пытается удалить только новые опубликованные объекты, идентичности которых всё ещё совпадают. Ошибка отката может оставить неопределённый результат. |
| Изменить существующий архив | `ArchiveUpdate` связывает разрешённый родительский каталог и ожидаемую версию исходного архива. Повторно открыть и проверить переписанный архив, затем один раз заменить оригинал через это полномочие. Обычное извлечение не может использовать этот специальный путь замены для перезаписи источника. |

Отмена до барьера публикации предотвращает текущую фиксацию. Уже выполняемая публикация может завершиться и сообщить фактический результат. Ранее зафиксированные извлечённые файлы остаются видимыми. Конечный снимок может сообщать зафиксированные данные вместе с `cancelled`, `failed` или предупреждением очистки. Успешная публикация архива целиком остаётся успешной даже при поздней отмене. [Отмена задачи](task-scheduling.md), [Изменение архива](../../engineering/archive-transfers.md), [Безопасное извлечение](../../engineering/zip-safe-extraction.md)

## Бюджеты вывода и границы целостности

Извлечение отдельно ограничивает заявленный и фактический вывод: 8 GiB на обычный файл и 20 GiB на задачу. Проверка высокого коэффициента может отклонить запрос при допуске в поддерживаемых форматах. Для ZIP заявленное отношение выше 1 000 к одному у записи больше 1 MiB требует явного разрешения. Разрешение не отменяет жёстких пределов. Solid- или потоковые декодеры могут выполнять работу над невыбранными данными. Эта работа, повторные чтения или попытки и вспомогательная работа декодера учитываются отдельно от опубликованных байтов.

Просмотр метаданных, допуск задач, память рабочих процессов и предпросмотр имеют собственные бюджеты. Большой дисковый индекс ZIP не увеличивает пределы извлечения или записи. Проверки целостности зависят от формата. Например, проверки структуры и читаемости ISO/UDF не предоставляют отсутствующую контрольную сумму каждого файла. [Большие индексы архивов](../engineering/large-index.md), [Проверка целостности](../engineering/archive-checking.md), [Учёт вспомогательной работы декодера](../engineering/auxiliary-decoding-work.md)

## Предпросмотр, временное открытие и секреты

- **Предпросмотр.** Выбор поддерживаемого файла запускает предпросмотр в видимой карточке свойств. Rust читает и проверяет всю допущенную запись в пределах бюджетов. Текст ограничен 256 KiB. Закодированные изображения ограничены 16 MiB; исходные размеры и число пикселей ограничены отдельно. Частный процесс изображений получает байты и возвращает ограниченную миниатюру. Он не получает имя архива, пароль или дескриптор назначения. Текущие форматы и ограничения описаны в [контракте предпросмотра](../engineering/content-preview.md).
- **Временное открытие.** Обычная запись извлекается в частный кэш по обычным правилам проверки задачи. Приложение передаёт проверенный файл системной ассоциации как локальный URL. Принятие передачи не доказывает, что внешняя программа закончила чтение. При следующей операции после срока хранения очистка проверяет идентичность кэша и блокировки. Изменения копии независимы от исходного архива. [Временное открытие](../engineering/archive-opening.md), [Передача архивов](../../engineering/archive-transfers.md)
- **Секреты.** Пароли открытия и извлечения остаются в специфичных для операции обнуляемых контейнерах в течение сеанса или задачи. Они не попадают в снимки задач или журнал подготовки. Правила частного хранения, сроков и раскрытия пользовательских данных описаны в [контракте конфиденциальности](../engineering/privacy.md) и [контракте паролей](../engineering/password-extraction.md).

## Журналы, остатки и проверка

Журналы подготовки записывают контекст задачи и относительные имена вывода при подготовке и фиксации. Обычная очистка проверяет владельца и идентичности и удаляет только известные подготовительные объекты. Частные журналы и оставшиеся объекты могут дать сведения после аварийного завершения. Среда подсчитывает возможные остатки при проверке назначения. Она не использует найденный журнал для повторной записи или удаления неизвестного содержимого. У истечения срока кэша частного временного вывода есть собственные проверки идентичности и блокировок.

При изменении этой границы проверять публикацию и очистку наряду с кодами ошибок. [Тесты ввода-вывода](https://github.com/xiaodaozhi/xdzip/blob/main/crates/xdzip-io/src/tests.rs), [тесты извлечения](https://github.com/xiaodaozhi/xdzip/blob/main/crates/xdzip-runtime/src/extraction/tests.rs) и [контракт безопасного извлечения](../../engineering/zip-safe-extraction.md) охватывают разные уровни. При изменении нативного поведения платформы требуются доказательства для соответствующей платформы.
