# Термины и ограничения реализации XDZip

## 1. Терминология

| Термин | Определение |
| --- | --- |
| Архив | Контейнер или поддерживаемый сжатый поток вместе с разрешённым источником. |
| Кодек | Реализация распознавания, сканирования, чтения или создания формата. |
| Сеанс | Открытый источник, обработчик, индекс и контекст просмотра. У задач свой жизненный цикл. |
| Запись | Реальная запись архива. У каталога также может быть синтетический узел для отображения. |
| SourceVersion | Отпечаток одного допущенного исходного файла или тома, вычисляемый по возможности. |
| QuerySnapshot | Текущий неизменяемый порядок результатов с ключом из сеанса, запроса, поколения и ревизии. |
| Поколение | Механизм замены запросов интерфейса, предотвращающий замещение новых результатов устаревшими. |
| Подготовленная операция | Ограниченный вход среды выполнения, включающий источник, выбор и параметры операции. |
| Задача | Жизненный цикл и результат операции, принятой в очередь. |
| Разрешение | Удерживаемое хостом право доступа к файлу или каталогу, отдельное от строки пути. |
| Приёмник вывода | Интерфейс записи с учётом объёма, квотами и транзакционным контролем. |
| Рабочий поток или процесс | Команды и задачи исполняются потоками хоста. Архивы и изображения обрабатывают отдельные процессы. |
| Фиксация | Публикация проверенного временного вывода разрешённой файловой или архивной операцией. |
| Снимок задачи | Последний отчёт о состоянии, ходе, запросе или результате. Промежуточные снимки могут объединяться. |
| Возможности | Пересечение реализации, свойств формата, платформы и правил. |
| Солидное сжатие | Несколько файлов делят сжатые блоки. Для чтения выбранного файла может потребоваться декодировать предыдущие данные. |
| Первый показанный кадр | Реально отрисованный и представленный кадр. Запись ui_ready его не заменяет. |

<a name="xdzip-2-units-and-values"></a>

## 2. Единицы и значения

Размеры памяти и файлов выражаются в двоичных KiB/MiB/GiB, где 1 MiB = 1024² байта. Передача и учёт сохраняют целое число байтов. Время выражается в ms или s. Для измерения длительности используются монотонные часы. Временные метки файлов по возможности сохраняют календарное представление и точность источника. Пропускная способность указывается в MiB/s с уточнением, считаются ли сжатые входные, декодированные или выходные байты.

100% загрузки одного ядра означает полностью занятое логическое ядро. Дерево процессов может превышать 100%. PSS, RSS, USS и физическое потребление памяти различаются. Размер сжатой загрузки, размер установки и размер исполняемого файла записываются отдельно.

## 4. Версии

У приложения, внутреннего интерфейса сборки CXX, внешнего протокола и схемы хранимых данных отдельные версии. По версии продукта нельзя определить версию протокола SDK. См. [проект SDK расширений форматов](codec-extension-sdk.md).
