# Использование XDZip в сценариях

Автономная CLI работает без Qt и сеанса рабочего стола. Выберите пакет `xdzip-cli-` для своей системы в разделе [выпусков GitHub](https://github.com/xiaodaozhi/xdzip/releases). Распакуйте пакет целиком и оставьте вспомогательную программу рядом с исполняемым файлом. Из распакованного каталога выполните `./bin/xdzip --help` в macOS или Linux либо `.\bin\xdzip.exe --help` в PowerShell.

В примерах `xdzip` находится в PATH. Выполните `setup` с распакованной CLI, чтобы зарегистрировать программу запуска для текущего пользователя. При необходимости добавьте каталог команды в PATH. С помощью `xdzip --version-json` проверьте, что найденная программа сообщает `"component":"cli"`. У настольной программы запуска и CLI может быть одинаковое имя команды. При конфликте используйте явный путь к распакованной CLI. [Установка и удаление команды](../engineering/command-line.md#xdzip-build-and-command-installation)

<a name="xdzip-create-and-check"></a>

## Создание и проверка

В новом закрытом рабочем каталоге с правом записи создайте папку `docs` с файлом `hello.txt`. Поместите второй файл `notes.txt` рядом с этой папкой. Следующие команды создают ZIP, добавляют второй файл в существующую папку `docs/` внутри архива и проверяют результат.

```sh
xdzip create sample.zip docs --level normal --json
xdzip add sample.zip notes.txt --into docs --conflict skip --json
xdzip test sample.zip --json
```

Выберите расширение и параметры создания по [таблице форматов](../../../README.ru-RU.md#xdzip-format-support). Поместите результат вне дерева исходных файлов. Родительская папка должна существовать. Команда `add` требует существующий подходящий архив. Используйте `--into` для существующей папки внутри архива или опустите этот параметр для добавления в корень. Команда `test` не записывает распакованные файлы. При успехе поле `data.check_kind` показывает уровень проверки. См. [реестр форматов](../engineering/format-registry.md) и [проверки целостности](../engineering/archive-checking.md).

<a name="xdzip-list-select-and-extract"></a>

## Просмотр списка, выбор и распаковка

Работайте с созданным архивом в том же каталоге. Используйте новую папку назначения или явно выберите способ обработки существующих файлов.

```sh
xdzip list sample.zip --limit 2 --json
xdzip extract sample.zip docs/hello.txt -C output --conflict skip --json
```

Пути элементов указываются точно, с учётом регистра и прямыми косыми чертами. Если несколько записей имеют один путь, выберите нужную запись по `id`, который возвращает `list`. Идентификаторы начинаются с 1. Например, замените `docs/hello.txt` во второй команде на `--entry-id 2`, если в списке у этого файла ID 2. Повторяйте `--entry-id` для нескольких элементов. Для сопоставления используйте `path`, для отображения — `display_name`. После изменения архива получите список заново.

Первая страница начинается со смещения 0. Для следующей страницы передайте `data.next_offset` в `--offset` с тем же `--limit`. Остановитесь, когда `next_offset` равен null. Смещение — позиция строки с отсчётом от нуля, ID — идентификатор физической записи. Каждый вызов заново открывает архив, поэтому сохраняйте исходный файл неизменным при чтении страниц. [Выбор элементов и ограничения списка](../engineering/command-line.md#xdzip-archive-behavior)

<a name="xdzip-run-without-prompts"></a>

## Запуск без запросов

`--json` отключает интерактивные запросы. Чтобы задание завершилось без участия пользователя, явно выберите политику конфликтов. Для команд с поддержкой паролей, например `extract`, `test` или `create` с шифрованием, укажите `--password-stdin` и передайте одну строку пароля в UTF-8 через закрытый канал стандартного ввода. Для создания зашифрованного архива также требуется `--encrypt`. Если не хватает необходимого решения или пароля, CLI возвращает `interaction_required`. [Параметры пароля и формата](../engineering/command-line.md#xdzip-archive-behavior)

<a name="xdzip-interpret-results"></a>

## Интерпретация результата

При работе с архивами через `--json` разбирайте объект UTF-8 в stdout. Читайте `schema_version`, `status`, `error_code`, `data`, `summary` и `warnings`. Сохраняйте доступ к stderr для диагностики. `--version-json` возвращает отдельный объект с идентификацией сборки.

| Код завершения | Что проверить |
| --- | --- |
| 0 | Прочтите результат и число пропусков. Для команд с передачей задачи настольному приложению статус `handed_off` подтверждает передачу. |
| 1 | Проверьте ошибку, предупреждения и сводку на предмет сбоя, частичного завершения и предупреждений об очистке. |
| 2 | Исправьте команду или аргументы. |
| 3 | Проверьте указанные требования к взаимодействию, авторизации, платформе или установке. |
| 130 | Отмена подтверждена. Проверьте, какие файлы уже сохранены окончательно. |

Неизвестные значения могут быть null. При сбое или отмене ранее записанные файлы могут сохраниться. Перед повтором проверьте `summary.committed_files`, если это поле есть. Передача настольному приложению, квитанции обновления и полный формат вывода описаны в [справочнике CLI](../engineering/command-line.md).
