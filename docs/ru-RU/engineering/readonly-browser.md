# Контракт реализации просмотра только для чтения

Документ определяет границы данных, ресурсов и взаимодействий при просмотре. Он дополняет документы о [домене и данных](../design/domain-data.md), [мосте Qt/Rust](../design/qt-rust-bridge.md) и [проектировании расширения форматов](../design/codec-extension-sdk.md), не фиксируя сторонний протокол или полный SDK форматов. Ниже приведены особые правила метаданных ZIP. TAR/TAR.GZ повторно используют модели просмотра и запросов; различия форматов описаны в [контракте TAR/GZIP](tar-gzip.md).

[Индексация больших архивов](large-index.md) описывает потоковые индексы на миллион записей для обычных ZIP/ZIP64 из одного файла, ограничения сброса на диск, модели по запросу и лимиты задач. Приведённые ниже ограничения снимка в памяти на 100 000 записей остаются основой для обычных форматов и первоначальной поддержки ZIP и не отменяют более новые условия допуска потокового ZIP.

## Данные и направление зависимостей

xdzip-codec-api определяет заимствованный ввод только для чтения, отмену, ограничения, записи и ошибки. xdzip-codec-zip реализует встроенную адаптацию метаданных ZIP без доступа к путям или права записи. xdzip-runtime открывает и удерживает файлы только для чтения и публикует неизменяемые снимки после успешного сканирования. xdzip-qt-bridge предоставляет точки входа рабочего потока через cxx; тонкие контроллеры C++ преобразуют ограниченные страницы в модели Qt, а QML отвечает за отображение и намерения действий.

Продукт перешёл на [среду команд и событий](product-runtime.md): интерфейс отправляет короткие команды, рабочий процесс Rust удерживает архив, а отдельный приёмник Qt доставляет результаты через ограниченный почтовый ящик. Синхронный мост QtConcurrent удалён. У каждого контроллера просмотра не более одного ожидающего запроса. Это по-прежнему не полный планировщик многозадачности, не ABI динамических плагинов и не протокол сторонних процессов.

## Поведение и данные

При открытии архива перечисляются непосредственные потомки корня. Поиск может включать физические записи потомков. Одинаковые имена сохраняют отдельные значения `EntryId`, а идентификаторы сеансов никогда не используются повторно. Интерфейс передаёт идентификаторы и количества байтов строками для сохранения точности. Доменный `PageRequest` может представлять до 256 строк. Среда продукта передаёт не более 128 строк и 64 KiB имён на страницу, вырезая страницы из одного упорядоченного результата запроса. Qt атомарно публикует результаты до 1 024 строк. Для больших результатов сохраняется логическое число строк, строки загружаются по требованию и кэшируются в количестве не более 1 024. Элементов постраничной навигации нет. См. [встроенный предпросмотр](content-preview.md) для предпросмотра по запросу пользователя и [открытие архива](archive-opening.md) для открытия элемента через системную ассоциацию.

Распознаются ZIP/ZIP64; проверяются локатор ZIP64, конечная запись и начальный диск центрального каталога. [Хост разделённых томов](archive-opening.md) предоставляет единый логический ввод; кодек по-прежнему отклоняет непреобразованные многодисковые метаданные. Размеры и смещения ZIP64 остаются 64-битными; буферы содержимого не выделяются по объявленным размерам. Количество записей центрального каталога должно совпадать с EOCD. При ошибке, отмене или превышении ограничений частичный список не публикуется. Имена разрешаются согласно [контракту кодировки](filename-encoding.md): сначала учитываются объявления Unicode, затем определяются необъявленные устаревшие кодировки; неразрешённые байты экранируются. Управляющие символы и управляющие символы двунаправленного текста также экранируются. Абсолютные и родительские пути, специальные файлы и подобные записи помечаются для проверки. Исходные байты имён всегда сохраняются; при выводе используются только фактические имена, пути которых отдельно проверены и разрешены.

Показываемые размеры, методы сжатия и признаки шифрования берутся из метаданных архива. При просмотре ZIP читается центральный каталог без проверки каждого локального заголовка и содержимого. Некоторые другие форматы, например сжатый TAR, декодируют внешний поток для обнаружения записей. Открытие не извлекает файлы элементов. Для большого обычного ZIP среда может создать закрытый [индекс метаданных на диске](large-index.md). Для проверки содержимого запросите отдельную [проверку целостности](archive-checking.md) или выполните [безопасное извлечение](zip-safe-extraction.md).

## Межплатформенные границы кодирования имён файлов

Уровень формата сохраняет исходные байты имён и физическую идентичность. Приоритет имеют флаг ZIP UTF-8 и Unicode Path, проверенный CRC; затем применяются проверка UTF-8 всей группы и ограниченное статистическое определение необъявленных имён на уровне архива. Устаревшие имена GBK/GB18030, Big5, Shift-JIS и аналогичных кодировок можно непосредственно использовать для просмотра, навигации, извлечения, временного открытия, экспорта и обычного изменения. Все потребители путей используют общие зафиксированные результаты декодирования и повторяют проверки пути, Unicode, регистра и конфликтов имён.

Определение не зависит от системной кодовой страницы или языка интерфейса и не гарантирует восстановление произвольных коротких имён, нескольких необъявленных кодировок или повреждённых символов, уже сохранённых как Unicode. Ручного выбора кодировки сейчас нет. Повреждённые объявления, ошибки строгого декодирования и аномальные пути остаются помеченными для проверки, их вывод запрещён. Приоритет, TAR/PAX, бюджеты, связь с содержимым и сохранение описаны в [контракте адаптивной кодировки имён](filename-encoding.md). Новые и добавленные имена остаются в UTF-8; при изменении для разрешённых устаревших имён добавляются явные объявления UTF-8.

## Ресурсы и жизненный цикл

В откалиброванном главном окне пять столбцов: имя, исходный размер, сжатый размер, тип и дата изменения. Тип определяется только по расширению отображаемого имени, JPG группируется с JPEG. Дата изменения берётся из корректной локальной даты и времени DOS центрального каталога ZIP без определения часового пояса; некорректные значения остаются пустыми. Все пять столбцов сортируются. Таблица показывает дату, но сортировка использует полное время DOS. Панель и отдельное окно свойств показывают время в 24-часовом формате с секундами, например `2026/10/15 12:34:56` в упрощённом китайском. Метод сжатия остаётся в подробностях, мост сохраняет коды сортировки по методу. Состояния шифрования и необходимости проверки сохраняются в подсказках строк, описаниях доступности и подробностях; записи, требующие внимания, отмечены рядом с именем, и визуальное упрощение не должно скрывать эту отметку.

При закрытии вкладки обычный продукт использует менеджер сеансов приложения, сохрающий фоновые задачи и результаты; страницы без задач освобождаются после асинхронного закрытия соединения. Кнопка с плюсом создаёт пустую вкладку или главное окно в соответствии с сохранённым режимом открытия. Открытие файла всегда предпочитает повторное использование стартовой страницы и устранение дубликатов; см. [контракт сеансов приложения](application-sessions.md). Независимые контроллеры и диагностические тесты сохраняют команду `CloseSession` для очистки состояния архива одного соединения. Флажок «Выбрать всё» в заголовке имеет три состояния. Размеры в строке состояния суммируют только выбранные метаданные текущего запроса, а не весь архив. Свидетельства поведения и фактической геометрии сохраняются согласно [проверке](../../../developers/qa/README.md).

Экранирование для отображения и копии моста требуют дополнительного места; эти значения не гарантируют RSS процесса или время выполнения. Метаданные обычного снимка в памяти находятся в памяти Rust. Индексы непосредственных потомков сохраняют идентичность строк, а кэши результатов — только отсортированные индексы. Измерения для 100 000 записей привязываются к коммиту, платформе и нагрузке согласно [проверке](../../../developers/qa/README.md); сами по себе они не подтверждают результаты для миллиона записей. Проверки длины и времени изменения до и после сканирования обнаруживают изменения по возможности и не являются атомарными снимками.

Отмена проверяется на границах чтения и обхода; чтение, заблокированное ОС, прервать нельзя. При закрытии занятого главного окна сначала запрашивается остановка, затем окно закрывается после уведомления о завершении, без ожидания завершения потока в GUI. Неожиданное уничтожение контроллера не оставляет висячих фоновых ссылок. Обычное закрытие окна и выход из приложения используют барьер завершения M1, общий для создания и извлечения. Ошибки записи и очистка подготовительных областей следуют соответствующим контрактам записи. После принудительного завершения подозрительные области только сообщаются; неизвестное содержимое не восстанавливается, не перезаписывается и не удаляется автоматически. Транзакции целого каталога и безопасность при потере питания не обещаются.

Источники должны быть обычными файлами. Первоначальное открытие, повторная проверка источника и копирование источника для задач используют `xdzip_io::open_regular_readonly`, проверяя тип на том же открытом дескрипторе. В Unix открытие до классификации выполняется без блокировки, чтобы избежать ожидания ввода-вывода, если путь заменён FIFO или другим специальным объектом. Обычные файлы и исходные символические ссылки на них по-прежнему можно использовать; версии источника привязаны к фактической идентичности файла. Ошибка первоначального открытия или типа возвращает `Io`; последующая ошибка повторной проверки или открытия для копирования возвращает `SourceChanged`. Это не атомарный снимок содержимого, не песочница и не принудительный предел времени ввода-вывода обычного файла.

Пути источника в мосте сейчас ограничены UTF-8, представимым без потерь. Для выбора файла используются независимые системные диалоги; кнопки окна macOS приложение не рисует. Фактический системный фокус, модальное владение и оформление окна требуют приёмки на рабочем столе.

## Приёмка и последующая проверка

Фактические тесты и снимки экрана фиксируются в issue или артефактах согласно [проверке](../../../developers/qa/README.md). Просмотр включает фактическое открытие, списки, внутренние пакетные запросы, деревья каталогов, выбор текущего запроса и жизненный цикл команд и событий с разработческими сборками на трёх платформах. Индексация ZIP64 на 100 000 записей и поколения запросов проверяются по [контракту просмотра ZIP](zip-readonly-browsing.md); запись отдельно определена [безопасным извлечением](zip-safe-extraction.md). Для предпросмотра содержимого действуют отдельные квоты содержимого и декодирования. Для официального выпуска по-прежнему требуется [проверка лицензий](../../../developers/qa/release-review.md); эта страница не фиксирует выводы приёмки этапов.

## Дополнения к взаимодействию при просмотре

- В безопасный явно заданный каталог архива можно войти двойным щелчком или установив фокус на флажок и нажав Enter; «Корневая папка» возвращает к корню. Обычные каталоги показывают только непосредственные файлы и каталоги, без рекурсивных потомков; поиск рекурсивно охватывает текущую область и показывает полные пути в архиве. В обычном списке видны только конечные имена, без изменения внутренних полных путей, копирования или навигации. Опасные имена не могут стать навигационными узлами, но остаются в снимке для поиска и проверки метаданных.
- Enter запускает поиск имени по буквальной подстроке после приведения Unicode к нижнему регистру, без регулярных выражений и сортировки по локали. Ввод ограничен 256 единицами UTF-16, точка входа Rust — 1 024 байтами UTF-8. Поиск охватывает текущий каталог. При возврате к корню поисковые слова сохраняются; новый сеанс их очищает.
- Обычные запросы в памяти фильтруют загруженный снимок из не более 100 000 записей, сортируют по запросу и возвращают до 128. Отмена проверяется для каждой отфильтрованной записи, а также до и после сортировки. Параметры каталога — физические EntryId или идентификаторы виртуальных каталогов с префиксом `d`, допустимость которых в текущем сеансе проверяет Rust; это не пути, составленные интерфейсом.
- Запрос ограничен, версионирован и выполняется одним работником. Страницы содержат полный QueryKey. Qt объединяет последнее намерение и отменяет старую работу. Устаревшие запросы или несовпадающие сеанс, запрос, поколение, ревизия или смещение не могут заменить текущий вид. Смещения вне диапазона возвращают ошибки; пустой результат имеет состояние Ready. Переходы по каталогам и поиск начинаются с первой страницы.
- При существующем снимке его список, сетка или пустое состояние сохраняются во время запросов каталога, сортировки или поиска до фиксации новых результатов; состояние занятости не заменяет ненадолго всю область наложением. При первом открытии ещё не готового архива по-прежнему показывается загрузка; последовательный допуск контроллера, отмена и проверки изменения источника сохраняются.
- Щелчок по строке или флажку переключает множественный выбор текущего запроса, различая дубликаты имён по физическому ID. Неявные каталоги используют отдельные ключи строк dN. Выбор и подробности очищаются после успешной замены модели запросом или новым сеансом; внутренние пакеты передачи не влияют на составленный список, а интерфейс не разбивает его на страницы. Подробности показывают метаданные последней активированной записи; фокус и набор флажков отдельно представляют фокус и выбор. «Выбрать всё» использует последнюю строку полного текущего списка как фокус подробностей, как при последовательном выборе отдельных записей до последней строки. Снятие всего выбора очищает подробности. При отсутствии выбора скрываются исходный и сжатый размеры, дата изменения, метод сжатия и действие извлечения записи в фокусе, вместо показа вводящих в заблуждение пустых свойств.
- Размеры в списке отображаются в B/KiB/MiB/GiB; преобразование является лишь приблизительным отображением, модели и Rust сохраняют исходные целые числа. Значки обозначают тип, карточки подробностей показывают свойства, а [предпросмотр](content-preview.md) автоматически загружается для одного поддерживаемого файла, пока карточка видна.
- Неизвестный несжатый размер отдельно сопровождается `size_known=false`, столбец исходного размера остаётся пустым и указывается, что размер неизвестен. Пустые файлы с известным размером по-прежнему показывают 0. Если общий размер выбора неизвестен, строка состояния показывает только количество без разделителя или заполнителя, а контроллер сохраняет неизвестное состояние; известный итог по-прежнему показывает размер. В обоих направлениях сортировки неизвестные размеры следуют за известными, с сохранением порядка идентичностей внутри групп. Для физической записи неизвестного размера можно запросить предварительную проверку метаданных, чтобы узнать причину отказа; для выбора с виртуальными каталогами это по-прежнему недоступно. Неизвестный размер не даёт разрешения на вывод или бюджета декодирования.

Для выбранных записей можно запросить [предварительную проверку метаданных извлечения](extraction-preflight.md) в независимом системном окне результатов. Она не записывает файлы и не меняет границы фазы только для чтения.

## Полный индекс каталогов и сортировка

- Rust строит явные и неявные каталоги по полному неизменяемому снимку; Qt не выводит дерево из текущей страницы. Каждый виртуальный узел имеет уникальный в сеансе ID `dN`, ID родителя, отображаемое имя, полный префикс архива и количество физических записей потомков. Непосредственные каталоги без явной записи отображаются как строки навигации с физическим id 0, navigation_id моста и physical=false; Qt использует ключи отображения dN. Их нельзя выбрать как физические объекты извлечения, и они не увеличивают число физических записей. Явные дубликаты записей не устраняются; строки навигации дополняют только каталоги без явных записей. Строки навигации можно выбирать, копировать их пути и входить в каталоги, но размер, метод и дата остаются пустыми. Предварительная проверка принимает только реальные физические записи и отключена для выбора со строками навигации.
- Родители публикуются раньше потомков в порядке первого появления в архиве. Одноимённые физические записи остаются независимыми. Количество узла включает всех потомков под префиксом, в том числе записи, требующие проверки, но исключает записи, точно равные префиксу каталога. Поиск по имени не изменяет эти количества.
- Записи с предупреждениями, неразрешёнными именами, обратными косыми чертами, пустыми компонентами, `.` или `..` не создают узлы; они остаются в физических снимках и рекурсивном поиске для проверки. Индексы обеспечивают навигацию, но не безопасность путей или разрешение извлечения.
- При любом превышении бюджета каталогов весь индекс каталогов отбрасывается, а интерфейс ясно уведомляется. Просмотр корня, поиск и переход в допустимые явные каталоги продолжаются. Без индекса не выводятся неявные каталоги; корень может быть пустым, хотя поиск по-прежнему охватывает полный физический снимок. Усечённое дерево никогда не показывается как полное. Для пространства каталогов действует собственный бюджет имён, не меняющий условия допуска сканирования конкретного формата.
- Щелчок по заголовкам имени, исходного размера, сжатого размера, типа или даты изменения переключает сортировку по возрастанию и убыванию; Enter/пробел их активирует. Меню сортировки справа вверху может восстановить порядок архива внутри групп каталогов и файлов. До разбиения на страницы фильтруется и сортируется весь результат, чтобы порядок был согласован между страницами. Имена используют лексикографический порядок скалярных значений Unicode с учётом регистра, без естественной сортировки и сортировки по локали. Числа сравниваются как исходные целые Rust. При равных значениях используются тип строки (физическая перед навигационной) и соответствующая идентичность по возрастанию; убывание не обращает порядок одноимённых записей. Каждый режим сначала группирует по признаку каталога, помещая явные и неявные каталоги перед файлами. Возрастание и убывание применяются внутри каждой группы; неизвестные исходные размеры остаются после известных в этой группе. Направление сортировки типа меняет только порядок категорий файлов. Категории используют нормализованные расширения, объединяя JPG и JPEG; файлы без расширения сохраняют отдельную группу. Локализованный отображаемый текст не является идентичностью каталога.
- Коды сортировки просмотра: 0 — порядок архива внутри каждой группы (сначала физические каталоги, затем неявные в порядке индекса), 1/2 — имя по возрастанию/убыванию, 3/4 — исходный размер, 5/6 — сжатый размер, 7/8 — номер метода ZIP, 9/10 — тип, 11/12 — время изменения; остальные отклоняются. При смене столбца, каталога или поиска происходит возврат к первой странице; выбор и подробности текущего запроса очищаются при успешной замене страницы. Недопущенное действие восстанавливает последние отображённые параметры запроса.
- Дерево поддерживает раскрытие и сворачивание, навигацию с клавиатуры и вход в каталог по Enter; горизонтальная прокрутка позволяет достигать глубоких уровней. Базовая высота строки — 32, отступ уровня — 12,8, место для папки — 16, расстояние между значком и текстом — 6,4; текст и значки выравниваются по вертикальному центру. Большой шрифт может увеличить высоту строки и ширину столбцов.

Навигация по каталогам и сортировка повторно проверяются по [общим методам](../../../developers/qa/README.md). Полную идентичность запроса, проверки источника и проверку 100 000 записей см. в [контракте просмотра ZIP](zip-readonly-browsing.md). Выбор интерфейса охватывает весь текущий запрос; внутренние пакеты и освобождение кэша его не очищают. Диапазонный выбор больших запросов перед подтверждением фиксируется в стабильных идентичностях.

## Общие элементы управления и контекстные команды

Меню, кнопки и сочетания клавиш повторно используют действия контроллера только для чтения. Щелчок правой кнопкой по выбранной записи сохраняет множественный выбор текущего запроса; по невыбранной записи — сначала выбирает только её. Диапазоны с Shift используют стабильные ID записей как якоря и очищаются при успешной замене результатов запросом или сортировкой. «Выбрать всё» охватывает полный запрос текущего каталога, включая строки навигации, с учётом допуска формата и индекса. Предварительная проверка отдельно ограничивает выбор 128 реальными физическими записями и отключается для наборов со строками навигации или сверх лимита. Имена и пути архива копируются в системный буфер обмена; у имён каталогов конечные разделители опускаются, а пути сохраняют исходную форму отображения.

Списки и сетки используют одну ограниченную модель и выбранные ID; отдельный индекс для сетки не создаётся. Направляющие каталогов, отметки последнего соседнего элемента, цепочки предков и навигационная цепочка выводятся из опубликованной полной модели каталогов без дополнительных запросов к формату. Сводки архива кэшируют физический итог открытия независимо от текущего каталога или поиска; число справа от навигационной цепочки показывает строки текущего списка, включая необходимые строки навигации.

Меню закрываются при изменении чтения, запроса или сеанса. Контроллер повторно проверяет допустимость операции при выполнении. Каждый `BrowserController` управляет одним сеансом архива, а приложение может содержать несколько вкладок или окон архивов. [Извлечение](zip-safe-extraction.md) получает явное намерение вывода и полномочия на целевой путь. [Создание](zip-creation.md) фиксирует собственное дерево входа и назначение. [Проверка целостности](archive-checking.md) выполняется как отдельная задача только для чтения. [Предварительная проверка](extraction-preflight.md) анализирует метаданные текущего источника.

## Идентичность запроса и ограничения ресурсов

Запрос создаёт один полный порядок, затем вырезает транспортные пакеты из кэшированных индексов строк. Пакеты содержат не более 128 строк и 64 KiB имён суммарно. Очередь команд остаётся ограниченной 8 MiB; события данных Rust и почтовый ящик Qt каждый применяют обратное давление при 32 MiB содержимого, чтобы вместить полные изображения в пределах лимитов. При изменении намерения поиска или каталога сохраняется только последнее ожидающее намерение; старые ответы не попадают в новые запросы. Обычная отмена или превышение лимита сохраняют последний успешный список; изменение версии источника очищает недействительные данные и требует повторного открытия.

До и после сканирования, а также на границах запроса и предварительной проверки проверяются длина, время изменения и доступное время создания дескрипторов источника и текущих путей. Unix дополнительно проверяет устройство/inode; Windows использует безопасную обёртку закреплённой версии winapi-util для индекса тома и файла, чтобы обнаружить замену пути с сохранением временных меток. Эти проверки не являются атомарными снимками файловой системы. Сводки выбора кэшируются по ревизии выбора модели и используют Rust u128 для точных сумм, избегая повторных обходов и 64-битного переполнения.

Адаптеры настроек Qt загружают язык интерфейса. Тип, состояние, ошибки и видимые пользователю даты используют каталоги переводов и локаль. Значения моста для числа байтов, идентичности записи, путей, исходного времени и параметров сортировки не зависят от языка. Возможности формата, идентичности и решения безопасности нельзя выводить из переведённого текста. Успешная смена языка немедленно обновляет текст интерфейса, не меняя выполняющиеся задачи; см. [настройки и локализацию](../ux/settings-localization.md).

После успешного открытия архива мост отправляет локальному адаптеру настроек интерфейса только archiveOpened(path). Недавние пути хранятся отдельно и не участвуют в доменных запросах, сортировке или разрешении задач. Пути, открытие которых не удалось, в недавние элементы не записываются.
