# Самораспаковывающиеся ZIP-архивы, созданные xdzip для Windows

[English](../../engineering/sfx-creation.md) | [简体中文](../../zh-CN/engineering/sfx-creation.md) | [繁體中文（台灣）](../../zh-TW/engineering/sfx-creation.md) | [日本語](../../ja-JP/engineering/sfx-creation.md) | [한국어](../../ko-KR/engineering/sfx-creation.md) | [Français](../../fr-FR/engineering/sfx-creation.md) | [Deutsch](../../de-DE/engineering/sfx-creation.md) | [Español](../../es-ES/engineering/sfx-creation.md) | [Português (Brasil)](../../pt-BR/engineering/sfx-creation.md) | Русский

Первый профиль SFX работает только на Windows x64 и создаётся с явным суффиксом `.sfx.exe`. Однотомный ZIP без шифрования, созданный методом Store или Deflate, помещается в модуль `xdzip-sfx.exe`, который собирается проектом. При создании модуль не запускается. Обычные файлы `.exe` исключены из создания, перетаскивания и регистрации системных ассоциаций.

Приложение загружает модуль только из собственного каталога или из общего родительского каталога закрытой папки `cli`. Оно открывает обычный файл ограниченного размера без перехода по ссылкам и проверяет PE32+, архитектуру x64, границы секций и метку версии проекта. Комментарий конечной записи ZIP содержит версионируемый блок из 64 байт. В нём записаны длины модуля и ZIP и SHA-256 предшествующих байтов. При запуске SFX проверяет этот блок, а затем использует общие правила ZIP и распаковки на Rust. Так выявляются повреждения и некорректные блоки. Проверка не подтверждает личность издателя или подлинность произвольного исполняемого кода.

Модуль работает без Qt и без установленного xdzip. Диалоговые окна Windows позволяют выбрать существующую папку назначения и способ разрешения конфликтов, показывают ход выполнения и дают возможность отменить операцию. Работа с архивом выполняется на Rust вне потока интерфейса. Модуль применяет общие права доступа, зафиксированные идентификаторы, ограничения ресурсов, проверки отдельных файлов, временную запись, обработку конфликтов и очистку. При отмене полностью сохранённые файлы остаются, а незавершённые временные данные удаляются. Модуль никогда не открывает и не запускает распакованные файлы, не вызывает сценарии, не устанавливает ПО, не повышает привилегии и не меняет ассоциации.

Для автоматизации доступны команда `--test` для проверки без записи и `--extract-to <existing-directory> --conflict skip|rename|overwrite` для распаковки. Некорректный блок, неподдерживаемый профиль или шифрование ZIP приводят к отказу до записи. Пароли данных, многотомные архивы, произвольные команды запуска, тихая установка и автоматический запуск файлов не поддерживаются. Созданный файл не подписан. Подпись и репутация издателя учитываются отдельно при публикации. [Правила PE и Authenticode](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format)

Настольное приложение по-прежнему использует Qt Quick. Автономный SFX использует системные диалоги согласно узкому исключению в [ADR-013](../design/architecture-decisions.md#xdzip-adr-013-standalone-windows-sfx-host).
