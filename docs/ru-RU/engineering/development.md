<a name="xdzip-obtain-and-modify"></a>

## Получение и изменение кода

Начните с актуального `main` и сохраните остальные изменения в рабочем каталоге. Область работы и ревью определены в [правилах участия](../../../CONTRIBUTING.md), разрешённая интеграция — в [руководстве по поставке](../../../developers/engineering/repository-hygiene.md). При изменении контракта обновляйте его языковые версии и затронутые проверки. Цвета и геометрия берутся из `specs/visual`.

<a name="xdzip-documentation-builds"></a>

## Сборка и проверка документации

Поддерживайте корневой README и соответствующие страницы docs для каждого языка интерфейса. Английские страницы по умолчанию используют `README.md` и `docs/`, переводы — `README.<locale>.md` и `docs/<locale>/`. Руководство сопровождающих использует английский США и упрощённый китайский. Под заголовком размещайте выбор языка. Текущий язык показывается текстом, остальные ведут к тому же разделу документации. Со страниц на упрощённом китайском ссылки ведут к китайской версии руководства сопровождающих, со всех остальных — к английской. При добавлении или переносе документа обновляйте указатели, входящие ссылки и якоря разделов.

Инструменты документации требуют Python 3.10+, lxml, Pandoc и Graphviz. Рекомендуются системные шрифты CJK. Команда `python3 scripts/build-design-html.py` создаёт под build/docs-html 16 подробных проектных документов и однофайловую версию из китайских исходников `docs/zh-CN/design/`. Загружаемый пакет записывается в dist/. Остальные технические руководства и документы по совместной работе указаны в docs/README.md. HTML служит форматом документации. Интерфейс продукта использует Qt Quick.

Запустите `python3 scripts/check-docs.py` для автономной проверки полноты переводов, взаимных языковых ссылок, языка ссылок в тексте, якорей Markdown, JSON и ресурсов оформления. Генератор HTML проверяет ссылки и структуру созданных страниц. При изменении проверяющего скрипта запустите `python3 scripts/test-check-docs.py`.

<a name="xdzip-product-toolchain-preparation"></a>

## Подготовка инструментов продукта

Для macOS подготовьте Xcode Command Line Tools и Qt. Для Windows нужны MSVC Build Tools, Windows SDK и совместимый Qt. Для Linux нужны компилятор, целевая среда glibc и зависимости Qt Wayland/X11. Версии зафиксированы в корневых файлах инструментов и CI. Источники и лицензии вносите в [таблицу инструментов](toolchain.md). Системы и сопровождение описаны в [политике поддержки](support-policy.md). Проверку конкретной лицензии и происхождения ведите в задаче по соответствующему выпуску.

В [Qt-приложении для разработки](../../../apps/desktop/README.md) приведены команды сборки и запуска из чистой рабочей копии, параметры CMake, архитектуры и цели macOS и ограничения внеэкранных тестов. После изменений сборки или установки перепроверьте пути с пробелами и китайскими символами. Для локальной разработки платная идентификация подписи не требуется. [Руководство по сборке](developer-build.md) описывает локальную ad-hoc подпись целостности DMG и ограничения CI на развёртывание приложения Mac.

## Независимые технические пробы

[Общая проба моста CMake/Cargo](../../../tools/bridge-probe/README.md) предлагает точку входа сборки в корне, закреплённые зависимости и проверки жизненного цикла. Записи о зависимостях см. в [обосновании выбора cxx](cxx-admission.md).
