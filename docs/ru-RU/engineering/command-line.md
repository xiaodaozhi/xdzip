# Контракт среды командной строки

[English](../../engineering/command-line.md) | [简体中文](../../zh-CN/engineering/command-line.md) | [繁體中文](../../zh-TW/engineering/command-line.md) | [日本語](../../ja-JP/engineering/command-line.md) | [한국어](../../ko-KR/engineering/command-line.md) | [Français](../../fr-FR/engineering/command-line.md) | [Deutsch](../../de-DE/engineering/command-line.md) | [Español](../../es-ES/engineering/command-line.md) | [Português (Brasil)](../../pt-BR/engineering/command-line.md) | Русский

CLI — независимый хост Rust, который вызывает службы форматов и безопасного ввода-вывода через тот же `xdzip-runtime`; он не зависит от Qt, QML или графического сеанса. Для 7z, RAR, CAB, ISO и UDF по-прежнему используются поставляемые изолированные рабочие процессы; поиск других программ распаковки в PATH не выполняется. Платформы и архитектуры определены [политикой поддержки](support-policy.md). Автономному CLI Linux не нужен X11; для запуска требуются системные OpenSSL 3 и сертификаты, а для сборки также libssl-dev и pkg-config.

Начиная с `v0.2.0`, официальные выпуски содержат автономные пакеты CLI для трёх платформ, а настольные пакеты включают частный CLI. Ранее опубликованные файлы не изменяются задним числом. Загрузки доступны на [странице выпусков](https://github.com/xiaodaozhi/xdzip/releases); границы сборки из исходников, установки и обновления описаны ниже и в [протоколе выпусков](release-protocol.md). Ход реализации и приёмки отслеживается в [#254](https://github.com/xiaodaozhi/xdzip/issues/254).

## Использование и вывод

```sh
xdzip --help
xdzip version
xdzip list archive.zip --json
xdzip extract archive.zip docs/ -C output
xdzip extract archive.zip --entry-id 3 -C output
xdzip create backup.7z docs/ --level normal
xdzip create data.iso docs/
xdzip create portable.sfx.exe docs/ --level normal
xdzip create private.zip docs/ --encrypt --password-stdin
xdzip add backup.zip notes.txt --into docs
xdzip test backup.zip
xdzip update --check
xdzip update --download --output downloads
xdzip update --yes
xdzip update --status
xdzip gui archive.zip
```

Без аргументов или с `--help` xdzip показывает справку. Варианты `version`, `--version` и `--version-json` сообщают идентичность из `VERSION.json` и состояния Git при сборке. `--version-json` выводит отдельный объект с product, version, build, revision, dirty, component, channel, configuration, distribution, platform и architecture. Язык справки и сообщений выбирается через `--language zh-CN|en-US`. По умолчанию проверяются `LC_ALL`, `LC_MESSAGES` и `LANG` в этом порядке; если выбранное значение начинается с `zh`, используется китайский. Публичные идентификаторы и коды ошибок — на английском языке. `l`, `x`, `c`, `a` и `t` являются сокращениями `list`, `extract`, `create`, `add` и `test`. Для буквальных аргументов файлов используйте `--`.

Все рабочие команды принимают `--json`. В stdout выводится ровно один объект JSON с постоянными полями schema_version (1), command, status, error_code, data, summary и warnings. Неизвестный размер равен null, в том числе для элементов общего сжатого потока TAR; исходные участники DEB ar сохраняют точные упакованные размеры. Данные списка содержат формат и записи с id, path, display_name, size, packed_size, method, directory, link, payload_supported, encrypted и warning. path — зафиксированное фактическое имя; некорректное или неразрешённое имя равно null. display_name служит только для экранированного отображения. Сводка задачи содержит фактические количества чтения, декодирования, проверки, фиксации, пропусков, каталогов и томов, сохраняя предупреждения очистки и неопределённые результаты.

Ход выполнения, ошибки и интерактивные запросы направляются в stderr. В режиме JSON, без терминала или с `--non-interactive` запросы не показываются. Если не хватает пароля или решения о конфликте, ожидающая задача отменяется, выполняется ожидание очистки и возвращается interaction_required. Коды выхода: 0 — успех или явная передача; 1 — ошибка, частичное завершение или предупреждение очистки; 2 — неверные аргументы; 3 — требуется взаимодействие, разрешение или условие установки; 130 — подтверждённая отмена. Явный пропуск является выполненной политикой; число пропусков сообщается отдельно. Если отмена не принята и фиксация завершилась, сохраняется фактический результат.

## Поведение архивов

`list` возвращает физические записи и сохраняет дубликаты. `extract` принимает полные точные пути элементов с учётом регистра и разделителями `/`. Каталоги раскрываются рекурсивно с сохранением иерархии ниже корня. Дублирующийся путь возвращает `ambiguous_member`. Используйте числовой ID из `list`, начиная с 1, через `--entry-id`; флаг можно повторять. Неразрешимые явно заданные пути или ID вызывают ошибку до создания каталога назначения. Шаблоны, чтение архива из stdin и запись извлечённого содержимого в stdout не поддерживаются.

`--limit` или `--offset` включает постраничный вывод. Смещение начинается с нуля и не превышает 1 000 000. При одном `--limit` смещение равно нулю, при одном `--offset` предел равен 128. Допустимый предел — 1–4 096. JSON `data` содержит `offset`, `total` и допускающий null `next_offset`. `summary.entries` считает фактически возвращённые строки. Обычный односоставной ZIP/ZIP64 может индексировать миллион записей, но список без страниц отклоняет более 100 000. Для обоих режимов общий бюджет сериализованных строк JSON и текстового представления — 16 MiB. Превышение возвращает `resource_limit` без частичных строк. Границы страниц не изменяют физические ID. См. [индексацию больших архивов](large-index.md).

По умолчанию extract использует текущий каталог. Если `-C` указывает на отсутствующий каталог, разрешение получают по компонентам от ближайшего безопасного существующего родителя, а не безусловно создают каталоги рекурсивно. Назначение, идентичность источника, ссылки, коллизии Unicode и регистра, подготовка, проверка и фиксация по-прежнему следуют [безопасному извлечению](zip-safe-extraction.md) и [кодировке имён](filename-encoding.md). Политика конфликта по умолчанию — Ask; `--conflict ask|skip|rename|overwrite` явно выбирает её. `--allow-high-ratio` подтверждает только высокую степень сжатия и не отменяет жёсткие ограничения ресурсов.

`create` выбирает профиль по [суффиксу](format-registry.md) результата и требует существующего родительского каталога. `--level store|fast|normal|best` проверяется для выбранного профиля. Для обычного TAR и ISO опустите уровень или выберите `store`. LHA (`.lzh` или `.lha`) использует уровни LH5 1, 6 и 9 для `fast`, `normal` и `best`. ZIP и 7z поддерживают `--encrypt` и `--volume-size`; 7z также поддерживает `--encrypt-names` и `--solid` согласно своему профилю. Размер тома задаётся положительным целым числом байтов или с суффиксами `KiB`, `MiB` и `GiB`. Неподдерживаемые выбранным профилем аргументы отклоняются до записи.

Пароль передаётся только скрытым вводом терминала или одной строкой UTF-8 через `--password-stdin`; символы конца строки удаляются, сам пароль не обрезается. Интерактивное создание с шифрованием требует повторного подтверждения. Открытые аргументы с паролями отклоняются; пароли не читаются из переменных окружения и не записываются в настройки или журналы. Длина и обнуление следуют [контракту паролей](password-extraction.md) и [контракту создания](zip-creation.md).

`add` отправляет обновление хосту и по умолчанию использует корень архива. `--into` выбирает существующий безопасный каталог по имени относительно архива. Допустимые входы могут добавлять или заменять записи. Перемещение внутри архива — операция настольного приложения. CLI разделяет проверки [изменения архивов](../../engineering/archive-transfers.md): допустимые форматы и записи, защита входов, временная пересборка и итоговая замена. `test` проверяет весь архив без создания файлов элементов. JSON `data.check_kind` сообщает силу завершённой проверки согласно [контракту проверки архивов](archive-checking.md).

Каждая операция CLI имеет собственную среду выполнения и не присоединяется к сеансам просмотра рабочего стола. Ctrl+C и сигналы завершения запрашивают совместную отмену и ожидают конечного состояния, очистки и завершения среды; ранее зафиксированные файлы сохраняются. `submit_wait` общей службы последовательно получает только краткую блокировку состояния, не ожидает места в очереди и не меняет неблокирующий допуск GUI. Страницы каталога содержат не более 128 физических записей. Для числа и имён SelectMembers действуют существующие ограничения; все запросы связаны с неизменяемой идентичностью сеанса.

## Сборка и установка команды

```sh
python3 scripts/cli.py build
python3 scripts/cli.py test
python3 scripts/cli.py package --output build/package/cli
build/cli/bin/xdzip --help
```

Эта точка входа использует закреплённые в репозитории Rust, CMake, платформенный C++ и существующий изолированный рабочий процесс, не требуя Qt. Упаковка Windows также требует существующий `prepare-windows-runtime.py` для подготовки закреплённой локальной среды VC++ с исходной лицензией. Общая точка сборки Qt также собирает CLI в частный каталог cli, не переименовывая исполняемый файл GUI, значок приложения или точки входа ассоциаций.

CLI, входящий в пакет macOS, находится в `Contents/Helpers/cli/`. Его обычный контекст JSON расположен в `Contents/Resources/xdzip-cli-context.json` и защищён подписью ресурсов приложения. CLI находит ресурс только в фиксированной структуре Contents/Helpers/cli и проверяет схему, настольный тип и фиксированный относительный путь GUI. Отсутствующие маркеры означают переносную идентичность; неверные отклоняются. Повторные сборки удаляют устаревшие сгенерированные маркеры в Helpers; не ослабляйте проверку подписи ради исправления структуры.

Новые настольные пакеты также объявляют `worker_relative` в контексте и разделяют рабочий процесс форматов с настольным приложением. Принимаются только фиксированные относительные пути платформы: соседний рабочий процесс рабочего стола в Windows, `Contents/MacOS/xdzip-native-codec` в macOS и соседний со сборкой или установленный в `bin/` процесс в Linux. Отсутствующий, связанный ссылкой или неожиданный рабочий процесс приводит к отклонению контекста без поиска в PATH или другой копии. Старые контексты без этого поля и автономные либо управляемые пакеты CLI сохраняют поиск соседнего процесса. Явное переопределение разработчиком имеет приоритет. Развёрнутый поиск проверяйте через `scripts/check-cli.py --default-worker`; одних тестовых переопределений недостаточно.

После распаковки автономного пакета запустите bin/xdzip, добавив .exe в Windows. `bin/xdzip setup` явно устанавливает стабильную пользовательскую точку входа и версионированный каталог среды. В Unix точка входа по умолчанию находится в ~/.local/bin, в Windows — в xdzip/cli/bin пользовательского LocalAppData. Каталоги управления используют платформенные расположения пользовательских данных. `--bin-dir` и `--install-dir` явно меняют пути. Пользователь самостоятельно добавляет каталог в PATH; инструмент не изменяет файлы запуска оболочки. Существующие точки входа и файлы регистрации никогда не перезаписываются.

Управляемая идентичность требует действительного installation.json. Каталог с именем versions без файла регистрации остаётся переносным.

При удалении работающего Windows-лаунчера принадлежащая инструменту копия с совпадающим хэшем перемещается в частный подкаталог .xdzip-retired того же каталога команд. Регистрация удаляется сразу, а результат записывает retained_launcher. Последующий явный setup очищает только копии из ограниченных квитанций, хэши которых всё ещё совпадают и процессы которых завершились. Изменённые файлы остаются и не перезаписываются. CLI в версионированном каталоге может повторно выполнить setup для восстановления регистрации.

Поле distribution отличает исходную сборку от идентичности выпуска. Обычная сборка из исходников, даже чистая и в конфигурации Release, поддерживает только проверку и загрузку. Автоматическая замена одновременно требует идентичность distribution от отдельного Release-конвейера, действительную управляемую установку и проверенную подпись цели.

Опция PATH установщика рабочего стола Windows по умолчанию выключена и отклоняет конфликты с другими командами xdzip. В Mac/Linux setup можно запустить из частного CLI настольного пакета; он регистрирует только CLI внутри настольной установки и не копирует отдельно обновляемое ядро. `setup --remove` удаляет только проверенные по хэшу точки входа и файлы регистрации, принадлежащие инструменту. Версионированные каталоги и материалы восстановления остаются; пользовательские данные и потенциально используемые каталоги среды не удаляются.

Стабильный лаунчер не использует экранирование оболочки. В Unix он выполняет реальный CLI через exec; в Windows ожидает дочерний консольный процесс и передаёт отмену и код выхода. Текущий каталог среды выбирает атомарный указатель current.json. Ошибка начальной установки, самопроверки новой версии или фиксации файлов не должна давать результат об успешной установке.

## Обновления, передача настольному приложению и восстановление

update относится к текущей установке. Автономный CLI обновляет только CLI; CLI внутри настольного пакета обновляет весь настольный выпуск. `--check` выполняет запрос, `--download` загружает и проверяет, операция по умолчанию устанавливает после подтверждения, а `--status` проверяет квитанции и фактическую идентичность. `--yes` подтверждает только это обновление и не заменяет системное разрешение. Переносные, изменённые, исходные или нераспознанные сборки могут только проверять и загружать. Для автоматической замены автономного CLI нужна управляемая чистая установка Release.

CLI использует фиксированные публичные GitHub Releases, канал и правила монотонного номера сборки. Пакеты CLI для трёх платформ имеют отдельные cli-release.json и cli-release.json.sig; встроенный открытый ключ проверяет исходные байты перед проверками размера и SHA-256. Отсутствие подписи или недоверенный ключ дают только сведения для ручного получения; неверная подпись явно отклоняется. Настольный release.json для шести пакетов не содержит записей CLI, а старые клиенты продолжают использовать исходный протокол.

Сеть по умолчанию использует системные сертификаты и стандартные переменные прокси. `--proxy` выбирает HTTP/SOCKS5-прокси без учётных данных; `--no-proxy` подключается напрямую; `--mirror` выбирает префикс HTTPS без учётных данных, запроса или фрагмента. Исходные URL GitHub, хосты перенаправления, размеры ответов, тайм-ауты и бюджеты загрузки остаются ограниченными. Сетевые ошибки, TLS, отсутствие сети, ограничение частоты и отсутствие совместимой новой версии сообщаются отдельно; автоматического опроса или повтора нет.

Автономное обновление подготавливается в частном каталоге пользователя, безопасно распаковывается через ту же среду архивов, проверяет полный фиксированный состав файлов и каждый хэш, продукт, компонент, локальные платформу и архитектуру, канал подписанного манифеста и запускает самопроверку новой версии `--version-json` до переключения указателя. Транзакции взаимно исключаются, а квитанции связаны с идентичностью цели. При сбое старый указатель сохраняется либо явно начинается восстановление; автоматический откат не выдумывается.

Проверка и загрузка настольного обновления запрашивают только неграфическую точку определения идентичности установки основного приложения; они не создают QApplication и не используют квитанции установки. Намерение установки передаётся через существующий канал единственного экземпляра того же пользователя, который принимает только ограниченный каталог запроса и версию кандидата, но не произвольные команды, пакеты или корни доверия. Файлы запроса и результата используют нативные разрешения каталогов Rust и безопасную фиксацию. Настольный контроллер независимо повторно проверяет и сопоставляет кандидата, используя существующие «О программе», установщик, Sparkle и барьер завершения всех задач. Настольные задачи CLI также удерживают защиту занятости установки; установка не может их уничтожить.

Терминал сообщает только handed_off после принятой передачи. Фактическая установка и восстановление зависят от настольных квитанций и идентичности работающего приложения; загрузка или передача не означает установку. Неинтерактивный режим отклоняет настольную установку, требующую GUI или системного разрешения. Границы безопасности установки и нативной приёмки описаны в [контракте обновлений](../../engineering/software-update.md). Автоматическая, нативная и ручная приёмка остаются разными видами проверки.

Профиль `.iso` создаёт несжатые образы данных ISO9660/Joliet уровня 0. Опустите `--level` или используйте `--level store`. Профиль Windows x64 `.sfx.exe` упаковывает ZIP Store/Deflate с помощью поставляемого соседнего `xdzip-sfx.exe`. Он отклоняет шифрование, solid-режим и тома. Ни один из профилей не поддерживает изменение существующего результата. См. [создание ISO](iso-creation.md) и [создание собственного SFX](sfx-creation.md).
