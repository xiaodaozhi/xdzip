# Проверка соответствия Qt SDK исходному коду

[English](../../engineering/qt-sdk-correspondence.md) | [简体中文](../../zh-CN/engineering/qt-sdk-correspondence.md) | [繁體中文（台灣）](../../zh-TW/engineering/qt-sdk-correspondence.md) | [日本語](../../ja-JP/engineering/qt-sdk-correspondence.md) | [한국어](../../ko-KR/engineering/qt-sdk-correspondence.md) | [Français](../../fr-FR/engineering/qt-sdk-correspondence.md) | [Deutsch](../../de-DE/engineering/qt-sdk-correspondence.md) | [Español](../../es-ES/engineering/qt-sdk-correspondence.md) | [Português (Brasil)](../../pt-BR/engineering/qt-sdk-correspondence.md) | Русский

Проверка соответствия использует фактические байты официальных архивов; совпадение номеров версий не доказывает эквивалентность сборки SDK. `scripts/qt_sdk_correspondence.py` связывает зафиксированные архивы исходного кода, предоставленные SDK SPDX исходников, декларации сборки, установленную конфигурацию и известные исправления потребителей SDK, записывая результат в build/. Инструмент не изменяет SDK и не утверждает варианты лицензии.

```sh
python3 scripts/qt_sdk_correspondence.py \
  --qt-prefix build/toolchain/Qt/6.8.2/macos \
  --output build/review/qt-sdk-correspondence.json
```

По умолчанию build/source-cache читается без сети и при отсутствии данных возникает ошибка. Только явно указанный --fetch загружает и проверяет официальные архивы из [зафиксированного манифеста](../../../scripts/corresponding-sources.json). Запускаемые по требованию Qt-процессы для трёх платформ выполняют --fetch после установки зафиксированного SDK и сохраняют JSON с другими записями проверки. На Mac по-прежнему загружаются только записи, без развёртывания, подписания или упаковки приложений. Если сборщик поставки исходников получает --qt-prefix, он включает эту запись, исправления и зафиксированный манифест в хеши поставки; см. [поставку исходного кода](source-delivery.md).

<a name="xdzip-verification-layers"></a>

## Уровни проверки

1. SHA-256 архива должен совпадать с зафиксированным значением; корень архива, пути элементов и фиксированный маркер `.tag` также должны совпадать. Тип объекта Git маркера записывается отдельно. Для маркера дерева сначала повторно вычисляется хеш зафиксированного исходного объекта коммита и проверяется его поле tree. Файлы читаются по отдельности без распаковки исходников проекта.
2. Если SDK предоставляет .source.spdx модуля, каждый объявленный SHA-1 сравнивается с содержимым архива. Записываются число совпадений, оба хеша различающихся файлов, объявленные SDK файлы, отсутствующие в архиве, и число неохваченных файлов архива. SHA-1 проверяет только исходную декларацию проекта; весь архив отдельно связывается зафиксированным SHA-256. Отсутствующие декларации, различия и неохваченные файлы не записываются как прошедшие проверку.
3. Сохраняются SPDX-хеши сборки модулей SDK, декларации компилятора и аргументы configure. Также читаются установленные modules/*.json, qconfig*.pri и заголовки конфигурации QT_FEATURE с сохранением содержимого и хешей. Абсолютные каталоги исходной сборочной среды в результате заменяются заполнителями; хеши файлов связывают исходные доказательства. Конфигурация не является полным кешем CMake, средой сборки или материалами инструментальной цепочки. Поля архитектуры SDK по умолчанию не представляют все архитектуры фактических библиотек и не позволяют ошибочно классифицировать универсальные библиотеки как x86_64.
4. [Исправление AGL](../../../scripts/qt-patches/macos-no-agl.patch) изменяет только lib/cmake/Qt6/FindWrapOpenGL.cmake в SDK, чтобы при использовании Qt этот проект не связывался со старым AGL. Инструмент читает оригинал из зафиксированного архива QtBase, применяет унифицированный diff, проверяет SHA-256 исправления, оригинала и результата, затем проверяет фактический файл SDK. Принимаются только оригинал или известная исправленная версия. CRLF SDK Windows сравнивается только после нормализации окончаний строк; сохраняются SHA-256 фактических байтов, SHA-256 LF и признак преобразования. Другие неизвестные изменения приводят к ошибке. Это не изменяет машинный код среды выполнения Qt и не доказывает пересборку Qt. Полную историю изменений SDK ещё необходимо проверить.

Записи соответствия исходников используют схему 2 и раздельно хранят зафиксированный archive_commit, фактический archive_marker архива, archive_marker_type и commit_tree_verified. `.tag` Qt Declarative 6.8.2 — дерево Git `0a8139c574fe150aba92d5f2484a8f3fdb774977`; тег выпуска соответствует коммиту `75534f3e7fff24ed7ccb364e2ed9950a73da879f`. Зафиксированный в репозитории исходный объект коммита в base64 позволяет без сети пересчитать хеш коммита и проверить его поле tree. Остальные сейчас зафиксированные маркеры модулей являются коммитами. Связь дерева устанавливает лишь отношение этих двух объектов Git, но не доказывает, что архив содержит всё дерево или сборка SDK эквивалентна ему.

source_commits в qt-license-sources.json обозначают только зафиксированные коммиты получения лицензионных текстов и хранятся отдельно от маркеров архивов и коммитов выпуска. Их нельзя представлять как коммиты сборки SDK. Исторические материалы схемы 1 помещали маркер дерева Qt Declarative в archive_commit; опубликованные материалы остаются без изменений. Последующие пояснения должны исправлять тип объекта и продолжать проверять тексты лицензий по исходному SHA-256.

<a name="xdzip-interpreting-results-and-release-boundaries"></a>

## Интерпретация результатов и границы выпуска

Производная версия безопасности QtNetwork отдельно записывает `network_security`; подтверждения связывают исправления, сборщик, дайджесты исходного QtCore и фактического QtNetwork, функции и реальную проверку транспорта. При чтении подтверждений инструмент повторно проверяет фактические байты SDK. Эти доказательства относятся только к изменённой библиотеке; исходный SPDX не переписывается как доказательство производной версии, а неохваченные факты других модулей не меняются. Входные данные и сопровождение описаны в [примечаниях к исправлениям Qt](../../../patches/qt/README.md).

Наличие SPDX исходников у модулей, количество совпадений, отсутствующих и неохваченных файлов, конфигурация и состояние исправлений определяются JSON текущего запуска. Нельзя переносить наблюдения одного SDK на другой. Без пофайловых деклараций нельзя заключать, что соответствие подтверждено; конкретные пробелы сохраняются.

Состояние отчёта всегда evidence-collected-not-build-equivalence. Для [фактической сборки исходников Qt и их загрузки или замены](../../../developers/engineering/candidate-verification.md#qt-source-and-compatible-replacement) существует отдельная процедура, но она не доказывает побайтовое воспроизведение исходного SDK. Пока полностью не выяснены материалы инструментальной цепочки и системного SDK, неохваченные или сгенерированные файлы, происхождение компонентов времени выполнения и соблюдение лицензий, нельзя утверждать, что все обязательства по соответствующему исходному коду выполнены или сборки воспроизводимы побайтно. Сохраняются неполный статус [атрибуции компонентов времени выполнения](runtime-attribution.md), выбор лицензий и проверки компонентов платформ.
