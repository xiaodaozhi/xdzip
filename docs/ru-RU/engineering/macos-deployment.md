# Локальный DMG для разработки на macOS

[English](../../engineering/macos-deployment.md) | [简体中文](../../zh-CN/engineering/macos-deployment.md) | [繁體中文](../../zh-TW/engineering/macos-deployment.md) | [日本語](../../ja-JP/engineering/macos-deployment.md) | [한국어](../../ko-KR/engineering/macos-deployment.md) | [Français](../../fr-FR/engineering/macos-deployment.md) | [Deutsch](../../de-DE/engineering/macos-deployment.md) | [Español](../../es-ES/engineering/macos-deployment.md) | [Português (Brasil)](../../pt-BR/engineering/macos-deployment.md) | Русский

Специальный workflow Release разрешает нативное развёртывание, необходимую подпись ad-hoc, упаковку app.zip и DMG и их загрузку. Задание macOS в запускаемом по запросу workflow Qt сохраняет проверку SDK. Для обоих релизных пакетов используется один развёрнутый, подписанный и проверенный .app; приложение, извлечённое из ZIP, дополнительно проверяется на запуск после перемещения. См. [протокол выпуска](release-protocol.md).

Локальный DMG для разработки является допустимым результатом разработки. Запускаемый по запросу workflow Qt проверяет нативную сборку и запуск на Apple Silicon без упаковки, подписания или загрузки приложения Mac. Локальные скрипты не устанавливают приложение, не меняют ассоциации по умолчанию, не загружают файлы и не читают учётные данные выпуска.

## Сборка и проверка

Предварительная проверка среды и параметры этапов описаны в [руководстве по сборке для разработчиков](../../engineering/developer-build.md). Подготовьте инструменты упаковки, соберите отдельное основное приложение Release из чистого коммита, затем упакуйте и проверьте:

```sh
python3 scripts/desktop.py prepare --packaging
python3 scripts/desktop.py build --build-dir build/desktop-dmg --macos-handler-rank Alternate
python3 scripts/desktop.py test --build-dir build/desktop-dmg
python3 scripts/desktop.py doctor --for-stage package --build-dir build/desktop-dmg
python3 scripts/desktop.py package --build-dir build/desktop-dmg --output-dir build/package-macos --kind all
python3 scripts/desktop.py verify --build-dir build/desktop-dmg --output-dir build/package-macos --kind all
```

Этапы не запускают предыдущие автоматически. Стандартный Qt SDK находится в `build/toolchain/Qt/6.8.2/macos`; для другого расположения передайте каждой команде `--qt-prefix`. Обычные сборки для разработки и тестирования по умолчанию используют `None`; основное приложение выше явно выбирает `Alternate`, не меняя пользовательские настройки по умолчанию. Локальный пакет macOS поддерживает только `all`. Workflow Qt по запросу не упаковывает и не загружает приложения Mac; исключение для специального Release описано в протоколе выпуска.

Перед macdeployqt общие проверки пакета проверяют нативный arm64, системный SDK, инструменты развёртывания, PATH и зафиксированные метаданные Rust, зависимости Python для проверки, а также материалы лицензий и схем Qt. build и test допускают незакоммиченный исходный код; package требует чистый коммит и соответствующую фактическую идентичность CLI, и кэш компиляции не позволяет обойти эти условия. Системный компилятор, SDK, lipo, codesign и hdiutil предоставляет системная цепочка инструментов, а не prepare.

macdeployqt также перемещает процесс предварительного просмотра изображений. В стандартный выбор платформенных плагинов Qt 6.8 входит только Cocoa, поэтому скрипт упаковки явно копирует offscreen до анализа библиотек приложения, чтобы обработать его зависимости от фреймворков Qt. Отсутствие плагина или рабочего процесса останавливает упаковку. После подписи целостности и аудита импортов очистите переопределения поиска Qt/QML/DYLD и проверьте набор форматов фактически включённого процесса изображений и декодирование собственного PNG; запись находится в `image-preview-deployed.json`. Модульные проверки скриптов не подтверждают приёмку развёрнутого пакета.

Нижележащие [build-macos-dmg.py](../../../scripts/build-macos-dmg.py) и [verify-macos-dmg.py](../../../scripts/verify-macos-dmg.py) содержат подробности об образе и нативной проверке. Для диагностики используйте их `--help`, не поддерживая отдельные повседневные инструкции. Их выходные пути должны быть новыми и находиться внутри build/. Каждый тип документа во входном приложении DMG должен объявлять `Viewer/Alternate`; иначе пересоберите приложение, а не переписывайте plist или подписи исходного пакета. macdeployqt анализирует фактический QML и развёртывает фреймворки Qt, плагины и QML. Добавьте переводы системных элементов Qt, уведомления проекта, уведомления вышестоящих проектов Rust, лицензии шрифтов, исходный SBOM и зафиксированные лицензионные материалы Qt. Сохраните внутренние символьные ссылки фреймворков и отклоняйте ссылки за пределы приложения. Удалите абсолютные RPATH компьютера разработчика и рекурсивно проверьте, что все нативные импорты разрешаются только в приложении или системе. Идентичность сборки не должна быть изменённой или неизвестной и должна соответствовать текущему чистому коммиту, чтобы связать фактические уведомления с ним.

Необязательный QML LocalStorage Qt использует QtSql, поэтому развёртывание копирует и драйверы баз данных. Продукт не поддерживает серверные базы данных; удалите драйверы кроме встроенного SQLite, чтобы в образ не попали PostgreSQL, ODBC, Mimer и другие клиенты вне SDK. Запишите удаления в отчёт и не выдавайте неразрешённые импорты за успешную проверку.

## Сокращение архитектур и стилей

DMG для разработки содержат только `arm64` для Apple Silicon. Настройки архитектуры CMake основного приложения не ограничивают файлы Qt SDK, копируемые macdeployqt, поэтому рекурсивно проверяйте каждый Mach-O в приложении, включая фреймворки, динамические библиотеки, плагины и нативные плагины QML. Сокращайте файлы с двумя архитектурами до одного `arm64` только в новой копии для упаковки. Отсутствие `arm64`, неизвестные архитектуры или оставшиеся дополнительные секции приводят к ошибке упаковки; архитектура основного исполняемого файла не заменяет проверку вложенных файлов. Сокращение выполняется до изменения RPATH и рекурсивной подписи ad-hoc.

Продукт использует Qt Quick Controls `Basic`. Развёртывание удаляет только явно перечисленные стили, отличные от Basic, и их выделенные импорты или плагины реализации, сохраняя Basic, общие элементы, Templates и фактические зависимости QML. Не уменьшайте пакет удалением неизвестных модулей. Неожиданное расположение стилей, отсутствие сохраняемых зависимостей или остатки неиспользуемых стилей приводят к ошибке аудита. При изменении стиля продукта или Qt SDK нужно одновременно обновить правила сокращения и тесты. Уменьшение размера не исключает лицензии Qt, материалы соответствующего исходного кода, системные переводы или необходимые плагины среды выполнения.

Оптимизируйте только новое подготовленное приложение в ограниченном `build/`, а не исходное основное приложение, Qt SDK или исходный код. Отчёты сохраняют проверки архитектуры и стилей, сокращённые бинарные файлы, списки удалений и фактические логические байты приложения до и после оптимизации с категориями фреймворков, плагинов, QML и прочего. Байты считаются по фактическому содержимому файлов без двойного учёта символьных ссылок; это не размер на диске Finder и не размер образа UDZO. Итоговый размер DMG записывается отдельно. Сравнения конкретных версий, выводы проверки и оставшаяся работа записываются в issues; исходные измерения остаются локальными артефактами.

`scripts/test-macos-bundle.py` использует небольшие собственные тестовые данные проекта в кроссплатформенной CI и проверяет распознавание архитектуры, работу только с копией, границы символьных ссылок, сохранение и удаление стилей и ошибки без средств развёртывания macOS. Он не заменяет проверку конечного пакета. Проверки DMG должны после копирования из подключённого образа рекурсивно подтвердить наличие только `arm64` во всех нативных файлах и соответствие стилей контракту, а также выполнить описанные ниже проверки изоляции поиска SDK и сценарии Cocoa/Metal.

## Проверка образа и выполнения

Сжатый образ UDZO содержит xdzip.app, ссылку Applications и инструкции по установке; выполните hdiutil verify. Штатно завершите старые версии до перетаскивания в Applications. В этом процессе нет обновления приложения или переноса задач при установке. Настройки и недавние элементы остаются в пользовательских каталогах и не удаляются автоматически при удалении приложения.

Храните JSON проверки развёртывания и CycloneDX SBOM на уровне файлов рядом с образом, связав их с инвентарём исходников того же коммита, итоговыми SHA-256 нативных файлов и связями импортов. SBOM остаётся неполным; перечисление файлов не является точным определением происхождения компонентов или утверждением лицензий. Инвентарь хранится вне образа во избежание рекурсивного хеширования самого себя.

Новый подготовленный `xdzip.app` существует только во время развёртывания, подписи, создания образа и проверки и автоматически удаляется как при успехе, так и при ошибке. DMG, JSON, SBOM и инструкции остаются; исходное основное приложение не изменяется. Отдельный подготовленный пакет, который система могла бы обнаружить повторно, не остаётся.

Изменённым ARM64 Mach-O нужны действительные кодовые каталоги, поэтому после копирования и изменения примените локальную подпись ad-hoc и проверьте вложенный код. **Это не подпись Developer ID и не нотариальное заверение и не означает доверия Gatekeeper.** Согласно [личной политике выпуска открытого ПО](../../../developers/engineering/release-runbook.md), формальная подпись и нотариальное заверение не обязательны для выпуска; проверка зависимостей, лицензий, безопасности и фактического пакета по-прежнему необходима. Не отключайте SIP и не удаляйте глобальные политики безопасности пользователя.

Скрипт проверки монтирует образ только для чтения, проверяет ссылку Applications, копирует приложение в изолированный путь с китайскими символами и пробелами и рекурсивно проверяет arm64, стили Basic и строгие подписи каждого нативного файла и пакета. После удаления переменных поиска SDK/QML/плагинов он запускает и закрывает приложение с Cocoa/Metal. Фактический продукт из образа открывает самостоятельно созданный ZIP, выполняет поиск, сортировку, извлечение и выход, независимо проверяет Unicode, пустые файлы и каталоги и каждый байт результата, а также проверяет идентичность сборки, архитектуру и backend Metal на фактическом первом кадре. Затем только в проверочной копии меняется идентичность библиотеки QtCore Mach-O и применяется повторная подпись ad-hoc; архитектура, стиль, подписи и запуск проверяются снова. Это подтверждает возможность изменения или замены развёрнутой библиотеки, но не доказывает пересборку Qt из соответствующего исходного кода, произвольную совместимость ABI или юридическое одобрение соответствия.

Проверка app.zip также использует стандартный параметр продукта для создания одноимённой папки при извлечении всего приложения, поэлементно сравнивает байты файлов, цели ссылок и безопасные разрешения с `ditto`, затем выполняет глубокую строгую проверку подписи и запуск Cocoa/Metal фактически извлечённого приложения. Внешний каталог не должен оканчиваться на `.app`. Временные приложения и регистрации, созданные проверкой, затем удаляются. Границы доверия подписи и нотариального заверения при этом не меняются.

На локальном компьютере всё ещё установлен SDK; проверки импортов и очистка среды не заменяют отдельный чистый Mac. Перетаскивание через Finder, системное «Открыть в программе», выбор по умолчанию, Gatekeeper, фактический перезапуск и подпись/нотариальное заверение остаются предметом [ручной проверки](../../../developers/qa/private-test-manual.md).

Командам редактирования нативных меню и стандартным элементам Qt нужны переводы qtbase системной локали. Кроме копирования `Contents/Resources/translations/qtbase_*.qm`, упаковка задаёт `Translations = Resources/translations` в `[Paths]` файла `Contents/Resources/qt.conf`, сохраняет существующие пути плагинов и QML и записывает файл до подписи целостности. Проверки запуска после перемещения проверяют и нативные обработчики редактирования, и роли меню приложения; проверок в каталоге разработки SDK недостаточно.

## Локальная подпись и включение Finder Sync

Finder Sync использует нативный appex и независимый relay внутри того же приложения; служебный помощник сохраняется. Полный порядок подписи: нативные образы, фреймворки и выделенные помощники, appex с точными правами песочницы, пакет relay и внешнее приложение, затем строгая проверка вложенного пакета. Не перезаписывайте подписанный appex позднее общей подписью без прав. Обычные сборки CI не подписывают и не включают расширение автоматически.

Для локальной проверки Finder завершите стандартную нативную сборку, затем явно выполните:

```sh
python3 scripts/sign-macos-finder.py --app build/desktop/apps/desktop/xdzip.app --output build/review/finder-signing.json
build/desktop/apps/desktop/xdzip.app/Contents/MacOS/xdzip --register-shell-integration
```

Скрипт подписи принимает только приложения проекта и выходные файлы внутри `build/` репозитория; он не развёртывает Qt, не создаёт DMG и не читает учётные данные выпуска. Его отчёт подтверждает только целостность ad-hoc и строгую вложенную проверку, но не Developer ID, нотариальное заверение, доверие Gatekeeper или одобрение лицензий выпуска. Приложение должно оставаться на исходном месте. Включите расширение Finder xdzip в системных настройках, в разделе объектов входа и расширений. Пути настроек и меню могут отличаться в разных версиях ОС; успешная регистрация не подтверждает приёмку меню или действия.

Перед завершением временной проверки используйте `--remove-shell-integration` того же приложения, чтобы отозвать собственные регистрации службы и расширения. Проверив исходное состояние, удаляйте только настройки и временные регистрации LaunchServices, созданные этой работой. Не меняйте другие приложения или ассоциации по умолчанию. Если Finder загрузил приложение, после обновлений выключите и снова включите собственное расширение в системных настройках, а не перезапускайте Finder. Границы передачи и отката описаны в [действиях файлового менеджера](shell-actions.md).

## Регистрация «Открыть в программе» для копий разработки и проверки

LaunchServices запоминает ранее открытые пакеты приложений; несколько копий с одним ID пакета в дереве сборки могут появляться в меню «Открыть в программе» системы или Codex. По этой причине не удаляйте системную базу, не перезапускайте Finder, не удаляйте проверочные пакеты и не меняйте пользовательские значения по умолчанию.

Новые пакеты разработки по умолчанию используют `LSHandlerRank=None` в созданном Info.plist; только выбранное основное приложение и поставляемый пакет сохраняют `Alternate`. Параметр CMake `XDZIP_MACOS_HANDLER_RANK` строго допускает только эти два значения. Автономная пересборка исходного кода, проверка продукта Qt из исходников и CI продукта Mac явно передают `None`, чтобы будущие изменения значения по умолчанию не возвращали тестовые копии в кандидаты. [Определение Apple для `None`](https://developer.apple.com/library/archive/documentation/General/Reference/InfoPlistKeyReference/Articles/CoreFoundationKeys.html) сохраняет перетаскивание файлов, не выбирая пакет обработчиком открытия типа. Оно не влияет на выбор файла в приложении или явное открытие приложения и не задаёт значения по умолчанию.

CI продукта Mac запускает `scripts/check-macos-registration.py` для запроса файловых кандидатов нового пакета через нативный `NSWorkspace`. Число кандидатов и регистрации, перечисленные по ID пакета, оцениваются отдельно; последние не заменяют фактические пользовательские кандидаты «Открыть в программе». Существующие обработчики по умолчанию должны сохраняться при временной регистрации. Типы без предыдущего обработчика могут временно разрешаться в нового кандидата; после отмены регистрации для всех проверенных типов должны восстановиться исходные обработчики и состояния кандидатов. Настройки `LSHandlers` текущего пользователя сравниваются только как снимки в памяти до, во время и после регистрации; их содержимое не выводится. Другие настройки и системные правила не входят в это сравнение.

`scripts/macos_launch_services.py` распознаёт только `org.xdzip.desktop`. Перемещение DMG, автономная пересборка исходников, проверка продукта Qt из исходников, замена QtCore и проверка системного открытия файлов записывают регистрации до запуска в пределах `build/` и при завершении или ошибке отменяют только регистрации добавленных тестовых копий. Существующие основные приложения и другие продукты сохраняются. Ошибка очистки приводит к ошибке проверки, а не молча считается успехом.

Перемещение DMG и замена QtCore сохраняют исходные объявления документов и проверки поставляемых пакетов, но копируют только в новые, не существующие пути `.app` внутри `build/`. Новый пакет автоматически удаляется после проверки или ошибки, необходимые хеши фиксируются в его области. JSON, журналы, основной пакет до замены, DMG и исходники Qt остаются. Очистка не принимает существующие приложения или символьные ссылки и не удаляет старые проверочные пакеты задним числом. Старые пакеты `Alternate`, регистрацию которых только отменили, могут быть вновь обнаружены и зарегистрированы системой или другими приложениями; постоянное отсутствие повторения не гарантируется. Если старые пакеты необходимо сохранить, до обработки отдельных копий их можно поместить в проверяемые и восстанавливаемые резервные копии с явного разрешения.

Просмотрите исторические остатки указанной утилитой, затем явно примените очистку. `--keep` должен указывать на существующее правильно идентифицированное основное приложение: текущую сборку разработки или установку в Applications.

```sh
python3 scripts/cleanup-macos-open-with.py --keep build/ui-release/apps/desktop/xdzip.app
python3 scripts/cleanup-macos-open-with.py --keep build/ui-release/apps/desktop/xdzip.app --apply
```

Утилита отменяет регистрацию только других копий xdzip внутри `build/` этого репозитория и недействительных путей с той же идентичностью. Она не удаляет пакеты, не меняет подписи и не задаёт приложение ZIP по умолчанию. Другие продукты, другие установки Applications и пути вне дерева сборки автоматически не обрабатываются. Пути, разрешающиеся через символьные ссылки за пределы области, не очищаются. Повторно проверьте регистрации, оставив только указанное основное приложение разработки. Если вне дерева сборки есть несколько установок, перечислите их отдельно как необработанные; не заявляйте о глобальном устранении дубликатов.

Запишите ход очистки, количество и выводы в соответствующий issue, например [обслуживание копий разработки #7](https://github.com/xiaodaozhi/xdzip/issues/7). Созданные JSON и результаты нативных проверок остаются только в локальных или CI-артефактах.
