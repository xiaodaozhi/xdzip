# Лицензирование средств разработки и среды выполнения Windows

[English](../../engineering/windows-licensing.md) | [简体中文](../../zh-CN/engineering/windows-licensing.md) | [繁體中文（台灣）](../../zh-TW/engineering/windows-licensing.md) | [日本語](../../ja-JP/engineering/windows-licensing.md) | [한국어](../../ko-KR/engineering/windows-licensing.md) | [Français](../../fr-FR/engineering/windows-licensing.md) | [Deutsch](../../de-DE/engineering/windows-licensing.md) | [Español](../../es-ES/engineering/windows-licensing.md) | [Português (Brasil)](../../pt-BR/engineering/windows-licensing.md) | Русский

Эта страница определяет применимые пути сборки и распространения Windows и используется вместе с [материалами системной среды](native-runtime-materials.md), [точкой сборки для разработчика](developer-build.md) и [контрактом установки](installers-associations.md). Конкретные среды, проверочные коммиты, хеши материалов и результаты приемки записываются в issue и локальные или CI-артефакты; страница не хранит доказательство лицензии отдельной машины.

<a name="xdzip-free-community-path-and-local-choice"></a>

## Бесплатный Community и локальный выбор

Оригинальное содержимое проекта опубликовано под Apache-2.0, лицензией открытого кода, одобренной OSI. Индивидуальные условия Visual Studio Community 2022 разрешают частным лицам разрабатывать собственные приложения; условия организаций также разрешают пользователям разрабатывать и тестировать приложения, выпущенные под лицензиями, одобренными OSI. Использование открытого кода организацией оценивать отдельно от другого коммерческого внутреннего применения; не переносить пригодность этого проекта на другие проекты.

Если сопровождающему нужна собственная среда Community, получить Community 2022 через [официальный установщик Microsoft](https://learn.microsoft.com/en-us/visualstudio/install/use-command-line-parameters-to-install-visual-studio?view=vs-2022), прочитать и принять [исходные условия этой версии](https://visualstudio.microsoft.com/license-terms/vs2022-ga-community/) и использовать ее в их рамках. Для сборки C++ выбрать `Microsoft.VisualStudio.Component.VC.Tools.x86.x64` и Windows SDK; устанавливать все рабочие нагрузки не требуется. Покупка Professional/Enterprise или отдельная заявка на сертификат распространения среды выполнения для каждого проекта не требуются.

Проверка лицензирования не требует постоянной локальной установки большой IDE. При сборке и публикации только в стандартной размещенной среде GitHub ниже применяются разрешение на размещенный Visual Studio и его условия REDIST; устанавливать локальный Community или покупать личный Enterprise для размещенной CI не нужно. Community — бесплатный выбор для сопровождающих, которым нужна собственная среда, а не дополнительное условие локальной установки для законности размещенной сборки.

Раздел 3 Community допускает файлы ПО и Build Tools на подходящих устройствах сборки; раздел 4 предоставляет права распространения перечисленного распространяемого кода при соблюдении требований к функциональности, последующих условий и ограничений. Загрузка VC_redist, установка Build Tools или одно приложение текста лицензии не доказывают право использовать инструменты разработки. Без лицензии Visual Studio исключение Build Tools охватывает компиляцию и сборку опубликованных третьими лицами компонентов C++ с открытым кодом, одобренных OSI и обоснованно необходимых для сборки собственных приложений. Оно не разрешает разработку или тестирование этих зависимостей, кроме небольших изменений, необходимых для их компиляции и сборки, и не является общим исключением для разработки всех собственных программ C++. Использование VS Code не предоставляет автоматически лицензию MSVC. См. [рекомендации Microsoft по лицензированию](https://www.microsoft.com/licensing/guidance/Visual-Studio) и [условия Build Tools](https://visualstudio.microsoft.com/license-terms/vs2022-ga-diagnosticbuildtools/).

Локально проверить продукт, полную версию, отсутствие статуса предварительной версии и компоненты C++, сообщаемые `vswhere`, войти в среду разработки фактического экземпляра и проверить `cl`, `link` и SDK. Установленные Build Tools 2019 не являются Community 2022 и не заменяют проверку текущего набора MSVC 2022. Общий `desktop.py prepare` не устанавливает системную IDE или SDK молча; для первой установки использовать установщик Microsoft, сохранять существующие инструменты и запрещать автоматическую перезагрузку.

Выбор 2022 — текущее решение для инструментов выпуска, а не утверждение, что бесплатная лицензия Community разрешает только 2022. [Таблица поддержки Qt 6.8](https://doc.qt.io/qt-6.8/supported-platforms.html) указывает Windows MSVC 2022; этот репозиторий использует соответствующий SDK `msvc2022_64`. Инструменты 2019 можно оставить для локальной разработки, но одной совместимости ABI между версиями недостаточно для подтверждения полной поддержки при смешивании с текущим SDK. [Правила совместимости Microsoft](https://learn.microsoft.com/en-us/cpp/porting/binary-compat-2015-2017?view=msvc-170) также обычно требуют, чтобы конечный компоновщик был не старее инструментов входных библиотек, и отдельно ограничивают библиотеки среды выполнения и `/GL`/`/LTCG`. Альтернативным конфигурациям нужны собственные лицензия и проверка; это не обязывает локально устанавливать полную IDE 2022.

<a name="xdzip-github-hosted-builds"></a>

## Сборки, размещенные GitHub

Windows workflow проекта использует стандартные размещенные GitHub исполнители `windows-2022`. Предустановлен Visual Studio Enterprise 2022, а не Community. Сопровождающие runner-images явно [подтвердили](https://github.com/actions/runner-images/issues/12945#issuecomment-3348002951), что предустановленный Enterprise доступен для публичных и частных размещенных исполнителей GitHub Actions/Azure DevOps по соглашению GitHub и Microsoft без отдельной личной лицензии Enterprise. Проект опирается на эту размещенную среду сборки; публичное объяснение не заменяет и не претендует на раскрытие полного соглашения.

Согласно [документации GitHub о размещенных исполнителях](https://docs.github.com/en/actions/concepts/runners/github-hosted-runners), каждое задание Windows получает независимую VM, а `Set up job` указывает образ и список ПО этого запуска. Workflow компилируют, тестируют, развертывают и выпускают только этот репозиторий в рамках [дополнительных условий Actions](https://docs.github.com/en/site-policy/github-terms/github-terms-for-additional-products-and-features#actions). Бесплатный вычислительный лимит публичного репозитория и права распространения компонентов Microsoft различаются.

CI записывает фактический продукт и версию VS, относительное расположение компилятора, версии инструментов и SDK в `windows-toolchain.json`, который хранится с пакетами и материалами того же коммита без ключей продукта и личных путей разработчиков. Это идентификация инструментов, а не автоматическое доказательство права лицензирования. Самостоятельно размещенные исполнители, скопированные из образов локальные инструменты, другие CI и общие серверы не наследуют размещенную лицензию; повторно проверить условия Community/Build Tools и устройств.

<a name="xdzip-microsoft-component-redistribution"></a>

## Распространение компонентов Microsoft

[Список REDIST VS 2022](https://learn.microsoft.com/en-us/visualstudio/releases/2022/redistribution) явно включает Community 2022 с действительной лицензией. Текущая сборка использует выпускной VC_redist x64, зафиксированный в [windows-runtime.json](../../../scripts/windows-runtime.json), извлекает его без изменений и отдельно проверяет восемь DLL CRT и исходную лицензию среды выполнения. Компиляторы, отладчики и `debug_nonredist` не включаются в пакет. Ни бесплатный Community для разработки, ни Enterprise-идентичность размещенной CI не перелицензируют DLL Microsoft под Apache-2.0.

Новые пакеты разработки не содержат `d3dcompiler_47.dll`, `dxcompiler.dll` или `dxil.dll` из Windows SDK, а также программную библиотеку OpenGL Mesa. В исторических пакетах эти три файла брались из `Redist/D3D/x64` указанного SDK. [Список REDIST SDK](https://learn.microsoft.com/en-us/legal/windows-sdk/redist) разрешает неизмененное распространение с приложениями Classic Windows при действительной лицензии SDK и запрещает распространение с приложениями UWP; xdzip — настольное приложение Classic Windows. Исторические лицензии, уведомления и условия распространения SDK продолжают применяться отдельно, даже если будущие пакеты удалят эти файлы.

Включенный `share/notices/Windows-runtime-NOTICE.txt` объясняет границы лицензирования каждого компонента на двух языках. Исходные условия Microsoft CRT находятся в `Microsoft-VC-runtime/license.rtf`. Установщик показывает исходное соглашение CRT и требует согласия, затем показывает уведомления компонентов. Пользователи переносимого пакета также должны прочитать и соблюдать включенные условия Microsoft. Оба пакета сохраняют оригинальные лицензии и происхождение. Последующие распространители должны самостоятельно соблюдать условия права использования и распространения; одна лицензия Apache-2.0 проекта не разрешает передачу компонентов Microsoft.

Показ или включение текста SDK само по себе не доказывает, что внешние распространители и конечные пользователи приняли требуемые SDK защитные условия, и не заменяет оценку действительности лицензии и ответственности издателя. Текущая страница согласия установщика относится только к CRT. Если графические DLL SDK будут снова распространяться, отдельно оценить применимые условия и согласие для установочного и переносимого пакетов и сохранить фактические доказательства в записи выпуска; см. исторический [#135](https://github.com/xiaodaozhi/xdzip/issues/135).

Перед компиляцией установщика проверить зафиксированный хеш соглашения CRT и двуязычного уведомления; материалы включают тот же исходный текст CRT и запись происхождения. Исторические условия SDK находятся в `Windows-SDK-graphics/sdk_license.rtf`. Исправления лицензирования не переписывают старые публичные ресурсы или историческую идентичность сборки; исправленные пакеты выпускаются с новой версией по [неизменяемому протоколу выпуска](release-protocol.md).
