# Контракты интерфейсов и проверки

[English](../../engineering/contracts.md) | [简体中文](../../zh-CN/engineering/contracts.md) | [繁體中文](../../zh-TW/engineering/contracts.md) | [日本語](../../ja-JP/engineering/contracts.md) | [한국어](../../ko-KR/engineering/contracts.md) | [Français](../../fr-FR/engineering/contracts.md) | [Deutsch](../../de-DE/engineering/contracts.md) | [Español](../../es-ES/engineering/contracts.md) | [Português (Brasil)](../../pt-BR/engineering/contracts.md) | Русский

Интерфейсы описаны в [модели предметной области](../design/domain-data.md), [мосте Qt/Rust](../design/qt-rust-bridge.md), [проекте расширений форматов](../design/codec-extension-sdk.md) и [планировании задач](../design/task-scheduling.md). Здесь указаны проверки перед фиксацией интерфейсов. Внутренний мост, два дескриптора и жизненный цикл уже реализованы. Границы описаны в [контракте выполнения](product-runtime.md). Также реализованы поколения запросов, проверки версий источника и операции создания и распаковки. См. [контракт просмотра](../../engineering/readonly-browser.md), [безопасную распаковку](zip-safe-extraction.md) и [создание архивов](zip-creation.md). Протокол для сторонних процессов имеет отдельное [испытание SDK в режиме чтения](sdk-trial.md). Стабильный SDK не выпущен, интеграции в продукт нет. Таблица перечисляет условия интеграции.

| Граница | Что подтвердить перед реализацией | Какие сбои проверить |
| --- | --- | --- |
| Интерфейс → мост | Владение дескрипторами, RequestId, неблокирующая подача, отказ при завершении | Полная очередь, повторное завершение, уничтоженный объект |
| Мост → интерфейс | session/query/generation/revision, пакеты страниц, порядок событий | Отбрасывание устаревших ответов, ошибка сужения целого, сохранение конечного состояния |
| Среда выполнения → кодек | Возможности вместо расширений, источник чтения, приёмник вывода, токен отмены | Неподдерживаемые функции, ошибки CRC, неполное чтение или запись |
| Среда выполнения → безопасный ввод-вывод | Разрешённый корень, сопоставление, подготовка, разрешение и подтверждение записи | Гонки на ссылках, заполненный диск, изменившаяся цель перезаписи |
| Расширение → хост | Версия рукопожатия, пределы кадров, возможности, жизненный цикл сеанса | Некорректные или слишком большие кадры, тайм-аут, перестановка, отказ в отмене |

Каждый интерфейс определяет корректность входа, владение, потоки, бюджеты ресурсов, категории ошибок, идемпотентность и границы отмены. Неизвестное значение отличается от нуля. TaskId и EntryId выполняют разные задачи. Выбранные элементы идентифицируются по записям, независимо от номеров строк.

CLI и графический интерфейс используют общие службы Rust. Catalog возвращает до 128 физических записей метаданных на страницу. SelectMembers разрешает полные эффективные пути и EntryId в одном неизменяемом сеансе, затем отправляет существующие задачи. Идентификаторы списка относятся только к своему сканированию и теряют силу после изменений архива. submit_wait ждёт только короткую блокировку допуска. Предел очереди и отказ при завершении остаются прежними. Графический интерфейс не раскрывает QML-кодирование внутренних команд. CLI не пишет файлы с путями из экранированного текста отображения.

Фиксированные метаданные хоста используют open_regular_nofollow, авторизацию каталога и проверку размера и идентичности. Символические ссылки и точки повторной обработки в конце пути отклоняются. Для чтения архивов, выбранных пользователем, сохраняются правила альтернативных путей. Запросы CLI к приложению передают ограниченный каталог запросов через необязательное расширение `cli_protocol=1` для единственного экземпляра того же пользователя. Прежний протокол открытия сохраняет версию 1. Экземпляр без расширения не подтверждает передачу запроса CLI. См. [контракт CLI](command-line.md) для результатов, кодов выхода и границ установки.

Внутренние контракты могут меняться с реализацией и обновляются в том же коммите. Сторонний протокол называют стабильным v1 после того, как две независимые реализации взаимодействуют и проходят тесты совместимости. Неизвестные версии явно отклоняются или по правилам согласования заменяются совместимой версией.
