# Структура репозитория и зависимости

[English](../../engineering/repository-layout.md) | [简体中文](../../zh-CN/engineering/repository-layout.md) | [繁體中文](../../zh-TW/engineering/repository-layout.md) | [日本語](../../ja-JP/engineering/repository-layout.md) | [한국어](../../ko-KR/engineering/repository-layout.md) | [Français](../../fr-FR/engineering/repository-layout.md) | [Deutsch](../../de-DE/engineering/repository-layout.md) | [Español](../../es-ES/engineering/repository-layout.md) | [Português (Brasil)](../../pt-BR/engineering/repository-layout.md) | Русский

Действующие модули продукта определены в корневых Cargo.toml и CMakeLists.txt. Таблица описывает существующие каталоги. Разделение на новые пакеты в архитектурных проектах относится к будущим изменениям.

| Каталог | Ответственность и зависимости |
| --- | --- |
| apps/desktop | Qt/QML, тонкие контроллеры C++, модели, настройки и взаимодействие с системой. Доступ к ядру через мост. |
| crates/xdzip-cli | Аргументы, терминал, JSON, управляемая установка и обновление без Qt. Прямые зависимости от среды выполнения, безопасного ввода-вывода и ядра обновления. Интерпретация форматов делегирована. |
| crates/xdzip-domain | Чистые типы и инварианты. Зависимости от Qt и конкретных кодеков запрещены. |
| crates/xdzip-codec-api | Контракты возможностей, заимствованного ввода, кодированного вывода и отмены. Зависит от модели предметной области. |
| crates/xdzip-compression | Общие алгоритмы и обёртки Deflate/Deflate64/GZIP, LZMA/LZMA2, BZip2, PPMd7, MSZIP, LZX и Quantum. Без сторонних зависимостей в продукте и без полномочий на пути и публикацию. См. [контракт](independent-rust-codecs.md). |
| crates/xdzip-crypto | Независимые от формата хеши SHA/HMAC и BLAKE с фиксированным объёмом памяти и обнулением секретного состояния. Повторно использует допущенные примитивы. За интерпретацию паролей и публикацию отвечают другие модули. |
| crates/xdzip-codec-zip, xdzip-codec-tar | Реализации ZIP и TAR/GZIP без произвольных путей вывода. |
| crates/xdzip-codec-lha, xdzip-codec-arj, xdzip-codec-arc, xdzip-codec-bh | Независимые профили структуры и записей [LHA](lha-containers.md)/[PMA](pma-streams.md), [ARJ](arj-streams.md), [ARC](arc-streams.md) и [BH](bh-containers.md) без полномочий на файловую систему. Доступность в продукте определяет реестр форматов. |
| crates/xdzip-codec-7z | Собственный контейнер 7z, графы методов, фильтры, композиция AES, потоковое создание и ограниченное переписывание. Не распоряжается путями файлов. |
| crates/xdzip-codec-cab | Собственный CAB только для чтения. Использует разрешённые хостом тома и общие алгоритмы. Сохраняет исходные имена, объявления UTF-8 и обычные записи с повторяющимися именами. Обнаружение томов и публикация относятся к обязанностям хоста. См. [контракт](independent-rust-codecs.md#cab只读规格) и [источники](cab-format-sources.md). |
| crates/xdzip-codec-optical | Чтение ISO9660/Joliet/Rock Ridge/UDF и запись новых образов данных ISO9660/Joliet. Работает с потоками без полномочий на пути. |
| crates/xdzip-codec-bridge | Тонкая граница CXX между изолированным процессом и кодеками Rust для 7z, RAR, CAB и оптических носителей. Разрешённые потоки, лимиты ресурсов и отмена. |
| crates/xdzip-codec-native, tools/native-codec | Изолированный процесс для реализаций 7z/RAR/оптических носителей/CAB на Rust. Тонкий C++ предоставляет только протокол и системные службы календаря и кодировок. Нативный получатель независимо проверяет предварительно учтённый вывод и вспомогательную работу. См. [контракт ввода-вывода](native-codecs.md). |
| crates/xdzip-extract-plan | Предварительная проверка метаданных и ограниченные отчёты без доступа к месту назначения и записи. |
| crates/xdzip-io | Деревья входов, нативная авторизация и идентификация, безопасная подготовка и фиксация файлов. |
| crates/xdzip-runtime | Сеансы, ограниченные индексы в памяти и на диске, запросы, выбор, ограниченный предварительный просмотр, задачи создания и распаковки, планирование. |
| crates/xdzip-qt-bridge | Мост типов cxx, два дескриптора и жизненный цикл. Зависит от среды выполнения. |
| crates/xdzip-plugin-protocol | Ограниченные CBOR и кадрирование только со стандартной библиотекой. Без полномочий на пути, процессы или Qt. |
| crates/xdzip-plugin-host, examples/sdk | Независимое испытание SDK только для чтения, контролируемый ввод-вывод, требования к нативной изоляции и независимый участник обмена на Python. Вне обнаружения форматов и зависимостей продукта при выполнении. |
| tools | Независимые средства проверки моста, форматов, ввода-вывода и числа процессов. У графического интерфейса свои точки входа. |
| scripts, .github | Генерация, проверки, средства развёртывания, CI и шаблоны совместной работы. |
| release-notes | Проверяемые примечания к конкретным выпускам и метаданные версий и сборок. Отчёты о выполнении и созданные пакеты хранятся отдельно. |
| design/hifi, design/assets | Детализированные изображения и исходные ресурсы приложения. |
| docs | Поддерживаемые проекты в Markdown, технические контракты, повторяемые методы проверки и нужные изображения. Отчёты о выполнении хранятся отдельно. |
| specs | Машиночитаемые сведения о визуальных параметрах, терминологии и зависимостях для ресурсов продукта, генераторов и проверок. |
| third_party | Сторонние исходники и лицензионные материалы, хранящиеся вместе с кодом. |

Отдельные xdzip-index и xdzip-platform, а также полные инструменты проверки соответствия внешних форматов относятся к будущей архитектуре. Сейчас индексирование находится в среде выполнения, а платформенные файловые операции реализованы в io и настольных адаптерах. Существующий plugin-host служит для [испытания SDK только для чтения](sdk-trial.md). Тесты в основном хранятся с модулями Rust, в apps/desktop/tests и в проверках сценариев. Пустые модули без реализации не создаются.

Продукт всегда направляет CAB в реализацию на Rust. Официальные обработчики Cab и специализированные для CAB LZX/Quantum не компилируются. Вызовы используют тот же изолированный процесс без новых программ в продукте, тестовых переключателей и резервного пути при сбое. codec-api определяет предварительный учёт работы над целым кадром. Контейнеры хранят допуски по кадрам, а нативные получатели и среда выполнения отдельно проверяют собственные допуски и ограничения вывода. См. [контракт собственной реализации](independent-rust-codecs.md#cab只读规格).

Зависимости описаны в [архитектуре системы](../design/system-architecture.md). Избегайте обратных зависимостей предметной области от среды выполнения, прямых уведомлений QML из кодеков и выбора текстов интерфейса платформенным слоем. Созданные привязки, образцы, отчёты и результаты сборки размещайте в build/, target/ или dist/ вне каталогов исходников. [Установка и ассоциации](installers-associations.md#兼容基线的长期输入) описывает данные для долговременной проверки совместимости с прежними версиями.

`tools/image-preview/` — внутренний процесс QtGui/QtSvg для статических изображений. Он получает ограниченное проверенное содержимое, возвращает ограниченные данные RGBA и не хранит пути архивов или мест назначения. Поддержку платформ и поведение при сбоях описывает [контракт предварительного просмотра](content-preview.md).
