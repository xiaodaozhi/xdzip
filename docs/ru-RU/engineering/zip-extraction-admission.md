# Допуск зависимостей для распаковки ZIP и записи результатов

[English](../../engineering/zip-extraction-admission.md) | [简体中文](../../zh-CN/engineering/zip-extraction-admission.md) | [繁體中文](../../zh-TW/engineering/zip-extraction-admission.md) | [日本語](../../ja-JP/engineering/zip-extraction-admission.md) | [한국어](../../ko-KR/engineering/zip-extraction-admission.md) | [Français](../../fr-FR/engineering/zip-extraction-admission.md) | [Deutsch](../../de-DE/engineering/zip-extraction-admission.md) | [Español](../../es-ES/engineering/zip-extraction-admission.md) | [Português (Brasil)](../../pt-BR/engineering/zip-extraction-admission.md) | Русский

На этой странице определены общие границы зависимостей безопасной распаковки и распаковки с паролем. Происхождение, лицензии и сведения о возможностях зависимостей при первоначальном допуске приведены в [зафиксированных исходных материалах](../../../specs/engineering/zip-extraction-dependencies.json). Точные текущие версии, включая AES, и контрольные суммы crates.io определяются корневым Cargo.lock. Проверяйте полный граф включённых зависимостей командой `cargo tree --locked -e features`. Исходная выдержка не является полным текущим перечнем зависимостей.

| Зависимость | Назначение и решение |
| --- | --- |
| xdzip-compression | Общая реализация Deflate и CRC-32, принадлежащая проекту: фиксированные буферы, строгие проверки последнего блока и точного расходования сжатых байтов. Независимый слой форматов обрабатывает контейнеры ZIP, дескрипторы и обёртку AES, заимствуя вход и приёмники вывода у хоста и сохраняя границы разрешения записи и полной проверки. flate2 используется только как эталон для тестов разработки. |
| cap-std / cap-fs-ext 4.0.3 | Удерживаемые полномочия каталога, открытие подкаталогов с nofollow, исключительная временная подготовка и относительная публикация. В отличие от соединения строк и создания после canonicalize хост проверяет полномочия каждого компонента и повторно проверяет его идентичность; универсальный unpack не вызывается. Транзитивные пакеты, например cap-primitives, также зафиксированы. |
| getrandom 0.4.2 | Случайные данные ОС для nonce закрытых рабочих областей, никогда не отметки времени, псевдослучайные значения или имена архивов. Возможности по умолчанию отключены. |
| rustix 1.1.5 | Эффективный идентификатор пользователя POSIX и примитивы файловой системы с повторным использованием зафиксированной версии. Возможности по умолчанию отключены; включены только std/process и транзитивно необходимая fs. |
| windows-sys 0.61.2 | Запрашивает владельца и DACL объектов Windows и проверяет SID. Написанный вручную unsafe изолирован и заимствует действительные дескрипторы, выровненные по DWORD буферы и LocalFree с RAII. В отличие от проверки только атрибута «только чтение», DACL проверяет предпосылки закрытой записи. Новая FFI должна проверять предпосылки для дескрипторов, буферов и освобождения, а также поведение при ошибке запроса. |
| unicode-normalization 0.1.25 | Создаёт ключи допуска NFD в нижнем регистре для псевдонимов имён задач, сохраняя исходное написание выходных имён. Ключ не считается полным приведением регистра файловой системы. Он охватывает распространённые Unicode-эквивалентные имена macOS за пределами строчных символов ASCII. |
| AES, HMAC, SHA-1, PBKDF2, constant_time_eq | Допущенные общие криптографические примитивы; точные версии и возможности указаны в [контракте зависимостей](../engineering/dependencies.md). Счётчик CTR ZIP, расположение соли и проверочного значения, аутентификация шифротекста и классификация ошибок реализованы проектом независимо. zip 9.0.3 служит только эталоном для тестов разработки. |
| zeroize 1.9.1 | Управляет жизненным циклом обнуления паролей, производных ключей и ограниченных буферов stdin тестовых проб; AES/HMAC/SHA-1 также включают свои средства очистки. Это не гарантирует удаления копий Qt, IME или всех прежних копий в памяти. |

Проверяйте конфигурацию Cargo, лицензии и публичные API общих зависимостей; правила происхождения независимых реализаций форматов описаны в [контракте независимой реализации](independent-rust-codecs.md). Семейство cap сопровождает Bytecode Alliance, getrandom и rustix предоставляют системные интерфейсы, Unicode normalization — общая библиотека Unicode. Обновления по-прежнему требуют фиксации версий и регрессионных тестов нативных границ; сопровождающие не заменяют тестирование или проверку уведомлений об уязвимостях. Новые пакеты не выполняют сетевых запросов во время работы. Сценарии сборки только проверяют конфигурацию компилятора или цели либо выбирают серверную реализацию системных вызовов Rust; они не загружают внешний код и не компилируют декодеры C. Лицензионные уведомления собирают полные исходные тексты; фактические выражения лицензий определяются зафиксированными материалами.

Сохраняйте фактические ответы OSV на запросы точных версий согласно [методу проверки](../../../developers/qa/README.md). Неудачный запрос нельзя считать отсутствием уведомлений. Это не полный cargo-audit. Имеющиеся уведомления cxx и выбор версии остаются в [записи зависимостей M2](../engineering/dependencies.md).

Допуск метаданных не разрешает декодирование автоматически. Независимый адаптер проверяет локальные заголовки, завершение потока, CRC и 32/64-битные дескрипторы данных, выбирая ширину по центральным и локальным значениям-маркерам ZIP64. Независимые тестовые данные Python force_zip64 покрывают допустимое смешение ширин и изменённые размеры. rawzip, zip и flate2 отсутствуют в обычных и сборочных зависимостях ZIP и хоста; исторические зафиксированные выдержки сохраняют только происхождение на тот момент.

Зафиксированные материалы перечисляют все зависимости, разрешённые Cargo для разных целевых платформ. Инструменты WASI/WIT/WebAssembly getrandom относятся только к неподдерживаемым целям и не входят в компиляцию или выполнение настольных версий для macOS, Windows и Linux. Перечень Cargo для всех целей нельзя считать составом настольной среды выполнения.

Уведомления пакета разработки используют фактически разрешённые узлы `cargo metadata --filter-platform <rustc host>` для сбора лицензий рабочего пространства и инструментов сборки текущей платформы и записывают target.json. Нескомпилированные пакеты WASI/UEFI не считаются зависимостями настольного дистрибутива. Отсутствие текста лицензии по-прежнему приводит к ошибке упаковки; имя лицензии Cargo не заменяет её текст. Полное разрешение MIT и сведения об авторских правах r-efi 6.0.0 находятся в AUTHORS; сборщик принимает это исключение для текста только для указанной версии и зафиксированного SHA-256.
