# Внешний пробный SDK только для чтения

[English](../../engineering/sdk-trial.md) | [简体中文](../../zh-CN/engineering/sdk-trial.md) | [繁體中文（台灣）](../../zh-TW/engineering/sdk-trial.md) | [日本語](../../ja-JP/engineering/sdk-trial.md) | [한국어](../../ko-KR/engineering/sdk-trial.md) | [Français](../../fr-FR/engineering/sdk-trial.md) | [Deutsch](../../de-DE/engineering/sdk-trial.md) | [Español](../../es-ES/engineering/sdk-trial.md) | [Português (Brasil)](../../pt-BR/engineering/sdk-trial.md) | Русский

`xdzip-plugin-protocol` и `xdzip-plugin-host` реализуют независимую пробу только для чтения, описанную в [проекте расширения форматов](../design/codec-extension-sdk.md). Она исключена из обнаружения форматов настольного приложения и CLI, установки, упаковки и автозапуска. Пользователь явно запускает пробную команду и выбирает пакет и источник; сторонние расширения в продукте остаются отключенными. Согласуется только `xdp1`, без создания, паролей, томов, ссылок, GUI или произвольных разрешений на пути хоста. Это не полноценная экосистема плагинов и не выпуск SDK.

<a name="xdzip-reproducible-entry-points"></a>

## Воспроизводимые точки входа

```sh
python3 scripts/sdk-trial.py test
python3 scripts/sdk-trial.py example --output-dir build/sdk-example
target/debug/xdzip-plugin-host scan build/sdk-example/owned-package/manifest.json build/sdk-example/owned.xdp
mkdir build/sdk-example/output
target/debug/xdzip-plugin-host read build/sdk-example/owned-package/manifest.json build/sdk-example/owned.xdp 0 build/sdk-example/output
```

В Windows используйте `python` и `.exe`. `test` собирает нативную эталонную программу и запускает регрессии Rust-фрейминга, независимой совместимости Python, вредоносного протокола, отмены, изменения источника, конфликтов и разрешений ядра. Python запускается только доверенной точкой проверки соответствия, скомпилированной для тестов; распространяемый хост не принимает интерпретатор, аргументы, оболочку или переключатель выполнения без песочницы. Пример создает собственный пакет, манифест и XDP1 только в `build/`; он не запускает выпуск или загрузку от третьих сторон. Журналы не содержат путей рабочего пространства и домашнего каталога; JSON связывает коммит, состояние изменений и хеши бинарных файлов. Оба являются локальными или CI-артефактами. Та же нативная матрица Foundation вызывает эту точку; отдельный [процесс пробного SDK](../../../.github/workflows/sdk-trial.yml) сначала проверяет совместимость песочницы с платформами, не повторяя несвязанные конвейеры форматов и Qt. Процесс Foundation также может вызвать повторно используемую пробу с `sdk_only=true`; это пропускает полную проверку Foundation и не подтверждает полный результат Foundation. В Windows проверяется отказ выполнения.

<a name="xdzip-package-admission"></a>

## Допуск пакета

Строгий JSON-манифест использует `deny_unknown_fields`. Поля: `manifest_version=1`, `plugin_id`, `version`, `author`, `protocol_majors=[1]`, `targets`, находящийся в пакете `entrypoint`, строчный шестнадцатеричный `sha256`, `formats=["xdp1"]`, `permissions`, `resources`, `license_files` и HTTPS `source_url`. Эталонный манифест, созданный выше через `example`, является исполняемой точкой входа для текущей схемы.

`permissions` имеют строго значения `broker_source_read=true`, `broker_output_write=true`, `network=false`; `resources` — строго `memory_bytes=536870912`, `threads=1`. Манифест ограничен 32 KiB, нативный исполняемый файл — 64 MiB; допускается не более четырех файлов лицензий по 128 KiB каждый. Точки входа и файлы лицензий не могут быть абсолютными, содержать переход к родительскому каталогу или выходить через ссылки и точки повторной обработки. Каждый элемент пакета открывается покомпонентно без следования ссылкам через удерживаемый каталог cap-std и после проверки не открывается повторно по исходной строке. Хост копирует из удерживаемого обычного файла, проверяет фактическое число байтов, SHA-256 и версию файла до и после копирования и выполняет только частную временную копию, сохраняя ее до завершения процесса и IPC. Объявленный хеш подтверждает согласованность выбранного пакета, но не удостоверяет издателя и не доказывает безопасность кода.

<a name="xdzip-wire-protocol-and-state"></a>

## Протокол и состояние

Собственное ограниченное подмножество CBOR следует [RFC 8949](https://www.rfc-editor.org/rfc/rfc8949.html) без сторонней реализации CBOR. Эталонный Rust-участник использует общий crate фрейминга; [Python-участник](../../../examples/sdk/reference.py) независимо реализует кодирование, декодирование и разбор XDP1 без импорта Rust или сгенерированного кода протокола. Совместимость охватывает несколько блоков реального содержимого и дайджест хоста.

Кадры имеют вид `u32 LE length + CBOR`; длина проверяется до выделения памяти. Пределы: кадр 1 MiB, отдельные bytes/text 256 KiB, глубина 16, массивы 128, карты 32 и декодированные узлы 8192. Принимаются только UInt, bytes, строгий текст UTF-8, массивы, карты с ключами UInt и bool. Отклоняются целые числа не в кратчайшей форме, повторные ключи, неопределенные длины, отрицательные числа, теги, числа с плавающей точкой и конечные данные. Ключи карты оболочки `1..5` — kind, request, operation, sequence и payload. Sequence начинается с 1 и последовательно увеличивается в каждом направлении; request увеличивается при каждом вызове, operation — случайная ненулевая идентичность хоста. Каждый ответ должен точно совпадать с текущей идентичностью. Неизвестные ключи payload `<128` отклоняются; `>=128` — необязательные поля, которые можно игнорировать.

| kind | Сообщение | Числовые ключи payload |
| --- | --- | --- |
| 1 | Hello | 1 минимальный major, 2 максимальный major, 3 ID пакета, 4 `xdp1` |
| 2 | Welcome | 1 major, 2 предел блока, 3 кредит одного блока, 4 общий бюджет чтения, 5 бюджет вывода |
| 10 | Probe | 1 токен источника, 2 длина источника |
| 11 | Open | 1 токен источника |
| 12 | Scan | 1 токен сеанса |
| 13 | ReadEntry | 1 сеанс, 2 элемент, 3 приемник, 4 число кредитов 1, 5 бюджет вывода, 6 токен кредита первого блока |
| 14 | Close | 1 сеанс |
| 20, 21 | ReadAt, ReadData | 1 токен источника, 2 смещение, 3 длина или байты |
| 30 | EntryBatch | 1 сеанс, 2 элемента; на запись: 1 токен, 2 сырой путь, 3 тип 0 файл / 1 каталог, 4 известный размер |
| 31 | ScanFinished | 1 фактическое число записей |
| 40 | WriteData | 1 приемник, 2 последовательность блоков с 0, 3 байты, 4 текущий токен кредита |
| 41 | FinishOutput | 1 приемник, 2 объявленное число вывода, 3 байты SHA-256 |
| 42 | WriteAck | 1 приемник, 2 последовательность следующего блока, 3 новый случайный токен кредита |
| 50, 51, 52 | Cancel, CancelAck, Shutdown | Пустая карта |
| 61 | OperationFinished | 1 результат, 0 успех / 1 отменено; Probe также имеет 2 формат, Open также имеет 2 сеанс |

Другие kinds отклоняются автоматом состояний этой пробы, даже если фрейминг их распознает. Hello должен прийти первым, обе стороны выбирают major 1; идентичность рукопожатия равна нулю, последующие вызовы ненулевые. После ScanFinished по-прежнему требуется единственное успешное конечное состояние. Одновременно выполняется только одна операция; фоновых повторов расширения нет. Текущий кредит одного блока строже максимума четырех по проекту; непредсказуемый токен обновляется после фактического приема каждого блока вывода и не может быть использован заранее или повторно.

<a name="xdzip-broker-budgets-and-publication"></a>

## Посредник, бюджеты и публикация

Токены источника, приемники и кредиты отдельных блоков — случайные 128-битные значения, не используемые повторно между операциями. Участник не получает пути архива или назначения. Хост возвращает не более 256 KiB за чтение в пределах разрешенного диапазона источника; переполнение смещения, чтение за EOF, нулевая длина и суммарное чтение более 64 MiB вызывают ошибку. Он проверяет `FileVersion` удерживаемого объекта и соответствующего пути до и после каждого чтения и до окончательной публикации. Используется существующий отпечаток идентичности, времени и длины; не утверждается возможность обнаружить произвольные одновременные изменения злоумышленника с той же учетной записью, восстановившего все метаданные.

Метаданные ограничены 1000 физическими записями и суммарно 256 KiB путей и токенов, токены записей уникальны. Хост строго проверяет сырые пути по PortablePath; одинаковые имена сохраняют отдельные идентичности. За раз явно выбирается одна обычная запись с заявленным размером до 4 MiB; каталог не может быть файловым выводом. Хост удерживает Grant назначения, частные Workspace и Stage, учитывает реальные байты и вычисляет SHA-256, не предоставляя участнику файловый дескриптор или право публикации.

Существующий безопасный ввод-вывод может публиковать без перезаписи только после успешного получения всех блоков, проверки количества и дайджеста FinishOutput, единственного конечного состояния, Close, нормального завершения после Shutdown и чистого EOF, идентичности источника и окончательной проверки отмены. Любая аномалия, повторное конечное состояние, сбой или тайм-аут сначала отзывает вывод; уничтожение удаляет stage до очистки workspace. Существующие цели не меняются. Разбор и ожидаемые дайджесты по-прежнему поступают от расширения; вычисление хоста не доказывает верность вывода вредоносного расширения содержимому архива.

Рукопожатие ограничено 2 секундами, каждый пробный вызов — 5 секундами всего без сброса срока прогрессом. CPU процесса ограничен 3 секундами, файловые дескрипторы — 32; прямой вывод в файл запрещен, core dump отключены. Очередь приема IPC содержит до четырех кадров, отправки — один; запись в канал ограничена 2 секундами. stderr сразу отбрасывается с нулевым бюджетом, недоверенное содержимое не пересылается. Отмена немедленно отзывает приемник, дает 2 секунды на сотрудничество, затем завершает и собирает процесс и каналы; Ack не разрешает публикацию. Эти бюджеты ограничивают небольшую пробу и не обещают производительности обычных больших архивов.

<a name="xdzip-platform-gates"></a>

## Условия платформ

| Платформа | Политика пробы и поведение при ошибке |
| --- | --- |
| macOS | Зафиксированная политика deny-default `/usr/bin/sandbox-exec` разрешает конкретную частную исполняемую копию, системные библиотеки/кэш dyld, чтения корневого загрузчика и метаданные `/var`. Пользовательские файлы, запись, сеть и fork запрещены; окружение очищается, наследуется только stdio. Нативные rlimit и контроль RSS каждые 20 ms завершают процесс при превышении 512 MiB или ошибке измерения. RSS измеряется периодически, поэтому короткие пики между замерами могут превышать порог; доступность интерфейса для будущего официального распространения не обещается. |
| Linux x86_64 / aarch64 | Landlock ABI ≥3 обрабатывает все файловые права v3 без правил записи, разрешая чтение только исполняемого файла и системных библиотек загрузчика. `no_new_privs` и проверенный по архитектуре список разрешенных системных вызовов seccomp включают readv/writev для стандартных каналов Rust и запрещают socket, fork/clone, ptrace, io_uring и другие. Действуют ограничение CPU 3 секунды, адресного пространства 512 MiB и другие rlimit. Отсутствие правил, ABI, seccomp или необходимых вызовов вызывает ошибку до exec. Реальные результаты платформы подтверждает только нативная CI. |
| Windows и другие платформы | Выполнение безусловно запрещено. AppContainer, Job и список разрешенных дескрипторов не реализованы и не проверены; обычный подпроцесс не заменяет песочницу. |

Выбор API Linux следует [документации ядра Landlock](https://docs.kernel.org/userspace-api/landlock.html) и UAPI; будущая работа для Windows следует [изоляции AppContainer](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-isolation). Нативный unsafe-код хоста ограничен модулем песочницы и документирует структуры, предусловия вызовов и поведение при ошибках; pre-exec не выделяет память и не ведет журнал. Эталонный участник добавляет контролируемые пробы fork/_exit/waitpid только в явном режиме аудита; дочерний процесс не выполняет очистку Rust или логику формата. Платформенные регрессии сначала используют собственные читаемые и записываемые маркеры, собственный localhost listener и self-exec как положительный контроль, затем проверяют отказ ядра на чтение, запись, сеть, прямой fork и self-exec по фактическому состоянию маркеров, файлов и соединений. Непроверенные платформы не отмечаются как пройденные, выполнение стороннего кода в настольном приложении остается отключенным.

<a name="xdzip-owned-xdp1-example-format"></a>

## Собственный пример формата XDP1

XDP1 — только образец совместимости и не заменяет реальный архивный формат. За четырьмя байтами `XDP1` следует количество записей `u32 LE`. Каждая запись содержит число байтов имени UTF-8 `u16 LE`, число байтов содержимого `u32 LE`, имя и несжатое содержимое. Допускается до 1000 записей без конечных данных; имена и содержимое читаются в пределах бюджета хоста. Токены элементов — четырехбайтовые физические порядковые номера LE без дедупликации по пути. Режимы ошибок Python явно выбираются только в тестах соответствия для проверки несанкционированного доступа, последовательности, повтора, дублирования идентичности, путей, кредитов, дайджестов, сбоев, отмены и повторных конечных состояний.
