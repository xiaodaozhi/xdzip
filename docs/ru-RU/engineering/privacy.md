# Жизненный цикл данных и диагностика

[English](../../engineering/privacy.md) | [简体中文](../../zh-CN/engineering/privacy.md) | [繁體中文](../../zh-TW/engineering/privacy.md) | [日本語](../../ja-JP/engineering/privacy.md) | [한국어](../../ko-KR/engineering/privacy.md) | [Français](../../fr-FR/engineering/privacy.md) | [Deutsch](../../de-DE/engineering/privacy.md) | [Español](../../es-ES/engineering/privacy.md) | [Português (Brasil)](../../pt-BR/engineering/privacy.md) | Русский

[Политика конфиденциальности](../../../PRIVACY.md) описывает, какие данные обрабатывает xdzip и какие настройки доступны пользователю. В таблице указано, где данные хранятся и когда удаляются. Просмотр, сжатие и распаковка работают автономно. xdzip не отправляет сопровождающим проекта телеметрию или содержимое архивов автоматически.

| Данные | Срок хранения | Хранение и очистка |
| --- | --- | --- |
| Настройки и темы | Между запусками, в схеме с номером версии | Изменения сохраняются атомарной заменой. При сбое предыдущие настройки сохраняются, а интерфейс сообщает об ошибке. |
| Предыдущие приложения по умолчанию в macOS | Локально, между запусками | При выборе xdzip отдельный файл сохраняет идентификатор пакета предыдущего приложения для этого типа содержимого. Восстановление или выбор другой программы удаляет запись для этого типа. |
| Недавние файлы | Необязательно, только локально | Закрытый файл `recent.json` содержит до 20 разных записей с пределом чтения 64 KiB. При отключении новые записи не добавляются. Очистка удаляет историю, не трогая исходные файлы. |
| Индексы архивов | Пока сеанс открыт | Небольшие индексы хранятся в памяти. Большие индексы ZIP используют закрытые файлы для метаданных и порядка запроса. При штатном закрытии, замене запроса, сбое или отмене известные файлы очищаются. При позднейшем создании можно удалить неиспользуемые остатки после сбоя по правилам идентификации и срока использования. Индексы не используются повторно между запусками. См. [индексы больших архивов](large-index.md). |
| Временные результаты и состояние восстановления | Во время задач и восстановления | Восстановление использует только контролируемые метаданные и очищает только объекты с подтверждённой принадлежностью. Оно не запускает содержимое архивов и не возобновляет запись по произвольным путям. |
| Предпросмотр в приложении | По запросу пользователя и в пределах ограничений | При смене контекста просмотра или завершении сеанса результат очищается. Запоздавшие результаты не могут вернуть недействительное содержимое. |
| Пароли | На время операции | Приложение не записывает пароли в настройки или журналы. Операционная система может держать дополнительные копии в памяти, которыми приложение не управляет. |
| Автономные проверки и загрузки обновлений | По запросу пользователя в применимых версиях | Запросы используют публичные службы выпусков и скачивания GitHub. Их может обрабатывать настроенный прокси. Необязательное HTTPS-зеркало получает исходный URL скачивания. Поставщики могут видеть данные соединения и версию приложения в запросах. В Windows MSIX автономное обновление отключено. |
| Квитанции операций обновления | Локально, с сохранением при перезапусках установки | Отдельный файл `update-state.ini` рядом с настройками хранит идентификаторы операции и цели. Неудачные загрузки могут остаться в закрытом кэше обновлений. Обновляющая программа читает только предусмотренные файлы квитанций и не исполняет их содержимое. |
| Статус и диагностика | В интерфейсе, терминале или локальных записях, в зависимости от функции | Приложение не отправляет диагностику автоматически. Копирование сведений о версии или файле записывает их в системный буфер обмена. Проверьте имена файлов, пути и другие личные сведения перед отправкой ошибки, журнала или снимка экрана. |

О сетевых запросах, подписях, передаче установщику и восстановлении см. [спецификацию обновлений](software-update.md).
