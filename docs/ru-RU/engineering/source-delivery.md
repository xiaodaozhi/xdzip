# Соответствующие исходники и материалы для пересборки

[English](../../engineering/source-delivery.md) | [简体中文](../../zh-CN/engineering/source-delivery.md) | [繁體中文](../../zh-TW/engineering/source-delivery.md) | [日本語](../../ja-JP/engineering/source-delivery.md) | [한국어](../../ko-KR/engineering/source-delivery.md) | [Français](../../fr-FR/engineering/source-delivery.md) | [Deutsch](../../de-DE/engineering/source-delivery.md) | [Español](../../es-ES/engineering/source-delivery.md) | [Português (Brasil)](../../pt-BR/engineering/source-delivery.md) | Русский

**Граница выпуска, 2026-11-05:** По указанию владельца этот сборщик предназначен только для локальной проверки и проверки пересборки. Архивы соответствующих исходников больше не предоставляются как ресурсы GitHub Release или артефакты Actions. Исторические публичные ресурсы Release и доступные для скачивания артефакты выпусков Actions, содержащие эти архивы, отозваны; будущие рабочие процессы выпуска отклоняют их создание и загрузку. Это решение не меняет лицензии компонентов и не доказывает выполнение обязательств по соответствующим исходникам, повторному связыванию и других обязательств. Снимки исходников, автоматически создаваемые GitHub для тегов публичного репозитория, отделены от этих вложений Release.

При обычном выпуске и приёмке нельзя запускать этот сборщик или создавать локальные архивы соответствующих исходников. Запуск допускается только при явном запросе пользователя на сбор исходников; ограничение на загрузку при этом остаётся в силе. Проверка лицензий должна выявлять реальные компоненты и обязательства, а не считать общие машинные отметки о необходимости проверки подтверждёнными дефектами.

scripts/prepare-source-delivery.py собирает исходники проекта из чистого коммита, полные входные данные Rust vendor, соответствующие Cargo.lock, фиксированные архивы исходников модулей Qt 6.8.2 и инструкции по пересборке и замене. Все результаты находятся в build/. Адрес загрузки не является поставленным исходным кодом, а сборщик не утверждает автоматически выбор варианта лицензии открытого ПО.

```sh
python3 scripts/prepare-source-delivery.py --output build/review/source-delivery \
  --qt-prefix build/toolchain/Qt/6.8.2/macos
python3 scripts/verify-source-delivery.py --delivery build/review/source-delivery \
  --qt-prefix build/toolchain/Qt/6.8.2/macos --output build/review/source-rebuild
```

Архивы модулей среды выполнения Qt — qtbase, qtdeclarative, qtsvg и qttranslations; необходимые для сборки qtshadertools, qttools и фиксированные исходные компоненты стандартной библиотеки Rust также доставляются из [официального архива Qt 6.8.2](https://download.qt.io/archive/qt/6.8/6.8.2/submodules/). Официальные значения .sha256 зафиксированы в scripts/corresponding-sources.json. Кэш и загрузки проверяются повторно; загрузки сначала сохраняются в частичные файлы и фиксируются после проверки. Проверяются только каталоги архивов, сторонние пути автоматически не извлекаются. Cargo vendor использует --locked, сохраняет контрольные суммы реестра и зависимости сборки и не выполняет сторонние сценарии сборки.

Поставка исходников также содержит фиксированный редактируемый Public Suffix List и его текст MPL-2.0. При сборе проверяются идентичности входных данных, архива Qt и генератора, затем данные C++ и двоичные тестовые данные создаются заново и сравниваются побайтно. При несовпадении операция останавливается и не устанавливает полного соответствия SDK или одобрения лицензирования выпуска.

Поставка сохраняет фиксированные входные данные Apache Tika, исходный NOTICE и текст OGL-UK-3.0 для данных MIME Qt Core. Проверяется указание авторства в архиве Qt, а данные MIME создаются заново скриптом преобразования фиксированного архива с допуском только нативных окончаний строк Windows. Полный NOTICE Tika охватывает более широкую исходную поставку и не означает, что остальные её зависимости поставляются xdzip.

Поставка также содержит исходники `common` CLDR 46 и исходную лицензию, использованные для генерации локалей Qt 6.8.2, но не остальную часть дерева исходников CLDR. Сбор проверяет версию CLDR в двух созданных исходных файлах Qt, хеш фиксированного исходного архива и выбранные входные данные. Второй этап генерации Qt дополнительно требует не включённую таблицу ISO 639-3; `qt-cldr-sources.json` фиксирует источник, версию и дайджест проверенного кандидата, а его [страница загрузки и условия источника](https://iso639-3.sil.org/code_tables/download_tables) требуют отдельной проверки. Воспроизведение созданных данных с этим кандидатом не устанавливает точный исторический ввод или полную идентичность сборки исходного SDK.

Исключение оригинальных таблиц ISO не удаляет все связанные идентификаторы из других данных CLDR. `common/validity/language.xml` CLDR 46 сохраняет компактные языковые коды, а `common/supplemental/supplementalMetadata.xml` содержит псевдонимы. В [локальном сравнении](https://github.com/xiaodaozhi/xdzip/issues/138#issuecomment-6588994510) набор кандидатов из трёх букв, построенный из этих поставленных файлов, охватывал 7 919 из 7 920 значений `Id` в кандидатной таблице ISO CLDR 46 и содержал 338 дополнительных значений. Тот же метод для подмножества CLDR 43.1 относительно более поздней таблицы охватывал 7 896 значений и содержал 338 дополнительных. Набор кандидатов не является исходной таблицей и не содержит всех её полей; совпадение одних идентификаторов не решает вопросы происхождения, разрешения или применимых условий. Исключение пяти файлов с именем ISO не доказывает отсутствие других связанных данных.

Подмножество CLDR 43.1 также сохраняет входной файл инструмента `language-subtag-registry` с датой 2023-02-14 в заголовке. Из его 8 049 трёхбуквенных языковых подтегов 7 713 совпадают с идентификаторами более поздней кандидатной таблицы ISO выше; причина этого межверсионного различия здесь не устанавливается. Инструкции Unicode по обновлению определяют файл как реестр языковых подтегов, полученный от IANA. Заявление IANA о CC0 охватывает только права, которыми она владеет или которые может сублицензировать, и сохраняет возможность прав третьих лиц. Сравнение и ограничения см. в [#140](https://github.com/xiaodaozhi/xdzip/issues/140#issuecomment-6589292716).

Подмножество CLDR 43.1 также включает два шрифта Noto, четыре файла Glyphicons, скрипты Bootstrap и Autosize и изображения эмодзи, используемые его веб-инструментом. `cldr43-webapp-notices/` предоставляет происхождение и лицензии этих шрифтов и скриптов и 908 изображений, совпадающих с двумя фиксированными версиями Noto Emoji, после проверки каждого фиксированного файла. Для остальных 963 исходных изображений, происхождение и условия распространения которых не установлены независимо, сборщик проверяет каждый исходный хеш и заменяет их 698 фиксированными изображениями Noto и 265 фиксированными изображениями Twemoji. Манифест записывает оба хеша, пути и источники; утверждение о нарушении не делается. Эти файлы не входят в интерфейс xdzip. Уведомления также определяют три исходных файла веб-инструмента с уведомлениями об авторских правах IBM и рассматривают их по Unicode-DFS-2016 на основе корневого README того выпуска, сохраняя уведомления и лицензию. Ещё 27 изображений веб-корня побайтно совпадают с фиксированным коммитом CLDR 2026 года и рассматриваются по лицензии Unicode-3.0 этого коммита с сохранением полного уведомления и отдельных хешей. Эта оценка не распространяется на товарные знаки, неперечисленные ресурсы или внешние зависимости.

Два полных текстовых файла подмножества CLDR 43.1 `docs/rfc`, `draft-davis-t-langtag-ext.txt` и `draft-davis-u-langtag-ext-00.txt`, побайтно совпадают с [черновиком расширения T IETF 2011 года](https://www.ietf.org/archive/id/draft-davis-t-langtag-ext-07.txt) и [черновиком расширения U 2010 года](https://www.ietf.org/archive/id/draft-davis-u-langtag-ext-00.txt). Сбор проверяет хеши и сохраняет авторские права и уведомления. Оба ссылаются на условия, действовавшие при публикации; раздел 3.c [TLP 4.0](https://trustee.ietf.org/wp-content/uploads/IETF-TLP-4.pdf) разрешает полное и неизменённое распространение вне процесса стандартизации в пределах прав, которые Trust может предоставить, с сохранением требуемых уведомлений. Эта оценка относится только к этим двум текстам, а не к другим HTML, XML, ресурсам или правам третьих лиц.

Для языков, уже содержащихся в исходниках Qt, извлеките ограниченный ввод генератора из оригинального `qlocale_data_p.h`. Например, после извлечения QtBase в текущий каталог выполните `python3 scripts/derive-qt-locale-code-input.py --qtbase qtbase-everywhere-src-6.8.2 --output build/qt-locale-codes.tsv`. Это охватывает только существующие ключи поиска и не является ни полной таблицей ISO 639-3, ни историческим исходным вводом. Добавление языков может потребовать отдельно полученных кодов и проверки их условий. Повторное создание восьми файлов с фиксированными исходниками Qt 6.8.2, данными CLDR 46 и этим производным вводом проверено с допуском только различий дат генерации и окончаний строк. Это не решает лицензирование таблицы ISO и не устанавливает полные соответствующие исходники.

Для конкретного дополнительного языка извлеките поставленное подмножество CLDR 43.1 и проверьте языковой подтег через `tools/cldr-code/src/main/resources/org/unicode/cldr/util/data/language-subtag-registry`, явно задав четыре поля кода. Поля ISO 639-2 примера Choctaw можно проверить по [списку Библиотеки Конгресса](https://www.loc.gov/standards/iso639-2/php/code_list.php), а ISO 639-3 — по [данным регистрационного органа](https://iso639-3.sil.org/code_tables/download_tables). Последнее пустое поле означает отсутствие двухбуквенного кода:

```sh
python3 scripts/derive-qt-locale-code-input.py --qtbase path/to/qtbase \
  --iana path/to/cldr43/tools/cldr-code/src/main/resources/org/unicode/cldr/util/data/language-subtag-registry \
  --add-language 'cho,cho,cho,' --output build/qt-locale-codes-with-cho.tsv
```

`--add-language` можно повторять. Поля — трёхбуквенный код, ISO 639-2/B, ISO 639-2/T и двухбуквенный код; отсутствующие поля оставляются пустыми, а оба поля части 2 задаются вместе или оба оставляются пустыми. Инструмент проверяет, что хотя бы один трёх- или двухбуквенный код является зарегистрированным языковым подтегом IANA, проверяет синтаксис и отклоняет конфликты ключей Qt. Он **не** выводит и не проверяет, относятся ли поля к одному языку, и не устанавливает соответствия ISO. Получатель должен проверить каждое соответствие и источник. Добавление языка Qt также требует обновления `enumdata.py`, предоставления данных локали CLDR и повторной генерации и сборки Qt; одна строка не добавляет язык. Это ограниченная производная таблица, а не полная таблица ISO и не доказательство идентичности исторического ввода или полноты соответствующих исходников.

В изолированном тесте ручное добавление тестового кода частного использования в enum инструмента Qt и производную таблицу создало новый enum и запись кода. Пересобранный Linux QtCore успешно прошёл прямой и обратный поиск, а изолированная копия исходной alpha.8 выполнила просмотр, отмену и извлечение вне экрана. Реальный язык или данные форматов локали CLDR не добавлялись; тест не заменяет проверку реальных входных данных и условий и не устанавливает все обязательства по соответствующим исходникам. Шаги и первоначальную ошибку пробы см. в [#138](https://github.com/xiaodaozhi/xdzip/issues/138#issuecomment-6611169790).

Другой вариант — независимо получить JSON-данные ISO 639-2 и 639-3 из `iso-codes` и преобразовать их во вход Qt. Например, в Linux с установленным пакетом данных:

```sh
python3 scripts/convert-iso-codes-for-qt.py \
  --iso-639-2 /usr/share/iso-codes/json/iso_639-2.json \
  --iso-639-3 /usr/share/iso-codes/json/iso_639-3.json \
  --output build/qt-iso-codes.tsv
```

Конвертер извлекает соответствия кодов без названий; полный ввод всё равно создаёт полный набор кодов. Он отклоняет неверные коды, дубликаты и конфликты ключей Qt, пропускает зарезервированный диапазон локального использования ISO 639-2 и сообщает SHA-256 входа и выхода. Сравнение Qt 6.8.2 с Ubuntu `iso-codes` 4.16.0-1 см. в [#138](https://github.com/xiaodaozhi/xdzip/issues/138); другие версии проверяются отдельно. Данные не включены. Заявленную лицензию, происхождение и условия распространения созданных таблиц необходимо проверить независимо; альтернативная таблица не устанавливает исторический ввод Qt или полное соответствие требованиям об исходниках.

Для воспроизведения сравнения независимо получите фиксированный [пакет Ubuntu `iso-codes` 4.16.0-1](https://archive.ubuntu.com/ubuntu/pool/main/i/iso-codes/iso-codes_4.16.0-1_all.deb). Следующий пример Linux требует `curl`, `dpkg-deb` и Python 3; он проверяет хеш пакета до локального извлечения и преобразования, не изменяя системную установку:

```sh
mkdir -p build && mkdir build/qt-iso-peer &&
curl --fail --location --silent --show-error --connect-timeout 15 --max-time 120 https://archive.ubuntu.com/ubuntu/pool/main/i/iso-codes/iso-codes_4.16.0-1_all.deb -o build/qt-iso-peer/iso-codes.deb &&
python3 -c "import hashlib,pathlib,sys; p=pathlib.Path('build/qt-iso-peer/iso-codes.deb'); h=hashlib.sha256(p.read_bytes()).hexdigest(); sys.exit(0 if h=='cafca0a3a1f07b44fbba53ab7a1f1d9755e6b80cc041173afe2b52e53bed97a7' else 'Package SHA-256 mismatch')" &&
dpkg-deb -x build/qt-iso-peer/iso-codes.deb build/qt-iso-peer/data &&
python3 scripts/convert-iso-codes-for-qt.py \
  --iso-639-2 build/qt-iso-peer/data/usr/share/iso-codes/json/iso_639-2.json \
  --iso-639-3 build/qt-iso-peer/data/usr/share/iso-codes/json/iso_639-3.json \
  --output build/qt-iso-peer/qt-locale-codes.tsv
```

Проверенные SHA-256 входных данных — `fa83810fdb59f9d84b4d58486d5e5e48e807d82a98d6a39ef0ba4fc57c2a9327` и `9636ce5266053867627140ce5ada1f9aa897ca07a7501302c1b14b8d1147cdda`; преобразованный результат — `85457a36e013e053b70dea19d500ebec2ae6bedf5dad9af0035b973c8db6a60a`. Ubuntu `usr/share/doc/iso-codes/copyright` объявляет LGPL-2.1-or-later, но одно заявление на уровне пакета не устанавливает историческое разрешение для таблицы SIL или права распространения полного набора кодов. Ни пакет, ни полная преобразованная таблица здесь не включены; происхождение, условия и последующее распространение проверяются отдельно.

Либо независимо получите [реестр языковых подтегов IANA](https://www.iana.org/assignments/language-subtag-registry/language-subtag-registry) и [список ISO 639-2 Библиотеки Конгресса](https://loc.gov/standards/iso639-2/ISO-639-2_utf-8.txt) и создайте другой ввод. Инструмент извлекает коды без названий, сообщает несовпавшие коды и хеши входа и выхода и отклоняет неверные или неоднозначные записи. Пример оболочки Linux/macOS использует новый каталог и проверяет оба исходных файла этого сравнения до преобразования:

```sh
(
  set -eu
  mkdir -p build
  mkdir build/qt-iana-loc-inputs
  curl --fail --location --output build/qt-iana-loc-inputs/iana.txt \
    https://www.iana.org/assignments/language-subtag-registry/language-subtag-registry
  curl --fail --location --output build/qt-iana-loc-inputs/loc.txt \
    https://loc.gov/standards/iso639-2/ISO-639-2_utf-8.txt
  python3 -c 'import hashlib,pathlib,sys; p=sys.argv[1:]; sys.exit(0 if all(hashlib.sha256(pathlib.Path(p[i]).read_bytes()).hexdigest()==p[i+1] for i in (0,2)) else "Input SHA-256 mismatch")' \
    build/qt-iana-loc-inputs/iana.txt 755fad43283be7b41ebe3c89ad054b6eaf928f404f9c0edb74799e0eab74beb1 \
    build/qt-iana-loc-inputs/loc.txt 42b71885e4dc885559fda5ad059fd81838cf4782cedb5fd08cc3431f7d067371
  python3 scripts/convert-iana-loc-for-qt.py \
    --iana build/qt-iana-loc-inputs/iana.txt \
    --loc build/qt-iana-loc-inputs/loc.txt \
    --output build/qt-iana-loc-inputs/qt-codes.tsv
)
```

В сравнении использовался файл IANA от 2026-09-17 с SHA-256 `755fad43283be7b41ebe3c89ad054b6eaf928f404f9c0edb74799e0eab74beb1`. Файл LoC в UTF-8, полученный напрямую 2026-11-03, имел размер 16 010 байт и SHA-256 `42b71885e4dc885559fda5ad059fd81838cf4782cedb5fd08cc3431f7d067371`. Первые три поля кода его 487 записей по отдельности совпали с предыдущей веб-реконструкцией. SHA-256 выхода конвертера с LF был `6a75bebfa694258a1a4125fc30512d8ae7994080701377b41306db665ad371c6`. Вместе эти входные данные создали 8268 строк, соответствующих всем 346 различным существующим ключам поиска Qt. Все восемь повторно созданных файлов совпали после нормализации дат генерации и окончаний строк; отрицательный контроль с изменением одного входа совпал в семи. Семь двухбуквенных подтегов IANA `bh`, `in`, `iw`, `ji`, `jw`, `mo`, `sh` не имели записи LoC, о чём инструмент сообщает. Другие версии и добавленные языки проверяйте отдельно. Исходные адреса могут измениться; исследуйте несовпадение хеша, а не обходите проверки. См. [#138](https://github.com/xiaodaozhi/xdzip/issues/138#issuecomment-6588040592).

[Заявление IANA/IETF](https://www.iana.org/help/licensing-terms) применяет CC0 к правам на реестры протоколов, которыми они владеют или которые могут сублицензировать, сохраняя возможность прав третьих лиц; оно не устанавливает автоматически все права на исходную таблицу SIL. Ни снимок IANA от 2026-09-17, ни ввод LoC, ни полная преобразованная таблица сравнения здесь не включены. Подмножество CLDR 43.1 отдельно содержит более ранний реестр, описанный выше. Получатели должны отдельно проверить происхождение, применимые условия и последующее распространение. Эта альтернатива не устанавливает ни исторический ввод Qt, ни полное соответствие требованиям к исходникам.

Независимое сравнение здесь означает отдельное получение и преобразование файлов, а не независимое происхождение стандартов. [Раздел 2.2.1 RFC 5646](https://www.rfc-editor.org/rfc/rfc5646#section-2.2.1) называет ISO 639-2, 639-3 и 639-5 источниками стандартов для трёхбуквенных языковых подтегов IANA. Совпадение значений не устанавливает независимое авторство или полную сублицензию.

Выход содержит xdzip-source.tar для фактического фиксированного коммита, rust-vendor.tar.gz, автономную конфигурацию Cargo, оригинальные архивы Qt, REBUILD.md и манифест SHA-256 и размера каждого файла. Манифест явно обозначен как собранный без проверки соответствия; он не заменяет проверки функций и патчей сборки SDK, платформенных сред выполнения, встроенных ресурсов или соблюдения лицензий. Повторно настроенные исходники проекта могут иметь неизвестную идентичность и должны связываться с исходным коммитом через внешний манифест поставки без создания фиктивной чистой идентичности Git.

Отдельный каталог `rar-wire-mappings/` сохраняет ограниченное происхождение ссылок на конечные соответствия, пояснения и точное исходное уведомление UnRAR 7.30 beta1, включённые в хешированную поставку. Фиксированное имя загрузки — `unrarsrc-7.3.1.tar.gz`; числовое имя не устанавливает отдельную версию исходного выпуска. В качестве консервативной меры уведомления поставка требует полного исходного второго абзаца лицензии в комментариях соответствующего исходного кода Rust и останавливается при его отсутствии или изменении. Крейт RAR консервативно объявляет `Apache-2.0 AND UnRAR`; не одобренный OSI идентификатор `UnRAR` присутствует в SPDX 3.28 и новее и может не распознаваться старыми инструментами. Эти материалы не содержат исходников официального движка и не перелицензируют полученные из ссылок факты как Apache-2.0. Применимые условия и фактические обязательства по распространению требуют проверки конкретного кандидата.

Для Linux ICU включены фиксированная полная лицензия ICU 73.2, официальный архив исходников выпуска ICU4C 73.2, фиксированные редактируемые исходники ICU, подмножество исходников CLDR 43.1 и исходники начальной загрузки ICU 73.1; они входят в общий манифест. Подмножество CLDR исключает пять файлов ISO 639-3, текст UTS #35 и связанные файлы в `docs/ldml`, а также два снимка документации, и заменяет 963 изображения веб-инструмента. Запись поставки сохраняет хеш исходного архива и каждое исключение и замену. [UTS #35 версии 43.1, опубликованный Unicode](https://www.unicode.org/reports/tr35/tr35-69/tr35.html), доступен отдельно на условиях владельца; наличие дополнительных передаваемых разрешений ещё предстоит установить. Сборщик также отклоняет файлы архива начальной загрузки с `iso-639-3` в имени; проверка имени не исключает данные в другой форме. Сбор проверяет хеши архивов, версии, встроенные лицензии и выбранные исходные файлы без извлечения сторонних путей. [Руководство по пересборке данных ICU](icu-cldr-rebuild.md) фиксирует сборки инструментов и объём генерации и редактирования. Совпадение исходных версий не доказывает, что поставщик собрал двоичные файлы из этих входных данных без патчей. Текущие пакеты разработки Windows исключают программный OpenGL и больше не собирают специальные материалы Mesa/LLVM; исторические поставки сохраняют исходные материалы и обязательства. См. [исходники и уведомления нативной среды выполнения](native-runtime-materials.md).

Приложение динамически связывается с Qt и предоставляет инструкции по пересборке исходников и замене совместимой библиотеки. [Проверка развёртывания macOS](macos-deployment.md) охватывает загрузку изменённых библиотек в изолированной копии без утверждения полной пересборки Qt из исходников. Фактические сборки исходников Qt и загрузка в продукт имеют отдельный процесс в [контракте автоматической проверки](../../../developers/engineering/candidate-verification.md). Побайтовая эквивалентность сборки SDK, точное указание статического связывания и выбор лицензий относятся к [проверке лицензий выпуска](https://github.com/xiaodaozhi/xdzip/issues/4), а не к повторному открытию завершённой разработки WP-12.

verify-source-delivery.py сначала повторно проверяет хеши файлов поставки, безопасно извлекает собственные входные данные проекта и vendor в новый каталог build/, собирает реальное приложение с пустым кэшем Cargo, CARGO_NET_OFFLINE=true и существующим фиксированным Qt SDK, затем выполняет дымовой тест запуска и остановки. Это проверяет автономное использование входных данных проекта и Rust, а не сборку модулей Qt из исходников или побайтово воспроизводимые сборки. Созданные каталоги исходников имеют неизвестную идентичность Git, связанную извне фиксированным коммитом и манифестом поставки.

Поставка исходников вызывает Cargo из выходного каталога с относительным назначением `vendor` и явным манифестом проекта. Принимаются только поддерживаемое сейчас сопоставление источников crates.io и относительная конфигурация `vendor`. Абсолютные каталоги, выход за пределы пути или неожиданные сопоставления вызывают ошибку вместо включения путей машины сборки в переносимую поставку.

Для фиксированных vendor-пакетов без отдельных файлов лицензий или уведомлений с обычными именами `rust-vendor-notices/` отдельно индексирует фиксированные исходные тексты по пакетам. Сборщик проверяет хеш Cargo-манифеста пакета, исходный Git-коммит и путь, SHA-256 текста лицензии и Git blob; неизвестные пробелы или несовпадения идентичности останавливают поставку. Каталог не изменяет файлы или контрольные суммы Cargo vendor. Исходные лицензионные выражения сохраняются без изменений; это не утверждает конкретный выбор лицензии или соответствие предыдущего выпуска.

[Проверка соответствия Qt SDK](qt-sdk-correspondence.md) всегда включает фиксированный манифест соответствия и воспроизводимый патч потребителя AGL. При --qt-prefix она также включает пофайловые проверки деклараций исходников, конфигурацию сборки и явные пробелы этого SDK. Манифест поставки рекурсивно хеширует подкаталоги патчей, а проверка пересборки снова проверяет эти байты. Без SDK запись проверки конфигурации не выдумывается.

Поставка сохраняет фиксированный объект Git-коммита Qt Declarative для автономной проверки связи коммита выпуска с объектом дерева `.tag` архива; манифест поставки хеширует его. Эта связь не устанавливает полноту архива или эквивалентность сборки SDK.

Фактические сборки Qt из исходников и загрузку или совместимую замену см. в [контракте автоматического завершения](../../../developers/engineering/candidate-verification.md). Автономную пересборку приложения с существующим SDK нельзя описывать как пересборку самого Qt из исходников.
