# Версия продукта и идентичность сборки

[English](../../engineering/versioning.md) | [简体中文](../../zh-CN/engineering/versioning.md) | [繁體中文](../../zh-TW/engineering/versioning.md) | [日本語](../../ja-JP/engineering/versioning.md) | [한국어](../../ko-KR/engineering/versioning.md) | [Français](../../fr-FR/engineering/versioning.md) | [Deutsch](../../de-DE/engineering/versioning.md) | [Español](../../es-ES/engineering/versioning.md) | [Português (Brasil)](../../pt-BR/engineering/versioning.md) | Русский

Необязательное поле `prerelease_number` отделяет порядковый номер предварительного выпуска от номера сборки. Например, alpha.1 может использовать сборку 14, а для alpha.2 номер сборки продолжит расти. Если поля нет, сохраняется прежнее толкование `channel.build`. Манифесты и имена файлов определены в [протоколе выпуска](release-protocol.md).

[VERSION.json](../../../VERSION.json) — единственный поддерживаемый источник версии, канала и номера сборки. Сборка читает текущие значения. Изменения версий отражены в [журнале](../../../CHANGELOG.md), поставки и проверки — в [задачах проекта](https://github.com/xiaodaozhi/xdzip/issues). Увеличение номера само по себе не утверждает выпуск.

Для проверки обновления, отката и совместимости настроек используются фиксированные исторические исходники вместе с текущей сборкой. [Сценарий подготовки прежнего продукта](../../../scripts/prepare-previous-product.py) поддерживает базовую версию полного продукта. [Сценарий совместимости настроек](../../../scripts/check-settings-compat.py) поддерживает базовый набор настроек. Изменяемые коммиты и версии здесь не повторяются. Схема настроек управляется независимо от версии продукта.

- `version` — `major.minor.patch` без начальных нулей. Несовместимые изменения, совместимые возможности и исправления используют соответствующие компоненты. Границы совместимости нужно описывать и для 0.x.
- `channel` поддерживает development, alpha, beta, rc и stable. Предварительные версии отображаются как `version-channel-abbreviation.build`, development сокращается до dev. Для stable отображается базовая версия.
- `build` — целое от 1 до 65535. Увеличивайте его для новой внешней поставки. Локальная компиляция автоматически не меняет номер. Изменение само не создаёт метку или выпуск. Числовые компоненты версии для ресурсов Windows тоже не превышают 65535.
- CMake читает JSON напрямую. `python3 scripts/sync-version.py` обновляет производные версии рабочего пространства Cargo и HTML. CI использует `--check`. Внутренние пакеты Rust наследуют версию рабочего пространства. После синхронизации обновите Cargo.lock и выполните `cargo check --workspace --locked`.
- Числовой ресурс Windows из четырёх частей содержит базовую версию и сборку. Текстовая версия сохраняет канал. В macOS `CFBundleShortVersionString` содержит базовую версию, `CFBundleVersion` — сборку, а длинная текстовая версия сохраняет канал. См. [документацию Apple](https://developer.apple.com/documentation/bundleresources/information-property-list/cfbundleversion). Используйте числовой формат платформы и не помещайте коммиты Git в числовые системные поля.
- В Windows `FileDescription` равно `xdzip Archive Manager`, в том числе в диспетчере задач. `ProductName` остаётся `xdzip`. Имя EXE и идентичность ассоциаций не зависят от отображаемого имени. Проверки сборки читают ресурсы действительного EXE.
- Настольная сборка формирует короткий коммит Git и признак незаписанных изменений. Без Git значение неизвестно. Пути компьютера, имена пользователей и нестабильные метки времени не включаются. Заголовок меняется только при изменении содержимого. Пересборка после коммита создаёт правильный идентификатор чистого состояния.

Версии модуля QML, протокола моста и схемы настроек независимы от версии продукта.

`xdzip --version`, Настройки → О программе и приложение предпросмотра читают одинаковые сведения. CLI обрабатывает параметры версии до создания интерфейса. На странице показаны версия, сборка, коммит, фактический Qt, система и архитектура, явно помечены разработческие каналы и незаписанные изменения. Копируемый JSON не содержит личных файлов, путей, имён машин или учётных данных. Кнопка проекта открывает браузер только по действию пользователя.

Крупный значок страницы использует платформенный PNG в 512 px. HTML использует вектор из того же источника без увеличения значка интерфейса в 72 px.

Страница О программе использует логические параметры настроек без нижней панели. Поддерживаются [поставляемые языки интерфейса](../ux/settings-localization.md), светлая и тёмная темы, размеры 100%, 125% и 150%. См. [макет страницы](../../../design/hifi/sources/settings.html?tab=about). Сведения в HTML формируются из того же JSON. Нативная версия Qt и коммит остаются неизвестными, если их нельзя получить.

Проверки используют `scripts/check-build-version.py` для действительной CLI и нативных ресурсов, `scripts/test-version.py`, `scripts/check-html-about.py` и `BrowserTest::versionAboutWindow`. Снимки и измерения хранятся в `build/review/about/`. Исходники, системные метаданные и запущенная версия должны совпадать. Сам номер версии не подтверждает подпись, ручную приёмку или совместимость.
