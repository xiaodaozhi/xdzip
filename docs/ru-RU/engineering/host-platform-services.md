# Службы календаря и кодировок хоста для процессов обработки форматов

[English](../../engineering/host-platform-services.md) | [简体中文](../../zh-CN/engineering/host-platform-services.md) | [繁體中文](../../zh-TW/engineering/host-platform-services.md) | [日本語](../../ja-JP/engineering/host-platform-services.md) | [한국어](../../ko-KR/engineering/host-platform-services.md) | [Français](../../fr-FR/engineering/host-platform-services.md) | [Deutsch](../../de-DE/engineering/host-platform-services.md) | [Español](../../es-ES/engineering/host-platform-services.md) | [Português (Brasil)](../../pt-BR/engineering/host-platform-services.md) | Русский

Rust обрабатывает поля форматов, правила совместимости паролей и проверку данных. Исторические правила часовых поясов ОС, кодовые страницы OEM и ANSI и локальные кодировки C относятся к среде хоста и доступны через необязательные службы `ReadSource`. Слой формата не должен угадывать их по имени файла, HostOS или текущему смещению UTC. Службы не зависят от Qt и не дают доступа к путям или права сохранять итоговые файлы.

<a name="xdzip-calendar-projection"></a>

## Преобразование в календарную дату

`Timestamp` различает FILETIME в единицах по 100 нс от начала 1601 года и целые секунды Unix без знака от начала 1970 года. `ReadSource::local_calendar` возвращает необязательный `Calendar`. Обычные файлы и источники в памяти по умолчанию используют детерминированное преобразование в UTC. Рабочий процесс приложения использует локальные правила часовых поясов ОС через синхронные вызовы CXX. Windows использует системные API часовых поясов, а Unix — `localtime_r`. Результат проверяется в обоих случаях. Если преобразование недоступно, календарь не возвращается. Неинициализированные поля читать нельзя.

Rust проверяет год, месяц, день, часы, минуты и секунды перед формированием значения DOS для отображения. 7z сохраняет UTC и диапазон 1980..2107. RAR применяет [зафиксированные правила совместимости](../../engineering/rar-format-sources.md) для внутренней модульной арифметики, переопределений времени и различий платформ. Затем используются календарь хоста и историческое циклическое приведение года. Исходная точность, признаки отсутствия значения и полные физические заголовки остаются в закрытом индексе формата. Точность отображения их не перезаписывает. Если время не преобразуется, безопасный вариант RAR показывает 0. Эталонная реализация может скопировать неопределённые данные после непроверенного отказа ОС.

<a name="xdzip-controlled-encoding-mappings"></a>

## Контролируемые преобразования кодировок

| Служба | Вход и выход | Граница хоста |
| --- | --- | --- |
| `oem_to_ansi_wide` | 512 единиц UTF-16 в 512 единиц UTF-16, включая NUL | Полное преобразование Windows через OEM и ANSI с реальным системным сопоставлением и заменами |
| `wide_to_ansi` | До 512 единиц UTF-16, включая NUL, в 512 байт | Текущая кодовая страница Windows ANSI. Универсальный символ замены не предполагается |
| `wide_to_local_prefix` | До 128 широких скалярных значений, включая NUL, в 512 байт | Текущая кодировка C в Unix. При отказе данные очищаются и попытка повторяется по фиксированному правилу с сохранением преобразованного префикса |

Возвращаемая длина не учитывает NUL. Реализации без служб хоста возвращают `None`. Вызывающий код формата может использовать только определённый переносимый резервный вариант или явно отклонить преобразование. Угадывать кодовую страницу нельзя. Вызовы продукта проверяют размеры, NUL и диапазоны результата. Недоступное преобразование возвращает стабильную категорию Unsupported.

Аргумент длины Windows [CharToOemBuffW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-chartooembuffw) считает широкие символы на входе, включая обрабатываемое заполнение после NUL. Это не ёмкость назначения в байтах. Хост проверяет через `GetCPInfo(CP_OEMCP)`, что кодовая страница требует не более четырёх байт на единицу. Затем он преобразует все 512 единиц во временный буфер на 2048 байт. Только потом он записывает NUL в байт 511 и преобразует результат в ANSI. Если требуемая ёмкость не подтверждена, преобразование отклоняется. Нельзя помещать результат обработки 512 широких символов в 512-байтовый буфер или заблаговременно укорачивать вход, чтобы обойти требование. Проверки на ОС покрывают полную границу DBCS в 511 единиц и включают независимое сравнение с прямым вызовом WinAPI.

Допуск 512 единиц, первый NUL, условия компенсации OEM, усечение по 127 единицам и по байтам, протокол старых маркеров и явный UTF8 в macOS относятся к правилам формата в Rust. Нельзя укорачивать пароль до системного преобразования, которое в исходной последовательности выполняется первым. Нельзя произвольно переносить срез внутри последовательности DBCS на границу символа.

<a name="xdzip-ownership-and-failure"></a>

## Владение данными и отказы

Срезы заимствуются только на время синхронного вызова. C++ не сохраняет указатели. Вызывающий код Rust определяет время обнуления секретных входов и результатов. Ограниченные временные буферы C++ для широких и узких символов очищаются при любом возврате. Очистка внутри ОС и всех прежних копий в памяти не гарантируется. Примитивы не записывают пароли в журнал и не передают их в аргументах процесса или переменных окружения.

Чтение проверяет отмену до вызова службы. Результаты служб не считаются выводом распаковки и не меняют число прочитанных, декодированных или записанных байт. Отказы сохраняют исходные категории источника, отмены и квоты и не должны ошибочно считаться сбоями пароля. Только слой формата по фактическому состоянию проверки определяет, можно ли отличить ошибку пароля от нарушения целостности.
