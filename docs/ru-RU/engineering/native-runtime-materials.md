# Происхождение и уведомления нативных компонентов выполнения

[English](../../engineering/native-runtime-materials.md) | [简体中文](../../zh-CN/engineering/native-runtime-materials.md) | [繁體中文（台灣）](../../zh-TW/engineering/native-runtime-materials.md) | [日本語](../../ja-JP/engineering/native-runtime-materials.md) | [한국어](../../ko-KR/engineering/native-runtime-materials.md) | [Français](../../fr-FR/engineering/native-runtime-materials.md) | [Deutsch](../../de-DE/engineering/native-runtime-materials.md) | [Español](../../es-ES/engineering/native-runtime-materials.md) | [Português (Brasil)](../../pt-BR/engineering/native-runtime-materials.md) | Русский

Этот контракт охватывает нативные компоненты выполнения, кроме Qt, в фактических пакетах и применяется вместе с [атрибуцией компонентов выполнения](runtime-attribution.md) и [соответствующим исходным кодом](source-delivery.md). Версия исходников, идентичность файлов, условия лицензий и фактическое выполнение обязательств проверяются отдельно; хеши файлов поставщика не являются одобрением лицензии. Исторические выводы по кандидату `v0.1.0` и дополнительные доказательства приведены в [#4](https://github.com/xiaodaozhi/xdzip/issues/4) и [#53](https://github.com/xiaodaozhi/xdzip/issues/53). Для будущих кандидатов создаются новые задачи выпуска; доказательства создаются только в build/ или артефактах CI.

[Руководство Microsoft по перераспространению среды выполнения](https://learn.microsoft.com/en-us/cpp/windows/redistributing-visual-cpp-files) и [список распространяемых компонентов VS 2022](https://learn.microsoft.com/en-us/visualstudio/releases/2022/redistribution) связывают права перераспространения с применимыми лицензиями. Текст лицензии установщика не доказывает право сопровождающего. [Обязательства Qt по открытому коду](https://www.qt.io/development/open-source-lgpl-obligations) требуют сохранять право пользователей получать соответствующий исходный код, изменять его, повторно компоновать и запускать изменённые библиотеки; динамическая компоновка не заменяет другие обязательства.

Бесплатный путь Community, отдельное право для размещённой Enterprise и условия перераспространения описаны в [лицензировании Windows](windows-licensing.md). Развёртывание включает исходные лицензии CRT/SDK, сведения о происхождении и двуязычный Windows-runtime-NOTICE.txt как в среде выполнения, так и в материалах. Перед компиляцией Setup проверяет хеш исходного соглашения CRT и показывает страницу его лицензии. DLL Microsoft не перелицензируются под Apache-2.0.

## Создание и проверка

`scripts/native-runtime-sources.json` фиксирует версию лицензии ICU, официальный URL и SHA-256. `collect-notices.py` собирает полную лицензию ICU в Linux и повторно проверяет хеши кешей и загруженных данных. Текущие пакеты разработки Windows не содержат `opengl32sw.dll` и больше не собирают для него уведомления Mesa/LLVM. Если каталог вывода уведомлений содержит старые специальные материалы, сбор отказывается повторно использовать его, чтобы не добавить их ошибочно в новый кандидат.

`prepare-source-delivery.py` включает лицензию ICU и зафиксированный перечень исходников. Материалы сохраняют исходные байты; манифест поставки пересчитывает размеры и хеши. Для исторических пакетов с библиотеками программной визуализации Mesa по-прежнему требуются соответствующие исторические исходники, уведомления и выполнение обязательств; новая политика не переписывает прошлую поставку.

Вложения материалов платформы должны включать каталоги, на которые ссылается `license_materials_base` в отчёте об атрибуции. Перед упаковкой повторно проверьте хеш каждого исходного текста лицензии. Идентичный текст в другом месте каталога среды выполнения не оправдывает отчёт, ссылающийся на отсутствующий относительный каталог.

Развёртывание Windows отключает поиск windeployqt в окружении для программного OpenGL, компиляторов D3D и DXC и больше не копирует три библиотеки графических компиляторов из Windows SDK. Область подготовки с такими именами отклоняется. Оставшуюся DLL программного OpenGL в корне контролируемой области подготовки удаляют, а одноимённые остатки в других местах отклоняют.

Упаковка macOS создаёт `deployment-audit.json`, `macos-deployment.json` и `runtime-attribution.json`, пока существует окончательное подписанное приложение. Файловый SBOM использует те же отчёты аудита и атрибуции. Нативные файлы Qt сравниваются по срезам arm64, всем байтам секций, UUID и версиям импорта с допустимым переносом путей Qt для развёртывания. Подписи, расположение команд загрузки и LINKEDIT не входят в вывод этого сравнения. Ненативные ресурсы связываются по точному совпадению байтов. Несвязанные файлы и пробелы исходного SPDX остаются; процесс не является полной бинарной эквивалентностью.

Если после публикации обнаружены отсутствующие уведомления, нельзя утверждать, что дополнительные материалы уже входили в исходный пакет. Артефакты и контрольные суммы исходной версии остаются неизменными; исправленным пакетам нужны новая версия и повторная проверка. Явно зафиксируйте дополнительные материалы и то, с чем они связаны.
