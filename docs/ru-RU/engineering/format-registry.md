# Декларации встроенных форматов

[English](../../engineering/format-registry.md) | [简体中文](../../zh-CN/engineering/format-registry.md) | [繁體中文](../../zh-TW/engineering/format-registry.md) | [日本語](../../ja-JP/engineering/format-registry.md) | [한국어](../../ko-KR/engineering/format-registry.md) | [Français](../../fr-FR/engineering/format-registry.md) | [Deutsch](../../de-DE/engineering/format-registry.md) | [Español](../../es-ES/engineering/format-registry.md) | [Português (Brasil)](../../pt-BR/engineering/format-registry.md) | Русский

Источником встроенных деклараций служит [archive-formats.json](../../../specs/engineering/archive-formats.json). В нём записаны стабильные идентификаторы и обозначения форматов, семейства контейнеров, внешнее сжатие, идентификаторы существующих внутренних процессов, поддерживаемые семейства методов, расширения для создания, охват проверок и возможные точки входа. Семейства методов обобщают контракты форматов. Перед операцией фактические записи, правила хоста и возможности платформы уточняют допустимые параметры, исторические варианты и сочетания.

Охват показывает, что подтверждает успешная [проверка целостности](archive-checking.md). `supported_content` проверяет поддерживаемое содержимое. `structure_and_readability` проверяет структуру и читаемость без гарантии контрольной суммы содержимого. `format_declared_checks` выполняет проверки, предусмотренные потоком, в том числе для профилей без проверочных данных. Возможность проверки определяется отдельно от её охвата. Например, профиль NSIS распознаёт ограниченные метаданные установщика и не поддерживает операцию проверки. Идентификаторы создания разрешаются в пределах методов записи, допустимых для каждого формата.

`creation_methods` сопоставляет транспортные идентификаторы хоста с именами методов. `creation_levels` определяет допустимые уровни для каждого формата. Оба значения передаются в сгенерированные варианты GUI и дескрипторы Rust. CLI, GUI и хост используют общую декларацию, которая поддерживает методы помимо Deflate и LZMA2. Store и Copy сохраняют идентификатор 0, Deflate — 8, LZMA2 — 32. Zstandard использует идентификатор хоста 93. LZ4 использует 256 только внутри своего контейнера, без интерпретации как метода ZIP. У форматов без создания нет уровней создания. Возможность перезаписи не зависит от возможности создания. Генератор отклоняет отсутствующие или неоднозначные идентификаторы и недопустимые уровни для формата.

| Операция | Встроенная поддержка |
| --- | --- |
| Создать новый архив | ZIP, 7z, TAR, TAR.GZ (`.tar.gz`, `.tgz`), отдельный GZIP, XZ/TAR.XZ, LZ4/TAR.LZ4, Zstandard/TAR.ZST, LHA (`.lha`, `.lzh`), ISO9660/Joliet и оболочка ZIP SFX для Windows x64. Отдельный поток принимает один обычный файл. См. [создание](zip-creation.md) и [потоки одного файла](single-file-streams.md). |
| Перезаписать существующий архив | Подходящие архивы ZIP/ZIPX, 7z, LHA/LZH уровня 2, TAR, TAR.GZ, TAR.XZ, TAR.ZST, TAR.LZ4, TAR.BZ2, TAR.LZMA, TAR.LZ, TAR.Z и TAR.BR. Зашифрованные, многотомные архивы и файлы с неподдерживаемыми записями или способом хранения исключены. См. [контракт изменения архивов](archive-transfers.md). |
| Просмотреть, распаковать, открыть запись, экспортировать или проверить | Для каждой операции отдельно проверяются возможности и записи. Например, у некоторых установщиков доступны только метаданные. См. [просмотр в режиме чтения](readonly-browser.md) и [проверка](archive-checking.md). |

После изменения спецификации выполните `python3 scripts/generate-format-registry.py`. Команда генерирует дескрипторы кодеков Rust, форматы-кандидаты C++ для перетаскивания и системной оболочки, варианты интерфейса JavaScript и таблицу значков установщика на Python. `--check` обнаруживает отсутствующие или устаревшие результаты без изменения файлов. `python3 scripts/test-format-registry.py` проверяет противоречивые возможности, дубли идентификаторов и расширений, недопустимые значения в целевых языках и устаревшие компоненты-потребители. Обычная CI выполняет обе проверки.

При открытии сначала применяются правила точки входа и источника из [открытия архивов](archive-opening.md), затем разрешённые байты распознаются и проверяются. Расширение или тип MIME даёт точку входа. Хост также проверяет идентичность источника, параметры операции, разрешение на запись и публикацию результата. `worker_id` выбирает встроенный путь чтения. Образы ISO читает рабочий процесс, а записывает хост Rust. Реестр отдельно учитывает создание и изменение существующего архива.

При необходимости точки входа различают перетаскивание и меню системы. Обычное расширение `.gz` допускает оба входа и создание из одного файла. `.tar.gz` и `.tgz` сохраняют семантику контейнера TAR. XPI/APK/IPA/CBZ сохраняют проверку ZIP и допустимые профили. См. [потоки одного файла](single-file-streams.md). Имена томов и разрешения источников определены в [открытии архивов](archive-opening.md). Реестр не меняет трактовку нумерованных файлов. Windows выбирает значок по последнему расширению, поэтому `.tar.gz` использует ассоциацию `gz`.

Добавляйте только реализованные декларации с соответствующими автоматическими тестами. При изменениях кода обновляйте затронутые [контракт собственных форматов](independent-rust-codecs.md), [контракт рабочих процессов форматов](native-codecs.md), описание возможностей и [критерии приёмки](../../../developers/qa/acceptance.md). Планы, ход работы и результаты фиксируйте в задачах. Созданные тестовые материалы храните в `build/` или артефактах CI.

`creation_wrappers` объявляет оболочку ZIP SFX для Windows x64 и её явное расширение `.sfx.exe`. Она повторно использует идентификаторы методов ZIP и отключает шифрование и тома. Обычные EXE не обрабатываются. При создании ISO9660 используются идентификатор метода хоста 260 и фиксированный уровень 0. См. [создание ISO](iso-creation.md) и [встроенное создание SFX](sfx-creation.md).
