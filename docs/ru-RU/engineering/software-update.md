# Контракт обновления по инициативе пользователя

При наличии идентичности пакета MSIX в Windows окно «О программе» не показывает встроенные обновления, а контроллер отклоняет существующую проверку обновлений GitHub. Обновления версии Store управляются Microsoft Store; для пакетов, установленных вне Store, автоматическое обновление в приложении не гарантируется. Ошибки запроса идентичности трактуются как идентичность пакета, чтобы предотвратить неправильное использование обновлений установщика. Обычные установки и другие платформы не меняются.

Автономная CLI и CLI внутри настольного пакета обновляют собственные установки согласно [контракту командной строки](command-line.md). Автономная CLI использует отдельный подписанный манифест и управляемый каталог версий. Встроенная CLI передаёт намерение использовать кандидат через IPC единственного экземпляра того же пользователя, а настольный контроллер независимо проверяет его. Принятие означает только handed_off; для реального успеха необходимы квитанция и идентичность запущенной версии. Защита занятой установки в Windows/Linux распространяется на задачи CLI; macOS защищает CLI блокировкой совместного использования, барьером фиксации и постоянным состоянием. Существующие задачи не отменяются неявно. Запросы идентичности CLI без интерфейса не создают QApplication и не читают и не удаляют квитанции установки.

`UpdateController` приложения проверяет публичные выпуски через окно «О программе». Закрытие окна не отменяет проверки или загрузки; при повторном открытии отображается то же состояние. Проверки запускает пользователь, без опроса при старте и автоматической установки. Окна продукта продолжают использовать окно «О программе» и общие элементы управления операциями.

## Выбор, сеть и конфиденциальность

Клиент обновления Qt использует HTTP/1.1 для метаданных, контрольных сумм и загрузки пакетов. Так применяется опубликованная мера снижения риска для фиксированного выпуска Qt. Транспорт обновления Sparkle на macOS отдельный. [Предупреждение безопасности Qt](https://www.qt.io/blog/security-advisory-cve-2026-96432)

Клиент читает только публичный [API выпусков](https://docs.github.com/en/rest/releases/releases) фиксированного репозитория `xiaodaozhi/xdzip`, не использует учётные данные и не отправляет имена файлов, содержимое архивов, пароли, последние записи или настройки. GitHub и CDN загрузки получают сведения о соединении и User-Agent с версией приложения. Страницы выпусков и папки загрузок открываются через системный интерфейс.

Каждая страница содержит не более 100 записей, всего не более 10 страниц; каждый ответ ограничен 8 MiB, манифесты — 256 KiB, подписи — 4 KiB. Исходные запросы допускают только HTTPS и явно зарегистрированные хосты GitHub/CDN. При заданном пользователем зеркале его HTTPS-сайт разрешается как адрес транспорта; допускается не более пяти перенаправлений. Для метаданных предел простоя составляет 15 секунд, общий предел — 30 секунд; для загрузок — 30 секунд простоя и один час всего. Кэш ETag в памяти содержит не более 24 записей; ответ 304 повторно использует только предыдущий успешный ответ. Отсутствие сети, ошибки TLS, тайм-ауты, ограничение частоты, усечение, отсутствие пакетов и ошибки манифеста являются сбоями, а не состоянием «уже обновлено». Повторные нажатия не запускают параллельные обновления.

Обновления используют настроенный системный, прямой или пользовательский HTTP/SOCKS5-прокси без учётных данных. Необязательное зеркало должно использовать HTTPS и не содержать учётных данных, запроса или фрагмента; к его базовому адресу добавляется полный исходный HTTPS URL GitHub. Исходные URL по-прежнему проверяются по фиксированному списку разрешённых хостов. Зеркала и перенаправления не изменяют содержимое подписанного манифеста, проверку, идентичность кандидата или барьеры установки. Изменения конфигурации применяются к следующему обновлению после завершения текущего. Нативный Sparkle macOS поддерживает системный, прямой и пользовательский HTTP CONNECT/SOCKS5-режимы без учётных данных. Каждый нативный экземпляр до запуска копирует проверенные режим и адрес прокси и использует одну политику сеанса для ленты и архива. При сбое пользовательского прокси переходить на прямое соединение нельзя. Прямой режим явно задаёт числовое значение 0 флагам HTTP, HTTPS, SOCKS, FTP, PAC и обнаружения в словаре прокси URLSession; словарь nil или пустые современные массивы прокси по-прежнему означают системный вариант по умолчанию. Доверие TLS, подписи выпусков и независимые барьеры установки не меняются.

HTTP 429 означает ограничение частоты. HTTP 403 классифицируется так только при нулевом остатке квоты, наличии корректного Retry-After в секундах либо явном указании ограничения в JSON-сообщении GitHub. Другие ответы 403 остаются сетевыми ошибками; исчерпание квоты не предполагается. Продукт не повторяет запрос автоматически и не читает учётные данные GitHub. Анонимная квота общая для исходного IP; права репозитория в CI не увеличивают её.

Ядро Rust без Qt выбирает кандидата по семантической версии, каналу и монотонно возрастающему номеру сборки и проверяет фиксированный репозиторий, все шесть классов пакетов, архитектуру, тип пакета, требования к минимальной системе и одинаковую идентичность кандидата. stable принимает только stable; alpha принимает alpha, beta, rc и stable; beta исключает alpha; rc принимает rc и stable; dev может проверять публичные выпуски. Увеличиваться должны и семантическая версия, и номер сборки; время публикации не заменяет их. Клиент также проверяет поддержку текущей системы и размер ресурсов Releases в байтах.

## Доверие и загрузки

`release.json.sig` проверяет точные байты манифеста. Корни доверия скомпилированы в клиент и вспомогательную программу установщика и не добавляются из загрузок или запросов. Метаданные JSON проверяются как UTF-8 до передачи строк через FFI; неверная кодировка явно приводит к ошибке, а не изменяет аутентифицированные байты символами замены. Форматы подписей, независимые ключи Sparkle, порядок доставки и неизменяемые ресурсы описаны в [протоколе выпуска](release-protocol.md). При отсутствии подписи или неизвестном открытом ключе предлагается только ручная загрузка с официальной страницы выпуска; неправильная подпись явно вызывает ошибку. Автоматическая замена отключена до настройки открытого ключа production.

Windows/Linux потоково загружают пакеты до 2 GiB в закрытый кэш обновления с проверкой длины и SHA-256; передача вспомогательной программе разрешена только после успешной публикации. Отмена или ошибка проверки не создаёт состояния, пригодного для установки. Портативные, изменённые, разрабатываемые или собранные из исходников сборки, а также сборки неизвестной идентичности предлагают только проверку и загрузку. Автоматическая замена также требует конфигурацию Release и действительную идентичность коммита; сборка из архива исходников без идентичности Git не считается установленной. Идентичность установки должна совпадать с системной записью об установке, путём работающей программы и маркером пакета.

macOS использует фиксированный Sparkle 2.10.0 и ограниченное расширение прокси `xdzip-proxy.2`; тонкий пользовательский драйвер Objective-C++ передаёт состояние в единое окно «О программе». Библиотека фреймворка и Ed25519 собираются нативно на Apple Silicon из фиксированных исходников и патчей; ресурсы, вспомогательная программа установщика и средства подписи сохраняют происхождение из фиксированного официального SDK. Побайтовая идентичность производного фреймворка исходному SDK не заявляется. Sparkle нативно проверяет ленту и архив; лента содержит только тот же выбранный кандидат. Не утверждается, что Sparkle выполняет дополнительную проверку SHA-256. DMG только для чтения, App Translocation, незарегистрированное приложение .app или отсутствие открытого ключа обновления ведут к ручной установке. Обычный CI не развёртывает, не подписывает и не загружает пакеты приложений Mac только из-за использования Sparkle.

При ручном варианте отображается первое невыполненное условие из идентичности установки, сеанса, отсутствия ленты автоматических обновлений или неверной сетевой конфигурации. Ошибка идентичности означает лишь сбой группы проверок, без предположения о конкретной причине; несколько условий могут требовать последовательного устранения. Окно «О программе» содержит ссылки на соответствующий выпуск и инструкции для DMG и объясняет извлечение app.zip, выход из старой версии и замену приложения. Успешная загрузка не означает успешную установку.

## Передача установки и восстановление

Существующие задачи продолжаются во время загрузки. Если после выбора загрузки и установки есть активные задачи, выполняется ожидание; пользователь может отменить ожидание и отложить обновление без неявной отмены задач или запросов пароля. После подготовки вспомогательной программы `prepareForUpdate` отклоняет активные задачи, запуск задач и модальные взаимодействия. После начала передачи новые сеансы и задачи не допускаются; до отправки фиксации установки все соединения Rust должны быть очищены и завершены. Передача не использует путь «немедленно перезапустить старую программу».

Windows копирует автономную вспомогательную программу без Qt в закрытый кэш только из зарегистрированного корня установки текущего пользователя. Она независимо повторно проверяет подпись, размер и хеш, ждёт завершения зафиксированного основного процесса, затем запускает существующий установщик Inno с интерактивным принятием лицензии. Барьер установки блокирует перезапуск во время замены.

Если корень установки не проходит проверки безопасности, окно «О программе» указывает на разрешения папки установки или ручную установку со страницы выпуска, не классифицируя отказ как сетевую ошибку. Существующие проверки каталога и идентичности не ослабляются.

Установки Ubuntu используют фиксированный путь `/usr/libexec/xdzip-update-helper`; координатор обычного пользователя вызывает polkit только с фиксированными аргументами. Вспомогательная программа root копирует пакет в закрытую область подготовки root, повторно проверяет подпись, имя пакета xdzip, архитектуру и версию и разрешает только фиксированные операции APT. Она не принимает команды, произвольные имена пакетов или целевые каталоги и не использует оболочку sudo. Отмена авторизации и отсутствие агента аутентификации — разные состояния. Несконфигурированный dpkg не сообщается как успех; автоматического отката и перезапуска старой программы нет. При перезапуске новой версии от исходного пользователя сохраняются ограниченные разрешённым списком каталоги XDG настроек, данных, кэша и состояния и язык рабочего стола, но не переопределения динамического загрузчика, Qt SDK или тестовой среды; эти переменные не передаются командам установки root.

В macOS обратный вызов установки Sparkle освобождается только после завершения всех соединений. Основная программа синхронно освобождает перехватчик выхода только после того, как провайдер отметит фактическую установку зафиксированной, и до вызова ответа установки SDK; один лишь барьер ожидания не должен разрешать преждевременный автоматический выход при закрытии последнего окна. После неудачной или отменённой передачи обычный выход продолжает ждать барьер наблюдения нативной вспомогательной программы. Фактическую замену архива и перезапуск выполняет Sparkle. После отмены план установки при следующем выходе не остаётся. Фреймворк, XPC и вспомогательная программа сохраняют отдельно необходимые параметры подписи и полномочия; общие правила повторной подписи нельзя применять ко всем.

Ответы на отмену Sparkle обрабатываются в асинхронном цикле обновления; завершение цикла не означает завершение отдельного процесса установщика. Для незафиксированной установки обычный выход запрашивает отмену, ждёт цикл и затем использует системный `/bin/ps` только для чтения, чтобы наблюдать процессы Autoupdate, совпадающие с точным путём фреймворка приложения. Перехватчик выхода освобождается лишь после их завершения. Совпадающий установщик фиксируется при готовности. Сбой проверки не разрешает выход; вспомогательную программу не завершают принудительно и данные посторонних процессов не журналируют. Повторные попытки после сбоя подготовки также ждут завершения старой вспомогательной программы до замены драйвера обновления. Зафиксированные установки используют штатный выход и перезапуск Sparkle.

Транзакции Windows/Linux используют случайные ID и фиксированные имена файлов ready/proceed/cancel/result. До выхода клиент сохраняет транзакцию, идентичность цели и каталог кэша в отдельном `update-state.ini` рядом с настройками, а не внутри их конфигурации. Вспомогательная программа атомарно записывает успешный результат до освобождения барьера и перезапуска. При следующем старте ограничиваются пути и размеры квитанций и проверяются транзакция и текущая идентичность версии, сборки и установки. Ошибка, отсутствие квитанции или несовпадение показывают восстановление без автоматического повтора установки. Запись восстановления без действительного URL кандидата всё ещё может открыть фиксированный официальный список выпусков. Материалы кэша сохраняются для исправления пользователем; публичные свидетельства не должны содержать полные приватные пути.

До освобождения установки Sparkle macOS сохраняет локальную запись попытки с целевой версией и сборкой. После перезапуска фактическая идентичность работающей программы и надёжные маркеры установки определяют завершение или восстановление. Запись не даёт полномочий на установку и не заменяет проверку подписи Sparkle.

## Границы проверки

Диагностика только для Mac может выполнять лишь полную цепочку продукта. Проверка всех платформ всегда выполняет шесть сценариев Sparkle и полную цепочку продукта, игнорируя диагностическую возможность пропуска шести сценариев.

Проверки системных конфликтов нативного загрузчика временно включают собственные статический прокси и PAC только на явно изолированных одноразовых размещённых runner Apple Silicon. Сначала требуются фактические обращения ленты и архива к прокси в системном режиме, затем нулевое число обращений в прямом режиме. Контроль HTTPS проверяет адреса соединений и сохраняет отклонение недоверенных сертификатов. Ограниченная вспомогательная программа сохраняет, восстанавливает и проверяет полные настройки прокси службы и содержимое hosts для фиксированных тестовых доменов, в том числе при EOF и тайм-ауте. Локальные запуски никогда не изменяют прокси, DNS или доверие к сертификатам. Отдельная полная цепочка продукта проверяет прямую установку при управляемом PAC, обычный перезапуск и активные снимки конфигурации обновления; проверки загрузчика не заменяют свидетельство установки.

Приёмка HTTPS без SDK на Mac использует ту же развёрнутую пробу и анонимные реальные запросы обновления. Записи содержат только код состояния, ошибку Qt и разрешённые заголовки ответа об ограничении частоты, а не исходные тела ошибок, IP источников или учётные данные. После подтверждения ограничения драйвер приёмки запускает не более трёх проб, ожидая до более позднего времени из Retry-After и сброса квоты. Без пригодного времени сброса основной квоты он отказывает в раннем повторе; другие подтверждённые ограничения используют возрастающую задержку не менее 60 секунд. Общее ожидание ограничено 3700 секундами; превышение явно вызывает ошибку с сохранением каждого результата и фактической задержки. Существующие тайм-ауты запросов, TLS, ограничения ответа, успешный статус и изоляция SDK остаются обязательными; повторы не объединяются в один успешный проход. Эта задержка относится только к специальному драйверу приёмки и не добавляет фоновые повторы в продукт и не разрешает пропуск заключительных специальных проверок.

Тестовые данные ядра охватывают каналы, dev, нарушенный порядок страниц, отсутствие пакетов, неверные подписи, минимальную систему и конфликты идентичности. Сетевые тестовые данные охватывают отмену, повторные нажатия, ограничения частоты, TLS, пределы ответа, ETag и повреждённые загрузки. Регрессии сеансов проверяют сохранение задач и передачу после завершения всех соединений. Реальные обновления со старой версии на новую на трёх платформах, отмена авторизации, перезапуск, ошибка и восстановление установки, сохранение настроек и ассоциаций и HTTPS без SDK требуют свидетельств из изолированной платформы; модульные тесты и компиляция CI их не заменяют. Полные обновления Mac требуют нативного Apple Silicon. Фактическое завершение и свидетельства отслеживаются в issue.

[Специальная нативная регрессия обновления](../../../.github/workflows/update-regression.yml) запускается только вручную, не содержит production-секретов и не загружает пакеты приложений. По умолчанию она охватывает все платформы и позволяет выбрать одну для диагностики, каждая со своей очередью; для окончательной приёмки по-прежнему нужны результаты всех платформ одного коммита. Windows на одноразовых GitHub runner и Linux в отдельном контейнере сначала используют собственный продукт протокола C и реальные Inno/APT для проверки отмены, ошибки и восстановления вспомогательной программы. Другая приватная цепочка обновления Qt собирает две реальные версии `browser_main`/QML, использует реальные действия мышью в окне «О программе» и проверяет манифесты и пакеты, ожидание выхода, Inno/APT, перезапуск единственного экземпляра от обычного пользователя и восстановление квитанции. Она также проверяет сохранение настроек, неизвестных ключей настроек, существующих значений по умолчанию и посторонних файлов каталога установки. Linux разделяет контейнеры SDK сборки и среды выполнения; последняя не содержит компилятора или Qt SDK и использует собственные каталоги XDG. CI Windows Server подменяет определение минимальной системы только под приватным макросом и не заменяет нативную приёмку Windows 11. Эта цепочка подменяет сетевой транспорт публичных URL GitHub; production HTTPS/TLS отдельно проверяется без SDK.

[Приёмка production-подписи](../../../.github/workflows/production-update-acceptance.yml), разрешённая отдельно, использует существующие ключи защищённой среды с сохранением закоммиченных открытых production-корней и следует реальной цепочке обновления и восстановления Qt. Подготовка не выполняет подпись. Независимый этап подписи сначала строго сверяет открытые корни доверия, затем проверяет этот фиксированный кандидат; исполнение отклоняет среды с секретами. Интерфейса произвольной подписи или публикации ресурсов нет. Подписанные кандидаты остаются на одноразовых runner; публичные артефакты содержат только ограниченные диагностику и сводки. Это фиксируется отдельно от регрессий с тестовыми ключами; только фактическое исполнение считается успешным, а совпадение ключей не означает успех установки. См. [протокол выпуска](release-protocol.md).

Расширенный сценарий задерживает завершение загрузки пакета, запускает реальную проверку AES до ожидания пароля и проверяет, что обновление ждёт задачу. Диалог пароля остаётся нативным модальным окном приложения; тест отменяет ожидание обновления через контроллер и явно фиксирует, что мышь в окне «О программе» на этом шаге не использовалась. После отмены сохраняются та же задача и тот же токен пароля; событие подтверждения метода ввода и кнопка подтверждения пароля завершают проверку, после чего установка повторно запускается из окна «О программе». Другой запуск отправляет системный выход настоящей основной программе при одновременном ожидании обновления и пароля, нажимает реальные элементы «Вернуться» и «Отменить и выйти» и проверяет ту же задачу и токен, завершение всех соединений, ноль передач установки и обычный перезапуск той же старой установки до обновления. Физический рабочий стол и действия человека проверяются по необходимости и фиксируются отдельно; проверка лицензий и разрешение выпуска также разделены.

Регрессия компонентов с двумя сеансами открывает одно и то же окно выхода через AppQuitGuard, DesktopIntegration и маршрутизацию всех сеансов, проверяя возврат, отмену и завершение ожидающей задачи AES. Подтверждение выхода может перекрывать только собственное модальное окно пароля или конфликта управляемого сеанса; нативные модальные окна QWidget по-прежнему блокируют выход. Эту компонентную проверку фиксируют отдельно от системного выхода полной основной программы во время ожидания обновления и нативной регрессии установки.

До первого системного выхода полный тест продукта Mac должен фактически увидеть, что окно пароля того же рабочего сеанса видимо, выведено на экран, принадлежит соответствующему основному окну и является текущим модальным окном приложения, а токены задачи и пароля не изменились. Запрос пароля Rust не доказывает готовность отложенного отображения. Системный выход отправляется только один раз после выполнения этих условий, затем проверяются реальный возврат, восстановление модального окна, отмена и завершение всех соединений. При тайм-ауте прогресс фиксируется до очистки; результаты выхода, созданные позже во время очистки, не могут заменить ошибку.

Приватная регрессия установки Windows приостанавливает реальный Inno после копирования нового `xdzip.exe` и до копирования других файлов, проверяет новую идентичность и повторно запускает реальную программу Qt. Требуется выход барьера запуска с кодом 11 без видимого окна и нового сеанса; затем копирование возобновляется и существующая приёмка обновления завершается. Дескрипторы наблюдения закрываются сразу, чтобы тест не продлевал барьер установщика. Старая и новая версии используют Qt 6.8.2; это не доказывает атомарную замену пакета приложения или миграцию между версиями Qt. В production-шаблоне установщика паузы нет.

Отдельно названное приватное приложение Qt для Mac использует реальное окно «О программе», завершение двух сеансов, Sparkle, подписанный app.zip и перезапуск в новую сборку, проверяя подмену ленты или архива и отмену. Только обнаружение кандидата использует локальную подмену loopback; публичные манифесты и каналы GitHub отдельно проверяются регрессиями ядра обновления и сети. Тестовые ключи вводятся только в приватную копию; production-ресурсы не меняются. Только свидетельства фактического исполнения можно записывать как успешные.

Специализированный тест вспомогательной программы Windows также нажимает реальную кнопку отмены на странице лицензии Inno и использует приватное внедрение ошибки InitializeSetup. Журналы установщика должны подтвердить этот путь, старую идентичность, отсутствие перезапуска и освобождение барьера установки. Linux использует реальный pkexec для отдельной проверки отказа политики, отсутствия агента аутентификации и стандартного D-Bus-агента, возвращающего Cancelled. Агент отмены обслуживает только фиксированные тестовые UID, действие и запрос, не получает пароли и не предоставляет полномочий. Успешное обновление отдельно проверяет существующие ассоциации ZIP, TAR и GZip по умолчанию. Автоматическое нажатие кнопки лицензии и тестовый агент не являются ручным подтверждением лицензии или приёмкой системного агента аутентификации рабочего стола.

Полные Qt-регрессии Windows/Linux отправляют реальный пакет с ошибкой инициализации Inno или postinst с однократным сбоем, фиксируют фактический запрос, транзакцию, квитанцию ошибки и освобождение барьера и запрещают автоматический перезапуск после сбоя. Восстановление запускает обычную основную программу. Приватная сетевая фабрика возвращает null, чтобы конструктор контроллера по умолчанию прочитал квитанцию из фактического кэша по умолчанию. Требуются состояние восстановления, та же фактическая идентичность установки, отсутствие новых задач, передачи установки и автоматического повтора, сохранение настроек и ассоциаций ZIP/TAR/GZip по умолчанию. При сбое Linux postinst новые файлы уже могут быть установлены; проверяются фактическая новая версия и наполовину настроенное состояние dpkg, а не утверждается сохранение старой версии. Только тест явно исправляет конфигурацию APT и сбрасывает отдельный успешный сценарий; это тестовое действие нельзя описывать как откат продукта.

Полные регрессии продукта Mac различают отмену на границе ожидания и фиксации и отказ файловой системы после фактической фиксации, обратимо применяя UF_IMMUTABLE к принадлежащему тесту корню старого приложения. Во втором случае необходимо записать фактическую фиксацию установки, точный PID вспомогательной программы, завершившейся самостоятельно, и её журнал ошибки разрешений; отмена передачи не заменяет ошибку установки. Флаги восстанавливаются только после проверки собственного участка, UID, dev/inode и исходных флагов. Не используйте sudo, не завершайте установщик принудительно и не подделывайте результаты. Оба случая восстановления обычно запускают старую версию и читают постоянные записи попыток. Фактические артефакты Apple Silicon показывают, прошли ли они проверку.

Другая полная цепочка продукта Mac собирает настоящие основные программы из двух чистых идентичностей исходников Release, сохраняя официальный bundle ID, маркеры установки и типы документов Alternate, и устанавливает их в собственный путь Applications одноразового runner. Старая версия использует реальные окно «О программе» и UpdateController для аутентификации манифеста, установки Sparkle и передачи после завершения соединений. Обычный запуск новой версии проверяет идентичность установки, квитанцию обновления, каталог конфигурации по умолчанию, настройки и неизвестные ключи, поведение единственного экземпляра и обработчик ZIP по умолчанию в LaunchServices. Приватный транспорт сопоставляет только фиксированные URL метаданных, аутентифицированный URL ленты и точный URL архива; подписи действительно проверяются, а HTTPS без SDK проверяется отдельно. Регрессия использует HOME и пути конфигурации по умолчанию исходного пользователя, не заменяя восстановление после перезапуска внедрением тестовых путей.
