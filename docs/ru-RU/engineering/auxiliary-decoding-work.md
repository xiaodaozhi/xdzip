# Учёт вспомогательной работы алгоритмов

[English](../../engineering/auxiliary-decoding-work.md) | [简体中文](../../zh-CN/engineering/auxiliary-decoding-work.md) | [繁體中文](../../zh-TW/engineering/auxiliary-decoding-work.md) | [日本語](../../ja-JP/engineering/auxiliary-decoding-work.md) | [한국어](../../ko-KR/engineering/auxiliary-decoding-work.md) | [Français](../../fr-FR/engineering/auxiliary-decoding-work.md) | [Deutsch](../../de-DE/engineering/auxiliary-decoding-work.md) | [Español](../../es-ES/engineering/auxiliary-decoding-work.md) | [Português (Brasil)](../../pt-BR/engineering/auxiliary-decoding-work.md) | Русский

Распаковка и проверка отдельно учитывают декодированные байты файлов, фактический вывод и вспомогательную работу алгоритмов. Инициализация модели PPM, сбросы при нехватке ёмкости и декодирование управляющих данных или параметров не входят в содержимое файлов. Они не должны увеличивать `decoded_bytes`, `written_bytes`, прогресс по файлам или коэффициент распаковки и давать допуск на предварительно учтённый вывод. В снимках задач не добавляется видимый пользователю вспомогательный счётчик.

`DecodedSink::charge_auxiliary(bytes)` сообщает только об уже выполненной вспомогательной работе. Реализация по умолчанию не меняет файловые счётчики. Перед выполнением алгоритмы проверяют допуск по оставшемуся бюджету. После выполнения они учитывают фактическую работу, включая работу до сбоя или отмены. Неиспользованные резервы не считаются выполненной работой. При ошибке, сбросе модели или повторе пароля затраты не возвращаются. Общий внутренний бюджет RAR по-прежнему ограничивает сумму декодирования файлов и вспомогательной работы.

<a name="xdzip-isolation-boundary"></a>

## Граница изоляции

- Сообщение `AUX_WORK=24` передаёт одно значение `u64` в порядке от младшего байта к старшему без содержимого. В пакете допускается значение от 1 до 65 536, на нём кадр должен точно завершиться. После успешного учёта хост отвечает пустым `ACK`. Ноль, усечённые данные, поля в конце, превышение лимита и недопустимые фазы отклоняются.
- Сообщение допустимо только при декодировании данных RAR. Оно не используется при сканировании метаданных, создании, изменении или с другими форматами. CXX передаёт числа синхронно и не сохраняет указатели Rust. Срезы ввода и вывода заимствуются только на время вызова. Исключения C++ преобразуются в стабильные ошибки внутри обратных вызовов. Раскрутка стека Rust не пересекает CXX. Аварийная остановка или выход процесса делают незавершённый вывод неуспешным.
- Нативный экземпляр декодирования накапливает до 20 GiB вспомогательной работы. Сумма сохраняется между записями, перезапусками процесса и сменой пароля. Выполненная работа записывается до вызова выходного интерфейса хоста. Отказ интерфейса не возвращает затраты при повторе. `AUX_WORK` не увеличивает `WorkerCredit`.
- Задачи распаковки и проверки среды выполнения независимо накапливают до 20 GiB вспомогательной работы. Объект учёта расположен вне циклов записей и повторного ввода пароля. Этот бюджет проверяется отдельно от фактических байтов файлов и лимитов вывода. Превышение или отмена приводят к сбою без публикации незавершённого файла. Изменение публичных счётчиков не позволяет обойти лимиты.
- `WORK=17` по-прежнему представляет декодированные байты файлов. Только успешный допуск даёт тому же действующему процессу одноразовый допуск на доставку `PRECHARGED_DATA=23`. Допуск расходуется до передачи и сбрасывается при перезапуске. Этим путём пользуются RAR, 7z и CAB. Сканирование и создание его не используют. Вспомогательная работа не даёт допуска для файлового вывода.

Допуск высокой степени сжатия использует зафиксированные объявленные размеры, размеры сжатых данных или всего архива. Лимиты декодирования и вывода применяются независимо. Если для файла в 87 байт инициализация модели требует несколько MiB работы, файловые счётчики всё равно отражают только его фактические 87 байт.

<a name="xdzip-required-acceptance-conditions"></a>

## Обязательные условия приёмки

- Обычный небольшой файл можно успешно распаковать и проверить после более чем 64 KiB вспомогательной работы и инициализации модели. Файловые счётчики точны, итоговая проверка содержимого проходит.
- Нативный слой и среда выполнения независимо проверяют отказ, когда объём повторяющихся фактически обработанных вспомогательных пакетов достигает 20 GiB. Повторный ввод пароля и замена процесса не сбрасывают накопленный расход. Незавершённые файлы не фиксируются.
- Запросы имитированного процесса для иных форматов, фаз метаданных, пустых и слишком больших пакетов, лишних полей и предварительно учтённого вывода с допуском только за вспомогательную работу отклоняются.
- Обычный `WORK` может дать допуск для предварительно учтённого вывода RAR тому же процессу. Допуск расходуется один раз и не используется повторно после ошибки или перезапуска.
- Протокольная оснастка проверяет только автомат состояний и учёт. Полный процесс RAR на Rust, фактический путь среды выполнения, три платформы и настольная приёмка требуют собственных результатов.

Протокольная оснастка компилирует только принадлежащий проекту `tools/native-codec/main.cpp` и заглушку без алгоритма сжатия.

```sh
cmake -S crates/xdzip-codec-native/tests -B build/auxiliary-protocol
cmake --build build/auxiliary-protocol --config Release
```

Укажите путь к оснастке в `XDZIP_NATIVE_CODEC_WORKER`, установите `XDZIP_AUXILIARY_PROTOCOL_FIXTURE=1` и явно запустите `cargo test -p xdzip-codec-native auxiliary_protocol -- --ignored`. Обычная целевая проверка использует `cargo test -p xdzip-codec-native -p xdzip-runtime auxiliary`. Тесты API кодеков проверяют совместимость выходного интерфейса по умолчанию. Материалы проверки остаются в build или CI. Результаты и оставшиеся пункты фиксируются в [задаче миграции #51](https://github.com/xiaodaozhi/xdzip/issues/51).
