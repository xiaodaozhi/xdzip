# Источники и лицензии форматов WIM, MSI и установщиков

На этой странице описаны технические источники, лицензионные ограничения и требования к поддержке WIM, MSI и форматов установщиков. Справочные материалы хранятся в `build/toolchain/references` или представлены ссылками на открытые спецификации. Ни один из них не является зависимостью продукта.

<a name="xdzip-wim"></a>

## WIM

- Эталонная реализация: `ebiggers/wimlib`, коммит `cd5e231c348c255ae5088873b5a66ee0eb96fa07`.
- Репозиторий предлагает GPLv3+ для проекта и условный выбор LGPL-2.1+ для библиотеки. Выбор LGPL зависит в том числе от того, не навязывают ли зависимости третьих сторон, такие как `libntfs-3g`, условия GPL.
- WIM — контейнер образов, а не обычный архив. Читатель с установленными ограничениями должен обрабатывать таблицы ресурсов, потоки метаданных, ресурсы из блоков, сжатие Xpress/LZX/LZMS, таблицы целостности, метаданные жёстких ссылок и выбор образа без монтирования или восстановления полномочий безопасности.

Эталонная реализация полезна для изучения формата и тестового корпуса, но действующая политика отказа от сторонних зависимостей времени выполнения не позволяет связывать её с xdzip. WIM **исключён по решению о продукте**: проект не берёт на себя разработку специального читателя образов, модели усиления при распаковке, ресурсов целостности, семантики жёстких ссылок и полного корпуса, необходимых для поддержки. Записи реестра, MIME, среды выполнения или CLI запрещены, пока это решение явно не пересмотрено.

<a name="xdzip-compound-file-and-msi"></a>

## Compound File и MSI

- Microsoft [MS-CFB] — основная открытая спецификация: https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-cfb/53989ce4-7b05-4f8d-829b-d08d6148375b . На странице опубликованы редакции PDF/DOCX и уведомление об интеллектуальных правах, разрешающее реализацию описанной технологии. Патентные лицензии по-прежнему регулируются применимыми программами Microsoft.
- До интерпретации данных MSI читатель CFB должен обработать распределение секторов и FAT/DIFAT, обход красно-чёрного дерева каталогов, распределение мини-потоков, ограничения размера потоков и обнаружение циклов.

Независимый читатель метаданных CFB технически возможен и уже реализован в компоненте `xdzip-codec-cfb` только для чтения. Прежде чем показывать строки хранилищ и потоков, он проверяет заголовки CFB 3.0/4.0, включая базовые размеры секторов 512 и 4096 байт, цепочки FAT/DIFAT, дерево каталогов, распределение мини-потоков, ограничения размеров потоков и циклы. Копирование необработанного потока доступно только после совпадения неизменяемого снимка метаданных. Таблицы MSI, встроенные файлы cabinet, пользовательские действия и преобразования остаются вне контракта: установщик не запускается, пользовательские действия не интерпретируются, пакеты не устанавливаются и обратная запись не выполняется. Суффикс `.msi` не даёт полномочий на выполнение. Проверки образцов и среды выполнения автоматизированы в тестах кодека и среды выполнения.

<a name="xdzip-nsis-and-other-sfx"></a>

## NSIS и другие SFX

- Эталонный исходный код NSIS: `kichik/nsis`, коммит `a96303eae3115221471bb127fa916a13d8bf9ecd`.
- Файл `COPYRIGHT` указывает zlib/libpng для большей части исходного кода и компрессора zlib, bzip2 для модуля bzip2 и Common Public License 1.0 для модуля LZMA.
- Файлы NSIS — исполняемые установщики со сценариями и встроенными данными. Анализатор должен оставаться за пределами выполнения, ограничивать диапазоны заголовка и данных и отделять методы сжатия от поведения установщика.
- Открытый исходный код определяет фиксированную запись `firstheader`: `flags`, `0xDEADBEEF`, слова сигнатуры `NullsoftInstallSystem`, `length_of_header` и `length_of_all_following_data`. Статический читатель может найти и проверить запись без открытия загрузочной части PE, но для сжатых блоков заголовка и полных собственных установщиков всё ещё нужна независимая модель.

NSIS **допущен только для статических метаданных**. Кодек просматривает только записи, выровненные по 512 байтам, в ограниченной дополнительной области PE, принимает два зафиксированных магических значения `firstheader`, ограничивает флаги и длины и требует, чтобы объявленный следующий диапазон помещался в физическом входе. Затем он публикует одну строку метаданных `NSIS/firstheader`. Кодек не распаковывает заголовок установщика и не раскрывает байты встроенных данных. Запись реестра `.exe` намеренно не является ни кандидатом для перетаскивания, ни системной ассоциацией; решающим остаётся определение по содержимому. Анализатор не зависит от Qt и API выполнения установщиков. Он никогда не запускает загрузочную часть PE, сценарий, пользовательскую страницу, подключаемый модуль или извлечённые данные. Другие форматы SFX остаются псевдонимами только тогда, когда их внутренний архив проходит проверку содержимого.

<a name="xdzip-admission-gates"></a>

## Условия допуска

1. Зафиксировать ревизии исходного кода и хеши текстов лицензий до использования справочного инструмента.
2. Создать полные, допускающие перераспространение тестовые образцы для каждого допущенного контейнера и метода сжатия. Образца только с заголовком недостаточно.
3. Сохранить независимость разбора CFB/WIM/NSIS от Qt и API установки, монтирования, реестра и выполнения сценариев.
4. Добавлять записи среды выполнения, CLI и рабочего стола только после успешных тестов точной физической идентичности, дубликатов, ограничений циклов, суммарных пределов ввода, работы и вывода, отмены, изменения источника и окончательной ошибки.
5. Оставить справочные компоненты GPL/LGPL/CPL в build/toolchain, если отдельное решение о зависимостях и лицензиях явно не изменит политику продукта.
