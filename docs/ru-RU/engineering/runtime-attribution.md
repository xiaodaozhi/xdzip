# Атрибуция фактических компонентов и лицензионные материалы

[English](../../engineering/runtime-attribution.md) | [简体中文](../../zh-CN/engineering/runtime-attribution.md) | [繁體中文](../../zh-TW/engineering/runtime-attribution.md) | [日本語](../../ja-JP/engineering/runtime-attribution.md) | [한국어](../../ko-KR/engineering/runtime-attribution.md) | [Français](../../fr-FR/engineering/runtime-attribution.md) | [Deutsch](../../de-DE/engineering/runtime-attribution.md) | [Español](../../es-ES/engineering/runtime-attribution.md) | [Português (Brasil)](../../pt-BR/engineering/runtime-attribution.md) | Русский

Этот процесс дополняет пофайловые SBOM, сопоставляя фактические библиотеки и плагины Qt с декларациями SPDX из SDK. Его результат — проверяемое свидетельство, а не автоматический выбор лицензии или подтверждение соблюдения требований. Полнота, необходимая для официального выпуска, пока не достигнута.

<a name="xdzip-inputs-and-sources"></a>

## Входные данные и источники

Начиная с Qt 6.8 предоставляются соответствующие сборке [инвентаризации SPDX](https://doc.qt.io/qt-6.8/licenses-used-in-qt.html). Инструменты читают только декларации времени выполнения, такие как qtbase, qtdeclarative, qtsvg и qttranslations, из sbom/ зафиксированного SDK Qt 6.8.2, исключая инструменты сборки и тестирования qttools. Проверяются версия SPDX, имя модуля и версия Qt; сохраняются SHA-256 исходного документа, пространство имен и стабильные ссылки на пакеты. В выводе остаются только необходимые поля, без копирования комментариев исходной сборки с путями на компьютерах разработчиков.

`scripts/qt-license-sources.json` фиксирует официальные коммиты исходников Qt и SPDX license-list-data, URL текстов лицензий и SHA-256. Загрузки кэшируются в build/; любое несовпадение хеша кэша или загрузки вызывает ошибку. Произвольные URL SPDX для загрузки материалов не используются. Помимо стандартных текстов LICENSES/ включаются исходные уведомления об алгоритмах плавного масштабирования Qt GUI и SVG, а также тексты LGPL-2.1, на которые ссылаются декларации системных зависимостей. Исходные тексты LicenseRef и авторские права сохраняются в JSON деклараций.

Уведомления среды выполнения Qt также включают зафиксированный редактируемый исходник Public Suffix List, используемый Qt Network, текст MPL-2.0 и инструкции по получению. Сборщик проверяет исходный blob, SHA-256 и байты лицензии. При предоставлении исходников отдельно проверяется, что эти данные воспроизводят две формы сгенерированных данных в архиве Qt; см. [соответствующие исходные материалы](../../engineering/source-delivery.md). Это не заменяет проверки исходников и замены других модулей Qt.

Уведомления Tika MIME в Qt Core сохраняют соответствующие указания Apache Software Foundation и PRONOM Национального архива Великобритании, тексты лицензий Apache-2.0 и OGL-UK-3.0 и полный зафиксированный исходный NOTICE. Полный NOTICE также описывает другие исходные компоненты Tika; это не означает их поставку с продуктом. Исходные данные MIME и проверка преобразования Qt описаны в [соответствующих исходных материалах](../../engineering/source-delivery.md).

<a name="xdzip-file-and-component-association"></a>

## Связь файлов и компонентов

1. Пересчитать хеши файлов внутри корня проверки и отклонить файлы, измененные после deployment-audit.json.
2. Режим macOS SDK использует фактически разрешенные относительные пути Qt SDK и идентичность байтов, не заявляя автономного развертывания.
3. Развертывание Linux записывает исходный путь SDK и SHA-256, а также путь артефакта и SHA-256 после patchelf. Последующие проверки сверяют записи в обоих направлениях и отклоняют устаревшие или измененные свидетельства копирования.
4. Windows предпочитает идентичность байтов файла SDK. Кандидаты с уникальным именем и отличающимися байтами помечаются только как filename-only-unverified-rewrite и регистрируются как пробелы, а не проверенные источники.
5. С помощью SPDX CONTAINS найти владельцев файлов, затем рекурсивно разрешить DEPENDS_ON, включая ссылки между репозиториями Qt и встроенные сторонние компоненты. Отсутствующие ссылки на пакеты остаются пробелами. Нельзя ошибочно включать все инструменты в среду выполнения через CONTAINS всего репозитория.
6. Не нативные QML и переводы без пофайловых деклараций связываются только с соответствующим исходным репозиторием; их отдельные лицензии не выводятся предположительно. Нативные библиотеки SDK без файловых записей SPDX, нативные файлы вне области Qt, лицензии NOASSERTION и отсутствующие тексты записываются отдельно.

Фактические байты файлов SDK могут отличаться от SHA-1 исходной сборочной декларации SPDX, например после обработки установки или подписания. Инструменты сохраняют ожидаемые значения, сравнения и пробелы, не предполагая причины. Связь байтов SDK, записи преобразования развертывания и исходные хеши upstream — три разных вида доказательств.

Специальная упаковка macOS создает связи развернутых файлов, пока существует окончательное подписанное приложение, сопоставляя входы SDK по точным байтам ресурсов либо по секциям arm64, UUID и версиям импорта, и добавляет отчет в SBOM фактических файлов. Сравнение исключает подписи, расположение команд загрузки и LINKEDIT. Область и специальные уведомления описаны в разделе [происхождение и уведомления нативной среды выполнения](native-runtime-materials.md). Обычный режим SDK тем самым не доказывает выводы о развертывании.

Для плагинов, перемещенных из каталогов QML в `Contents/PlugIns/quick/`, связь развертывания может использовать проверенные символические ссылки QML внутри пакета, чтобы найти единственный вход SDK. При создании и использовании записей повторно проверить фактические ссылки, проверенные цели и хеши файлов, затем выполнить такое же сравнение байтов или Mach-O. Отсутствующее происхождение остается непроверенным; несколько разных источников или измененные ссылки отклоняются. Совпадение только имени не усиливает атрибуцию и не устраняет различия хешей исходного SDK или пробелы проверки лицензий.

Rust сохраняет полный граф сборки узла и создает кандидатов среды выполнения, следуя обычным зависимостям от настольного `xdzip-qt-bridge`, обработчика форматов `xdzip-codec-bridge` и фактического `xdzip-update-helper` для Windows/Linux; в macOS отдельного корня помощника обновления нет. Инструменты сборки, разработки и proc-macro и их зависимости исключаются. Это потенциальные входы среды выполнения, а не доказательство сохранения машинного кода каждого пакета после связывания; удаление линкером, нативный C/C++ и библиотеки компилятора требуют дальнейшей проверки.

Простые старые альтернативы лицензий Cargo, разделенные косой чертой, становятся SPDX `OR` в исходном CycloneDX, а оригинал upstream сохраняется в `xdzip:cargo_license_raw`. Выражения с косой чертой и неоднозначным приоритетом отклоняются. Исходные инвентаризации сборки и уведомления не переписываются; стандартные `AND`, `OR` и `WITH` остаются без изменений. Это нормализация формата, а не выбор варианта лицензии или одобрение выпуска.

<a name="xdzip-execution-and-delivery"></a>

## Выполнение и поставка

Известная исправленная производная QtNetwork добавляет `network_security_variant` к записям файлов; отчеты также сохраняют полные повторно проверенные подтверждения сборки. Различия дайджестов исходного SDK остаются видимыми; проверка выпуска объясняет их зафиксированным исходным кодом, полными патчами, подтверждениями сборки и доказательствами преобразований при развертывании. Подготовка выпуска требует связать окончательную атрибуцию Network с этими байтами; совпадения имени недостаточно. Исходная и артефактная SBOM отдельно отмечают идентичность производной, не превращая общий незавершенный статус в одобрение лицензии.

```sh
python3 scripts/prepare-runtime-notices.py --qt-prefix /path/to/Qt/6.8.2/gcc_64 \
  --output build/review/notices/Qt-runtime
python3 scripts/runtime_attribution.py --audit build/review/deployment-audit.json \
  --root build/review/linux --qt-prefix /path/to/Qt/6.8.2/gcc_64 \
  --deployment build/review/linux-deployment.json --output build/review/runtime-attribution.json
python3 scripts/sbom.py --audit build/review/deployment-audit.json \
  --source build/review/source-build.cdx.json --attribution build/review/runtime-attribution.json \
  --output build/review/artifact-files.cdx.json
```

Linux передает записи преобразования развертывания; другие платформы опускают --deployment. Отчеты записываются вне корня проверки во избежание рекурсивной самоинвентаризации. Рабочие процессы Qt по запросу и Release подготавливают лицензионные материалы до развертывания и окончательного хеширования. Windows и Linux помещают уведомления в фактические среды выполнения; Linux tar.gz также их поставляет. Qt по запросу на macOS читает SDK и сохраняет только журналы и JSON. Явно разрешенный специальный процесс Release отдельно развертывает, подписывает ad hoc, упаковывает и проверяет фактические материалы согласно [протоколу выпуска](release-protocol.md), сохраняя отдельные область развертывания и хеши. Записи SDK не заменяют атрибуцию окончательного пакета приложения.

runtime-attribution.json содержит файлы, компоненты, отношения, исходные декларации, авторские права, источники текстов и пробелы. artifact-files.cdx.json добавляет те же компоненты и известные отношения владельцев, связывая отчет с теми же хешами фактического аудита и идентичностью сборки. Проверки официальной схемы CycloneDX и ссылок продолжаются; compositions остается незавершенным.

Проверки по умолчанию допускают явно зарегистрированные пробелы проверки разработки, но никогда не отмечают их молча как пройденные. Ошибки идентичности, пути, байтов, версии, записи копирования или хеша текста лицензии немедленно приводят к сбою. --require-complete блокирует выпуск и сейчас завершается ошибкой при незавершенной атрибуции или материалах выпуска. Тесты охватывают переписанные файлы, устаревшие записи копирования, выход за пределы пути, неверные версии, пропуски между документами, неполные SBOM и исключение инструментов Rust.

<a name="xdzip-unresolved-release-gates"></a>

## Нерешенные условия выпуска

[Сборщик предоставления исходников](../../engineering/source-delivery.md) сохраняет фактический исходный код проекта, Rust vendor, четыре архива модулей Qt среды выполнения, два архива модулей сборки и инструкции по пересборке и динамической замене. Он не доказывает поэлементную эквивалентность сборок SDK и upstream. Для каждого выпуска еще нужно проверить точную атрибуцию статической компоновки, системные и распространяемые среды выполнения, отдельные лицензии всех встроенных ресурсов, выбор вариантов открытых лицензий и выполнение обязательств. Изменение или замена метаданных при [локальной проверке развертывания Mac](../../engineering/macos-deployment.md) и [фактическая сборка Qt из исходников, загрузка и замена](../../../developers/engineering/candidate-verification.md#qt-source-and-compatible-replacement) — разные процессы с отдельными доказательствами; ни один не устанавливает побайтовую эквивалентность сборки произвольного SDK. Инвентаризации исходников и поля SPDX не заменяют лицензионные обязательства. Происхождение и лицензии исторического кандидата `v0.1.0` приведены в [#4](https://github.com/xiaodaozhi/xdzip/issues/4) и [#53](https://github.com/xiaodaozhi/xdzip/issues/53); последующие кандидаты требуют отдельной проверки, платная подпись не является условием. Существующая приемка рабочего стола остается в [#5](https://github.com/xiaodaozhi/xdzip/issues/5).

[Проверка соответствия Qt SDK](qt-sdk-correspondence.md) также фиксирует коммиты закрепленных архивов, пофайловые хеши в декларациях исходников SDK, установленную конфигурацию и известный потребительский патч AGL. Совпадения в заявленной области не доказывают полную эквивалентность сборки SDK; существующие препятствия для выпуска остаются.

Автоматизированное завершение добавляет фактические карты линкера и члены статических библиотек, хеши ресурсов среды выполнения, доверенные версии нативных зависимостей и точно обратимый анализ двоичных различий; см. [полный контракт](../../../developers/engineering/candidate-verification.md). Помечать преобразование объясненным только при точном совпадении хешей восстановленных байтов с декларациями upstream. Не удалять исходные различия SDK и не угадывать недокументированную историю издателя.
