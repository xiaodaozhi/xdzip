Статус: интерактивный черновик для проверки дизайна. Исходники находятся в [design/html](../../../design/html/README.md), точка входа — [index.html](../../../design/html/index.html). <a name="xdzip-interaction-decisions"></a>

## Решения по взаимодействию

<a name="xdzip-selection-and-search"></a>

### Выбор и поиск

- Каждый выбор соответствует стабильному ID записи, а не номеру отсортированной строки. Смена запроса или каталога очищает выбор, чтобы избежать недоразумений со скрытым выбором.
- Выбрать всё в текущем списке и извлечь весь архив — разные понятия. Отметка папки раскрывается в файлы-потомки с устранением дубликатов.
- Во время композиции IME запросы не отправляются; обновление происходит после compositionend. Проверки имитированных событий браузера не заменяют нативную приёмку IME на macOS/Windows/Linux.
- Enter или двойной щелчок по обычному файлу извлекает временную копию и открывает её через системную ассоциацию; для каталога выполняется вход в него. Пункт свойств сохраняется. HTML демонстрирует только ход и автоматическое скрытие; он не записывает файлы и не вызывает систему. Автоматический предпросмотр содержимого Qt описан в [контракте предпросмотра](../engineering/content-preview.md).

<a name="xdzip-extraction-and-conflicts"></a>

### Извлечение и конфликты

- Показывать конечный путь в реальном времени; одноимённый каталог добавлять только один раз. Пустые или явно недоступные для записи примерные пути блокируют запуск; после смены места назначения предварительная проверка повторяется.
- По умолчанию спрашивать при конфликте; доступны пропуск, автоматическое переименование и перезапись. Соседний текст объясняет последствия перезаписи.
- Начальный фокус панели конфликта находится на Пропустить; перезапись не является действием Enter по умолчанию. Применение к последующим конфликтам ограничено текущей задачей; примерные данные создают только один конфликт.
- Переименования отображаются в итоговой сводке и сведениях о файлах. Пропуски не являются ошибками; существующие файлы примера не считаются завершёнными записями.

<a name="xdzip-tasks-and-results"></a>

### Задачи и результаты

- Возврат к просмотру не отменяет задачу; её можно снова открыть из строки состояния.
- Запрос отмены → остановка с отключением повторной отмены → сводка отмены. Извлечение сохраняет опубликованные элементы; создание архива не публикует промежуточных результатов.
- При заполнении диска задача останавливается, успешные результаты сохраняются. Повтор выбирает только ошибочные или незавершённые элементы и возвращает к подтверждению плана.
- При изменении источника архив нужно открыть заново, а не незаметно использовать старый индекс.
- Задача создания учитывает один итоговый архив; отмена показывает ноль созданных архивов и явно сохраняет старый архив.

<a name="xdzip-archive-creation-and-capabilities"></a>

### Создание архивов и возможности

Прототип демонстрирует уровни ZIP, упаковку TAR и параметры сжатия GZIP. Он проверяет основные поля входа, имени и места назначения и меняет расширение вместе с форматом. Текущие варианты продукта используют [встроенный реестр форматов](../engineering/format-registry.md), включая профили создания [ISO](../engineering/iso-creation.md) и [Windows SFX](../engineering/sfx-creation.md). Допущенные параметры описаны в [работе с паролем](password-extraction.md) и [контракте томов](../engineering/archive-opening.md).

<a name="xdzip-visuals-and-adaptation"></a>

### Визуальное оформление и адаптация

Сохраняются тёпло-серая, кобальтово-синяя и графитовая темы. Высота обычной строки — 40, компактной — 32. Акцент текста в тёмной теме не зависит от заливки кнопок для читаемости мелкого текста. При узком настольном окне подробности становятся закрываемым наложением. Мобильная проверка сворачивает боковую панель и вторичные столбцы таблицы; панели операций адаптируются к узким экранам и прокручиваются.

Интерфейсы операций являются отдельными окнами согласно [спецификации окон платформы](platform-windows.md). HTML имитирует их через dialog: окна решений ограничивают фокус, ход, результаты и настройки немодальны, при закрытии выполняется попытка вернуть фокус. Закрытие окна конфликта отменяет задачу, а не молча пропускает её; закрытие хода только скрывает подробности. Qt использует настоящие отдельные окна верхнего уровня.

<a name="xdzip-theme-selection"></a>

### Выбор темы

На странице настроек три нативных радиопереключателя, системная, светлая и тёмная темы, организованы через `fieldset#setting-theme` с легендой «Appearance theme». Каждая карточка использует общий ресурс `theme-system`, `theme-light` или `theme-dark` и связывает текстовую метку с элементом ввода. Настоящие переключатели участвуют в щелчках по карточке, переключении клавиатурой и фокусе. Выбор использует общую отметку переключателя и синхронизирует границу карточки и предпросмотр, не заменяя управление неинтерактивным снимком.

Это описание проверки дизайна HTML. Текущие настройки находятся в памяти; системная тема определяется только при выборе. Изменения системной темы во время работы, сохранение между запусками, немедленная запись и обработка ошибок в продуктовых настройках Qt требуют отдельной проверки.

<a name="xdzip-verification-and-remaining-boundaries"></a>

## Проверка и оставшиеся границы

Скрипт проверки браузера — scripts/check-html-design.py. Он проверяет реальные щелчки, статистику, отключённые состояния, связь форматов, восстановление, мобильное переполнение и автономную работу в одном файле. Отчёты сопровождают экспортированный пакет прототипа; браузерные проверки используют только Chromium.

Текущая поставка главного окна включает два независимых сеанса примерных архивов, список/сетку, сортировку по полю, рекурсивное дерево каталогов, иерархический путь, контекстные/выпадающие/подменю и состояния кнопок. См. [контракт компонентов и взаимодействия](main-window-components.md) и [метод проверки](../../../developers/qa/README.md). `scripts/check-html-controls.py` проверяет их реальным вводом в браузере; [страница проверки компонентов](../../../design/html/components.html) использует ту же реализацию, что основной интерфейс.

HTML проверяет только примерные состояния и не доказывает реальное планирование задач, авторизацию, гонки путей, CRC или доступность платформы. Qt объединяет реальное создание/извлечение, перетаскивание, системные диалоги выбора, сохраняемые настройки и независимые сеансы архивов в необязательных вкладках или нескольких окнах. Фактические границы нескольких форматов, индексирования миллиона записей обычного однофайлового ZIP и ограниченного предпросмотра описаны соответственно в [обработчиках форматов](../engineering/native-codecs.md), [большом индексировании](../engineering/large-index.md) и [предпросмотре содержимого](../engineering/content-preview.md); приёмка записывается в соответствующих issues. Настройки HTML сохраняют демонстрационное состояние только внутри страницы, не между запусками, и не доказывают нативное следование системной теме или приёмку доступности.

Эти ограничения не меняют целевые возможности программного дизайна. «Завершено» в прототипе означает только состояние демонстрационной задачи и не доказывает поставку реального сжатия или извлечения.

<a name="xdzip-current-directory-queries-and-card-revisions"></a>

## Запросы текущего каталога и изменения карточек

Корневая запись называется «Root» и показывает только непосредственные файлы и папки. Поиск находит потомков в текущей области и показывает полные пути внутри архива. Обычные списки и сетки показывают только конечное имя; копирование и навигация сохраняют полные пути. Справа от цепочки пути отображается число строк текущего списка. Заголовок дерева каталогов — «Archive», выровнен по вертикали с цепочкой; при наведении на дерево плавающая подсказка не появляется.

Подсветка наведения списка охватывает всю строку. У сеток примерно 16 логических пикселей горизонтального внутреннего отступа; флажок размером 8 пикселей слева сверху появляется при наведении и остаётся видимым при выборе. Меню кнопок находятся в 4 единицах от кнопки и имеют мягкую тень. Кнопка повторного открытия предпросмотра фиксирована квадратом со стороной 28. Параметры находятся в layout-scale.json, directory-tree.json и controls.json; фактическая проверка следует [общему методу](../../../developers/qa/README.md).

<a name="xdzip-settings-window"></a>

## Окно настроек

Настройки сохраняют исходные заголовки со значками, карточки предпросмотра тем, плотность, недавнюю историю и пояснение приватности, добавляя размер текста и язык интерфейса. Предпросмотр темы и шрифта можно отменить; Сохранить и Восстановить умолчания используют черновики. HTML хранит демонстрационное состояние только на текущей странице. В демонстрации HTML выбор языка показывает настройку, действующую со следующего запуска Qt; ни страница проверки дизайна, ни содержимое примерного архива не доказывают охват переводов продукта. Текущее переключение языка Qt, включённые ресурсы и сохранение описаны в [настройках и локализации](settings-localization.md).
