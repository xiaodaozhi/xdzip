# Licencias de herramientas de desarrollo y entornos de ejecución de Windows

Esta página define las vías aplicables de compilación y redistribución en Windows y se utiliza junto con los [materiales nativos](native-runtime-materials.md), la [entrada de compilación para desarrolladores](../../engineering/developer-build.md) y el [contrato de instalación](../../engineering/installers-associations.md). Los entornos concretos, commits de verificación, hashes de materiales y conclusiones de aceptación se registran en incidencias y artefactos locales o CI; esta página no conserva prueba de licencia de una máquina.

<a name="xdzip-free-community-path-and-local-choice"></a>

## Vía gratuita Community y elección local

El contenido original del proyecto se publica bajo Apache-2.0, licencia de código abierto aprobada por OSI. Los términos individuales de Visual Studio Community 2022 permiten a las personas desarrollar sus propias aplicaciones; los términos para organizaciones también permiten a sus usuarios desarrollar y probar aplicaciones publicadas bajo licencias aprobadas por OSI. Evaluar por separado el uso de código abierto de una organización y sus otros usos comerciales internos; no extender la elegibilidad de este proyecto a otros.

Cuando un mantenedor necesite su propio entorno Community, obtener Community 2022 del [instalador oficial de Microsoft](https://learn.microsoft.com/en-us/visualstudio/install/use-command-line-parameters-to-install-visual-studio?view=vs-2022), leer y aceptar [los términos originales de esa versión](https://visualstudio.microsoft.com/license-terms/vs2022-ga-community/) y usarlo dentro de su alcance. Para compilaciones C++ seleccionar `Microsoft.VisualStudio.Component.VC.Tools.x86.x64` y el SDK de Windows; no es necesario instalar todas las cargas de trabajo. No se requiere comprar Professional/Enterprise ni solicitar un certificado independiente de distribución del runtime por proyecto.

La revisión de licencias no exige mantener un IDE grande instalado localmente. Si solo se compila y publica en el entorno estándar alojado por GitHub descrito abajo, la base aplicable es la autorización de Visual Studio alojado y sus términos REDIST; no hace falta instalar Community local ni comprar Enterprise personal para CI alojada. Community es una opción gratuita para quien necesite su propio entorno, no una condición adicional de instalación local para la legitimidad de la compilación alojada.

La sección 3 de Community permite archivos de software y Build Tools en dispositivos de compilación elegibles; la sección 4 concede derechos de distribución del código distribuible listado, sujetos a requisitos de funcionalidad, términos posteriores y restricciones. Descargar VC_redist, instalar Build Tools o incluir solo un texto de licencia no demuestra elegibilidad para usar herramientas de desarrollo. Sin licencia de Visual Studio, la excepción de Build Tools cubre compilar y construir componentes C++ de código abierto de terceros aprobados por OSI que sean razonablemente necesarios para construir las propias aplicaciones. No permite desarrollar o probar esas dependencias salvo modificaciones menores necesarias para compilarlas y construirlas, y no es una excepción general para desarrollar todos los programas C++ propios. Usar VS Code no proporciona automáticamente licencia MSVC. Consulta la [orientación de licencias de Microsoft](https://www.microsoft.com/licensing/guidance/Visual-Studio) y los [términos de Build Tools](https://visualstudio.microsoft.com/license-terms/vs2022-ga-diagnosticbuildtools/).

Verificar localmente producto, versión completa, estado no preliminar y componentes C++ indicados por `vswhere`, entrar en el entorno de desarrollo de la instancia real y comprobar `cl`, `link` y el SDK. Build Tools 2019 instalados no son Community 2022 y no sustituyen la verificación de la cadena MSVC 2022 actual. `desktop.py prepare` genérico no instala silenciosamente un IDE o SDK del sistema; para la primera instalación usar el instalador de Microsoft, conservar herramientas existentes e impedir el reinicio automático.

Elegir 2022 es la decisión actual de herramientas para entrega, no una afirmación de que Community gratuita solo permita 2022. La [tabla de soporte de Qt 6.8](https://doc.qt.io/qt-6.8/supported-platforms.html) enumera Windows MSVC 2022; este repositorio usa el SDK `msvc2022_64` correspondiente. Las herramientas 2019 pueden conservarse para desarrollo local, pero la compatibilidad ABI entre versiones no demuestra por sí sola soporte completo al mezclarlas con el SDK actual. Las [reglas de compatibilidad de Microsoft](https://learn.microsoft.com/en-us/cpp/porting/binary-compat-2015-2017?view=msvc-170) también requieren generalmente que el enlazador final no sea anterior a las herramientas de las bibliotecas de entrada y restringen por separado bibliotecas de ejecución y `/GL`/`/LTCG`. Las configuraciones alternativas necesitan su propia licencia y verificación; esto no obliga a instalar localmente el IDE 2022 completo.

<a name="xdzip-github-hosted-builds"></a>

## Compilaciones alojadas por GitHub

El flujo de Windows del proyecto usa ejecutores estándar alojados por GitHub `windows-2022`. El producto preinstalado es Visual Studio Enterprise 2022, no Community. Los mantenedores de runner-images han [confirmado](https://github.com/actions/runner-images/issues/12945#issuecomment-3348002951) que Enterprise preinstalado está disponible para ejecutores alojados públicos y privados de GitHub Actions/Azure DevOps mediante un acuerdo entre GitHub y Microsoft, sin licencia Enterprise personal adicional. El proyecto se apoya en ese entorno; la explicación pública no reemplaza ni pretende revelar el acuerdo completo.

Según la [documentación de ejecutores alojados de GitHub](https://docs.github.com/en/actions/concepts/runners/github-hosted-runners), cada trabajo Windows recibe una máquina virtual independiente y `Set up job` indica la imagen y el inventario de software de esa ejecución. Los flujos solo compilan, prueban, despliegan y publican este repositorio dentro del alcance de los [términos adicionales de Actions](https://docs.github.com/en/site-policy/github-terms/github-terms-for-additional-products-and-features#actions). La cuota gratuita de cómputo de repositorios públicos y los derechos de redistribución de componentes Microsoft son distintos.

CI registra el producto y versión VS reales, ubicación relativa del compilador, versiones de herramientas y SDK en `windows-toolchain.json`, conservado con paquetes y materiales del mismo commit sin claves de producto ni rutas privadas de desarrolladores. Identifica herramientas, pero no demuestra automáticamente elegibilidad de licencia. Ejecutores autoalojados, herramientas copiadas localmente desde imágenes, otros servicios CI y servidores compartidos generales no heredan la licencia alojada; volver a comprobar términos Community/Build Tools y condiciones de dispositivos.

<a name="xdzip-microsoft-component-redistribution"></a>

## Redistribución de componentes Microsoft

La [lista REDIST de VS 2022](https://learn.microsoft.com/en-us/visualstudio/releases/2022/redistribution) incluye explícitamente Community 2022 con licencia válida. La compilación actual usa VC_redist x64 de versión final fijado en [windows-runtime.json](../../../scripts/windows-runtime.json), lo extrae sin modificar y comprueba individualmente ocho DLL CRT y la licencia original del runtime. No incluye compiladores, depuradores ni `debug_nonredist`. Ni la vía gratuita Community ni la identidad Enterprise de CI alojada vuelven a licenciar las DLL de Microsoft bajo Apache-2.0.

Los nuevos paquetes de desarrollo no incluyen `d3dcompiler_47.dll`, `dxcompiler.dll` ni `dxil.dll` del SDK de Windows, ni una biblioteca OpenGL por software Mesa. En paquetes históricos estos tres archivos procedían de `Redist/D3D/x64` de un SDK explícito. La [lista REDIST del SDK](https://learn.microsoft.com/en-us/legal/windows-sdk/redist) permite distribuirlos sin modificar con aplicaciones Classic Windows bajo una licencia SDK válida y prohíbe distribuirlos con aplicaciones UWP; xdzip es una aplicación de escritorio Classic Windows. Las licencias, avisos y condiciones históricas del SDK siguen siendo aplicables por separado aunque futuros paquetes eliminen estos archivos.

El archivo incluido `share/notices/Windows-runtime-NOTICE.txt` explica en ambos idiomas los límites de licencia de cada componente. Los términos originales de Microsoft CRT están en `Microsoft-VC-runtime/license.rtf`. El instalador muestra el acuerdo CRT original y exige aceptarlo, y después muestra avisos de componentes. Los usuarios portables también deben leer y cumplir los términos Microsoft incluidos. Ambos paquetes conservan licencias originales y procedencia. Los redistribuidores posteriores deben cumplir por sí mismos condiciones de elegibilidad y distribución; Apache-2.0 del proyecto no autoriza por sí sola reenviar componentes Microsoft.

Mostrar o incluir el texto SDK no demuestra por sí solo que distribuidores externos y usuarios finales aceptaran los términos de protección exigidos por el SDK ni sustituye la evaluación de licencia válida y responsabilidad del publicador. La página actual de aceptación del instalador se aplica solo a CRT. Si se vuelven a redistribuir DLL gráficas del SDK, evaluar por separado los términos y aceptación para paquetes instalador y portable y conservar evidencia real en el registro de entrega; consulta el histórico [#135](https://github.com/xiaodaozhi/xdzip/issues/135).

Antes de compilar el instalador, comprobar el hash fijado del acuerdo CRT y el aviso bilingüe; los materiales incluyen el mismo texto CRT original y registro de procedencia. Los términos SDK históricos están en `Windows-SDK-graphics/sdk_license.rtf`. Las correcciones de licencia no reescriben antiguos activos públicos ni identidad histórica de compilación; emitir paquetes corregidos con nueva versión según el [protocolo de entrega inmutable](release-protocol.md).
