# Verificación de correspondencia entre el SDK de Qt y el código fuente

[English](../../engineering/qt-sdk-correspondence.md) | [简体中文](../../zh-CN/engineering/qt-sdk-correspondence.md) | [繁體中文（台灣）](../../zh-TW/engineering/qt-sdk-correspondence.md) | [日本語](../../ja-JP/engineering/qt-sdk-correspondence.md) | [한국어](../../ko-KR/engineering/qt-sdk-correspondence.md) | [Français](../../fr-FR/engineering/qt-sdk-correspondence.md) | [Deutsch](../../de-DE/engineering/qt-sdk-correspondence.md) | Español | [Português (Brasil)](../../pt-BR/engineering/qt-sdk-correspondence.md) | [Русский](../../ru-RU/engineering/qt-sdk-correspondence.md)

La verificación de correspondencia utiliza los bytes reales de los archivos oficiales; coincidir en el número de versión no demuestra equivalencia de compilación del SDK. `scripts/qt_sdk_correspondence.py` relaciona los archivos fuente fijados, los SPDX de fuentes proporcionados por el SDK, las declaraciones de compilación, la configuración instalada y los parches conocidos aplicados por quienes utilizan el SDK, y escribe el resultado en build/. No modifica el SDK ni aprueba opciones de licencia.

```sh
python3 scripts/qt_sdk_correspondence.py \
  --qt-prefix build/toolchain/Qt/6.8.2/macos \
  --output build/review/qt-sdk-correspondence.json
```

Por defecto se lee build/source-cache sin conexión y se falla si falta. Solo --fetch indicado expresamente descarga y verifica los archivos oficiales del [manifiesto fijado](../../../scripts/corresponding-sources.json). Los flujos Qt bajo demanda para las tres plataformas ejecutan --fetch después de instalar el SDK fijado y conservan el JSON con los demás registros de verificación. En Mac solo se suben registros, sin desplegar, firmar ni empaquetar aplicaciones. Cuando el recolector de entrega de fuentes recibe --qt-prefix, incluye este registro, los parches y el manifiesto fijado en los hashes de la entrega; véase [entrega de fuentes](source-delivery.md).

<a name="xdzip-verification-layers"></a>

## Capas de verificación

1. El SHA-256 del archivo debe coincidir con el valor fijado; también deben coincidir la raíz del archivo, las rutas de sus miembros y el marcador `.tag` fijado. Registra por separado el tipo de objeto Git del marcador. Si es un árbol, recalcula primero el hash del objeto commit original fijado y verifica su campo tree. Lee los archivos individualmente sin extraer el código del proyecto original.
2. Si el SDK proporciona el .source.spdx de un módulo, compara cada SHA-1 declarado con el contenido del archivo. Registra el número de coincidencias, ambos hashes de las diferencias, los archivos declarados por el SDK que faltan en el archivo y el número de archivos no cubiertos. SHA-1 solo comprueba la declaración original del proyecto; el archivo completo está ligado por separado al SHA-256 fijado. Las declaraciones ausentes, diferencias y archivos no cubiertos no se registran como aprobados.
3. Conserva los hashes SPDX de compilación de módulos del SDK, las declaraciones del compilador y los argumentos de configure. Lee también los modules/*.json, qconfig*.pri y las cabeceras de configuración QT_FEATURE instaladas y conserva su contenido y hashes. Sustituye en la salida los directorios absolutos del entorno de compilación original por marcadores; los hashes de archivo vinculan la evidencia original. La configuración no es la caché CMake completa, el entorno de compilación ni todos los materiales de la cadena de herramientas. Los campos de arquitectura predeterminada del SDK no representan todas las arquitecturas de las bibliotecas reales y no deben clasificar erróneamente las bibliotecas universales como x86_64.
4. El [parche AGL](../../../scripts/qt-patches/macos-no-agl.patch) solo modifica lib/cmake/Qt6/FindWrapOpenGL.cmake del SDK para evitar enlazar con AGL antiguo cuando este proyecto utiliza Qt. La herramienta lee el original del archivo QtBase fijado, aplica el diff unificado, verifica los SHA-256 del parche, original y resultado y comprueba el archivo real del SDK. Solo acepta el original o la versión parcheada conocida. Para CRLF del SDK de Windows, compara solo tras normalizar los finales de línea y conserva el SHA-256 de bytes reales, el SHA-256 LF y un marcador de conversión. Otros cambios desconocidos fallan. Esto no modifica código máquina de ejecución de Qt ni demuestra que Qt se haya recompilado. Todavía debe verificarse el historial completo de modificaciones del SDK.

Los registros de correspondencia usan el esquema 2 y conservan por separado archive_commit fijado, archive_marker real del archivo, archive_marker_type y commit_tree_verified. El `.tag` de Qt Declarative 6.8.2 es el árbol Git `0a8139c574fe150aba92d5f2484a8f3fdb774977`; la etiqueta de publicación corresponde al commit `75534f3e7fff24ed7ccb364e2ed9950a73da879f`. Un objeto commit original en base64 fijado en el repositorio permite recalcular sin conexión el hash del commit y validar su campo tree. Los demás marcadores de módulos fijados actualmente son commits. La relación del árbol solo establece la relación entre esos dos objetos Git; no demuestra que el archivo contenga todo el árbol ni que el SDK tenga una compilación equivalente.

Los source_commits de qt-license-sources.json identifican únicamente commits fijados para obtener textos de licencia y se guardan por separado de los marcadores de archivo y commits de publicación. No pueden presentarse como commits de compilación del SDK. Los materiales históricos del esquema 1 colocaban el marcador de árbol de Qt Declarative en archive_commit; los activos publicados permanecen sin cambios. Las explicaciones posteriores deben corregir el tipo de objeto y seguir verificando los textos de licencia con el SHA-256 original.

<a name="xdzip-interpreting-results-and-release-boundaries"></a>

## Interpretación de resultados y límites de publicación

El derivado de seguridad de QtNetwork registra `network_security` por separado, con comprobantes que vinculan parches, herramienta de compilación, hashes del QtCore original y del QtNetwork real, características y verificación real del transporte. Al leer los comprobantes, la herramienta vuelve a verificar los bytes reales del SDK. Esta evidencia solo se aplica a la biblioteca modificada; no reescribe el SPDX original como prueba del derivado ni cambia los hechos no cubiertos de otros módulos. Consulta las [notas de parches de Qt](../../../patches/qt/README.md) para las entradas y el mantenimiento.

La disponibilidad de SPDX de fuentes por módulo, los recuentos de coincidencias, ausencias y elementos no cubiertos, la configuración y el estado de parches se determinan por el JSON generado en la ejecución actual. No generalices las observaciones de un SDK a otro. Sin declaraciones por archivo, no infieras que la correspondencia haya pasado; conserva las lagunas concretas.

El estado del informe es siempre evidence-collected-not-build-equivalence. La [compilación real de las fuentes de Qt y su carga o sustitución](../../../developers/engineering/candidate-verification.md#qt-source-and-compatible-replacement) tiene un procedimiento separado, pero no demuestra la reproducción byte a byte del SDK original. Hasta aclarar por completo los materiales de la cadena de herramientas y del SDK del sistema, los archivos no cubiertos o generados, la procedencia en ejecución y el cumplimiento de licencias, no afirmes que se hayan cumplido todas las obligaciones de fuentes correspondientes ni que las compilaciones sean reproducibles byte a byte. Siguen vigentes el estado incompleto de la [atribución en ejecución](runtime-attribution.md), las opciones de licencia y las revisiones de ejecución por plataforma.
