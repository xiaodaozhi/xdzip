# File-list opening, bidirectional drag-and-drop, and archive modification

Context-menu “Open” acts on the right-clicked entry without changing multiple selection, reusing the double-click and Enter entry point. Directories are entered; regular files use the private cache, password, and associated-application rules for [temporary opening](archive-opening.md). Session or query changes close the menu; execution still verifies stable entry identity.

## External drag-out

Once list or grid dragging reaches the system threshold, freeze the selection and archive directory. Dragging an unselected item first selects only that item; dragging a selected item preserves the selection. Expand directory descendants, deduplicate parent/child selections, retain relative hierarchy below the current directory and empty directories, and do not delete archive content. Links are not published through drag-out. The manifest is limited to 100,000 entries and a 4 MiB name/structure budget and remains subject to safe-extraction byte, path, password, and quota constraints.

Creating a drag-out manifest prepares transfer metadata; it is not directory reading. During preparation and native handoff, retain the committed list/grid, selection, and directory without showing the main page's “Reading” overlay. Requests retain busy and cancellation semantics. Actual opening, directory queries, and archive modification continue to use their own waiting feedback.

Windows supplies content through OLE `IDataObject` FILEDESCRIPTOR/FILECONTENTS and asynchronous capability. Background preparation starts after the destination accepts; consumers can read only after the private copy is fully verified. Synchronous consumers cannot make the GUI wait for the task; unsupported targets fail explicitly. Explorer chooses final location and name conflicts. FILEDESCRIPTORW paths must be shorter than 260 UTF-16 units. Content streams are read-only; after cancellation, stop supplying subsequent data. Exit waits for the native transfer until asynchronous consumers finish.

macOS provides Finder with top-level file or directory promises through NSFilePromiseProvider. Once a private copy is ready, Finder's local file URL is authorized through a separate Rust PublishExport task. Files are staged individually, source-verified, and published without overwriting existing regular files. POSIX regular files retain the safe-extraction `0600 | (mode & 0155)` permission policy, preserving executable bits while stripping privilege and external write bits. Directory merges and partial completion follow safe-extraction output boundaries; no overall transfer rollback is promised. File-promise callbacks wait in the background; file writes always enter the bounded task queue and shutdown barrier.

The supported Linux baseline is Ubuntu 24.04 x86_64 with X11. Prepare a private copy first. Once ready, start file-URL drag-and-drop if the mouse remains pressed; if released early, ask the user to drag again and reuse the copy. The file manager determines final copying and name conflicts. The application does not infer the final destination or successful saving. Wayland is outside this support commitment.

Export and temporary-open caches are separate. Use random directories, identity markers, and active locks; preparation failure publishes no URL. Retain items for seven days and perform bounded later cleanup. Do not delete files when dragging returns if consumers may still need them. Closing a page retains the task's controller. Explicit exit cancels preparation and waits for Rust workers and native consumers to finish.

Export and copy tasks do not automatically open Explorer, Finder, or the destination directory after drag-out. Ordinary extraction's “open folder when finished” choice belongs only to that explicit extraction request and must not be inherited by later export or temporary-open requests. A user explicitly selecting Open in the result window retains the existing behavior.

## External drop and confirmation

CAB, ISO, UDF, and RAR are read-only. External addition and internal moves are rejected both in the UI and at Rust execution entry points. Drag-out, temporary opening, and ordinary extraction reuse existing safe-read paths. A filename extension or disabled UI state does not replace core capability checks.

The file-list body of an open archive accepts real local files and directories, copy only. Dropped archive files are added as ordinary inputs; dropping on the welcome page still opens them. Reject remote URLs, virtual attachments, links, and special objects. Freeze session, current directory, and inputs on drop; search pages require entering a directory first.

Before addition, Rust applies [creation input filtering](m4-creation.md#macos-元数据输入过滤), excluding `.DS_Store` files and `__MACOSX`/`_MACOSX` directories at every level. If no valid entries remain, the result window shows an explicit failure and original archive bytes remain unchanged. Do not delete host originals or existing metadata in the archive.

UpdateWindow follows the creation design with an icon title and three cards for files to add, destination, and options. The file area shares ArchiveInputPanel with CreateWindow. Users can continue selecting files/directories, deduplicate, and remove items by mouse, keyboard, or accessibility. Regular-file sizes reuse background summaries of at most 256 items; directory totals are unknown. Summaries are previews and do not replace task input freezing. Window drafts are independent; hidden windows do not take over metadata requests. The target archive and internal directory are read-only and come from the session and directory frozen at drop; confirmation revalidates stable identity. Ask, Skip, Rename, and Replace policies are offered; Ask is the default. Same-name directories merge using the original spelling; file/directory conflicts are rejected. Replace applies to regular files inside the archive and grants no authority to overwrite host input files. The archive is unchanged before confirmation. Visuals use the creation window's 491 logical-unit width, three cards, and shared controls; see the [independent design](../../design/hifi/sources/archive-add.html).

After an add or internal move is accepted, the main page's cancellation action sends task cancellation using the original session's actual task identity, including when a name-conflict prompt has closed but the task is still waiting for a decision. It cannot merely cancel an already finished task-registration request. After cancellation, continue waiting for the task terminal state, cleanup, and reopening of the original archive before restoring directory queries and selection; do not unfreeze old entry identities early.

During modification, keep the committed file page visible, but old query and selection identities cannot be operated on. The page waiting overlay retains the add or move name according to the actual command until refresh ends. Once runtime accepts cancellation, mark it immediately; conflict and password prompts lose decision eligibility, and the progress window displays cancellation while following the actual terminal state. A conflict window binds to task and prompt tokens. A prompt dismissed by the user is not automatically reopened by another task update, but may be explicitly reopened through the task entry. Task changes, prompt-token replacement, terminal state, and exit close the old prompt; buttons must not submit an old decision to a new task.

## Internal drag-and-drop move

Once dragging in the file list or grid reaches the system threshold, first treat it as an internal move, freezing the current session, query generation, selection version, source archive directory, and stable entry IDs. Dragging an unselected item first selects only that item; dragging a selected item preserves multiple selection. Source items remain drawn in place. Destination folders use the existing selection color in list, grid, and directory tree. Operation guidance reuses tooltip font size, maximum width, and padding, with at most four lines bounded by the current client area. This is immediate drag state, not the ordinary hover-tooltip timer.

Folders in the current directory and any indexed directory in the left tree can receive drops, including moves from a subdirectory to the root. Accept only this session's private drag identity; do not interpret external URLs or entries from another session as moves. The list, grid, and left tree use the same destination restrictions. The destination cannot be any selected folder, a descendant at any depth, or the source directory. Reject the entire mixed selection, not just the target folder. Search pages, stale selections, and currently unmodifiable archives are also rejected. Rejected targets retain immediate explanations and a no-drop state; releasing does not start a task. Encryption, split volumes, and their combination have distinct explanations. External-addition rejection is also shown on hover and the actual drop remains rejected.

Releasing over a valid destination immediately starts an independent move task, reusing progress, name-conflict, and result windows. Regular-file conflicts default to Ask and support Skip, Use New Name, and Replace, with apply-to-later-conflicts. Folders merge; file/folder type conflicts fail. Skipped source files remain in their original locations and necessary explicit source directories are retained. Fully moved source entries disappear; empty and implicit directories can be moved. When moving the current implicit source directory empty, add an empty-directory record to preserve the browsing location. After success or failure, reopen the original archive, retain source directory and sort order, and clear selection of old physical IDs. During edit admission, execution, and reopen, retain a list snapshot and freeze directory queries; old identities cannot initiate browsing.

MoveOptions carries only bounded source directory, target directory, and selection identity, not host paths. The core re-resolves immediate source entries and rejects cycles, the original location, and stale identities. Moves and additions share namespace, conflict decisions, complete content verification, and same-volume atomic replacement. ZIP copies compressed payloads unchanged and rewrites names. TAR retains regular record headers and supported PAX attributes other than path, writes paths as UTF-8 PAX, and converts GNU long names to PAX; TAR.GZ rebuilds the outer GZIP. Extensions that cannot be safely retained fail explicitly. Pre-commit failure or cancellation preserves original archive bytes.

When the pointer leaves the source window's client area or the source window becomes inactive, transfer the frozen selection to the existing platform external-copy flow and end internal dragging. Once promoted to system drag-out, do not treat exported data returned to the application as an internal move or new input. This prevents private staged content from being added again; platform drag-out rules remain unchanged.

The bridge adds a Move command, reusing the bounded heavy-task queue, task exit barrier, and stable-session validation. Page `edit_restriction` bit 0 means encrypted, bit 1 split, and bit 2 other unsupported records. `update_allowed` holds only when all bits are zero. Reasons come from the entire read-only source snapshot, not the current page. Rejection messages describe capability and do not grant write authority.

## Regular archive modification transaction

Update supports regular single-file ZIP, TAR, TAR.GZ, and 7z. It does not rewrite encryption, split volumes, links, special records, or names that cannot be safely preserved. Capability is determined from the entire source snapshot, not just the current page. Once the task is accepted, release the metadata session; old entry IDs accept no new actions. The task retains the source handle and identity.

Names use frozen results from the [encoding contract](filename-encoding.md). Resolved legacy names are explicitly written as UTF-8 during rewrite, and the archive namespace plus Unicode/case collisions are checked again. After freezing source version and the no-follow InputTree, create a complete new archive in a private workspace on the original archive's volume. An independent ZIP record layer copies original compressed payloads and preserves admitted metadata; new entries use Deflate 6. The independent Rust 7z backend rebuilds the archive and adds content using normal-level LZMA2. TAR retains original record groups; TAR.GZ re-encodes the outer GZIP stream. Retained ZIP, TAR, and supported 7z records are processed in original physical order, with new entries appended. See the [in-house specification](independent-rust-codecs.md#7z读写规格) for 7z preservation and rebuild boundaries. The new archive must still verify expected entry types, sizes, and complete payloads without omissions, duplicates, or mixed-in records. Duplicate or ambiguous records, ZIP self-extracting prefixes, and unrewritable extensions fail explicitly rather than being silently dropped. TAR global PAX records are not currently rewritten.

The archive namespace includes implicit parent directories, limited to 100,000 nodes; names and the normalized index share a 16 MiB budget to prevent deeply nested paths from creating an unbounded index. Rescan the new archive and decode each file into a bounded verification sink, then revalidate input, original archive, and destination identities. Only an ArchiveUpdate capability bound to the original file version can replace it as a whole; ordinary creation/extraction source protection remains unchanged. Explicitly reject using the original archive as an added input. If required atomic filesystem primitives are unavailable, fail without first deleting or truncating, or simulating replacement by copy/delete. Version checks are best effort and do not promise content CAS against malicious same-account concurrent writes or power-loss durability.

Pre-commit cancellation or failure preserves original archive bytes. Once a commit permit is obtained, successful publication wins; cleanup failure is recorded separately. After success or failure reopen the same source and clear invalid physical-entry selection. Tasks use distinct update, move, export, and export-copy kinds; private preparation is not treated as successful system copying.

7z modification follows the same namespace, conflict, source-revalidation, and atomic-replacement contract; solid content requires decode and rebuild. Rebuild input uses explicitly bounded buffers. Total original and added content cannot exceed the native adapter's 512 MiB cache limit and is also subject to the backend's 1 GiB process-memory budget. Exceeding limits returns a resource error explicitly; the limit does not grant disk-cache authority and the original archive remains unchanged. Successful output may use normal compression and a non-solid layout and does not promise to preserve original compressed streams, algorithm combinations, solid blocks, or physical record order. Archives with encrypted names, encrypted content, or any split 7z volumes reject modification, including an empty encrypted directory.

RAR uses an independent read-only Rust backend and offers no addition, replacement, or internal move. The archive-wide other-unsupported-record `edit_restriction` bit is always set; a current page without unsupported entries cannot bypass it. 7z/RAR links and special objects are not written out. External copying and temporary opening still use existing preflight and safe-output tasks.

## Acceptance boundaries

List and grid full-name tooltips are suppressed throughout internal moves, native-copy preparation, and actual native dragging; cancel the old stationary timer. Internal/external handoff must not briefly re-enable the source tooltip. Windows uses OLE return, macOS the native drag-end callback, and Qt prepared drag the exec return to end gesture state. Asynchronous copying may continue; copying-task completion is not the end of the mouse gesture. Afterward, first obtain a fresh pointer position and then wait a full stationary 1,200 ms again, preventing cached source hover from reviving a tooltip.

Drag previews represent only frozen source names, icons, and selected count. They do not read or extract content or grant destination-write authority. Internal previews obtain values from a valid drag token; after leaving the window, clear the internal overlay and hand off to native copy feedback. Windows IDataObject retains bounded, thread-safe private HGLOBAL formats for Shell images and separately holds a COM reference to the unique DragContext stream without reading or copying its contents; GetData returns independent references. File descriptors, content streams, and preferred actions must not be overwritten. Failure does not alter existing safe-output and cancellation semantics. Native images use non-premultiplied BGRA for the Shell; bitmap ownership transfers at initialization. On COM/GDI preparation failure, retain the system cursor. See the [drag specification](../../specs/visual/drag-preview.json) for styling.

Core coverage includes three formats, current directory, original content and empty directories, conflict policies, source changes, protected inputs, and cancellation. Qt covers real context Open and add confirmation, both languages, light/dark themes, multiple font sizes, and frozen sessions. Windows native protocol tests verify asynchronous data objects and actual content streams. Move regressions cover list/grid, directory tree, rejected targets, mixed selections, directory merges, metadata preservation, and boundary handoff; three formats are independently rechecked by Python readers. Real Explorer, Finder, Ubuntu Files, and desktop drops are checked as needed and recorded separately when executed. Offscreen and protocol receivers do not stand in for unperformed desktop actions. Stage evidence is recorded in the relevant issues and local/CI artifacts.
