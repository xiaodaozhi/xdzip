# RAR independent implementation basis and compatibility boundaries

In-house RAR migration retains complete read-only scope for legacy, RAR5, RAR7, passwords, header encryption, solid archives, and authorized volumes; no RAR encoder is developed. Capability replacement and removal of official dependencies remain subject to [migration task #51](https://github.com/xiaodaozhi/xdzip/issues/51). Container code or Store reading alone does not establish full migration. See the [isolated backend contract](native-codecs.md) for current routing and sources.

## Container candidate contract

`xdzip-codec-rar` depends on project codec API/domain, shared compression/crypto, and admitted general AES, SHA2 compression primitives, and zeroization. CRC32 reuses the shared implementation; no third-party RAR, archive, or compression-format library is introduced. It implements `MetadataCodec`/`PayloadCodec` and runs through shared CXX bridging in the existing isolated worker with no official failure fallback. Wiring alone does not replace full compatibility acceptance; product route switching follows the [migration contract](independent-rust-codecs.md#实现边界).

- The host supplies ordered authorized streams and lengths of each physical volume, at most 1,024. Check volume-local ranges before converting to absolute positions; archive names grant no path access. Reidentify each volume header and check format generation, volume number, header-encryption state, and continuation relationships. Merge only explicit split-before/after; ordinary duplicate names retain distinct identities. Regular-file and service continuation chains are retained separately; services consume no regular EntryId.
- Ordinary 1.5..4 header checks use the low 16 bits of ordinary CRC32; modern headers store full CRC32. Earlier 1.4 containers have no header CRC and their separate content checksum cannot be mixed with it. Verify ordinary plaintext-header checks before interpreting bounded fields/extras. Modern vint is at most 10 bytes with only valid 0/1 bits in the last byte; non-shortest representations with correct mathematical values are allowed. head-size itself is at most three bytes and total plaintext header at most 2 MiB. Skip unknown skippable extras by their bounds; unknown required decoding features cannot masquerade as successful ordinary content.
- The private index retains each fragment's original header, volume/header/packed ranges, known/unknown sizes, raw name, decode version, compression strength, declared/effective algorithm, dictionary, solid state, times, type, CRC/hash, and password description. Public method retains UnpVer, such as 50 or 70; public packed_size is the first visible fragment's packed size, not the sum. Allocate EntryId consecutively from 1 in first-visible ordinary-record order.
- Resolve declared legacy Unicode using mathematical commands first; otherwise use shared archive-level legacy detection. Preserve the raw name area; convert legacy separators only after character decoding to avoid splitting multibyte `0x5c`. Unicode surrogates must pair completely; reject truncated commands, embedded NUL, and out-of-range copies. RAR5 strictly validates declared UTF-8. Unix name mapping and redirection retain warnings; links/special objects cannot be ordinary output.
- Metadata reads are at most 64 MiB; physical headers at most 100,000; names at most 4,096 bytes each; raw-name total and decoded/display totals each at most 16 MiB. Lower caller limits win. Payload rescans keep accumulating the original input allowance; actual input and decoding work are each at most 20 GiB and files at most 8 GiB. Algorithm workspaces are admitted before execution under the default 1 GiB memory ceiling.
- Algorithm injection receives only bounded plaintext packed streams, borrowed controls, and the host sink. The container handles fragment packed checks, decryption, full input consumption, exact file size, and final complete content verification. Algorithms own state, compressed-stream termination, and their memory preflight. The candidate executes Store, 13/15, 20/26, RAR29 LZ/PPM, and modern LZ, outputting blocks of at most 8 KiB without accumulating whole files. Directories complete only after zero size/packed, original-header revalidation, and required empty-content checks. Reject name warnings, links, and special records first; they cannot bypass public entry admission.
- Preserve identified domain I/O error categories first. Only bare Interrupted without a wrapped error can retry. Cancellation, quota, source change, I/O, output failure, or validation failure poisons the instance; failure is not EOF, entry_done, or publication eligibility. The host retains source identity, path checks, private staging, and final commit. Public DecodeError currently has no distinct SourceChanged variant and maps it to SourceIo; the source host retains the specific cause.

## Modern LZ candidate specification

- Effective algorithm 0 uses 64 distance symbols and algorithm 1 uses 80. A declared version-1 compatibility bit still selects effective algorithm 0; do not choose trees by tool version or extension. Independent MSB bit reading and canonical Huffman trees consume declared valid bits, not Deflate's LSB order. New tables target 430/446 code lengths respectively. Unused trees may be empty; consuming absent codes, oversubscription, or out-of-range runs fails explicitly.
- Block-header verification, valid bits in the last byte, and last-block flag jointly determine bitstream termination. Known output size, final content CRC, and complete packed consumption are checked independently; producing declared size is not early success. Empty blocks do not underflow unsigned arithmetic; content cannot decode without valid tables. The candidate uses strict policies for out-of-range runs, unfinished filter ranges, and trailing packed bytes. Healthy samples do not prove equivalence to all historical recovery behavior.
- Non-solid compressed files reset valid dictionary history, recent distances, last length, and tables; solid compressed files retain them while resetting input blocks, filters, and file offsets per file. Use the effective window determined by the first compressed file, minimum working window 256 KiB; non-power-of-two windows wrap by their actual modulus. Later smaller/non-power-of-two declarations do not change the modulus. Midstream growth returns Unsupported rather than reproducing malformed-chain exceptions dependent on old allocation caches. Release the old window before non-solid replacement to avoid two large windows coexisting.
- Store copies and verifies files whether or not its solid bit is set; it neither adds to LZ history nor clears tables, recent distances, or last length. Directories and services are not new compression initialization points. Randomly selecting a solid file restores from the preceding non-solid compressed file and actually decodes prefixes in physical order. Store is not a restart point; skips and repeated replay count as actual work.
- Delta, x86 E8, x86 E8/E9, and ARM filters process complete separate logical ranges. Prefilter bytes always form LZ history; transformed copies go to file CRC and sink. Ranges may cross blocks/physical volumes but not files; start and file offsets must not be confused with ring indexes. A range is at most 4 MiB and at most 8,192 items may be pending. Reject overlaps, reverse order, unknown transforms, and incomplete ranges. These are candidate resource policies, not claimed format extremes.
- Instruction batches plan at most 8 KiB output or 256 instructions. Before execution reserve remaining work locally only; do not report unperformed progress to the public sink. After execution, including bytes completed before partial failure or cancellation, settle only actual WORK and convert it to one-time prepaid allowance. Unperformed reservations cannot fund output and are not reused after failure. Continue accumulating actual work while staging complete filter ranges. Deduct private container credit before prepaid delivery; final size, CRC, cancellation, and write failures still apply. Default sinks may conservatively charge again. Store uses ordinary output accounting. The worker delivers credited RAR content through PRECHARGED_DATA; Native receiver and runtime independently check host credit, exact sizes, and quotas. Old worker credit cannot be reused after restart, completion, or failure.
- Reserve 288 MiB outside the LZ dictionary for bounded metadata, filter copies, queues, and other state, jointly admitted against the 1 GiB worker ceiling. This is a conservative memory policy, not the maximum wire-format dictionary; a declared size does not grant allocation. Cancellation or error poisons the entire payload state; do not continue another entry with a retained partial dictionary.

### Exact storage for large logical dictionaries

Modern effective-algorithm-1 compressed files whose complete dictionaries exceed dense-storage admission use exact Constant/Raw paged history with at most a 1 TiB logical window. Pages are 64 KiB and hold either a constant byte or an exclusively owned raw buffer. Reads, writes, and distances use the original logical window's true modulus. Unproduced history is unreadable; overlapping matches execute byte by byte. History stores prefilter content and does not alias final output buffers. Other algorithms, Store, unknown methods, and service records receive no large-dictionary exception.

The page directory, slot table, free pool, all retained capacity, temporary peaks, private state, and 16 MiB allocator allowance total at most 512 MiB. The outer 288 MiB and password state are separate; the 1 GiB worker ceiling remains. Check budgets before every allocation; do not reserve huge address space by logical window size or switch to disk history. Fully initialize a Raw page before writing a different value to a constant page. Fold only when the entire valid page length is sequentially overwritten with identical new bytes. Partial-page solid continuation retains original tails and candidate state; non-solid replacement releases old storage first. Buffers returned to pools remain charged by actual capacity.

Actual initialization of directories, slot tables, and Raw pages uses the separate auxiliary-work channel, checking cancellation and settling in blocks of at most 8 KiB. It does not add file progress or delivery credit. Complete fallible storage preparation before accepting output bytes, then commit history without allocation. Output rejection changes neither history bytes nor cursor; completed initialization is not refunded and errors poison the payload. This efficiently handles constant pages but does not guarantee arbitrary low-entropy streams or large dictionaries fit; oversized Raw working sets explicitly return Limit.

Real algorithm-1 interoperability checks obtain only pinned compressed test data and notices under build/CI, checking original header identity and complete plaintext SHA-256, CRC, size, WORK, AUX, and retained capacity without saving large plaintext or third-party implementations. Mathematical page tests and independent healthy compressed streams are recorded separately. One successful stream does not establish acceptance of all extended distances or encrypted, solid, and cross-volume combinations.

Independent known modern x86 plaintext can be checked using the [controlled PE data recipe](../../crates/xdzip-codec-rar/tests/fixtures/modern-x86-owned/README.md). A stream normally generated by the official author must actually select E8 or E8/E9 and pass complete content checks through direct LZ, Payload, and the real worker. PE name, tool version, or descriptor count alone is insufficient. Test inputs are not executed; PE files or generated archives are not stored in the repository. Other solid, encrypted, and cross-volume combinations remain separately accepted.

## RAR29 PPM candidate specification

- `xdzip-compression` shares ordered statistical contexts, binary probabilities, SEE, exclusions, successor materialization, and a nominal-capacity ledger. RAR29 and 7z use the same model through different range adapters rather than duplicating statistics. RAR uses a four-byte carryless initial value, independent normalization, and binary intervals discarding division remainders in both branches. 7z retains its five-byte initial value, remainder, and termination rules.
- A mode header starts at a complete aligned F byte. The reset bit determines whether the entire model is rebuilt; the memory field represents nominal capacity 1..256 MiB, and order maps header fields to encodable 2..64. Optional escape changes only when declared; reset does not restore it automatically. A retention request requires an already valid model with established continuity. Each mode initialization rebuilds the four-byte range; headerless cross-file continuation is not a substitute. An independent random starting point without a previous model fails explicitly.
- Nominal 12-byte units and deterministic class, fragmentation, merging, and borrowing rules control format-specified model restarts. Rust objects, history, indexes, traversal scratch, fixed state, and other decode state receive separate admission based on actual storage. Reset releases the old arena first to avoid two large allocations. Capacity restart retains the already decoded current symbol and range. Actual OOM, quota, cancellation, source I/O, or model-invariant errors are terminal failures and cannot masquerade as capacity restarts.
- New-arena initialization and capacity restarts first admit auxiliary-work budgets. Actual fills/clears run in storage chunks of at most 64 KiB and bounded probability-table rows, checking cancellation and accumulating completed initialization bytes. Subsequent range-read failure, cancellation, and `clear` do not refund completed work. The outer layer settles actual differences on success and failure against a cumulative 20 GiB limit together with control/parameter-symbol auxiliary work. Separate AUX grants no prepaid file-delivery credit; future reservations are not actual progress.
- PPM delivers one model byte after completed statistical update and normalization. Escape, filter parameters, and match parameters all update the model normally. File bytes generated by RLE or LZ copies are not fed back into PPM. Outer layers verify file termination, mode switching, output size, content CRC, and declared packed boundaries. RAR does not accept escaping the root as 7z END or impose 7z's final code-zero condition. Failed models stay poisoned until explicitly cleared by outer recovery.
- After actual PPM EOF, drain remaining input only within the complete declared packed range while continuing input-quota, cancellation, and fragment checks. PPM arithmetic tails do not use modern CBC's 0..15-byte alignment limit. Missing actual EOF or mismatched size/CRC cannot succeed through tail policy. A following solid file rereads its mode header and a new range; the reset bit independently determines model retention. The pinned reference outputs a literal escape for controls 1 and 6..255 after escape. If the candidate strictly rejects 6..255, record that acceptance difference separately; do not claim the reference also rejects it.

## RAR29 LZ and standard-filter candidate specification

- RAR29 independently reads MSB bitstreams; 404 differential code lengths form 299/60/17/28-symbol trees. Prior code-length baselines, low four-bit distance repetition, four recent distances, and last match length remain in compressed state. Do not apply modern 64/80-distance tables to this legacy algorithm. File terminators also govern whether the next solid file rereads mode. Uninitialized reuse, empty-tree consumption, out-of-range runs/output, and distances before history fail.
- Outer PPM escape controls file termination, mode switches, literal escape, filters, and two copy kinds. Parameter bytes still decode through the model; match output enters LZ history and final file streams only, not statistical-model feedback. Packed remainder draining after PPM EOF and pure-LZ bitstream termination are separate policies.
- Standard filter programs first check bounded packets, program length, XOR, and fixed CRC/length identity. Admit only six established product-baseline transforms: E8, E8/E9, Itanium, Delta, RGB, and Audio. The candidate executes no arbitrary archive VM. Definitions, cached lengths, and last selection retain solid state; offsets are recalculated per file, and unfinished ranges cannot be discarded by reset.
- Unfiltered bytes remain LZ history. Standard transforms with identical start and length may chain; reject other overlaps, reverse ordering, and unfinished ranges. A range is 1..262,143 bytes; at most 8,192 definitions and pending items. These are candidate resource policies. Delta has at most 1,024 channels, Audio 128; admit their wire parameters and initialization buffers first.
- Legacy E8 PC uses full 32-bit file position, not modern modulo 16 MiB. Itanium transforms original bundle/template and instruction fields; RGB and Audio have separate predictor states. Audio includes adaptation at the first sample and negative coefficients down to -17; modern Delta or E8 mathematical vectors are not substitutes.
- Every actual transformed byte, PPM parameter, and actual model initialization consumes auxiliary-work budget. Settle auxiliary work through separate `charge_auxiliary` nonzero messages of at most 64 KiB. It cannot increase decoded_bytes, expansion-ratio numerator, or delivery credit, and solid-prefix skipping still forwards it. Worker, Native receiver, and runtime each enforce the [auxiliary work contract](auxiliary-decoding-work.md). Earlier candidates routing auxiliary counts through WORK do not satisfy it. Processing loops check cancellation by chunk; auxiliary work completed before failure is not refunded.

## Ancient container and historical-password candidate specification

- The 1.4 main header is at least seven bytes including `RE~^`; file headers have 21 fixed bytes followed by a bounded name and skippable extra material. Payload starts at declared headSize end. Main 0x01/0x08 indicate volume/global solid; original 0x80 is not the later header-encryption bit. Files use only 0x01/0x02/0x04 for split-before/after/encryption. Directories derive from DOS attributes; later file-window or solid bits are not reused. Dictionary is fixed at 64 KiB.
- Ancient method values use 0..5 directly. Selector 2 maps to public UnpVer13; others map to 10. Compressed admission is only for baselined 13/15; 10 supports Store only. Global solid continues from the second logical file; physical continuation fragments inherit the same logical file state. New files reset bit reading and content checksums; Store does not inject into compression history.
- Each ancient logical file starts 16-bit c=0 and computes `c=ROTL16((c+x) mod65536,1)` for each actual final output byte x, directly comparing the final header's u16 without final XOR. Preserve intermediate-fragment u16 values without treating them as packed CRC. Complete content checksum spans fragments; a solid predecessor's checksum does not carry to the next file. Later containers using same-generation algorithms still use ordinary CRC32.
- Ancient encryption always uses the old13 byte-password family without salt/IV; selector10 does not change this. Later 13/15 use their respective byte families, 20/26 use the old block family, and RAR3 uses original SHA1 derivation composition and AES128-CBC. Each logical file has a fresh cipher; physical split fragments are continuous, and password state does not cross files with compression solid state. old13/15 accept no block-alignment tail; old block-cipher Store truncates to actual size. RAR29 PPM's declared-tail policy applies separately.
- RAR3 encrypted headers reread an 8-byte salt per header, decrypt the first block to obtain actual header length, then validate the complete aligned span in that volume and ordinary header CRC. Preserve original salt/ciphertext for payload revalidation. The outer layer first checks 4,096 UTF-8 bytes. The old path additionally retains the native callback's complete-input limit of 511 local wide units, including input after the first NUL; only then take content before first NUL and apply the crypt 127-unit boundary. This is historical host-entry behavior, not a format password-length specification; modern KDF entry policy is separate.
- Windows applies OEM-to-ANSI wide projection to the complete zero-padded 512 UTF-16 units only for non-ancient containers with HostDOS legacy files, then truncates at wide index 127. Legacy 13/15/20 next encode to ANSI in a 512-byte buffer and truncate at raw byte 127, which may split DBCS. RAR3 directly uses the low 16 bits of projected wide units. Ancient content receives no later DOS compensation. Conversions use synchronous borrowed host services. OS failure is explicitly Unsupported; typed source errors and cancellation keep their categories. Without services, use only provably equivalent ASCII paths.
- macOS legacy narrow passwords first take 127 Unicode scalars, explicitly encode UTF-8, then truncate at raw byte 127, possibly leaving an incomplete trailing sequence. Ordinary Linux uses the current thread locale's stateful conversion, retaining the actual prefix after EILSEQ retry; this project's independent worker does not change process locale for it. Linux's U+FFFE-marked recovery path removes the marker in Rust, recovers U+E080..E0FF original bytes, and sends ordinary units to host conversion. Do not apply it to Apple or unmarked strings. Non-Windows RAR3 wide projection retains the original scalar prefix and uses low 16 bits of units; low 16 bits equal to zero are not mistaken for original NUL. Intermediate wide, narrow, single-character, and key buffers are zeroized; fixed projection scratch has a separate 4 KiB budget.
- Without a trusted independent verifier, header Invalid or content Integrity returns PasswordOrIntegrity for safe host retry. SourceChanged/SourceIo, Limit, Cancelled, Output, and Unsupported are not wrapped as password ambiguity. A verified modern check mismatch remains WrongPassword, while corruption under a verified key remains integrity error. Physical original-header changes on revalidation are source errors, not password errors inferred from ciphertext changes.

## 13/15 family candidate specification

- 13 and 15 retain their respective public UnpVer while entering one independent adaptive decoder. The window is fixed at 64 KiB; finite canonical code tables, literal ranking, distance ranking, flag models, Short variants, and special modes are represented separately without reusing later differential code-length tables or copying another Deflate/PPM implementation.
- The first non-solid compressed file resets history and statistics; later solid compressed files retain dictionary, rankings, and match state. Each file still reinitializes bit cursor and flags/repeats/special states; prior leftover control bits or special modes cannot cross files. Store does not call compressed initialization or fill/clear compressed history.
- Before actual output, check declared remaining size and valid historical distance; matches cannot cross file end. After reaching actual unpacked size, consume the complete host-authorized remaining packed input with normal input quotas and cancellation, without inventing a modern final-block flag absent in this generation. Fail without enough real bits; do not pad with zero bytes.
- Reserve local budget for bounded matches and output batches of at most 8 KiB. Settle executed bytes on success and failure paths; only originally produced bytes create one-time delivery credit. Errors poison the compressed instance; only explicit reset can use new independent state. A solid starting point without predecessor state cannot assume recovery.

## Modern password and integrity candidate specification

- Plaintext archive crypt may appear once before this volume's main header. Each later header restarts AES256-CBC with its own IV, decrypts the first block for actual header length, then checks the complete IV and aligned ciphertext span in that volume. Header CRC covers actual fields only; alignment tails are not parsed as extras. Private physical fragments retain original IV and ciphertext headers for bytewise payload-rescan verification; equivalent decrypted metadata cannot replace source identity.
- The same PBKDF2-HMAC-SHA256 chain produces AES key, hash key, and folded check at `2^L`, then 16 more, then 16 more iterations, with `L<=24`. A task-private 16-slot cache and cumulative budget continue from metadata scanning into payload objects and do not reset per file or volume. Defaults are at most `2^26` actual HMACs and 4 GiB derived-hash input. Cache hits do not rederive; work performed before cancellation is not refunded. A conservative 16 KiB cache/scratch budget is separately included in algorithm-memory preflight.
- Outer passwords are at most 4,096 UTF-8 bytes; check that limit before truncating at the first U+0000. The native compatibility profile takes the first 127 UTF-16 units on Windows or Unicode scalars on Unix, then generates derived bytes. A lone surrogate at the Windows truncation boundary exists only in private compatibility bytes, not public str or names. This is reference compatibility behavior, not a format-universal rule. Passwords, derived intermediates, and keys use zeroizing lifetimes without promising erasure of all OS historical copies.
- Return WrongPassword on mismatch only when the check's own SHA256 checksum is valid and it is not an untrusted all-zero legacy-service value. A bad checksum disables fast checking; a correct key can still succeed through structural/content verification. Invalid/Integrity without a trusted verifier remains ambiguous through public PasswordOrIntegrity and cannot be called a reliable wrong password.
- Content CBC restarts per file and continues across authorized split fragments; blocks may combine the end of one fragment and beginning of the next. Each fragment's packed CRC/BLAKE2sp always covers physical ciphertext before decryption; final content checks cover complete filtered plaintext. The current candidate strictly requires identical complete crypt parameters across a fragment chain; healthy samples do not prove every historical split encoding equivalent.
- Store selects actual content by unpacked size; LZ terminates by a complete last block and valid bits. Only minimum 0..15-byte alignment tails follow, with unrestricted values and no PKCS7 interpretation. LZ read-ahead buffers count toward tail length; outer CBC consumption alone is insufficient. The complete declared ciphertext must still be consumed and counted as input. Reference recovery accepting additional whole garbage blocks is outside candidate success.
- Reuse shared streaming BLAKE2sp32 state. When a known BLAKE2sp extra exists, choose its full-width check and retain the basic CRC field without requiring both, matching the pinned reference's selection semantics. If flag2 declares a keyed tweak, HMAC ordinary CRC's LE4 and XOR eight LE32 values; ordinary BLAKE2sp32 uses full HMAC32. Without flag2 no tweak applies even when encrypted. Unknown hashes remain Unsupported; CRC/checks do not establish source authenticity.
