# ISO9660 and Joliet creation

The first writer creates a single non-bootable data image with 2048-byte sectors, an ISO9660 primary namespace and a Joliet supplementary namespace. It follows [ECMA-119, fifth edition](https://ecma-international.org/wp-content/uploads/ECMA-119_5th_edition_december_2024.pdf), including the Joliet specification reproduced in Annex C. No external image authoring engine is linked or launched.

Only ordinary files and explicit directories are admitted. The Joliet namespace preserves names exactly, using big-endian UCS-2, at most 64 characters per component. The full encoded Joliet path, including file-version bytes and the parent-directory count, is limited to 240 bytes. Supplementary-plane characters, `*`, `?`, `;`, unsafe relative paths, duplicate paths, missing parents and file/directory collisions are rejected before writing. Primary identifiers are deterministic unique ASCII aliases, not replacement names in the Joliet view. The initial profile limits directory hierarchy to eight levels including root, directory count to 65535 including root, file size to less than 4 GiB, total image size to 20 GiB and planned metadata to 64 MiB. Timestamps use UTC and are bounded to the representable on-disc range.

The writer plans both directory trees and little/big-endian path tables before streaming file contents. Directory records never cross sectors, every sector is zero-padded and both numerical representations agree. Frozen input indices grant stream access, never filesystem paths. Cancellation, short/growing input, output errors and exhausted budgets stop encoding; only the host can publish the staging file.

Creation reopens the complete image, matches records by decoded Joliet name rather than enumeration order, and compares decoded file bytes to the frozen source before final publication. Structural checks of arbitrary ISO images remain distinct from this source comparison: ISO does not supply ordinary-file checksums. Independent readers must verify both primary aliases and exact Joliet names and file bytes.

UDF, Rock Ridge writing, El Torito/boot images, compression, passwords, volume sets and modification of an existing image are not provided. CLI and desktop use the same creation registry and task path.
