# Isolated format worker contract

7z, RAR, CAB, and ISO/UDF use [independent Rust backends](independent-rust-codecs.md) through a shared thin CXX boundary in the same isolated worker. ZIP, TAR, and TAR.GZ use in-process Rust backends. The product does not search user PATH for alternatives or invoke external command-line extractors.

CAB always uses the independent Rust route in the product, without test switches, official handlers, or failure fallback. See the [in-house contract](independent-rust-codecs.md#cab只读规格) for complete frames, shared algorithms, and resource boundaries, and [CAB sources](cab-format-sources.md) for provenance and reference-analysis roles.

## Build and sources

The unified preparation entry point runs `scripts/prepare-native-codecs.py`. The [product source manifest](../../scripts/native-codec-sources.json) is currently empty; preparation does not download or extract official format sources, and offline builds need no UnRAR or 7-Zip archives. General source tooling retains bounded extraction and digest verification for explicitly declared source materials; cached contents cannot automatically enter the product.

The product does not compile or link official UnRAR/7-Zip containers, algorithms, common utilities, file adapters, or format registries. 7z, RAR, CAB, ISO, and UDF use Rust without runtime-failure fallback. Internal CMake `XDZIP_7Z_BACKEND=rust`, `XDZIP_RAR_BACKEND=rust`, and `XDZIP_CAB_BACKEND=rust` record fixed identity. Generated `native-codec-source-list.txt` completely records seven project-owned glue files. Gates check paths and sets, rejecting reintroduction of official sources or retired `host_file.cpp`. `platform_time.cpp` and `platform_encoding.cpp` return only OS local calendars and character-set mappings to Rust; they do not interpret archive time formats or password-byte rules. Shared Deflate/Deflate64, LZMA, BZip2, PPMd, LZX, and Quantum are reused according to actual formats without duplicate format libraries.

Corresponding source materials accompany actual deployed versions; download links alone are insufficient. Historical builds and independent official reference tools continue under their own original terms. An empty current product-source manifest does not alter obligations for existing deliveries.

## Authority and lifecycle

The Rust core holds source authorization, split-volume identity, destination authorization, staging, and commit capabilities. Rust 7z/RAR/CAB/optical backends run in a separate worker, reading authorized streams and outputting currently approved entry data through a bounded protocol without user destination paths or arbitrary file-access interfaces. Strings and slices borrowed synchronously through CXX are valid only during the call; pointers are not retained. C++ exceptions and Rust unwinds become stable errors. OOM/abort fails the worker, and the host discards incomplete staging.

Host initial source seeks, worker random reads, creation input, and EOF probes consistently retain typed quota, cancellation, unsupported, and source-change errors. Even if the outer I/O kind is Interrupted, its typed cause is not erased. Only Interrupted without a typed cause may be retried after checking cancellation; prepaid source work is not refunded. Scan retains SourceChanged; content reading uses existing source-error semantics; creation rejects commit on source errors.

The worker receives no command-line password, outputs no arbitrary archive-provided diagnostics, and inherits no application credentials or proxy environment. Errors map to stable codes. Passwords for opening encrypted directories remain only in zeroizing containers for the current session and related tasks and are not persisted across launches. Session close and task terminal states release their respective containers. Cancellation stops reading and output; on timeout terminate and reap the worker. Worker failure cannot produce success. Process isolation is not an OS sandbox and does not claim to prevent a compromised process from accessing all same-user resources.

Worker UTF-8/wide-character conversion strictly validates Unicode scalars. Windows uses UTF-16 surrogate pairs; macOS and Linux use 32-bit wide characters. Invalid UTF-8, isolated surrogates, and out-of-range scalars throw `std::range_error`, mapped at the worker boundary to protocol error 2 without a successful terminal state. Conversion preserves embedded NUL; host name/path safety checks remain responsible for rejecting unsafe names.

7z creation writes bounded offsets and blocks to host-private staging through EncodeOutput::write_at. The native process retains only stream position and does not accumulate the entire output archive in memory. The host separately meters actual bytes written and archive-length high-water mark; header rewrites do not increase split-volume content length. Host-side checks revalidate offsets, block sizes, cumulative output, and cancellation. Outputs without random-write capability are explicitly rejected.

Tasks retain host entry, path, metadata, and actual-byte budgets; the default native budget is 1 GiB. Windows uses a Job Object commit-memory limit, Linux an absolute virtual-address-space limit, and macOS startup virtual-address baseline plus budget excluding dyld reservations. Unix address-space limits are not RSS accounting. Dictionaries and solid workspaces are admitted before allocation; operations that cannot fit fail explicitly without silent unbounded disk staging. Retries and solid skips accumulate actual work.

RAR modern effective algorithm 1 may represent large logical dictionaries using [bounded exact paged history](rar-format-sources.md#大逻辑字典的精确存储); a logical declaration is not an allocation grant. Directory, retained pages, and temporary peaks have independent limits; original worker budgets and dynamic failure behavior remain.

Actual algorithm initialization/control auxiliary work uses separate `AUX_WORK=24`, currently only for RAR payloads. Host and runtime independently accumulate auxiliary budgets without counting them as file decoding, expansion ratio, public progress, or prepaid credit. See [auxiliary algorithm work accounting](auxiliary-decoding-work.md) for protocol, retry lifecycle, and required acceptance.

## Capability boundaries

7z browsing, extraction, integrity testing, and creation are declared separately. Creation uses LZMA2, normal level, non-solid, unencrypted, and non-split by default. Solid, content encryption, filename encryption, and numbered volumes are verified as independent capabilities. Filename encryption requires a password. Encrypted filenames prompt during metadata opening; an incomplete scan cannot publish a partial index.

Unencrypted, non-split 7z archives whose entries can all be safely retained may reuse addition, replacement, and internal move. Solid contents use bounded rebuilding. Encryption, split volumes, links, and unsupported special records remain rejected for modification. Source rechecks and full verification precede same-volume atomic replacement. Independent delete and rename entry points are outside this extension.

RAR always uses `xdzip-codec-rar`, read-only with no official fallback. Legacy, RAR5, RAR 7 extensions, passwords, header encryption, solid archives, and volumes are separately verified; algorithm/compatibility limits follow the [in-house specification](independent-rust-codecs.md#rar只读规格). No creation, modification, repair, or password recovery is provided. RAR initialization/control work uses the auxiliary channel; actual decode output uses WORK and prepaid delivery, without counting model initialization as file size or expansion ratio.

CAB supports Store, MSZip, Quantum, and LZX; single and same-directory split volumes are read-only. Rust validates and freezes authorized volume sets from header relationships before sending original volume names and boundaries to workers. Missing or mismatched volumes cannot publish a partial index; see the [split-volume contract](archive-opening.md). Preserve CAB raw names and UTF-8 declarations; legacy names use [shared filename resolution](filename-encoding.md), not host-code-page guesses for output paths.

`xdzip-codec-optical` parses ISO9660, Joliet, Rock Ridge, and UDF without linking official Iso/Udf handlers. Hybrid images prefer the UDF namespace; recognized UDF corruption does not silently fall back to ISO. Detect content rather than relying on extensions for authorization. ISO/UDF support browsing, extraction, temporary opening, export, and testing only; no disk mounting, boot-image execution, creation, or update. Boot-image records are readable files only; links and special objects remain non-outputtable. Image checks verify structure, ranges, and actual readability without claiming ordinary-file checksums. See the [in-house specification](independent-rust-codecs.md#iso与udf只读规格) for partition maps and explicit unsupported-extension boundaries.

## Verification and delivery

Actual support claims require official-tool interoperability, known output bytes, corruption, and resource-limit samples. Magic detection, successful calls, or self-reading/self-writing with one backend alone do not independently establish interoperability. Three-platform core/Qt checks, deployment verification, native visual checks, and desktop drag-and-drop are recorded separately; stage evidence stays in issues and local/CI artifacts.

CTest `native_unicode_conversion` directly compiles the worker conversion implementation and covers UTF-8 length boundaries, non-BMP, embedded NUL, invalid sequences, and platform wide-character boundaries. `native_unicode_protocol` sends invalid creation names to the actual worker and checks error responses and failed exit. Run on Windows, macOS, and Linux; one platform cannot replace verification of both wide-character widths.

RAR route acceptance covers scanning, testing, and safe extraction through the actual worker, including small files, PPM initialization, passwords, and authorized volumes. Small files and PPM initialization must not alone trigger high-expansion-ratio rejection, and auxiliary work must not increase public byte counts. Failure must publish no files. Source gates jointly check the empty product manifest, fixed Rust identities, complete compiled source list, and thin RAR entry; symbols or successful output alone do not prove official code exited.

Foundation uses `scripts/check-rar-rust-interop.py --worker <built-worker> --output build/<evidence>` to run the original complete explicit `native_backend_tests` batch. The entry point first prepares pinned URL, size, and SHA-256 public small PPM, large PPM, and legacy-password samples under `scripts/rar-rust-fixtures.json`, then creates a single-member subset containing only the original compressed stream, project-owned mathematical unknown-size and known-empty headers, and the environment required for project-owned 20/26 fixtures. Each network response is at most 512 KiB. Prepared files and evidence stay under build; no 2 GiB plaintext is generated and author tools are not executed. Missing or mismatched inputs must fail; skipped tests cannot substitute for environment preparation. The wrapper must also actually run hostile auxiliary-work workers, unknown-size protocol checks, Native small-file accounting, solid rereads, the complete project-owned E8E9 byte digest, and real OS character-mapping probes. Probes use only CXX headers and the strictly unique Release static library in the fixed Rust output directory beside the current worker, recording header, static-library, and probe digests. Missing or ambiguous inputs fail. A separate component check verifies the large version-26 full SHA; the runtime batch checks complete large-file counts, CRC, and zero staging once through the actual worker. Explicit `--large-digest` adds a complete worker SHA check.

Interoperability uses pinned official 26.05 reference tools separate from the product worker. On Windows, download 7zr.exe from the same official release and verify its digest, then extract only x64/7za.exe from verified 7z2605-extra.7z and reverify that member's independent SHA-256. This does not depend on system tar LZMA support, run installers, or borrow unpinned PATH tools. Linux and macOS read only the specified 7zz member from verified tar.xz. Any download/cache/extracted digest mismatch stops the flow. These references remain in build/ test directories and do not enter product deployment.

Development packages remain experimental. Component licenses, corresponding source, and relinking requirements are separately reviewed for actual builds; completing this feature does not automatically approve official release.
