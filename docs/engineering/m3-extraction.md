# M3 safe ZIP extraction implementation

This contract defines host-safe output, actual extraction, conflicts, cancellation, and commit behavior. Actual execution results and current defects are recorded in relevant issues and Actions artifacts rather than accumulated here.

Format plugins receive only borrowed input, immutable entry snapshots, and host `DecodedSink`. ZIP metadata scanning and payload decoding are separate. Store, Deflate, and ZIP64 local headers, central directories, data descriptors, declared sizes, actual sizes, CRC, and Deflate StreamEnd must agree. AES-256 authentication and CRC differences follow the [password extraction contract](password-extraction.md). Other encryption, other compression methods, names unresolved under the [encoding contract](filename-encoding.md), and links/special objects not admitted by the dedicated policy below remain unsupported. Split sources are presented as unified logical input by the [split-volume read layer](archive-opening.md). Raw ZIP64 local data descriptors can coexist with an ordinary central directory; validate width using local and central size sentinels. Remaining compressed bytes after stream end and streams with correct output but no final block both fail.

All output first passes the shared portable-name parser, rejecting traversal, absolute paths, reserved device names, illegal characters, and ambiguous components. Task preparation freezes selection: full root extraction includes every physical record; selected directories expand all descendants; selected files remove the current-directory prefix. The browser's root list still shows only direct files and folders. Common Unicode NFD/lowercase-equivalent names map to the first spelling; regular-file aliases enter conflict resolution. File/directory conflicts and ambiguous parents are rejected before destination objects are created. This comparison is not a complete simulation of all filesystem naming rules; native exclusive creation makes the final determination.

The default archive-named wrapper folder is derived by the host from the archive name, with the same name used for UI preview and actual output. After removing the archive extension, remove a trailing `.app` case-insensitively so macOS Finder does not mistake an ordinary outer folder for an application bundle. For example, `demo.app.zip` extracts to `demo/`; the internal `demo.app` name and contents remain unchanged. If removal leaves an empty name, use `archive`. The derived directory still passes portable-name checks and destination authorization. This also applies to supported compound extensions and split archives and does not change output paths when the same-name folder option is unchecked.

The user-selected destination becomes an `xdzip-io::Grant` capability holding a directory handle. Open child directories component by component without following links and retain/recheck parent-chain identities. POSIX targets must belong to the current effective user and not grant group or other-user write permission. Windows checks reparse points, owner, and DACL. Modification permissions are allowed only to the current user, SYSTEM, Administrators, and Creator Owner for inheritance. Other SIDs may receive read-only, enumeration, and execute permissions within FILE_GENERIC_READ/FILE_GENERIC_EXECUTE; GENERIC_READ/GENERIC_EXECUTE use the same file-permission boundary. Write, create, append, delete, delete-child, change-owner, change-ACL, GENERIC_WRITE/GENERIC_ALL, and unknown bits remain rejected, checking both effective and inheritance-only ACEs. This permits existing read-only observer accounts without treating externally writable directories as safe. Windows output inherits existing read-only sharing and does not promise to hide contents from those accounts or rewrite user directory ACLs. Links, special objects, external owners, and externally writable destinations remain rejected.

Private work directories are exclusively created with system-random 128-bit names; POSIX directories use 0700 and files 0600. Staging filenames use host-generated sequence numbers, not temporary paths supplied by the archive. Meter actual decoded bytes per block: 8 GiB per file and 20 GiB per task. A declared compression ratio above 1000:1 with output above 1 MiB requires explicit permission; hard byte limits remain. Each decoder uses fixed buffers rather than accumulating all extracted data in memory.

Commit only after complete verification and data synchronization. By default do not overwrite: exclusively create a same-volume hard link, then remove the private link. When overwrite is allowed, recheck the existing regular file's identity, size, and modification time and replace by same-volume rename, never deleting or truncating the old file first. Reject hard-linked leaves and the source archive itself. Fail if the filesystem lacks the commit primitive; there is no copy/delete fallback. Identity checks are best effort, not content CAS against same-account concurrent editing, and do not promise directory metadata durability after power loss. Count created directories and committed files separately; do not invent whole-task rollback.

The private journal records relative paths and task identity for preparation and commit. Cleanup deletes only known identity-matching objects. Unknown files, replaced destinations, or deletion failures retain recovery materials and report cleanup warnings. Random work directories after a crash are counted and reported only; they are not automatically parsed, executed, or recursively deleted. Recovery acceptance covers crash, identity-change, and cleanup-failure paths.

Tasks and metadata each use one worker thread. At most 32 tasks are retained, including those awaiting terminal-state consumption. Queue accounting conservatively includes immutable snapshots and plans, with at most 64 MiB cumulative. Ordinary commands own at most 8 MiB cumulative data. Each task retains only its latest display snapshot; output progress is at most 10 Hz and terminal states are published after cleanup. The GUI receiver and mailbox remain bounded and cannot grow indefinitely if the GUI pauses. Conflict prompts have one-shot task-local prompt IDs; cancellation and exit wake waiters independently of data-queue capacity.

Admission closure uses a monotonic atomic flag published under the same state lock and queried by nonblocking submit. After shutdown returns, valid commands consistently return Closed even while the exit worker holds the lock, rather than a retryable Busy. This flag determines rejection only and does not bypass task/request state checks under the lock.

Cancellation linearizes through an atomic commit permit: cancellation before commit writes no destination; after commit starts, allow whole-file atomic publication and count the committed file in the final result. Cancellation after the final task completes cannot change success. Closing a progress window only hides it and the task continues. Exiting the program cancels and waits for workers and source handles without joining on the GUI thread.

Windows and macOS ACL queries are isolated unsafe boundaries; each call explains handle, pointer, buffer, and release prerequisites. Verification results record actually covered platforms and exceptional paths. See [ZIP extraction dependency admission](zip-extraction-admission.md) for dependency and advisory checks. Actual acceptance follows [verification](../qa/README.md) and is recorded in relevant issues and artifacts.

OWNER RIGHTS (S-1-3-4) represents dynamic object-owner permissions and is accepted only after owner verification against the current user/SYSTEM/Administrators. It cannot make an external owner or another SID trusted. Native regressions also verify inheritance to staging files and new output parents and, with OWNER RIGHTS present, acceptance of Everyone read-only access while still rejecting modification rights.

Windows cap directory handles do not allow FILE_SHARE_DELETE, so the OS rejects parent-directory rename attacks. Acceptance also proves external directories remain unchanged and safe destinations publish within authorized directories. Cleanup of an empty private work directory uses cap's consuming remove_open_dir after identity revalidation, closing the handle before deletion. Only verified empty directories are removed; nofollow, ACL, and link rejection rules are not relaxed.

The Qt bridge passes destination/task DTOs without output capability; IDs enter QML as opaque strings. Menus, extraction options, conflicts, progress/results, and exit use real tasks. System Quit and window close both pass task decisions before entering the asynchronous shutdown barrier. Continuous progress is at most 10 Hz; prompts, cancellation, cleanup, and terminal states are immediate. Runtime failures do not guess committed totals: retain the latest state and explicitly mark counts incomplete.

The interface follows [logical dimensions](../../specs/visual/layout-scale.json), the [window registry](../../specs/visual/window-registry.json), and [design standard](../visual/design-standard.md). Extraction, task, and conflict windows are all 491 units wide; footer action text is 13 and hints 12. A fixed bottom action area and scrollable body keep small screens and large fonts usable. Large artwork uses a 216-pixel transparent export from the same SVG, not an enlarged 72-pixel image; the [asset specification](../../specs/visual/operation-assets.json) retains common-source relationships. Native system title bars and the design's system-appearance illustration are accepted separately.

Current output belongs to the current account; POSIX directories use 0700 and ordinary files default to 0600. Before publication, restore `0600 | (mode & 0155)` for ordinary files from ZIP Unix creators on the held staging handle: preserve read/execute bits while stripping group/other write and setuid/setgid/sticky. Do not change ownership, restore extended attributes or original modification times, or automatically execute applications. Executable bits and relative symbolic links restore application-bundle layout but do not establish installation, signature verification, or system security review. Corruption, special entries, and source/destination changes stop the current task by default. Earlier committed files remain; there is no silent continuation, whole-task rollback, or automatic retry.

When submitting a task, the Qt controller retains busy serial admission and rejects duplicate requests. taskStarting distinguishes extraction/creation submission from directory reading. Ordinary controls use browsingBusy for appearance; the browsing workspace displays the latest committed snapshot rather than depicting task submission as directory rereading. browserQueryAvailable preserves the query entry's appearance during submission; actual commands still pass existing serial-request protection. “Start extraction” and other confirmation controls retain normal appearance during taskStarting. Click handling and the controller still use busy to block duplicates; admission rejection does not flash disabled colors. Switch to the real task window only after acceptance. Rejection/failure retains the confirmation window and error explanation; do not optimistically clear directories or fabricate early success.

Automatic target checking after opening extraction confirmation, rechecking after editing, and creation-window target checks and input metadata previews are also operation preparation. They retain committed browsing snapshots and cannot trigger browsingBusy or close browserQueryAvailable, avoiding main-list overlays, disabled toolbar colors, and menu-closure flicker. busy still covers the full request cycle and protects serial admission; target-check feedback appears only in the operation window. Initial opening of an unready archive still shows loading. During directory/query changes, retain the committed nonempty list or empty state until a new snapshot commits. If failure invalidates the source snapshot, clear invalid data.

Extraction targets are automatically checked when opening the window, choosing a directory, and finishing edits. Creation and extraction retain separate results bound to window generation, request, path, and extraction session. A path change immediately invalidates the old result; submission is blocked while queued or checking. Stale receipts cannot authorize a new path or another window. Both windows share status icons and wording; extraction retains its path layout, same-name folder, and staging warning. This check is only operation preparation; actual writes revalidate source and destination capabilities.

## Safe ZIP symbolic-link restoration

Only symbolic links from POSIX ZIP Unix creators may be restored. TAR symbolic/hard links, Windows symbolic links, and other special objects still return unsupported_link. Fully decode link content into a bounded sink before obtaining output authorization, verifying local header, length, and format-specific CRC/authentication. Encrypted links are delayed until task preparation under the [password extraction contract](password-extraction.md). Each link is at most 4,096 bytes and the total at most 4 MiB; names follow PortablePath. Relative targets may contain `.`/`..`, but links encountered must be expanded in filesystem order before subsequent parent components. Reject output-root escapes, absolute paths, backslashes, controls, and reserved device paths; nonexistent prefixes and using a file as a directory are also rejected.

All targets must close within the selected output graph using original spellings. This supports Framework Versions/Current, link expansion in target-path prefixes, and relative `.`/`..` common in macOS app bundles. Normalize each expansion relative to the link's parent and reject output-root escape. Follow at most 64 links; reject cycles, dangling/out-of-bounds targets, case/Unicode ambiguity, duplicate names, and links used as write parents. Selecting only a link without its dependencies is rejected; do not borrow existing external links in the destination tree. Publish all regular files and directories first, then exclusively create links through held no-follow parent handles. Existing links are neither overwritten nor followed. Each publication revalidates source and parent-chain identity and cancellation permits and records the transaction journal. Filesystems without link creation fail explicitly without degrading links to text files.

Tasks with links require all file/link leaves to be absent: check together at startup and again when committing regular files. Conflicts fail; skip/rename/overwrite cannot break the frozen dependency graph. Existing safe regular directories may be reused. As with ordinary extraction, later failure or cancellation retains already committed items; whole-archive transactions and automatic rollback are not promised. Completion counts include link-content bytes and link count. Read-only metadata preflight does not read link content; no warnings do not mean link output was admitted.

## macOS extended ACL control

Query extended ACLs for directory and regular-file authorization through held handles, retaining checks for current effective-user ownership, no group/other mode write permissions, and one hard link for regular files. Known deny rules grant no modification authority and are acceptable. Other principals' allow rules may grant only read, enumeration, execute, attribute-read, and security-information-read capabilities. A common user-directory `everyone deny delete` is not rejected merely because an extended ACL exists.

Modification rights such as write, create, append, delete, delete-child, write attributes, write extended attributes, change ACL, and change owner are allowed only to principals explicitly matching the current effective user UID. User identity matching includes system resolution and the synthetic user UUID used by the system; group principals cannot substitute for the current user. Reject external principals' effective and inheritance-only modification rights alike; an earlier deny does not exempt a dangerous allow. Reject unknown permission bits, unknown rule types, unverifiable identity, and ACL query or release failure. Distinguish absence of an ACL from other query errors.

Apply checks to the destination root, each parent directory, staging directory, and ordinary file to replace, rerunning them at existing identity-revalidation boundaries. Staging files are exclusively created inside verified private directories; directory ACL checks constrain inherited permissions. The checks do not automatically clear or rewrite user ACLs. Existing read-only sharing may be inherited by output; content is not promised hidden from read-only shared accounts. Acceptance must verify actual publication with safe ACLs and rejection of dangerous ACLs on project-owned temporary objects. Record results in the [security fix issue](https://github.com/xiaodaozhi/xdzip/issues/6) and local/CI artifacts.

System context-menu smart and per-archive directories are explicit task layouts governed by [file-manager actions](shell-actions.md). Smart decisions use the complete verified output graph. When a wrapper is needed, exclusively create it through the shared destination capability and use numbered conflict avoidance without reusing an existing directory. Ordinary browsing extraction's same-name option continues using the existing destination capability.
