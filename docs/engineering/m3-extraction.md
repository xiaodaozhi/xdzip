# M3 安全 ZIP 解压实现

本契约定义宿主安全输出、真实解压、冲突、取消与提交行为；具体执行结果和当前缺陷记录于对应 issue 及 Actions 工件，不在本页累积验收报告。

格式插件只获得借用输入、不可变条目快照和宿主 `DecodedSink`。ZIP 元数据扫描与负载解码分离。Store、Deflate、单卷 ZIP64 的本地头、中央目录、数据描述符、声明大小、实际大小、CRC 和 Deflate StreamEnd 必须一致；单卷 AES-256 的认证与 CRC 差异按[密码解压契约](password-extraction.md)处理，其他加密、分卷、其他压缩方法、非 UTF-8 名称和未通过下文专门策略的链接／特殊对象仍不支持。原始 ZIP64 本地数据描述符可与普通中央目录组合，按本地与中央目录的大小哨兵验证宽度。流结束后剩余的压缩字节及输出正确但缺少终止块的流都失败。

所有输出先通过共享 portable 名称解析器，拒绝路径穿越、绝对路径、保留设备名、非法字符和歧义组件。任务准备阶段冻结选择：根目录全量解压包括全部物理记录；所选目录展开全部后代；所选文件去除当前目录前缀。浏览器根目录列表仍仅显示直属文件和文件夹。常见 Unicode NFD／小写等价名称按首个拼写映射，普通文件别名进入冲突流程；文件与目录冲突、父目录歧义在创建目标对象前拒绝。该比较不是所有文件系统名称规则的完整模拟，最终排他创建仍由原生文件系统裁决。

用户选择的目标目录通过 `xdzip-io::Grant` 转为持有目录句柄的能力。子目录逐组件 no-follow 打开，保留并复核父链身份。POSIX 目标须属于当前有效用户且不能向组或其他用户开放写权限；Windows 检查重解析点、所有者和 DACL，修改权限只允许当前用户、SYSTEM、Administrators 和继承用途的 Creator Owner。其他 SID 可以具有 FILE_GENERIC_READ／FILE_GENERIC_EXECUTE 的只读、枚举及执行权限，GENERIC_READ／GENERIC_EXECUTE 使用相同的文件权限边界；写入、创建、追加、删除、删除子项、改所有者、改 ACL、GENERIC_WRITE／GENERIC_ALL 及未知位仍拒绝，有效与仅继承 ACE 同样检查。这样可接受个人目录已有的只读观察账户，而不会将外部可写目录判为安全。Windows 输出沿用目标的只读共享权限，不承诺对已有只读账户隐藏文件内容，也不修改用户目录 ACL。链接、特殊对象、外部所有者和外部可写目标继续拒绝。

私有工作目录以系统随机 128-bit 名字排他创建，POSIX 目录 0700、文件 0600。阶段文件使用宿主生成的顺序号，不使用归档提供的临时路径。真实解码字节逐块计量：单文件 8 GiB、单任务 20 GiB；声明压缩比高于 1000:1 且输出大于 1 MiB 时须显式允许，硬字节限额保持不变。每个解码器使用固定缓冲区，解压数据不整体积累到内存。

完整校验与数据同步后才提交。默认不覆盖：同卷硬链接的排他创建成功后移除私有链接；允许覆盖：复核已有普通文件的身份、大小和修改时间，使用同卷重命名替换，绝不先删除或截断旧文件。拒绝硬链接叶子和源归档本身。文件系统不支持提交原语时失败，没有复制／删除退路。身份校验是 best effort，不是同账户并发编辑的内容 CAS，也不承诺断电后的目录元数据持久化。目录已创建、文件已提交的效果分别计数，不虚构任务整体回滚。

私有 journal 记录准备与提交的相对路径和任务身份。清理只删除身份匹配的已知对象；发现未知文件、目标被替换或删除失败时保留恢复材料并报告清理警告。崩溃后的随机工作目录只统计提示，不自动解析、执行或递归删除。恢复策略与完整独立审查仍属于正式发行前的门禁。

任务和元数据各用一个工作线程。最多 32 个任务，等待终态消费的任务也占槽；队列保守计入不可变快照和计划，累计不超过 64 MiB。普通命令累计拥有数据不超过 8 MiB。每个任务只保留最新显示快照，输出进度最多 10 Hz，终态在清理后发布；GUI 接收线程和其邮箱继续有界，不能因 GUI 暂停无限增长。冲突提示具有任务内单次使用的 prompt ID，取消和退出会唤醒等待，不依赖数据队列有空间。

关闭准入以同一状态锁下发布的单调原子标记供非阻塞 submit 查询；shutdown 返回后，即使退出工作线程正持有锁，合法命令仍稳定返回 Closed，不会误报可重试的 Busy。该标记只决定拒绝，不绕过锁下的任务与请求状态检查。

取消通过原子提交许可线性化：开始提交前取消不写目标；提交已经开始时允许完成整文件原子发布，并在最终结果中计入已提交文件；最后任务完成后取消不能改变成功结果。关闭进度窗口只隐藏窗口，任务继续；退出程序须取消并等待工作线程与源句柄退出，不在 GUI 线程 join。

Windows 与 macOS ACL 查询属于隔离的 unsafe 边界，每个调用解释句柄、指针、缓冲区和释放前提。当前是单维护者开发验证，不能将这些自检称为独立安全评审。依赖准入与公告查询见 [ZIP 解压依赖](zip-extraction-admission.md)，实际验收按[验证方法](../qa/README.md)在对应 issue 与工件登记。

OWNER RIGHTS（S-1-3-4）表示对象所有者的动态权限，只在所有者已通过当前用户／SYSTEM／Administrators 检查后接受；不能使外部所有者或其他 SID 变为受信账户。原生回归同时验证继承到阶段文件与新建输出父目录，以及存在 OWNER RIGHTS 时接受 Everyone 的只读访问、仍拒绝其修改权限。

Windows cap 目录句柄不允许 FILE_SHARE_DELETE，父目录改名攻击会在系统层被拒绝；验收同时证明外部目录未改变及安全目标发布仍在授权目录内。空私有工作目录清理在身份复核后使用 cap 的 consuming remove_open_dir，先关闭句柄再删除；只删除已验证的空目录，不放宽 nofollow、ACL 或链接拒绝规则。

Qt 桥接只传不含输出能力的目标／任务 DTO，ID 以不透明字符串进入 QML。菜单、解压选项、冲突、进度／结果和退出均接入真实任务；系统 Quit 同窗口关闭先经过任务决策，再进入异步关闭屏障。持续进度最多 10 Hz；提示、取消、清理及终态立即发布。运行时异常不猜测已提交总量，保留最近状态并明确标记计数不完整。

界面以[逻辑尺寸](../visual/layout-scale.json)、[窗口登记](../visual/window-registry.json)及[设计规范](../visual/design-standard.md)为准，解压、任务与冲突统一宽 491；footer 操作字 13、提示 12。固定底部操作区与可滚动正文保证小屏和大字号可操作。大图使用同一 SVG 的 216 像素透明导出，不放大 72 像素小图；[素材规范](../visual/operation-assets.json)保留同源关系。原生系统标题栏与稿中的系统外观示意分开验收。

当前输出归属当前账户，POSIX 目录使用 0700、普通文件默认 0600。ZIP Unix 创建者的普通文件在持有暂存文件句柄上、发布前恢复 `0600 | (mode & 0155)`：保留读／执行位，剥离组和其他用户写位及 setuid／setgid／sticky。不改变所有者，不恢复扩展属性或原始修改时间，不自动执行应用。可执行位和相对符号链接属于应用包布局还原，不代表安装、签名验证或系统安全审查。损坏、特殊项和源／目标变化默认停止当前任务；保留早前已提交文件，没有静默继续、整任务回滚或自动重试。

提交任务时，Qt 控制器继续使用 busy 串行准入并拒绝重复请求；taskStarting 区分解压／创建任务提交与目录读取。主窗口加载遮罩和普通控件外观使用 browsingBusy，不能把任务提交误画为目录重新读取。browserQueryAvailable 保持提交期间的查询入口外观，实际命令仍经过原有串行请求防护。解压确认的“开始解压”及其他控件在 taskStarting 期间保持正常外观；点击处理和控制器继续用 busy 拦截重复请求，拒绝准入时不闪现禁用色。任务受理后才切换到真实任务窗口，拒绝或失败保留确认窗口和错误说明；不乐观清空目录或提前伪造任务成功。

打开解压确认窗口后的自动目标检查、手动重检，以及创建窗口的目标检查和输入元数据预览也属于操作准备。它们保持已提交的浏览快照，不能触发 browsingBusy 或关闭 browserQueryAvailable，避免主列表遮罩、工具栏禁用色和菜单关闭造成闪烁。busy 仍覆盖完整请求周期，继续保护串行准入；目标检查中的反馈只在操作窗口显示。实际打开归档、切换目录和预检仍使用原有加载状态，失败导致源快照失效时仍清除失效数据。

## ZIP 符号链接安全恢复

仅 POSIX ZIP Unix 创建者的符号链接可恢复，TAR 符号／硬链接、Windows 符号链接及其他特殊对象仍返回 unsupported_link。链接内容在取得输出授权前以受限 sink 完整解码，验证本地头、长度与相应格式的 CRC／认证；加密链接按[密码解压契约](password-extraction.md)延迟到任务准备阶段。单项最多 4096 字节，合计最多 4 MiB，名称沿用 PortablePath 规则；不接受绝对、父级、点、反斜杠、控制字符或保留设备路径。

所有目标必须按原始拼写在本次选中输出图内闭合，支持 Framework 的 Versions/Current 及目标路径前缀中的链接展开；最多跟随 64 次，拒绝循环、悬空、大小写／Unicode 歧义、重复名称及链接作为写入父目录。仅选择一个链接而未选择其依赖时拒绝，不借用目标树中的外部既有链接。先发布全部普通文件和目录，最后通过持有的 no-follow 父目录句柄排他创建链接，已有链接不会被覆盖或跟随。每次发布仍复核源和父链身份、取消许可并记事务日志。链接创建不支持的文件系统明确失败，不降级为普通文本文件。

带链接的任务要求所有文件／链接叶子为空：启动时统一检查，提交普通文件时再次检查；遇到冲突即失败，不能用跳过／改名／覆盖破坏冻结的依赖图。已有安全普通目录可复用。与普通解压一致，后续失败或取消保留此前已提交项，不承诺整包事务或自动回滚；完成统计包含链接内容字节及链接数量。只读元数据预检不读取链接内容，其无警告不代表通过链接输出准入。

## macOS 扩展 ACL 控制

目录和普通文件授权通过持有的句柄查询扩展 ACL，保留当前有效用户所有权、组和其他用户无 mode 写权限以及普通文件单硬链接检查。已知的 deny 规则不授予修改能力，可以接受；其他主体的 allow 规则仅可授予读取、枚举、执行、读取属性和安全信息等只读能力。常见用户目录的 `everyone deny delete` 不因存在扩展 ACL 而被拒绝。

写入、创建、追加、删除、删除子项、写属性、写扩展属性、改 ACL 和改所有者等修改权限，只允许明确匹配当前有效用户 UID 的主体。当前用户身份匹配覆盖系统解析及系统使用的合成用户 UUID，不接受组主体作为当前用户的替代。外部主体的有效与仅继承修改权限同样拒绝，前置 deny 不使危险 allow 规则获得豁免。未知权限位、未知规则类型、身份无法核实、ACL 查询或释放失败均拒绝，无 ACL 的缺失结果与其他查询错误分开处理。

此检查用于目标根、逐级父目录、暂存目录和待替换普通文件，并在已有身份复核边界重新执行。暂存文件在已核实的私有目录内排他创建，目录 ACL 检查同时约束其继承权限。它不自动清除或改写用户 ACL，原有只读共享权限可能继承到输出，不承诺对只读共享账户隐藏内容。验收必须在自有临时对象上同时验证安全 ACL 的实际发布与危险 ACL 的拒绝，具体结果记录于[安全修复 issue](https://github.com/xiaodaozhi/xdzip/issues/6)及本地／CI 工件。
