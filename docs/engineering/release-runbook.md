# 发布操作手册

跨平台预发布使用[发布协议 v1](release-protocol.md)，按完整标签冻结源码，草稿汇集全部六类包及源码、通知、许可、SBOM 和重建材料。全部核验通过才公开 Pre-release，随后下载全部附件复验哈希。未完成的许可来源复核和未执行的人工验收在实验性预发布说明中公开，不视为稳定发行获批。

WP-12 已按所有者批准标记为开发与验收完成，剩余[发行许可复核](../qa/release-review.md)保持开放。本仓库尚无经批准的正式发行版本。本手册由发布工作包执行，不能将未勾选项解释为通过。

2026-10-19 用户确定个人 GitHub 开源项目发行政策：通过 GitHub Releases 提供未正式签名的安装包，不要求注册付费开发者账号、购买签名证书、Developer ID 签名或 macOS 公证。macOS 只保留 Apple Silicon 运行所需的 ad-hoc 完整性签名，Windows 交付未签名安装器。正式签名可在未来具备条件时另行选择，不作为 WP-12 或后续稳定发行的硬性门槛。版本、提交、工件哈希、源码、许可与安全要求继续有效；本政策不自动授权上传或发布。

1. 按[版本机制](versioning.md)更新 VERSION.json 并同步派生版本，确认版本范围与能力矩阵，关闭或标记未达门槛的特性。准备 `release-notes/<完整版本>.md`，记录一致的 version/build 元数据与中英文说明，按平台和提交引用真实验收；运行 `python3 scripts/publish-release.py --check-notes`，缺失说明时不能沿用旧版内容。
2. 从确定提交构建源码、各平台未签名包、调试符号、SBOM、NOTICE 与依赖许可证。
3. 记录工具链、哈希、features、目标和基准环境；验证源码可重建未签名部分。
4. 核验未正式签名的交付方式：验证 macOS ad-hoc 完整性签名，明确 Windows 安装器未签名，在发布说明中如实说明系统可能出现的安全提示和已验证的安装限制。不要求用户关闭系统安全保护，不宣称获得平台发行者信任。
5. 在干净系统检查安装、首开、文件关联、Unicode、权限、退出、升级/卸载和 Qt 依赖完整性。
6. 核对安全、互操作与缺陷回归结果，记录实际执行范围和已知限制。
7. 核对版本专属发布说明、已知限制、完整安装/下载体积及校验和，经发布负责人确认后上传。草稿与说明文件不一致时停止，先显式对齐已审阅输入；不会自动覆盖草稿中的人工修订。
8. 发行后确认下载工件与已验证哈希一致；发生问题撤回问题渠道并说明影响，保留诊断证据。

v0.1 手动下载更新；不在活跃任务中覆盖程序或插件。回退前检查设置 schema 兼容性，保留旧可运行版本，不能强行降级数据。bundle ID、GitHub Releases 渠道和维护周期按项目支持政策记录；不申请或虚构正式签名身份与证书。

WP-12 准备材料从[部署依赖核验与 SBOM](deployment-audit.md)和[人工专项清单](../qa/private-test-manual.md)生成。源码图和实际文件清单必须与同一源码／可执行文件身份一致；当前完整性标记 incomplete，仍须完成实际部署组件归属与许可确认；干净机器人工核验已按用户结论登记，见 WP-12 当前验收记录。已有 Windows 当前用户及 Ubuntu 24.04 实验安装器，见[安装与关联](installers-associations.md)。macOS 开发 .app 不代替独立安装包验证，交付 DMG 继续核验部署依赖与 ad-hoc 完整性。

本地 Mac 可按用户明确要求制作[开发 DMG](macos-deployment.md)，源码与重建材料使用[交付收集器](source-delivery.md)。ad-hoc 签名不等于 Developer ID 或公证，但符合本项目当前签名政策；镜像核验不自动批准发行。
