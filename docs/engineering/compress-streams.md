This contract defines the byte profile for the independent Rust LZW reader and its single-file/TAR composition. The utility's history and 9–16-bit dictionary behavior follow [OpenBSD compress(1)](https://man.openbsd.org/compress.1) and [ncompress](https://vapier.github.io/ncompress/). POSIX specifies the utility rather than a complete byte layout. Historical eight-code alignment and 9-bit compatibility differences are documented in the [upstream discussion](https://github.com/vapier/ncompress/issues/5) and checked with independent known-content inputs. Source observations supplement the wire rules; the Rust implementation is not a translation of reference code.

## Wire and dictionary rules

Require magic bytes `1F 9D`, then one properties byte: bits 0–4 declare maximum width 9–16, bit 7 selects block mode, and reserved bits 5–6 must be zero. Codes start at width 9, with least-significant bits first. Each group contains up to eight codes and occupies `width` bytes when full. A width transition or CLEAR discards the remainder of its old group and begins a new aligned group. Historical alignment and final unused bits are unspecified and need not be zero.

Literal codes are 0–255. Block mode reserves 256 for CLEAR and starts new dictionary entries at 257; non-block mode starts at 256. Begin with a literal, including after CLEAR. Reconstruct each new string as the previous string followed by the first byte of the current string. The next not-yet-defined code is admitted only for the ordinary previous-string-plus-first-byte special case. Reject all larger or otherwise undefined codes. Dictionary parents are earlier entries; bound every reverse expansion before output. When the next dictionary index reaches `2^width`, increase width before the next code if below the declared maximum. At full capacity keep the dictionary until CLEAR or EOF. CLEAR resets width and dictionary occupancy; it cannot be the first code, repeat without a literal, or terminate the file without a following literal.

A three-byte header alone represents an empty stream. A nonempty final group must contain a complete code; after its last complete code, fewer than eight unused bits may remain. An incomplete code occupying a whole leftover byte is invalid. There is no explicit EOF code, original size, filename, timestamp, checksum or authentication field. Additional bytes are interpreted as codes; arbitrary structure-preserving changes or tails that themselves form valid codes cannot always be distinguished from content. No concatenated-member or damaged legacy-stream repair is promised.

The reader follows the declared maximum for saturated 9-bit dictionaries. Pinned ncompress 1.0.2 decodes the owned saturated 9-bit input completely; the pinned 7-Zip 26.06 reference stops after its first 256 decoded bytes with a data error. This is recorded as a reference limitation, not a successful 7-Zip check. Short 9-bit, forced CLEAR and non-block vectors are independently accepted by both. Historical malformed `-b9` outputs are not silently reparsed under another width policy.

## Admission and host integration

Before dictionary allocation, admit `4 * 2^max_bits + 8192 + 512` bytes for u16 parents, byte suffixes, bounded reverse expansion, input buffering and fixed state. Reject invalid properties and insufficient memory before allocating these tables. Primitive work has a separate hard maximum of 96 GiB units: charge each code, each reverse-expansion byte, each dictionary insertion and each delivered byte. Fail before exceeding the budget. Return at most 8192 bytes per primitive read so host cancellation remains reachable; typed source errors remain terminal and retain their original payload on first propagation. The controlled filter retains the stable failure for subsequent calls.

The format integration uses the existing controlled-stream, filename and task contracts. Source bytes and decoded bytes have separate common ceilings; TAR composition also validates its complete record stream and tail. `.z` is an ordinary-file candidate; `.tar.z` and `.taz` are TAR candidates. Detect actual TAR headers from decoded bytes, and retain same-filter filename hints only for the already validated zero-only ordinary/TAR ambiguity. A hint grants no path access and cannot hide a damaged TAR header. The stream has no embedded output name; virtual names use only the authorized basename policy. LZW's read method identifier is scoped to these containers and grants no ZIP or creation capability.

Browse, check and extract integrations must preserve immutable physical identity, frozen sources, actual byte budgets, cancellation, staging and host publication. Z and TAR.Z checks establish structure and readability. The format has no content checksum. Unsupported headers, invalid dictionaries, malformed groups, quota failures, source changes and sink errors cannot become successful EOF. TAR.Z editing rebuilds a standard block-mode stream and uses an early CLEAR to stay at nine-bit codes.

## Independent inputs and automated acceptance

The owned generator pins ncompress 1.0.2 and 7-Zip 26.06 reference identities under `build/toolchain/`; neither enters a production dependency. Reference-produced inputs include actual matches, empty and zero streams, full-width growth, natural CLEAR and TAR. Additional owned textbook LZW/code-packing inputs cover all maximum widths, full dictionaries, non-block mode, explicit resets and the not-yet-defined-code special case. Every input is fully decoded by pinned ncompress; all except saturated 9-bit are also fully decoded by pinned 7-Zip. Record that difference explicitly.

Regressions cover exact memory/work budgets, short reads, bare retryable versus typed terminal interruptions, invalid initial/forward codes, reserved properties, incomplete groups, terminal CLEAR and unspecified padding. Format registration additionally requires actual runtime/CLI/Qt browse/check/extract and zero-only ambiguity, read-only/check-strength notes, system candidates, bilingual/theme/font layouts and shared main/menu measurements. Progress and actual acceptance belong in the delivery issue; generated evidence remains under `build/` or CI.
