# ZIP extraction and output dependency admission

This page defines dependency boundaries shared by safe and password extraction. The M3 baseline admission's provenance, licenses and feature excerpts are in the [baseline pinned materials](../../specs/engineering/zip-extraction-dependencies.json). Current exact versions including AES and crates.io checksums are governed by root Cargo.lock; check the complete enabled graph with `cargo tree --locked -e features`. Do not treat the baseline excerpt as the complete current dependency inventory.

| Dependency | Purpose and decision |
| --- | --- |
| xdzip-compression | Project-owned shared Deflate and CRC-32 with fixed buffers, strict final-block and exact compressed-byte consumption checks. The independent format layer handles ZIP containers, descriptors and AES wrapping, borrowing host input and output sinks while preserving output authorization and complete verification boundaries. flate2 is a development-test reference only. |
| cap-std / cap-fs-ext 4.0.3 | Held directory capabilities, nofollow subdirectory opens, exclusive staging and relative publication. Unlike string concatenation and creation after canonicalize, the host performs component authorization and identity rechecks; it does not invoke generic unpack. Transitive packages such as cap-primitives are pinned too. |
| getrandom 0.4.2 | OS randomness for private workspace nonces, never timestamps, pseudorandom values or archive names. Default features disabled. |
| rustix 1.1.5 | POSIX effective user identity and filesystem primitives, reusing the locked version. Default features disabled; only std/process and transitively needed fs enabled. |
| windows-sys 0.61.2 | Queries Windows object owner and DACL and checks SID. Handwritten unsafe is isolated, borrowing valid handles, DWORD-aligned buffers and RAII LocalFree. Unlike checking read-only attributes alone, DACL checks private-output prerequisites. New FFI must verify handle, buffer and release preconditions and query failure behavior. |
| unicode-normalization 0.1.25 | Generates NFD plus lowercase admission keys for task-name aliases, retaining original output spelling. The key is not treated as complete filesystem casefolding. It covers common macOS Unicode-equivalent names beyond ASCII lowercase. |
| AES, HMAC, SHA-1, PBKDF2, constant_time_eq | Admitted generic cryptographic primitives; exact versions and features are in the [dependency contract](dependencies.md). ZIP CTR counting, salt and verification-value layout, ciphertext authentication and error classification are independently implemented by the project. zip 9.0.3 is a development-test reference only. |
| zeroize 1.9.1 | Zeroization lifecycle for passwords, derived keys and bounded stdin buffers for test probes; AES/HMAC/SHA-1 also enable their cleanup features. It does not guarantee erasure of Qt, IME or all historical memory copies. |

Review Cargo configuration, licensing and public APIs for generic dependencies; source rules for independent format implementations are in the [independent implementation contract](independent-rust-codecs.md). The cap family is maintained by Bytecode Alliance, getrandom and rustix provide system interfaces, and Unicode normalization is a general Unicode library. Upgrades still require pinned versions and native boundary regressions; maintainers do not replace regression testing or advisory checks. New packages make no runtime network requests. Packages with build scripts only probe compiler/target configuration or select Rust syscall backends; they do not download external code or compile C decoders. License notices collect complete upstream texts; pinned materials govern actual license expressions.

Retain actual OSV exact-version query responses under the [verification method](../qa/README.md). A failed query cannot be interpreted as finding no advisories. This is not a complete cargo-audit. Existing cxx advisories and version selection remain in the [M2 dependency record](dependencies.md).

Metadata admission does not automatically approve decoding. The independent adapter validates local headers, stream termination, CRC and 32/64-bit data descriptors, choosing width according to central and local ZIP64 sentinels. Independent Python force_zip64 fixtures cover valid mixed widths and tampered sizes. rawzip, zip and flate2 are absent from ordinary and build dependency closures for ZIP and the host; historical pinned excerpts retain provenance only for their time.

Pinned materials list all cross-target Cargo resolution dependencies. getrandom's WASI/WIT/WebAssembly toolchain applies only to unsupported targets and does not enter macOS, Windows or Linux desktop compilation or runtime. An all-target Cargo inventory must not be interpreted as desktop runtime scope.

Development-package notices use actual resolution nodes from `cargo metadata --filter-platform <rustc host>` to collect current-platform workspace and build-tool licenses, recording target.json. Uncompiled WASI/UEFI packages are not treated as desktop release dependencies. Missing license text still fails packaging; a Cargo license name cannot replace its text. The complete MIT grant and copyright for r-efi 6.0.0 are in AUTHORS; the collector accepts this text exception only for that version and pinned SHA-256.
