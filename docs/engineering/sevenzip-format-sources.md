# 7z format sources and independent implementation

This document records reusable sources and implementation boundaries. Migration acceptance and remaining capabilities are tracked in [issue #50](https://github.com/xiaodaozhi/xdzip/issues/50); fixed Rust routing and removal of the official product dependency do not automatically establish cross-platform, manual or release acceptance. General replacement rules are in the [independent implementation contract](independent-rust-codecs.md).

## Specifications and reference identity

Container fields, variable-length integers, method graphs, properties and file mappings follow official `DOC/7zFormat.txt` and `DOC/Methods.txt`. The pinned reference is the [7-Zip 26.05 official source archive](https://github.com/ip7z/7zip/releases/download/26.05/7z2605-src.tar.xz), SHA-256 `0b6080b8c3e7a579161d2d495224c0e51c467576cb4c7048b0ab485ef44cc22e`. The two documents have SHA-256 values `8ec976b73ca88710286be1e991e49dbab485d9c0bf2410a80fa87e657850f82b` and `b16ea5fdc50345fa2cb031f06fe410cea0b089f74a4138ac8141b9e2d816ffc7`, respectively.

The LZMA bitstream also refers to Igor Pavlov's 2015-06-14 [official specification package](https://www.7-zip.org/a/lzma-specification.7z), archive SHA-256 `4529aca392d6b9598f72086e7d136b1e05d2863bf7a757836d3fd4f49e623b58`, whose specification text has SHA-256 `6a4d441c2fa1d8d37b0189c7147a4b5424d5cdb122a7fc1fbebd022864ed54fb`. Only format prose, specification mathematics and pseudocode are read; the reference decoder in the package is not used as Rust porting input. Downloading documents or samples grants no new redistribution license.

Generic Deflate follows RFC 1951 and shares one implementation with ZIP, GZIP and MSZIP. Deflate64 explicitly selects extended rules in that implementation: a 64 KiB history, distance codes 30/31 and length code 285; ordinary Deflate/MSZIP are unchanged. The enhanced Deflate section of [PKWARE APPNOTE](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT) is only an overview. Specific bitstream differences are supplemented by factual analysis of the pinned reference and independent reading verification; the overview must not be presented as a complete specification. AES-CBC mathematics and independent vectors follow [NIST SP 800-38A](https://nvlpubs.nist.gov/nistpubs/Legacy/SP/nistspecialpublication800-38a.pdf). 7z properties, UTF-16LE password derivation and zero padding are additional format rules and cannot be inferred from ZIP AES or PKCS#7. The BZip2 manual and PPMd format name do not fully specify historical bitstreams, model restart or termination; these implementations cannot be described as achievable by reading the manuals alone.

## Reference analysis and original coding

An analyst selectively reads the following groups in the pinned original archive to supplement omitted fields, mathematical states, capacity restarts, termination and error relationships. Handoffs contain facts and identification requirements only, with no reference code, line-by-line rewriting, class/array layouts, function decomposition, copied control flow or translated comments. Rust algorithms are independently organized by implementers who have not read the corresponding reference implementations; an analyst does not implement an algorithm they analyzed. The container author likewise has not read the official container implementation and codes independently from documentation and factual handoffs.

## Interoperability boundaries

Success between the owned writer and reader does not substitute for an independent reference. Tests separately verify known output from independent compressors, official reading of owned compressed streams, consumption of all input, termination, CRC, corruption, quotas, cancellation and source errors. Component verification and host/process/platform acceptance are recorded separately.

Historical compatibility tolerances require individual confirmation. For example, a BZip2 7z node may accept nonzero unused bits in the final byte and exactly four repeated bytes at the end of a block without an additional count byte, but still requires correct CRC, declared size and complete stream termination. This does not admit extra trailing bytes or concatenated streams. Final-byte bits and additional bytes are not the same kind of padding.

PPMd7 distinguishes termination profiles for known and unknown outer lengths. After exact output, a known-length 7z node checks range terminal state and packed range without consuming an additional END symbol; the shared reader for unknown lengths requires END. Format-defined model-capacity restarts and host memory admission are separate: insufficient memory must not trigger a fabricated format restart. Independent comparison inputs include capacity-restart streams generated by the pinned official C encoder. The generator and original reference source are local testing tools only and are not production dependencies.
