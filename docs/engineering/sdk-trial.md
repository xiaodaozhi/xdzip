# External read-only SDK trial

`xdzip-plugin-protocol` and `xdzip-plugin-host` implement the independent read-only trial described in the [format extension design](../design/06-codec-extension-sdk.md). It is excluded from desktop and CLI format discovery, installation, packaging and automatic startup. Users explicitly run the trial command and select the package and source; third-party extensions remain disabled in the product. Only `xdp1` is negotiated, with no creation, passwords, volumes, links, GUI or arbitrary host-path permissions. This is neither a complete plugin ecosystem nor an SDK release.

## Reproducible entry points

```sh
python3 scripts/sdk-trial.py test
python3 scripts/sdk-trial.py example --output-dir build/sdk-example
target/debug/xdzip-plugin-host scan build/sdk-example/owned-package/manifest.json build/sdk-example/owned.xdp
mkdir build/sdk-example/output
target/debug/xdzip-plugin-host read build/sdk-example/owned-package/manifest.json build/sdk-example/owned.xdp 0 build/sdk-example/output
```

On Windows use `python` and `.exe`. `test` builds the native reference program and runs Rust framing regressions, independent Python interoperability, malicious protocol, cancellation, source change, conflict and kernel-permission regressions. Python is launched only by the trusted conformance entry point compiled for tests; the released host accepts no interpreter, arguments, shell or unsandboxed-execution switch. The example generates an owned package, manifest and XDP1 under `build/` only; it does not trigger a release or third-party download. Logs omit workspace and user-home paths; JSON binds the commit, dirty state and binary hashes. Both are local or CI artifacts. The same native Foundation matrix calls this entry point; the separate [SDK trial workflow](../../.github/workflows/sdk-trial.yml) first resolves sandbox platform compatibility without repeating unrelated format and Qt pipelines. Before that workflow reaches the default branch, the existing Foundation entry can call the same reusable workflow with `sdk_only=true`; this skips the full Foundation gate and does not establish a full Foundation result. Windows verifies refusal to execute.

## Package admission

The strict JSON manifest uses `deny_unknown_fields`. Fields are `manifest_version=1`, `plugin_id`, `version`, `author`, `protocol_majors=[1]`, `targets`, an in-package `entrypoint`, lowercase hexadecimal `sha256`, `formats=["xdp1"]`, `permissions`, `resources`, `license_files` and an HTTPS `source_url`. The reference manifest generated by `example` above is a runnable entry to the current schema.

`permissions` are exactly `broker_source_read=true`, `broker_output_write=true`, `network=false`; `resources` are exactly `memory_bytes=536870912`, `threads=1`. The manifest is ≤32 KiB, the native executable ≤64 MiB, and at most four license files are allowed, each ≤128 KiB. Entrypoints and license files cannot be absolute, contain parent traversal, or escape via links or reparse points. Each package member is opened component by component without following links through a held cap-std directory, and is not reopened by its original string after verification. The host copies from the held regular file, verifies actual byte count, SHA-256 and file version before and after copying, and executes only the private temporary copy, retaining it until process and IPC teardown. The declared hash establishes consistency of the selected package contents; it neither authenticates the publisher nor proves the code safe.

## Wire protocol and state

An owned bounded CBOR subset follows [RFC 8949](https://www.rfc-editor.org/rfc/rfc8949.html) without a third-party CBOR implementation. The Rust reference peer reuses the framing crate; the [Python peer](../../examples/sdk/reference.py) independently implements encoding, decoding and XDP1 parsing without importing Rust or generated protocol code. Interoperability covers multiple blocks of actual content and the host digest.

Frames are `u32 LE length + CBOR`; length is checked before allocation. Frames are ≤1 MiB, individual bytes/text ≤256 KiB, depth ≤16, arrays ≤128, maps ≤32 and decoded nodes ≤8192. Only UInt, bytes, strict UTF-8 text, arrays, UInt-keyed maps and bool are accepted. Non-shortest integers, duplicate keys, indefinite lengths, negative integers, tags, floats and trailing data are rejected. Envelope map keys `1..5` are kind, request, operation, sequence and payload. Sequence starts at 1 and increases consecutively in each direction; request increases per invocation and operation is a random nonzero host identity. Each response must match the current identity exactly. Unknown payload keys `<128` are rejected; `>=128` are ignorable optional fields.

| kind | Message | Numeric payload keys |
| --- | --- | --- |
| 1 | Hello | 1 minimum major, 2 maximum major, 3 package ID, 4 `xdp1` |
| 2 | Welcome | 1 major, 2 block limit, 3 single-block credit, 4 total read budget, 5 output budget |
| 10 | Probe | 1 source token, 2 source length |
| 11 | Open | 1 source token |
| 12 | Scan | 1 session token |
| 13 | ReadEntry | 1 session, 2 entry, 3 sink, 4 credit count 1, 5 output budget, 6 first-block credit token |
| 14 | Close | 1 session |
| 20, 21 | ReadAt, ReadData | 1 source token, 2 offset, 3 length or bytes |
| 30 | EntryBatch | 1 session, 2 entries; per record: 1 token, 2 raw path, 3 type 0 file / 1 directory, 4 known size |
| 31 | ScanFinished | 1 actual record count |
| 40 | WriteData | 1 sink, 2 block sequence starting at 0, 3 bytes, 4 current credit token |
| 41 | FinishOutput | 1 sink, 2 declared output count, 3 SHA-256 bytes |
| 42 | WriteAck | 1 sink, 2 next block sequence, 3 new random credit token |
| 50, 51, 52 | Cancel, CancelAck, Shutdown | Empty map |
| 61 | OperationFinished | 1 outcome, 0 success / 1 cancelled; Probe also has 2 format, Open also has 2 session |

Other kinds are rejected by this trial's state machine even if framing recognizes them. Hello must arrive first and both sides select major 1; handshake identity is zero, subsequent calls nonzero. ScanFinished must still be followed by a unique successful terminal. Only one operation runs at a time and there are no background extension retries. The current single-block credit is stricter than the design maximum of four; an unpredictable credit token is refreshed after actual acceptance of each output block and cannot be prepaid or replayed.

## Broker, budgets and publication

Source tokens, sinks and per-block credits are random 128-bit values and cannot be reused across operations. The peer receives neither archive nor destination paths. The host returns at most 256 KiB per read within the authorized source range; offset overflow, past EOF, zero length and cumulative reads over 64 MiB fail. It checks the `FileVersion` of the held object and corresponding path before and after each read and before final publication. This reuses the existing identity/time/length fingerprint and does not claim to detect arbitrary concurrent modifications by a same-account attacker who restores all metadata.

Metadata is limited to 1000 physical records and ≤256 KiB total paths and tokens, with unique record tokens. The host strictly validates raw paths against PortablePath; duplicate names retain separate identities. One regular entry is explicitly selected at a time, with declared size ≤4 MiB; directories cannot be file output. The host holds the destination Grant, private Workspace and Stage, meters actual bytes and computes SHA-256 without giving the peer a file handle or publication authority.

Existing safe I/O may publish without overwriting only after all output blocks, FinishOutput count and digest, the unique terminal, Close, normal exit after Shutdown and clean EOF, source identity and final cancellation checks succeed. Any anomaly, duplicate terminal, crash or timeout revokes output first; destruction removes the stage before cleaning the workspace. Existing targets remain unchanged. Parsing and expected digests still come from the extension; host computation cannot prove a malicious extension's output is faithful to the archive.

Handshake is limited to 2 seconds and each trial invocation to 5 seconds total, without progress resetting the deadline. Per-process CPU is limited to 3 seconds, file descriptors to 32, direct file output is disallowed and core dumps are disabled. IPC receive queues hold at most four frames, send queues one, and pipe writes have a 2-second limit. stderr is discarded directly, with a zero budget; untrusted content is not forwarded. Cancellation immediately revokes the sink, gives 2 seconds for cooperation, then kills and reaps the process and pipes; Ack is not permission to publish. These resource budgets constrain a small trial, not a performance promise for ordinary large archives.

## Platform gates

| Platform | Trial policy and failure behavior |
| --- | --- |
| macOS | Fixed `/usr/bin/sandbox-exec` deny-default policy permits the precise private executable copy, system libraries/dyld cache, root loader reads and `/var` metadata. User files, writes, network and fork are denied; the environment is cleared and only stdio inherited. Native rlimits plus 20 ms RSS supervision terminate above 512 MiB or on measurement failure. RSS is sampled, so brief peaks between samples may exceed the threshold; this interface is not promised for future official distribution. |
| Linux x86_64 / aarch64 | Landlock ABI ≥3 handles all v3 file rights, with no write rules and read access only to the executable and system loader libraries. `no_new_privs` and an architecture-checked seccomp syscall allowlist include readv/writev required by Rust standard pipes, while denying socket, fork/clone, ptrace, io_uring and others. CPU/AS 512 MiB and other rlimits apply. Missing rules, ABI, seccomp or required syscalls fail before exec. Only native CI establishes actual results for this platform. |
| Windows and other platforms | Execution is unconditionally refused. AppContainer, Job and handle allowlisting have not been implemented and verified; an ordinary subprocess is not substituted for a sandbox. |

Linux API choices follow the [kernel Landlock documentation](https://docs.kernel.org/userspace-api/landlock.html) and UAPI; future Windows work follows [AppContainer isolation](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-isolation). Native host unsafe code is confined to the sandbox module and documents layouts, call preconditions and failure behavior; pre-exec does not allocate or log. The reference peer adds controlled fork/_exit/waitpid probes only in explicit audit mode; the child does not run Rust cleanup or format logic. Platform regressions first use owned readable/writable markers, an owned localhost listener and self-exec as positive controls, then verify kernel denial of reads, writes, network, direct fork and self-exec against actual marker, file and connection state. Untested platforms are not marked as passed, and desktop third-party execution remains disabled.

## Owned XDP1 example format

XDP1 is only an interoperability fixture and does not replace any real archive format. Four bytes `XDP1` are followed by a `u32 LE` record count. Each record contains a `u16 LE` UTF-8 name byte count, `u32 LE` content byte count, name and uncompressed content. At most 1000 records are allowed, with no trailing data; names and content are read within host budgets. Entry tokens are four-byte LE physical ordinals, with no path-based deduplication. Python fault modes are explicitly selected only in conformance tests to verify unauthorized access, sequencing, replay, duplicate identity, paths, credits, digests, crashes, cancellation and duplicate terminals.
