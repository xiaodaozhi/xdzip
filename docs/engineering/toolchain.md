# Toolchain and platform freeze

Development tool versions are pinned by rust-toolchain.toml, Cargo.lock, CMake and CI; support scope follows the [support policy](support-policy.md). This table defines verification for upgrades and releases. Specific observations remain in issues/Actions; a single machine's tool inventory is not a release dependency lock.

| Item | Current direction | Evidence required for freeze |
| --- | --- | --- |
| Rust | rust-toolchain.toml pins 1.99.0, edition 2024, rust-version 1.99 | On upgrade check dependency MSRV, three-target tests and Clippy; keep toolchain and Cargo configuration aligned |
| Qt | Pinned 6.8.2 SDK; QtNetwork uses `6.8.2-xdzip-network.1`, derived with official security patches. Local SDK under `build/toolchain/Qt/6.8.2/<platform-subdirectory>`; dynamic deployment | Pinned provenance/hashes, module licenses and three-platform smoke; check security maintenance before each release and reverify source and replacement on upgrade |
| C++ | C++17 and Qt-matched compiler | macOS clang, Windows MSVC and Linux compiler versions |
| CMake | Root requires 3.24 or later, using Ninja | Verify actual build version, generated-header dependencies and clean configuration; workflow pins CI tool versions |
| Python | Shared desktop entry requires 3.10+; packaging validation tools use isolated environments | Use the same interpreter for subsequent Python scripts and check pinned tool dependencies per stage; browser design tools are not product build dependencies |
| cxx | 1.0.205; bridge generated at build time, no stable binary ABI | Matching crate/generator versions, shutdown-race and exception-boundary regressions |
| Systems | macOS 14+ arm64, maintained Windows 11 x64, Ubuntu 24.04 X11 x64 | Verify actual environments under approved support policy; do not extend CI host evidence into guarantees for all system versions |

On Windows, desktop builds, Qt source builds and delivered-source rebuilds temporarily use a UTF-8 console code page for MSVC/Ninja and restore the original afterward. Without a console, they create a temporary hidden console for the process and children; external processes must not attach. Guarded builds sharing an existing console serialize using the attached-process list; independent consoles can build in parallel. Processes must remain attached during protection. An invalid process list stops the build; after a 30-second wait, retry is requested. Older scripts without a window handle use incompatible locks, and this coordination does not prevent other programs changing console settings. Before and after building, checks inspect Ninja dependency records for compiled objects. If a source with a direct quoted include or same-directory angle include has no recorded dependencies, stop, retain the old directory and request a new build directory without automatically deleting or reusing objects. Ninja may intentionally omit system headers, so sources using only system headers may have zero dependencies. The check does not cover angle includes resolved via other search paths or all implicit compiler inputs, and does not evaluate preprocessing conditions; it may conservatively reject inactive includes. Direct CMake/Ninja bypasses these entry protections: ensure compiler output matches Ninja's prefix and verify a real header change triggers recompilation after changing code pages or toolchains.

GitHub-hosted Apple Silicon jobs use macOS 15 runners while the product deployment target remains macOS 14.0. A runner upgrade does not establish real-device verification on macOS 14; platform compatibility and manual acceptance are recorded separately.

See the [developer build guide](developer-build.md) for daily preparation, checks and execution. `scripts/desktop.py doctor` checks build by default; `doctor --for-stage package` checks the complete packaging chain in advance. prepare's `--install-rust`, `--install-qt` and `--packaging` explicitly prepare the respective tools and pinned materials. Developers still install system compilers/SDKs; preflight is not an implicit installer.

The fixed local toolchain directory is `build/toolchain/`. Qt SDK, `qmllint` and `qmake` use `build/toolchain/Qt/6.8.2/<platform-subdirectory>`; `aqtinstall` and shared Python tools use `build/toolchain/desktop-tools`; Qt download staging uses `build/toolchain/qt-install-tool`. Shared entry points use these directories instead of separate caches for build, test, package or individual Qt checks. CI using runner temporary directories must pass explicit parameters without changing the local default layout.

Preflight runs Rust/Cargo actually on PATH, verifies pinned versions and native host, and checks CMake, Ninja, Qt prefix and platform tools. An installed compiler unavailable to the current shell is still missing. Packaging also checks Rust locked dependency metadata, Qt SPDX/license materials and schema cache. All subsequent processes use the same checked environment, preventing a successful build followed by missing rustc/cargo during license collection. Missing Docker or Inno Setup affects only stages requiring them and does not block ordinary development builds.

Each record includes version, download source, SHA-256, license, target, owner, verification commit and date. Rust/Qt security updates trigger revalidation; patches no longer maintained are not retained indefinitely. Minimum-system candidates are not formal support commitments.

System maintenance, Qt security update channels and upgrade verification responsibility follow the [support policy](support-policy.md). Record provenance and licensing conclusions under the [release review process](../qa/release-review.md).

Windows main-window client-area extension is implemented by WindowsFrame using public Qt window interfaces and Win32, without linking GuiPrivate. On initial binding to a normal window, it determines the frame from current QWindow client logical dimensions, DPR and native border metrics; subsequent theme or DPI reapplication refreshes only the border. For a PMv2 normal window with no local scaling override and Qt PassThrough rounding, WM_GETDPISCALEDSIZE preserves the pending SIZE's pre-scaling adjustment, scales the client area and adds actual target-DPI borders. Invalid metrics, overflow or other states do not modify SIZE and return control to Qt. Borrowed native messages and writable structures are used only in the synchronous callback. Reverify affected client areas, borders and window states on Qt upgrade or SDK replacement. Physical dual-screen dragging and visuals are checked as needed; programmatic results do not stand in for unperformed physical verification.

Daily CI independently installs the rust-toolchain.toml-pinned Rust version, rustfmt and clippy in a runner temporary directory and checks that the actual compiler resides there before running Rust formatting, avoiding an incomplete host rustup toolchain. Full Rust and signing-tool tests run locally or in the relevant on-demand workflow according to the change.
