# BH containers and the admitted BlakHole profile

`xdzip-codec-bh` reads sequential BlakHole (`.bh`) members from the host-owned source. The product profile is intentionally narrow: it requires the `BH 05 07` prefix, the observed fixed header constants, ordinary-file metadata, exact packed and decoded sizes, and the IEEE CRC-32 declared by each member. Members are retained in physical order, so duplicate names remain distinct and the frozen row identity is independent of display-name decoding.

The only payload method admitted by this implementation is method 8, raw RFC 1951 Deflate. The shared bounded Deflate reader requires a complete stream and exact compressed-span consumption; trailing bytes, truncated streams, decoded-size mismatches, and CRC mismatches fail the payload task. Unknown methods remain visible with a warning and cannot be extracted or counted as verified content.

The header layout currently admitted is the five-byte fixed prefix followed by a 16-bit little-endian header length, constant bytes `25 d8 0c 00`, method, a four-byte DOS-shaped timestamp, packed size, decoded size, CRC-32, attributes `0x20`, five zero reserved bytes, a four-byte filename length, and the filename bytes. The header length must equal `37 + filename_length`; members are contiguous and the final payload ends exactly at physical EOF. No archive trailer, directory record, SFX prefix, resynchronization, padding, or neighboring-file scan is accepted.

BH has no public maintained specification. Format observations are pinned to `ashang/libxad`'s `support/formats/BLAKHOLE.TXT` (revision `dbe67a865207e49cd917ad9170a11b9eaa83998a`, SHA-256 `fdb2b4d2fffa7760eef4b3ccbabdcd6b2d43df33949a1b793f9efb7e4c2c0f2d`) and Hawkynt/CompressionWorkbench's `docs/BLAKHOLE-ON-DISK.md` (commit `ab61c59f789d82c628d3c5b4bac264afbdc0c7a7`, SHA-256 `f79f66d98d6c922ea4b64bde3ff5540a4d894de6632375513f3db89876e27bca`). The latter is a single provenance-bearing five-member sample, so it does not establish Store, encryption, directories, solid blocks, or volume behavior.

IZArc Command Line Add-On v1.1 was retained as a build-only reference. The official download publishes MD5 `9002c7634768e5336244f9accb2223b0`; the local `IZArcCL.exe` SHA-256 is `959050AFC513C64FD61F9EE15837054D0FAEE5EFB98C9107B4DC5D9A528A62D4`. Its extracted `IZARCC.exe` and `IZARCE.exe` both terminate with Windows `0xC0000005` before producing output in this environment, so no Store, compression-level, password, or extraction claim is based on that tool. The reference remains under `build/toolchain` and is not a product dependency.

BH is read only. Creation, modification, encryption, multi-volume archives, and a dedicated Linux MIME registration are outside the admitted scope. The format registry and the [archive-checking contract](archive-checking.md) describe this exact boundary; a `.bh` suffix is an entry candidate, while complete content validation remains authoritative.
