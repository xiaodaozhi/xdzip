# WP-11 TAR/GZIP 实现契约

状态：已实现，平台验证结果以本地／CI 工件为准，桌面人工验收仍待系统权限。沿用 [M3 安全解压](m3-extraction.md)与 [WP-10 创建](m4-creation.md)的输入授权、暂存、冲突、取消及整体提交。

## 范围与能力

目标为 TAR、TAR.GZ 浏览、创建和安全解压。TAR 为容器，GZIP 为一层压缩过滤器，按内容探测，不按后缀选择读取后端。ZIP 行为保持兼容。当前不启用独立 GZIP 单文件创建、嵌套自动展开、加密或分卷 TAR。

TAR 接受普通文件与目录，解析 PAX 路径及 GNU 长名称。符号链接、硬链接、设备、FIFO、稀疏和未知类型不能解压。所有输出名称继续经过 PortablePath 与宿主冲突预检，格式库不获得文件路径或 unpack 权限。目录权限、所有者与特殊 mode 不恢复。日期作为展示元数据，不承诺恢复。

## 有界流式处理

完整扫描后才发布索引，扫描期间条目数与总量未知。元数据沿用 100,000 条、单名称 4096 字节及累计名称预算；流式来源的编码输入和解码工作各最高 24 GiB，单个 GNU／PAX 扩展头最多 64 KiB，每条最多四个扩展头。全局 PAX、GNU 长链接与稀疏变体不在本轮能力内，明确拒绝。常见的前置 ./ 在 TAR 名称中规范化，根目录标记不作为输出项。顺序流的读取与跳过同样检查取消和字节预算，不以 seek 绕过损坏流检查。GZIP 必须读至 EOF 验证 CRC 与 ISIZE，多 member 仅作为同一连续 TAR 字节流；尾部非零垃圾、截断及损坏均失败。拒绝未经验证的部分索引。

解压按物理顺序处理选择，跳过未选内容仍计量并可取消，不承诺随机读取。PayloadReader 只获得来源与宿主 sink；来源版本在扫描、解码和提交边界仍由宿主验证。每条提交和整体创建失败语义沿用现有安全 I/O 契约。

## 创建与界面

创建窗口启用已有 TAR、TAR.GZ 分段，不改变窗口密度。格式切换同步扩展名；TAR 禁用压缩级别，两个 TAR 格式都禁用密码及分卷并清空相关值。TAR.GZ 使用 GZIP 0／1／6／9 级别。逐条压缩后大小未知，显示为横线，不伪装成 0 字节。主窗口格式标记按真实格式和文字宽度自适应，TAR 日期以 UTC 展示，日期超出既有显示范围时保留未知。创建冻结输入树、流式写入、终止 TAR/GZIP、重新扫描及逐项解码校验，验证成功后才整体发布。冲突改名保留完整复合扩展名。

## 验证与限制

必须覆盖系统 tar／Python tarfile 双向互操作，长路径、Unicode、空目录、重复项、PAX/GNU、特殊项、路径逃逸、截断、CRC、资源限额、取消及旧文件保护；Qt 真实创建、重开与解压复用现有任务和冲突窗口。实际证据只生成到 build/ 或 CI 工件。

本轮 macOS 桌面人工验收受系统 Computer Use 权限阻塞，未登记为通过；原生自动化与离屏检查不能替代该项。独立安全审查另行登记，不随开发测试通过自动完成。
