# ASAR container contract

English | [简体中文](../zh-CN/engineering/asar-containers.md) | [繁體中文（台灣）](../zh-TW/engineering/asar-containers.md)

The format follows Electron's [ASAR description](https://github.com/electron/asar#format) and Chromium's [Pickle contract](https://chromium.googlesource.com/chromium/src/+/main/base/pickle.h). An eight-byte size Pickle precedes a Pickle string containing a JSON directory tree; stored file offsets are decimal strings relative to the payload area. Each tree entry retains its own identity even when files share the same stored bytes. Optional integrity declares SHA-256 for the complete file and each fixed-size block. These declarations are corruption checks, not package or application authentication.

## Admission and identity

Validate all four little-endian length words, four-byte alignment, exact string length, zero padding and source bounds before parsing the tree. Limit the header to 8 MiB, nesting to 64 path components, node count and owned name bytes to the common scan limits. Use bounded general JSON parsing with duplicate-key rejection and preserved object order. Reject malformed UTF-8, invalid field types, nonintegral/unsafe sizes, overflowing decimal offsets and unknown required profiles. A name component must not gain safety by joining it to a prefix. Keep unsafe original names visible with unsupported/warning flags and let the host refuse their output.

Assign physical identities in JSON tree order, including explicit directories and empty files. The root object is structural. Preserve separate entries for exact shared payload ranges; refuse partial overlaps, ranges outside the authorized source and unreferenced trailing data. A file without an integrity declaration provides only structure and readability checks. Validate a present declaration completely, including digest width, algorithm, block size/count and the empty-file rule; do not silently ignore unsupported declarations.

## Read-only export and verification

The backend receives an authorized seekable stream and a host sink. It opens no other path, follows no link and runs no application. `unpacked` records are visible but unsupported: an adjacent `.asar.unpacked` directory is not an input grant. Declared links remain unsupported, with their record identity preserved. The executable flag grants no mode restoration or execution. Passwords, volumes, creation and rewriting are outside this profile.

Reparse the complete header before payload use and compare the projected index with the immutable host snapshot. Retain bounded offsets and optional digests privately. Read stored ranges incrementally under cumulative input, decoded-byte and cancellation limits. Check complete-file and block SHA-256 before reporting payload success, including empty files. Output may enter private staging while checks run; only the host can publish verified files. SHA-256 work counts actual 64-byte compression blocks, including padding. Input, delivered bytes and hash work have separate private 24 GiB ceilings; host task limits may be stricter, and rereading shared ranges refunds no credit. Errors are terminal for the opened reader. Source identity checks remain best-effort mutation detection, not an atomic or authenticated snapshot.

Registration requires owned inputs generated or independently read by the pinned author tool, covering directories, empty/UTF-8 files, shared payloads, absent/present multi-block integrity, external records and executable declarations. Regressions cover duplicate JSON keys, arithmetic, alignment, truncation, overlap, invalid digests, unsafe names, source changes, exact quotas, cancellation and output failure. Actual runtime/CLI/Qt tasks and affected candidate/read-only/check-note/layout behavior use automation. Reference tools and generated evidence stay under `build/`; test inputs and generator source remain versioned. Progress and actual acceptance belong in the delivery issue.
