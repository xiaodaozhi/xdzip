# Zstandard stream contract

English | [简体中文](../zh-CN/engineering/zstandard-streams.md)

The wire profile follows [RFC 8878](https://www.rfc-editor.org/rfc/rfc8878.html), the author's [format 0.4.3](https://github.com/facebook/zstd/blob/v1.5.7/doc/zstd_compression_format.md), and the [XXH64 specification](https://github.com/Cyan4973/xxHash/blob/v0.8.3/doc/xxhash_spec.md). Product algorithms are independent Rust implementations. Independent reference libraries/programs generate owned test content only; they never enter product dependencies. Host authority and publication follow [single-file streams](single-file-streams.md).

## Frame and resource admission

Validate standard magic, reserved bits, window calculation, optional dictionary identifier, optional content size, block types/sizes, terminal block and optional low 32 bits of seed-zero XXH64. Ignore the specified unused header bit when reading and write it as zero. A zero dictionary identifier does not request a dictionary; nonzero identifiers and references requiring external history are unsupported. Neither a header nor archive content grants another pathname or execution authority. Single-segment frames must also pass the window budget before allocation.

Window history is bounded at 64 MiB within a 128 MiB working limit. Blocks decode at most the smaller of the window size and 128 KiB. Checked arithmetic must precede allocations, indexing and copies. Raw, RLE and compressed blocks use the same decoded accounting. Concatenated standard frames and skippable frames are admitted within physical input, task byte budgets and cancellation; require at least one standard frame. Per-frame block and total frame/skippable counts are bounded at 100,000. Discovery uses at most 8 MiB of compressed input and a 512-byte decoded prefix. Strong frame or TAR identification cannot downgrade after damage. Full scanning validates termination and every declared size/check before publishing an observed virtual row.

## Entropy and sequence processing

Read reverse bitstreams from their nonzero end marker with exact consumption. FSE normalized counts, zero runs, table logs, symbol bounds, state transitions and table reuse require explicit validation. Huffman weights, implied final weight, complete prefix space and one/four-stream literal boundaries must agree with observed output. Repeat entropy tables and repeat offsets reset at frame boundaries and retain only format-defined state between blocks. Sequence literal lengths, match lengths, offset extra bits, repeat-offset zero-literal adjustments, overlap and accessible history are checked before output. Reject impossible or incomplete states and poison readers after failure. Terminal host I/O errors, cancellation, limits, invalid data and unsupported profiles retain their classifications.

## Creation and product integration

An admitted writer must use real compressed sequence blocks for compressible ordinary content, rather than completing the feature with only raw/RLE blocks. Offered levels select bounded match-search effort and each must decode independently, including empty, incompressible and multiple-block inputs. Emit content XXH64 and only format-valid raw fallback. Start another standard frame before exceeding the per-frame block policy, resetting history, offsets, entropy tables and checksum together. Input and output buffers are admitted before writing, and completion remains explicit.

Ordinary Zstandard accepts one regular file; TAR.ZST uses the shared TAR parser/writer. Registration requires matching host, actual CLI and Qt automatic checks, including frozen-source rechecks, cancellation, exact byte quotas, staging, failure cleanup and final publication. Creation methods and levels come from the shared format registry. These profiles gain no passwords, volumes or rewriting. Checking uses `format_declared_checks`, because input frames may omit content checksums. Generated execution evidence remains under `build/` or CI; actual platform coverage and release approval are separate.

The bounded writer uses 128 KiB independent match-search blocks, raw literals, normative predefined FSE tables and explicit non-repeat offsets. It reuses the four-byte hash-chain matcher with LZ4, with at most 65535-byte distances and search depths 1/16/64 for levels 1/6/9. Incompressible blocks use raw fallback and uniform blocks may use RLE. The frame declares a 128 KiB window, omits content size and always includes XXH64; the host still validates exact frozen input length. A frame closes after at most 65536 blocks, and another begins only when more input arrives. These writer choices do not narrow the reader's admitted Huffman, FSE, repeat or window profiles.
