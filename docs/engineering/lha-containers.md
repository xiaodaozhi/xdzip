# LHA wire and algorithm contract

English | [简体中文](../zh-CN/engineering/lha-containers.md) | [繁體中文](../zh-TW/engineering/lha-containers.md) | [日本語](../ja-JP/engineering/lha-containers.md) | [한국어](../ko-KR/engineering/lha-containers.md) | [Français](../fr-FR/engineering/lha-containers.md)

LHA/LZH and historical LArc are a family of sequential member containers. A filename extension, recognizable method string or successful Store member does not establish decoding support for another method. The raw primitives in `xdzip-compression` receive an admitted packed span and an independently validated decoded size, without filesystem, process, filename or publication authority. Product registration and container admission require the separate acceptance below.

## Sources and reference boundaries

Its pinned Git blob is `b09a87759e4cee9c99f69616b2e975493253d412`. The repository commit is `16619b066b189ef289bb8b07b37d1c38d550da99`.

That document is not a complete compressed-bitstream specification. Limited observations of the same original author's sources supplement field widths and historical behavior: [huf.c](https://github.com/jca02266/lha/blob/16619b066b189ef289bb8b07b37d1c38d550da99/src/huf.c), blob `15f90e1bb3079f6c11d852b9cb8a86fc7f240c35`, for static-tree alphabets; [slide.c](https://github.com/jca02266/lha/blob/16619b066b189ef289bb8b07b37d1c38d550da99/src/slide.c), blob `5dd5f9863993a6f4eda7398ecf4fe6f4ad7a711b`, for default space-filled history and the separate broken-archive repair mode; [larc.c](https://github.com/jca02266/lha/blob/16619b066b189ef289bb8b07b37d1c38d550da99/src/larc.c), blob `c6f8f1ca111705a11dd744ac01e458e95377366d`, and [lha_macro.h](https://github.com/jca02266/lha/blob/16619b066b189ef289bb8b07b37d1c38d550da99/src/lha_macro.h), blob `5c207426d0450468857187f5d74a675d695e3cc2`, for LArc fields and absolute-reference origins. No strict clean-room claim is made. Rust state, bounded shared prefix decoding, error handling and resource admission are independently expressed; reference source is not copied, translated or compiled into the product.

[jLHA](https://github.com/umjammer/jlha/tree/0a6348d96e9bbb1ac5ee8b3f6ff1c2c75b17d0d9) 0.0.11, [Lhasa](https://github.com/fragglet/lhasa/releases/tag/v0.6.0) 0.6.0 and 7-Zip 26.06 are independent test references. Their fixed identities and public API harness are recorded with the [owned fixtures](../../tests/fixtures/lha/README.md). Java algorithm source is not used as product code. Reference method coverage and default-history disagreements remain distinct from successful byte comparisons. Reference libraries and tools stay under `build/toolchain/` and outside production dependency closures.

## Container framing requirements

`xdzip-codec-lha::inspect` implements the level-0/1/2/3 framing below; `LhaCodec` projects physical entries and `Reader` performs bounded payload decoding independently of Qt. Runtime, CLI and Qt expose the `LZH` format, with `.lha` and `.lzh` as opening and association candidates. A suffix or family marker is only a proposal: complete metadata must pass before publication. Strong valid TAR, ZIP, optical and SFX discovery retains priority; a raw TAR marker alone may be disambiguated by complete LHA validation. Creation admits LH5 levels 1/6/9 with level-2 headers; eligible level-2 archives can be rewritten. Metadata reads are capped at 64 MiB, physical records at 100,000, chained extensions at 256 per member and accumulated level-1 and level-3 headers at 1 MiB. Caller name and entry limits remain binding. Level-0 CRC omission is represented explicitly; unknown OS-specific base tails, unsupported extension kinds and header levels are not interpreted as ordinary supported data.

Each physical member consists of a header and its exact packed range. A zero terminator ends the archive; trailing data, missing termination, impossible ranges and malformed later members cannot publish a partial index. Levels 0 and 1 retain their byte-sized base-header sum and DOS-shaped timestamp. Level 1's skip size includes chained extended headers and must be reduced by their exact total before the payload range is admitted. Level 2's little-endian total header length bounds all its extensions and uses Unix seconds. Fields and extension links must be checked before arithmetic, allocation or seeking. A declared extended header CRC is calculated with its own CRC field zeroed, separately from the payload CRC. Header extensions and comments grant no adjacent-file, permission or execution authority.

Level 3 uses the fixed little-endian size-field width 4 at offset 0, a 32-byte base, total header size at offset 24 and the first 32-bit extension size at offset 28. Each extension ends in a 32-bit next-size field. It retains 32-bit packed/original sizes and Unix seconds; the wider header does not automatically grant 64-bit file sizes. Total header length is admitted against 1 MiB before allocation, with at most 256 extensions; malformed minimum sizes, overflowing/out-of-header links and extra tails fail. Fields are based on the original author's [level-3 header comments](https://github.com/jca02266/lha/blob/16619b066b189ef289bb8b07b37d1c38d550da99/src/header.c), Git blob `df8ae5e3f9dece45325d499cf63c34fc2bb0ec99`. Its README cautions that the historical level-3 specification was not fixed; the admitted common extensions are separately demonstrated by jLHA and Lhasa, without claiming every historical extension.

An exactly 256-byte-aligned level-2 header would start with a zero byte and conflict with the terminator. The original author's documented workaround permits exactly one zero padding byte in that case, included in the total size and header CRC. Other header tails and nonzero padding are rejected. This is validated with an independently encoded 222-byte filename, without truncating its name to accommodate a reference tool's legacy path limit.

Resolve archive names independently of output authorization. Preserve physical order, duplicates and raw names. Resolve legacy encoding before interpreting a backslash as a separator, so a multibyte trail byte cannot invent a directory. Extended filename and dirname fields have explicit uniqueness and composition rules; ambiguous duplicate declarations fail rather than select a convenient spelling. Directory and special/link records cannot be treated as ordinary files. Raw Unix modes are metadata, never permission restoration. Existing source freezing, portable-path preflight, selected-entry identity, private staging and final publication remain host responsibilities.

Raw names preserve dirname bytes, their `0xff` separators, filename bytes and the exact boundary between these fields. Sample complete dirname components and the filename independently using the shared bounded legacy detector; separator bytes cannot contaminate encoding detection or complete a multibyte character across fields. Decode each field strictly before normalizing actual decoded backslashes and composing `/` separators. Apply suspicious-path checks to each component and the final name. Raw names, effective names and escaped display retain their shared limits and cancellation. The same frozen effective name is used by directory expansion, selected extraction, preview and export. Unknown methods, undecodable or suspicious names, links, special types and contradictory directory declarations remain visible with a warning and cannot emit payloads. Unix modes confer no permission restoration.

The product admits Store (`-lh0-`, `-lz4-`), LH1–LH7, LZS and LZ5; PMA methods remain outside product admission. Entry method IDs are scoped to LZH and are not ZIP method numbers. Checks use `format_declared_checks`: present header/payload CRCs must pass, but an ancient level-0 member without a CRC provides structure, size and readability only. LH2 requires a payload CRC for finite-variant admission. Passwords, volumes and repair profiles are unsupported. One zero byte is an empty archive; a malformed later record cannot produce a successful partial list. Opening scans names and framing, while a check or extraction actually decodes content and validates its declared checks.

Store markers `-lh0-` and `-lz4-` require equal packed/decoded sizes. Historical `-lz4-` has no relationship to modern LZ4. `-lhd-` declares a directory. Method families LH1–LH3, PMarc, extended headers, passwords and volumes each require their own validated profile and independent samples; neither an extension nor a generic Huffman/LZW implementation supplies those capabilities automatically. Unknown methods must remain distinguishable from decoded regular files. Framing validation does not validate payload content.

## Static LH4–LH7 primitive

`LzhReader` implements MSB-first blocks of 1–65535 literal/match commands. LH4 and LH5 use position alphabet 14 and a 4-bit tree count; LH6 uses 16 and 5 bits; LH7 uses 17 and 5 bits. Their dictionaries have 12, 13, 15 and 16 address bits respectively. This distinguishes dictionary capacity from the broader encoded position alphabet; out-of-dictionary distances fail.

The 19-symbol code-length tree describes a 510-symbol literal/length tree. Their count fields have 5 and 9 bits. Short-tree lengths use three bits with a bounded unary extension, and the length tree supports its three specified zero runs. Count zero selects an explicitly bounded singleton without consuming symbol bits. Ordinary canonical trees must be complete, nonempty, nonoversubscribed and no deeper than 16 bits. Symbols 0–255 are literals, 256–509 mean lengths 3–256. Position zero means distance one; other positions use a leading power of two plus their low bits. Overlapping copies retain history across blocks.

The initial dictionary contains spaces, following ordinary original LHa behavior. No zero-filled broken-archive repair fallback is attempted. The known decoded size must end exactly at a command and block boundary, and the reader must consume the entire admitted byte span. Unused bits in the final byte are ignored; additional whole bytes, truncation, zero command counts and output overruns fail. An empty decoded member requires an empty packed span. CRC-16 verification belongs to the container.

## LH1–LH3 primitives and LH2 variants

`LhDynamicReader` implements LH1's 314-symbol adaptive model, 4096-byte dictionary, lengths 3–60 and fixed canonical upper bits of distance minus one; its lower six bits are explicit. LH2 uses 286 initial symbols, symbol 285 plus an 8-bit extension for longer lengths, an 8192-byte dictionary and a position alphabet that grows after each crossed 64-byte output boundary. Out-of-range extended lengths fail. Both retain space history and exact sizes/spans. `LzhReader` additionally accepts LH3's 286-symbol per-block tree, optional transmitted or fixed 128-symbol position tree, the three-length singleton sentinel and the same 8-bit length extension. Zero blocks, invalid sentinels and incomplete/oversubscribed trees fail.

The general sibling-property update is independently expressed using stable node identities, explicit ranks and subtree exchange. Rebuilding halves positive leaf weights upward, preserves their current rank order and merges two sorted queues. The reconstructed root is taken from the completed merge, independently of the root identity used before growth. Actual comparisons, swaps, rebuilding and initialization are charged. The theoretical basis is [Vitter's analysis of FGK](https://www.ittc.ku.edu/~jsv/Papers/Vit87.jacm.pdf), section 2; wire-specific alphabet, fixed-position and threshold facts are observed in pinned [dhuf.c](https://github.com/jca02266/lha/blob/16619b066b189ef289bb8b07b37d1c38d550da99/src/dhuf.c), Git blob `bcb08bdccf6c6396938e3b2d9b6b032a991aa26e`, and [shuf.c](https://github.com/jca02266/lha/blob/16619b066b189ef289bb8b07b37d1c38d550da99/src/shuf.c), blob `2c18ed6a909cfa7fd1d591af1e7f0bd90e269fd7`. This extends the source-observation disclosure above, without translating their implementation structures.

Original Unix LH2 leaves its initial singleton position weight unchanged and counts position updates separately. jLHA updates the singleton through its generic model. These produce incompatible real bitstreams under the same `-lh2-` marker. Raw APIs expose an explicit `Lh2Variant` selector; general method-2 constructors use the jLHA counter convention. The container requires a declared CRC for LH2 and validates both finite variants completely into non-output sinks. Invalid structure or CRC can eliminate a variant; source, cancellation, quota and host failures terminate immediately. All probes retain actual input, decoded and auxiliary work charges. Successful variants must have equal decoded sizes and SHA-256 digests, or the result is ambiguous and unsupported. A uniquely valid or identical result is decoded again for output and must match its selected digest and CRC. These hashes bind probe and delivery bytes, not archive authenticity. No candidate bytes are published or reused as output credit.

The original C file is unmodified, hash-pinned and compiled only as a test oracle under `build/toolchain/`, with an owned bounded host harness. Stress generation invokes the original test-only encoder/growth state within that reference build; it is not transplanted into the product. Varying-distance samples cross both character and position rescaling thresholds for each variant. One owned LH2 stream is generated through public generic tree APIs with the original singleton convention and independently read in full by the author decoder. Reference disagreements, including original Unix failing jLHA's long/space profiles, are recorded as such rather than repaired or counted as passes.

## Container creation and publication

Creation uses method `lh5`, levels 1/6/9 and level-2 headers for `.lzh` or `.lha`; the default desktop suffix is `.lzh`. The host creation-method ID is 259, distinct from the LZH entry's scoped method ID 5. Store, passwords, solid grouping, and volumes are unsupported for creation. Input is at most 100,000 frozen records, 16 MiB of names and 24 GiB of actual reads; headers total at most 64 MiB. A member's original and packed lengths must each fit unsigned 32 bits, and Unix modification seconds must fit unsigned 32 bits without truncation. Output is bounded by 24 GiB and ordinary files retain a cumulative raw-encoder work ledger across members. CRC processing covers actual admitted source bytes once and remains bounded by the input and header limits. A completely exhausted read budget can conservatively fail before the final EOF probe.

Only portable ordinary files and directories are accepted. Directories use `-lhd-`, zero sizes and zero payload CRC; regular files use LH5 even when a small or incompressible input expands. Names are UTF-8 in separate filename and `0xff`-delimited dirname extensions. Common-header CRC and per-file CRC-16 are always emitted. Exactly aligned level-2 headers retain the required single padding byte. Reading a validated directory during verification succeeds without emitting bytes or granting directory or permission authority.

UTF-8 here is an undeclared naming convention, not a universal Unicode flag. The owned jLHA public-API harness explicitly selects UTF-8 and checks complete paths independently of payloads. Legacy Windows readers may instead use their OEM code page and display different names even when every byte and CRC passes. The inspected original 7-Zip [LZH name projection](https://github.com/ip7z/7zip/blob/main/CPP/7zip/Archive/LzhHandler.cpp), Git blob `1b6e3b9d9905abe28b53e39b1267465fe2fc7f03`, selects `CP_OEMCP`; this source observation explains the reference limitation without adding its implementation to the product. No universal filename interoperability claim is made.

The codec receives frozen source indices and an empty private seekable staging output. It first validates every record's bounds, then streams content and CRC, finalizes its raw encoder, patches packed size and CRC, and restores the sequential endpoint before the next member. Unsupported random writing or any source/output/limit/cancellation failure aborts without a successful terminator. No final path or commit authority enters the codec. Host verification compares LHA's frozen effective names with input names, while other containers retain their original raw-name comparison; it actually decodes all content before the existing frozen-source recheck and atomic publication. Failed verification, source mutation or cancellation retains any old target and cleans private staging.

`scripts/check-lzh-creation.py` independently parses and checks generated level-2 fields, boundaries, UTF-8 names, timestamps and both CRCs, then compares complete multi-member contents through pinned jLHA, Lhasa and 7-Zip. Directory/name results and payload results are recorded separately. Runtime, CLI and Qt creation, reopening, checking and extraction remain separately automated; a raw-writer roundtrip does not substitute for those entry points.

Existing level-2 LHA/LZH archives are editable when all members have a declared content CRC and pass name, record and payload admission. Retained data is copied in packed form. For a changed path, preserve the original method, sizes, timestamps, attributes and admitted non-name extensions, regenerate the UTF-8 name extensions and update the common header CRC. New files use the LH5 writer. Headers at levels 0, 1 and 3 are browseable under the read profiles. See the [archive modification contract](archive-transfers.md).

## Raw LH5 writer

`LzhWriter` is a bounded raw encoder, separate from product creation admission. It retains an 8192-byte history across 32768-byte input blocks and emits real length-4–256 matches through the shared four-byte hash chains. Levels 1/6/9 search 1/16/64 candidates, with distances capped at the LH5 dictionary rather than the match finder's broader capacity. It emits complete canonical trees: C symbols 0/1 have length 8 and the remaining 508 have length 9; the two used length symbols each have length 1; position symbols 0/1 have length 3 and the remaining twelve have length 4. This deliberately bounded fixed-tree strategy does not claim optimal entropy coding or Store fallback. Command counts are actual counts, intermediate blocks are not byte-aligned, and only the final partial byte is zero-filled. Empty input emits no packed bytes.

Admission is 1 MiB for actual hash chains, bounded input/history, at most 32768 four-byte commands, output buffering and control state. Actual hash initialization, seed/lookups, candidate comparisons, copies, bits and output attempts consume a cumulative 96 GiB work ledger; input and packed bytes each have a 24 GiB cap. Callbacks cover at most 8192 work units and writes accept at most 8192 input bytes. `finish_with_work()` retains the remaining ledger across members. Short writes and bare interruption retry without duplicating bytes; typed interruption, cancellation, output and resource failures terminate the instance. No sink path or publication authority is exposed. Nonfinal `flush()` preserves one continuous bitstream; successful completion still requires `finish()`.

The explicitly invoked `scripts/check-lzh-writer.py` exports owned raw-writer output with independently constructed test-only level-0 framing, and compares all bytes through pinned jLHA, Lhasa and 7-Zip, including 7-Zip's CRC test. Empty, one-byte, all-byte, space, deterministic random, long and exact-window repetitions cover each level. This establishes raw interoperability; product container writing, name metadata and atomic host publication require separate tests.

## LArc primitive

`LarcReader` separately selects LZS or LZ5. LZS has a 2048-byte space-filled ring, initial write index 2031, MSB-first literal flag, 8-bit literal or 11-bit absolute reference followed by a 4-bit length minus two. Match lengths are 2–17. LZ5 has a 4096-byte ring, initial write index 4078, eight LSB-first flags per byte, and byte-aligned literals or two-byte absolute references with lengths 3–18. Absolute indices are not relative distances, and neither method reuses Stac LZS framing.

LZ5's initial ring contains thirteen repeats of each byte, then ascending bytes, descending bytes, 128 zeroes and 110 spaces. The remaining eighteen unwritten slots have incompatible historical defaults; reading one before it has actually been written is rejected. This makes the admitted result unambiguous without choosing a repair variant. Source/destination overlap and ring wrap retain normal byte-by-byte semantics. Final flag or subbyte fill is ignored only within the exact last consumed byte; a complete extra byte is rejected. Known output sizes and CRC checks remain mandatory at container level.

## Resources, failure and acceptance

All raw readers cap packed and decoded sizes separately at 24 GiB and cumulative work at 96 GiB units. LH4–LH7 admit dictionary size plus 64 KiB; LArc admits dictionary size plus 32 KiB, covering history initialization flags, input buffering and control state. Smaller caller limits remain binding. Bit fields, tree construction, repeat expansion, dictionary initialization and output consume work before use; `work_remaining()` permits a container to retain one actual-work ledger across members and failures. Memory and field counts are admitted before allocation, and reads return at most 8192 bytes.

LH3 uses dictionary plus 64 KiB; dynamic LH1/LH2 conservatively admit 192 KiB. A payload instance shares hard 24 GiB actual-input and decoded-work ledgers and a 96 GiB algorithm ledger across members, repeated requests and LH2 probes. Metadata rescanning is included in its input ledger. LH2 additionally admits at most 24 GiB of actual SHA compression-block bytes, including final padding, and reports these through auxiliary-work admission. Discarded candidates consume decoded work through `charge_skipped`; final delivery uses ordinary writes and gains no prepaid credit. Source and scan snapshots are compared before any payload, and any final error poisons the payload instance.

Cooperative callbacks cover bounded work even without new source reads. Only bare `Interrupted` I/O retries; typed interruptions retain their error object and terminate. Source, work, cancellation, malformed data and sink failures never authorize fallback or reuse of partly updated state. A caller must drain to EOF, verify the declared payload CRC and retain output privately until success. These CRC-16 values detect accidental corruption, not authenticity or password verification. The shared reflected polynomial is `0xa001`, initial value zero, without a final xor.

`FORMAT-LHA` in [acceptance requirements](../../developers/qa/acceptance.md) separates raw interoperability, container validation and actual runtime/CLI/Qt integration. No primitive test establishes product entry points, write support, passwords, volumes, another platform or release approval. Reference results and work-package progress belong in issues and generated evidence under `build/` or CI.
