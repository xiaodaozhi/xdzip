# Built-in format declarations

The built-in declaration source is [archive-formats.json](../../specs/engineering/archive-formats.json). It records stable format identifiers, labels, container families, outer compression, existing private worker identifiers, supported method families, creation suffixes and entry-point candidates. Method families summarize the corresponding format contracts; they do not promise every parameter, historical variant or combination. Actual records, host policy and platform capabilities narrow the declaration before an operation starts.

Run `python3 scripts/generate-format-registry.py` after changing the specification. It generates the Rust codec descriptors, C++ drag-and-drop/Shell candidates, JavaScript UI choices and Python installer icon mappings. `--check` rejects missing or stale output without changing files. `python3 scripts/test-format-registry.py` checks contradictory capabilities, duplicate identifiers/suffixes, invalid generated-language values and stale consumers. Routine CI runs both checks.

The registry grants no file, output or execution authority. Reader detection and container validation still use bounded authorized streams; a suffix or MIME type only offers an entry point. The host independently validates output basenames, task settings, source identities and publication. Read-only formats cannot gain creation or rewriting by registering another extension. The existing private worker identifiers remain unchanged, and descriptors do not load external backends or negotiate third-party extensions.

Entry-point candidates distinguish drag-and-drop from Shell menus where required. Ordinary `.gz` now offers both entry points and single-file creation; `.tar.gz` and `.tgz` keep their TAR container semantics. XPI/APK/IPA/CBZ candidates retain ZIP validation and admitted profiles. See [single-file streams](single-file-streams.md). Split-volume spelling and source authorization remain governed by [archive opening](archive-opening.md); the registry does not reinterpret numbered files. Windows uses final-extension icon mappings, so `.tar.gz` uses the `gz` association.

Add only implemented declarations with matching automated acceptance. Source changes update the [in-house format contract](independent-rust-codecs.md), [format-worker contract](native-codecs.md), user capability documentation and [acceptance entries](../qa/acceptance.md) as applicable. Keep plans, progress and execution conclusions in issues, and generated test evidence under `build/` or CI artifacts.
