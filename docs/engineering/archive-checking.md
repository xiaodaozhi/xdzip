# Archive integrity checking

The toolbar's “Test” action performs one real background check of an eligible current archive, covering all physical records, including duplicate names, directories, and empty files, regardless of current directory, search, or selection. Whole-archive checking is not currently supported for archives using the disk index; see [large archive indexing](large-index.md). The check holds only frozen input sources and metadata. It obtains no destination authorization, creates no staging or output files, and does not use extraction path mapping or link publication.

## Formats and results

ZIP/ZIP64, Store/Deflate, supported numbered volumes, and PKZIP volumes are decoded entry by entry into a bounded discard sink. Checks cover central-directory and local headers, descriptors, sizes, exact compressed-stream termination, CRC, and supported AES-256 authentication. ZIP symbolic links with safe names have only their payload checked; targets are not interpreted and links are not created, so platform link-output restrictions do not apply. Unknown methods, encryption, unsafe names, and other unadmitted records still fail; they are not skipped before claiming the archive passed.

7z and RAR use independent Rust backends in isolated workers and decode each physical entry into the same bounded discard sink, validating decoding termination, declared size, and checks actually supplied by the container. Other data decoded inside a solid block to reach the current selection counts as work only; it does not increase the current file's verified count. Directories, empty files, and encrypted entries cannot be skipped before reporting whole-archive success. Legacy RAR, RAR5, and new RAR 7 algorithms are accepted using independent known-content samples; identical magic alone does not establish version compatibility.

CAB uses an in-house Rust container and shared algorithms in an isolated worker, validating the volume set, actual decoded sizes, and checks supplied by complete data frames. ISO/UDF checks descriptors, directories, data extents, and declared sizes and actually reads all supported regular files. They generally have no per-file content checksums and cannot detect arbitrary content tampering that preserves structure. Image links, devices, and other unsupported records cannot be skipped before claiming whole-archive success. Hybrid-image checks use the frozen UDF namespace and do not fall back to ISO after failure.

TAR and TAR.GZ rescan the complete stream sequentially inside the check task against frozen physical-record metadata, checking header checksums, lengths, two end blocks, and the tail. TAR.GZ continues to EOF and verifies GZIP CRC/ISIZE; it does not extract all content a second time after the complete scan. TAR has no file-content checksum and can establish only format structure and readability, not arbitrary structure-preserving content tampering. TAR links, special objects, and sparse files remain unsupported. This feature does not establish source trust or check for malware.

The first structural, payload, source, resource, or unsupported-entry error ends the task. Results distinguish success, failure, and cancellation, show counts of verified and unchecked files, and retain the failed entry and stable error code. Every physical record is checked, but `files`/`verified_files` count only non-directory files, including empty files. Directories and directory-only archives must also complete structural validation before success. Reads completed during or before checking do not mean the whole archive passed.

## Scheduling, source, and resources

`Check { session }` freezes the source through `Source::fork()`, format, metadata, and original session identity, then enters the same bounded heavy-task queue and application-level serial admission as creation and extraction. At start, after reading, and before a successful terminal state, recheck the source handle and every volume path's identity, size, and time information. A source change returns `source_changed` and invalidates only the corresponding original session. This is best-effort detection, not an atomic input-content snapshot, and does not promise to detect concurrent in-place changes that preserve identity and timestamps.

Actual decoding is limited to 8 GiB per file and 20 GiB per task; wrong-password retries do not reset cumulative work. ZIP retains a separate 64 MiB location-metadata budget and shared 20 GiB actual-input-read budget. TAR/GZIP retains its existing 24 GiB full-stream read limit. 7z/RAR/CAB/ISO/UDF additionally use a 1 GiB native-worker memory limit. Input reads and solid skipping are also bounded; exceeding a limit is a resource failure, not an integrity pass. Task/event counts, snapshot detail, and retained memory follow existing queue limits. Successful terminal states do not set write, commit, saved-directory, or output-path counts.

Task kind is explicitly sent to Qt as `kind=check`. `read_bytes` means actual source reads, including headers and retries; `decoded_bytes` means actual decoding work; `verified_bytes`/`verified_files` increase only after required checks complete. During the complete TAR/GZIP scan, do not invent file-level percentages; actual bytes read and speed remain visible. Count full-stream files as verified only after success.

AES passwords reuse the [password protocol](password-extraction.md): independent control slot, one-shot prompt identity, task-local cache, at most ten wrong verification-value responses per entry, immediate failure for authentication corruption, and secret zeroization. Cancellation and shutdown wake password waits regardless of ordinary command-queue capacity. Closing the browsing page or progress window does not cancel an accepted task; reopen results from the global task entry. Explicit exit still waits for cancellation and asynchronous joins.

## Verification boundaries

Core regressions cover supported formats, empty files, directories, duplicate names, ZIP link payloads, password retry/cancellation, corrupt payloads, source changes, actual counts, and no output. Bridge and Qt verification covers the real toolbar-to-background-task-and-result flow; password routing, historical tasks, cross-session admission, and exit are checked separately. Bilingual multiple-font-size, light/dark, and native desktop visual acceptance are recorded separately in issues. Generated evidence remains only in build/ or CI artifacts.

Older RAR encrypted entries lack a verifier that reliably distinguishes a wrong password from corrupt content. Request a password separately before decoding each encrypted entry; do not automatically apply the preceding entry's password to a later entry that may use a different secret. RAR5 and other supported formats continue task-local reuse. Encrypted decoding or encrypted-header integrity failures without a trusted password verifier report `password_or_integrity`, preserving the ambiguity between wrong password and corruption. Plaintext header checks, source changes, cancellation, limits, and output I/O are not misclassified as password problems.

Archives containing unknown uncompressed sizes remain browsable. Whole-archive checks mark the total unknown and fail with `unsupported_feature` before opening payloads or requesting passwords, retaining actual verified and decoded counts. Unknown sizes are not checked as empty files, and internal sentinels are not used as progress denominators.
