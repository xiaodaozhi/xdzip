# 界面设计与修正流程

本流程在界面创作前执行，不等到实现完成后补写。规范入口为 [界面设计规范](design-standard.md)。

1. **确定目标与环境。** 列出功能、真实数据和缺失能力，明确平台、逻辑窗口、辅助字号、菜单及独立窗口的尺寸范围；记录系统缩放、浏览器页面缩放、审阅倍率与 DPR。
2. **先确定参数。** 在权威 JSON 中定义组件尺寸、字号、槽位、内边距、对齐边和状态。明确此次变更的密度边界，例如主窗口 0.8、菜单 1、独立操作窗口 1。新增硬编码必须有对应规范值或明确说明。
3. **冻结独立依据。** 保存原图哈希和量测坐标。尺寸政策可以显式修订；原图和历史证据不得为了让检查通过而替换。维护可追溯的修订记录，验收脚本不能只把运行参数与自身比较。
4. **先检查组合关系。** 设计按钮、表格、树和菜单时同步检查字号比例、行高比例、图标比例和交互状态；至少同时展示一个下拉菜单、一个右键菜单和一个子菜单。主窗口正常比例验收通过后再进入 Qt。
5. **统一生成与实现。** 由规范生成 HTML 展示契约和共享参数、Qt Theme；Qt 使用逻辑布局和真实字体尺寸。仅替换主题颜色或素材不能代替尺寸对照。
6. **测量并修正。** 同一逻辑宽度逐区核验标题栏、标签、工具栏、面包屑、目录树、表头、文件行、预览、底栏与菜单。检查坐标、字体、图标可见范围、基线、内边距和 hover／focus；修正后重新采集对应证据。
7. **验证缩放与行为。** 检查浏览器 100%／125%、DPR 1／1.25／2、Qt 高 DPR、窄窗口和辅助字号。真实点击展开／折叠，键盘进入／退出子菜单，验证禁用项、选择状态、边缘位置和焦点归还；排除 Qt 回收池中未显示的对象。
8. **交付与准入。** 更新规范、功能映射、生成文件、自动化 gate、对照图和差异清单。相关检查通过后按仓库约定推送 main，完成三平台复验；尚未验证的原生装饰和未实现能力保留为明确条目，不补画假状态。

每次界面变更的审阅记录必须回答：采用哪份规范；哪组参数改变；按哪个倍率换算；是否同时测量菜单与主窗口；哪些真实交互已验证；是否还有未完成的视觉或功能差异。
