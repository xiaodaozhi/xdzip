## 생성 기능과 필드 오류

- ZIP의 네 단계는 Store/Deflate 1/6/9에 대응하며 기본값은 2 일반입니다. TAR와 TAR.GZ를 생성할 수 있고 형식을 바꾸면 확장자를 동기화하고 암호와 분할 설정을 지웁니다. TAR는 수준을 비활성화하며 TAR.GZ 수준 0/1/2/3은 GZIP 0/1/6/9에 대응합니다. 형식 변경은 확장자를 동기화하지만 대상을 알리지 않고 덮어쓸 수 없습니다.
- 입력이 없거나 이름이 비었거나 대상이 잘못되었거나 권한이 없으면 생성 버튼을 비활성화하고 필드 옆에 이유를 표시합니다. 오류는 테두리 색만 바꾸지 않고 화면 읽기에서 읽을 수 있는 텍스트로 제공합니다.
- 중복 입력과 디렉터리 확장은 코어에서 처리하며 UI는 선택 요약만 표시합니다. 생성 화면의 이미지 아이콘은 형식 표시이며 이미지 미리보기가 아닙니다.
- ZIP과 7z는 각각 지원하는 암호 및 분할 설정을 제공합니다. 7z는 파일 이름도 암호화할 수 있습니다. 실제 쓰기 기능은 형식 레지스트리를 참조합니다. [ZIP 생성](../engineering/zip-creation.md), [형식 레지스트리](../engineering/format-registry.md)

## 작업 데이터와 예외

예 A는 파일 세 개, 8.4 + 6.2 + 12.8 = 27.4 MB입니다. 두 개가 성공하면 14.6 MB가 저장되고 나머지 PDF는 12.8 MB입니다. 성공, 건너뛴 항목, 미완료 항목의 수를 혼동해서는 안 됩니다. 예 B는 파일 30개와 77.5 MB의 전체 압축 파일이며 46.5 MB는 60%로 예 A와 같은 시점이 아닙니다.

백분율은 알려진 전체 바이트와 실제 계량에서 계산합니다. 전체가 알려지지 않으면 남은 시간을 만들어 내지 않고 불확정 진행률을 사용합니다. 단계가 바뀌면 속도를 다시 추정합니다. 그림의 6.2 MB/s와 약 5초는 안정된 단계의 예일 뿐입니다. 파일 수는 완료와 처리 중을 구분하며 현재 항목 순번을 성공 수로 사용하지 않습니다.

디스크 가득 참: 중지하고 게시된 항목을 유지하며 공간을 확보하거나 대상을 바꾼 뒤 재계획합니다. 원본 변경: 다시 시도할 때 압축 파일을 다시 열며 이전 인덱스를 재사용할 수 없습니다. 단순 취소: 미완료 항목에 황색 또는 중립색을 사용하고 손상으로 보고하지 않습니다. 오류 코드는 세부 정보에 표시하고 일반 화면에는 호출 스택이나 내부 브리지 용어를 표시하지 않습니다.

<a name="xdzip-immediately-applied-settings"></a>

## 즉시 적용되는 설정

테마, 글꼴 크기, 밀도, 언어, 열기 방식, 개인정보 스위치는 변경이 성공하면 즉시 저장되고 적용됩니다. 최근 기록 지우기는 즉시 실행되며 원본 파일은 삭제하지 않습니다. 실패하면 이전 설정을 유지하고 메시지를 표시합니다. 정보와 업데이트는 설정의 정보 페이지에 있으며, 파일 연결은 OS 확인이 필요하고 실제 결과를 반영합니다. 네트워크 페이지는 검증된 프록시와 미러 주소를 저장합니다. [설정 계약](settings-localization.md)을 참조하세요.

기존 호스트의 기본 출력 예산은 파일당 8 GiB, 작업당 20 GiB이며 현재 설정 창에서는 할당량을 편집할 수 없습니다. 나중에 제한을 추가하면 양의 정수와 오버플로를 검증하고 파일당 제한이 작업 제한을 넘지 않도록 하며 새 계획에만 적용합니다. 실행 중인 작업의 불변 권한을 변경하거나 공간 검사를 우회하지 않습니다.

<a name="xdzip-window-layout-and-asset-mapping"></a>

## 창, 레이아웃 및 에셋 대응

모든 작업 창은 [플랫폼 창 명세](platform-windows.md)를 따릅니다. macOS 기본 제목 표시줄에는 잘라낸 신호등 버튼을 사용하지 않습니다. Windows/Linux 제목 버튼 위치, 비활성 상태, 시스템 메뉴, 이동은 플랫폼 계층에서 검증합니다. 플랫폼 비교 이미지의 Linux 오른쪽 컨트롤은 모든 데스크톱 환경에 대한 하드코딩된 약속이 아닙니다.

현재 치수는 [layout-scale.json](../../../specs/visual/layout-scale.json), [창 등록부](../../../specs/visual/window-registry.json), [디자인 표준](../visual/design-standard.md)을 따르며 초기의 지나치게 큰 제안을 대체합니다. 생성, 추출, 충돌, 진행, 결과의 너비는 491로 같고 설정은 용도별로 등록된 차이인 612를 사용합니다. 제목 20, 본문 13, 바닥글 버튼 13, 보조 텍스트 12입니다. 높이는 콘텐츠와 각 창의 상한을 따르며 본문은 스크롤됩니다. 바닥글이 있는 작업 창은 이를 고정하고 접근 가능하게 유지하며 설정에는 바닥글이 없습니다. 설정은 글꼴 크기 100%/125%/150%를 제공합니다. 전체 배율이나 스크린샷의 물리 픽셀에서 구성 요소 치수를 도출하지 않습니다.

| 용도 | 추가 에셋 | 공유 / 동적 부분 |
| --- | --- | --- |
| 생성 제목, 입력 추가 | archive-add, image-file, remove | folder, file-pdf, new |
| 충돌, 부분 실패 | document-warning, status-warning, info | file-pdf. 비교 카드와 텍스트는 QML로 그림 |
| 실행 진행률 | document-download, image-file, info | 진행률 표시줄과 숫자를 동적으로 그림 |
| 성공, 건너뛰기, 취소, 중지 | status-success, status-skipped, status-stopped, spinner, clock | Qt 컨트롤이 spinner를 회전 |
| 설정 | settings-tile, theme-system | 테마 미리보기, 스위치, 숫자 입력은 구성 요소이며 settings는 작은 아이콘 |

에셋은 `design/assets/`에 있습니다. `reference/`는 외형 비교를 위해 원본 픽셀 조각을 보존합니다. `svg/`와 `png/`는 투명한 런타임 에셋이며 원본 레이어라고 불러서는 안 됩니다. 모든 SVG는 24×24 캔버스를 사용하고 PNG는 24×24, 48×48, 72×72로 내보내되 같은 논리 표시 크기를 유지합니다. HTML 파일 목록은 원본 좌표 공간의 48×48 슬롯을 사용하고 Qt는 약 31.75×39.69 논리 픽셀을 사용합니다. PDF, 텍스트, 코드, Markdown 아이콘은 중심과 보이는 높이 22픽셀을 공유하면서 윤곽 너비는 각각 유지합니다. 폴더도 같은 캔버스의 중앙에 놓습니다. 어두운 SVG는 에셋을 조정한 것이며 완전한 어두운 동작은 실제 Qt와 대비 검사가 필요합니다.

<a name="xdzip-directory-tree-addition"></a>

## 디렉터리 트리 추가

B01 탐색에는 공식 아트보드 세 개와 공유 조각 26개가 있는 [디렉터리 트리 B 명세](directory-tree.md)가 추가됩니다. 노드 화살표는 하위 디렉터리에 따라 결정되며 확장, 현재 디렉터리, 키보드 포커스는 독립적입니다. 로딩, 빈 압축 파일, 루트 파일, 탐색 제한, 실패, 숨겨진 현재 경로는 별도로 정의하고 기존 읽기 전용 도메인 계약은 변경하지 않습니다. HTML과 Qt는 기본 탐색, 연결선, 숨겨진 현재 분기 표시를 통합합니다. 스켈레톤과 전용 경계 아이콘은 디자인 에셋으로 남습니다. 통합 범위는 디렉터리 트리 명세를 참조하세요.

<a name="xdzip-changes-and-revalidation"></a>

## 변경과 재검증

주요 상태는 HTML과 Qt에서 사용되었습니다. 이후 변경에서도 원본 디자인과 수정된 매개변수, 컨트롤과 기능의 대응, 공유 구성 요소와 창 계약을 확인하고 영향을 받는 플랫폼을 검증합니다. 디자인이나 정적 검사만으로 네이티브 기능과 접근성을 증명할 수 없습니다. 실제 결론은 해당 issue에 기록하며 이 목록으로 과거 수용 결과를 초기화하지 않습니다.
