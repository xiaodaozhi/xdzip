# 작업 창과 무결성 검사

[English](../../ux/task-windows.md) | [简体中文](../../zh-CN/ux/task-windows.md) | [繁體中文](../../zh-TW/ux/task-windows.md) | [日本語](../../ja-JP/ux/task-windows.md) | 한국어 | [Français](../../fr-FR/ux/task-windows.md) | [Deutsch](../../de-DE/ux/task-windows.md) | [Español](../../es-ES/ux/task-windows.md) | [Português (Brasil)](../../pt-BR/ux/task-windows.md) | [Русский](../../ru-RU/ux/task-windows.md)

애플리케이션의 작업 진입점은 모든 세션을 모으고 세션 UUID와 백엔드 작업 ID로 진행률, 암호, 충돌, 결과를 전달합니다. 페이지를 닫아도 해당 컨트롤러는 유지되며 명시적으로 종료하면 모든 비동기 join이 끝날 때까지 기다립니다. [애플리케이션 세션 계약](../engineering/application-sessions.md)을 참조하세요.

작업 메뉴 행에는 작업 아이콘, 압축 파일 이름, 순번 태그, 상태 태그가 표시됩니다. 아이콘은 생성, 추출, 검사, 추가, 이동, 내보내기용 공유 에셋을 사용하며 작업 유형 텍스트 접두사는 표시하지 않습니다. 두 태그는 같은 구성 요소를 사용합니다. 순번은 백엔드 번호를 유지하며 세션 간 내부 식별 정보는 바뀌지 않습니다. 긴 파일 이름은 생략하지만 접근 가능한 이름에는 작업, 번호, 파일 이름, 상태를 포함합니다.

`ExtractWindow`와 `CreateWindow`는 초안을 작업 진행률과 별도로 표시합니다. 각 압축 파일 세션에는 `TaskWindow`가 있는 `OperationTasks` 프레젠터가 있습니다. 작업을 선택하면 스냅샷을 바인딩하고 같은 보기에서 종료 결과를 표시합니다. 보기를 닫아도 작업은 계속 실행됩니다. 독립적인 파일 관리자 작업이 유일한 진입점을 잃게 되는 경우 창을 다시 표시할 수 있습니다. 시스템이 임시 파일 열기를 수락하면 해당 작업 창은 숨겨집니다. 전달이 거부되면 결과를 유지하여 다시 시도할 수 있습니다. [임시 열기](../engineering/archive-opening.md)를 참조하세요.

[내장 레지스트리](../engineering/format-registry.md)는 생성 형식과 수준을 결정합니다. 단일 파일 스트림, ISO 데이터 이미지, Windows x64 ZIP 자체 추출 파일도 포함합니다. 7z의 기본값은 일반 LZMA2이며 솔리드 모드, 콘텐츠 암호화, 파일 이름 암호화, 분할 볼륨은 별도 옵션입니다. 파일 이름 암호화에는 콘텐츠 암호화가 필요합니다. 형식을 바꾸면 이전 형식의 옵션을 지웁니다. 컨트롤은 스크롤되는 본문에 남습니다.

무결성 검사는 동일한 TaskWindow 레이아웃을 재사용합니다. 실제 도구 모음의 “검사”는 전체 압축 파일에 대한 읽기 전용 백그라운드 작업을 제출하고 읽기, 암호 대기, 취소, 종료 상태를 `kind=check`로 표시합니다. 현재 선택과 무관하며 첫 오류에서 중지하고 검증된 수와 확인하지 않은 수를 별도로 표시합니다. 추출이나 생성의 확정 수는 검사 수가 아닙니다. 형식 및 안전 범위는 [검사 계약](../engineering/archive-checking.md)을 참조하세요. 구성 요소 개발 미리보기에는 “인터페이스 미리 보기입니다. 검사를 수행하지 않습니다.”라고 명시된 별도의 IntegrityWindow가 계속 제공됩니다.

HTML 검사 버튼은 명시적으로 표시된 UI 데모를 실행합니다. 닫거나 탐색으로 돌아가도 데모 상태는 유지되고 다시 열면 현재 진행률이 표시됩니다. 취소하면 데모가 끝나며 종료 상태는 더 진행되지 않아야 합니다. 완료와 취소는 같은 구조와 바닥글을 사용합니다. 객체 경로, 읽은 바이트, 파일 수, 속도, 남은 예상 시간, 단계, 현재 항목은 데이터 슬롯이며 UI는 파일을 탐색하거나 읽거나 추출하지 않습니다. 예제 숫자는 실제 검사 결과가 아닙니다.

창 너비, 밀도, 글꼴, 반경, 테두리, 진행률 표시줄, 아이콘 슬롯, 설명 정렬은 [시각 표준](../visual/design-standard.md)과 [고정된 원본](../../../specs/visual/integrity-reference.json)을 따릅니다. 전체를 알 수 없으면 확정 백분율을 표시하지 않습니다. 큰 글자에서는 바닥글을 접근 가능하게 유지하면서 본문을 스크롤할 수 있습니다. 닫기는 취소를 발생시키지 않으며 취소 버튼이 명시적으로 요청합니다. 검사 종료 화면에는 저장된 파일을 표시하거나 대상 폴더를 열어서는 안 됩니다.

고충실도 원본은 [무결성 검사 진행](../../../design/hifi/screens/integrity-progress.png)이며 런타임 아이콘은 공유 에셋의 document-check입니다. 원본을 자른 이미지는 참고용이며 동적 UI는 공유 구성 요소를 사용합니다.

## 일반 치수와 작업 찾기

아이콘, 제목, 부제목이 있는 생성, 추가, 추출, 작업/결과, 충돌, 설정, 정보 창은 OperationHeader를 공유합니다. 기준은 48 논리 단위 아이콘 슬롯, 제목 20, 부제목 13, 일반 높이 96입니다. 긴 문구와 큰 글꼴은 공유 글꼴 측정값에 따라 높이가 늘어나며 본문은 계속 스크롤되고 바닥글은 움직이지 않습니다. 텍스트만 있는 암호, 사전 검사, 종료/재시작 확인에는 없는 장식 아이콘을 추가하지 않습니다. 매개변수, 독립 상태, 등록은 [시각 표준](../visual/design-standard.md)을 참조하세요.

작업 버튼 오른쪽에는 한 쌍의 화살표를 유지합니다. 앱 내 작업 메뉴는 최대 360 논리 픽셀과 현재 창에서 사용할 수 있는 높이로 제한하며 기록은 내부에서 스크롤하고 지우기 버튼은 고정하여 접근할 수 있습니다. 지우기는 완료, 실패, 취소된 기록만 숨깁니다. 실행 중, 대기열, 암호/충돌 대기, 취소 중, 정리 중인 작업은 남깁니다. 지울 기록이 없으면 버튼을 비활성화합니다. 이 동작은 작업을 취소하거나 원본 압축 파일 또는 사용자 출력을 삭제하지 않으며 원래 컨트롤러나 종료 장벽을 바꾸지 않습니다. 지우기로 숨겨진 결과 창은 빈 스냅샷을 표시하지 않고 닫습니다.

지우기 버튼은 장식 배경이 아닌 대화형 메뉴 콘텐츠에 속합니다. 포인터, 키보드, 네이티브 접근성은 같은 지우기 의도를 호출합니다. 구분선 양쪽에 4 논리 단위를 두고 버튼 아래에는 공유 메뉴 패딩만 사용하며 추가 바닥글 간격을 넣지 않습니다. 작업 행은 가로와 세로 패딩이 같고 상태 배지는 사용 가능한 콘텐츠의 오른쪽에 정렬합니다. 스크롤바 너비는 실제로 넘칠 때만 예약합니다. 레이블은 스냅샷 종류에 따라 검사, 추출, 생성, 추가, 이동, 내보내기를 구분하며 생성이 아닌 모든 작업을 추출이라고 부르지 않습니다. 활성화는 전체 작업 식별 정보와 원래 컨트롤러를 유지하며 검사 작업을 추출로 전환하지 않습니다.

2026-10-15 개정: 생성, 추출, 공유 작업 창은 너비 491 논리 픽셀을 사용합니다. 진행과 결과의 높이는 콘텐츠에 따라 최대 600까지 조정합니다. 접힌 세부 정보에는 펼침 공간을 예약하지 않으며 펼친 목록은 최대 168입니다. 작업 ID를 바꾸면 세부 정보 펼침을 초기화하고 같은 작업의 업데이트는 사용자 선택을 유지합니다. 파일 존재 창은 너비가 같고 최대 높이 560이며 일반 밀도와 공유 바닥글을 사용합니다. 이 치수는 네이티브 독립 창이나 취소의 의미를 변경하지 않습니다.

작업 실행 중 현재 파일은 한 줄을 차지하고 가운데를 생략하여 경로 시작과 파일 이름 끝을 유지합니다. 전체 일반 텍스트 경로는 데이터와 접근 가능한 이름에 남습니다. 같은 상태와 글꼴 크기에서 경로 길이만으로 카드나 창의 높이가 바뀌어서는 안 됩니다. 다른 경로 카드와 종료 설명은 계속 줄바꿈됩니다. 일반 추출 결과는 제한된 세부 목록 대신 committedFiles를 사용하여 “파일 N개 처리함”만 표시합니다. 0은 명시하고 건너뛴 파일과 미완료 파일은 제외합니다. 일괄 생성을 포함한 생성 결과는 “파일 N개”만 표시합니다. outputParts는 일반 생성에서 분할 볼륨을 포함한 생성 파일 수를, 일괄 작업에서는 성공한 작업 수를 셉니다. 일괄 추출도 제한된 세부 목록의 파일 이름이 아닌 성공한 추출 작업 수를 세어 “파일 N개”만 표시합니다. 이름과 크기는 생략합니다. 일괄 통계는 세 열을 사용하고 처음에는 완료, 미완료, 취소 수를 한 줄에 표시합니다. 가운데 아래쪽 화살표는 나머지 수를 표시하고 위쪽 화살표는 접습니다. 버튼에는 도구 설명과 읽을 수 있는 접근성 이름을 유지합니다. 다른 작업은 펼침 상태를 초기화하고 같은 작업의 업데이트는 유지합니다. 일괄 생성 결과는 볼륨 그룹 중복 제거 수를 생략합니다. 일괄 추출에서는 선택한 다른 파일이 같은 볼륨 그룹에 속해 건너뛴 파일을 “건너뜀(같은 그룹)”으로 표시합니다. 생성과 추출은 미완료 파일과 이유를 펼칠 수 있는 세부 정보에 나열하며 작업 수준 오류는 별도로 표시합니다.

상태 표시줄 버튼은 앱 전체에서 보존된 작업 행 수를 셉니다. 활성 수는 별개이며 도구 설명과 종료 정책에 사용됩니다. 컨트롤러별 기록이 64를 초과하면 제거 가능한 종료 기록을 삭제해 정리합니다. 작업을 다시 열 때는 탐색 페이지가 닫힌 뒤에도 세션 UUID와 작업 ID를 사용합니다.

작업 목록은 작업 ID로 항목 식별 정보를 유지합니다. 진행률과 상태는 목록을 다시 만들거나 마우스 오버, 강조 표시, 키보드 포커스를 방해하지 않고 제자리에서 갱신합니다. 새 작업과 기록 제거 시 영향을 받은 항목만 삽입하거나 삭제하고 나머지의 식별 정보와 선택을 유지합니다. 정렬은 작업 ID 내림차순이며 마우스나 키보드 활성화는 항상 해당 ID를 다시 엽니다. QML 데이터 모델은 작업 기록의 UI 투영일 뿐 스냅샷, 취소, 커밋, 종료 상태, 종료 장벽의 의미를 바꾸지 않습니다.

이 업데이트는 기존 창과 메뉴 레이아웃, 논리 단위, 시각 상태를 변경하지 않습니다. HTML 디자인의 작업 메뉴는 연속 진행 중 노드를 다시 만들지 않고 기존 원본을 유지합니다. 런타임 검증에서는 정지된 마우스 오버, 키보드 탐색, 제자리 상태 갱신, 작업 추가, 기록 제거를 계속 확인합니다.

## 네이티브 선택기와 끌어다 놓기 활성화

압축 파일 열기, 파일/디렉터리 추가, 추출 또는 생성 대상 변경은 실제 호출한 Quick 창을 공유 NativeDialogPolicy에 전달합니다. 선택기는 호출 창을 임시 소유자로 하는 독립 네이티브 애플리케이션 모달 대화 상자로 유지됩니다. 중첩 이벤트 루프를 벗어난 뒤 호출 창이 아직 존재하고 보일 때만 해당 창의 활성화 복원을 대기열에 넣습니다. 항상 주 창을 복원해서는 안 됩니다. 닫힌 호출 창을 다시 살려서는 안 됩니다. 시스템 선택기 텍스트는 계속 시스템 언어를 따릅니다.

시작 페이지가 유효한 로컬 압축 파일 끌어다 놓기를 수락하면 수신 창은 다음 이벤트 루프에서 활성화를 요청합니다. 거부된 끌어다 놓기와 일반적인 작업 완료는 전경 활성화를 요청하지 않습니다. 유효한 선택은 [시작 페이지 끌어다 놓기 허용](welcome.md#xdzip-real-qt-integration)을 참조하세요.

## 종료와 재시작 확인

QuitWindow와 RestartWindow는 OperationConfirmationWindow를 상속하며 애플리케이션 모달, 일반 밀도, 적응형 높이, 스크롤 가능한 본문과 고정 바닥글을 사용합니다. 버튼은 돌아가기, 대기, 종료 취소, 나중에, 재시작 의도를 유지하며 기존 컨트롤러가 파일 게시와 작업 정리를 처리합니다. 중지 중에는 결정 동작과 Escape 닫기를 비활성화하며 제목이나 설명이 바뀌어도 이전 치수를 복원하지 않습니다.

이전에는 확인 창의 시각 상태 없이 작업 종료 성공을 검사했으므로 기능과 시각 증거를 별도로 기록합니다. 창 무결성, 기본 클래스, 치수 검사는 [필수 절차](../visual/design-workflow.md), 디자인은 [확인 상태](../../../design/hifi/sources/confirmations.html)를 참조하세요.

암호 추출은 별도의 `waiting_password` 상태와 요청 식별 정보를 사용합니다. TaskWindow는 암호 대기를 표시하고 다시 열기를 제공하며 애플리케이션 모달 PasswordWindow가 입력과 취소를 처리합니다. 충돌 `promptId`는 사용하지 않습니다. 수명 주기는 [암호 추출 상호작용](password-extraction.md)을 참조하세요.
