# 플랫폼 창과 제목 표시줄

[English](../../ux/platform-windows.md) | [简体中文](../../zh-CN/ux/platform-windows.md) | [繁體中文（台灣）](../../zh-TW/ux/platform-windows.md) | [日本語](../../ja-JP/ux/platform-windows.md) | 한국어 | [Français](../../fr-FR/ux/platform-windows.md) | [Deutsch](../../de-DE/ux/platform-windows.md) | [Español](../../es-ES/ux/platform-windows.md) | [Português (Brasil)](../../pt-BR/ux/platform-windows.md) | [Русский](../../ru-RU/ux/platform-windows.md)

xdzip 작업 인터페이스는 독립적인 최상위 창을 사용하며 기본 창에 붙은 시트나 그 안에 그리는 오버레이 패널을 사용하지 않습니다. 독립 창이라고 해서 별도 프로세스나 모든 보조 창의 작업 표시줄 항목이 필요한 것은 아닙니다. 드롭다운 메뉴와 도구 설명은 가벼운 Popup으로 유지되며 작업 창이 아닙니다.

<a name="xdzip-window-contract"></a>

## 창 계약

| 창 | 기본 창과의 관계 | 닫기 / Escape | 최소화 / 최대화 |
| --- | --- | --- | --- |
| 추출 또는 생성 양식 | 찾아보기에서 열면 일시적 소유자가 있는 비모달 `OperationWindow` | 새 작업을 제출하지 않고 초안 또는 확인 창 닫기 | 비활성 / 비활성 |
| 작업 충돌 확인 | 작업 창의 호스트가 소유한 비모달 확인 창. 작업은 결정을 기다림 | 확인 창을 닫고 작업에서 다시 열거나 거기서 작업을 명시적으로 취소 | 비활성 / 비활성 |
| 암호, 종료 또는 재시작 확인 | 애플리케이션 모달. 네이티브 파일 선택기도 호출 창을 일시적 소유자로 갖는 애플리케이션 모달 | 암호, 종료 및 재시작마다 명시적인 닫기 또는 확인 동작 제공 | 네이티브 대화 상자 기능에 따름 |
| 작업 진행과 결과 | 비모달 `TaskWindow`. 다른 모달 창이 활성화되지 않으면 찾아보기 계속 가능 | 세부 정보를 닫고 작업 항목에서 다시 열기. 독립 작업도 활성 작업에 접근하는 방법 유지 | 최소화 / 비활성 |
| 설정 및 정보 | 비모달. 트레이 항목은 찾아보기 소유 창 없이 열 수 있음 | 화면 닫기. 이미 저장한 설정은 계속 적용 | 비활성 / 비활성 |

작업 취소는 진행 창을 닫는 것과 무관한 명시적 작업 명령입니다. 백그라운드 완료는 전경의 포커스를 빼앗지 않으며 열린 세부 정보 또는 작업 항목을 갱신합니다. 애플리케이션 종료는 여전히 작업 종료 정책을 따르며 기본 창 닫기를 보조 창 닫기에 직접 대응시킬 수 없습니다.

<a name="xdzip-platform-appearance"></a>

## 플랫폼별 모양

- macOS: 왼쪽 위에 빨강, 노랑, 초록 컨트롤이 있는 시스템 장식 제목 표시줄을 사용하고 네이티브 컨트롤을 사용자 지정 색 점으로 대체하지 않습니다. 고정 크기 작업 창은 빨간 닫기를 유지하고 사용할 수 없는 최소화와 확대를 비활성화하며 진행 창은 최소화할 수 있습니다. 실제 버튼 사용 가능 여부는 AppKit/Qt 창 기능에 달려 있으며 실제 기기에서 승인합니다. 기본 창은 일반적인 크기 조절, 최소화, 전체 화면 기능을 유지합니다.
- Windows는 QML 캡션 버튼, 크기 조절 가능한 네이티브 프레임, DWM 그림자를 갖춘 클라이언트 확장 기본 제목 표시줄을 사용합니다. 끌기, 가장자리 크기 조절, 시스템 스냅에는 플랫폼 기능을 사용합니다. 독립 작업 창은 네이티브 장식을 사용합니다. [Windows 및 Ubuntu 기본 디자인](../../../design/hifi/sources/main.html?platform=windows)을 참조하세요.
- Ubuntu X11은 오른쪽 통합 컨트롤과 일반 상태의 둥근 테두리를 사용합니다. 컴포지팅과 입력 영역 형성 기능이 있는 세션은 클릭이 통과하는 부드러운 그림자도 표시합니다. 최대화 및 전체 화면 창은 각진 모서리로 사용 가능한 영역을 채웁니다. 창 시스템이 이동과 크기 조절을 처리합니다. 독립 작업 창은 시스템 장식을 유지합니다. 사용자 지정 X11 경로 밖의 다른 백엔드는 일반 장식을 사용합니다. Wayland는 지원 범위 밖입니다. [Ubuntu 기본 디자인](../../../design/hifi/sources/main.html?platform=linux)을 참조하세요.

각 작업 창은 고유한 제목, 테두리, 그림자와 끌 수 있는 제목 표시줄을 가지며 뒤의 기본 창을 웹 페이지처럼 어둡게 하거나 흐리게 하지 않습니다. 처음 열 때 소유 창의 디스플레이에서 사용 가능한 영역 중앙에 배치합니다. 복원 위치는 보이는 화면 안으로 제한해야 합니다. 도구 모음이나 내용이 제목 표시줄을 가려서는 안 됩니다.

<a name="xdzip-qt-quick-implementation-constraints"></a>

## Qt Quick 구현 제약

`OperationWindow`는 선택적 `transientParent`가 있는 독립 `Window`를 사용하며 기본값은 `Qt.NonModal`입니다. `PasswordWindow`와 `OperationConfirmationWindow`는 `Qt.ApplicationModal`을 명시적으로 사용합니다. 네이티브 선택기는 실제 호출 창을 일시적 소유자로 사용하고 그 창이 보이는 동안에만 활성화를 복원합니다. [창 레지스트리](../../../specs/visual/window-registry.json)와 [작업 창](task-windows.md)을 참조하세요.

Windows/Linux 사용자 지정 제목 표시줄에는 실제 플랫폼의 창 이동, 크기 조절, 시스템 메뉴 지원이 필요하며 QML 위치를 수동으로 바꾸어 시스템 끌기를 흉내 내지 않습니다. `WindowController`는 창 수명 주기, 소유 관계, 닫기 요청, 작업 화면 다시 열기를 관리합니다. 코어가 작업을 소유하므로 화면을 파괴해도 활성 작업은 파괴되지 않아야 합니다. 스레드 간 창 상태 갱신은 정의된 브리지 이벤트만 사용합니다.

<a name="xdzip-prototype-evidence-and-limits"></a>

## 프로토타입 증거와 한계

HTML 프로토타입은 독립 창의 모양, 제목 표시줄 끌기, 차단 및 비차단 상호작용과 닫기 동작을 모의합니다. 상단 “Platform” 선택기는 macOS, Windows, Linux 비교용이며 제품 설정이 아닙니다. 브라우저 `dialog`는 한 페이지 안에 남으므로 실제 네이티브 창, 시스템 버튼, 시스템 최소화, 작업 표시줄 또는 다중 디스플레이 동작을 제공하지 못합니다. 작업 창 최소화는 세부 정보를 숨기는 방식으로 모의합니다.

프로토타입 기본 창의 플랫폼 컨트롤은 모양을 보여 주는 예시입니다. 덮어쓰기 확인에서 생성으로 돌아가면 예제 양식은 여전히 초기화되며 제품 구현은 초안을 보존해야 합니다. 이러한 한계는 네이티브 승인이 완료되었다는 증거가 될 수 없습니다.

<a name="xdzip-real-device-acceptance-criteria"></a>

## 실제 기기 승인 기준

1. 각 작업 창은 기본 창에 올바르게 연결된 독립 플랫폼 창이며 시트나 웹 페이지식 오버레이가 없습니다.
2. 신호등 또는 오른쪽 버튼 순서, 비활성 상태, 닫기 요청이 플랫폼과 창 기능에 맞으며 다양한 글꼴 크기와 배율에서 제목과 시스템 버튼이 겹치지 않습니다.
3. 창 끌기, 화면 경계, 다중 디스플레이, 125%/150%/200% 배율과 밝은/어두운 테마가 정상 동작합니다.
4. 작업 세부 정보를 닫아도 작업은 계속되며 작업 항목에서 다시 열 수 있습니다. 충돌 창을 닫으면 사용자가 확인 창을 다시 열거나 작업을 명시적으로 취소할 때까지 작업이 기다립니다.
5. 소유자 모달 동작, 포커스 복원, 키보드 탐색, 화면 읽기 프로그램용 제목과 시스템 단축키가 동작하며 무관한 압축 파일 창을 불필요하게 차단하지 않습니다.
6. Windows 시스템 메뉴와 스냅 및 Linux X11을 각각 확인합니다. Wayland는 초기 지원 범위 밖입니다. 기존 Qt 실제 기기 결과는 [WP-12 #5](https://github.com/xiaodaozhi/xdzip/issues/5)에 있습니다. 이 목록은 나중에 영향받은 항목을 다시 확인하기 위한 것이며 완료된 승인을 초기화하지 않습니다.
