# 암호가 필요한 압축 풀기 상호 작용

[English](../../ux/password-extraction.md) | [简体中文](../../zh-CN/ux/password-extraction.md) | [繁體中文（台灣）](../../zh-TW/ux/password-extraction.md) | [日本語](../../ja-JP/ux/password-extraction.md) | 한국어 | [Français](../../fr-FR/ux/password-extraction.md) | [Deutsch](../../de-DE/ux/password-extraction.md) | [Español](../../es-ES/ux/password-extraction.md) | [Português (Brasil)](../../pt-BR/ux/password-extraction.md) | [Русский](../../ru-RU/ux/password-extraction.md)

지원되는 ZIP, 7z, RAR 작업은 암호가 필요한 항목을 만나면 `waiting_password` 상태가 됩니다. 런타임은 작업 ID와 요청 ID가 포함된 요청을 게시합니다. QML은 입력과 취소 의도만 전달하며 복호화, 인증과 파일 확정은 코어가 담당합니다. 암호 요청과 이름 충돌은 별도 상태입니다. 암호 요청을 충돌 창에 보내면 안 됩니다. 형식, 인증, 재시도와 출력 범위는 [기술 계약](../engineering/password-extraction.md)을 따릅니다.

7z 또는 RAR 파일 이름이 암호화된 경우 열기 단계에서 PasswordWindow를 재사용하여 암호를 요청합니다. 「압축 파일 암호」와 「열기 계속」을 표시하며 창을 닫으면 이번 열기만 취소되고 압축 풀기나 검사 작업은 만들어지지 않습니다. 열기는 별도의 `open` 식별 정보와 증가하는 요청 ID를 사용합니다. 오래된 요청이 새 열기 작업에 암호를 제출할 수 없습니다. 전체 검색이 끝나기 전에는 부분 파일 목록을 표시하지 않습니다. 열기 암호와 콘텐츠 암호는 저장하지 않습니다.

7z가 `password_or_integrity`를 반환하면 같은 창에 중국어로 「密码不匹配或加密数据损坏，请重试。」, 영어로 「The password does not match or the encrypted data is damaged. Try again.」을 표시합니다. 이 결과만으로 암호가 틀렸다고 확정하거나 재입력으로 손상이 복구된다고 보장할 수 없습니다. 사용자는 취소할 수 있습니다. 작업 재시도는 기존 한도를 따르며 한도에 도달해도 원인이 불확실한 분류를 유지합니다.

PasswordWindow는 앱 모달이며 기존 시스템 제목 표시줄을 씁니다. 클라이언트 영역 너비는 491, 높이는 최대 600이며 현재 화면의 사용 가능한 높이에 맞게 제한됩니다. 제목 크기는 20, 본문은 13, 보조 문구는 12입니다. 본문은 내용에 따라 늘어나거나 독립적으로 스크롤하고 하단 버튼은 계속 사용할 수 있습니다. 치수는 [password-reference.json](../../../specs/visual/password-reference.json), 상세 설계 기준은 [P02 독립 창 상태](../../../design/hifi/sources/password-extraction.html)를 따릅니다. 지원되는 언어, 밝은 테마와 어두운 테마, 100%／125%／150% 글자 크기에 같은 치수 규칙을 적용합니다.

창에는 현재 암호화 항목의 이름, 암호 입력란, 표시／숨기기 동작과 작업 범위 설명이 나옵니다. 표시 동작에는 명확한 텍스트와 접근 가능한 이름이 있으며 암호가 포함된 도구 설명은 없습니다. 입력은 기본적으로 가려집니다. 제출, 취소, 창 닫기 또는 요청 ID 변경 시 입력란을 비우고 가림 상태를 복원합니다. 암호는 설정, 클립보드, 로그, 작업 스냅샷 또는 보고서에 기록하지 않습니다. UI 문자열 정리만으로 이전 Qt 메모리 복사본이 모두 지워진다고 보장하지 않습니다. 비밀 정보를 담는 컨테이너의 수명은 런타임 계약을 따릅니다.

외부 압축 파일의 암호는 비어 있거나 제어 문자를 포함할 수 있습니다. 앞뒤 공백을 제거하거나 만들기 암호의 1~128바이트 제한을 적용하지 않습니다. 압축 풀기 암호는 UTF-8로 최대 1,024바이트입니다. 입력란은 UTF-16 단위 최대 1,024개를 받고 제출 전에 UTF-8 바이트 수를 검사합니다. 백엔드도 다시 검사합니다. 한도를 넘으면 실제 오류를 표시하고 수정할 수 있도록 입력을 보존합니다. 재시도 요청은 새 ID를 사용하고 이전 입력을 지운 뒤 「암호가 일치하지 않거나 암호화된 데이터가 손상되었습니다. 다시 시도하세요.」를 표시합니다.

압축 풀기를 계속하면 정확한 작업 ID, 요청 ID와 원래 암호를 컨트롤러에 보냅니다. 수락되면 즉시 입력란을 비우고 가림 상태를 복원하며 중복 제출을 막습니다. 작업 스냅샷에서 해당 요청을 벗어난 것이 확인되면 창이 닫힙니다. 만료, 취소 또는 중복 요청은 다른 작업에 제출할 수 없습니다. 즉시 거부되면 유효한 요청과 입력을 유지하여 재시도할 수 있습니다. 컨트롤러는 병렬 작업의 요청을 순서대로 표시하며 나중 요청이 미해결 요청을 조용히 대체하지 않습니다.

「작업 취소」를 누르거나 네이티브 창을 닫으면 해당 창의 작업이 취소되어 찾을 수 없는 대기 상태가 남지 않습니다. Escape는 공통 포커스 정책에 따라 먼저 현재 컨트롤의 포커스를 벗어나고 다음에 창을 닫아 작업을 취소합니다. 암호 입력란의 Return／Enter는 동일한 요청 ID, 길이 및 제출 대기 검사를 거쳐 암호를 제출합니다. 버튼은 기존 키보드 동작을 유지합니다. 작업 창의 「암호 입력 대기 중」 상태는 실제 진행률을 유지하며 요청을 다시 열 수 있습니다. 작업 종료 시 관련 요청을 지웁니다.

디자인 데모는 빈 입력란과 관리 대상 예제 파일 이름만 사용하고 실제 압축 파일이나 암호를 검사하지 않습니다. 자동화는 입력 가림, 빈 암호, 비 ASCII 바이트 경계, 거부 및 중복 제출, 요청 교체, 취소와 닫기, 작은 화면 스크롤과 고정 하단 버튼을 확인합니다. 기능 결과와 네이티브 시각 인수는 별도로 기록합니다.
