# 디렉터리 트리 B: 디자인, 자산과 통합

[English](../../ux/directory-tree.md) | [简体中文](../../zh-CN/ux/directory-tree.md) | [繁體中文](../../zh-TW/ux/directory-tree.md) | [日本語](../../ja-JP/ux/directory-tree.md) | 한국어 | [Français](../../fr-FR/ux/directory-tree.md) | [Deutsch](../../de-DE/ux/directory-tree.md) | [Español](../../es-ES/ux/directory-tree.md) | [Português (Brasil)](../../pt-BR/ux/directory-tree.md) | [Русский](../../ru-RU/ux/directory-tree.md)

상태: **핵심 디렉터리 상호 작용은 Qt 읽기 전용 탐색에 통합되었으며, 경계 상태 자산은 통합을 기다립니다**. 상호 작용은 [읽기 전용 탐색 계약](../engineering/readonly-browser.md)을 따릅니다. 일반 디렉터리 탐색은 직속 자식을 사용하고 검색은 현재 범위를 재귀적으로 탐색하며, 출력 권한은 읽기 전용 탐색과 별도로 다룹니다.

현재 세 아트보드는 [다단계 확장](../../../design/hifi/screens/directory-tree-capsule.png), [노드 및 상호 작용 상태](../../../design/hifi/screens/directory-tree-states.png), [빈 상태와 탐색 경계](../../../design/hifi/screens/directory-tree-boundaries.png)입니다. 공유 갤러리에서 전체 아트보드를 보고 [자산 라이브러리](../../../design/assets/index.html#directory-tree)에서 개별 슬라이스를 볼 수 있습니다. 다단계 확장은 편집 가능한 원본에서 내보내며 제목 표시줄은 현재 캡슐 탭과 동기화합니다. 보드 상단과 중앙의 목록은 맥락만 제공하며 제목 표시줄, 도구 모음이나 파일 표를 다시 정의하지 않습니다. [과거 다단계 원본](../../../design/hifi/screens/directory-tree.png)은 26개 슬라이스의 출처와 독립 측정 기준으로 변경하지 않고 보존합니다.

아트보드는 확대되어 있고 각 카드의 배율이 다릅니다. 이미지의 텍스트, 반경과 픽셀 치수를 직접 컨트롤 크기로 사용할 수 없습니다. [구성 요소 매개변수](../../../specs/visual/directory-tree.json)는 구현된 논리 치수를 명시하고 자산 매니페스트는 물리적 자르기 좌표를 별도로 기록합니다. 구현은 논리 너비 1024와 공유 소스 캔버스 변환을 사용합니다. 새 구성 요소 전체를 다시 확대하지 마세요.

Qt는 아래 논리 값을 직접 사용합니다. 1548픽셀 참조는 layout-scale.json에 따라 논리 픽셀 1024에 대응합니다. DPR은 샘플링 밀도와 선 정렬만 결정하며 논리 크기 변환에는 들어가지 않습니다.

## 트리 구조와 개수

완전한 인덱스는 명시적 및 암묵적 디렉터리를 제공합니다. 리프는 **하위 디렉터리가 없음**을 뜻하며 파일이 없다는 뜻은 아닙니다. Glacier Lake에 하위 디렉터리가 있으면 부모 화살표와 별개로 자체 확장 화살표가 있습니다.

```text
Root                               ← current directory
▼ 01 Photos                     12
  ▼ Glacier Lake                 6
    ▸ Lakeside Trail             3  ← deeper directory, not expanded
      Snow Mountain View          3  ← files only, retains empty arrow slot
  ▸ Mountain Sunrise             4
    Other Photos                 2  ← no subdirectories
▸ 02 Documents                   8
  03 Maps                        4  ← no subdirectories
```

예제 아카이브에는 사진 12개, 문서 8개, 지도 4개와 루트 파일 6개가 있습니다. 루트 목록은 직속 디렉터리 3개와 직속 파일 6개를 표시하며 하위 항목을 펼치지 않습니다. 접힌 가지의 하위 항목도 매개변수 파일에 모두 기록하여 리프에 가짜 화살표를 붙이지 않습니다. 다른 보드의 명시적 빈 디렉터리는 별도의 상태 예제이며 이 30개 항목 예제에 추가하지 않습니다.

디렉터리 숫자는 중복 이름을 포함하고 디렉터리 접두사와 동일한 레코드는 제외한, 접두사 아래 모든 하위 **물리 아카이브 레코드**를 나타냅니다. 하위 디렉터리 개수가 아니며 이름 검색에 따라 바뀌지 않습니다. 트리 행에는 개수를 표시하지 않습니다. 아카이브 요약은 전체 물리 레코드 수를 유지하고 목록 제목 오른쪽은 현재 디렉터리 행 수를 표시하므로 정의가 다릅니다. 일반 목록은 마지막 이름을, 검색 결과는 아카이브 안의 전체 경로를 표시합니다.

화살표는 알려진 하위 디렉터리의 유무만 따릅니다. 부모가 접혔을 때 오른쪽, 펼쳐졌을 때 아래를 가리킵니다. 파일만 있는 노드나 빈 노드에는 화살표가 없지만 같은 수준에서는 화살표 슬롯, 아이콘 슬롯과 텍스트 시작 위치를 동일하게 유지합니다. 완전한 인덱스를 읽는 동안 노드별 화살표, 개수나 구조를 추측하거나 노드별 비동기 로딩 상태를 추가하지 않습니다.

## 레이아웃, 글꼴과 동적 지오메트리

| 항목 | 기본 논리 크기 / 동작 |
| --- | --- |
| 기본 사이드바 너비 | 193.16. 메인 창 구조 경계에서는 193으로 반올림 |
| 행 높이 | 최소 32. 큰 글꼴에서는 매개변수 공식에 따라 증가 |
| 단계별 들여쓰기 | 12.8. 노드 유형과 무관 |
| 화살표 히트 영역 / 그래픽 슬롯 | 최소 19.2×19.2 / 14.4×14.4. 리프도 같은 슬롯 유지 |
| 폴더 아이콘 슬롯 | 16×16. 공유 24단위 SVG를 비례 확대/축소하며 현재 트리의 18 슬롯을 대체 |
| 아이콘과 텍스트 간격 / 끝 여백 | 6.4 / 16. 표시되는 개수 없음 |
| 본문 | 11.2. Qt는 11로 반올림하고 같은 소스의 글꼴 사용 |
| 레코드 개수 | 데이터와 접근성 의미에 유지. 행에 표시하지 않고 개수 열도 예약하지 않음 |
| 현재 디렉터리 | 연한 파란 배경, 오른쪽 모서리 반경 6.4, 직선 왼쪽 가장자리와 전체 높이의 너비 2.4 표시기 |
| 키보드 포커스 | 추가 외곽선이나 포커스 막대 없이 행 점유 영역 유지. 현재 디렉터리 표시기는 유지 |
| 계층선 | 너비 1. 배경에 대해 절제된 계층 표현 |
| 숨겨진 현재 디렉터리 표시 | 투명한 19.2단위 슬롯의 4.8단위 점. 이름과 행 중심 공유 |

연결선은 표시된 조상 체인과 마지막 형제 플래그로 동적으로 그립니다. 부모 세로선은 펼쳐진 하위 트리를 통과하여 마지막 형제의 중심까지 이어집니다. 마지막 연결은 L자로 끝나며 다음 최상위 그룹까지 이어지지 않습니다. 각 세로선의 중심 X는 큰 접근성 글꼴을 포함하여 부모 아래쪽 화살표 끝의 X와 정렬합니다. 안쪽 선은 각각 독립적으로 끝나므로 일반 선 이미지 하나를 모든 행에 걸쳐 쓸 수 없습니다. 선분을 대상 DPR에 맞추고 텍스트, 화살표와 폴더는 행의 세로 중심을 공유합니다.

계층 영역은 가로로 스크롤합니다. 너비는 현재 펼쳐져 보이는 노드의 실제 이름, 들여쓰기와 끝 여백 16만 사용합니다. 이름은 숫자 오버레이 없이 완전히 표시합니다. 접은 뒤 너비를 다시 계산해 숨겨진 깊은 노드가 빈 공간을 남기지 않으며 왼쪽 표시기는 뷰포트 가장자리에 고정합니다. 행을 가리켜도 떠 있는 도구 설명은 표시하지 않습니다. 전체 경로는 접근성 설명과 세부 정보에서 사용할 수 있습니다. 세로 스크롤은 디렉터리 뷰포트 안에서만 이루어지고 스크롤바가 메인 창 테두리를 둘러싸지 않습니다.

모든 디렉터리는 같은 폴더 자산을 사용합니다. 가지 점, 채워진 정보/경고 아이콘과 분할 스피너에는 밝은/어두운 SVG와 1×/2×/3× PNG가 있습니다. 선, 포커스 프레임, 배경, 스켈레톤, 텍스트와 안내는 동적 구성 요소입니다. 어두운 매개변수는 전역 테마를 재사용하면서 선과 표시 색상을 추가합니다. **완전한 어두운 디렉터리 트리 원본은 아직 미완성**이며 어두운 아이콘 내보내기가 전체 아트보드를 대체하지 않습니다. 기존 렌더링과 데스크톱 검수 결론은 관련 이슈와 아티팩트에 별도로 기록합니다.

Qt의 상호 작용 일관성은 [검증 방법](../../../developers/qa/README.md)에 따라 기록합니다. 아트보드와 슬라이스는 원본 디자인 이력을 보존하며 현재 행 개수, 포커스와 모서리는 이 페이지와 논리 명세를 따릅니다.

## 상호 작용과 독립 상태

확장, 현재 디렉터리, 호버와 키보드 포커스는 독립적으로 저장되며 동시에 존재할 수 있습니다. 현재 디렉터리는 오른쪽의 파일 체크박스 선택과도 다릅니다.

루트는 별도로 탐색할 수 있는 항목이며 항상 펼쳐져 있고 일반 노드의 확장/접기에 참여하지 않습니다. 오른쪽 클릭, Menu 키 또는 Shift+F10으로 메뉴를 열면 “하위 디렉터리 접기”는 화면의 설명 줄이나 도구 설명 없이 비활성 상태를 유지합니다. 접근성 설명은 “根目录始终展开” / “Root is always expanded”입니다. 일반 트리 행이 없다고 하위 디렉터리도 없는 것은 아닙니다. 일반 부모의 확장/접기는 실제 하위 디렉터리에 따라 결정되며 일반 리프는 접근성 설명 “This node has no subdirectories”를 유지합니다. 이유는 접근성에서만 제공하고 화면에는 힌트로 표시하지 않습니다. 메뉴를 열거나 비활성 항목을 클릭해도 디렉터리, 파일 선택이나 트리 확장이 바뀌지 않아야 합니다.

| 동작 | 결과 |
| --- | --- |
| 화살표 클릭 | 해당 노드만 펼치거나 접음. 디렉터리 조회, 파일 선택과 세부 정보는 그대로 유지 |
| 이름 클릭 또는 Enter | 현재 세션의 디렉터리 ID로 진입. 조회가 성공적으로 교체되면 기존 계약에 따라 현재 디렉터리 조회, 파일 선택과 세부 정보 초기화 |
| 위 / 아래 | 표시된 디렉터리 행 사이에서 포커스 이동. 파일 목록을 자동으로 바꾸지 않음 |
| 오른쪽 | 접힌 부모를 확장하고 이미 확장된 경우 첫 번째 자식으로 이동. 리프는 그대로 유지 |
| 왼쪽 | 펼쳐진 부모를 접고 그렇지 않으면 부모로 이동. 최상위 노드는 그대로 유지 |
| 현재 디렉터리의 조상 접기 | 현재 디렉터리와 파일 목록을 유지하고 숨겨진 포커스는 가장 가까운 표시된 조상으로 반환 |
| 새 아카이브 세션 | 이전 노드 ID, 확장, 포커스와 가지 점을 지움. 다른 아카이브의 상태를 재사용하지 않음 |

예를 들어 경로가 `01 Photos / Glacier Lake`일 때 `01 Photos`를 접어도 오른쪽에는 Glacier Lake가 계속 표시됩니다. Photos 행에는 파란 끝 점만 나타나고 Glacier Lake의 현재 디렉터리 배경은 적용되지 않습니다. 루트도 현재 디렉터리가 되지 않습니다. 파란 점은 **가장 가까운 표시된 접힌 조상**에 나타납니다. 숨겨진 현재 디렉터리 하나에는 가지 표시 하나만 있습니다. 다시 펼치면 Glacier Lake의 현재 배경이 복원됩니다.

트리 자체는 키보드 탐색의 단일 진입점입니다. 노드는 안정적인 ID, 이름, 단계, 확장 상태, 위치와 레코드 개수에 대한 접근성 의미를 유지합니다. 리프를 확장 가능하다고 표시하지 않고 장식용 폴더, 선과 점은 중복으로 알리지 않습니다. 숨겨진 현재 경로에는 접근성 설명이 있으며 파란색만으로 전달하지 않습니다. 화살표 키와 화살표 클릭이 행 활성화로 전파되어서는 안 됩니다.

## 상태 범위와 복구

| 상태 | 디렉터리 트리 | 파일 목록 / 복구 |
| --- | --- | --- |
| 읽는 중 | 로딩 메시지, 개수 미상. 스켈레톤은 향후 디자인 자산. 탐색 비활성 | 전역 로딩 상태를 따르고 완전한 인덱스 게시 후 트리를 한 번 교체 |
| 빈 아카이브 | 루트 행에 숫자 없음. “이 아카이브는 비어 있습니다” | 빈 목록. 다른 아카이브를 계속 열 수 있음 |
| 루트 파일만 있음 | 루트 행에 숫자 없음. “하위 디렉터리가 없습니다” | 여섯 파일을 정상 표시. 전체 페이지를 빈 상태로 만들지 않음 |
| 디렉터리 인덱스 제한 초과 | 불완전한 트리를 게시하지 않고 “디렉터리가 표시 제한을 초과합니다” 표시 | 현재 기능 범위에서 루트, 검색과 적격 명시적 디렉터리 탐색을 계속 |
| 읽기 실패 | 탐색을 흐리게 하고 명시적 오류 표시 | 아카이브를 다시 열기. 실패를 0이나 빈 디렉터리로 해석하지 않음 |
| 하위 디렉터리가 있는 노드 | 각 단계에 독립 화살표 | 확장은 해당 디렉터리로 들어가는 것이 아님 |
| 비어 있지 않은 / 빈 리프 | 개수는 데이터에 유지. 둘 다 행 개수나 화살표를 표시하지 않음 | 이름은 활성화 가능. 빈 디렉터리도 탐색 가능 |
| 긴 이름 / 깊은 중첩 | 전체 이름, 접근 가능한 경로, 가로 스크롤과 표시 노드에 따른 너비 | 경로 필터링은 일관성 유지 |
| 글꼴 150% (200%는 과거 스트레스 사례만 해당) | 슬롯과 행이 커지고 선을 행 중심에 다시 정렬 | 이름, 화살표와 포커스가 잘리지 않음 |
| 숨겨진 현재 디렉터리 | 가장 가까운 표시된 조상에 가지 점 표시 | 목록은 현재 경로를 유지하고 다시 펼치면 현재 행 복원 |

탐색 제한과 전역 읽기 실패는 서로 다른 상태입니다. 이유, 가능한 동작과 개수 출처를 “빈 디렉터리” 템플릿에 함께 넣을 수 없습니다. 기존 32,768개 노드, 64단계와 디렉터리 이름 4 MiB 예산은 읽기 전용 계약에서 정하며 디자인이 이를 올리거나 우회하지 않습니다.

## 자산 제공과 실제 통합

원본 픽셀 슬라이스 26개는 `design/assets/reference/tree-*.png`에 있으며 각각 출처, SHA-256, `x,y,width,height`와 용도를 기록합니다. `component_reference_coverage`는 공유 벡터나 동적 구성 요소를 개별적으로 가리킵니다. 정적인 전체 행 이미지를 상호 작용 컨트롤로 설명하거나 슬라이스의 흰 배경을 제거해 투명도를 조작하지 마세요.

| 부분 | 자산 / 그리기 | 현재 통합 |
| --- | --- | --- |
| 폴더, 오른쪽/아래 화살표 | 공유 자산의 `folder`, `chevron-right`, `chevron-down` | 기존 공유 리소스를 사용할 수 있음. Qt 델리게이트에 B 아이콘과 치수 사용 |
| 로딩, 정보, 경고 | 새 `tree-spinner`, `tree-info`, `tree-warning` | 밝은/어두운 SVG 8개와 투명 PNG 24개의 일부. 기존 윤곽 아이콘으로 바꾸지 않고 보드의 채워진 형태와 분할 형태 유지 |
| 숨겨진 현재 가지 | 새 `tree-active-branch` | 두 테마용 투명 PNG 6개 제공. Qt가 가장 가까운 표시된 접힌 조상을 표시할 때 사용 |
| 선, 현재 배경, 포커스, 스켈레톤, 힌트 | 매개변수 파일의 치수와 테마로 동적 그리기 | 스타일과 로직 명세 완료. 두 번째 비트맵 컨트롤 세트는 제공하지 않음 |
| 정식 아트보드 | `hifi/screens/directory-tree*.png` | 디자인 비교를 위해 확인된 원본 바이트 보존 |

Qt는 연결선, 가지 점, 16단위 폴더 슬롯과 디렉터리 컨텍스트 메뉴를 통합합니다. HTML은 완전한 재귀 예제 계층을 사용하고 Qt는 실제 제한된 인덱스를 사용합니다. 현재 조상을 접어도 조회를 제출하지 않습니다. 로딩 스켈레톤과 전용 정보/오류 아이콘은 디자인 자산으로 남고 완전한 어두운 아트보드는 미완성입니다. 아이콘 통합이 플랫폼별 스크린 리더나 HiDPI 검수를 증명하지는 않습니다. 기존 수동 결론은 [WP-12 #5](https://github.com/xiaodaozhi/xdzip/issues/5)를 따릅니다.

## 통합 후 검수

1. 같은 논리 너비 1024, 글꼴 설정, DPR과 상태 데이터로 실제 디렉터리 영역을 캡처하고 해당 확인 아트보드 영역 및 명세와 비교합니다. 배율 관계를 기록하고 시각적 판단과 구조적 단언을 별도로 보존합니다.
2. 각 단계의 화살표, 아이콘과 이름 시작 위치를 맞추고 숫자 행 열은 두지 않습니다. 아이콘, 텍스트, 점과 화살표는 행 중심을 공유합니다. 지오메트리 차이의 목표는 물리 픽셀 1개 이하이며 글꼴 차이의 플랫폼과 실제 폴백을 기록합니다.
3. 더 깊은 접힌 가지와 비어 있지 않은 리프를 포함해 최소 세 단계를 확장합니다. 마지막 형제와 펼쳐진 하위 트리를 통과하는 연결선의 연속성과 끝을 검수합니다.
4. 현재, 호버와 포커스를 각각 및 함께 확인합니다. 화살표 클릭은 디렉터리 조회를 제출하거나 파일 선택을 지우지 않습니다. Enter 활성화는 조회 성공 시 초기화 규칙을 따릅니다.
5. Glacier Lake가 현재 디렉터리일 때 Photos를 접습니다. 목록 경로가 유지되고 루트는 선택되지 않으며 Photos에는 가지 점만 표시됩니다. 다시 펼쳐 현재 행을 복원합니다. 포커스가 숨겨진 경우에도 키보드 탐색이 가능해야 합니다.
6. 실제 제한된 인덱스로 빈 아카이브, 루트 파일, 명시적 빈 디렉터리, 읽기 실패와 디렉터리 제한을 확인합니다. 개수, 비활성화와 복구 동작을 별도로 확인합니다.
7. 긴 이름, 100%/125%/150% 글꼴과 과거 200% 스트레스 사례, 최소 창, 허용된 최대 인덱스 깊이에서 이름이 완전히 보이고 가로 스크롤이 계층에만 영향을 주며 전체 경로에 접근할 수 있는지 확인합니다. 트리 스크롤은 아카이브 요약이나 하단 통계를 이동하지 않습니다.
8. 실제 밝은/어두운 렌더링, 일반/Retina/Windows 고 DPI, 키보드와 스크린 리더 검수를 완료합니다. 이미지 검사나 자산 생성 성공은 이 런타임 검사를 대체하지 않습니다.

[검증 방법](../../../developers/qa/README.md)에 따라 원본, 슬라이스, 자산과 실제 마우스, 키보드, 메뉴와 트리 동작을 별도로 확인합니다. 검사하지 않은 접근성과 플랫폼 차이는 명시적으로 표시합니다.
