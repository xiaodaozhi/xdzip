# 도메인 모델과 압축 파일 데이터

[English](../../design/domain-data.md) | [简体中文](../../zh-CN/design/domain-data.md) | [繁體中文](../../zh-TW/design/domain-data.md) | [日本語](../../ja-JP/design/domain-data.md) | 한국어 | [Français](../../fr-FR/design/domain-data.md) | [Deutsch](../../de-DE/design/domain-data.md) | [Español](../../es-ES/design/domain-data.md) | [Português (Brasil)](../../pt-BR/design/domain-data.md) | [Русский](../../ru-RU/design/domain-data.md)

런타임은 압축 파일 세션, 완료된 인덱스와 해당 세션의 최신 쿼리를 소유합니다. Qt는 결과의 뷰를 유지하고 CLI는 별도의 카탈로그 명령으로 물리 레코드를 읽을 수 있습니다. 둘 다 같은 Rust 서비스에 작업을 제출합니다. [시스템 아키텍처](system-architecture.md), [Qt/Rust 브리지](qt-rust-bridge.md)

## 신원과 소스 버전

| 신원 또는 데이터 | 현재 표현과 범위 |
| --- | --- |
| `SessionId` | 열린 압축 파일의 영이 아닌 런타임 신원. 새로 열기에 성공할 때마다 새 세션을 만든다. 파일 경로는 입력과 UI 라우팅에 사용한다. |
| `SourceVersion` | 런타임은 허용된 각 부분의 일반 파일 신원, 길이와 사용 가능한 타임스탬프를 기록한다. 관련 읽기 및 쓰기 경계에서 열린 객체와 해당 경로를 다시 검사한다. 변경 감지는 가능한 범위에서 수행한다. |
| `EntryId` | 세션 안의 물리 압축 파일 레코드를 식별한다. 이름이 같은 레코드도 서로 다른 ID를 유지한다. |
| 탐색 신원 | 인덱싱된 디렉터리를 나타낸다. 하위 항목으로 합성된 가상 디렉터리는 물리 항목 ID 없이 트리나 목록에 나타날 수 있다. |
| `QueryKey` | 세션, 쿼리 ID, 세대와 스냅샷 수정 버전을 결합한다. 오프셋은 이 결과의 위치를 가리킨다. |
| 요청, 작업과 확인 신원 | 서비스는 연결 내에서 요청과 작업 번호를 할당한다. 확인은 특정 작업에 속한다. 공통 데스크톱 작업 항목은 컨트롤러의 세션 신원과 작업 번호를 함께 사용한다. |

도메인 타입은 압축 파일과 쿼리 신원이 0이 아니도록 보장합니다. 네이티브 브리지에서는 타입이 지정된 Rust 값을 생성된 CXX 데이터로 나타냅니다. 64비트 전체가 필요한 ID는 불투명 문자열로 QML에 전달합니다. 행 번호는 특정 쿼리의 위치일 뿐입니다. ## 물리 항목과 출력 이름

`xdzip-codec-api::Entry`는 형식, 물리 신원, 이름 표현, 크기 정보, 파일 종류 플래그, 수정 정보 및 형식별 방식과 암호화 필드를 포함합니다. 원시 이름 바이트, 선택적인 디코딩된 UTF-8 표기, 인코딩 결정과 이스케이프된 표시 텍스트는 별도로 저장합니다. 출력 시 런타임은 유효 이름을 이식 가능한 경로 정책과 허용된 대상에 따라 검증합니다. 해결되지 않은 이름은 계속 표시할 수 있지만 해당 레코드나 디렉터리의 추출은 거부됩니다.

원본 크기에는 별도의 `size_known` 플래그가 있어 크기가 0으로 알려진 파일과 크기를 모르는 파일을 구분합니다. 일부 압축 컨테이너는 항목별 압축 크기가 없습니다. 방식 값은 형식에 따라 해석합니다. 시간 데이터도 ZIP의 로컬 DOS 시간 같은 형식 관례를 유지하며 시간이 없으면 알 수 없는 상태로 남습니다. `payload_supported()`는 현재 레코드를 디코딩할 수 있는지 결정합니다. 출력은 선택된 작업, 소스 상태, 이름과 파일 시스템 규칙에도 의존합니다. ## 인덱스, 쿼리와 페이지 수명 주기

런타임은 소스를 열고 제한된 검사를 완료한 후 압축 파일과 첫 페이지를 게시합니다. 검사는 취소할 수 있습니다. 손상된 끝부분, 암호 누락 또는 소스 변경 시 부분 인덱스를 게시하지 않습니다. 탐색에는 별도 예산이 있습니다. 디렉터리 트리가 이를 초과해도 루트 탐색과 물리 검색을 지원할 수 있습니다. 일반 단일 파일 ZIP/ZIP64는 비공개 디스크 경로를 통해 최대 100만 레코드를 보유할 수 있습니다. 다른 형식과 분할 경로는 각자의 한도를 유지합니다.

`Archive::query_page`는 디렉터리, 텍스트, 정렬 방식, 오프셋과 예상 쿼리 신원을 받습니다. 새 쿼리는 새 세대로 오프셋 0에서 시작합니다. 런타임은 완전한 결과 순서를 만들고 압축 파일마다 현재 불변 쿼리 하나를 유지합니다. 페이지는 그 순서에서 행 신원을 해결합니다. 검색과 정렬은 압축 파일 레코드의 원래 신원을 유지합니다. 모든 정렬은 디렉터리를 파일보다 앞에 묶고 동률을 신원으로 결정적으로 정하며 같은 그룹에서 알 수 없는 크기를 알려진 크기 뒤에 둡니다.

일반 도메인 `PageRequest`는 최대 256행을 검증합니다. 데스크톱 런타임 전송은 이름 예산 64 KiB로 최대 128행을 요청합니다. Qt는 작은 결과를 전체 확정하고 큰 결과는 최대 1,024행을 상주시킵니다. 세션, 쿼리, 세대, 수정 버전 또는 오프셋이 일치하지 않는 응답은 현재 데이터를 대체할 수 없습니다. ## 선택과 작업 입력

Qt 모델은 불러온 결과의 선택을 ID로 저장하고 큰 결과의 선택은 현재 결과 내 제한된 범위로 저장합니다. 모두 선택은 해당 결과 전체를 포함합니다. 작업은 전체 압축 파일과 명시적으로 선택한 검색 결과 집합을 구분할 수 있습니다. Rust는 추출 확인을 위해 `FreezeSelection`으로 전체 쿼리 키에 따라 페이지 간 선택자를 해결합니다. 디렉터리 확장은 실제 하위 항목을 해결하고 물리 ID 중복을 제거합니다. 작업 한도를 초과하면 오류를 반환합니다. CLI는 `SelectMembers`로 멤버 경로와 물리 ID를 해결합니다.

추출, 검사와 편집은 필요한 소스와 유지된 메타데이터를 가진 작업별 잡을 준비합니다. 생성은 옵션을 받은 뒤 별도의 `InputTree`를 검사하고 검증합니다. 메타데이터 사전 검사는 잠재적 문제를 설명할 수 있지만 작업에 출력 권한을 주지 않습니다. 런타임은 쓰기 전에 입력을 다시 확인하고 관련 권한을 얻습니다. 잡이 선택을 소유한 후에는 UI 변경으로 범위가 바뀌지 않습니다. ## 결과와 데이터 수명

| 데이터 | 수명 |
| --- | --- |
| 현재 압축 파일, 쿼리와 디스크 인덱스 | 서비스 세션에 속한다. 쿼리 교체나 세션 종료는 관련 비공개 데이터를 해제하되 잡이 독립적으로 유지하는 리소스는 예외다. 디스크 메타데이터 인덱스는 압축 파일을 다시 열 때 재구축한다. |
| 작업 스냅샷 | 런타임은 실제 상태, 바이트와 항목 수, 정리 상태, 제한된 상세 목록이 포함된 제한 스냅샷을 게시한다. 데스크톱은 앱 세션 동안 소유 컨트롤러를 통해 작업 결과를 유지한다. |
| 사용자 설정 | 압축 파일 인덱스와 작업 결과와 별도로 관리한다. 데이터 보존과 개인정보는 설정 및 개인정보 계약에 설명한다. |
| 작업 공간과 저널 | 비공개 출력 준비와 상대 경로 게시 기록이 정리와 검사를 지원한다. 재시작해도 미완료 압축 파일 쓰기를 재생하지 않는다. |

## 현재 구현 범위 밖의 설계안

검색 가능한 인덱스의 점진적 게시, 독자적인 수정 버전과 시작 토큰을 가진 재사용 계획, 영구적인 페이지형 작업 기록은 설계안입니다. 현재 명령은 각자 제한된 잡을 준비하고 대기열에 넣으며 현재 쿼리 하나를 유지하고 제한된 작업 스냅샷을 반환합니다. 영구 복구에는 소스와 출력 검증을 위한 별도 설계도 필요합니다.
