# 파일 권한과 안전한 게시

[English](../../design/file-security.md) | [简体中文](../../zh-CN/design/file-security.md) | [繁體中文](../../zh-TW/design/file-security.md) | [日本語](../../ja-JP/design/file-security.md) | 한국어 | [Français](../../fr-FR/design/file-security.md) | [Deutsch](../../de-DE/design/file-security.md) | [Español](../../es-ES/design/file-security.md) | [Português (Brasil)](../../pt-BR/design/file-security.md) | [Русский](../../ru-RU/design/file-security.md)

호스트는 열 수 있는 파일과 검증된 출력을 게시할 위치를 제어합니다. 백엔드는 격리된 압축 파일 작업 프로세스에서 실행될 때도 제한된 리더와 싱크를 받습니다. 압축 파일 이름, 선언 크기, 체크섬과 페이로드는 입력 데이터입니다. 호스트의 파일 검사는 형식이 수행하는 검사와 독립적으로 적용됩니다. [시스템 아키텍처](system-architecture.md), [압축 파일 작업 프로토콜](../engineering/native-codecs.md)

## 원본과 대상 승인

- **압축 파일 원본.** `Source::open`은 선택된 경로를 `xdzip-io::open_regular_readonly`로 열고 열린 파일의 유형을 검사합니다. Unix에서는 분류용 열기가 비차단 방식이므로 FIFO가 열기를 막지 못합니다. 사용자가 선택한 경로는 링크를 통해 일반 파일로 해석될 수 있습니다. 분할 볼륨 검색은 제한되며 형식별로 다릅니다. 호스트는 승인된 인접 부분을 고정하고 파일 식별 정보와 버전을 검사합니다. 코덱은 제공된 스트림만 지정할 수 있습니다. [원본 구현](https://github.com/xiaodaozhi/xdzip/blob/main/crates/xdzip-runtime/src/source.rs), [볼륨 처리](../engineering/archive-opening.md)
- **생성 입력.** `InputTree`는 제한된 메타데이터와 파일 식별 정보로 선택된 입력을 순회합니다. 읽기는 버전을 검사하면서 해당 트리에서 멤버를 엽니다. 현재 개인 준비 디렉터리는 자신의 입력 스캔에서 제외됩니다. 감지된 원본 변경은 작업을 중지합니다. 파일 식별 정보, 크기와 시간 검사는 최선의 변경 감지이며 완전한 콘텐츠 스냅샷은 아닙니다. [입력 트리](https://github.com/xiaodaozhi/xdzip/blob/main/crates/xdzip-io/src/input.rs), [압축 파일 생성](../engineering/zip-creation.md)
- **대상.** `Grant`는 선택한 디렉터리 객체와 식별 정보를 보유합니다. 추출은 모든 원본 볼륨 식별 정보도 보호 파일로 전달합니다. 생성과 편집은 각 작업 경로에서 고정된 입력 또는 원래 압축 파일 식별 정보를 검사합니다. 하위 폴더와 준비 영역은 보유한 디렉터리를 통해 접근하고 게시 전에 부모 식별 정보를 다시 검사합니다. `CheckTarget`과 추출 사전 검사는 작업 시작 전에 유용한 결과를 제공할 수 있습니다. 쓰기 권한은 작업 중 다시 검사합니다. [대상 권한](https://github.com/xiaodaozhi/xdzip/blob/main/crates/xdzip-io/src/target.rs), [추출 사전 검사](../engineering/extraction-preflight.md)

<a name="xdzip-name-mapping-platform-protection-and-links"></a>

압축 파일을 만들거나 풀 때 확인된 대상을 사용하면, 쓰기 작업은 디렉터리의 식별자가 호출자가 확인한 객체와 일치하는지 검사합니다. 압축에 사용하는 입력은 처음 승인된 파일의 식별자를 유지합니다. 자동으로 찾은 분할 파일을 열 때 마지막 경로 요소의 링크를 따라가지 않습니다. Windows에서 압축 파일을 제자리에서 편집할 때는 원래 소유자, 읽기 권한 및 원본 영역을 유지합니다. 이 보호를 유지할 수 없으면 원본 압축 파일을 그대로 둡니다.

## 이름 매핑, 플랫폼 보호와 링크

1. **압축 파일 상대 표기를 검증합니다.** 런타임은 고정된 선택을 해석하고 해당하면 선택 하위 트리 접두사를 제거하며 `PortablePath`로 상대 UTF-8 구성 요소를 허용합니다. 절대 또는 드라이브 경로, 제어 문자, 모호한 구분자, 부모 구성 요소, 예약된 장치 이름과 끝 공백 또는 점은 거부합니다. 검증된 표기는 대상 권한에 대한 입력일 뿐입니다.
2. **출력을 만들기 전에 충돌을 계획합니다.** 추출은 소문자 NFD 키를 사용해 일반적인 대소문자 및 Unicode 별칭을 비교합니다. 모호한 디렉터리 표기와 파일/디렉터리 충돌은 준비를 실패시킵니다. 일반 파일 별칭은 공통 표기로 매핑되어 이름 충돌 정책을 적용할 수 있습니다. 실제 파일 시스템에서 요청한 이름을 사용할 수 있는지는 네이티브 배타적 게시가 계속 결정합니다. 표시 표기와 물리 항목 식별 정보는 분리됩니다.
3. **허가된 트리를 순회합니다.** 출력은 보유한 디렉터리 권한에서 내려가며 링크를 따라가지 않고 자식 디렉터리를 엽니다. 승인된 루트, 부모 식별 정보와 덮어쓰기에서 예상되는 말단을 다시 검사합니다. 교체된 대상이나 안전하지 않은 링크는 거부합니다. 같은 볼륨의 이름 변경 전 마지막 검사는 경쟁을 줄입니다. 일반 이름 변경은 같은 계정 권한을 가진 프로세스에 대해 콘텐츠 비교 후 교환을 보장하지 않습니다.

| 플랫폼 | 출력 객체 검사 |
| --- | --- |
| Linux와 macOS | 소유자는 현재 유효 사용자여야 합니다. 그룹 및 다른 사용자의 쓰기 권한을 거부하며 기존 일반 파일의 하드 링크는 하나여야 합니다. macOS는 상속된 수정 권한을 포함한 네이티브 ACL도 검사합니다. |
| Windows | 보유 객체의 재분석 지점, 소유자, 파일 ID, 일반 파일의 하드 링크 수와 DACL을 검사합니다. 유효 규칙과 상속 전용 접근 규칙은 수정을 신뢰할 수 있는 주체로 제한해야 합니다. 기존 읽기 전용 공유는 유지할 수 있습니다. |
| 개인 평문 또는 임시 작업 공간 | 추가 기밀성 검사로 무관한 읽기 주체를 제외합니다. Windows에서는 배타적으로 만든 개인 캐시 디렉터리에 보호된 DACL을 적용할 수 있습니다. 사용자가 선택한 일반 추출 대상은 자체 읽기 공유 정책을 유지합니다. |

ZIP 심볼릭 링크 출력은 승인된 Unix 링크 그래프로 제한됩니다. 런타임은 링크 게시 전에 선택된 그래프와 없어야 하는 말단을 검증하고 일반 대상을 먼저 확정합니다. 작업은 콘텐츠를 쓰기 위해 압축 파일이 만든 링크를 따라가지 않습니다. 다른 미지원 링크나 특수 파일 프로필은 명시적으로 실패합니다. POSIX 일반 파일 모드는 소유자 읽기/쓰기와 함께 안전한 읽기/실행 비트를 준비 영역에 복원할 수 있습니다. 특권 비트와 외부 쓰기 비트는 제외합니다. 추출 경로는 확정 후 타임스탬프를 복원하지 않습니다.

## 준비, 검증과 확정

대상 권한은 같은 볼륨에 배타적인 개인 작업 공간을 만듭니다. 호스트는 코덱 출력을 준비 파일에 계량하며 씁니다. 게시 전에 디코딩 완료, 예상 크기와 형식이 제공하는 무결성 또는 인증 검사가 통과해야 합니다. `Stage::finish`는 파일을 비우고 동기화하며 검사된 버전을 보유합니다. 호스트는 확정 과정에서 준비 영역과 대상을 다시 검사합니다. 데이터 동기화와 단일 파일의 원자적 가시성이 정전 시 디렉터리 메타데이터의 지속성을 입증하지는 않습니다.

| 동작 | 게시 의미 |
| --- | --- |
| 파일 추출 또는 파일 약속 게시 | 각 적격 파일을 검증 후 게시합니다. 덮어쓰지 않으면 같은 볼륨에 하드 링크를 배타적으로 만들고 이후 개인 준비 링크를 제거합니다. 덮어쓰는 추출은 예상된 안전한 일반 파일을 요구하고 먼저 자르지 않은 채 같은 볼륨의 이름 변경으로 교체합니다. 파일 약속은 항상 덮어쓰지 않고 게시합니다. 파일 시스템에 필요한 연산이 없거나 대상이 바뀌면 해당 쓰기가 실패합니다. 이미 게시된 파일이나 생성된 디렉터리를 작업 전체에서 롤백하지 않습니다. |
| 단일 압축 파일 생성 | 준비 영역에 인코딩하고 다시 열어 생성 프로필의 예상 항목과 내용을 검증한 뒤 전체 압축 파일을 한 번 게시합니다. 이름 충돌 시 새 이름을 선택하거나 조건에 맞는 교체를 허용할 수 있습니다. 보호된 입력은 덮어쓰기 대상이 될 수 없습니다. |
| 분할 볼륨 생성 | 준비된 압축 파일 내용을 검증하고 모든 부분을 준비하여 기존 볼륨을 덮어쓰지 않고 새 평면 집합을 게시합니다. 부분들은 개별적으로 보이게 됩니다. 부분 실패 시 롤백은 새로 게시된 객체 중 식별 정보가 여전히 일치하는 것만 제거하려고 합니다. 롤백 실패는 불확실한 결과를 남길 수 있습니다. |
| 기존 압축 파일 수정 | `ArchiveUpdate`는 승인된 부모와 예상되는 원본 압축 파일 버전을 연결합니다. 다시 쓴 압축 파일을 열어 검증한 뒤 해당 권한으로 원본을 한 번 교체합니다. 일반 추출은 이 특별한 교체 경로로 원본을 덮어쓸 수 없습니다. |

게시 게이트 전 취소는 현재 확정을 막습니다. 이미 진행 중인 게시는 완료되어 실제 결과를 보고할 수 있습니다. 이전에 확정된 추출 파일은 계속 보입니다. 종료 스냅샷은 확정된 데이터를 `cancelled`, `failed` 또는 정리 경고와 함께 보고할 수 있습니다. 압축 파일 전체 게시가 성공하면 늦게 취소가 도착해도 성공을 유지합니다. [작업 취소](task-scheduling.md), [압축 파일 수정](../engineering/archive-transfers.md), [안전한 추출](../engineering/zip-safe-extraction.md)

## 출력 예산과 무결성 범위

추출은 선언된 출력과 실제 출력을 별도로 제한하며 일반 파일당 8 GiB, 작업당 20 GiB입니다. 지원 형식에서는 높은 비율 검사로 승인 시 요청을 거부할 수 있습니다. ZIP에서 1 MiB를 넘는 항목의 선언 비율이 1,000 대 1을 초과하면 명시적 허용이 필요합니다. 허용해도 엄격한 제한은 유지됩니다. 솔리드 또는 스트리밍 디코더는 선택되지 않은 데이터에 작업을 쓸 수 있습니다. 이 작업, 반복 읽기나 시도와 보조 디코더 작업은 게시된 바이트와 별도로 계산합니다.

메타데이터 탐색, 작업 승인, 작업 프로세스 메모리와 미리 보기에는 자체 예산이 있습니다. 대형 디스크 기반 ZIP 인덱스가 추출이나 쓰기 제한을 높이지 않습니다. 무결성 검사는 형식에 따라 적용합니다. 예를 들어 ISO/UDF 구조 및 읽기 가능성 검사는 없는 파일별 체크섬을 제공하지 않습니다. [대형 압축 파일 인덱스](../engineering/large-index.md), [무결성 검사](../engineering/archive-checking.md), [보조 디코더 계량](../engineering/auxiliary-decoding-work.md)

## 미리 보기, 임시 열기와 비밀 정보

- **미리 보기.** 지원되는 파일을 선택하면 보이는 속성 카드에서 미리 보기가 시작됩니다. Rust는 예산 내에서 승인된 전체 항목을 읽고 검증합니다. 텍스트는 256 KiB로 제한합니다. 인코딩 이미지는 16 MiB로 제한하며 원본 치수와 픽셀 수에는 별도 제한이 있습니다. 개인 이미지 프로세스는 바이트를 받아 제한된 썸네일을 반환하며 압축 파일 이름, 암호나 대상 핸들은 받지 않습니다. 현재 형식과 제한은 [미리 보기 계약](../engineering/content-preview.md)에 설명되어 있습니다.
- **임시 열기.** 일반 항목은 작업의 일반 검증 규칙에 따라 개인 캐시에 추출됩니다. 데스크톱은 검증된 파일을 로컬 URL로 시스템 연결 프로그램에 전달합니다. 전달이 수락되었다고 외부 프로그램이 읽기를 마친 것은 아닙니다. 보존 기간 후의 다음 작업에서 정리는 캐시 식별 정보와 잠금을 검사합니다. 사본의 편집은 원본 압축 파일과 독립적입니다. [임시 열기](../engineering/archive-opening.md), [압축 파일 전송](../engineering/archive-transfers.md)
- **비밀 정보.** 열기와 추출 암호는 세션 또는 작업 수명 동안 작업별로 분리되고 해제 시 제로화되는 컨테이너에 유지됩니다. 작업 스냅샷이나 준비 저널에는 들어가지 않습니다. 사용자 데이터의 개인 저장, 보존과 공개 규칙은 [개인정보 보호 계약](../engineering/privacy.md)과 [암호 계약](../engineering/password-extraction.md)에 설명되어 있습니다.

## 저널, 잔여물과 검증

준비 저널은 준비와 확정 시 작업 컨텍스트와 상대 출력 이름을 기록합니다. 일반 정리는 소유권과 식별 정보를 검사하고 알려진 준비 객체만 제거합니다. 개인 저널과 남은 객체는 비정상 종료 후 증거를 제공할 수 있습니다. 런타임은 대상을 검사할 때 가능한 잔여물을 셉니다. 발견한 저널로 쓰기를 재실행하거나 알 수 없는 콘텐츠를 삭제하지 않습니다. 개인 임시 출력의 캐시 만료에는 자체 식별 및 잠금 검사가 있습니다.

이 경계를 변경할 때 오류 코드뿐 아니라 게시와 정리도 검증합니다. [I/O 테스트](https://github.com/xiaodaozhi/xdzip/blob/main/crates/xdzip-io/src/tests.rs), [추출 테스트](https://github.com/xiaodaozhi/xdzip/blob/main/crates/xdzip-runtime/src/extraction/tests.rs), [안전한 추출 계약](../engineering/zip-safe-extraction.md)은 서로 다른 계층을 다룹니다. 네이티브 플랫폼 동작을 변경하면 해당 플랫폼의 증거가 필요합니다.
