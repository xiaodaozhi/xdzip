# xdzip 아키텍처 결정 기록

[English](../../design/architecture-decisions.md) | [简体中文](../../zh-CN/design/architecture-decisions.md) | [繁體中文](../../zh-TW/design/architecture-decisions.md) | [日本語](../../ja-JP/design/architecture-decisions.md) | 한국어 | [Français](../../fr-FR/design/architecture-decisions.md) | [Deutsch](../../de-DE/design/architecture-decisions.md) | [Español](../../es-ES/design/architecture-decisions.md) | [Português (Brasil)](../../pt-BR/design/architecture-decisions.md)

초기 기록은 2026년 10월 11일 자이며 이후 기록은 각각 날짜를 명시합니다. 수락은 해당 아키텍처 결정을 채택했다는 뜻입니다. 현재 구현에 관한 설명은 각 결정을 유지 중인 계약과 기능 근거에 연결합니다. 결정을 대체할 때는 원본을 보존하고 새 기록을 추가합니다.

## ADR-001: 제품의 유일한 인터페이스로 Qt Quick 사용

**상태: 수락.**

**현재 구현.** 데스크톱은 Qt Quick/QML과 얇은 C++ 어댑터로 구성됩니다. Windows SFX의 시스템 대화 상자 호스트는 ADR-013의 제한된 예외입니다. [데스크톱 인터페이스](qt-quick-ui.md)

배경: 제품에는 현대적인 데스크톱 UI, 일관된 경험, 낮은 자원 사용량이 필요합니다. 같은 코어를 사용하는 Slint, Tauri, Qt Quick 프로토타입을 완성했습니다. 인터페이스 기능과 일관성, 기존 Linux 소프트웨어 렌더링 측정치를 고려해 제품 단계에서는 Qt Quick을 선택했습니다. 다른 플랫폼은 추가 검증이 필요합니다.

결정: Qt Quick/QML과 Qt Quick Controls 2에 얇은 C++ 적응 계층을 사용합니다. Slint와 Tauri는 과거 실험으로 남기고 제품에 포함하지 않습니다.

비용: Qt 런타임, QML 모듈, 언어 간 빌드 및 라이선스 작업을 유지해야 합니다. Mac과 Windows의 입력, 접근성, GPU 및 배포에는 추가 테스트가 필요합니다. 0.80 MiB 프로토타입 실행 파일은 완전한 Qt 설치 패키지가 아닙니다.

재평가 조건: 대상 플랫폼에서 Qt가 필요한 기능, 라이선스 또는 보안 유지보수를 충족하지 못하고 실제 최적화 후에도 핵심 제품 예산에 미달하는 경우입니다. 일반적인 성능 변동만으로 프레임워크 선택을 반복하지 않습니다.

## ADR-002: 압축 파일의 모든 업무 로직은 Rust가 소유

**상태: 수락.**

**현재 구현.** Rust 런타임이 압축 파일 상태와 작업을 관리합니다. 파일 선택은 데스크톱의 의도를 나타내며 파일 시스템 권한은 호스트 I/O 계층에서 부여합니다. [시스템 아키텍처](../../design/system-architecture.md)

결정: 도메인, 인덱스, 계획, 작업, 할당량, 경로 정책 및 형식 레지스트리는 Rust에 둡니다. Qt는 상태를 표시하고 시스템 파일 선택을 허용하며 사용자의 결정을 전달합니다. 업무 테스트에는 Qt가 필요하지 않습니다.

대안: libarchive나 7zip을 C++/QML에 직접 연결하거나 각 UI에 제어 로직을 반복할 수 있습니다. 그러나 코어가 플랫폼 UI에 결합되고 보안과 취소를 일관되게 검증하기 어려워집니다. Rust도 네이티브 라이브러리의 보안 위험을 없애지는 못하며 해당 라이브러리는 작업 프로세스에서 격리할 수 있습니다.

재평가 조건: 플랫폼 API를 Rust에서 안정적으로 구현할 수 없다면 업무 책임을 변경하지 않고 작은 플랫폼별 C++ 포트를 허용합니다.

## ADR-003: 빌드 시 생성하는 cxx 브리지

**상태: 수락.**

**현재 구현.** 제품은 명령과 이벤트에 별도의 핸들을 사용하는 타입 지정 브리지를 빌드해 사용합니다. 이벤트 수신기와 종료 수명 주기는 [브리지 계약](qt-rust-bridge.md)에 정의되어 있습니다.

결정: 제품 내부에는 cxx가 생성하고 같은 커밋에서 빌드한 타입 안전 브리지를 사용합니다. 장기간 수동 C ABI를 유지하지 않고 빈번한 경로에서 JSON을 직렬화하지 않습니다. 브리지에는 Qt 업무 로직을 넣지 않습니다.

대안: 실험적인 C ABI 유지, CXX-Qt로 QObject 생성, 로컬 IPC로 GUI와 전체 코어 연결이 있습니다. cxx는 Qt 모델과 스레드 경계를 명시하면서 초기 단계에 QObject 생성 프레임워크를 추가하지 않습니다. 대신 얇은 QObject 계층과 CMake/Cargo 조정을 유지해야 합니다.

보장하지 않는 범위: cxx는 임의의 Rust/Qt 버전 사이의 동적 바이너리 호환성을 제공하지 않으며 제3자 형식 프로토콜을 생성하지 않습니다.

재평가 조건: 지원하는 데스크톱 빌드 또는 수명 주기 검증이 실패하거나 어댑터 계층이 크게 증가하는 경우입니다. 조용히 전환하지 않고 ADR을 통해 CXX-Qt 또는 명시적으로 버전 관리되는 C ABI를 평가합니다.

## ADR-004: 내장 소스 SDK와 외부 프로세스 프로토콜 분리

**상태: 설계 경계 수락. 외부 프로토콜은 실험 단계.**

**현재 구현.** 제품 형식은 명시적으로 등록된 내장 형식입니다. 함께 제공되는 형식 작업 프로세스는 자체 프로토콜을 사용합니다. 외부 CBOR 구현은 독립적인 읽기 전용 시험입니다. [형식 어댑터와 시험](codec-extension-sdk.md)

결정: 내장 형식에는 Rust 소스 인터페이스를, 외부 확장에는 별도의 제한된 프로세스 프로토콜을 사용합니다. I/O 권한은 호스트가 보유합니다.

근거: Rust 동적 라이브러리 ABI는 불안정하고 프로세스 내부의 임의 네이티브 플러그인은 충돌 격리와 자원 관리를 해칩니다. 기존 네이티브 코덱의 이전, 스레드, 탐색 및 성능 검증 비용 때문에 현재 Wasm을 범용 형식 런타임으로 우선하지 않지만 향후 사용을 배제하지는 않습니다.

비용: 프로토콜, 중개자, 샌드박스 및 IPC 오버헤드가 발생합니다. 독립 구현 두 개가 상호 운용된 뒤에만 프로토콜을 고정합니다.

## ADR-005: 실제 파일 쓰기는 호스트가 중앙에서 제어

**상태: 수락.**

**현재 구현.** 런타임이 작업을 준비하고 `xdzip-io`가 권한, 임시 준비 및 확정을 관리합니다. 형식 어댑터는 읽기 인터페이스와 출력 대상을 사용합니다. [파일 권한](file-security.md)

결정: 백엔드는 승인된 `OutputSink`에만 기록합니다. 실제 경로, 충돌, 임시 준비 및 확정은 호스트가 제어합니다. 라이브러리의 일반 압축 해제를 임의 디렉터리에 직접 호출하지 않습니다. 단, 이식 부분이 호스트의 제약을 따른다고 완전히 검증된 경우는 예외입니다.

근거: 형식마다 경로 보호를 따로 구현하면 불일치가 생기기 쉽고 문자열 검사만으로 링크나 경쟁 상태를 막을 수 없습니다. 세 플랫폼에서 안전한 파일 계층을 구현하고 장애를 테스트하는 비용이 듭니다.

보장하지 않는 범위: 호스트는 악성 플러그인 출력의 의미적 정확성을 증명하거나 이미 같은 사용자를 제어하는 악성 프로세스를 막을 수 없습니다. 플러그인의 신뢰와 권한은 계속 명시해야 합니다.

## ADR-006: 압축 해제는 파일별로, 새 압축 파일은 전체를 확정

**상태: 수락.**

**현재 구현.** 압축 해제는 파일을 개별적으로 게시합니다. 생성과 편집은 임시 압축 파일을 검증한 뒤 교체하거나 게시합니다. 분할 생성은 검증된 전체를 한 부분씩 게시하고 일부 실패 시 제한된 롤백을 시도합니다. [게시 의미](file-security.md)

결정: 각 압축 해제 파일은 임시 준비와 검증을 거친 뒤 게시하며 실패한 작업에는 일부 결과가 남을 수 있습니다. 새 압축 파일은 전체를 쓴 뒤 게시합니다. 기본적으로 덮어쓰지 않습니다.

근거: 기존 디렉터리에 병합하면서 모든 플랫폼에서 디렉터리 전체를 진정으로 원자적인 트랜잭션으로 만드는 일은 간단하지 않습니다. 전체 작업을 롤백한 것처럼 처리하면 사용자의 이후 변경을 삭제할 수 있습니다. 자세한 결과와 복구 로그가 필요하며 취소 의미도 명확히 설명해야 합니다.

재평가 조건: 완전히 새로운 디렉터리를 전체 게시하는 모드는 제한된 조건에서 별도로 구현할 수 있습니다. 기존 디렉터리 병합의 의미는 변경하지 않습니다.

## ADR-007: 제한된 액터와 작업 풀, 푸시 이벤트

**상태: 수락.**

**현재 구현.** 연결마다 명령과 작업 스레드를 분리하고 데스크톱에서는 무거운 작업을 직렬로 허용합니다. Rust 큐와 Qt 메시지함은 제한됩니다. 일반화된 자원 토큰 풀은 설계 선택지로 남아 있습니다. [작업 스케줄링](task-scheduling.md), [Qt/Rust 브리지](qt-rust-bridge.md)

결정: 가벼운 스케줄러가 상태를 결정하고 제한된 풀이 작업을 실행하며 Qt는 별도 이벤트 수신 스레드를 둡니다. 진행률은 합치고 종료 상태는 전달하며 취소와 종료에는 독립적인 제어 요청 접수를 제공합니다.

대안: 동기 GUI 호출, 파일당 스레드, 무제한 Tokio 또는 `spawn_blocking`, 지속적인 폴링이 있습니다. 압축 파일 작업은 주로 동기 CPU/I/O 작업이므로 비동기라는 이름만으로 무제한 작업을 도입하지 않습니다. 향후 실제 네트워크 I/O에는 비동기 런타임을 국소적으로 사용할 수 있습니다.

비용: 백프레셔, 종료 및 자원 대여를 명시적으로 관리해야 합니다. 장점은 유휴 오버헤드가 낮고 작업이 GUI를 압도하지 않는 것입니다.

## ADR-008: 기능에 따라 첫 버전의 형식 제한

**상태: 수락.**

**현재 구현.** 초기 형식은 역사적 배경입니다. 유지 중인 레지스트리와 런타임 허용 조건이 현재 소스의 기능을 정의하며 확장된 읽기와 생성 프로필, 작업별 제약도 포함합니다. [형식 레지스트리](../engineering/format-registry.md)

결정: v0.1은 ZIP Store/Deflate와 TAR/GZIP을 사용하고 암호화, 분할, RAR, 7z 및 추가 알고리즘은 개별 검증합니다. UI는 확장자만으로 완전한 지원을 추론하지 않습니다.

근거: 형식 이름은 실제 기능 전체를 설명할 수 없습니다. 초기 형식 표는 더 짧지만 사용자에게 정직하고 검증 가능합니다.

## ADR-009: 작은 제품 데이터와 사용자 콘텐츠 분리

**상태: 수락.**

**현재 구현.** 설정, 인덱스 및 저널은 서로 다른 수명을 가집니다. 디스크 기반 인덱스는 비공개이며 세션에 한정됩니다. 영구 인덱스 재사용과 미완료 작업 재실행은 설계 선택지입니다. [도메인 모델](domain-data.md), [파일 게시](file-security.md)

결정: 설정, 임시 인덱스, 트랜잭션 로그 및 확장 매니페스트의 수명 주기를 분리합니다. 기본적으로 원격 측정을 하지 않고 암호를 영구 저장하지 않으며 실행을 넘어서 압축 파일 인덱스를 캐시하지 않습니다.

비용: 여러 스키마와 정리 규칙이 필요합니다. 실행 간 인덱스를 다시 고려하려면 소스 신원, 무효화, 개인정보 및 용량을 새로 설계해야 합니다.

## ADR-010: 완전한 배포와 라이선스를 아키텍처 조건으로 관리

**상태: 수락.**

**현재 구현.** GitHub 바이너리와 Microsoft Store MSIX는 문서화된 별도의 패키징 경로를 따릅니다. 각 경로의 실제 배포 의존성, 산출물 무결성 및 라이선스 자료를 검토합니다. [빌드와 릴리스](build-release.md)

결정: Qt를 기본적으로 동적 배포하고 실제 모듈의 라이선스를 검토합니다. 설치 크기에는 런타임을 포함합니다. 서명, SBOM, 교체 및 소스 제공 의무를 릴리스 검사에 포함합니다.

대안: 실행 파일만 비교하거나 릴리스 직전에 `LICENSE`를 추가하는 방법이 있습니다. 어느 쪽도 제품이 작거나 합법적으로 배포 가능함을 증명하지 않습니다.

비용: 배포와 라이선스를 지속적으로 유지해야 합니다. 정적 Qt 빌드나 스토어 배포에는 별도 ADR과 라이선스 검토가 필요하며 크기 최적화 PR에서 부수적으로 변경할 수 없습니다.

## ADR-011: 초기 지원 범위와 개인 프로젝트 유지보수 정책

**상태: 2026년 10월 19일 수락, 프로젝트 소유자가 명시적으로 승인.**

**현재 구현.** 현재 지원과 업데이트에는 [지원 정책](../engineering/support-policy.md)과 [업데이트 계약](../../engineering/software-update.md)을 적용합니다. 수동 업데이트 조항은 v0.1을 설명합니다.

결정: 초기에는 Apple Silicon arm64의 macOS 14 이상, 유지 중인 Windows 11 x86_64, X11과 glibc 2.39 이상을 사용하는 Ubuntu 24.04 LTS x86_64를 지원합니다. 최신 공개 버전만 우선 유지하고 고정 응답 시간을 약속하지 않은 채 가능한 범위에서 피드백을 처리합니다. v0.1은 수동 업데이트를 사용하고 개발 미리보기는 실험 상태로 유지합니다. [지원 정책](../engineering/support-policy.md)을 참조하세요.

근거: 기존 네이티브 빌드, 설치 프로그램 및 런타임 의존성이 범위를 제한합니다. 이전 설계의 미검증 OS와 아키텍처 약속을 개인 오픈 소스 프로젝트의 유지보수 능력에 맞게 줄입니다. Intel Mac, Windows 10, ARM64 Windows/Linux, 다른 배포판 또는 Wayland 지원은 약속하지 않습니다. 범위를 확대하려면 먼저 구현하고 실제로 검증해야 합니다.

경계: 개인 GitHub 오픈 소스 배포에는 유료 개발자 계정, 서명 인증서, Developer ID 또는 공증이 필요하지 않습니다. macOS는 무결성에 필요한 ad-hoc 서명을 유지합니다. 이 정책은 라이선스 출처와 패키지 검증을 대체하지 않으며 향후 모든 OS 버전과의 호환성을 뜻하지 않습니다.

## ADR-012: 각 형식을 독립적인 Rust 형식 및 압축 알고리즘으로 이전

**상태: 2026년 10월 25일 수락, 소유자가 구현을 명시적으로 승인. 제3자 형식 엔진의 장기 선택을 대체하지만 이전이 완료되었다는 뜻은 아닙니다.**

**현재 구현.** 현재 제품 라우팅은 Rust 형식 구현을 사용합니다. 해당하는 7z, RAR, CAB 및 광학 매체 읽기는 함께 제공되는 작업 프로세스를 사용합니다. 현재 작업 목록에는 프로세스 내 ISO 작성기도 있습니다. 각 작업은 [형식 레지스트리](../engineering/format-registry.md)와 [어댑터 설계](codec-extension-sdk.md)에서 확인하세요.

결정: 형식 분석과 압축 및 압축 해제 알고리즘에 독립적인 Rust 구현을 사용합니다. 범용 암호화, 문자 인코딩 및 시스템 기반 라이브러리는 허용합니다. 먼저 공식 명세를 바탕으로 동작 명세를 정의하고 독립적으로 구현합니다. 참조 소스를 줄마다 번역하거나 이름만 바꾸어 복사하지 않습니다. 소스를 본 개발자는 엄격한 클린룸 개발을 주장하지 않습니다. 자료 부족과 라이선스 제한은 별도 검토하며 특히 RAR 인코더는 개발하지 않습니다.

이전 계획은 당시 기능에 따라 ZIP, TAR, TAR.GZ, 7z, RAR, CAB, ISO 및 UDF를 각각 수락하고 교체하는 것이었습니다. 아직 통과하지 못한 형식은 현재 구현을 유지하고 조용한 대체 실행이나 RAR/CAB/ISO/UDF의 읽기 전용 범위 확대를 하지 않습니다. 공통 압축 알고리즘은 재사용합니다. 이름, 신원, 허용된 I/O, 자원, 취소 및 확정은 계속 Rust 호스트가 관리하며 Rust로 바뀌어도 작업 프로세스 격리는 없어지지 않습니다.

비용: 호환성, 보안, 성능, 퍼징 및 알고리즘을 장기적으로 독립 유지해야 합니다. 제3자 참조 구현은 테스트에 사용할 수 있지만 이전한 형식은 해당 엔진을 제품 의존성과 배포 파일에서 제거해야 합니다. 자료와 인터페이스 규칙은 [자체 백엔드 계약](../../engineering/independent-rust-codecs.md), 진행 상황과 실제 수락은 [#45](https://github.com/xiaodaozhi/xdzip/issues/45)를 참조하세요.

## ADR-013: 독립 Windows SFX 호스트

**상태: 소유자가 승인한 첫 SFX 프로필에 대해 2026년 11월 16일 수락.**

**현재 구현.** [SFX 계약](../engineering/sfx-creation.md)은 Windows 프로필과 독립적인 Rust 및 시스템 대화 상자 진입점을 정의합니다.

배경: 생성된 Windows x64 자동 압축 해제 파일은 xdzip이나 Qt를 설치하지 않아도 동작해야 합니다. 모든 압축 파일에 또 다른 완전한 Qt 앱을 넣으면 불필요한 배포 런타임이 추가됩니다.

결정: 데스크톱은 Qt Quick을 유지하고 기존 생성 창을 재사용합니다. 프로젝트 소유의 독립 SFX 실행 파일은 Windows 시스템 폴더 및 작업 대화 상자만 사용하며 글꼴, DPI, 크기 및 접근성은 시스템이 제어합니다. ZIP, 검증, 출력 권한, 충돌, 진행률, 취소 및 정리는 기존 Rust 코어를 사용합니다. 이는 ADR-001에 대한 배포 호스트의 제한된 예외이며 다른 데스크톱 프레임워크나 새로운 사용자 정의 위젯 라이브러리가 아닙니다.

비용: 추가 Windows 실행 파일, 버전 관리되는 엔벌로프, 정적 CRT 연결, Qt가 없는 의존성 감사 및 네이티브 대화 상자 호스트를 유지하고 자동 테스트합니다. 압축 해제된 콘텐츠는 절대 실행하지 않습니다. 생성된 실행 파일 서명은 고정 스텁 서명과 별개입니다.

재평가 조건: 설치 프로그램, 페이로드 자동 실행, 추가 실행 플랫폼 또는 사용자 정의 SFX 인터페이스 요청에는 각각 별도의 범위 설정과 아키텍처 검토가 필요합니다.
