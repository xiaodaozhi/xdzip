# UI 디자인과 수정 절차

[English](../../visual/design-workflow.md) | [简体中文](../../zh-CN/visual/design-workflow.md) | [繁體中文](../../zh-TW/visual/design-workflow.md) | [日本語](../../ja-JP/visual/design-workflow.md) | 한국어 | [Français](../../fr-FR/visual/design-workflow.md) | [Deutsch](../../de-DE/visual/design-workflow.md) | [Español](../../es-ES/visual/design-workflow.md) | [Português (Brasil)](../../pt-BR/visual/design-workflow.md) | [Русский](../../ru-RU/visual/design-workflow.md)

이 절차는 UI를 만들기 전에 수행하며 구현 후에 문서를 보충하는 절차가 아닙니다. 사양의 출발점은 [UI 디자인 표준](design-standard.md)입니다.

1. **목표와 환경을 정의합니다.** 기능, 실제 데이터와 부족한 기능을 나열합니다. 플랫폼과 논리 창, 접근성 글자 크기, 메뉴, 독립 창의 치수 범위를 지정합니다. 시스템 배율, 검토 배율과 DPR을 기록합니다.
2. **먼저 매개변수를 정의합니다.** 크기, 타이포그래피, 슬롯, 안쪽 여백, 정렬과 상태에 사양 JSON을 사용합니다. 좌표계와 구성 요소별 밀도를 기록합니다. 기본 창과 메뉴의 측정 기준은 독립적이며 각 독립 창은 창 등록부의 수식을 사용합니다. 작업 본문 배율과 공통 바닥글 치수는 별도로 확인합니다. 실제 픽셀은 측정 증거를 읽을 때만 DPR로 변환합니다.
3. **독립적인 참조를 고정합니다.** 원본 이미지 해시와 측정 좌표를 저장합니다. 크기 정책을 명시적으로 개정할 수 있지만 검사를 통과시키기 위해 원본 이미지나 과거 증거를 교체해서는 안 됩니다. 추적 가능한 개정 기록을 유지하며 수락 스크립트가 런타임 매개변수를 자기 자신과만 비교하지 않도록 합니다.
4. **먼저 구성을 확인합니다.** 버튼, 표, 트리와 메뉴를 디자인할 때 글꼴, 행 높이, 아이콘 비율과 상호작용 상태를 함께 확인하고 드롭다운, 컨텍스트 메뉴와 하위 메뉴를 각각 하나 이상 동시에 표시합니다. 같은 작업 창을 기본 창과 독립 진입점에서 각각 열어 최종 창 너비와 본문, 바닥글, 컨트롤 크기가 같은지 확인합니다.
5. **일관되게 생성하고 구현합니다.** 사양에서 공통 매개변수와 Qt Theme을 생성합니다. Qt는 논리 레이아웃과 실제 글꼴 크기를 사용합니다. 테마 색상이나 자산만 바꾸는 것은 치수 비교를 대신하지 않습니다.
6. **측정하고 수정합니다.** 같은 논리 너비에서 제목 표시줄, 탭, 도구 모음, 이동 경로, 디렉터리 트리, 표 머리글, 파일 행, 미리 보기, 하단 표시줄과 메뉴를 영역별로 확인합니다. 좌표, 글꼴, 아이콘의 보이는 경계, 기준선, 안쪽 여백, 호버와 포커스를 확인하고 수정 후 영향받은 증거를 다시 수집합니다.
7. **배율과 동작을 검증합니다.** Qt의 높은 DPR, 좁은 창과 접근성 글자 크기를 확인합니다. 실제로 클릭하여 펼치고 접으며 키보드로 하위 메뉴에 들어가고 나옵니다. 비활성 항목, 선택, 가장자리 위치와 포커스 복귀를 검증합니다. Qt 재활용 풀에서 표시되지 않는 객체는 제외합니다.
8. **전달하고 수락합니다.** 영향받은 사양, 기능 매핑, 생성 파일, 자동 검사와 차이 기록을 갱신합니다. 커밋과 푸시 전에 관련 로컬 검증을 완료합니다. 필요에 따라 세 플랫폼의 전체 검사를 실행하고 검증하지 않은 네이티브 장식과 구현하지 않은 기능을 명시한 채로 두며 가짜 상태를 그리지 않습니다.

실제로 사용한 사양, 매개변수와 배율, 기본 창 및 메뉴 측정값, 검증한 상호작용과 남은 차이를 기록합니다. 고정된 수동 설문은 필요하지 않습니다.

## 창 등록과 필수 검사

모든 독립 QML 창과 인라인 Window를 [창 등록부](../../../specs/visual/window-registry.json)에 등록합니다. 추상 기본 클래스, 제품 작업 창, 독립 속성 창과 개발 미리 보기도 포함합니다. 등록하지 않은 새 창, 변경된 상속, 고정 수식과 다른 크기, 글꼴 크기나 높이를 재정의하는 확인 창, 스크롤 가능한 본문 누락은 `check-window-contracts.py --self-test`를 실패시킵니다. 검사는 수동으로 유지하는 고정 목록 대신 소스에서 창을 찾습니다. 시스템 기본 선택기의 예외는 등록부에 설명하며 이를 이용해 애플리케이션 창 등록을 우회할 수 없습니다.

종료와 다시 시작 확인에는 OperationConfirmationWindow를 사용합니다. 매개변수는 layout-scale.json의 operation.confirmation에서 가져오며 이전 기본 너비 612나 글자 크기에 따라 갑자기 바뀌는 고정 높이를 사용하지 않습니다. 짧은 문구는 내용에 맞게 크기를 정하고 긴 본문이나 작은 화면은 스크롤하며 바닥글에 항상 접근할 수 있어야 합니다. 모든 바닥글 버튼의 모양은 여전히 공통 구성 요소가 결정합니다. 긴 번역은 버튼 안에서 줄바꿈할 수 있으며 작업 버튼은 한 행을 유지합니다.

정적 등록부 검사는 일상 CI에서 실행하고 Qt 런타임 기하 및 상호작용 검사는 로컬 또는 필요 시 세 플랫폼 Qt 워크플로에서 실행합니다. Qt 검사는 종료, 중지, 다시 시작, 중국어와 영어, 밝은 테마와 어두운 테마, 100/125/150% 글자 크기와 작은 화면 본문 스크롤을 다룹니다. 필요 시 워크플로는 DPR 1/1.25/2를 다룹니다. 정적 검사에는 과거의 과도한 크기, 누락된 창, 고정 높이와 스크롤 누락에 대한 변이 검증이 포함됩니다.

창을 변경할 때 기능과 실제로 수행한 시각 검사를 별도로 기록하고 가능하면 스크린샷과 치수를 수집합니다. 실제 종료 작업이 통과했다고 종료 창의 외관이 승인된 것은 아닙니다. 소스 등록부가 완전해도 모든 플랫폼의 시각 검사가 통과한 것은 아닙니다. 네이티브 메뉴, 시스템 장식과 사용할 수 없는 장치의 한계를 명시적으로 보존하되 유지 관리자가 고정된 수동 수락 양식을 반복 작성하도록 요구하지 않습니다.
