# HTML 시각 충실도 검토

[English](../../visual/html-fidelity.md) | [简体中文](../../zh-CN/visual/html-fidelity.md) | [繁體中文（台灣）](../../zh-TW/visual/html-fidelity.md) | [日本語](../../ja-JP/visual/html-fidelity.md) | 한국어 | [Français](../../fr-FR/visual/html-fidelity.md) | [Deutsch](../../de-DE/visual/html-fidelity.md) | [Español](../../es-ES/visual/html-fidelity.md) | [Português (Brasil)](../../pt-BR/visual/html-fidelity.md) | [Русский](../../ru-RU/visual/html-fidelity.md)

고충실도 이미지는 시각적 기준이며 HTML은 편집 가능한 구현입니다. 도구 모음 위와 아래의 치수는 현재 CSS에서 역산하지 않고 [고정된 최초 기본 창](../../../design/hifi/screens/main-light.png)에서 각각 측정합니다. 현재 표시는 [밝은 캡슐 탭 디자인](../../../design/hifi/screens/main-capsule-light.png)과 [어두운 디자인](../../../design/hifi/screens/main-capsule-dark.png)을 사용하며 [편집 가능한 원본](../../../design/hifi/sources/main.html)에서 내보냅니다. 이는 독립 측정을 대체하지 않습니다. 제목 표시줄은 layout-scale.json의 명시적 개정에 따라 검수합니다. 원본 그림에는 부드러운 가장자리와 생성된 글리프가 있으므로 테스트 개수만으로 전체 페이지의 픽셀 완전 일치를 입증할 수 없습니다.

<a name="xdzip-fixed-reproducible-conditions"></a>

## 고정된 재현 조건

- 원본 캔버스는 1586×992 PNG와 일치하고 창은 원점 `(20,30)`에서 1548×940입니다. 원래 앵커 검사는 여전히 장치 픽셀 비율 1의 1588×1000 브라우저 뷰포트를 사용합니다. 원본을 늘리지 않고 상단을 `(20,30)-(1568,167)`, 내용을 `(20,167)-(1568,970)`으로 자릅니다.
- 원본 SHA-256은 [header-reference.json](../../../design/html/header-reference.json)과 [body-reference.json](../../../design/html/body-reference.json)에 고정되어 있습니다. 원본이 바뀌면 재측정해야 하며 조용히 교체하지 않습니다.
- 포함된 오프라인 글꼴 [Xdzip Design Sans SC](../../../design/assets/fonts/README.md)는 `document.fonts.ready` 이후 측정합니다. 플랫폼 대체 글꼴에 따른 너비 변화를 줄이기 위해 실제 굵기 400–750을 고정합니다.
- 생성된 이미지에서 원래 글꼴 패밀리를 확인할 수 없습니다. 글리프 윤곽과 시스템 안티앨리어싱은 여전히 다를 수 있으므로 차이를 별도로 기록하고 원래 글꼴을 복원했다고 주장하지 않습니다.

<a name="xdzip-display-size-and-source-pixels"></a>

## 표시 크기와 원본 픽셀

일반 디자인 표시는 [너비 1024 논리 픽셀 창](README.md)을 사용하고 원본 좌표를 `1024 / 1548`로 균일하게 변환합니다. 기본 창은 1024 × 약 621.81 CSS 픽셀로 표시되며 원본도 같은 배율을 사용합니다. 이 비율은 명시적인 디자인 관례이며 PNG에서 Retina나 DPI를 추론한 것이 아닙니다.

`display-spec.js`는 모든 아트보드 치수와 표시 배율의 유일한 원본입니다. 데스크톱은 일반 디자인 크기, 모바일은 맞춤을 기본으로 하며 넓은 화면에서 자동 확대되지 않도록 맞춤 배율을 일반 크기 이하로 제한합니다. 원본 픽셀 모드는 `scale=1`을 사용해 원본 픽셀 치수와 HTML 및 이미지 양쪽의 스크롤을 유지합니다. 장치 픽셀 비율은 래스터화 밀도에만 영향을 주며 CSS 논리 너비는 바꾸지 않습니다.

원본과 HTML을 각각의 컨테이너에 독립적으로 맞추지 않습니다. 머리글과 본문 앵커는 계속 원본 픽셀 좌표로 측정하며 표시 배율은 보정된 간격이나 글꼴 크기를 바꾸지 않습니다. 크기 일관성은 실제 화면 경계, 원본의 자연 크기, 모바일 스크롤, 독립 미리 보기와 오프라인 단일 파일 출력을 각각 포함합니다. 증거는 [검증 방법](../../../developers/qa/README.md)에 따라 보관합니다.

<a name="xdzip-canvas-and-content-scrolling"></a>

## 캔버스와 콘텐츠 스크롤

검토 도구에 삽입된 HTML은 루트 문서에 `overflow:hidden`을 적용한 고정 크기 아트보드입니다. 이렇게 하면 일반 스크롤바가 캔버스 치수를 소비하고 서로를 유발하는 일을 막습니다. 검토 페이지는 세로로 스크롤하며 바깥 캔버스는 너비가 부족할 때만 가로로 이동합니다. `scrollbar-gutter:stable`은 일반 스크롤바 너비를 예약해 임계 높이에서 맞춤 배율이 반복적으로 변하지 않게 합니다. 독립 미리 보기는 `auto`를 사용합니다. 파일 목록, 긴 속성과 작업 창은 콘텐츠 컨테이너 안의 스크롤을 유지하고 직접 연 비삽입 원본 캔버스는 페이지 스크롤을 유지합니다. 원본 캔버스, 창 또는 구성 요소 치수는 바뀌지 않습니다.

Playwright는 기본적으로 `--hide-scrollbars`를 사용하므로 이전 스크린샷 및 크기 매트릭스는 실제 일반 스크롤바를 다루지 않았습니다. 이제 크기와 미리 보기 검사는 이 인자를 명시적으로 제거하고 루트 스크롤바 공간 예약, 창의 네 모서리 가시성, 바깥 가로 이동과 긴 속성의 마지막 버튼 접근을 확인합니다. 1 px 작은 캔버스와 삽입 규칙을 제거한 부정 사례로 스크롤바 공간 경쟁을 재현하고 감지합니다. 재현 및 수정 스크린샷은 [검증 방법](../../../developers/qa/README.md)에 따라 실행 산출물에 보관합니다. 이것이 모든 브라우저나 시스템의 스크롤바 외관을 입증하지는 않습니다.

| 영역 | 이전 | 원본에 맞춘 수정 |
| --- | --- | --- |
| 활성 탭 | 시작 x299, 너비 244 | x293, 너비 246 |
| 비활성 탭 | x557, 너비 244 | x542, 너비 262 |

| 닫기 컨트롤 | 버튼 하나와 단순 span 하나 | 같은 아이콘/이름/닫기 구조와 명시적 슬롯 |

| 활성 탭 아래 테두리 | 제목 표시줄 선과 겹침 | 흰 도구 모음 표면에 연결하고 왼쪽 어깨 전환은 별도 정의 |
| 검색과 추출 | 가로 및 세로 경계가 치우침 | 각각 `(906,101,449,51)`과 `(1368,101,183,51)`에 비교 |
| 도구 모음 왼쪽 아이콘 | 일반 버튼 크기와 간격으로 배치 | 원본 그림 앵커에 맞춰 배치하고 검사 |

머리글 구성 요소 슬롯과 타이포그래피는 `hifi.css`의 제목 표시줄, 탭, 도구 모음 절에 모으며 일반 `.icon-button` 치수나 상속된 줄 높이에 의존하지 않습니다. 밝은 테마와 어두운 테마는 형상을 공유합니다. Windows/Linux 제목 장식은 브라우저 시연으로 남고 제품 네이티브 창은 별도로 검수합니다.

<a name="xdzip-content-below-the-toolbar"></a>

## 도구 모음 아래의 내용

본문에는 압축 파일 카드, 디렉터리 트리, 경로 표시줄, 표 머리글과 행, 선택, 파일 미리 보기와 하단 상태 표시줄이 포함됩니다. 열 경계, 행 높이, 안쪽 여백, 아이콘 중심과 보이는 잉크를 기록하고 [독립 기준](../../../design/html/body-reference.json)과 비교합니다. 엄격한 형상 및 분리된 아이콘 잉크 허용 오차는 2 px이며 텍스트 윤곽은 수동 검토용으로만 기록합니다. 폴더 광학 크기는 명시적 디자인 개정으로 새 윤곽을 공유 자산에서 약 25.7% 균일하게 확대했습니다. 오래된 폴더 잉크 예시 다섯 개를 비교용으로 유지하고 독립 기록된 새 디자인 경계로 확인하며 다른 원본 앵커는 변경하지 않습니다.

본문 검토는 같은 크기의 콘텐츠 잘라내기를 사용하며 사이드바, 목록, 미리 보기와 상태 표시줄의 영역별 비교를 유지합니다. 전후 스크린샷, 커밋과 측정값은 해당 issue 또는 Actions 산출물에만 두고 특정 실행 결과를 사양에 기록하지 않습니다. 모바일 검토는 영역별로 수행하고 차이를 감추려고 데스크톱 레이아웃을 바꾸지 않습니다.

원본은 한 항목을 선택하면서 전체 선택을 비워 두고 절약률 26%를 표시하면서 막대는 약 56% 채웁니다. 이는 모순된 정적 상태입니다. HTML은 문서화된 의미상 예외로 각각 부분 선택 `indeterminate`와 실제 26% 채우기를 유지합니다. 미리 보기 전용 검사는 일반 오버플로와 긴 콘텐츠 스크롤을 다루고 기존 상호작용 검사는 선택, 탐색, 정렬, 검색과 예제 동작을 다룹니다. 형상 검사는 기능 검증을 대체하지 않습니다.

본문 검토, 같은 크기의 영역별 비교와 측정 증거는 [검증 방법](../../../developers/qa/README.md)에 따라 별도로 저장합니다. 알 수 없는 원본 글꼴, 생성된 부드러운 가장자리, 조명과 안티앨리어싱 차이에 대한 설명을 유지합니다. 이 HTML 증거는 Qt 제품의 해당 보정을 입증하지 않습니다.

<a name="xdzip-checks-and-delivery"></a>

## 검사와 전달

실행:

```sh
python scripts/build-html-design.py
python scripts/check-html-header.py
python scripts/check-html-body.py
python scripts/check-html-preview.py
python scripts/check-html-references.py
python scripts/check-html-scale.py
python scripts/check-html-design.py
python scripts/build-html-header-review.py
python scripts/build-html-body-review.py
```

머리글 검사는 독립된 원본 앵커를 사용합니다. DOM 경계와 중심의 편차는 최대 1 px이고 분리된 영역의 실제 아이콘 잉크 경계는 최대 2 px입니다. 흰 드롭다운 화살표 잉크의 허용 오차는 1 px이며 탭 오른쪽 어깨는 원본 흰 표면과 곡선을 샘플링하고 부드러움에 대해 단일 채널 허용 오차 10/255를 적용합니다. 글리프 윤곽은 측정하고 기록만 합니다. 오버레이와 차이 이미지에는 안티앨리어싱, 조명과 글리프 차이가 포함되므로 총 픽셀 차이를 만들어 낸 유사도로 바꾸지 않습니다.

오프라인 머리글 파일은 `dist/xdzip-header-review.html`, 본문 파일은 `dist/xdzip-body-review.html`입니다. 둘 다 원본, 이전, 이후, 투명 오버레이와 픽셀 차이를 전환하며 본문 검토는 모바일 영역 선택도 제공합니다. 단일 파일 UI는 `dist/xdzip-hifi-design.html`입니다.

이 HTML 검사와 오프라인 검토는 필요할 때 로컬에서 실행하며 데스크톱 제품 CI의 기본 항목이 아닙니다. 형상 검사가 통과한 후에도 앵커 실패를 조사하고 오버레이 증거를 살펴봅니다. 기본 창 HTML 검사는 다른 페이지나 Qt 제품의 보정 및 네이티브 데스크톱 검수를 대체하지 않습니다.

기본 창과 메뉴의 일반 밀도는 [UI 표준](design-standard.md)을 따릅니다. Qt 메뉴와 목록의 글꼴 크기 비율은 함께 검사해야 합니다. 로컬 HTML 검토 시 [검증 방법](../../../developers/qa/README.md)에 따라 실제 페이지 확대율을 확인합니다. 이전 원본 이미지 좌표와 일치하는 것만으로는 이를 대체할 수 없습니다.
