# xdzip 시각 사양

사양의 출발점은 [UI 디자인 표준](design-standard.md), [필수 디자인 절차](design-workflow.md), [밀도와 단위 계약](../../../specs/visual/layout-scale.json)입니다. 기본 창과 메뉴의 비율 재검증은 [공통 방법](../../../developers/qa/README.md)에 따라 기록합니다.

현재 설계 참고 자료는 [design/hifi](../../../design/hifi/README.md)에 있습니다.

[tokens.json](../../../specs/visual/tokens.json)은 테마와 공통 구현 매개변수를 담으며 기계가 읽을 수 있는 시각 입력은 `specs/visual/`에 있습니다. 기본 창의 형상과 글꼴은 고정밀 원본과 측정값을 바탕으로 1024/1548로 환산한, 독립적으로 고정된 [qt-main-reference.json](../../../specs/visual/qt-main-reference.json)에서 생성합니다. 이전의 너비 1280 기준은 일반 밀도로 변환했습니다. 반올림, 실제 스크린샷과 미구현 기능은 [검증 방법](../../../developers/qa/README.md)에 따라 별도로 기록하며 구현 매개변수 자체를 디자인 승인 기준으로 삼을 수 없습니다.

## 조사 근거와 적용

1. [공식 Bandizip Windows UI](https://www.bandisoft.com/bandizip/screenshots/): 디렉터리 트리, 파일 표, 명확한 추출 진입점과 상태 표시줄을 유지하고 크고 화려한 도구 모음을 텍스트와 가는 선 아이콘으로 단순화해 하나의 주요 동작을 강조합니다.
2. [공식 Bandizip macOS UI](https://www.bandisoft.com/bandizip.mac/screenshots/): 공식 파일 탐색 시연과 압축 파일 생성 패널을 살펴보고 내용과 추출 위치를 선택하기 전에 탐색하는 흐름을 유지합니다.
3. [Bandizip 추출 안내](https://www.bandisoft.com/bandizip/help/how-to-unzip/): 파일을 열어도 자동 추출하지 않습니다. 사용자가 대상, 범위와 충돌 처리를 확인한 뒤에만 작업을 시작합니다.
4. [공식 Transmit UI](https://panic.com/transmit/): 파일 관리자 수준의 정보 밀도, 경로 탐색과 절제된 구분선을 참고합니다.
5. [Linear 2026 디자인 개편](https://linear.app/now/behind-the-latest-design-refresh): 중앙 내용을 강조하는 차분한 사이드바, 간결한 탐색, 부드러운 테두리와 중립적인 배경을 참고합니다.

조사는 2026-10-11에 공개된 공식 스크린샷, 시연과 기사를 이용해 진행했으며 각 제품의 현재 설치 가능한 최신 버전을 나타낸다고 주장하지 않습니다. 제3자 조사 자료는 별도 실험 작업 공간에 보관하며 이 저장소에는 포함하지 않습니다.

## 시각 시스템

따뜻한 회색 배경, 코발트색 주요 동작과 흑연색 어두운 테마를 사용합니다. 큰 그라데이션이나 반투명 유리 배경으로 정보 계층을 대신하지 않습니다. 일반 파일 목록은 명확하고 평평한 구조를 유지하며 그림자는 오버레이에만 사용합니다. 왼쪽은 ‘어디인가’, 가운데는 ‘무엇이 있는가’, 오른쪽은 ‘무엇을 선택했는가’에 답합니다.

Qt는 [Xdzip Design Sans SC](../../../design/assets/fonts/README.en.md)의 글리프와 측정값을 공유합니다. Qt는 같은 소스의 TTF를 사용하고 부분 집합 밖의 압축 파일 이름에는 플랫폼 대체 글꼴을 사용합니다. 기본 목록 텍스트는 13, 머리글과 도구 모음은 12, 패널 제목은 13 논리 픽셀이며 Qt 글꼴 픽셀의 정수로 반올림합니다. 파일 이름은 접근성 이름에 전체를 보존하고 화면에서 생략할 때는 말줄임표와 전체 이름 호버 힌트를 사용합니다. 파일 아이콘은 약 31.75 논리 픽셀의 공통 슬롯을 쓰며 유형별 크기 보정은 하지 않습니다.

기본 창의 초기 크기는 1024 × 622, 최소 크기는 832 × 544 논리 픽셀입니다. 사이드바와 미리 보기의 원본 측정값은 약 193.16 / 257.98이며 Qt 구조 경계에서는 193 / 258로 반올림합니다. 디렉터리 행은 약 43, 파일 행은 44.65입니다. 패널 제목의 높이는 46, 표 머리글은 34, 검색과 주요 버튼은 약 33.74입니다. 디렉터리 트리 B는 독립적으로 높이 32와 아이콘 슬롯 16을 유지합니다. 너비가 928 미만이면 미리 보기를 접고 버튼을 통해 별도 네이티브 창으로 엽니다. 설정에서는 글꼴 크기 100%/125%/150%를 제공하며 이전의 200% 값은 150%로 읽습니다. 큰 글꼴은 넘침을 감추는 전체 확대 대신 실제 레이아웃, 스크롤과 별도 상세 창을 사용합니다. 패널 드래그와 너비 저장은 구현되지 않았습니다.

## 기본 창 상호작용

- Qt는 독립적인 압축 파일 세션을 지원하며 저장된 열기 방식에 따라 캡슐형 탭 또는 기본 창을 만듭니다. 다시 열면 기존 세션을 활성화합니다. 페이지는 경로, 선택, 정렬 및 스크롤 상태를 유지하며 페이지를 닫아도 작업은 계속됩니다. [애플리케이션 세션 계약](../engineering/application-sessions.md)을 참조하세요.
- 선택이 없으면 주요 버튼은 ‘모두 풀기’, 선택이 있으면 ‘선택 항목 풀기’입니다. 드롭다운에는 항상 다른 범위가 제공됩니다.
- 파일 표는 정렬, 다중 선택, 범위 선택과 키보드 탐색을 지원합니다. 폴더를 두 번 클릭하면 들어가고 일반 파일을 두 번 클릭하면 임시 사본을 추출해 시스템으로 엽니다. 속성 카드에는 지원되는 단일 파일이 자동으로 미리 표시됩니다. 범위와 안전성은 [미리 보기 계약](../engineering/content-preview.md)을 참조하세요.
- 검색은 현재 디렉터리와 하위 항목을 재귀적으로 대상으로 하며 루트 검색은 전체 내용을 대상으로 합니다. 결과에는 압축 파일 안의 전체 경로를, 일반 디렉터리 목록에는 마지막 이름을 표시합니다.
- 상세 정보를 닫았다가 다시 열 수 있습니다. 미리 보기에는 비동기 읽기와 리소스 제한이 필요하며 지원하지 않는 항목에는 속성과 추출 진입점을 표시합니다. 작업 취소 후 늦게 도착한 미리 보기 결과는 버립니다.
- 상태 표시줄에는 선택 개수와 원본 크기, 인덱스 상태, 다시 열 수 있는 작업 기록 개수를 표시합니다. 실행 중 작업 수는 힌트와 종료 보호를 별도로 결정합니다. 완료되지 않은 인덱스에는 완전한 개수를 임의로 만들지 않고 ‘읽는 중’으로 표시합니다.

## 추출 패널 상호작용

패널은 압축 파일, 대상, 선택 범위, 충돌 정책과 완료 동작을 묶습니다. 예시 선택 크기는 8.4 + 6.2 + 12.8 = 27.4 MB입니다. 파일 목록은 요약이며 더 큰 목록에는 ‘모두 보기’를 제공합니다.

기본 대상은 마지막으로 사용한 디렉터리입니다. ‘압축 파일 이름으로 폴더 만들기’는 불필요한 중첩을 피하도록 최종 경로 미리 보기를 즉시 갱신합니다. 경로 권한, 여유 공간과 압축 파일 읽기 실패를 텍스트로 표시합니다. 확인 중은 별도 상태로 표시하고 확인되지 않은 공간은 ‘알 수 없음’으로 표시합니다.

충돌의 기본값은 묻기이며 건너뛰기, 자동 이름 변경과 덮어쓰기도 사용할 수 있습니다. 덮어쓰기의 결과를 명확히 표시합니다. 실행 중에는 실제 단계, 처리한 파일 수, 바이트 진행률과 계산할 수 있는 속도를 표시하고 총량을 모르면 불확정 진행률을 사용합니다. 취소 후에는 백그라운드가 중지 완료를 확인할 때까지 ‘중지 중’을 표시합니다.

## 구성 요소 상태와 접근성

| 구성 요소 | 필요한 상태와 피드백 |
| --- | --- |
| 주요 버튼 | 일반, 호버, 누름, 키보드 포커스, 비활성화, 제출 중. 중복 시작 방지 |
| 파일 행 | 일반, 호버, 선택, 창이 포커스를 잃은 상태의 선택, 키보드 포커스. 선택 시 텍스트 색상 외의 변화도 제공 |
| 검색 | 비어 있음, 입력 중, 검색 중, 결과 없음, 지우기. Escape는 텍스트를 유지하고 포커스를 벗어남 |
| 미리 보기 | 선택 없음, 로딩 중, 로드됨, 미지원, 오류, 취소됨 |
| 작업 | 대기, 실행, 암호 또는 충돌 결정 대기, 중지 중, 완료, 일부 실패, 실패 |
| 모달 패널 | 포커스 제한, 제출 전 패널은 Escape로 닫기, 시작 버튼으로 포커스 복귀 |

Qt 구현 후 테마 색상의 본문 대비가 WCAG AA를 충족하는지 확인합니다. 추가 포커스 링을 그리지 않고 현재 디자인 표준에 따라 포커스 표시와 이탈을 처리합니다. 스크린 리더용 이름과 상태 알림을 제공하고 시스템의 동작 감소 설정을 존중합니다. 일반 전환의 권장 시간은 120–160 ms이며 장식용 파일 목록 효과를 계속 애니메이션하지 않습니다.

## Qt Quick 구현 제약

Qt는 공통 `Theme`과 생성된 치수를 사용합니다. `ArchiveTabs`, `ArchiveToolbar` 및 `SessionPage`의 목록, 격자, 디렉터리 부분은 기본 레이아웃을 공유합니다. `InspectorPanel`, `ExtractWindow`, `CreateWindow`, `TaskWindow`는 각자의 데이터와 레이아웃 경계를 유지합니다. QML은 상태와 사용자 의도를 표현하고 Rust 런타임이 인덱싱, 압축 파일 읽기와 쓰기, 형식 검증을 담당합니다.

macOS, Windows와 Linux는 내용 레이아웃과 상호작용 모델을 공유하며 창 제어, 메뉴와 단축키는 플랫폼 관례를 따릅니다. 여기 그려진 macOS 프레임이 다른 플랫폼에 신호등 버튼 복제를 요구하지는 않습니다. 대규모 실시간 흐림은 구현 요건이 아니며 정적 마스크로 스크린샷의 배경 강조 감소를 재현할 수 있습니다.

기본 창의 밝은 테마 또는 어두운 테마와 함께 작업 상태, 설정, 데스크톱 통합을 검토합니다. 다른 상태나 크기 예외는 [창 레지스트리](../../../specs/visual/window-registry.json)에서 찾습니다. 디자인 페이지는 네이티브 창이나 메뉴의 내용을 보여줄 수 있으나 실제 장식, 활성화, 배율과 메뉴 동작은 해당 플랫폼에서 확인해야 합니다.

## 플랫폼 창 개정

작업 패널은 모두 [별도 플랫폼 창](../ux/platform-windows.md)이 됩니다. 이전 추출 원본의 내용 영역 닫기 버튼, 둥근 패널과 마스크는 별도 제목 표시줄과 플랫폼 장식으로 대체하며 색상, 글꼴과 내용 구조는 유지합니다. 현재 파일 유형 아이콘, 목록 정렬과 세 플랫폼 제목 표시줄에는 보조 검토 자료인 대화형 프로토타입이 있습니다.

## 원본과 공통 에셋 라이브러리

[전체 원본](../../../design/hifi/README.md)은 `design/hifi/screens/`에 있으며 기본 창, 추출 확인과 작업 상태 보드 8개를 포함합니다. 기능과 복구는 [상태 계약](../ux/hifi-state-spec.md)을 참조하세요. 원본 바이트를 보존하며 구현에 맞추려고 원본이나 슬라이스를 수정하지 않습니다.

[공통 에셋 라이브러리](../../../design/assets/README.md)는 기본 창과 작업 상태 에셋을 납품 배치별로 나누지 않고 통합합니다. 투명 런타임 아이콘의 유일한 그래픽 소스는 SVG이며 Qt에서는 같은 소스의 다중 해상도 PNG로 렌더링합니다. `reference/`의 원본 픽셀 비교용 슬라이스 45개는 원본 그림, 자르기와 배경을 보존합니다. 하나의 매니페스트로 용도를 식별해 배경이 있는 슬라이스를 투명 레이어로 착각하지 않게 합니다.

모든 투명 아이콘은 24×24 캔버스를 공유합니다. PDF, 텍스트, 코드와 Markdown 아이콘은 중심과 가시 높이 22픽셀을 공유하면서 실루엣 너비와 내부 스타일의 차이를 유지합니다. 폴더는 가운데 정렬된 가로형 가시 실루엣 22×약 18.86을 사용합니다. 이 높이 제약은 런타임 아이콘에 적용하며 원본 슬라이스에는 적용하지 않습니다. 1×/2×/3× PNG는 24×24, 48×48, 72×72이며 배율은 논리 크기를 바꾸지 않습니다. Qt는 동등 변환 후 약 31.75×39.69 논리 픽셀을 사용합니다. 유형별 CSS 확대, 이동 및 선 두께 보정을 제거합니다.

파일 목록의 이동 경로와 오른쪽 미리 보기 또는 상세 제목은 표시줄 높이, 글꼴 크기와 텍스트의 세로 중심을 공유합니다. Qt는 `PaneHeader`와 `Theme.mainPaneTitleSize`를 사용합니다. 제목은 스크롤 내용 위에 유지되며 큰 글꼴은 두 패널 높이를 함께 늘립니다. 실제 측정값은 [검증 방법](../../../developers/qa/README.md)에 따라 실행 아티팩트에 보관합니다.

사진 미리 보기는 패널 제목 바로 아래에서 시작하고 위쪽을 파일 목록 머리글에 맞추며 추가 상단 간격을 두지 않습니다. 검색 힌트가 나타나면 실제로 차지하는 공간에 따라 정렬합니다. 기존 이미지 높이와 아래쪽 간격을 유지합니다. 사진 정렬 재검사는 샘플 이미지 2개, 밝은 테마와 어두운 테마, 세 가지 창 장식 및 검색 변화를 다룹니다.

파일 목록의 원본 크기와 압축 크기 머리글 및 값은 오른쪽 정렬하고 유형 머리글과 내용은 왼쪽 정렬하며 각 열에서 공통 내용 패딩을 사용합니다. 소스 공간 기준 크기 열의 오른쪽 패딩은 26과 22픽셀, 유형 열의 왼쪽 패딩은 28픽셀입니다. 재검증 시 보이는 모든 행의 텍스트 레이아웃 경계를 기록합니다.

아이콘 실루엣, 원본 픽셀 슬라이스 크기와 런타임 캔버스 크기를 각각 기록합니다. 폴더를 종이 모양으로 늘릴 필요가 없으며 슬롯을 채우려고 SVG를 변형해서는 안 됩니다. 시각 변경은 그래픽 소스에서 수행하고 에셋 갤러리에서 검토한 뒤 두 구현에 동기화합니다.

## 디렉터리 트리 B 개정 (2026-10-12)

정식 보드 3개가 다단계 확장, 노드 상호작용과 탐색 경계를 정의합니다. [디렉터리 트리 사양](../ux/directory-tree.md)을 참조하세요. 원본 픽셀 슬라이스 26개가 공통 `assets/reference`에 들어가며 분기점, 채워진 상태 아이콘과 분할 스피너는 두 테마의 SVG와 세 해상도의 PNG를 사용합니다. 연결선, 상태 배경, 포커스와 텍스트는 [구성 요소 매개변수](../../../specs/visual/directory-tree.json)에서 동적으로 그리며 이것이 전역 토큰을 자동으로 덮어쓰지는 않습니다. 보드는 확대된 시각 설명이며 정확한 논리 치수와 소스 픽셀 사각형은 별도로 기록합니다. Qt는 재귀 디렉터리, 연결선과 숨겨진 현재 분기 표시를 통합하며 전용 경계 아이콘과 스켈레톤은 디자인 리소스로 남고 완전한 어두운 보드는 미완성입니다.

## 현재 기본 디자인 도구 모음 개정 (2026-10-12)

위의 이전 일반 제어 제안은 더 이상 기본 도구 모음에 적용되지 않습니다. 현재 원본 측정값은 높이 51 소스 픽셀, 글꼴 18 소스 픽셀, 아이콘 32 소스 픽셀이며 1024/1548로 환산하면 높이 약 33.74, 정수 글꼴 12, 아이콘 캔버스 21.17입니다. 도구 모음 영역 높이는 53입니다. 이전 너비 1280 기준 42.17/15/26.46 변환은 일반 밀도로 대체했으며 일반 작업 창은 등록된 대응 관계를 유지합니다.

일반 왼쪽 및 오른쪽 도구 모음 동작과 검색 및 주요 동작은 각각 그룹을 이룹니다. 큰 글꼴에서는 높이가 늘어나고 최소 창 크기에서 오른쪽 동작을 모두 표시하기 위해 검색 영역이 줄어들 수 있습니다. 비활성 텍스트에 그룹 불투명도를 적용하지 않으며 주요 버튼은 자체 비활성 배경을 가집니다. 추출 주요 버튼은 비활성 구분선과 화살표 모양을 유지하며 실제 추출과 범위 메뉴는 런타임 기능을 따릅니다. 선택이 없으면 선택 범위와 메타데이터 사전 검사가 비활성화되고 무결성 검사는 압축 파일의 기능을 따릅니다. 재검증은 [공통 검증 방법](../../../developers/qa/README.md)에 따라 기록합니다.

## 애플리케이션 브랜드와 플랫폼 아이콘

각 형식의 시스템 문서 아이콘은 [파일 연결 아이콘 사양](file-association-icons.md)를 따릅니다. 이 계열은 이후 형식별 통합을 위한 디자인 에셋으로 아래의 브랜드 형상을 재사용하면서 형식 레이블, 강조색과 작은 크기 단순화를 구분합니다.

브랜드는 서로 엮인 띠 4개와 아래가 열린 U자 형태를 사용하며 형상은 `scripts/brand_assets.py`에서 관리합니다. 독립 마크, 애플리케이션 아이콘과 ZIP 문서 마스터는 `design/assets/brand/`에 있습니다. UI의 `app-mark`, `archive`, `archive-grey`는 각각 애플리케이션, 파란 압축 파일과 회색 압축 파일을 나타내며 모두 같은 브랜드 형상에서 생성합니다. 애플리케이션은 파란 둥근 외곽을, 문서는 접힌 모서리가 있는 종이를 사용합니다. 정체성은 공유하지만 외곽은 서로 다른 역할을 합니다.

현재 마크는 가는 2:3 가로세로 비율을 유지하며 이전 마크의 너비로 늘리지 않습니다. 바탕은 네 모서리에 회전 대칭의 연속 곡률 곡선을 사용하며 직선 가장자리의 0에서 대각선 중점까지 곡률을 부드럽게 증가시켜 중간이 깎인 모양을 피합니다. 조명과 바탕은 하나의 경로를 공유하며 반지름이 다른 선이나 열린 하이라이트 선을 겹치지 않습니다. 문서 배지도 같은 윤곽 정의를 사용합니다.

이는 이전 고정밀 원본의 ZIP 지퍼 아이콘을 구분할 수 없게 복제한 것이 아니라 명시적인 새 브랜드 개정입니다. 전체 원본 10개, 원본 픽셀 아이콘 참조 45개와 예시 사진 3개는 원본 바이트를 보존합니다. 새로 생성된 `brand/identity-reference.png`는 현재 브랜드 방향의 검토 참조이며 런타임 에셋이 아닙니다. 기본 에셋 매니페스트는 참조 범위를 기록하고 이전 브랜드 참조를 과거 디자인 역할로 명시합니다.

작은 UI 아이콘은 24×24 캔버스를 유지합니다. 플랫폼 아이콘은 16/24/32/48/64/128/256/512/1024픽셀의 투명 PNG를 내보냅니다. 16/24/32 크기에서는 읽을 수 없는 텍스트와 큰 이미지용 조명을 단순화하면서 엮인 띠와 U자 인식 구조를 유지합니다. 애플리케이션과 ZIP 문서 아이콘은 각각 7개 크기의 ICO와 11개 밀도 표현의 ICNS를 제공합니다. 시스템 용도로 24단위 UI 아이콘을 무한히 확대하거나 큰 그림자를 축소해 작은 크기의 잡음으로 만들지 않습니다.

시스템 애플리케이션 아이콘은 Qt 창, macOS 앱 번들, Windows 실행 파일 리소스와 Linux 데스크톱 실행기 및 hicolor 디렉터리에 통합됩니다. ZIP 문서의 플랫폼 형식은 설치 프로그램과 파일 연결에 사용하며 시스템 열기 요청은 통합 라우팅을 통해 실제 탐색으로 전달합니다. [설치 및 연결 계약](../engineering/installers-associations.md)을 참조하세요. 사용자의 기본값을 변경하지 않고 열기 후보만 등록합니다. 플랫폼 검증은 [공통 방법](../../../developers/qa/README.md)에 따라 기록합니다.

누락된 테마, 성공, 취소, 충돌과 진행 그래픽은 원본 픽셀 참조를 바탕으로 의미가 구별되는 에셋으로 완성합니다. 큰 취소 그림은 사각형 중지 기호를 사용하고 시스템 테마는 전체 창 구조를 유지합니다. Qt는 IntentRadioButton으로 마우스, 키보드와 접근성 동작을 하나의 선택 모델로 전달합니다. 에셋은 모양만 담당합니다. 생성 검사, 대상 플랫폼 표시와 원본과의 차이를 별도로 기록하며 기존 승인이 이 개정의 결과를 대신할 수 없습니다.

## 대화형 컨트롤 사양

[controls.json](../../../specs/visual/controls.json)은 메뉴 열, 행 높이, 반지름, 색상, 포커스와 힌트 시간을 정의하고 [directory-tree.json](../../../specs/visual/directory-tree.json)은 디렉터리 계층을 정의합니다. 두 사양에서 QML Theme를 생성하며 검사를 통해 치수와 테마의 수동 중복을 방지합니다. 기본 디자인의 논리 픽셀과 소스 픽셀 비율은 `layout-scale.json`에서 가져옵니다. 기능 목록과 입력 계약은 [기본 창 구성 요소 설명](../ux/main-window-components.md)을 참조하며 실제 렌더링과 동작은 [검증 방법](../../../developers/qa/README.md)에 따라 해당 issue와 아티팩트에 기록합니다.
