이 표준은 UI 제작과 Qt 구현에 적용됩니다. 치수 변환은 [layout-scale.json](../../../specs/visual/layout-scale.json), 색상, 공유 컨트롤 및 디렉터리 트리는 각각 [tokens.json](../../../specs/visual/tokens.json), [controls.json](../../../specs/visual/controls.json), [directory-tree.json](../../../specs/visual/directory-tree.json)을 따릅니다. 원본 측정값은 [qt-main-reference.json](../../../specs/visual/qt-main-reference.json)에 있으며 구현 결과로부터 원본을 역으로 다시 쓰지 않습니다.

## 콘텐츠 미리 보기

콘텐츠 상태는 기존 속성 카드의 너비, 높이, 반경, 주 창 밀도 및 텍스트 역할을 유지합니다. 안쪽 여백, 간격, 아이콘 및 로딩 표시기 매개변수는 layout-scale.json의 main.content_preview에서 생성합니다. 단일 파일 선택 시 보이는 속성 카드에서 미리 보기를 자동으로 시작합니다. 로딩, 비밀번호 대기, 일반 텍스트, 이미지, 오류 및 다중 선택은 카드를 공유하며 읽기나 비밀번호 대기 중 취소에 접근할 수 있습니다. 다중 선택 메시지 위의 파일 유형 아이콘 두 개는 기존 미리 보기 아이콘 크기를 사용하고 가로 16픽셀, 세로 8픽셀만큼 겹칩니다. 카드는 사용 가능한 메타데이터 중 선택 항목의 목록 순서를 사용하며 메타데이터가 없으면 일반 파일 아이콘을 사용합니다. 포인터 호버나 키보드 포커스 시 오른쪽 위에 떠 있는 ArchiveAction이 나타납니다. 정사각형은 28논리 픽셀, 반경 3픽셀, 안쪽 여백 6픽셀, 새로 고침 글리프 16픽셀입니다. 텍스트는 선택 가능한 일반 텍스트이며 선택에는 공유 강조 배경과 accentText 전경을 사용합니다. 이미지는 종횡비를 유지하며 래스터와 제한된 정적 SVG는 브라우저, HTML 또는 외부 링크 실행 없이 이미지 슬롯을 공유합니다. SVG는 제한된 워커에서 래스터화하고 원본을 QML에 전달하지 않습니다. 주 창과 독립 속성 뷰어는 InspectorPanel을 재사용하며 미리 보기를 닫거나 항목을 바꾸면 즉시 지웁니다. 비밀번호 창은 [비밀번호 요청](../ux/password-extraction.md) 레이아웃과 공유 footer를 유지하고 미리 보기 작업에 대한 문구만 바꿉니다. 주 창과 메뉴 비율은 여전히 동시에 재검증해야 합니다.

## 인터페이스 글꼴과 사용자 데이터

Qt 시작 시 고정 UI 텍스트용으로 포함된 Noto Sans SC 파생 부분 집합을 설치하기 전에 시스템 기본 글꼴 패밀리를 캡처합니다. 파일, 압축 파일 및 디렉터리 이름, 경로와 이를 포함하는 메시지 또는 필드는 캡처한 패밀리를 우선하며 누락된 글리프는 Qt/플랫폼 대체를 사용합니다. 파일 이름이 포함된 복합 메시지는 전체에 시스템 글꼴을 사용할 수 있으며 정적 자리표시자와 작업 텍스트는 UI 글꼴을 유지합니다. 표시, 디렉터리 트리 너비 및 드래그 미리 보기 측정은 해당하는 동일 글꼴을 사용합니다. 글꼴 크기는 여전히 논리 치수와 접근성 배율을 따르며 시스템 DPI는 구성 요소의 논리 치수를 바꾸지 않습니다. 실제 사용자 데이터 글리프와 너비는 런타임 플랫폼에 따르며 구조 치수는 같은 논리 규격을 따릅니다.

## 단위와 밀도

1. 모든 치수는 Qt 장치 독립 논리 픽셀로 제공합니다. 스크린샷의 물리 픽셀은 디자인 값과 비교하기 전에 DPR로 나눕니다. 1×/2×/3× 에셋은 샘플링 선명도에만 영향을 주며 아이콘 슬롯에는 영향을 주지 않습니다.
2. 이전 너비 1280인 주 창 기준을 125%로 보고 `1 / 1.25 = 0.8`로 100%에 변환합니다. 새 기본 클라이언트 영역은 1024×622, 최소는 832×544, 미리 보기 접기 임계값은 928입니다. 이 밀도 보정을 제목, 도구 모음, 패널, 파일 목록, 디렉터리 트리, 상태 표시줄 및 글꼴에 적용합니다.
3. 팝업 메뉴와 힌트는 주 창과 함께 축소하지 않고 일반 밀도를 사용합니다. 메뉴 기본값은 너비 240, 최소 행 높이 32, 글꼴 13 및 아이콘 슬롯 18입니다. 주 목록 목표 글꼴은 약 12.57이며 Qt에서 13으로 반올림합니다. 메뉴/목록 글꼴 비율은 0.95–1.10이어야 합니다. 개별 매개변수와 비율을 함께 검사합니다.
4. 원래 주 클라이언트 영역 1548×940은 측정 좌표입니다. 기본 참조는 `1024 / 1548`로 변환하며 메뉴는 위 논리 치수를 유지합니다. 일반 작업 창은 `1280 / 1548`을 유지합니다. 추출 원본은 별도 `819.2 / 1548` 매핑과 약 491 창 너비를 사용하며, 이는 이전에 내장 진입점보다 25% 컸던 독립 진입점의 명시적 밀도 보정입니다. 모든 진입점은 최종 논리 크기를 공유하며 내장 및 독립 표시 간 구성 요소 글꼴이 달라서는 안 됩니다.
5. 브라우저 검토 배율, 페이지 확대, 시스템 배율 및 DPR은 구성 요소 크기 매개변수에 들어가지 않습니다. Qt는 밀도 보정에 `Item.scale`, 축소한 스크린샷 또는 추가 1.25 배율을 사용하지 않으며 규격 매개변수로 실제 레이아웃과 정수 pixelSize를 생성합니다.
6. 논리 픽셀 1개 두께의 구분선과 포커스 선은 지정값을 유지하고 OS가 네이티브 창 장식을 담당합니다. 소수 공간 치수는 유지하고 구조 경계와 창 크기는 가장 가까운 정수로 반올림합니다. Qt 글꼴 크기는 밀도 변환 후 접근성 배율 적용 전에 반올림합니다.

새 작은 배지와 태그는 모서리 반경 3논리 픽셀을 사용합니다. 더 큰 반경은 명시적으로 승인된 구성 요소 형태에만 사용하며 작은 태그가 캡슐 모양이 되지 않게 합니다. 표준 버튼, 필드 및 창은 공유 기하를 사용합니다.

## 제목 영역 개정

주 제목 표시줄 높이는 48논리 픽셀입니다. 탭은 높이 32, 반경 16의 떠 있는 캡슐이며 위아래 여백은 각각 8입니다. 활성 탭은 완전한 테두리를 가지며 도구 모음에 붙지 않습니다. 탭 닫기, 더하기 및 설정은 제목 표시줄의 세로 중심을 공유합니다. 큰 글꼴은 위아래 여백을 같게 유지하면서 먼저 캡슐 높이를 늘립니다. 이는 보관된 원본의 아래쪽에 붙은 탭을 대체합니다.

활성 탭 굵기는 600, 비활성은 400이며 활성 윤곽선 없이 호버 시에만 공유 채우기를 사용합니다. 탭은 기존 선호 너비와 최소 112 사이에서 사용 가능한 너비를 나누며 글자가 커지면 상하한이 증가합니다. 넘침은 보이는 스크롤바 없는 가로 뷰포트를 사용하고 설정이나 시스템 버튼을 압박하지 않으면서 새로 만들기, 양방향 스크롤 및 탭 목록 항목을 유지합니다. 휠, 트랙패드, 키보드 전환, 메뉴 활성화 및 드래그 가장자리 스크롤은 하나의 제한된 뷰포트를 공유합니다. 열기, 전환, 닫기 및 크기 변경 후 활성 탭은 완전히 보이며 사용자가 명시적으로 스크롤한 위치를 되돌리지 않습니다. 창 내부 드래그는 떠 있는 캡슐과 삽입 표시를 보이고 놓으면 안정적인 세션 식별에 따라 재정렬하며 Escape 또는 입력 취소는 드래그를 버립니다. 매개변수는 스크린샷 픽셀이 아닌 layout-scale.json의 titlebar에서 가져옵니다.

탭 닫기는 정사각형 적중 영역과 중앙 위치를 유지하며 호버/눌림 배경은 원형입니다. 오류 없는 단일 일반 유휴 시작 페이지에서는 숨기고 로딩, 오류, 여러 탭 및 압축 파일 탭에서는 기존 표시를 유지합니다. 숨겨진 버튼은 키보드 포커스를 받거나 보이는 접근성 동작으로 나타날 수 없습니다.

시작 페이지 로딩 카드의 본문은 스크롤하며 “불러오기 취소”는 오른쪽 아래 고정 작업 영역에서 공유 OperationFooterButton을 사용합니다. 로딩은 추출이 아니며 “추출 취소”를 재사용하지 않습니다. 취소 후 취소 중을 표시하고 중복 제출을 비활성화하며 로딩이 끝나면 시작 페이지 포커스를 복원합니다. 카드 논리 너비는 360, 안쪽 여백은 24이며 footer 모양을 덮어쓰지 않고 반투명 오버레이와 공유 버튼 치수를 유지합니다.

열려 있는 압축 파일을 기다리는 수정 작업은 layout-scale.json의 operation_overlay 투명도를 적용한 카드 매개변수를 재사용합니다. 중복 동작을 차단하는 동안 원래 파일 페이지는 계속 보입니다. 제목, 설명, 진행 접근성 이름 및 취소는 실제 추가, 이동, 이름 변경 또는 삭제 작업을 명시하며 작업 정리와 디렉터리 새로 고침 후 상호 작용을 복원합니다. 수락된 취소는 무효가 된 충돌 및 비밀번호 요청을 즉시 닫고 진행 상태는 취소 중을 표시하며 실제 종료 상태를 따릅니다. 충돌 창은 특정 작업과 요청 토큰에 바인딩되며 작업이 바뀌거나 토큰이 만료되면 닫힙니다.

현재 [밝은 주 창](../../../design/hifi/screens/main-capsule-light.png), [어두운 주 창](../../../design/hifi/screens/main-capsule-dark.png) 및 [다단계 디렉터리 디자인](../../../design/hifi/screens/directory-tree-capsule.png)은 이 제목 영역을 사용합니다. 이전 주 창과 디렉터리 원본은 독립 측정, SHA-256 및 조각 출처를 바꾸지 않고 `design/hifi/screens`에 남으며 현재 내보내기는 독립 기하 검증을 대체하지 않습니다.

목록과 격자 항목 메뉴는 압축 파일 항목 편집 디자인과 표준 팝업 밀도를 공유합니다. 이름 변경과 삭제는 스크롤 가능한 본문과 고정 footer가 있는 공유 491논리 픽셀 확인 창을 사용합니다. 파일 이름은 시스템 사용자 데이터 글꼴을 사용합니다. 이름 변경은 공유 필드에 포커스를 주고 파일의 확장자를 제외한 이름을 선택합니다. 삭제는 열 때 취소에 포커스를 둡니다.

## 구성 요소 규칙

### 설정 창 범주 개정

소유자 없는 트레이 설정과 정보는 현재 디스플레이 작업 영역과 전체 네이티브 프레임을 기준으로 공유 화면 중앙 정렬을 재사용합니다. 오른쪽 아래 알림 영역 포인터 위치를 유지하지 않고 네이티브 생성과 높이 조정 후 다시 중앙 정렬합니다. 설정 치수, 타이포그래피 및 밀도는 변경하지 않습니다.

Windows MSIX ID에서는 정보 페이지의 업데이트 제목, 구분선 및 전체 업데이트 섹션을 생략하며 버전 정보는 기존 다음 공유 그룹 간격을 사용합니다. 창 치수, 글꼴 및 기타 콘텐츠는 변경하지 않으며 채널별 배율이나 밀도를 추가하지 않습니다.

설정과 정보는 너비 612논리 단위, 선호 클라이언트 높이 532인 비모달 창을 공유하며 사용 가능한 화면 높이로 제한합니다. 공유 OperationHeader 아래 1단위 구분선 다음에 사이드바 탐색과 독립적으로 스크롤하는 오른쪽 페이지가 옵니다. 사이드바 기준 너비는 144, 일반 행 높이 40, 아이콘 슬롯 18, 왼쪽에서 아이콘까지 15입니다. 첫 행은 위쪽에 닿고 선택은 오른쪽 구분선에 맞닿습니다. 큰 글자는 실제 가장 넓은 단어와 아이콘 간격에 맞춰 사이드바를 넓히며 영어는 단어 사이에서 줄 바꿈하고 행이 커지거나 스크롤됩니다. 선택되지 않은 항목의 호버는 두 테마에서 사이드바와 구분되는 공유 controlHover를 사용합니다. 페이지 안쪽 여백은 20, 그룹 간격은 16입니다. 매개변수는 스크린샷, DPR 또는 검토 배율이 아닌 layout-scale.json의 operation.settings를 따릅니다.

페이지는 모양, 일반, 개인정보, 파일 연결, 네트워크 및 정보입니다. 설정에는 footer나 저장, 취소, 완료 버튼이 없습니다. 성공한 변경은 즉시 적용하며 실패 시 적용된 값을 유지하고 이유를 표시합니다. 정보는 버전, 라이선스 및 사용자가 시작한 업데이트를 유지하며 모든 정보 진입점은 독립 정보 창 대신 이 페이지를 엽니다. 변경되지 않은 조각을 다시 생성하지 않고 테마 카드, 설정 아이콘, 브랜드 및 기존 상태 에셋을 재사용합니다.

설정 선택 행에서 설명과 오른쪽 정렬 선택기가 나란히 들어가지 않으면 설명을 선택기 위에 둡니다. MSIX 파일 연결 페이지의 공유 기본 앱 버튼은 콘텐츠 너비 안에 유지합니다. 긴 번역은 사용 가능한 너비에서 줄 바꿈하고 큰 글꼴에서도 읽을 수 있어야 합니다.

페이지 본문은 사이드바 제목이나 그 구분선을 반복하지 않으며 실제 섹션 제목과 구분선은 유지합니다. 정보의 기본 업데이트 동작은 상태 행을 공유하고 오른쪽 정렬합니다. 확인 중에는 확인 취소, 사용 가능 시 다운로드, 다운로드 및 설치 또는 릴리스 페이지, 다운로드 중에는 다운로드 취소, 완료 후에는 설치 또는 다운로드 위치 열기를 표시합니다. 확인과 확인 취소는 같은 위치와 크기를 유지하고 진행은 아래에 표시합니다. 보조 다운로드 위치 동작은 오른쪽 정렬합니다.

각 구성 요소는 치수, 글꼴, 아이콘 슬롯, 안쪽 여백, 정렬 기준선, 적중 영역, 상태 및 데이터 원본을 지정합니다. 기본 상태만으로는 부족합니다. 버튼은 일반, 호버, 눌림, 포커스, 비활성화 및 작업 중을 포함합니다. 메뉴는 키보드 선택, 하위 메뉴, 체크, 비활성화, 가장자리 반전 및 스크롤을 포함합니다. 트리는 계층, 리프, 접힌 현재 경로, 깊은 스크롤 및 긴 이름을 포함합니다. 목록은 헤더/콘텐츠 가장자리 정렬, 정렬, 다중 선택 및 비어 있거나 알 수 없는 상태를 포함합니다.

숫자 열은 공통 오른쪽 가장자리, 유형 열은 왼쪽에 정렬합니다. 탐색 경로와 미리 보기 제목의 높이, 글꼴 및 기준선을 맞추고 미리 보기 위쪽은 파일 헤더 위쪽에 맞춥니다. 아이콘은 슬롯 중앙에 두고 텍스트는 글꼴 메트릭으로 정렬합니다. 배경이 포함된 스크린샷의 임시 조각 대신 공유 에셋을 사용합니다.

파일 목록 체크박스 오른쪽 가장자리에서 아이콘 슬롯까지의 간격은 layout-scale.json의 fileSelectionGap에 따라 12논리 픽셀입니다. 이는 원래 약 21.17 간격을 줄이며 아이콘 슬롯, 아이콘/텍스트 간격 및 다른 열 경계를 유지하면서 파일 아이콘, 파일 이름 및 이름 헤더가 함께 왼쪽으로 이동합니다. 동결된 원본과 측정값은 변경하지 않습니다.

주 창 일반 밀도 보정과 접근성 글꼴 배율은 별도 단계입니다. 현재 옵션은 100%/125%/150%이며 이전 200% 설정은 150%로 읽습니다. 큰 글꼴은 높이를 늘리거나 스크롤 또는 독립 상세 표시를 허용하며 선택을 상쇄하기 위해 텍스트를 줄이지 않습니다. 200%를 직접 주입하는 테스트는 과거 스트레스 테스트일 뿐 현재 제품 옵션이 아닙니다. 모든 시각적 예외의 이유와 검증 범위를 기록합니다.

## 검증 조건

Qt를 같은 논리 너비에서 비교하고 원본의 바깥 배경만 잘라 명시적 배율로 표시합니다. 최대 기하 오차는 1논리 픽셀, 텍스트/아이콘 세로 중심 오차는 0.5, 정렬된 패널 위쪽 오차는 0.01입니다. 스크린샷 보고서는 커밋, 플랫폼, 렌더러, 브라우저 확대, 검토 배율, DPR 및 논리 창 치수를 명시합니다.

대응하는 Qt 측정은 높은 DPR에서 동일한 논리 창, 글꼴 및 메뉴 매개변수를 검증합니다. 도구는 CSS 확대를 실제 브라우저 페이지 확대로, 오프스크린 스크린샷을 네이티브 데스크톱 검증으로 속여서는 안 됩니다. 검사 수는 시각적 충실도의 백분율이 아닙니다.

[UI 디자인 워크플로](design-workflow.md)를 따릅니다. 규격, 생성 출력, 실제 좌표, 스크린샷 또는 상호 작용 증거가 없으면 전체 검증을 완료로 표시하지 않습니다.

## 주 창 상호 작용 개정

주 도구 모음의 아이콘/텍스트 간격은 6으로 고정하고 독립 아이콘은 콘텐츠 상자 중앙에 둡니다. 목록/격자/정렬 버튼은 28×28 고정 둥근 정사각형이며 헤더 간격은 6.4이고 탐색 경로가 남은 공간을 차지합니다. 탐색 경로 버튼은 일반적으로 높이 28과 세로 안쪽 여백을 사용합니다. 메뉴는 호출 버튼에서 4단위 떨어지며 아래쪽 메뉴는 위로 열립니다. 트리 행은 파일 수를 표시하지 않으며 선택된 왼쪽 가장자리는 전체 높이 표시기가 있는 직선이고 자식 노드에는 사방 윤곽선이 없습니다. 트리 너비는 펼친 노드의 실제 텍스트 메트릭을 사용합니다. 개정된 상호 작용과 측정은 [검증 방법](../../../developers/qa/README.md)에 따라 기록합니다.

## 작업 창 및 작업 상태 에셋

### 공유 아이콘 헤더

생성, 추가, 추출, 작업/결과, 충돌 및 설정 창은 OperationHeader를 공유합니다. 정보는 설정에 있고 무결성 검사는 TaskWindow를 통해 이를 상속합니다. 아이콘 슬롯은 48×48, 제목 20, 부제 13, 가로 안쪽 여백 24, 세로 안쪽 여백 20, 아이콘/텍스트 간격 16, 제목/부제 간격 6, 일반 높이 기준 96입니다. 아이콘은 창별 캔버스/그림 덮어쓰기 없이 종횡비를 유지하고 중앙에 놓습니다. 제목과 부제는 밝은/어두운 테마에서 text/textSecondary를 사용하는 일반 텍스트이며 글꼴 크기는 응용 프로그램 접근성 설정에 따라서만 바뀝니다. 긴 텍스트나 큰 글꼴은 텍스트를 축소하거나 본문/footer를 덮지 않고 공유 글꼴 메트릭에 따라 헤더를 늘립니다.

[operation.header](../../../specs/visual/layout-scale.json)는 유일한 매개변수 원본이며 창 매핑은 [window-registry.json](../../../specs/visual/window-registry.json)에 있습니다. 이는 창별 아이콘 슬롯, 중앙 정렬 24단위 정보 브랜드 및 창별 헤더 높이를 대체하며 과거 이미지, 해시 및 측정은 변경하지 않습니다. 텍스트 전용 비밀번호, 사전 검사 및 종료/재시작 헤더에는 임의의 장식 아이콘을 추가하지 않고 안전 상호 작용을 유지합니다. 주 창과 메뉴 밀도는 계속 별도 측정합니다.

작업 일러스트는 아카이브 아이콘의 접힌 종이와 XD 배지를 사용합니다. 작은 배지는 동작과 결과를 나타냅니다. PDF는 같은 종이에 빨간 PDF 배지를 사용합니다. 24단위 캔버스와 기존 아이콘 영역에 맞춰 표시합니다.

file-archive는 황토색 가로 이빨과 직사각형 손잡이가 있는 단순한 평면 파일 범주 기호를 유지하고 두 테마에서 같은 기호 색상을 사용하며 소스와 SVG 및 PNG 내보내기도 이 스타일을 유지합니다.

형태는 공유 24단위 벡터 캔버스를 사용하고 헤더는 공유 48논리 픽셀 슬롯을 유지합니다. 밝은/어두운 SVG와 1×/2×/3× PNG는 하나의 정의를 공유하며 archive-add와 file-archive는 9× 내보내기도 유지합니다. 브랜드 및 연결 아이콘은 브랜드 정의를 유지하고 과거 그림과 조각은 변경하지 않습니다.

일반 독립 창은 1280/1548 원본 좌표 변환과 약 612 너비를 유지합니다. 진행 원본은 819.2/1548로 일반 너비 491에 매핑하며 클라이언트 높이는 콘텐츠에 따라 최대 600, 제목 20, 본문 13, 공유 footer 글꼴 13/12입니다. 작업 창은 현재 검토 맥락의 원본 좌표로 역변환하며 추출에서 진행으로 들어갈 때 다시 축소할 수 없습니다. 추출은 [extract-reference.json](../../../specs/visual/extract-reference.json)에 동결된 원본 해시, 측정 및 매핑을 사용합니다. 너비 491, 제목 20, 본문 13, 경로 필드 높이 약 35 및 내장 변경 버튼 약 69×24입니다. Qt는 Item.scale이나 스크린샷 축소 없이 실제 레이아웃 크기를 사용합니다. 독립 및 내장 진입점은 같은 최종 치수를 산출해야 합니다.

추출 대상과 충돌 카드는 균일한 배경을 사용하고 범위는 연한 헤더 띠와 흰색 본문을 사용합니다. 밝은 카드는 #F4F6FA, 테두리는 #DFE5EF, 경로/드롭다운 테두리는 #DCE2EC이며 어두운 대응값은 tokens.json에 있습니다. 경로 아이콘, 편집 가능한 경로 및 변경은 하나의 테두리를 공유합니다. 체크박스는 공유 선택 그래픽을 사용합니다. 모든 작업 창은 선택, 비활성화, 키보드 탐색, Escape, 포커스 반환 및 가장자리 반전을 제공하는 xdzip 내장 드롭다운을 재사용합니다. 메뉴는 호출자에서 4논리 픽셀 떨어집니다.

모든 footer 버튼은 layout-scale.json에서 생성된 텍스트 13, 보조 텍스트 12 및 아이콘 슬롯 16논리 픽셀을 사용합니다. 본문은 별도로 스크롤하고 footer는 접근 가능합니다. 내장/독립 진입점에 따라 글꼴, 색상 및 1논리 픽셀 선이 바뀌지 않습니다. 실제 비교는 [검증 방법](../../../developers/qa/README.md)에 따라 기록합니다.

“압축 파일 이름으로 폴더 만들기”와 대상 검사 피드백은 24단위 아이콘 슬롯, 16단위 가시 표시 및 8단위 아이콘/텍스트 간격을 공유합니다. 시각적 중심과 텍스트 시작점을 맞추고 각 행은 텍스트와 표시를 세로 중앙 정렬합니다. 검사 또는 실패 중에도 아이콘 슬롯을 유지해 텍스트가 왼쪽으로 뛰지 않게 합니다. 변경의 오른쪽 안쪽 여백은 세로 안쪽 여백과 같으며 경로 필드와 실제 버튼 높이 차이의 절반으로 계산합니다. 큰 글꼴에서도 이 관계를 유지합니다.

작업 결과 원판은 [status-icons.json](../../../specs/visual/status-icons.json)의 단색 채우기와 흰색 의미 표시를 사용하고 24단위 캔버스와 가시 지름 20을 가지며 그라데이션, 하이라이트, 얇은 테두리 또는 그림자를 사용하지 않습니다. 밝은/어두운 SVG 및 1×/2×/3× PNG를 함께 내보냅니다. 기존 원본과 조각은 새 스타일로 다시 쓰지 않고 과거 픽셀을 유지합니다. 실제 검증은 [일반 방법](../../../developers/qa/README.md)에 따라 기록합니다.

## 루트 및 파일 항목 상호 작용

디렉터리 트리 맨 위의 “압축 파일”은 탐색 경로 제목과 세로 중심을 공유합니다. 일반 디렉터리 탐색은 직접 파일과 폴더만 표시하며 트리 항목은 “루트 폴더”입니다. 전체 압축 파일 경로는 데이터에 남고 일반 목록은 마지막 이름을, 검색 결과는 전체 경로를 표시합니다. 트리 호버에는 떠 있는 힌트가 없으며 전체 경로는 접근성 설명으로 남습니다. 부모 세로선의 X 중심은 부모 펼침 화살표의 X 중심에 맞춥니다.

목록 호버는 행의 모든 열을 덮으며 선택 채우기가 우선합니다. 격자 가로 안쪽 여백은 16, 카드 슬롯 144×124, 슬롯 간격 12, 아이콘 슬롯 40입니다. 체크박스는 카드 왼쪽 위에서 8×8 위치에 있으며 호버 시 나타나고 선택 시 계속 보입니다. 접근성 글꼴은 실제 메트릭에 따라 슬롯을 늘립니다. 미리 보기 다시 열기 버튼도 28×28입니다. 메뉴 그림자 반경은 12, 세로 오프셋은 4입니다. 고정 Qt 행 높이는 레이아웃 행 슬롯 높이와 같아야 하며 고정 슬롯에 추가 글꼴 행간을 넣지 않습니다. 백분율 행 슬롯은 24, 바이트/파일 수 슬롯은 18입니다. 경로 카드 제목과 지표는 지정된 행 높이를 유지하며 여러 줄 지표는 실제 줄 수에 따라 늘어납니다. 기본 글꼴 크기에서 진행 창의 세 본문 설명을 모두 표시하며 작은 화면이나 큰 텍스트에서는 footer를 고정하고 접근 가능하게 유지하면서 본문을 스크롤할 수 있습니다.

각 주 창은 현재 독립 OS 창인 ExtractWindow, CreateWindow 및 TaskWindow를 각각 하나씩 소유합니다. 추출, 생성 및 실제 무결성 검사 진행/결과는 TaskWindow를 재사용하며 다른 작업을 선택하면 상태마다 창을 만들지 않고 같은 창을 갱신합니다. 구성 요소 미리 보기는 별도로 IntegrityWindow를 사용하며 실제 검사를 수행하지 않습니다. [작업 창 계약](../ux/task-windows.md)을 참조합니다.

## 2026-10-16 Windows 주 창 개정

Ubuntu 제목 디자인을 참조합니다.

빈 제목 영역 드래그는 startSystemMove를 호출하고 더블 클릭은 최대화/복원을 전환합니다. Windows는 WS_THICKFRAME을 유지합니다. Windows 11은 WS_CAPTION을 유지하고 Windows 10 클라이언트 버전은 해당 제목 스타일이 사용자 지정 제목 표시줄을 덮지 않도록 제거합니다. 네이티브 적중 검사는 가장자리와 모서리를 처리하며 최대화는 시스템 작업 영역과 네이티브 크기 조절 여백을 사용합니다. DWM은 QML 둥근 사각형이나 그림자 대체물 없이 시스템 테두리, 그림자 및 지원되는 Windows 11 모서리를 제공합니다. 제목 버튼은 키보드 포커스와 접근성 이름을 유지하며 닫기는 기존 작업 결정과 비동기 종료 장벽을 따릅니다. 작업 창은 시스템 장식을 유지하고 macOS 네이티브 신호등은 변경하지 않습니다.

DWM 확장과 복원은 위쪽에 네이티브 장치 픽셀 하나를 유지하며 네이티브 크기 조절 메트릭은 창 DPI의 시스템 메트릭에서 가져옵니다. 이는 QML 논리 크기가 아닌 Win32 경계입니다. 어두운 프레임은 테마에 따라 갱신하고 DPI, 시스템 테마 및 합성 변경 후 다시 적용합니다. Qt 업그레이드 시 관련 크기와 상태 회귀를 다시 실행하고 물리 듀얼 모니터 드래그 및 네이티브 시각은 필요에 따라 검사하며 수행하지 않은 제한을 기록합니다. 지원되지 않는 모서리 속성이나 합성은 시스템 기능으로 대체하며 버전 간 동일한 장식을 주장하지 않습니다.

회귀는 네이티브 창 스타일, DWM 비클라이언트 렌더링, 조회 가능한 모서리 기본 설정과 보이는 테두리, 실제 클라이언트 치수, 최대화/복원, 최소화 및 닫기를 검사합니다. contentItem 스크린샷은 외부 프레임과 그림자를 입증할 수 없으며 데스크톱 합성 스크린샷과 상태 기록은 build/에 별도 저장하고 내부 캔버스 스크린샷으로 대체하지 않습니다.

전체 화면은 일반적인 위쪽 네이티브 픽셀 하나의 테두리나 가장자리 크기 조절 적중 영역 없이 시스템의 테두리 없는 클라이언트 영역 계산을 사용합니다. 그렇지 않으면 클라이언트 영역이 화면을 덮지 않아 최소화/복원 후 Qt가 상태를 일반으로 잘못 식별할 수 있습니다. 일반 및 최대화 창은 시스템 테두리, 모서리 기능 및 그림자 규칙을 유지하며 이러한 Win32 매개변수는 QML 논리 크기에 들어가지 않습니다.

과거 재시작 확인은 공유 창 규칙을 유지하며 설정 언어 변경은 이제 즉시 적용되어 이를 발생시키지 않습니다. 빈 생성 입력 목록은 안내 자리표시자 없는 빈 목록 상자로 남으며 추가와 아래의 실제 요약은 유지합니다.

## 네이티브 데스크톱 메뉴

부드러운 앱 내부 메뉴 그림자는 controls.json의 menuShadowAsset에서 공유 nine-slice PNG로 생성하고 팝업 시 흐린 Canvas 픽셀을 생성하지 않고 첫 프레임에 메뉴 본문과 함께 표시합니다. 밝은/어두운 테마와 접근성 글꼴 100%/125%/150%는 별도 에셋을 가지며 200%는 테스트 에셋으로 남습니다. 그림자 반경과 오프셋은 DPR에 따라 변하지 않습니다.

macOS 메뉴 막대와 모든 플랫폼의 트레이 메뉴는 네이티브로 그리며 글꼴, 행 높이, 선택 및 접근성은 시스템이 결정합니다. 앱 내부 팝업 너비 240이나 행 높이 32를 사용하지 않습니다. [데스크톱 통합 규격](../ux/desktop-integration.md)에 따라 디자인과 동작을 검증하며 주 창 밀도와 제목 매개변수는 변경하지 않습니다.

## 2026-10-19 확인 창 일반 밀도

종료, 작업 중지 및 과거 재시작 확인은 [operation.confirmation](../../../specs/visual/layout-scale.json)을 공유합니다. 클라이언트 너비 491, 제목 20, 본문 13, 콘텐츠 안쪽 여백 24, 단락 간격 12, 최대 높이 600이며 사용 가능한 화면으로 제한합니다. 높이는 실제 본문과 공유 footer에 따릅니다. 270/540 같은 고정 단계나 이전 기본 작업 창 612/25/16을 사용하지 않습니다. 본문은 스크롤하고 footer는 고정됩니다. 버튼 세 개는 글꼴을 줄이거나 넘치거나 세로로 쌓이지 않고 버튼 내부에서 텍스트를 줄 바꿈하여 영어 150%에서 공유 행 높이를 늘릴 수 있습니다. 중지 중에는 기하 정책을 보존하고 결정을 비활성화합니다.

SettingsWindow 너비 612와 독립 속성 뷰어 너비 360은 등록된 용도별 차이이며 같은 확인 유형의 불일치 크기가 아닙니다. 정보는 설정에 통합되어 독립 AboutWindow가 등록되지 않습니다. 전체 목록과 예외는 [window-registry.json](../../../specs/visual/window-registry.json)을 참조합니다.

## 비밀번호 추출 요청

PasswordWindow는 [password-reference.json](../../../specs/visual/password-reference.json)과 P02 독립 디자인을 따릅니다. 너비 491, 최대 높이 600, 본문 안쪽 여백 24, 제목 20, 본문 13 및 보조 텍스트 12입니다. 네이티브 제목 표시줄은 주 창 제목 표시줄을 바꾸지 않고 플랫폼이 그립니다. 본문은 스크롤하고 공유 footer는 고정되며 입력은 OperationField와 OperationFrame을, 표시/숨김과 footer 동작은 공유 버튼을 재사용합니다. 일반, 호버, 눌림, 비활성, 대기, 오류 재시도 및 밝은/어두운 테마는 기존 역할을 사용하며 새 윤곽선이나 footer 덮어쓰기는 없습니다. 비밀번호 정리, 요청 식별, 취소 및 빈 비밀번호 규칙은 [상호 작용 계약](../ux/password-extraction.md)에 있습니다.

시작 페이지 본문은 시작 영역 위쪽에서 고정 28논리 픽셀 아래에 시작하며 가로로만 중앙 정렬하고 본문 높이에 따라 세로 중앙 정렬하지 않습니다. 오류 피드백은 제목, 설명, 기본 동작 또는 드롭 영역 좌표를 바꾸지 않고 형식 힌트 뒤에 오며 긴 메시지는 자연스럽게 늘어나고 스크롤합니다. 피드백은 공유 위험 텍스트와 18논리 픽셀 status-warning 아이콘을 사용하고 간격 8, 위쪽 간격 10입니다. 접근성 역할은 AlertMessage이며 아이콘을 중복으로 알리지 않습니다. 매개변수는 welcome-reference.json에 있습니다.

## 압축 파일 추가 확인

UpdateWindow는 C01 [생성 그림](../../../design/hifi/screens/create.png)을 독립 참조로 사용하며 논리 너비 491, 제목 20, 본문 13, 보조 텍스트 12 및 공유 footer를 사용합니다. 아이콘 헤더 아래에는 파일 추가, 위치 추가 및 추가 옵션의 연한 카드 세 개가 있고 각각 흰색 내부 패널이 있습니다. 가로 콘텐츠 안쪽 여백은 18, 카드 안쪽 여백 13, 내부 패널 안쪽 여백 10, 카드 간격 10입니다. 대상 압축 파일과 내부 디렉터리는 읽기 전용 필드를 사용하고 충돌 정책은 공유 드롭다운을 사용합니다. 높이는 본문과 footer에 따라 최대 736과 사용 가능한 화면 높이까지 조정하며 본문은 독립적으로 스크롤하고 footer는 접근 가능합니다.

생성과 추가는 ArchiveInputPanel을 공유하며 기존 생성 컨트롤 ID를 보존하면서 원래 C01 파일 아이콘, 이름, 오른쪽 정렬 크기 및 원형 빼기를 사용합니다. 입력 목록은 가상화 뷰, 빈 상태/행 기준 38 및 최대 뷰포트 148을 사용합니다. 큰 글꼴은 공유 제거 역할의 적중 영역 28과 그래픽 24를 바꾸지 않고 실제 메트릭에 따라 행을 늘립니다. 사용자는 파일/폴더를 추가하고 중복을 제거하거나 삭제할 수 있습니다. 제한된 백그라운드 요약은 일반 파일 크기를 제공하고 디렉터리 합계는 알 수 없는 상태로 남습니다. 숨겨진 창은 다른 창의 요약을 갱신하거나 빼앗지 않으며 메타데이터 갱신은 선택된 경로를 바꾸지 않습니다.

권위 있는 매개변수는 layout-scale.json의 operation.adding이며 기존 생성 및 공유 컨트롤 매개변수를 재사용합니다. 독립 매핑은 [add-reference.json](../../../specs/visual/add-reference.json)에 있습니다. 중국어/영어, 밝은/어두운 테마, 100%/125%/150%, 긴 이름 및 빈 선택을 검사합니다. Qt는 카드, 컨트롤, 스크롤 및 footer를 별도로 검사하며 주 창/메뉴 비율은 별도로 측정합니다. 오프스크린 성공은 네이티브 데스크톱 검증을 대체하지 않습니다.

## 압축 파일 내부 이동 상태

내부 드래그는 주 창, 메뉴 또는 행 높이 비율을 바꾸지 않습니다. 대상은 기존 목록 선택과 treeSelectionColor를 사용합니다. 피드백은 tooltipSurface/tooltipText, tooltipMaxWidth, tooltipPadding 및 mainBodySize를 사용하고 최대 네 줄이며 고정 작업 창 없이 클라이언트 영역 안에서 반전하거나 제한합니다. 유효하지 않은 대상은 구체적인 이유를 표시하고 원본 행은 선택 색상을 유지합니다. 진행 및 충돌 창 치수를 재사용하며 파일 충돌은 건너뛰기, 이름 변경, 바꾸기 및 이후 충돌에 적용을 제공합니다.

파일 드래그가 시스템 임계값을 넘으면 대상 디렉터리를 기다리지 않고 즉시 포인터를 따라가는 아이콘/이름 카드를 표시합니다. 단일 항목은 유형 아이콘과 이름을 표시하며 여러 항목은 선택 개수를 추가합니다. 이름은 일반 텍스트이며 중간을 생략하고 대상 설명은 최대 네 줄입니다. 카드는 입력을 처리하지 않으며 드롭 감지를 차단할 수 없습니다. 대상 커서와 구체적인 텍스트는 허용/거부를 계속 표현합니다. 아래/오른쪽으로 16만큼 오프셋하고 클라이언트 경계 내로 제한하며 취소 또는 완료 시 즉시 지웁니다. 최대 너비 280, 아이콘 24, 안쪽 여백 10, 간격 8, 반경 8이며 공유 힌트 색상과 메뉴 텍스트를 사용하고 접근성 글꼴에 맞춰 텍스트와 최대 너비를 늘립니다. [drag-preview.json](../../../specs/visual/drag-preview.json)을 참조합니다.

외부 복사는 플랫폼 드래그 세션을 사용합니다. Windows Shell과 Linux QDrag는 투명한 64논리 단위 미리 보기, 48단위 아이콘 및 다중 선택 개수 배지를 사용하며 99보다 크면 99+로 표시합니다. 비트맵 저장만 창 DPR로 샘플링하며 논리 치수는 바뀌지 않습니다. Mac은 AppKit 네이티브 파일 약속 이미지와 시스템 피드백을 유지합니다. 네이티브 커서는 복사 또는 거부를 표현하며 외부 복사를 압축 파일 내부 이동으로 묘사하거나 성공 전에 완료를 표시하지 않습니다. 네이티브 이미지 준비 실패 시 콘텐츠 검증을 약화하지 않고 안전한 전송과 기본 시스템 커서를 유지합니다. [Windows Shell 드래그 피드백](https://learn.microsoft.com/en-us/windows/win32/shell/dataobject)과 [Qt 6.8 QDrag](https://doc.qt.io/qt-6.8/qdrag.html)를 참조합니다.

추출 확인의 네이티브 및 본문 제목은 “解压文件” / “Extract files”이며 도구 모음 추출 동작은 별도 번역 ID를 유지합니다. 제목 개정은 창 치수, 본문 또는 footer를 바꾸지 않습니다.

첫 본문 그룹은 공유 헤더 뒤에 operation.header.bodyGap을 두며 현재 0논리 픽셀입니다. 헤더 안쪽 여백이 이미 간격을 제공하므로 이전 hero 간격을 추가하지 않습니다. 카드 안쪽 여백, 본문 단락 및 설정 섹션 간격은 본문 컨테이너 내부에 유지합니다. Qt은 실행 중 및 세 종료 작업 뷰 모두에 대해 헤더 아래쪽에서 첫 그룹까지의 경계를 측정합니다.

## 정보의 라이선스 고지

스크롤 가능한 정보 설정 페이지는 xdzip 원본 코드와 Qt의 저작권, xdzip 라이선스 및 선택한 Qt LGPL-3.0 옵션을 명시하고 포함된 GPL-3.0 및 LGPL-3.0 본문을 안내합니다. 새 창이나 footer 없이 기존 텍스트 역할과 줄 바꿈을 재사용하며 Qt는 이중 언어 문구를 공유합니다.

## 동적 작업 창 높이

작업 경로 및 결과 개정은 실행 중 현재 파일 슬롯을 중간 생략이 있는 한 줄로 유지하고 완전한 일반 텍스트 접근성 이름을 제공합니다. 경로 길이만으로 카드나 창 크기를 바꾸지 않습니다. 일반 추출 결과 캡션은 보존된 상세 레코드와 관계없이 커밋된 파일 수만 포함합니다. 생성 캡션은 이름이나 크기 없이 “N files”만 표시하며 일반 출력에는 outputParts, 일괄 생성에는 성공한 작업 수를 사용합니다. 일괄 생성 결과는 볼륨 그룹 중복 제거 수를 생략하고 일괄 추출 결과는 이를 유지하며 확장 가능한 상세는 기존 동작을 유지합니다. 기존 논리 치수, 밀도 및 큰 글꼴 적응이 계속 권위 있는 기준입니다.

각 작업 창은 콘텐츠, 글꼴 및 사용 가능한 화면에 따른 기존 목표 클라이언트 높이를 유지합니다. 조정 중에는 먼저 목표 방향으로 제약을 넓히고 목표 높이를 설정한 다음 양쪽 경계를 목표값으로 복원하여 오래된 제약으로 플랫폼이 거부하는 일을 방지합니다. 이후 클라이언트 높이는 고정됩니다. 다시 열기, 콘텐츠 변경 및 늦은 플랫폼 기하 콜백은 화면 배율 곱셈이나 새 크기 매개변수 없이 같은 논리 단위를 사용합니다. 런타임 기하 검사는 네이티브 데스크톱 시각 검증을 대체하지 않습니다.
