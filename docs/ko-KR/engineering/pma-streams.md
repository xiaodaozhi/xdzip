# PMA 컨테이너와 PMarc 방식

[English](../../engineering/pma-streams.md) | [简体中文](../../zh-CN/engineering/pma-streams.md) | [繁體中文（台灣）](../../zh-TW/engineering/pma-streams.md) | [日本語](../../ja-JP/engineering/pma-streams.md) | 한국어 | [Français](../../fr-FR/engineering/pma-streams.md) | [Deutsch](../../de-DE/engineering/pma-streams.md) | [Español](../../es-ES/engineering/pma-streams.md) | [Português (Brasil)](../../pt-BR/engineering/pma-streams.md) | [Русский](../../ru-RU/engineering/pma-streams.md)

PMarc는 `-pm0-`, `-pm1-`, `-pm2-` 방식을 사용하는 LHA 유사 순차 헤더를 사용합니다. 이들은 서로 다른 알고리즘이며 이름이 비슷한 LH 방식의 별칭이 아닙니다. 읽기 전용 PMA 프로필은 레벨 0 헤더의 PM0, PM1, PM2 멤버를 탐색, 검사, 선택 추출 대상으로 허용합니다. 알 수 없는 방식은 콘텐츠 미지원 경고와 함께 계속 표시됩니다. 생성, 수정, 암호화, 분할 볼륨, 복구는 허용되지 않으며 형식 레지스트리가 최종 기준입니다.

<a name="xdzip-sources-and-reference-boundary"></a>

## 출처와 참조 범위

Yoshihiko Mino의 [원본 소프트웨어 페이지](https://www.asahi-net.or.jp/~am9y-mn/fswlist.htm), [PMarc 2.00 설명서](https://www.asahi-net.or.jp/~am9y-mn/doc/pmarc2.doc), [원본 도구 패키지](https://www.asahi-net.or.jp/~am9y-mn/arc/pmarc200.pma)는 PM2, 바이너리 및 텍스트 모드, CP/M의 128바이트 파일 레코드를 설명합니다. 설명서는 확장자와 달리 CP932 일반 텍스트입니다. 도구와 문서의 식별 정보, 컴파일러, 에뮬레이터, 독립적으로 작성한 입력은 [테스트 자료](../../../tests/fixtures/pma/README.md)에 기록되어 있습니다. 원본 도구에는 각자의 조건이 적용되며 재배포하거나 제품 의존성에 포함하지 않습니다.

설명서는 압축 비트스트림의 완전한 명세가 아닙니다. 제한적인 형식 관찰에는 Simon Howard의 [PM2 디코더](https://github.com/fragglet/lhasa/blob/v0.6.0/lib/pm2_decoder.c), Git blob `b711988f2ac8a21ea4081e06020ecbd3fb83c49c`, [PMA 공통 정보](https://github.com/fragglet/lhasa/blob/v0.6.0/lib/pma_common.c), blob `7433c3b6fcbd742963a7a63a03d21d858e798631`를 Lhasa의 ISC 라이선스에 따라 사용합니다. 엄격한 클린룸 구현을 주장하지 않습니다. Rust는 프로젝트의 제한된 비트 판독기, 일반적인 완전 정규 접두 코드 구현, 독립적으로 표현한 평면 바이트 순열을 사용하며 참조의 연결 목록이나 트리 구조를 복사하지 않습니다. 참조 알고리즘의 소스나 바이너리는 제품에 컴파일되지 않습니다.

원본 PMarc 2.00은 해시로 고정하고 소스를 검증한 CP/M 에뮬레이션에서 실행하며, 모든 입력과 출력을 관리하는 테스트 디렉터리로 제한하고 바이너리 I/O를 명시적으로 선택합니다. Lhasa 0.6.0과 문서화된 IBM-PC 이식판의 원본 PMext 2.22가 전체 출력 바이트를 각각 독립적으로 비교합니다. 원본 인코더는 길이가 0인 입력을 건너뛰고 빈 압축 파일을 만들므로 인코딩된 빈 멤버의 증거가 아닙니다. 형식에 따라 독립적으로 작성한 사례는 28비트 리터럴 접두 코드와 허용되는 선행 비트 변형을 별도로 다룹니다. 소스 관찰, 생성 데이터, 실제 참조 비교는 출처를 구분합니다.

## 컨테이너 요구 사항

PMA 헤더와 페이로드 범위에는 산술, 체크섬, 이름, 중복, 고정된 원본, 특수 객체에 관한 [LHA](lha-containers.md)와 동일한 규칙이 필요합니다. PM0은 압축 크기와 원래 크기가 같은 Store입니다. PM1과 PM2를 LH 디코더로 전달해서는 안 됩니다. 존재하는 페이로드 CRC-16은 전체 디코딩 후 검증되어야 하며, 방식을 열거나 목록에 표시하는 것만으로는 콘텐츠 유효성이 입증되지 않습니다.

원본 CP/M 압축 파일은 0 바이트와 다음 128바이트 레코드 경계에 도달하기에 충분한 `0x1a` 채움으로 끝납니다. 허용되는 채움 형식은 정확히 정렬되어야 하며 채움은 최대 127바이트이고 모두 해당 값이어야 합니다. 정확한 0 종료자는 채움이 없는 컨테이너를 구분할 수도 있습니다. 이는 구체적인 프레이밍 요구 사항이지 임의의 뒤따르는 바이트를 무시하거나, 없는 종료자를 만들어 내거나, 디코딩된 EOF 바이트를 추가할 수 있다는 뜻이 아닙니다. 컨테이너 채움은 멤버의 압축 구간에 속하지 않습니다. 원본 고정에는 채움을 포함한 전체 물리 파일이 포함되어야 합니다.

8바이트 제안만으로 형식을 공개하지 않습니다. 호스트가 행을 공개하기 전에 전체 메타데이터 체인, 정확한 0 종료자, 선택적인 물리적 채움을 검증해야 합니다. 모든 약한 형식 계열 탐색은 하나의 입력 계량을 공유합니다. CP/M 빈 압축 파일은 제한된 채움으로 PMA로 식별하며, 구별할 수 없는 1바이트 0 종료자는 기존 LZH 선택을 유지합니다. 강한 컨테이너는 약한 탐색보다 우선하며 원시 TAR 표식과의 충돌에는 완전한 컨테이너 허용 검사가 필요합니다. 호스트에서 비롯된 형식이 잘못된 입력의 타입 지정 값을 포함해 원본 I/O 오류는 종료 오류로 남습니다.

페이로드 출력 전에 물리 행 ID, 원시 및 디코딩된 이름, 플래그, 크기, 방식을 다시 비교합니다. PMA 방식 2는 LHA의 LH2 변형을 시험하지 않고 PM2로 바로 전달됩니다. CRC 실패, 미지원 방식, 원본 변경 시 호스트의 비공개 임시 저장과 기존 파일 보호가 유지됩니다. `.pma`는 해당 플랫폼에서 셸 및 끌어다 놓기 후보입니다. 전용 MIME 형식은 선언하지 않으므로 Linux에서 PMA 기본 연결을 추가한다는 뜻은 아닙니다.

레벨 0 기본 헤더의 길이 31바이트와 체크섬이 GZIP의 `1f 8b` 또는 Unix Z의 `1f 9d`와 우연히 일치할 수 있습니다. 뒤의 바이트가 완전한 `-lh`, `-lz`, `-pm` 계열 표식을 이루면, 탐지는 우연히 일치한 2바이트 스트림 제안 때문에 거부하지 않고 해당 계열의 전체 허용 검사를 유지합니다. 표식의 `-`는 허용된 GZIP 방식 8도 유효한 Unix Z 플래그도 아닙니다. 이는 제한된 헤더 구분이며 디코딩에 실패한 페이로드를 재시도하지 않습니다. 유효한 스트림 형식과 호스트 오류는 평소대로 처리합니다.

## PM1 형식 프로필

`Pm1Reader`는 PMA 어댑터가 공유하는 원시 기본 요소입니다. PMA 방식 1은 고정된 메타데이터를 비교한 뒤 LHA 방식과 독립적으로 여기에 바로 진입합니다. 형식 관찰에는 ISC 라이선스의 Lhasa [PM1 참조 구현](https://github.com/fragglet/lhasa/blob/v0.6.0/lib/pm1_decoder.c), Git blob `bb2937e382c8c8a8f5783b94a96b9b59e2c4e74b`를 사용합니다. Rust는 참조의 압축된 상대 오프셋 트리와 독립적으로 고정 코드워드를 직접 표현하고 공유된 제한 평면 최신 사용 순열을 사용합니다. 엄격한 클린룸이나 참조 구현에 대한 런타임 의존성을 주장하지 않습니다.

5비트 선택기는 32개의 고정 리터럴 범주 알파벳 중 하나를 선택합니다. 범주는 0/16/32/64/128/192에서 시작하는 순위를 각각 4/4/5/6/6/6개의 하위 비트로 선택합니다. 선택기 17은 범주 3/4 분기를 반복하고 범주 0/1/5를 생략하며, 반복된 두 분기는 관찰된 의미를 유지합니다. 선택기 31에는 범주 비트가 없으며 순위 0–15만 허용합니다. 리터럴이나 복사된 모든 바이트는 최신 사용 순서를 갱신합니다. 독립 생성기는 제품의 코드워드 조회표가 아니라 확장된 기호 알파벳을 사용합니다.

명령은 명시적인 기록 복사 또는 1–216바이트 리터럴 블록입니다. 더 짧은 리터럴 블록은 디코딩 출력이 남아 있으면 후속 복사를 암시하며, 216바이트 블록은 명시적 명령 선택으로 돌아갑니다. 선언된 마지막 리터럴은 가상의 복사를 읽지 않고 멤버를 끝낼 수 있습니다. 복사 클래스 0/1은 길이 2를, 다른 클래스는 길이 3–244를 인코딩합니다. 거리 접두 코드는 디코딩된 바이트 64/576/2624에서 늘어납니다. 클래스 3/4/5의 하위 필드는 각각 320, 832/1088/1600, 2880/3136/3648/4672/6720바이트에서 넓어집니다. 거리는 오프셋에 1을 더한 값으로 이미 출력된 내용을 참조해야 하며 겹침과 순환을 지원하는 16 KiB 링을 사용합니다. PM2의 초기 공백은 PM1에 기록을 제공하지 않습니다.

리터럴과 복사 길이는 선언된 남은 출력에 들어가야 하며 추가된 완전한 압축 바이트는 거부됩니다. 마지막 1바이트 미만의 채움은 무시하지만 누락 바이트를 0으로 대체하지 않습니다. 참조 구현의 과거 EOF 복구는 이 프로필 범위 밖입니다. 허용 메모리는 기록 16 KiB와 입력, 상태, 임시 공간용 32 KiB이며 압축 및 디코딩 크기는 각각 24 GiB, 작업량은 96 GiB가 엄격한 상한이고 호출자의 더 작은 예산도 적용됩니다. 원본 읽기, 접두 비교, 순위 이동, 원본과 무관한 복사는 협력적 취소와 타입 지정 종료 오류를 유지합니다.

## PM2 형식 모델

스트림은 최상위 비트부터 읽으며 선행 비트의 두 값은 디코딩 결과를 바꾸지 않는지 독립적으로 시험합니다. 코드 표는 5비트 개수 1–29와 3비트 최소 길이를 선언합니다. 최소 길이가 0이면 상수 기호 `count - 1`을 선택합니다. 그렇지 않으면 3비트 필드가 각 길이 값을 읽을 폭을 선언하며, 값이 0이면 부재, 그 외에는 `minimum + value - 1`입니다. 완전한 정규 트리가 필요합니다. 최대 29개 잎은 최대 28개 유효 깊이를 허용하며 `Prefix<29>`는 기존 Brotli/LZH `Canonical = Prefix<17>` 인스턴스를 늘리지 않고 이를 지원합니다. 잘못된 개수, 초과 할당되거나 불완전한 트리, 과도한 깊이는 사용 전에 실패합니다.

코드 0–7은 바이트의 최신 사용 순위를 선택하며 기준은 0/8/16/32/64/96/128/192, 추가 폭은 3/3/4/5/5/5/6/6입니다. 초기 순서는 16진수로 `20–7f, 00–1f, a0–df, 80–9f, e0–ff`입니다. 기록 복사를 포함한 모든 출력 바이트는 앞으로 이동합니다. Rust 구현은 제한된 평면 순열을 검색하고 회전하며 실제 비교와 이동을 계량합니다.

코드 8–28은 복사입니다. 클래스 0–14는 길이 2–16을 만듭니다. 클래스 15–20은 기준 17/25/33/65/129/256과 폭 3/3/5/6/7/0을 사용합니다. 클래스 0은 6비트 오프셋을 직접 읽고 클래스 1–19는 위치 표를 사용합니다. 위치 0은 하위 6비트를 읽고, 위치 1–7은 하위 `position + 5`비트를 읽은 뒤 해당 2의 거듭제곱 기준을 더합니다. 클래스 20은 항상 오프셋 0을 사용합니다. 실제 거리는 오프셋에 1을 더한 값입니다. 기록은 공백으로 채운 8192바이트 링이며 겹치는 참조와 초기 기록 참조는 바이트 단위 의미를 유지합니다.

필요할 때 위치 표는 처음에 3비트 길이 5개를 가지며 출력 1024바이트에서 6개, 2048에서 7개, 4096에서 8개가 됩니다. 4096에서는 명시적 비트가 코드 표 교체를 제어하고 그 뒤에 8개 위치 표가 옵니다. 8192부터는 4096바이트마다 명시적 비트가 두 표의 교체를 제어합니다. 이벤트는 복사 내부와 출력의 정확한 끝을 포함해 출력 바이트의 정확한 위치에서 발생합니다. 원본 경계 샘플에는 최종 제어 필드가 포함됩니다. 이를 생략하거나 성공한 부분 출력으로 대체할 수 없습니다.

존재하는 기호가 하나인 위치 표는 상수입니다. 모든 값이 0인 표는 부재로 표현되며 최종 제어 이벤트를 포함해 사용하지 않은 채 남을 수 있습니다. 실제로 그 표가 필요한 명령은 실패합니다. 0으로 채운 표를 가상의 기호로 복구하지 않습니다. 위치 표의 필요 여부는 코드 표 선택으로 결정됩니다. 마지막 1바이트 미만 채움은 무시하지만 논리적 압축 바이트는 정확히 끝나야 하며 추가된 완전한 바이트는 거부됩니다.

<a name="xdzip-limits-and-failure"></a>

## 제한과 실패

PM2는 8192바이트 기록과 버퍼 입력, 접두 표, 최신 사용 상태, 제한된 임시 공간용 32 KiB를 허용합니다. 압축 및 디코딩 크기는 각각 24 GiB, 알고리즘 작업량은 96 GiB가 엄격한 상한입니다. 호출자의 더 작은 예산도 유효합니다. 생성, 표 읽기, 최신 사용 연산, 복사, 비트를 계량하며 `work_remaining()`은 멤버 간 실제 작업량을 유지합니다. 읽기는 최대 8192바이트를 반환하고 추가 원본 읽기가 없어도 협력적으로 확인합니다.

부가 정보가 없는 `Interrupted` I/O만 재시도합니다. 타입 지정 중단은 해당 정보를 유지하고 종료하며, 원본, 잘못된 데이터, 취소, 리소스 오류는 인스턴스를 사용 불가능하게 만듭니다. 호스트는 끝까지 성공적으로 읽고 선언 크기와 CRC를 확인하며 성공할 때까지 출력을 비공개로 유지해야 합니다. 원시 판독기에는 파일 이름, 프로세스, 권한, 파일 시스템 게시 권한이 들어가지 않습니다. 원시 테스트, 완전한 컨테이너 테스트, runtime/CLI/Qt 작업, 다른 플랫폼, 릴리스 허가는 서로 별개의 증거입니다.
