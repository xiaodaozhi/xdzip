# ZIP 생성 구현 계약

[English](../../engineering/zip-creation.md) | [简体中文](../../zh-CN/engineering/zip-creation.md) | [繁體中文](../../zh-TW/engineering/zip-creation.md) | [日本語](../../ja-JP/engineering/zip-creation.md) | 한국어 | [Français](../../fr-FR/engineering/zip-creation.md) | [Deutsch](../../de-DE/engineering/zip-creation.md) | [Español](../../es-ES/engineering/zip-creation.md) | [Português (Brasil)](../../pt-BR/engineering/zip-creation.md) | [Русский](../../ru-RU/engineering/zip-creation.md)

명시적으로 선택한 파일과 디렉터리로 새 ZIP 아카이브를 만듭니다. 기본값은 레벨 2의 일반 압축이며 Deflate 6을 사용합니다. Store와 Deflate 1/6/9, WinZip AES-256 콘텐츠 암호화와 번호가 붙은 분할 볼륨을 지원합니다. 생성과 추출은 [TAR/GZIP](tar-gzip.md), AES-256 읽기는 [암호 추출](password-extraction.md), 분할 읽기는 [분할 볼륨 계약](archive-opening.md)을 참조하세요. 일반 단일 파일 아카이브에 명시적으로 추가할 때는 [끌어 놓기와 수정 계약](archive-transfers.md)을 사용하며 새 아카이브의 소스 보호 예외를 재사용하지 않습니다. 호스트는 입력 승인, 준비, 검증, 충돌 결정과 최종 저장을 소유합니다. 형식 계층은 항목, 읽을 수 있는 입력과 쓸 수 있는 출력만 받습니다.

## 입력 트리와 제한

선택은 일반 파일이나 디렉터리의 절대 경로여야 합니다. 같은 경로와 이미 선택한 디렉터리 안의 선택을 중복 제거합니다. 재귀 시 루트 디렉터리 이름을 유지하며 빈 디렉터리는 명시적 레코드를 만듭니다. 링크, 재분석 지점, 장치 등 특수 객체를 거부합니다. 공통 부모별로 루트 디렉터리 핸들을 묶으며 최대 128개입니다. 제한은 100,000개 항목, 64단계, 이름 총 16 MiB, 파일당 8 GiB, 전체 입력 20 GiB입니다. 제한된 루트 핸들과 현재 입력 파일만 보유하고 항목마다 파일 디스크립터를 열지 않습니다.

이름이 있는 항목을 새로 보관할 때는 대소문자, Unicode 표기, 형식에서 지원하는 일반 문장 부호를 그대로 유지합니다. 표기가 다른 이름은 함께 보관할 수 있습니다. 항목 경로가 정확히 중복되거나 형식에서 이름을 표현할 수 없으면 저장 전에 오류를 보고합니다. 항목에는 기존 상대 경로 안전 규칙이 적용됩니다. 단일 파일 압축 스트림의 가상 파일 이름은 출력 아카이브의 기본 이름에서 파생됩니다.

먼저 입력 부모의 시스템 별칭을 같은 위치로 정규화하며 선택한 말단 링크는 따르지 않습니다. 루트를 연 뒤 디렉터리 식별 정보를 결합하고 다시 검사합니다. 디렉터리 검색은 루트 핸들 아래를 링크를 따르지 않고 순회하며 디렉터리 식별 정보와 필터링된 자식 목록, 파일 식별 정보·길이·수정 시각을 유지합니다. 인코딩 전후와 저장 전에 다시 검사하고 각 파일 버전은 열 때와 EOF에서 검사합니다. 추가, 삭제, 이름 변경, 링크 교체와 관찰 가능한 콘텐츠 변경은 소스 변경으로 실패합니다. 식별 정보와 타임스탬프 검사는 최선의 노력이며 원자적 콘텐츠 스냅샷이 아니고 같은 계정이 메타데이터를 의도적으로 복원한 편집의 탐지를 보장하지 않습니다.

아래 macOS 메타데이터를 제외하고 생성은 선택한 모든 일반 입력을 유지합니다. 기존 대상 아카이브, 이전 볼륨과 다른 디렉터리의 같은 이름 파일은 일반 입력이므로 대상 경로와 겹친다는 이유로 조기 거부하거나 조용히 제외할 수 없습니다. 입력 트리는 이 작업이 만든 비공개 준비 작업 디렉터리를 식별 정보가 일치할 때 별도로 필터링합니다. `.xdzip-*`나 대상 파일 이름을 와일드카드로 제외하지 않습니다. 디렉터리 별칭을 정규화하고 보유 핸들 식별 정보를 검증합니다. 비공개 작업 디렉터리나 그 별칭을 명시적으로 선택하는 것은 계속 거부합니다.

인코딩은 비공개 준비 파일에만 쓰고 완전한 검증 후 최종 충돌 보호 단계에 들어갑니다. 대상이 입력에도 포함되면 일반 충돌 질문을 보여주고 해당 입력의 덮어쓰기를 금지하며 새 이름이나 취소를 허용합니다. 이전 대상 파일만 선택한 경우에도 같은 흐름을 적용하여 원본 바이트를 새 이름의 아카이브에 포함합니다. UI를 우회하는 직접 덮어쓰기 매개변수나 덮어쓰기 응답은 `protected_source`를 반환하고 원본을 보존합니다. 아카이브 작업 중 추가된 파일을 재귀적으로 다시 발견하지 않습니다. 최종 아카이브는 저장할 때만 게시하며 커지는 준비 파일을 자기 자신에 담지 않습니다.

이름 충돌 창은 확립된 논리 너비와 공통 푸터를 유지합니다. 제목과 보호 문구는 사용 가능한 본문 너비 안에서 줄 바꿈하며 접근성 글자 크기로 최소 레이아웃 너비가 늘어나 가로로 잘리면 안 됩니다. 본문이 너무 높으면 스크롤하고 결정 버튼은 계속 접근할 수 있습니다.

## macOS 메타데이터 입력 필터링

ZIP, AES-256 ZIP, 번호가 붙은 ZIP 볼륨, TAR, TAR.GZ 생성과 일반 아카이브에 추가는 Rust `InputTree` 정책을 공유합니다. 모든 호스트 플랫폼에서 대소문자를 구분하는 말단 이름의 정확한 일치로 일반 파일 `.DS_Store`와 디렉터리 `__MACOSX`, `_MACOSX`의 전체 하위 트리를 모든 단계에서 제외합니다. 명시적으로 선택한 루트와 재귀 순회도 포함합니다. `._*`, 숨김 파일이나 접두사 와일드카드로 확장하지 않습니다. `_MACOSX`/`__MACOSX`라는 일반 파일은 입력으로 남습니다. 명시적으로 선택해 제외된 디렉터리의 하위 항목은 중복 선택으로 다시 추가하지 않습니다. 선택하거나 발견한 링크, 재분석 지점과 특수 객체는 기존 no-follow 거부를 유지하며 필터링으로 읽기 권한을 얻지 않습니다.

필터링은 이 아카이브의 입력에만 적용하며 호스트 원본을 삭제하거나 수정하지 않고 기존 아카이브 레코드를 정리하지 않습니다. 메타데이터 필터링만으로 비게 된 디렉터리와 그 빈 상위 디렉터리는 쓰지 않습니다. 실제 빈 디렉터리와 0바이트 일반 파일은 유지합니다. 유효한 항목이 남지 않으면 인코딩이나 충돌 질문 전에 `empty_input`으로 실패합니다. 기존 결과 창은 “macOS 메타데이터를 제외한 뒤 압축할 파일이나 폴더가 없습니다.”를 표시합니다. 새 아카이브를 게시하거나 기존 아카이브를 수정하지 않습니다. 선택 요약은 제한된 메타데이터 미리 보기로 유지하며 GUI 재귀 스캔 없이 백그라운드 작업 스캔이 최종 유효 콘텐츠를 결정합니다.

고정된 구성과 저장 전 재검증에 같은 필터를 사용합니다. 메타데이터 내용이나 존재 여부가 바뀌어도 유효 입력이 실패하지 않지만 일반 항목과 잘라낸 디렉터리의 일반 자식 변경은 계속 소스 변경으로 처리합니다. 스캔 제한은 나중에 잘리는 일반 디렉터리에도 적용되어 필터링으로 항목/이름 제한을 우회할 수 없습니다. 추출, 임시 열기, 내부 이동과 macOS 파일 프로미스 게시에는 새 입력 필터를 적용하지 않습니다. 일반 `InputTree::scan`은 모든 내용을 유지합니다.

## 형식 인터페이스와 검증

인코딩 인터페이스는 Qt와 파일 경로에서 독립적입니다. 호스트는 순서가 있는 불변 항목 목록과 순번으로 열리는 읽기 전용 스트림을 제공합니다. 형식 계층은 호스트 스트림에 쓰고 실제 처리한 바이트를 보고합니다. ZIP은 독립 Rust 레코드 작성기와 공통 Deflate 백엔드를 사용하며 고정 UTF-8 이름과 일반 파일/디렉터리 권한을 쓰고 특권 비트는 사용하지 않습니다. 큰 항목과 중앙 디렉터리는 자동으로 ZIP64를 사용합니다. 소스 크기는 고정된 값과 일치해야 하며 실패한 준비 스트림은 게시할 수 없습니다.

데이터와 압축 스트림을 완료하고 중앙 디렉터리를 쓴 뒤 호스트는 준비된 ZIP을 다시 스캔하고 각 항목을 디코딩해 헤더, 크기, CRC와 스트림 종료를 검사합니다. 항목 이름, 유형과 크기는 고정된 입력 트리와 일치해야 합니다. 전체 아카이브 저장은 검증과 소스 재검증 후에만 허용하며 디렉터리 목록만으로 아카이브 무결성을 증명하지 않습니다. 읽기, 압축, 쓰기와 검증은 백그라운드 무거운 작업 스레드에서 실행하고 주기적으로 취소를 확인합니다.

## 준비, 충돌과 전체 아카이브 저장

M3에서 검증한 디렉터리 승인, 같은 볼륨의 비공개 준비 영역과 전체 파일 커밋 기능을 사용합니다. 이름 충돌은 기본적으로 질문하며 새 이름이나 확인된 일반 파일 교체를 지원합니다. 디렉터리, 링크, 특수 객체 또는 입력에 참여하는 파일 식별 정보를 덮어쓰지 않습니다. 충돌 결정은 작업 및 질문 ID에 결합하고 커밋 전에 기존 대상을 다시 검사합니다. 파일 시스템에 필요한 기능이 없으면 복사/삭제로 원자적 저장을 흉내 내지 않고 실패합니다.

macOS 생성 출력은 [M3 확장 ACL 경계](zip-safe-extraction.md#macos-扩展-acl-控制)를 재사용하여 외부 수정 권한을 주지 않는 거부/읽기 전용 ACL은 허용하고 외부의 유효 또는 상속 전용 수정 권한은 거부합니다. 대상 루트, 준비 디렉터리, 새 부모와 기존 출력을 공통 규칙으로 검사합니다. 사용자 ACL을 다시 쓰거나 기존 읽기 전용 공유 계정에서 아카이브 내용을 숨긴다고 약속하지 않습니다.

분할하지 않으면 생성 작업은 ZIP 하나를 전체로 저장합니다. 검증이나 저장 전 취소는 알려진 준비 파일을 제거하고 기존 아카이브를 보존합니다. 이미 쓴 입력 항목을 저장한 파일로 집계할 수 없습니다. 취소와 최종 커밋은 기존 게이트를 공유합니다. 커밋 허가 전에는 취소가 우선하고 허가 후에는 전체 커밋 결과가 우선합니다. 커밋 성공 후 취소해도 성공이 취소로 바뀌지 않습니다. 정리 실패는 복구 가능한 자료를 경고와 함께 보존하며 알 수 없는 준비 디렉터리를 삭제하지 않습니다.

## 작업과 인터페이스

생성과 추출은 제한된 백그라운드 작업 채널, 제어와 종료 방법을 공유합니다. 작업 스냅샷은 생성/추출과 합계의 확인 여부를 구분합니다. 스캔 중에는 합계 불명을 표시하고 스캔 후 고정된 파일 수와 크기를 사용합니다. 쓰는 동안 실제 입력 읽기, 출력 쓰기와 현재 파일을 표시합니다. 검증은 별도로 표시하며 검증한 바이트를 입력 읽기로 다시 집계하지 않습니다.

생성 창은 고해상도 디자인을 따르며 경로 필드, 내장 드롭다운, 체크박스, 버튼과 푸터를 재사용합니다. 파일 추가, 디렉터리 추가, 제거, 이름, 대상, Store/Deflate, 레벨과 완료 결과 열기를 사용할 수 있습니다. 레벨은 0 압축 없음, 1 빠름, 2 일반, 3 최대이며 기본 2로 Store/Deflate 1/6/9에 대응합니다. 별도 알고리즘 컨트롤은 없습니다. 분할 볼륨과 암호는 실제 생성 매개변수입니다. TAR/TAR.GZ는 [WP-11](tar-gzip.md)의 안전 생성 흐름을 재사용하며 형식별 기능은 해당 계약이 제어합니다. 작업 창은 수정된 일반 밀도를 사용합니다. 창을 닫아도 작업은 계속되며 상태 표시줄에서 다시 열거나 취소하고 충돌을 해결할 수 있습니다.

## 선택 요약과 공유 컨트롤

일반 파일을 선택하면 기존 Rust 메타데이터 작업자가 현재 파일 길이를 읽으며 GUI는 디스크를 읽거나 디렉터리를 재귀 스캔하지 않습니다. InspectInputs는 최대 256개 경로를 받아 고정된 입력 순서로 반환하고 크기를 십진 바이트 문자열로 브리지합니다. symlink_metadata는 선택한 말단 링크를 따르지 않습니다. 요약은 십진 MB를 사용합니다. 0바이트 파일은 크기가 알려져 있으며 디렉터리와 실패는 0이 아니라 알 수 없음입니다. 256개를 넘으면 미검사 항목 설명을 유지하고 실제 생성에는 기존 제한이 적용됩니다. 빠른 편집은 최신 경로 집합으로 합쳐지며 오래된 결과가 새 선택을 대체하지 않습니다. 대상 검사가 우선하고 일반 조회는 기존 취소를 사용합니다. 요약은 사전 승인이 아니며 시작 후 작업이 입력 트리를 다시 만듭니다.

대상 검사와 입력 요약은 백그라운드 준비입니다. 추가/제거 컨트롤의 활성 외관을 바꾸거나 시작 페이지에 검사 힌트를 게시하지 않습니다. 실제 요청은 계속 직렬이며 현재 경로의 생성 검사가 성공한 후에만 생성을 활성화합니다. 추출은 독립된 검사 상태를 가지며 같은 경로의 생성 검사로 대체할 수 없습니다. [추출 계약](zip-safe-extraction.md)을 참조하세요.

여섯 유형의 작업 창은 푸터 버튼을 공유하며 필드, 본문 동작, 원형 제거와 분할 그룹 옵션은 해당 역할 컴포넌트를 재사용합니다. 외관과 글자 크기는 layout-scale.json에서 생성하고 창에서 덮어쓰지 않습니다. 실제 요약, 컨트롤 측정과 스크린샷은 [검증 방법](../../../developers/qa/README.md)에 따라 build/ 또는 CI 아티팩트에 보관합니다.

## 검수

메타데이터 루트 항목, 중첩 디렉터리, 혼합 선택, 여러 단계의 메타데이터 전용 디렉터리, 실제 빈 디렉터리, 암호화와 번호 볼륨을 다루고 필터링 후 아무것도 없으면 새 출력 없이 이전 출력이 보존되는지 검사합니다. 실제 Store/Deflate, Unicode 이름, 빈 파일/디렉터리, 쓰기, 재열기와 추출 상호 운용성을 확인하고 Python zipfile로 콘텐츠, CRC와 디렉터리를 독립적으로 검증합니다. 소스 변경, 이름 충돌, 링크/특수 객체, 입력 트리 안의 출력, 명시 선택 또는 디렉터리에서 발견한 원래 대상 바이트의 포함, 부모 경로와 대소문자/Unicode 별칭, 다른 디렉터리의 동명 입력, 이전 대상만 선택한 경우의 일반 이름 변경, 입력 식별 정보 덮어쓰기 보호, 검증 실패, 충돌 변경 및 이전 아카이브를 보존하는 취소를 확인합니다. 코어/브리지/Qt를 빌드하고 세 플랫폼에서 백그라운드 수명 주기와 일반 밀도 및 높은 DPR의 실제 캡처를 확인합니다. 실제 입력 크기, 시간, 리소스와 검증 비용을 기록하고 레벨만으로 압축률을 추측하지 않습니다.

## AES-256 콘텐츠 암호화

“암호 입력”이 활성화되면 암호는 비어 있지 않은 1–128 UTF-8바이트여야 합니다. 앞뒤 공백을 제거하지 않고 제어 문자와 잘못된 Unicode는 거부합니다. 독립 WinZip AE-2 AES-256 래핑, OS 난수 솔트와 허용된 범용 AES/PBKDF2/HMAC 라이브러리를 사용합니다. 암호 기본 요소를 직접 구현하거나 ZipCrypto로 대체하지 않습니다. 빈 파일을 포함한 모든 일반 파일을 암호화하고 CRC 필드는 0, 인증 코드는 마지막에 씁니다. 일반 디렉터리 레코드와 파일 이름은 보이므로 파일 이름 암호화를 주장하지 않습니다. 매개변수는 [자체 형식 계약](independent-rust-codecs.md)을 참조하세요.

소스 인코딩 인터페이스는 암호를 빌릴 뿐 파일 경로나 커밋 권한이 없습니다. Rust 암호 컨테이너는 Debug에서 항상 `[REDACTED]`를 표시하고 범위를 벗어날 때 0으로 지웁니다. 대기 중 취소, 거부와 종료도 0화를 유발합니다. 암호는 스냅샷, 로그, 설정, 명령줄이나 복구 로그에 들어가지 않습니다. Qt 암호 필드는 닫기, 취소 또는 제출 시 지웁니다. Qt와 시스템 메모리의 이전 복사본을 모두 지울 수 있다고 보장할 수 없으며 Rust 컨테이너 0화는 전체 프로세스의 안전한 삭제가 아닙니다.

쓰기 후 검증은 각 항목을 제한된 폐기 싱크로 복호화하고 EOF까지 읽어 인증과 스트림 종료를 검사한 뒤 고정된 입력 이름, 유형과 크기를 확인합니다. 잘못된 암호, 손상이나 취소는 절대 게시하지 않습니다. 독립적인 7-Zip 디코딩은 상호 운용성 통과 조건입니다. 지원되는 AES-256 결과는 일반 ZIP처럼 앱에서 자동으로 열리고 실제 암호 추출로 진행할 수 있습니다. 번호가 붙은 볼륨은 첫 부분을 앱에서 자동으로 엽니다. 어느 경우도 시스템 폴더를 자동으로 열지 않습니다.

## 분할 볼륨 매개변수와 게시

드롭다운 옵션은 분할 없음, 3MB, 4MB, 5MB, 10MB, 20MB, 25MB(Gmail), 100MB, 300MB, 650MB(CD), 700MB(CD), 4GB(FAT32), 4.7GB(DVE), 사용자 지정입니다. MB/GB는 십진 바이트를 사용합니다. 사용자 지정은 공통 드롭다운을 bytes, KB, MB, GB 단위의 양의 정수 입력으로 바꿉니다. 빈 값, 0, 숫자가 아닌 값 또는 24 GiB 초과는 유효하지 않습니다. 최대 1,024개 볼륨이며 실제 압축 출력이 볼륨 수 제한을 넘으면 게시하지 않습니다.

바이트 분할 이름은 `.zip.001`, `.zip.002` 등이며 마지막 볼륨은 작을 수 있습니다. 이는 7-Zip 호환 번호 분할이지 다중 디스크 헤더 `.z01`이 아닙니다. 완전한 ZIP을 먼저 완성하고 검증한 후 고정 64 KiB 버퍼로 비공개 파일에 분할하고 각 볼륨을 동기화하고 닫습니다. 메모리와 열린 일반 파일 수는 볼륨 수에 선형적으로 증가하지 않습니다. 준비에는 완전한 ZIP과 볼륨 복사본이 모두 필요할 수 있습니다. 전체 ZIP 출력은 24 GiB로 제한되고 복사본은 최대 같은 공간이 필요하여 최악의 준비 공간은 약 48 GiB입니다. 작업 쓰기 집계는 분할 복사를 아카이브 크기로 중복 계산하지 않습니다.

분할 생성은 사용자가 선택한 이전 볼륨, 기본 `.zip`, `.zip.1025`와 다른 일반 입력을 유지하고 같은 macOS 메타데이터 제외를 적용하며 식별 정보가 일치하는 비공개 준비 디렉터리를 걸러냅니다. 기존 출력 볼륨은 최종 저장 시 그룹 충돌 이름 변경 또는 취소를 사용하며 이전 볼륨이 입력이라는 이유만으로 조기 실패하지 않습니다. 이전 볼륨이나 입력 파일 식별 정보를 덮어쓰지 않습니다.

그룹의 모든 대상을 사전 검사합니다. 이전 볼륨이 있으면 그룹 전체 이름 변경이나 취소를 지원하며 덮어쓰기는 비활성입니다. 커밋 허가를 얻은 뒤 볼륨을 교체 없이 개별적으로 게시합니다. 여러 파일에는 공통 원자적 가시성 지점이 없으므로 다중 파일 원자 트랜잭션을 주장하지 않습니다. 이후 실패는 이 작업이 게시하고 식별 정보가 여전히 일치하는 볼륨만 롤백합니다. 동시에 생성된 이전 파일은 변경하지 않으며 롤백 실패는 복구 경고와 불확실한 결과를 명시적으로 보고합니다. 허가 전에는 취소가 우선하고 그 후에는 일부 볼륨 집합을 성공으로 위장하지 않고 전체 그룹 커밋/롤백 결과에 따라 마칩니다.

## 결과 레코드와 인터페이스

결과 창은 [결과 디자인 매개변수](../../../specs/visual/result-reference.json)에 따라 제목, 3열 통계, 미완료 카드와 대상 위치를 유지합니다. 펼친 세부 정보는 보조 원고와 공통 아이콘을 사용합니다. 본문은 스크롤하고 푸터는 고정합니다. 컨트롤 논리 크기는 DPR이나 브라우저 확대율에 영향을 받지 않습니다.

실제로 완료, 명시적으로 건너뜀 또는 실패한 각 파일의 상태를 기록하며 진행률 비율로 성공을 추측하지 않습니다. 스냅샷은 최신 128개 항목, 이름당 최대 1,024 UTF-8바이트와 생략 수를 유지하는 공통 제한 레코드 목록을 사용합니다. 통계는 항상 전체 파일을 포함합니다. 생성 레코드는 실제 게시된 아카이브/볼륨을 설명하며 실패 시 읽은 입력을 저장된 것으로 집계하지 않습니다. 레코드는 현재 메모리 작업에만 존재하고 기본적으로 실행 사이에 지속되지 않습니다.

지원되는 아카이브 생성 후 작업 ID의 첫 성공 종료 상태에서 Qt는 최종 커밋된 경로를 직렬 열기 큐에 넣습니다. 현재 읽기/접수가 끝난 뒤 앱에서 자동으로 엽니다. 실패, 취소와 중복 종료 상태는 열지 않습니다. 사용자가 같은 파일을 명시적으로 열면 Qt 정규 경로를 정규화된 네이티브 구분자로 비교하고 Windows에서는 대소문자 구분 없이 보류 중 자동 열기 의도를 소비합니다. 이 비교는 UI 의도만 중복 제거하며 출력 권한을 주지 않습니다. 다른 열기가 새 세션과 추출 의도를 무효화하지 않도록 합니다. 번호 볼륨도 첫 부분을 열며 [분할 볼륨 호스트](archive-opening.md)가 전체 집합을 검증하고 읽으며 누락 볼륨을 명시적으로 보고합니다. 결과 창은 실제 출력 파일과 볼륨 수를 유지하며 외부 리더가 더 이상 필요하지 않습니다.

완료 동작은 2026-10-16에 변경되었습니다. 생성은 시스템 파일 관리자를 자동으로 열지 않으며 생성 창에서 디렉터리 자동 열기 옵션을 제거합니다. 이전 startCreation의 openAfter 매개변수는 무시합니다. 작업 접수와 종료 경로 모두 생성 작업의 시스템 디렉터리 자동 열기를 금지합니다. 성공 결과는 기존 암호화 및 번호 볼륨 읽기를 사용해 앱 내 열기 큐로 계속 전달합니다. 결과 통계는 “저장됨” 라벨을 사용합니다. [UI 계약](../ux/welcome-opening.md)을 참조하세요.

[시스템 컨텍스트 메뉴](shell-actions.md)의 생성 작업은 별도 완료 정책을 가집니다. 성공 결과는 앱 내 자동 열기 큐에 들어가지 않습니다. 단일 및 다중 생성은 실제 독립 결과를 표시하며 사용자가 결과의 디렉터리 동작을 명시적으로 클릭할 때만 시스템 파일 관리자를 호출합니다.

## ISO와 자체 SFX 프로필

[ISO9660/Joliet 생성](iso-creation.md)과 [Windows ZIP SFX 생성](sfx-creation.md)은 이 입력 트리와 출력 승인, 취소, 충돌, 최종 게시 계약을 재사용합니다. 각각의 더 좁은 이름, 크기, 방식과 플랫폼 제한은 게시 전에 적용됩니다. SFX 래핑은 생성 중 실행 파일을 실행하지 않습니다.
