# 파일 목록 열기, 양방향 드래그 앤 드롭과 아카이브 수정

[English](../../engineering/archive-transfers.md) | [简体中文](../../zh-CN/engineering/archive-transfers.md) | [繁體中文](../../zh-TW/engineering/archive-transfers.md) | [日本語](../../ja-JP/engineering/archive-transfers.md) | 한국어 | [Français](../../fr-FR/engineering/archive-transfers.md) | [Español](../../es-ES/engineering/archive-transfers.md)

컨텍스트 메뉴의 “열기”는 다중 선택을 바꾸지 않고 오른쪽 클릭한 항목에 적용하며 두 번 클릭과 Enter 진입점을 재사용합니다. 디렉터리는 들어가고 일반 파일에는 [임시 열기](archive-opening.md)의 비공개 캐시, 비밀번호와 연결된 응용 프로그램 규칙을 적용합니다. 세션이나 조회가 바뀌면 메뉴를 닫고 실행 시 안정적인 항목 ID를 다시 검증합니다.

## 외부로 드래그

목록이나 격자의 드래그가 시스템 임계값에 도달하면 선택과 아카이브 디렉터리를 고정합니다. 선택되지 않은 항목을 드래그하면 먼저 그 항목만 선택하고, 선택된 항목을 드래그하면 선택을 유지합니다. 디렉터리 하위 항목을 확장하고 부모/자식 중복 선택을 제거하며 현재 디렉터리 아래 상대 계층과 빈 디렉터리를 보존합니다. 아카이브 콘텐츠는 삭제하지 않습니다. 링크는 외부 드래그로 게시하지 않습니다. 매니페스트는 100,000개 항목과 이름/구조 예산 4 MiB로 제한되며 안전한 압축 풀기의 바이트, 경로, 비밀번호와 할당량 제한도 적용됩니다.

외부 드래그 매니페스트 생성은 전송 메타데이터 준비이며 디렉터리 읽기가 아닙니다. 준비와 네이티브 인계 중에는 확정된 목록/격자, 선택과 디렉터리를 유지하고 메인 페이지의 “읽는 중” 오버레이를 표시하지 않습니다. 요청은 처리 중 및 취소 의미를 유지합니다. 실제 열기, 디렉터리 조회와 아카이브 수정은 각자의 대기 피드백을 계속 사용합니다.

Windows는 OLE `IDataObject` FILEDESCRIPTOR/FILECONTENTS와 비동기 기능을 통해 콘텐츠를 제공합니다. 대상이 수락한 후 백그라운드 준비가 시작되며 수신자는 비공개 복사본이 완전히 검증된 후에만 읽을 수 있습니다. 동기 수신자가 GUI를 작업 대기 상태로 만들 수 없으며 지원되지 않는 대상은 명시적으로 실패합니다. Explorer가 최종 위치와 이름 충돌을 결정합니다. FILEDESCRIPTORW 경로는 UTF-16 단위 260보다 짧아야 합니다. 콘텐츠 스트림은 읽기 전용이며 취소 후 후속 데이터 제공을 중지합니다. 종료는 비동기 수신자가 끝날 때까지 네이티브 전송을 기다립니다.

macOS는 NSFilePromiseProvider로 최상위 파일 또는 디렉터리 약속을 Finder에 제공합니다. 비공개 복사본이 준비되면 Finder의 로컬 파일 URL을 별도 Rust PublishExport 작업으로 승인합니다. 파일은 개별적으로 준비 영역에 두고 소스를 검증하며 기존 일반 파일을 덮어쓰지 않고 게시합니다. POSIX 일반 파일은 안전한 압축 풀기의 `0600 | (mode & 0155)` 권한 정책을 유지하여 실행 비트를 보존하고 특권 비트와 외부 쓰기 비트를 제거합니다. 디렉터리 병합과 부분 완료는 안전한 압축 풀기 출력 경계를 따르며 전체 전송 롤백은 보장하지 않습니다. 파일 약속 콜백은 백그라운드에서 기다리고 파일 쓰기는 항상 제한된 작업 큐와 종료 장벽에 들어갑니다.

지원되는 Linux 기준은 X11을 사용하는 Ubuntu 24.04 x86_64입니다. 먼저 비공개 복사본을 준비합니다. 준비 후에도 마우스를 누르고 있으면 파일 URL 드래그 앤 드롭을 시작합니다. 일찍 놓았다면 다시 드래그하도록 요청하고 복사본을 재사용합니다. 최종 복사와 이름 충돌은 파일 관리자가 결정합니다. 앱은 최종 대상이나 저장 성공을 추론하지 않습니다. Wayland는 이 지원 범위 밖입니다.

내보내기와 임시 열기 캐시는 분리됩니다. 무작위 디렉터리, ID 표시와 활성 잠금을 사용하고 준비 실패 시 URL을 게시하지 않습니다. 항목을 7일간 보존하고 나중에 제한된 정리를 수행합니다. 수신자가 계속 필요할 수 있으면 드래그가 반환될 때 파일을 삭제하지 않습니다. 페이지를 닫아도 작업의 컨트롤러는 유지됩니다. 명시적 종료는 준비를 취소하고 Rust 작업자와 네이티브 수신자가 끝날 때까지 기다립니다.

Linux에서는 그룹 쓰기가 가능한 umask로 생성된 디렉터리를 포함하여 앱 소유 캐시 루트를 사용 전에 현재 사용자로 제한합니다. 링크된 캐시 루트, 다른 소유자의 디렉터리 또는 권한 변경 실패는 준비를 중지합니다.

외부 드래그 준비는 일반 압축 풀기 결과 창을 열지 않아야 합니다. 내보내기 및 복사 작업은 드래그 후 Explorer, Finder 또는 대상 디렉터리를 자동으로 열지 않습니다. 일반 압축 풀기의 “완료되면 폴더 열기” 선택은 해당 명시적 압축 풀기 요청에만 속하며 이후 내보내기나 임시 열기 요청에 상속되지 않아야 합니다. 사용자가 결과 창에서 명시적으로 열기를 선택하면 기존 동작을 유지합니다.

X11에서는 준비된 복사본을 네이티브 드래그에 넘기기 전에 실제 왼쪽 버튼 상태를 확인합니다. 사용자가 준비 중 버튼을 놓았다면 새 드래그를 시작하지 않습니다. Qt가 네이티브 드래그 객체의 수명을 관리합니다. 수신 응용 프로그램이 드래그 루프가 반환된 후에도 데이터를 요청할 수 있으므로 앱은 그 시점에 객체를 파괴해서는 안 됩니다.

## 외부 드롭과 확인

기존 CAB, ISO, UDF와 RAR 아카이브는 추가, 교체, 내부 이동, 이름 변경 또는 삭제를 지원하지 않습니다. 인터페이스와 Rust 실행 진입점 모두 이 제한을 강제합니다. 지원되는 레코드는 같은 보호된 읽기 경로를 통해 외부로 드래그하거나 임시 열기 또는 압축 풀기를 할 수 있습니다. [새 ISO 이미지 만들기](iso-creation.md)는 별도 동작입니다.

열린 아카이브의 파일 목록 본문은 실제 로컬 파일과 디렉터리를 복사로만 받습니다. 드롭한 아카이브 파일은 일반 입력으로 추가하고 시작 페이지에 드롭하면 계속 열기 동작을 수행합니다. 원격 URL, 가상 첨부, 링크와 특수 객체는 거부합니다. 드롭 시 세션, 현재 디렉터리와 입력을 고정하며 검색 페이지에서는 먼저 디렉터리로 들어가야 합니다.

추가 전에 Rust는 [생성 입력 필터](zip-creation.md#macos-元数据输入过滤)를 적용하여 모든 단계의 `.DS_Store` 파일과 `__MACOSX`/`_MACOSX` 디렉터리를 제외합니다. 유효한 항목이 남지 않으면 결과 창에 명시적 실패를 표시하고 원래 아카이브 바이트를 변경하지 않습니다. 호스트 원본이나 아카이브의 기존 메타데이터를 삭제하지 않습니다.

UpdateWindow는 아이콘 제목과 추가할 파일, 대상, 옵션의 세 카드로 구성된 생성 디자인을 따릅니다. 파일 영역은 CreateWindow와 ArchiveInputPanel을 공유합니다. 사용자는 파일/디렉터리 선택을 계속하고 중복을 제거하며 마우스, 키보드 또는 접근성으로 항목을 제거할 수 있습니다. 일반 파일 크기는 최대 256개 항목의 백그라운드 요약을 재사용하고 디렉터리 총계는 알 수 없습니다. 요약은 미리 보기이며 작업 입력 고정을 대체하지 않습니다. 창 초안은 독립적이고 숨겨진 창은 메타데이터 요청을 넘겨받지 않습니다. 대상 아카이브와 내부 디렉터리는 읽기 전용이며 드롭 시 고정한 세션과 디렉터리에서 가져옵니다. 확인 시 안정적인 ID를 재검증합니다. 묻기, 건너뛰기, 이름 변경과 교체 정책을 제공하며 기본값은 묻기입니다. 같은 이름의 디렉터리는 원래 표기로 병합하고 파일/디렉터리 충돌은 거부합니다. 교체는 아카이브 안의 일반 파일에 적용되며 호스트 입력 파일을 덮어쓸 권한을 주지 않습니다. 확인 전에는 아카이브가 바뀌지 않습니다. 시각 디자인은 생성 창의 논리 너비 491, 세 카드와 공유 컨트롤을 사용합니다. [독립 디자인](../../../design/hifi/sources/archive-add.html)을 참조하세요.

아카이브 편집이 수락된 후 메인 페이지의 취소 동작은 원래 세션의 실제 작업 ID로 작업 취소를 보냅니다. 이름 충돌 프롬프트가 닫혔지만 작업이 여전히 결정을 기다리는 경우도 포함됩니다. 이미 끝난 작업 등록 요청만 취소해서는 안 됩니다. 취소 후에도 작업 종료 상태, 정리와 원래 아카이브의 재열기를 기다린 뒤 디렉터리 조회와 선택을 복원하며 이전 항목 ID의 고정을 일찍 해제하지 않습니다.

수정 중에는 확정된 파일 페이지를 계속 표시하지만 이전 조회와 선택 ID는 조작할 수 없습니다. 페이지 대기 오버레이는 새로 고침이 끝날 때까지 실제 추가, 이동, 이름 변경 또는 삭제 명령을 표시합니다. 런타임이 취소를 수락하면 즉시 표시합니다. 충돌과 비밀번호 프롬프트는 결정을 받을 자격을 잃고 진행 창은 실제 종료 상태를 따르면서 취소를 표시합니다. 충돌 창은 작업과 프롬프트 토큰에 결합됩니다. 사용자가 닫은 프롬프트는 다른 작업 업데이트로 자동 재개방하지 않지만 작업 진입점을 통해 명시적으로 다시 열 수 있습니다. 작업 변경, 프롬프트 토큰 교체, 종료 상태와 종료 시 기존 프롬프트를 닫으며 버튼이 이전 결정을 새 작업에 제출해서는 안 됩니다.

## 내부 드래그 앤 드롭 이동

파일 목록이나 격자의 드래그가 시스템 임계값에 도달하면 먼저 내부 이동으로 취급하고 현재 세션, 조회 세대, 선택 버전, 원본 아카이브 디렉터리와 안정적인 항목 ID를 고정합니다. 선택되지 않은 항목을 드래그하면 먼저 그 항목만 선택하고 선택된 항목을 드래그하면 다중 선택을 유지합니다. 원본 항목은 제자리에 계속 그립니다. 대상 폴더는 목록, 격자와 디렉터리 트리에서 기존 선택 색상을 사용합니다. 동작 안내는 도구 설명의 글꼴 크기, 최대 너비와 여백을 재사용하고 최대 네 줄로 현재 클라이언트 영역에 제한합니다. 이는 즉각적인 드래그 상태이며 일반 호버 도구 설명 타이머가 아닙니다.

현재 디렉터리의 폴더와 왼쪽 트리에 인덱스된 모든 디렉터리는 하위 디렉터리에서 루트로의 이동을 포함하여 드롭을 받을 수 있습니다. 이 세션의 비공개 드래그 ID만 수락하고 외부 URL이나 다른 세션 항목을 이동으로 해석하지 않습니다. 목록, 격자와 왼쪽 트리는 같은 대상 제한을 사용합니다. 선택된 폴더, 그 아래 모든 깊이의 하위 항목 또는 원본 디렉터리는 대상이 될 수 없습니다. 대상 폴더만이 아니라 혼합 선택 전체를 거부합니다. 검색 페이지, 오래된 선택과 현재 수정할 수 없는 아카이브도 거부합니다. 거부된 대상은 즉각적인 설명과 드롭 불가 상태를 유지하며 놓아도 작업을 시작하지 않습니다. 암호화, 분할 볼륨과 그 조합에는 서로 다른 설명을 제공합니다. 외부 추가 거부도 호버 시 표시하고 실제 드롭도 거부합니다.

유효한 대상 위에서 놓으면 진행, 이름 충돌과 결과 창을 재사용하는 독립 이동 작업을 즉시 시작합니다. 일반 파일 충돌은 기본적으로 묻고 건너뛰기, 새 이름 사용과 교체, 이후 충돌에도 적용을 지원합니다. 폴더는 병합하고 파일/폴더 유형 충돌은 실패합니다. 건너뛴 원본 파일은 원래 위치에 남고 필요한 명시적 원본 디렉터리는 유지합니다. 완전히 이동한 원본 항목은 사라지며 빈 디렉터리와 암묵적 디렉터리도 이동할 수 있습니다. 현재 암묵적 원본 디렉터리를 비우는 이동에서는 탐색 위치를 보존하도록 빈 디렉터리 레코드를 추가합니다. 성공 또는 실패 후 원래 아카이브를 다시 열고 원본 디렉터리와 정렬 순서를 유지하며 이전 물리 ID의 선택을 지웁니다. 편집 접수, 실행과 재열기 중에는 목록 스냅샷을 유지하고 디렉터리 조회를 고정하며 이전 ID로 탐색을 시작할 수 없습니다.

MoveOptions는 제한된 원본 디렉터리, 대상 디렉터리와 선택 ID만 가지며 호스트 경로는 포함하지 않습니다. 코어는 직속 원본 항목을 다시 해석하고 순환, 원래 위치와 오래된 ID를 거부합니다. 이동과 추가는 이름 공간, 충돌 결정, 완전한 콘텐츠 검증과 동일 볼륨 원자적 교체를 공유합니다. ZIP은 압축된 데이터를 그대로 복사하고 이름을 다시 씁니다. TAR은 경로를 제외한 일반 레코드 헤더와 지원되는 PAX 속성을 유지하고 경로를 UTF-8 PAX로 기록하며 GNU 긴 이름을 PAX로 변환합니다. 압축 TAR은 외부 스트림을 재구축합니다. 안전하게 유지할 수 없는 확장은 명시적으로 실패합니다. 커밋 전 실패나 취소는 원래 아카이브 바이트를 보존합니다.

포인터가 원본 창의 클라이언트 영역을 벗어나거나 원본 창이 비활성화되면 고정된 선택을 기존 플랫폼 외부 복사 흐름에 넘기고 내부 드래그를 끝냅니다. 시스템 외부 드래그로 전환한 뒤 앱으로 반환된 내보낸 데이터를 내부 이동이나 새 입력으로 취급하지 않습니다. 이렇게 비공개 준비 콘텐츠의 재추가를 막으며 플랫폼 외부 드래그 규칙은 바꾸지 않습니다.

`Move`, `Update`, `EditEntries` 명령은 제한된 작업 큐를 사용하고 현재 세션을 검증합니다. 작업 접수 시 명령 스레드는 아카이브 스냅샷을 폐기합니다. 컨트롤러는 종료 상태와 재열기를 기다리는 동안 마지막으로 렌더링한 페이지를 유지할 수 있습니다. 페이지 `edit_restriction` 비트 0은 암호화, 비트 1은 분할 볼륨, 비트 2는 재작성 미지원 형식, 디스크 인덱스 ZIP, 안전하지 않은 레코드 또는 미지원 방식을 포함한 기타 제한을 나타냅니다. `update_allowed`는 모든 비트가 해제된 경우에만 true입니다. 런타임은 전체 소스 스냅샷으로 적격성을 계산하며 작업은 쓰기 전에 입력을 계속 검증합니다.

## 아카이브 내부 이름 변경과 삭제

항목 컨텍스트 메뉴는 내부 이동과 같은 아카이브 전체 편집 요건을 사용하며 일반 디렉터리 보기에서 이용할 수 있습니다. 오른쪽 클릭은 해당 행을 포함한 선택을 유지하거나 클릭한 행만 선택합니다. 이름 변경에는 정확히 한 항목이 필요합니다. 삭제는 한 이름 또는 선택 항목 수를 확인하고 폴더의 재귀 삭제를 설명합니다. 대화상자는 원래 세션, 조회, 디렉터리와 선택에 결합되며 변경되면 무효화됩니다. 작업자는 불변인 현재 아카이브에서 선택자를 다시 해석하고 선택된 모든 루트가 지정 디렉터리의 직속 자식인지 확인합니다.

이름 변경은 이식 가능한 이름 구성 요소 하나를 받아 선택 항목과 하위 경로를 다시 씁니다. 같은 항목의 표기만 바꾸는 것은 허용합니다. 정규 대상 이름을 가진 기존 파일이나 명시적 또는 암묵적 디렉터리가 있으면 실패합니다. 삭제는 선택한 디렉터리 아래 모든 레코드와 선택 파일을 한 트랜잭션으로 제거합니다. 마지막 자식을 삭제해도 현재 폴더를 보존하며 필요하면 암묵적 폴더를 빈 디렉터리로 구체화합니다. 빈 루트는 항목이 0개인 아카이브로 남습니다. 비어 있게 다시 쓴 TAR.GZ에는 고정 GZIP 주석을 넣어 일반 `.gz` 이름에서도 TAR로 열 수 있게 합니다. ## 일반 아카이브 수정 트랜잭션

Update는 [형식 레지스트리](format-registry.md)의 조건에 맞는 단일 파일 ZIP/ZIPX, 7z, 레벨 2 LHA/LZH, TAR과 압축 TAR 프로필을 지원합니다. 암호화, 분할 볼륨, 링크, 특수 레코드 또는 안전하게 보존할 수 없는 이름은 다시 쓰지 않습니다. 기능은 현재 페이지만이 아니라 전체 소스 스냅샷에서 결정합니다. 작업이 수락되면 메타데이터 세션을 해제하고 이전 항목 ID는 새 동작을 받지 않습니다. 작업은 소스 핸들과 ID를 유지합니다.

이름은 [인코딩 계약](filename-encoding.md)의 고정된 결과를 사용합니다. 해결된 레거시 이름은 재작성 시 명시적 UTF-8로 쓰고 아카이브 이름 공간과 Unicode/대소문자 충돌을 다시 확인합니다. 소스 버전과 링크를 따르지 않는 InputTree를 고정한 뒤 원래 아카이브와 같은 볼륨의 비공개 작업 공간에 완전한 새 아카이브를 만듭니다. 독립 ZIP 레코드 계층은 원래 압축 데이터를 복사하고 허용된 메타데이터를 유지하며 새 항목은 Deflate 6을 사용합니다. 유지된 ZIP/ZIPX 레코드는 Store, Deflate, Deflate64, BZip2, LZMA 또는 XZ를 사용할 수 있습니다. 독립 Rust 7z 백엔드는 아카이브를 재구축하고 일반 수준 LZMA2로 콘텐츠를 추가합니다. TAR은 원래 레코드 그룹을 유지하고 압축 TAR은 외부 스트림을 다시 인코딩합니다. LHA/LZH는 적격 레벨 2 멤버의 압축 데이터를 복사하고 변경된 이름을 UTF-8로 출력하며 새 파일을 LH5로 인코딩합니다. 유지된 ZIP, TAR, LHA와 지원되는 7z 레코드는 원래 물리 순서대로 처리하고 새 항목을 뒤에 붙입니다. 7z 보존과 재구축 경계는 [자체 명세](../../engineering/independent-rust-codecs.md#7z读写规格)를 참조하세요. 새 아카이브는 누락, 중복이나 혼입 없이 예상 항목 유형, 크기와 전체 데이터를 검증해야 합니다. 중복 또는 모호한 레코드, ZIP 자체 압축 풀기 접두사와 재작성할 수 없는 확장은 조용히 버리지 않고 명시적으로 실패합니다. TAR 전역 PAX 레코드는 현재 재작성하지 않습니다. 압축 TAR의 마지막 레코드를 삭제할 때 단일 스트림 접미사로 결과가 일반 압축 파일로 다시 열리게 되면 커밋 전에 재작성이 실패합니다. 표시된 TAR.GZ는 기존 예외를 사용합니다.

아카이브 이름 공간에는 암묵적 부모 디렉터리가 포함되며 100,000개 노드로 제한합니다. 깊은 경로가 제한 없는 인덱스를 만드는 것을 막기 위해 이름과 정규화 인덱스는 16 MiB 예산을 공유합니다. 새 아카이브를 다시 스캔하고 각 파일을 제한된 검증 싱크로 디코딩한 뒤 입력, 원래 아카이브와 대상의 ID를 다시 검증합니다. 원래 파일 버전에 결합된 ArchiveUpdate 권한만 전체 파일을 교체할 수 있으며 일반 생성/압축 풀기의 소스 보호는 바뀌지 않습니다. 원래 아카이브를 추가 입력으로 사용하는 것은 명시적으로 거부합니다. 필요한 원자적 파일 시스템 프리미티브가 없으면 먼저 삭제하거나 잘라내지 않고, 복사/삭제로 교체를 흉내 내지 않고 실패합니다. 버전 검사는 최선의 변경 탐지이며 같은 계정의 악의적 동시 쓰기에 대한 콘텐츠 CAS나 전원 손실 내구성을 보장하지 않습니다.

커밋 전 취소나 실패는 원래 아카이브 바이트를 보존합니다. 커밋 허가를 얻은 후에는 성공적인 게시가 우선하며 정리 실패는 별도로 기록합니다. 성공 또는 실패 후 같은 소스를 다시 열고 무효한 물리 항목 선택을 지웁니다. 작업은 update, move, rename, delete, export와 export-copy 종류를 구분하며 비공개 준비를 시스템 복사 성공으로 취급하지 않습니다.

7z 수정은 같은 이름 공간, 충돌, 소스 재검증과 원자적 교체 계약을 따릅니다. 솔리드 콘텐츠는 디코딩 및 재구축이 필요합니다. 재구축 입력은 명시적으로 제한된 버퍼를 사용합니다. 원본과 추가 콘텐츠 합계는 네이티브 어댑터의 512 MiB 캐시 제한을 넘을 수 없으며 백엔드의 1 GiB 프로세스 메모리 예산도 적용됩니다. 제한을 초과하면 리소스 오류를 명시적으로 반환하고 디스크 캐시 권한을 주지 않으며 원래 아카이브는 변경되지 않습니다. 성공 출력은 일반 압축과 비솔리드 레이아웃을 사용할 수 있으며 원래 압축 스트림, 알고리즘 조합, 솔리드 블록 또는 물리 레코드 순서 보존을 보장하지 않습니다. 암호화된 이름, 암호화된 콘텐츠 또는 분할 7z 볼륨이 있는 아카이브는 빈 암호화 디렉터리를 포함하여 수정을 거부합니다.

RAR은 독립 읽기 전용 Rust 백엔드를 사용하며 추가, 교체 또는 내부 이동을 제공하지 않습니다. 아카이브 전체의 기타 미지원 레코드 `edit_restriction` 비트는 항상 설정되므로 현재 페이지에 미지원 항목이 없어도 우회할 수 없습니다. 7z/RAR 링크와 특수 객체는 출력하지 않습니다. 외부 복사와 임시 열기는 기존 사전 검사와 안전 출력 작업을 계속 사용합니다.

## 검수 경계

목록과 격자의 전체 이름 도구 설명은 내부 이동, 네이티브 복사 준비와 실제 네이티브 드래그 내내 억제하고 이전 정지 타이머를 취소합니다. 내부/외부 인계 중 원본 도구 설명을 잠시라도 다시 활성화해서는 안 됩니다. Windows는 OLE 반환, macOS는 네이티브 드래그 종료 콜백, Qt 준비 드래그는 exec 반환으로 제스처 상태를 끝냅니다. 비동기 복사는 계속될 수 있으며 복사 작업 완료가 마우스 제스처의 종료는 아닙니다. 이후 새 포인터 위치를 먼저 얻고 정지 상태에서 다시 전체 1,200 ms를 기다려 캐시된 원본 호버가 도구 설명을 되살리지 않게 합니다.

드래그 미리 보기는 고정된 원본 이름, 아이콘과 선택 개수만 나타냅니다. 콘텐츠를 읽거나 압축을 풀지 않으며 대상 쓰기 권한도 주지 않습니다. 내부 미리 보기는 유효한 드래그 토큰에서 값을 얻고 창을 벗어나면 내부 오버레이를 지우고 네이티브 복사 피드백에 넘깁니다. Windows IDataObject는 Shell 이미지용으로 제한되고 스레드 안전한 비공개 HGLOBAL 형식을 유지하고 별도로 고유 DragContext 스트림의 COM 참조를 콘텐츠를 읽거나 복사하지 않고 보유합니다. GetData는 독립 참조를 반환합니다. 파일 기술자, 콘텐츠 스트림과 선호 동작을 덮어써서는 안 됩니다. 실패해도 기존 안전 출력과 취소 의미는 바뀌지 않습니다. 네이티브 이미지는 Shell용 비사전곱 BGRA를 사용하며 비트맵 소유권은 초기화 때 이전됩니다. COM/GDI 준비 실패 시 시스템 커서를 유지합니다. 스타일은 [드래그 명세](../../../specs/visual/drag-preview.json)를 참조하세요.

코어 범위에는 세 형식, 현재 디렉터리, 원래 콘텐츠와 빈 디렉터리, 충돌 정책, 소스 변경, 보호 입력과 취소가 포함됩니다. Qt는 실제 컨텍스트 열기와 추가 확인, 양쪽 언어, 밝은/어두운 테마, 여러 글꼴 크기와 고정 세션을 다룹니다. Windows 네이티브 프로토콜 테스트는 비동기 데이터 객체와 실제 콘텐츠 스트림을 검증합니다. 이동 회귀는 목록/격자, 디렉터리 트리, 거부된 대상, 혼합 선택, 디렉터리 병합, 메타데이터 보존과 경계 인계를 다루며 세 형식은 Python 리더로 독립적으로 다시 확인합니다. 실제 Explorer, Finder, Ubuntu Files와 데스크톱 드롭은 필요에 따라 확인하고 실행 시 별도로 기록합니다. 오프스크린 및 프로토콜 수신자는 실행하지 않은 데스크톱 동작을 대신하지 않습니다. 단계 증거는 관련 이슈와 로컬/CI 아티팩트에 기록합니다.
