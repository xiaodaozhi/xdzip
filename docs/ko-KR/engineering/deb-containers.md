# DEB 컨테이너 계약

[English](../../engineering/deb-containers.md) | [简体中文](../../zh-CN/engineering/deb-containers.md) | [繁體中文（台灣）](../../zh-TW/engineering/deb-containers.md) | [日本語](../../ja-JP/engineering/deb-containers.md) | 한국어 | [Français](../../fr-FR/engineering/deb-containers.md) | [Deutsch](../../de-DE/engineering/deb-containers.md) | [Español](../../es-ES/engineering/deb-containers.md) | [Português (Brasil)](../../pt-BR/engineering/deb-containers.md) | [Русский](../../ru-RU/engineering/deb-containers.md)

패키지 외부 구조는 Debian의 [deb(5)](https://manpages.debian.org/unstable/dpkg-dev/deb.5.en.html)를 따르고 공통 ar 필드는 [ar(5)](https://man.netbsd.org/ar.5)를 따릅니다. 일반 `!<arch>\n` 레이아웃만 허용합니다. 각 60바이트 헤더에는 크기가 제한된 ASCII 이름, 시간, 소유자, 모드, 크기 필드와 필수 끝 표시가 있습니다. 10진 필드, 8진 모드, 정확한 데이터 구간, 홀수 길이 멤버의 줄 바꿈 패딩과 실제 파일 끝을 검증합니다. thin 아카이브, 과거 형식과 긴 이름 확장은 지원하지 않으며 외부 파일 접근 권한도 부여하지 않습니다.

`debian-binary`가 첫 번째입니다. 주 버전 2, 제한된 10진 부 버전과 제한된 추가 버전 행을 허용하고 호환되지 않는 주 버전은 거부합니다. control과 data 멤버는 이 순서로 나타납니다. 밑줄로 시작하는 확장이 사이에 올 수 있으며 이후 추가 멤버도 보존합니다. control은 압축되지 않은 TAR, GZIP, XZ 또는 Zstandard를 허용합니다. data는 BZip2와 LZMA Alone도 허용합니다. 접미사만이 아니라 실제 TAR과 필터 구현이 선택된 각 멤버를 검증합니다. 지원하지 않는 필수 멤버 프로필은 명시적으로 실패합니다. Deb822 필드, 메타데이터에 나열된 체크섬, 서명과 설치 가능성은 컨테이너 검증 범위 밖입니다.

## 보기와 물리적 식별자

기존 디렉터리 모델은 서로 겹치지 않는 세 접두사를 제공합니다. `members/`에는 버전과 압축된 TAR 멤버를 포함하여 모든 원시 ar 멤버가 있습니다. `control/`과 `data/`에는 해당 TAR 레코드가 있습니다. 이는 내보내기 보기입니다. 모두 압축을 풀면 원시 멤버와 펼쳐진 레코드를 모두 내보냅니다. `control/` 또는 `data/`만 선택하면 해당 보기만 내보냅니다. 패키지를 설치하거나 스크립트를 실행하지 않습니다.

원시 레코드에는 ar 순서대로 안정적인 식별자를 부여하고, 그다음 각 TAR의 물리적 레코드 순서대로 control과 data 식별자를 부여합니다. 중복, 원시 이름과 해석된 이름, 경고 및 특수 항목 플래그와 타임스탬프의 의미를 보존합니다. 표시 이름은 원본이나 출력에 대한 권한이 되지 않습니다. 하위 항목의 원시 이름과 해석된 이름에 모두 접두사를 붙이되 안전하지 않은 구성 요소를 정규화로 없애지 않습니다. 접두사를 붙이기 전에 원래의 안전하지 않은 표기를 표시하여 절대 경로가 안전해 보이는 상대 하위 항목으로 바뀌지 않게 합니다. 기존 TAR 파서는 무해한 빈 `.` 루트 표시를 생략합니다. 접두사에서 추론한 디렉터리 노드는 가상 상태로 남으며 실제 항목을 만들어 내지 않습니다. 링크와 특수 객체는 TAR의 미지원 플래그를 유지합니다. 호스트의 일반 경로 검사는 안전하지 않은 출력을 계속 거부합니다. 메타데이터를 열 때 두 내부 검색과 선언된 검사를 모두 완료한 후에만 행을 게시합니다.

## 원본 소유권, 작업량과 데이터 검증

내부 판독기는 이미 승인된 원본의 제한된 보기만 받습니다. 상대 위치 이동과 읽기는 멤버의 물리적 구간을 벗어나거나 다른 파일을 열 수 없습니다. 공유 보기는 루트 원본에 대한 실제 접근을 직렬화하면서 독립적인 논리 커서를 유지합니다. unsafe 포인터나 자기 참조 포인터는 추가하지 않습니다. 형식이 구분된 취소 및 제한 오류를 보존하고 일반 호스트 읽기 실패는 I/O 오류로 유지합니다. 빌림 충돌과 불가능한 읽기 수는 패닉을 일으키거나 종료된 실패를 재시도하지 않고 거부합니다.

기존 제어 스트림과 TAR 판독기에 소유형 원본 입력을 추가하되 빌려 쓰는 호출자와 동일한 초기화 및 허용 규칙을 유지합니다. 물리적 순서의 요청 동안 각 내부 데이터 판독기를 유지하여 여러 레코드를 추출할 때 파일마다 TAR을 다시 검색하지 않게 합니다. 데이터를 사용하기 전에 외부 구조와 두 TAR 인덱스를 다시 분석하고 해당 판독기를 유지하며 새 전체 인덱스를 투영하여 불변 상위 스냅숏과 비교합니다. 호출자가 제공한 이름, 식별자, 유형, 방법과 크기로 다른 레코드를 대체할 수 없습니다. 패딩과 멤버 구간도 다시 검증합니다. 판독기는 실패 후 재개할 수 없습니다. 호스트 원본 검사, 임시 준비, 파일별 검증과 최종 게시가 계속 우선합니다. 기존 원본 식별 검사는 변경을 가능한 범위에서 감지합니다. ar에는 콘텐츠 체크섬이 없으며 이 검사는 원자적이거나 인증된 원본 스냅숏을 만들지 않습니다. 분석한 ar 소유자와 모드 필드는 권한 복원 권리를 부여하지 않습니다.

멤버와 행 수, 원시 이름과 해석된 이름 및 표시 이름의 바이트, 물리적 원본 구간과 메타데이터 디코딩 작업량에 패키지 전체의 공통 제한을 적용합니다. control과 data가 각각 새로운 누적 디코딩 할당량을 받지는 않습니다. 입력 I/O는 각 준비 또는 전달 단계에서 공유 보기 전체에 걸쳐 계산합니다. 기존 TAR 인덱싱과 데이터 재열기처럼 준비와 전달은 별도 단계입니다. 준비 중 캐시된 바이트는 추가 원본 접근 권한을 주지 않습니다. 전달은 원시 멤버 내보내기와 실제 내부 디코딩을 전달된 파일 바이트와 별도로 계산합니다. 다음 읽기, 쓰기 또는 할당 전에 초과를 거부하고 레코드 경계와 원본 읽기에서 취소를 확인합니다.

이 프로필은 읽기 전용이며 암호, 분할 볼륨, 패키지 생성 또는 다시 쓰기를 제공하지 않습니다. 원시 ar 멤버의 압축 크기는 알 수 있지만 압축된 TAR 하위 레코드의 크기는 알 수 없습니다. 검사는 `format_declared_checks`를 사용하여 컨테이너 구조, 읽기 가능성과 허용된 내부 필터가 실제로 선언한 검사를 검증합니다. 이는 패키지 인증이 아닙니다. 자동화된 수락 검증에는 알려진 콘텐츠를 가진 독립 참조, 모든 허용 필터 계열, 중첩 경계, 중복 식별자, 잘못된 외부 구조와 내부 검사, 정확한 예산, 원본 변경과 취소, 실제 CLI/Qt 탐색, 검사와 추출이 포함됩니다. 생성된 증거는 `build/` 또는 CI에 보관하며 플랫폼과 릴리스 승인은 별도로 다룹니다.
