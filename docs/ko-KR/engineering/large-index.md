# 대형 압축 파일 인덱싱과 필요할 때 탐색

[English](../../engineering/large-index.md) | [简体中文](../../zh-CN/engineering/large-index.md) | [繁體中文](../../zh-TW/engineering/large-index.md) | [日本語](../../ja-JP/engineering/large-index.md) | 한국어 | [Français](../../fr-FR/engineering/large-index.md) | [Deutsch](../../de-DE/engineering/large-index.md) | [Español](../../es-ES/engineering/large-index.md) | [Português (Brasil)](../../pt-BR/engineering/large-index.md) | [Русский](../../ru-RU/engineering/large-index.md)

일반 단일 파일 ZIP/ZIP64의 소스 기능 한도는 물리 레코드 100만 개입니다. 다른 형식과 분할 볼륨 경로는 기존 100,000개 항목 허용 한도를 유지합니다. 형식 이름만으로 모든 조합의 한도가 확대되었다고 볼 수 없습니다. 디렉터리, 중복 이름, 검토가 필요한 레코드는 물리 항목에 포함되며 암시적 탐색 디렉터리는 표시 행만 추가합니다.

<a name="xdzip-scanning-and-storage"></a>

## 검사와 저장

ZIP은 일반 ZIP 파서로 레코드를 개별 검사합니다. 먼저 전체 압축 파일의 이전 인코딩 이름을 제한적으로 표본 추출하고 같은 인코딩 결정으로 두 번째 검사를 수행합니다. 두 번의 읽기는 합계 최대 512 MiB이며 중앙 디렉터리는 최대 256 MiB, 원시 이름 합계는 최대 128 MiB, 디코딩 이름과 표시 이름 합계는 최대 128 MiB입니다. 각 원시 또는 디코딩 이름은 계속 4 KiB로 제한됩니다. 손상된 끝부분, 취소, 소스 변경은 전체 결과를 실패시키며 부분 인덱스를 게시하지 않습니다.

활성 메타데이터가 64 MiB에 도달하거나 항목이 100,000개를 넘으면 레코드를 비공개 디스크 저장소로 하나씩 옮기고 기존 이름과 레코드를 해제하여 전체 인덱스 두 개를 동시에 유지하지 않습니다. 물리 위치 표에는 최대 100만 개의 u64 오프셋이 들어갑니다. 디스크 메타데이터는 최대 512 MiB이며 파일 이름과 내용은 진단 문자열에 포함하지 않습니다. 디렉터리 트리는 32,768개 노드, 64개 깊이, 이름 예산 4 MiB로 제한됩니다. 초과하면 트리를 게시하지 않으며 루트 탐색과 물리 검색은 계속 사용할 수 있습니다.

임시 파일은 호스트 임시 디렉터리 아래 무작위 이름의 `xdzip-index-*` 디렉터리에 있습니다. 현재 사용자만 읽고 쓸 수 있으며 보유한 디렉터리 및 일반 파일 핸들로 조작합니다. 정상 종료, 쿼리 교체, 실패, 취소는 알려진 파일과 신원이 확인된 빈 디렉터리를 정리합니다. 충돌 잔여물은 디렉터리의 무작위 신원과 일치하는 16바이트 마커 및 배타적 임대로 식별합니다. 이후 생성 시 제한적으로 검사하여 7일보다 오래된 미사용 알려진 파일만 정리합니다. 링크, 신원 불일치, 알 수 없는 객체는 보존합니다. 낯선 내용을 재귀적으로 삭제하거나 실행 간 인덱스를 복원 또는 재사용하지 않습니다.

Windows에서는 새 디렉터리가 먼저 일반 소유자 및 수정 권한 검사를 통과해야 기밀 저장을 위해 DACL을 보호합니다. 관련 없는 주체에 상속된 수정 권한은 임대나 메타데이터 파일을 쓰기 전에 거부하며 런타임이 조용히 덜 사적인 위치를 사용하지 않습니다. 격리 검증 시 테스트 프로세스의 `TMP`와 `TEMP`만 현재 사용자, SYSTEM, Administrators만 수정할 수 있는 ACL을 가진 새 소유 디렉터리로 지정합니다. 실제 사용자 디렉터리의 ACL을 바꾸거나 권한 검사를 완화하지 않습니다. 할당, 실제 디스크 쿼리와 병합, 활성 임대, 알려진 파일 정리, 관련 없는 수정 권한의 거부를 각각 검증합니다.

<a name="xdzip-queries-and-selection"></a>

## 쿼리와 선택

검색과 정렬은 완전하고 불변인 행 순서를 만듭니다. 정렬 키는 각각 최대 8 MiB인 비공개 병합 런에 기록하며 최대 128개 런과 512 MiB의 임시 정렬 저장소를 사용합니다. 최종 쿼리는 이름 전체를 다시 복사하지 않고 행 토큰만 저장합니다. 비교는 원래 정수, 기존 이름과 유형 규칙, 안정적인 물리 신원을 유지합니다. 모든 정렬 모드는 명시적 및 암시적 디렉터리를 파일 앞에 두며 방향은 각 그룹 안에 적용됩니다. 알 수 없는 크기는 해당 디렉터리 또는 파일 그룹의 알려진 값 뒤에 오고 내림차순도 중복 항목의 신원 순서를 바꾸지 않습니다. 취소는 검사, 정렬 런과 병합 전후에 확인하며 비교기 내부의 순서 관계를 바꾸지 않습니다.

브리지는 배치당 최대 128개 행과 64 KiB의 이름을 전송합니다. 최대 1,024개 행의 쿼리는 기존 전체 확정 방식을 유지합니다. 더 큰 Qt 모델은 전체 논리 행 수를 유지하고 보이는 위치만 불러오며 상주 캐시는 최대 1,024개 행입니다. 불러오지 않은 행은 항목 동작을 제출할 수 없습니다. 각 지연 페이지는 세션, 쿼리, 세대, 수정 버전, 요청 오프셋에 연결되며 오래된 페이지는 새 결과에 들어갈 수 없습니다.

페이지 간 선택은 현재 불변 쿼리의 제한된 범위로 표현하며 최대 4,096개 범위입니다. 모두 선택은 현재 쿼리 전체를 포함하고 캐시를 벗어나도 선택은 바뀌지 않습니다. 추출 확인 전에 Rust가 범위를 물리 또는 탐색 신원으로 고정하며 쿼리가 바뀌어도 계속 사용합니다. 작업의 100,000개 항목 한도를 넘는 선택은 명시적으로 거부하며 조용히 줄이지 않습니다. 상주하지 않는 선택의 총 크기는 현재 표시하지 않습니다. 상주 내용을 넘어서는 대량 클립보드 복사는 불완전한 목록을 조용히 복사하지 않고 리소스 한도를 반환합니다.

<a name="xdzip-task-boundaries"></a>

디스크 쿼리는 이름을 비교할 때 레코드 버퍼를 재사용하고 행을 전송할 때 항목 레코드를 구성합니다. 결과가 적은 검색이나 정렬은 모든 배치를 모아 결과를 확정할 때까지 처리 중 상태를 유지합니다. 화면에 표시할 페이지 요청은 이미 확정된 쿼리의 캐시를 채웁니다.

## 작업 경계

디스크 인덱스에서 선택한 일반 파일은 전체 소스 재검증, 안전한 계획, 전체 항목 검증, 기존의 승인된 확정 후 추출할 수 있습니다. 고정된 계획은 계속 100,000개 항목과 64 MiB 메타데이터로 제한되며 파일과 실제 디코딩 바이트 한도는 [추출 계약](zip-safe-extraction.md)을 따릅니다. 디렉터리 확장 시 해결되지 않은 이름을 건너뛸 수 없으며 이 인덱스 구성에서는 선택된 링크를 거부합니다. ZIP 리더는 전체 중앙 디렉터리의 물리 오프셋을 다시 확인하고 선택한 데이터 위치만 유지하면서 겹침, 로컬 헤더, 크기, CRC, 인증과 취소 검사를 보존합니다.

디스크 인덱스를 사용하는 압축 파일은 현재 전체 압축 파일의 수정이나 검사를 지원하지 않습니다. 비어 있는 메모리 투영을 완전한 압축 파일로 취급할 수 없습니다. 생성, 다른 형식, 분할 볼륨, 다시 쓰기의 기존 한도는 변하지 않습니다. [내용 미리 보기](content-preview.md)를 별도로 참조하세요. CLI 물리 목록과 선택은 같은 인덱스를 재사용하며 [명시적 페이지 나누기](command-line.md#xdzip-archive-behavior)로 대형 압축 파일의 전체 물리 범위를 얻습니다. 페이지를 나누지 않은 응답은 100,000개 항목과 16 MiB 직렬화 데이터 또는 텍스트 예산을 유지하며 초과하면 전체가 실패합니다.

<a name="xdzip-verification"></a>

## 검증

`scripts/probe-large-index.py`는 중국어 이름, 중복, 중첩 디렉터리가 있는 실제 ZIP64를 `build/`에 생성하고 실제 `xdzip-m2-probe`를 호출합니다. 프로브는 모든 쿼리 배치를 읽고 검사, 정렬, 조회, 디스크 바이트, 플랫폼에서 사용 가능한 메모리 지표를 별도로 기록합니다. 샘플 생성기는 100만 개 파일 이름 배열을 메모리에 만들지 않습니다. 범위, 실패, 취소, 정리, 오래된 페이지와 선택 파일의 실제 출력은 [승인 요구 사항](../../../developers/qa/acceptance.md)을 따르며 결과는 issue, 로컬 또는 CI 산출물에 남습니다. 측정은 실제 기기와 작업 부하에 대한 증거이며 보편적 성능을 보장하지 않습니다.
