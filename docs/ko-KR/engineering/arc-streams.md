# ARC 컨테이너와 압축 스트림 프로필

[English](../../engineering/arc-streams.md) | [简体中文](../../zh-CN/engineering/arc-streams.md) | [繁體中文](../../zh-TW/engineering/arc-streams.md) | [日本語](../../ja-JP/engineering/arc-streams.md) | 한국어 | [Français](../../fr-FR/engineering/arc-streams.md) | [Deutsch](../../de-DE/engineering/arc-streams.md) | [Español](../../es-ES/engineering/arc-streams.md) | [Português (Brasil)](../../pt-BR/engineering/arc-streams.md) | [Русский](../../ru-RU/engineering/arc-streams.md)

`ArcReader`는 ARC 방식 3–9의 제한된 원시 디코딩을 구현합니다. 방식 1과 2는 컨테이너의 Store 프로필입니다. `xdzip-codec-arc`와 `ArcCodec`은 완전한 구조와 필수 CRC-16을 런타임, CLI와 데스크톱 탐색, 검사 및 추출에 연결합니다. [형식 레지스트리](../../../specs/engineering/archive-formats.json)는 이 읽기 전용 범위를 선언하며 생성, 수정, 암호와 볼륨은 사용할 수 없습니다.

<a name="xdzip-container-and-host-admission"></a>

## 컨테이너와 호스트 승인

승인된 프로필은 일반 ARC 5.x 구조를 사용하며 ARC 6.x 추가 메타데이터와 Spark 확장은 지원한다고 주장하지 않습니다. 각 멤버는 `0x1a`와 원래 방식 바이트로 시작합니다. 방식 1은 25바이트를 사용하고 0이 아닌 다른 방식은 일반 29바이트 헤더를 사용합니다. 13바이트 파일 이름 필드에는 비어 있지 않은 NUL 종료 이름이 있어야 합니다. 모든 정수는 리틀 엔디언입니다. 압축 길이는 15, DOS 날짜/시간은 19/21, 필수 CRC-16은 23, 일반 디코딩 길이는 25에 있습니다. 이전 Store는 압축 길이를 상속하며 두 Store 방식 모두 길이가 같아야 합니다. 압축 범위는 들어맞아야 하고 다음 표식은 필수이며 정확한 2바이트 `1a00` 종료자는 물리 EOF와 일치해야 합니다. 재동기화, 접두사 스캔, 채우기나 인접 파일은 승인하지 않습니다.

컨테이너는 모든 물리 중복과 알 수 없는 방식을 보존합니다. 메타데이터 읽기는 엄격한 64 MiB, 최대 100000개 레코드, 호출자가 제한한 원시 이름과 물리 입력 24 GiB 상한을 가집니다. SHA-256은 정확한 `Index`를 다시 열 때 무시된 이름 채우기를 포함해 모든 헤더 바이트와 종료자를 결합합니다. 헤더 해시는 페이로드를 인증하지 않습니다. 각 리더는 실제 입력과 디코딩 바이트 각각 24 GiB, 작업 96 GiB의 누적 장부를 가지며 디코딩 전 테이블 CRC 바이트 작업을 예약하고 모든 실패에서 예산 환급이나 부분 인덱스 게시 없이 종료합니다.

호스트는 강한 컨테이너와 ZIP/SFX 우선순위를 유지하고 공유 탐색 장부 아래 약한 ARC 후보를 완전히 검증합니다. 이름은 공유된 제한 압축 파일 인코딩 결정에 따라 완전한 필드로 디코딩한 뒤 DOS 역슬래시를 변환합니다. 원래 바이트와 방식 ID는 계속 사용할 수 있습니다. 의심스럽거나 미해결된 이름과 알 수 없는 방식은 페이로드 권한 없이 표시됩니다. ARC에는 승인된 디렉터리, 링크, 모드 복원 또는 외부 객체 프로필이 없습니다. 이전 XOR에는 암호화 플래그가 없으므로 암호 추측이나 대체 없이 스트림, 크기와 CRC 검증이 필수입니다. 이 프로필은 전용 Linux MIME 등록을 주장하지 않습니다.

페이로드를 열 때 고정된 항목을 다시 투영해 비교하며 선택된 ID는 물리 행을 식별하고 정확히 일치해야 합니다. 런타임 사전 검사, 고정된 호스트 원본 식별 정보, 개인 준비 영역, 취소, 이전 파일 보호와 최종 게시가 계속 우선합니다. 전체 `supported_content` 검사는 승인된 모든 일반 멤버를 실제 디코딩하고 정확한 크기와 CRC-16을 검증하며 미지원 행에서 실패합니다. 지원되는 물리 선택은 미지원 이웃이 있어도 추출할 수 있습니다.

## 소스와 참조

Howard Chu와 Anibal Monsalve Salazar가 유지하는 원래 ARC Unix 포트는 [커밋 `70f0b93516d0ee222db5cf1241aad0db1b721c0d`](https://github.com/ani6al/arc/tree/70f0b93516d0ee222db5cf1241aad0db1b721c0d)에 고정되어 있습니다. `Arcinfo`에는 Robert Freed의 ARC 5.12 구조 설명이 기록되어 있습니다. 제한된 와이어 관찰에 `arcunp.c`, `arcusq.c`, `arclzw.c`를 사용합니다. 작성자의 `LICENSE`와 `COPYING`은 GPL 라이선스를 기록합니다. 참조 알고리즘은 프로젝트 소유 테스트 어댑터와 함께 build/toolchain에서만 변경 없이 컴파일하며 제품에 컴파일하거나 배포하지 않습니다.

독립 비교는 Russell Marks의 nomarch 1.4, GPL 버전 2 이상을 사용합니다. 원래 소스 패키지는 [Debian 소스 풀](https://deb.debian.org/debian/pool/main/n/nomarch/)에서 받을 수 있으며 SHA-256 `fe20da34e0d3ba0cf6388701f44ac22224cf65130ddbc5fcbc27bc4949a6e1ad`, 22411바이트로 관리자의 소스 설명과 일치합니다. 엄격한 클린룸을 주장하지 않습니다. 제품 코드는 프로젝트 소유 비트, 입력, 작업과 할당 기본 요소로 와이어 필드를 표현합니다. [자체 픽스처 기록](../../../tests/fixtures/arc/README.md)은 네이티브 인코더 출력, 직접 작성한 와이어 입력, 완전한 바이트 독립 비교와 참조 제한을 구분합니다.

## 방식 범위

| 방식 | 와이어 프로필 | 후속 단계 |
| --- | --- | --- |
| 1 | 원래 길이가 암시된 이전 25바이트 구조 | Store |
| 2 | 일반 29바이트 구조 | Store |
| 3 | DLE `0x90` 연속 구간과 이스케이프된 DLE가 있는 바이트 | 없음 |
| 4 | 명시적 부호 있는 자식을 가진 squeeze 트리, 하위 비트 우선 코드와 EOF 기호 256 | 방식 3 RLE |
| 5 | 고정 12비트 상위 비트 우선 코드, 원래 해시 사전 | 없음 |
| 6 | 같은 원래 해시 사전 | 방식 3 RLE |
| 7 | 고정 12비트 코드, 개선된 해시 | 방식 3 RLE |
| 8 | 최대 너비 12의 초기 바이트, 9–12비트 그룹화 하위 비트 우선 LZW | 방식 3 RLE |
| 9 | 너비 헤더 없음, 9–13비트 그룹화 하위 비트 우선 LZW | 없음 |

알 수 없는 방식, Spark 확장, 암호와 SFX 구조에는 별도의 컨테이너 승인이 필요합니다. 알고리즘 이름이 같아도 다른 방식의 비트 순서, 사전, 정렬, 재설정 또는 RLE 단계를 허가하지 않습니다.

<a name="xdzip-rle-and-squeeze-trees"></a>

## RLE와 squeeze 트리

일반 바이트는 출력되고 반복 이력이 됩니다. DLE 뒤의 0은 이력을 바꾸지 않고 문자 그대로의 DLE를 출력합니다. 0이 아닌 개수는 직전 일반 바이트의 `count - 1`개 사본을 출력하며 이력 없는 개수는 유효하지 않습니다. 이스케이프는 완전해야 하고 정확한 디코딩 크기가 각 반복을 제한합니다. RLE 상태는 사전 문자열과 호출자 출력 청크를 가로질러 유지됩니다.

Squeeze는 리틀 엔디언 노드 수 최대 256으로 시작하고 노드마다 부호 있는 16비트 자식 둘이 이어집니다. 음수가 아닌 자식은 내부 노드를 가리키며 음수 값은 0부터 256까지 기호 `-child - 1`을 인코딩합니다. 루트는 0이며 이전 노드 0개 형식에는 암묵적 EOF 자식이 있습니다. 전체 그래프는 순환, 공유 내부 자식, 도달할 수 없는 내부 노드 또는 범위 밖 간선이 없는 루트 트리여야 하며 EOF에 도달할 수 있어야 합니다. EOF까지 하위 비트부터 순회합니다. 압축 입력은 해당 종료자와 같은 바이트에서 끝나야 하며 사용하지 않은 마지막 비트는 무시합니다. 선언 크기까지 디코딩하는 것은 EOF 검사를 대체하지 않습니다.

<a name="xdzip-fixed-dictionaries"></a>

## 고정 사전

4096개 슬롯 사전은 처음에 전임자 `0xffff`로 바이트 문자열 0–255를 삽입합니다. 코드는 물리 해시 슬롯을 식별합니다. 이전 해시는 `((prefix + suffix) mod 65536) | 0x0800`의 제곱 중간 12비트를 사용합니다. 방식 7은 대신 16비트 합에 15073을 곱하고 하위 12비트를 취합니다. 이 상수는 이전 와이어 식별자를 정의합니다.

충돌은 기존 슬롯 체인을 따라가고 마지막 요소에서 101슬롯 뒤부터 탐색한 다음 순환하며 선형 검색합니다. 모든 탐색과 접두사 확장은 제한되고 계량됩니다. 새 문자열은 이전 문자열과 현재 문자열의 첫 바이트입니다. 아직 없는 코드는 정확히 새로 삽입된 KwKwK 슬롯에 대해서만 승인합니다. 가득 찬 사전은 성장을 멈춥니다. 12비트 코드는 바이트 사이에서 상위 니블이 먼저이며 이후 LSB 프로필과 다릅니다. 사용하지 않은 마지막 니블은 무시하며 누락된 코드 바이트나 추가 완전 바이트는 유효하지 않습니다.

<a name="xdzip-dynamic-dictionaries"></a>

## 동적 사전

첫 코드는 바이트여야 합니다. 코드 256은 CLEAR이며 257부터 순차 사전 추가가 시작됩니다. 너비는 사전 임계값에서 방식 최대값까지 증가합니다. 코드는 8개 그룹으로 묶으며 너비 변경이나 CLEAR는 이전 그룹을 끝내고 사용하지 않은 정렬 비트를 소비한 뒤 새 그룹을 시작합니다. 정렬 비트는 지정되지 않았습니다. CLEAR는 다음 사전 슬롯과 너비를 재설정하고 다음 리터럴을 요구하며 재설정 전 사전 문자열을 빌릴 수 없습니다. 합성 EOF 코드나 바이트를 제공하지 않습니다.

사전 성장, KwKwK, 최대 너비 동작과 적응형 재설정은 RLE 단계와 별도입니다. 강제 LZW 네이티브 참조 입력은 모든 너비와 실제 재설정을 입증합니다. 직접 작성한 CLEAR 입력은 이전 그룹의 여덟 위치 각각을 독립적으로 다룹니다.

<a name="xdzip-budgets-and-failures"></a>

## 예산과 실패

압축 길이와 디코딩 길이는 각각 엄격한 24 GiB, 작업은 96 GiB 상한입니다. 호출자의 더 작은 제한이 우선합니다. 전체 개인 메모리 승인은 방식 3에 16 KiB, 방식 4에 32 KiB, 방식 5–7에 64 KiB, 방식 8–9에 96 KiB입니다. 이 한도에는 8192바이트 입력 버퍼, 사전, 역방향 확장, 그래프 검증과 상태가 포함됩니다.

사전 초기화, 소비 비트, 트리 간선, 해시 탐색, 접두사 확장, 스택 전달과 출력/반복 작업을 계량합니다. `work_remaining()`은 컨테이너 소유 누적 장부를 위한 생성자 작업을 포함합니다. 협력적 폴링은 입력에 의존하는 작업과 그렇지 않은 작업 모두를 다룹니다. 출력 읽기는 최대 8192바이트입니다. 짧은 입력, 타입이 지정된 호스트 오류, 할당량 소진, 취소, 잘못된 코드/트리, 후행 데이터와 디코딩 크기 불일치는 인스턴스를 종료합니다. 첫 오류는 페이로드를 보존하며 이후 읽기는 재개할 수 없습니다. 완료된 리더는 추가 작업을 소비하지 않고 안정적인 EOF를 반환합니다.

ARC의 필수 페이로드 CRC-16과 완전한 물리 구조는 컨테이너에 속합니다. 원시 성공만으로 콘텐츠를 인증하거나 파일 시스템, 경로, 프로세스, 인접 파일 또는 게시 권한을 부여하지 않습니다.
