# 격리된 형식 워커 계약

[English](../../engineering/native-codecs.md) | [简体中文](../../zh-CN/engineering/native-codecs.md) | [繁體中文](../../zh-TW/engineering/native-codecs.md) | [日本語](../../ja-JP/engineering/native-codecs.md) | 한국어 | [Français](../../fr-FR/engineering/native-codecs.md) | [Deutsch](../../de-DE/engineering/native-codecs.md) | [Español](../../es-ES/engineering/native-codecs.md) | [Português (Brasil)](../../pt-BR/engineering/native-codecs.md) | [Русский](../../ru-RU/engineering/native-codecs.md)

7z, RAR, CAB, ISO/UDF 읽기는 격리된 워커의 공유 CXX 경계 뒤에서 [내장 Rust 코덱](../../engineering/independent-rust-codecs.md)을 사용합니다. 같은 워커가 호스트가 제어하는 작업에서 7z 쓰기도 처리합니다. Rust 호스트는 ZIP, TAR, 압축 스트림, DEB와 [새 ISO9660/Joliet 이미지](iso-creation.md)를 프로세스 내부에서 처리합니다. 형식 선택은 내장 경로를 사용하며 어떤 경로도 PATH에서 명령줄 디코더를 찾지 않습니다.

CAB는 제품에서 항상 독립 Rust 경로를 사용하며 테스트 스위치, 공식 처리기, 실패 폴백이 없습니다. 전체 프레임, 공유 알고리즘과 리소스 범위는 [자체 계약](../../engineering/independent-rust-codecs.md#cab-read-only-specification), 출처와 참조 분석 역할은 [CAB 소스](../../engineering/cab-format-sources.md)를 참조하세요.

호스트는 runtime 시작 전에 검증된 절대 워커 경로 하나를 등록할 수 있습니다. 같은 등록을 반복하면 성공하고 충돌하거나 상대적인 경로는 선택을 바꾸지 않고 거부합니다. 명시적인 개발자 워커 재정의가 우선이고 그다음 등록된 경로를 사용하며 아무것도 등록되지 않은 경우에만 실행 파일 옆 워커를 사용합니다. 데스크톱 CLI 번들은 이 등록으로 데스크톱 워커를 공유합니다. 독립 패키지는 로컬 워커를 유지하며 주변 디렉터리에서 다른 데스크톱 설치를 추론하지 않습니다.

<a name="xdzip-build-and-sources"></a>

## 빌드와 소스

통합 준비 진입점은 `scripts/prepare-native-codecs.py`를 실행합니다. [제품 소스 매니페스트](../../../scripts/native-codec-sources.json)는 현재 비어 있습니다. 준비 과정은 공식 형식 소스를 다운로드하거나 압축 해제하지 않으며 오프라인 빌드에도 UnRAR 또는 7-Zip 아카이브가 필요하지 않습니다. 일반 소스 도구는 명시적으로 선언된 자료에 대한 제한된 압축 해제와 다이제스트 검증을 유지하며 캐시된 콘텐츠가 제품에 자동으로 들어가지 않습니다.

제품은 공식 UnRAR/7-Zip 컨테이너, 알고리즘, 공통 유틸리티, 파일 어댑터, 형식 레지스트리를 컴파일하거나 링크하지 않습니다. 7z, RAR, CAB, ISO, UDF는 런타임 실패 폴백 없이 Rust를 사용합니다. 내부 CMake의 `XDZIP_7Z_BACKEND=rust`, `XDZIP_RAR_BACKEND=rust`, `XDZIP_CAB_BACKEND=rust`는 고정된 식별 정보를 기록합니다. 생성된 `native-codec-source-list.txt`는 프로젝트 소유 연결 파일 일곱 개를 빠짐없이 기록합니다. 검사는 경로와 집합을 확인하여 공식 소스나 제거된 `host_file.cpp`의 재도입을 거부합니다. `platform_time.cpp`와 `platform_encoding.cpp`는 OS 로컬 달력과 문자 집합 매핑만 Rust에 반환하며 압축 파일 시간 형식이나 암호 바이트 규칙을 해석하지 않습니다. 공유 Zstandard/FSE/Huffman/XXH64, LZ4/XXH32, Deflate/Deflate64, LZMA, BZip2, PPMd, LZX, Quantum은 실제 형식에 따라 재사용하여 형식 라이브러리를 중복하지 않습니다.

해당 소스 자료는 실제 배포 버전에 함께 제공하며 다운로드 링크만으로는 충분하지 않습니다. 과거 빌드와 독립적인 공식 참조 도구에는 각자의 원래 조건이 계속 적용됩니다. 현재 제품 소스 매니페스트가 비어 있어도 기존 제공물의 의무는 바뀌지 않습니다.

<a name="xdzip-authority-and-lifecycle"></a>

## 권한과 수명 주기

Rust 코어가 원본 승인, 분할 볼륨 식별, 대상 승인, 임시 준비와 커밋 권한을 보유합니다. Rust 7z/RAR/CAB/광학 백엔드는 별도 워커에서 실행하며 승인된 스트림을 읽고 현재 승인된 항목 데이터를 제한된 프로토콜로 출력합니다. 사용자 대상 경로나 임의 파일 접근 인터페이스는 받지 않습니다. CXX로 동기적으로 빌린 문자열과 슬라이스는 호출 중에만 유효하며 포인터를 보관하지 않습니다. C++ 예외와 Rust unwind는 안정적인 오류로 변환합니다. OOM/abort는 워커를 실패시키고 호스트는 불완전한 임시 출력을 버립니다.

호스트의 초기 원본 seek, 워커의 임의 읽기, 생성 입력과 EOF 프로브는 할당량, 취소, 미지원, 원본 변경의 타입 지정 오류를 일관되게 보존합니다. 바깥 I/O 종류가 Interrupted여도 타입 지정 원인을 지우지 않습니다. 타입 지정 원인이 없는 Interrupted만 취소를 확인한 후 재시도할 수 있으며 선지불한 원본 작업은 환불하지 않습니다. Scan은 SourceChanged를 유지하고 콘텐츠 읽기는 기존 원본 오류 의미를 사용하며 생성은 원본 오류 시 커밋을 거부합니다.

워커는 명령줄 암호를 받지 않고 압축 파일이 제공한 임의 진단을 출력하지 않으며 애플리케이션 자격 증명이나 프록시 환경을 상속하지 않습니다. 오류는 안정적인 코드로 매핑됩니다. 암호화된 디렉터리를 열 암호는 현재 세션과 관련 작업의 0으로 지우는 컨테이너에만 남고 실행 간에 저장하지 않습니다. 세션 종료와 작업 종료 상태는 각각의 컨테이너를 해제합니다. 취소하면 읽기와 출력을 중지하며 시간 초과 시 워커를 종료하고 회수합니다. 워커 실패는 성공을 만들 수 없습니다. 프로세스 격리는 OS 샌드박스가 아니며 침해된 프로세스가 같은 사용자의 모든 리소스에 접근하는 것을 막는다고 주장하지 않습니다.

워커의 UTF-8/와이드 문자 변환은 Unicode 스칼라 값을 엄격히 검증합니다. Windows는 UTF-16 서로게이트 쌍을 사용하고 macOS와 Linux는 32비트 와이드 문자를 사용합니다. 잘못된 UTF-8, 고립된 서로게이트, 범위 밖 스칼라는 `std::range_error`를 발생시키며 워커 경계에서 성공 종료 상태 없는 프로토콜 오류 2로 변환합니다. 변환은 포함된 NUL을 유지하며 안전하지 않은 이름 거부는 호스트 이름/경로 안전 검사의 책임입니다.

7z 생성은 EncodeOutput::write_at으로 제한된 오프셋과 블록을 호스트의 비공개 임시 영역에 씁니다. 네이티브 프로세스는 스트림 위치만 유지하며 출력 압축 파일 전체를 메모리에 쌓지 않습니다. 호스트는 실제 쓴 바이트와 압축 파일 길이의 최고 수위를 별도로 계량합니다. 헤더 재작성은 분할 볼륨 콘텐츠 길이를 늘리지 않습니다. 호스트 측 검사는 오프셋, 블록 크기, 누적 출력과 취소를 재검증합니다. 임의 쓰기 기능이 없는 출력은 명시적으로 거부합니다.

작업은 호스트의 항목, 경로, 메타데이터와 실제 바이트 예산을 유지하며 기본 네이티브 예산은 1 GiB입니다. Windows는 Job Object 커밋 메모리 제한, Linux는 절대 가상 주소 공간 제한, macOS는 시작 가상 주소 기준에 예산을 더하고 dyld 예약을 제외한 값을 사용합니다. Unix 주소 공간 제한은 RSS 계량이 아닙니다. 사전과 솔리드 작업 영역은 할당 전에 허용 여부를 확인하며 예산에 맞지 않는 작업은 무제한 디스크 임시 저장으로 조용히 전환하지 않고 명시적으로 실패합니다. 재시도와 솔리드 건너뛰기는 실제 작업을 누적합니다.

RAR 현대 유효 알고리즘 1은 [제한된 정확한 페이지 기록](../../engineering/rar-format-sources.md#exact-storage-for-large-logical-dictionaries)으로 큰 논리 사전을 표현할 수 있습니다. 논리적 선언은 할당 권한이 아닙니다. 디렉터리, 보유 페이지, 임시 피크에는 각각 제한이 있으며 원래 워커 예산과 동적 실패 동작은 유지됩니다.

실제 알고리즘 초기화/제어 보조 작업은 별도의 `AUX_WORK=24`를 사용하며 현재 RAR 페이로드에만 적용됩니다. 호스트와 runtime은 보조 예산을 독립적으로 누적하고 파일 디코딩, 확장 비율, 공개 진행률, 선불 크레딧에 포함하지 않습니다. 프로토콜, 재시도 수명 주기, 필요한 수용 조건은 [보조 디코딩 작업 계량](auxiliary-decoding-work.md)을 참조하세요.

<a name="xdzip-capability-boundaries"></a>

## 기능 범위

7z 탐색, 추출, 무결성 검사, 생성은 별도로 선언합니다. 생성은 기본적으로 LZMA2, 일반 수준, 비솔리드, 암호화 없음, 분할 없음입니다. 솔리드, 콘텐츠 암호화, 파일 이름 암호화, 번호가 있는 볼륨은 독립 기능으로 검증합니다. 파일 이름 암호화에는 암호가 필요합니다. 암호화된 파일 이름은 메타데이터를 열 때 암호를 요청하며 불완전한 스캔은 부분 인덱스를 게시할 수 없습니다.

암호화되지 않고 분할되지 않았으며 모든 항목을 안전하게 유지할 수 있는 7z 압축 파일은 추가, 교체, 내부 이동을 재사용할 수 있습니다. 솔리드 콘텐츠는 제한된 재구성을 사용합니다. 암호화, 분할, 링크, 지원하지 않는 특수 레코드는 계속 수정할 수 없습니다. 원본 재확인과 완전한 검증 뒤에 같은 볼륨에서 원자적으로 교체합니다. 독립 삭제와 이름 변경 진입점은 이 확장 범위 밖입니다.

RAR는 항상 `xdzip-codec-rar`를 사용하며 공식 폴백 없는 읽기 전용입니다. 구형, RAR5, RAR 7 확장, 암호, 헤더 암호화, 솔리드 압축 파일과 분할 볼륨을 별도로 검증하며 알고리즘과 호환성 제한은 [자체 명세](../../engineering/independent-rust-codecs.md#rar-read-only-specification)를 따릅니다. 생성, 수정, 복구, 암호 복원은 제공하지 않습니다. RAR 초기화/제어 작업은 보조 채널을 사용하고 실제 디코딩 출력은 WORK와 선불 전달을 사용하며 모델 초기화를 파일 크기나 확장 비율에 포함하지 않습니다.

CAB는 Store, MSZip, Quantum, LZX를 지원하며 단일 볼륨과 같은 디렉터리의 분할 볼륨은 읽기 전용입니다. Rust는 헤더 관계에 따라 승인된 볼륨 집합을 검증하고 고정한 뒤 원래 볼륨 이름과 경계를 워커로 보냅니다. 볼륨이 없거나 일치하지 않으면 부분 인덱스를 게시할 수 없습니다. [분할 볼륨 계약](archive-opening.md)을 참조하세요. CAB 원시 이름과 UTF-8 선언을 보존하며 구형 이름은 [공유 파일 이름 해석](filename-encoding.md)을 사용하고 호스트 코드 페이지로 출력 경로를 추측하지 않습니다.

`xdzip-codec-optical`은 공식 Iso/Udf 처리기를 링크하지 않고 ISO9660, Joliet, Rock Ridge, UDF를 파싱합니다. 하이브리드 이미지는 UDF 네임스페이스를 우선하며 인식된 UDF 손상 시 ISO로 조용히 폴백하지 않습니다. 승인에는 확장자 대신 콘텐츠를 탐지합니다. ISO/UDF 판독기는 마운트나 부팅 이미지 실행 없이 탐색, 추출, 임시 열기, 내보내기와 검사를 지원합니다. 프로세스 내부 [ISO9660/Joliet 기록기](iso-creation.md)는 일반 데이터 이미지를 생성하며 UDF 생성과 업데이트는 지원하지 않습니다. 부팅 이미지 레코드는 읽을 수 있는 파일일 뿐이며 링크와 특수 객체는 출력할 수 없습니다. 이미지 검사는 구조, 범위와 실제 읽기 가능성을 검증하며 일반 파일에 콘텐츠 체크섬을 보장한다고 주장하지 않습니다. 파티션 맵과 지원하지 않는 확장의 명시적 범위는 [자체 명세](../../engineering/independent-rust-codecs.md#iso-and-udf-read-only-specification)를 참조하세요.

<a name="xdzip-verification-and-delivery"></a>

## 검증과 제공

실제 지원 주장은 공식 도구 상호 운용성, 알려진 출력 바이트, 손상과 리소스 제한 샘플을 필요로 합니다. 매직 탐지, 성공한 호출 또는 한 백엔드만으로 직접 읽고 쓰는 것은 상호 운용성을 독립적으로 입증하지 못합니다. 세 플랫폼의 코어/Qt 검사, 배포 검증, 네이티브 시각 검사와 데스크톱 끌어다 놓기는 별도로 기록하며 단계별 증거는 issue와 로컬 또는 CI 산출물에 보관합니다.

CTest `native_unicode_conversion`은 워커 변환 구현을 직접 컴파일하고 UTF-8 길이 경계, 비 BMP, 포함된 NUL, 잘못된 시퀀스와 플랫폼 와이드 문자 경계를 다룹니다. `native_unicode_protocol`은 실제 워커에 잘못된 생성 이름을 보내 오류 응답과 실패 종료를 확인합니다. Windows, macOS, Linux에서 실행해야 하며 한 플랫폼이 두 와이드 문자 폭의 검증을 대신할 수 없습니다.

RAR 경로 수용은 실제 워커를 통한 스캔, 검사와 안전한 추출을 다루며 작은 파일, PPM 초기화, 암호, 승인된 볼륨을 포함합니다. 작은 파일과 PPM 초기화만으로 높은 확장 비율 거부가 발생해서는 안 되며 보조 작업은 공개 바이트 수를 늘려서는 안 됩니다. 실패 시 파일을 게시해서는 안 됩니다. 소스 검사는 빈 제품 매니페스트, 고정된 Rust 식별 정보, 전체 컴파일 소스 목록과 얇은 RAR 진입점을 함께 확인합니다. 심볼이나 성공 출력만으로 공식 코드가 제외되었음을 증명할 수 없습니다.

Foundation은 `scripts/check-rar-rust-interop.py --worker <built-worker> --output build/<evidence>`로 원래의 전체 명시적 `native_backend_tests` 배치를 실행합니다. 진입점은 먼저 `scripts/rar-rust-fixtures.json`에 URL, 크기와 SHA-256이 고정된 공개 소형 PPM, 대형 PPM, 구형 암호 샘플을 준비한 다음 원래 압축 스트림만 포함하는 단일 멤버 부분 집합, 프로젝트 소유의 수학적 크기 미상 및 알려진 빈 헤더, 프로젝트 소유 20/26 테스트 자료에 필요한 환경을 생성합니다. 각 네트워크 응답은 최대 512 KiB입니다. 준비된 파일과 증거는 build에 남고 2 GiB 평문을 생성하거나 작성자 도구를 실행하지 않습니다. 입력 누락이나 불일치는 실패해야 하며 건너뛴 테스트가 환경 준비를 대신할 수 없습니다. 래퍼는 악의적인 보조 작업 워커, 크기 미상 프로토콜 검사, 네이티브 소형 파일 계량, 솔리드 재읽기, 프로젝트 소유 E8E9 전체 바이트 다이제스트와 실제 OS 문자 매핑 프로브도 실행해야 합니다. 프로브는 현재 워커 옆 고정 Rust 출력 디렉터리의 CXX 헤더와 엄격히 유일한 Release 정적 라이브러리만 사용하고 헤더, 정적 라이브러리, 프로브 다이제스트를 기록합니다. 입력 누락이나 모호함은 실패합니다. 별도 구성 요소 검사는 대형 버전 26의 전체 SHA를 검증하고 runtime 배치는 실제 워커를 통해 대형 파일 전체 수, CRC와 임시 출력 0을 한 번 검사합니다. 명시적인 `--large-digest`는 워커의 전체 SHA 검사를 추가합니다.

상호 운용성은 제품 워커와 별개로 고정된 공식 26.05 참조 도구를 사용합니다. Windows에서는 같은 공식 릴리스의 7zr.exe를 다운로드하고 다이제스트를 확인한 뒤 검증된 7z2605-extra.7z에서 x64/7za.exe만 추출하고 해당 멤버의 독립 SHA-256을 다시 검증합니다. 시스템 tar의 LZMA 지원에 의존하지 않고 설치 프로그램을 실행하거나 고정되지 않은 PATH 도구를 빌려 쓰지 않습니다. Linux와 macOS는 검증된 tar.xz에서 지정된 7zz 멤버만 읽습니다. 다운로드, 캐시 또는 추출 결과의 다이제스트가 다르면 중지합니다. 이 참조 도구는 build/ 테스트 디렉터리에만 남고 제품 배포에 들어가지 않습니다.

개발 패키지는 계속 실험적입니다. 구성 요소 라이선스, 해당 소스와 재링크 요구 사항은 실제 빌드별로 별도 검토하며 이 기능의 완료가 정식 릴리스를 자동 승인하지 않습니다.

[runtime 워커 검증 진입점](../../../developers/qa/runtime-worker-tests.md)은 선언된 전체 통합 목록과 고정 입력을 자동으로 준비합니다. 준비되지 않은 `native_backend_tests --ignored` 배치를 직접 호출하는 대신 이를 사용하세요. 선택적인 전체 라이브러리 모드는 무시된 결과가 없어야 합니다.
