# 제품 런타임과 Qt 수명 주기

[English](../../engineering/product-runtime.md) | [简体中文](../../zh-CN/engineering/product-runtime.md) | [繁體中文](../../zh-TW/engineering/product-runtime.md) | [日本語](../../ja-JP/engineering/product-runtime.md) | 한국어 | [Français](../../fr-FR/engineering/product-runtime.md) | [Deutsch](../../de-DE/engineering/product-runtime.md) | [Español](../../es-ES/engineering/product-runtime.md) | [Português (Brasil)](../../pt-BR/engineering/product-runtime.md) | [Русский](../../ru-RU/engineering/product-runtime.md)

이 문서는 데스크톱 앱이 명령과 이벤트로 Rust 런타임에 연결되는 방식과 큐 역압, 종료 및 플랫폼별 빌드를 설명합니다. 각 기능의 범위는 [읽기 전용 탐색](readonly-browser.md)과 [안전한 추출](zip-safe-extraction.md)을 참고하세요.

<a name="xdzip-implemented-services"></a>

## 구현된 서비스

`xdzip-runtime::service`가 제품 서비스를 구현합니다. GUI는 `CommandClient`를 한 번만 가져오고 전용 Qt 수신 스레드는 `EventReceiver`를 한 번만 가져옵니다. Rust 명령 스레드는 연결에서 열린 압축 파일과 탐색 스냅샷을 소유합니다. 별도의 Rust 작업 스레드는 필요한 원본과 설정을 갖춘 준비된 작업을 받아 작업 업데이트를 게시합니다. 압축 파일 핸들과 동기식 스캔 진입점은 Rust에 남습니다. ABI는 [Qt/Rust 브리지](../design/qt-rust-bridge.md), 소유권과 승인은 [작업 스케줄링](../design/task-scheduling.md)을 참고하세요.

핵심 명령에는 Open, Browse, Preflight, CloseSession, Snapshot이 있으며 기존 실제 탐색과 사전 검사는 모두 이를 사용합니다. 승인된 일반 요청에는 재사용하지 않는 ID가 부여되고, 제한된 데이터 이벤트를 최대 하나 반환한 뒤 Finished를 정확히 하나 반환합니다. 오류는 Finished를 바로 반환합니다. 페이지에는 세션, 요청, 오프셋 식별 정보가 담깁니다. 각 RuntimeConnection에는 세션 하나와 순차적인 GUI 대기 요청이 있습니다. 쿼리에는 전체 쿼리 ID, GUI 세대와 스냅샷 리비전도 포함됩니다. [ZIP 탐색 계약](zip-readonly-browsing.md)을 참고하세요. 세션을 넘나드는 요청은 stale_session을 반환합니다.

GUI의 일반 승인은 큐 공간을 기다리지 않고 try_lock을 사용하며 경로 4 KiB, 검색 1 KiB, 선택 항목 128개, 디렉터리 ID 21바이트, 정렬 코드 0–12를 검증합니다. 거부되면 ID를 소비하지 않으며 Busy는 재시도할 수 있습니다. 취소에는 최대 128개 항목의 별도 제어 채널과 자체 Finished 확인 응답이 있습니다. 확인 응답은 대상이 이미 끝나지 않았음을 보장하지 않습니다. 종료는 독립적이고 멱등적인 RequestId를 유지하며 마지막 사용 가능 ID를 예약하므로 일반 ID가 소진되거나 큐가 가득 차도 작동합니다.

Qt 컨트롤러는 승인 대기 명령을 하나만 보유합니다. 일시적인 Busy는 이벤트 루프의 단발 1 ms 타이머로 최대 32회 재시도하며 지속적인 포화 상태에서만 재시도를 요청합니다. 이는 완료 기한이 아닙니다. 취소, 종료 또는 연결 해제 시 승인되지 않은 명령을 즉시 철회하고 유휴 상태에서는 재시도 타이머를 실행하지 않습니다. 잘못된 인자와 ID 소진은 busy로 위장하지 않고 별도로 보고합니다. 연결 해제 후 Open은 비활성화됩니다.

## 제한된 전송

- 미완료 일반 요청은 최대 128개이며 수신자가 Finished를 꺼낼 때만 용량이 해제됩니다. 요청마다 이벤트 슬롯 두 개를 예약해 데이터가 종료 상태를 밀어내지 못하게 합니다.
- Rust 데이터 이벤트는 이미지 최대 16 MiB와 그 컨테이너를 포함해 누적 콘텐츠 예산 32 MiB를 사용합니다. 예산 초과 시 게시가 대기하며 취소나 종료가 대기를 깨워 취소된 종료 상태를 대신 낼 수 있습니다. 단일 이벤트가 너무 크면 resource_limit을 반환합니다.
- Rust 명령의 누적 콘텐츠 한도는 8 MiB로 유지되며 초과분은 승인 시 거부됩니다. 이미지 이벤트의 더 큰 예산은 이 한도에 영향을 주지 않습니다.
- Qt 메일박스는 최대 256개 이벤트와 32 MiB 콘텐츠를 보유합니다. 일반 데이터는 최대 128개 슬롯이고 나머지는 종료 및 제어 이벤트용입니다. Rust 이벤트마다 Qt 콜백을 만들지 않습니다.
- 하나의 알림 체인은 한 차례에 최대 32개 이벤트 또는 약 4 ms 동안 처리하고 남으면 다음 차례를 게시합니다. 단일 이벤트 처리는 선점할 수 없습니다. 빈 큐는 예약을 멈추고 수신자는 조건 변수에서 대기합니다.
- Open의 Page에는 전체 제한된 디렉터리 인덱스도 포함됩니다. 최대 32,768개 노드와 이름/접두사 합계 4 MiB이며 `replace_directories`로 교체를 표시합니다. 빈 인덱스도 명시적으로 교체합니다. Browse는 인덱스를 다시 보내지 않으며 `navigation_limited`는 축소된 인덱싱을 명시합니다. Rust는 이름과 접두사의 바이트를 계산하고 Qt 메일박스는 브리지가 생성한 노드 및 부모 ID 문자열도 계산합니다. 노드 컨테이너와 깊이는 별도 제한이 있습니다. 해당 요청의 Finished가 성공한 후 새 페이지와 디렉터리 모델을 함께 적용합니다.
- Page의 `total`은 현재 목록 행 수이고 `archive_total`은 압축 파일의 물리 레코드 수를 별도로 보유합니다. 일반 탐색은 현재 디렉터리의 직접 파일과 디렉터리를 나열하고 검색은 물리적 일치를 재귀적으로 반환합니다. 명시적 레코드가 없는 디렉터리는 `navigation_id`와 `physical=false`를 사용합니다. Qt 행 키는 `dN`이고 원래 물리 ID는 별도로 유지되며 가상 노드는 Preflight를 제출할 수 없습니다. 전체 경로는 행 메타데이터에 남고 일반 탐색에는 마지막 이름, 검색에는 전체 경로를 표시합니다.
- 문자열 예산은 RSS가 아닙니다. 컨테이너, 스냅샷 및 변환 중인 이벤트 하나에 추가 공간이 필요하지만 항목과 페이지는 제한됩니다. 브리지 배치에는 최대 128개 항목이 포함됩니다. 원래 100,000개 항목 스캔 기준은 [ZIP 탐색 계약](zip-readonly-browsing.md), 이후 일반 단일 파일 ZIP 확장은 [대용량 압축 파일 인덱싱](large-index.md)을 참고하세요.

제어 이벤트와 일반 이벤트를 번갈아 가져와 지속적인 취소 확인 응답이 일반 종료 상태를 굶주리게 하지 않습니다. 전달할 때 증가하는 시퀀스 번호를 부여합니다. Qt는 오래된 시퀀스를 버리며 제어 확인 응답과 오래된 request_id는 현재 화면을 변경하지 않습니다.

독립 작업 채널의 `Task`/`TaskUpdate` 봉투는 원래 작업 생성 request_id를 유지합니다. 상관관계 기록은 제한된 작업 제어 슬롯에 보관되고 작업 종료 상태가 전달될 때 해제됩니다. 수락 데이터보다 먼저 오거나 요청 Finished 뒤에 올 수 있습니다. 두 번째 일반 데이터 슬롯을 소비하지 않고 일반 요청을 다시 해제하거나 완료하지 않으며 준비 자리표시자를 실제 TaskId와 원본 세션에 정확히 연결합니다. 이 ID는 취소 요청 ID가 아니며 작업 제어는 계속 TaskId를 사용합니다.

## 종료, 소멸 및 실패

개별 압축 파일을 닫거나 창을 닫아도 앱과 작업이 트레이에서 계속 실행될 수 있습니다. 앱을 종료하거나 재시작할 때 조정자는 승인을 중단하고 취소를 요청하며 Rust가 세션을 해제하는 동안 이벤트를 비웁니다. 수신자는 Rust 스레드 둘의 종료를 기다린 뒤 `ShutdownReady`를 반환합니다. 데스크톱은 Qt 수신자가 끝나고 메일박스가 비워진 뒤 종료합니다. GUI 스레드는 파일 작업이나 이벤트 전달을 기다리는 스레드의 종료를 기다리지 않습니다.

취소와 종료 제어는 데이터 큐 용량과 무관하게 제한된 상태 연산을 포함한 짧은 임계 구역을 사용합니다. 협력적 취소는 운영체제가 막고 있는 읽기를 중단하지 못하므로 엄격한 실시간 종료를 보장하지 않습니다. 여기의 읽기 전용 요청은 출력 트랜잭션을 만들지 않습니다. 생성/추출 확정, 임시 영역 정리와 종료 결과는 [생성](zip-creation.md) 및 [안전한 추출](zip-safe-extraction.md) 계약을 각각 따릅니다.

QObject가 일찍 소멸하면 메일박스를 닫고 수신자를 깨우며 서비스를 중단합니다. 백그라운드 작업은 공유 큐와 Rust 수신자 핸들만 보유하고 컨트롤러 포인터는 보유하지 않습니다. Qt는 소멸된 객체의 알림을 자동으로 취소합니다. 이벤트 소비 콜백이 연결을 동기적으로 소멸시킬 때도 QPointer가 수명을 보호합니다. 수신을 포기할 때 소멸자에서 스레드를 기다리지 않으며 작업은 협력적으로 끝납니다. 정상 ShutdownReady만 스레드 대기 완료를 입증합니다.

읽기 전용 작업자 핸들러에서 스택 해제가 가능한 panic이 발생하면 경계에서 이를 잡고 전체 서비스를 버리고 RuntimeFault를 보내며 미완료 요청을 runtime_unavailable로 끝냅니다. 세션은 재사용하지 않습니다. 이는 읽기 전용 실패만 정의하며 절반만 완료된 생성/추출 트랜잭션의 복구를 약속하지 않습니다. 확정된 항목, 불확실한 결과와 쓰기 정리는 각 계약을 따릅니다. 복구 불가능한 할당 실패, 프로세스 중단 또는 오염된 내부 잠금은 종료 이벤트 전달을 보장하지 않습니다. 예기치 않은 EOF나 연결 실패 시 Qt는 대기 상태를 일괄 종료해 영구적인 사용 중 상태를 방지합니다.

<a name="xdzip-verification-and-build"></a>

## 검증과 빌드

[일반 검증](../../../developers/qa/README.md)을 참고하세요. Rust 핵심 테스트에는 Qt가 필요하지 않으며 Qt 창, 모델, 스트레스 및 종료 사례는 세 플랫폼에서 네이티브로 빌드하고 실행합니다. macOS CI는 앱을 배포하거나 업로드하지 않고 arm64와 SDK 환경의 Cocoa 시작을 검증합니다. 명시적 요청 시 로컬 개발 DMG를 만들 수 있습니다. Windows/Linux는 포함된 Qt를 배포하고 SDK 없는 실행을 검증합니다. [빌드 안내](../../engineering/developer-build.md)를 참고하세요. 이 검사는 정식 출시 승인이 아닙니다.

초기 쿼리는 불변 결과 식별 정보를 할당하며 이후 배치는 모든 QueryKey 필드와 매개변수에 일치해야 합니다. Qt는 이전 요청을 취소하고 최신 의도를 합치면서 시퀀스와 요청 ID 검사를 유지합니다. 배치는 이름도 64 KiB로 제한하고 다시 필터링하거나 정렬하지 않습니다. 과거 검수는 당시 사용 가능한 기능에만 한정됩니다.

애플리케이션 계층은 여러 독립 연결을 만들 수 있으며 도메인 런타임은 연결별로 세션을 격리합니다. 전역 작업 식별과 무거운 작업의 순차 승인은 [애플리케이션 세션 계약](application-sessions.md)을 참고하세요.
