# ARJ 압축 스트림과 컨테이너 승인

[English](../../engineering/arj-streams.md) | [简体中文](../../zh-CN/engineering/arj-streams.md) | [繁體中文](../../zh-TW/engineering/arj-streams.md) | [日本語](../../ja-JP/engineering/arj-streams.md) | 한국어 | [Français](../../fr-FR/engineering/arj-streams.md) | [Deutsch](../../de-DE/engineering/arj-streams.md) | [Español](../../es-ES/engineering/arj-streams.md) | [Português (Brasil)](../../pt-BR/engineering/arj-streams.md) | [Русский](../../ru-RU/engineering/arj-streams.md)

`ArjReader`는 ARJ 방식 1–4의 제한된 원시 디코딩을 제공합니다. Store는 이 리더가 아니라 컨테이너에 속합니다. `xdzip-codec-arj`는 호스트 소유 원본에서 완전한 물리 구조와 CRC 검증된 멤버 전달을 제공합니다. `ArjCodec`은 승인된 프로필을 런타임, CLI와 데스크톱 탐색, 검사 및 추출에 연결합니다. [형식 레지스트리](../../../specs/engineering/archive-formats.json)는 읽기 전용 경계를 선언하며 생성, 재작성, 암호와 볼륨은 사용할 수 없습니다.

<a name="xdzip-host-admission-and-names"></a>

## 호스트 승인과 이름

열두 바이트 주 헤더 후보는 형식이나 행을 게시하지 않습니다. 런타임은 먼저 검증된 강한 컨테이너와 ZIP/SFX의 우선순위를 유지하고 공유 약한 탐색 입력 장부 아래 제안된 ARJ 메타데이터를 완전히 스캔합니다. 검증되지 않은 원시 TAR 표식은 완전한 ARJ 승인으로 모호성을 해소합니다. 유효하지 않은 추측은 아무것도 게시하지 않으며 타입이 지정된 호스트 오류, 취소와 할당량이 계속 우선합니다.

어댑터는 물리 멤버 순번, 원래 방식 바이트와 원시 이름을 보존합니다. ANSI 플래그가 있는 이름과 OEM 이름은 별도의 인코딩 그룹으로 완전한 필드 샘플링 제한 1 MiB를 공유하며 주변 로캘로 선택하지 않습니다. 구분자를 해석하기 전에 멀티바이트 이름 전체를 디코딩합니다. 이식 경로 플래그가 없는 DOS 유사 호스트만 역슬래시를 슬래시로 바꿉니다. 이식 또는 Unix의 문자 그대로의 역슬래시는 의심 상태로 남습니다. 명시적 디렉터리는 끝 슬래시를 얻으며 의심스럽거나 미해결된 이름, 알 수 없는 방식과 미지원 객체 프로필은 페이로드 권한 없이 표시됩니다. 디코딩된 이름은 최대 4,096바이트, 보유한 표시/디코딩 할당은 16 MiB 또는 호출자의 더 작은 제한입니다. 속성은 복원하지 않습니다.

페이로드를 열 때 전달 전에 고정된 전체 항목 집합을 다시 투영하고 비교합니다. 선택된 각 레코드는 물리 행과 정확히 일치해야 하며 미지원 선택과 모든 디코딩 실패는 페이로드 인스턴스를 무효화합니다. 호스트 식별 검사, 사전 검사, 개인 준비 영역, 취소와 최종 게시는 공통 런타임 의미를 유지합니다. `supported_content` 검사는 승인된 모든 일반 멤버를 완전히 디코딩하고 정확한 크기와 필수 CRC-32를 검증합니다. 미지원 행은 전체 성공을 막습니다. 이전 텍스트는 호스트 줄바꿈 변환 없이 CRC가 적용된 압축 파일 바이트로 전달합니다.

## 소스와 참조 경계

[오픈 소스 ARJ 프로젝트](https://arj.sourceforge.net/)는 [소스 3.10.22](https://arj.sourceforge.net/files/arj-3.10.22.tar.gz), SHA-256 `589e4c9bccc8669e7b6d8d6fcd64e01f6a2c21fe10aad56a83304ecc3b96a7db`와 [Win32 3.10 패키지](https://arj.sourceforge.net/files/arjw_310.exe), SHA-256 `e5cc5d8f82c5f08246e1c0a8c5be77e5f796c2dd30f987e6bbb27a2c1df1e371`을 제공합니다. 소스에는 GNU GPL 버전 2 문서가 포함됩니다. 제한된 와이어 형식 관찰에 `defines.h`, `decode.c`, `arj_arcv.c`를 사용하며 네이티브 참조는 원래 조건과 변경되지 않은 상태로 build/toolchain에만 둡니다.

독립 비교는 공식 [7-Zip](https://www.7-zip.org/)과 그 [ARJ 핸들러](https://github.com/ip7z/7zip/blob/main/CPP/7zip/Archive/ArjHandler.cpp), Git blob `da890f279d35c00bc61d332ce55f4d96ecd6d373`의 제한된 소스 관찰을 사용합니다. 엄격한 클린룸을 주장하지 않습니다. Rust 구현은 프로젝트 소유 비트, 접두사와 LZ 기본 요소를 재사용하고 빠른 단항 필드를 직접 표현합니다. 참조 소스, 바이너리와 압축 엔진은 제품 의존성에 들어가지 않습니다. 정확한 구성 요소와 자체 입력 식별 정보는 [픽스처](../../../tests/fixtures/arj/README.md)에 기록합니다.

<a name="xdzip-static-methods-13"></a>

## 정적 방식 1–3

방식 1–3은 정적 Huffman/LZ 와이어 모델을 공유하지만 네이티브 인코더는 서로 다른 검색을 선택할 수 있습니다. 16비트 블록 명령 수, 19기호 길이 알파벳, 510기호 리터럴/길이 알파벳, 17기호 위치 알파벳과 5비트 위치 수는 명시적 ARJ 프로필로 공유 제한 LZH 접두사 구현을 재사용합니다. LH3의 이전 트리 필드나 공개 LHA 방식 식별자를 얻지 않습니다. 블록 명령 수 0은 승인하지 않습니다.

리터럴 기호는 0–255이며 나머지는 `symbol - 253`으로 3–256 길이를 얻습니다. 위치 기호 0은 오프셋 0이며 그렇지 않으면 `2^(symbol - 1)`에 같은 수의 하위 비트를 더합니다. 실제 거리는 오프셋에 1을 더하며 최대 26624이고 이미 출력한 바이트를 참조해야 합니다. 32 KiB 링은 제한된 논리 이력을 구현하며 더 큰 할당이 승인 범위를 넓히지 않습니다. LHA의 초기 공백은 별도로 남아 ARJ 출력을 초기화할 수 없습니다. 사전 순환과 겹치는 복사는 바이트 단위 순차 의미를 유지합니다. 완전한 정규 트리, 단일 기호 필드, 0 연속 구간과 16비트 코드 깊이는 공유 접두사 검증과 작업량 계량을 유지합니다.

<a name="xdzip-fast-method-4"></a>

## 빠른 방식 4

스트림은 최상위 비트부터 사용합니다. 길이 필드는 앞의 1비트를 0–7개 세며 최대가 아니면 0에서 멈춥니다. 같은 수의 하위 비트를 읽고 `2^count - 1`을 더합니다. 0은 8비트 리터럴, 0이 아닌 값은 값에 2를 더한 3–256바이트 복사를 뜻합니다. 포인터도 앞의 1비트를 0–4개 세며 하위 너비는 `9 + count`, 기준은 `512 * (2^count - 1)`입니다. 오프셋에 1을 더한 최대 거리는 15872입니다. 모든 참조는 이미 출력된 이력을 가리켜야 하며 16 KiB 링에서 겹침과 순환을 처리합니다. 초기 이력 복구는 허용하지 않습니다.

<a name="xdzip-limits-and-failures"></a>

## 제한과 실패

정적 프로필은 이력 32 KiB와 입력/테이블/임시 공간 64 KiB를 허용합니다. 빠른 디코딩은 이력 16 KiB와 입력/상태/임시 공간 32 KiB를 허용합니다. 압축 및 디코딩 크기는 각각 엄격한 24 GiB, 작업은 96 GiB 상한이며 호출자의 더 작은 예산이 우선합니다. 출력 읽기는 최대 8192바이트입니다. 접두사 연산, 이력 작업과 원본에 의존하지 않는 복사는 협력적 폴링을 유지합니다. `work_remaining()`은 컨테이너의 누적 실제 작업 장부를 지원합니다.

선언된 길이를 초과할 수 없습니다. 논리 압축 바이트는 정확히 끝나야 하며 마지막 1바이트 미만 채우기는 무시하고 완전한 추가 바이트나 누락 입력은 실패하며 EOF 0바이트를 만들어 내지 않습니다. 추가 정보가 없는 `Interrupted`만 재시도합니다. 타입이 지정된 오류는 최초 페이로드를 유지하고 종료하며 원본, 잘못된 데이터, 할당량 또는 취소 오류는 리더를 무효화합니다. 원시 리더에는 경로, 자격 증명, 실행, 파일 시스템 게시 또는 CRC 권한이 없습니다.

<a name="xdzip-bounded-physical-containers"></a>

## 제한된 물리 컨테이너

`inspect`는 오프셋 0 압축 파일, 첫 주 헤더 너비 30/34, 파일 너비 30/34/46, 최대 2600바이트의 완전한 기본 블록을 검증합니다. 이름과 주석은 정확히 끝나야 하고 파일 이름 위치 필드는 잘라낼 권한을 주지 않으며 모든 기본/확장 CRC-32가 통과해야 합니다. 각 레코드는 16비트 길이의 확장 블록을 최대 256개 허용합니다. 불투명 파일 속성은 검증해 메타데이터 식별 정보에 포함하지만 적용하거나 실행하지 않습니다. 정확한 `60 ea 00 00` 종료자가 물리 원본의 끝이어야 하며 SFX 접두사, 채우기 또는 복구 꼬리를 추론하지 않습니다.

메타데이터 읽기는 64 MiB, 물리 항목은 100000개, 원시 이름은 각각 4096바이트 및 합계 16 MiB로 제한하고 호출자의 더 작은 제한도 유지합니다. 이후 실패 시 부분 인덱스를 게시하지 않습니다. SHA-256은 무시된 주석/수정자/속성을 포함해 전체 물리 메타데이터와 종료자를 다루며 `Reader::open`은 출력 전에 이를 다시 스캔하고 모든 레코드 및 물리 길이와 비교합니다. 원본 오류는 종료 상태로 남고 잘못된 데이터 추측으로 바꾸지 않습니다. Unix 호스트 타임스탬프는 선택적 호스트 달력만 사용하며 투영이 없으면 0, 콜백 오류는 종료합니다.

멤버 프로필은 필요 버전 11까지, DOS/Unix/OS2/Win95/WinNT 호스트, 암호화되지 않은 바이너리/이전 텍스트 방식 0–4와 빈 Store 디렉터리를 허용합니다. 미지원 방식, 미래 버전, 특수 유형, Unix 특수 모드와 암호화/연속/장 필드는 명시적으로 남고 디코딩할 수 없습니다. 주 볼륨/보호/보안/이중 이름/암호화/장 프로필과 이중 이름 파일 레이아웃은 승인하지 않습니다. 접근 모드와 속성은 권한이나 특수 파일 생성을 허가하지 않습니다. 이전 텍스트는 7-Zip과 같이 압축 파일 크기와 CRC가 적용된 바이트로 전달합니다. 네이티브 Win32 ARJ는 텍스트 프로필에서 LF를 CRLF로 확장하지만 호스트 의존 줄바꿈 변환은 수행하지 않습니다.

리더 하나는 새 메타데이터 스캔을 포함한 누적 실제 입력 24 GiB, 디코딩 출력 24 GiB, 작업 96 GiB를 유지합니다. 남은 작업을 상태 저장 디코더에 빌려주기 전에 선언된 출력의 CRC 비트 단계 작업을 예약합니다. 성공 멤버는 그 예약과 실제 구성/모델/Store 작업을 정확히 계량하며 실패는 환급 없이 종료합니다. 호출자 싱크 계량에는 구성이 포함되며 초기화 후부터 시작하지 않습니다. 모든 읽기는 최대 8192바이트로 제한하고 스냅샷과 물리 인덱스를 검사하며 페이로드/CRC/싱크/취소/할당량 실패는 인스턴스를 무효화합니다.

<a name="xdzip-required-container-and-host-admission"></a>

## 필요한 컨테이너와 호스트 승인

완전한 인덱스를 게시하기 전에 ARJ 주 및 파일 헤더, 제한된 첫 헤더 레이아웃, CRC-32, 확장 헤더 체인, 정확한 압축 범위와 길이 0 종료 표식이 모두 유효해야 합니다. 물리 ID는 중복 레코드를 유지합니다. 이름, 코드 페이지, 구분자, 디렉터리, 이전 텍스트/바이너리 유형, 특수 객체와 모든 알 수 없는 방식은 명시적 투영과 페이로드 승인이 필요하며 표식을 인식했다고 콘텐츠가 허가되지는 않습니다.

선언된 각 파일 CRC는 완전한 디코딩 후 통과해야 합니다. 헤더와 선택적 압축 파일 보안 필드는 암호학적 진위를 뜻하지 않습니다. 암호, 암호화 방식, 볼륨, 연속 항목, 장, 복구/보안 꼬리와 자체 추출 래퍼에는 별도 프로필과 증거가 필요합니다. 스크립트, 자동 명령, 외부 속성, 인접 경로나 실행 플래그는 권한을 주지 않습니다. 호스트 원본 고정, 선택 추출, 누적 입력/작업/출력 예산, 개인 준비 영역, 취소, 이전 파일 보호와 최종 게시는 [추출 계약](zip-safe-extraction.md)을 따릅니다.

픽스처 생성기는 프로젝트 소유 바이너리 입력만 만들고 요청 및 실제 방식을 기록하며 네이티브 ARJ와 7-Zip으로 전체 출력을 독립적으로 읽습니다. 네이티브 Store 대체는 Store로 남습니다. 암호화되지 않은 타임스탬프, 사용하지 않는 시간 유래 수정자와 해당 헤더 CRC만 정규화하며 압축 바이트와 콘텐츠 CRC는 변경하지 않습니다. 네이티브 빈 입력은 Store 항목을 만들며 인코딩된 빈 압축 스트림의 증거가 아닙니다. 제품 승인은 [QA 범위](../../../developers/qa/README.md)에 따라 실제 런타임/CLI/Qt와 적용 가능한 후보/레이아웃 자동화도 필요합니다.
