# AES Crypt 읽기 전용 봉투

[English](../../engineering/aescrypt-envelopes.md) | [简体中文](../../zh-CN/engineering/aescrypt-envelopes.md) | [繁體中文（台灣）](../../zh-TW/engineering/aescrypt-envelopes.md) | [日本語](../../ja-JP/engineering/aescrypt-envelopes.md) | 한국어 | [Français](../../fr-FR/engineering/aescrypt-envelopes.md) | [Deutsch](../../de-DE/engineering/aescrypt-envelopes.md) | [Español](../../es-ES/engineering/aescrypt-envelopes.md) | [Português (Brasil)](../../pt-BR/engineering/aescrypt-envelopes.md) | [Русский](../../ru-RU/engineering/aescrypt-envelopes.md)

독립 Rust 백엔드 `xdzip-codec-aescrypt`는 AES Crypt 스트림 버전 0, 1, 2와 3을 읽습니다. 애플리케이션 버전 번호는 별개입니다. 일반 가상 파일 하나를 표시하며 생성, 수정, 볼륨 또는 외부 확장 가져오기 기능은 없습니다. 이 형식은 압축 없이 암호화된 데이터를 포함하므로 행의 방식은 Store이고 암호화 플래그는 참입니다. 압축 크기는 전체 물리적 봉투입니다. 백엔드는 `.aes`가 아니라 콘텐츠 감지로 선택합니다.

<a name="xdzip-admission-and-authentication"></a>

## 허용과 인증

네 버전 모두 열기 암호가 필요합니다. 빈 파일을 포함하여 정확한 크기 메타데이터가 표시되기 전에 전체 암호문을 인증합니다. 불변 아카이브 세션은 검사, 미리 보기와 추출을 위해 기존 호스트 비밀 슬롯에 제한된 열기 자격 증명을 보관하며 새로운 항목별 암호 메커니즘은 추가하지 않습니다. 두 번째 전체 인증을 거쳐 작업 판독기를 허용합니다. 내보내기 단계는 실제로 복호화하는 암호문과 정확히 같은 암호문을 인증하며 최종 MAC과 크기 검사가 끝난 후에만 성공합니다. 호스트는 코덱 성공과 원본 검사 후에만 임시 출력을 게시합니다. 검증되지 않은 블록은 최종 게시 권한을 주지 않습니다.

버전 0–2는 UTF-16LE 암호 바이트를 사용하는 지정된 8192회 SHA-256 ACKDF를 사용합니다. 버전 0은 데이터 키를 직접 파생하며 잘못된 암호와 암호문 손상을 구별하지 못해 `password_or_integrity`를 보고합니다. 버전 1–2는 CBC 복호화 전에 감싼 세션 IV와 키를 HMAC-SHA-256으로 인증합니다. 검증 실패는 `wrong_password`를 보고하지만 감싼 데이터 손상으로도 발생할 수 있습니다. 버전 3은 UTF-8 PBKDF2-HMAC-SHA-512를 사용하고 감싼 세션 바이트와 버전 바이트 `03`을 인증하며 데이터에는 PKCS#7 패딩을 사용하는 AES-256-CBC를 적용합니다. 메타데이터 허용과 내보내기 후 모두 실제 암호문 인증이 패딩 검증보다 먼저이며 패딩은 암호 검증에 사용하지 않습니다. MAC 비교는 고정 너비이며 허용된 상수 시간 기본 요소를 사용합니다.

모든 버전이 암호문 HMAC-SHA-256을 검증합니다. 그러나 버전 0–2는 최종 평문 길이의 16에 대한 나머지를 인증 범위 밖에 저장합니다. 이 필드를 바꾸면 MAC을 무효화하지 않고 보고 및 내보내기 길이가 바뀔 수 있습니다. 버전 2–3의 확장도 암호화되거나 인증되지 않습니다. 따라서 `format_declared_checks`는 형식이 선언한 모든 검사를 통과했다는 뜻일 뿐 봉투의 모든 필드, 발신자 신원 또는 파일 출처를 인증하지 않습니다. 버전 3의 암호화된 패딩은 평문 길이를 인증합니다. 이전 버전 검사가 성공해도 평문 길이가 완전히 인증되었다고 설명해서는 안 됩니다.

## 이름, 제한과 실패

가상 기본 이름은 호스트가 승인한 기본 이름에서 대소문자를 구분하지 않고 `.aes`를 제거한 값만 사용합니다. 안전하지 않거나 비어 있거나 점 또는 두 점인 이름은 `content`가 됩니다. 인증되지 않은 `FILENAME`, `URI`, `CREATED_BY`와 컨테이너 확장 값은 경로, 네트워크, 프로세스 또는 실행 권한을 주지 않습니다. 타임스탬프와 실행 권한은 복원하지 않습니다. 첫 멤버 이름이 정확히 `AES`인 일반 TAR은 제한된 구조 판별 후에도 TAR입니다. 확장에 TAR 마커가 있는 유효한 암호화 봉투는 AES Crypt로 유지됩니다. AES Crypt로 허용된 후 인증에 실패해도 TAR, ZIP 또는 다른 형식으로 돌아가지 않습니다.

버전 1–3은 예약 바이트가 0이어야 하며 확장 레코드는 NUL로 구분된 식별자가 필요합니다. 허용 제한은 확장 레코드 256개, 1 MiB 헤더, 버전 3의 반복 횟수 1~2,000,000입니다. 반복 횟수 0, 잘못된 형식, 잘림 또는 블록 정렬되지 않은 데이터는 KDF 작업 전에 거부합니다. 알 수 없는 버전은 지원하지 않습니다. 이전 버전의 나머지 값은 0–15여야 하며 암호문 길이가 0이면 나머지도 0이어야 합니다. 버전 3에는 패딩된 블록이 하나 이상 필요합니다. 손상 데이터 복구는 제공하지 않습니다.

판독기 전용 누적 할당량은 실제 입력, 실제 해시 압축 블록 작업, 실제 AES 블록 작업과 전달된 평문에 각각 최대 24 GiB의 엄격한 한도가 있습니다. 메타데이터 인증, KDF와 이후 읽기를 포함하며 실패 후 예산을 돌려주지 않습니다. 호출자의 메타데이터 입력 및 이름 제한은 허용 조건을 더 엄격하게만 할 수 있습니다. 해시 작업은 KDF, HMAC 패드와 최종 처리를 계산하며 CBC는 감싼 세션 자료를 포함한 모든 실제 블록을 계산합니다. 추가 허용 및 KDF 작업은 데이터 전달 전에 호스트 출력 대상에 부과됩니다. 일반 디코딩은 기존 호스트 원본, 출력, 작업 예산의 적용을 받으며 평문은 파일당 8 GiB, 작업당 20 GiB를 넘을 수 없습니다. 일반 코덱 인터페이스는 UTF-8 암호를 최대 4096바이트 허용하지만 제품 공통 자격 증명 제한은 1024바이트입니다. 반복 상한은 애플리케이션 리소스 정책이며 형식의 최대값이 아닙니다.

KDF 중, 각 읽기와 제한된 CBC 배치마다 취소를 확인합니다. 암호에서 파생한 해시, 중간 KDF 블록, 키, IV 체인과 평문 버퍼는 지울 수 있는 상태를 사용합니다. 허용된 AES 기본 요소는 0으로 지우기 기능을 활성화합니다. 코덱은 파생 키만 보관하고 추가 평문 암호를 보관하지 않습니다. 협조적 취소로 차단된 운영체제 읽기를 중단할 수는 없습니다. 원본, 취소, 할당량과 출력 오류는 유형을 보존하며 단순히 중단된 읽기만 재시도합니다. 판독기 오류는 종료됩니다. 호스트의 원본 식별, 크기와 시간 검사는 가능한 범위의 변경 감지일 뿐 원자적 원본 스냅숏이 아닙니다.

## 출처와 회귀 입력

주요 구조 및 암호 규칙은 작성자의 [AES Crypt 스트림 사양](https://www.aescrypt.com/aes_stream_format.html)과 [엔진 스트림 설명](https://github.com/terrapane/aescrypt_engine/blob/master/stream_format.md)입니다. 독립 백엔드는 허용된 범용 AES와 SHA-2 기본 요소를 사용하며 AES Crypt 런타임이나 공식 애플리케이션을 사용하지 않습니다. 암호화 파일을 실행하거나 애플리케이션 라이선스를 우회하지 않습니다. 공유 비밀 SHA-512/HMAC 상태는 RFC 2104와 [RFC 4231](https://www.rfc-editor.org/rfc/rfc4231)을 따릅니다.

[프로젝트 소유 테스트 자료](../../../tests/fixtures/aescrypt/README.md)는 독립적으로 인코딩한 버전 0–3을 포함하며 별도의 Python 암호 디코더로 교차 검증합니다. 고정 공개 테스트 키와 IV는 결정적인 테스트 입력 전용입니다. 참조 구현은 `build/toolchain/`에, 생성된 증거는 `build/` 또는 CI에 보관합니다. 수락 항목은 [검증 요구 사항](../../../developers/qa/acceptance.md)의 `FORMAT-AESCRYPT`입니다. [암호 처리](password-extraction.md), [검사](archive-checking.md), [안전한 압축 풀기](zip-safe-extraction.md)도 참고하세요.
