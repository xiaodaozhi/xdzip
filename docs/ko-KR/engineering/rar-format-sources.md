# RAR 독립 구현 근거 및 호환성 경계

[English](../../engineering/rar-format-sources.md) | [简体中文](../../zh-CN/engineering/rar-format-sources.md) | [繁體中文](../../zh-TW/engineering/rar-format-sources.md) | [日本語](../../ja-JP/engineering/rar-format-sources.md) | 한국어 | [Français](../../fr-FR/engineering/rar-format-sources.md) | [Deutsch](../../de-DE/engineering/rar-format-sources.md) | [Español](../../es-ES/engineering/rar-format-sources.md) | [Português (Brasil)](../../pt-BR/engineering/rar-format-sources.md)

자체 RAR 이전은 레거시, RAR5, RAR7, 비밀번호, 헤더 암호화, 솔리드 압축 파일 및 승인된 볼륨에 대한 완전한 읽기 전용 범위를 유지하며 RAR 인코더는 개발하지 않습니다. 기능 대체와 공식 의존성 제거는 [이전 작업 #51](https://github.com/xiaodaozhi/xdzip/issues/51)의 적용을 받습니다. 컨테이너 코드나 Store 읽기만으로 전체 이전이 입증되지는 않습니다. 현재 라우팅과 출처는 [격리 백엔드 계약](native-codecs.md)을 참조합니다.

## 출처와 역할

현대 컨테이너 필드는 RARLAB의 [RAR 5.0 형식 기술 문서](https://www.rarlab.com/technote.htm)를 따르며 RAR7 알고리즘 식별은 [UnRAR7 참고](https://www.rarlab.com/unrar7notes.htm)를 참조합니다. 기술 문서는 압축, 과거 비밀번호, VM 또는 체크섬 조정 알고리즘을 완전히 공개하지 않으므로 메서드 이름에서 누락된 상태 기계를 추론할 수 없습니다. 온라인 문서에는 독립 버전 번호나 서명이 없으며 저장된 HTML을 업스트림의 서명된 릴리스로 제시하지 않습니다.

공식 문서가 다루지 않는 이전 컨테이너 및 검증 동작에 대해 독립 분석자가 고정된 UnRAR 소스에서 사실만 담은 전달 자료를 준비했습니다. 참조의 업스트림 내부 버전은 7.30 beta1이며 다운로드 아카이브 이름 `unrarsrc-7.3.1.tar.gz`가 다른 업스트림 릴리스 버전을 입증하지는 않습니다. 아카이브 SHA-256은 `634900842a3737d9cc15bbcc71d4c74cc713437e0bca296a573424fe5f2660ab`입니다. UnRAR 라이선스가 적용되며 정확한 원본 라이선스와 출처는 [유한 매핑 자료](../../../third_party/rar-wire-mappings/README.md)를 참조합니다. 컨테이너, 현대 LZ/필터, 솔리드 처리 및 비밀번호에는 각각 별도의 전달 자료가 있으며 한 문서가 다른 알고리즘 분석의 완료를 입증하지 않습니다.

최초 컨테이너 구현자는 참조 코어를 읽지 않고 공식 문서와 참조 코드 표현이 없는 수학적 전달 자료 `RAR-CONTAINER-2026-10-26-v1`을 사용했습니다. 고정된 컨테이너 사실의 SHA-256은 `116ed2926619ea3009f00a6b6991f5d939581bca30a2060df2c77c51724f9839`, Unicode 보충 경계는 `b456b85b59e97c96c78c1936df6d46c893a9f9b26cc61511cfc411dec20a2750`, 출처는 `b68b0def40ca7b7f3220fa6caf928f239113366bf9a1969372c52063ce240827`입니다. 이후 레거시 서비스 호환성 보완에서 최초 컨테이너 작성자는 코드 동결 후 범위가 한정된 헤더 파싱과 바이트 읽기 부분을 읽고 사실 분석자가 되었으며 해당 컨테이너의 수정을 중단했습니다. 참조에 노출되지 않은 다른 구현자가 수치 사실을 바탕으로 최종 서비스 허용을 독립적으로 완료했습니다. 레거시 서비스 보완 본문 SHA-256은 `2554d6752cd5c8e0f59f97c5a90a9291ba2d8908960a65f50e1c5b54301bad08`, 동결 목록은 `39cad28299020679ab1a8e98e723c3eb8310008861bcea9c6ba76aa80f8fc853`입니다. 생성된 사실, 소스 범위 및 검증 보고서는 참조 코드, 구조, 주석 또는 줄 단위 번역을 복사하지 않고 로컬/CI 산출물로 유지합니다. 이는 엄격한 클린룸 개발이나 라이선스 결론이 아니며 참조 도구와 과거 배포물의 라이선스 의무는 유지됩니다.

현대 LZ는 사실만 담은 `RAR5-RAR7-LZ-FACTS-2026-10-26-v1`을 사용하며 목록 SHA-256은 `b86978fb63c90c38b4dc0fa0831a27598fff12407f561d25fef8d923d83f8ea5`입니다. LZ 코어는 `02e31d56e5a1538d5b0d72222908e2dcc626259e68ec00e6d32e11b5cb92df13`, 검증 경계 보완은 `7fdef948fdd8ab82376ed1aa8f1a3bba6016569fb1c036f5e0ec53f8f37d0e49`, 필터는 `09933ca42c68676a63092a3de9fecb38dda4086cac13a1b7a63f9bc0f818fb30`, RAR7 차이는 `43ada71358a7df4f2c6ed84f0e7661dfeb16169e7f6d1bee3cebe46f6243139c`입니다. Store/윈도 보완 `RAR-SOLID-STORE-WINDOW-2026-10-26-v1`은 `37de8e2d60a96ba92c0e4b400c77556d15a0adc448bc94e4328144979d0713f4`입니다. 구현자는 해당 참조 코어를 읽지 않았으며 RAR 압축 인코더를 개발하지 않습니다. 고정된 선언적 수학 비트 벡터는 테스트 데이터이지 독립적으로 작성자가 압축한 샘플이 아닙니다.

프로젝트는 자체 예산, 순차 쓰기 및 솔리드 불변 조건을 사용해 대형 논리 사전의 Constant/Raw 저장을 독립적으로 설계했습니다. 구현자는 프로젝트 설계와 수치 사실을 읽었고 해당 타사 디코더는 읽지 않았습니다. 실제 RAR7 테스트 데이터 분석자는 고정된 압축 파일 식별, 헤더 숫자, 알려진 전체 0 생성법 및 도구 기록만 구현자에게 전달했습니다. 테스트 진입점은 압축 데이터와 원본 고지만 다운로드하며 업스트림 구현이나 README는 다운로드하지 않습니다. 스크립트가 생성한 자료 기록은 테스트 데이터의 출처와 라이선스 경계를 유지하며 법적 결론을 뜻하지 않습니다.

현대 암호화 버전 0은 사실만 담은 `RAR5-CRYPTO-FREEZE-2026-10-26-v1`을 사용합니다. 비밀번호/래핑 본문은 `029f03e1cf7dff2ae804fb99f7dbacb8ac0306498476119a4d851cbe9a52e9fb`, BLAKE2sp 프로파일은 `1574159e24c956a2287d605501dff63f1ee67d0028cfd9fe3dadcdbbeee8f795`, 출처는 `e13a21f12cc3df777d8d1d2332e38d9e525aceed02ddb0ce93a54c4cf8a2577a`입니다. 공유 `xdzip-crypto`는 자체 SHA256 상태 래핑, RFC2104 HMAC 및 BLAKE2s/sp 조합을 제공합니다. AES와 SHA2 압축 기본 기능은 범용 의존성 허용 정책을 따르며 참조 라운드 함수나 테이블을 다시 작성하지 않습니다.

RAR29 PPM은 사실만 담은 `RAR29-PPM-2026-10-26-v1`을 사용합니다. 본문 SHA-256은 `9425e386ee75acac31f843d61480b02dbba7ed56ae6ef550e45e54fd8ee32114`, 출처는 `4de014dc4cf1de581d32e10c6b166bc2e14542c04ca1cc6cf46cee1dced39482`입니다. 파일 재진입, 압축 꼬리 및 이스케이프 보완 `RAR29-PPM-BOUNDARIES-2026-10-26-v1`의 본문은 `540795a89e33a2bbf43b3317f30b8c0f0550884740f0230594f33cf949a9aa92`, 독립 동결본은 `e3b6e475bd2c7438de3c366c19d2f156bcaec6ca7426c250aff1e61eb04ae8e5`입니다. 구현자는 해당 타사 모델, 범위 또는 할당자 구현을 읽거나 번역하지 않고 프로젝트 고유의 PPMd H 통계 모델과 수학적 설명을 재사용했습니다. 원래 PPMd의 퍼블릭 도메인 선언이 RAR 래핑이나 기타 수정을 자동으로 재라이선스하지 않으며 참조 도구와 공개 픽스처는 각자의 출처와 라이선스를 유지합니다.

RAR29 LZ와 여섯 표준 필터는 사실만 담은 본문 `e375c541e106d43a3e58a2fe8aab79f60ffc71beff08b76c2a66f26d0fd355cb` 및 `eeecbd9a247d4a8c98e3d1cd11371106c16fbb5bd565406731908241e7432d8a`를 따르며 레거시 비밀번호 본문은 `9650bce5affb20ea4d616e1e68c25d52e5fa703bd0b7c56b3915fad825abdcb4`입니다. 고대 컨테이너 보완 `RAR14-CONTAINER-2026-10-26-v1`의 본문은 `d3a86f3cad6e1893959d40cc691e7c7d4ddfec4b96abc9f4ba12ea98fd7f484c`, 독립 동결 목록은 `e6adcbf16ad688c82ad5bd39ae7cdd4379003ae82dd19b30b4dd53ce52223f9c`입니다. 이 자료는 숫자, 경계 및 검증 동작만 전달합니다. 각 구현자는 처음 자신의 모듈을 구현할 때 해당 UnRAR 코어를 읽지 않았으며 고정된 공개 압축 파일과 공식 도구는 독립 블랙박스 참조로만 유지됩니다.

13/15 계열은 레거시 알고리즘 사실 본문 `d4cd5d61ee4b16fa7202cb6840d0e9592d67205c4fdbfd02f3e515320ebf96ef`를 따릅니다. 유한 접두사 및 Short 매핑은 독립 데이터 테이블 전달 자료이며 SHA-256은 각각 `2e50aa5c3c9f97609cf7b7c91676b7266de9ca65ee977f9184c42ec104c9edeb`와 `31d4186b3dbf06bdbf5aabd5f08cfa800bc810709cfd042fe6f32ef22c9cad1b`입니다. 출처는 고정된 UnRAR 참조로 유지됩니다. 유한 와이어 매핑, 독립 CSV 및 자체 Rust 구조만으로 저작권이나 재라이선스를 결정할 수 없습니다.

레거시 컨테이너 예외와 Windows 호스트 문자 투영은 추가 동결 자료 `RAR-COMPATIBILITY-GAPS-2026-10-26-v1`, 사실 본문 `142e47f9a3c2920e0e0c674555df669ecde0bc29549a9a45f03133d11957a4ef`를 사용합니다. Unix/macOS 추가 사실 `RAR-COMPATIBILITY-GAPS-UNIX-2026-10-26-v2`는 `3853684c35ee672956ccaadb3efc1f1fffb58e0a7fa472d41c261fbacd69a479`, 시간 투영 사실은 `2ea490c2304c8fe5188af371d77fe9013b23ae66e6ff4fe05cf489cb7c914a20`입니다. 순수 시스템 서비스는 로컬 문자/달력 변환만 수행하며 형식 선택, 한도, 잘림 및 DOS 산술은 Rust에 남습니다. 시스템 실패를 확인하지 않은 참조 동작이 초기화되지 않은 데이터의 반환을 허용하지는 않습니다.

소스 분리는 실제 노출에 따라 기록합니다. 현대 ARM 구현과 수학 테스트가 완료된 후 테스트 데이터 검색 결과 요약에 다른 타사 디코더의 ARM 표현식이 실수로 표시되었습니다. 기존 ARM 구현을 즉시 동결했으며 그 구현자는 더 이상 해당 알고리즘을 수정하지 않습니다. 필요한 수정은 노출되지 않은 구현자가 사실 전달 자료를 사용해 수행합니다. 압축 해제 코어를 읽지 않았다는 주장은 타사 코드 조각을 전혀 본 적이 없다는 뜻이 아니며 위에서 설명한 이후의 범위 제한 서비스 컨테이너 열람도 포함하지 않습니다. 정확한 질의, 노출 범위 및 경과는 로컬 산출물에 보관합니다.

## 컨테이너 후보 계약

`xdzip-codec-rar`는 프로젝트 codec API/도메인, 공유 압축/암호화 및 승인된 범용 AES, SHA2 압축 기본 기능과 소거 기능에 의존합니다. CRC32는 공유 구현을 재사용하며 타사 RAR, 압축 파일 또는 압축 형식 라이브러리를 도입하지 않습니다. `MetadataCodec`/`PayloadCodec`을 구현하고 공식 실패 폴백 없이 기존 격리 워커의 공유 CXX 브리지를 통해 실행됩니다. 연결만으로 전체 호환성 검증을 대신할 수 없으며 제품 경로 전환은 [이전 계약](independent-rust-codecs.md#实现边界)을 따릅니다.

- 호스트는 승인된 순서의 스트림과 각 물리 볼륨의 길이를 최대 1,024개 제공합니다. 절대 위치로 변환하기 전에 볼륨 내부 범위를 검사하며 압축 파일 이름은 경로 접근을 허용하지 않습니다. 각 볼륨 헤더를 다시 식별하고 형식 세대, 볼륨 번호, 헤더 암호화 상태 및 연속 관계를 검사합니다. 명시적인 split-before/after만 병합하며 일반 중복 이름은 각각 다른 식별을 유지합니다. 일반 파일과 서비스 연속 체인은 별도로 유지하고 서비스는 일반 EntryId를 소비하지 않습니다.
- 일반 1.5..4 헤더 검사는 일반 CRC32의 하위 16비트를 사용하며 현대 헤더는 전체 CRC32를 저장합니다. 그 이전의 1.4 컨테이너에는 헤더 CRC가 없으며 별도의 콘텐츠 체크섬과 혼동할 수 없습니다. 범위가 제한된 필드와 extra를 해석하기 전에 일반 평문 헤더 검사를 검증합니다. 현대 vint는 최대 10바이트이며 마지막 바이트에는 유효한 0/1 비트만 허용합니다. 수학적 값이 올바르면 최단 길이가 아닌 표현도 허용합니다. head-size 자체는 최대 3바이트, 전체 평문 헤더는 최대 2 MiB입니다. 알 수 있지만 건너뛸 수 있는 extra는 범위에 따라 건너뛰며 알 수 없는 필수 디코딩 기능을 성공적인 일반 콘텐츠로 가장할 수 없습니다.
- 비공개 인덱스는 각 조각의 원래 헤더, 볼륨/헤더/압축 범위, 알려진 또는 알 수 없는 크기, 원시 이름, 디코딩 버전, 압축 강도, 선언 및 유효 알고리즘, 사전, 솔리드 상태, 시간, 유형, CRC/해시 및 비밀번호 설명을 유지합니다. 공개 메서드는 50 또는 70과 같은 UnpVer를 유지하며 공개 packed_size는 합계가 아닌 처음 보이는 조각의 압축 크기입니다. EntryId는 처음 보이는 일반 레코드 순서에 따라 1부터 연속 할당합니다.
- 선언된 레거시 Unicode는 먼저 수학적 명령으로 결정하고 그렇지 않으면 공유 압축 파일 단위 레거시 감지를 사용합니다. 원시 이름 영역을 보존하고 다중 바이트 `0x5c`가 분리되지 않도록 문자 디코딩 후에만 레거시 구분자를 변환합니다. Unicode 서로게이트는 완전한 쌍이어야 하며 잘린 명령, 내장 NUL 및 범위를 벗어난 복사는 거부합니다. RAR5는 선언된 UTF-8을 엄격히 검증합니다. Unix 이름 매핑과 리디렉션의 경고를 유지하며 링크와 특수 객체는 일반 출력이 될 수 없습니다.
- 메타데이터 읽기는 최대 64 MiB, 물리 헤더는 최대 100,000개, 이름은 각각 최대 4,096바이트, 원시 이름 합계와 디코딩/표시 합계는 각각 최대 16 MiB입니다. 호출자의 더 낮은 한도가 우선합니다. 페이로드 재스캔은 원래 입력 허용량을 계속 누적하며 실제 입력과 디코딩 작업은 각각 최대 20 GiB, 파일은 최대 8 GiB입니다. 알고리즘 작업 공간은 실행 전 기본 메모리 상한 1 GiB에 따라 승인합니다.
- 알고리즘 주입에는 제한된 평문 압축 스트림, 빌린 제어 및 호스트 sink만 제공됩니다. 컨테이너는 조각 압축 검사, 복호화, 전체 입력 소비, 정확한 파일 크기 및 최종 전체 콘텐츠 검증을 처리합니다. 알고리즘은 상태, 압축 스트림 종료 및 자체 메모리 사전 검사를 담당합니다. 후보는 Store, 13/15, 20/26, RAR29 LZ/PPM 및 현대 LZ를 실행하며 파일 전체를 누적하지 않고 최대 8 KiB 블록을 출력합니다. 디렉터리는 크기와 압축 크기 0, 원래 헤더 재검증 및 필요한 빈 콘텐츠 검사가 완료된 후에만 완료됩니다. 이름 경고, 링크 및 특수 레코드를 먼저 거부하며 공개 항목 허용을 우회할 수 없습니다.
- 식별된 도메인 I/O 오류 분류를 먼저 보존합니다. 래핑된 오류가 없는 순수 Interrupted만 재시도할 수 있습니다. 취소, 할당량, 원본 변경, I/O, 출력 실패 또는 검증 실패는 인스턴스를 오염시키며 실패는 EOF, entry_done 또는 게시 가능 상태가 아닙니다. 호스트는 원본 식별, 경로 검사, 비공개 스테이징 및 최종 커밋을 담당합니다. 공개 DecodeError에는 현재 별도 SourceChanged 변형이 없어 이를 SourceIo로 매핑하며 원본 호스트는 구체적인 원인을 유지합니다.

## 현대 LZ 후보 규격

- 유효 알고리즘 0은 거리 심볼 64개, 알고리즘 1은 80개를 사용합니다. 선언된 버전 1 호환 비트는 여전히 유효 알고리즘 0을 선택하므로 도구 버전이나 확장자로 트리를 선택하지 않습니다. 독립적인 MSB 비트 읽기와 정규 Huffman 트리는 Deflate의 LSB 순서가 아닌 선언된 유효 비트를 소비합니다. 새 테이블의 코드 길이 수는 각각 430/446입니다. 사용하지 않는 트리는 비어 있을 수 있으며 없는 코드 소비, 초과 할당 또는 범위 밖 반복은 명시적으로 실패합니다.
- 블록 헤더 검증, 마지막 바이트의 유효 비트 및 마지막 블록 플래그가 함께 비트스트림 종료를 결정합니다. 알려진 출력 크기, 최종 콘텐츠 CRC 및 전체 압축 입력 소비는 각각 확인하며 선언 크기 출력만으로 조기 성공하지 않습니다. 빈 블록에서 부호 없는 산술 언더플로가 발생하지 않으며 유효한 테이블 없이는 콘텐츠를 디코딩할 수 없습니다. 후보는 범위 밖 반복, 미완성 필터 범위 및 뒤따르는 압축 바이트에 엄격한 정책을 적용합니다. 정상 샘플이 모든 과거 복구 동작과의 동등성을 입증하지는 않습니다.
- 비솔리드 압축 파일은 유효 사전 이력, 최근 거리, 마지막 길이 및 테이블을 재설정합니다. 솔리드 압축 파일은 이들을 유지하되 파일마다 입력 블록, 필터 및 파일 오프셋을 재설정합니다. 첫 압축 파일이 결정한 유효 창을 사용하며 최소 작업 창은 256 KiB입니다. 2의 거듭제곱이 아닌 창은 실제 모듈러스로 순환합니다. 이후 더 작거나 2의 거듭제곱이 아닌 선언이 모듈러스를 바꾸지 않습니다. 스트림 중간 확장은 이전 할당 캐시에 의존하는 잘못된 체인의 예외를 재현하지 않고 Unsupported를 반환합니다. 비솔리드 교체 전 이전 창을 해제해 두 큰 창이 동시에 존재하지 않도록 합니다.
- Store는 솔리드 비트 설정 여부와 관계없이 파일을 복사하고 검증하며 LZ 이력에 추가하거나 테이블, 최근 거리 또는 마지막 길이를 지우지 않습니다. 디렉터리와 서비스는 새로운 압축 초기화 지점이 아닙니다. 솔리드 파일을 임의 선택하면 앞선 비솔리드 압축 파일부터 복원하고 물리 순서대로 접두부를 실제 디코딩합니다. Store는 재시작 지점이 아니며 건너뛰기와 반복 재생은 실제 작업으로 계산합니다.
- Delta, x86 E8, x86 E8/E9 및 ARM 필터는 완전하고 분리된 논리 범위를 처리합니다. 필터 전 바이트는 항상 LZ 이력을 구성하고 변환된 복사본은 파일 CRC와 sink로 전달합니다. 범위는 블록이나 물리 볼륨을 넘을 수 있지만 파일을 넘을 수 없으며 시작 및 파일 오프셋을 링 인덱스와 혼동해서는 안 됩니다. 범위는 최대 4 MiB이고 대기 항목은 최대 8,192개입니다. 겹침, 역순, 알 수 없는 변환 및 불완전한 범위는 거부합니다. 이는 후보의 자원 정책이며 형식의 최대치를 주장하지 않습니다.
- 명령 배치는 최대 8 KiB 출력 또는 256개 명령을 계획합니다. 실행 전 남은 작업은 로컬에서만 예약하며 수행하지 않은 진행을 공개 sink에 보고하지 않습니다. 부분 실패나 취소 전 완료된 바이트를 포함하여 실행 후 실제 WORK만 정산하고 일회성 선불 허용량으로 변환합니다. 수행하지 않은 예약은 출력에 사용할 수 없으며 실패 후 재사용하지 않습니다. 완전한 필터 범위를 스테이징하는 동안 실제 작업을 계속 누적합니다. 선불 전달 전에 비공개 컨테이너 크레딧을 차감하며 최종 크기, CRC, 취소 및 쓰기 실패 검사는 계속 적용됩니다. 기본 sink는 보수적으로 다시 청구할 수 있습니다. Store는 일반 출력 계산을 사용합니다. 워커는 PRECHARGED_DATA로 크레딧 처리된 RAR 콘텐츠를 전달하며 Native 수신기와 런타임은 호스트 크레딧, 정확한 크기 및 할당량을 독립적으로 검사합니다. 재시작, 완료 또는 실패 후 이전 워커 크레딧을 재사용할 수 없습니다.
- 제한된 메타데이터, 필터 복사본, 대기열 및 기타 상태를 위해 LZ 사전 밖에 288 MiB를 예약하고 워커 상한 1 GiB에 대해 함께 승인합니다. 이는 보수적인 메모리 정책이지 와이어 형식의 최대 사전이 아니며 선언된 크기가 할당 권한을 부여하지 않습니다. 취소나 오류는 전체 페이로드 상태를 오염시키므로 유지된 부분 사전으로 다른 항목을 계속 처리하지 않습니다.

### 대형 논리 사전의 정확한 저장

전체 사전이 밀집 저장 허용량을 초과하는 현대 유효 알고리즘 1 압축 파일은 최대 1 TiB 논리 창에서 정확한 Constant/Raw 페이지 이력을 사용합니다. 페이지는 64 KiB이며 상수 바이트 또는 독점 소유 원시 버퍼를 보관합니다. 읽기, 쓰기 및 거리는 원래 논리 창의 실제 모듈러스를 사용합니다. 생성되지 않은 이력은 읽을 수 없고 겹치는 일치는 바이트 단위로 실행됩니다. 이력은 필터 전 콘텐츠를 저장하며 최종 출력 버퍼와 별칭을 공유하지 않습니다. 다른 알고리즘, Store, 알 수 없는 메서드 및 서비스 레코드에는 대형 사전 예외가 적용되지 않습니다.

페이지 디렉터리, 슬롯 테이블, 빈 풀, 모든 유지 용량, 일시적 최대 사용량, 비공개 상태 및 할당자 허용량 16 MiB의 합계는 최대 512 MiB입니다. 외부 288 MiB와 비밀번호 상태는 별도이며 워커 상한 1 GiB는 유지됩니다. 모든 할당 전에 예산을 검사하고 논리 창 크기만큼 거대한 주소 공간을 예약하거나 디스크 이력으로 전환하지 않습니다. 상수 페이지에 다른 값을 쓰기 전에 Raw 페이지를 완전히 초기화합니다. 유효 페이지 전체 길이를 동일한 새 바이트로 순차적으로 덮어쓴 경우에만 접습니다. 부분 페이지 솔리드 연속은 원래 끝부분과 후보 상태를 유지하며 비솔리드 교체는 이전 저장소를 먼저 해제합니다. 풀로 반환된 버퍼도 실제 용량으로 계속 청구합니다.

디렉터리, 슬롯 테이블 및 Raw 페이지의 실제 초기화는 별도 보조 작업 채널을 사용하고 취소를 확인하며 최대 8 KiB 블록으로 정산합니다. 파일 진행이나 전달 크레딧을 추가하지 않습니다. 출력 바이트를 수락하기 전에 실패 가능한 저장소 준비를 끝내고 할당 없이 이력을 커밋합니다. 출력 거부는 이력 바이트나 커서를 바꾸지 않으며 완료된 초기화는 환불하지 않고 오류는 페이로드를 오염시킵니다. 이는 상수 페이지를 효율적으로 처리하지만 임의의 저엔트로피 스트림이나 대형 사전이 들어간다고 보장하지 않으며 너무 큰 Raw 작업 집합은 명시적으로 Limit를 반환합니다.

실제 알고리즘 1 상호 운용성 검사는 build/CI에 고정된 압축 테스트 데이터와 고지만 가져오고 대형 평문이나 타사 구현을 저장하지 않은 채 원래 헤더 식별과 전체 평문 SHA-256, CRC, 크기, WORK, AUX 및 유지 용량을 검사합니다. 수학적 페이지 테스트와 독립적인 정상 압축 스트림은 별도로 기록합니다. 하나의 성공한 스트림은 모든 확장 거리나 암호화, 솔리드 및 볼륨 간 조합의 검증을 입증하지 않습니다.

독립적으로 알려진 현대 x86 평문은 [제어된 PE 데이터 생성법](../../../crates/xdzip-codec-rar/tests/fixtures/modern-x86-owned/README.md)으로 확인할 수 있습니다. 공식 작성자가 일반적으로 생성한 스트림이 실제로 E8 또는 E8/E9를 선택하고 직접 LZ, Payload 및 실제 워커를 통한 전체 콘텐츠 검사를 통과해야 합니다. PE 이름, 도구 버전 또는 디스크립터 수만으로는 부족합니다. 테스트 입력은 실행하지 않으며 PE 파일이나 생성한 압축 파일을 저장소에 보관하지 않습니다. 다른 솔리드, 암호화 및 볼륨 간 조합은 별도로 검증합니다.

## RAR29 PPM 후보 규격

- `xdzip-compression`은 순서가 있는 통계 문맥, 이진 확률, SEE, 제외, 후속 상태 실체화 및 명목 용량 원장을 공유합니다. RAR29와 7z는 통계를 중복하지 않고 서로 다른 범위 어댑터를 통해 같은 모델을 사용합니다. RAR은 4바이트 carryless 초기값, 독립 정규화 및 두 분기 모두에서 나눗셈 나머지를 버리는 이진 구간을 사용합니다. 7z는 5바이트 초기값, 나머지 및 종료 규칙을 유지합니다.
- 모드 헤더는 완전히 정렬된 F 바이트에서 시작합니다. 리셋 비트가 전체 모델 재구성 여부를 결정하며 메모리 필드는 명목 용량 1..256 MiB, order는 헤더 필드를 인코딩 가능한 2..64에 매핑합니다. 선택적 이스케이프는 선언된 경우에만 바뀌며 리셋이 자동으로 복원하지 않습니다. 유지 요청에는 연속성이 확립된 유효한 모델이 이미 있어야 합니다. 각 모드 초기화는 4바이트 범위를 다시 구성하며 헤더 없는 파일 간 연속은 대체할 수 없습니다. 이전 모델 없는 독립 임의 시작점은 명시적으로 실패합니다.
- 명목 12바이트 단위와 결정적인 클래스, 단편화, 병합 및 차용 규칙이 형식에서 정한 모델 재시작을 제어합니다. Rust 객체, 이력, 인덱스, 순회 임시 공간, 고정 상태 및 기타 디코딩 상태는 실제 저장량을 기준으로 별도 승인합니다. 리셋은 큰 할당 두 개가 동시에 존재하지 않도록 이전 arena를 먼저 해제합니다. 용량 재시작은 이미 디코딩한 현재 심볼과 범위를 유지합니다. 실제 OOM, 할당량, 취소, 원본 I/O 또는 모델 불변식 오류는 최종 실패이며 용량 재시작으로 가장할 수 없습니다.
- 새 arena 초기화와 용량 재시작은 먼저 보조 작업 예산을 승인받습니다. 실제 채우기/지우기는 최대 64 KiB 저장 청크와 제한된 확률 테이블 행 단위로 실행하여 취소를 확인하고 완료된 초기화 바이트를 누적합니다. 이후 범위 읽기 실패, 취소 및 `clear`는 완료된 작업을 환불하지 않습니다. 외부 계층은 제어 및 매개변수 심볼의 보조 작업과 함께 누적 20 GiB 한도에 대해 성공과 실패 시 실제 차이를 정산합니다. 별도 AUX는 선불 파일 전달 크레딧을 부여하지 않으며 미래 예약은 실제 진행이 아닙니다.
- PPM은 통계 갱신과 정규화가 완료된 뒤 모델 바이트 하나를 전달합니다. 이스케이프, 필터 매개변수 및 일치 매개변수는 모두 모델을 정상 갱신합니다. RLE 또는 LZ 복사로 생성된 파일 바이트는 PPM에 다시 입력하지 않습니다. 외부 계층은 파일 종료, 모드 전환, 출력 크기, 콘텐츠 CRC 및 선언된 압축 경계를 검증합니다. RAR은 루트 이스케이프를 7z END로 허용하지 않으며 7z의 최종 코드 0 조건을 적용하지 않습니다. 실패한 모델은 외부 복구가 명시적으로 지울 때까지 오염 상태를 유지합니다.
- 실제 PPM EOF 이후에도 입력 할당량, 취소 및 조각 검사를 계속하면서 선언된 전체 압축 범위 안에서만 남은 입력을 비웁니다. PPM 산술 꼬리에는 현대 CBC의 0..15바이트 정렬 한도를 사용하지 않습니다. 실제 EOF가 없거나 크기/CRC가 일치하지 않으면 꼬리 정책으로 성공할 수 없습니다. 다음 솔리드 파일은 모드 헤더와 새 범위를 다시 읽으며 리셋 비트가 모델 유지 여부를 독립적으로 결정합니다. 고정된 참조는 이스케이프 뒤 제어값 1과 6..255에 대해 리터럴 이스케이프를 출력합니다. 후보가 6..255를 엄격히 거부한다면 그 검증 차이를 별도로 기록하고 참조도 이를 거부한다고 주장하지 않습니다.

## RAR29 LZ 및 표준 필터 후보 규격

- RAR29는 MSB 비트스트림을 독립적으로 읽습니다. 차등 코드 길이 404개가 299/60/17/28 심볼 트리를 구성합니다. 이전 코드 길이 기준값, 거리 하위 4비트 반복, 최근 거리 4개 및 마지막 일치 길이는 압축 상태에 남습니다. 이 레거시 알고리즘에 현대 64/80 거리 테이블을 적용하지 않습니다. 파일 종료자는 다음 솔리드 파일이 모드를 다시 읽는지 결정합니다. 초기화되지 않은 재사용, 빈 트리 소비, 범위 밖 반복/출력 및 이력 이전을 가리키는 거리는 실패합니다.
- 외부 PPM 이스케이프는 파일 종료, 모드 전환, 리터럴 이스케이프, 필터 및 두 종류의 복사를 제어합니다. 매개변수 바이트도 모델을 통해 디코딩하며 일치 출력은 LZ 이력과 최종 파일 스트림에만 들어가고 통계 모델에 피드백되지 않습니다. PPM EOF 후 압축 나머지 비우기와 순수 LZ 비트스트림 종료는 별도 정책입니다.
- 표준 필터 프로그램은 먼저 제한된 패킷, 프로그램 길이, XOR 및 고정 CRC/길이 식별을 검사합니다. E8, E8/E9, Itanium, Delta, RGB 및 Audio의 확립된 제품 기준 변환 여섯 개만 허용합니다. 후보는 임의의 압축 파일 VM을 실행하지 않습니다. 정의, 캐시된 길이 및 마지막 선택은 솔리드 상태로 유지하고 오프셋은 파일마다 다시 계산하며 미완성 범위를 리셋으로 버릴 수 없습니다.
- 필터 전 바이트는 LZ 이력에 남습니다. 시작과 길이가 같은 표준 변환은 연결할 수 있으며 다른 겹침, 역순 및 미완성 범위는 거부합니다. 범위는 1..262,143바이트이고 정의 및 대기 항목은 최대 8,192개입니다. 이는 후보 자원 정책입니다. Delta는 최대 1,024개 채널, Audio는 128개 채널을 사용하며 와이어 매개변수와 초기화 버퍼를 먼저 승인합니다.
- 레거시 E8 PC는 현대의 16 MiB 모듈러가 아닌 전체 32비트 파일 위치를 사용합니다. Itanium은 원래 번들/템플릿과 명령 필드를 변환하며 RGB와 Audio는 별도의 예측 상태를 가집니다. Audio는 첫 샘플에서의 적응과 -17까지의 음수 계수를 포함하며 현대 Delta 또는 E8 수학 벡터로 대체할 수 없습니다.
- 실제 변환된 모든 바이트, PPM 매개변수 및 실제 모델 초기화는 보조 작업 예산을 소비합니다. 보조 작업은 최대 64 KiB의 0이 아닌 별도 `charge_auxiliary` 메시지로 정산합니다. decoded_bytes, 확장 비율 분자 또는 전달 크레딧을 늘릴 수 없으며 솔리드 접두부를 건너뛸 때도 전달합니다. 워커, Native 수신기 및 런타임이 각각 [보조 작업 계약](auxiliary-decoding-work.md)을 적용합니다. 보조 수치를 WORK로 전달한 이전 후보는 이 계약을 만족하지 않습니다. 처리 루프는 청크마다 취소를 확인하며 실패 전에 완료된 보조 작업은 환불하지 않습니다.

## 고대 컨테이너 및 과거 비밀번호 후보 규격

- 1.4 메인 헤더는 `RE~^`를 포함해 최소 7바이트입니다. 파일 헤더는 고정 21바이트 뒤에 제한된 이름과 건너뛸 수 있는 추가 자료가 옵니다. 페이로드는 선언된 headSize 끝에서 시작합니다. 메인 0x01/0x08은 볼륨/전역 솔리드를 나타내며 원래 0x80은 이후 헤더 암호화 비트가 아닙니다. 파일은 split-before/after/암호화에 0x01/0x02/0x04만 사용합니다. 디렉터리는 DOS 속성에서 결정하며 이후 파일 창 또는 솔리드 비트를 재사용하지 않습니다. 사전은 64 KiB로 고정됩니다.
- 고대 메서드 값은 0..5를 직접 사용합니다. 선택자 2는 공개 UnpVer13, 나머지는 10으로 매핑합니다. 압축 허용은 기준이 확립된 13/15만 해당하며 10은 Store만 지원합니다. 전역 솔리드는 두 번째 논리 파일부터 이어지며 물리 연속 조각은 같은 논리 파일 상태를 상속합니다. 새 파일은 비트 읽기와 콘텐츠 체크섬을 재설정하고 Store는 압축 이력에 데이터를 주입하지 않습니다.
- 각 고대 논리 파일은 16비트 c=0으로 시작해 실제 최종 출력 바이트 x마다 `c=ROTL16((c+x) mod65536,1)`을 계산하고 최종 XOR 없이 최종 헤더의 u16과 직접 비교합니다. 중간 조각의 u16 값은 압축 CRC로 취급하지 않고 보존합니다. 전체 콘텐츠 체크섬은 조각에 걸쳐 적용되며 솔리드 선행 파일의 체크섬을 다음 파일로 이어가지 않습니다. 같은 세대 알고리즘을 사용하는 이후 컨테이너는 여전히 일반 CRC32를 사용합니다.
- 고대 암호화는 솔트/IV 없는 old13 바이트 비밀번호 계열을 항상 사용하며 selector10도 이를 바꾸지 않습니다. 이후 13/15는 각각의 바이트 계열, 20/26은 이전 블록 계열, RAR3는 원래 SHA1 파생 조합과 AES128-CBC를 사용합니다. 각 논리 파일은 새 암호 상태를 가지며 물리 분할 조각은 연속되고 비밀번호 상태는 압축 솔리드 상태와 함께 파일을 넘지 않습니다. old13/15는 블록 정렬 꼬리를 허용하지 않으며 이전 블록 암호 Store는 실제 크기로 자릅니다. RAR29 PPM의 선언된 꼬리 정책은 별도로 적용됩니다.
- RAR3 암호화 헤더는 헤더마다 8바이트 솔트를 다시 읽고 첫 블록을 복호화해 실제 헤더 길이를 얻은 뒤 해당 볼륨에서 정렬된 전체 범위와 일반 헤더 CRC를 검증합니다. 페이로드 재검증을 위해 원래 솔트/암호문을 보존합니다. 외부 계층은 먼저 UTF-8 4,096바이트를 검사합니다. 이전 경로는 추가로 첫 NUL 뒤 입력을 포함한 전체 입력에 대해 네이티브 콜백의 로컬 wide 단위 511개 제한을 유지한 다음 첫 NUL 이전 내용만 취하고 암호화 127단위 경계를 적용합니다. 이는 과거 호스트 진입 동작이지 형식 비밀번호 길이 규격이 아니며 현대 KDF 진입 정책은 별도입니다.
- Windows는 고대가 아닌 컨테이너의 HostDOS 레거시 파일에만 0으로 채운 전체 UTF-16 512단위에 OEM-to-ANSI wide 투영을 적용한 뒤 wide 인덱스 127에서 자릅니다. 레거시 13/15/20은 다음으로 512바이트 버퍼에 ANSI로 인코딩하고 원시 바이트 127에서 자르므로 DBCS가 분리될 수 있습니다. RAR3는 투영된 wide 단위의 하위 16비트를 직접 사용합니다. 고대 콘텐츠에는 이후 DOS 보정을 적용하지 않습니다. 변환은 동기적으로 빌린 호스트 서비스를 사용합니다. OS 실패는 명시적 Unsupported이며 형식화된 원본 오류와 취소는 각 분류를 유지합니다. 서비스가 없으면 동등성이 증명된 ASCII 경로만 사용합니다.
- macOS 레거시 좁은 비밀번호는 먼저 Unicode 스칼라 127개를 취하고 명시적으로 UTF-8로 인코딩한 뒤 원시 바이트 127에서 잘라 끝에 불완전한 시퀀스가 남을 수 있습니다. 일반 Linux는 현재 스레드 로캘의 상태 유지 변환을 사용하고 EILSEQ 재시도 후 실제 접두부를 유지하며 이 프로젝트의 독립 워커는 이를 위해 프로세스 로캘을 바꾸지 않습니다. Linux의 U+FFFE 표시 복구 경로는 Rust에서 표시를 제거하고 U+E080..E0FF 원래 바이트를 복원하며 일반 단위는 호스트 변환에 보냅니다. Apple이나 표시 없는 문자열에는 적용하지 않습니다. Windows가 아닌 RAR3 wide 투영은 원래 스칼라 접두부와 단위의 하위 16비트를 사용하며 하위 16비트가 0이어도 원래 NUL로 오인하지 않습니다. 중간 wide, narrow, 단일 문자 및 키 버퍼는 소거하며 고정 투영 임시 공간에는 별도 4 KiB 예산을 둡니다.
- 신뢰할 수 있는 독립 검증자가 없으면 헤더 Invalid 또는 콘텐츠 Integrity는 안전한 호스트 재시도를 위해 PasswordOrIntegrity를 반환합니다. SourceChanged/SourceIo, Limit, Cancelled, Output 및 Unsupported는 비밀번호 모호성으로 감싸지 않습니다. 검증된 현대 검사 불일치는 WrongPassword를 유지하고 검증된 키에서의 손상은 무결성 오류로 유지합니다. 재검증 중 물리적 원래 헤더 변경은 원본 오류이며 암호문 변경에서 추론한 비밀번호 오류가 아닙니다.

## 과거 보조 헤더 및 접두부 후보 규격

- 내장 레거시 주석에서 메인 부모 CRC는 고정 13바이트만 포함합니다. 파일 부모 CRC는 실제 소비한 고정 필드, LARGE, 이름, 솔트 및 해석된 처음 세 확장 시간을 포함하며 아카이브 시간 슬롯은 소비하지 않습니다. type75 자식은 부모의 HeadSize 안에서 고정 13바이트 헤더 CRC를 독립적으로 검증합니다. 주석 내용은 범위 내에서 건너뛸 수 있지만 콘텐츠 CRC 검증을 주장하거나 참조의 이후 전체 읽기/BrokenHeader 복구 흐름을 형식 규칙으로 삼지 않습니다.
- AV76과 SIGN79는 common7, LONG에 대한 추가 dataSize4 및 선언된 데이터 범위만 사용해 건너뜁니다. UO는 정확한 type77+subtype0x0101에서만 일반 CRC를 우회하며 공통 14바이트와 선언 범위로 위치를 찾습니다. 다른 하위 유형과 일반 파일은 계속 일반 헤더 CRC를 검사하며 과거 문자열 끝을 추측하려고 NUL을 스캔하지 않습니다.
- END는 선택적 archiveCRC/볼륨 번호 뒤의 선언된 불투명 꼬리를 건너뜁니다. 정확한 과거 예외는 일반 END+REVSPACE CRC가 실패하고 이번 읽기의 끝 앞에 있는 원래 물리 바이트 7개가 모두 0일 때만 적용됩니다. 이는 볼륨 EOF가 아닌 현재 물리 헤더 끝을 기준으로 합니다. 암호화 헤더에서는 복호화된 논리 꼬리나 END 소비 후 트레일러가 아닌 물리적 솔트/암호문 범위의 마지막 7바이트를 검사합니다. 암호화 REV에는 여전히 독립 실제 샘플이 없습니다.
- 고대 SFX는 오프셋 1에 특별한 허용 경로를 유지합니다. 실제 스캔 길이가 31바이트를 넘고 오프셋이 2 이상이면 절대 바이트 28..31은 RSFX여야 합니다. 승인된 전체 검색에서 가장 큰 고대 마커 시작 위치는 4 MiB−19입니다. 후보는 오래된 네이티브 단일 64 KiB 반환으로 생긴 더 좁은 검색 범위를 복사하지 않고 승인된 짧은 읽기를 범위 내에서 채웁니다. 접두부는 실행하지 않습니다.
- Windows 레거시 Unicode의 보정되지 않은 상위 비트 구간은 검증된 signed-char에서 16비트 단위로의 부호 확장을 사용합니다. 보정된 구간은 하위 바이트 산술을 유지하며 둘을 혼합할 수 없습니다. Windows 이외는 로컬 ABI 및 wide 변환 실제 샘플을 확보할 때까지 보정되지 않은 상위 비트 구간에 Unsupported를 유지합니다. 공개 문자열은 여전히 유효한 스칼라여야 하며 공유 이름 보안 검사를 통과해야 합니다.

## 13/15 계열 후보 규격

- 13과 15는 각각 공개 UnpVer를 유지하면서 하나의 독립 적응형 디코더로 진입합니다. 창은 64 KiB로 고정되며 유한 정규 코드 테이블, 리터럴 순위, 거리 순위, 플래그 모델, Short 변형 및 특수 모드를 별도로 표현합니다. 이후의 차등 코드 길이 테이블을 재사용하거나 다른 Deflate/PPM 구현을 복사하지 않습니다.
- 첫 비솔리드 압축 파일은 이력과 통계를 재설정하고 이후 솔리드 압축 파일은 사전, 순위 및 일치 상태를 유지합니다. 각 파일은 여전히 비트 커서와 플래그/반복/특수 상태를 다시 초기화하며 이전에 남은 제어 비트나 특수 모드는 파일을 넘어갈 수 없습니다. Store는 압축 초기화를 호출하거나 압축 이력을 채우거나 지우지 않습니다.
- 실제 출력 전에 선언된 잔여 크기와 유효한 이력 거리를 검사하며 일치는 파일 끝을 넘을 수 없습니다. 실제 압축 해제 크기에 도달한 후 일반 입력 할당량과 취소를 유지하면서 호스트가 승인한 남은 압축 입력을 모두 소비합니다. 이 세대에 없는 현대 최종 블록 플래그를 만들어 내지 않습니다. 실제 비트가 부족하면 실패하며 0바이트로 채우지 않습니다.
- 제한된 일치와 최대 8 KiB 출력 배치에 대해 로컬 예산을 예약합니다. 성공과 실패 경로에서 실행된 바이트를 정산하며 실제 생성된 바이트만 일회성 전달 크레딧을 만듭니다. 오류는 압축 인스턴스를 오염시키며 명시적 리셋 후에만 새 독립 상태를 사용할 수 있습니다. 선행 상태가 없는 솔리드 시작점은 복구를 가정할 수 없습니다.

## 현대 비밀번호 및 무결성 후보 규격

- 평문 아카이브 암호화는 이 볼륨의 메인 헤더 앞에 한 번 나타날 수 있습니다. 이후 각 헤더는 자체 IV로 AES256-CBC를 다시 시작하고 첫 블록을 복호화해 실제 헤더 길이를 얻은 다음 해당 볼륨의 전체 IV 및 정렬된 암호문 범위를 검사합니다. 헤더 CRC는 실제 필드만 포함하며 정렬 꼬리는 extra로 파싱하지 않습니다. 비공개 물리 조각은 페이로드 재스캔 시 바이트 단위 검증을 위해 원래 IV와 암호문 헤더를 보존하며 동등한 복호화 메타데이터로 원본 식별을 대체할 수 없습니다.
- 동일한 PBKDF2-HMAC-SHA256 체인은 `2^L`, 이후 16회, 이후 다시 16회 반복하여 AES 키, 해시 키 및 접힌 검사값을 생성하며 `L<=24`입니다. 작업 전용 16슬롯 캐시와 누적 예산은 메타데이터 스캔에서 페이로드 객체까지 이어지며 파일이나 볼륨마다 재설정하지 않습니다. 기본 한도는 실제 HMAC 최대 `2^26`회와 파생 해시 입력 4 GiB입니다. 캐시 적중 시 재파생하지 않으며 취소 전에 수행된 작업은 환불하지 않습니다. 보수적인 16 KiB 캐시/임시 공간 예산은 알고리즘 메모리 사전 검사에 별도로 포함됩니다.
- 외부 비밀번호는 최대 UTF-8 4,096바이트이며 첫 U+0000에서 자르기 전에 이 한도를 검사합니다. 네이티브 호환 프로파일은 Windows에서 앞의 UTF-16 127단위, Unix에서 Unicode 스칼라 127개를 취한 뒤 파생 바이트를 만듭니다. Windows 절단 경계의 단독 서로게이트는 비공개 호환 바이트에만 존재하며 공개 str이나 이름에는 존재하지 않습니다. 이는 참조 호환 동작이지 형식 공통 규칙이 아닙니다. 비밀번호, 파생 중간값 및 키는 수명 종료 시 소거하지만 모든 OS 과거 복사본의 소거를 보장하지 않습니다.
- 검사 자체의 SHA256 체크섬이 유효하고 신뢰할 수 없는 전체 0 레거시 서비스 값이 아닐 때만 불일치를 WrongPassword로 반환합니다. 체크섬이 잘못되면 빠른 검사를 비활성화하며 올바른 키는 구조/콘텐츠 검증으로 여전히 성공할 수 있습니다. 신뢰할 수 있는 검증자 없는 Invalid/Integrity는 공개 PasswordOrIntegrity를 통해 모호한 상태로 남으며 확실한 잘못된 비밀번호로 부를 수 없습니다.
- 콘텐츠 CBC는 파일마다 재시작하고 승인된 분할 조각을 넘어 계속되며 블록은 한 조각의 끝과 다음 조각의 시작을 결합할 수 있습니다. 각 조각의 압축 CRC/BLAKE2sp는 항상 복호화 전 물리 암호문을 대상으로 하고 최종 콘텐츠 검사는 필터가 적용된 전체 평문을 대상으로 합니다. 현재 후보는 조각 체인 전체에서 완전한 암호화 매개변수가 동일해야 한다고 엄격히 요구하며 정상 샘플이 모든 과거 분할 인코딩의 동등성을 입증하지는 않습니다.
- Store는 압축 해제 크기에 따라 실제 콘텐츠를 선택하고 LZ는 완전한 마지막 블록과 유효 비트로 종료합니다. 뒤에는 최소 0..15바이트 정렬 꼬리만 허용하며 값은 제한하지 않고 PKCS7로 해석하지 않습니다. LZ 미리 읽기 버퍼는 꼬리 길이에 포함하며 외부 CBC 소비만으로는 부족합니다. 선언된 전체 암호문은 여전히 소비하고 입력으로 계산해야 합니다. 추가 전체 쓰레기 블록을 허용하는 참조 복구는 후보의 성공 범위 밖입니다.
- 공유 스트리밍 BLAKE2sp32 상태를 재사용합니다. 알려진 BLAKE2sp extra가 있으면 고정된 참조의 선택 의미에 따라 전체 폭 검사를 선택하고 기본 CRC 필드는 보존하되 둘 다 요구하지 않습니다. flag2가 키가 있는 조정을 선언하면 일반 CRC의 LE4에 HMAC을 적용하고 LE32 값 8개를 XOR하며 일반 BLAKE2sp32는 전체 HMAC32를 사용합니다. 암호화되어도 flag2가 없으면 조정하지 않습니다. 알 수 없는 해시는 Unsupported이며 CRC/검사값은 원본 진위를 입증하지 않습니다.

## RAR20/26 LZ 및 Audio 후보

20/26 계열은 사실만 담은 전달 자료 `RAR20-26-2026-10-26-v1`을 따르며 본문 SHA-256은 `d240cac882e8120eb5f20c7894395732b9798bd133479604ae79d5bde24b04d5`입니다. 구현자는 해당 UnRAR, Junrar 또는 기타 타사의 LZ/Audio 알고리즘 구현을 읽지 않았고 RAR 압축 인코더를 제공하지 않습니다. 원래 테스트 압축 파일, 알려진 WAV, 단언 및 라이선스는 독립 데이터 참조일 뿐입니다. 소스 검색 중 타사의 일반 압축 파일 식별 코드 요약이 우연히 반환되었지만 이 세대의 LZ/Audio 알고리즘을 포함하거나 구현에 영향을 주지 않았습니다. 이는 엄격한 클린룸 개발을 입증하지 않습니다.

20과 26은 원래의 엔트로피 및 Audio 상태 기계를 공유하며 제한된 공유 MSB 입력, 최대 1 MiB 링 이력 및 실제 출력 도우미로 디코딩합니다. 새 코드 길이 테이블은 바이트 정렬되지 않으며 완전히 구성한 후에만 커밋하고 1,028개 항목의 이전 기준값에서 건드리지 않은 값은 보존합니다. 범위를 벗어난 잘못된 반복은 엄격히 거부합니다. 최근 일치 4개는 중복 거리를 시간순으로 유지합니다. Audio는 실제 PCM 이력을 쓰는 예측 모드이며 1..4채널, 채널 간 차이, 32번째 샘플 이후 채널별 적응 및 -17..16 계수를 지원합니다. 모드/테이블 전환은 예측 상태를 지우지 않으며 비솔리드 리셋만 지웁니다.

컨테이너의 알려진 압축 해제 크기가 콘텐츠 경계를 결정하며 일치는 남은 크기를 초과할 수 없습니다. 이 세대에는 추가 필수 EOF 심볼이 없습니다. 크기에 도달한 뒤 후보는 현재 물리 바이트에서 실제 바이트가 최소 5개 남아야 한다는 안정된 규칙에 따라 심볼 하나를 관찰합니다. 다음 테이블 제어를 식별하면 이후 솔리드 파일을 위해 완전히 파싱하고 다른 심볼은 추가 콘텐츠나 PCM 갱신을 만들지 않습니다. 그런 다음 입력 오류, 취소 및 컨테이너 검증을 유지하면서 승인된 압축 범위를 완전히 비웁니다. 이는 명시적 레거시 꼬리 허용 정책이지 버퍼링의 영향을 받는 모든 참조 복구 동작과의 동등성이나 임의 꼬리를 유효 콘텐츠로 해석한다는 주장이 아닙니다. 실패 후 인스턴스는 오염 상태로 남으며 형식 리셋으로 실패 상태가 사라지지 않습니다.

레거시 초기화와 테이블 제어는 먼저 보조 작업을 예약하고 출력 크레딧 없이 실제 완료된 작업을 정산하며 실제 생성된 콘텐츠만 일회성 전달 크레딧을 만듭니다. 후보 메모리 사전 검사에는 보수적인 외부 288 MiB와 유지된 이력 용량이 포함되며 워커의 1 GiB 구현 예산 안에 있습니다. 이는 자원 정책이지 형식 제한이 아닙니다.

## 아직 닫히지 않은 호환성 조건

13/15, 20/26, RAR29 LZ/PPM/표준 필터, 과거 비밀번호 및 초기 체크섬의 후보 구현이 존재합니다. 각 과거 조합은 여전히 개별 실제 샘플과 전체 경로 검증이 필요합니다. 구성 요소나 작성자 압축 파일 하나의 통과가 전체 이전을 대체하지 않습니다. RAR7 유효 알고리즘 1의 독립적이고 성공적인 압축 샘플은 [#43](https://github.com/xiaodaozhi/xdzip/issues/43)에서 추적하며 고정된 출처, 전체 평문 및 워커/런타임 업무 경로를 각각 검증합니다. Store, 수학적 비트 벡터 및 호환 알고리즘 0 샘플은 대체물이 아닙니다. 각 필터의 독립 실제 샘플 범위를 별도로 기록하며 필터 코드의 존재는 검증을 입증하지 않습니다. 고정된 기존 UnRAR 기준은 레거시 표준 필터 여섯 개만 실행하며 과거 VM이라는 이름이 임의의 압축 파일 프로그램 해석기로 확장되지는 않습니다.

공개 `Entry.size_known`은 알 수 없는 크기와 알려진 빈 파일을 구분합니다. 전체 조각 체인의 알려진 크기가 일치하면 크기를 복원합니다. 크기를 전혀 알 수 없는 항목은 `size_known=false,size=0`으로 탐색 및 공개할 수 있으며 과거 내부 센티널 `0x7fffffff7fffffff`은 공개하지 않습니다. Native ROW `0x40`은 RAR 알 수 없는 크기 전용이며 size=0과 함께 사용해야 합니다. CAB의 `0x20` 의미를 보존하며 다른 형식이나 예약된 `0x80`은 거부합니다. 런타임과 Qt는 이 표시를 유지합니다. 알 수 없는 크기를 포함한 원시 크기와 선택 합계는 명시적인 알 수 없음 상태와 함께 `—`로 표시합니다. 크기 오름차순과 내림차순 모두 알 수 없는 항목을 알려진 항목 뒤에 놓고 물리적 식별로 동률을 안정적으로 정합니다. 사전 검사는 `unknown_size`와 알 수 없는 총계를 보고합니다. 전체 압축 파일 검사, 추출, 임시 열기 및 내보내기는 콘텐츠를 얻기 전에 거부하며 알 수 없음을 빈 파일로 취급하거나 디코딩/출력 할당량으로 사용하지 않습니다.

현대 Unix/FILETIME 타임스탬프는 완전한 비공개 값을 유지합니다. 공개 DOS 시간은 [호스트 달력 서비스](host-platform-services.md)를 통해 투영합니다. 직접 API의 기본값은 UTC이고 제품 워커는 해당 날짜의 로컬 규칙을 사용합니다. Rust는 과거 모듈러 산술, 128년 순환, 짝수 초 절단 및 비정상 소수 무시를 유지합니다. OS 투영 실패는 참조에서 확인하지 않은 시스템 실패의 정의되지 않은 결과와 달리 명시적 0입니다. 세 플랫폼의 전체 제품 증거는 별도로 검증합니다.

레거시 서비스 LARGE/확장 시간은 완전한 헤더 CRC, 필요한 32/40바이트 기준부, 이름, 64비트 압축 범위 및 예산이 통과한 뒤 범위 내에서 건너뛸 수 있습니다. 원래 꼬리는 해석하지 않은 데이터로 유지합니다. 솔트/시간 구획을 추측하거나 0으로 채운 비밀번호 매개변수를 만들고 일반 파일 시간을 바꾸거나 서비스 출력 또는 서비스 콘텐츠 인증을 제공하지 않습니다. 수학적 메타데이터 양성/음성 대조와 정상적인 독립 작성자 압축 파일은 별도로 기록하며 정상 대형 서비스 콘텐츠 샘플의 부재는 증거의 한계로 남습니다. 알려진 평문의 작성자 범위에는 고대 압축 분할 파일, RAR20 일반 및 Audio 솔리드, RAR20/RAR26 압축 분할 볼륨 및 실제 UnpVer26 2 GiB와 1바이트 파일이 포함됩니다. 이런 제한된 양성 사례가 모든 볼륨, 채널 또는 꼬리 테이블 전이의 검증을 입증하지는 않습니다. Windows 이외 레거시 Unicode의 보정되지 않은 상위 비트 구간, 과거 비ASCII 비밀번호 암호문 및 레거시 압축/Store 교차는 별도로 추적합니다. 수학적 컨테이너, OS 변환만의 결과 및 선언 버전 변경을 정상적인 작성자 상호 운용성으로 가장하지 않습니다.

현대 압축 파일은 현재 종료 레코드가 없으면 안전하게 실패하며 이전 형식은 레코드 경계의 정확한 EOF를 허용합니다. SFX 검색은 앞의 4 MiB로 제한하며 고대 경계는 위 규격을 따릅니다. 중복 보안 extra의 엄격한 거부 및 기타 잘못된 입력 정책이 공식 형식의 필수 조건이라고 주장하지 않습니다. 건너뛴 서비스 콘텐츠에는 전체 콘텐츠 무결성을 보장하지 않습니다. 호스트 원본 식별 검사는 최선의 노력을 유지하며 메타데이터 재스캔은 원자적인 입력 콘텐츠 스냅샷이 아닙니다.
