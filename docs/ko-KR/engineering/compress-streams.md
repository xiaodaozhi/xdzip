# Unix compress Z 계약

[English](../../engineering/compress-streams.md) | [简体中文](../../zh-CN/engineering/compress-streams.md) | [繁體中文（台灣）](../../zh-TW/engineering/compress-streams.md) | [日本語](../../ja-JP/engineering/compress-streams.md) | 한국어 | [Français](../../fr-FR/engineering/compress-streams.md) | [Deutsch](../../de-DE/engineering/compress-streams.md) | [Español](../../es-ES/engineering/compress-streams.md) | [Português (Brasil)](../../pt-BR/engineering/compress-streams.md) | [Русский](../../ru-RU/engineering/compress-streams.md)

이 계약은 독립적인 Rust LZW 리더의 바이트 형식과 단일 파일 및 TAR 조합을 정의합니다. 유틸리티의 역사와 9–16비트 사전 동작은 [OpenBSD compress(1)](https://man.openbsd.org/compress.1)과 [ncompress](https://vapier.github.io/ncompress/)를 따릅니다. POSIX는 전체 바이트 배치가 아니라 유틸리티를 규정합니다. 과거의 8코드 정렬과 9비트 호환성 차이는 [업스트림 논의](https://github.com/vapier/ncompress/issues/5)에 기록되어 있으며 내용이 알려진 독립 입력으로 확인합니다. 소스 관찰은 형식 규칙을 보완하며 Rust 구현은 참조 코드의 번역이 아닙니다.

<a name="xdzip-wire-and-dictionary-rules"></a>

## 바이트 형식과 사전 규칙

매직 바이트 `1F 9D` 뒤에 속성 바이트가 있어야 합니다. 비트 0–4는 최대 너비 9–16을 선언하고 비트 7은 블록 모드를 선택하며 예약 비트 5–6은 0이어야 합니다. 코드는 너비 9에서 시작하고 최하위 비트부터 저장합니다. 각 그룹은 최대 8개 코드를 포함하며 가득 차면 `width`바이트를 차지합니다. 너비 변경이나 CLEAR는 이전 그룹의 나머지를 버리고 새로 정렬된 그룹을 시작합니다. 과거 정렬 비트와 마지막 미사용 비트는 규정되지 않으며 0일 필요가 없습니다.

리터럴 코드는 0–255입니다. 블록 모드는 256을 CLEAR에 예약하고 새 사전 항목을 257부터 시작하며 비블록 모드는 256부터 시작합니다. CLEAR 뒤를 포함하여 리터럴로 시작합니다. 새 문자열은 이전 문자열 뒤에 현재 문자열의 첫 바이트를 붙여 재구성합니다. 다음 미정의 코드는 이전 문자열 뒤에 그 첫 바이트를 붙이는 일반적인 특수한 경우에만 허용합니다. 더 큰 코드와 그 밖의 미정의 코드는 거부합니다. 사전의 부모는 이전 항목이며 출력 전에 모든 역방향 확장을 제한합니다. 다음 사전 인덱스가 `2^width`에 도달하면 선언된 최댓값 미만인 경우 다음 코드 전에 너비를 늘립니다. 용량이 가득 차면 CLEAR 또는 EOF까지 사전을 유지합니다. CLEAR는 너비와 사전 점유 상태를 초기화하며 첫 코드가 되거나 리터럴 없이 반복되거나 뒤따르는 리터럴 없이 파일을 끝낼 수 없습니다.

3바이트 헤더만 있으면 빈 스트림입니다. 비어 있지 않은 마지막 그룹에는 완전한 코드가 있어야 하며 마지막 완전한 코드 뒤에는 8비트 미만의 미사용 비트가 남을 수 있습니다. 남은 한 바이트 전체를 차지하는 불완전한 코드는 유효하지 않습니다. 명시적 EOF 코드나 원래 크기, 파일 이름, 타임스탬프, 체크섬, 인증 필드가 없습니다. 추가 바이트는 코드로 해석합니다. 구조를 보존하는 임의의 변경이나 그 자체로 유효한 코드를 이루는 꼬리는 내용과 항상 구분할 수 없습니다. 연결된 멤버 지원이나 손상된 과거 스트림 복구는 보장하지 않습니다.

포화된 9비트 사전에서는 선언된 최대 너비를 따릅니다. 고정된 ncompress 1.0.2는 프로젝트 소유의 포화 9비트 입력을 완전히 디코딩하지만 고정된 7-Zip 26.06 참조 구현은 처음 256바이트를 디코딩한 뒤 데이터 오류로 중단됩니다. 이는 참조 구현의 제한으로 기록하며 7-Zip 검증 성공으로 간주하지 않습니다. 짧은 9비트, 강제 CLEAR, 비블록 벡터는 둘 다 독립적으로 수용합니다. 잘못된 과거 `-b9` 출력을 다른 너비 정책으로 조용히 다시 파싱하지 않습니다.

<a name="xdzip-admission-and-host-integration"></a>

## 허용과 호스트 통합

사전을 할당하기 전에 u16 부모, 바이트 접미부, 제한된 역방향 확장, 입력 버퍼, 고정 상태를 위한 `4 * 2^max_bits + 8192 + 512`바이트를 허용합니다. 유효하지 않은 속성과 부족한 메모리는 테이블을 할당하기 전에 거부합니다. 기본 작업에는 별도의 엄격한 상한인 96 GiB 단위가 있습니다. 각 코드, 역방향 확장 바이트, 사전 삽입, 전달 바이트를 계산하고 예산을 초과하기 전에 실패합니다. 호스트에서 취소할 수 있도록 기본 읽기당 최대 8192바이트를 반환합니다. 형식화된 소스 오류는 종료 오류로 남고 처음 전파할 때 원래 내용을 보존합니다. 제어된 필터는 이후 호출에도 안정적인 실패를 유지합니다.

형식 통합은 기존 제어 스트림, 파일 이름, 작업 계약을 사용합니다. 소스 바이트와 디코딩 바이트에는 별도의 공통 상한이 있고 TAR 조합은 전체 레코드 스트림과 꼬리도 검증합니다. `.z`는 일반 파일 후보이고 `.tar.z`와 `.taz`는 TAR 후보입니다. 디코딩 바이트에서 실제 TAR 헤더를 감지하고 같은 필터의 파일 이름 힌트는 이미 검증된 전체 0 내용의 일반 파일/TAR 모호성에만 유지합니다. 힌트는 경로 접근 권한을 주지 않으며 손상된 TAR 헤더를 숨길 수 없습니다. 스트림에 출력 이름이 없으므로 가상 이름은 허용된 기본 이름 정책만 사용합니다. LZW 읽기 방식 식별자는 이 컨테이너에 한정되며 ZIP이나 생성 기능을 부여하지 않습니다.

찾아보기, 검사, 추출 통합은 불변의 물리적 식별성, 고정된 소스, 실제 바이트 예산, 취소, 준비 및 호스트 게시를 보존해야 합니다. Z와 TAR.Z 검사는 구조와 읽기 가능성을 확인합니다. 이 형식에는 내용 체크섬이 없습니다. 지원하지 않는 헤더, 유효하지 않은 사전, 잘못된 그룹, 할당량 실패, 소스 변경, 출력 대상 오류를 성공적인 EOF로 처리해서는 안 됩니다. TAR.Z 편집은 표준 블록 모드 스트림을 재구성하고 이른 CLEAR를 사용해 9비트 코드를 유지합니다.

<a name="xdzip-independent-inputs-and-automated-acceptance"></a>

## 독립 입력과 자동 승인

프로젝트 소유 생성기는 `build/toolchain/`에 ncompress 1.0.2와 7-Zip 26.06 참조 구현의 식별 정보를 고정합니다. 둘 다 제품 의존성에는 포함되지 않습니다. 참조 구현이 생성한 입력에는 실제 일치, 빈 스트림과 0 스트림, 전체 너비까지의 증가, 자연스러운 CLEAR 및 TAR이 포함됩니다. 추가 자체 교과서 LZW와 코드 패킹 입력은 모든 최대 너비, 가득 찬 사전, 비블록 모드, 명시적 초기화 및 미정의 코드 특수 사례를 다룹니다. 고정된 ncompress는 모든 입력을 완전히 디코딩하며 고정된 7-Zip도 포화 9비트를 제외한 모든 입력을 완전히 디코딩합니다. 이 차이를 명시적으로 기록합니다.

회귀 검사는 정확한 메모리와 작업 예산, 짧은 읽기, 재시도 가능한 단순 중단과 종료되는 형식화된 중단, 유효하지 않은 초기 코드와 전방 코드, 예약 속성, 불완전한 그룹, 마지막 CLEAR, 규정되지 않은 패딩을 다룹니다. 형식 등록에는 실제 runtime/CLI/Qt 찾아보기, 검사, 추출과 전체 0 모호성, 읽기 전용 및 검사 강도 설명, 시스템 후보, 이중 언어와 테마 및 글꼴 크기 레이아웃, 기본 창과 메뉴의 공동 측정도 필요합니다. 진행과 실제 승인은 납품 issue에 기록하고 생성된 증거는 `build/` 또는 CI에 보관합니다.
