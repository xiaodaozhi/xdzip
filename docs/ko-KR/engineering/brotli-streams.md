# 일반 Brotli 스트림 계약

[English](../../engineering/brotli-streams.md) | [简体中文](../../zh-CN/engineering/brotli-streams.md) | [繁體中文](../../zh-TW/engineering/brotli-streams.md) | [日本語](../../ja-JP/engineering/brotli-streams.md) | 한국어 | [Français](../../fr-FR/engineering/brotli-streams.md) | [Deutsch](../../de-DE/engineering/brotli-streams.md) | [Español](../../es-ES/engineering/brotli-streams.md) | [Português (Brasil)](../../pt-BR/engineering/brotli-streams.md) | [Русский](../../ru-RU/engineering/brotli-streams.md)

`xdzip-compression::BrotliReader`는 일반 RFC 7932 Brotli 스트림 하나를 독립적으로 디코딩합니다. 호출자가 소유한 `Read` 권한과 허용된 압축 범위를 받으며 파일 이름, 파일 시스템, 네트워크, 프로세스 또는 출력 게시 권한은 없습니다. 제품은 [형식 레지스트리](format-registry.md)에 Brotli(`.br`)와 TAR.BR(`.tar.br`)을 등록합니다. 둘 다 공통 호스트의 소스, 작업, 할당량, 임시 준비와 게시 규칙을 사용하여 탐색, 미리 보기, 검사와 선택 항목 추출을 지원합니다. 조건에 맞는 기존 TAR.BR은 표준 비압축 메타블록으로 다시 써서 편집할 수 있습니다. 두 프로파일 모두 새 압축 파일 생성이나 분할 볼륨을 지원하지 않습니다. [압축 TAR 다시 쓰기](single-file-streams.md#xdzip-rewriting-compressed-tar-archives)를 참조하세요.

<a name="xdzip-wire-profile"></a>

## 스트림 프로파일

리더는 표준 윈도 선언 10–24, 압축, 비압축 및 메타데이터 메타블록, 단순 및 복합 정준 접두사 코드, 연결된 코드 길이 반복, 세 가지 블록 전환 범주, 네 가지 리터럴 컨텍스트, RLE 및 역 MTF 컨텍스트 맵, 명시적, 최근, 직접 및 접미 거리와 겹치는 기록 복사를 모두 허용합니다. 사전 복사는 규범 단어 길이 4–24와 121개의 모든 바이트 변환을 적용하며 0바이트를 생성하는 변환도 포함합니다. 최근 거리는 메타블록 사이에 유지되고 적격 기록 참조에서만 갱신됩니다. 원시 바이트, 사전 바이트와 기록 복사는 모두 리터럴 컨텍스트를 갱신합니다.

출처는 [RFC 7932](https://www.rfc-editor.org/rfc/rfc7932.txt), SHA-256 `394abd1879e016f4eac89512c2acaf92f7b2d67feb8ab58b6b118c213be07146`입니다. 검증된 [정오표 5948](https://www.rfc-editor.org/errata/eid5948)은 3.5절의 편집상 오타를 수정합니다. [RFC 9841](https://www.rfc-editor.org/rfc/rfc9841.html)은 공유 사전, 큰 윈도와 별도 컨테이너를 추가하지만 이 확장은 일반 스트림 프로파일 밖입니다. 예약된 확장 윈도 패턴은 지원하지 않는 것으로 보고합니다. 외부 사전은 검색하거나 가져오지 않습니다.

정확히 하나의 스트림은 유효한 0 채움으로 끝나고 허용된 바이트 범위를 소비해야 합니다. 비정준 길이 필드, 예약 메타데이터 비트, 유효하지 않거나 초과 할당되거나 불완전한 트리, 반복된 기호, 맵이나 유형의 빈틈, 유효하지 않은 거리나 변환 및 블록 밖 출력은 실패합니다. 이 프로파일은 연결, 뒤따르는 바이트와 잘린 스트림을 거부합니다. Brotli에는 내용 체크섬, 전체 스트림의 디코딩 크기 선언, 암호화, 멤버 경로 또는 타임스탬프가 없습니다. 디코딩 성공은 허용된 구조, 선언된 메타블록 크기와 읽기 가능성을 확인할 뿐이며 변경 후에도 유효한 스트림이면 손상으로 감지할 수 없습니다.

<a name="xdzip-product-discovery-and-presentation"></a>

## 제품의 탐지와 표시

Brotli에는 고정 매직이 없습니다. 강한 소스 시그니처, 유효한 일반 TAR 메타데이터와 ZIP/SFX 탐지가 우선합니다. 남은 헤더 없는 경로에서 제한된 Brotli 접두사는 일반 또는 TAR 조합을 후보로 제안하며 형식이나 행을 게시하기 전에 전체 메타데이터 검사로 스트림 전체를 검증해야 합니다. 일반 후보가 실패하면 기존 LZMA Alone 후보로 진행할 수 있습니다. Brotli 디코딩 후 인식된 TAR 헤더는 우선 결정 근거이므로 TAR 파싱 실패가 일반 파일이나 LZMA 성공이 될 수 없습니다. 압축 바이트의 검증되지 않은 원시 TAR 표식은 완전히 유효한 Brotli 허용으로만 구분하며 후보가 유효하지 않으면 원래 TAR 실패를 보존합니다. 소스, 취소와 리소스 오류는 종료 오류입니다.

하나의 24 GiB 실제 읽기 장부가 Brotli/LZMA 후보 조사와 반복 메타데이터 읽기를 모두 포함하며 후보 사이에 반환하지 않습니다. 다른 강한 형식과 텍스트 외피 탐지는 기존의 별도 한도를 유지합니다. 1바이트 빈 Brotli 스트림은 허용하지만 빈 물리 파일은 유효하지 않습니다. 파일 이름 접미사는 후보를 검증하지 않습니다. 전체 검증 후 같은 필터의 `.br` 또는 `.tar.br` 힌트만 1024바이트 이상인 전체 0 출력의 모호성을 해결합니다. 관계없는 힌트는 빈 TAR 기본값을 유지합니다. 실제 TAR 헤더는 일반 접미사보다 우선합니다.

일반 Brotli는 호스트에서 얻은 안전한 기본 이름, 알려진 디코딩 크기와 전체 물리 압축 크기를 가진 일반 가상 파일 하나로 표시합니다. TAR.BR은 TAR 물리 항목 신원을 유지하며 하위 항목의 압축 크기는 알 수 없습니다. 둘 다 실제 Brotli 방식과 구조 검사 설명을 표시하고 체크섬이 있다고 암시하지 않습니다. 일반 압축 파일 그림을 재사용하며 기존 MIME 선언 `application/x-brotli`가 일반 셸 후보를 제공합니다.

<a name="xdzip-resource-and-control-rules"></a>

## 리소스와 제어

기록을 할당하기 전에 `(1 << window_bits) + 2 MiB`를 허용합니다. 두 번째 항은 제한된 접두사 기호, 블록과 컨텍스트 벡터, 입력 버퍼와 고정 상태를 보수적으로 포함하며 선언된 각 개수도 독립적으로 제한합니다. 범주마다 최대 256개 블록 유형 또는 컨텍스트 트리가 있습니다. 리터럴 맵은 최대 16384개, 거리 맵은 1024개 항목이며 접두사 알파벳은 최대 704개 기호입니다. 정적 규범 데이터는 외부 I/O 권한을 주지 않습니다.

압축 입력과 누적 출력은 각각 엄격한 24 GiB 한도를 가지며 호출자가 더 줄일 수 있습니다. 실제 비트 파싱, 접두사 구성, 기호와 반복 확장, 컨텍스트 MTF 이동 및 출력은 최대 96 GiB 단위인 하나의 누적 작업 장부를 소비하며 실패해도 반환하지 않습니다. 메타블록 출력 선언은 디코딩 전에 허용되며 호출자 할당량을 늘리지 않습니다. 읽기 호출은 최대 8192 디코딩 바이트를 반환합니다. `with_poll`은 헤더나 출력 없는 작업을 포함해 제한된 작업 간격마다 권한 없는 협력 콜백을 호출하므로 취소가 추가 소스 바이트 필요 여부에 의존하지 않습니다. 콜백, 소스 및 할당량 오류는 종료 오류입니다. 단순 중단 읽기만 재시도하며 형식화된 중단은 오류 객체를 유지하고 편의 메서드로 재시도하지 않습니다.

호출자는 EOF까지 읽고 성공할 때까지 출력을 비공개로 유지해야 합니다. 나중에 발생한 오류는 이전 청크를 무효화하며 프리미티브는 이를 게시하지 않습니다. 실패한 리더는 재개할 수 없습니다. 협력 제어는 차단된 하위 운영체제 읽기를 중단할 수 없습니다. 소스 고정과 최종 게시는 호스트의 책임입니다.

<a name="xdzip-normative-data-and-validation"></a>

## 규범 데이터와 검증

정적 사전과 세 컨텍스트 표는 고정된 RFC에서 직접 추출하고 모든 규범 길이와 CRC를 검사합니다. 단어 깊이와 변환 식별자도 검증합니다. [데이터 출처와 라이선스](../../../third_party/brotli-rfc7932/README.md)는 이 표준 상수를 다루며 Brotli 참조 구현은 링크하지 않습니다. 소스와 배포 고지에 IETF 개정 BSD 고지를 유지합니다. 데스크톱과 CLI 고지 수집 진입점은 Cargo 의존성 및 참조 런타임과 별도로 이를 수집합니다.

[자체 테스트 데이터](../../../tests/fixtures/brotli/README.md)는 생성하거나 독립적으로 구성한 뒤 고정된 작성자 디코더로 바이트 단위 검사합니다. 품질, 윈도, 컨텍스트에 따른 실제 출력, 블록 전환, 거리 매개변수, 모든 규범 변환과 메타데이터 및 원시 블록을 포함합니다. 정확한 할당량, 잘림, 채움, 짧은 입력, 형식화된 오류, 작업 폴링과 결정적 변형이 상호 운용 사례를 보완합니다. 참조 도구는 `build/toolchain/`, 증거는 `build/` 또는 CI에 보관합니다. [승인 요구 사항](../../../developers/qa/acceptance.md)의 `FORMAT-BROTLI`는 프리미티브 테스트와 별도로 제품 통합을 규정합니다.
