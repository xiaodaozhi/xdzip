# 디스크 이미지와 기타 압축 형식의 소스 및 라이선스

[English](../../engineering/disk-image-archive-format-sources.md) | [简体中文](../../zh-CN/engineering/disk-image-archive-format-sources.md) | [繁體中文](../../zh-TW/engineering/disk-image-archive-format-sources.md) | [日本語](../../ja-JP/engineering/disk-image-archive-format-sources.md) | 한국어 | [Français](../../fr-FR/engineering/disk-image-archive-format-sources.md) | [Deutsch](../../de-DE/engineering/disk-image-archive-format-sources.md) | [Español](../../es-ES/engineering/disk-image-archive-format-sources.md) | [Português (Brasil)](../../pt-BR/engineering/disk-image-archive-format-sources.md) | [Русский](../../ru-RU/engineering/disk-image-archive-format-sources.md)

이 페이지는 DAA, ISZ, ZPAQ, PEA, BOND, J2J와 관련 형식의 공개 기술 자료, 라이선스 제한과 지원 요건을 설명합니다. 공개 형식 설명이 디코더 배포 권한을 부여하지 않으며 참조 구현도 반드시 재배포 가능한 제품 의존성은 아닙니다. 아래 참조는 어느 것도 xdzip에 링크되지 않습니다. 형식이 제품 레지스트리에 들어가기 전에 소스 리비전, 라이선스 텍스트, 완전한 테스트 자료, 리소스 제한, 실패 동작을 확정해야 합니다.

<a name="xdzip-daa-10"></a>

## DAA 1.0

- **공개 명세:** 공급업체가 공개한 DAA 1.0 명세는 찾지 못했습니다. 공개 설명은 DAA를 PowerISO의 독점 디스크/압축 이미지로 식별하고 헤더, 청크 길이 테이블과 독립적으로 압축된 ISO 청크를 설명합니다. 공개 기록은 zlib와 LZMA 변형 및 110 같은 이후 내부 버전을 다루지만 안정적인 1.0 계약을 정의하지 않습니다.
- **참조 구현:** `daa2iso` 0.1.7e, Debian/Fedora GPL-2.0-or-later 패키지입니다. 소스는 과거 연구에만 유용합니다. 현재 권위 있는 공개 저장소에서 업스트림 Git 커밋이나 공급업체 명세를 고정할 수 없습니다.
- **라이선스와 재배포:** 구현은 GPL-2.0-or-later입니다. 구현 라이선스는 독점 DAA 기술에 대한 권리를 부여하지 않으며 프로젝트에는 xdzip으로 디코더를 제공할 독립 허가 기록이 없습니다.
- **완전한 샘플:** 공개 샘플은 출처와 버전이 고정되지 않은 디스크 이미지나 다중 파트 압축 파일인 경우가 많습니다. 구형 헤더, 버전 110, 다중 파트 순서, zlib, LZMA, 난독화, 체크섬, 잘못된 청크를 다루는 재배포 가능한 코퍼스는 현재 허용되지 않았습니다.
- **클린룸 실현 가능성:** 안정적인 데이터 형식 기록과 법적 결정 이후에는 제한된 ISO 재구성이 기술적으로 가능할 수 있습니다. GPL 디코더만 역분석하는 것은 제품 구현 증거로 충분하지 않습니다.
- **기능 범위:** 제품 결정으로 영구 미지원입니다. DAA 탐지기, 코덱, 레지스트리 항목, MIME, 연결, 판독기나 기록기를 추가하지 않습니다. 과거 연구는 향후 허용을 승인하지 않습니다.
- **결론:** **제품 결정으로 영구 제외.** xdzip은 DAA 지원을 추진하지 않습니다. 위 소스, 라이선스와 샘플 결과는 과거 연구로 남으며 미해결 제공 조건이 아닙니다.

<a name="xdzip-isz"></a>

## ISZ

- **공개 명세:** EZB Systems의 *ISZ File Format Specification* 버전 1.00, 2006-07-03 개정판은 `IsZ!` 시그니처, 고정 헤더, 선택적 세그먼트 정의 테이블, 청크 정의 테이블과 데이터 블록을 문서화합니다. 헤더 필드는 섹터 크기와 총수, 암호 모드, 세그먼트 크기, 블록 수와 크기, 포인터 길이, 세그먼트 번호, 테이블과 데이터 오프셋을 포함합니다. 청크 플래그는 0, 저장, zlib, BZip2 블록을 구분합니다. 명세는 [ImgBurn 포럼 사본](https://forum.imgburn.com/topic/14260-isz-images-supporting/#comment-115553)에 재현되어 있습니다.
- **참조 구현:** CDEmu `libmirage` ISZ 필터 커밋 `39fcffe09739e1dc40bef4781646f9ffb8b7dc4e`와 Play- `IszImageStream` 커밋 `5bb010f27d8e2309f37b1f8eba0f74ecd546b29b`입니다. 둘 다 참조 분석 자료로만 사용합니다. `Helias/isz-tool`은 Python 판독기지만 이 환경에서 권위 있는 불변 커밋과 라이선스 기록을 얻지 못했습니다.
- **라이선스와 재배포:** EZB 명세 8절은 제품에 ISZ 기술을 포함하려면 EZB에 연락해 조건이 있는 무료 라이선스를 받아야 한다고 설명합니다. 공개 텍스트나 허용적인 라이선스의 독립 판독기가 있다고 해서 제품 라이선스 조건이 면제되지 않습니다. CDEmu와 Play-는 xdzip 의존성이 아닙니다.
- **완전한 샘플:** 공개 도구로 유효한 Store, zlib, BZip2 블록을 만들 수 있지만 완전한 재배포 가능 매트릭스에는 단일 볼륨 및 세그먼트 이미지, 0 블록, 모든 포인터 길이, 정확한 마지막 블록, 암호 모드, 테이블 난독화, 잘림, 오프셋, 원본 변경 사례도 필요합니다. 현재 그런 자체 코퍼스는 저장소에 기록되지 않았습니다.
- **클린룸 실현 가능성:** 암호화되지 않은 단일 볼륨 읽기 전용 부분은 기술적으로 ISO 탐색과 분리할 수 있습니다. 초기 구현은 문서화된 네 블록 종류를 하나의 가상 `image.iso` 출력으로 디코딩하되 마운트하거나 부팅을 실행하지 않을 수 있습니다. 그러나 법적 허가, 불변 참조 고정, 완전한 테스트 자료가 코딩에 앞서야 합니다.
- **기능 범위:** 조건을 통과하기 전에는 `.isz`를 등록하거나 `IsZ!`에서 지원을 추론하거나 암호, AES, 세그먼트 분할, 쓰기, 직접 광학 이미지 탐색을 제공하지 않습니다. 나중에 허용한다면 디코더는 헤더/버전, 포인터 및 세그먼트 테이블, XOR/난독화 해제 규칙, 블록/데이터 범위, 논리 크기 산술, 완전한 블록 종료, 취소, 입력/작업/출력 제한을 검증해야 합니다.
- **결론:** **제품 결정으로 제외.** xdzip은 이 작업 패키지에서 ISZ 지원을 추진하거나 제품 라이선스를 위해 EZB에 연락하지 않습니다. 결정을 재검토하지 않으면 `.isz` 탐지기나 레지스트리 항목을 추가할 수 없습니다.

<a name="xdzip-zpaq"></a>

## ZPAQ

- **공개 명세:** Matt Mahoney의 *The ZPAQ Open Standard Format for Highly Compressed Data* 버전 2.03과 2.06입니다. 형식은 ZPAQL 바이트코드로 압축 해제 프로그램을 저장하고 솔리드 블록, 저널링, 중복 제거, SHA-1 레코드, 이후 레벨의 암호화와 다중 파트 압축 파일을 지원합니다.
- **참조 구현:** `zpaq/zpaq` 태그 `6.22`와 해당 `libzpaq` 소스입니다. 이 태그는 본 평가의 고정 연구 참조이며 구현 작업 전에 커밋 해시와 라이선스 텍스트 해시를 기록해야 합니다.
- **라이선스와 재배포:** 참조 구현과 설정 파일은 GPLv3입니다. 타사 압축 런타임을 사용하지 않는 정책에 따라 현재 제품에 링크할 수 없습니다. 공개 표준은 클린룸 분석을 지원하지만 디코더 가상 머신과 설정 코퍼스에는 별도의 구현과 검토가 필요합니다.
- **완전한 샘플:** 유용한 코퍼스는 레벨 1과 2 블록, 임의 ZPAQL 프로그램, 저널 업데이트, 중복 제거, 암호화 및 다중 파트 레코드, SHA-1 검증, 잘못된 VM 또는 블록 경계를 다뤄야 합니다. 저장소에 그런 자체 코퍼스는 없습니다.
- **클린룸 실현 가능성:** 이론상 가능하지만 작은 컨테이너 파서가 아니라 가상 머신과 리소스 계량 프로젝트입니다. 안전한 제한은 바이트코드 해석, 모델 메모리, 압축 해제 출력, 기록과 중복 제거 상태를 계량해야 합니다.
- **기능 범위:** 향후 첫 부분은 읽기 전용, 비암호화, 비다중 파트, 비저널 방식이며 VM 부분 집합을 선언합니다. 생성, 업데이트, 암호 처리, 무제한 솔리드 추출을 의미하지 않습니다.
- **결론:** **제품 결정으로 제외.** xdzip은 ZPAQL 가상 머신을 구현하지 않고 이에 의존하는 ZPAQ 프로필을 허용하지 않습니다. 결정을 재검토하지 않으면 `.zpaq` 탐지기나 레지스트리 항목을 추가할 수 없습니다.

<a name="xdzip-pea"></a>

## PEA

- **공개 명세:** PeaZip의 *Pack, Encrypt, Authenticate* 명세는 PEA 1.x와 아직 제안 단계인 PEA 2.0, 스트림, 볼륨 및 객체 제어, 종료 표식, PCOMPRESS 수준을 다룹니다. 명세는 [`pea_help.pdf`](https://peazip.github.io/pea_help.pdf)로 공개되고 [pea-file-format.html](https://peazip.github.io/pea-file-format.html)에 요약되어 있습니다. 현재 공식 페이지는 PEA와 PCOMPRESS 명세를 명시적으로 퍼블릭 도메인에 공개합니다.
- **참조 구현:** `peazip/PeaZip` 커밋 `81b31f7e487b462980a52ac0f2e0b3cf700fe799`이며 `peazip-sources/dev/pea_utils.pas`와 `unit_pea.pas`를 포함합니다. 구현은 LGPLv3이고 포함된 Wolfgang Ehrhardt 암호화 유닛은 zlib/libpng 라이선스를 사용합니다. 소스 릴리스 URL은 [peazip-11.4.0.src.zip](https://github.com/peazip/PeaZip/releases/download/11.4.0/peazip-11.4.0.src.zip)입니다. 고정 소스는 참조 분석 자료로만 사용합니다.
- **라이선스와 재배포:** 형식 명세 자체에는 제품 라이선스 장애가 없지만 LGPLv3 엔진과 암호화 의존성을 현재 제품에 기본적으로 복사하거나 링크할 수 없습니다. 클린룸 Rust 구현은 퍼블릭 도메인 형식 기록과 독립적으로 선택한 알고리즘을 사용해야 하며 참조 바이너리는 테스트 전용입니다.
- **완전한 샘플:** 허용된 프로필에는 파일, 디렉터리, 유효한 UTF-8 이름, 빈 데이터와 비어 있지 않은 데이터, 잘림, 후행 바이트, 원본 변경과 제한을 다루는 자체 작성 완전 Store 테스트 자료가 있습니다. 더 넓은 코퍼스에는 PEA 1.x와 2.0, 여러 스트림, 볼륨 경계, PCOMP 수준, 인증 실패, 암호화 헤더, 잘못된 종료 표식, 큰 선언 크기가 필요하며 이 프로필은 제품 범위 밖입니다.
- **클린룸 실현 가능성:** 암호화되지 않은 단일 스트림 Store/Deflate 판독기는 기술적으로 가능하지만 인증과 암호화는 별도 보안 작업으로 다뤄야 합니다. 이 형식의 무결성 설계상 구조 파싱만으로 콘텐츠 검증을 주장할 수 없습니다.
- **기능 범위:** 향후 허용은 먼저 읽기 전용으로 하고 암호, 암호화, 다중 볼륨, 생성, 수정을 제공하지 않습니다. 추출한 각 스트림은 게시 전에 선언된 다이제스트와 종료 인증 검사를 통과해야 합니다.
- **결론:** **보수적 읽기 전용 프로필로 허용됨.** xdzip은 현재 PEA 1.x, 물리 볼륨 하나, UTF-8 이름, PCOMPRESS0 저장 파일/디렉터리를 허용하며 객체, 스트림, 볼륨 검사는 하지 않습니다. 암호, 인증/암호화 스트림, 체크섬 알고리즘, PCOMPRESS1–3, 분할 볼륨, PEA 2.0, 생성과 수정은 지원하지 않습니다. LGPL 참조는 테스트 전용이며 제품에 링크하지 않습니다.

<a name="xdzip-bond"></a>

## BOND

- **공개 명세:** Bandizip BOND 압축 형식의 명세, 시그니처, 버전이나 압축 계약을 찾지 못했습니다. 최근 Bandizip 릴리스 노트는 “일부 BOND 파일”의 취약점을 언급하지만 데이터 형식 정의는 아닙니다. 공개 `.bond` 확장자 데이터베이스는 주로 다른 직렬화 형식인 Microsoft Bond 스키마 데이터를 설명합니다.
- **참조 구현:** 권위 있는 압축 형식 식별, 고정 리비전과 재배포 가능 라이선스를 가진 구현을 찾지 못했습니다.
- **라이선스와 재배포:** 알 수 없습니다. 형식 소유자, 기술 권리와 참조 조건을 모르는 동안 제품이나 디코더를 허용할 수 없습니다.
- **완전한 샘플:** 신뢰할 수 있는 버전 관리 소스의 샘플은 없습니다. 파일 확장자만으로는 허용 가능한 테스트 자료의 식별이 되지 않습니다.
- **클린룸 실현 가능성:** 시그니처와 압축 파일을 Microsoft Bond 데이터 또는 다른 바이너리 페이로드와 구별할 충분한 완전 샘플이 없으면 평가할 수 없습니다.
- **기능 범위:** 탐지, 확장자 등록, 탐색, 추출, 검사, 생성, 암호, 분할을 지원하지 않습니다.
- **결론:** **제품 결정으로 제외되었으며 Bandizip 압축 형식인지 확인되지 않음.** 이 작업 패키지에서는 `.bond` 탐지기나 레지스트리 항목을 추가하지 않습니다.

<a name="xdzip-j2j"></a>

## J2J

- **공개 명세:** J2J 압축 형식의 명세, 시그니처, 버전이나 개발자 기록을 찾지 못했습니다. 과거 Bandizip 기능 목록에는 J2J가 추출 전용으로 언급되지만 현재 공식 형식 페이지에는 기술적 정의가 없습니다. 다른 J2J 검색 결과는 관련 없는 job-to-job 데이터 집합이나 JPEG-to-JPEG 도구를 설명합니다.
- **참조 구현:** 고정 리비전과 라이선스를 갖고 Bandizip 압축 판독기와 연결할 수 있는 구현이 없습니다.
- **라이선스와 재배포:** 알 수 없습니다. 타사 확장자 페이지와 과거 소프트웨어 목록은 라이선스 허가가 아닙니다.
- **완전한 샘플:** 저장소에는 신뢰할 수 있고 재배포 가능한 샘플 매트릭스가 없습니다. `.j2j` 이름만으로 컨테이너 식별을 확정할 수 없습니다.
- **클린룸 실현 가능성:** 시그니처, 레코드 모델, 압축/암호화 동작이 문서화되고 완전한 코퍼스가 제공되기 전에는 평가할 수 없습니다.
- **기능 범위:** 탐지, 확장자 등록, 탐색, 추출, 검사, 생성, 암호, 분할을 지원하지 않습니다.
- **결론:** **제품 결정으로 제외되었으며 Bandizip 압축 형식인지 확인되지 않음.** 이 작업 패키지에서는 `.j2j` 탐지기나 레지스트리 항목을 추가하지 않습니다.

## 형식 지원 요건

1. 권위 있는 명세 또는 법적 검토를 거친 클린룸 프로토콜을 기록합니다. 블로그, 확장자 데이터베이스 또는 디코더 소스만으로는 충분하지 않습니다.
2. 각 연구 소스를 불변 커밋 또는 콘텐츠 해시에 고정하고 해당 라이선스 텍스트를 기록합니다.
3. 지원을 주장하는 각 방식, 버전, 볼륨 모드, 암호화 상태, 종료 조건에 대해 완전하고 재배포 가능한 테스트 자료 매트릭스를 만듭니다. 헤더 전용이나 Store 전용 샘플은 상호 운용성을 증명할 수 없습니다.
4. 입력 읽기, 메타데이터, 압축 해제 작업, 메모리, 논리 출력, 기록, 암호화 상태, 취소에 대해 제한된 리소스 모델을 정의합니다. 게시 전에 잘못된 오프셋, 순환, 오버플로와 원본 변경을 거부합니다.
5. 각 디코더를 Qt, 마운트, 부팅, 설치 프로그램, 스크립트, 레지스트리와 임의 프로세스 실행 API로부터 독립시킵니다.
6. 코덱, 스냅샷 식별 정보, 정확한 페이로드 동작, 실패 분류가 대상 자동 검사를 통과한 뒤에만 runtime, CLI, 연결과 사용자 문서를 연결합니다.
7. 차단된 후보는 평가에서도 차단 상태로 유지합니다. Bandizip이나 타사 목록에 이름이 있다는 이유만으로 확장자, MIME 항목이나 제품 기능을 부여해서는 안 됩니다.

저장소 검사 `python scripts/test-m10-source-gates.py`는 여섯 개의 이중 언어 섹션이 필요한 증거 필드를 유지하고 각 결론이 차단, 제외 또는 허용으로 명시되며 차단 또는 제외된 후보가 `specs/engineering/archive-formats.json`에 들어가지 않았는지 확인합니다.
