# 앱 세션과 종료 계약

[English](../../engineering/application-sessions.md) | [简体中文](../../zh-CN/engineering/application-sessions.md) | [繁體中文](../../zh-TW/engineering/application-sessions.md) | [日本語](../../ja-JP/engineering/application-sessions.md) | 한국어 | [Français](../../fr-FR/engineering/application-sessions.md)

탭 컨텍스트 메뉴는 “닫기”, “다른 탭 닫기”, “오른쪽 탭 닫기”를 제공합니다. Shift+F10 또는 메뉴 키는 포커스된 탭에 적용됩니다. 오른쪽 클릭은 현재 페이지를 바꾸지 않습니다. 명령은 탭의 안정적인 식별 정보를 고정하고 소유 창의 현재 시각 순서에만 적용하며 다른 창에 영향을 주면 안 됩니다. 순서 변경, 창 크기 변경, 대상 소멸 또는 모달 작업 진입 시 메뉴를 닫습니다. 적용할 대상이 없는 일괄 동작은 비활성화합니다. 일괄 닫기는 한 번만 제출합니다. 현재 페이지가 열린 채 남으면 유지하고 아니면 기준 탭으로 전환하여 페이지가 반복해서 깜박이지 않게 합니다. 마지막 페이지를 닫으면 시작 페이지가 복원되며 작업과 결과는 전역 작업 진입점에 남습니다.

한 사용자 로그인 세션에서 일반 설치형과 포터블 프로세스는 단일 인스턴스, 트레이와 앱 메뉴를 공유합니다. Windows 패키지 프로세스는 별도의 단일 인스턴스 네임스페이스를 사용하고 일반 설치로 요청을 전달하지 않아 Store 실행이 일반 버전의 업데이트 인터페이스로 넘어가는 것을 막습니다. 두 프로세스가 공존하면 각각 트레이를 소유합니다. 기존 설치/업데이트 게이트는 둘 다 보수적으로 제한합니다. 공존, 설정과 연결은 실제 설치 환경 검증이 필요합니다. 버전 조회는 GUI를 만들기 전에 반환합니다. 스모크 테스트, 데스크톱 프로브와 테스트는 격리된 경로를 사용하고 실제 사용자 인스턴스에 연결하지 않습니다.

`SingleInstance`는 메인 창을 만들기 전에 QLockFile로 소유자를 선출하며 충돌 후 남은 로컬 서버는 잠금 소유자만 제거할 수 있습니다. QLocalServer는 UserAccessOption을 사용합니다. 구조화 JSON 프로토콜은 버전 1이며 메시지당 256 KiB, 절대 경로 128개, 연결 32개로 제한합니다. 후속 프로세스는 기본 인스턴스의 준비를 기다리고 요청 ID의 확인 응답을 받은 뒤 종료합니다. 15초 안에 통신이 실패하면 명시적으로 보고하고 두 번째 일반 UI를 만들지 않습니다. Windows에서 실행 프로세스는 서버 핸드셰이크의 PID를 사용하여 이번 사용자 동작에 대한 전경 활성화 권한을 넘기며 영구 최상위 상태를 사용하지 않습니다. IPC는 명령 인터프리터를 거치지 않고 사용자 경로를 로그에 기록하지 않습니다.

`ApplicationSessions`는 Qt 앱 계층의 조정자로 형식을 해석하거나 디렉터리를 승인하거나 파일을 커밋하지 않습니다. 각 세션은 독립적인 SessionPage, BrowserController와 Rust RuntimeConnection을 소유합니다. 열린 페이지는 조회, 선택, 디렉터리와 탐색 상태를 유지합니다. 창이 페이지를 수용하며 탭은 아카이브마다 숨겨진 네이티브 메인 창을 만들지 않습니다. 파일 연결, 명령줄, 네이티브 파일 열기 이벤트, 열기, 최근 항목, 끌어 놓기와 생성 결과가 모두 열기 의도를 제출합니다. 아카이브나 작업이 없는 유휴 시작 페이지 재사용을 우선합니다. 중복 경로는 아직 열린 세션만 활성화합니다. 여러 파일 요청은 순서대로 수락하고 마지막을 활성화합니다. 경로 정규화는 UI 중복 제거 전용이며 쓰기 권한을 주지 않습니다.

`desktop/openMode=tabs|windows`의 기본값은 tabs이며 스키마 버전 1과 알 수 없는 필드를 유지합니다. 성공적인 설정 변경은 기존 페이지를 옮기지 않고 이후 열기에 즉시 적용됩니다. 제목 표시줄의 더하기는 이 설정에 따라 페이지나 창을 엽니다.

탭 순서 변경은 안정적인 세션 식별 정보와 해당 창의 대상 인덱스를 제출합니다. 해당 창에서 열린 세션의 표시 순서만 바꾸며 작업 접수에 사용하는 컨트롤러 집합은 바꾸지 않습니다. 드래그를 놓거나 키보드로 순서를 바꾼 뒤 활성 페이지, 아카이브, 컨트롤러, 선택과 작업 식별 정보를 유지하고 다른 창과 닫힌 백그라운드 세션의 상대 순서는 바꾸지 않습니다. 비활성 탭을 닫아도 페이지를 전환하지 않습니다. 활성 탭을 닫으면 시각적으로 오른쪽 이웃을, 없으면 왼쪽 이웃을 선택합니다. 잘못된 식별 정보, 닫힌 세션, 범위 밖 인덱스 또는 종료 중 순서 요청은 무시하고 Rust 연결을 만들거나 파괴하지 않습니다. 현재는 창 내부 순서 변경만 지원하며 창 간 드래그, 창 분리와 실행 간 순서 복원은 지원하지 않습니다. 탭 표시줄 오버플로는 보이는 영역만 바꾸며 세션을 버리면 안 됩니다. 메뉴와 키보드 활성화 시 활성 탭이 보이도록 합니다.

최대 32개의 생존 세션을 보유하며 한도에서 명시적으로 알립니다. 백그라운드 작업이 모든 슬롯을 차지하면 마지막 탐색 페이지를 닫을 때 그 셸을 재사용해 시작 페이지와 전역 작업 진입점을 표시하며 추가 런타임을 만들지 않습니다. 탭이나 메인 창을 닫으면 해당 페이지의 디렉터리, 검색, 정렬, 선택, 스크롤과 보기 상태를 지우지만 백그라운드 작업은 취소하지 않습니다. 작업이나 완료 결과가 있는 페이지는 컨트롤러와 작업에 필요한 데이터를 보유합니다. 통합 작업 메뉴는 “세션 UUID/백엔드 작업 ID”를 사용하며 다른 연결의 같은 숫자 ID는 같은 작업이 아닙니다. 암호, 충돌과 결과 창은 원래 세션 컨트롤러가 계속 처리합니다. 작업이 없는 닫힌 페이지는 먼저 비동기 종료를 요청하고 수신 스레드 join 후에만 세션 집합에서 제거합니다.

세션 종료 후 늦게 도착한 시작, 사전 검사, 암호와 충돌 이벤트는 창을 자동으로 열거나 포커스를 빼앗지 않습니다. 작업과 요청 토큰은 남습니다. 사용자가 전역 작업 진입점에서 작업을 명시적으로 열면 원래 세션의 진행 상태와 대기 요청을 표시합니다. 페이지를 닫아도 요청은 취소되지 않습니다.

전역 작업 진입점은 복합 식별 정보로 원래 컨트롤러의 작업 창을 표시합니다. 먼저 호출한 메뉴를 닫고 현재 아카이브 탭을 전환하거나 닫힌 탐색 페이지 또는 메인 창을 복원하지 않습니다. 암호, 충돌과 취소 동작은 원래 컨트롤러로 계속 전달합니다. 잘못되었거나 만료된 작업 식별 정보는 무시합니다. 탐색 페이지를 닫는 것과 작업을 명시적으로 보는 것은 별개의 사용자 의도입니다.

작업 메뉴 내용이 바뀐 뒤 표시 영역에 들어가는 짧은 목록은 첫 항목부터 시작합니다. 오래된 스크롤 위치 때문에 작업 행이 잘리면 안 됩니다. 높이 제한을 넘는 목록은 스크롤 가능하게 유지하며 지우기 영역은 고정합니다.

작업 기록 지우기는 앱 계층의 표시 의도입니다. 컨트롤러는 권위 있는 백엔드 스냅샷과 늦은 확인 응답을 유지하고 제한된 기록에서 종료 항목만 숨김으로 표시합니다. 같은 종료 상태의 중복 업데이트로 다시 나타나면 안 됩니다. 활성 수, 준비 플레이스홀더, 암호, 충돌, 취소와 join에는 숨김 표시를 사용하지 않습니다. 완료 기록이 없으면 변경 알림을 내지 않습니다. 기록 제거 시 숨김 표시도 제거합니다. 보이는 작업이 없는 닫힌 컨트롤러는 기존 비동기 종료 흐름으로 회수합니다. 세션 간 지우기는 컨트롤러 식별 정보로 수행하며 같은 숫자 ID라는 이유로 다른 세션의 활성 작업을 지우면 안 됩니다.

생성, 추출과 무결성 검사는 준비, 암호/충돌 대기, 커밋과 정리를 포함해 앱 계층에서 직렬로 접수합니다. 접수를 기다리는 컨트롤러는 제한된 명령 하나만 유지하며 취소할 수 있고 GUI 스레드를 차지하지 않습니다. 각 Rust 연결의 작업 순서와 안전성 의미도 그대로 적용합니다. 명시적인 종료는 먼저 모든 세션에 대해 확인합니다. 기다리기를 선택하면 모든 작업 완료 후 종료하고 취소를 선택하면 모든 연결의 취소, 정리와 join을 기다립니다. 종료 완료 상태만 검사하며 그 검사에서 종료를 다시 시작하지 않습니다.

무거운 작업 스냅샷은 `TaskAccepted`보다 먼저 또는 해당 요청의 `Finished`보다 늦게 도착해도 원래 작업 생성 요청 ID를 가집니다. 컨트롤러는 요청, 원래 세션과 작업 식별 정보가 모두 일치할 때만 준비 플레이스홀더를 실제 작업에 결합합니다. 다른 요청이나 세션의 스냅샷이 플레이스홀더를 소비할 수 없습니다. 작업과 플레이스홀더는 한 번만 집계하며 종료 작업은 더 이상 활성 상태가 아닙니다. 결합은 실제 접수 응답을 대체하지 않고 작업 창을 일찍 열거나 직렬 접수, 취소 또는 모든 연결 join 장벽을 우회하지 않습니다.

모든 작업의 종료 대기는 앱 계층 작업 수와 join 장벽에만 수렴합니다. 한 페이지가 먼저 끝나도 이전의 단일 페이지 자동 닫기 동작을 실행하거나 그 페이지 종료 때문에 마지막 창을 숨기거나 종료 확인을 다시 표시하지 않습니다.

종료 확인을 표시하기 전에 앱 계층 `quitDecisionPending`을 설정합니다. 이 결정 동안 모든 세션과 창에서 대기열의 암호 질문과 이를 명시적으로 다시 표시하라는 요청을 일시 중지하여 확인 창을 가리지 못하게 합니다. 돌아가기나 기다리기를 선택하면 아직 유효한 작업과 질문 토큰만 재개합니다. 취소, 정리와 join 중에는 표시를 계속 중지하고 암호 창을 다시 열지 않습니다. 이 상태는 기존 요청을 숨기거나 취소하지 않으며 세션 종료 후 명시적 작업 접근도 바꾸지 않습니다.

시스템 종료, 앱 메뉴와 트레이의 명시적 종료는 같은 데스크톱 경로를 사용합니다. 관리 세션이 소유한 암호와 충돌 질문은 전역 종료 확인으로 대체될 수 있습니다. 돌아가기는 작업과 요청 토큰을 보존하며 취소 후 종료도 모든 연결의 정리와 join을 기다립니다. 네이티브 파일 선택기, 다른 모달 컨트롤과 관리 창 밖의 질문은 계속 종료를 막고 앞에 남습니다. 일반 모달 검사가 암호 대기 중 종료를 삼키거나 확인을 우회하여 작업을 취소하면 안 됩니다.

트레이 설정과 정보는 공통 설정 창을 직접 표시합니다. 메인 창이 숨겨졌거나 최소화되었거나 없으면 메인 창을 만들거나 복원하지 않고 독립 인스턴스를 사용합니다. 트레이 종료는 전역 종료로 바로 이동하고 작업 대기 중 공통 확인을 사용합니다. “메인 창 표시”는 탐색 창을 명시적으로 복원하거나 만듭니다.

트레이를 끄거나 호스트를 잃어도 닫힌 대화상자나 완료 결과를 다시 열지 않습니다. 표시되거나 최소화된 메인 창은 전역 작업 진입점을 제공합니다. 그 진입점이 없으면 원래 암호와 충돌 토큰을 유지하면서 숨겨진 활성 작업만 복원합니다. 이 자동 복구를 위해 메인 창을 만들거나 복원하지 않습니다. 열린 설정 창은 계속 사용할 수 있습니다. 트레이, 접근 가능한 창이나 활성 작업이 남지 않으면 숨겨진 메인 창 객체가 보유되어 있어도 모든 연결의 join을 기다린 뒤 종료합니다.

트레이를 다시 켜면 기존 명령과 현재 작업 상태를 가진 컨텍스트 메뉴를 계속 사용할 수 있어야 합니다. Windows에서 즉시 껐다 켜는 변경과 반복되는 호스트 가용성 변경도 포함하며 아이콘 복원만으로는 충분하지 않습니다.

메인 창이 보일 때 “표시하고 활성화”는 창을 올리고 활성화를 요청만 합니다. 숨겨지거나 최소화되었을 때는 먼저 일반 상태로 복원한 후 최대화하지 않고 이전 일반, 최대화 또는 전체 화면 상태로 복원합니다. 차단하는 모달 창의 활성화를 우선합니다. 팝업의 transientParent는 실제 호출 창입니다. 마지막 메인 창 닫기는 계속 트레이 설정을 따릅니다. 설정과 정보는 통합 진입점을 사용하여 먼저 기존 창을 활성화하고 정보 동작에서는 해당 페이지로 전환합니다.

`showMinimized()`는 원래 상태 비트를 바꿉니다. 복원 중에는 최소화 상태에서 저장한 최대화 또는 전체 화면 플래그를 추가한 뒤 최소화 플래그만 제거하며 먼저 일반 창을 표시하지 않습니다. 네이티브 회귀는 Qt 요청을 완료된 창 관리자 상태로 취급하지 않고 창이 실제로 노출되고 활성화되며 최종 상태가 확인될 때까지 기다립니다.

Cocoa 경로는 소유 NSWindow의 최소화와 전체 화면 전환 알림을 관찰합니다. 전환 중 복원 요청을 대기 상태로 유지하고 네이티브 확인 후 계속합니다. 같은 네이티브 창이 여전히 표시되고 노출되어 있고 진행 중인 전환이 없는데 Qt가 최소화로 보고하면 오지 않을 네이티브 확인을 기다리지 않고 효과 없는 Qt 상태 요청을 취소하고 저장된 상태를 복원합니다. 네이티브 창이 파괴될 때 관찰자를 제거합니다. 창을 얻을 수 없으면 요청을 대기 상태로 유지하고 고정 지연을 완료 증거로 사용하지 않습니다.

전체 화면 진입 또는 완료 콜백 중 최소화 요청은 이후 Qt 상태에 덮이거나 AppKit이 수락하지 않은 채 Qt에 기록될 수 있습니다. 같은 네이티브 창에 대한 요청을 기록합니다. 진입 후 여전히 보이고 전환 중이 아니면 다음 이벤트 루프 턴에서 Qt 상태를 네이티브 전체 화면과 맞추고 최소화를 다시 시도합니다. 더 최근의 복원, 일반 또는 최대화 요청이 우선합니다. 창이 파괴되었거나 사용 불가능하면 재시도하지 않습니다. 상태를 맞추는 동안 복원 요청이 도착해도 우선하며 이전 최소화 요청을 취소합니다.

암호와 종료 순서 회귀는 실제 AES 대기를 사용합니다. 작업 알림이 요청을 확립한 뒤 지연 창 표시 전 같은 페이지, 다른 세션과 다른 창에서 동기적으로 종료하는 경우와 기다리기를 선택하는 경우를 다룹니다. 창 표시 후 실제로 게시된 종료는 전달 대조군입니다. 실제 알림과 전달 상태를 기록합니다. 대기 중 암호 창이 종료 결정을 가리지 않고 돌아가기/기다리기가 같은 토큰을 유지하며 취소가 모든 join을 완료하는지 검증합니다. 제어된 동기 알림 순서는 과거 플랫폼 이벤트 순서의 증거가 아닙니다.

검수는 실제 네이티브 창 상태 변경, 동시 시작과 충돌 잔여물, Unicode와 일괄 라우팅, 두 열기 방식, 저장/취소와 재시작, 세션 간 ID 충돌, 백그라운드 작업, 암호/충돌, 전역 종료와 수신 스레드 회수를 포함합니다. 오프스크린 테스트가 증명하는 것은 상태 계약뿐이며 네이티브 시각, 접근성 또는 수동 데스크톱 검수를 대체하지 않습니다. 증거는 build/ 또는 CI 아티팩트에 보관합니다.

종료가 실제 취소와 join에 들어가면 IPC는 새 의도를 명시적으로 거부합니다. 채널을 닫은 후에만 선출 잠금을 해제하고 모든 연결이 끝난 후에만 재시작 프로세스를 실행합니다. 이전 인스턴스의 반복 정리가 새 엔드포인트를 제거하면 안 됩니다. Windows 재시작도 현재 사용자 동작에 대한 전경 권한을 전달합니다.

차단 대화상자 중 외부 열기를 받으면 마지막 활성화 의도를 유지하고 차단 창을 먼저 활성화하며 그 창이 닫힌 뒤 해당 새 창을 표시하여 숨겨진 새 창이 진입점을 잃지 않게 합니다. 설정 창은 실제 호출자를 유지하며 다른 메인 창이 포커스를 얻어도 소유권이 바뀌지 않습니다.

네이티브 회귀 진입점은 `python3 scripts/check-native-sessions.py --tests <browser-tests> --output build/review/native-sessions.json`입니다. Linux는 Xvfb와 Openbox를 사용하는 실제 X11 창 관리 경로를 사용하고 Windows와 macOS는 시스템 창 관리자를 사용합니다. 스크립트는 자신이 시작한 검증 프로세스만 관리합니다. 온디맨드 Qt 워크플로와 Release는 이 진입점을 공유합니다. 네이티브 로그와 JSON은 build/ 또는 CI 아티팩트에 남으며 실행하지 않은 수동 시각, GPU, IME 또는 화면 읽기 검사의 증거가 될 수 없습니다.

Linux에서는 Openbox의 `--startup` 콜백 후에만 Qt 테스트 프로세스를 만듭니다. `_NET_SUPPORTING_WM_CHECK`는 창 관리자 식별 정보만 선언하며 테마와 이벤트 처리가 준비되었다는 증거가 아닙니다. `scripts/check-x11-startup.py`와 `scripts/test-x11-startup-supervision.py`는 각각 콜드 스타트 준비와 시간 초과 정리를 검사하고 자체 프로세스 로그를 보존합니다. 추가 대기나 재시도는 원래 첫 창 어설션을 대체하지 않습니다.

메인 창 닫기는 최소화와 다릅니다. 트레이가 있을 때 마지막 창을 닫으면 그 창의 모든 탐색 탭을 지우고 설정과 정보를 포함한 소유 대화상자를 모두 닫고 저장되지 않은 외관 미리 보기를 취소하며 적용된 설정은 보존합니다. 네이티브 창 리소스를 파괴한 뒤 메인 창을 숨깁니다. 트레이, Dock 또는 파일 인자 없는 두 번째 실행에서 복원하면 시작 페이지 하나만 표시하고 이전 탭이나 소유 대화상자는 복원하지 않습니다. 마지막이 아닌 창도 자신의 탐색 탭과 소유 대화상자를 닫고 정리하되 다른 창에는 영향을 주지 않습니다. 백그라운드 작업과 질문 토큰은 원래 컨트롤러에 남으며 사용자가 작업을 명시적으로 열 때만 해당 네이티브 창을 다시 만듭니다. 모달 창이 막고 있으면 먼저 활성화하고 메인 창 닫기를 수락하지 않습니다.

창을 닫아도 실제 백그라운드 작업은 취소되지 않으며 소유 세션은 복합 식별 정보로 유지됩니다. 일반적으로 새 빈 세션이 시작 페이지를 수용합니다. 생존 세션 32개 한도에서는 닫힌 페이지의 아카이브 없는 셸을 일시적으로 사용하며 이전 제목, 로딩과 오류 표시를 숨깁니다. 비동기 join으로 슬롯이 비면 제한을 넘지 않고 빈 세션을 만듭니다. 이 교체는 숨겨진 창을 드러내거나 다른 창의 포커스를 빼앗지 않습니다. 전역 작업 진입점은 작업 창만 표시합니다. 파일 열기 요청은 닫힌 탐색 페이지를 복원하지 않고 새 세션에서 다시 읽습니다. 백그라운드 작업이 같은 파일을 여전히 수정 중이면 새 페이지는 취소 가능한 대기를 표시하고 작업 종료 후 다시 읽습니다. 그 대기를 취소해도 원래 작업에는 영향을 주지 않습니다.

열기가 실패하거나 취소된 후 읽는 중이 아니고 활성 작업이나 암호 질문이 없는 시작 페이지는 다른 열기에 재사용할 수 있습니다. 이전 경로는 성공적으로 열린 아카이브 식별 정보로 취급하지 않습니다. 작업 때문에 보유된 닫힌 아카이브를 다시 열 때는 현재 유휴 시작 페이지를 우선하여 새 세션에서 읽고 원래 작업의 독립 식별 정보를 유지합니다. 사용자가 명시적으로 만든 다른 페이지와 다른 창은 영향을 받지 않습니다. 대기를 취소하거나 대기 페이지를 닫아도 작업 종료 후 열기 요청이 되살아나면 안 됩니다.

열기가 진행 중으로 표시되는 동안 사용자가 취소하면 백그라운드 완료 응답이 이미 큐에 있어도 결과를 커밋하거나 암호 질문을 표시하지 않습니다. 컨트롤러는 원래 요청의 완료를 기다리고 확립되었을 수 있는 런타임 아카이브 세션을 조회해 닫습니다. 정리 중 busy를 유지하며 반복 취소가 정리를 중지하지 않습니다. 취소 정리가 성공했다고 주장하지 않고 실제 정리 실패를 보고합니다. 다른 수락된 백그라운드 작업은 각자의 수명 주기를 유지합니다.

메인 창 닫기를 수락할 때 활성화 세대를 증가시키고 모달 대기 연결을 해제합니다. 이미 큐에 들어간 오래된 깨우기 콜백도 세대를 검사해야 하며 모달이 닫힌 직후 메인 창을 다시 표시하거나 이전 탭을 복원할 수 없습니다. 이 무효화는 일반 열기 진입점과 공유하며 백그라운드 작업을 취소하지 않습니다.

업데이트 전달은 즉시 재시작이 아니라 별도의 `prepareForUpdate` 장벽을 사용합니다. 작업, 작업 시작 또는 모달 상호 작용이 있으면 전달을 거부합니다. 다운로드는 계속할 수 있고 대기는 취소할 수 있습니다. 수락한 뒤 새 의도 진입점을 닫고 모든 Rust 연결을 정리합니다. 모든 join이 끝난 후에만 `readyForUpdate`를 내보내며 조기 종료하지 않습니다. 업데이트 제공자는 설치 커밋을 해제하기 전에 종료 장벽을 알리고 그 후에만 메인 앱이 일반 종료 가로채기를 해제합니다. 설치 커밋이 실패하면 정보 페이지에 복구 진입점을 남기고 일반 사용자 종료를 허용하며 이전 버전을 자동 재시작하지 않습니다. [소프트웨어 업데이트](../../engineering/software-update.md)를 참조하세요.

## 파일 관리자 작업 세션

[파일 관리자 컨텍스트 동작](shell-actions.md)은 탐색 페이지나 메인 창이 없는 작업 세션을 사용합니다. 기존 복합 작업 식별 정보, 직렬 접수와 종료 join 장벽을 공유합니다. 콜드 스타트는 독립 작업 호스트만 로드하고 이미 실행 중인 인스턴스는 탭을 전환하거나 메인 창을 복원하지 않습니다. 일괄 준비와 입력 대기는 전역 활동에 포함되며 성공한 생성은 탐색 열기 큐에 들어가지 않습니다. 메인 창이 명시적으로 표시될 때만 탐색 창을 만듭니다.
