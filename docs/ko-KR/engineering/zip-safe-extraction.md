# 안전한 ZIP 추출 구현

[English](../../engineering/zip-safe-extraction.md) | [简体中文](../../zh-CN/engineering/zip-safe-extraction.md) | [繁體中文](../../zh-TW/engineering/zip-safe-extraction.md) | [日本語](../../ja-JP/engineering/zip-safe-extraction.md) | 한국어 | [Français](../../fr-FR/engineering/zip-safe-extraction.md) | [Deutsch](../../de-DE/engineering/zip-safe-extraction.md) | [Español](../../es-ES/engineering/zip-safe-extraction.md) | [Português (Brasil)](../../pt-BR/engineering/zip-safe-extraction.md) | [Русский](../../ru-RU/engineering/zip-safe-extraction.md)

이 계약은 호스트의 안전한 출력, 실제 추출, 충돌, 취소와 커밋 동작을 정의합니다. 실제 실행 결과와 현재 결함은 여기에 누적하지 않고 관련 이슈와 Actions 아티팩트에 기록합니다.

형식 플러그인은 빌린 입력, 불변 항목 스냅샷과 호스트의 `DecodedSink`만 받습니다. ZIP 메타데이터 스캔과 페이로드 디코딩은 별개입니다. Store, Deflate, ZIP64의 로컬 헤더, 중앙 디렉터리, 데이터 디스크립터, 선언 크기와 실제 크기, CRC, Deflate StreamEnd가 일치해야 합니다. AES-256 인증과 CRC 차이는 [암호 추출 계약](password-extraction.md)을 따릅니다. 그 밖의 암호화와 압축 방식, [인코딩 계약](filename-encoding.md)으로 해결되지 않은 이름, 아래 전용 정책에서 허용하지 않는 링크와 특수 객체는 계속 지원하지 않습니다. [분할 볼륨 읽기 계층](archive-opening.md)은 분할 소스를 하나의 논리 입력으로 제공합니다. 원시 ZIP64 로컬 데이터 디스크립터는 일반 중앙 디렉터리와 공존할 수 있으므로 로컬 및 중앙 크기 센티널로 폭을 검증합니다. 스트림 종료 후 압축 바이트가 남거나 출력은 맞지만 최종 블록이 없는 스트림은 모두 실패합니다.

모든 출력은 공통 이식 가능 이름 파서를 먼저 통과하며 경로 탈출, 절대 경로, 예약 장치 이름, 불법 문자와 모호한 구성 요소를 거부합니다. 작업 준비는 선택을 고정합니다. 루트 전체 추출은 모든 물리 레코드를 포함하고, 선택한 디렉터리는 모든 하위 항목으로 확장하며, 선택한 파일에서는 현재 디렉터리 접두사를 제거합니다. 브라우저의 루트 목록은 여전히 직속 파일과 폴더만 보여줍니다. Unicode NFD와 소문자화 기준으로 같은 이름은 첫 표기에 매핑하고 일반 파일 별칭은 충돌 해결에 넘깁니다. 파일과 디렉터리 충돌 및 모호한 부모는 대상 객체를 만들기 전에 거부합니다. 이 비교는 모든 파일 시스템의 이름 규칙을 완전히 모의하지 않으며 네이티브 배타적 생성이 최종 결정합니다.

기본 아카이브 이름 외부 폴더는 호스트가 아카이브 이름에서 유도하며 UI 미리 보기와 실제 출력에 같은 이름을 사용합니다. 확장자를 제거한 뒤 끝의 `.app`을 대소문자 구분 없이 제거하여 macOS Finder가 일반 외부 폴더를 앱 번들로 오인하지 않게 합니다. 예를 들어 `demo.app.zip`은 `demo/`에 추출되고 내부 `demo.app`의 이름과 내용은 그대로입니다. 제거 후 이름이 비면 `archive`를 사용합니다. 유도한 디렉터리도 이식 가능 이름 검사와 대상 승인을 통과해야 합니다. 지원되는 복합 확장자와 분할 아카이브에도 적용하며 같은 이름 폴더 옵션이 꺼진 경우 출력 경로를 바꾸지 않습니다.

사용자가 선택한 대상은 디렉터리 핸들을 가진 `xdzip-io::Grant` 권한이 됩니다. 자식 디렉터리는 링크를 따르지 않고 구성 요소별로 열며 부모 체인 식별 정보를 보유하고 다시 검사합니다. POSIX 대상은 현재 유효 사용자의 소유여야 하며 그룹이나 다른 사용자에게 쓰기 권한을 주어서는 안 됩니다. Windows는 재분석 지점, 소유자와 DACL을 검사합니다. 수정 권한은 현재 사용자, SYSTEM, Administrators와 상속을 위한 Creator Owner에만 허용합니다. 다른 SID에는 FILE_GENERIC_READ/FILE_GENERIC_EXECUTE 범위의 읽기, 열거와 실행을 허용할 수 있으며 GENERIC_READ/GENERIC_EXECUTE도 같은 파일 권한 경계를 사용합니다. 쓰기, 생성, 추가, 삭제, 자식 삭제, 소유자 변경, ACL 변경, GENERIC_WRITE/GENERIC_ALL 및 알 수 없는 비트는 유효 ACE와 상속 전용 ACE 모두에서 계속 거부합니다. 이는 외부에서 수정 가능한 디렉터리를 안전하다고 취급하지 않으면서 기존 읽기 전용 관찰 계정을 허용합니다. Windows 출력은 기존 읽기 전용 공유를 상속하며 해당 계정에서 내용을 숨기거나 사용자 디렉터리 ACL을 다시 쓰겠다고 약속하지 않습니다. 링크, 특수 객체, 외부 소유자와 외부에서 쓸 수 있는 대상은 계속 거부합니다.

비공개 작업 디렉터리는 시스템 난수 128비트 이름으로 배타적으로 만듭니다. POSIX 디렉터리는 0700, 파일은 0600을 사용합니다. 준비 파일 이름은 아카이브가 제공한 임시 경로가 아니라 호스트가 생성한 일련번호를 사용합니다. 실제 디코딩 바이트는 블록별로 측정하며 파일당 8 GiB, 작업당 20 GiB로 제한합니다. 선언 압축률이 1000:1을 초과하고 출력이 1 MiB를 초과하면 명시적 허가가 필요하지만 고정 바이트 제한은 유지됩니다. 각 디코더는 추출 데이터를 모두 메모리에 쌓지 않고 고정 버퍼를 사용합니다.

Snap에서 사용자의 실제 홈 디렉터리 바로 아래 작업 공간은 보이는 접두사 `xdzip-work-`를 사용합니다. 이 접두사와 `.xdzip-work-`를 모두 잔여물 후보로 집계합니다. 둘 다 같은 난수 이름, 비공개 권한, 식별 정보 검사와 정리 규칙을 유지합니다.

완전한 검증과 데이터 동기화 후에만 커밋합니다. 기본적으로 덮어쓰지 않고 같은 볼륨에 하드 링크를 배타적으로 만든 뒤 비공개 링크를 제거합니다. 덮어쓰기가 허용되면 기존 일반 파일의 식별 정보, 크기와 수정 시각을 다시 확인하고 같은 볼륨 내 이름 변경으로 교체하며 이전 파일을 먼저 삭제하거나 자르지 않습니다. 하드 링크가 여러 개인 최종 항목과 원본 아카이브 자체는 거부합니다. 파일 시스템에 필요한 커밋 기능이 없으면 복사·삭제 대체 없이 실패합니다. 식별 정보 검사는 최선의 노력이며 같은 계정의 동시 편집에 대한 콘텐츠 CAS가 아니고 정전 후 디렉터리 메타데이터의 지속성도 보장하지 않습니다. 생성한 디렉터리와 커밋한 파일을 따로 집계하며 작업 전체 롤백을 만들어 내지 않습니다.

비공개 저널은 준비와 커밋을 위한 상대 경로와 작업 식별 정보를 기록합니다. 정리는 알려져 있고 식별 정보가 일치하는 객체만 삭제합니다. 알 수 없는 파일, 교체된 대상 또는 삭제 실패가 있으면 복구 자료를 보존하고 정리 경고를 보고합니다. 충돌 후 난수 작업 디렉터리는 집계하고 보고만 하며 자동으로 파싱, 실행 또는 재귀 삭제하지 않습니다. 복구 검수는 충돌, 식별 정보 변경과 정리 실패 경로를 포함합니다.

작업과 메타데이터는 각각 작업자 스레드 하나를 사용합니다. 종료 상태 소비를 기다리는 작업을 포함하여 최대 32개를 보유합니다. 큐 계산에는 불변 스냅샷과 계획을 보수적으로 포함하며 누적 최대 64 MiB입니다. 일반 명령이 소유하는 데이터는 누적 최대 8 MiB입니다. 각 작업은 최신 표시 스냅샷만 유지하고 출력 진행률은 최대 10 Hz이며 종료 상태는 정리 후 게시합니다. GUI 수신자와 메일박스도 제한되어 GUI가 멈춰도 무한히 증가하지 않습니다. 충돌 질문은 작업 내 일회용 질문 ID를 가지며 취소와 종료는 데이터 큐 용량과 관계없이 대기를 깨웁니다.

접수 종료는 같은 상태 잠금 아래 게시하고 비차단 제출에서 조회하는 단조 원자 플래그를 사용합니다. 종료가 반환된 후에는 종료 작업자가 잠금을 보유하더라도 유효한 명령이 재시도 가능한 Busy 대신 일관되게 Closed를 반환합니다. 이 플래그는 거부만 결정하며 잠금 아래의 작업과 요청 상태 검사를 건너뛰지 않습니다.

취소는 원자적 커밋 허가를 통해 순서가 결정됩니다. 커밋 전 취소는 대상에 쓰지 않으며, 커밋이 시작된 뒤에는 파일 전체의 원자적 게시를 허용하고 커밋한 파일을 최종 결과에 집계합니다. 마지막 작업이 끝난 뒤의 취소는 성공을 바꿀 수 없습니다. 진행 창을 닫으면 숨기기만 하며 작업은 계속됩니다. 프로그램 종료는 취소하고 작업자와 소스 핸들을 기다리되 GUI 스레드에서 join하지 않습니다.

Windows와 macOS ACL 조회는 격리된 unsafe 경계이며 각 호출은 핸들, 포인터, 버퍼와 해제의 전제 조건을 설명합니다. 검증 결과는 실제로 다룬 플랫폼과 예외 경로를 기록합니다. 의존성과 보안 권고 검사는 [ZIP 추출 의존성 허용](zip-extraction-admission.md)을 참조하세요. 실제 검수는 [검증 방법](../../../developers/qa/README.md)에 따르고 관련 이슈와 아티팩트에 기록합니다.

OWNER RIGHTS (S-1-3-4)는 객체 소유자의 동적 권한을 나타내며 소유자가 현재 사용자, SYSTEM 또는 Administrators인지 검증한 뒤에만 허용합니다. 외부 소유자나 다른 SID를 신뢰하게 만들지는 않습니다. 네이티브 회귀는 준비 파일과 새 출력 부모로의 상속도 검증하며, OWNER RIGHTS가 있을 때 Everyone의 읽기 전용 접근은 허용하면서 수정 권한은 계속 거부하는지도 확인합니다.

Windows cap 디렉터리 핸들은 FILE_SHARE_DELETE를 허용하지 않으므로 OS가 부모 디렉터리 이름 변경 공격을 거부합니다. 검수는 외부 디렉터리가 변경되지 않고 안전한 대상이 승인된 디렉터리 안에 게시되는지도 증명합니다. 빈 비공개 작업 디렉터리 정리는 식별 정보 재검증 후 핸들을 소비하는 cap의 remove_open_dir을 사용하여 삭제 전에 핸들을 닫습니다. 검증된 빈 디렉터리만 제거하며 nofollow, ACL과 링크 거부 규칙을 완화하지 않습니다.

Qt 브리지는 출력 권한 없이 대상과 작업 DTO를 전달하며 ID는 불투명 문자열로 QML에 들어갑니다. 메뉴, 추출 옵션, 충돌, 진행/결과와 종료는 실제 작업을 사용합니다. 시스템 종료와 창 닫기는 모두 비동기 종료 장벽에 들어가기 전에 작업 결정을 거칩니다. 연속 진행률은 최대 10 Hz이며 질문, 취소, 정리와 종료 상태는 즉시 전달합니다. 런타임 실패 시 커밋 합계를 추측하지 않고 최신 상태를 유지하며 집계가 불완전함을 명시합니다.

인터페이스는 [논리 크기](../../../specs/visual/layout-scale.json), [창 레지스트리](../../../specs/visual/window-registry.json), [디자인 표준](../visual/design-standard.md)을 따릅니다. 추출, 작업과 충돌 창은 모두 너비 491단위이며 푸터 동작 글자는 13, 힌트는 12입니다. 고정된 하단 동작 영역과 스크롤 가능한 본문으로 작은 화면과 큰 글자에서도 사용할 수 있습니다. 큰 아트워크는 72픽셀 이미지를 확대하지 않고 같은 SVG에서 내보낸 216픽셀 투명 이미지를 사용합니다. [에셋 명세](../../../specs/visual/operation-assets.json)는 공통 소스 관계를 보존합니다. 네이티브 시스템 제목 표시줄과 디자인의 시스템 외관 그림은 별도로 검수합니다.

현재 출력은 현재 계정에 속하며 POSIX 디렉터리는 0700, 일반 파일은 기본 0600을 사용합니다. 게시 전에 ZIP Unix 작성자의 일반 파일에는 보유한 준비 핸들에서 `0600 | (mode & 0155)`를 복원합니다. 읽기와 실행 비트는 보존하고 그룹/기타 쓰기와 setuid/setgid/sticky는 제거합니다. 소유권을 변경하거나 확장 속성과 원래 수정 시각을 복원하거나 앱을 자동 실행하지 않습니다. 실행 비트와 상대 심볼릭 링크는 앱 번들 구조를 복원하지만 설치, 서명 검증 또는 시스템 보안 심사를 증명하지 않습니다. 손상, 특수 항목 및 소스/대상 변경은 기본적으로 현재 작업을 중지합니다. 이전에 커밋한 파일은 남으며 조용한 계속, 작업 전체 롤백 또는 자동 재시도는 없습니다.

작업을 제출할 때 Qt 컨트롤러는 busy 직렬 접수를 유지하고 중복 요청을 거부합니다. taskStarting은 추출/생성 제출을 디렉터리 읽기와 구분합니다. 일반 컨트롤은 외관에 browsingBusy를 사용하며 탐색 작업 영역은 제출을 디렉터리 재읽기로 표현하지 않고 최신 커밋 스냅샷을 표시합니다. browserQueryAvailable은 제출 중 조회 진입점의 외관을 유지하지만 실제 명령은 기존 직렬 요청 보호를 통과합니다. ‘압축 풀기 시작’ 등 확인 컨트롤은 taskStarting 중 정상 외관을 유지합니다. 클릭 처리와 컨트롤러는 여전히 busy로 중복을 막으며 접수 거부 시 비활성 색상이 번쩍이지 않습니다. 실제 작업 창 전환은 수락 후에만 합니다. 거부나 실패 시 확인 창과 오류 설명을 유지하고 디렉터리를 낙관적으로 지우거나 조기 성공을 꾸미지 않습니다.

추출 확인을 연 뒤 자동 대상 검사, 편집 후 재검사, 생성 창의 대상 검사와 입력 메타데이터 미리 보기도 작업 준비입니다. 이들은 커밋된 탐색 스냅샷을 유지하며 browsingBusy를 유발하거나 browserQueryAvailable을 닫지 않아 주 목록 오버레이, 도구 모음 비활성 색상과 메뉴 닫힘 깜박임을 방지합니다. busy는 여전히 전체 요청 주기를 포함하고 직렬 접수를 보호하며 대상 검사 결과는 작업 창에만 표시합니다. 아직 준비되지 않은 아카이브의 최초 열기는 계속 로딩을 보여줍니다. 디렉터리나 조회가 바뀌는 동안 새 스냅샷이 커밋될 때까지 커밋된 목록 또는 빈 상태를 유지합니다. 실패가 소스 스냅샷을 무효화하면 유효하지 않은 데이터를 지웁니다.

추출 대상은 창을 열거나 디렉터리를 선택하거나 편집을 끝낼 때 자동으로 검사합니다. 생성과 추출은 창 세대, 요청, 경로와 추출 세션에 연결된 별도 결과를 유지합니다. 경로 변경은 이전 결과를 즉시 무효화하고 대기 또는 검사 중 제출을 막습니다. 오래된 응답으로 새 경로나 다른 창을 승인할 수 없습니다. 두 창은 상태 아이콘과 문구를 공유하며 추출은 경로 배치, 같은 이름 폴더와 준비 경고를 유지합니다. 이 검사는 작업 준비일 뿐이며 실제 쓰기는 소스와 대상 권한을 다시 검증합니다.

## 안전한 ZIP 심볼릭 링크 복원

POSIX ZIP Unix 작성자의 심볼릭 링크만 복원할 수 있습니다. TAR 심볼릭/하드 링크, Windows 심볼릭 링크와 기타 특수 객체는 계속 unsupported_link를 반환합니다. 출력 승인을 얻기 전에 링크 내용을 제한된 싱크로 완전히 디코딩하고 로컬 헤더, 길이와 형식별 CRC/인증을 검증합니다. 암호화 링크는 [암호 추출 계약](password-extraction.md)에 따라 작업 준비까지 지연합니다. 링크당 최대 4,096바이트, 총 최대 4 MiB이며 이름은 PortablePath를 따릅니다. 상대 대상에는 `.`/`..`가 들어갈 수 있지만 만난 링크는 후속 부모 구성 요소보다 먼저 파일 시스템 순서로 확장해야 합니다. 출력 루트 탈출, 절대 경로, 역슬래시, 제어 문자와 예약 장치 경로를 거부하며 존재하지 않는 접두사나 파일을 디렉터리로 사용하는 경우도 거부합니다.

모든 대상은 원래 표기를 사용하여 선택한 출력 그래프 안에서 닫혀야 합니다. 이는 Framework Versions/Current, 대상 경로 접두사의 링크 확장과 macOS 앱 번들에서 흔한 상대 `.`/`..`를 지원합니다. 각 확장을 링크 부모 기준으로 정규화하고 출력 루트 탈출을 거부합니다. 최대 64개 링크를 따르며 순환, 끊어졌거나 범위를 벗어난 대상, 대소문자/Unicode 모호성, 중복 이름과 쓰기 부모로 쓰이는 링크를 거부합니다. 의존성 없이 링크만 선택하면 거부하며 대상 트리에 기존 외부 링크를 빌려 쓰지 않습니다. 모든 일반 파일과 디렉터리를 먼저 게시한 후 보유한 no-follow 부모 핸들을 통해 링크를 배타적으로 만듭니다. 기존 링크는 덮어쓰거나 따르지 않습니다. 각 게시는 소스와 부모 체인 식별 정보, 취소 허가를 재검증하고 트랜잭션 저널에 기록합니다. 링크 생성이 없는 파일 시스템은 링크를 텍스트 파일로 바꾸지 않고 명시적으로 실패합니다.

링크가 있는 작업은 모든 파일/링크 말단이 없어야 하며 시작 시 함께 검사하고 일반 파일 커밋 시 다시 검사합니다. 충돌은 실패하며 건너뛰기/이름 변경/덮어쓰기로 고정된 의존성 그래프를 깨뜨릴 수 없습니다. 기존 안전한 일반 디렉터리는 재사용할 수 있습니다. 일반 추출과 같이 이후 실패나 취소에도 이미 커밋된 항목은 남으며 전체 아카이브 트랜잭션이나 자동 롤백을 약속하지 않습니다. 완료 집계에는 링크 콘텐츠 바이트와 링크 수가 포함됩니다. 읽기 전용 메타데이터 사전 검사는 링크 내용을 읽지 않으므로 경고가 없다고 링크 출력이 허용된 것은 아닙니다.

## macOS 확장 ACL 제어

보유한 핸들로 확장 ACL을 조회하여 디렉터리와 일반 파일을 승인하며, 현재 유효 사용자 소유, 그룹/기타 모드 쓰기 권한 없음, 일반 파일의 하드 링크 하나라는 검사도 유지합니다. 알려진 거부 규칙은 수정 권한을 주지 않으므로 허용됩니다. 다른 주체의 허용 규칙은 읽기, 열거, 실행, 속성 읽기와 보안 정보 읽기 권한만 부여할 수 있습니다. 흔한 사용자 디렉터리의 `everyone deny delete`는 확장 ACL이 있다는 이유만으로 거부하지 않습니다.

쓰기, 생성, 추가, 삭제, 자식 삭제, 속성과 확장 속성 쓰기, ACL과 소유자 변경 등의 수정 권한은 현재 유효 사용자 UID와 명시적으로 일치하는 주체에만 허용합니다. 사용자 식별 일치에는 시스템 조회와 시스템이 사용하는 합성 사용자 UUID가 포함되며 그룹 주체가 현재 사용자를 대체할 수 없습니다. 외부 주체의 유효 및 상속 전용 수정 권한을 모두 거부하며 앞선 거부가 위험한 허용의 면제 근거가 되지 않습니다. 알 수 없는 권한 비트, 알 수 없는 규칙 유형, 검증할 수 없는 식별 정보와 ACL 조회 또는 해제 실패를 거부합니다. ACL 부재와 다른 조회 오류는 구분합니다.

대상 루트, 각 부모 디렉터리, 준비 디렉터리와 교체할 일반 파일에 검사를 적용하고 기존 식별 정보 재검증 경계에서 반복합니다. 준비 파일은 검증된 비공개 디렉터리 안에 배타적으로 생성하며 디렉터리 ACL 검사는 상속 권한을 제한합니다. 검사는 사용자 ACL을 자동으로 지우거나 다시 쓰지 않습니다. 기존 읽기 전용 공유가 출력에 상속될 수 있으며 공유 계정에서 내용을 숨긴다고 보장하지 않습니다. 검수는 프로젝트 소유 임시 객체에서 안전한 ACL을 사용한 실제 게시와 위험한 ACL 거부를 확인해야 합니다. 결과는 [보안 수정 이슈](https://github.com/xiaodaozhi/xdzip/issues/6)와 로컬/CI 아티팩트에 기록합니다.

시스템 컨텍스트 메뉴의 스마트 디렉터리와 아카이브별 디렉터리는 [파일 관리자 동작](shell-actions.md)이 관리하는 명시적 작업 레이아웃입니다. 스마트 결정은 완전히 검증된 출력 그래프를 사용합니다. 외부 폴더가 필요하면 공통 대상 권한을 통해 배타적으로 만들고 기존 디렉터리를 재사용하지 않고 번호를 붙여 충돌을 피합니다. 일반 탐색 추출의 같은 이름 옵션은 기존 대상 권한을 계속 사용합니다.
