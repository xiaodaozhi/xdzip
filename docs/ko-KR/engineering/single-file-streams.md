# 단일 파일 스트림과 ZIP 파생 패키지

[English](../../engineering/single-file-streams.md) | [简体中文](../../zh-CN/engineering/single-file-streams.md) | [繁體中文](../../zh-TW/engineering/single-file-streams.md) | [日本語](../../ja-JP/engineering/single-file-streams.md) | 한국어 | [Français](../../fr-FR/engineering/single-file-streams.md) | [Deutsch](../../de-DE/engineering/single-file-streams.md) | [Español](../../es-ES/engineering/single-file-streams.md) | [Português (Brasil)](../../pt-BR/engineering/single-file-streams.md) | [Русский](../../ru-RU/engineering/single-file-streams.md)

[내장 레지스트리](format-registry.md)는 일반 GZIP을 TAR.GZ와 별도로 선언합니다. `xdzip-codec-stream`은 독립적인 `xdzip-compression`의 [RFC 1952](https://www.rfc-editor.org/rfc/rfc1952) 구현을 메타데이터, 페이로드, 생성 계약에 맞춥니다. 참조 압축 라이브러리는 제품 의존성에 포함되지 않습니다.

<a name="xdzip-discovery-and-read-boundaries"></a>

## 탐지와 읽기 범위

GZIP 인식은 압축 데이터를 최대 256 KiB 읽어 디코딩된 접두부 최대 512바이트를 확인합니다. 유효한 구형 TAR 헤더 또는 명시적 `ustar` 표식은 TAR.GZ를 선택합니다. 인식된 TAR가 손상되면 일반 파일로 폴백하지 않고 실패합니다. 그 외에는 GZIP 스트림 전체를 검사한 뒤 단일 일반 파일 항목을 게시합니다. 디코딩된 스트림이 최소 1024바이트이고 모두 0이면 빈 TAR와 0으로 채운 일반 파일을 구별할 수 없습니다. 전체 스트림 검증 후에만 같은 외부 필터에 등록된 가장 긴 확장자로 보기를 결정합니다. 명시적인 일반 확장자는 파일을, TAR 확장자는 컨테이너를 유지하고 이름이 없거나 알 수 없으면 빈 TAR를 우선합니다. 압축 파일 편집으로 생성한 빈 TAR.GZ는 고정 GZIP 주석을 가집니다. 정확히 두 개의 0으로 된 TAR 종료 블록을 검증한 뒤 일반 확장자에서도 TAR.GZ를 선택합니다. 0 접두부 뒤에 0이 아닌 일반 데이터가 오면 GZIP으로 남습니다. 이 힌트는 강한 TAR 식별, 손상된 압축, 검사, 할당량 또는 원본 권한을 무시할 수 없습니다.

검사 허용은 물리 입력 길이와 실제 디코딩된 바이트를 각각 24 GiB로 제한합니다. `ControlledStream`은 읽기 전에 취소를 확인하고 첫 타입 지정 오류를 유지합니다. 디코딩이 정확히 경계에 도달하면 EOF와 초과를 구분하려고 비공개 디코딩 바이트 하나를 추가로 확인할 수 있지만 그 바이트는 전달하지 않습니다. TAR는 같은 제어 스트림을 그대로 또는 GZIP 필터와 함께 사용합니다. 전체 스트림 EOF에서 빈 멤버를 포함해 각 멤버의 CRC32와 ISIZE를 검증해야 합니다. 연결된 멤버는 하나의 논리 파일을 이룹니다. 헤더 플래그, 제한된 선택 필드, 헤더 체크섬, 잘림과 멤버가 아닌 후행 바이트는 독립 GZIP 디코더가 계속 검증합니다.

행 크기는 32비트 ISIZE 필드가 아니라 전체 디코딩 후 관찰한 바이트 수입니다. 호스트는 `ReadSource::source_name_hint`로 기본 이름을 제공할 수 있으며 코덱은 ASCII 대소문자를 무시하고 끝의 `.gz`를 제거하고 구분자, 제어 문자와 특수 이름을 거부하며 그렇지 않으면 `content`를 사용합니다. 헤더 FNAME은 무시하고 표시 텍스트는 별도로 이스케이프합니다. 모든 출력 이름은 계속 호스트의 이식 가능한 경로 및 대상 검사를 통과해야 합니다. 힌트는 파일 시스템 권한을 부여하지 않습니다. 페이로드 디코딩은 불변 행, 압축 길이와 관찰된 크기에 결합되고 성공 전에 EOF를 다시 검증하며 실패하거나 완료된 뒤 재개할 수 없습니다. 기존 작업 제한은 파일당 8 GiB, 작업당 20 GiB입니다.

<a name="xdzip-creation-and-publication"></a>

## 생성과 게시

일반 `.gz` 생성은 정확히 하나의 일반 입력 파일을 받아 Deflate 수준 0/1/6/9를 사용합니다. 디렉터리, 여러 파일, 암호, 분할, 솔리드 모드, 헤더 암호화는 거부합니다. 인코더는 고정된 입력을 EOF까지 읽고 정확한 크기와 취소를 확인한 뒤 호스트 소유 임시 영역에서 GZIP 트레일러를 완성합니다. 호스트는 게시 전에 준비된 스트림, 원본 버전, 출력 트랜잭션을 검증합니다. GZIP은 입력 파일 이름을 보존하지 않으며 다시 열 때 가상 이름은 압축 파일 기본 이름에서 얻습니다. 따라서 검증은 원래 입력 이름을 요구하지 않고 일반 파일 식별 정보와 크기를 비교합니다. 일반 GZIP은 압축 파일 수정을 지원하지 않습니다. TAR.GZ 생성과 재작성은 별도 컨테이너 계약을 유지합니다.

데스크톱 생성 선택지, 시작 화면 레이블과 연결 후보는 안정적인 레지스트리 식별자에서 생성합니다. 공유 형식 선택기는 기존 컨트롤 매개변수에서 치수를 얻습니다. CLI 생성은 같은 확장자 레지스트리를 사용하고 가장 긴 일치를 우선하여 `.gz`보다 `.tar.gz`를 보존합니다. 충돌 시 이름을 바꿔도 `.tgz`를 포함해 실제 등록된 확장자를 유지합니다.

<a name="xdzip-zip-derived-candidates"></a>

## ZIP 파생 후보

`.xpi`, `.apk`, `.ipa`, `.cbz`는 기존 ZIP 판독기의 진입점 후보입니다. 콘텐츠 검증, Store/Deflate, 허용된 WinZip AES-256 프로필, 경로 처리와 리소스 제한은 ZIP과 같습니다. 확장자만으로 다른 방식이나 암호화 체계를 허용하지 않습니다. 이 작업은 패키지 매니페스트, 애플리케이션 설치, 패키지 서명을 해석하지 않습니다. 이 별칭은 생성 확장자를 추가하지 않습니다. Windows 별칭은 ZIP 아이콘을 재사용하고 macOS는 확장자를 선언하여 할당된 형식을 확인하되 모든 ZIP 기본값을 교체하지 않습니다. Linux는 사용 가능한 해당 MIME 후보를 사용하고 IPA는 일반 ZIP 연결을 유지합니다.

<a name="xdzip-xz-admission-and-wire-contract"></a>

## XZ 허용과 데이터 형식 계약

XZ 프로필은 [Tukaani 형식 1.2.1](https://tukaani.org/xz/xz-file-format-1.2.1.txt)을 따라야 합니다. 디코더를 할당하기 전에 스트림 플래그와 헤더 CRC를 검증하고 예약 플래그, 비정규 또는 오버플로가 발생하는 9바이트 가변 정수, 지원하지 않는 필터, 예산 초과 사전을 거부합니다. 블록 헤더는 8–1024바이트이며 검증된 CRC, 선택적인 0이 아닌 압축 크기와 선택적 디코딩 크기, 크기를 보존하는 최대 세 개의 Delta/BCJ 필터 뒤에 오는 LZMA2, 0으로 채운 헤더 패딩을 가집니다. LZMA2 종료 표식이 정확한 압축 경계를 정하며 선택적 크기는 관찰된 작업을 확인합니다. 엄격한 7z 생성자와 크기를 알 수 없는 멤버 디코딩을 분리하고 종료를 검증한 후에만 원본을 반환합니다.

블록 패딩, 선언된 모든 콘텐츠 검사(None, CRC32, CRC64 또는 SHA-256), 각 인덱스 레코드와 관찰된 패딩 제외 및 디코딩 크기, 인덱스 패딩/CRC, 푸터 역방향 크기/플래그/CRC/매직, 연결 스트림과 4바이트 0 스트림 패딩을 검증합니다. None은 콘텐츠 체크섬을 제공하지 않으며 체크섬 보장으로 표시해서는 안 됩니다. 스트림 수와 스트림당 블록 수를 각각 100,000으로 제한하고 고정 파싱/필터 버퍼를 128 MiB 작업 메모리 허용량에 포함하며 취소와 독립적인 입력/출력 제한을 유지합니다. 실패하면 스트림을 더 사용할 수 없고 디코딩된 데이터는 전체 검증과 원본 검사가 성공할 때까지 호스트 임시 영역에 남습니다. 생성에는 실제 LZMA2 압축, 독립적으로 재설정되는 제한 블록과 선언된 콘텐츠 체크섬이 필요하며 기록기를 수용하기 전에 독립 디코딩으로 출력 바이트를 검증해야 합니다.

ZIPX는 기존 ZIP 레코드와 물리적 식별 정보를 사용합니다. 방식별 허용은 BZip2 12, LZMA 14, XZ 95를 포함해 [APPNOTE 6.3.10](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)을 따릅니다. LZMA 속성 헤더는 LZMA Alone과 다르며 일반 목적 플래그 비트 1이 EOS 요구 여부를 제어합니다. 허용된 데이터 디스크립터 프로필에는 EOS가 필요하며 크기가 있는 로컬 레코드는 생략할 수 있습니다. 정확한 페이로드 범위, 로컬/중앙 일관성, 디스크립터, 디코딩 크기와 ZIP CRC는 계속 필수입니다. 검증된 구현이 없는 방식은 레코드별로 지원하지 않으며 확장자로 다른 알고리즘이나 암호화 프로필을 활성화하지 않습니다.

XZ (`.xz`)와 TAR.XZ (`.tar.xz`, `.txz`)는 이 프로필을 읽기, 검사, 추출에 구현합니다. 생성은 CRC64, 최대 16 MiB의 독립 블록, LZMA2 수준 1/6/9를 사용하며 수준 0, 암호, 분할을 거부합니다. 일반 XZ는 정확히 하나의 일반 입력을 받아 호스트 기본 이름에서 가상 출력 이름을 얻습니다. TAR.XZ는 기존 TAR 기록기를 통해 일반 파일과 디렉터리를 받아 압축 파일 편집을 지원합니다. ZIPX는 `.zipx`를 ZIP 후보로 추가하고 기존 Store/Deflate와 함께 암호화되지 않은 방식 9, 12, 14, 95를 읽습니다. 이 방식을 사용하는 적격 ZIP과 ZIPX도 편집할 수 있습니다. 유지된 멤버는 압축 데이터와 방식을 보존합니다. AES-256은 기존 Store/Deflate 프로필로 제한됩니다. PPMd I, JPEG, WavPack은 명시적으로 지원하지 않습니다.

## 필터 적용 스트림 프로필

BZip2 (`.bz2`, `.bz`), LZMA Alone (`.lzma`), Lzip v1 (`.lz`)은 독립 스트림으로 읽기 전용입니다. TAR 조합은 `.tar.bz2`, `.tar.bz`, `.tbz`, `.tbz2`, `.tar.lzma`, `.tlz`, `.tar.lz`를 허용합니다. 확장자는 진입점이며 모호한 약칭은 실제 바이트로 판단합니다. 어댑터는 독립 알고리즘을 재사용합니다. 할당 전에 허용 여부를 확인하고 알고리즘 작업 메모리 128 MiB, 기존 스트림 바이트 제한, 연결 멤버 최대 100,000개를 적용해야 합니다. BZip2는 각 블록과 결합 CRC를 검증하고 완전한 스트림의 연결을 허용합니다. LZMA Alone은 [13바이트 형식](https://github.com/tukaani-project/xz/blob/master/doc/lzma-file-format.txt)을 따릅니다. 속성/사전 5바이트와 리틀 엔디언 크기 8바이트로 구성되며 크기가 모두 1이면 EOS가 필요하고 크기가 알려지면 유효한 range 종료 또는 EOS를 허용하며 후행 데이터는 거부합니다. 콘텐츠 체크섬 없이 구조와 읽기 가능성을 검증합니다. Lzip v1은 [형식 명세](https://datatracker.ietf.org/doc/draft-diaz-lzip/02/)를 따라 고정 LZMA 속성, 인코딩된 사전 범위, EOS와 트레일러의 CRC32, 디코딩 크기, 전체 멤버 크기를 검사합니다. 다른 버전은 명시적으로 실패합니다. 연결된 Lzip 멤버는 하나의 논리 파일을 이룹니다.

알고리즘의 멤버 판독기는 검증된 EOF 후에만 남은 입력을 반환하며 다음 컨테이너 바이트를 삼켜서는 안 됩니다. 별도의 생성 방식은 기존 7z 판독기의 전체 범위/알려진 크기 엄격 동작을 유지해야 합니다. 접두부 탐지와 잘못된 입력 테스트로 분리를 입증해야 합니다. TAR는 탐색과 편집을 위해 이 필터를 재사용합니다. 압축된 TAR의 파싱 실패가 일반 파일 성공으로 바뀌어서는 안 됩니다. LZMA Alone에는 강한 매직이 없으므로 유효한 TAR 헤더, ZIP SFX 또는 다른 강한 컨테이너 식별보다 우선할 수 없습니다. 레지스트리와 진입점 선언에는 대응 구현과 자동 수용이 필요합니다. 레지스트리는 검사 강도와 알 수 없는 압축 크기를 기록하여 CLI와 인터페이스에 일관되게 표시합니다. 알려진 LZMA 크기가 256 GiB 이상이면 더 작은 실제 작업 예산과 별개로 약한 탐지에서 제외합니다. Windows와 macOS는 이 후보에 기존의 이름 없는 일반 압축 파일 이미지를 재사용합니다.

<a name="xdzip-automated-acceptance"></a>

## 자동 수용

스트림 crate의 독립 참조 판독기/기록기 테스트로 멤버 체크섬, 잘림, 후행 바이트, 입력 변경, 취소, 정확한 할당량, 가상 이름을 검증합니다. runtime 테스트는 분류, 빈 TAR 우선, 단일 파일 생성, 검사, 추출과 게시 없는 거부를 다룹니다. 실제 CLI 회귀는 네 수준과 ZIP 별칭을 모두 포함합니다. Qt 테스트는 안정적 식별자 선택, 단일 파일 허용, 실제 생성과 다시 열기, 네이티브 접근성 메타데이터, 키보드 선택과 글자 크기 100/125/150%의 이중 언어 레이아웃을 다룹니다. 생성된 선언, 설치 프로그램 매핑, 창 및 공유 컨트롤 계약에는 별도의 자동 검사가 있습니다. 실제 실행 결과를 작업 issue에 기록하며 이 검사로 실행하지 않은 플랫폼 동작이나 릴리스 허가를 입증하지 않습니다.

LZ4와 TAR.LZ4는 [표준 프레임 계약](lz4-streams.md)을 사용합니다. 독립/연결 블록, 선언된 검사와 연결/건너뛸 수 있는 프레임을 읽습니다. 생성은 256 KiB 독립 블록, 블록과 콘텐츠 XXH32, 수준 1/6/9를 사용한 실제 LZ4 압축을 출력합니다. 일반 LZ4는 하나의 일반 입력을 받고 TAR.LZ4는 생성과 편집에 공유 TAR 기록기를 사용합니다. 암호와 분할은 지원하지 않습니다. 검사는 선언된 체크섬만 검증하며 구형 프레임과 외부 사전은 지원하지 않습니다.

Zstandard (`.zst`)와 TAR.ZST (`.tar.zst`, `.tzst`)는 [Zstandard 스트림 계약](zstandard-streams.md)을 따릅니다. 읽기는 제한된 표준 프레임 raw/RLE/압축 블록, Huffman/FSE, 반복 오프셋, 윈도 기록, 선언된 검사, 연결, 건너뛸 수 있는 프레임을 허용합니다. 생성은 수준 1/6/9, 128 KiB 윈도와 필수 XXH64를 사용하는 실제 LZ/FSE를 사용하며 일반 Zstandard는 하나의 일반 입력을 받습니다. TAR.ZST는 편집을 지원합니다. 암호와 분할은 지원하지 않습니다. 0이 아닌 사전 식별자, 사용할 수 없는 외부 기록과 예산 초과 윈도는 거부합니다. 검사는 선언된 체크만 검증하며 형식에 없는 체크를 보장하지 않습니다.

<a name="xdzip-rewriting-compressed-tar-archives"></a>

## 압축된 TAR 압축 파일 재작성

압축 파일 편집은 지원되는 TAR 레코드를 보존하고 외부 스트림을 원래 형식으로 재구성합니다. TAR.XZ, TAR.LZ4, TAR.ZST는 기존 프레임 기록기를 일반 압축으로 사용합니다. TAR.BZ2는 64 KiB 입력 조각과 블록 및 스트림 CRC를 가진 BZh1 블록을 출력합니다. TAR.LZMA와 TAR.LZ는 8 MiB 사전과 종료 표식이 있는 LZMA1을 출력합니다. Lzip 버전 1은 CRC와 크기 트레일러도 출력합니다. TAR.Z는 9비트에서 조기 CLEAR를 수행하는 블록 LZW를 사용합니다. TAR.BR은 [RFC 7932](https://www.rfc-editor.org/rfc/rfc7932)에 정의된 압축되지 않은 메타 블록을 출력하며 결과가 원래 Brotli 스트림보다 클 수 있습니다.

재작성 후 호스트는 원본을 교체하기 전에 준비된 결과를 다시 검사하고 디코딩합니다. 복합 TAR 확장자는 다시 열 때 빈 압축 파일 보기를 유지합니다. 모호한 단독 스트림 확장자는 마지막 레코드 삭제 시 커밋 전에 실패합니다. [압축 파일 수정 계약](archive-transfers.md)을 참조하세요.
