# 읽기 전용 탐색 구현 계약

[English](../../engineering/readonly-browser.md) | [简体中文](../../zh-CN/engineering/readonly-browser.md) | [繁體中文](../../zh-TW/engineering/readonly-browser.md) | [日本語](../../ja-JP/engineering/readonly-browser.md) | 한국어 | [Français](../../fr-FR/engineering/readonly-browser.md) | [Deutsch](../../de-DE/engineering/readonly-browser.md) | [Español](../../es-ES/engineering/readonly-browser.md) | [Português (Brasil)](../../pt-BR/engineering/readonly-browser.md) | [Русский](../../ru-RU/engineering/readonly-browser.md)

이 문서는 탐색 데이터, 리소스와 상호 작용 경계를 정의하고 [도메인과 데이터](../design/domain-data.md), [Qt/Rust 브리지](../design/qt-rust-bridge.md), [형식 확장 설계](../design/codec-extension-sdk.md)를 보완합니다. 제삼자 프로토콜이나 완전한 형식 SDK를 확정하지 않습니다. 아래에 ZIP 메타데이터 고유 규칙을 설명합니다. TAR/TAR.GZ는 탐색 및 조회 모델을 재사용하며 형식 차이는 [TAR/GZIP 계약](tar-gzip.md)을 참조하세요.

일반 단일 파일 ZIP/ZIP64의 100만 항목 스트리밍 인덱스, 디스크 스필 제한, 온디맨드 모델과 작업 제한은 [대형 아카이브 인덱스](large-index.md)를 참조하세요. 아래 100,000개 항목 메모리 스냅샷 제한은 일반 형식과 초기 ZIP 지원의 기준이며 새로운 스트리밍 ZIP 접수 조건을 덮어쓰지 않습니다.

## 데이터와 의존성 방향

xdzip-codec-api는 빌린 읽기 전용 입력, 취소, 제한, 항목과 오류를 정의합니다. xdzip-codec-zip은 경로나 쓰기 권한 없이 내장 ZIP 메타데이터 적응을 구현합니다. xdzip-runtime은 읽기 전용 파일을 열어 보유하고 스캔 성공 후 불변 스냅샷을 게시합니다. xdzip-qt-bridge는 cxx를 통해 작업자 스레드 진입점을 공개하고, 얇은 C++ 컨트롤러는 제한된 페이지를 Qt 모델로 변환하며 QML은 표시와 동작 의도를 처리합니다.

제품은 [명령/이벤트 런타임](product-runtime.md)으로 이전했습니다. GUI는 짧은 명령을 제출하고 Rust 작업자가 아카이브를 보유하며 별도의 Qt 수신자가 제한된 메일박스를 통해 결과를 전달합니다. QtConcurrent 동기 브리징은 제거되었습니다. 탐색 컨트롤러마다 보류 요청은 최대 하나입니다. 이는 완전한 멀티태스크 스케줄러, 동적 플러그인 ABI 또는 제삼자 프로세스 프로토콜이 아닙니다.

## 동작과 데이터

아카이브를 열면 루트의 직속 자식을 나열합니다. 검색은 하위 물리 레코드를 포함할 수 있습니다. 중복 이름도 각각 별도의 `EntryId`를 유지하고 세션 ID는 재사용하지 않습니다. UI는 정밀도 보존을 위해 ID와 바이트 수를 문자열로 전송합니다. 도메인 `PageRequest`는 최대 256행을 표현할 수 있습니다. 제품 런타임은 페이지당 최대 128행과 이름 64 KiB를 전송하고 하나의 정렬된 조회 결과에서 페이지를 잘라냅니다. Qt는 최대 1,024행 결과를 원자적으로 게시합니다. 더 큰 결과는 논리 행 수를 유지하고 필요할 때 행을 가져오며 최대 1,024행을 캐시합니다. 페이지 넘김 컨트롤은 없습니다. 사용자가 요청한 미리 보기는 [내장 미리 보기](content-preview.md), 시스템 연결로 구성원을 여는 방법은 [아카이브 열기](archive-opening.md)를 참조하세요.

ZIP/ZIP64를 인식하고 ZIP64 로케이터, 끝 레코드와 중앙 디렉터리의 시작 디스크를 검증합니다. [분할 볼륨 호스트](archive-opening.md)는 통합된 논리 입력을 제공하며 코덱은 변환되지 않은 다중 디스크 메타데이터를 계속 거부합니다. ZIP64 크기와 오프셋은 64비트로 유지하고 선언된 크기로 콘텐츠 버퍼를 할당하지 않습니다. 중앙 디렉터리 개수는 EOCD와 일치해야 합니다. 오류, 취소와 한도 초과는 부분 목록을 게시하지 않습니다. 이름은 [인코딩 계약](filename-encoding.md)에 따라 Unicode 선언을 우선한 뒤 선언되지 않은 레거시 인코딩을 탐지하고 해결되지 않은 바이트를 이스케이프합니다. 제어 문자와 양방향 텍스트 제어 문자도 이스케이프합니다. 절대 경로, 부모 경로, 특수 파일 등의 레코드는 “확인 필요”로 표시합니다. 원시 이름 바이트는 항상 보존하며 출력은 별도로 경로 검증과 승인을 받은 유효 이름만 사용합니다.

브라우저에 표시되는 크기, 압축 방식과 암호화 플래그는 아카이브 메타데이터에서 옵니다. ZIP 탐색은 중앙 디렉터리를 읽고 모든 로컬 헤더나 페이로드를 검사하지 않습니다. 압축 TAR 등 다른 일부 형식은 레코드를 찾기 위해 바깥 스트림을 디코딩합니다. 열기만으로 구성원 파일을 추출하지 않습니다. 대형 일반 ZIP에서는 런타임이 비공개 [디스크 메타데이터 인덱스](large-index.md)를 만들 수 있습니다. 콘텐츠 검증에는 별도의 [무결성 검사](archive-checking.md)나 [안전 추출](zip-safe-extraction.md)을 요청하세요.

## 플랫폼 간 파일 이름 인코딩 경계

형식 계층은 원시 이름 바이트와 물리 식별 정보를 보존하고 ZIP UTF-8 플래그와 CRC로 검증한 Unicode Path를 우선한 다음 그룹 전체 UTF-8 검사와 선언되지 않은 이름에 대한 제한된 아카이브 단위 통계 탐지를 사용합니다. 레거시 GBK/GB18030, Big5, Shift-JIS 등의 이름은 탐색, 이동, 추출, 임시 열기, 내보내기와 일반 수정에 직접 사용할 수 있습니다. 모든 경로 소비자는 고정된 디코딩 결과를 공유하고 경로, Unicode/대소문자와 이름 충돌 검사를 반복합니다.

탐지는 시스템 코드 페이지나 UI 언어에 의존하지 않으며 임의의 짧은 이름, 선언되지 않은 여러 인코딩 또는 이미 Unicode로 저장된 깨진 글자의 복원을 보장하지 않습니다. 현재 수동 인코딩 선택기는 없습니다. 손상된 선언, 엄격한 디코딩 실패 또는 비정상 경로는 확인 필요로 유지하고 출력을 거부합니다. 우선순위, TAR/PAX, 제한, 페이로드 결합과 저장은 [적응형 파일 이름 인코딩 계약](filename-encoding.md)을 참조하세요. 새로 만들거나 추가하는 이름은 UTF-8로 유지하며 수정 시 해결된 레거시 이름에 명시적 UTF-8 선언을 추가합니다.

## 리소스와 수명 주기

조정된 메인 창은 이름, 원래 크기, 압축 크기, 유형과 수정 날짜의 다섯 열을 표시합니다. 유형은 표시 이름의 확장자로만 추정하며 JPG는 JPEG로 묶습니다. 수정 날짜는 ZIP 중앙 디렉터리의 유효한 DOS 로컬 날짜/시간에서 가져오고 시간대는 추정하지 않습니다. 잘못된 값은 비워 둡니다. 다섯 열 모두 정렬할 수 있습니다. 표는 날짜를 표시하지만 정렬은 전체 DOS 시간을 사용합니다. 속성 패널과 독립 속성 창은 초가 포함된 24시간 시간을 표시합니다. 예를 들어 중국어 간체에서는 `2026/10/15 12:34:56`입니다. 압축 방식은 세부 정보에 남고 브리지는 방식 정렬 코드를 유지합니다. 암호화/확인 필요 상태는 행 힌트, 접근성 설명과 세부 정보에 남습니다. 주의가 필요한 항목은 이름 옆에 표시가 있으며 시각적 단순화로 가리면 안 됩니다.

일반 제품은 탭을 닫을 때 앱 세션 관리자를 사용하여 백그라운드 작업과 결과를 보존합니다. 작업이 없는 페이지는 비동기 연결 종료 후 회수합니다. 더하기 버튼은 저장된 열기 모드에 따라 빈 탭이나 메인 창을 만듭니다. 파일 열기는 항상 시작 페이지 재사용과 중복 제거를 우선합니다. [앱 세션 계약](application-sessions.md)을 참조하세요. 독립 컨트롤러와 진단 테스트는 한 연결의 아카이브 상태를 지우는 `CloseSession` 명령을 유지합니다. 제목 표시줄 전체 선택 체크박스는 세 상태입니다. 상태 표시줄 크기는 현재 조회에서 선택한 메타데이터만 합산하며 아카이브 총계가 아닙니다. 동작과 실제 지오메트리 증거는 [검증](../../../developers/qa/README.md)에 따라 보존합니다.

| 항목 | 현재 제한 |
| --- | --- |
| 물리 레코드 | 100,000 |
| 원시 이름 하나 | 4 KiB |
| 원시 이름 합계 | 16 MiB |
| 이스케이프된 표시 이름 | 16 MiB |
| 재읽기를 포함한 총 읽기 바이트 | 64 MiB |
| 스캔 버퍼 | 256 KiB |
| 브리지 전송 배치 | 128개 항목 |
| Qt 현재 조회 모델 | 논리 행은 인덱스 접수 조건에 따르고 최대 1,024행 상주, 델리게이트 가상화 |
| 독립 디렉터리 인덱스 | 32,768개 노드, 64단계 |
| 디렉터리 이름과 전체 접두사 합계 | 4 MiB |

표시 이스케이프와 브리지 복사는 추가 공간을 사용하며 이 값은 프로세스 RSS나 시간 보장이 아닙니다. 일반 메모리 스냅샷 메타데이터는 Rust 메모리에 있습니다. 직속 자식 인덱스는 행 식별 정보를 유지하고 조회 결과 캐시는 정렬된 인덱스만 보유합니다. 100,000개 항목 측정은 [검증](../../../developers/qa/README.md)에 따라 커밋, 플랫폼과 작업 부하에 결합하며 그것만으로 100만 항목 결과를 증명하지 않습니다. 스캔 전후 길이와 수정 시각 검사는 최선의 변경 탐지이며 원자적 스냅샷이 아닙니다.

읽기와 순회 경계에서 취소를 확인합니다. OS가 차단한 읽기는 중단할 수 없습니다. 사용 중인 메인 창을 닫으면 먼저 중지를 요청하고 완료 알림 후 닫으며 GUI 스레드에서 join하지 않습니다. 예상치 못한 컨트롤러 파괴도 매달린 백그라운드 참조를 남기지 않습니다. 일반 창 닫기와 앱 종료는 생성과 추출이 공유하는 M1 종료 장벽을 사용합니다. 쓰기 실패와 준비 영역 정리는 각각의 쓰기 계약에 따릅니다. 강제 종료 후 의심스러운 준비 영역은 보고만 하며 알 수 없는 내용을 자동 복구, 덮어쓰기 또는 삭제하지 않습니다. 전체 디렉터리 트랜잭션과 장치 전원 손실 안전성은 약속하지 않습니다.

소스는 일반 파일이어야 합니다. 최초 열기, 소스 재검증과 작업용 소스 복사는 모두 `xdzip_io::open_regular_readonly`를 사용하고 같은 열린 핸들에서 유형을 검사합니다. Unix에서는 경로가 FIFO나 다른 특수 객체로 교체된 경우 I/O 대기를 피하도록 분류 전에 비차단으로 엽니다. 일반 파일과 일반 파일을 가리키는 소스 심볼릭 링크는 계속 사용할 수 있으며 소스 버전은 실제 파일 식별 정보에 결합됩니다. 최초 열기/유형 실패는 `Io`, 이후 소스 재검증이나 복사용 열기 실패는 `SourceChanged`를 반환합니다. 이는 원자적 콘텐츠 스냅샷, 샌드박스 또는 강제된 일반 파일 I/O 시간 제한이 아닙니다.

브리지 소스 경로는 현재 손실 없이 표현 가능한 UTF-8로 제한됩니다. 파일 선택은 독립 네이티브 대화상자를 사용하며 macOS 신호등은 앱이 그리지 않습니다. 실제 시스템 포커스, 모달 소유권과 창 장식에는 데스크톱 검수가 필요합니다.

## 검수와 후속 확인

실제 테스트와 스크린샷은 [검증](../../../developers/qa/README.md)에 따라 이슈/아티팩트에 기록합니다. 탐색에는 실제 열기, 목록, 내부 배치 조회, 디렉터리 트리, 현재 조회 선택과 명령/이벤트 수명 주기가 포함되며 세 플랫폼 개발 빌드로 확인합니다. 100,000개 항목 ZIP64 인덱스와 조회 세대는 [ZIP 탐색 계약](zip-readonly-browsing.md)으로 검증하고 쓰기는 [안전 추출](zip-safe-extraction.md)이 별도로 규정합니다. 콘텐츠 미리 보기는 별도의 콘텐츠/디코딩 할당량을 따릅니다. 정식 출시는 여전히 [출시 라이선스 검토](../../../developers/qa/release-review.md)가 필요하며 이 페이지는 단계 검수 결론을 기록하지 않습니다.

## 탐색 상호 작용의 추가 사항

- 안전한 명시적 아카이브 디렉터리는 두 번 클릭하거나 체크박스에 초점을 둔 뒤 Enter를 눌러 들어갈 수 있습니다. “루트 폴더”는 루트 범위로 돌아갑니다. 일반 디렉터리는 직속 파일과 디렉터리만 표시하며 하위 항목을 재귀적으로 표시하지 않습니다. 검색은 현재 범위를 재귀적으로 검색하고 전체 아카이브 경로를 표시합니다. 일반 목록에는 기본 이름만 표시하지만 내부 전체 경로, 복사와 탐색은 바뀌지 않습니다. 위험한 이름은 탐색 노드가 될 수 없지만 검색과 메타데이터 확인을 위해 아카이브 스냅샷에 남습니다.
- Enter로 이름 검색을 실행합니다. Unicode 소문자 변환 후 리터럴 부분 문자열을 비교하며 정규식이나 로캘 정렬을 사용하지 않습니다. 검색 입력은 최대 256 UTF-16 단위, Rust 진입점은 최대 1,024 UTF-8바이트입니다. 검색은 현재 디렉터리 범위를 대상으로 합니다. 루트로 돌아가도 검색어는 유지되고 새 세션에서는 지워집니다.
- 일반 메모리 조회는 최대 100,000개 항목을 적재한 스냅샷을 필터링하고 요청한 대로 정렬한 뒤 최대 128개를 반환합니다. 필터링하는 각 레코드와 정렬 전후에 취소를 확인합니다. 디렉터리 매개변수는 물리적 EntryId 또는 `d` 접두사가 있는 가상 디렉터리 ID이며 Rust가 현재 세션에서 사용할 수 있는지 검증합니다. GUI가 파일 경로를 이어 붙이지 않습니다.
- 조회는 단일 작업자에서 실행되며 한도와 버전이 있습니다. 페이지에는 완전한 QueryKey가 들어갑니다. Qt는 최신 의도를 합치고 이전 작업을 취소합니다. 오래된 요청 또는 세션, 조회, 세대, 리비전, 오프셋이 일치하지 않는 응답은 현재 뷰를 대체할 수 없습니다. 범위를 벗어난 오프셋은 오류를 반환하고 빈 결과도 Ready입니다. 디렉터리 이동과 검색은 첫 페이지부터 시작합니다.
- 기존 스냅샷이 있으면 디렉터리, 정렬 또는 검색 조회 중 새 결과를 확정할 때까지 목록/격자 또는 빈 상태를 유지합니다. 바쁨 상태가 전체 영역을 잠시 오버레이로 대체하지 않습니다. 준비되지 않은 아카이브를 처음 열 때는 로딩을 표시하며 컨트롤러의 순차 접수, 취소와 소스 변경 확인은 유지합니다.
- 행이나 체크박스를 클릭하면 현재 조회의 다중 선택이 전환되며 중복 이름도 물리 ID로 구분합니다. 암묵적 디렉터리는 별도의 dN 행 키를 사용합니다. 조회 성공 또는 새 세션이 모델을 교체한 뒤 선택과 세부 정보를 지웁니다. 내부 전송 배치는 합성된 목록에 영향을 주지 않으며 UI는 페이지를 나누지 않습니다. 세부 정보는 가장 최근에 활성화한 항목의 메타데이터를 표시하고, 포커스와 체크박스 집합은 각각 포커스와 선택을 나타냅니다. 모두 선택은 항목을 마지막 행까지 개별 선택한 것과 같이 현재 전체 목록의 마지막 행을 세부 정보의 포커스로 사용합니다. 모두 선택 해제는 세부 정보를 지웁니다. 선택 항목이 없을 때는 잘못된 빈 속성을 표시하지 않고 원래 크기, 압축 크기, 수정 날짜, 압축 방식과 포커스된 항목의 압축 풀기 동작을 숨깁니다.
- 목록 크기는 B/KiB/MiB/GiB로 표시합니다. 변환은 근사 표시용이며 모델과 Rust에는 원래 정수가 남습니다. 파일 아이콘은 유형을 나타내고 세부 정보 카드는 속성을 표시합니다. 카드가 보이는 동안 지원되는 파일 하나를 선택하면 [미리 보기](content-preview.md)가 자동으로 로드됩니다.
- 압축 해제 크기를 알 수 없는 항목은 별도로 `size_known=false`를 가지며 원래 크기 열을 비워 두고 크기를 알 수 없다고 표시합니다. 크기가 알려진 빈 파일은 0으로 표시합니다. 선택 항목의 전체 크기를 알 수 없을 때 상태 표시줄에는 구분자나 자리 표시자 없이 선택 개수만 표시하고 컨트롤러는 알 수 없는 상태를 유지합니다. 전체 크기를 알면 크기도 표시합니다. 두 정렬 방향 모두 알려지지 않은 크기를 알려진 크기 뒤에 놓고 각 그룹 안에서는 ID 순서를 유지합니다. 물리적 크기 미상 항목은 거부 이유를 확인하기 위해 메타데이터 사전 검사를 요청할 수 있지만 가상 디렉터리를 포함한 선택은 여전히 요청할 수 없습니다. 크기를 모른다는 사실은 출력 권한이나 디코딩 예산을 부여하지 않습니다.

선택한 항목에 대해 독립된 네이티브 결과 창에서 [압축 풀기 메타데이터 사전 검사](extraction-preflight.md)를 요청할 수 있습니다. 파일을 쓰지 않고 읽기 전용 단계의 경계도 바꾸지 않습니다.

## 완전한 디렉터리 인덱스와 정렬

- Rust는 완전한 불변 스냅샷에서 명시적/암묵적 디렉터리를 구성합니다. Qt는 현재 페이지로 트리를 추론하지 않습니다. 각 가상 노드에는 세션 내에서 고유한 `dN` ID, 부모 ID, 표시 이름, 전체 아카이브 접두사와 하위 물리 레코드 수가 있습니다. 명시적 레코드가 없는 직속 디렉터리는 물리 id 0, 브리지 navigation_id, physical=false인 탐색 행으로 나타나며 Qt는 dN 표시 키를 사용합니다. 이 행은 물리적 압축 풀기 선택 대상이 아니며 물리 레코드 수를 늘리지 않습니다. 명시적 중복 레코드는 중복 제거하지 않고 탐색 행은 명시적 레코드가 없는 디렉터리만 채웁니다. 탐색 행을 선택하고 경로를 복사하고 들어갈 수 있지만 크기, 방식과 날짜는 비어 있습니다. 사전 검사는 실제 물리 레코드만 받으며 탐색 행을 포함한 선택에서는 사용할 수 없습니다.
- 아카이브에서 처음 나타난 순서대로 부모를 자식보다 먼저 게시합니다. 같은 이름의 물리 항목은 독립적으로 유지합니다. 노드 수에는 확인이 필요한 항목을 포함하여 접두사 아래의 모든 하위 항목이 포함되지만 디렉터리 접두사와 정확히 같은 레코드는 제외됩니다. 이름 검색으로 이 수가 바뀌지 않습니다.
- 경고가 있거나 이름을 해결하지 못한 레코드 및 역슬래시, 빈 구성 요소, `.`, `..`가 있는 레코드는 노드를 만들지 않습니다. 이 레코드는 확인할 수 있도록 물리 스냅샷과 재귀 검색에 남습니다. 인덱스는 탐색을 제공하며 경로 안전성이나 압축 풀기 권한을 보장하지 않습니다.
- 디렉터리 예산을 하나라도 초과하면 전체 디렉터리 인덱스를 버리고 UI에 명확히 알립니다. 루트, 검색과 조건에 맞는 명시적 디렉터리 탐색은 계속합니다. 인덱스 없이 암묵적 디렉터리를 추론하지 않습니다. 루트가 비어 보여도 검색은 전체 물리 스냅샷을 대상으로 할 수 있습니다. 잘린 트리를 완전한 것처럼 표시하지 않습니다. 디렉터리 공간에는 별도의 이름 예산이 있으며 형식별 스캔 접수 조건은 바뀌지 않습니다.
- 이름, 원래 크기, 압축 크기, 유형 또는 수정 날짜 머리글을 클릭하면 오름차순과 내림차순이 전환되고 Enter/Space로도 활성화할 수 있습니다. 오른쪽 위 정렬 메뉴는 디렉터리와 파일 각 그룹의 아카이브 순서를 복원할 수 있습니다. 페이지를 나누기 전에 전체 결과를 필터링하고 정렬하여 페이지 간 순서를 일관되게 유지합니다. 이름은 자연 정렬이나 로캘 정렬이 아닌 대소문자를 구분하는 Unicode 스칼라 사전순을 사용합니다. 숫자는 원래 Rust 정수를 비교합니다. 값이 같으면 행 유형(물리 행 우선)과 해당 ID의 오름차순으로 정하며 내림차순에서도 같은 이름 레코드의 순서를 뒤집지 않습니다. 모든 정렬은 먼저 디렉터리 플래그로 그룹을 나누어 명시적 및 암묵적 디렉터리를 파일 앞에 둡니다. 오름차순/내림차순은 각 그룹 안에 적용하며 원래 크기 미상 항목은 그 그룹에서 크기를 아는 항목 뒤에 남습니다. 유형의 오름차순/내림차순은 파일 범주 순서만 바꿉니다. 파일 범주는 정규화한 확장자를 사용하여 JPG와 JPEG를 묶고 확장자가 없는 파일은 별도 파일 그룹으로 유지합니다. 현지화된 표시 텍스트는 디렉터리 ID가 아닙니다.
- 탐색 정렬 코드: 0은 각 그룹의 아카이브 순서(물리 디렉터리 다음에 인덱스 순서의 암묵적 디렉터리), 1/2는 이름 오름차순/내림차순, 3/4는 원래 크기, 5/6은 압축 크기, 7/8은 ZIP 방식 번호, 9/10은 유형, 11/12는 수정 시간입니다. 그 밖의 코드는 거부합니다. 열, 디렉터리 또는 검색을 바꾸면 첫 페이지로 돌아가고 페이지가 성공적으로 교체되면 현재 조회의 선택과 세부 정보를 지웁니다. 허용되지 않은 동작은 마지막으로 표시한 조회 매개변수를 복원합니다.
- 트리는 펼치기/접기, 키보드 탐색과 Enter를 통한 디렉터리 진입을 지원하며 가로 스크롤로 깊은 단계에 접근할 수 있습니다. 기본 행 높이는 32, 단계 들여쓰기는 12.8, 폴더 슬롯은 16, 아이콘과 텍스트 간격은 6.4이며 텍스트와 아이콘을 세로 중앙에 둡니다. 글꼴이 커지면 행 높이와 열 너비가 늘어날 수 있습니다.

[일반 검증 방법](../../../developers/qa/README.md)에 따라 디렉터리 탐색과 정렬을 다시 확인합니다. 전체 조회 ID, 소스 검사와 100,000개 항목 검증은 [ZIP 탐색 계약](zip-readonly-browsing.md)을 참조하세요. UI 선택은 현재 조회 전체를 대상으로 하며 내부 배치와 캐시 회수로 지워지지 않습니다. 큰 조회의 범위 선택은 확인하기 전에 안정적인 ID로 고정합니다.

## 공유 컨트롤과 문맥 명령

메뉴, 버튼과 단축키는 읽기 전용 컨트롤러 동작을 재사용합니다. 선택된 항목을 마우스 오른쪽 버튼으로 클릭하면 현재 조회의 다중 선택을 유지하고, 선택되지 않은 항목을 오른쪽 클릭하면 먼저 그 항목만 선택합니다. Shift 범위는 안정적인 항목 ID를 앵커로 사용하며 조회 또는 정렬이 결과를 성공적으로 교체하면 지워집니다. 모두 선택은 형식/인덱스 접수 조건에 따라 탐색 행을 포함한 현재 디렉터리의 전체 조회를 대상으로 합니다. 사전 검사는 별도로 최대 128개의 실제 물리 레코드로 선택을 제한하며 탐색 행을 포함하거나 한도를 초과하면 사용할 수 없습니다. 이름과 아카이브 경로는 시스템 클립보드에 복사합니다. 디렉터리 이름은 끝 구분자를 생략하지만 경로는 원래 표시 형식을 유지합니다.

목록과 격자는 제한된 모델 하나와 선택된 ID를 공유하며 격자용 인덱스를 따로 만들지 않습니다. 디렉터리 안내선, 마지막 형제 표시, 조상 체인과 이동 경로는 형식을 추가 조회하지 않고 게시된 완전한 디렉터리 모델에서 파생합니다. 아카이브 요약은 현재 디렉터리/검색과 독립적으로 열기 시점의 물리 총계를 캐시합니다. 이동 경로 오른쪽의 개수는 필요한 탐색 행을 포함한 현재 목록 행 수를 표시합니다.

읽기, 조회 또는 세션이 바뀌면 메뉴를 닫습니다. 컨트롤러는 실행 시 동작의 허용 여부를 다시 확인합니다. 각 `BrowserController`는 아카이브 세션 하나를 관리하며 앱은 여러 아카이브 탭이나 창을 호스팅할 수 있습니다. [압축 풀기](zip-safe-extraction.md)는 명시적 출력 의도와 대상 권한을 얻습니다. [만들기](zip-creation.md)는 자체 입력 트리와 대상을 고정합니다. [무결성 검사](archive-checking.md)는 별도 읽기 전용 작업으로 실행됩니다. [사전 검사](extraction-preflight.md)는 현재 소스의 메타데이터를 분석합니다.

## 조회 ID와 리소스 제한

조회는 완전한 순서 하나를 생성한 뒤 캐시된 행 인덱스에서 전송 배치를 잘라냅니다. 배치는 최대 128행 및 총 64 KiB의 이름을 포함합니다. 명령 큐는 8 MiB로 유지하며 Rust 데이터 이벤트와 Qt 메일박스는 각각 32 MiB의 콘텐츠 배압을 두어 완전한 제한 크기 이미지를 수용합니다. 검색 또는 디렉터리 의도가 바뀌면 대기 중인 최신 의도만 유지하고 이전 응답은 새 조회에 들어가지 않습니다. 일반적인 취소나 한도 초과 시 마지막으로 성공한 목록을 유지합니다. 소스 버전이 바뀌면 무효 데이터를 지우고 다시 열어야 합니다.

스캔 전후 및 조회/사전 검사 경계에서 소스 핸들과 현재 경로의 길이, 수정 시간과 사용 가능한 생성 시간을 확인합니다. Unix는 장치/inode도 검사하며 Windows는 고정된 winapi-util의 안전 래퍼를 통해 볼륨/파일 인덱스를 사용하여 타임스탬프를 유지하는 경로 교체를 탐지합니다. 이 검사는 파일 시스템의 원자적 스냅샷이 아닙니다. 선택 요약은 모델 선택 리비전별로 캐시하고 정확한 합계를 위해 Rust u128을 사용하여 반복 순회와 64비트 오버플로를 피합니다.

Qt 설정 어댑터가 UI 언어를 불러옵니다. 유형, 상태, 오류와 사용자에게 보이는 날짜에는 번역 카탈로그와 로캘을 사용합니다. 바이트 수, 항목 ID, 경로, 원시 시간과 정렬 매개변수에 대한 브리지 값은 언어에 따라 변하지 않습니다. 번역된 텍스트에서 형식 기능, ID 또는 보안 결정을 추론하지 않습니다. 언어 변경이 성공하면 실행 중인 작업을 바꾸지 않고 UI 텍스트를 즉시 갱신합니다. [설정과 현지화](../ux/settings-localization.md)를 참조하세요.

아카이브를 성공적으로 열면 브리지는 로컬 UI 설정 어댑터에 archiveOpened(path)만 내보냅니다. 최근 경로는 별도로 저장하며 도메인 조회, 정렬 또는 작업 권한에 참여하지 않습니다. 실패한 경로는 최근 항목에 기록하지 않습니다.
