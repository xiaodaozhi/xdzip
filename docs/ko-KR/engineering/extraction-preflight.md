# 압축 풀기 사전 검사: 메타데이터 단계

[English](../../engineering/extraction-preflight.md) | [简体中文](../../zh-CN/engineering/extraction-preflight.md) | [繁體中文](../../zh-TW/engineering/extraction-preflight.md) | [日本語](../../ja-JP/engineering/extraction-preflight.md) | 한국어 | [Français](../../fr-FR/engineering/extraction-preflight.md) | [Deutsch](../../de-DE/engineering/extraction-preflight.md) | [Español](../../es-ES/engineering/extraction-preflight.md) | [Português (Brasil)](../../pt-BR/engineering/extraction-preflight.md) | [Русский](../../ru-RU/engineering/extraction-preflight.md)

이 모듈은 메타데이터 사전 검사 규칙을 제공합니다. 대상 권한 부여, 디코딩, 쓰기, 임시 준비 또는 커밋 기능은 없습니다.

<a name="xdzip-implementation-and-boundaries"></a>

## 구현과 경계

`xdzip-extract-plan`은 도메인과 메타데이터 인터페이스에만 의존하며 Qt, 형식 파서 또는 추가 타사 의존성이 없습니다. 입력은 세션 스냅숏, 물리적 EntryId 집합과 취소이고 출력은 제한된 보고서뿐이며 쓰기에 사용할 경로나 안전 승인 플래그가 아닙니다. `xdzip-runtime`이 스냅숏을 보유하고 Qt가 작업 스레드 브리지를 통해 호출합니다.

선택은 비어 있지 않아야 하고 물리적 ID 128개로 제한되며 모든 ID가 현재 스냅숏에 속해야 합니다. 디렉터리를 선택하면 검색, 페이지 구분 또는 현재 디렉터리 범위와 관계없이 원래 이름의 슬래시 경계를 사용해 모든 하위 항목을 확장합니다. 디렉터리와 자식을 함께 선택해도 자식은 한 번만 셉니다. 같은 이름의 물리 레코드를 경로로 병합하지 않습니다. 디렉터리 통계는 명시적 레코드만 세며 디렉터리 객체를 만들어 내지 않습니다.

사전 검사는 제한된 허용과 독립 취소를 갖춘 명령 및 이벤트 서비스를 통해 실행됩니다. 런타임은 검사 전후에 열린 원본의 식별을 확인합니다. 디스크 인덱스 ZIP은 선택된 물리 레코드와 필요한 하위 항목을 인덱스에서 불러옵니다. 선택, 쿼리 또는 세션을 변경하면 보고서가 지워집니다. 결과는 기록된 메타데이터에 근거한 추정치입니다. 사전 검사는 멤버 내용을 디코딩하거나 대상 경로를 예약하거나 쓰기를 승인하지 않습니다.

<a name="xdzip-rules-performed"></a>

## 수행하는 규칙

- 이름은 UTF-8로 해석할 수 있어야 하며 최대 4 KiB, 구성 요소 64개, 요소당 255바이트입니다. 원래 이름은 복구하거나 다시 쓰지 않습니다.
- 절대 경로, 빈 구성 요소, `.`, `..`, 역슬래시, 콜론, 제어 및 양방향 제어 문자 및 구성 요소 끝의 공백 또는 점을 거부합니다.
- 확장자가 있는 형태와 위 첨자 COM/LPT 숫자를 포함한 일반 Windows 장치 이름을 거부하고 플랫폼 공통의 이식 가능한 이름 부분 집합을 보수적으로 적용합니다.
- 기존 메타데이터 경고를 보고하고 레코드의 내용과 암호 기능 플래그를 사용합니다. 암호화된 레코드는 지원되는 암호 요구 또는 지원하지 않는 암호화를 보고할 수 있습니다. 크기가 알려졌으나 내용이 지원되지 않는 레코드도 방식 문제를 보고합니다. 사전 검사는 판독기가 투영한 메타데이터와 기능을 사용하며 내용을 복호화, 인증 또는 디코딩하지 않습니다.
- 정확히 중복된 이름, Unicode 소문자 비교에 따른 충돌, 대소문자가 다른 부모 디렉터리 별칭과 양쪽 삽입 순서의 파일 및 디렉터리 충돌을 검사합니다. 암시적 부모 디렉터리는 같은 이름의 명시적 디렉터리로 보완할 수 있지만 명시적 디렉터리 레코드 중복은 여전히 충돌합니다.
- 선언된 파일 크기가 8 GiB를 넘거나 합계가 20 GiB를 넘는 경우와 정수 오버플로를 보고합니다. ZIP 레코드의 선언된 압축률이 1000:1을 넘으면 검토를 요청합니다. 디렉터리 크기는 출력 바이트에 포함하지 않습니다.

Unicode 소문자 비교는 완전한 대소문자 접기나 파일 시스템의 NFC/NFD 동등성이 아닙니다. 비 ASCII 구성 요소가 하나라도 있으면 대상 파일 시스템에서 동등성과 충돌을 추가로 확인해야 한다는 안내가 표시됩니다. 문제가 없는 보고서도 출력을 승인하지 않습니다.

<a name="xdzip-resources-and-failures"></a>

## 리소스와 실패

스냅숏 레코드는 최대 100,000개 검사하고 선택 및 확장된 이름은 합계 최대 4 MiB입니다. 충돌 인덱스에 저장된 비교 키와 원래 표기는 컨테이너 오버헤드를 제외하고 합계 최대 8 MiB입니다. 구성 요소 순회 깊이는 제한되며 외부 레코드마다 취소를 확인합니다. 보고서는 모든 문제를 세지만 대표 문제 최대 64개만 브리지를 통과합니다. 여기에는 물리 레코드 ID와 안정적인 이유만 있으며 임의의 아카이브 오류 텍스트는 없습니다.

빈 선택, 외부 ID, 인덱스 제한 또는 취소는 부분 성공 보고서가 아니라 오류를 반환합니다. 오버플로한 합계는 0으로 잘라내지 않고 “사용할 수 없음”으로 표시합니다. 기본 문제는 보고만 하며 자동으로 덮어쓰거나 이름을 바꾸거나 무시하거나 건너뛰지 않습니다.

알 수 없는 비압축 크기는 안정적인 이유 `unknown_size`를 보고합니다. `declared_bytes=None`은 합계를 알 수 없다는 뜻이며 크기가 알려진 빈 파일의 `Some(0)`과 다릅니다. 알 수 없는 값은 총 크기 제한 또는 알 수 없는 방식 문제를 만들어 내지 않습니다. 실제 정수 오버플로는 여전히 총 제한 문제를 발생시킵니다. 출력 작업은 크기를 알 수 없는 레코드를 디코딩, 임시 준비 또는 암호 상호작용 전에 별도로 거부합니다.

<a name="xdzip-desktop-entry-point"></a>

## 데스크톱 진입점

항목을 선택하고 “압축을 풀기 전에 메타데이터 확인…”을 클릭합니다. 결과는 독립적인 비모달 최상위 `OperationWindow`를 사용하고 기본 창을 임시 소유자로 삼으며 네이티브 제목 표시줄을 유지합니다. 앱은 macOS 신호등 버튼을 그리지 않습니다. 결과를 닫으면 해당 창만 닫힙니다. 기본 창을 닫을 때는 협조적 취소를 사용하고 GUI 스레드에서 작업자를 기다리지 않습니다.

<a name="xdzip-boundary-with-actual-extraction"></a>

## 실제 압축 풀기와의 경계

[실제 안전한 압축 풀기](zip-safe-extraction.md)는 출력 계량, CRC 및 구조 검증, 대상 권한, 플랫폼 경로 재검사, 충돌, 임시 준비와 파일 커밋을 독립적으로 구현합니다. 사전 검사의 128개 선택에 제한되지 않으며 물리 레코드 100,000개의 계획과 가상 디렉터리 선택을 지원합니다. 사전 검사 보고서를 쓰기 권한으로 재사용하지 않습니다. 작업을 시작할 때 [파일 보안 사양](../design/file-security.md)에 따라 대상 권한을 다시 얻고 원본을 재검증하며 실제 내용을 확인해야 합니다. 네이티브 실패 동작과 현재 알려진 결함은 관련 계약과 이슈에서 추적합니다.

<a name="xdzip-window-and-result-presentation"></a>

## 창과 결과 표시

사전 검사는 너비 491 논리 픽셀의 공통 작업 창을 사용합니다. 본문은 내용에 맞게 조정되고 클라이언트 영역 최대 높이는 600이며 긴 문제 목록은 스크롤되고 고정 바닥글은 접근할 수 있습니다. 데이터와 메타데이터 단계의 권한 경계는 변하지 않습니다. 매개변수와 디자인 소스는 [사전 검사 매개변수](../../../specs/visual/preflight-reference.json)를 참고하세요.

사전 검사 설명 위치는 2026-10-15에 변경되었습니다. “이 보고서는 메타데이터만 확인합니다…”를 스크롤 가능한 본문 끝으로 옮기고 12포인트 설명 텍스트를 사용합니다. 바닥글은 더 이상 이 설명을 담지 않고 뒤로 작업만 유지하며 보고서 길이와 관계없이 같은 글꼴 크기의 공통 작업 전용 바닥글과 높이가 같습니다.
