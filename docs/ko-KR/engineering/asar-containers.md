# ASAR 컨테이너 계약

[English](../../engineering/asar-containers.md) | [简体中文](../../zh-CN/engineering/asar-containers.md) | [繁體中文](../../zh-TW/engineering/asar-containers.md) | [日本語](../../ja-JP/engineering/asar-containers.md) | 한국어 | [Français](../../fr-FR/engineering/asar-containers.md) | [Deutsch](../../de-DE/engineering/asar-containers.md) | [Español](../../es-ES/engineering/asar-containers.md) | [Português (Brasil)](../../pt-BR/engineering/asar-containers.md) | [Русский](../../ru-RU/engineering/asar-containers.md)

이 형식은 Electron의 [ASAR 설명](https://github.com/electron/asar#format)과 Chromium의 [Pickle 계약](https://chromium.googlesource.com/chromium/src/+/main/base/pickle.h)을 따릅니다. 크기를 담은 여덟 바이트 Pickle 뒤에 JSON 디렉터리 트리를 담은 Pickle 문자열이 옵니다. 파일 오프셋은 데이터 영역 기준의 십진 문자열입니다. 여러 파일이 같은 저장 바이트를 공유하더라도 각 트리 항목은 자체 식별 정보를 유지합니다. 선택적 무결성 선언에는 전체 파일 및 각 고정 크기 블록의 SHA-256이 들어갑니다. 이 선언은 손상을 검사하며 패키지나 앱을 인증하지 않습니다.

<a name="xdzip-admission-and-identity"></a>

## 허용 조건 및 식별

트리를 분석하기 전에 리틀 엔디언으로 저장한 네 개의 길이 워드, 네 바이트 정렬, 정확한 문자열 길이, 0 채움 및 원본 범위를 확인합니다. 헤더는 8 MiB, 중첩은 경로 구성 요소 64개로 제한합니다. 노드 수와 보유한 이름 바이트 수에는 공통 검색 한도를 적용합니다. 일반 JSON을 한도 내에서 분석하고 중복 키를 거부하며 객체 순서를 유지합니다. 잘못된 UTF-8, 잘못된 필드 유형, 정수가 아니거나 안전한 범위를 벗어난 크기, 오버플로가 발생하는 십진 오프셋 및 알 수 없는 필수 프로필을 거부합니다. 이름 구성 요소는 접두 경로와 독립적으로 검증합니다. 안전하지 않은 원본 이름은 미지원 및 경고 표시와 함께 보존하여 호스트가 출력을 거부할 수 있게 합니다.

명시적 디렉터리와 빈 파일을 포함해 JSON 트리 순서대로 물리적 식별 정보를 할당합니다. 루트 객체는 구조용입니다. 동일한 데이터 범위를 공유하는 항목은 별도로 보존합니다. 일부만 겹치는 범위, 승인된 원본 밖의 범위, 참조되지 않는 후행 데이터를 거부합니다. 무결성 선언이 없는 파일은 구조와 읽을 수 있는지만 검사합니다. 선언이 있으면 해시 길이, 알고리즘, 블록 크기와 수 및 빈 파일 규칙을 모두 검증합니다. 지원하지 않는 선언은 명시적으로 알립니다.

<a name="xdzip-read-only-export-and-verification"></a>

## 읽기 전용 내보내기 및 검증

백엔드는 승인되었으며 읽기 위치를 바꿀 수 있는 스트림과 호스트의 출력 대상을 받습니다. 다른 경로를 열거나 링크를 따라가거나 앱을 실행하지 않습니다. `unpacked` 레코드는 표시되지만 지원되지 않습니다. 인접한 `.asar.unpacked` 디렉터리는 입력 승인에 포함되지 않습니다. 선언된 링크의 식별 정보는 보존하되 링크는 지원하지 않습니다. 실행 가능 플래그는 모드 복원이나 실행을 허용하지 않습니다. 암호, 볼륨, 만들기 및 다시 쓰기는 이 프로필의 범위 밖입니다.

데이터를 사용하기 전에 전체 헤더를 다시 분석하고 결과 인덱스를 변경 불가능한 호스트 스냅샷과 비교합니다. 한도를 적용한 오프셋과 선택적 해시를 내부에 유지합니다. 입력 누계와 디코딩된 바이트 한도, 취소 조건을 적용하면서 저장 범위를 순차적으로 읽습니다. 빈 파일을 포함해 파일 전체와 각 블록의 SHA-256을 검사한 뒤 성공을 보고합니다. 검사 중에 출력이 비공개 임시 영역에 들어갈 수 있으며 검증된 파일을 확정할 권한은 호스트에만 있습니다. SHA-256 작업량에는 채움을 포함해 실제로 처리한 64바이트 압축 블록을 셉니다. 입력, 전달한 바이트 및 해시 작업량에는 각각 24 GiB의 내부 한도가 있습니다. 호스트의 작업 한도가 더 엄격할 수 있으며 공유 범위를 다시 읽어도 사용한 허용량은 돌아오지 않습니다. 오류가 발생하면 열어 둔 리더를 더 사용할 수 없습니다. 원본 식별 검사는 가능한 범위에서 변경을 탐지하며 원자적이거나 인증된 스냅샷을 보장하지 않습니다.

등록에는 버전을 고정한 참조 도구에서 생성하거나 독립적으로 읽은 관리 대상 입력이 필요합니다. 디렉터리, 빈 파일과 UTF-8 이름의 파일, 공유 데이터, 다중 블록 무결성 선언 유무, 외부 레코드, 실행 가능 선언을 포함합니다. 회귀 검사는 JSON 중복 키, 산술, 정렬, 잘림, 겹침, 잘못된 해시, 안전하지 않은 이름, 원본 변경, 정확한 할당량, 취소 및 출력 실패를 다룹니다. 실제 런타임, CLI, Qt 작업과 영향받는 후보 표시, 읽기 전용 동작, 검사 결과 안내 및 레이아웃을 자동화해서 검증합니다. 참조 도구와 생성된 증거는 `build/`에 두고 테스트 입력과 생성기 소스는 버전 관리합니다. 진행과 실제 인수 결과는 해당 이슈에 기록합니다.
