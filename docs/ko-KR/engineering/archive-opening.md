# 분할 볼륨 읽기와 임시 열기

[English](../../engineering/archive-opening.md) | [简体中文](../../zh-CN/engineering/archive-opening.md) | [繁體中文](../../zh-TW/engineering/archive-opening.md) | [日本語](../../ja-JP/engineering/archive-opening.md) | 한국어 | [Français](../../fr-FR/engineering/archive-opening.md) | [Deutsch](../../de-DE/engineering/archive-opening.md) | [Español](../../es-ES/engineering/archive-opening.md) | [Português (Brasil)](../../pt-BR/engineering/archive-opening.md) | [Русский](../../ru-RU/engineering/archive-opening.md)

데스크톱 파일 선택, 파일 관리자 요청과 CLI는 같은 Rust 원본 열기 규칙을 사용합니다. 호스트는 허용된 볼륨 집합을 확인하고 원본 식별 정보를 기록한 뒤 허가된 바이트를 검사합니다. 선택된 백엔드는 때로 [격리된 형식 작업 프로세스](native-codecs.md)를 통해 [탐색 메타데이터](readonly-browser.md)를 제공합니다. 항목을 명시적으로 열면 연결된 앱을 위한 검증된 임시 사본이 만들어집니다. 전체 압축 파일을 확인하려면 별도의 [무결성 검사](archive-checking.md)를 사용합니다.

TAR로 보이는 헤더가 전체 구조 검사에 실패하면, 형식을 식별하지 못한 원본과 동일한 후보 순서와 공용 입력 한도로 검사합니다. TAR 헤더와 유효한 자체 압축 풀기 ZIP 파일이 모두 확인되지 않은 경우에만 마지막으로 독립 LZMA를 시도합니다.

<a name="xdzip-split-zip"></a>

## 분할 ZIP

읽기 계층은 `name.zip.001`, `.002` 같은 연속된 번호의 바이트 스트림과 `name.z01`, `.z02`, 마지막 `name.zip` 같은 PKZIP 볼륨을 지원합니다. 어느 볼륨에서나 열 수 있습니다. 볼륨은 같은 디렉터리에 연속된 이름으로 있어야 하며 최대 1,024개입니다. 누락된 볼륨, 링크, 특수 파일은 거부합니다. 확장자는 인접한 볼륨 집합을 찾는 데만 사용합니다. 실제 컨테이너는 원본 바이트로 판별하고 백엔드가 전체를 검사합니다.

ZIP64의 기존 디스크 번호가 0xFFFF이면 인접 locator의 제한된 총 볼륨 수를 이용해 실제 집합을 먼저 찾습니다. 이 자리표시자를 65,535개 볼륨이 누락된 것으로 오인하지 않습니다. 이 탐색은 종료 레코드와 디렉터리의 전체 검증을 대체하지 않습니다.

Rust 호스트는 각 볼륨의 식별 정보, 길이, 수정 시각을 보유합니다. 논리 입력은 압축 파일 전체를 합치지 않고 필요할 때 볼륨 경계를 넘어 읽습니다. PKZIP 디스크 상대 오프셋은 단일 볼륨의 제한된 중앙 디렉터리 뷰로 변환합니다. 기존 코덱은 디렉터리, 로컬 헤더, CRC, 암호 인증과 추출 할당량을 계속 검사합니다. 모든 원본 볼륨을 사용할 때마다 그리고 결과 확정 전에 다시 검증하며, 변경되면 작업을 중단합니다. 모든 원본 볼륨의 식별 정보는 출력에 의한 덮어쓰기에서 보호됩니다.

PKZIP 정규화는 승인된 중앙 레코드만 처리하며 중앙 디렉터리 디지털 서명 종료 레코드를 지원하지 않습니다. 이 거부는 서명 검증 실패를 뜻하지 않습니다. 일반 단일 볼륨 압축 파일은 해당 레코드를 제한된 범위에서 읽을 수 있지만 암호 서명을 검증하지 않으며, 재배치 중 알 수 없는 메타데이터가 사라지거나 손상되지 않도록 수정을 거부합니다.

검수 범위에는 번호 볼륨, PKZIP, ZIP64, 볼륨을 가로지르는 헤더와 데이터, 누락되거나 연속되지 않은 볼륨, 원본 교체, 잘못된 디스크 번호, 중국어 이름과 일반 단일 볼륨 회귀 검사가 포함됩니다.

<a name="xdzip-7z-and-rar-volumes"></a>

## 7z 및 RAR 볼륨

번호가 매겨진 7z 볼륨은 name.7z.001, .002처럼 연속된 바이트 스트림입니다. RAR은 name.partN.rar 또는 name.rar, name.r00 같은 이전 이름을 사용하며 격리된 Rust RAR 리더에 전달할 때 각 물리 볼륨의 경계를 유지합니다. 두 형식 모두 존재하는 어느 부분에서나 같은 디렉터리의 집합을 찾을 수 있습니다. 제한은 1,024개 볼륨과 디렉터리 탐색 항목 100,000개입니다. 누락 볼륨, 이름 번호 충돌, 링크, 재분석 지점은 명시적으로 거부합니다.

Rust는 각 볼륨 핸들의 식별 정보, 길이와 타임스탬프를 보유하고 ReadSource::volume_lengths()로 네이티브 어댑터에 허가 범위를 알립니다. 네이티브 프로세스는 허가된 범위만 호스트에 읽도록 요청할 수 있으며 볼륨을 바꿀 때 압축 파일이 제공하는 임의의 호스트 경로를 허용하지 않습니다. 모든 볼륨은 원본 재검증과 출력 덮어쓰기 방지 대상입니다. 첫 볼륨이나 이후 어느 볼륨이든 변경되면 작업이 중단됩니다.

7z와 RAR의 파일 이름 암호화에는 열 때 암호가 필요할 수 있습니다. 일반 Open이 password_required를 반환하면 인덱스를 게시하지 않습니다. Qt는 기존 암호 창을 재사용하고 처음 선택한 파일과 길이가 제한된 비밀을 OpenWithPassword로 다시 보냅니다. 검증 값이 틀리면 wrong_password를 반환합니다. 성공 후에는 세션과 승인된 작업만 암호를 보유합니다. 세션을 닫으면 그 사본을 해제하며 설정이나 복구 기록에 쓰지 않습니다.

<a name="xdzip-cab-volumes"></a>

## CAB 볼륨

CAB 볼륨 이름은 헤더에서 가져오며 유효한 파일 이름이면 무엇이든 가능합니다. 번호 볼륨의 바이트 연결 규칙은 적용되지 않습니다. 다음 참조는 한 번에 한 볼륨씩 진행합니다. 논리적 이전 참조는 바로 앞 볼륨이 아니라 이어지는 파일이 처음 나타난 더 앞의 볼륨을 가리킬 수 있습니다. 기존 샘플에는 바로 앞 볼륨을 참조하는 경우도 있습니다. 사용자가 선택한 볼륨에서 Rust는 논리적 이전 참조를 역방향으로 따라간 다음 같은 디렉터리의 전체 집합을 순방향으로 찾습니다. 집합 식별 정보, 연속된 볼륨 순서와 각 식별 정보를 검증한 뒤 각 볼륨의 길이와 원래 이름을 고정합니다. 디코더는 모든 파일 조각을 검증하며 인접하지 않은 이전 볼륨은 이어지는 파일이 실제로 시작한 볼륨이어야 합니다. 제한은 1,024개 볼륨과 같은 디렉터리의 탐색 항목 100,000개입니다. 누락, 오류, 순환, 중복 식별 정보, 절대 경로, 디렉터리 구분자, 상위 경로 탈출, 링크와 재분석 지점을 거부합니다. 열린 부분 집합을 완전한 압축 파일로 게시하지 않습니다.

작업 프로세스의 볼륨 변경 콜백은 이 허가된 집합의 이름만 선택할 수 있으며 각 볼륨은 별도의 제한된 스트림을 제공합니다. 모든 볼륨은 작업과 파일 확정 전의 원본 재검증 및 출력 덮어쓰기 방지에 참여합니다. 네이티브 처리기의 경고나 볼륨 누락 결과를 성공한 인덱스로 바꿀 수 없습니다. 단일 및 분할 CAB는 읽기 전용입니다.

<a name="xdzip-double-clicking-regular-files"></a>

## 일반 파일 두 번 클릭

디렉터리를 두 번 클릭하면 이전처럼 그 안으로 들어갑니다. 일반 파일을 두 번 클릭하면 해당 물리 항목만 포함한 백그라운드 추출 작업이 제출되고 사용자 개인 캐시의 임의 이름 디렉터리에 출력됩니다. 링크와 특수 객체는 이 경로로 열 수 없습니다. 암호, CRC, 인증, 취소와 앱 전체의 무거운 작업 순차 승인은 계속 적용되며 사용자가 추출 대상을 고를 필요는 없습니다.

출력이 성공하면 명령 인터프리터 없이 로컬 파일 URL로 시스템 연결 프로그램을 호출합니다. 시스템이 열기 요청을 수락한 경우에만 해당 작업 진행 창을 자동으로 숨깁니다. 추출 실패, 취소 또는 시스템 거부 시 창은 읽을 수 있는 오류와 함께 계속 표시됩니다. 시스템 수락은 외부 앱이 파일 읽기를 마쳤다는 뜻이 아니므로 요청을 보낼 때 임시 파일을 삭제할 수 없습니다.

임시 디렉터리는 예측할 수 없는 128비트 임의 이름을 사용하며 데이터와 식별 마커를 분리합니다. 출력 디렉터리는 현재 사용자와 신뢰할 수 있는 시스템 주체만 접근할 수 있습니다. Windows에서는 이 작업 전용으로 새로 만든 빈 디렉터리에만 보유한 핸들을 통해 보호된 DACL을 설정하고 평문을 쓰기 전에 다시 검사합니다. 사용자가 선택한 디렉터리의 공유 권한은 변경하지 않습니다. POSIX는 0700을 사용하고 상속된 macOS ACL을 확인합니다. 권한을 보장할 수 없으면 출력을 거부합니다. [Win32 DACL API](https://learn.microsoft.com/en-us/windows/win32/api/aclapi/nf-aclapi-setsecurityinfo)를 참고하세요.

잠금이 유지되는 동안 정리하지 않습니다. 완료된 출력은 최소 7일 동안 보관하고, 이후 임시 열기 때 만료되고 잠기지 않은 디렉터리를 정리합니다. 캐시는 최대 256개 항목을 보유하며 한도에 도달하면 명시적으로 거부합니다. 각 검사는 4,096개 항목으로 제한합니다. 정리는 개인 권한, 마커와 이름을 검증하고 링크를 따라가지 않습니다. 임시 사본의 변경 사항은 압축 파일에 다시 쓰지 않습니다.

임시 파일 정리는 앱이 만든 개인 캐시로 제한하며 사용자의 추출 디렉터리를 검사하거나 삭제하지 않습니다. 검수 범위에는 성공 시 자동 숨김, 실패 시 창 유지, 취소, 암호 재시도, 중복 파일 이름, Unicode와 특수 문자, 페이지를 닫은 후 작업 라우팅, 임시 디렉터리 안전과 종료 시 정리 정책이 포함됩니다.

읽기 전용 [Brotli/TAR.BR](brotli-streams.md) 승인은 행을 게시하기 전에 헤더 없는 후보를 완전히 검증하고 Brotli/LZMA 후보 읽기 장부를 공유합니다. 강한 원본과 유효한 TAR/ZIP 발견의 우선순위를 유지하며 손상된 디코딩 TAR을 일반 스트림으로 낮추지 않습니다.

[LHA/LZH](lha-containers.md) 후보는 게시 전에 헤더와 이름의 완전하고 제한된 검증이 필요하며 0 하나로 된 빈 압축 파일도 포함합니다. 약한 LHA, Brotli, LZMA 후보는 실제 읽기 장부 하나를 공유합니다. 강하고 유효한 컨테이너 발견이 우선하며 완전한 LHA 승인은 유효하지 않은 원시 TAR 표식의 모호함을 해소할 수 있습니다. 암호, 볼륨, 복구 프로필은 승인하지 않습니다.

[PMA](pma-streams.md)는 같은 약한 탐색 공유 장부와 완전한 메타데이터 승인을 사용하며 정확한 0 종료자와 선택적인 제한된 CP/M 채우기를 허용합니다. 레벨 0 PM0/PM1/PM2 콘텐츠를 지원하고 알 수 없는 방식은 표시하되 지원하지 않습니다. 채워진 빈 CP/M 컨테이너는 PMA로 식별하며 구별할 수 없는 1바이트 0 종료자는 이전 LZH 선택을 유지합니다. 생성, 암호, 볼륨, 수정, 복구 프로필은 승인하지 않습니다.
