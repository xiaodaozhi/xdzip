# RAR 獨立實現依據與相容邊界

[English](../../engineering/rar-format-sources.md) | [简体中文](../../zh-CN/engineering/rar-format-sources.md) | 繁體中文 | [日本語](../../ja-JP/engineering/rar-format-sources.md)

RAR 自研遷移保留舊版、RAR5、RAR7、密碼、頭部加密、固實與授權分卷的完整隻讀範圍，不開發 RAR 編碼器。能力替代及官方依賴退出仍由[遷移任務 #51](https://github.com/xiaodaozhi/xdzip/issues/51)驗收；容器程式碼或 Store 讀取存在不代表完整遷移。現有產品路由與來源見[隔離後端契約](native-codecs.md)。

<a name="xdzip-来源和角色"></a>

## 來源和角色

現代容器欄位依據 RARLAB 的 [RAR 5.0 格式技術說明](https://www.rarlab.com/technote.htm)，RAR7 演算法辨識參考 [UnRAR7 說明](https://www.rarlab.com/unrar7notes.htm)。技術說明並未完整公佈壓縮、歷史密碼、VM 或 checksum tweak 演算法，不能從方法名稱推導缺失狀態機。線上技術說明沒有獨立版本號或簽名，不把儲存的 HTML 當作上游簽名釋出。

舊容器及官方技術說明未覆蓋的接受行為，經獨立分析者按固定 UnRAR 來源形成純事實交接。固定參考的上游內部版本為 7.30 beta1，下載歸檔檔名為 `unrarsrc-7.3.1.tar.gz`，不據檔名另推上游發行版本。歸檔 SHA-256 為 `634900842a3737d9cc15bbcc71d4c74cc713437e0bca296a573424fe5f2660ab`，許可為 UnRAR，精確原始許可與來源說明見[有限對映材料](../../../third_party/rar-wire-mappings/README.md)。容器、現代 LZ/過濾器、固實與密碼分別交接，不據某一稿存在宣稱其他演算法已經完成分析。

## 容器候選契約

`xdzip-codec-rar` 依賴專案的 codec API、domain、共享 compression/crypto，以及已准入的通用 AES、SHA2 壓縮原語與歸零設施。CRC32 複用共享實現，不引入第三方 RAR、歸檔或壓縮格式庫。它實現 `MetadataCodec`/`PayloadCodec`，經共享 CXX 橋接在既有隔離 worker 中執行，沒有官方失敗回退。該接線本身不替代完整相容驗收，產品路由切換仍遵守[遷移契約](independent-rust-codecs.md#xdzip-%E5%AE%9E%E7%8E%B0%E8%BE%B9%E7%95%8C)。

- 宿主提供有序授權流及每個物理卷的長度，最多 1,024 卷。卷內範圍先檢查再換算絕對位置，包內名稱不賦予路徑訪問許可權。每卷重新識別頭部，檢查格式代、卷號、頭加密狀態及繼續關係；只有顯式 split-before/after 合併，普通同名記錄保留獨立身份。普通檔案與 service 繼續鏈分別儲存，service 不佔普通 EntryId。
- 1.5..4 普通頭低 16 位校驗來自通常 CRC32，現代頭儲存完整 CRC32；更早的 1.4 容器沒有頭 CRC，其獨立內容 checksum 不能混用。先驗證普通明文頭校驗，再解釋有界欄位與 extra。現代 vint 最多 10 位元組，最後位元組只允許有效位 0/1，允許數學值正確的非最短表示；head-size 自身最多 3 位元組，明文總頭最多 2 MiB。未知可跳 extra 按其邊界跳過，未知必要解碼特性不能假作普通內容成功。
- 私有索引保留每片原始頭、卷/頭/packed 範圍、known/unknown 尺寸、原始名稱、解碼版本、壓縮強度、宣告/生效演算法、字典、solid、時間、型別、CRC/hash 與密碼描述。公開 method 保留 UnpVer，例如 50 或 70；公開 packed_size 為首次可見片的 packed 大小，不替換成所有片總和。EntryId 按首次可見普通記錄順序從 1 連續分配。
- 舊名稱先按宣告 Unicode 的數學命令解析，否則呼叫共享歸檔級舊編碼檢測。保留原始名稱區，字元解碼完成後才轉換舊路徑分隔符，避免誤拆多位元組字元中的 `0x5c`。Unicode surrogate 必須完整配對，拒絕截短命令、嵌入 NUL 及越界複製。RAR5 嚴格驗證宣告 UTF-8，對映 Unix 名字和 redirection 保留警告，連結及特殊物件不能普通輸出。
- 後設資料讀取最多 64 MiB，物理頭記錄最多 100,000，單名稱最多 4,096 位元組，原始名稱合計及解碼/展示各最多 16 MiB，呼叫方更低限制優先。負載重掃繼續累計原有輸入餘額，實際輸入和解碼工作各最多 20 GiB，單檔案最多 8 GiB；演算法工作區在執行前按預設 1 GiB 記憶體上限准入。
- 演算法注入介面只接收有界明文 packed 流、借用控制與宿主 sink。容器負責片級 packed 校驗、解密、完整輸入消費、精確檔案尺寸及最終完整內容校驗，演算法負責其狀態、壓縮流終止和自身記憶體預檢。候選執行 Store、13/15 族、20/26 族、RAR29 LZ/PPM 與現代 LZ，按不超過 8 KiB 的塊輸出，不累積整個檔案。目錄僅在零尺寸、零 packed、原頭複驗及所需空內容校驗成功後完成；名稱 warning、link 與特殊記錄先拒絕，不能繞過公共條目准入直接輸出。
- 識別到的領域 I/O 錯誤先保留其類別，只有沒有包裝錯誤的裸 Interrupted 可以重試。取消、配額、來源改變、I/O、輸出失敗或校驗失敗後例項 poison；不會把失敗當 EOF、entry_done 或釋出資格。宿主持有來源身份、路徑檢查、私有暫存及最終提交。公共 DecodeError 暫無獨立 SourceChanged 變體，對映為 SourceIo，來源宿主保留具體原因。

<a name="xdzip-现代-lz-候选规格"></a>

## 現代 LZ 候選規格

- 實際演算法 0 使用 64 距離符號，演算法 1 使用 80 距離符號。宣告版本 1 的相容位仍選擇實際演算法 0，不能按工具版本或副檔名選樹。獨立 MSB 位讀取與規範 Huffman 樹讀取宣告有效位，不復用 Deflate 的 LSB 碼序。新表的目標碼長分別為 430/446 項，未使用的樹可以為空，消費不存在程式碼、過度訂閱或越界遊程明確失敗。
- 塊頭校驗、末位元組有效位與最後塊標誌共同決定位流終態。已知輸出尺寸、最終內容 CRC、完整 packed 消費各自檢查，不能在產生宣告大小時提前成功。空塊不做無符號下溢；沒有有效表不能解碼內容。候選對越界遊程、未完成過濾範圍、尾隨 packed 位元組等採取嚴格策略，健康樣本透過不證明這些策略與所有歷史恢復行為一致。
- 非 solid 壓縮檔案重置字典有效歷史、最近距離、上次長度和表；solid 壓縮檔案保留它們，每檔案仍重置輸入塊、過濾器和檔案偏移。採用首次壓縮檔案確定的有效視窗，最小工作視窗為 256 KiB；非二次冪視窗按真實模數環繞。後續較小或非冪宣告不改變既有模數，中途增大明確 Unsupported，不復制依賴舊分配快取的壞連結受例外。非 solid 更換視窗時先釋放舊視窗，避免兩個大視窗同時存活。
- Store 自身無論 solid 位是否置位都只複製並校驗檔案，不向 LZ 字典加入內容，也不清空表、最近距離或上次長度。目錄和 service 不成為新的壓縮初始化點。隨機選擇 solid 檔案從前一個非 solid 壓縮檔案恢復，按物理順序實際解碼字首；Store 不是恢復點，跳過內容和重複重放都計入實際工作。
- Delta、x86 E8、x86 E8/E9 與 ARM 過濾器處理獨立的完整邏輯區間。過濾前位元組始終作為 LZ 歷史，變換後的副本才交給檔案 CRC 與 sink。區間可跨塊/物理卷，不能跨檔案；起點及檔案偏移不與環形下標混淆。單區間最多 4 MiB、掛起項最多 8,192，重疊、倒序、未知變換及不完整區間拒絕。資源上限是候選治理策略，不聲稱為格式極值。
- 指令批次最多 8 KiB 計劃輸出或 256 條指令。執行前僅在本地預留剩餘工作配額，不向公共 sink 報告尚未執行的進度。執行後，包括部分失敗和取消前已完成的位元組，只結算真實 WORK 並轉換為單次預計費額度；未執行的預留不能成為輸出額度，失敗後不復用。完整過濾區間暫存期間也持續累計實際工作。預計費交付前扣減容器私有額度，最終尺寸、CRC、取消和寫入失敗仍檢查；預設 sink 可能保守再次計費。Store 保持普通輸出計量。worker 透過 PRECHARGED_DATA 交付已有額度的 RAR 內容，Native 接收端與執行時分別核驗宿主額度、精確尺寸及配額；重啟、結束或失敗後不能複用舊 worker 額度。
- LZ 字典之外預留 288 MiB，用於有界後設資料、過濾副本、佇列及其他狀態，合計先按 1 GiB worker 上限准入。它是保守記憶體政策，不是線格式最大字典，不能把格式可宣告尺寸當可分配許可。取消和錯誤使整個負載狀態 poison，不以保留的半字典繼續另一條目。

<a name="xdzip-大逻辑字典的精确存储"></a>

### 大邏輯字典的精確儲存

現代實際演算法 1 的壓縮檔案在完整字典超出連續儲存准入時，採用精確 Constant/Raw 分頁歷史，邏輯視窗最多 1 TiB。頁尺寸為 64 KiB，每頁獨立儲存一個常量位元組或獨佔原始緩衝，讀寫和距離仍按原邏輯視窗的真實模數執行。尚未產生的歷史不可讀，重疊匹配逐位元組執行；歷史儲存過濾前內容，不與最終輸出緩衝別名。其他演算法、Store、未知方法和服務記錄不獲得大字典准入例外。

分頁目錄、槽表、空閒池、所有保留容量、臨時峰值、私有狀態及 16 MiB allocator allowance 合計最多 512 MiB，外圍 288 MiB 與密碼狀態另計，worker 的 1 GiB 上限保持不變。每次分配之前檢查預算，不能按邏輯視窗預留巨大地址空間或轉為磁碟歷史。常量頁發生不同值寫入前完整初始化一個 Raw 頁，只有完整順序覆蓋該頁的有效長度且所有新位元組相同時才摺疊。半頁的固實續寫保留原尾部與候選狀態，非固實替換先釋放舊儲存。歸還池中緩衝仍按真實容量計費。

目錄、槽表和 Raw 頁的實際初始化使用獨立輔助工作通道，按最多 8 KiB 分塊檢查取消並結算；它不增加檔案進度或交付信用。寫入先完成可失敗的儲存準備，再接受輸出位元組，最後無分配地提交歷史。輸出拒絕時不改變歷史位元組或遊標，已執行的初始化不退款，錯誤仍使負載 poison。該表示可高效處理常量頁，不保證任意低熵流或任意大字典都能在預算內完成；Raw 工作集過大仍明確 Limit。

真實演算法 1 的互操作檢查僅在 build/CI 獲取固定來源的壓縮測試資料與 notice，檢查原始頭身份以及全部原文 SHA-256、CRC、尺寸、WORK、AUX 和保留容量；不儲存大明文或第三方實現。數學頁測試與獨立健康壓縮流分別記錄，單個成功流不證明所有擴充套件距離或加密、固實、跨卷組合已驗收。


現代 x86 的獨立已知原文可按[受控 PE 資料配方](../../../crates/xdzip-codec-rar/tests/fixtures/modern-x86-owned/README.md)驗證。官方作者正常生成的流須實際選擇 E8 或 E8/E9，並同時透過直接 LZ、Payload 和真實 worker 的完整內容核對；PE 名稱、工具版本或描述符計數本身不足以證明成功。資料輸入不執行，不在倉庫儲存 PE 或生成歸檔，其他固實、加密、跨卷組合仍分別驗收。

<a name="xdzip-rar29-ppm-候选规格"></a>

## RAR29 PPM 候選規格

- `xdzip-compression` 共享有序統計上下文、二元機率、SEE、排除、後繼實體化及名義容量賬本。RAR29 和 7z 透過不同的 range 介面卡使用同一模型，不復制第二套統計實現。RAR 採用四位元組 carryless 初值、獨立歸一化及雙分支丟棄除法餘數的二元區間；7z 保持原有五位元組初值、餘數和終態規則。
- 模式頭從已對齊的完整 F 位元組開始。reset 位決定整個模型是否重建，記憶體欄位表示 1..256 MiB 名義容量，order 按頭欄位對映至可編碼的 2..64 範圍。可選 escape 僅在宣告時更新，reset 不把它自行恢復為預設值。保留請求必須已有連續性明確的有效模型；每次模式初始化仍重建四位元組 range，不能用無頭的跨檔案續讀替代。獨立隨機起點缺失此前模型時明確失敗。
- 名義 12 位元組單位及確定性等級、碎片、合併和借用規則控制格式規定的模型重啟；Rust 物件、歷史、索引、遍歷 scratch、固定狀態及其他解碼狀態另外按真實儲存准入。reset 先釋放舊 arena，避免雙份大分配。容量重啟保留目前已經解出的 symbol 和 range；實際 OOM、配額、取消、源 I/O 或模型不變數錯誤均為終止失敗，不能冒充容量重啟。
- 新 arena 初始化和容量重啟先准入輔助工作預算，實際填充或清空按最多 64 KiB 的儲存塊及有界機率錶行執行，檢查取消並累計已完成的初始化位元組。後續 range 讀取失敗、取消和 `clear` 都不退回已經執行的工作。外層在成功與失敗路徑結算實際差額，與控制及引數 symbol 的輔助工作共同計入累計 20 GiB 上限；獨立 AUX 通道不產生可交付檔案位元組的預計費額度，未來預留也不冒充實際進度。
- PPM 每次交付一個完成統計更新並歸一化的模型位元組，escape、過濾器引數和匹配引數均正常更新模型。RLE 或 LZ 複製產生的檔案位元組不再次喂回 PPM。檔案終止、模式切換、輸出尺寸、內容 CRC 和宣告 packed 邊界由外層核驗；RAR 不接受逃逸出根作為 7z END，也不施加 7z 的末尾 code-zero 條件。失敗模型保持 poison，只有外層明確恢復時才清除狀態。
- 實際解出 PPM EOF 後，外層排空受完整宣告 packed 範圍約束的剩餘輸入，繼續檢查輸入配額、取消和分片校驗。PPM 算術尾不套用現代 CBC 的 0..15 位元組對齊限制；沒有真實 EOF、尺寸或 CRC 不符時不能借尾部政策成功。PPM EOF 後下一個 solid 檔案重新讀取模式頭和新 range，reset 位單獨決定是否保留統計模型。固定參考對 escape 後控制 1 及 6..255 均輸出一個字面 escape；若候選嚴格拒絕 6..255，應單獨登記接受範圍差異，不能冒稱參考也拒絕。


<a name="xdzip-rar29-lz-与标准过滤器候选规格"></a>

## RAR29 LZ 與標準過濾器候選規格

- RAR29 獨立讀取 MSB 位流，404 個差分碼長分成 299/60/17/28 符號樹。舊碼長基線、低四位距離重複、最近四距離和上次匹配長度在壓縮狀態內儲存，不把現代 64/80 距離表套入舊演算法。檔案終止符同時控制下一固實檔案是否重讀模式；未初始化的複用、空樹消費、越界遊程、輸出越界及歷史之前的距離均失敗。
- PPM 外層 escape 控制檔案終止、模式切換、字面 escape、過濾器與兩種複製。引數位元組仍經模型解碼，匹配輸出只進入 LZ 歷史與最終檔案流，不反向修改統計模型。PPM EOF 的剩餘 packed 排空政策與純 LZ 的位流終態分別處理。
- 標準過濾器程式先檢查有界 packet、程式長度、XOR 與固定 CRC/長度身份，僅選擇 E8、E8/E9、Itanium、Delta、RGB、Audio 六種已有產品基線變換。候選不執行任意包內 VM。定義、快取長度及最後選擇保留固實狀態，每檔案重新計算偏移，未完成區間不能被 reset 丟棄。
- 未過濾位元組保持為 LZ 歷史，相同起點和長度的標準變換可串聯，其他重疊、倒序及未完成區間拒絕。單區間長度 1..262,143 位元組，最多 8,192 個定義和掛起項，是候選資源政策。Delta 通道最多 1,024，Audio 最多 128；各自線引數和初始化緩衝均先准入。
- 舊 E8 的 PC 使用完整 32 位檔案位置，不按現代規則取 16 MiB 模。Itanium 按原始 bundle/template 和指令欄位變換，RGB 與 Audio 各有獨立預測狀態。Audio 包含首個取樣的適配及負係數到 -17 的邊界，不能由現代 Delta 或 E8 數學向量代替。
- 每個實際變換位元組、PPM 引數與實際模型初始化均扣輔助工作預算。輔助工作透過獨立 `charge_auxiliary` 通道、至多 64 KiB 的非零訊息結算，不能增加 decoded_bytes、膨脹率分子或交付 credit，跳過固實字首仍轉發該通道。worker、Native 接收端與執行時分別執行[輔助工作契約](auxiliary-decoding-work.md)；將輔助量交給 WORK 的早期候選不滿足該計量契約。處理迴圈分塊檢查取消，失敗前已完成的輔助工作不退款。


<a name="xdzip-古老容器与历史密码候选规格"></a>

## 古老容器與歷史密碼候選規格

- 1.4 主頭最小 7 位元組包含 `RE~^` 標記，檔案頭固定 21 位元組後跟有界名稱和可跳額外材料，payload 從宣告 headSize 末尾開始。main 的 0x01/0x08 分別表示卷和全域性 solid；原檔的 0x80 不是後代頭加密位。檔案只用 0x01/0x02/0x04 表示 split-before/after/加密，目錄來自 DOS 屬性，不復用後代檔案視窗或 solid 位。字典固定 64 KiB。
- 古老方法值直接使用 0..5，selector 2 映為公開 UnpVer13，其餘映為 10。壓縮准入僅開放有既有基線的 13/15，10 只允許 Store。全域性 solid 從第二個邏輯檔案開始延續狀態，物理繼續片繼承同一邏輯檔案狀態；新檔案重置位讀取和內容校驗，Store 不向壓縮字典注入內容。
- 每個古老邏輯檔案從 16 位 c=0 開始，對實際最終輸出 byte x 計算 `c=ROTL16((c+x) mod65536,1)`，最後直接比較最終頭的 u16，不末 XOR。中間片 u16 原值保留，但不作為 packed CRC；完整內容 checksum 連續跨片，solid 前檔案的 checksum 不傳給下一檔案。後代容器的同代演算法仍使用其普通 CRC32。
- 古老加密始終選擇 old13 位元組密碼族，無 salt/IV，selector10 不改變它。後代 13/15 使用各自位元組族，20/26 使用舊分組族，RAR3 使用原創 SHA1 派生組合和 AES128-CBC。每邏輯檔案 fresh cipher，物理 split 片連續，密碼狀態不隨壓縮固實狀態跨檔案。old13/15 不接受塊對齊尾，舊分組密碼的 Store 根據真實尺寸擷取，RAR29 PPM 的宣告尾政策另外適用。
- RAR3 加密頭每頭重新讀取 8 位元組 salt，先解首塊取得真實頭長，再核驗本卷完整對齊跨度及普通頭 CRC。保留原始 salt/密文供負載複驗。外層先檢查 4,096 UTF8 位元組，舊路徑另外保持原 native callback 的完整輸入最多 511 個本地寬單元，包括首個 NUL 後的輸入；之後才取首個 NUL 前內容並應用 crypt 的 127 單元邊界。它是歷史宿主入口限制，不是格式密碼長度規範，現代 KDF 的現有入口政策另列。
- Windows 僅對非古老容器且 HostDOS 的舊檔案，先將零填充完整 512 UTF16 單元送宿主 OEM 到 ANSI 寬投影，再在寬索引 127 截止。舊 13/15/20 接著經 ANSI 編碼到 512 位元組緩衝，再在原始 byte127 截止，允許落在 DBCS 中間；RAR3 直接使用投影后的寬單元低 16 位。古老內容不執行後代 DOS 補償。轉換使用同步借用宿主服務，系統失敗明確 Unsupported，typed 來源錯誤及取消保持原類別；無服務時僅使用可證明相同的 ASCII 路徑。
- macOS 的舊窄密碼先取 127 Unicode scalar，再明確編碼 UTF8，最後原始 byte127 截止，允許形成不完整尾序列。普通 Linux 使用目前執行緒 locale 的有狀態轉換，EILSEQ 重試後保留實際字首；本專案獨立 worker 未為此切換程序 locale。帶 U+FFFE 的 Linux 恢復路徑在 Rust 移除標記、恢復 U+E080..E0FF 原 byte，普通單元仍交給宿主轉換，不能把該協議套到 Apple 或無標記字串。RAR3 非 Windows 寬投影保留原始 scalar 字首，再取單元低 16 位，低 16 位為零不被誤作原始 NUL。中間寬、窄、單字元及金鑰緩衝均歸零，固定投影 scratch 單獨預算 4 KiB。
- 沒有可信獨立 verifier 時，頭 Invalid 或內容 Integrity 返回 PasswordOrIntegrity，供宿主安全重試；SourceChanged/SourceIo、Limit、Cancelled、Output、Unsupported 不被包裝成密碼歧義。已驗證的現代 check mismatch 仍是 WrongPassword，已驗證金鑰下的損壞仍是完整性錯誤。物理原頭複驗變化按來源錯誤處理，不據密文變化誤報密碼。


<a name="xdzip-历史辅助头与前缀候选规格"></a>

## 歷史輔助頭與字首候選規格

- 嵌入舊 comment 時，main parent CRC 只覆蓋固定 13 位元組，file parent CRC 覆蓋實際消費的固定欄位、LARGE、名稱、salt 和已解釋的前三種擴充套件時間；archive-time 槽不消費。type75 child 獨立驗證固定 13 位元組 header CRC，並限制在父 HeadSize 中。註釋內容可有界跳過，不聲稱驗證其內容 CRC，也不把參考後續 full-read/BrokenHeader 恢復流程翻譯成格式規則。
- AV76、SIGN79 只按 common7、LONG 時額外 dataSize4 和宣告資料範圍跳過；UO 僅 type77+subtype0x0101 精確免 generic CRC，按公共 14 位元組和宣告範圍定位。其他 subtype 和普通檔案仍執行正常頭 CRC，不掃描 NUL 猜測歷史字串尾。
- END 在可選 archiveCRC/卷號後跳過已宣告 opaque 尾。只有 END+REVSPACE 的正常 CRC 失敗，且本次讀取結束前七個物理原位元組全零，才能使用精確歷史豁免。它相對目前物理頭末尾，不相對卷 EOF；頭加密時檢查 salt/cipher 物理區間的末七位元組，不能檢查解密後的邏輯尾或消費 END 後 trailer。加密 REV 仍缺獨立實樣。
- 古老 SFX 在偏移 1 保留特殊接受路徑；偏移至少 2 且實際掃描長度超過 31 位元組時要求絕對 byte28..31 為 RSFX。完整授權搜尋的古老標記最大起點為 4 MiB−19。候選有界補齊授權流的短讀，不復制舊 native 單次 64 KiB 返回量造成的更窄搜尋範圍。字首永不執行。
- Windows 舊 Unicode 無修正高位 run 按已驗證的 signed-char 到 16 位單元擴充套件，帶修正的 run 仍按低 byte 數學處理，二者不能混用。非 Windows 對該高位無修正分支暫保留 Unsupported，等待本地 ABI 與寬轉換實樣；公共字串仍須為有效標量且經過共享名稱安全政策。


<a name="xdzip-1315-族候选规格"></a>

## 13/15 族候選規格

- 13 與 15 保留各自公開 UnpVer，進入同一獨立自適應解碼器。視窗固定 64 KiB，有限規範碼錶、字面排名、距離排名、標誌模型、Short 變體及特殊模式分別表達，不復用後代差分碼長表或複製另一套 Deflate/PPM。
- 首個非 solid 壓縮檔案重置歷史和統計；後續 solid 壓縮保留字典、排名及匹配狀態。每檔案仍重新初始化位遊標、flags/repeats/special 狀態，不能把前檔案剩餘控制位或特殊模式帶到新檔案。Store 不呼叫壓縮初始化，也不填充或清空壓縮歷史。
- 每次實際輸出前先檢查宣告剩餘尺寸和有效歷史距離，匹配不得越過檔案末尾。達到真實 unpacked size 後完整消費宿主授權的剩餘 packed 輸入，繼續計入輸入配額和取消，不虛構本代不存在的現代末塊標誌。沒有足夠真實位時失敗，不用零位元組補齊。
- 有界匹配和至多 8 KiB 輸出批次先預留本地預算，已執行的位元組在成功或失敗路徑結算，只有原始產生位元組可建立一次性交付額度。錯誤後壓縮例項 poison，只有明確 reset 才能使用新的獨立狀態；solid 起點缺前驅狀態時不能推斷恢復。


<a name="xdzip-现代密码与完整性候选规格"></a>

## 現代密碼與完整性候選規格

- 明文 archive crypt 只允許在本卷 main 前出現一次。後續每頭以自身 IV 重啟 AES256-CBC，先解首塊取得真實頭長，再檢查本卷完整的 IV 與對齊密文跨度。頭 CRC 僅覆蓋真實欄位；對齊尾不解析成 extra。私有物理片保留原始 IV 和密文頭，負載重掃逐字核驗，不能用解密後的等價後設資料代替來源身份。
- 同一 PBKDF2-HMAC-SHA256 鏈的 `2^L`、再加 16、再加 16 次分別形成 AES key、hash key 與摺疊 check，`L<=24`。任務私有 16 槽 cache 及累計預算沿後設資料掃描繼續進入負載物件，不因每個檔案或卷重新獲得配額。預設最多 `2^26` 次實際 HMAC 和 4 GiB 派生雜湊輸入；命中不重複派生，取消前執行的工作不退款。16 KiB 保守 cache/scratch 預算單獨計入演算法記憶體預檢。
- 外層密碼最多 4,096 UTF8 位元組，先檢查該限制，再在首個 U+0000 截止。native 相容 profile 在 Windows 截前 127 個 UTF16 單元，在 Unix 截前 127 個 Unicode scalar，再生成派生位元組。Windows 截斷邊界的孤立 surrogate 僅存在於私有相容位元組，不成為公共 str 或名稱。該平臺差異是參考相容行為，不冒充格式統一規則。密碼、派生中間值和金鑰使用歸零生命週期，不能承諾擦除系統的全部歷史副本。
- 只有 check 自身 SHA256 checksum 有效，且不是舊 service 的全零不可信值，才能據 mismatch 返回 WrongPassword。checksum 壞意味著禁用快速檢查，正確金鑰仍可憑結構與內容校驗成功。無可信 verifier 的 Invalid/Integrity 透過公共 PasswordOrIntegrity 保留歧義，不能把這種失敗宣稱為可靠 wrong-password。
- 內容 CBC 每檔案重啟，跨授權 split 片連續，塊可由前片末尾與後片開頭合成。每片 packed CRC/BLAKE2sp 始終先覆蓋物理密文位元組，再進入解密；最終內容校驗覆蓋過濾後的完整明文。片鏈目前要求完整 crypt 引數一致，這是嚴格候選政策，健康樣本不能證明全部歷史分卷寫法均等價。
- Store 根據 unpacked size 擷取真實內容，LZ 根據完整最後塊和有效位終止；其後只允許最小 0..15 位元組對齊尾，尾值不限，不解釋 PKCS7。LZ 的預讀緩衝也參與尾部計數，不能只看外層 CBC 已消費量。完整宣告密文仍須消費和計入輸入。允許更多整塊垃圾的參考恢復行為不在候選成功範圍。
- 複用共享 BLAKE2sp32 流式狀態。存在已知 BLAKE2sp extra 時選其完整寬度校驗，保留基本 CRC 欄位但不同時要求二者，這是固定參考的選擇語義。flag2 宣告 keyed tweak 時，普通 CRC 的 LE4 經 HMAC 後異或八個 LE32，普通 BLAKE2sp32 經完整 HMAC32；無 flag2 時即使加密也不 tweak。未知 hash 仍 Unsupported，CRC/check 均不提供來源真實性。

## RAR20/26 LZ 與 Audio 候選

20/26 族依據純事實交接 `RAR20-26-2026-10-26-v1`，主文 SHA-256 為 `d240cac882e8120eb5f20c7894395732b9798bd133479604ae79d5bde24b04d5`。實現者未閱讀對應 UnRAR、Junrar 或其他第三方 LZ/Audio 演算法實現，不提供 RAR 壓縮編碼器。原始測試歸檔、已知 WAV、測試斷言與許可僅用於獨立資料對照。來源搜尋曾意外返回第三方通用歸檔識別程式碼摘要，未包含或用於本代 LZ/Audio 演算法；不據此作嚴格潔淨室宣告。

20 與 26 共享原創熵與 Audio 狀態機，透過共享有界 MSB 輸入、最多 1 MiB 環形歷史和實際輸出助手解碼。新碼長表不位元組對齊，完整構建後才提交，保留未覆蓋的 1,028 項舊基線；壞遊程越界嚴格拒絕。最近四次匹配按時間保留重複距離。Audio 是寫入真實 PCM 歷史的預測模式，支援 1..4 通道、跨通道差值、每通道第 32 個樣本後適配及 -17..16 係數，模式或表切換不清空預測狀態，非固實才重置。

容器的 known unpacked size 決定內容邊界，匹配不得跨過剩餘尺寸。本代沒有額外強制 EOF 符號。到達尺寸後，候選按目前物理位元組起真實剩餘至少五位元組的穩定規則觀察一個符號，識別下一批表控制時必須完整解析成功，供後續固實檔案保留；其他符號不產生額外內容或更新 PCM。然後排空完整已授權 packed 範圍，保留輸入錯誤、取消和容器校驗。這是明確的舊尾部接受政策，不聲稱等同於參考工具受緩衝狀態影響的所有恢復行為，也不把任意尾部解釋為有效內容。失敗後例項保持 poison，格式 reset 不解除失敗狀態。

歷史初始化與表控制先預留輔助工作，再結算真正完成的操作，不提供輸出 credit；真實生成內容才提供一次交付 credit。候選記憶體預檢包括保守的外圍 288 MiB 及保留的歷史容量，最多使用 worker 的 1 GiB 實現預算。該數值是實現資源政策，不是格式限制。

固定 Junrar `v8.1.0`、提交 `57091f9ccd43661cf8f12c389917cc24950df707` 的 RAR2.06 加密壓縮樣本提供完整 87 位元組獨立內容。另兩個原始 RAR20 Boat 歸檔隨小型來源清單保留在 [legacy20 fixtures](../../../crates/xdzip-codec-rar/tests/fixtures/legacy20/sources.json)，對應公開 WAV 的完整尺寸、SHA-256 和 CRC，包含實際雙通道 Audio 與普通 LZ 對照；原檔位元組未修改，內容的 CC BY-SA 4.0 歸屬及上游原始許可分別保留。宣告式位向量與獨立 Python PCM 數學對照另驗模式切換、1..4 通道、適配邊界、固實狀態、距離、錯誤、配額和輸出失敗，不能替代作者實樣。固定官方 RAR 2.90 作者程式另以本專案數學原文生成普通、固實和強制 Audio 固實三個原始歸檔，見 [自有 RAR20 fixtures](../../../crates/xdzip-codec-rar/tests/fixtures/legacy20-owned/README.md)。每檔三個成員均為真實 UnpVer20，固實後續成員帶真實 solid 標誌；普通迴歸對九份完整輸出共 591,561 位元組逐位元組比較，包含全新 reader 的前驅重放，不依賴作者程式或網路。另有官方 2.90 原生生成的 [RAR26 大檔案實樣](../../../crates/xdzip-codec-rar/tests/fixtures/legacy26-owned/README.md)，真實 UnpVer26、method1、LARGE，已知原文為 2 GiB 加 1 位元組，歸檔約 1 MiB。顯式 release 迴歸只使用有界 sink 與增量 SHA，要求完整 CRC、位元組數和一次交付額度檢查成功，不儲存大明文；普通 debug 測試預設忽略這項重負載。所有舊尾表控制轉換、其他實際 Audio 通道數及其他分卷、固實、加密組合仍須分別覆蓋；修改版本欄位的數學向量不計作者版本 26 互操作。

<a name="xdzip-尚未闭合的兼容条件"></a>

## 尚未閉合的相容條件

13/15 族、20/26 族、RAR29 LZ/PPM/標準過濾器、歷史密碼與早期 checksum 已有候選實現，各歷史組合仍需逐項實樣與整鏈驗收。元件或單個作者檔成功不替代完整遷移。RAR7 生效演算法 1 的獨立壓縮成功樣本由 [#43](https://github.com/xiaodaozhi/xdzip/issues/43)跟蹤，必須分別核對固定來源、完整原文和 worker/runtime 業務鏈，Store、數學位向量和相容演算法 0 樣本不替代它；每種過濾器的獨立真實樣本覆蓋也分別記錄，不能由過濾程式碼存在推定全部驗收。固定現有 UnRAR 基線僅執行六種舊標準過濾器，不據歷史 VM 名稱擴充套件為任意包內程式直譯器。

公開 `Entry.size_known` 區分未知尺寸與已知空檔案。完整片鏈取得一致 known 尺寸時恢復尺寸；全部 unknown 可瀏覽併發布 `size_known=false,size=0`，不會發布歷史內部 sentinel `0x7fffffff7fffffff`。Native ROW 的 `0x40` 僅供 RAR 表示未知尺寸，必須搭配 size=0；保留 CAB 的 `0x20` 語義，其他格式或保留 `0x80` 拒絕。執行時與 Qt 保留該標記，原始大小及含未知尺寸的選中彙總顯示 `—`，狀態明確提示未知，大小升降序都將未知項放在已知項之後，以物理身份穩定打破平局。預檢報告 `unknown_size` 且總量不可知；整包檢查、解壓、臨時開啟及匯出在取得內容前明確拒絕，不把未知項當空檔案，也不使用它充當解碼或輸出配額。

現代 Unix/FILETIME 時間保留私有完整值，公開 DOS 時間透過[宿主日曆服務](host-platform-services.md)投影：直接 API 預設 UTC，產品 worker 使用日期對應本地規則，Rust 保留歷史模運算、128 年 wrap、偶秒截斷及異常 fraction 忽略規則。OS 無法投影時明確定義為 0，有別於參考未檢查系統失敗產生的未定義結果；三平臺完整產品證據仍分別驗收。

舊服務的 LARGE/extended-time 可在完整頭 CRC、必需 32/40 位元組基礎、名稱、64 位 packed 範圍與預算透過後有界跳過。原始尾部保留為不解釋的資料，不猜測 salt/time 分割槽，不構造補零密碼引數，不改變普通檔案時間，不提供服務輸出或服務內容認證。數學後設資料正負對照與健康獨立作者檔分別記錄，缺少健康大服務內容樣本仍是證據邊界。已知原文作者覆蓋包含古老壓縮分卷、RAR20 普通與 Audio 固實、RAR20 與 RAR26 壓縮分卷，以及真實 UnpVer26 的 2 GiB + 1 位元組單檔案；這些有限正例不擴充套件為所有分卷、通道或尾錶轉換已經驗收。非 Windows 的舊 Unicode 高位無修正 run、歷史非 ASCII 密碼密文、舊壓縮和 Store 混排等相容條件繼續分別跟蹤，不以數學容器、純 OS 轉換或宣告版本變異冒充健康作者互操作。

現代無 end 的檔案目前 fail-closed，舊格式允許恰好記錄邊界 EOF。SFX 搜尋限定為前 4 MiB，古老邊界另按上述精確範圍。重複安全 extra 的嚴格拒絕等壞輸入策略不冒稱官方格式禁止。跳過服務內容不提供其完整內容校驗保證。來源身份檢查仍是宿主盡力檢測，不宣稱後設資料重掃形成輸入內容的原子快照。
