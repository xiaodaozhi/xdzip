Windows MSIX 包身份下關於頁不顯示應用內更新區域，更新控制器也拒絕發起現有 GitHub 更新檢查。商店交付時由 Microsoft Store 管理更新；側載包不獲得本應用的自動更新承諾。身份查詢異常按包身份處理，避免誤用安裝器更新。現有普通安裝與其他平臺行為不變。

獨立 CLI 和桌面包內的 CLI 按[命令列契約](command-line.md)更新目前安裝。獨立 CLI 使用單獨簽名清單和管理式版本目錄，桌面 CLI 透過同使用者單例項通道提交候選意圖，桌面控制器再次驗證。accepted 只表示 handed_off，實際成功仍要求回執及執行身份。Windows/Linux 安裝佔用擴充套件到 CLI 任務，macOS 透過共享使用鎖、提交門和持久狀態保護 CLI；已有任務不被隱式取消。命令列無 GUI 身份查詢不建立 QApplication，也不讀取後清除安裝回執。


關於頁透過應用級 `UpdateController` 檢查公開版本。關閉關於頁不取消檢查或下載，再次開啟仍顯示同一狀態。檢查只由使用者主動觸發，不在啟動時輪詢，不自動安裝。產品視窗繼續複用關於頁和共享操作控制元件。

<a name="xdzip-选择网络与隐私"></a>

## 選擇、網路與隱私

Qt 更新客戶端透過 HTTP/1.1 獲取後設資料、校驗資訊和程式包，規避目前固定 Qt 版本受影響的 HTTP/2 路徑。macOS 的 Sparkle 更新使用獨立傳輸。參閱 [Qt 安全通告](https://www.qt.io/blog/security-advisory-cve-2026-96432)。

客戶端只讀取固定倉庫 `xiaodaozhi/xdzip` 的公開 [Releases API](https://docs.github.com/en/rest/releases/releases)，不使用憑據，不上傳檔名、歸檔內容、密碼、最近記錄或設定。GitHub 與其下載 CDN 會收到網路連線資訊及包含應用版本的 User-Agent。點選發布頁或下載目錄使用系統開啟介面。

每頁最多 100 條，最多 10 頁，每次響應最多 8 MiB，清單最多 256 KiB，簽名最多 4 KiB。原始請求只允許 HTTPS 和明確登記的 GitHub/CDN 主機；使用者配置映象時傳輸地址允許該 HTTPS 映象站點，重定向最多 5 次；後設資料有 15 秒無資料超時和 30 秒總上限，下載有 30 秒無資料超時及一小時總上限。記憶體 ETag 快取最多 24 項，304 只複用先前成功響應。離線、TLS、超時、限流、截斷、缺包和清單錯誤均為失敗，不等同於“已是最新”。重複點選不發起並行更新。

更新使用設定中的系統代理、直連或自定義 HTTP/SOCKS5 代理，地址不含憑據。可選映象必須是 HTTPS，且不含憑據、查詢或片段；構造方式為映象地址後拼接完整原始 GitHub HTTPS 地址。原始 URL 仍需透過固定主機白名單，映象和重定向不會改變已簽名清單的內容、校驗、候選身份或安裝門。配置在目前更新操作結束後用於下一次操作。macOS Sparkle 原生更新支援系統、直連和無憑據的自定義 HTTP CONNECT／SOCKS5 三種模式。每個原生更新例項在啟動前複製已驗證的模式和代理地址，feed 與歸檔使用同一會話策略；自定義代理失敗時禁止回退直連。直連在 URLSession 的代理字典中將 HTTP、HTTPS、SOCKS、FTP、PAC 和自動發現開關顯式設為數值 0；nil 字典或空的現代代理陣列仍代表系統預設，不能用作直連。TLS 信任、釋出簽名及獨立安裝門保持原有約束。

HTTP 429 表示限流。HTTP 403 只有在剩餘額度為零、有效秒數的 Retry-After，或 GitHub JSON 錯誤訊息明確表示限流時才歸為限流；其他 403 保留為網路失敗，不推斷配額耗盡。產品不自動重試，也不讀取 GitHub 憑據。匿名額度按請求源 IP 共享，CI 的倉庫讀取許可權不能改變匿名請求額度。

無 Qt Rust 核心按語義版本、渠道和單調 build 選擇，驗證固定倉庫、完整六類包、架構、包型、最低系統契約和同候選身份。穩定版只接收穩定版；alpha 可接收 alpha、beta、rc、stable；beta 不接收 alpha；rc 只接收 rc、stable；dev 可檢查公開版本。語義版本和 build 都必須遞增，不按釋出時間推斷。客戶端再檢查目前系統支援範圍和 Releases 資產位元組數。

<a name="xdzip-信任与下载"></a>

## 信任與下載

`release.json.sig` 驗證清單原始位元組，信任根編入客戶端和安裝助手，不能從下載內容或請求中增加。JSON 後設資料進入字串 FFI 前先驗證 UTF-8，非法編碼明確失敗，不能透過替換字元改變待驗籤原位元組。簽名格式、獨立 Sparkle 金鑰、金鑰交付順序和不可變資產要求見[釋出協議](release-protocol.md)。缺簽名或未知公鑰只提供官方釋出頁手動下載；錯誤簽名明確失敗。生產公鑰尚未配置時不允許自動覆蓋。

Windows/Linux 將最多 2 GiB 的包流式寫入私有更新快取，同時核對長度和 SHA-256，成功提交後才允許交給助手。取消或校驗失敗不產生可安裝狀態。便攜包、dirty、開發/原始碼或身份不明的構建只提供檢查與下載。自動覆蓋還要求 Release 配置和有效提交身份，不把無 Git 身份的原始碼歸檔構建當作安裝版。安裝身份須同時匹配系統安裝記錄、執行路徑及隨包標記。

macOS 使用固定 Sparkle 2.10.0 和 `xdzip-proxy.2` 受限代理擴充套件，透過薄 Objective-C++ 使用者驅動把狀態送入統一關於頁。框架主庫與 Ed25519 從鎖定原始碼和補丁以 Apple Silicon 原生編譯，資源、安裝助手和簽名工具保留鎖定官方 SDK 來源；派生框架不聲稱與上游 SDK 位元組相同。feed 和歸檔由 Sparkle 原生驗證，feed 只包含已選定的同一個候選；不聲稱 Sparkle 執行了額外 SHA-256。只讀 DMG、App Translocation、未登記的 .app 或缺少更新公鑰均提供手動安裝入口。普通 CI 不因引入 Sparkle 而部署、簽名或上傳 Mac 應用包。

手動回退展示目前首先未滿足的條件：安裝身份、會話、缺少自動更新源或無效的網路配置。安裝身份不合格僅表示整組身份檢查未透過，不推測具體是哪一項；多個條件同時不滿足時仍可能需要依次處理。關於頁提供同版本釋出頁和 DMG 指引，下載 app.zip 後說明解壓、退出舊版及替換應用；下載成功不等於安裝成功。

<a name="xdzip-安装交接与恢复"></a>

## 安裝交接與恢復

下載期間原有任務繼續執行。選擇下載安裝後有活動任務則等待，使用者可取消等待並暫緩更新，不隱式取消任務或密碼請求。助手準備完成後 `prepareForUpdate` 拒絕活動任務、任務啟動與模態互動；進入交接後禁止新會話和新任務，所有 Rust 連線完成清理及 join 才傳送安裝提交。交接不使用“立即重啟舊程式”路徑。

Windows 僅從登記的目前使用者安裝根複製獨立無 Qt 助手到私有快取，助手獨立複驗簽名、大小和雜湊，等待已捕獲主程序退出後交給現有 Inno 安裝器，保留互動許可確認。安裝門阻止替換期間再次啟動。

安裝根未透過安全檢查時，關於頁明確提示檢查安裝目錄許可權或從釋出頁手動安裝，不將該拒絕歸為網路故障；原有目錄和身份檢查不因此放寬。

Ubuntu 安裝版使用固定 `/usr/libexec/xdzip-update-helper`，普通使用者協調器僅透過固定引數呼叫 polkit。root 助手將包複製到 root 私有暫存後重新驗籤及核對 xdzip 包名、架構、版本，只允許固定 APT 操作，不接受命令、任意包名或目標目錄，不使用 sudo shell。授權取消與缺少認證代理返回獨立狀態。dpkg 未配置不報告成功，不自動回滾或啟動舊程式。新版以原使用者重啟時保留有界白名單中的 XDG 設定、資料、快取與狀態目錄及桌面語言，不繼承動態載入器、Qt SDK 或測試環境覆蓋；這些變數不傳入 root 的安裝命令。

macOS 在全部 join 完成後才釋放 Sparkle 安裝回撥；主程式僅在 provider 已標記實際 committed 後、呼叫 SDK 安裝回復前同步釋放退出攔截，不能在 join 屏障上提前允許末窗自動退出。提交失敗或取消後，普通退出繼續等待原生 helper 觀察門；Sparkle 負責實際歸檔替換和重啟。取消不會留下下次退出時安裝的計劃。Framework、XPC 與 helper 單獨保留所需簽名引數和 entitlements，不能套用通用重籤規則。

Sparkle 的取消回覆在非同步更新週期中處理，週期結束不等同於獨立安裝程序已經退出。未提交安裝時，普通退出路徑先請求取消，等待週期結束，再透過系統 `/bin/ps` 只讀觀察與本應用框架路徑精確匹配的 Autoupdate 程序，確認其結束後才釋放退出攔截。準備完成時先記錄匹配的安裝程序，觀察失敗不當作退出許可，不終止安裝助手，也不記錄無關程序資訊。準備失敗後的重試同樣等待舊安裝助手結束，不能替換尚未完成退出觀察的更新驅動。已經提交的安裝由 Sparkle 按原生流程退出和重啟。

Windows/Linux 的事務使用隨機 ID 和固定名稱的 ready/proceed/cancel/result 檔案。客戶端在退出前把事務、目標身份和快取目錄儲存到設定旁獨立 `update-state.ini`，不混入設定配置。助手先原子寫成功結果，再釋放門和重啟。下次啟動限制回執路徑與大小，核對事務及目前版本/build/安裝身份；失敗、缺回執或身份不符顯示恢復入口，不自動重試安裝。恢復記錄缺少有效候選地址時仍可開啟固定的官方釋出列表。快取材料保留供使用者修復，公開證據不得含私人完整路徑。

macOS 在釋放 Sparkle 安裝前儲存目標版本/build 的本地嘗試記錄。重開時以實際執行身份和可靠安裝標記判斷完成或需要恢復；此記錄不賦予安裝許可權，也不代替 Sparkle 驗籤。

<a name="xdzip-验证边界"></a>

## 驗證邊界

Mac 單平臺診斷可只執行完整產品鏈；全平臺模式始終執行 Sparkle 六場景與完整產品鏈，不採納跳過六場景的診斷選項。

原生下載器的系統衝突檢查只在帶隔離標記的一次性 hosted Apple Silicon runner 暫時啟用自有靜態代理和 PAC。先要求系統模式的 feed／歸檔實際命中代理，再要求直連零命中；HTTPS 對照核對連線去向並保留不可信證書拒絕。受限助手儲存和核驗恢復該服務完整代理設定及固定測試域名的 hosts 內容，EOF 與超時也恢復。本機不修改代理、DNS 或證書信任。完整產品鏈另外執行受控 PAC 下直連安裝、普通重啟和活動更新配置快照；下載器檢查不能代替安裝證據。


Mac 無 SDK HTTPS 驗收使用同一個已部署探針及匿名真實更新請求。記錄只儲存狀態碼、Qt 錯誤和白名單限流響應頭，不儲存原始錯誤正文、源 IP 或憑據。確認限流後，驗收驅動最多啟動三次探針，按 Retry-After 與配額重置時間中較晚者等待；缺少可用主配額重置時間時拒絕提前重試，已確認的其他限流使用至少 60 秒的遞增退避。累計等待最多 3700 秒，超預算明確失敗，保留每輪結果和實際等待記錄。每次請求原有超時、TLS、響應大小、成功狀態和 SDK 隔離要求保持；失敗重試不合併成一次透過。此退避只用於專用驗收驅動，不能作為產品背景重試或最終專項跳過條件。

核心夾具覆蓋渠道、dev、亂序分頁、缺包、錯誤簽名、最低系統和身份衝突；網路夾具覆蓋取消、重複點選、限流、TLS、響應上限、ETag 與損壞下載；會話迴歸核對任務保留和所有 join 後交接。真實三平臺舊版到新版、授權取消、再次啟動、安裝失敗/恢復、設定/關聯保留以及無 SDK HTTPS 需要隔離平臺實證，不能由單元測試或 CI 編譯替代。Mac 完整更新必須在 Apple Silicon 原生環境執行。具體完成狀態及證據由 issue 跟蹤。

[專用原生更新迴歸](../../../.github/workflows/update-regression.yml)僅手動排程，不攜帶生產秘密，不上傳應用包。預設驗證全部平臺，也可選擇單個平臺定位故障，各選擇使用獨立佇列；最終驗收仍要求同提交的全平臺結果。Windows 在一次性 GitHub runner、Linux 在專用容器先使用擁有的 C 協議產品和真實 Inno/APT 驗證助手取消、失敗及恢復。另一條私有 Qt 升級鏈路編譯兩個真實 `browser_main`/QML 版本，透過實際關於頁滑鼠輸入，執行清單與包驗證、退出 join、Inno/APT、普通使用者單例項重啟和回執恢復，並核對設定、未知設定鍵、現有預設關聯及安裝目錄的無關檔案保留。Linux 將構建 SDK 和執行容器分開，執行容器沒有編譯器或 Qt SDK，並使用自定義 XDG 目錄；Windows Server CI 僅在私有宏下替換最低系統判斷，不替代 Windows 11 原生驗收。該鏈路替換公開 GitHub URL 的網路 transport，生產 HTTPS/TLS 則單獨透過無 SDK 執行驗證。

[生產簽名專項](../../../.github/workflows/production-update-acceptance.yml)在所有者授權後使用受保護環境的已有金鑰，沿用真實 Qt 產品升級與異常恢復鏈，保留已提交的生產公鑰。準備階段不簽名，獨立簽名步驟先嚴格匹配公開信任根，再核驗本次固定候選；執行階段拒絕秘密環境。它不提供任意資產簽名或釋出介面，簽名候選只存於一次性 runner，公開工件僅含有界的診斷與摘要。此專項和原測試金鑰迴歸分別記錄，實際執行才算透過，金鑰匹配也不等於安裝成功。具體約束見[釋出協議](release-protocol.md)。

增強場景延遲包下載完成事件，啟動真實 AES Check 直到等待密碼，再驗證更新進入等待任務。密碼窗保持原生應用模態，此時夾具透過 controller 呼叫取消更新等待，並在證據中明確標記該步驟未使用關於頁滑鼠；取消後同任務及密碼令牌保持，再透過輸入法提交事件及密碼確認按鈕完成 Check，最後從關於頁再次安裝。另一輪在更新與密碼等待並存時向真實主程式投遞系統 Quit，點選實際退出視窗的返回、取消並退出，核對同任務／令牌、所有 join、零安裝交接以及同舊安裝正常重開後再升級。透過輸入法提交事件輸入密碼不等同於真人輸入法驗收；實體桌面和真人輸入按需檢查並單獨記錄，許可複核和發行授權仍分別處理。

另有雙會話元件迴歸，經 AppQuitGuard、DesktopIntegration 和全會話路由進入同一退出視窗，核對 AES 等待任務的返回／取消及所有連線完成 join 後就緒訊號只發出一次。只允許受管理會話自己的密碼／衝突模態被退出確認覆蓋，原生 QWidget 模態仍阻擋退出。該元件檢查與完整主程式在更新等待期間的系統 Quit、原生安裝回歸分別記錄。

Mac 完整產品夾具在首次投遞系統 Quit 前，須實際觀察同一工作會話的密碼窗已可見、已 exposed、屬於該主視窗且正是應用模態窗，任務與密碼令牌仍一致；不能把 Rust 已產生密碼請求等同於延遲呈現的視窗已經就緒。達到前提後僅投遞一次 Quit，繼續驗證真實返回、模態恢復、取消和全部 join。超時時先凍結目前進度，再執行清理；清理期間後來生成的退出結果不能覆蓋失敗結論。

Windows 私有安裝回歸在新 `xdzip.exe` 複製完成、其餘檔案尚未開始複製時暫停真實 Inno，核對新程式身份並再次啟動真實 Qt 程式，要求啟動門返回 11、沒有可見視窗及新會話，再放行復制並完成原有升級驗收。測試觀察門時立即關閉自己的控制代碼，不能替安裝器維持門的生命週期。新舊均為 Qt 6.8.2，此迴歸不建立原子應用包或跨 Qt 版本遷移保證，生產安裝模板不新增暫停邏輯。
