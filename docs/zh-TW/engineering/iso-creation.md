# ISO9660 與 Joliet 建立

[English](../../engineering/iso-creation.md) | [简体中文](../../zh-CN/engineering/iso-creation.md) | 繁體中文（台灣）

首版寫入器建立單卷、不可啟動的資料映象，使用 2048 位元組扇區，同時寫入 ISO9660 主名稱空間和 Joliet 補充名稱空間。依據為 [ECMA-119 第五版](https://ecma-international.org/wp-content/uploads/ECMA-119_5th_edition_december_2024.pdf)，包括附錄 C 收錄的 Joliet 規範。不連結或啟動外部映象製作引擎。

僅准入普通檔案和顯式目錄。Joliet 使用大端 UCS-2，原樣保留名稱，每個元件最多 64 個字元。完整 Joliet 路徑按識別符號位元組、檔案版本和父目錄計數合計，最多 240 位元組。補充平面字元、分號、不安全的可移植路徑、重複路徑、缺少父目錄和檔案/目錄衝突在寫入前拒絕。主名稱空間使用確定且唯一的 ASCII 別名，不替換 Joliet 檢視中的原名。首版目錄層級限制為包含根目錄的八級，目錄數量最多 65535 個且包含根目錄，單檔案小於 4 GiB，映象總大小最多 20 GiB，規劃的後設資料最多 64 MiB。時間使用 UTC，限制在盤上可表示的範圍內。

寫入器先規劃兩套目錄樹和大小端路徑表，再流式寫入檔案內容。目錄記錄不能跨扇區，扇區用零填充，數值的大小端表示必須一致。凍結的輸入索引僅授予流訪問，不授予檔案系統路徑。取消、輸入縮短或增長、輸出錯誤和預算耗盡均終止編碼，只有宿主能夠釋出暫存檔案。

建立後重新開啟完整映象，按解碼後的 Joliet 名稱匹配記錄，不依賴列舉順序，並在最終提交前把解碼檔案位元組與凍結源逐位元組比較。這不同於任意 ISO 的結構檢查，ISO 不提供普通檔案校驗和。獨立讀取器必須驗證主名稱空間別名、準確的 Joliet 名稱和檔案位元組。

不提供 UDF、Rock Ridge 寫入、El Torito/啟動盤、壓縮、密碼、多卷或現有映象修改。CLI 與桌面複用相同的建立登記和任務流程。
