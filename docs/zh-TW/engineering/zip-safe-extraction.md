# 安全 ZIP 解壓實現

[English](../../engineering/zip-safe-extraction.md) | [简体中文](../../zh-CN/engineering/zip-safe-extraction.md) | 繁體中文 | [日本語](../../ja-JP/engineering/zip-safe-extraction.md) | [한국어](../../ko-KR/engineering/zip-safe-extraction.md) | [Français](../../fr-FR/engineering/zip-safe-extraction.md) | [Deutsch](../../de-DE/engineering/zip-safe-extraction.md) | [Español](../../es-ES/engineering/zip-safe-extraction.md) | [Português (Brasil)](../../pt-BR/engineering/zip-safe-extraction.md) | [Русский](../../ru-RU/engineering/zip-safe-extraction.md)

本契約定義宿主安全輸出、真實解壓、衝突、取消與提交行為；具體執行結果和目前缺陷記錄於對應 issue 及 Actions 工件，不在本頁累積驗收報告。

格式外掛只獲得借用輸入、不可變條目快照和宿主 `DecodedSink`。ZIP 後設資料掃描與負載解碼分離。Store、Deflate、ZIP64 的本地頭、中央目錄、資料描述符、宣告大小、實際大小、CRC 和 Deflate StreamEnd 必須一致；AES-256 的認證與 CRC 差異按[密碼解壓契約](password-extraction.md)處理，其他加密、其他壓縮方法、未按[編碼契約](filename-encoding.md)解析的名稱和未透過下文專門策略的連結／特殊物件仍不支援。分卷源由[分卷讀取層](archive-opening.md)提供統一邏輯輸入。原始 ZIP64 本地資料描述符可與普通中央目錄組合，按本地與中央目錄的大小哨兵驗證寬度。流結束後剩餘的壓縮位元組及輸出正確但缺少終止塊的流都失敗。

所有輸出先透過共享 portable 名稱解析器，拒絕路徑穿越、絕對路徑、保留裝置名、非法字元和歧義元件。任務準備階段凍結選擇：根目錄全量解壓包括全部物理記錄；所選目錄展開全部後代；所選檔案去除目前目錄字首。瀏覽器根目錄列表仍僅顯示直屬檔案和資料夾。一般解壓縮依各個目標父目錄的規則判斷大小寫或 Unicode 等價名稱能否共存。能使用原名時保留原名，衝突時預設加上編號，保留兩份檔案及各自的目錄樹。任務明細列出改名項目的原始與實際路徑。封存中完全相同的路徑同時宣告為檔案和目錄時，會在寫入前拒絕。

一般解壓縮會盡量保留檔名中的普通標點 `? * < > " |`。目標檔案介面拒絕時，以底線替換，必要時加上編號，避開現有項目和封存內的原名。替換名稱不會覆蓋現有項目，改名後的目錄保留自己的子項。任務明細列出原始與實際路徑。原有路徑安全限制仍然適用。

預設的同名資料夾由宿主從歸檔名稱派生，介面預覽和實際輸出使用同一名稱。去除歸檔副檔名後若以 `.app` 結尾，還要去除此字尾，大小寫不敏感，避免 macOS Finder 將普通外層資料夾誤認成應用包；例如 `demo.app.zip` 解壓到 `demo/`，其內部原有的 `demo.app` 名稱和內容不變。去除後為空時使用 `archive`，派生目錄仍經過 portable 名稱檢查和目標授權。該規則同樣適用於已支援的複合副檔名及分卷歸檔，不改變未勾選同名資料夾時的輸出路徑。

使用者選擇的目標目錄透過 `xdzip-io::Grant` 轉為持有目錄控制代碼的能力。子目錄逐元件 no-follow 開啟，保留並複核父鏈身份。POSIX 目標須屬於目前有效使用者且不能向組或其他使用者開放寫許可權；Windows 檢查重解析點、所有者和 DACL，修改許可權只允許目前使用者、SYSTEM、Administrators 和繼承用途的 Creator Owner。其他 SID 可以具有 FILE_GENERIC_READ／FILE_GENERIC_EXECUTE 的只讀、列舉及執行許可權，GENERIC_READ／GENERIC_EXECUTE 使用相同的檔案許可權邊界；寫入、建立、追加、刪除、刪除子項、改所有者、改 ACL、GENERIC_WRITE／GENERIC_ALL 及未知位仍拒絕，有效與僅繼承 ACE 同樣檢查。這樣可接受個人目錄已有的只讀觀察賬戶，而不會將外部可寫目錄判為安全。Windows 輸出沿用目標的只讀共享許可權，不承諾對已有隻讀賬戶隱藏檔案內容，也不修改使用者目錄 ACL。連結、特殊物件、外部所有者和外部可寫目標繼續拒絕。

私有工作目錄以系統隨機 128-bit 名字排他建立，POSIX 目錄 0700、檔案 0600。階段檔案使用宿主生成的順序號，不使用歸檔提供的臨時路徑。真實解碼位元組逐塊計量：單檔案 8 GiB、單任務 20 GiB；宣告壓縮比高於 1000:1 且輸出大於 1 MiB 時須顯式允許，硬位元組限額保持不變。每個解碼器使用固定緩衝區，解壓資料不整體積累到記憶體。

Snap 在使用者實際家目錄內建立工作目錄時，使用可見前綴 `xdzip-work-`。該前綴和 `.xdzip-work-` 都計入可能的殘留，並沿用相同的隨機命名、私有權限、身分檢查與清理規則。

完整校驗與資料同步後才提交。預設不覆蓋：同卷硬連結的排他建立成功後移除私有連結；允許覆蓋：複核已有普通檔案的身份、大小和修改時間，使用同卷重新命名替換，絕不先刪除或截斷舊檔案。拒絕硬連結葉子和源歸檔本身。檔案系統不支援提交原語時失敗，沒有複製／刪除退路。身份校驗是 best effort，不是同賬戶併發編輯的內容 CAS，也不承諾斷電後的目錄後設資料持久化。目錄已建立、檔案已提交的效果分別計數，不虛構任務整體回滾。

私有 journal 記錄準備與提交的相對路徑和任務身份。清理只刪除身份匹配的已知物件；發現未知檔案、目標被替換或刪除失敗時保留恢復材料並報告清理警告。崩潰後的隨機工作目錄只統計提示，不自動解析、執行或遞迴刪除。恢復策略的驗收須覆蓋上述崩潰、身份變化和清理失敗路徑。

任務和後設資料各用一個工作執行緒。最多 32 個任務，等待終態消費的任務也佔槽；佇列保守計入不可變快照和計劃，累計不超過 64 MiB。普通命令累計擁有資料不超過 8 MiB。每個任務只保留最新顯示快照，輸出進度最多 10 Hz，終態在清理後釋出；GUI 接收執行緒和其郵箱繼續有界，不能因 GUI 暫停無限增長。衝突提示具有任務內單次使用的 prompt ID，取消和退出會喚醒等待，不依賴資料佇列有空間。

關閉准入以同一狀態鎖下發布的單調原子標記供非阻塞 submit 查詢；shutdown 返回後，即使退出工作執行緒正持有鎖，合法命令仍穩定返回 Closed，不會誤報可重試的 Busy。該標記只決定拒絕，不繞過鎖下的任務與請求狀態檢查。

取消透過原子提交許可線性化：開始提交前取消不寫目標；提交已經開始時允許完成整檔案原子釋出，並在最終結果中計入已提交檔案；最後任務完成後取消不能改變成功結果。關閉進度視窗只隱藏視窗，任務繼續；退出程式須取消並等待工作執行緒與源控制代碼退出，不在 GUI 執行緒 join。

Windows 與 macOS ACL 查詢屬於隔離的 unsafe 邊界，每個呼叫解釋控制代碼、指標、緩衝區和釋放前提。驗證結果須記錄實際覆蓋的平臺和異常路徑。依賴准入與公告查詢見 [ZIP 解壓依賴](zip-extraction-admission.md)，實際驗收按[驗證方法](../../../developers/qa/README.md)在對應 issue 與工件登記。

OWNER RIGHTS（S-1-3-4）表示物件所有者的動態許可權，只在所有者已透過目前使用者／SYSTEM／Administrators 檢查後接受；不能使外部所有者或其他 SID 變為受信賬戶。原生迴歸同時驗證繼承到階段檔案與新建輸出父目錄，以及存在 OWNER RIGHTS 時接受 Everyone 的只讀訪問、仍拒絕其修改許可權。

Windows cap 目錄控制代碼不允許 FILE_SHARE_DELETE，父目錄改名攻擊會在系統層被拒絕；驗收同時證明外部目錄未改變及安全目標釋出仍在授權目錄內。空私有工作目錄清理在身份複核後使用 cap 的 consuming remove_open_dir，先關閉控制代碼再刪除；只刪除已驗證的空目錄，不放寬 nofollow、ACL 或連結拒絕規則。

Qt 橋接只傳不含輸出能力的目標／任務 DTO，ID 以不透明字串進入 QML。選單、解壓選項、衝突、進度／結果和退出均接入真實任務；系統 Quit 同視窗關閉先經過任務決策，再進入非同步關閉屏障。持續進度最多 10 Hz；提示、取消、清理及終態立即釋出。執行時異常不猜測已提交總量，保留最近狀態並明確標記計數不完整。

介面以[邏輯尺寸](../../../specs/visual/layout-scale.json)、[視窗登記](../../../specs/visual/window-registry.json)及[設計規範](../visual/design-standard.md)為準，解壓、任務與衝突統一寬 491；footer 操作字 13、提示 12。固定底部操作區與可滾動正文保證小屏和大字號可操作。大圖使用同一 SVG 的 216 畫素透明匯出，不放大 72 畫素小圖；[素材規範](../../../specs/visual/operation-assets.json)保留同源關係。原生系統標題欄與稿中的系統外觀示意分開驗收。

目前輸出歸屬目前賬戶，POSIX 目錄使用 0700、普通檔案預設 0600。ZIP Unix 建立者的普通檔案在持有暫存檔案控制代碼上、釋出前恢復 `0600 | (mode & 0155)`：保留讀／執行位，剝離組和其他使用者寫位及 setuid／setgid／sticky。不改變所有者，不恢復擴充套件屬性或原始修改時間，不自動執行應用。可執行位和相對符號連結屬於應用包佈局還原，不代表安裝、簽名驗證或系統安全審查。損壞、特殊項和源／目標變化預設停止目前任務；保留早前已提交檔案，沒有靜默繼續、整任務回滾或自動重試。

提交任務時，Qt 控制器繼續使用 busy 序列准入並拒絕重複請求；taskStarting 區分解壓／建立任務提交與目錄讀取。普通控制元件外觀使用 browsingBusy，瀏覽工作區按最近一次已提交快照顯示，不能把任務提交誤畫為目錄重新讀取。browserQueryAvailable 保持提交期間的查詢入口外觀，實際命令仍經過原有序列請求防護。解壓確認的“開始解壓”及其他控制元件在 taskStarting 期間保持正常外觀；點選處理和控制器繼續用 busy 攔截重複請求，拒絕准入時不閃現禁用色。任務受理後才切換到真實任務視窗，拒絕或失敗保留確認視窗和錯誤說明；不樂觀清空目錄或提前偽造任務成功。

開啟解壓確認視窗後的自動目標檢查、編輯後的重檢，以及建立視窗的目標檢查和輸入後設資料預覽也屬於操作準備。它們保持已提交的瀏覽快照，不能觸發 browsingBusy 或關閉 browserQueryAvailable，避免主列表遮罩、工具欄禁用色和選單關閉造成閃爍。busy 仍覆蓋完整請求週期，繼續保護序列准入；目標檢查中的意見回饋只在操作視窗顯示。初次開啟未就緒的歸檔仍顯示載入狀態；切換目錄或查詢時保留已提交的非空列表或空狀態，直到新快照提交。失敗導致源快照失效時仍清除失效資料。

解壓目標在開啟視窗、選擇目錄及結束編輯時自動檢查；建立與解壓分別儲存檢查結果，並以視窗代次、請求、路徑和解壓會話關聯。路徑改變立即使舊結果失效，排隊或檢查期間不能提交；過期回執不能授權新路徑或另一視窗。兩窗使用相同狀態圖示和提示，解壓保留原有路徑佈局、同名資料夾與暫存提示。該檢查僅供操作準備，真實寫入仍按源與目標能力重新驗證。

<a name="xdzip-zip-符号链接安全恢复"></a>

## ZIP 符號連結安全恢復

僅 POSIX ZIP Unix 建立者的符號連結可恢復，TAR 符號／硬連結、Windows 符號連結及其他特殊物件仍返回 unsupported_link。連結內容在取得輸出授權前以受限 sink 完整解碼，驗證本地頭、長度與相應格式的 CRC／認證；加密連結按[密碼解壓契約](password-extraction.md)延遲到任務準備階段。單項最多 4096 位元組，合計最多 4 MiB，名稱沿用 PortablePath 規則；允許相對目標中的 `.`／`..` 元件，但必須按檔案系統順序先展開遇到的連結，再處理後續父級元件。越過輸出根、絕對路徑、反斜槓、控制字元或保留裝置路徑仍拒絕；不存在的字首和把檔案作為目錄同樣拒絕。

所有目標必須按原始拼寫在本次選中輸出圖內閉合，支援 Framework 的 Versions/Current、目標路徑字首中的連結展開，以及 macOS 應用包常用的相對 `.`／`..` 元件。每次展開都相對連結父目錄歸一化，並拒絕越過輸出根；最多跟隨 64 次，拒絕迴圈、懸空、越界、大小寫／Unicode 歧義、重複名稱及連結作為寫入父目錄。僅選擇一個連結而未選擇其依賴時拒絕，不借用目標樹中的外部既有連結。先發布全部普通檔案和目錄，最後透過持有的 no-follow 父目錄控制代碼排他建立連結，已有連結不會被覆蓋或跟隨。每次釋出仍復核源和父鏈身份、取消許可並記事務日誌。連結建立不支援的檔案系統明確失敗，不降級為普通文字檔案。

帶連結的任務要求所有檔案／連結葉子為空：啟動時統一檢查，提交普通檔案時再次檢查；遇到衝突即失敗，不能用跳過／改名／覆蓋破壞凍結的依賴圖。已有安全普通目錄可複用。與普通解壓一致，後續失敗或取消保留此前已提交項，不承諾整包事務或自動回滾；完成統計包含連結內容位元組及連結數量。只讀後設資料預檢不讀取連結內容，其無警告不代表透過連結輸出准入。

<a name="xdzip-macos-扩展-acl-控制"></a>

## macOS 擴充套件 ACL 控制

目錄和普通檔案授權透過持有的控制代碼查詢擴充套件 ACL，保留目前有效使用者所有權、組和其他使用者無 mode 寫許可權以及普通檔案單硬連結檢查。已知的 deny 規則不授予修改能力，可以接受；其他主體的 allow 規則僅可授予讀取、列舉、執行、讀取屬性和安全資訊等只讀能力。常見使用者目錄的 `everyone deny delete` 不因存在擴充套件 ACL 而被拒絕。

寫入、建立、追加、刪除、刪除子項、寫屬性、寫擴充套件屬性、改 ACL 和改所有者等修改許可權，只允許明確匹配目前有效使用者 UID 的主體。目前使用者身份匹配覆蓋系統解析及系統使用的合成使用者 UUID，不接受組主體作為目前使用者的替代。外部主體的有效與僅繼承修改許可權同樣拒絕，前置 deny 不使危險 allow 規則獲得豁免。未知許可權位、未知規則型別、身份無法核實、ACL 查詢或釋放失敗均拒絕，無 ACL 的缺失結果與其他查詢錯誤分開處理。

此檢查用於目標根、逐級父目錄、暫存目錄和待替換普通檔案，並在已有身份複核邊界重新執行。暫存檔案在已核實的私有目錄內排他建立，目錄 ACL 檢查同時約束其繼承許可權。它不自動清除或改寫使用者 ACL，原有隻讀共享許可權可能繼承到輸出，不承諾對只讀共享賬戶隱藏內容。驗收必須在自有臨時物件上同時驗證安全 ACL 的實際釋出與危險 ACL 的拒絕，具體結果記錄於[安全修復 issue](https://github.com/xiaodaozhi/xdzip/issues/6)及本地／CI 工件。

系統右鍵的智慧與逐包目錄是顯式任務佈局，規則見[檔案管理器操作](shell-actions.md)。智慧判斷使用完整已驗證輸出圖；需要外層目錄時經共享目標能力排他建立並使用編號避讓，不復用已有目錄。普通瀏覽解壓的同名目錄選項繼續透過原有目標能力處理。
