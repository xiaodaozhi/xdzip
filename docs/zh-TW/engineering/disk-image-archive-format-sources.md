# 磁碟映像與其他歸檔格式的資料和許可

[English](../../engineering/disk-image-archive-format-sources.md) | [简体中文](../../zh-CN/engineering/disk-image-archive-format-sources.md) | 繁體中文 | [日本語](../../ja-JP/engineering/disk-image-archive-format-sources.md) | [한국어](../../ko-KR/engineering/disk-image-archive-format-sources.md) | [Français](../../fr-FR/engineering/disk-image-archive-format-sources.md) | [Deutsch](../../de-DE/engineering/disk-image-archive-format-sources.md) | [Español](../../es-ES/engineering/disk-image-archive-format-sources.md) | [Português (Brasil)](../../pt-BR/engineering/disk-image-archive-format-sources.md) | [Русский](../../ru-RU/engineering/disk-image-archive-format-sources.md)

本文介紹 DAA、ISZ、ZPAQ、PEA、BOND 和 J2J 等格式的公開技術資料、許可限制與支援條件。公開描述資料格式不等於允許釋出解碼器，參考實現也不一定可以作為產品依賴再分發；下列參考實現均不連結進 xdzip。格式進入產品登記前，須確認原始碼版本、許可文字、完整樣本、資源限制和失敗行為。

<a name="xdzip-daa-10"></a>

## DAA 1.0

- **公開規範**：沒有找到廠商釋出的 DAA 1.0 規範。公開資料把 DAA 描述為 PowerISO 的專有磁碟或歸檔映象，通常包含頭部、分塊長度表和逐塊壓縮的 ISO 資料。公開記錄涉及 zlib、LZMA 和後來的內部版本 110，但沒有穩定的 1.0 契約。
- **參考實現**：`daa2iso` 0.1.7e，Debian 和 Fedora 的 GPL-2.0-or-later 軟體包。它只能用於歷史研究。目前無法從權威公開倉庫固定上游 Git 提交，也沒有廠商規範可固定。
- **許可和再分發**：實現使用 GPL-2.0-or-later。該許可沒有授予 DAA 專有技術的產品權利，專案也沒有可把解碼器釋出到 xdzip 的獨立許可記錄。
- **完整樣本**：公開樣本通常是來源和版本未固定的磁碟映像或多卷歸檔。目前沒有登記覆蓋舊頭部、版本 110、多卷順序、zlib、LZMA、混淆、校驗和畸形分塊的可再分發語料庫。
- **淨室可行性**：在獲得穩定線格式記錄和法律結論後，有界 ISO 重建在技術上可能可行。僅依賴 GPL 解碼器做逆向，不能作為產品實現依據。
- **能力邊界**：按產品決定永久不支援。不得增加 DAA 探測器、codec、登記、MIME、關聯、讀取器或寫入器。歷史資料研究不授予後續准入許可權。
- **結論**：**按產品決定明確不支援，永久放棄。** xdzip 不再推進 DAA。上述來源、許可和樣本結論僅保留為歷史研究，不再作為等待解決的交付門檻。

<a name="xdzip-isz"></a>

## ISZ

- **公開規範**：EZB Systems，《ISZ File Format Specification》1.00 版，修訂日期為 2006 年 7 月 3 日，定義 `IsZ!` 簽名、固定頭部、可選分段定義表、塊定義表和資料塊。頭部包含扇區尺寸、總扇區數、密碼模式、分段尺寸、塊數、塊尺寸、指標長度、分段號、表偏移和資料偏移。塊標誌區分零塊、儲存塊、zlib 塊和 BZip2 塊。可見 [ImgBurn 規範副本](https://forum.imgburn.com/topic/14260-isz-images-supporting/#comment-115553)。
- **參考實現**：CDEmu `libmirage` 的 ISZ 過濾器，提交 `39fcffe09739e1dc40bef4781646f9ffb8b7dc4e`，以及 Play- 的 `IszImageStream`，提交 `5bb010f27d8e2309f37b1f8eba0f74ecd546b29b`。二者只用於參考分析。`Helias/isz-tool` 是 Python 讀取器，但本環境未能取得權威不可變提交和許可記錄。
- **許可和再分發**：EZB 規範第 8 節寫明，把 ISZ 技術併入產品需要聯絡 EZB，取得帶條件的免費許可。公開文字或寬鬆許可的獨立讀取器，都不能自動取消產品許可門檻。CDEmu 和 Play- 不作為 xdzip 依賴。
- **完整樣本**：可以用公開工具生成有效的 Store、zlib 和 BZip2 塊，但完整可再分發矩陣還需要單卷和分段映像、零塊、不同指標長度、精確尾塊、密碼模式、表混淆、截斷、偏移越界和來源變化樣本。倉庫尚未登記這樣的自有語料庫。
- **淨室可行性**：無加密、單卷、只讀子集在技術上可以與 ISO 瀏覽分開。首個實現可以把四種有文件的塊解碼成一個虛擬 `image.iso` 檔案，不掛載，也不執行啟動映像。但在編碼前必須取得法律許可、固定不可變參考和完整夾具集。
- **能力邊界**：門檻透過前，不登記 `.isz`，不因 `IsZ!` 自動宣稱支援，也不開放密碼、AES、分段、寫入或直接光碟瀏覽。未來准入時必須驗證頭部和版本、指標表與分段表、XOR 或反混淆規則、塊和資料範圍、邏輯尺寸運算、完整塊結束、取消以及輸入、工作和輸出額度。
- **結論**：**按產品決定明確不支援**。本工作包不推進 ISZ，也不聯絡 EZB 取得產品許可。除非重新作出決定，不得增加 `.isz` 探測器或登記項。

<a name="xdzip-zpaq"></a>

## ZPAQ

- **公開規範**：Matt Mahoney，《The ZPAQ Open Standard Format for Highly Compressed Data》2.03 和 2.06 版。格式在塊頭中儲存 ZPAQL 解壓程式，支援固實塊、日誌更新、去重、SHA-1 記錄，較新級別還涉及加密和分卷。
- **參考實現**：`zpaq/zpaq` 的 `6.22` 標籤及對應 `libzpaq` 原始碼。本評估把該標籤作為固定研究參考，但真正開始實現前仍需記錄提交雜湊和許可文字雜湊。
- **許可和再分發**：參考實現和配置檔案使用 GPLv3。按目前不引入第三方歸檔執行時的政策，不能連結進產品。公開標準支援淨室分析，但解碼虛擬機和配置語料仍需獨立實現與複核。
- **完整樣本**：有效語料庫需要覆蓋 1、2 級塊、任意 ZPAQL 程式、日誌更新、去重、加密和分卷記錄、SHA-1 校驗，以及畸形虛擬機和塊邊界。倉庫沒有這套自有語料庫。
- **淨室可行性**：理論上可行，但這是虛擬機和資源計量專案，不是小型容器解析器。必須分別計量位元組碼執行、模型記憶體、解壓輸出、歷史視窗和去重狀態。
- **能力邊界**：未來第一切片只能是隻讀、無加密、非分卷、非日誌更新，並宣告支援的虛擬機子集。不自動獲得建立、更新、密碼或無界固實解壓能力。
- **結論**：**按產品決定明確不支援**。xdzip 不實現 ZPAQL 虛擬機，也不接受依賴虛擬機的 ZPAQ 配置。除非重新作出決定，不得增加 `.zpaq` 探測器或登記項。

<a name="xdzip-pea"></a>

## PEA

- **公開規範**：PeaZip，《Pack, Encrypt, Authenticate》規範，覆蓋 PEA 1.x、仍處於提案狀態的 PEA 2.0 流、多流和分卷控制、物件控制、結束標記以及 PCOMPRESS 級別。規範見 [`pea_help.pdf`](https://peazip.github.io/pea_help.pdf)，摘要見 [pea-file-format.html](https://peazip.github.io/pea-file-format.html)。目前官方頁面明確說明 PEA 和 PCOMPRESS 規範屬於公有領域。
- **參考實現**：`peazip/PeaZip`，提交 `81b31f7e487b462980a52ac0f2e0b3cf700fe799`，包含 `peazip-sources/dev/pea_utils.pas` 和 `unit_pea.pas`。實現使用 LGPLv3，隨附的 Wolfgang Ehrhardt 密碼單元使用 zlib/libpng 許可。原始碼釋出地址為 [peazip-11.4.0.src.zip](https://github.com/peazip/PeaZip/releases/download/11.4.0/peazip-11.4.0.src.zip)。固定原始碼只作參考分析材料。
- **許可和再分發**：格式規範本身沒有產品許可阻塞，但 LGPLv3 引擎和密碼依賴不能預設複製或連結進目前產品。淨室 Rust 實現應依據公有領域格式記錄並獨立選擇演算法，參考程式只用於測試，不能成為執行時依賴。
- **完整樣本**：已准入配置使用自有完整 Store 夾具，覆蓋檔案、目錄、UTF-8 有效名稱、空與非空資料、截斷、尾隨位元組、來源變化和限額。更廣的語料庫仍需包含 PEA 1.x 和 2.0、多流、分卷邊界、PCOMP 級別、認證失敗、加密頭部、畸形結束標記和大尺寸宣告，這些配置仍在產品邊界外。
- **淨室可行性**：無加密、單流、Store 或 Deflate 讀取器在技術上可行，但認證和加密必須作為獨立安全工作。由於該格式有完整性設計，僅做結構解析不能宣稱內容驗證完成。
- **能力邊界**：未來應先只讀，不開放密碼、加密、多卷、建立或修改。每個流都要在釋出前透過宣告的摘要和終止認證。
- **結論**：**已准入保守只讀配置**。xdzip 目前准入 PEA 1.x、單一物理卷、UTF-8 名稱、PCOMPRESS0 儲存檔案與目錄，不含物件、流或卷校驗。密碼、認證/加密流、校驗演算法、PCOMPRESS1–3、分卷、PEA 2.0、建立和修改仍不支援。LGPL 參考實現只作測試材料，不連結進產品。

<a name="xdzip-bond"></a>

## BOND

- **公開規範**：沒有找到 Bandizip BOND 歸檔的規範、簽名、版本或壓縮契約。Bandizip 近期更新說明提到“某些 BOND 檔案”漏洞，但這不是線格式定義。公開 `.bond` 副檔名資料庫主要描述 Microsoft Bond 模式資料，與歸檔格式不同。
- **參考實現**：沒有找到能夠證明其為歸檔格式、擁有固定版本和可再分發許可的參考實現。
- **許可和再分發**：未知。在格式所有者、技術權利和參考條款明確前，不得准入產品或解碼器。
- **完整樣本**：沒有可信、版本化來源的完整樣本。僅憑檔名副檔名不能確定夾具身份。
- **淨室可行性**：在無法區分歸檔、Microsoft Bond 資料或其他二進位載荷前，無法評估。
- **能力邊界**：不識別，不登記字尾，不瀏覽，不解壓，不檢查，不建立，不處理密碼或分卷。
- **結論**：**按產品決定明確不支援，且尚未確認是 Bandizip 歸檔格式**。本工作包不增加 `.bond` 探測器或登記項。

<a name="xdzip-j2j"></a>

## J2J

- **公開規範**：沒有找到 J2J 歸檔的規範、簽名、版本或開發者記錄。歷史 Bandizip 功能列表曾把 J2J 列為只解壓，現代官方格式頁面沒有技術定義。其他 J2J 搜尋結果指向 job-to-job 資料集或 JPEG-to-JPEG 工具，與歸檔無關。
- **參考實現**：沒有找到能與 Bandizip 歸檔讀取器對應、具有固定版本和許可的參考實現。
- **許可和再分發**：未知。第三方副檔名頁面和舊軟體列表不是許可授權。
- **完整樣本**：倉庫沒有可信、可再分發的樣本矩陣。`.j2j` 檔名不能建立容器身份。
- **淨室可行性**：在簽名、記錄模型、壓縮或加密行為和完整語料庫明確前，無法評估。
- **能力邊界**：不識別，不登記字尾，不瀏覽，不解壓，不檢查，不建立，不處理密碼或分卷。
- **結論**：**按產品決定明確不支援，且尚未確認是 Bandizip 歸檔格式**。本工作包不增加 `.j2j` 探測器或登記項。

<a name="xdzip-格式支持条件"></a>

## 格式支援條件

1. 記錄權威規範或經過法律複核的淨室協議。部落格、副檔名資料庫或單個解碼器原始碼都不夠。
2. 每個研究來源固定到不可變提交或內容雜湊，並記錄適用許可文字。
3. 為每個聲稱支援的方法、版本、分卷模式、加密狀態和終止條件建立完整可再分發夾具矩陣。只有頭部或 Store 樣本不能證明互操作。
4. 為輸入讀取、中繼資料、解壓工作、記憶體、邏輯輸出、歷史、密碼狀態和取消定義有界資源模型。在釋出前拒絕畸形偏移、環、溢位和來源變化。
5. 所有解碼器獨立於 Qt、掛載、啟動、安裝器、指令碼、登錄檔和任意程序執行 API。
6. 只有 codec、快照身份、準確載荷行為和失敗分類透過定向自動化後，才能接入 runtime、CLI、關聯入口和使用者文件。
7. 阻塞候選繼續在評估中標為阻塞。不能因為 Bandizip 或第三方列表出現名稱，就獲得字尾、MIME 或產品能力。

倉庫迴歸命令 `python scripts/test-m10-source-gates.py` 會檢查六項雙語記錄是否保留必要證據欄位，每項結論是否明確為阻塞、明確不支援或已准入，以及阻塞或明確不支援的候選是否誤加入 `specs/engineering/archive-formats.json`。
