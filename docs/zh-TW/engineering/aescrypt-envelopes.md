# AES Crypt 只讀封裝

[English](../../engineering/aescrypt-envelopes.md) | [简体中文](../../zh-CN/engineering/aescrypt-envelopes.md) | 繁體中文（台灣）

獨立 Rust 後端 `xdzip-codec-aescrypt` 讀取 AES Crypt 流版本 0、1、2、3，應用程式版本與流版本分開。每個封裝呈現一個普通虛擬檔案，不提供建立、修改、分卷或外部擴充套件獲取能力。內容僅加密而不壓縮，因此條目方法顯示 Store，同時標記已加密。壓縮大小為完整物理封裝長度。識別依據內容，不依賴 `.aes` 字尾。

<a name="xdzip-准入与认证"></a>

## 准入與認證

四個版本都必須在開啟時提供密碼，包括空檔案。釋出精確大小的後設資料前，必須認證整個密文。不可變歸檔會話透過現有秘密槽保留有界的開啟密碼，供檢查、預覽、提取使用，不另設逐條目密碼模型。任務讀取器再次完整認證封裝後才准入。匯出過程對實際解密的同一批密文計算認證，最終認證碼與大小檢查成功後才返回成功。主機只有在格式解碼和源檢查成功後才提交暫存檔案，未驗證的資料塊不授予最終釋出許可權。

0–2 版使用指定的 8192 輪 SHA-256 ACKDF，密碼編碼為 UTF-16LE。0 版直接派生資料金鑰，無法區分錯誤密碼與密文損壞，返回 `password_or_integrity`。1–2 版先對封裝的會話 IV/金鑰驗證 HMAC-SHA-256，再進行 CBC 解密，驗證失敗返回 `wrong_password`，該錯誤也可能來自封裝金鑰損壞。3 版採用 UTF-8 密碼與 PBKDF2-HMAC-SHA-512，對封裝會話位元組及版本位元組 `03` 認證，資料採用 AES-256-CBC 與 PKCS#7 填充。後設資料准入和匯出都先完成密文認證，再檢查填充，不能以填充作為密碼驗證器。認證碼比較使用已准入的固定寬度常量時間原語。

所有版本都驗證密文的 HMAC-SHA-256。但是 0–2 版把最後一塊的明文長度模 16 放在認證範圍之外，修改該欄位可能改變報告及匯出的長度，卻不使認證碼失效。2–3 版的擴充套件欄位同樣未加密、未認證。因此 `format_declared_checks` 僅表示格式宣告的檢查透過，不表示全部封裝欄位、傳送者身份或來源已認證。3 版的加密填充可以認證明文長度，舊版檢查成功不能描述為明文長度獲得完整認證。

<a name="xdzip-名称限制与失败"></a>

## 名稱、限制與失敗

虛擬名稱僅從主機授權的原始檔基名移除大小寫不敏感的 `.aes` 得到，不安全、空、點或雙點名稱回退為 `content`。未認證的 `FILENAME`、`URI`、`CREATED_BY` 及空容器擴充套件值不授予路徑、網路、程序或執行許可權，不恢復時間和執行位。首條成員恰好名為 `AES` 的普通 TAR 透過有界結構消歧保留為 TAR，擴充套件內含 TAR 標記的合法加密封裝仍為 AES Crypt。進入 AES Crypt 後，認證失敗不會回退為 TAR、ZIP 或其他格式。

1–3 版要求保留位元組為零，非空擴充套件記錄必須包含以 NUL 分隔的標識。准入限制為最多 256 條擴充套件、1 MiB 頭部，3 版迭代數為 1 至 2,000,000。零迭代、結構損壞、截斷或非整塊密文在執行 KDF 前拒絕。未知版本返回不支援。舊版長度模值須為 0–15，空密文只能宣告零；3 版至少有一個填充塊。不提供損壞修復。

讀取器分別限制累計實際輸入、實際雜湊壓縮塊工作、實際 AES 塊工作和交付明文，每項硬上限為 24 GiB。計算包括後設資料認證、KDF 和後續重複讀取，失敗不退還預算。呼叫者的後設資料輸入及名稱限制只能收緊准入。雜湊計算包含 KDF、HMAC 內外墊與結束塊，CBC 計算包含全部實際處理塊及封裝會話材料。附加准入和 KDF 工作在交付載荷前計入主機接收端。正常解碼繼續受主機源、輸出、任務限制約束，明文單檔案上限 8 GiB、單任務上限 20 GiB。通用格式介面最多接收 4096 個 UTF-8 密碼位元組，產品共享密碼入口仍為 1024 位元組。迭代上限是應用資源策略，不是格式定義的最大值。

KDF、每次讀取和有界 CBC 批次都檢查取消。密碼派生雜湊、中間 KDF 塊、金鑰、IV 鏈和明文緩衝使用可擦除狀態，已准入 AES 原語啟用清零功能。格式讀取器保留派生金鑰，不再複製儲存明文密碼。協作式取消不能中斷阻塞的作業系統讀取。源、取消、配額、輸出錯誤保留型別，僅重試無附加錯誤的中斷讀取。讀取器出錯後終止使用。主機物理身份、大小和時間檢查是盡力檢測源變化，不承諾原子內容快照。

<a name="xdzip-资料与回归输入"></a>

## 資料與迴歸輸入

結構和密碼學規則依據作者的 [AES Crypt 流規範](https://www.aescrypt.com/aes_stream_format.html)及[引擎流說明](https://github.com/terrapane/aescrypt_engine/blob/master/stream_format.md)。後端使用已准入的通用 AES 與 SHA-2 原語，不引入 AES Crypt 執行時或官方應用程式，不執行解密檔案，也不繞過應用許可。共享秘密 SHA-512/HMAC 狀態遵循 RFC 2104 與 [RFC 4231](https://www.rfc-editor.org/rfc/rfc4231)。

[自有樣本集](../../../tests/fixtures/aescrypt/README.md)包含獨立編碼的 0–3 版輸入，並由獨立 Python 密碼學解碼器交叉核對。固定公開測試金鑰與 IV 只用於確定性樣本。參考工具只留在 `build/toolchain/`，生成證據只留在 `build/` 或 CI。驗收條目為[驗收要求](../../../developers/qa/acceptance.md)中的 `FORMAT-AESCRYPT`。另見[密碼處理](password-extraction.md)、[歸檔檢查](archive-checking.md)及[安全提取](zip-safe-extraction.md)。
