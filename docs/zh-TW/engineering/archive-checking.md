# 壓縮檔完整性檢查

[English](../../engineering/archive-checking.md) | [简体中文](../../zh-CN/engineering/archive-checking.md) | 繁體中文（台灣） | [日本語](../../ja-JP/engineering/archive-checking.md) | [한국어](../../ko-KR/engineering/archive-checking.md) | [Français](../../fr-FR/engineering/archive-checking.md) | [Deutsch](../../de-DE/engineering/archive-checking.md) | [Español](../../es-ES/engineering/archive-checking.md) | [Português (Brasil)](../../pt-BR/engineering/archive-checking.md) | [Русский](../../ru-RU/engineering/archive-checking.md)

工具欄“測試”對符合條件的目前歸檔執行一次真實背景檢查，覆蓋全部物理記錄，包含重複名稱、目錄和空檔案，不受目前目錄、搜尋或選擇影響。進入磁碟索引的歸檔暫不支援整包檢查，見[大歸檔索引](large-index.md)。檢查只持有凍結的輸入來源與後設資料，不取得目標目錄授權、不建立暫存或輸出檔案，不使用解壓路徑對映和連結釋出流程。

UU/UUE 和 XXE 檢查文字封裝中的每個物理成員，包括空檔案與同名記錄，驗證計數行或已准入的 Base64 填充及精確結束標記。它們不提供校驗和或認證，替換有效字母表字元可能改變內容而不報錯。標頭中的路徑與模式不授予輸出或執行權限，詳見[文字封裝契約](text-envelopes.md)。

Z 與 TAR.Z 驗證 Unix compress LZW 碼、字典邊界、CLEAR/碼寬對齊及物理 EOF，TAR.Z 另驗證完整 TAR 記錄與末尾。格式沒有內容校驗和、解碼大小欄位或認證，結構檢查成功不能發現所有保持結構的替換或有效碼尾部。繼續使用相同受控源和任務限額，詳見 [compress 契約](compress-streams.md)。
<a name="xdzip-格式与结果"></a>

## 格式與結果

普通 GZIP、BZip2、LZMA Alone 和 Lzip v1 解碼到同一有界丟棄接收器，驗證精確終止和觀察尺寸。GZIP 檢查逐成員 CRC/ISIZE，BZip2 檢查塊與組合 CRC，Lzip 檢查 CRC、資料尺寸和完整成員尺寸。LZMA Alone 無內容校驗和，成功只表示結構與可讀性成立。壓縮 TAR 組合重新掃描完整容器及壓縮 EOF，不再另解一次負載。檢查強度由[內建能力表](format-registry.md)登記，邊界及組合見[壓縮流契約](single-file-streams.md)。

ZIP 檢查適用於符合條件的 ZIP／ZIP64，包括支援的編號分卷和 PKZIP 分卷。解碼器將受支援的條目負載寫入有界丟棄接收器，校驗中央目錄、本地頭、描述符、流精確終止、宣告大小、CRC 及已支援的 AES-256 認證。未加密的 Deflate64、BZip2、LZMA、XZ 條目還須符合下文的方法限制。名稱安全的 ZIP 符號連結只校驗負載，不解析目標或建立連結。未知方法、未支援的加密、危險名稱及其他不符合條件的記錄會導致檢查失敗。

7z 和 RAR 使用隔離工作程序中的獨立 Rust 後端，逐物理條目解碼到同一個有界丟棄接收器，驗證解碼終止、宣告大小和容器實際提供的校驗。固實塊內為到達目前選擇而解碼的其他資料只累計工作量，不增加目前檔案的已驗證計數。目錄、空檔案和加密條目均不能跳過後報告整包成功。RAR 舊版、RAR5 和 RAR 7 新演算法分別使用獨立已知內容樣本驗收，不能僅以相同魔數代表版本相容。

CAB 使用隔離工作程序內的自研 Rust 容器與共享演算法，驗證卷集合、實際解碼大小和完整資料幀提供的校驗。ISO/UDF 檢查描述符、目錄、資料範圍和宣告大小，並實際讀取所有受支援普通檔案；它們沒有普遍的逐檔案內容校驗和，不能發現任意保持結構的內容篡改。映象連結、裝置及其他不支援記錄不能跳過後宣稱整包透過。混合映象檢查凍結的 UDF 名稱空間，不在失敗後改查 ISO 名稱空間。

TAR 與 TAR.GZ 在檢查任務內重新順序掃描完整流，對照凍結的物理記錄後設資料，檢查頭校驗、長度、兩個結束塊及尾部。TAR.GZ 繼續消費到 EOF，核對 GZIP CRC／ISIZE，不在完整掃描之後再次解壓全部內容。TAR 沒有檔案內容校驗和，只能確認格式結構與可讀性，無法發現任意保持結構的內容篡改。TAR 連結、特殊物件和稀疏檔案仍不支援。本功能不證明歸檔來源可信，也不檢查惡意軟體。

複合檔案（MSI）檢查容器結構及原始資料流的可讀性，沒有內容校驗和。NSIS 僅提供靜態安裝器後設資料。具體邊界見 [MSI 與 NSIS 格式說明](wim-msi-installer-format-sources.md)。

首個結構、負載、來源、資源或不支援條目錯誤結束任務。結果區分成功、失敗與取消，顯示已驗證及未檢查檔案數，保留失敗條目和穩定錯誤碼。所有物理記錄均參與校驗，`files`／`verified_files` 仍只統計非目錄檔案，空檔案參與檔案數。目錄和純目錄包也必須完成結構校驗後才能成功。檢查中或此前已完成的讀取不等於整包透過。

<a name="xdzip-调度来源与资源"></a>

## 排程、來源與資源

`Check { session }` 凍結來源 `Source::fork()`、格式、後設資料和原始會話身份，進入與建立、解壓相同的有界重任務佇列及應用級序列准入。開始、讀取後及成功終態前複核來源控制代碼、全部卷路徑的身份、大小和時間資訊。來源變化返回 `source_changed`，只失效對應的原會話。此檢測是盡力檢查，不是輸入內容的原子快照，不承諾檢測保留身份和時間資訊的併發原地修改。

實際解碼受單檔案 8 GiB、任務累計 20 GiB 限制，錯誤密碼重試不重置累計工作量。ZIP 保留獨立 64 MiB 定位後設資料預算和共享 20 GiB 實際輸入讀取預算；TAR／GZIP 保留既有 24 GiB 整流讀取上限。7z／RAR／CAB／ISO／UDF 額外使用原生程序 1 GiB 記憶體上限，輸入讀取與固實跳過同樣有界，超限為資源限制而非完整性透過。任務與事件數量、快照明細和保留記憶體沿用既有佇列上限。成功終態不設定寫入、提交、儲存目錄或輸出路徑計數。

任務種類由 `kind=check` 明確傳至 Qt。`read_bytes` 表示實際來源讀取量，包含頭部與重試；`decoded_bytes` 表示實際解碼工作，`verified_bytes`／`verified_files` 只在要求的校驗完成後增加。TAR／GZIP 完整掃描期間不編造檔案級百分比，實際讀取量與速度仍可見，成功後才將整流檔案計為已驗證。

AES 密碼複用[密碼協議](password-extraction.md)：獨立控制槽、一次性提示身份、任務內快取、最多每條十次錯誤驗證值響應、認證破壞直接失敗及秘密歸零。取消和退出喚醒密碼等待，不依賴普通命令佇列容量。關閉瀏覽頁或進度視窗不取消已接收任務，結果從全域性任務入口重開；明確退出仍等待取消及非同步執行緒結束。

<a name="xdzip-验证边界"></a>

## 驗證邊界

核心迴歸覆蓋支援格式、空檔案、目錄、重複名稱、ZIP 連結負載、密碼重試／取消、損壞負載、來源變化、實際計數和無輸出。橋接與 Qt 驗證真實工具欄到背景任務和結果閉環，密碼路由、歷史任務、跨會話准入及退出獨立檢查。雙語多字號、淺深色與原生桌面視覺驗收分別登記在 issue，生成證據僅儲存於 build/ 或 CI 工件。

舊式 RAR 加密條目缺少可可靠區分錯誤密碼與損壞內容的驗證值，因此每個加密條目解碼前分別請求密碼，不能把前一條密碼直接套用到可能使用不同秘密的下一條。RAR5 和受支援的其他格式繼續任務內複用。未取得可信密碼驗證值的加密解碼或加密頭完整性失敗報告 `password_or_integrity`，保留錯誤密碼或內容損壞的歧義；明文頭校驗、來源變化、取消、限額及輸出 I/O 不誤歸類為密碼問題。

包含未知原始大小的歸檔仍可瀏覽；整包檢查的總量標為未知，並在開啟載荷或請求密碼前以 `unsupported_feature` 失敗，已驗證和解碼產量保持實際值。未知大小不按空檔案驗證，也不將內部哨兵值用作進度分母。

XZ 和 TAR.XZ 使用 `format_declared_checks`，須驗證宣告的 CRC32、CRC64、SHA-256 和結構欄位；宣告 None 的流沒有內容校驗和。介面須說明此區別，不承諾每份輸入都有內容校驗和。新增未加密 ZIP 方法 9、12、14、95 仍須滿足精確解碼尺寸及外層 ZIP CRC，LZMA 資料描述符配置須有 EOS。未知方法可展示，但不能計為內容驗證成功。

AES Crypt 使用 `format_declared_checks` 和保留的開啟密碼。後設資料准入之前與實際任務解碼之後，都必須通過完整密文 HMAC 驗證。0–2 版不認證尾部長度模值，擴充欄位也未認證。檢查成功僅表示格式宣告的檢查透過，範圍見 [AES Crypt 契約](aescrypt-envelopes.md)。

Brotli 與 TAR.BR 使用 `structure_and_readability`，必須透過完整流結束、宣告的元塊大小和全部准入詞典/歷史變換，Brotli 本身不提供內容校驗和。詳見 [Brotli 契約](brotli-streams.md)。

LHA/LZH 使用 `format_declared_checks`，實際解碼全部受支援普通檔案，驗證準確長度和所有存在的頭部、載荷 CRC-16。古老 0 級成員可缺少 CRC，此時僅檢查結構、尺寸與可讀性；LH2 必須按 CRC 約束執行有限變體准入。未知方法、異常名稱、連結或特殊物件不能跳過後宣稱整包成功，詳見 [LHA 契約](lha-containers.md)。

PMA 使用 `format_declared_checks`，完整解碼准入的 PM0/PM1/PM2，核對準確尺寸及存在的載荷 CRC-16；缺少 CRC 的成員僅檢查結構、尺寸和可讀性。未知方法和其他不支援條目阻止整包成功。CP/M 填充作為物理容器結構驗證，位於成員壓縮區間之外，詳見 [PMA 契約](pma-streams.md)。

ARJ 使用 `supported_content`。完整後設資料准入驗證主頭部、檔案頭部及擴充套件頭部 CRC-32；檢查透過 Store 或方法 1–4 完整解碼所有準入普通成員，核對準確尺寸和必需載荷 CRC-32，舊文字保留 CRC 覆蓋的原始位元組，不轉換換行。未知或不支援記錄阻止整包成功，詳見 [ARJ 契約](arj-streams.md)。

ARC 使用 `supported_content`，完整驗證物理結構，透過舊/新 Store 或方法 3–9 實際解碼，核對準確尺寸及必需 CRC-16/IBM。不跳過未知方法、可疑名稱或不支援配置後宣稱整包成功。頭部 SHA 繫結用於凍結快照，不提供認證，詳見 [ARC 契約](arc-streams.md)。

BH 使用 `supported_content`，完整驗證 `BH 05 07` 成員結構、方法 8 raw Deflate 結束、準確解碼長度和必需 CRC-32。未知方法、固定欄位錯誤、可疑名稱和不支援配置仍保持可見，但會阻止整包檢查成功，詳見 [BH 契約](bh-containers.md)。

ALZ 使用 `supported_content`，完整驗證單卷結構、Store 或原始 Deflate 的載荷結束、準確解碼長度和必需 CRC-32。加密、資料描述符、改造 BZip2、分卷和未知方法記錄保持可見，但會阻止整包檢查成功，詳見 [ACE、ALZ 與 EGG 資料門檻](ace-alz-egg-format-sources.md)。

EGG 使用 `supported_content`，完整驗證無加密、非固實普通單卷結構、Store 或原始 Deflate 塊結束、準確塊尺寸和必需 CRC-32。AZO、BZip2、LZMA、加密、分卷、固實和未知方法記錄保持可見，但會阻止整包檢查成功，詳見 [ACE、ALZ 與 EGG 資料門檻](ace-alz-egg-format-sources.md)。
