# ZIP 建立實現契約

[English](../../engineering/zip-creation.md) | [简体中文](../../zh-CN/engineering/zip-creation.md) | 繁體中文 | [日本語](../../ja-JP/engineering/zip-creation.md) | [Français](../../fr-FR/engineering/zip-creation.md) | [Deutsch](../../de-DE/engineering/zip-creation.md) | [Español](../../es-ES/engineering/zip-creation.md)

從明確選擇的檔案與目錄建立新 ZIP；預設 2-正常壓縮，使用 Deflate 6；支援 Store 與 Deflate 1／6／9、WinZip AES-256 內容加密和編號分卷。TAR/GZIP 的建立與解壓見[格式說明](tar-gzip.md)，AES-256 讀取見[密碼解壓](password-extraction.md)；分卷讀取見[分卷契約](archive-opening.md)，普通單檔案歸檔的顯式新增使用[檔案拖放與修改契約](archive-transfers.md)，不復用新建歸檔的源保護例外。輸入授權、暫存、校驗、重名決策和最終儲存由宿主負責，格式層只接收條目、可讀輸入與可寫輸出。

<a name="xdzip-输入树与预算"></a>

## 輸入樹與預算

選擇項必須為絕對路徑的普通檔案或目錄。去重同一路徑，並去除已選擇目錄內部的重複選擇；目錄遞迴保留根目錄名稱，空目錄寫入顯式記錄。拒絕連結、重解析點、裝置等特殊物件，拒絕不可移植名稱與大小寫碰撞。根目錄控制代碼按共同父目錄合併，最多 128 個；條目最多 100,000，深度最多 64，名稱總量最多 16 MiB，每檔案最多 8 GiB，輸入總量最多 20 GiB。只持有有限根控制代碼和目前讀取檔案，不為每個條目持有一個檔案描述符。

輸入父目錄的系統別名先歸一到同一位置，所選葉物件不跟隨連結；開啟根後繫結並複核目錄身份。目錄發現使用根控制代碼下的 no-follow 遍歷，儲存目錄身份與過濾後的子項清單、檔案身份／長度／修改時間。編碼前後和儲存前複核；開啟每個檔案與讀到 EOF 時複核檔案版本。新增、刪除、改名、連結替換和可觀察內容修改失敗為來源變化。身份／時間戳複核是盡力檢測，不是原子內容快照，不能保證識別同賬戶刻意恢復後設資料的編輯。

除下述 macOS 後設資料外，建立保留使用者選擇的全部普通輸入，已有目標壓縮檔、舊分卷和其他目錄內的同名檔案均按普通輸入處理，不能因其與目標路徑重合而提前拒絕或靜默排除。輸入樹另外過濾本次已建立、身份匹配的私有暫存工作目錄，不能按 `.xdzip-*` 或目標檔名稱通配過濾。目錄路徑別名先歸一併與持有控制代碼身份核對；顯式選擇私有工作目錄及其目錄別名繼續拒絕。

編碼只寫入私有暫存檔案，完整校驗透過後才進入最終重名守衛。目標也參與輸入時，正常顯示重名提示，禁止覆蓋該輸入，允許使用新名稱或取消；僅選擇舊目標檔案也沿用同一流程，其原位元組包含在新名稱的壓縮檔中。直接覆蓋引數或繞過介面的覆蓋回答均返回 `protected_source`，原檔案保持不變。歸檔過程中不重新遞迴發現新增檔案，最終壓縮檔在儲存階段才釋出，不把正在增長的暫存檔案歸檔進自身。

重名視窗保持既定邏輯寬度與共享 footer；標題和保護說明在正文可用寬度內換行，輔助字號不能透過擴大布局最小寬度造成橫向裁切。正文超高時滾動，決策按鈕保持可達。

<a name="xdzip-macos-元数据输入过滤"></a>

## macOS 後設資料輸入過濾

建立 ZIP、AES-256 ZIP、編號分卷 ZIP、TAR 和 TAR.GZ，以及向普通歸檔新增檔案，共用 Rust `InputTree::scan_for_archive` 策略。在全部宿主平臺，按完整末級名稱精確匹配並排除普通檔案 `.DS_Store`，以及目錄 `__MACOSX`、`_MACOSX` 的整棵子樹，覆蓋顯式選擇與目錄遞迴。名稱區分大小寫，不擴大為 `._*`、隱藏檔案或名稱字首通配；同名普通 `_MACOSX`／`__MACOSX` 檔案仍作為輸入。顯式選擇被排除目錄及其後代時，後代不因重複選擇重新加入。所選及發現的連結、重解析點和特殊物件繼續遵循原 no-follow 拒絕規則，不透過過濾獲得讀取許可權。

僅從本次歸檔輸入中排除，不刪除或修改主機原檔案，也不清理原歸檔的既有記錄。因過濾後設資料才變空的目錄及其空祖先不寫入；真正的空目錄和零位元組普通檔案繼續保留。過濾後沒有有效條目時，在編碼與重名提示前以 `empty_input` 失敗，現有結果視窗顯示“排除 macOS 後設資料後，沒有可壓縮的檔案或資料夾。”，不釋出新包、不修改已有歸檔。選擇摘要仍是有界後設資料預覽，最終有效內容由背景任務掃描決定，不在 GUI 遞迴掃描。

凍結與儲存前複核使用同一過濾策略。後設資料的內容及存在性變化不使有效輸入失敗，普通條目及被裁剪目錄中的普通子項變化仍觸發來源變化。掃描預算同時約束最終被裁剪的普通目錄，不能借過濾繞過條目和名稱預算。解壓、臨時開啟、包內移動和 macOS 檔案承諾釋出不應用新增輸入過濾；普通 `InputTree::scan` 保留所有內容。

<a name="xdzip-格式接口与校验"></a>

## 格式介面與校驗

編碼介面獨立於 Qt 和檔案路徑。宿主提供有序的不可變條目列表及按序號開啟的只讀流；格式層寫入宿主流並報告實際處理位元組。ZIP 採用獨立 Rust 記錄寫入器與共享 Deflate 後端，固定 UTF-8 名稱、普通檔案／目錄許可權，不保留特權位。大條目和中央目錄自動使用 ZIP64。來源大小必須與凍結值一致，失敗留下的暫存流不具有釋出資格。

寫完資料、結束壓縮流、寫完中央目錄後，宿主重新掃描暫存 ZIP，並逐條解碼檢查頭、大小、CRC 和流終止。條目名、型別、大小必須與凍結輸入樹一致。校驗與來源複核透過後才允許整體儲存；不把僅能列目錄視為歸檔完整性證明。讀取、壓縮、寫出及校驗均在背景重任務執行緒執行，定期檢查取消。

<a name="xdzip-暂存冲突与整体保存"></a>

## 暫存、衝突與整體儲存

使用 M3 已驗證的目錄授權、同卷私有暫存和整體檔案提交原語。預設詢問重名，支援使用新名稱或替換已確認的普通檔案；不覆蓋目錄、連結、特殊物件或參與輸入的檔案身份。重名決策繫結任務與提示 ID，提交前再次複核現有目標。檔案系統不能提供所需原語時失敗，不以複製／刪除模擬原子儲存。

macOS 建立輸出複用 [M3 擴充套件 ACL 邊界](zip-safe-extraction.md#xdzip-macos-%E6%89%A9%E5%B1%95-acl-%E6%8E%A7%E5%88%B6)，允許不向外部主體授予修改能力的拒絕／只讀 ACL，拒絕外部有效或僅繼承修改許可權；目標根、暫存目錄、新建父目錄和已有輸出均按共享邊界檢查。不改寫使用者 ACL，也不保證對既有隻讀共享賬戶隱藏壓縮檔內容。

不分卷時建立任務整體儲存一個 ZIP。校驗或儲存前取消，移除本次已知暫存檔案，現有歸檔保持不變；不能把已經寫出的輸入條目計為已經儲存的檔案。取消與最終提交共享既有門閂；提交許可獲得前取消勝出，許可獲得後整體提交結果勝出。成功提交後到達的取消不把成功改成取消。清理失敗保留可恢復材料並標記警告，不刪除陌生暫存目錄。

<a name="xdzip-任务与界面"></a>

## 任務與介面

建立與解壓共用有界背景任務通道、控制與退出機制。任務快照明確區分建立／解壓及總量是否已知；掃描階段顯示未知總量，掃描完成後使用凍結檔案數與大小。寫入過程中顯示實際輸入讀取量、輸出寫入量與目前檔案；校驗階段單獨標明，不能把校驗位元組再次計為輸入讀取量。

新建視窗按高保真原稿與 HTML 佈局實現，複用路徑框、內建下拉、核取方塊、按鈕與 footer。新增檔案、新增目錄、移除、名稱、目標、Store／Deflate、級別、開啟完成結果均可操作。級別為 0-不壓縮、1-快速壓縮、2-正常壓縮、3-最大壓縮，預設 2；分別對映 Store／Deflate 1／6／9。演算法不另設控制元件。分卷和密碼為真實建立引數；TAR/TAR.GZ 在 [WP-11](tar-gzip.md) 中複用此安全建立閉環，格式專屬能力按其契約控制。執行視窗使用修正後的正常密度，關閉視窗後任務繼續；任務可在狀態列重新開啟，並可取消和處理重名。

<a name="xdzip-选择摘要与共用控件"></a>

## 選擇摘要與共用控制元件

選擇普通檔案後，在已有 Rust 後設資料工作執行緒讀取目前檔案長度，GUI 不讀取磁碟或遞迴目錄。InspectInputs 最多 256 路徑，返回順序固定、大小以十進位制位元組字串橋接；symlink_metadata 不跟隨所選葉連結。摘要使用十進位制 MB；零位元組是已知大小，目錄與失敗為未知，不把未知寫成零。超過 256 項保留未檢查說明，實際建立仍採用原有建立預算。快速編輯合併最新路徑集合，過期結果不覆蓋新選擇；目標檢查優先，普通查詢按已有取消機制執行。摘要不是預檢授權，輸入樹在任務開始後重新建立。

目標路徑檢查和輸入摘要屬於背景準備，不改變新增、移除輸入控制元件的可用外觀，也不向起始頁釋出檢查提示。檢查期間繼續序列化實際請求；建立按鈕僅在目前路徑的建立檢查透過後可用。解壓檢查使用獨立狀態，不能以相同路徑的建立檢查代替，詳見[解壓契約](zip-safe-extraction.md)。

六類操作視窗共用 footer 按鈕；欄位、正文動作、圓形移除與分段組選項複用對應角色元件。外觀與字號生成自 layout-scale.json，不由視窗覆蓋。真實摘要、控制元件量測及截圖按[驗證方法](../../../developers/qa/README.md)儲存到 build/ 或 CI 工件。

<a name="xdzip-验收"></a>

## 驗收

覆蓋後設資料根項、巢狀目錄、混選、僅含後設資料的多層目錄、真正空目錄、加密與編號分卷，以及過濾後為空時沒有新輸出且保留舊輸出。真實 Store／Deflate、Unicode 名稱、空檔案與空目錄的寫入、重新開啟和解壓互操作；獨立 Python zipfile 驗證內容、CRC 與目錄。驗證來源變化、名稱碰撞、連結／特殊物件、輸出在輸入樹內、顯式或目錄發現的舊目標位元組完整入包、父路徑及大小寫／Unicode 別名、異目錄同名輸入、僅選舊目標後的正常改名、輸入身份覆蓋保護、校驗失敗、重名變化與取消保留舊歸檔。三平臺核心／橋接／Qt 構建與背景生命週期檢查，正常密度及高 DPR 實際捕獲。效能記錄實際輸入量、耗時、資源與校驗開銷，不由壓縮級別推定壓縮率。

<a name="xdzip-aes-256-内容加密"></a>

## AES-256 內容加密

啟用“輸入密碼”後，密碼不能為空，接受 1–128 個 UTF-8 位元組，拒絕控制字元及無效 Unicode；不修剪前後空格。使用獨立 WinZip AE-2 AES-256 封裝，隨機鹽來自作業系統，AES、PBKDF2、HMAC 使用已准入通用密碼學庫，禁止自行實現密碼學原語或退回 ZipCrypto。每個普通檔案（包括空檔案）都加密，CRC 欄位為零，最後寫入認證碼；普通目錄記錄和檔名仍可見，不宣稱檔名加密。具體引數見[自研格式契約](independent-rust-codecs.md)。

原始碼編碼介面僅借用密碼，沒有檔案路徑與提交許可權。Rust 密碼容器在 Debug 中固定顯示 `[REDACTED]`，離開作用域時歸零；佇列取消、拒絕和退出同樣觸發歸零。密碼不進入快照、日誌、配置、命令列或恢復日誌。Qt／HTML 密碼框關閉、取消或提交後清空；Qt/瀏覽器及系統記憶體中的歷史副本無法保證擦除，不能把 Rust 容器歸零表述為全程序安全擦除。

寫後校驗逐項解密到有界丟棄接收端，讀到 EOF 驗證認證碼與流終止，同時對照凍結輸入的名稱、型別和大小；錯誤密碼、內容破壞或取消均不釋出。獨立 7-Zip 解碼是互操作門檻。受支援的 AES-256 結果與普通 ZIP 一樣在應用內自動開啟，可進入真實密碼解壓；編號分卷在應用內自動開啟首卷，均不自動開啟系統資料夾。

<a name="xdzip-分卷参数与发布"></a>

## 分卷引數與釋出

下拉選項：不分卷、3MB、4MB、5MB、10MB、20MB、25MB (Gmail)、100MB、300MB、650MB (CD)、700MB (CD)、4GB (FAT32)、4.7GB (DVE)、自定義。MB/GB 使用十進位制位元組。自定義將統一下拉改為可輸入正整數，右側單位為位元組、KB、MB、GB；空值、零、非數字或超出 24 GiB 無效。最多 1024 卷；實際壓縮結果超出卷數預算時不釋出。

格式為位元組分卷 `.zip.001`、`.zip.002` 等，最後一卷可較小。這是 7-Zip 相容的編號分卷，不是帶多磁碟頭的 `.z01` 格式。先寫完並驗證完整 ZIP，再用固定 64 KiB 緩衝分割到私有檔案，每卷同步後關閉控制代碼。記憶體和已開啟普通檔案數量不隨卷數線性增長；暫存磁碟最多需要完整 ZIP 加分卷副本，完整 ZIP 寫出上限為 24 GiB，分卷副本另需不超過完整 ZIP 的空間，暫存最壞約 48 GiB；任務寫出計數不把分卷複製重複計算為歸檔大小。

分卷同樣保留使用者選擇的舊卷、基名 `.zip`、`.zip.1025` 和其他普通輸入，應用相同的 macOS 後設資料排除，並過濾身份匹配的私有暫存目錄。已有輸出卷在最終儲存時按整組衝突規則改名或取消，不因舊卷參與輸入而提前失敗；不覆蓋舊卷或參與輸入的檔案身份。

整組預檢所有目標，存在舊卷時支援整組改名或取消；覆蓋動作禁用。取得提交許可後逐捲進行 no-replace 釋出；多個檔案沒有共同原子可見點，不聲稱多檔案原子事務。後續失敗只回滾本次釋出且身份仍匹配的卷；併發建立的舊檔案保持不變，回滾失敗明確標記恢復警告與結果不確定。取消在提交許可前勝出，許可後按整組提交／回滾結果結束，不留下偽裝為成功的部分卷集。

<a name="xdzip-结果记录与界面"></a>

## 結果記錄與介面

結果視窗採用 [結果原稿引數](../../../specs/visual/result-reference.json)，標題、三列統計、未完成卡片與目標位置沿用原稿；展開明細使用補充原稿和統一圖示。正文滾動、footer 固定，控制元件邏輯尺寸不受 DPR 或瀏覽器縮放影響。

每個真實檔案完成、明確跳過或失敗時記錄狀態，不從進度比例推算成功。快照透過共享有界記錄列表儲存最近 128 項，每項名稱最多 1024 UTF-8 位元組，顯示省略數量；統計始終覆蓋全部檔案。建立記錄描述實際釋出歸檔／分卷，失敗不把已讀取輸入算成已儲存。記錄僅存於目前記憶體任務，預設不跨啟動持久化。

成功建立受支援歸檔後，Qt 按任務 ID 的首次成功終態，將最終提交路徑放入序列開啟佇列；等待目前讀取／准入結束後自動在應用中開啟。失敗、取消和重複終態不觸發開啟。使用者顯式開啟同一檔案時，以 Qt 規範路徑比較並統一原生分隔符（Windows 同時忽略大小寫），消費尚未執行的自動開啟意圖。此比較僅用於介面意圖去重，不授予輸出許可權。去重可避免再次開啟導致新會話與解壓意圖失效。編號分卷輸出同樣自動開啟首卷，由[分卷讀取主機](archive-opening.md)驗證並讀取完整卷組；缺卷時明確報錯。結果視窗保留真實輸出檔案與卷數，不再要求外部讀取器。

2026-10-16 完成行為修訂：建立不自動呼叫系統檔案管理器，建立視窗移除目錄自動開啟選項。舊 startCreation 的 openAfter 引數忽略；任務接受及終態兩條路徑均禁止建立任務自動開啟系統目錄。成功結果沿用應用內開啟佇列，加密與編號分卷使用現有讀取能力。結果統計使用“已儲存”標籤。詳見 [介面契約](../ux/welcome-opening.md)。

來自[系統右鍵](shell-actions.md)的建立任務攜帶獨立完成策略，成功結果不進入應用內自動開啟佇列。單項和多項建立均顯示真實獨立結果，只有使用者主動點選結果中的目錄操作才交給系統檔案管理器。
