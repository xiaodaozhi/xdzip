# ARJ 壓縮流與容器准入

[English](../../engineering/arj-streams.md) | [简体中文](../../zh-CN/engineering/arj-streams.md) | 繁體中文（台灣）

`ArjReader` 提供 ARJ 方法 1–4 的有界原始解碼，Store 由容器處理。`xdzip-codec-arj` 在主機提供的源上完整驗證物理結構，並按 CRC 交付成員。`ArjCodec` 將准入配置接入 runtime、CLI 和桌面的瀏覽、檢查與提取，[格式登記](../../../specs/engineering/archive-formats.json) 宣告只讀邊界，不支援建立、修改、密碼或分卷。

<a name="xdzip-主机准入与名称"></a>

## 主機准入與名稱

十二位元組主頭部候選不釋出格式或條目。runtime 先保留已驗證強容器及 ZIP/SFX 的優先順序，再以共享弱探測輸入賬本完整掃描 ARJ 後設資料。未經驗證的原始 TAR 標記透過完整 ARJ 准入消歧。無效猜測不釋出條目，帶型別主機錯誤、取消和配額耗盡保持權威。

適配層保留物理成員序號、原始方法位元組和名稱。ANSI 標記名稱與 OEM 名稱分組判定編碼，共享 1 MiB 完整欄位取樣上限，不依賴目前系統區域。先解碼完整多位元組名稱，再解釋分隔符。只有沒有可移植路徑標記的 DOS 類主機才將反斜槓轉換為正斜槓；可移植路徑和 Unix 中的字面反斜槓保持可疑。顯式目錄補末尾斜槓。可疑或未解析名稱、未知方法和不支援物件保持可見，不獲得載荷許可權。解碼名稱上限為 4096 位元組，保留的顯示/解碼名稱分配上限為 16 MiB，更小呼叫方限制仍生效，不恢復屬性。

開啟載荷時先重新投影並比較完整凍結條目集合，選中條目須與對應物理行完全相同。不支援選擇或任何解碼失敗都會使載荷例項進入終止狀態。主機身份檢查、預檢、私有暫存、取消和最終提交保持共享 runtime 語義。`supported_content` 檢查實際解碼所有準入普通成員，核對準確尺寸和必需 CRC-32；不支援條目阻止整包成功。舊文字交付歸檔中 CRC 覆蓋的位元組，不按主機轉換換行。

<a name="xdzip-来源与参考边界"></a>

## 來源與參考邊界

[ARJ 開源專案](https://arj.sourceforge.net/) 提供 [3.10.22 原始碼](https://arj.sourceforge.net/files/arj-3.10.22.tar.gz)，SHA-256 為 `589e4c9bccc8669e7b6d8d6fcd64e01f6a2c21fe10aad56a83304ecc3b96a7db`，以及 [Win32 3.10 工具包](https://arj.sourceforge.net/files/arjw_310.exe)，SHA-256 為 `e5cc5d8f82c5f08246e1c0a8c5be77e5f796c2dd30f987e6bbb27a2c1df1e371`。原始碼包含 GNU GPL 第 2 版文字，有限線格式觀察涉及 `defines.h`、`decode.c`、`arj_arcv.c`。原生參考保持未修改及原有條款，僅位於 build/toolchain。

獨立比較使用官方 [7-Zip](https://www.7-zip.org/)，有限原始碼觀察來自其 [ARJ 處理器](https://github.com/ip7z/7zip/blob/main/CPP/7zip/Archive/ArjHandler.cpp)，Git blob 為 `da890f279d35c00bc61d332ce55f4d96ecd6d373`。不宣稱嚴格淨室。Rust 複用專案自研的位、字首和 LZ 原語，直接表達快速方法的一元位欄位。參考原始碼、二進位制或壓縮引擎不進入產品依賴閉包。元件與自有輸入的準確身份見[樣本說明](../../../tests/fixtures/arj/README.md)。

<a name="xdzip-静态方法-13"></a>

## 靜態方法 1–3

方法 1–3 共用靜態 Huffman/LZ 線格式，原生編碼器可採用不同查詢策略。16 位塊命令數、19 符號碼長表、510 符號字面量/長度表、17 符號位置表和五位位置計數，透過顯式 ARJ 配置複用有界 LZH 字首實現，不獲得 LH3 的舊樹欄位或公共 LHA 方法編號。零塊命令數未准入。

字面量為 0–255，其餘符號按 `symbol - 253` 得到 3–256 位元組長度。位置符號零表示偏移零，否則偏移為 `2^(symbol - 1)` 加相應數量的低位。實際距離為偏移加一，最多 26624，且必須引用已經輸出的位元組。32 KiB 環實現該邏輯歷史，較大分配不擴大准入範圍。LHA 的初始空格保持獨立，不能初始化 ARJ 輸出。迴繞與重疊複製按順序逐位元組執行，完整規範碼樹、單符號欄位、零遊程和 16 位碼深保留共享字首的驗證及工作計量。

<a name="xdzip-快速方法-4"></a>

## 快速方法 4

位流高位在先。長度欄位統計 0–7 個連續一位，未達最大值時以零停止，再讀取相同位數的低位，加上 `2^count - 1`。零表示八位字面量，非零表示該值加二的複製長度，範圍為 3–256。指標類似地統計 0–4 個連續一位，低位寬度為 `9 + count`，基數為 `512 * (2^count - 1)`。偏移加一得到實際距離，最多 15872。每次引用必須指向已輸出歷史，在 16 KiB 環中處理重疊與迴繞，不修復初始歷史。

<a name="xdzip-限额与失败"></a>

## 限額與失敗

靜態配置為 32 KiB 歷史及輸入、表、臨時空間另加 64 KiB，快速配置為 16 KiB 歷史及輸入、狀態、臨時空間另加 32 KiB。壓縮與解碼硬上限各為 24 GiB，工作硬上限為 96 GiB，呼叫者更小預算仍保持權威。單次輸出讀取最多 8192 位元組。字首操作、歷史工作和不讀源的複製均保留協作取消點，`work_remaining()` 支援容器累計實際工作。

宣告長度不能超出，邏輯壓縮位元組必須準確結束。最終不足一位元組的填充忽略，完整多餘位元組或輸入不足均失敗，不虛構 EOF 零位元組。只有無附加錯誤的 `Interrupted` 可以重試，型別化錯誤保留首次載荷並終止。源、格式、預算和取消錯誤均使例項失效。原始讀取器不擁有路徑、憑據、執行、檔案系統釋出或 CRC 許可權。

<a name="xdzip-有界物理容器"></a>

## 有界物理容器

`inspect` 驗證偏移零開始的歸檔，主首頭寬度為 30、34，檔案首頭寬度為 30、34、46，完整基塊最多 2600 位元組。名稱和註釋必須準確終止，檔名位置欄位不授予截斷許可權，全部基頭及擴充套件頭 CRC-32 均須透過。每個記錄最多 256 個擴充套件塊，長度為 16 位。檔案不透明屬性須驗證並納入後設資料身份，不應用或執行。準確的 `60 ea 00 00` 終止必須位於物理源結尾，不推測 SFX 字首、填充或恢復尾部。

後設資料讀取最多 64 MiB，物理條目最多 100000，單個原始名稱最多 4096 位元組，總名稱最多 16 MiB，呼叫者更小限額仍生效。後續失敗不能釋出部分索引。SHA-256 覆蓋完整物理後設資料及終止，包括未解釋的註釋、修飾位元組和屬性。輸出前，`Reader::open` 重新掃描並核對摘要、全部記錄及物理長度。源故障保持終止，不能成為格式無效猜測。Unix 主機時間只使用可選主機日曆投影，缺失投影為零，回撥錯誤則終止。

成員配置准入所需版本至 11，主機為 DOS、Unix、OS2、Win95、WinNT，支援未加密二進位制及舊文字的方法 0–4，以及空 Store 目錄。不支援方法、未來版本、特殊型別、Unix 特殊模式、加密、續卷和章節欄位保持顯式且不能解碼。主頭的分卷、保護、安全、雙名、加密和章節配置，以及雙名檔案佈局未准入。模式和屬性不授予許可權或特殊檔案建立能力。舊文字按歸檔尺寸及 CRC 對應的位元組交付，與 7-Zip 一致；原生 Win32 ARJ 對該文字配置會把 LF 擴充套件為 CRLF，xdzip 不做依賴宿主的換行轉換。

一個讀取例項累計實際輸入上限為 24 GiB，包括本次完整後設資料掃描，解碼輸出上限為 24 GiB，工作上限為 96 GiB。向有狀態解碼器借出剩餘工作前，先為宣告輸出預留 CRC 位步驟成本。成功成員準確累計該預留和實際構造、模型及 Store 工作，失敗即終止且不退還。呼叫者 sink 計量包含構造，不能從初始化之後才開始計費。讀取始終最多 8192 位元組，核對快照及物理索引，載荷、CRC、sink、取消或預算錯誤均使例項失效。

<a name="xdzip-容器与主机准入要求"></a>

## 容器與主機准入要求

釋出完整索引前，須驗證 ARJ 主頭與檔案頭、有界首頭佈局、CRC-32、擴充套件頭鏈、準確壓縮跨度，以及零長度終止標記。物理 ID 保留同名記錄，名稱、內碼表、分隔符、目錄、舊文字及二進位制型別、特殊物件和未知方法均須明確投影與載荷准入，識別標記不能授予內容能力。

完整解碼後須透過宣告的檔案 CRC，頭部與可選歸檔安全欄位不等於密碼學認證。密碼、加密方法、分卷、續卷條目、章節、恢復及安全尾部、自解壓包裝均須單獨配置與證據。指令碼、自動命令、外部屬性、鄰接路徑或可執行標記均不授予許可權。主機凍結源、選中提取、累計輸入/工作/輸出預算、私有暫存、取消、舊檔案保護及最終釋出遵循[提取契約](zip-safe-extraction.md)。

樣本生成器僅建立自有二進位制輸入，記錄請求及實際方法，並由原生 ARJ 和 7-Zip 獨立比較完整輸出。原工具回退為 Store 時繼續記錄 Store。只規範化未加密時間戳、不使用但隨時間變化的修飾位元組及對應頭部 CRC，壓縮位元組與內容 CRC 不變。原生空輸入得到 Store 條目，不證明編碼了空壓縮流。產品准入還須按[驗收範圍](../../../developers/qa/README.md)執行實際 runtime、CLI、Qt 及適用候選和佈局自動化。
