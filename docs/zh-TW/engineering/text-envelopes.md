# UU、UUE 與 XXE 文字封裝

[English](../../engineering/text-envelopes.md) | [简体中文](../../zh-CN/engineering/text-envelopes.md) | 繁體中文（台灣）

傳統 UU 欄位與位元順序依據 [NetBSD uuencode(5)](https://man.netbsd.org/uuencode.5)。Base64 模式見 [uuencode(1)](https://man.netbsd.org/uuencode.1) 與 [GNU Sharutils](https://www.gnu.org/software/sharutils/manual/sharutils.html)。XX 字元表為 `+-0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz`，已與 [UUDeview](https://github.com/hannob/uudeview) 的公開編碼器核對。Rust 讀取器依欄位與位元規則獨立編寫；參考 C 實作僅供測試，絕不是執行階段相依套件。

<a name="xdzip-准入配置与边界"></a>

## 准入配置與邊界

接受由 `begin`、一個空格、一至四位八進位模式數字、一個空格及非空原始檔名構成的標頭。標頭模式只驗證語法，絕不還原權限。UU 與 XX 共用此標頭；以完整有效的計數資料列判定實際字元表，空成員也包括用於判定的零計數列。每列第一個六位元值宣告解碼後的位元組數為 0–63，字元數必須恰為 `1 + 4 * ceil(count / 3)`。UU 的零值接受空格或反引號。依高位元優先順序，將四個六位元值解碼為三個位元組，丟棄最後一組未使用的位元組，不要求歷史填補位元為零。零計數列之後必須立即接上完全符合 `end` 的一列；不修復縮短或損壞的列。

`begin-base64` 變體接受 4–76 個字元的普通 Base64 資料列，每列長度為四的倍數，且填補位元須依規範為零。帶填補的列結束資料內容，之後只允許完全符合 `====` 的結尾列；內容可以為空。裸 Base64、MIME 組合、GNU `begin-encoded` 檔名擴充、多段修復、yEnc 和 BinHex 不在此設定範圍內。`.uu` 和 `.uue` 是 UU 候選，`.xxe` 是 XXE 候選；候選副檔名不決定實際字元表。

接受 LF、CRLF，以及最後不帶換行的完整結尾列。成員之前、之間及之後可有長度受限的傳輸文字。看似標頭但格式錯誤或不受支援的列必須報錯，絕不能忽略而隱藏成員。第一個標頭須在前 64 KiB 內開始；每個傳輸列或標頭列最多 8192 位元組。強容器簽章、光碟描述項及有效 TAR 標頭優先於文字候選偵測。須完整驗證才能接受此格式，不能只依賴副檔名或 `begin` 一詞。全由 XX 成員構成的封裝標為 XXE；普通 UU、Base64 與混合成員封裝標為 UU。每個實體成員都保留序列化順序識別碼、原始名稱及實際編碼，包括同名成員。

<a name="xdzip-宿主权限配额与检查"></a>

## 宿主許可權、配額與檢查

後端只接收已授權、可定位的來源及主程式擁有的輸出接收端。標頭檔名須經共用的壓縮檔層級名稱解析、顯示逸出及危險路徑檢查；它不會開啟輸入，也不會授予輸出路徑權限。讀取器不還原權限、不存取外部檔案、不執行命令，也不建立目錄；不提供寫入器、改寫、加密或分割檔案的權限。編碼後的資料內容與結尾範圍構成已知的壓縮大小；資料大小由已驗證的列計算。

中繼資料驗證在共用掃描限制內讀取整個封裝，通常限制為實際來源讀取 64 MiB、100,000 個項目、每個原始檔名 4096 位元組，以及原始名稱和顯示名稱各 16 MiB 的累計預算。僅保留受限的成員範圍，不保留解碼後內容。交付資料前重新掃描，將完整投影索引與主程式的不可變快照比較；隨後保留定位資訊，以便任意選取實體成員，而不必每次重掃先前成員。中繼資料及重複讀取資料列共用私有的 24 GiB 累計輸入上限，交付位元組另有 24 GiB 上限；主程式更嚴格的工作與單檔限制仍然適用。讀取、逐列處理、交付至接收端與獨立取消權杖均採協作式檢查。保留來源失敗的型別，不重試終止性的 `Interrupted` 失敗。任何來源、結構、配額、取消或接收端錯誤都會使已開啟的讀取器失效，重試不會退還工作預算。

檢查只驗證結構與可讀性，**不提供檢查碼或身分驗證**。修改有效的六位元字元可能改變輸出，卻不會造成檢查失敗。暫存與最終發布仍由主程式負責；來源識別檢查只會盡力偵測變更，不構成經驗證的快照。即使只解壓縮選取的成員，也會驗證整個封裝；不支援的標頭擴充或後續格式錯誤的成員不能被靜默跳過。

<a name="xdzip-自动化验收"></a>

## 自動化驗收

專案自有參考輸入涵蓋所有位元組值、空檔案、列尾餘數、UU 零值別名、CRLF、XX 與 Base64、傳輸文字，以及含同名項目的混合成員。固定獨立參考來源的版本，只呼叫其公開編碼器；UU 另以 Python `binascii` 驗證，Base64 則使用獨立標準解碼器。另測試 0–63 的所有計數長度、危險與 Unicode 名稱、精確輸入／名稱／解碼限制、短讀取、具型別的失敗、快照不符、取消、終止後拒絕繼續及既有輸出保持不變。實際執行階段、CLI 和 Qt 工作涵蓋瀏覽、檢查、解壓縮、實體選取、唯讀說明、檢查強度提示和已登錄的候選格式。受影響的雙語、主題、字級版面及主視窗與選單比例使用自動化檢查。參考程式與產生的證據保留在 `build/`；進度和實際結果記錄於交付 issue。
