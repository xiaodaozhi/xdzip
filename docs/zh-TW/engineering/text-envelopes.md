# UU、UUE 與 XXE 文字封裝

[English](../../engineering/text-envelopes.md) | [简体中文](../../zh-CN/engineering/text-envelopes.md) | 繁體中文（台灣）

傳統 UU 欄位與位序依據 [NetBSD uuencode(5)](https://man.netbsd.org/uuencode.5)。Base64 模式參見 [uuencode(1)](https://man.netbsd.org/uuencode.1) 與 [GNU Sharutils](https://www.gnu.org/software/sharutils/manual/sharutils.html)。XX 字母表為 `+-0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz`，已與 [UUDeview](https://github.com/hannob/uudeview) 的公共編碼器核對。Rust 讀取器依據這些欄位與位規則獨立編寫，參考 C 實現僅為測試工具，不成為執行時依賴。

<a name="xdzip-准入配置与边界"></a>

## 准入配置與邊界

接受 `begin`、一個空格、一至四位八進位制許可權、一個空格及非空原始檔名。頭部許可權只驗證語法，不恢復。UU 與 XX 使用相同頭部，根據完整有效的計數正文行識別實際字母表，空成員也以零長度行識別。每行首個六位值宣告 0–63 個解碼位元組，字元數必須恰為 `1 + 4 * ceil(count / 3)`。UU 的零值接受空格或反引號。按高位優先將四個六位值還原為三個位元組，丟棄末組未使用位元組，不要求歷史填充位全為零。零長度行後必須立即出現獨佔一行的 `end`，不修復縮短或損壞的行。

`begin-base64` 變體接受 4–76 字元的普通 Base64 行，每行為四的倍數，填充位必須為零。帶填充的行結束正文，之後只允許獨佔一行的 `====` 結束標記，正文可為空。裸 Base64、MIME 組裝、GNU `begin-encoded` 檔名擴充套件、多段修復、yEnc 和 BinHex 不屬於此配置。`.uu`、`.uue` 是 UU 候選，`.xxe` 是 XXE 候選，字尾不決定實際字母表。

接受 LF、CRLF 和末尾無換行的完整結束標記。成員前、成員間及成員後可有受限的傳輸文字。形似頭部但損壞或不支援的行必須報錯，不能忽略而隱藏成員。首個頭部起點必須在前 64 KiB 內，傳輸與頭部單行最多 8192 位元組。強容器簽名、光碟描述符和有效 TAR 頭部優先於文字候選探測。完整驗證後才准入，不能依賴字尾或單詞 `begin`。全 XX 成員封裝標記為 XXE，普通 UU、Base64 及混合成員封裝標記為 UU。每個物理成員保留序列化順序身份、原始名稱和實際編碼，包括同名成員。

<a name="xdzip-宿主权限配额与检查"></a>

## 宿主許可權、配額與檢查

後端只接收已授權可定址源與宿主接收器。頭部檔名經過共享的歸檔級名稱解析、顯示轉義和危險路徑檢查，不開啟輸入，也不授予輸出路徑。讀取器不恢復許可權、不訪問外部檔案、不執行命令、不建立目錄，不提供建立、修改、加密或分卷許可權。正文與結束標記的編碼區間作為已知壓縮大小，有效行計數用於計算載荷大小。

後設資料階段在共享掃描限額內驗證整個封裝，通常最多實際讀取 64 MiB、100,000 條記錄、單個原始名稱 4096 位元組，原始名稱和顯示名稱各受 16 MiB 累計預算限制。只保留受限成員區間，不保留解碼內容。載荷使用前重新掃描，與宿主不可變快照比較完整投影索引；隨後保留定位資訊，按物理記錄任意選擇，不為每個檔案重掃前序成員。後設資料和重複正文讀取共享私有 24 GiB 累計輸入上限，交付位元組另受 24 GiB 上限，宿主任務和單檔案更嚴格限額繼續生效。在讀取、逐行工作、接收器寫入及獨立取消令牌處協作檢查。保留源介面卡的型別化錯誤，不重試已經終止的 `Interrupted` 失敗。任何源、結構、配額、取消或接收器錯誤都使目前讀取器終止，重試不返還預算。

檢查只驗證結構與可讀性，**不提供校驗和或認證**。修改有效六位字元可能改變輸出而不觸發檢查失敗。暫存與最終提交仍由宿主負責，源身份檢查盡力發現變化，不構成已認證快照。即使只提取選中成員，也驗證整個封裝；不支援的頭部擴充套件或後續損壞成員不能被靜默跳過。

<a name="xdzip-自动化验收"></a>

## 自動化驗收

自有參考輸入覆蓋全部位元組值、空檔案、行尾餘數、UU 零值別名、CRLF、XX、Base64、傳輸文字，以及包含同名記錄的混合成員。固定獨立參考原始碼版本，只呼叫公共編碼器；UU 另用 Python `binascii` 核對，Base64 用獨立標準解碼器核對。補充覆蓋 0–63 的所有行計數、危險和 Unicode 名稱、精確輸入/名稱/解碼預算、短讀取、型別化錯誤、快照不一致、取消、終止後拒絕繼續，以及已有輸出保持不變。實際 runtime、CLI 和 Qt 任務覆蓋瀏覽、檢查、提取、物理選擇、只讀說明、檢查強度提示和登記候選。受影響雙語、主題、字號佈局及主視窗與選單比例透過自動化檢查。參考程式和生成證據保留在 `build/`，進展與實際結果記錄在交付 issue。
