# 普通 Brotli 流契約

[English](../../engineering/brotli-streams.md) | [简体中文](../../zh-CN/engineering/brotli-streams.md) | 繁體中文（台灣） | [日本語](../../ja-JP/engineering/brotli-streams.md) | [한국어](../../ko-KR/engineering/brotli-streams.md) | [Français](../../fr-FR/engineering/brotli-streams.md) | [Deutsch](../../de-DE/engineering/brotli-streams.md) | [Español](../../es-ES/engineering/brotli-streams.md) | [Português (Brasil)](../../pt-BR/engineering/brotli-streams.md) | [Русский](../../ru-RU/engineering/brotli-streams.md)

`xdzip-compression::BrotliReader` 獨立解碼單一普通的 RFC 7932 Brotli 串流。它只接收呼叫端持有的 `Read` 能力及允許的壓縮範圍，未持有檔名、檔案系統、網路、程序或發佈輸出的權限。產品透過[格式登記](format-registry.md)接入 Brotli（`.br`）及 TAR.BR（`.tar.br`），可瀏覽、預覽、檢查及解壓選取項目，並沿用共用的來源、任務、配額、暫存和提交規則。符合條件的現有 TAR.BR 可透過寫入標準未壓縮中繼區塊來修改。這兩種格式均不支援新建或分卷。詳見[改寫帶外層壓縮的 TAR](single-file-streams.md#xdzip-rewriting-compressed-tar-archives)。

<a name="xdzip-数据范围"></a>

## 資料範圍

讀取器接受標準 10–24 位視窗、壓縮/未壓縮/後設資料元塊、簡單和複雜規範字首碼、連續重複碼長、三類塊切換、四類字面量上下文、零遊程和逆 MTF 上下文表，以及顯式、近期、直接、字尾距離和重疊歷史複製。詞典複製接受 4–24 位元組原始詞和全部 121 種位元組變換，包括產生零位元組的變換。近期距離跨元塊保留，僅合格的歷史回溯更新快取。未壓縮、詞典和歷史複製位元組都更新字面量上下文。

依據 [RFC 7932](https://www.rfc-editor.org/rfc/rfc7932.txt)，SHA-256 為 `394abd1879e016f4eac89512c2acaf92f7b2d67feb8ab58b6b118c213be07146`。已確認的[勘誤 5948](https://www.rfc-editor.org/errata/eid5948)修正 3.5 節的文字筆誤。[RFC 9841](https://www.rfc-editor.org/rfc/rfc9841.html)新增共享詞典、大視窗和單獨容器，不在普通流範圍內。保留的擴展視窗模式返回不支援，不發現或下載外部詞典。

一個流必須以合法零填充結束，並精確消費已准入位元組跨度。非規範長度、後設資料保留位、無效/過滿/不完整碼樹、重複符號、上下文表或型別缺口、無效距離/變換、超出元塊輸出都會失敗。拒絕拼接、額外尾位元組和截斷。Brotli 沒有內容校驗和、完整流解碼大小宣告、加密、成員路徑或時間欄位。成功只證明准入結構、宣告的元塊大小和可讀性，仍能形成合法流的位元組變動無法被識別為損壞。

<a name="xdzip-产品识别与呈现"></a>

## 產品識別與呈現

Brotli 沒有固定魔數，強源簽名、有效普通 TAR 後設資料和 ZIP/SFX 識別保持優先。剩餘無魔數路徑先用有界 Brotli 字首提出普通流或 TAR 組合候選，完整後設資料掃描驗證整個流後才釋出格式和條目。普通候選無效時可以繼續既有 LZMA Alone 候選。解碼後識別到的 TAR 頭具有約束力，TAR 解析失敗不能轉成普通檔案或 LZMA 成功。壓縮位元組中未經驗證的原始 TAR 標記，僅能透過完整合法的 Brotli 准入消歧；猜測無效時保留原 TAR 失敗。源、取消和資源錯誤直接終止。

Brotli/LZMA 候選探測及重複後設資料讀取共用一份 24 GiB 實際讀取預算，候選之間不退還。其他強格式和文字封裝識別保留各自既定邊界。接受單位元組的空 Brotli 流，空物理檔案仍無效。字尾不能驗證候選，完整驗證後，同過濾器的 `.br` 或 `.tar.br` 提示僅消歧至少 1024 位元組的全零輸出，其他提示保留空 TAR 預設值，真實 TAR 頭仍優先於普通流字尾。

普通 Brotli 顯示一個普通虛擬檔案，名稱來自安全的主機基名，解碼大小已知，壓縮大小為完整物理長度。TAR.BR 保留 TAR 物理條目身份，子項壓縮大小未知。兩者都顯示實際 Brotli 方法及結構檢查提示，不承諾校驗和。複用通用歸檔圖示，既有 `application/x-brotli` MIME 宣告提供普通檔案管理器候選。

<a name="xdzip-资源与控制"></a>

## 資源與控制

分配歷史前須准入 `(1 << window_bits) + 2 MiB`。後一項保守覆蓋有界字首符號、塊/上下文向量、輸入緩衝和固定狀態，每個宣告的數量也獨立受限。每類最多 256 個塊型別或上下文樹，字面量表最多 16384 項，距離表 1024 項，字首字母表最多 704 個符號。靜態標準資料不授予外部 I/O。

壓縮輸入和累計輸出各有 24 GiB 硬上限，呼叫者只能收緊。實際位讀取、字首構建、符號/重複展開、上下文 MTF 移動和輸出消費同一份累計工作預算，最多 96 GiB 工作單位，失敗不退還。元塊輸出宣告在解碼前准入，不能擴大呼叫者配額。每次讀取最多返回 8192 個解碼位元組。`with_poll` 按有界工作間隔呼叫不持有任何權限的協作控制回呼，頭部和零輸出計算也覆蓋，因此取消不依賴繼續讀取源位元組。回撥、源和配額錯誤都是終止錯誤。僅重試不帶額外錯誤物件的中斷讀取，型別化中斷保留原錯誤物件，不被便利方法自動重試。

呼叫者必須讀到 EOF，並在成功前私有保留輸出。後續失敗使先前資料塊整體無效，原語不釋出檔案，失敗讀取器不能恢復使用。協作控制不能中斷阻塞的底層系統讀取，凍結源和最終提交由主機負責。

<a name="xdzip-标准数据与验证"></a>

## 標準資料與驗證

靜態詞典和三張上下文表直接從固定 RFC 提取，核對全部規範長度與 CRC，同時驗證詞長位深和變換編號。[資料來源與許可](../../../third_party/brotli-rfc7932/README.md)僅覆蓋這些標準常量，不連結 Brotli 參考實現。原始碼和分發材料保留 IETF 修訂 BSD 宣告，桌面與 CLI 的宣告收集入口獨立於 Cargo 依賴和參考執行時收集該材料。

[專案構造樣本](../../../tests/fixtures/brotli/README.md)經編碼或獨立構造後，由固定作者解碼器逐位元組核對，覆蓋等級、視窗、實際影響輸出的上下文、塊切換、距離引數、全部標準變換、後設資料及未壓縮塊。精確配額、截斷、填充、短輸入、型別化錯誤、工作輪詢和確定性變異補充互操作樣本。參考工具僅在 `build/toolchain/`，生成證據僅在 `build/` 或 CI。[驗收要求](../../../developers/qa/acceptance.md)中的 `FORMAT-BROTLI` 另行約束產品接入，原語測試不代替產品驗收。
