# TAR/GZIP 實作契約

[English](../../engineering/tar-gzip.md) | [简体中文](../../zh-CN/engineering/tar-gzip.md) | 繁體中文（台灣）

本契約定義 TAR／TAR.GZ 的瀏覽、建立與安全解壓縮邊界。平台結果與人工驗收記錄在 issue 或 CI 成品中。此流程沿用[安全解壓縮](zip-safe-extraction.md)與 [ZIP 建立](zip-creation.md)的輸入授權、暫存、衝突、取消及整個壓縮檔的提交方式。

<a name="xdzip-范围与能力"></a>

## 範圍與能力

支援 TAR 和 TAR.GZ 的瀏覽、建立與安全解壓縮。TAR 是容器，GZIP 是壓縮過濾器；讀取時依內容偵測，而非依副檔名選擇後端。ZIP 行為保持相容。目前不啟用巢狀自動展開、加密或分割 TAR。一般單檔 GZIP 使用獨立的[串流契約](single-file-streams.md)。

TAR 標頭、數值、PAX、串流編碼與改寫由獨立 Rust 記錄層實作；GZIP 封裝、CRC-32 及 Deflate 的 LZ77／Huffman 由共用的 `xdzip-compression` 實作。`tar` 和 `flate2` 僅作為開發測試參考，不進入這些 crate 的正式產品相依套件閉包。規格、來源及限制見[獨立格式契約](independent-rust-codecs.md)。

TAR 接受一般檔案與目錄，並解析 PAX 路徑及 GNU 長名稱。符號連結、硬連結、裝置、FIFO、稀疏檔案和未知類型不能解壓縮。所有輸出名稱仍須通過 PortablePath 和主程式的衝突預檢；格式函式庫不取得檔案路徑或解壓縮權限。不還原目錄權限、擁有者或特殊模式。日期僅作為顯示用中繼資料，不保證還原。

<a name="xdzip-有界流式处理"></a>

## 有界流式處理

傳統檔名編碼、GNU 長名稱與 PAX UTF-8/BINARY 宣告依[編碼契約](filename-encoding.md)統一解析。只有完成整體掃描後才發布索引；掃描期間項目數與總量未知。中繼資料沿用 100,000 個項目、每個名稱 4,096 位元組及累計名稱預算。串流來源的編碼輸入與解碼工作各最多 24 GiB；每個 GNU／PAX 擴充標頭最多 64 KiB，每個項目最多四個擴充標頭。全域 PAX 只接受沒有檔案語義的 comment 文字，以相容 git archive；依宣告的記錄長度完整檢查後即丟棄，不繼承至項目。全域 path、size、mtime、linkpath、稀疏與未知欄位仍明確拒絕；GNU 長連結與稀疏變體不支援。全域註解也計入每項四個標頭及串流位元組預算，不會讓未完成的局部擴充變成有效。TAR 名稱常見的前置 `./` 會正規化，根目錄標記不作為輸出項目。循序讀取和略過同樣檢查取消與位元組預算；定位不能繞過損壞串流檢查。GZIP 必須讀至 EOF 並驗證 CRC 與 ISIZE；多個成員僅構成同一條連續的 TAR 位元組串流。尾端非零雜訊、截斷與損壞都會失敗；未驗證的部分索引會被拒絕。

TAR.GZ 不提供逐項壓縮大小。高壓縮比准入會比較所選項目的宣告總量與完整凍結來源大小；超過 1000:1 且大於 1 MiB 時仍須明確允許，此許可不會繞過掃描工作或輸出配額。中繼資料預檢不會憑空產生逐項壓縮比。

解壓縮依實體順序處理所選項目；略過未選內容仍會計量且可取消，不承諾隨機讀取。PayloadReader 只能取得來源與主程式的輸出接收端。主程式仍在掃描、解碼和提交邊界驗證來源版本。逐項提交與整體建立失敗的語義依既有安全 I/O 契約執行。

<a name="xdzip-创建与界面"></a>

## 建立與介面

建立視窗啟用既有 TAR 和 TAR.GZ 選項，不改變視窗密度。切換格式時更新副檔名；TAR 停用壓縮等級，兩種 TAR 格式都停用密碼與分割檔案並清空其值。TAR.GZ 使用 GZIP 0／1／6／9 等級。逐項壓縮大小未知時顯示橫線，而非 0 位元組。Rust 依來源名稱統一產生以壓縮檔命名的目標資料夾，並透過受限橋接提供預覽。TAR.GZ 移除完整複合副檔名且不區分大小寫；基底名稱為空時回退至 archive。UI 不另行推導目標；PortablePath 與已授權根目錄會再次驗證。主視窗格式標籤依實際格式與文字寬度調整。TAR 日期以 UTC 顯示，超出現有顯示範圍時保持未知。建立時對 Unicode 或長路徑明確寫入 PAX UTF-8 path，大檔案寫入 PAX size，避免參考讀取器猜測本機編碼。凍結輸入樹、串流輸出、結束 TAR/GZIP、重新掃描並逐項解碼驗證，全部成功後才整體發布。衝突重新命名時保留完整複合副檔名。

<a name="xdzip-验证与限制"></a>

## 驗證與限制

驗證須涵蓋與系統 tar／Python tarfile 雙向互通、長路徑、Unicode、空目錄、重複項、PAX/GNU、特殊項目、路徑逃逸、截斷、CRC、資源限制、取消及既有檔案保護。Qt 實際建立、重新開啟與解壓縮沿用既有工作和衝突視窗。實際證據只產生於 build/ 或 CI 成品。

依[通用驗證方法](../../../developers/qa/README.md)選擇受影響的桌面操作與無障礙功能重新驗證；原生自動化與離螢幕檢查不能取代人工檢查。實際結果與限制記錄於對應 issue。既有桌面驗收見 [WP-12 #5](https://github.com/xiaodaozhi/xdzip/issues/5)；單次權限或環境阻礙不保留在此契約中。`v0.1.0` 的歷史發行授權審查見 [#4](https://github.com/xiaodaozhi/xdzip/issues/4) 和 [#53](https://github.com/xiaodaozhi/xdzip/issues/53)；後續候選版本需要新的發行 issue。

CLI 建立入口接受 .tgz 作為 .tar.gz 的同格式別名，使用相同的 GZIP 編碼、驗證與提交。一般非 TAR 的 GZIP 由獨立的單檔編解碼器處理。
