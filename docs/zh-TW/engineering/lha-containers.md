# LHA 資料與演算法契約

[English](../../engineering/lha-containers.md) | [简体中文](../../zh-CN/engineering/lha-containers.md) | 繁體中文 | [日本語](../../ja-JP/engineering/lha-containers.md) | [한국어](../../ko-KR/engineering/lha-containers.md) | [Français](../../fr-FR/engineering/lha-containers.md)

LHA/LZH 與歷史 LArc 是按成員順序排列的容器家族。字尾、可識別的方法字串或成功的 Store 成員，都不能證明另一方法可解碼。`xdzip-compression` 原語只接收已准入的壓縮跨度和經容器獨立驗證的解碼大小，沒有檔案系統、程序、檔名或輸出釋出許可權。產品登記和容器准入另按下述條件驗收。

<a name="xdzip-容器结构要求"></a>

## 容器結構要求

`xdzip-codec-lha::inspect` 實現下述 0、1、2、3 級結構，`LhaCodec` 投影物理條目，`Reader` 獨立於 Qt 執行有界載荷解碼。runtime、CLI 和 Qt 提供 `LZH` 格式，`.lha`、`.lzh` 作為開啟及檔案關聯候選。字尾或方法族標記只提出候選，完整後設資料透過後才釋出。有效 TAR、ZIP、光碟和自解壓歸檔的強識別仍優先，只有未經驗證的原始 TAR 標記才可由完整 LHA 驗證消歧。建立支援 LH5 1/6/9 壓縮等級及第 2 級標頭，符合條件的第 2 級壓縮檔可以修改。後設資料讀取最多 64 MiB，物理記錄最多 100000 條，單成員擴充套件最多 256 條，1、3 級累計頭部最多 1 MiB，呼叫者的名稱及條目限制仍有效。0 級缺少 CRC 時顯式表示，不把未知系統基頭尾部、擴充套件型別或頭級別解釋為普通受支援資料。

每條物理成員由頭部及其精確壓縮區間構成，零終止位元組結束歸檔。多餘尾部、缺少結束標記、越界區間和後續損壞成員，都不能釋出部分索引。0、1 級保留基頭位元組和校驗及 DOS 形狀時間；1 級跳過大小包含擴充套件頭鏈，載荷准入前必須減去其精確總長度；2 級小端頭部總長限制全部擴充套件，時間使用 Unix 秒。算術、分配和跳轉前驗證欄位及擴充套件連結。宣告的擴充套件頭 CRC 在其自身 CRC 欄位置零後計算，與載荷 CRC 分開。擴充套件和註釋不授予鄰接檔案、許可權或執行能力。

3 級在偏移 0 儲存固定為 4 的小端長度欄位寬度，基頭為 32 位元組，偏移 24 儲存頭部總長，偏移 28 儲存首個 32 位擴充套件大小，每個擴充套件以 32 位下一擴充套件大小結束。壓縮及原始檔案大小仍為 32 位，時間為 Unix 秒，寬頭部不自動授予 64 位檔案大小。分配前以 1 MiB 准入總長，擴充套件最多 256 條，拒絕不足的最小大小、溢位或越出頭部的連結及額外尾位元組。欄位依據原作者[3 級頭部註釋](https://github.com/jca02266/lha/blob/16619b066b189ef289bb8b07b37d1c38d550da99/src/header.c)，Git blob `df8ae5e3f9dece45325d499cf63c34fc2bb0ec99`。其 README 提醒歷史 3 級規範尚未固定，目前常見擴充套件由 jLHA、Lhasa 分別演示，不聲稱覆蓋全部歷史擴充套件。

2 級頭長若恰為 256 位元組的倍數，首位元組零會與終止標記衝突。原作者文件規定，此時可補且僅補一個零位元組，並計入總長和頭部 CRC；其他頭部尾位元組及非零填充應拒絕。獨立編碼的 222 位元組檔名驗證該規則，不為了參考工具的舊路徑上限而截短成員名稱。

歸檔名稱解析獨立於輸出授權，保留物理順序、同名項及原始名稱。先解析舊編碼，再解釋反斜槓分隔符，避免多位元組尾位元組憑空生成目錄。擴充套件檔名和目錄名有明確唯一性和組合規則，歧義重複宣告應失敗，不挑選方便的拼寫。目錄、特殊物件和連結不能作為普通檔案處理，原始 Unix 模式僅為後設資料，不恢復許可權。凍結源、可移植路徑預檢、選中條目身份、私有暫存和最終釋出仍由主機負責。

原始名稱保留目錄欄位、其中的 `0xff` 分隔符、檔名欄位及兩者準確邊界。整包有界舊編碼檢測分別取樣完整目錄分量和檔名，分隔位元組不能汙染檢測，也不能跨欄位拼成多位元組字元。逐欄位嚴格解碼後，才規範化實際解碼所得的反斜槓並組合 `/` 分隔符；分別檢查各分量和最終名稱的異常路徑。原始名稱、有效名稱和轉義顯示保留共享限額與取消點。目錄展開、選中提取、預覽和匯出使用同一凍結有效名稱。未知方法、無法解碼或異常名稱、連結、特殊型別及相互矛盾的目錄宣告保持可見並標記警告，不能輸出載荷，Unix 模式不授予許可權恢復能力。

產品准入 Store（`-lh0-`、`-lz4-`）、LH1–LH7、LZS 和 LZ5，PMA 方法尚未准入產品。條目方法編號只在 LZH 內有效，不等於 ZIP 方法編號。檢查型別為 `format_declared_checks`：存在的頭部及載荷 CRC 必須透過，但沒有 CRC 的古老 0 級成員只提供結構、尺寸與可讀性檢查。LH2 的有限變體准入必須有載荷 CRC。暫不支援密碼、分卷或修復配置。單個零位元組表示空歸檔，後續記錄損壞不能得到成功的部分清單。開啟時掃描名稱和結構，檢查或提取時才實際解碼並驗證宣告校驗。

Store 標識 `-lh0-` 和 `-lz4-` 要求壓縮及解碼大小相等，歷史 `-lz4-` 與現代 LZ4 無關，`-lhd-` 表示目錄。LH1–LH3、PMarc、擴充套件頭、密碼和分卷均須有各自驗證範圍與獨立樣本，不能由字尾或通用 Huffman/LZW 實現自動獲得。未知方法須與可解碼普通檔案區分，容器結構有效不代表載荷內容有效。

<a name="xdzip-静态-lh4lh7-原语"></a>

## 靜態 LH4–LH7 原語

`LzhReader` 處理高位在先、每塊 1–65535 條字面量或匹配命令的位流。LH4、LH5 的位置字母表均為 14，樹數量欄位 4 位；LH6 為 16 和 5 位，LH7 為 17 和 5 位。四種字典地址位數分別為 12、13、15、16。字典容量與可編碼的位置字母表不同，超過字典容量的距離必須失敗。

19 符號碼長樹描述 510 符號的字面量/長度樹，兩類數量欄位分別為 5 位、9 位。短樹碼長由 3 位及有界一元擴充套件表示，長度樹接受規定的三種零遊程。數量為零時選擇已檢查範圍的單符號，不再讀取符號位。普通規範碼樹須完整、非空、不過滿，深度不超過 16。0–255 為字面量，256–509 為 3–256 位元組匹配；位置零表示距離一，其他位置使用二的冪字首及低位。重疊複製和跨塊歷史保持連續。

初始字典按原始普通 LHa 行為填充空格，不回退到全零的損壞歸檔修復模式。宣告的解碼大小須精確結束於命令和塊邊界，讀取器須消費整個壓縮位元組跨度；忽略最後位元組未用位，但拒絕額外完整位元組、截斷、零命令數和輸出超限。空解碼成員要求空壓縮跨度，CRC-16 由容器負責驗證。

<a name="xdzip-lh1lh3-原语与-lh2-变体"></a>

## LH1–LH3 原語與 LH2 變體

`LhDynamicReader` 實現 LH1 的 314 符號動態模型、4096 位元組字典、3–60 位元組匹配和固定規範碼錶示的減一距離高位，其低六位直接儲存。LH2 使用 286 個初始符號，285 加 8 位擴充套件表示較長匹配，字典 8192 位元組，位置字母表在跨過每個 64 位元組輸出邊界後增長，超範圍長度應失敗。兩者保留空格歷史和精確大小、跨度。`LzhReader` 另接受 LH3 的逐塊 286 符號樹、可選傳入或固定的 128 符號位置樹、前三碼長單符號哨兵及相同的 8 位長度擴充套件，拒絕零命令塊、無效哨兵和不完整或過滿碼樹。

通用兄弟性質更新獨立表達為穩定節點身份、顯式排序及子樹交換。重建時正葉權重向上折半，保持目前葉順序，用兩個有序佇列合併，並從合併結果取得新根，不依賴增長前的根身份，實際比較、交換、重建及初始化都扣工作量。理論依據為 [Vitter 對 FGK 的分析](https://www.ittc.ku.edu/~jsv/Papers/Vit87.jacm.pdf)第 2 節，資料專用字母表、固定位置和閾值補充參考固定 [dhuf.c](https://github.com/jca02266/lha/blob/16619b066b189ef289bb8b07b37d1c38d550da99/src/dhuf.c)，Git blob `bcb08bdccf6c6396938e3b2d9b6b032a991aa26e`，及 [shuf.c](https://github.com/jca02266/lha/blob/16619b066b189ef289bb8b07b37d1c38d550da99/src/shuf.c)，blob `2c18ed6a909cfa7fd1d591af1e7f0bd90e269fd7`。這是對前述原始碼觀察範圍的補充，不移植其實現結構。

原始 Unix LH2 不更新初始單符號位置葉的權重，位置更新次數單獨累計；jLHA 透過通用模型更新該葉。兩者在相同 `-lh2-` 標識下產生不相容的真實位流。原語提供顯式 `Lh2Variant` 選擇入口，通用方法 2 構造器預設使用 jLHA 的計數約定。容器要求 LH2 宣告 CRC，把兩個有限候選完整解碼至不輸出的接收端。結構或 CRC 無效可排除候選，源、取消、預算及主機錯誤立即終止，所有探測保留實際輸入、解碼及輔助工作消耗。成功候選的大小與 SHA-256 摘要須一致，否則為歧義、不支援；唯一有效或完全一致的結果再解碼輸出，並複核選定摘要和 CRC。摘要僅約束探測與交付位元組，不證明歸檔真實性；不釋出候選資料，也不將其變為輸出抵扣額度。

原始 C 檔案保持未修改並固定摘要，僅在 `build/toolchain/` 透過專案自有有界主機工具編譯為測試參考。邊界樣本僅在參考構建中呼叫原始編碼及增長狀態，不移植到產品；兩種變體都用實際變化的距離跨過字元與位置模型重建閾值。一份自有 LH2 流透過公開通用碼樹 API 按原始單符號約定生成，並由原作者解碼器完整讀取。原始 Unix 不能正確讀取 jLHA 的長資料及空格配置等差異單獨記錄，不修復或計為透過。

<a name="xdzip-容器创建与发布"></a>

## 容器建立與釋出

建立採用 `lh5` 方法、1/6/9 級及 2 級頭部，接受 `.lzh`、`.lha`，桌面預設字尾為 `.lzh`。主機建立方法編號為 259，與 LZH 條目內的方法編號 5 區分，建立作業不支援 Store、密碼、固實分組或分卷。輸入最多 100000 條凍結記錄，名稱合計 16 MiB，實際讀取最多 24 GiB，頭部合計最多 64 MiB。單成員原始及壓縮長度都須能由無符號 32 位表示，Unix 修改秒數也須能由無符號 32 位表示，不截斷。輸出最多 24 GiB，普通檔案跨成員共用累計原始編碼工作賬本。CRC 只處理實際准入源位元組，受輸入及頭部上限約束；讀取預算完全耗盡時，可在最終 EOF 探測前保守失敗。

只接受可移植普通檔案和目錄。目錄用 `-lhd-`、零尺寸及零載荷 CRC，普通檔案即使很小或不可壓縮而膨脹，仍使用 LH5。名稱以 UTF-8 分別放入檔名擴充套件和 `0xff` 分隔的目錄擴充套件，始終輸出共同頭部 CRC 與逐檔案 CRC-16。2 級頭部恰好對齊時保留規定的單個填充位元組。驗證時讀取已驗證目錄可成功返回，但不輸出位元組，也不授予目錄操作或許可權恢復能力。

此處 UTF-8 是未宣告的名稱約定，不是通用 Unicode 標記。自有 jLHA 公共 API 測試宿主顯式選擇 UTF-8，並把完整路徑與載荷分別核對。舊 Windows 讀取器可能使用 OEM 內碼表，即使所有位元組和 CRC 透過，也顯示不同名稱。所查原作者 7-Zip [LZH 名稱投影](https://github.com/ip7z/7zip/blob/main/CPP/7zip/Archive/LzhHandler.cpp)，Git blob `1b6e3b9d9905abe28b53e39b1267465fe2fc7f03`，選擇 `CP_OEMCP`；該原始碼觀察解釋參考工具限制，不把其實現加入產品，不宣稱名稱普遍互通。

編碼器只接收凍結源索引和空的私有可隨機寫暫存輸出。先驗證全部記錄邊界，再流式處理內容及 CRC，完成原始編碼後回填壓縮尺寸和 CRC，並在下一成員前恢復順序寫入終點。不支援隨機寫或任何源、輸出、預算及取消失敗都會終止，不寫成功終止標記；最終路徑和提交許可權不進入編碼器。主機複核把 LHA 凍結有效名稱與輸入名稱比較，其他容器保留原始名稱比較，並在凍結源複核和原子釋出前實際解碼全部內容。驗證失敗、源變化或取消保留舊目標並清理私有暫存。

`scripts/check-lzh-creation.py` 獨立解析並驗證生成的 2 級欄位、邊界、UTF-8 名稱、時間戳及兩類 CRC，再以固定身份 jLHA、Lhasa、7-Zip 比較完整多成員內容，分別記錄目錄、名稱與載荷結果。runtime、CLI、Qt 的建立、重開、檢查和提取另由自動化覆蓋，原始編碼往返不能代替這些入口。

現有 LHA/LZH 壓縮檔的每個項目都必須使用第 2 級標頭、宣告內容 CRC，且符合名稱、記錄及壓縮資料要求，才可修改。保留項目的壓縮資料會原樣複製。更改路徑時，會保留原始方法、大小、時間戳記、屬性及允許的非名稱擴充，重新產生 UTF-8 名稱擴充並更新通用標頭 CRC。新檔案使用 LH5 寫入器。第 0、1、3 級標頭可依讀取設定檔瀏覽。詳見[壓縮檔修改規則](archive-transfers.md)。

<a name="xdzip-lh5-原始编码器"></a>

## LH5 原始編碼器

`LzhWriter` 是有界原始編碼器，獨立於產品建立准入。它跨 32768 位元組輸入塊保留 8192 位元組歷史，透過共享四位元組雜湊鏈輸出真實的 4–256 位元組匹配。1、6、9 級分別搜尋 1、16、64 個候選，距離以 LH5 字典上限約束，不沿用匹配器更寬的容量。輸出完整規範碼樹：C 符號 0、1 碼長 8，其餘 508 個碼長 9，實際使用的兩個碼長符號各佔 1 位，位置符號 0、1 碼長 3，其餘十二個碼長 4。這是明確有界的固定樹策略，不宣稱最優熵編碼，也不回退 Store。命令數量準確，中間塊不按位元組對齊，僅最終不足一位元組的部分補零，空輸入不輸出壓縮位元組。

實際雜湊鏈、輸入與歷史、最多 32768 個四位元組命令、輸出緩衝和控制狀態按 1 MiB 准入。實際雜湊初始化、播種、查詢、候選比較、複製、位操作和輸出嘗試消耗累計 96 GiB 工作賬本，輸入與壓縮位元組分別最多 24 GiB。每最多 8192 工作單位回撥，單次寫入最多接收 8192 位元組；`finish_with_work()` 可把剩餘賬本交給後續成員。短寫和無附加錯誤的中斷重試不重複位元組，型別化中斷、取消、輸出及資源失敗終止該例項，不暴露輸出路徑或釋出許可權。非最終 `flush()` 保留連續位流，成功結束仍須呼叫 `finish()`。

顯式執行 `scripts/check-lzh-writer.py` 會匯出原始編碼器結果，以獨立構造的測試專用 0 級頭包裝，再用固定身份 jLHA、Lhasa 和 7-Zip 完整比較位元組，包括 7-Zip 的 CRC 測試。每級覆蓋空、單位元組、全部位元組、空格、確定性隨機、長內容和準確視窗重複。這隻證明原語互操作，產品容器寫入、名稱後設資料和主機原子釋出仍須分別驗證。

<a name="xdzip-larc-原语"></a>

## LArc 原語

`LarcReader` 分別選擇 LZS、LZ5。LZS 使用 2048 位元組空格環，初始寫位置 2031，高位在先的字面量標誌，隨後為 8 位字面量，或 11 位絕對位置及減二的 4 位長度，匹配長 2–17。LZ5 使用 4096 位元組環，初始寫位置 4078，每個標誌位元組低位在先處理八條命令，字面量和雙位元組絕對引用按位元組對齊，匹配長 3–18。絕對位置不能解釋為相對距離，兩者均不復用 Stac LZS 結構。

LZ5 初始環依次包含每個位元組重複十三次、遞增位元組、遞減位元組、128 個零和 110 個空格。其餘十八個未寫位置存在不相容的歷史預設值，實際寫入前讀取這些位置應拒絕，不擅自選擇修復變體。源與目標重疊、環繞都保持逐位元組複製語義。忽略最後已消費位元組中的剩餘標誌或位填充，拒絕額外完整位元組。容器仍須檢查宣告的輸出大小和 CRC。

<a name="xdzip-资源失败和验收"></a>

## 資源、失敗和驗收

原語分別限制壓縮及解碼大小為 24 GiB，累計工作為 96 GiB 單位。LH4–LH7 准入字典加 64 KiB，LArc 為字典加 32 KiB，覆蓋歷史初始化標誌、輸入緩衝和控制狀態，呼叫者只能收緊。位欄位、碼樹構造、重複展開、字典初始化及輸出先扣工作量；容器可透過 `work_remaining()` 跨成員及失敗保留同一份實際工作預算。分配前准入記憶體及欄位數量，每次讀取最多返回 8192 位元組。

LH3 准入字典加 64 KiB，動態 LH1/LH2 保守准入 192 KiB。一個載荷例項跨成員、重複請求和 LH2 探測，共用 24 GiB 實際輸入、24 GiB 解碼工作、96 GiB 演算法工作硬預算，後設資料重掃也計入輸入。LH2 另准入最多 24 GiB 實際 SHA 壓縮塊位元組，包含結束填充，並透過輔助工作介面上報。丟棄候選以 `charge_skipped` 扣解碼工作，最終交付仍普通寫入，不授予預付額度。任何載荷前比較完整源和掃描快照，最終失敗使例項終止。

協作回撥覆蓋無需新源讀取的有界計算，僅重試無附加錯誤的 `Interrupted`，型別化中斷保留原錯誤物件並終止。源、預算、取消、損壞和接收端錯誤不授予回退或繼續使用部分狀態的許可權。呼叫者須讀到 EOF，驗證宣告的載荷 CRC，並在成功前私有保留輸出。CRC-16 用於意外損壞檢測，不能證明真實性或密碼正確，反射多項式為 `0xa001`，初始值零，無最終異或。

[驗收要求](../../../developers/qa/acceptance.md)中的 `FORMAT-LHA` 分別約束原語互操作、容器和實際 runtime/CLI/Qt 接入。原語測試不能證明產品入口、寫入、密碼、分卷、其他平臺或發行許可。參考結果與工作包進度記錄在 issue，生成證據只放 `build/` 或 CI。
