# PMA 容器與 PMarc 方法

[English](../../engineering/pma-streams.md) | [简体中文](../../zh-CN/engineering/pma-streams.md) | 繁體中文（台灣）

PMarc 使用類似 LHA 的順序頭部，方法為 `-pm0-`、`-pm1-`、`-pm2-`。它們是不同演算法，不能當成名稱相近的 LH 方法。只讀 PMA 配置准入 0 級頭部的 PM0、PM1、PM2，支援瀏覽、檢查和選中提取。未知方法仍可見，但帶有內容不支援警告。建立、修改、加密、分卷和修復未准入，格式登記保持權威。

<a name="xdzip-来源与参考边界"></a>

## 來源與參考邊界

美濃吉彥的[原作者軟體頁](https://www.asahi-net.or.jp/~am9y-mn/fswlist.htm)、[PMarc 2.00 原手冊](https://www.asahi-net.or.jp/~am9y-mn/doc/pmarc2.doc)及[原工具包](https://www.asahi-net.or.jp/~am9y-mn/arc/pmarc200.pma)說明 PM2、二進位及文字模式，以及 CP/M 的 128 位元組檔案記錄。手冊雖然字尾為 `.doc`，實際是 CP932 純文字。工具、文件、編譯器、模擬器及自有輸入身份見[樣本說明](../../../tests/fixtures/pma/README.md)。原工具保留各自條款，不再分發，也不進入產品依賴閉包。

手冊不是完整的壓縮位流規範。有限線格式觀察參考 Simon Howard 的 [PM2 解碼器](https://github.com/fragglet/lhasa/blob/v0.6.0/lib/pm2_decoder.c)，Git blob `b711988f2ac8a21ea4081e06020ecbd3fb83c49c`，以及 [PMA 共同事實](https://github.com/fragglet/lhasa/blob/v0.6.0/lib/pma_common.c)，blob `7433c3b6fcbd742963a7a63a03d21d858e798631`，其許可為 Lhasa 的 ISC。不宣稱嚴格淨室。Rust 使用專案有界位讀取器、共享完整規範字首實現和獨立表達的平面位元組排列，不複製參考實現的連結串列或樹結構；參考演算法原始碼或二進位不編入產品。

PMarc 2.00 原工具執行於按摘要固定、原始碼核驗的 CP/M 模擬環境，全部源和輸出限定在自有測試目錄，顯式使用二進位 I/O。Lhasa 0.6.0 和原 PMext 2.22 的已說明 IBM-PC 移植版分別完整比較輸出位元組。原編碼器跳過零長度輸入，生成空歸檔，不能據此證明編碼了空成員。自編線格式樣本另覆蓋 28 位字面量字首和接受的首位變體。原始碼觀察、生成資料和實際參考比較保留各自來源。

<a name="xdzip-容器要求"></a>

## 容器要求

PMA 頭部與載荷區間須滿足 [LHA](lha-containers.md) 的相同算術、校驗、名稱、同名項、凍結源和特殊物件規則。PM0 為 Store，壓縮及原始尺寸相等，PM1、PM2 不得轉入 LH 解碼器。實際解碼完成後必須驗證存在的載荷 CRC-16，開啟或列出方法不能證明內容有效。

原始 CP/M 歸檔以一個零位元組結束，再用 `0x1a` 補到下一個 128 位元組記錄邊界。准入填充形式必須準確對齊，最多 127 個填充位元組且全部等於該值；未填充容器也可在準確零終止處結束。這是具體結構要求，不允許忽略任意尾部、合成缺失終止符或追加解碼 EOF 位元組。容器填充不屬於成員壓縮區間，凍結源須覆蓋包括填充在內的整個物理檔案。

八位元組候選不能自行釋出格式，須先驗證完整後設資料鏈、準確零終止及可選物理填充，主機才釋出條目。所有弱格式探測共用輸入計量帳本。CP/M 空歸檔透過有界填充識別為 PMA，無法區分的單個零終止仍沿用先前的 LZH 選擇。強容器優先於弱探測，原始 TAR 標記衝突仍須完整驗證容器。源 I/O 故障保持終止，包括主機以型別化錯誤返回的輸入無效值。

載荷輸出前重新比較物理條目 ID、原始及解碼名稱、標記、尺寸和方法。PMA 方法 2 直接進入 PM2，不執行 LHA 的 LH2 變體試解。CRC 失敗、不支援方法和源變化均保留主機私有暫存與舊檔案保護。`.pma` 納入適用平台的 shell、拖入候選，但不宣告專用 MIME 型別，因此不表示新增 Linux PMA 預設關聯。

0 級基頭的 31 位元組長度與校驗和可能恰好組成 GZIP 的 `1f 8b` 或 Unix Z 的 `1f 9d`。如果後續位元組明確構成 `-lh`、`-lz`、`-pm` 家族標記，識別仍須完整准入家族容器，不因偶合的兩位元組流標記提前拒絕。標記中的 `-` 既不是准入的 GZIP 方法 8，也不是有效 Unix Z 標誌。這是有界頭部消歧，不重試已經失敗的解碼載荷；有效流格式和主機錯誤保留通常處理。

<a name="xdzip-pm1-线格式配置"></a>

## PM1 線格式配置

`Pm1Reader` 是 PMA 介面卡複用的原始解碼器。凍結後設資料比較後，PMA 方法 1 直接進入該原語，獨立於 LHA 方法。線格式觀察參考 Lhasa 的 [PM1 實現](https://github.com/fragglet/lhasa/blob/v0.6.0/lib/pm1_decoder.c)，Git blob 為 `bb2937e382c8c8a8f5783b94a96b9b59e2c4e74b`，許可為 ISC。Rust 直接表達固定碼字，不沿用參考的相對偏移壓縮樹，並複用有界平面最近使用排列。不宣稱嚴格淨室，也不引入參考執行時依賴。

五位選擇值指定 32 種固定字面量類別配置之一。類別對應排名基數 0、16、32、64、128、192，低位寬度為 4、4、5、6、6、6。選擇值 17 保留重複的類別 3、4 分支，缺少類別 0、1、5，兩個重複分支均保留觀察到的含義；選擇值 31 不讀取類別位，只允許排名 0–15。每個字面量或複製位元組均更新排列。獨立生成器使用展開的符號配置，不讀取產品碼字表。

命令為顯式歷史複製或 1–216 位元組的字面量塊。較短塊在仍有解碼輸出時隱含後續複製，216 位元組塊則回到顯式命令選擇。宣告的最終字面量可直接結束成員，不讀取虛構複製。複製類別 0、1 編碼長度二，其餘類別編碼 3–244。距離前綴在輸出 64、576、2624 位元組處擴增；類別 3、4、5 的低位分別在 320，832、1088、1600，以及 2880、3136、3648、4672、6720 位元組處加寬。實際距離為偏移加一，必須引用已經輸出的內容，在 16 KiB 環中處理重疊及迴繞，PM2 的初始空格不能授予 PM1 歷史。

字面量與複製長度必須在剩餘宣告輸出之內，完整多餘壓縮位元組拒絕，最終不足一位元組的填充忽略，但缺少位元組絕不補零。歷史參考的 EOF 修復不屬於該配置。記憶體准入為 16 KiB 歷史及輸入、狀態、臨時空間另加 32 KiB，壓縮與解碼硬上限各為 24 GiB，工作硬上限為 96 GiB，呼叫者更小預算仍生效。源讀取、字首比較、排名移動及不讀源的複製均保持協作取消和型別化錯誤終止。

<a name="xdzip-pm2-线格式模型"></a>

## PM2 線格式模型

位流高位在先，首位的兩個值均經獨立驗證，不改變解碼結果。碼錶用五位宣告 1–29 個符號、三位宣告最小碼長。最小碼長零表示常量符號 `count - 1`，否則先用三位元宣告寬度，再依該寬度讀取每個碼長值，零表示該符號不存在，非零表示 `minimum + value - 1`。必須形成完整規範碼樹。最多 29 個葉子，至多 28 層有效深度，`Prefix<29>` 支援該範圍，不增大現有 Brotli、LZH 的 `Canonical = Prefix<17>` 例項。異常數量、過度訂閱、不完整碼樹和過深碼長在使用前失敗。

符號 0–7 指定位元組的最近使用排名，基數依次為 0、8、16、32、64、96、128、192，附加寬度為 3、3、4、5、5、5、6、6 位。初始順序按十六進位為 `20–7f, 00–1f, a0–df, 80–9f, e0–ff`。每個輸出位元組，包括歷史複製，都移動到最前。Rust 查詢和旋轉有界平面排列，實際比較與移動均計量。

符號 8–28 表示複製。類別 0–14 的長度為 2–16，類別 15–20 使用基數 17、25、33、65、129、256，以及附加寬度 3、3、5、6、7、0 位。類別零直接讀取六位偏移，類別 1–19 使用位置表。位置零讀取六個低位，位置 1–7 讀取 `position + 5` 個低位，再加該位數的二次冪基數。類別 20 固定偏移零，實際距離等於偏移加一。歷史為填充空格的 8192 位元組環，重疊和初始歷史引用均逐位元組執行。

需要時，位置表初始含五個三位碼長，在輸出 1024、2048、4096 位元組處分別擴增為六、七、八項。4096 位元組處用顯式位決定是否替換碼錶，隨後讀取八項位置表；從 8192 起每隔 4096 位元組，用顯式位決定是否同時替換兩表。事件在準確輸出位元組處發生，包括複製內部和輸出恰好結束時。原工具邊界樣本包含最終控制欄位，不能省略，也不能以部分輸出成功代替完整解碼。

位置表只有一個在場符號時表示常量；全零表表示位置表不存在，可以始終不使用，包括在最終控制事件，但任何實際需要它的命令都會失敗，不把全零表修復成虛構符號。是否讀取位置表由碼錶選擇決定。最終不足一位元組的填充忽略，但邏輯壓縮位元組必須準確結束，完整多餘位元組拒絕。

<a name="xdzip-限额与失败"></a>

## 限額與失敗

PM2 為 8192 位元組歷史及輸入緩衝、字首表、最近使用狀態和有界臨時空間另加 32 KiB 准入。壓縮及解碼尺寸各最多 24 GiB，演算法工作最多 96 GiB，呼叫者更小預算仍生效。構造、讀表、排列、複製及位操作均計量，`work_remaining()` 可跨成員保留實際工作。單次讀取最多 8192 位元組，即使不再讀取源，也保持協作取消點。

只有無附加錯誤的 `Interrupted` I/O 可重試，型別化中斷保留錯誤載荷並終止。源、格式、取消及預算錯誤會使例項失效，主機必須成功讀到結束、驗證宣告尺寸及 CRC，並在成功前保持輸出私有。名稱、程序、許可權和檔案系統釋出權不進入原始讀取器。原語、完整容器、runtime、CLI、Qt、其他平台和發行許可分別記錄證據。
