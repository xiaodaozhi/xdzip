# 壓縮檔密碼與加密目錄開啟

[English](../../engineering/password-extraction.md) | [简体中文](../../zh-CN/engineering/password-extraction.md) | 繁體中文 | [日本語](../../ja-JP/engineering/password-extraction.md) | [한국어](../../ko-KR/engineering/password-extraction.md) | [Français](../../fr-FR/engineering/password-extraction.md) | [Deutsch](../../de-DE/engineering/password-extraction.md) | [Español](../../es-ES/engineering/password-extraction.md) | [Português (Brasil)](../../pt-BR/engineering/password-extraction.md) | [Русский](../../ru-RU/engineering/password-extraction.md)

本契約補充[安全解壓](zip-safe-extraction.md)，定義密碼、認證和任務互動。格式與檔案安全邏輯仍獨立於 Qt，密碼視窗只提交使用者意圖。實際開發進度與平臺驗證見 [issue #11](https://github.com/xiaodaozhi/xdzip/issues/11)，本頁不儲存執行報告。

<a name="xdzip-能力与格式边界"></a>

## 能力與格式邊界

支援 ZIP／ZIP64 的 WinZip AES-256，AE-1 和 AE-2，實際壓縮方法為 Store 或 Deflate。可以選擇明文、加密及混合條目，空檔案也須驗證認證碼；各檔案密碼可以不同。AES-128／192、傳統 ZipCrypto、其他加密方式仍不支援；受支援分卷使用[統一邏輯輸入](archive-opening.md)，密碼和認證規則不變。檔名、目錄結構和普通 ZIP 後設資料可見，密碼功能不為它們提供加密或真實性保證。

AES 欄位遵循 [WinZip 格式規範](https://www.winzip.com/en/support/aes-encryption/)：標記方法為 99、加密位開啟，唯一的 AES extra 使用 AE vendor、已知版本、256-bit strength 和受支援的實際方法。目前只接受 7 位元組已定義資料，未知擴充套件保持拒絕。AE-1 另外核對解碼內容 CRC，AE-2 的儲存 CRC 必須為零。中央目錄、本地頭、資料描述符的宣告一致性仍獨立檢查，不以認證碼代替結構驗證。

格式介面卡先對照凍結快照的物理記錄身份、原始名稱、型別、大小、方法、加密位和密碼支援標記，再為本次任務記錄完整 flags 與 AES profile，驗證本地頭、中央目錄、描述符與負載範圍的一致性。最初快照不儲存完整 flags／profile，來源變化仍依賴既有身份與版本的盡力檢測，不構成輸入內容的原子快照。本機檔頭或中央目錄中的 ZIP64 大小哨兵值均參與描述符寬度判定。ZIP 容器與 AES 封裝由專案獨立實現，密碼學原語使用[已准入基礎庫](dependencies.md)，不呼叫格式庫的解包功能。

解密器只讀取已經驗證的單條密文範圍，不接收輸出路徑。Store 或共享 Deflate 裸流解碼器核對精確壓縮位元組消費、解碼大小及 AE-1 CRC，密文完整消費後核對 HMAC 認證碼，全部成功才返回成功。空檔案同樣完成認證。密文和解碼資料使用有界緩衝，不將整檔案累積在記憶體；不再構造供第三方 ZIP 庫讀取的私有歸檔檢視。

<a name="xdzip-7zrar-与加密目录"></a>

## 7z、RAR 與加密目錄

7z 與 RAR 沿用相同的宿主解碼接收器、安全輸出、實際配額及錯誤分類。目前產品路由和自研候選邊界見[隔離後端契約](native-codecs.md)及[獨立實現契約](independent-rust-codecs.md)。7z AES-CBC 沒有獨立密碼驗證值時，已識別加密後設資料的解碼/解析失敗、加密內容的尺寸/流終止/CRC 失敗使用 `password_or_integrity`，表示密碼不匹配或加密資料損壞，不冒充確定的 `wrong_password`。外層明文頭校驗失敗仍為容器損壞，來源 I/O、來源改變、資源限額、取消、不支援特性和輸出失敗也不改成密碼錯誤。RAR 沿用已有歷史版本和目前版本密碼邊界；新舊格式、頭部加密、固實和分卷的組合分別驗收。

檔名或目錄加密在後設資料掃描前要求秘密，OpenWithPassword 是唯一攜帶該秘密的開啟命令，密碼容器在入隊前有界並歸零釋放，事件不包含秘密。完整掃描成功前沒有部分可瀏覽索引。成功後會話保留零化容器，已准入任務可克隆一個私有副本以便關閉頁面後繼續；副本不進入快照、日誌或設定。任務解碼器重開時使用同一密碼，隨後條目密碼仍透過獨立提示控制槽響應。

7z 建立可同時設定內容密碼和檔名加密；檔名加密要求非空建立密碼，僅 7z 可設定。ZIP 保持僅內容加密，TAR／TAR.GZ 拒絕加密引數。加密 7z 和所有 RAR 不接納修改。

<a name="xdzip-秘密与控制协议"></a>

## 秘密與控制協議

`extraction::Password` 與建立密碼型別分開。解壓接受原樣 UTF-8，最多 1,024 位元組，允許空值、空格及控制字元，不修剪或套用建立的 1–128 位元組規則；非 UTF-8 原始密碼不由目前文字介面表達。輸入分配容量同樣有界。Rust 所有權容器在 Debug 中固定脫敏，在拒絕、替換、取消或離開作用域時歸零。

密碼由 `Client::respond_password(task, prompt, Password)` 透過獨立控制槽傳入，不進入普通命令佇列。每個提示使用任務內單次有效的 ID，並區分重名與密碼兩種提示；舊 ID、跨型別響應、重複響應、終態或取消後的響應均拒絕。快照只攜帶 `PasswordPrompt { id, name, retry }` 與 `waiting_password` 狀態，不含密碼或密碼摘要。GUI mailbox 對提示名稱繼續計入位元組限額。

第一次需要密碼時暫停目前任務，等待顯式響應；任務內成功使用的密碼可用於後續加密條目。驗證值不匹配或收到明確的 `password_or_integrity` 時清除舊快取、給出新提示，最多每物理條目十次失敗，達到上限保留實際終態錯誤分類，不能把不確定失敗強制改成 `wrong_password`。7z 加密目錄開啟同樣複用現有密碼窗和開啟請求身份，使用者可取消此次開啟。具有獨立認證碼的格式在認證碼不匹配時仍按內容完整性失敗停止，不因此進入密碼重試。兩位元組驗證值也不能排除所有錯誤密碼，最終認證仍為必需條件。

取消和退出不依賴普通佇列剩餘容量，喚醒密碼等待並清空未消費的秘密。內容密碼只在任務生命週期使用，加密目錄密碼限定於開啟會話及其已准入任務；均不寫入設定、事件、日誌、命令列、恢復記錄或測試截圖。Qt 輸入和受控傳輸緩衝在提交、關閉、取消、換提示及退出時清空；Qt、系統輸入法及依賴內部的歷史副本不保證全程序擦除，Rust 容器歸零不作此保證。

<a name="xdzip-输出重试与链接"></a>

## 輸出、重試與連結

普通檔案每次嘗試均使用新的私有暫存檔案。錯誤密碼、認證失敗、流結構錯誤或取消會退出此次暫存的生命週期，嘗試按身份刪除；刪除失敗時最終工作區清理會報告警告並保留恢復材料，不能承諾立即刪除。完整校驗、同步、來源複核和提交許可全部透過後，才按既有策略釋出或替換檔案，未認證暫存不會作為目標檔案釋出。已存在的目標在認證失敗時保持不變。重試產生的實際解碼／寫入計數保留，繼續受單檔案 8 GiB、任務 20 GiB 與源讀取限額約束，不能透過重試重置預算。

ZIP 任務建立解碼器時有 64 MiB 的實際後設資料讀取預算，隨後切換至共享的 20 GiB 輸入讀取預算，本地頭、描述符、密文及所有密碼重試都消費同一計數。該輸入讀取量不同於原始檔長度或已儲存輸出量，超限停止，不在重試時重置。

一個任務可以在後續檔案失敗前已經提交早前驗證透過的檔案；仍不承諾整包事務回滾。重名跳過無需讀取相應檔案內容，不能將跳過記為已認證。取消後已提交項、清理警告和計數不確定性沿用安全解壓契約。

若選中加密符號連結，全部選中連結的負載與依賴圖在任務 Preparing 階段、取得輸出授權及建立派生目錄前完成認證和校驗，再先發布普通檔案、最後釋出連結。路徑、4,096 位元組單連結／4 MiB 合計、64 次跟隨、閉合依賴圖、無寫入父連結及佔用葉子拒絕等策略不放寬。POSIX 執行許可權仍僅恢復已准入的安全位；Windows ZIP 連結和 TAR 連結保持不支援。

<a name="xdzip-界面与验证"></a>

## 介面與驗證

密碼視窗及高保真依據見[密碼互動](../ux/password-extraction.md)。任務等待時自動顯示應用模態視窗，也可從任務視窗重新顯示。錯誤響應使用新 token，清空舊輸入；接受響應後防止重複提交。系統關閉或取消按鈕取消目前任務，Escape 繼續遵循共享的先退出控制元件焦點、再關閉視窗規則。

建立與解壓密碼框透過顯式的介面文案屬性提供輔助名稱，不從輸入內容派生名稱。Qt 6.8.2 會在密碼狀態下隱藏附加名稱，因此桌面程式為這兩個欄位安裝專用輔助介面：僅覆蓋名稱，狀態、文字／值和動作繼續使用 Qt 實現，密碼標記與遮蔽不變。該介面繼承 Qt Quick 的私有類，構建及執行依賴與所用 Qt Quick 版本匹配；升級或替換該庫時須重新構建並驗證介面、密碼保密和三平臺相容。自動介面檢查與系統讀屏人工驗收分別記錄。

驗收要求覆蓋原始 AES 欄位／CRC／描述符／ZIP64、同名物理記錄、正確和錯誤密碼、認證破壞、混合檔案、不同密碼、空密碼／控制字元、重試資源累計、滿佇列、取消／退出喚醒、來源變化、舊目標保護、連結和執行許可權，以及獨立 7-Zip 雙向位元組核對。介面檢查分別覆蓋實際控制器閉環、可訪問動作、雙語多字號、淺深色、DPR 與原生視窗。自動化不等於系統讀屏人工驗收。

RAR 未取得可信密碼驗證值時，加密頭或內容的解碼完整性失敗同樣使用 `password_or_integrity`；已驗證匹配的可信密碼驗證值、明文頭校驗和非密碼類失敗仍保留各自分類。歷史單條密碼及平臺字元投影規則見[RAR 實現依據](rar-format-sources.md)。未知尺寸在解碼和密碼互動之前拒絕，不為不可輸出的條目額外索取秘密。

舊式 RAR 加密條目缺少可可靠區分錯誤密碼與損壞內容的驗證值，因此每個加密條目解碼前分別請求密碼，不能把前一條密碼直接套用到可能使用不同秘密的下一條。RAR5 和受支援的其他格式繼續任務內複用。舊 RAR 的 CRC 或頭部損壞仍作為完整性失敗，不冒充已確認的錯誤密碼。

AES Crypt 0–3 版雖然不加密檔名，仍須開啟密碼，完整密文認證後才釋出精確大小的後設資料。檢查、預覽、匯出透過現有秘密槽保留該會話密碼，不另設逐條目提示。0 版驗證歧義、1–3 版會話金鑰驗證，以及舊版未認證長度和擴充欄位，遵循 [AES Crypt 契約](aescrypt-envelopes.md)。
