# DEB 容器契約

[English](../../engineering/deb-containers.md) | [简体中文](../../zh-CN/engineering/deb-containers.md) | 繁體中文（台灣） | [日本語](../../ja-JP/engineering/deb-containers.md) | [한국어](../../ko-KR/engineering/deb-containers.md) | [Français](../../fr-FR/engineering/deb-containers.md) | [Deutsch](../../de-DE/engineering/deb-containers.md) | [Español](../../es-ES/engineering/deb-containers.md) | [Português (Brasil)](../../pt-BR/engineering/deb-containers.md) | [Русский](../../ru-RU/engineering/deb-containers.md)

套件外層遵循 Debian 的 [deb(5)](https://manpages.debian.org/unstable/dpkg-dev/deb.5.en.html)，一般 ar 欄位遵循 [ar(5)](https://man.netbsd.org/ar.5)。只接受一般的 `!<arch>\n` 版面。每個 60 位元組標頭包含長度受限的 ASCII 名稱、時間、擁有者、模式、大小欄位及必要的結尾標記。驗證十進位欄位、八進位模式、精確的資料範圍、奇數長度成員的換行填補與實際檔案結尾。thin 壓縮檔、歷史格式和長名稱擴充均不支援，也不授予外部檔案存取權。

`debian-binary` 必須排在第一個。接受主版本 2、受限的十進位次版本和受限的額外版本列，拒絕不相容的主版本。control 與 data 成員依此順序出現；中間可以有底線開頭的擴充成員，後續額外成員也會保留。control 接受未壓縮 TAR、GZIP、XZ 或 Zstandard；data 額外接受 BZip2 和 LZMA Alone。每個選取的成員都由實際 TAR 與過濾器實作驗證，不能只憑副檔名判斷。不支援的必要成員設定會明確失敗。Deb822 欄位、中繼資料中列出的檢查碼、簽章和可安裝性均不在容器驗證範圍內。

<a name="xdzip-视图与物理身份"></a>

## 檢視與物理身份

現有目錄模型提供三個互不重疊的前綴。`members/` 包含所有原始 ar 成員，包括版本與壓縮的 TAR 成員；`control/` 和 `data/` 包含對應的 TAR 記錄。這些都是匯出檢視：全部解壓縮會同時匯出原始成員與展開的記錄；只選取 `control/` 或 `data/` 時，僅匯出該檢視。不會安裝套件或執行指令碼。

原始記錄依 ar 順序取得穩定識別碼，接著依各 TAR 的實體記錄順序分配 control 與 data 的識別碼。保留重複項目、原始與解析後名稱、警告及特殊類型旗標與時間戳記的意義；顯示名稱不會成為來源或輸出授權。子項的原始與解析後名稱都加上前綴，不透過正規化消除不安全的路徑元件；加前綴前先標記原本不安全的名稱，避免絕對路徑變成看似安全的相對子項。現有 TAR 解析器會省略無害的空 `.` 根標記。由前綴推導的目錄節點仍是虛擬節點，不會虛構實體項目。連結和特殊物件保留 TAR 的不支援旗標；主程式的路徑檢查仍會拒絕不安全的輸出。開啟中繼資料時，兩個巢狀掃描與其宣告的檢查都須完成，才能發布任何列。

<a name="xdzip-源所有权工作量与载荷复核"></a>

## 源所有權、工作量與載荷複核

內層讀取器只能取得既有授權來源範圍受限的檢視。相對定位與讀取不能超出成員的實體範圍，也不能開啟其他檔案。共用檢視依序存取根來源，並各自維持邏輯游標；不新增 unsafe 或自我參照指標。保留具型別的取消與超限錯誤，一般主程式讀取失敗仍歸類為 I/O 錯誤。遇到借用衝突或不可能的讀取數量時應拒絕，而非造成程式崩潰或重試終止錯誤。

擴充現有受控串流與 TAR 讀取器以接收擁有所有權的來源輸入，同時保留借用式呼叫與相同的初始化及准入規則。依實體順序提出請求時，保留各內層資料讀取器，避免解壓多個記錄時每個檔案都重新掃描 TAR。使用內容前重新解析外層與兩個 TAR 索引，保留這些讀取器，投影完整的新索引並與不可變的上層快照比較。呼叫者提供的名稱、識別碼、類型、方法和大小不能用來替換其他記錄；填補和成員範圍也會再次驗證。讀取器失敗後不能繼續。主程式的來源檢查、暫存、逐檔驗證與最終發布仍具決定權。現有來源識別檢查只能盡力偵測變更；ar 沒有內容檢查碼，這些檢查也不會建立原子性或經驗證的來源快照。解析 ar 擁有者與模式欄位不會授予還原權限的能力。

成員與列數、原始／解析後／顯示名稱的位元組、實體來源範圍和解碼中繼資料的工作量，都按整個套件套用共同限制；control 和 data 不會各自獲得一份新的累計解碼額度。每個準備或交付階段中，共用檢視的實際輸入 I/O 會合併計數。準備與交付分開進行，沿用現有 TAR 索引及重新開啟內容的方式；準備期間快取的位元組不授予額外來源存取權。交付時原始成員匯出與實際內層解碼仍分別計量，且與交付的檔案位元組分開計算。超限時須在下一次讀取、寫入或配置之前拒絕，並在記錄邊界及讀取來源時檢查取消。

此設定為唯讀，不支援密碼、分割檔案、建立套件或改寫。原始 ar 成員的壓縮大小已知，壓縮 TAR 的子記錄則未知。檢查使用 `format_declared_checks`，驗證容器結構、可讀性及已採用的內層過濾器實際宣告的檢查；這不代表套件已通過身分驗證。自動化驗收包含獨立的已知內容參考、所有已採用的過濾器類型、巢狀範圍、重複識別碼、損壞外層及內層檢查、精確限額、來源變更與取消，以及實際 CLI/Qt 瀏覽、檢查和解壓縮。產生的證據保留在 `build/` 或 CI，與平台及發行核准分別記錄。
