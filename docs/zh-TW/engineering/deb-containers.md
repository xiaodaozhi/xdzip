# DEB 容器契約

[English](../../engineering/deb-containers.md) | [简体中文](../../zh-CN/engineering/deb-containers.md) | 繁體中文（台灣）

軟體包外層遵循 Debian 的 [deb(5)](https://manpages.debian.org/unstable/dpkg-dev/deb.5.en.html)，通用 ar 欄位遵循 [ar(5)](https://man.netbsd.org/ar.5)。僅准入普通 `!<arch>\n` 佈局。每個 60 位元組頭包含有界 ASCII 名稱、時間、所有者、模式、尺寸和必需尾標記。驗證十進位制欄位、八進位制模式、精確載荷跨度、奇數成員的換行填充及物理 EOF。thin、歷史佈局和長名稱擴充套件不支援，也不授予外部檔案訪問權。

`debian-binary` 必須在首位。接受主版本 2、有界十進位制次版本及有界附加版本行，拒絕不相容主版本。control 與 data 成員按此順序出現，之間可保留以下劃線開頭的擴充套件，後續額外成員也予以保留。control 接受無壓縮 TAR、GZIP、XZ、Zstandard，data 另接受 BZip2 和獨立 LZMA。須由實際 TAR 與過濾器實現驗證對應成員，不能只憑字尾；不支援的必需成員配置明確失敗。不把 Deb822 欄位、後設資料中列出的摘要、簽名或可安裝性當作容器校驗範圍。

<a name="xdzip-视图与物理身份"></a>

## 檢視與物理身份

現有目錄模型提供三個獨立字首。`members/` 包含全部原始 ar 成員，包括版本和壓縮 TAR；`control/`、`data/` 包含對應 TAR 記錄。這些是匯出檢視，全部提取同時匯出原始成員和展開記錄，選擇 `control/` 或 `data/` 只匯出該檢視。不安裝軟體包，也不執行指令碼。

原始成員按 ar 順序分配穩定身份，之後按各 TAR 的物理記錄順序分配 control 和 data 身份。保留重複記錄、原始與解析名稱、警告和特殊型別標誌及時間含義，顯示名稱不成為源或輸出許可權。子項的原始與解析名稱都新增字首，不透過規範化隱藏不安全元件；加字首之前先標記原本不安全的名稱，絕對路徑不能變成看似安全的相對子項。既有 TAR 解析器省略合法的空 `.` 根標記，由字首推導的目錄節點仍為虛擬節點，不偽造物理記錄。連結和特殊物件保留 TAR 的不支援標誌，宿主路徑檢查繼續拒絕不安全輸出。釋出任何行之前須完整掃描兩個內層並驗證其宣告的校驗。

<a name="xdzip-源所有权工作量与载荷复核"></a>

## 源所有權、工作量與載荷複核

內層讀取器僅獲得既有授權源的有界檢視，相對定位和讀取不能逃出成員物理跨度，也不能開啟其他檔案。共享檢視序列訪問根源，各自保持邏輯位置，不新增 unsafe 或自引用指標。保留具備型別的取消和超限錯誤，普通宿主讀取失敗仍歸為 I/O。借用衝突和不可能的讀取數量明確失敗，不崩潰或重試終止錯誤。

為既有受控流和 TAR 讀取器增加擁有式源輸入，保留借用式呼叫和相同的初始化准入規則。內層載荷讀取器在按物理順序請求期間保持存活，避免逐檔案重掃 TAR。載荷使用前重新解析外層和兩個 TAR 索引，保留對應讀取器，投影完整的新索引並與不可變父快照比較。呼叫者提供的名稱、身份、型別、方法和尺寸不能替換其他記錄，填充與成員跨度也會重新校驗，失敗後不可繼續。宿主源檢查、暫存、逐檔案驗證及最終釋出仍為許可權邊界。既有源身份檢查只提供盡力變化檢測，ar 沒有內容校驗和，也不構成原子或已認證源快照；解析 ar 所有者和模式欄位不授予許可權恢復能力。

成員與行數量、原始/解析/顯示名稱位元組、物理源跨度和解碼後設資料工作量均按整個軟體包累計限制，control 和 data 不各自獲得新的累計解碼額度。同一準備或交付階段內，跨共享檢視累計實際輸入 I/O。準備與交付分開，沿用 TAR 索引和載荷重開規則；快取的準備位元組不授予額外源訪問。交付同時計量原始成員匯出和實際內層解碼，與已交付檔案位元組分開。下一次讀取、寫入或分配前拒絕超限，在記錄邊界及源讀取檢查取消。

本配置只讀，不提供密碼、分卷、軟體包建立或修改。原始 ar 成員壓縮尺寸已知，壓縮 TAR 子項則未知。檢查使用 `format_declared_checks`，驗證容器結構、可讀性和內層實際宣告的校驗，不代表軟體包認證。自動化驗收覆蓋獨立已知內容、全部准入過濾器族、子跨度、重複身份、損壞外層和內層校驗、精確預算、源變化及取消，以及實際 CLI/Qt 瀏覽、檢查和提取。生成證據僅保留在 `build/` 或 CI，平臺和發行批准分別登記。
