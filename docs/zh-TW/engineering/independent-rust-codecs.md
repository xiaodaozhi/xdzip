# 自研 Rust 格式與演算法契約

[English](../../engineering/independent-rust-codecs.md) | [简体中文](../../zh-CN/engineering/independent-rust-codecs.md) | 繁體中文 | [日本語](../../ja-JP/engineering/independent-rust-codecs.md) | [Français](../../fr-FR/engineering/independent-rust-codecs.md) | [Deutsch](../../de-DE/engineering/independent-rust-codecs.md) | [Español](../../es-ES/engineering/independent-rust-codecs.md) | [Português (Brasil)](../../pt-BR/engineering/independent-rust-codecs.md)

本文說明內建 Rust 格式實現、支援範圍及相容性驗證方法。可執行的操作由[格式登記表](format-registry.md)宣告，程序分工見[格式工作程序契約](native-codecs.md)。

<a name="xdzip-实现边界"></a>

## 實現邊界

內建能力宣告和產品入口對映使用[格式登記表](format-registry.md)。宣告只是候選能力，仍由實際容器條目、宿主策略及平臺支援進一步收斂，不能替代容器校驗或授予檔案許可權。

容器解析、編碼、解碼與壓縮演算法採用獨立 Rust 實現，允許經准入的通用密碼學、字元編碼、系統及橋接基礎庫。第三方格式庫、演算法庫和命令列工具可以作為獨立測試參照，不成為遷移完成格式的產品執行依賴。僅刪除直接依賴不足以證明替代完成，須檢查普通依賴及構建依賴的傳遞閉包和交付檔案。

程式識別格式後選用對應的內建實現，解碼失敗不會切換後端。ZIP、TAR、TAR.GZ 和 7z 可建立歸檔，也可改寫符合條件的現有歸檔。RAR、CAB 和 UDF 只提供讀取操作。ISO 讀取經工作程序執行，[ISO9660/Joliet 寫入器](iso-creation.md)在 Rust 宿主中建立新的資料映像，現有 ISO 映像不支援改寫。各格式均有明確的配置與資源邊界，例如 RAR7 LZ 需要使用獨立來源的壓縮流樣本驗證互操作性。

領域層、Qt 橋接和公共 codec trait 保持現有所有權。後端不獲得目標路徑或自行釋出檔案。名稱原始位元組、物理 EntryId、重複條目、編碼解析、來源身份、卷授權、路徑預檢、暫存、校驗與提交繼續遵守現有工程契約。共享演算法只實現一次，容器獨立處理封裝、塊邊界、字典重置及校驗語義。原生後端遷移為 Rust 後仍保留工作程序的取消、終止和資源治理。

ASAR 只讀讀取遵循 [ASAR 契約](asar-containers.md)，限制保序 JSON/Pickle 後設資料，保留共享儲存區間並驗證可選 SHA-256。通用 JSON 與雜湊原語不授予外部檔案訪問或應用執行能力。

只讀 UU/UUE/XXE 讀取器遵循[文字封裝契約](text-envelopes.md)。計數字母表、Base64、成員身份和結束驗證均由獨立 Rust 程式碼實現，參考流編碼器不進入執行時依賴閉包。

Unix compress 與 TAR.Z 複用[compress 契約](compress-streams.md)規定的獨立有界 LZW 原語和受控流/TAR 組合，碼、字典佔用、分組對齊、工作量和記憶體准入均不依賴第三方壓縮執行時。

共享 LH4–LH7 和 LArc LZS/LZ5 原始解碼器遵循 [LHA 資料與演算法契約](lha-containers.md)。容器方法、CRC 和產品准入分別驗證，原語不能自動授予登記的歸檔能力。共享規範字首碼保留各格式各自的深度與單符號規則。

<a name="xdzip-来源与独立实现"></a>

## 來源與獨立實現

先依據官方技術資料定義欄位、狀態轉換、數值範圍、錯誤行為及測試向量，再編寫程式碼。參考實現只用於補充行為理解，不進行逐行語言轉換、改名複製、結構搬運或註釋複製。規範規定的標識和常量記錄章節；計算表優先用明確數學規則生成。測試參照的來源及許可證與產品依賴分別管理。

已經接觸參考原始碼的開發者不宣稱嚴格潔淨室開發。需要來源隔離的模組，由分析者提交不含程式碼表達的行為規格，再交給未接觸參考實現的實現者。參考原始碼、文件、測試資料本身的許可證不會因 Rust 重寫消失；舊版交付及過渡依賴繼續履行各自義務。

RAR 官方技術說明不完整，解碼演算法缺口須記錄並進行專項許可審查；不開發 RAR 編碼器，不將 UnRAR 的限制解釋為允許重建 RAR 壓縮演算法。公開規範中的專有擴充套件、專利提示和再分發條件需要分別核查，獨立編寫不等於法律風險歸零。

<a name="xdzip-tar-记录规格"></a>

## TAR 記錄規格

DEB 的只讀普通 ar 外層透過擁有式受限子源複用同一套 TAR 與受控過濾器實現，原始、control、data 匯出檢視、共享輸入及解碼預算和快照投影見 [DEB 契約](deb-containers.md)。不引入軟體包安裝器、指令碼執行或第三方格式執行時。

獨立記錄層位於 `xdzip-codec-tar/src/record.rs`。佈局依據 [POSIX pax 的 ustar 與 pax 交換格式](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/pax.html)，GNU 擴充套件參見 [GNU tar 格式說明](https://www.gnu.org/software/tar/manual/html_node/Standard.html)。不引用參考庫的內部實現或私有 API。

- 記錄為 512 位元組，頭校驗使用無符號位元組和，並把校驗欄位的八個位元組視為空格。名稱、大小、時間、型別和 ustar 字首按規定偏移讀取。GNU 頭的字首位置不是 ustar 路徑字首。
- 普通數值接受有界八進位制和非負 GNU base-256。負數及 u64 溢位拒絕；無效時間保留未知展示，不改變有效載荷定位。資料按 512 位元組補齊，結束至少兩個全零記錄，之後只允許預算內的全零填充。
- PAX 長度包含十進位制長度本身、空格、鍵值和換行。長度須有進展且不越界，鍵非空，記錄以換行結束，不含 NUL。區域性 path、size、mtime 和 hdrcharset 沿用現有解釋，GNU 長名稱和全域性 comment 的限制見 [TAR/GZIP 契約](tar-gzip.md)。
- 建立寫入 ustar；非 ASCII 或超長名稱使用區域性 PAX UTF-8 path。超出八進位制範圍的大小與時間用 PAX 欄位，普通頭寫可表示的佔位值。擴充套件資料最多 64 KiB。輸入嚴格讀取凍結大小，隨後最多探測一個位元組，來源變長或變短均不成功。
- 重寫保留普通頭的所有者、mode、時間和已准入的其他後設資料；重新命名更新路徑和字符集宣告並重新計算校驗。PAX size 控制資料長度，不能按普通頭佔位大小截斷資料。壞頭、壞擴充套件、結束記錄缺失及資源超限都在宿主釋出之前失敗。

`tar` 僅作為開發測試的獨立讀寫參照。[依賴政策](../../../scripts/rust-codec-policy.json)由 Foundation 檢查生產依賴閉包，禁止 tar、filetime 和已退出的壓縮庫迴流至 TAR 實現。鎖檔案仍記錄開發測試參照，不能僅據鎖檔案判斷產品可達性。

<a name="xdzip-共享-deflate-与-gzip-规格"></a>

## 共享 Deflate 與 GZIP 規格

普通 GZIP 與 TAR 過濾器共用 `xdzip-codec-stream`，宿主命名、預算、完整流校驗和建立限制見[單檔案壓縮流契約](single-file-streams.md)。

`xdzip-compression` 無第三方生產依賴。格式定義依據 [RFC 1951 第 3 節](https://www.rfc-editor.org/rfc/rfc1951)及 [RFC 1952 第 2.3 節](https://www.rfc-editor.org/rfc/rfc1952)，不搬運附錄示例程式碼。長度、距離和額外位數為規範中的線格式表，CRC 查表由 IEEE 多項式在編譯期生成。

共享公開介面為 `DeflateReader`、`DeflateWriter`、`GzipReader`、`GzipWriter` 與增量 `Crc32`。ZIP 與 GZIP 使用同一套 Deflate 編解碼器。裸流 Reader 只讀取已准入的壓縮範圍，區分實際消費與緩衝預讀；只有 BFINAL 結束且實際消費恰等於壓縮大小時返回成功 EOF。不能用輸出大小或 CRC 相同代替壓縮流終止，也不接受範圍內的第二條流或尾隨垃圾。

`DeflateReader::with_dictionary` 接收至多 32 KiB、按時間排列的已准入歷史，只初始化匹配視窗，不將歷史作為新流輸出。ZIP/GZIP 的普通構造仍從空視窗開始。CAB 的 `MszipDecoder` 依據 [MS-MCI](https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-mci/27f0a9bf-9567-4e40-ad66-6ae9ab9d2786)複用此介面，每個 CK 幀重置 Deflate 位流、保留邏輯 folder 的末 32 KiB；壓縮幀最多 32,780 位元組、輸出最多 32,768 位元組，要求精確尺寸與完整裸流 EOF。只有完整幀透過後更新歷史，失敗後不能繼續使用該 folder，`finish` 後不能追加幀。共享演算法不驗證 CAB 物理片段校驗及卷鏈，由獨立容器負責；CAB 的產品切換與其他方法驗收見 [#48](https://github.com/xiaodaozhi/xdzip/issues/48)。

- 解碼處理 Store、固定和動態 Huffman，跨塊保留 32 KiB 環形歷史，允許重疊匹配。拒絕保留塊型別、LEN/NLEN 不匹配、過度訂閱碼錶、不允許的不完整碼錶、缺失結束符、越界重複長度、保留符號和歷史之前的距離。
- 編碼使用有界雜湊鏈 LZ77、頻率構造的規範 Huffman 碼和碼長遊程編碼。樹深度超出 15 時使用固定樹，不截斷碼長。級別 0 以至多 65,535 位元組儲存塊輸出，1/6/9 以至多 2 MiB 塊和 4/32/128 個候選搜尋上限編碼；收益不足時拆為儲存塊，避免無壓縮收益的資料膨脹。編碼歷史每塊重建，壓縮率及輸出位元組不承諾與參考庫一致。
- 解碼中間狀態為視窗及有界碼錶，編碼中間狀態隨單塊上限有界，不收集整個歸檔。宿主繼續累計輸入、解碼工作及輸出配額。編碼塊有界完成後返回控制權，不在共享演算法中新增執行緒或檔案許可權。
- GZIP 校驗魔數、方法和保留標誌，處理 extra、名稱、註釋及可選頭 CRC。單成員頭最多 64 KiB，超限拒絕。逐成員驗證 CRC-32 和模 2^32 的 ISIZE，所有成員串接為同一 TAR 流。必須讀至 EOF；截斷、壞尾部和非成員垃圾不能作為成功結束。
- Writer 只有成功 finish 才產生最終塊和尾部，Drop 不寫出資料。輸出失敗後不能繼續作為成功流使用。記憶體緩衝不賦予釋出許可權，宿主仍在全量複驗後提交。

有限固定種子變異測試只證明其實際覆蓋，不聲稱完成長期模糊測試。編碼效能、壓縮率及三平臺結果獨立記錄，後續最佳化不能放寬完整性和配額檢查。

<a name="xdzip-zip-记录与密码封装规格"></a>

## ZIP 記錄與密碼封裝規格

ZIP 的 EOCD、ZIP64、中央/本地頭、額外欄位及描述符依據 [PKWARE APPNOTE](https://www.pkware.com/documents/casestudies/APPNOTE.TXT)，AES 封裝依據 [WinZip AE-1/AE-2 規範](https://www.winzip.com/en/support/aes-encryption/)。獨立實現容器、名稱擴充套件、記錄定位、編解碼組合和認證邊界；通用密碼學原語按[依賴准入](dependencies.md)使用，不實現 RAR 編碼或額外 ZIP 專有加密擴充套件。

- 物理中央記錄逐項保留，同名條目不合並。尾部必須完整、count/size/offset 一致；存在多個恰好覆蓋 EOF 的尾記錄候選時拒絕歧義，分卷歸一前後採用相同規則，不能用註釋內嵌尾記錄隱藏真實目錄。ZIP64 哨兵按實際存在的欄位順序解釋，經典尾記錄的兩個磁碟號和兩個計數可獨立使用 0xFFFF 佔位，讀取 ZIP64 實值後再判斷單卷；所有非佔位值必須與對應實值一致。拒絕損壞、重複的關鍵欄位和未經宿主歸一的多磁碟後設資料。掃描只展示有界後設資料，宣告的大數值保持精確 u64，內容範圍在負載階段複驗。
- 單任務後設資料讀取預算 64 MiB，之後的本地頭、描述符、壓縮資料、密文及密碼重試累計消費同一個 20 GiB 輸入預算。名稱和快照身份不能在負載階段重新猜測。實際輸出先暫存，完整讀取並驗證成功後才由宿主提交。
- 逐條核對本地/中央名稱、關鍵標誌、方法、CRC、大小、AES profile 和 ZIP64 寬度。資料和可選描述符必須位於下一條本地記錄及中央目錄之前，不能跨入其他記錄。Store 核對精確尺寸與 CRC，Deflate 額外要求嚴格裸流 EOF；32/64 位及有/無簽名描述符均按欄位匹配驗證，不能把恰等於簽名的 CRC 誤認成簽名。
- AES-256 使用 16 位元組隨機鹽、PBKDF2-HMAC-SHA1 的格式規定引數、兩個 32 位元組金鑰和兩位元組密碼驗證值；CTR 計數從 1 開始，按小端塊編碼。只對密文計算 HMAC-SHA1，並驗證前 10 位元組認證碼。AE-1 同時驗證 CRC，AE-2 要求宣告 CRC 為零。認證失敗是完整性失敗，不冒充確定的錯誤密碼。
- 密碼仍由宿主借用，格式層不持久化、不列印。派生金鑰和流狀態使用歸零生命週期，AES/HMAC/SHA1 開啟基礎庫提供的清理特性；不保證 Qt、輸入法或 CPU 的所有歷史副本都可擦除。認證完成之前的輸出不獲得釋出資格。
- 建立使用流式輸出、顯式描述符和 ZIP64 邊界，目錄明文，普通檔案可選擇 Store/Deflate 與 AES。編號分卷仍由宿主在整包驗證後分割和提交。普通包重寫保留有效壓縮載荷、註釋及已准入後設資料，重新計算記錄偏移；加密、分卷、自解壓字首及無法安全保留的後設資料繼續拒絕修改。空包也檢查中央目錄前的材料，不能因沒有本地記錄而丟棄字首；真正空包仍可加入內容並保留歸檔註釋。
- 修改時間寫入 DOS 欄位並攜帶精確秒擴充套件；對非負且適合有符號 32 位的 Unix 秒寫入 UT extra，其他可表示時間寫入 NTFS FILETIME mtime。NTFS 的 atime/ctime 為零，依據 [Common ZIP 約定](https://commonzip.org/spec/#lastmodifiedtimestamp)不為其賦予有效時間含義；APPNOTE 本身不定義零值為缺失。負數 Unix 秒不使用 UT，避免獨立工具將其解釋為未來日期。普通重寫保留原時間擴充套件，不補造訪問或建立時間。
- 改名寫入 UTF-8 標誌並移除陳舊 Unicode Path extra；該標誌也宣告條目註釋為 UTF-8，因此原註釋不滿足 UTF-8 時明確拒絕改名，保留原包，不靜默轉碼或丟棄註釋。未改名記錄可保留原始標誌和註釋。

`rawzip`、`zip`、`flate2` 僅作測試參照，已遷移 ZIP 的普通及構建依賴閉包禁止這些格式和演算法庫迴流。測試參照的許可繼續保留，容器可讀取不等於所有宣告方法都可解碼。

<a name="xdzip-7z读写规格"></a>

## 7z讀寫規格

`xdzip-codec-7z` 是自研讀寫後端，在既有隔離工作程序中固定執行，沒有官方處理器或失敗回退。容器處理方法圖、壓縮頭、外部屬性、子流、UTF-16LE 原始名稱與物理 EntryId，圖執行器呼叫共享演算法及獨立 AES 封裝，不取得路徑或釋出許可權。官方 7-Zip 原始碼與容器適配退出產品構建，固定官方參考工具只用於測試。規範、參考分析角色和許可區分見[7z 來源](sevenzip-format-sources.md)。

方法圖按實際埠關係流式執行，保留字典、模型和有界節點緩衝，不物化或快取整個 payload folder。後設資料終端輸出仍受 64 MiB 限制，後設資料、字典、模型、節點緩衝及工作區合計在分配前按預設 1 GiB 准入。單檔案最多 8 GiB，任務實際輸入與終端解碼工作各最多 20 GiB，逆序訪問及重啟重複計費。順序讀取同一 solid folder 保留圖狀態；檔案具有獨立子流 CRC 時，精確尺寸與該 CRC 透過即可完成該檔案，後續檔案繼續同一圖。沒有獨立子流 CRC 時，先完成 folder 終態和已有 folder CRC 再完成檔案。完整結束時核對所有已連線 packed 範圍、節點尺寸、EOF 及提供的 CRC，不把未引用的額外 payload 當作普通檔案檢查範圍。

Header、Additional 與 payload 共用圖執行器。後設資料讀取和輸出分別受掃描預算約束；進入 payload 時僅一次初始化其輸入和終端工作計數，重啟不重置。中間節點工作與 AES KDF 跨兩個階段累計。終端輸出才計入宿主實際解碼工作，包含未選區間；中間節點另有累計工作上限，不能把 AES、解壓及過濾器每層輸出重複計作同一檔案的宿主工作。遞迴讀取在呼叫上游前預留目前節點預算，失敗釋放未執行預留，實際工作不退款。

AES KDF 以實際累計輪數和 hash 輸入位元組准入，失敗或重試不返還額度，不以輸出配額換取無界雜湊。任務區域性最多快取 16 個已派生金鑰，以密碼、迭代引數和鹽匹配，IV 不屬於派生身份；密碼變化清除舊快取，不在不同會話間複用。快取命中不偽造額外 KDF 工作，固定快取及密碼副本按 16 KiB 計入預檢，節點驗證金鑰與自身 KDF 引數匹配後才使用。密碼、金鑰、owned hash 狀態及候選內容緩衝使用歸零生命週期，不宣稱能擦除 Qt 或系統的所有歷史副本。

Zstandard/FSE/Huffman/XXH64、LZ4/XXH32、LZMA1/2、BZip2、PPMd7 與共享 Deflate/Deflate64 位於 `xdzip-compression`，其生產依賴仍為空，不引入相應壓縮演算法庫。Deflate64 只切換同一 Deflate 實現中的格式差異，ZIP、GZIP 和 MSZIP 保持普通模式。PPMd7 顯式區分已知長度和 END profile，格式模型重啟不能替代宿主記憶體准入。LZMA2 writer 支援有界搜尋級別 1/6/9，在單 chunk 無收益時用格式允許的 raw 回退，不將只有 raw 分塊的封裝標記為已完成壓縮器。共享 Reader 顯式限制 packed 範圍，只有已驗證完整終態才返回成功 EOF，錯誤後不能繼續。`Read` 的輸出分片上限不代表單個 block 或模型操作具有相同 CPU 上界。

AES 使用已准入的通用 AES、SHA-256、隨機數及 zeroize 原語。獨立實現格式屬性、UTF-16LE 密碼 KDF、CBC 組合及塊裁剪，不引入 7z 格式庫。CBC 本身沒有認證能力，容器仍須完成實際提供的 CRC 及尺寸校驗；不能把任意完整性失敗冒充確定的錯誤密碼。建立 profile、秘密清理和最終釋出仍需宿主全鏈路驗收。

建立按 Copy 或 LZMA2 級別 1/6/9 流式寫入宿主隨機暫存，solid 只改變檔案分組。每個加密 folder 與加密頭使用新隨機 IV，任務內複用匹配的 KDF 身份，頭部名稱在加密區內。輸入讀取精確宣告長度後還須檢查真實 EOF 和凍結來源身份，包含空檔案；不能合成 EOF。宿主和工作程序均限制讀寫塊、偏移、累計工作及實際輸出，進度訊息不增加讀寫許可權。

重寫只支援未加密、非分卷且所有記錄為可安全保留的普通檔案或目錄，未知必要後設資料、anti、連結和特殊物件明確拒絕。工作程序持有最多 512 MiB 的保留及新增內容，字典、模型、後設資料和工作集合計在預設 1 GiB 內預檢。保留記錄的原始 attrs、ctime、atime、mtime 按已理解欄位重建，物理順序和同名記錄身份不合並。重寫以選中的 FilesInfo 實體為準，重新組織壓縮圖；無檔案引用的 folder 和未引用屬性 blob 不屬於結構保真承諾。來源複驗、整包驗證及同卷原子釋出仍屬於宿主。

<a name="xdzip-cab只读规格"></a>

## CAB只讀規格

`xdzip-codec-cab` 是自研只讀後端，範圍為 Store、MSZIP、LZX、Quantum 和宿主已經授權的同目錄卷鏈。產品固定使用 Rust，沒有官方處理器或執行失敗回退；官方 Cab 容器與其專用 LZX/Quantum 演算法不進入編譯清單。CMake 的內部 `XDZIP_CAB_BACKEND=rust` 僅記錄固定構建身份，不是可選擇的產品後端。開發、平臺和桌面人工驗收分別由[任務 #48](https://github.com/xiaodaozhi/xdzip/issues/48)及關聯驗收條目維護，不自動批准正式發行。

容器依據 MS-CAB，MSZIP 依據 MS-MCI 並複用共享 Deflate；LZX、Quantum 呼叫 `xdzip-compression` 的獨立解碼器。官方歸檔文件的狀態、1997 年 LZX 原件映象的真實性限度、MS-PATCH 與 CAB 的差異，以及參考分析者和未讀原始碼實現者的分工，見[CAB 格式來源與實現依據](cab-format-sources.md)。這些來源及角色限制不能因 Rust 後端而省略。

- `ReadSource::volume_lengths()`、`volume_names()` 提供凍結的物理卷邊界和原始卷名。宿主負責發現、來源身份和同目錄授權，最多 1,024 卷；格式層在每卷本地範圍內解釋偏移，再檢查卷基址相加，不能讀過本卷末尾而借用下一卷位元組。卷名和 disk label 不賦予檔案訪問許可權。缺卷、set/index/名稱或續接矛盾必須使整次掃描失敗，不釋出部分索引。
- 掃描核對容器版本、保留欄位、區域範圍與不重疊關係、檔案區間和 CFDATA 片段。跨卷未完成幀先核對各片段校驗，再拼成一個邏輯壓縮幀。folder 是壓縮/字典單元，不是檔案系統目錄；只有新邏輯 folder 重置歷史，檔案及物理卷切點不重置。最後一幀可短，前面的完整邏輯幀輸出均為 32,768 位元組。未知壓縮方法或引數明確返回不支援，不能跳過後釋出不完整內容。
- 只有規範明確的 continued 記錄合併為同一邏輯檔案，名稱、偏移、尺寸、時間和屬性須一致；普通同名、重複或重疊輸出區間分別保留。`EntryId` 從 1 連續分配，依據首次 CFFILE 的物理出現順序，不按名字排序，也不把源偏移作為身份。公開 `Entry.method` 保持既有值 0，實際壓縮方法只儲存在私有 folder 後設資料中；DOS 時間按原值保留，不補造時區。
- 名稱透過全檔 `names::resolve_cab` 解析。原始位元組及 CFFILE 的 UTF-8 宣告分別保留，`scan_with_encoding_flags` 同步返回原宣告；不能從 ASCII 名稱解析後的 `NameEncoding` 倒推原宣告。舊編碼先嚴格解碼，再把 CAB 分隔符轉換為共享路徑形式，防止 Shift-JIS 尾位元組 `0x5c` 變成分隔符。損壞宣告保留可見警告並拒絕輸出，不以宿主內碼表替代。名稱和路徑規則繼續遵守[檔名編碼契約](filename-encoding.md)。
- 只讀能力包括後設資料和普通檔案內容，不提供建立、重寫、執行或連結/特殊物件輸出。空檔案同樣驗證所需幀與歷史；負載開啟時重掃並與凍結條目快照逐項比對。實際觸達的 CFDATA 必須完整驗證校驗和、壓縮流終止及精確輸出長度，不能在選中檔案的末位元組處截斷幀校驗。CFDATA 的零 checksum 表示未提供該校驗，不補造內容認證保證。保留取消、配額和源 I/O 失敗類別，不能吞成成功或無條件重試；解碼失敗後的負載例項不能繼續使用半更新狀態。
- 預設後設資料讀取最多 64 MiB，物理 CFFILE 記錄最多 100,000，含繼續副本；邏輯 folder 最多 100,000，物理 CFDATA 片段最多 1,000,000。共享掃描預算預設單名稱 4,096 位元組，原始名稱總量和解碼/展示文字各 16 MiB，呼叫方更低限額仍有效。負載例項重掃後繼續累計實際輸入，輸入和解碼工作各最多 20 GiB；單檔案宿主上限 8 GiB，不擴大 CFFILE 欄位本身的範圍。所有長度乘加、分配和源範圍均先檢查。
- 完整邏輯幀輸出最多 32,768 位元組，Store、MSZIP、LZX 的壓縮幀分別限制為 32,768、32,780、38,912 位元組。Quantum 完整壓縮幀設 1 MiB 資源准入限額，該值不宣稱為官方格式規定的最大膨脹。跨卷切分不會擴大單個邏輯幀限額。解碼狀態和一個輸出幀有界保留；按順序選擇同 folder 檔案可複用狀態及該幀，不為每個檔案從頭重放整個字首。

CAB 與 ISO/UDF 共享 `xdzip-codec-bridge`，在既有隔離工作程序中以同步借用的 CXX 回撥讀授權流、發後設資料及有界輸出。卷陣列和位元組切片只在呼叫期間借用，異常與 unwind 不跨邊界。直接 codec API 用於 worker 和獨立探針，不替代產品的程序隔離；宿主持有取消、強制終止、來源複驗、暫存和最終提交能力。

完整幀計量使用 `DecodedSink::charge_skipped` 與 `write_precharged_chunk`。新幀全部解碼並驗證後，先把整幀輸出位元組數計入實際工作，包括選中區間之前及之後的位元組，再交付選中內容。容器為該快取幀儲存等量未消費額度；輸出只能在剩餘額度內預計費交付，耗盡後的重複或重疊交付走普通 `write_chunk` 再計工作。換幀丟棄舊幀未用額度，不按名稱、條目或偏移自動豁免重複輸出。未實現預計費支援的 sink 預設轉入普通寫入，可能保守重複計費，但保持輸出與上限檢查。

worker 協議以 `WORK`（17，小端 `u64` 位元組數）請求宿主准入，以 `PRECHARGED_DATA`（23）傳遞已有額度的內容，每個輸出塊最多 64 KiB，並等待宿主 ACK。Native 接收端僅允許 CAB、7z、RAR 在同一個持續 worker 的已准入額度內使用非空預計費輸出；其他格式或不足額度均拒絕，條目完成時仍核對精確宣告尺寸。重啟、結束或失敗後不得沿用舊 worker 額度。執行時提取 sink 與檢查 sink 再以任務私有額度獨立核驗，正常檔案切換可保留尚未消費的額度，但額度消費一次後不能再次使用。預計費只免除已計工作重複增加，檔案宣告尺寸、單檔案 8 GiB、累計實際輸出 20 GiB、取消和寫入失敗檢查仍生效。額度在交付前扣減，部分輸出失敗不會把它退回重用；宿主拒絕 `WORK` 不產生任何新額度。RAR 的輔助工作單獨准入，不產生預計費輸出額度，見[輔助工作契約](auxiliary-decoding-work.md)。

<a name="xdzip-rar只读规格"></a>

## RAR只讀規格

`xdzip-codec-rar` 的古老/舊/現代容器、物理片身份、授權卷、名稱、Store、13/15 與 20/26 族、RAR29 LZ/PPM/標準過濾器、現代 LZ/過濾器及歷史/現代密碼契約見[RAR 實現依據](rar-format-sources.md)。產品固定使用該 Rust 路由，不編譯或部署 UnRAR，沒有失敗回退。未知尺寸顯式表示並禁止輸出，現代時間透過格式無關宿主服務投影，輔助解碼工作獨立計費。各歷史組合、真實過濾器與跨平臺相容證據仍按[完整遷移任務 #51](https://github.com/xiaodaozhi/xdzip/issues/51)分別驗收，不能因單族成功縮減範圍；RAR7 演算法 1 的獨立健康實樣由 #43 跟蹤。

<a name="xdzip-iso与udf只读规格"></a>

## ISO與UDF只讀規格

`xdzip-codec-optical` 只接收借用的 `ReadSource`，不訪問檔案系統或掛載映象。ISO 依據 [ECMA-119 第五版](https://ecma-international.org/wp-content/uploads/ECMA-119_5th_edition_december_2024.pdf)的卷描述符、目錄、擴充套件屬性和附錄 C Joliet，以及 [Rock Ridge 1.12](https://bitsavers.org/projects/cdrom/Rock_Ridge_Interchange_Protocol.pdf)、SUSP 1.12 與 [El Torito 1.0](https://bitsavers.org/projects/cdrom/El_Torito_CD-ROM_Spec.pdf)編寫。UDF 依據 [ECMA-167 第三版](https://ecma-international.org/publications-and-standards/standards/ecma-167/)第 1、3、4 部分及 [OSTA UDF 2.60（PDF 映象）](https://www.13thmonkey.org/documentation/UDF/udf260.pdf)的結構限制、分割槽與字符集規定編寫。實現不轉換第三方解析器原始碼，規範原文和第三方測試工具不作為本專案原創材料再許可。

- ISO 核對雙端整數、卷範圍、目錄記錄及檔案區段，支援多區段普通檔案、Joliet UCS-2、Rock Ridge 名稱續接、SUSP CE、CL/PL/RE 目錄重定位與連結/特殊型別識別。非 Joliet 原始名稱交給共享有界編碼解析，不呼叫系統 OEM 轉碼。啟動目錄及映象僅表示為可讀取記錄。跨卷 ISO、交錯檔案、面向記錄的擴充套件屬性、Rock Ridge SF 稀疏及 ZF 壓縮擴充套件明確拒絕；不能把未知必須特性當普通檔案解碼。
- UDF 區分邏輯塊號與物理偏移，驗證 descriptor tag 的位置、校驗和、CRC 和尺寸，處理主/備錨點、VDS 續鏈、FSD、FE/EFE、FID 與 ICB。物理、sparable、VAT 1.50/2.x、metadata/mirror 分割槽對映分別准入。Sparable 分割槽的標準 `*UDF Non-Allocatable Space` 系統記錄按 OSTA 3.3.7.2 驗證名稱、型別、Metadata/System/Stream 標誌、零資訊長度和未記錄尾分配，僅作系統後設資料，不成為輸出條目。短、長、擴充套件 AD 及續接按實際 recorded/information 長度解釋，支援內聯、未記錄零區段和非連續內容，不將資料範圍相加後假設連續。目錄圖、分配續鏈及對映迴圈均有界，CS0 嚴格轉 Unicode。
- UDF 普通檔案的命名 streams、未知系統 streams、transformed 資料、未知對映/ICB 策略和不能解釋的 extended AD 長度組合明確拒絕。實時檔案及其他特殊型別標為不可輸出，符號連結和多連結普通檔案同樣拒絕輸出。已識別 UDF 的失敗不會改用 ISO；VDS/metadata 的規範內冗餘恢復不改變所選名稱空間。
- EntryId 按選定名稱空間的原始目錄記錄遍歷順序分配，不按解碼名稱排序或合併重名記錄，不將檔案資料的扇區偏移充作條目身份。解析結果儲存資料、零區段和內聯內容的獨立 extent 列表；負載開啟時重掃並核對凍結後設資料，解碼時核對條目身份、範圍與精確輸出長度。沒有逐檔案 CRC 的格式不補造內容校驗保證，同尺寸內容變化可能仍然可讀；宿主來源身份檢查繼續獨立執行。
- 後設資料讀取最多 64 MiB，普通條目最多 100,000，單名稱最多 4,096 位元組，總名稱和展示文字使用共享掃描預算；總輸出 extent 最多 1,000,000，內聯總量最多 64 MiB。ISO 目錄深度最多 256，單記錄 CE 最多 128 個區域、1 MiB；宿主可輸出路徑仍受更嚴格的共享限制。UDF 分割槽對映最多 256、單分配表最多 262,144 個 extent、續鏈最多 4,096。所有加法、乘法和源範圍均檢查溢位。
- 實際解碼保留單檔案 8 GiB、累計工作及輸入各 20 GiB 限制，以有界緩衝讀取和輸出。`xdzip-codec-bridge` 在既有工作程序內透過同步借用的 CXX 回撥傳遞授權流；異常與 unwind 不跨邊界，程序終止使未完成輸出失敗。宿主保留記憶體治理、取消、強制終止、來源複驗、私有暫存及最終提交。官方 7-Zip Iso/Udf 處理器從構建和登錄檔移除，不保留執行時回退。

獨立樣本必須具有可核驗的生成工具或來源及已知內容；自編碼規範向量只驗證實現的內部狀態組合。metadata、VAT、sparable 等擴充套件的獨立實樣與三平臺驗收單獨登記於[遷移任務 #47](https://github.com/xiaodaozhi/xdzip/issues/47)，不能由程式碼存在或物理分割槽樣本透過推定其他對映已驗收。測試工具、參考 worker 與產品 worker 分別記錄身份，不把參考工具不支援的樣本記為驗證透過。

<a name="xdzip-能力与验证基线"></a>

## 能力與驗證基線

| 後端 | 必須保持的能力 | 獨立實現要素 |
| --- | --- | --- |
| ZIP | Store/Deflate、ZIP64、AE-1/AE-2 AES-256、現有分卷、建立與普通包修改 | 記錄、額外欄位、資料描述符、加密封裝、共享 Deflate |
| TAR、TAR.GZ | ustar、既有 PAX/GNU、普通檔案與目錄、建立與修改、多成員 GZIP | 記錄層、擴充套件狀態、流式寫入，GZIP 封裝與共享 Deflate |
| 7z | Store、LZMA/LZMA2、PPMd、BZip2/Deflate 解碼、BCJ/BCJ2、分支與 Delta 過濾器、固實、密碼與頭加密、編號分卷、建立與受限重建 | 解碼圖、實際准入的方法組合，資源與編碼策略；不因底層有編碼器而擴大產品建立選項 |
| RAR | 舊版、RAR5、RAR7 的既有隻讀邊界、密碼、固實和分卷 | 分版本解碼器、過濾器、加密封裝與狀態重置 |
| CAB | Store、MSZIP、Quantum、LZX、同目錄卷鏈 | 記錄、檔案與資料夾對映、跨塊字典和跨卷檔案 |
| ISO、UDF | ISO9660、Joliet、Rock Ridge、UDF、混合映像選擇 | 卷及分割槽對映、名稱空間、區段、目錄圖和特殊項限制 |

每項切換需要雙向互操作（只讀格式為獨立樣本讀取）、損壞與截斷、數值溢位、資源限制、取消和真實宿主業務鏈迴歸。自研編碼器與解碼器互相成功不足以證明相容。模糊測試和基準使用固定來源，記錄實際覆蓋和時間，有限隨機變異測試不冒充長期 fuzz。實際執行的 Windows、Linux、Apple Silicon 自動檢查與桌面檢查分別登記，正式發行仍需獨立許可複核。
