# 應用會話與退出契約

[English](../../engineering/application-sessions.md) | [简体中文](../../zh-CN/engineering/application-sessions.md) | 繁體中文 | [日本語](../../ja-JP/engineering/application-sessions.md) | [한국어](../../ko-KR/engineering/application-sessions.md) | [Français](../../fr-FR/engineering/application-sessions.md) | [Deutsch](../../de-DE/engineering/application-sessions.md) | [Español](../../es-ES/engineering/application-sessions.md) | [Português (Brasil)](../../pt-BR/engineering/application-sessions.md) | [Русский](../../ru-RU/engineering/application-sessions.md)

標籤右鍵選單提供“關閉、關閉其他、關閉右側”，Shift+F10 或選單鍵作用於焦點標籤。右擊不切換目前頁，命令凍結標籤穩定身份，僅按該標籤所屬視窗的目前視覺順序操作，不能影響其他視窗。重排、視窗尺寸變化、目標消失或進入模態操作時關閉選單；沒有對應目標時禁用批次項。批次關閉一次提交，保留未被關閉的目前頁，否則切換到錨點標籤，避免逐頁閃切。最後一頁關閉後恢復起始頁，任務和結果繼續留在全域性任務入口。

同一使用者登入會話內，普通安裝和便攜程序共用單例項、托盤和應用選單。Windows 包身份使用獨立的單例項名稱空間，不向普通安裝程序轉發請求，避免商店包啟動後落入普通版的更新介面；兩種程序並存時各自持有托盤。現有安裝更新門仍保守約束兩者，並存、設定和關聯須在實際安裝環境驗證。版本查詢在建立 GUI 前返回；煙測、桌面探針和測試使用獨立路徑，不連線真實使用者例項。

`SingleInstance` 在建立主視窗前用 QLockFile 選舉，持鎖者才可移除崩潰殘留的本地伺服器。QLocalServer 使用 UserAccessOption，結構化 JSON 協議版本為 1，限制單條 256 KiB、128 個絕對路徑和 32 個連線。後啟動者等待主例項就緒，收到請求 ID 對應的確認後退出，15 秒內通訊失敗明確報錯，不建立第二個正常 UI。Windows 根據伺服器握手中的 PID 轉交本次使用者啟動的前臺啟用許可權，不設定永久置頂。IPC 不經過命令直譯器，不記錄使用者路徑。

`ApplicationSessions` 是 Qt 應用層協調器，不解釋格式、授權目錄或檔案提交。每個會話擁有獨立 SessionPage、BrowserController 和 Rust RuntimeConnection，開啟的頁面保留查詢、選擇、目錄與瀏覽狀態。視窗只承載頁面，標籤頁不會為每個歸檔建立隱藏的原生主視窗。檔案關聯、命令列、原生檔案開啟事件、開啟按鈕、最近記錄、拖放和建立結果統一提交開啟意圖。優先複用無歸檔且無任務的歡迎頁，重複路徑只啟用尚未關閉的會話，多檔案請求按順序接收並啟用最後一個。路徑規範化只用於 UI 去重，不授予寫入許可權。

`desktop/openMode=tabs|windows` 預設 tabs，schema 保持 1，未知欄位保留。設定操作成功後立即影響後續開啟，不遷移已開啟頁面。標題欄加號按此設定新建頁面或視窗。

標籤排序透過穩定會話身份和視窗內目標索引提交，只改變同一視窗未關閉會話的展示順序，不重排用於任務准入的控制器集合。拖動釋放或鍵盤排序後保持目前活動頁、歸檔、控制器、選擇和任務身份，其他視窗與已關閉背景會話的相對順序不變。關閉非活動標籤不切換頁面，關閉活動標籤優先選擇視覺順序中的右鄰，否則選擇左鄰。無效身份、已關閉會話、越界或退出期間的排序請求忽略；不建立或銷燬 Rust 連線。目前僅支援視窗內重排，不支援跨視窗拖放、分離視窗或跨啟動恢復順序。標籤欄溢位僅改變可視區域，不能丟棄會話；選單與鍵盤啟用後保證活動標籤可見。

最多保留 32 個存活會話，達到限額明確提示。所有槽均由背景任務保留時，關閉最後瀏覽頁複用原頁顯示歡迎與全域性任務入口，不建立額外執行時。關閉標籤或主視窗清除該頁的目錄、搜尋、排序、選擇、滾動與檢視狀態，但不取消背景任務。仍有任務或完成結果的頁面保留所屬控制器和任務所需資料，統一任務選單使用“會話 UUID/後端任務 ID”，不能把另一個連線中相同數字 ID 當作同一任務。密碼、衝突和結果視窗仍由原會話控制器處理。無任務的關閉頁面先請求非同步關閉，接收執行緒完成 join 後才從會話集合移除。

會話關閉後，延遲到達的開始、預檢、密碼與衝突事件不自動彈窗或搶焦點。任務與請求令牌繼續保留，使用者從全域性任務入口主動開啟時再顯示原會話的進度和待處理請求，關閉頁面不等於取消請求。

全域性任務入口只按複合身份顯示原控制器的任務視窗，先關閉呼叫選單，不切換目前歸檔標籤，不恢復已關閉的歸檔頁面或主視窗。任務的密碼、衝突和取消仍路由到原控制器；無效或已失效的任務身份忽略。關閉瀏覽頁與顯式檢視任務是獨立的使用者意圖。

任務選單的內容變化後，能在視口內完整容納的短列表從首項顯示，不能沿用舊滾動位置而把任務行裁出視口；超出高度限制的列表仍可滾動，清除區保持固定。

清除任務歷史是應用層展示意圖。控制器保留後端快照與遲到回執，僅在有界歷史中標記已終結專案不再展示，同一終態的重複更新不能使其重新出現。活動計數、準備佔位、密碼、衝突、取消及join不使用隱藏標記；沒有完成歷史時不傳送變化。歷史淘汰同時刪除隱藏標記，已關閉且無可見任務的控制器按既有非同步退出流程回收。跨會話清理按各控制器身份操作，不能用相同數字ID清除另一個會話的活動任務。



建立、解壓和完整性檢查在應用級序列准入，包括準備、密碼或衝突等待、提交與清理階段。等待准入的控制器僅保留一個有界命令，可取消，不佔用 GUI 執行緒。單個 Rust 連線的任務順序和安全語義繼續有效。明確退出時，先對所有會話作統一確認，選擇等待則全部任務結束後退出，選擇取消則等待全部連線完成取消、清理與 join；只檢查關閉完成狀態，不在狀態檢查中再次觸發關閉。

重任務快照攜帶建立任務的原始請求 ID，即使先於 `TaskAccepted` 或晚於該請求的 `Finished` 到達也保持不變。控制器僅在請求、原始會話與任務身份匹配時，將準備佔位繫結到實際任務；其他請求或會話的快照不能抵消佔位。實際任務與佔位只計一次，已終結任務不再計為活動任務。繫結不代替真實接納回執，不提前觸發任務視窗，不繞過序列准入、取消和全部連線 join 屏障。

等待全部任務退出只由應用級任務總數與 join 屏障收斂。某一頁面先完成任務時，不執行舊單頁自動關閉，也不因該頁結束而隱藏最後視窗或再次顯示退出確認。

退出確認顯示前即設定應用級 `quitDecisionPending`。所有會話與視窗的排隊密碼提示及顯式重新顯示在此期間暫停，不能覆蓋退出確認；返回或選擇等待解除暫停後，只重新顯示仍有效的同一任務與提示令牌。進入取消、清理與 join 後保持暫停，不重新開啟密碼視窗。該狀態不隱藏或取消已有請求，也不改變關閉會話後的顯式任務入口。

系統 Quit、應用選單與托盤的顯式退出經過同一桌面路由。受管理會話自己的密碼與衝突提示允許被全會話退出確認覆蓋；選擇返回保留原任務和請求令牌，取消並退出仍等待所有連線清理與 join。原生檔案選擇器、其他模態控制元件及不屬於受管理視窗的提示繼續阻擋退出請求並保持前臺，不能用通用模態檢查誤吞密碼等待期間的退出，也不能直接繞過確認取消任務。

托盤的設定與關於直接顯示共享設定視窗；主視窗隱藏、最小化或不存在時使用獨立例項，不建立或恢復主視窗。托盤退出直接進入全域性退出路由，任務等待時仍使用共享退出確認；“顯示主視窗”可顯式恢復或建立瀏覽視窗。

關閉托盤設定或托盤宿主不可用時，不重新開啟已關閉的彈窗或已完成結果。可見或最小化的主視窗提供全域性任務入口；沒有該入口時，僅恢復隱藏的活動任務視窗，保留原密碼與衝突令牌，不因自動恢復而建立或顯示主視窗。已開啟的設定視窗繼續可用。沒有托盤、可訪問視窗和活動任務後，等待所有連線結束再退出，不能因仍保留隱藏的主視窗物件而滯留背景。

重新啟用托盤後，其右鍵選單仍可開啟，並保留原有命令及目前任務狀態。Windows 下關閉後立即開啟、多次切換托盤宿主可用狀態也須滿足此規則，不能只恢復圖示。



主視窗可見時，“顯示並啟用”只提升和請求啟用。隱藏或最小化時恢復先前普通、最大化或全屏狀態，不先還原再最大化。阻塞的模態視窗優先啟用，彈窗 transientParent 繫結實際呼叫視窗。關閉最後一個主視窗繼續遵循托盤設定。設定與關於從統一入口進入，已有視窗優先啟用，關於入口切換到該視窗的關於頁。

`showMinimized()` 會替換原狀態位。恢復時先在仍最小化的狀態下補齊儲存的最大化或全屏標誌，再僅移除最小化標誌，不先顯示普通視窗。原生迴歸等待視窗實際暴露、啟用及最終狀態確認，避免把 Qt 請求值當作視窗管理器已完成的狀態。

Cocoa 路徑觀察所屬 NSWindow 的最小化與全屏轉換通知；轉換進行時保留恢復請求，並在原生確認後繼續。若 Qt 已報告最小化而同一原生視窗仍可見、已暴露且沒有轉換進行，則撤銷未生效的 Qt 狀態請求並恢復儲存狀態，避免等待不會到來的原生確認。原生視窗銷燬時移除觀察，無法取得視窗時繼續保留請求，不以固定延時判斷完成。

全屏進入期間或進入完成回撥內的最小化請求可能被 Qt 後續狀態覆蓋，或被 Qt 記錄而未被 AppKit 接受。記錄同一原生視窗的請求，進入完成後如視窗仍可見且沒有轉換，在下一次事件迴圈將 Qt 狀態與原生全屏對齊並補發最小化。較新的恢復、普通或最大化請求優先；視窗被銷燬或原生視窗不可用時不補發。對齊過程中到達的恢復請求也優先，不再執行舊的最小化請求。

密碼與退出順序迴歸使用真實 AES 等待，覆蓋任務通知已建立請求、延遲視窗尚未顯示時的同步 Quit，同頁、其他會話、其他視窗及選擇等待，另以視窗已顯示後的真實 posted Quit 作投遞對照。必須記錄實際通知與投遞狀態，確認排隊密碼視窗不覆蓋退出決定，返回或等待保留同一令牌，取消後完成全部 join；受控同步通知順序不能替代某個平臺歷史事件順序的證據。

驗收包括實際原生視窗狀態變化、併發啟動與崩潰殘留、Unicode 和批次路由、兩種開啟模式、儲存與取消及重啟、跨會話 ID 衝突、背景任務、密碼與衝突、全域性退出和接收執行緒回收。離屏測試只能證明狀態契約，不能代替原生視覺、輔助功能和桌面人工驗收。證據儲存在 build/ 或 CI 工件。

退出進入實際取消與 join 階段後，IPC 明確拒絕新意圖。關閉通道後才釋放選舉鎖，全部連線完成後才啟動重啟程序，舊例項的重複清理不能移除新端點。Windows 重啟同樣轉交本次使用者操作的前臺許可權。

阻塞彈窗期間接收的外部開啟保留最後一個啟用意圖，先啟用阻塞視窗，待其關閉後顯示對應新視窗，不使隱藏的新視窗失去入口。設定視窗保留實際呼叫者，不因另一主視窗獲得焦點而改變所屬關係。

原生迴歸入口為 `python3 scripts/check-native-sessions.py --tests <browser-tests> --output build/review/native-sessions.json`。Linux 使用 Xvfb 和 Openbox 的真實 X11 視窗管理路徑，Windows、macOS 使用系統視窗管理器；指令碼只管理自己啟動的驗證程序。按需 Qt 工作流與 Release 共用此入口，原生日誌和 JSON 儲存在 build/ 或 CI 工件，不能據此宣稱完成未執行的人工視覺、GPU、輸入法或螢幕閱讀檢查。

Linux 在 Openbox 的 `--startup` 回撥後才建立 Qt 測試程序；`_NET_SUPPORTING_WM_CHECK` 僅宣告視窗管理器身份，不能證明主題和事件處理已經就緒。`scripts/check-x11-startup.py` 與 `scripts/test-x11-startup-supervision.py` 分別檢查冷啟動就緒和超時清理，保留各自程序日誌，不用增加等待或重試代替原有首窗斷言。

關閉主視窗與最小化不同。關閉有托盤的最後視窗會清空該視窗所有瀏覽標籤，關閉包括設定在內的全部所屬彈窗，撤銷尚未儲存的外觀預覽並保留已生效的設定，銷燬其原生視窗資源後再隱藏主視窗；從托盤、Dock 或無檔案引數的第二次啟動喚出後僅顯示一個起始頁，不恢復舊標籤或附屬彈窗。非最後視窗繼續關閉並清理自己的瀏覽標籤與附屬彈窗，其他視窗不受影響。背景任務及提示令牌仍由原控制器保留，使用者明確開啟任務時才重新建立對應原生視窗。存在阻塞模態視窗時先啟用它，不接受主視窗關閉。

關閉視窗不取消真實背景任務，任務所屬會話繼續按組合身份保留。正常情況下使用新的空白會話承載起始頁。達到 32 個存活會話時暫用已關閉頁面的無歸檔外殼，隱藏舊標題、載入及錯誤意見回饋；非同步 join 釋放槽位後再建立空白會話，不越過上限。該替換不喚出隱藏視窗，不搶走另一視窗焦點。全域性任務入口僅顯示任務視窗；檔案開啟請求不恢復已關閉的瀏覽頁，而使用新會話重新讀取。若同一檔案仍在被背景任務修改，新頁面顯示可取消等待，任務終結後重新讀取，取消等待不影響原任務。

檔案開啟失敗或取消後，未在讀取、沒有活動任務和密碼提示的起始頁可再次用於開啟；舊路徑不作為成功開啟的歸檔身份。重新開啟因任務保留的已關閉歸檔時優先複用目前空閒起始頁，讀取新會話，原任務保留獨立身份；使用者主動新建的其他頁面和其他視窗不受影響。取消等待或關閉等待頁不能在任務完成後復活該開啟請求。

使用者在開啟仍顯示進行中時取消，即使背景完成回執已排隊，也不能提交該開啟結果或顯示密碼提示。控制器等待原請求結束，查詢並關閉可能已建立的背景歸檔會話；清理期間繼續保持忙碌，重複取消不終止清理。清理失敗時顯示實際錯誤，不報告取消清理成功；其他已接受的背景任務仍按各自生命週期處理。

接受主視窗關閉時遞增啟用世代並斷開模態等待連線，已經排隊的舊喚醒回撥也必須檢查世代，不能在模態彈窗剛關閉後重新顯示主視窗或恢復舊標籤。此失效處理與正常開啟入口共用，不取消背景任務。

更新交接使用獨立 `prepareForUpdate` 屏障，不復用立即重啟。存在任務、任務啟動或模態互動時拒絕交接；下載可繼續，等待可取消。接受後關閉新意圖入口並清理全部 Rust 連線，所有 join 完成僅發 `readyForUpdate`，不提前退出。更新提供者在釋放安裝提交之前發出退出屏障訊號，主程式此時才解除正常退出攔截。安裝提交失敗時保留關於頁恢復入口，使用者可正常退出，不啟動舊版本自動重啟。詳細行為見[主動更新](software-update.md)。

## 檔案管理器操作會話

[檔案管理器右鍵操作](shell-actions.md)使用不含瀏覽頁和主視窗的操作會話，共用既有複合任務身份、序列准入和退出 join 屏障。冷啟動僅載入獨立操作宿主；已執行例項不切換標籤或恢復主視窗。批次準備與等待輸入期間計入全域性活動數，建立成功不進入瀏覽開啟佇列。顯式顯示主視窗時再建立瀏覽視窗。
