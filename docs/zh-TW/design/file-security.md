# 檔案授權與安全寫出

[English](../../design/file-security.md) | [简体中文](../../zh-CN/design/file-security.md) | 繁體中文 | [日本語](../../ja-JP/design/file-security.md) | [한국어](../../ko-KR/design/file-security.md) | [Français](../../fr-FR/design/file-security.md) | [Deutsch](../../de-DE/design/file-security.md) | [Español](../../es-ES/design/file-security.md) | [Português (Brasil)](../../pt-BR/design/file-security.md) | [Русский](../../ru-RU/design/file-security.md)

由宿主決定可開啟哪些檔案，以及驗證後的內容可寫到哪裡。格式後端只能使用有界的讀取器和輸出接收器，獨立歸檔工作程序也遵循這一邊界。歸檔名稱、宣告大小、校驗和及內容都屬於輸入資料。宿主檔案檢查與格式校驗分別生效。[系統架構](system-architecture.md)、[歸檔工作程序協議](../engineering/native-codecs.md)

<a name="xdzip-来源与目标授权"></a>

## 來源與目標授權

- **歸檔來源。** `Source::open` 透過 `xdzip-io::open_regular_readonly` 開啟選定路徑，並核對實際開啟的檔案型別。Unix 以非阻塞方式開啟物件後再判斷型別，避免開啟命名管道時卡住。使用者選定的路徑可以經連結指向普通檔案。分卷探索依格式執行並受限額約束。宿主凍結允許讀取的相鄰分卷，核對其檔案身份和版本。編解碼器只能定位宿主提供的資料流。[來源實現](../../../crates/xdzip-runtime/src/source.rs)、[分卷處理](../engineering/archive-opening.md) 在本機 NTFS 上，可以編輯共用可寫入目錄中的封存檔，也可以編輯允許其他使用者存取的封存檔。替換檔案在受保護的私人目錄中準備，並保留原檔案的擁有者、存取規則與來源區域。繼承規則會變為受保護的明確規則，因此父目錄權限的後續變更不會自動傳遞。無法保留規則時，原封存檔維持不變。檔案識別、大小與時間會盡力偵測來源變化，替換作業並非對檔案內容的原子比較。
- **建立輸入。** `InputTree` 在後設資料與檔案身份限制內遍歷選定輸入。讀取時從目錄樹開啟對應成員並校驗版本。掃描時排除本次建立的私有暫存目錄，檢測到來源變化就停止作業。檔案身份、大小與時間資訊用於盡力檢測變化，無法據此獲得完整的內容快照。[輸入目錄樹](../../../crates/xdzip-io/src/input.rs)、[歸檔建立](../engineering/zip-creation.md)
- **寫出目標。** `Grant` 持有選定目錄物件及其身份。解壓把所有源分卷身份一併列為受保護檔案。建立和修改分別透過自己的任務路徑核對凍結輸入或原歸檔的身份。子目錄與暫存均透過已有目錄控制代碼訪問，提交前會重新核對父目錄身份。`CheckTarget` 和解壓預檢可以在任務開始前提供檢查結果，實際操作仍須重新校驗寫出授權。[目標授權](../../../crates/xdzip-io/src/target.rs)、[解壓預檢](../engineering/extraction-preflight.md)

<a name="xdzip-名称映射平台保护与链接"></a>

建立或解壓縮使用已檢查的目的地時，寫入工作會核對目錄身分與呼叫端確認的物件一致。壓縮檔輸入保留最初允許時的檔案身分。自動找到的分卷在開啟時禁止跟隨末層連結。Windows 就地編輯壓縮檔會保留原檔的擁有者、讀取權限和來源區域。若無法保留這些保護，原壓縮檔會留在原處。

## 名稱對映、平臺保護與連結

1. **校驗歸檔相對名稱。** 執行時解析凍結的選區，按需去掉所選子樹的字首，並使用 `PortablePath` 接受相對 UTF-8 路徑元件。絕對路徑、磁碟機代號路徑、控制字元、有歧義的分隔符、父目錄元件、裝置保留名及結尾空格或點都會被拒絕。透過語法檢查的名稱只作為目標授權的輸入。
2. **提前規劃名稱衝突。** 解壓計劃以小寫 NFD 鍵比較常見的大小寫和 Unicode 等價名稱。目錄拼寫歧義及檔案與目錄衝突會在準備時失敗。普通檔案的等價名稱對映到同一拼寫，由執行時執行重名策略。實際檔案系統上的名稱仍須透過原生排他釋出確認。顯示名稱與物理條目身份分開保留。
3. **沿已授權目錄樹訪問。** 輸出從持有的目錄能力出發，逐層開啟子目錄時拒絕跟隨連結。提交前重新檢查授權根、父目錄身份以及預期覆蓋的末級物件。目標被替換或遇到不安全連結時會拒絕。同卷重新命名前的最後檢查能縮小競態範圍，普通重新命名無法對同賬號程序提供內容級的比較交換保證。

| 平臺 | 對輸出物件的檢查 |
| --- | --- |
| Linux 與 macOS | 物件必須歸目前有效使用者所有，拒絕組或其他使用者的寫許可權，已有普通檔案必須只有一個硬連結。macOS 還檢查原生 ACL，包括可能繼承的修改許可權。 |
| Windows | 透過已持有物件檢查重解析點、所有者、檔案 ID、普通檔案硬連結數和 DACL。有效或僅繼承的訪問規則必須將修改許可權限定在受信任主體內。現有的唯讀共享可以保留。 上述本機 NTFS 封存檔編輯也允許共用寫入權限。 |
| 私有明文或臨時工作資料 | 額外執行保密檢查，排除無關讀取者。Windows 上可為排他建立的私有快取目錄設定受保護的 DACL。使用者選定的一般解壓目標保留自己的讀取共享策略。 |

ZIP 符號連結的輸出僅適用於透過校驗的 Unix 連結圖。執行時先驗證選區內的連結關係和要求不存在的末級物件，提交普通目標檔案後才釋出連結。任務寫出時不會跟隨歸檔建立的連結。其他不受支援的連結或特殊檔案會明確失敗。POSIX 普通檔案可在暫存時恢復安全的讀與執行位，並保留所有者讀寫許可權，排除特權位與其他主體的寫許可權。解壓路徑不會在提交後恢復時間戳。

## 暫存、驗證與提交

宿主使用目標授權在同一卷內排他建立私有工作區，按限額把後端輸出寫入暫存檔案。釋出前須完成解碼、核對預期大小，並透過格式提供的完整性或認證檢查。`Stage::finish` 排清緩衝並同步檔案，保留已校驗的版本。提交時宿主再次檢查暫存物件與目標。同步檔案資料以及單個檔案的原子可見性，無法保證斷電後目錄後設資料一定持久化。

| 操作 | 釋出語義 |
| --- | --- |
| 解壓或釋出檔案承諾 | 每個符合條件的檔案驗證後單獨釋出。無覆蓋時排他建立同卷硬連結，再清理私有暫存連結。允許覆蓋時，解壓須匹配預期且安全的普通檔案，透過同卷重新命名替換，避免先截斷。檔案承諾釋出始終禁止覆蓋。檔案系統缺少所需原語或目標發生變化時，相關寫入失敗。已提交檔案與已建立目錄不執行整單回滾。 |
| 建立單檔案歸檔 | 編碼到暫存後重新開啟，按照建立配置驗證預期條目及內容，再一次釋出整個歸檔。名稱衝突可以選擇新名稱或允許符合條件的替換。受保護的輸入不能成為覆蓋目標。 |
| 建立分卷 | 驗證暫存歸檔內容，將每一卷暫存後釋出為同一目錄下的新卷組，禁止覆蓋已有分卷。每卷分別變為可見。部分失敗時，回滾只嘗試移除身份仍匹配的本次新發布物件。回滾失敗可能使結果不確定。 |
| 修改已有歸檔 | `ArchiveUpdate` 繫結授權父目錄與預期的原歸檔版本。重新開啟並驗證已重寫的暫存歸檔後，透過這一授權一次替換原歸檔。普通解壓不能使用這種專用替換方式覆蓋自己的來源。 |

在取得提交許可前取消，目前提交不會開始。已經在執行的釋出可以完成並報告實際結果。先前提交的解壓檔案仍可見，最終快照可能在帶有提交記錄的同時報告 `cancelled`、`failed` 或清理警告。整包成功釋出後，遲到的取消不會改寫成功結果。[任務取消](task-scheduling.md)、[歸檔修改](../engineering/archive-transfers.md)、[安全解壓](../engineering/zip-safe-extraction.md)

## 輸出預算與完整性範圍

解壓分別限制宣告輸出與實際輸出，普通檔案上限為 8 GiB，任務上限為 20 GiB。支援的格式會在准入時檢查高壓縮比。ZIP 中超過 1 MiB 且宣告壓縮比超過 1,000 比 1 的條目需要顯式允許，但硬性額度仍然有效。固實或流式後端可能需要處理未選中的資料。相關工作量、重複讀取或重試以及輔助解碼消耗，與釋出位元組數分別計量。

後設資料瀏覽、任務准入、工作程序記憶體和預覽各自有預算。較大的 ZIP 磁碟索引不會提高解壓或寫入限額。完整性檢查的範圍取決於格式。例如，ISO/UDF 的結構與可讀性檢查無法補足格式沒有提供的逐檔案校驗和。[大型歸檔索引](../engineering/large-index.md)、[完整性檢查](../engineering/archive-checking.md)、[輔助解碼計量](../engineering/auxiliary-decoding-work.md)

## 預覽、臨時開啟與密碼

- **預覽。** 屬性卡可見時，選取單一支援的檔案會自動開始預覽。Rust 在限額內完整讀取並驗證條目。文字上限為 256 KiB，編碼圖片上限為 16 MiB，原圖尺寸和畫素數另有限制。專用圖片程序接收位元組並返回受限縮圖，接收的資料中沒有歸檔名稱、密碼或目標控制代碼。目前格式及限制見[預覽契約](../engineering/content-preview.md)。
- **臨時開啟。** 普通條目按任務的常規驗證規則解壓到私有快取。桌面以本地 URL 將驗證後的檔案交給系統關聯應用。系統接受交接請求並不表示外部程式已讀完檔案。保留期滿後，後續操作會核對快取身份與鎖並清理。編輯臨時副本與原歸檔的內容相互獨立。[臨時開啟](../engineering/archive-opening.md)、[歸檔傳輸](../engineering/archive-transfers.md)
- **密碼。** 開啟和解壓密碼在會話或任務存續期間儲存在對應操作且釋放時會清零的容器中，不進入任務快照或暫存日誌。使用者資料的本地存放、保留與披露規則見[隱私工程契約](../engineering/privacy.md)和[密碼契約](../engineering/password-extraction.md)。

<a name="xdzip-日志遗留文件与验证"></a>

## 日誌、遺留檔案與驗證

暫存日誌在準備與提交時記錄任務上下文和相對輸出名稱。正常清理核對所有權與身份，只刪除已知的暫存物件。異常終止後，私有日誌與遺留物件可用於判斷實際情況。執行時檢查目標時會統計可能存在的遺留工作區，不根據發現的日誌重放寫入或刪除未知內容。私有臨時輸出的過期清理另有身份和鎖檢查。

修改這一邊界時，要核對實際提交及清理結果和錯誤碼。[I/O 測試](../../../crates/xdzip-io/src/tests.rs)、[解壓測試](../../../crates/xdzip-runtime/src/extraction/tests.rs)和[安全解壓契約](../engineering/zip-safe-extraction.md)分別覆蓋不同層級。改動涉及原生平臺行為時，需要對應平臺的驗證證據。
