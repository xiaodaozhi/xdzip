# 效能設計與測量

[English](../../design/performance.md) | [简体中文](../../zh-CN/design/performance.md) | 繁體中文（台灣）

XDZip 分別約束索引、傳輸、任務執行和圖片預覽的記憶體與工作量。下面的程式碼限額屬於實現規則。耗時、記憶體和吞吐資料取決於構建和工作負載，後文的參考指標是設計目標。

<a name="xdzip-当前代码中的限额与机制"></a>

## 目前程式碼中的限額與機制

| 範圍 | 目前行為與資源開銷 |
| --- | --- |
| 普通單檔案 ZIP/ZIP64 | 流式掃描最多接收一百萬條物理記錄，還受名稱、中央目錄和讀取預算限制。熱後設資料超過 64 MiB，或新增記錄會使常駐條目超過十萬條時，將記錄遷入私有磁碟儲存。後設資料檔案上限為 512 MiB，另有位置表。瀏覽掃描後設資料。 |
| 記憶體和磁碟查詢 | 執行時一次建立目前不可變結果的順序。磁碟路徑生成每段最多 8 MiB 的排序段，再歸併為條目令牌順序。名稱與排序儲存均受限。快取儲存目前查詢，介面的渲染結果及查詢歷史另有生命週期。 |
| 導航與 Qt 傳輸 | 目錄樹限制為 32,768 個節點、64 層與 4 MiB 名稱資料。目錄樹超額時仍可保留根目錄瀏覽和搜尋。橋接每頁最多傳 128 行及 64 KiB 名稱資料。大結果最多常駐 1,024 行，邏輯行數覆蓋完整結果。 |
| 命令、任務與寫出 | 後設資料執行緒與任務執行緒分別使用有界佇列。桌面重任務逐個准入。解碼工作量、輸出位元組數、檔案提交和工作程序資源分別計量。固實或流式格式在到達選中項前可能要讀取或解碼前置資料。 |
| 預覽與原生工作程序 | 文字與圖片編碼資料有各自的位元組上限。圖片尺寸、畫素數、解碼程序執行和縮圖大小獨立受限。格式工作程序遵守自己的協議及程序限額。 |

[磁碟索引實現](../../../crates/xdzip-runtime/src/disk_index.rs)、[大型歸檔索引](../engineering/large-index.md)、[Qt/Rust 橋接限額](qt-rust-bridge.md)、[任務准入](task-scheduling.md)、[輸出預算](file-security.md)、[預覽限額](../engineering/content-preview.md)

記憶體開銷包含 Qt、字型、渲染與模型、歸檔後設資料、位置表和查詢緩衝、解碼器狀態、子程序及 I/O 緩衝。64 MiB 是後設資料遷移閾值，程序樹記憶體還包含索引以外的開銷。擴大的後設資料准入不會提高解壓配額，使用磁碟索引的會話也無法執行整包測試或修改。私有索引寫入和解壓暫存分別產生磁碟開銷。

<a name="xdzip-测量当前实现"></a>

## 測量目前實現

| 入口 | 測量或驗證的範圍 |
| --- | --- |
| `scripts/probe-large-index.py` 與 `xdzip-m2-probe` | 生成專案自有 ZIP64，執行真實掃描、排序和分頁查詢，分別報告各階段與儲存。場景包含重複名稱、長名稱和目錄結構，並記錄是否進入磁碟路徑。 |
| `scripts/measure-desktop.py` 與 `xdzip-process-metrics` | 測量桌面程序樹、啟動和瀏覽。啟用解壓選項時驅動真實解壓，並獨立驗證輸出位元組。記錄渲染後端、構建身份和實際負載。 |
| `scripts/run-performance-suite.py` | 收集 Release 構建的啟動、穩定空閒與瀏覽觀測，並使用自有樣本與鎖定的核心探針比較解壓。報告記錄構建及樣本身份。這是一項觀測性比較，參考機器驗收是獨立條件。 |
| `scripts/check-runtime-resources.py` | 檢查探針返回的執行時資源及字型回執，說明本次探針的資源身份和覆蓋範圍。互動耗時由獨立測量入口獲取。 |

[大索引探針](../../../scripts/probe-large-index.py)、[桌面測量](../../../scripts/measure-desktop.py)、[效能套件](../../../scripts/run-performance-suite.py)、[執行時資源探針](../../../scripts/check-runtime-resources.py)、[證據採集](../../../developers/engineering/candidate-verification.md#performance-and-resource-evidence)

比較時記錄提交與構建配置、系統與架構、渲染後端、硬體、輪次、樣本、裝置和快取條件，區分冷啟動和重複啟動。測量條件允許時，分別報告首次互動、歸檔掃描、查詢排序、頁面傳輸及介面可見的時間。區分取消意見回饋與實際停止及清理。吞吐報告分別說明輸入、解碼和已提交的位元組數。

程序樹工具分別標註 Linux PSS、macOS 實體記憶體佔用和 Windows 私有已提交記憶體，並在可用時報告 RSS 或工作集。比較時採用相同指標及相近條件。真實安裝包的下載大小和安裝後大小分別記錄。離屏和原型測量只說明各自環境下的觀測。

<a name="xdzip-对比测试负载"></a>

## 對比測試負載

| 負載 | 測量內容 |
| --- | --- |
| B01/B08 空視窗、空閒和主題切換 | 啟動與幀耗時、空閒 CPU、保留記憶體與渲染後端。 |
| B02 十萬與一百萬條 ZIP 記錄 | 後設資料掃描、遷移、排序、分頁獲取，並分別記錄記憶體與磁碟開銷。 |
| B03/B04 一個大型普通檔案或大量小檔案 | 吞吐、取消、目標檔案操作、同步及清理。小檔案耗時可能主要來自檔案操作。 |
| B05/B06 高壓縮比內容或長流末端的條目 | 配額處理與到達所選條目之前額外消耗的解碼工作。 |
| B07 有重任務排隊時瀏覽 | 一個重操作執行、另一個等待期間的搜尋與分頁耗時。 |
| B09 隨包工作程序及完整安裝包 | 程序樹開銷、協議成本、下載體積與安裝體積。 |

這些是對比場景。選用與變更對應的負載，使用專案自有樣本，並記錄大小和雜湊。

<a name="xdzip-参考目标与后续研究"></a>

## 參考目標與後續研究

既有設計以配備 16 GiB 記憶體、本地 SSD、60 Hz 顯示器的 Apple Silicon 為參考，使用系統字型、實際 GPU 和 Release 構建。下列目標用於可比條件下的測量。最新版本與其他平臺的實際表現需要各自的觀測。

| 場景 | 設計目標 |
| --- | --- |
| 空視窗重複啟動 | 至少 30 輪後，到可互動幀的 P95 不超過 500 毫秒 |
| 開啟並查詢快取中的十萬條 ZIP 記錄 | 後設資料準備 P95 不超過 1 秒，已有索引的查詢到可見 P95 不超過 80 毫秒 |
| 熱頁跳轉與介面排程 | 頁面跳轉到可見的 P95 不超過 50 毫秒，介面執行緒連續阻塞的 P95 不超過 8 毫秒 |
| 記憶體 | 程序樹空視窗目標不超過 150 MiB，瀏覽十萬條記錄且無預覽和解碼字典時不超過 256 MiB |
| 空閒 CPU | 穩定後平均不超過單個邏輯核心的 0.5% |
| 取消 | 分別測量意見回饋和本地流式協作停止，P95 目標依次為 50 和 250 毫秒 |
| 解壓與分發 | 以相同負載和 I/O 設定比較桌面與核心，吞吐損耗目標不超過 10%。Mac 單架構包的下載和安裝體積目標分別為 100 MiB 與 250 MiB。 |

按塊並行解壓、跨會話持久化複用索引，以及共享 CPU 令牌排程仍是設計選項。調整併發或儲存前，先分析目前序列任務及記憶體、磁碟路徑。比較時保持相同的位元組驗證、取消和安全提交條件。[架構演進](architecture-evolution.md)、[檔案提交](file-security.md)
