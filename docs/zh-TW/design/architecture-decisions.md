早期記錄日期為 2026-10-11，後續記錄各自注明日期。已採用表示架構決策生效。各段的目前實現說明將決策關聯到維護中的契約及能力依據。替代舊決策時，保留原記錄並追加新記錄。

<a name="xdzip-adr-001qt-quick-作为唯一产品界面"></a>

## ADR-001：Qt Quick 作為唯一產品介面

**狀態：Accepted。**

**目前實現。** 桌面已採用 Qt Quick/QML 與薄 C++ 適配層。Windows SFX 的系統對話方塊宿主屬於 ADR-013 中的有限例外。[桌面介面](qt-quick-ui.md)

背景：產品要求現代桌面 UI、統一體驗和低佔用；已完成 Slint、Tauri、Qt Quick 的同核心原型。結合介面能力、統一體驗與現有 Linux 軟體渲染資料，專案選定 Qt Quick 進入產品階段；其他平臺表現仍需驗證。

決定：Qt Quick/QML + Qt Quick Controls 2，C++ 薄適配。Slint/Tauri 作為歷史實驗保留，不打包進產品。

代價：承擔 Qt 執行庫、QML 模組、跨語言構建和許可工作；Mac/Windows 輸入、無障礙、GPU 和部署必須補測。不能把 0.80MiB 原型程式當 Qt 完整安裝包。

重新評估觸發：Qt 目標平臺無法滿足必要功能/許可/安全維護，且經過實際最佳化仍無法達到核心產品預算。普通效能波動不觸發重複框架選型。

<a name="xdzip-adr-002rust-持有全部归档业务"></a>

## ADR-002：Rust 持有全部歸檔業務

**狀態：Accepted。**

**目前實現。** Rust 執行時持有歸檔狀態與任務。檔案選擇屬於桌面意圖，由宿主 I/O 層執行檔案系統授權。[系統架構](system-architecture.md)

決定：領域、索引、計劃、任務、配額、路徑策略和格式登錄檔在 Rust；Qt 只表示狀態、授權系統檔案選擇和使用者決定。業務測試不需 Qt。

替代方案：把 libarchive/7zip 直接接到 C++/QML，或在每個 UI 中重複控制邏輯。代價是核心與平臺 UI 耦合，無法一致驗證安全/取消。Rust 也不免除原生庫安全風險，相關庫可工作程序隔離。

重新評估觸發：某個平臺 API 無法在 Rust 可靠實現時，允許小型平臺 C++ port，不改變業務所有權。

<a name="xdzip-adr-003构建期-cxx-桥接"></a>

## ADR-003：構建期 cxx 橋接

**狀態：已採用。**

**目前實現。** 產品已構建並使用型別化橋接，命令和事件使用獨立控制代碼。事件接收器及關閉生命週期見[橋接契約](qt-rust-bridge.md)。

決定：產品內部用 cxx 生成的型別安全橋接，同提交構建；不維護長期手寫 C ABI，不在熱點路徑 JSON 序列化。橋接不含 Qt 業務。

替代方案：沿用實驗 C ABI、使用 CXX-Qt 自動生成 QObject、透過本地 IPC 連線 GUI 和整個核心。cxx 保留明確的 Qt 模型和執行緒邊界，避免首階段依賴額外 QObject 生成框架；代價是自行維護薄 QObject 層和 CMake/Cargo 編排。

不承諾：cxx 不提供跨任意 Rust/Qt 版本的動態二進位制相容，也不生成第三方格式協議。

重新評估觸發：受支援平臺的桌面構建或生命週期驗證失敗，或適配層明顯膨脹。屆時以 ADR 評估 CXX-Qt 或顯式版本化 C ABI，不默默切換。

<a name="xdzip-adr-004内置源码-sdk-与外部进程协议分离"></a>

## ADR-004：內建原始碼 SDK 與外部程序協議分離

**狀態：已採用該設計邊界，外部協議仍為試驗。**

**目前實現。** 產品格式透過顯式註冊內建。隨包格式工作程序使用自己的協議，外部 CBOR 實現是獨立的只讀試驗。[格式介面卡與擴充套件試驗](codec-extension-sdk.md)

決定：內建格式採用 Rust 原始碼介面，外部擴充套件采用獨立且有界的程序協議。I/O 授權仍由宿主持有。

原因：Rust 動態庫 ABI 不穩定；任意程序內原生外掛破壞崩潰隔離和資源治理。採用 Wasm 作為通用格式執行時暫不優先，原因是現有原生 codec 遷移、執行緒、seek 和效能驗證成本，不否認其未來用途。

代價：協議、broker、沙箱和 IPC 開銷。協議需兩個獨立實現互通後凍結。

<a name="xdzip-adr-005宿主集中控制真实文件写入"></a>

## ADR-005：宿主集中控制真實檔案寫入

**狀態：Accepted。**

**目前實現。** 執行時準備操作，`xdzip-io` 持有授權、暫存和提交，格式介面卡使用讀取器和接收器。[檔案授權](file-security.md)

決定：後端只寫被批准的 OutputSink，真實路徑、衝突、暫存和提交由宿主控制。禁止直接呼叫庫的通用 unpack 到任意目錄，除非完整驗證其埠已受宿主約束。

原因：各格式重複實現路徑保護很容易出現差異；僅檢查字串無法阻止連結/競態。代價是自己實現三個平臺檔案安全層和故障測試。

不承諾：宿主能證明惡意外掛輸出內容語義正確，或阻止同使用者已被控制的惡意程序。外掛信任和許可權仍需明確。

<a name="xdzip-adr-006按文件提交解压整体提交新建归档"></a>

## ADR-006：按檔案提交解壓，整體提交新建歸檔

**狀態：Accepted。**

**目前實現。** 解壓逐檔案釋出。建立和修改在釋出或替換前驗證暫存歸檔。分卷建立驗證後逐個釋出，部分失敗時執行受限回滾。[提交語義](file-security.md)

決定：解壓各檔案先暫存校驗再發布，任務失敗可保留部分完成；新歸檔整體寫完再發布。預設不覆蓋。

原因：合併進現有目錄無法跨平臺簡單提供真正全目錄原子事務；假裝全任務回滾會誤刪使用者後續修改。代價是詳細結果和恢復日誌，取消語義需要講清。

重新評估觸發：新增“全新目錄整體釋出”模式，可在受限條件下獨立實現，不改變已有目錄合併語義。

<a name="xdzip-adr-007有界-actor工作池和事件推送"></a>

## ADR-007：有界 actor/工作池和事件推送

**狀態：Accepted。**

**目前實現。** 目前每個連線使用獨立的命令和任務執行緒，桌面序列准入重任務，Rust 佇列與 Qt 郵箱均有界。通用資源令牌池仍是設計選項。[任務排程](task-scheduling.md)、[Qt/Rust 橋接](qt-rust-bridge.md)

決定：輕量排程器決定狀態，有界池執行工作；Qt 獨立事件接收執行緒，進度合併、終態必達；取消和 shutdown 有獨立控制准入。

替代方案：GUI 同步呼叫、每檔案一個執行緒、無限 Tokio/spawn_blocking、常駐輪詢。歸檔主要是同步 CPU/I/O，不因“非同步”字樣引入無限任務；未來真正網路 I/O 可區域性使用非同步執行時。

代價：明確背壓、關閉和資源 lease；收益是空閒低佔用、不會被任務淹沒 GUI。

<a name="xdzip-adr-008能力驱动首版限制格式"></a>

## ADR-008：能力驅動，首版限制格式

**狀態：Accepted。**

**目前實現。** 首批格式是歷史背景。目前原始碼能力由維護中的登錄檔與執行時准入決定，包含後續擴充套件的讀取與建立配置，以及各操作自己的限制。[格式登錄檔](../engineering/format-registry.md)

決定：v0.1 ZIP Store/Deflate 和 TAR/GZIP；加密、分卷、RAR、7z 與額外演算法逐項驗證。UI 不按字尾推斷完整支援。

原因：格式名稱不能描述所有實際特性。代價是首版格式表較短，收益是對使用者誠實且可驗證。

<a name="xdzip-adr-009小型产品数据与用户内容分离"></a>

## ADR-009：小型產品資料與使用者內容分離

**狀態：Accepted。**

**目前實現。** 設定、索引和暫存日誌有獨立生命週期。磁碟索引是會話私有資料。持久複用索引及重放未完成作業仍是設計選項。[領域模型](domain-data.md)、[檔案提交](file-security.md)

決定：設定、臨時索引、事務日誌和擴充套件清單分生命週期管理。預設無遙測、不持久密碼、不跨啟動快取歸檔索引。

代價：多種 schema 和清理規則。重新評估跨啟動索引時需新增源身份、失效、隱私與容量設計。

<a name="xdzip-adr-010完整分发和许可进入架构门槛"></a>

## ADR-010：完整分發和許可進入架構門檻

**狀態：Accepted。**

**目前實現。** GitHub 二進位制包與 Microsoft Store MSIX 現已使用各自文件中的打包渠道，按渠道核對實際部署依賴、工件完整性和許可材料。[構建與發行](build-release.md)

決定：Qt 預設動態部署，準確模組許可審查；安裝體積包含執行庫；簽名、SBOM、替換/原始碼義務進入釋出檢查。

替代方案：只比較 executable 或釋出前才補 LICENSE。它們不能證明產品小或可合法分發。

代價：部署和許可持續維護。Qt 靜態構建或商店發行需單獨 ADR 與許可審查，不能由 size 最佳化 PR 順手改變。

<a name="xdzip-adr-011首批支持范围与个人项目维护政策"></a>

## ADR-011：首批支援範圍與個人專案維護政策

**狀態：Accepted，2026-10-19，由專案所有者明確批准。**

**目前實現。** 目前支援範圍及更新行為見[支援政策](../engineering/support-policy.md)和[更新契約](../engineering/software-update.md)。手動更新條款描述 v0.1。

決定：首批支援 macOS 14 及以上 Apple Silicon arm64、仍受維護的 Windows 11 x86_64，以及 Ubuntu 24.04 LTS x86_64、X11、glibc 2.39 及以上。只優先維護最新公開版本，盡力處理意見回饋，不承諾固定響應時限；v0.1 手動下載更新，開發預覽保持實驗性。詳見[支援政策](../engineering/support-policy.md)。

原因：以現有原生構建、安裝器和執行依賴為邊界，收窄舊設計未驗證的系統與架構承諾，符合個人開源專案的維護能力。代價是不承諾 Intel Mac、Windows 10、ARM64 Windows/Linux、其他發行版或 Wayland。擴大範圍須先補充實現與實測。

邊界：個人 GitHub 開源發行不要求付費開發者賬號、簽名證書、Developer ID 或公證，macOS 保留必需的 ad-hoc 完整性；該政策不代替許可來源與包驗證，也不推斷所有未來系統版本相容。

<a name="xdzip-adr-012逐格式迁移至独立-rust-格式与压缩算法实现"></a>

## ADR-012：逐格式遷移至獨立 Rust 格式與壓縮演算法實現

**狀態：Accepted，2026-10-25，由專案所有者明確批准實施。替代第三方格式引擎的長期選型，不表示遷移已經完成。**

**目前實現。** 目前產品路由使用 Rust 格式實現。適用的 7z、RAR、CAB 和光碟映象讀取走隨包工作程序，目前也有程序內 ISO 寫入器。具體操作見[格式登錄檔](../engineering/format-registry.md)和[介面卡設計](codec-extension-sdk.md)。

決定：格式解析及壓縮、解壓演算法採用獨立 Rust 實現，允許通用密碼學、字元編碼和系統基礎庫。依據官方規範先定義行為規格，再獨立實現，參考原始碼不逐行轉換或改名複製。已經接觸原始碼的開發者不宣稱嚴格潔淨室開發；來源不足及許可限制需單獨審查，尤其不開發 RAR 編碼器。

遷移方案按當時的能力逐個驗收並替換 ZIP、TAR、TAR.GZ、7z、RAR、CAB、ISO 和 UDF。未達標格式保留目前實現，不靜默回退，不擴大 RAR/CAB/ISO/UDF 的只讀範圍。共享壓縮演算法複用，名稱、身份、授權 I/O、資源、取消和提交繼續由 Rust 宿主管理；工作程序隔離不因改為 Rust 而取消。

代價：獨立承擔相容性、安全、效能、模糊測試及長期演算法維護。第三方參照可用於測試，但完成遷移的格式須從產品依賴和交付檔案中移除對應引擎。來源與介面規則見[自研後端契約](../engineering/independent-rust-codecs.md)，進展與實際驗收在 [#45](https://github.com/xiaodaozhi/xdzip/issues/45)登記。

<a name="xdzip-adr-013-独立-windows-sfx-宿主"></a>

## ADR-013: 獨立 Windows SFX 宿主

**狀態：按所有者授權的首版 SFX 範圍採用，2026-11-16。**

**目前實現。** [SFX 契約](../engineering/sfx-creation.md)說明 Windows 配置與獨立的 Rust 和系統對話方塊入口。

背景：生成的 Windows x64 自解壓包必須無需安裝 xdzip 或 Qt 即可工作。每個歸檔附帶另一套完整 Qt 應用會增加獨立的部署執行時。

決定：桌面繼續使用 Qt Quick 並複用現有建立視窗。自有獨立 SFX 程式僅使用 Windows 系統目錄和任務對話方塊，字型、DPI、尺寸及輔助功能由系統控制。ZIP、校驗、輸出授權、衝突、進度、取消和清理繼續使用現有 Rust 核心。這是 ADR-001 的有限發行宿主例外，不是另一套桌面框架或自定義控制元件庫。

成本：維護並自動化驗證一個額外的 Windows 可執行程式、版本化封裝、靜態 CRT 連結、無 Qt 依賴審計和原生對話方塊宿主。絕不執行解壓內容。為生成檔案簽名與為固定解壓程式簽名分開處理。

重新評估觸發條件：安裝器、自動執行載荷、其他可執行平臺或自定義 SFX 介面須另行確定範圍並評審架構。
