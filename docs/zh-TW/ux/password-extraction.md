# 密碼解壓互動

[English](../../ux/password-extraction.md) | [简体中文](../../zh-CN/ux/password-extraction.md) | 繁體中文 | [日本語](../../ja-JP/ux/password-extraction.md) | [한국어](../../ko-KR/ux/password-extraction.md) | [Français](../../fr-FR/ux/password-extraction.md) | [Deutsch](../../de-DE/ux/password-extraction.md) | [Español](../../es-ES/ux/password-extraction.md) | [Português (Brasil)](../../pt-BR/ux/password-extraction.md) | [Русский](../../ru-RU/ux/password-extraction.md)

受支援的 ZIP、7z 和 RAR 任務在遇到需要密碼的條目時進入 `waiting_password`。執行時釋出帶任務 ID 和請求 ID 的密碼請求；QML 只表達輸入與取消意圖，不負責解密、認證或檔案提交。密碼請求與重名衝突是不同狀態，不能把密碼請求交給重名視窗。格式、認證、重試次數及輸出邊界以[工程契約](../engineering/password-extraction.md)為準。

7z 或 RAR 的檔名加密在開啟階段請求密碼，複用同一 PasswordWindow。此時顯示“開啟密碼”“繼續開啟”，說明關閉只取消目前開啟，不生成解壓或檢查任務。開啟請求使用獨立的 `open` 身份和遞增請求 ID，舊請求不能向新開啟提交密碼；在完整掃描前不展示部分檔案列表。開啟密碼與內容密碼都不持久儲存。

7z 返回 `password_or_integrity` 時，同一密碼窗顯示“密碼不匹配或加密資料損壞，請重試。”，英文為“The password does not match or the encrypted data is damaged. Try again.”。它不能確認密碼一定錯誤，也不意味著重新輸入必能修復損壞；使用者仍可取消。任務重試沿用現有限額，達到上限仍保留這一不確定錯誤分類，不顯示成已證實的密碼驗證失敗。

PasswordWindow 使用應用程式強制回應視窗及現有系統標題列，內容區寬 491，最高 600，並受目前螢幕的可用高度限制。標題字級為 20、正文為 13、輔助說明為 12。正文會隨內容增長或獨立捲動，底部按鈕保持可操作。尺寸來自 [password-reference.json](../../../specs/visual/password-reference.json)，高擬真依據為 P02 獨立狀態設計。所有支援的介面語言、淺色和深色主題，以及 100%／125%／150% 字級都採用相同的尺寸規則。

視窗顯示目前加密條目的名稱、密碼輸入框、顯示／隱藏密碼動作與目前任務範圍說明。顯示動作使用明確文字和可讀名稱，不增加包含密碼的提示。輸入預設為掩碼；提交後、取消、視窗關閉或請求 ID 改變時，清空輸入並恢復掩碼。密碼不寫入設定、剪貼簿、日誌、任務快照或報告。UI 的字串清理不宣稱可擦除 Qt 記憶體中的所有歷史副本，底層秘密容器的生命週期由執行時契約約束。

外來壓縮檔的密碼可以為空，也可以包含控制字元。不要移除前後空白，或套用建立密碼的 1–128 位元組限制。解壓縮密碼上限為 1,024 個 UTF-8 位元組，輸入框最多接受 1,024 個 UTF-16 單元，並在提交前檢查 UTF-8 位元組數。後端會再次檢查。超出限制時顯示實際錯誤並保留輸入，供使用者修改。重試請求使用新的請求 ID，清空舊輸入並顯示「密碼不匹配或加密資料損壞，請重試。」。

繼續解壓向控制器提交精確的任務 ID、請求 ID 和原始密碼。提交獲接收後立即清空欄位、恢復掩碼並禁止重複提交，視窗等待任務快照確認離開該請求後關閉。過期、取消或重複請求不能提交到其他任務；立即拒絕時保留目前有效請求和輸入，允許重試。並行任務的請求由控制器依次呈現，不能用後來的請求靜默覆蓋尚未處理的任務。

點選“取消任務”或關閉原生視窗取消視窗對應的目前任務，不把任務留在不可發現的等待狀態。Escape 遵循應用共享焦點策略，第一次退出目前控制元件焦點，之後關閉視窗並取消任務。Return／Enter 在密碼欄位中提交目前密碼，仍受同一請求身份、長度和 pending 檢查；按鈕保留既有鍵盤啟用語義。任務視窗的“等待輸入密碼”狀態保留真實進度並提供重開請求動作；終止任務清除相關密碼請求。

設計演示只使用空欄位和自有示例檔名，不讀取真實壓縮檔，不驗證密碼。自動化必須核對輸入掩碼、空密碼、非 ASCII 位元組邊界、拒絕和重複提交、請求替換、取消與關閉，以及小屏滾動與固定 footer；功能透過與原生視覺驗收分別記錄。
