# 任務視窗與完整性檢查

[English](../../ux/task-windows.md) | [简体中文](../../zh-CN/ux/task-windows.md) | 繁體中文（台灣） | [日本語](../../ja-JP/ux/task-windows.md) | [한국어](../../ko-KR/ux/task-windows.md) | [Français](../../fr-FR/ux/task-windows.md) | [Deutsch](../../de-DE/ux/task-windows.md) | [Español](../../es-ES/ux/task-windows.md) | [Português (Brasil)](../../pt-BR/ux/task-windows.md) | [Русский](../../ru-RU/ux/task-windows.md)

任務進行中的“目前檔案”固定為單行，中間省略，保留路徑開頭和檔名末尾。完整純文字路徑仍保留在資料與輔助功能名稱中；相同狀態和字號下，路徑長度不能改變卡片或視窗高度。其他路徑卡片及終態說明仍可換行。普通解壓結果摘要僅顯示“已處理 N 個檔案”，數量取自 committedFiles，不依賴有界明細列表；零檔案明確顯示為零，不計入跳過或未完成項。壓縮結果摘要僅顯示“N 個檔案”，不顯示名稱或容量。普通壓縮按 outputParts 統計實際輸出檔案，包括分卷；批次壓縮按成功完成的壓縮任務數統計；批次解壓也僅顯示“N 個檔案”，按成功完成的解壓任務數統計，不拼接歸檔名稱或容量。批次統計每行三列，預設顯示已完成、未完成和已取消；點選居中的向下箭頭展開其餘計數，再次點選向上箭頭收起；按鈕保留懸停說明和可讀的輔助功能名稱。切換任務時恢復摺疊，同一任務更新保留展開狀態。批次壓縮結果不顯示卷組去重計數，批次解壓結果將同一分卷組中重複選擇而跳過的檔案計為“同組跳過”。壓縮和解壓結果的未完成檔案及其原因統一在可展開的處理明細中顯示，任務級錯誤仍單獨提示。

應用任務入口聚合所有會話，以會話 UUID 和後端任務 ID 路由進度、密碼、衝突和結果。關閉頁面保留所屬控制器，顯式退出等待全部非同步 join，見[應用會話契約](../engineering/application-sessions.md)。

任務選單一行依次顯示操作圖示、歸檔檔名、序號標籤、狀態標籤。圖示按建立、解壓、檢查、新增、移動和匯出選擇共享素材，不顯示操作型別文字字首；兩種標籤使用同一元件，序號保留後端編號，跨會話內部身份不變。長檔名省略，無障礙名稱仍包含操作型別、序號、檔名和狀態。

`ExtractWindow` 和 `CreateWindow` 單獨展示操作草稿。每個歸檔會話的 `OperationTasks` 管理一個 `TaskWindow`，選擇任務後繫結快照，完成後在同一視窗展示結果。關閉視窗後任務繼續執行。獨立的檔案管理器操作如果會因此失去唯一的活動任務入口，可以重新顯示任務視窗。系統接受臨時檔案的開啟請求後，任務視窗隱藏。交接失敗時仍可開啟結果並重試。見[臨時開啟](../engineering/archive-opening.md)。

建立格式與級別由[內建格式登記](../engineering/format-registry.md)提供，其中包括獨立壓縮流、ISO 資料映像和 Windows x64 的 ZIP 自解壓包。7z 預設使用正常級別的 LZMA2，另有固實、內容加密、檔名加密及分卷選項。啟用檔名加密須先啟用內容加密。切換格式時清理原格式選項，控制元件仍放在可滾動的正文中。

完整性檢查複用同一 TaskWindow 佈局，真實工具欄“測試”提交整包只讀背景任務，按 `kind=check` 展示讀取、密碼等待、取消和終態。檢查物件不受目前選擇影響，首錯停止，已驗證與未檢查檔案數分別顯示，不把解壓或建立的提交計數當作檢查數量。格式與安全邊界見[檢查契約](../engineering/archive-checking.md)。元件開發預覽仍提供獨立的 IntegrityWindow，並明確標記“介面預覽，不執行實際校驗”。

HTML 的檢查按鈕執行明確標註的介面演示。關閉或返回瀏覽保留演示狀態，重新開啟顯示目前進度；取消結束演示，終態不得繼續推進。完成、取消使用同一結構和頁尾。物件路徑、讀取位元組、檔案數、讀取速度、剩餘估算、階段和目前條目是資料槽位，不在 UI 中掃描、讀取或解壓檔案。示例數字不是真實檢查結果。

視窗的寬度、密度、字號、圓角、邊框、進度條、圖示槽和說明對齊來自 [視覺規範](../visual/design-standard.md)與 [凍結原稿](../../../specs/visual/integrity-reference.json)。未知總量不顯示確定百分比；大字號允許正文滾動，頁尾保持可操作。關閉不會發出取消訊號；取消動作顯式發出取消請求。檢查終態不得顯示已儲存檔案或開啟目標資料夾。

高保真原稿為 [完整性檢查進度](../../../design/hifi/screens/integrity-progress.png)，執行圖示為統一素材庫的 document-check。原稿裁剪只作參考，動態介面使用共享元件。

<a name="xdzip-正常尺寸与任务发现"></a>

## 正常尺寸與任務發現

帶圖示、標題、副標題的建立、新增、解壓、任務與結果、衝突、設定、關於視窗，共用 OperationHeader。基準為 48 邏輯單位的圖示槽、標題 20、副標題 13、正常高度 96；長文案與大字號按共享字型度量增高，正文繼續滾動，頁尾不隨之移動。文字型密碼、預檢與退出／重啟確認不憑空新增裝飾圖示。引數、獨立狀態稿與登記見[視覺規範](../visual/design-standard.md)。

任務按鈕右側保留上下箭頭。應用內任務選單最高 360 邏輯畫素，同時受目前視窗可用高度約束；歷史列表內部滾動，底部清除按鈕固定可達。清除僅隱藏已完成、失敗或已取消的任務歷史；執行、排隊、等待密碼／衝突、取消與清理中的任務保留。沒有可清除歷史時按鈕禁用。動作不取消任務，不刪除源歸檔或使用者輸出，不改變任務的原始控制器或退出屏障。清除後關閉已被隱藏的結果視窗，不顯示空快照。

清除按鈕位於選單的可互動內容層，不放在只用於繪製的背景層；滑鼠、鍵盤與原生輔助功能必須執行同一清除動作。分隔線上下各保留 4 邏輯單位，按鈕底部僅使用共享選單內距，不疊加額外的頁尾留白。任務選單項的左右內距與上下內距相同，狀態標記右對齊可用行內容，僅列表實際溢位時預留捲軸寬度。任務名稱根據原快照的kind區分檢查、解壓、建立、新增、移動與匯出，不用解壓作為所有非建立任務的名稱；點選仍按完整任務身份開啟原控制器，不將檢查任務改路由為解壓。


2026-10-15 修訂：建立、解壓與共享任務窗寬度統一為 491 邏輯畫素。進度和結果按內容自適應高度，最多 600；明細摺疊時不保留展開空間，展開列表最多 168。切換任務 ID 清空明細展開狀態，同一任務的進度更新不重置使用者選擇。檔案已存在視窗同寬，最高 560，沿用正常密度和共享頁尾。尺寸修訂不改變原生獨立視窗及取消語義。

狀態列任務按鈕顯示全應用保留的任務條目數。活動任務數另用於提示和退出判斷。單個控制器的任務記錄超過 64 條時，移除可以清理的終態記錄。重新開啟任務時繼續使用會話 UUID 和任務 ID，原瀏覽頁已關閉時也一樣。

任務發現列表以任務 ID 保持條目身份。進度與狀態變化在原條目更新，不重建整張列表，不中斷滑鼠懸停、高亮或鍵盤焦點；新增任務、淘汰歷史時只插入或移除對應條目，保留其餘條目的身份和選擇。排序仍為任務 ID 倒序，點選或鍵盤啟用始終重開對應 ID 的任務。QML 使用的資料模型只是任務歷史的介面投影，不改變任務快照、取消、提交、終態或退出屏障語義。

此更新不改變既有視窗、選單的佈局、邏輯單位或視覺狀態。HTML 設計的任務選單不隨持續進度重建節點，沿用現有原稿；執行驗證仍需覆蓋靜止懸停、鍵盤導航、狀態原位更新、任務新增與歷史淘汰。

<a name="xdzip-原生选择器与拖放激活"></a>

## 原生選擇器與拖放啟用

開啟壓縮檔、新增檔案／目錄、更改解壓或建立目標位置，均將實際呼叫的 Quick 視窗傳給共享 NativeDialogPolicy。選擇器仍為獨立原生對話方塊，使用應用模態和呼叫視窗的 transient ownership；退出巢狀事件迴圈後，僅當呼叫視窗仍存在且可見時，排隊恢復該視窗的啟用，不能固定恢復主視窗。呼叫視窗關閉後不得重新顯示。系統選擇器文案繼續遵循系統語言。

歡迎頁接收有效的本地歸檔拖放後，接收視窗在下一次事件迴圈請求啟用。無效拖放和普通任務完成均不請求前臺啟用。拖放的選擇規則見[歡迎頁接入](welcome.md#xdzip-qt-%E7%9C%9F%E5%AE%9E%E6%8E%A5%E5%85%A5)。

<a name="xdzip-退出与重启确认"></a>

## 退出與重啟確認

QuitWindow 和 RestartWindow 繼承 OperationConfirmationWindow，統一應用模態、正常密度、自適應高度、可滾動正文與固定頁尾。按鈕繼續表達原有返回、等待、取消退出、稍後和重啟意圖，檔案提交與任務清理仍由既有控制器處理。正在停止時禁用決策動作與 Escape 關閉，標題和說明變化不恢復舊尺寸。

此前僅驗證任務退出成功而遺漏確認框視覺，現將功能與視覺證據分開記錄。視窗完整性、基類和尺寸檢查見[強制流程](../visual/design-workflow.md)，對應狀態稿見[確認視窗](../../../design/hifi/sources/confirmations.html)。

密碼解壓使用獨立的 `waiting_password` 狀態和請求身份，TaskWindow 顯示等待輸入密碼並提供重開動作，應用模態 PasswordWindow 處理輸入與取消。它不使用重名衝突的 `promptId`；具體生命週期見[密碼解壓互動](password-extraction.md)。
