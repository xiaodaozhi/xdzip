<a name="xdzip-信息与布局"></a>

## 資訊與佈局

起始頁主標題為“打包與解壓，都簡單一點。”，英文為“Pack and unpack, a little simpler”。副文案繼續說明先瀏覽、按需解壓與打包分享。

預設客戶區 1024×622，最小 832×544；標題區 48，膠囊 32，底欄 32。內容組寬 608，僅水平居中，從可用正文頂部固定 28 邏輯畫素開始，不垂直居中。標題 30，窄視窗 28，說明 13，操作標題 16，卡片說明 12。兩張操作卡寬 296、高 124，間隔 16、內距 20、圓角 8。它們是歡迎頁入口卡片，不替代操作視窗共享按鈕。

標題欄完整複用主視窗原有元件，保留品牌、起始標籤、新增標籤與外觀設定；歡迎頁不改變標題欄的佈局、尺寸、字型或圖示。正文不展示空檔案樹、空表頭、搜尋框或解壓工具欄；開啟壓縮檔後再進入瀏覽佈局。主操作為“開啟壓縮檔”，次操作為“建立壓縮檔”；下方依次顯示拖入區和“支援開啟”區域。分類名稱旁顯示已登記的副檔名數量，進入首頁預設預覽“壓縮檔”。點選其他分類切換預覽，再點選目前分類收起。目前分類以強調色文字和字重標識。預覽使用常規介面字型和淺底細描邊標籤，單行排列，超出時顯示省略號，懸停可檢視目前分類的副檔名。“檔案關聯”可直接開啟設定中的關聯開關。底欄“檔案在本機處理”表達處理位置，不作安全保證。任務數字取真實歷史資料，稿中 0 僅為首次進入的空歷史狀態。

不放示例最近檔案、樣例容量或產品尚未具備的格式能力。標題區交通燈只表示 macOS 裝飾位置，正式實現使用平臺視窗能力；Windows、Linux 沿用平臺裝飾，不複製交通燈。

<a name="xdzip-交互设计"></a>

## 互動設計

- 首次啟動、最後一個壓縮檔標籤關閉、開啟失敗後沒有可瀏覽壓縮檔時可進入歡迎頁；背景任務繼續執行，不因歡迎頁重置。
- 開啟入口呼叫系統檔案選擇器，取消停留歡迎頁。開啟成功後切換真實壓縮檔標籤，失敗顯示可恢復錯誤，不能偽造成功列表。
- 新建入口開啟既有建立視窗，取消保留歡迎頁。快捷鍵候選 macOS 為 ⌘O、⌘N，Windows/Linux 為 Ctrl+O、Ctrl+N；實施前核對應用快捷鍵繫結，本稿不表示已接入。
- 拖入符合條件的選擇時，拖入區用 2 邏輯畫素的強調色邊框和選中底色高亮，移出後恢復。實際開啟見 [Qt 接入](#xdzip-qt-%E7%9C%9F%E5%AE%9E%E6%8E%A5%E5%85%A5)。
- 卡片完整區域可點選，標題欄之後的鍵盤順序為開啟、新建、任務。鍵盤焦點不增加外框，遵循全視窗統一失焦規則。Hover、pressed 使用共享 accentHover、accentPressed，不能只改變透明度。
- 開啟請求進行中時，開啟卡片以忙碌標記和“正在開啟…”替代標題，臨時禁止重複開啟和拖入；禁用使用 accentDisabled、accentDisabledText。新建視窗是否可並行沿用宿主規則，不借歡迎頁改變任務語義。忙碌、禁用與錯誤為實施契約，四張靜態原稿未展示這些狀態。
- 設定和任務彈出選單沿用 240 寬、13 字號、32 最小行高，與正文 13 字號比例為 1；歡迎頁不另造選單樣式。卡片 16 字號是入口標題，不能作為選單密度比較基準。

<a name="xdzip-验证方法与边界"></a>

## 驗證方法與邊界

歡迎頁需覆蓋淺深色、最小視窗、拖入狀態和選單／標題欄比例，檢查 DPR 1、1.25、2 及真實頁面縮放。不要用縮小截圖代替佈局或將 CSS 縮放當成瀏覽器頁面縮放。執行結果、圖片和幾何報告只進入本地／CI 工件，狀態由對應 issue 記錄。

Qt 使用歡迎頁及瀏覽器迴歸，並透過實際產品入口開啟檔案。自動檢查不能替代原生拖放、螢幕閱讀器和輸入法驗證。

<a name="xdzip-qt-真实接入"></a>

## Qt 真實接入

WelcomePage、WelcomeAction 僅表達佈局和意圖。啟動及關閉壓縮檔後顯示歡迎頁，成功開啟後進入對應歸檔會話瀏覽；空壓縮檔仍是有效瀏覽狀態。首次讀取期間禁用重複開啟及新建，顯示“正在開啟…”與取消載入；失敗保留歡迎頁和真實錯誤訊息，可重新選擇檔案。建立草稿關閉後不產生任務。背景任務列表不隨歡迎頁重置。

開啟按鈕和系統快捷鍵複用 chooseArchive，新建複用 CreateWindow。原生檔案選擇器保持系統視窗，取消不建立會話。Qt 按已儲存的標籤／視窗模式路由，空白起始頁優先複用，重複歸檔啟用既有會話。

由桌面會話管理器接收時，歡迎頁一次可拖入最多 128 個本地檔案。每項須匹配生成的拖放字尾或支援的分卷命名規則。單會話開發入口僅接收一項。目錄和非本地 URL 會被拒絕。這些規則用於選擇開啟入口，實際格式識別和來源校驗仍由 Rust 執行時完成。僅登記顯式開啟入口的格式可用“開啟壓縮檔”。詳見[格式登記](../engineering/format-registry.md)。

尺寸取 welcome-reference.json，經 generate-qml-theme.py 進入 Theme；字號放大增長卡片與正文，正文可滾動，鍵盤聚焦入口時自動滾到可見範圍。狀態列和標題區獨立增長，不使用 Item.scale。Qt 使用共享 PNG 圖示，主按鈕使用既有的深色／淺色筆畫圖形；不從原稿裁切執行素材。

自動化入口為 tst_welcome.qml、browser_test.cpp 的 welcomeOpensRealArchivesAndReturns 與 scripts/check-qt-welcome.py。按需三平臺 Qt 工作流在 DPR 1、1.25、2 檢查真實開啟、關閉、失敗恢復及 36 項幾何，選單同時檢查 240 寬、13 字號。原生拖放、檔案選擇器、讀屏和輸入法按需檢查，離屏結果不冒充未執行的桌面操作。

歡迎頁只替換內容，並複用相同的 Qt ArchiveTabs 元件。`screens/welcome-titlebar-*.png` 保留標題列設計。迴歸比較開啟壓縮檔前後的標題列、分頁及外觀按鈕幾何。

讀取狀態：首次開啟期間的取消入口移入正文浮動遮罩，進度未知時顯示活動進度條，不模擬百分比；詳見 [讀取遮罩契約](welcome-opening.md)。原始歡迎頁點陣圖保留，動態稿提供 opening=1 狀態。

錯誤／警告提示追加在格式提示下方，文字使用共享危險色並配 status-warning 圖示。出現、換行、清除或更換錯誤訊息均不改變標題與入口卡片的頂部座標；長內容由正文滾動。關閉托盤駐留主視窗後再次顯示只有一個起始頁，背景任務不取消。舊歡迎頁 PNG 保留歷史位元組，不能用舊居中圖覆蓋頂部定位契約。
