# 平臺視窗與標題欄規範

[English](../../ux/platform-windows.md) | [简体中文](../../zh-CN/ux/platform-windows.md) | 繁體中文（台灣）

xdzip 的操作介面使用獨立頂層視窗，不使用附著主視窗的 sheet 或在主視窗內部繪製的遮罩面板。獨立視窗不等於獨立程序，也不要求每個輔助視窗占一個工作列入口。下拉選單、工具提示保持輕量 Popup，不屬於操作視窗。

<a name="xdzip-窗口契约"></a>

## 視窗契約

| 視窗 | 與主視窗的關係 | 關閉 / Escape | 最小化 / 最大化 |
| --- | --- | --- | --- |
| 解壓或建立表單 | 非模態 `OperationWindow`，從瀏覽入口開啟時從屬於呼叫視窗 | 關閉草稿或確認視窗，不提交新任務 | 禁用／禁用 |
| 任務重名提示 | 從屬於操作宿主的非模態提示，任務等待決定 | 關閉提示後可從任務入口重開，也可在任務視窗明確取消任務 | 禁用／禁用 |
| 密碼、退出或重啟提示 | 應用模態，原生檔案選擇器同樣為應用模態並從屬於呼叫視窗 | 密碼、退出和重啟各有明確的關閉或確認動作 | 由原生對話方塊能力決定 |
| 任務進度和結果 | 非模態 `TaskWindow`，無其他模態視窗時可繼續瀏覽 | 關閉詳情後可從任務入口重開。獨立操作會保留活動任務的入口 | 允許最小化／禁用最大化 |
| 設定和關於 | 非模態，從托盤開啟時可以沒有瀏覽視窗所有者 | 關閉檢視，已儲存的設定繼續生效 | 禁用／禁用 |

取消任務是明確的任務命令，獨立於關閉進度視窗。任務在背景結束時，不搶奪前臺焦點；詳情已開啟時更新結果，否則更新任務入口。應用退出仍按任務退出策略處理，不能把主視窗關閉直接對映為輔助視窗關閉。

<a name="xdzip-平台外观"></a>

## 平臺外觀

- macOS：使用系統裝飾標題欄，紅黃綠控制元件位於左上角；不以自繪彩色圓點替代原生控制元件。固定尺寸操作窗保留紅色關閉，禁用不可用的最小化、縮放按鈕；進度窗允許收起。實際按鈕可用狀態由 AppKit/Qt 的視窗能力共同決定，並在真機驗收。主視窗保持正常縮放、最小化及全屏能力。
- Windows 主視窗將標題區延伸進客戶區，視窗按鈕由 QML 繪製，保留可縮放的原生邊框和 DWM 陰影。拖動、邊緣縮放和系統貼靠由平臺處理。獨立操作窗保留系統裝飾。見 [Windows 主視窗稿](../../../design/hifi/sources/main.html?platform=windows)。
- Ubuntu X11 主視窗使用右側內嵌按鈕，普通狀態為透明圓角，最大化和全屏時為直角，移動與縮放由視窗系統處理。獨立操作窗保留系統裝飾，非自繪 X11 路徑使用普通裝飾。Wayland 不在支援範圍內。見 [Ubuntu 主視窗稿](../../../design/hifi/sources/main.html?platform=linux)。

操作視窗各自有標題、邊框、陰影和可拖動標題欄；背後的主視窗不加網頁式變暗或模糊。初次開啟居中於所屬視窗所在顯示器的可用區域；恢復位置必須夾取到可見螢幕內。標題欄不能被工具欄或內容覆蓋。

<a name="xdzip-qt-quick-实现约束"></a>

## Qt Quick 實現約束

`OperationWindow` 是獨立的 `Window`，可指定 `transientParent`，預設使用 `Qt.NonModal`。`PasswordWindow` 和 `OperationConfirmationWindow` 顯式使用 `Qt.ApplicationModal`。原生選擇器以實際呼叫視窗為所有者，只在該視窗仍可見時恢復其啟用狀態。見[視窗登記](../../../specs/visual/window-registry.json)與[任務視窗](task-windows.md)。

Windows/Linux 自繪標題欄需要真正的平臺視窗移動、調整尺寸和系統選單支援，不以 QML 手動修改位置模擬系統拖動。`WindowController` 負責視窗生命週期、所有權、關閉請求和任務檢視重開；任務由核心持有，銷燬檢視不能銷燬正在執行的任務。視窗狀態跨執行緒只透過已定義橋接事件更新。

<a name="xdzip-原型证据与限制"></a>

## 原型證據與限制

HTML 原型模擬獨立視窗外觀、標題欄拖動、阻塞或非阻塞互動及關閉語義。頂部“平臺”選擇器用於對照 macOS、Windows、Linux；不屬於產品設定。瀏覽器 `dialog` 仍在同一瀏覽器頁面內，不能提供真正的原生視窗、系統按鈕、系統最小化、工作列或多顯示器行為。收起任務視窗透過隱藏詳情模擬。

原型主視窗的平臺控制區為外觀示意；覆蓋確認返回新建時仍重置示例表單，正式實現必須保留草稿。這些限制不能作為完成原生驗收的證據。

<a name="xdzip-实机验收门槛"></a>

## 實機驗收門檻

1. 各操作窗是獨立平臺視窗，正確關聯主視窗；不生成 sheet，無網頁式遮罩。
2. 紅綠燈/右側按鈕的順序、禁用狀態、關閉請求符合平臺和視窗能力；標題與系統按鈕在不同字型、縮放下不重疊。
3. 視窗拖動、螢幕邊界、多顯示器、125%/150%/200% 縮放，以及深淺主題正常。
4. 關閉任務詳情後任務繼續，任務入口可以重開。關閉重名視窗後任務繼續等待，直到使用者重開提示作出決定或明確取消任務。
5. 所屬視窗的模態限制、焦點恢復、鍵盤導航、讀屏標題與系統快捷鍵有效；其他壓縮檔視窗不被無故阻塞。
6. Windows 系統選單／貼靠和 Linux X11 分別驗證；Wayland 不在首批支援範圍。既有 Qt 實機結論見 [WP-12 #5](https://github.com/xiaodaozhi/xdzip/issues/5)，本清單用於後續受影響項複驗，不重置已完成驗收。
