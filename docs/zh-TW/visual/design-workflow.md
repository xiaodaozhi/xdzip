# 介面設計與修正流程

[English](../../visual/design-workflow.md) | [简体中文](../../zh-CN/visual/design-workflow.md) | 繁體中文（台灣）

本流程在介面創作前執行，不等到實現完成後補寫。規範入口為 [介面設計規範](design-standard.md)。

1. **確定目標與環境。** 列出功能、真實資料和缺失能力，明確平臺、邏輯視窗、輔助字號、選單及獨立視窗的尺寸範圍；記錄系統縮放、審閱倍率與 DPR；使用 HTML 原型時再記錄瀏覽器頁面縮放。
2. **先確定引數。** 用規格 JSON 定義尺寸、字號、槽位、內邊距、對齊和狀態。記錄座標系及元件自己的密度。主視窗和選單使用獨立度量，各獨立視窗按視窗登記中的表示式計算。操作正文的比例和共享頁尾的尺寸須分別檢查。DPR 僅用於把量測證據中的物理畫素換算回邏輯單位。
3. **凍結獨立依據。** 儲存原圖雜湊和量測座標。尺寸政策可以顯式修訂；原圖和歷史證據不得為了讓檢查透過而替換。維護可追溯的修訂記錄，驗收指令碼不能只把執行引數與自身比較。
4. **先檢查組合關係。** 設計按鈕、表格、樹和選單時同步檢查字號比例、行高比例、圖示比例和互動狀態；至少同時展示一個下拉選單、一個右鍵選單和一個子選單。同一操作窗分別從主視窗和獨立入口開啟，核驗最終視窗寬度、正文、footer 和控制元件尺寸相同。使用 HTML 原型時，應先對照原稿凍結引數，再作為 Qt 的實現依據。
5. **統一生成與實現。** 由規範生成 HTML 展示契約和共享引數、Qt Theme；Qt 使用邏輯佈局和真實字型尺寸。僅替換主題顏色或素材不能代替尺寸對照。
6. **測量並修正。** 同一邏輯寬度逐區核驗標題欄、標籤、工具欄、麵包屑、目錄樹、表頭、檔案行、預覽、底欄與選單。檢查座標、字型、圖示可見範圍、基線、內邊距和 hover／focus；修正後重新採集對應證據。
7. **驗證縮放與行為。** 檢查 Qt 高 DPR、窄視窗和輔助字號；按需複核 HTML 時另檢查瀏覽器 100%／125% 與 DPR 1／1.25／2。真實點選展開／摺疊，鍵盤進入／退出子選單，驗證禁用項、選擇狀態、邊緣位置和焦點歸還；排除 Qt 回收池中未顯示的物件。
8. **交付與准入。** 更新受影響的規範、功能對映、生成檔案、自動檢查和差異記錄。提交、推送前完成本地相關驗證；三平臺完整檢查按需觸發，尚未驗證的原生裝飾和未實現能力保留為明確條目，不補畫假狀態。

介面變更記錄實際採用的規範、引數與倍率、主視窗和選單量測、已驗證互動及剩餘差異，無須填寫固定人工問卷。

## 視窗登記與強制檢查

所有獨立 QML 視窗及內聯 Window 登記在 [視窗清單](../../../specs/visual/window-registry.json)，包括抽象基類、產品操作窗、獨立屬性視窗和開發預覽。新增視窗未登記、繼承改變、尺寸偏離凍結表示式、確認視窗自行覆蓋字號或高度、可滾動正文缺失均使 `check-window-contracts.py --self-test` 失敗。檢查從原始碼發現視窗，不再依賴人工維護的固定檔案列表。系統原生選擇器的例外在清單中說明，不能借例外繞過應用視窗登記。

退出和重啟確認統一使用 OperationConfirmationWindow。引數來自 layout-scale.json 的 operation.confirmation，不使用舊預設 612 寬或按字號跳變的固定高度。短文案按內容自適應，長正文或小螢幕滾動，footer 固定可達。所有 footer 按鈕仍由共享元件決定外觀；長翻譯允許按鈕內換行，動作保持一行。

靜態登記檢查接入日常 CI，Qt 執行時幾何及互動檢查在本地或按需三平臺 Qt 工作流執行。Qt 檢查覆蓋退出、停止、重啟，中英文，淺深色，100/125/150% 字號，以及小螢幕正文滾動；按需 Qt 工作流覆蓋 DPR 1/1.25/2。HTML 實際佈局可按需在本地獨立量測，不作為日常 CI 門檻，也不能冒充未執行的 Qt 或原生視覺檢查。靜態檢查包含歷史大尺寸、遺漏視窗、固定高度和丟失滾動的破壞性變體驗證。

視窗變更分別記錄功能與實際執行的視覺檢查，具備條件時由執行者採集截圖及尺寸。不能因為真實退出任務已透過，就寫成退出視窗樣式已驗收；不能因為原始碼清單完整，就寫成全部平臺視覺已透過。原生選單、系統裝飾和未具備的裝置繼續保留明確限制，不要求維護者重複填寫固定人工驗收表。
