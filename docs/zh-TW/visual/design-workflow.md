# 介面設計與修正流程

[English](../../visual/design-workflow.md) | [简体中文](../../zh-CN/visual/design-workflow.md) | 繁體中文 | [日本語](../../ja-JP/visual/design-workflow.md) | [한국어](../../ko-KR/visual/design-workflow.md) | [Français](../../fr-FR/visual/design-workflow.md) | [Deutsch](../../de-DE/visual/design-workflow.md) | [Español](../../es-ES/visual/design-workflow.md) | [Português (Brasil)](../../pt-BR/visual/design-workflow.md) | [Русский](../../ru-RU/visual/design-workflow.md)

本流程應在建立介面前執行，而不是等實作完成後才補寫文件。規範入口為[介面設計規範](design-standard.md)。

1. **確定目標與環境。** 列出功能、實際資料和缺少的能力，明確指定平台、邏輯視窗、無障礙字級、選單及獨立視窗的尺寸範圍。記錄系統縮放、審查倍率與 DPR；使用 HTML 原型時也要記錄瀏覽器頁面縮放。
2. **先確定參數。** 以規格 JSON 定義尺寸、字體排版、插槽、內距、對齊和狀態，記錄座標系及元件專屬密度。主視窗和選單使用獨立量測標準，各獨立視窗使用視窗登錄表中的運算式。操作內容的縮放和共用頁尾尺寸須分別檢查。只有讀取量測證據時才使用 DPR 換算實體像素。
3. **固定獨立參考依據。** 儲存原圖雜湊和量測座標。尺寸政策可以明確修訂，但不得為了讓檢查通過而替換原圖或歷史證據。保留可追溯的修訂紀錄；驗收指令碼不能只將執行時參數與自身比較。
4. **先檢查組合。** 設計按鈕、表格、樹狀檢視和選單時，同時檢查字體、列高和圖示比例及互動狀態；至少同時展示一個下拉選單、右鍵選單和子選單。分別從主視窗與獨立入口開啟同一操作視窗，確認最終視窗寬度、內容、頁尾與控制項尺寸相同。使用 HTML 原型時，先對照原稿固定參數，再作為 Qt 實作依據。
5. **一致地產生與實作。** 從規格產生 HTML 顯示契約、共用參數及 Qt Theme。Qt 使用邏輯配置和實際字體大小；僅替換主題顏色或素材不能代替尺寸比較。
6. **量測並修正。** 在相同邏輯寬度下分區檢查標題列、分頁、工具列、麵包屑、目錄樹、表格標題、檔案列、預覽、底列與選單。檢查座標、字體、圖示可見範圍、基線、內距及滑鼠懸停與焦點；修正後重新收集受影響的證據。
7. **驗證縮放與行為。** 檢查 Qt 高 DPR、窄視窗和無障礙字級。按需審查 HTML 時，也檢查瀏覽器 100%／125% 縮放及 DPR 1／1.25／2。實際點擊展開與收合，使用鍵盤進出子選單，驗證停用項目、選取狀態、邊緣位置和焦點返回；排除 Qt 回收池中未顯示的物件。
8. **交付與驗收。** 更新受影響的規格、功能對應、產生的檔案、自動檢查和差異紀錄。提交及推送前完成相關本機驗證；按需執行完整的三平台檢查，明確保留尚未驗證的原生視窗裝飾及尚未實作的能力，不繪製虛構狀態。

記錄實際使用的規格、參數與倍率、主視窗和選單量測、已驗證的互動及剩餘差異，無須填寫固定的人工問卷。

## 視窗登記與強制檢查

每個獨立 QML 視窗及內嵌 Window 都須登記在[視窗登錄表](../../../specs/visual/window-registry.json)，包括抽象基底類別、產品操作視窗、獨立屬性視窗和開發預覽。新增視窗未登記、繼承關係改變、尺寸偏離固定運算式、確認視窗覆寫字級或高度，以及缺少可捲動的內容區，都會使 `check-window-contracts.py --self-test` 失敗。檢查會從原始碼發現視窗，不依賴人工維護的固定清單。系統原生選擇器的例外在登錄表中說明，不能以此繞過應用程式視窗的登記。

結束和重新啟動的確認視窗統一使用 OperationConfirmationWindow。參數來自 layout-scale.json 的 operation.confirmation，不使用舊預設寬度 612，也不使用隨字級跳動的固定高度。短文字依內容調整大小；內容較長或螢幕較小時可捲動，頁尾始終可操作。頁尾按鈕的外觀仍由共用元件決定；較長的譯文可在按鈕內換行，動作按鈕仍維持同一列。

靜態登錄檢查在日常 CI 執行；Qt 執行階段的幾何與互動檢查在本機或按需執行的三平台 Qt 工作流程中進行。Qt 檢查涵蓋結束、停止和重新啟動，中英文、淺色與深色、100/125/150% 字級，以及小螢幕內容捲動；按需工作流程涵蓋 DPR 1/1.25/2。可按需在本機另行量測 HTML 實際版面，但它不是日常 CI 門檻，也不能替代未執行的 Qt 或原生視覺檢查。靜態檢查包含針對歷史過大尺寸、遺漏視窗、固定高度及缺少捲動的變異驗證。

視窗變更須分別記錄功能與實際執行的視覺檢查，並在可能時收集截圖和尺寸。實際結束工作通過不代表結束視窗的外觀已驗收；原始碼登錄表完整也不代表所有平台的視覺檢查通過。原生選單、系統視窗裝飾和無法使用的裝置須保留明確限制，不要求維護者反覆填寫固定的人工驗收表。
