# 介面設計規範

[English](../../visual/design-standard.md) | [简体中文](../../zh-CN/visual/design-standard.md) | 繁體中文（台灣）

[任務路徑與結果摘要修訂](../../../design/hifi/sources/task-windows.html)將進行中的“當前檔案”限制為單行、中間省略，保留完整純文字輔助功能名稱，路徑長度不改變卡片或視窗高度。普通解壓結果摘要僅含完整任務統計中的已提交檔案數，不依賴保留的明細記錄；壓縮結果摘要僅顯示“N 個檔案”，不顯示名稱或容量；普通壓縮使用 outputParts，批次壓縮使用成功任務數。批次壓縮結果不顯示卷組去重計數，批次解壓結果仍顯示該計數；可展開明細保留現有行為。邏輯尺寸、密度與大字號適配繼續沿用既有規範。

本規範約束介面創作、HTML 設計交付和 Qt 實現。尺寸換算以 [layout-scale.json](../../../specs/visual/layout-scale.json) 為準；顏色、共享控制元件和目錄樹分別以 [tokens.json](../../../specs/visual/tokens.json)、[controls.json](../../../specs/visual/controls.json)、[directory-tree.json](../../../specs/visual/directory-tree.json) 為準。原稿量測儲存在 [qt-main-reference.json](../../../specs/visual/qt-main-reference.json)，不以實現結果反向改寫原圖。

<a id="主動內容預覽"></a>

## 內容預覽

[內容狀態稿](../../../design/hifi/sources/content-preview.html)沿用現有屬性卡的寬度、高度、圓角、主視窗密度與文字角色。內距、間距、圖示和載入指示引數由 layout-scale.json 的 main.content_preview 生成。屬性卡可見時，選取單一檔案就會自動開始預覽。讀取、等待密碼、純文字、圖片、錯誤和多選提示均顯示在卡片內，讀取或等待密碼時可以取消。多選提示上方重疊顯示兩個項目類型圖示，沿用預覽圖示尺寸，水平錯開 16 個邏輯像素，垂直錯開 8 個邏輯像素。圖示依列表順序取自具有中繼資料的選取項目，資料不足時使用通用檔案圖示補齊。將滑鼠移到預覽區，或用鍵盤將焦點移到按鈕時，右上角會顯示共用的 ArchiveAction。按鈕為 28 個邏輯像素見方，圓角半徑為 3、邊距為 6，重新載入圖示為 16。文字為純文字且可選擇，圖片保持比例，柵格與受限靜態 SVG 均透過同一圖片槽顯示，不增加瀏覽器、HTML 或外部連結執行入口；SVG 在受限工作程序內柵格化，不把原文交給 QML。主視窗與獨立屬性檢視器複用同一 InspectorPanel，關閉預覽或更換條目立即清空。密碼視窗沿用[密碼輸入視窗](../ux/password-extraction.md)的佈局和共享頁尾，僅按預覽任務切換文案。主視窗及選單的既有比例仍須同時複驗。


<a name="xdzip-界面字体与用户数据"></a>

## 介面字型與使用者資料

Qt 啟動時儲存系統預設字型家族，再安裝內建的 Noto Sans SC 衍生子集作為固定介面文案字型。檔名、歸檔名、目錄名、路徑以及包含這些內容的提示和編輯欄位優先使用儲存的系統字型；缺少字形時由 Qt 和平臺繼續回退。含檔名的複合提示可整段使用系統字型，靜態佔位和操作文字保留介面字型。文字顯示、目錄樹寬度及拖動預覽測量須使用對應的相同字型；字號仍遵從現有邏輯尺寸和輔助字號，不因系統 DPI 調整元件邏輯尺寸。HTML 審閱示例仍使用內建子集；使用者資料的實際字形與文字寬度以執行平臺為準，結構尺寸按同一邏輯規範核驗。


<a name="xdzip-单位与密度"></a>

## 單位與密度

1. 所有交付值使用邏輯畫素：HTML 的 CSS px、Qt 的 device-independent pixel。截圖物理畫素除以 DPR 後才能和設計值比較。素材的 1×／2×／3×僅決定取樣清晰度，不改變圖示槽尺寸。
2. 主視窗此前 1280 寬的基準按 125% 處理，折算到 100% 使用 `1 / 1.25 = 0.8`。新預設客戶區為 1024×622；最小客戶區為 832×544，預覽收起閾值為 928。標題區、工具欄、分欄、檔案列表、目錄樹、底欄的空間尺寸和字號都執行這次密度校正。
3. 彈出選單與提示採用正常密度，不再跟隨主視窗密度一起縮小。選單預設 240 寬、最小 32 行高、13 字號、18 圖示槽。主列表目標約 12.57，Qt 取 13；選單／列表字號比例必須落在 0.95～1.10。不能只檢查各自的引數而漏掉相互比例。
4. 主原稿內部客戶區 1548×940 是量測座標。HTML 主畫布換算比例為 `1024 / 1548`；選單的 CSS 源座標反向換算，最終保持上述邏輯尺寸。普通操作視窗沿用 `1280 / 1548`。解壓原稿採用單獨的 `819.2 / 1548` 對映，視窗約 491 寬；這是修正獨立入口比嵌入入口大 25% 的明確密度調整。各入口必須共用同一最終邏輯尺寸，不能在嵌入和獨立展示時分別指定元件字號。
5. 瀏覽器審閱倍率、瀏覽器頁面縮放、系統縮放和 DPR 都不得寫入元件尺寸引數。Qt 不透過 `Item.scale`、視窗截圖縮小或額外 1.25 係數實現密度校正；由規範引數生成真實佈局與整數 pixelSize。
6. 1 邏輯畫素分隔線與焦點描邊保留規範值，原生系統視窗裝飾由作業系統負責。空間尺寸保留小數；結構邊界和視窗尺寸按最近整數取整，Qt 字號在密度換算後、輔助字號放大前取整。

新增的緊湊標籤和徽章使用 3 邏輯畫素圓角，保持直邊清晰。更大的圓角僅用於設計已明確批准的控制元件形態。標準按鈕、輸入框和視窗繼續遵循對應的共享尺寸。

<a name="xdzip-标题区修订"></a>

## 標題區修訂

主標題欄採用 48 邏輯畫素高度；標籤採用 32 高、16 圓角的懸浮膠囊，上下各留 8。活動標籤使用完整邊框，不與工具欄相連。標籤關閉、加號、設定按鈕與標題欄共享垂直中心。輔助字號放大時先增高膠囊，再保留上下相等留白。此修訂替代原圖的底部吸附標籤，原圖保持存檔。

活動標籤字重 600，非活動標籤字重 400，無活動描邊，僅懸停使用共享底色。標籤寬度在既有首選寬度與 112 的最小寬度之間均分可用空間，字號放大時寬度上限與下限隨之增長。超出後使用不顯示捲軸的橫向視口，保留新建、雙向滾動和標籤列表入口，設定及系統按鈕不被擠壓。滾輪、觸控板、鍵盤切換、選單啟用與拖動邊緣滾動共用同一有界視口；活動標籤在開啟、切換、關閉和尺寸變化後完整可見，使用者主動滾動不被拉回。視窗內拖動顯示浮動膠囊與插入標記，釋放後按穩定會話身份排序，Escape 或輸入取消放棄拖動。引數來自 layout-scale.json 的 titlebar，不從截影象素推導。

標籤關閉按鈕保持既有正方形命中區域與居中位置，懸停及按下背景的圓角為寬高的一半，形成圓形。主視窗只有一個普通、空閒且無錯誤的起始頁時隱藏該按鈕；載入、錯誤或多標籤狀態下仍按既有規則顯示，歸檔標籤的關閉行為不變。隱藏的按鈕不得獲得鍵盤焦點或作為可見輔助功能操作。


起始頁載入卡片的正文可滾動，“取消載入”使用共享 OperationFooterButton，在卡片右下固定操作區中顯示。載入不是解壓，不復用“取消解壓”文案。取消發出後顯示取消中並禁用重複提交，載入結束後恢復起始頁焦點。卡片邏輯寬度 360、內距 24，保留既有半透明遮罩與共享按鈕尺寸，不覆蓋 footer 按鈕樣式。

已開啟壓縮包的修改等待複用該卡片引數，背景採用 layout-scale.json 的 operation_overlay 透明政策，原檔案頁繼續顯示且阻止重複操作。標題、說明、進度輔助名稱和取消按鈕會顯示實際執行的新增、移動、重新命名或刪除操作，任務清理和目錄重新整理完成後恢復操作。取消請求已接納時立即關閉失效的重名與密碼提示，進度窗顯示取消中並繼續跟隨真實終態；重名視窗繫結具體任務及提示令牌，切換任務或令牌失效時關閉。

清單和格狀檢視的項目選單共用[壓縮檔項目編輯設計](../../../design/hifi/sources/archive-entry-edit.html)及標準快顯選單密度。重新命名與刪除共用寬 491 個邏輯像素的確認視窗，內文可捲動，頁尾固定。檔名採用系統的使用者資料字型。開啟重新命名視窗時，焦點移至共用輸入欄位，檔案預設選取不含副檔名的部分。開啟刪除視窗時，焦點移至取消按鈕。

當前[淺色主視窗](../../../design/hifi/screens/main-capsule-light.png)、[深色主視窗](../../../design/hifi/screens/main-capsule-dark.png)和[多級目錄圖](../../../design/hifi/screens/directory-tree-capsule.png)同步此標題區，來自[可編輯設計源](../../../design/hifi/sources/main.html)。舊主視窗與目錄樹原圖在畫廊歷史區儲存，原有獨立量測、SHA-256 和切片來源保持不變；當前設計匯出不用於替代獨立幾何驗收。

## 元件規則

<a name="xdzip-设置窗口分类修订"></a>

### 設定視窗分類修訂

無 owner 的托盤設定和關於視窗複用共享螢幕居中策略，以當前顯示器的可用區域和完整原生邊框定位；原生視窗建立及高度確定後重新居中，避免指標位於通知區時沿用右下角位置。視窗尺寸、字號與密度仍沿用設定規範。


Windows MSIX 包身份的關於頁省略更新標題、分隔線和整個更新區域，版本資訊直接沿用其後的共享分組間距。視窗尺寸、字號和其他內容沿用既有規範，不按渠道改變縮放或密度。

設定與關於共用一個 612 邏輯畫素寬的非模態視窗，客戶區首選高度 532，受螢幕可用高度約束。共享 OperationHeader 底部有 1 邏輯單位分隔線，下方為左側導航和獨立滾動的右側頁面；左欄基準寬 144、正常行高 40、圖示槽 18，圖示距側欄左邊 15，首行貼齊頂部，選中背景與右側分隔線相接。輔助字號增大時，左欄按實際最寬單詞和圖文間距適當增寬，英文在單詞之間換行；行按內容增長並允許滾動。未選中項懸停使用共享 controlHover 顏色，淺深主題均與側欄底色區分。頁面內距 20，分組間距 16。實際引數以 layout-scale.json 的 operation.settings 為準，不從截圖、DPR 或審閱倍率推導。

六個頁面依次為外觀、通用、隱私、檔案關聯、網路和關於。設定視窗不再使用 footer 或儲存、取消、完成按鈕；提交成功的變更即時生效，失敗時保持已生效值並顯示原因。關於頁面保留版本、許可證和使用者主動更新；所有關於入口開啟該頁，不再建立獨立關於視窗。主題卡片、設定圖示、品牌和已有狀態素材繼續複用原資源，不重複生成未變化切圖。

正文不重複顯示與側欄相同的頁面標題，也不保留標題下的分隔線；實際設定分組標題及分組之間的分隔線保留。關於頁的更新主要操作與狀態同一行、右側對齊：檢查中顯示“取消檢查”，發現版本後顯示下載、下載安裝或釋出頁入口，下載中顯示“取消下載”，下載完成後顯示安裝或開啟下載位置。檢查與取消檢查保持相同位置和尺寸，進度條位於狀態行下方；需要同時提供下載目錄的次要操作時靠右排列。


每個元件必須明確尺寸、字號、圖示槽、內邊距、對齊邊、命中區域、狀態和資料來源。禁止只交付預設狀態。按鈕必須覆蓋 normal、hover、pressed、focus、disabled、busy；選單必須覆蓋鍵盤選中、子選單、checked、disabled、邊緣翻轉和滾動；目錄樹必須覆蓋子層級、葉節點、摺疊當前路徑、深層滾動和長名稱；檔案列表必須覆蓋表頭／內容同邊對齊、排序、多選、空態和未知資料。

數字列同邊右對齊，型別列同邊左對齊。麵包屑與預覽標題區高度、字號、文字基線一致；預覽頂邊與檔案表頭頂邊一致。圖示按槽居中，文字按字型度量對齊。所有圖示使用統一素材庫，不從帶底色截圖中臨時裁切。

檔案列表選框右邊緣到檔案圖示槽的留白為 12 邏輯畫素，來自 layout-scale.json 的 fileSelectionGap。此修訂將原稿約 21.17 的空白收緊，檔案圖示、名稱文字及“名稱”表頭同步左移，保留原有圖示槽、圖文間距和其他列邊界；凍結原稿及原始量測不改寫。

主視窗正常密度校正與輔助字號放大是兩個獨立步驟。當前字號選項為 100%／125%／150%，舊 200% 設定按 150% 讀取。輔助字號增加時可增高、滾動或開啟獨立詳情視窗，不能用縮小文字抵消選擇；測試直接注入 200% 只表示歷史壓力場景，不表示產品仍提供該選項。任何視覺例外必須記錄理由和驗證範圍。

<a name="xdzip-验收门槛"></a>

## 驗收門檻

HTML 與 Qt 必須在同一邏輯寬度下對比；原稿只裁去外背景並按明確比例展示。幾何誤差最多 1 邏輯畫素，文字／圖示垂直中心誤差最多 0.5，要求共線的分欄頂邊誤差最多 0.01。截圖報告必須寫明提交、平臺、渲染後端、瀏覽器縮放、審閱倍率、DPR 和邏輯視窗尺寸。

按需進行 HTML 對照時驗證 100%／125% 瀏覽器頁面縮放及 DPR 1／1.25／2；對應的 Qt 測量驗證高 DPR 下視窗、字型、選單仍使用相同邏輯引數。驗證工具不能用 CSS zoom 冒充真實瀏覽器頁面縮放，也不能把離屏截圖寫成原生桌面視窗驗收。檢查數不是視覺還原百分比。

變更按 [介面設計流程](design-workflow.md) 執行；規範、生成輸出、實際座標、截圖和互動證據缺一項時，不能標記完整驗收。

<a name="xdzip-主窗口交互修订"></a>

## 主視窗互動修訂

主工具欄圖文間距固定為 6；圖示獨佔按鈕時在內容框居中。列表／網格／排序按鈕採用固定 28×28 圓角方形，標題區間距固定為 6.4，麵包屑吸收剩餘空間。麵包屑按鈕正常高度為 28，上下留白；選單與呼叫按鈕間隔 4，底部選單向上展開。樹行不顯示檔案數，左邊選中邊平直、指示線全高，子節點不使用四邊描邊。樹寬按已展開節點的真實文字度量計算。修訂後的互動與量測按[驗證方法](../../../developers/qa/README.md)登記。

<a name="xdzip-操作窗口与任务状态素材"></a>

## 操作視窗與任務狀態素材

<a name="xdzip-共享图标标题区"></a>

### 共享圖示標題區

建立、新增、解壓、任務及結果、衝突和設定視窗統一使用 OperationHeader，關於內容位於設定頁，完整性檢查隨 TaskWindow 繼承。圖示槽為48×48，標題20、副標題13，左右內距24、上下20、圖文間距16、標題與副標題間距6，正常高度基準96。圖示保持原素材比例並居中，不使用視窗自己的 canvas／artwork 尺寸覆蓋。標題與副標題均為純文字，淺深色沿用 text／textSecondary，字號只按應用輔助字號變化。長文案或大字號使標題區按同一字型度量公式增高，不縮小字、不覆蓋正文或footer。

引數唯一來源為 [operation.header](../../../specs/visual/layout-scale.json)，獨立狀態稿為 [operation-headers.html](../../../design/hifi/sources/operation-headers.html)，視窗對應關係在 [window-registry.json](../../../specs/visual/window-registry.json)。本修訂替代舊的各窗圖示槽、關於頁居中品牌標題24及視窗專用header高度；原始圖片、雜湊和歷史量測不改寫。密碼、預檢、退出／重啟確認等文字型標題區不憑空加入裝飾圖示，也不修改其既有安全互動。主視窗與選單密度仍分別量測。

## 操作控制元件複用與建立視窗修訂

[create-reference.json](../../../specs/visual/create-reference.json) 固定 C01 原圖雜湊、控制元件裁剪座標與當前修訂。操作按鈕、輸入框、下拉框及 footer 按鈕的圓角統一為 5，淺色描邊 #DCE2EC、深色 #485469，普通中性按鈕底色 #FAFBFD。正文動作高 28、footer 動作高 32；footer 的文字 13、說明 12，不再由每扇視窗覆蓋形狀、描邊、字型、顏色與密度。危險動作仍使用語義危險色，焦點不增加額外描邊。

設定視窗的密度、文字大小、語言和開啟方式下拉框共用相同邏輯高度：不低於正文按鈕高度，文字需要更多空間時使用文字高度加 8，確保大字號不裁切。可編輯輸入框的文字選區使用現有 accent 背景和 accentText 前景，淺深色均保持可讀；主視窗搜尋、操作欄位和可編輯下拉框以及 HTML 示例遵循同一顏色關係，不改變未選中文字與佔位文字。


Qt 使用 OperationButton、OperationFooterButton、OperationFrame、OperationSelect、OperationRemoveButton 和 OperationSegmentedGroup。視窗僅提供文字、資料、狀態與操作；共享元件承擔所有外觀與行為。HTML 使用同一生成引數及共用樣式、分段組選項生成器。下拉圖示槽為 18，槽右邊到控制元件右邊為 6；HTML 下拉描邊以 inset outline 繪製，避免瀏覽器對分數 CSS border 向下取整後移動圖示。

建立列表使用 28 命中區域與 24 圖示槽的圓形減號，來自統一素材庫；檔案大小靠右。壓縮格式是一條連續分段 radio group，等寬、零間距、單一外描邊，禁用格式不接受滑鼠或鍵盤選擇。檔案摘要讀取後臺普通檔案後設資料，三個原稿同名夾具的實際大小為 8.4、6.2、12.8 MB，顯示“3 個檔案，27.4 MB”。目錄總量保留未知，開始任務時重新凍結輸入樹。

資訊分隔使用逗號、句號、換行或明確標籤，不使用中點。此規則約束當前介面和維護文件，不改寫既有高保真點陣圖；歷史截圖和捕獲 JSON 不進入當前原始碼樹。共享控制元件規則由 scripts/check-operation-components.py 約束；實際量測、互動與限制按[驗證方法](../../../developers/qa/README.md)登記。

截圖、量測及對照報告只儲存到忽略的 build/ 或 dist/，CI 工件短期保留；原始碼倉庫只儲存設計原稿、素材、規範引數和檢查程式碼。不可用已經刪除的歷史實現截圖作為測試輸入或設計權威。

<a name="xdzip-完整性检查与系统窗口"></a>

## 完整性檢查與系統視窗

完整性檢查沿用任務進度的 491 寬、自適應客戶區高（最高 600）、20 標題、13 正文、共享 footer 和正常密度。高保真原稿為 screens/integrity-progress.png，凍結依據見 integrity-reference.json。保持標題區、物件路徑、漸變進度條、已讀取位元組與檔案數、三列指標、當前檔案、說明與 footer 的同一佈局；僅替換操作名稱、藍色文件勾選插圖、檢查物件、平均讀取、讀取並校驗和取消檢查。禁止再使用單獨的瀏覽器原生 progress 條或不同尺寸的檢查卡片。

HTML 複用 taskProgressBody、taskProgressFooter 和進度樣式；Qt IntegrityWindow 繼承 TaskWindow。檢查是隻讀語義，終態不顯示目標儲存統計或開啟輸出目錄動作。元件開發預覽必須明確標記為未執行實際校驗；主視窗的真實工具欄命令按[檢查契約](../engineering/archive-checking.md)啟用。淺深色、未知總量、長路徑、輔助字號、關閉與取消均沿用共享契約。

Qt 固定行高必須同時作為佈局的行槽高度，不能再把額外字型 leading 算進固定行槽。百分比行槽為 24，位元組與檔案數行槽為 18；路徑卡片標題與指標保持既定行高，多行指標按實際行數增高。預設字號下，三類進度視窗的正文說明完整顯示；小螢幕或輔助字號下正文可滾動，footer 仍固定可達。

每個主視窗當前各持有一個 ExtractWindow、CreateWindow 和 TaskWindow，均為作業系統獨立視窗。解壓、建立和真實完整性檢查的進度與結果複用 TaskWindow；選擇其他任務時同一視窗更新內容，並不是為每種狀態新建視窗。元件開發預覽另用 IntegrityWindow，不執行真實檢查。詳見[任務視窗契約](../ux/task-windows.md)。

<a name="xdzip-2026-10-15-操作与选择修订"></a>

## 2026-10-15 操作與選擇修訂

本節替代歷史原稿中的進度、結果和重名視窗尺寸；原始 PNG、雜湊與裁剪依據繼續保留，不透過縮放截圖改變尺寸。當前修訂狀態稿見 [操作視窗與按鈕狀態](../../../design/hifi/operation-revisions.html)。

- 解壓、建立、進度、結果及檔案已存在視窗統一為 491 邏輯畫素寬。任務正文加 footer 決定視窗高度，最高 600，明細列表自身最高 168；收起明細後恢復實際內容高度。重名視窗正文按 0.8 的正常密度換算，標題 20、正文 13、說明 12，最高 560，footer 使用共享控制元件且固定可達。大字號只增長內容或滾動。
- 壓縮格式為連續 radio 分段組。僅第一個選項保留左側兩個圓角，最後一個保留右側兩個圓角，中間所有角為直角，選中、hover、pressed、focus 均不得改變此規則。
- 所有藍色按鈕透過共享 tokens 區分 normal、hover、pressed、disabled。按下使用 accentPressed，禁用使用 accentDisabled 和 accentDisabledText，不以整體透明度或灰藍混合代替；鍵盤按下與滑鼠按下使用同一狀態。
- 解壓目標欄位在外部點選、Escape、Return 和數字鍵盤 Enter 後退出編輯焦點，不啟動解壓；第一次 Escape 保留視窗，後續 Escape 按視窗規則關閉。範圍標題與右側次要數量分欄排布，整行保留單一 radio 命中區域。
- 全選和逐項選擇共用焦點詳情語義，全選聚焦當前列表最後一項，取消全選清空詳情。未選擇時隱藏四項屬性和預覽解壓動作。預覽解壓按鈕必須保留 hover、pressed、focus 和 disabled。
- 狀態列按鈕統計各會話中可重開的任務，活動數另用於提示和退出判斷。100% 字號下，任務選單沿用 240 邏輯畫素寬、13 字號和至少 32 的行高，依次顯示操作圖示、檔名、序號和狀態。`CommandMenuTag` 使用共享內邊距與圓角，序號用中性色，狀態用語義色。檔名省略以給標籤留空間，無障礙名稱保留操作型別、序號、檔名及狀態。較長的歷史在選單限高內滾動，清理與任務身份見[任務視窗](../ux/task-windows.md)。


起始頁與壓縮檔案頁的任務按鈕共用相同的內部佈局，右邊距為 `layout-scale.json` 中的 14 邏輯畫素；切換頁面時按鈕、圖示、箭頭和選單錨點保持水平對齊。右邊距不隨字型倍率或裝置畫素比換算為元件尺寸。


標籤文字的實際寬高直接繫結當前字型的隱式尺寸，位置由外框與文字尺寸同步計算，保證選單開啟或字號變化後的首個渲染幀仍與標籤外框居中，不等待後續佈局補正。首幀檢查同時核對文字尺寸、共享內距和中心位置。

- 選單中的不可用動作保留禁用狀態，不顯示原因副行、hint 或 tooltip，準確原因僅供輔助功能描述讀取。未選中時“解壓所選”和“解壓後設資料預檢”沿用此規則。真實操作失敗與安全錯誤仍在對應任務或欄位中明確顯示。

格式徽標使用內容探測結果的標籤，最小寬度為 32 邏輯畫素，左右內邊距各 6。按實際標籤量測寬度，允許隨文字增長。建立窗透過 `OperationSelect` 顯示登記的格式及適用選項。長標籤和大字號使用共享控制元件度量和可滾動正文，保持視窗登記寬度及共享頁尾可達。見[建立格式選擇稿](../../../design/hifi/sources/create-format-selector.html)和[格式登記](../engineering/format-registry.md)。

<a name="xdzip-2026-10-15-焦点与系统标题栏修订"></a>

外部複製交由平臺拖放會話：Windows Shell 與 Linux QDrag 使用 64 邏輯單位透明預覽、48 圖示及多選數量徽標；計數超過 99 顯示 99+。僅點陣圖儲存按視窗 DPR 取樣，不改變邏輯尺寸。Mac 保留 AppKit 原生檔案 promise 影象與系統反饋。原生系統游標表達複製或拒絕，不把外部複製畫成包內移動；沒有收到成功結果前不顯示已完成。原生影象準備失敗保留安全傳輸與系統預設游標，不降級內容校驗。參考 [Windows Shell 拖動反饋](https://learn.microsoft.com/en-us/windows/win32/shell/dataobject)與 [Qt 6.8 QDrag](https://doc.qt.io/qt-6.8/qdrag.html)。


解壓確認視窗的原生與正文標題均為“解壓檔案”，英文為“Extract files”；工具欄“解壓”動作名稱保持獨立翻譯項，不與視窗標題共用。視窗尺寸、正文與 footer 不因標題修訂改變。

標題區與其首個正文分組之間統一使用 operation.header.bodyGap，當前為 0 個邏輯畫素。標題區自身已包含底部留白，正文不得再疊加舊 hero 的外部間距。卡片內距、正文段落及設定分組間距保留在正文容器內部。Qt 和 HTML 均測量標題區下邊界到首個正文分組上邊界，覆蓋任務執行與三種終態。

<a name="xdzip-操作窗口的动态高度"></a>

## 操作視窗的動態高度

操作視窗的目標客戶區高度仍按各視窗既有的內容、字號及可用螢幕表示式計算。動態調整時先放寬朝目標方向的高度約束，再設定目標高度，最後將上下限恢復為目標值，避免系統按舊限制拒絕調整；完成後視窗仍是固定客戶區高度。視窗重開、內容變化及平臺遲到的幾何回撥繼續使用同一邏輯單位，不引入螢幕縮放係數或新尺寸引數。執行時幾何檢查不能代替原生桌面視覺驗收。
