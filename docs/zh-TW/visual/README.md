3. [Bandizip 解壓操作說明](https://www.bandisoft.com/bandizip/help/how-to-unzip/)：開啟檔案不自動解壓。使用者確認目標目錄、範圍和重名處理後才開始任務。
4. [Transmit 官方介面](https://panic.com/transmit/)：借鑑檔案管理工具的資訊密度、路徑導航和剋制的分隔方式。
5. [Linear 2026 介面改版說明](https://linear.app/now/behind-the-latest-design-refresh)：參考較安靜的側欄、緊湊導航、柔和邊框及中性底色，讓中央內容區成為視覺重點。

<a name="xdzip-视觉系统"></a>

## 視覺系統

採用暖灰底色、鈷藍主操作和石墨深色主題。避免以大面積漸變或磨砂背景替代資訊層級。正常檔案列表保持清晰平面結構；陰影只用於浮層。左側回答“在哪裡”，中間回答“有什麼”，右側回答“選中了什麼”。

Qt 共用 [Xdzip Design Sans SC 字型](../../../design/assets/fonts/README.md)的字形與度量，Qt 使用同源 TTF，超出子集的歸檔名稱使用平臺回退。主列表 13、列頭與工具欄 12、分欄標題 13 邏輯畫素；字型採用 Qt 整數畫素取整。檔名保留完整可訪問名稱；視覺截斷顯示省略號並提供懸停全文。檔案圖示共用約 31.75 邏輯畫素槽位，不按檔案型別分別補償尺寸。

主視窗初始 1024 × 622、最小 832 × 544 邏輯畫素。側欄與預覽欄的源測量約 193.16 / 257.98，Qt 結構邊界取整為 193 / 258；目錄行約 43，檔案行約 44.65。分欄標題高 46，表頭高 34，搜尋與主按鈕約 33.74。目錄樹 B 獨立保持 32 高與 16 圖示槽。窄於 928 時預覽欄收起，透過按鈕開啟獨立原生視窗。設定提供 100%／125%／150% 字號，舊 200% 配置按 150% 讀取；大字號透過真實佈局、滾動和獨立詳情視窗適配，不以整體縮放掩蓋溢位。分欄拖拽與寬度記憶尚未實現。

<a name="xdzip-主窗口交互"></a>

## 主視窗互動

- Qt 支援獨立歸檔會話，按已儲存的開啟模式建立膠囊標籤頁或主視窗，重複開啟啟用已有會話。各頁面保留路徑、選擇、排序和滾動狀態，關閉頁面後任務繼續執行，見[應用會話契約](../engineering/application-sessions.md)。
- 主按鈕：沒有選擇時為“全部解壓”，有選擇時為“解壓所選”；下拉選單始終提供另一種範圍。
- 檔案表格支援排序、多選、範圍選擇和鍵盤導航。資料夾雙擊進入；普通檔案雙擊經臨時解壓交給系統開啟。屬性卡會自動預覽單一支援的檔案，支援範圍與安全邊界見[預覽契約](../engineering/content-preview.md)。
- 搜尋遞迴目前目錄及其後代，根目錄搜尋覆蓋全部內容；搜尋結果顯示完整壓縮檔內路徑，普通目錄列表顯示末級名稱。
- 詳情欄支援關閉與重新開啟。預覽需非同步讀取並限制資源；不支援時顯示屬性和解壓入口。任務取消後丟棄遲到的預覽結果。
- 狀態列顯示選擇數量與原始大小、索引狀態和可重開的任務歷史數；活動任務數單獨用於提示與退出保護。索引尚未結束時明確標記“正在讀取”，不展示偽造的完整數量。

<a name="xdzip-解压面板交互"></a>

## 解壓面板互動

面板集中展示歸檔、目標位置、選擇範圍、同名策略和完成後行為。示例選中 8.4 + 6.2 + 12.8 = 27.4 MB。檔案列表只作摘要，較多時顯示“檢視全部”。

目標位置預設使用上次目錄；“建立同名資料夾”在最終路徑預覽中即時體現，避免重複巢狀。路徑許可權、剩餘空間和歸檔讀取失敗均用文字提示；檢查中的狀態獨立顯示，無法確認空間時顯示“未知”。

重名預設詢問，另外提供跳過、自動重新命名和覆蓋。使用者選擇覆蓋時清楚標記後果。執行中顯示實際階段、已處理檔案數、可計算時的位元組進度與速度；未計算出總量時使用不定進度。取消後顯示“正在停止”，由背景確認停止後再結束任務。

<a name="xdzip-qt-quick-实施约束"></a>

## Qt Quick 實施約束

Qt 使用共享 `Theme` 與生成的尺寸引數。`ArchiveTabs`、`ArchiveToolbar` 和 `SessionPage` 中的列表、網格及目錄區域共用主視窗布局。`InspectorPanel`、`ExtractWindow`、`CreateWindow` 和 `TaskWindow` 各有資料和佈局邊界。QML 呈現狀態與使用者意圖，Rust 執行時負責索引、歸檔讀寫和格式校驗。

macOS、Windows、Linux 共用內容佈局與互動模型；視窗按鈕、選單與快捷鍵遵循各平臺習慣。這裡繪製 macOS 視窗外框，不要求其他平臺複製交通燈按鈕。大面積實時模糊不作為實現要求；截圖中的背景弱化可用靜態遮罩實現。

可審閱主視窗的淺色或深色，以及任務狀態、設定和桌面整合。其他狀態與尺寸例外見[視窗登記](../../../specs/visual/window-registry.json)。設計頁可以展示原生視窗或選單的內容。裝飾、啟用、縮放和系統選單的實際表現須在對應平臺核對。

<a name="xdzip-原稿与统一素材库"></a>

## 原稿與統一素材庫

[完整原稿](../../../design/hifi/README.md) 集中在 `design/hifi/screens/`，包括主視窗、解壓確認與八張操作狀態圖板。功能及恢復路徑見 [狀態契約](../ux/hifi-state-spec.md)。原稿保持原始位元組，原稿及其切片不能因實現需要而修改。

[統一素材庫](../../../design/assets/README.md) 集中全部主視窗與操作狀態素材，取消按交付批次拆分的目錄。SVG 是透明執行圖示的唯一圖形源，Qt 使用同源多倍率 PNG。45 張原畫素對照切片儲存在 `reference/`，保留精美原圖、裁切範圍及背景。兩者都在同一清單中標明用途，避免把帶背景切片當作透明圖層。

所有透明圖示共用 24×24 畫布。PDF、文字、程式碼和 Markdown 圖示統一中心與 22 畫素可見高度，保留各型別的輪廓寬度和內部樣式；資料夾採用 22×約18.86 的橫向可見輪廓並在畫布居中。此高度約束用於執行圖示，不描述原稿切片的尺寸。1×/2×/3× PNG 分別為 24×24、48×48、72×72；倍率不改變邏輯大小。Qt 檔案列表使用同尺度換算後的約 31.75×39.69 邏輯畫素槽位，取消逐型別 CSS 放大、平移和描邊補償。

檔案列表麵包屑與右側預覽／詳情標題共用欄高、字號和文字垂直中心。Qt 使用 `PaneHeader` 與 `Theme.mainPaneTitleSize`；標題保持在滾動內容上方，大字號同步增加兩欄高度。實際量測按[驗證方法](../../../developers/qa/README.md)保留於執行工件。

照片預覽從分欄標題下邊緣直接開始，頂邊與檔案列表表頭一致，不增加額外頂部間距；搜尋提示條出現時，按其實際佔位同步對齊。圖片高度和下方內容間距沿用既有規格。照片對齊複驗覆蓋兩張示例圖片、淺深色、三種視窗裝飾及搜尋變化。

檔案列表的原始大小、壓縮大小標題與數值靠右對齊，型別標題與內容靠左對齊；每列共用內容邊距。複驗須記錄全部可見行的文字佈局邊緣。

圖示輪廓形狀、原畫素對照切片尺寸與執行畫布尺寸分別記錄；資料夾無需被拉長成紙張形狀，SVG 也不應為填滿槽位而變形。視覺調整集中在圖形源完成，在素材畫廊複核後再同步兩種實現。

## 目錄樹 B 元件修訂（2026-10-12）

新增三張正式圖板定義多級展開、節點互動和導航邊界，見[目錄樹規格](../ux/directory-tree.md)。26 張原畫素切片進入統一 `assets/reference`，分支圓點、實心狀態圖示與分段轉輪使用兩主題 SVG 與三倍率 PNG。連線線、狀態背景、焦點與文字按[獨立元件引數](../../../specs/visual/directory-tree.json)動態繪製；引數不自動覆蓋現有全域性 tokens。目前圖板為放大視覺說明，精確邏輯尺寸與源畫素矩形分別記錄。Qt 已接入遞迴目錄、連線線及隱藏目前分支標記；專用邊界圖示／骨架仍為設計資源，完整深色元件圖板待補齊。

<a name="xdzip-当前主稿的工具栏修订2026-10-12"></a>

## 目前主稿的工具欄修訂（2026-10-12）

上述早期通用控制元件建議不再用於主工具欄。目前控制元件的原稿量測為 51 源畫素高、18 源畫素字號、32 源畫素圖示，按主視窗 1024/1548 換算為約 33.74 高、12 整數字號和 21.17 圖示畫布；工具欄區域高 53。此前按 1280 寬換算的 42.17/15/26.46 已被正常密度取代；普通操作視窗繼續使用各自登記的對映。

工具欄左右普通動作與搜尋/主操作分組佈局；大字號可增長高度，搜尋框可收縮，保證最小視窗下右側操作完整可見。禁用文字不疊加整組透明度，主按鈕使用單獨的禁用背景顏色。解壓主按鈕保留分隔線和下拉箭頭的禁用外觀，實際解壓與範圍選單按執行時能力啟用，未選中時禁用所選範圍與後設資料預檢；完整性檢查按目前歸檔能力啟用。複驗按[通用驗證方法](../../../developers/qa/README.md)記錄。

<a name="xdzip-应用品牌与平台图标"></a>

## 應用品牌與平臺圖示

各格式的系統文件圖示使用[檔案關聯圖示規範](file-association-icons.md)。該家族複用以下品牌幾何，提供獨立格式標籤、輔助色與小尺寸簡化；作為後續逐格式接入的設計素材。

應用品牌採用四條交錯帶與開放的 U 形下部，幾何統一維護在 `scripts/brand_assets.py`。獨立標記、應用圖示與 ZIP 文件母版位於 `design/assets/brand/`；介面的 `app-mark`、`archive`、`archive-grey` 分別用於應用、藍色歸檔和灰色歸檔身份，均從同一品牌幾何生成。應用使用藍色圓角外形，文件使用紙張與折角外形，身份共用而外框各有職責。

目前標記保留修長的 2:3 比例，不橫向拉伸為舊標記寬度。底板使用四角旋轉對稱的連續曲率曲線，曲率從直邊的零值平滑增加到對角中點，避免圓角中間出現斜切感。光照與底板使用同一路徑；不疊加不同半徑的描邊或開口高光線。文件徽章沿用同一輪廓定義。

這是明確的新品牌設計修訂，不能把它描述為舊高保真原稿中 ZIP 拉鍊圖示的無差別還原。十張完整原稿、45 張原畫素圖示參考和三張示例照片保持原位元組；新生成的 `brand/identity-reference.png` 是目前品牌的視覺方向，用於審閱，不作為執行資源。主素材清單逐項記錄參考覆蓋，對舊品牌參考明確標註歷史設計角色。

介面小圖示仍使用 24×24 畫布；平臺圖示分別從母版匯出 16/24/32/48/64/128/256/512/1024 畫素透明 PNG。16/24/32 畫素簡化不可讀文字及大圖光影，保留交錯帶與 U 形的識別結構；應用和 ZIP 文件各提供含七種尺寸的 ICO、含十一種密度表示的 ICNS。不能把 24 單位介面圖示無限放大充當系統圖示，也不把大圖陰影縮成小尺寸噪點。

系統應用圖示接入 Qt 視窗、macOS app bundle、Windows 可執行資源以及 Linux 桌面啟動項 / hicolor 圖示目錄。ZIP 文件平臺格式已用於安裝器及檔案關聯，系統開啟請求透過統一路由進入真實瀏覽，詳見[安裝與關聯契約](../engineering/installers-associations.md)。只註冊開啟候選，不修改使用者預設應用。平臺驗證按[通用方法](../../../developers/qa/README.md)記錄。

主題、成功、取消、衝突及進度缺圖從原畫素參考補齊為獨立語義素材；取消大圖使用方形停止符號，系統主題保留完整視窗結構。Qt 使用 IntentRadioButton 將滑鼠、鍵盤與輔助功能動作路由至同一選擇模型；素材只負責外觀。此次新增與修訂素材的生成檢查、目標平臺顯示和原稿差異分別記錄，既有驗收不能代替本輪結果。

## 可操作控制元件規範

[controls.json](../../../specs/visual/controls.json)定義選單四列、行高、圓角、顏色、焦點和提示時序；[directory-tree.json](../../../specs/visual/directory-tree.json)定義目錄層級。兩份規格生成 QML Theme，透過檢查避免手工複製尺寸與主題。主稿的邏輯 / 源畫素比例從 `layout-scale.json` 讀取。功能清單與輸入契約在[主視窗元件說明](../ux/main-window-components.md)，真實渲染與行為按[驗證方法](../../../developers/qa/README.md)儲存到對應 issue 與工件。
