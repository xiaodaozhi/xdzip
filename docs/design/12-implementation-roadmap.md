# xdzip：12 实施路线与现有原型迁移

## 1. 当前与目标

独立实验工作区中的 `crates/lab-core` 使用固定十万条样例、JSON 和 C ABI、单模拟任务；`apps/qt` 有后台 QThread、分页模型和 QML 界面。它们证明界面路线可行，没有真实格式、文件授权或安全输出。

目标是保留实验资料并建立正式产品边界，不把实验 Engine 改成包罗万象的业务对象。本次只生成设计，以下目录和任务均待实施。

```text
apps/desktop/                 CMake、C++ 控制器/模型、QML、平台集成
crates/xdzip-domain/
crates/xdzip-codec-api/
crates/xdzip-codec-zip/
crates/xdzip-codec-tar/
crates/xdzip-index/
crates/xdzip-io/
crates/xdzip-platform/
crates/xdzip-runtime/
crates/xdzip-plugin-host/    后续启用，协议先独立定义
crates/xdzip-qt-bridge/
tools/codec-conformance/
tests/fixtures/               自建、授权、可生成样本
docs/design/                  本文档集
experiments/ui-lab/            原型及测量，迁移时保留原始证据
```

xdzip 从独立仓库开始，不复制实验代码作为产品基础。上表 experiments 仅是未来可选的证据归档位置；需要迁入时先核查来源和可复现性。正式 workspace default-members 和打包清单只含 Qt 产品，实验工具需明确命令运行。

## 2. 实施工作包

| 里程碑 | 工作包 | 退出条件 |
|---|---|---|
| M0 基线冻结 | 工具链/平台、Qt许可模块、构建清单、领域 ID、需求测试清单 | 支持矩阵可解释，依赖版本及发行路径明确 |
| M1 产品骨架 | cxx 双句柄、Qt 控制器、空闲事件、关闭、无 Qt 核心测试 | 三平台最小构建与关闭竞态通过；无 GUI 同步长调用 |
| M2 只读 ZIP | 探测、真实目录索引、查询/选择、源版本、能力 | 10 万条真实元数据流畅；损坏/不支持特性可解释 |
| M3 安全解压 | 平台授权、路径映射、暂存、CRC、冲突、配额、取消 | 原生链接竞态、磁盘满、cancel/commit、目标外无变化 |
| M4 创建及 TAR | ZIP创建、TAR/TAR.GZ组合、输入树、安全提交、摘要 | 双向互操作；取消保留旧归档；流式进度真实 |
| M5 v0.1 私测 | Mac IME/GPU/无障碍、三平台包和基础基准 | P01～P12/P15 对应首版项达标，范围明确，无真实扩展执行 |
| M6 大索引/预览 | 磁盘索引、百万条、结果分页、受限预览 | 资源上限与清理可验证，无自动执行内容 |
| M7 额外格式 | 7z、条件满足的 RAR只读、独立加密/分卷能力 | 每个组合独立互操作/取消/许可，不只打开一个样例 |
| M8 SDK 试验 | CBOR协议、broker、样例扩展、权限与平台沙箱 | 两个独立实现互通；平台越权测试通过才启用第三方 |
| M9 v1.0 | 安全审查、发行合规、性能参考机、支持政策 | 三平台签名包和全部已声明能力通过发布门槛 |

M1→M2→M3 是关键路径；设计系统与测试样本可同时由不同贡献者开发，但任何 UI 接入以服务契约为准。没有沙箱实现经验时先交付内置扩展式产品，不阻塞可靠 ZIP MVP，也不提前放开第三方代码执行。

## 3. 原型资产处理

| 现有资产 | 复用方式 | 必须替换/补充 |
|---|---|---|
| Qt 虚拟分页模型 | 缓存思路、generation guard、键盘验证 | QuerySnapshot身份、增量扫描、完整模型信号与结果类型 |
| Qt QML 主窗口 | 虚拟化与交互经验；正式视觉以已确认高保真稿为准 | tokens、可访问性、IME、能力、真实错误与任务摘要 |
| lab-core 条目生成器 | 大数据 UI/性能测试 fixture | 不用作真实读取；领域类型独立建模 |
| JSON/C ABI | 保留比较和回归实验 | 正式桥接迁到 cxx，实验 ABI 不成为外部 SDK |
| 单模拟任务 | 自动化流程示例 | 多任务状态机、资源池、实际字节、提交许可和输出日志 |
| Linux 测量脚本 | 环境记录和顺序轮换方法 | 原生 Mac/Windows、真实 GPU、完整打包和真实 I/O |
| Slint/Tauri 原型 | 历史研究与 UI 独立性证据 | 不进入产品运行时/安装包依赖 |

从实验复制代码时逐段审查线程/所有权，不能因为原型 Clippy 通过就认为产品路径安全已证明。任务轮询被事件接收取代后，基准取消指标定义同步更新。

## 4. 推荐首个实现增量

先交付可审查的最小产品切片：打开一个普通 ZIP → 展示真实目录 → 选择一个小文件 → 到新建私有子目录安全解压 → 校验 → 结果摘要。包含 cxx、线程、授权、路径和取消，但暂不支持覆盖旧文件。

该增量通过后再加入冲突覆盖、全部解压、新建归档和 TAR。一次接入所有格式会把 codec、I/O 和界面问题混在一起，不利于确定安全边界。

## 5. 工作分工接口

UI 维护者交付 tokens、QObject 模型、焦点和平台交互；核心维护者交付领域、运行时、索引与任务；安全文件层维护者交付各平台授权/提交；格式维护者交付适配器和互操作；发布维护者交付包、签名、SBOM 和基准。

这是分工建议，不是本次已启动的多代理工作。每个工作包以依赖、产物、验收和风险明确交接。尚缺专长的安全/许可证项保留为发行阻断，不假设人员必然到位。

## 6. 排期方法

不在未验证 cxx/平台文件 API 前承诺精确完成日期。M1/M3 是最大技术不确定性，先用技术验证缩小工作量，再按一到两周可验收增量计划。每阶段展示真实操作和失败行为，不能只展示静态 UI。

范围扩展只能通过明确需求和能力表进入；新格式若新增原生库、密码、分卷或特殊输出，需重新评估安全、调度和许可，而非仅改后缀列表。
