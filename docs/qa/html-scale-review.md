# HTML 展示尺寸复核

日期：2026-10-12。范围为审阅入口、原稿对照、独立预览和离线单文件的展示比例；内部顶部与正文继续沿用原稿独立锚点。

## 尺寸定义

| 基准 | 主窗口 | 完整画布 | 用途 |
| --- | --- | --- | --- |
| 源图片坐标 | 1548 × 940 | 1586 × 992 | 原稿像素 1:1 测量 |
| 正常设计尺寸 | 1280 × 约777.26 | 约1311.42 × 820.26 | 默认桌面展示 |

正常比例为 `1280 / 1548 = 0.826873385`，沿用视觉规范中的逻辑窗口宽度，按原稿比例保持高度。不推断图片的 DPI 或 Retina 倍率，不按设备像素比自动除以 2。内部组件保持原稿坐标，统一变换整个画布，避免独立缩小文字、图标和间距破坏对齐。

## 修正原因

原先 HTML 与原稿采用了不同的缩放路径：HTML 的“100%”固定为源坐标大小，原稿图片却一直 `width:100%`，并受到独立容器内边距影响。源画布还被设为 1588 × 1000，与 PNG 的 1586 × 992 不同。

修正前独立浏览器测量显示：1200 宽视口的“100%”模式中，HTML 窗口宽1548，原稿显示窗口约1108.78；手机适应模式也有约11.29%的尺寸差。不能仅凭截图把差异归因于浏览器缩放、设备像素比或旧文件。

## 统一展示规则

- 桌面默认“100%（设计尺寸）”；手机默认适应屏幕。适应模式最多显示正常设计尺寸，不在宽屏继续放大。
- HTML 与原稿共用 `display-spec.js`、相同源尺寸、同一倍率和同样的可滚动范围；图片不再独立适应容器。
- “原稿像素 1:1”明确显示源坐标大小。切换模式时两侧同步，不能一侧滚动、一侧缩小。
- 独立预览打开当前画面，沿用平台、主题和倍率；主窗口不再被替换成解压窗口。
- 空归档和损坏归档仍在主窗口画布中展示，不会因独立操作窗口样式而隐藏。
- 固定内嵌画布不分配根文档滚动条空间。页面上下滚动，窄屏在正常或原稿像素倍率下保留外层横向平移；内容容器独立滚动。画布宽度观察补足经典页面滚动条改变可用宽度时的重新拟合。

## 验证与交付

执行 `python scripts/build-html-design.py`、`python scripts/check-html-scale.py`。验证读取原始 PNG 尺寸，不从当前 CSS 反推目标；覆盖源像素和正常尺寸、适应屏幕、设备像素比、原稿比例、独立窗口、异常状态及离线资源。

尺寸报告和同倍率截图生成于 `dist/html-scale-review/`。可操作单文件为 `dist/xdzip-hifi-design.html`。本轮为 HTML 展示校准，不将浏览器装饰视为原生 Qt 系统窗口验收。

顶部27项与正文70项严格检查继续在源坐标运行，文字轮廓仍独立记录；展示尺寸通过不等于字体、光影或所有操作图板已逐像素还原。

本地结果：**391 项检查全部通过**。移除 Playwright 默认的 `--hide-scrollbars`，在真实经典滚动条环境重跑既有 369 项，并增加网页／离线各五项：CSS 缩放 1.1／1.2／1.25、画布视口缩小 1 px，以及移除嵌入规则的负向用例。负向用例须实际产生滚动条占位；修复用例须保持根条占位为零、窗口四边可见。另加入网页／离线、1200 宽度、1008／1014／1020 高度、原稿收起／展开的 12 项临界高度用例，保持原有尺寸断言。

矩阵覆盖 288 种画面、屏幕宽度、设备像素比与倍率组合，以及原稿尺寸契约、同步滚动、独立预览首开和重复开窗。宽度390/1200/1827、DPR1/2的正常窗口均保持1280逻辑宽；原稿像素模式保持1548宽。两层正常截图尺寸同为1312×822（浏览器截图对亚像素边界取整），JavaScript错误与外部资源请求均为零。真实经典条测试曾揭示手机适应模式沿用旧宽度的问题；补充画布宽度观察后，16个失败组合复验通过，未放宽原尺寸断言。
