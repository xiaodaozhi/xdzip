# 文件类型排序回归

日期：2026-10-13。类型排序的升序、降序都保持文件夹在前；目录身份读取数据中的标记，不比较“文件”“文件夹”显示文案。

原问题：Rust 中目录和无后缀文件都使用空字符串作为类型键，相同键按物理记录 ID 排列，因此混排。现改为先区分目录／文件，再比较文件的规范化扩展类别；降序只反转类别，目录分组和相同类别的身份顺序保持。普通目录列表、隐式导航目录和递归搜索共用这一规则。

HTML 另有对应问题：文件未设置 `folder` 字段时，`Number(undefined)` 为 `NaN`，目录分组比较失效。现先转成布尔值，缺失标记按普通文件处理，再比较分组。

## 回归样本与检查

[type-order.zip](../../tests/fixtures/zip/type-order.zip) 是项目自建的确定性 ZIP，生成方式和 SHA-256 见[样本说明](../../tests/fixtures/zip/README.md)。记录故意交错排列，不依赖真实用户归档。

| 边界 | 预期与检查 |
| --- | --- |
| 无后缀文件与目录 | 类型升降序中，目录始终先于 README、LICENSE 等文件 |
| 带扩展名的目录 | `item-folder.ZIP/` 按目录标记分组，不按 ZIP 文件处理 |
| 隐式目录 | 根目录的 `item-implicit/` 与显式目录位于同一目录组 |
| 递归搜索 | 搜索仅返回物理记录，目录／文件分组仍保持 |
| 大小写 JPG／JPEG | 同属 JPEG 类别，记录 ID 稳定决定先后 |
| 同名物理记录 | 两条 `item-duplicate` 均保留，两个排序方向中 ID 顺序不变 |
| 内部传输批次 | 将已排序结果分成 3 条批次，拼接顺序与完整查询一致 |
| Qt 实际操作 | 鼠标点击类型表头切换两个方向，并验证搜索后的名称、顺序及“文件”“文件夹”显示值 |
| HTML 缺失目录标记 | 注入两个没有 folder 字段的无后缀文件，通过实际表头点击验证分组及重复记录顺序 |

Rust 工作区测试与 Clippy `-D warnings` 通过；本地 Qt 6.8.2、Linux offscreen / software 的 5 组 CTest 通过，包含 `typeHeaderSortGroupsDirectoriesBeforeExtensionlessFiles`；离线 HTML 共享交互检查 23 项通过，无页面错误、无外部请求。C++ 格式、JavaScript 语法、字体覆盖、单文件 HTML 生成及文档链接检查通过。

本次改变排序语义与测试，不改变组件尺寸、素材或窗口装饰。本地证据不代表新提交已完成 macOS 原生验证；三平台 CI 的完整浏览测试组会执行新增用例。
