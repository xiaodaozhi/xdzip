# 发行审查流程

本页定义每个候选可复用的审查方法，不登记某一候选的进度或审批结果。当前事项、责任角色和资源限制记录于[独立发行审查 issue](https://github.com/xiaodaozhi/xdzip/issues/4)；工作包完成、自动检查成功和正式发行批准是不同结论。

## 候选与输入

审查绑定明确的版本、完整提交 SHA、源码包、各平台实际安装包和 SHA-256。提供同提交的 SBOM、来源与通知、离线重建、Qt 源码及替换验证、性能与人工验收材料。源树或包发生变化时重新评估受影响项，不能混用不同提交的二进制与历史报告。机器报告的 `automatic_complete` 和 `release_ready` 不因 issue 关闭或文档整理而改写。

## 评审项目

| 编号 | 范围 | 所需结论 |
| --- | --- | --- |
| RR-01 | 许可来源与再分发义务 | 实际交付的 Qt、Rust、原生库、字体及图标的来源、适用许可、通知、对应源码及替换材料逐项核对；修补缺失材料后重建实际候选及校验和 |
| RR-02 | 独立安全审查 | 独立审查者针对固定提交的真实报告，以及发现处理与回归；作者自查、自动测试和扫描不能冒充独立结论 |
| RR-03 | 私密报告提交与接收演练 | 在具备条件时验证实际提交、所有者接收、通知与私密关闭；入口启用或匿名可见不能代替端到端演练 |

项目维护者负责汇总与跟踪。资源或条件不可用时，在 issue 如实登记未执行和限制，不自动视为通过或豁免，不要求购买审查服务或付费签名身份。已有有效人工验收不因材料整理而失效。

## 记录和交接

许可核对遵循[运行时归属](../engineering/runtime-attribution.md)、[对应源码](../engineering/source-delivery.md)及[SDK 对应核验](../engineering/qt-sdk-correspondence.md)。哈希对应不等于取得再分发许可或复现上游构建历史，补充通知不代表旧包已经包含通知，禁止改写已交付包及原校验和。

安全审查使用[交接方法](independent-security-review.md)及[报告模板](independent-security-review-template.md)。每个结论注明编号、候选、实际执行范围与限制。漏洞细节、用户文件、密码及私人路径通过已有私密渠道交接，不在公开 issue 上传利用样本。不由代理擅自联系审查者、发送报告或创建演练漏洞。

私密流程演练由具备条件的协作者明确标记为演练，不伪造漏洞影响，不发布 Advisory 或申请 CVE。只检查入口时记录为入口检查；实际通知、接收和私密关闭分别记录结果。

## 发行决定

系统范围和维护方式遵循[支持政策](../engineering/support-policy.md)。实际发行前复查依赖安全、未解决缺陷、通知、源码、工件和哈希，并按[发布手册](../engineering/release-runbook.md)处理评审结论与已知限制。未经所有者对具体结果的批准，不创建 Release、标签或公开上传安装包。

付费开发者账号、签名证书、Developer ID 和公证不要求；macOS 保留必要的 ad-hoc 完整性签名，Windows 使用未签名安装器。这不批准未完成的许可或安全审查。
