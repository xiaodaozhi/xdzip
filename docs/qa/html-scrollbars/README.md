# HTML 画布滚动复核

日期：2026-10-12。范围为 HTML 审阅画布的滚动职责与经典滚动条回归，不改变原稿、图标或产品组件尺寸。

## 问题与修正

内嵌源画布之前沿用浏览器文档滚动。在真实经典滚动条环境中，画布视口比源尺寸少 1 px，就能触发纵向滚动条；纵向条挤占宽度后又触发横向条。窗口本身仍在画布内完整显示，外侧却增加两条粗滚动条。该路径可以复现截图里的现象；仅凭截图不能确定当时视口尺寸偏差的具体来源。

此前 Playwright 默认启用 `--hide-scrollbars`，自动截图掩盖了经典条的实际占位。现在明确移除该参数，保留既有几何断言，同时检查根条占位和窗口四边，避免只验证图片看起来完整。

修正后的职责如下：

| 层级 | 滚动规则 |
| --- | --- |
| 内嵌画布根文档 | 固定源尺寸，隐藏根文档溢出，不分配根滚动条空间 |
| 审阅页面 | 按页面内容上下查看 |
| 画布外层 | 当屏幕窄于当前倍率时允许横向平移；与原稿同步 |
| 文件列表、预览属性、操作窗口 | 按真实内容独立滚动，长内容末尾操作可达 |
| 直接打开的非嵌入 canvas.html | 保留浏览器文档滚动 |

真实滚动条验证也发现手机适应模式的旧问题：切换画面或展开原稿改变了页面滚动条、可用宽度随之改变，只有 `window.resize` 无法及时更新倍率。审阅工具增加画布宽度观察，宽度变化后重新等比拟合，忽略仅高度变化的通知。

在页面高度临界值附近，缩放后的高度可能反复跨过浏览器高度，导致纵向条出现／消失、宽度变化又触发重新缩放。审阅页面使用 `scrollbar-gutter:stable` 稳定经典页面滚动条的预留宽度；没有溢出时该位置只有页面背景，实际条仍按需出现。独立预览恢复 `auto`，保持按图板尺寸开窗。该规则只控制审阅页面，不占用内嵌图板空间。

- [专项测量](validation.json)与[完整尺寸矩阵](../html-scale/validation.json)。

执行 `python scripts/check-html-scale.py`，391 项通过：覆盖网页／离线、390／1200／1827 宽度、DPR 1／2、三种倍率、原稿同步和独立预览，并加入三档 CSS 缩放、1 px 容错、移除规则的负向检查以及 12 项页面临界高度检查。执行 `python scripts/check-html-preview.py`，17 项通过：验证真实经典条开启时正常属性无溢出、长属性确实滚动且解压按钮可点击。顶部 27 项、正文 70 项、原稿加载 27 项与示例流程 20 条也通过。

上述证据来自 Linux Chromium 浏览器。它们验证 HTML 画布与内容滚动，不代替 macOS Safari、原生 Qt 窗口或整页视觉一致性验收。

[独立补充检查](independent-audit.json)另有 45 项通过，涵盖网页／离线／隔离来源、临界高度反复展开原稿、真实列表滚轮、长属性与操作窗口的底部按钮、直接打开源画布，以及离线独立预览初始尺寸。隔离来源预览栏只验证程序滚动与操作可达，未将指针滚轮尝试计为成功；独立预览的任意手动缩放尺寸未作全面验收。离线手机对照文件为 `dist/xdzip-scrollbar-review.html`。
