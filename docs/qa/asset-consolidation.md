## 原有素材的实际用途

此前素材分散在两个目录，但已经同时用于运行界面：HTML 合计加载 94 张浅深色 SVG 和三张示例照片，Qt 的 37 个资源别名分别从两处引用透明 PNG。操作状态包中的信息、图片与文档图标也已进入 Qt，完整操作窗口原稿用于功能状态设计和视觉对照。

精美的原像素切片包含原图背景，原稿没有可导出的透明矢量图层。因此它们用于直接对照重建图标的轮廓、渐变和细节，不能直接作为任意主题下的透明运行图标。此次合并保留十张完整原稿及全部 48 张切片的原始字节：45 张图标/插图对照素材放入 `reference/`，三张照片放入 `demo/`；照片继续用于 HTML 示例。

统一后的 `svg/` 为图形源，`png/` 为同源导出，HTML 和 Qt 引用同一素材清单。Qt 当前 37 个资源别名引用 34 张不同的 3× PNG；多个别名可以指向同一文件。当前文件列表映射覆盖目录、PDF、文本、代码、Markdown 和图片。

## 原有尺寸问题与本次修复

此前透明图标的画布已经都是 24×24，但纸张主体、折角、边框与可见高度不同；HTML 又分别对 PDF、文本、代码及 Markdown 设置大小、放大、平移和描边补偿。因此画布看似统一，实际图形仍参差不齐。

本次从共用 SVG 修复图形，PDF、文本、代码和 Markdown 图标在 24×24 画布中统一中心与 22 像素可见高度，各自保留相应的轮廓宽度、折角或边框样式。文件夹保持 15 像素可见高度的横向轮廓并居中。上述高度是透明运行图标的几何约束，不是原稿中所有文件图标的共同高度；文件夹也不拉伸成纸张形状。

| 层次 | 尺寸与规则 |
| --- | --- |
| 共用矢量源 | `viewBox="0 0 24 24"`，透明背景 |
| PNG 导出 | 1× 为 24×24、2× 为 48×48、3× 为 72×72；相同逻辑尺寸 |
| HTML 文件列表 | 所有文件类型与目录共用 48×48 源空间槽位；正常展示约 39.7×39.7 逻辑像素 |
| Qt 文件列表 | 沿用 18×18 逻辑像素槽位；按设备倍率请求资源并等比显示 |
| 原像素对照切片 | 保留原裁切矩形与背景，不用切片物理尺寸设置运行图标 |

HTML 移除逐类型 CSS 图形变换，Qt 按文件类型选择统一资源。两者的图形源一致；当前 Qt 产品列表密度与 HTML 原稿展示比例不同，素材共用不代表两个实现的显示尺寸已达到 1:1。

## 目录与维护

`hifi/` 只保存完整原稿及其画廊；`assets/` 保存全部运行图标、照片、对照素材、字体与清单。目录按用途组织，名称不携带交付批次。旧输入路径、迁移后路径和迁移前 SHA-256 在迁移清单中对应；对照切片和完整原稿记录原字节保留，已重建的 SVG/PNG 不冒充原切片。

素材变更只修改统一 SVG 生成源，再重新导出 PNG 和 HTML 嵌入资源。资源集成检查拒绝未登记文件与原背景切片进入 Qt。HTML、Qt 及生成器中不另存一套手绘文件图标。

## 检查与边界

当前完整原稿画廊已通过十张图片的 SHA-256 校验和生成同步检查。内嵌原图的离线画廊在 Chromium、390×844 视口中加载全部十张图片，无横向溢出，目录按功能展示且只有一个素材入口。离线素材画廊在 390 和 1280 像素视口下的 351 张图片全部加载，无外部请求及横向溢出，详见[验证记录](asset-review/gallery-validation.json)。素材清单、引用、透明度、倍率、图标几何及实际窗口验证结果在本轮集成完成后补入此处；未完成的验证不标记通过。
