Esta página define os caminhos aplicáveis de compilação e redistribuição no Windows e é usada com os [materiais nativos](native-runtime-materials.md), a [entrada de compilação para desenvolvedores](../../engineering/developer-build.md) e o [contrato de instalação](installers-associations.md). <a name="xdzip-free-community-path-and-local-choice"></a>

## Caminho Community gratuito e escolha local

O conteúdo original do projeto é publicado sob Apache-2.0, licença de código aberto aprovada pela OSI. Os termos individuais do Visual Studio Community 2022 permitem que pessoas desenvolvam seus próprios aplicativos; os termos de organizações também permitem que seus usuários desenvolvam e testem aplicativos publicados sob licenças aprovadas pela OSI. Avaliar separadamente o uso de código aberto de uma organização e outros usos comerciais internos; não estender a elegibilidade deste projeto a outros.

Quando um mantenedor precisar do próprio ambiente Community, obter Community 2022 pelo [instalador oficial da Microsoft](https://learn.microsoft.com/en-us/visualstudio/install/use-command-line-parameters-to-install-visual-studio?view=vs-2022), ler e aceitar [os termos originais dessa versão](https://visualstudio.microsoft.com/license-terms/vs2022-ga-community/) e utilizá-lo em seu escopo. Para compilações C++, selecionar `Microsoft.VisualStudio.Component.VC.Tools.x86.x64` e o SDK do Windows; não é necessário instalar todas as cargas de trabalho. Não há exigência de comprar Professional/Enterprise ou solicitar certificado separado de distribuição do runtime para cada projeto.

A revisão de licenças não exige manter um IDE grande instalado localmente. Ao compilar e publicar apenas no ambiente padrão hospedado pelo GitHub abaixo, a base aplicável é a autorização do Visual Studio hospedado e seus termos REDIST; não é necessário instalar Community local ou comprar Enterprise pessoal para CI hospedada. Community é uma opção gratuita quando mantenedores precisam do próprio ambiente, não uma condição adicional de instalação local para a legitimidade da compilação hospedada.

A seção 3 do Community permite arquivos de software e Build Tools em dispositivos de compilação elegíveis; a seção 4 concede direitos de distribuição do código distribuível listado, sujeitos a requisitos de funcionalidade, termos posteriores e restrições. Baixar VC_redist, instalar Build Tools ou apenas incluir um texto de licença não comprova elegibilidade para usar ferramentas de desenvolvimento. Sem licença do Visual Studio, a exceção do Build Tools abrange compilar e construir componentes C++ de código aberto de terceiros aprovados pela OSI e razoavelmente necessários para construir seus aplicativos. Ela não permite desenvolver ou testar essas dependências, exceto pequenas modificações necessárias para compilá-las e construí-las, e não é uma exceção geral para desenvolver todos os próprios programas C++. Usar VS Code não fornece automaticamente licença MSVC. Consulte as [orientações de licença da Microsoft](https://www.microsoft.com/licensing/guidance/Visual-Studio) e os [termos do Build Tools](https://visualstudio.microsoft.com/license-terms/vs2022-ga-diagnosticbuildtools/).

Verificar localmente produto, versão completa, condição não preliminar e componentes C++ informados por `vswhere`, entrar no ambiente de desenvolvimento da instância real e verificar `cl`, `link` e o SDK. Build Tools 2019 instalados não são Community 2022 e não substituem a verificação da cadeia MSVC 2022 atual. O `desktop.py prepare` genérico não instala silenciosamente IDE ou SDK do sistema; na primeira instalação usar o instalador da Microsoft, preservar ferramentas existentes e impedir reinicialização automática.

Escolher 2022 é a decisão atual da cadeia de entrega, não uma afirmação de que a licença Community gratuita permita apenas 2022. A [tabela de suporte Qt 6.8](https://doc.qt.io/qt-6.8/supported-platforms.html) lista Windows MSVC 2022; este repositório usa o SDK `msvc2022_64` correspondente. Ferramentas 2019 podem permanecer para desenvolvimento local, mas compatibilidade ABI entre versões não comprova suporte completo quando misturadas ao SDK atual. As [regras de compatibilidade da Microsoft](https://learn.microsoft.com/en-us/cpp/porting/binary-compat-2015-2017?view=msvc-170) também exigem geralmente que o vinculador final não seja mais antigo que as ferramentas das bibliotecas de entrada e restringem separadamente runtimes e `/GL`/`/LTCG`. Configurações alternativas exigem licença e verificação próprias; isso não obriga a instalação local do IDE 2022 completo.

<a name="xdzip-github-hosted-builds"></a>

## Compilações hospedadas pelo GitHub

O workflow Windows do projeto usa runners padrão hospedados pelo GitHub `windows-2022`. O produto pré-instalado é Visual Studio Enterprise 2022, não Community. Os mantenedores de runner-images [confirmaram](https://github.com/actions/runner-images/issues/12945#issuecomment-3348002951) que o Enterprise pré-instalado está disponível para runners hospedados públicos e privados do GitHub Actions/Azure DevOps por acordo entre GitHub e Microsoft, sem licença Enterprise pessoal separada. O projeto utiliza esse ambiente; a explicação pública não substitui nem afirma revelar o acordo completo.

Segundo a [documentação de runners hospedados do GitHub](https://docs.github.com/en/actions/concepts/runners/github-hosted-runners), cada job Windows recebe uma VM independente e `Set up job` aponta para a imagem e o inventário de software daquela execução. Os workflows compilam, testam, implantam e publicam apenas este repositório dentro dos [termos adicionais do Actions](https://docs.github.com/en/site-policy/github-terms/github-terms-for-additional-products-and-features#actions). A franquia gratuita de processamento de repositórios públicos e os direitos de redistribuição de componentes Microsoft são distintos.

A CI registra produto e versão reais do VS, localização relativa do compilador, versões de ferramentas e SDK em `windows-toolchain.json`, guardado com pacotes e materiais do mesmo commit sem chaves de produto ou caminhos privados de desenvolvedores. Ele identifica ferramentas, não comprova automaticamente elegibilidade de licença. Runners auto-hospedados, ferramentas copiadas localmente das imagens, outros serviços CI e servidores compartilhados gerais não herdam a licença hospedada; verificar novamente termos Community/Build Tools e condições dos dispositivos.

<a name="xdzip-microsoft-component-redistribution"></a>

## Redistribuição de componentes Microsoft

A [lista REDIST do VS 2022](https://learn.microsoft.com/en-us/visualstudio/releases/2022/redistribution) inclui explicitamente Community 2022 com licença válida. A compilação atual usa VC_redist x64 de versão final fixado em [windows-runtime.json](../../../scripts/windows-runtime.json), extrai-o sem alterações e verifica individualmente oito DLLs CRT e a licença original do runtime. Não inclui compiladores, depuradores ou `debug_nonredist`. Nem o caminho gratuito Community nem a identidade Enterprise da CI hospedada relicenciam DLLs Microsoft sob Apache-2.0.

Novos pacotes de desenvolvimento não incluem `d3dcompiler_47.dll`, `dxcompiler.dll` ou `dxil.dll` do SDK do Windows, nem biblioteca OpenGL por software Mesa. Em pacotes históricos esses três arquivos vinham de `Redist/D3D/x64` de um SDK explícito. A [lista REDIST do SDK](https://learn.microsoft.com/en-us/legal/windows-sdk/redist) permite distribuí-los sem alteração com aplicativos Classic Windows sob licença SDK válida e proíbe distribuí-los com aplicativos UWP; xdzip é um aplicativo desktop Classic Windows. Licenças, avisos e condições históricas do SDK permanecem aplicáveis separadamente mesmo que pacotes futuros removam esses arquivos.

O arquivo incluído `share/notices/Windows-runtime-NOTICE.txt` explica em ambos os idiomas os limites de licença de cada componente. Os termos originais do CRT Microsoft ficam em `Microsoft-VC-runtime/license.rtf`. O instalador mostra o acordo CRT original e exige aceitação, depois mostra avisos de componentes. Usuários portáteis também devem ler e cumprir os termos Microsoft incluídos. Ambos os pacotes preservam licenças originais e procedência. Redistribuidores posteriores devem cumprir suas próprias condições de elegibilidade e distribuição; Apache-2.0 do projeto, por si só, não autoriza repassar componentes Microsoft.

Exibir ou incluir o texto SDK não comprova por si só que distribuidores externos e usuários finais aceitaram os termos de proteção exigidos pelo SDK nem substitui a avaliação de licença válida e responsabilidade do publicador. A página atual de aceitação do instalador aplica-se apenas ao CRT. Se as DLLs gráficas do SDK forem redistribuídas novamente, avaliar separadamente termos e aceitação dos pacotes instalador e portátil e guardar evidências reais no registro de entrega; consulte o histórico [#135](https://github.com/xiaodaozhi/xdzip/issues/135).

Antes de compilar o instalador, verificar o hash fixado do acordo CRT e do aviso bilíngue; os materiais incluem o mesmo texto CRT original e registro de origem. Os termos SDK históricos ficam em `Windows-SDK-graphics/sdk_license.rtf`. Correções de licença não reescrevem ativos públicos antigos nem identidade histórica de compilação; emitir pacotes corrigidos com nova versão segundo o [protocolo de entrega imutável](release-protocol.md).
