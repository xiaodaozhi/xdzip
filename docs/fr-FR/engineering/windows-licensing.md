# Licences des outils de développement et runtimes Windows

[English](../../engineering/windows-licensing.md) | [简体中文](../../zh-CN/engineering/windows-licensing.md) | [繁體中文](../../zh-TW/engineering/windows-licensing.md) | [日本語](../../ja-JP/engineering/windows-licensing.md) | [한국어](../../ko-KR/engineering/windows-licensing.md) | Français | [Deutsch](../../de-DE/engineering/windows-licensing.md) | [Español](../../es-ES/engineering/windows-licensing.md) | [Português (Brasil)](../../pt-BR/engineering/windows-licensing.md) | [Русский](../../ru-RU/engineering/windows-licensing.md)

Cette page définit les voies applicables à la compilation et à la redistribution Windows, avec les [composants natifs](native-runtime-materials.md), l’[entrée de compilation développeur](developer-build.md) et le [contrat d’installation](installers-associations.md). Environnements précis, commits de vérification, empreintes des composants et conclusions d’acceptation sont consignés dans les tickets et artefacts locaux ou CI ; cette page ne conserve pas de preuve de licence propre à une machine.

<a name="xdzip-free-community-path-and-local-choice"></a>

## Option Community gratuite et choix local

Le contenu original du projet est publié sous Apache-2.0, licence open source approuvée par l’OSI. Les conditions individuelles de Visual Studio Community 2022 permettent aux particuliers de développer leurs propres applications ; les conditions des organisations permettent aussi à leurs utilisateurs de développer et tester des applications publiées sous une licence approuvée par l’OSI. Évaluer séparément l’usage open source d’une organisation et ses autres usages commerciaux internes ; ne pas étendre l’admissibilité de ce projet à d’autres projets.

Lorsqu’un mainteneur a besoin de son propre environnement Community, obtenir Community 2022 via l’[installateur Microsoft officiel](https://learn.microsoft.com/en-us/visualstudio/install/use-command-line-parameters-to-install-visual-studio?view=vs-2022), lire et accepter [les conditions originales de cette version](https://visualstudio.microsoft.com/license-terms/vs2022-ga-community/) et l’utiliser dans leur cadre. Pour C++, sélectionner `Microsoft.VisualStudio.Component.VC.Tools.x86.x64` et le SDK Windows ; l’installation de toutes les charges de travail n’est pas requise. Il n’est pas nécessaire d’acheter Professional/Enterprise ni de demander un certificat distinct de distribution du runtime pour chaque projet.

La revue de licence n’exige pas qu’un grand IDE reste installé localement. Si compilation et publication n’utilisent que l’environnement GitHub hébergé standard ci-dessous, le fondement applicable est l’autorisation Visual Studio hébergée et ses conditions REDIST ; il n’est pas nécessaire d’installer Community localement ou d’acheter une licence Enterprise personnelle pour la CI hébergée. Community est un choix gratuit pour les mainteneurs qui ont besoin de leur environnement, pas une condition supplémentaire d’installation locale pour la légitimité d’une compilation hébergée.

La section 3 de Community permet les fichiers logiciels et Build Tools sur des appareils de compilation admissibles ; la section 4 accorde des droits de distribution pour le code distribuable listé sous réserve des fonctionnalités, conditions en aval et restrictions. Télécharger VC_redist, installer Build Tools ou inclure seulement un texte de licence ne démontre pas l’admissibilité aux outils de développement. Sans licence Visual Studio, l’exception Build Tools couvre la compilation de composants C++ open source tiers approuvés par l’OSI et raisonnablement nécessaires à la compilation de vos applications. Elle ne permet pas de développer ou tester ces dépendances, sauf modifications mineures nécessaires à leur compilation, et n’est pas une exception générale pour développer tous ses propres programmes C++. VS Code ne fournit pas automatiquement une licence MSVC. Voir les [conseils de licence Microsoft](https://www.microsoft.com/licensing/guidance/Visual-Studio) et les [conditions Build Tools](https://visualstudio.microsoft.com/license-terms/vs2022-ga-diagnosticbuildtools/).

Vérifier localement le produit, la version complète, le statut non préliminaire et les composants C++ indiqués par `vswhere`, entrer dans l’environnement de développement de l’instance réelle, puis vérifier `cl`, `link` et le SDK. Build Tools 2019 installés ne sont pas Community 2022 et ne remplacent pas la vérification de la chaîne MSVC 2022 actuelle. `desktop.py prepare` générique n’installe pas silencieusement un IDE ou SDK système ; pour une première installation, utiliser l’installateur Microsoft, conserver les outils existants et interdire le redémarrage automatique.

Le choix de 2022 est la décision actuelle pour la chaîne de livraison et ne signifie pas que la licence Community gratuite n’autorise que 2022. Le [tableau de prise en charge Qt 6.8](https://doc.qt.io/qt-6.8/supported-platforms.html) liste Windows MSVC 2022 ; ce dépôt utilise le SDK `msvc2022_64` correspondant. Les outils 2019 peuvent rester pour le développement local, mais la compatibilité ABI entre versions ne suffit pas à établir une prise en charge complète avec le SDK actuel. Les [règles de compatibilité Microsoft](https://learn.microsoft.com/en-us/cpp/porting/binary-compat-2015-2017?view=msvc-170) exigent généralement que l’éditeur de liens final ne soit pas plus ancien que les outils des bibliothèques d’entrée et limitent séparément les runtimes et `/GL`/`/LTCG`. Les configurations alternatives exigent leur propre licence et vérification ; cela n’impose pas l’installation locale de l’IDE 2022 complet.

<a name="xdzip-github-hosted-builds"></a>

## Compilations hébergées par GitHub

Le workflow Windows du projet utilise les runners GitHub hébergés standards `windows-2022`. Le produit préinstallé est Visual Studio Enterprise 2022, pas Community. Les mainteneurs de runner-images ont [confirmé](https://github.com/actions/runner-images/issues/12945#issuecomment-3348002951) que cette version Enterprise est disponible pour les runners hébergés GitHub Actions/Azure DevOps publics et privés dans le cadre d’un accord GitHub-Microsoft, sans licence Enterprise personnelle supplémentaire. Le projet s’appuie sur cet environnement ; cette explication publique ne remplace pas l’accord complet et ne prétend pas le divulguer.

Selon la [documentation GitHub des runners hébergés](https://docs.github.com/en/actions/concepts/runners/github-hosted-runners), chaque job Windows reçoit une machine virtuelle indépendante et `Set up job` indique l’image et l’inventaire logiciel de cette exécution. Les workflows ne compilent, testent, déploient et publient que ce dépôt, dans le cadre des [conditions supplémentaires Actions](https://docs.github.com/en/site-policy/github-terms/github-terms-for-additional-products-and-features#actions). Le quota de calcul gratuit des dépôts publics et les droits de redistribution des composants Microsoft sont distincts.

La CI enregistre le produit et la version VS réels, l’emplacement relatif du compilateur, les versions des outils et du SDK dans `windows-toolchain.json`, conservé avec les paquets et composants du même commit sans clé de produit ni chemin privé de développeur. Cela identifie les outils et ne prouve pas automatiquement l’admissibilité aux licences. Les runners auto-hébergés, outils copiés localement depuis les images, autres services CI et serveurs partagés généraux n’héritent pas de la licence hébergée ; revérifier les conditions Community/Build Tools et celles des appareils.

<a name="xdzip-microsoft-component-redistribution"></a>

## Redistribution des composants Microsoft

La [liste REDIST VS 2022](https://learn.microsoft.com/en-us/visualstudio/releases/2022/redistribution) inclut explicitement Community 2022 sous licence valide. La compilation actuelle utilise VC_redist x64 de version finale fixé dans [windows-runtime.json](../../../scripts/windows-runtime.json), extrait sans modification et contrôle individuellement huit DLL CRT et la licence originale du runtime. Elle n’inclut ni compilateurs, ni débogueurs, ni `debug_nonredist`. Ni l’option gratuite Community ni l’identité Enterprise de la CI hébergée ne replacent les DLL Microsoft sous Apache-2.0.

Les nouveaux paquets de développement ne contiennent ni `d3dcompiler_47.dll`, `dxcompiler.dll` ou `dxil.dll` du SDK Windows, ni bibliothèque OpenGL logicielle Mesa. Dans les anciens paquets, ces trois fichiers provenaient de `Redist/D3D/x64` d’un SDK explicite. La [liste REDIST du SDK](https://learn.microsoft.com/en-us/legal/windows-sdk/redist) permet leur distribution inchangée avec des applications Classic Windows sous licence SDK valide et l’interdit avec les applications UWP ; xdzip est une application desktop Classic Windows. Licences, avis et conditions des anciens SDK restent applicables séparément même si les futurs paquets retirent ces fichiers.

Le fichier inclus `share/notices/Windows-runtime-NOTICE.txt` explique les limites de licence de chaque composant dans les deux langues. Les conditions originales du CRT Microsoft sont dans `Microsoft-VC-runtime/license.rtf`. L’installateur affiche l’accord CRT original et demande son acceptation, puis affiche les avis des composants. Les utilisateurs portables doivent aussi lire et respecter les conditions Microsoft incluses. Les deux paquets conservent licences originales et provenance. Les redistributeurs en aval doivent satisfaire eux-mêmes aux conditions d’admissibilité et de distribution ; Apache-2.0 du projet n’autorise pas à lui seul la redistribution des composants Microsoft.

Afficher ou inclure le texte SDK ne prouve pas à lui seul que les distributeurs externes et utilisateurs finaux ont accepté les conditions de protection exigées par le SDK et ne remplace pas l’évaluation de licence et de responsabilité de l’éditeur. La page d’acceptation actuelle de l’installateur ne concerne que le CRT. Si les DLL graphiques SDK sont à nouveau redistribuées, évaluer séparément conditions applicables et acceptation des paquets installateur et portable et conserver les preuves réelles dans le dossier de livraison ; voir l’historique [#135](https://github.com/xiaodaozhi/xdzip/issues/135).

Avant de compiler l’installateur, vérifier l’empreinte fixée de l’accord CRT et de l’avis bilingue ; les composants incluent le même texte CRT original et son enregistrement de provenance. Les anciennes conditions SDK sont dans `Windows-SDK-graphics/sdk_license.rtf`. Une correction de licence ne réécrit pas les anciens fichiers publics ni l’identité de compilation historique ; publier les paquets corrigés sous une nouvelle version selon le [protocole de livraison immuable](release-protocol.md).
