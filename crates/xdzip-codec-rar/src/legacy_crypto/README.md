# 历史 RAR 密码候选

此私有模块依据 `LEGACY-RAR-CRYPTO-2026-10-26-v1` 纯数学交接独立实现，只负责只读密码准备及解密。它不实现 RAR 压缩编码器，不带路径、进程或发布权限。RAR3 AES、旧 13 字节状态、旧 15 字节状态、旧 20 专用分组密码严格区分；文件之间重置密码流，文件的物理分卷片段之间连续。

标准 SHA1 的消息调度、轮函数、初始值和终结来自 [FIPS 180-4 第 4、5、6.1 节](https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.180-4.pdf) 数学定义。私有 SHA1 状态及输入缓冲可归零，不新增第三方密码依赖，也不把它作为新安全用途的通用摘要接口。RAR3 使用一条连续 SHA1 消息的 262144 段和 16 个摘要副本检查点，按冻结事实实现长输入消息调度回写，AES128 使用已准入原语。无盐与存在的零盐是两个缓存身份。缓存固定 16 槽，保守预检 16 KiB；派生先准入所有工作，取消后不返还已保留的配额，这不是执行完成计数。

RAR3 原始密码字节遵原 native 平台兼容：Windows 前 127 个 UTF16 单元逐个 LE16；Unix 前 127 个本地宽 scalar 的低 16 位逐个 LE16。外层均保持 4096 UTF8 字节准入。该差异不是统一格式编码规范。非 BMP 的独立作者归档仍需额外证据，长输入调度已另以官方任意密文观察核对。

投影前先按已核对的 native host 行为截首 U+0000，外层字节上限仍检查完整原始 str。公开 `Some("")` 保留本 API 的显式候选语义，`None` 才缺密码；不声称原 `SecPassword` host 会对空串执行 KDF。ASCII 窄入口只检查 NUL 前缀与前 127 个原生单元，忽略不会参与派生的后缀。

旧 13/15/20 使用 `NarrowPassword::from_projected` 接收宿主已明确投影的窄密码字节，截前 127 字节、首 NUL 结束。`ascii` 便利入口只接收跨平台无歧义的 ASCII；它不会把任意 UTF8 当作 Windows ACP、DOS OEM 或 Unix locale。对应宿主非 ASCII 投影契约须另明确。

旧 20 的固定有限置换来自冻结 `rar20-cipher-permutation-v1.csv`，SHA256 `c38eb742ed1231b555a35ff7ee882b829eabaff62958109d7b8b84b68d96e928`。唯一已知来源是固定受限参考 `crypt2.cpp` 的有限输入输出映射，原始来源和 LicenseRef-UnRAR 限制没有消失，不称项目原创常量或独立公开规范。具体 provenance 由通用 RAR 来源文档登记，专项许可复核仍独立进行。密码准备中必要的正向分组数学只用于构造读取密钥状态，不是 RAR 压缩编码器。`Old20Cache` 只缓存一个活动密码的不可变初始状态，每个新文件取得新的工作副本；预算不为重复准备计费，后续文件内容仍由宿主累计解码和输出计量。

`LegacyReader` 只读取授权 packed 范围，保留 byte 或 block 状态，提供 consumed/decoded/remaining/finish。旧 13/15 无数学对齐 padding；旧 20/AES128 只允许调用方已确认内容终止后的显式至多 15 字节尾部，不猜测 PKCS7 或要求零。带 payload 的 Interrupted 转为 Other 并保留类型，避免标准 Read combinator 吞错误；裸 OS Interrupted 重试。源错、取消、截断、未读完 finish 等均 poison。

低层普通测试涵盖 SHA1 与独立 hashlib 的填充边界、固定短密码 KDF、两真实 RAR3 密文与 .NET AES 明文 SHA256、五真实加密头的 CRC 低16/名称/true length/跨度，以及旧状态的数学向量、缓存、配额、类型错误和非零对齐尾。旧 13/15/20 历史作者归档、RAR3 长密码回写的独立归档、非 ASCII 窄密码及分卷矩阵不得仅以数学通过记成互操作成功。完整 RAR29 LZ/PPM/VM、宿主服务链和 GUI 验收分别记录。

后续已新增独立官方 UnRAR7.23 raw oracle：旧13/15/20各三种ASCII密码共九组，RAR3长原始输入L66/L128/L262三组，合计570B完整解密输出逐字节一致。包装内容CRC故意不符，工具exit3，不记健康归档成功；该工具版本不与数学事实的固定7.30 beta1来源混同。RAR3 `key_projected_units` 另允许宿主传入已经完成条件OEM处理、首NUL和127单元截断后的low16单元，最多127项。低16值为0也可能来自Unix非BMP原始非零宽字符，不再凭该值截断；宿主须在丢弃高位前解决真正的NUL边界，并保留原始str的4096字节准入。

另有三个固定历史密码 Store 测试样本，分别声明旧13/15/20密码族，本低层实际解密得到每个87B、合计261B，逐一匹配预存SHA256，旧15/20再匹配声明CRC32。来源固定为 Junrar v8.1.0、commit `57091f9ccd43661cf8f12c389917cc24950df707` 的数据及测试声明，仅查看了测试中密码和来源行，没有读取其Java解码算法。样本自称由历史DOS工具创建，这是上游来源声明，未独立证明历史可执行文件身份，也不推定数据有新许可。官方UnRAR7.23另外对这些原档test/extract均成功；这里新增的Rust结论仅是已知完整Store内容与密码层互读，压缩文件、整容器/宿主链和GUI不由此自动通过。
