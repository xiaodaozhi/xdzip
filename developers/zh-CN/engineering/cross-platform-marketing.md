# 单平台截图生成三平台宣传图方案

[English](../../engineering/cross-platform-marketing.md) | 简体中文

目标是一次采集十种语言的真实应用界面，再分别生成 Windows、macOS 和 Ubuntu 风格的宣传图，供官网等展示使用。跨平台转换的成品是合成示意图，不是目标平台实机截图，也不能作为目标平台功能、视觉验收或商店合规的证据。三平台保持 [150% 截图比例](marketing-screenshot-scale.md)，不得先用其他倍率拍摄再放大冒充原生比例。

## 一次采集

建议使用 Windows 现有自动化：它准备四个自有演示场景，并分别保存客户区、原生窗口参考图和带摘要的采集回执。针对新构建显式传入实际程序、预期 SHA-256 和完整源码提交号，验证产品版本、场景及十种语言后执行采集；现有 Windows 商店导入器只接受配置中固定的旧候选，新流程须单独适配回执，不能伪造固定候选状态。不要把旧版本截图当作当前版本，也不要将窗口参考图误当作客户区。macOS 和 Linux 的现有记录器需要手动准备场景，也可作为真实来源，但须先把其回执适配到同一来源格式。

四场景为起始页、创建、预览、工作区。起始页显示 Ctrl 和 ⌘ 等平台专属快捷键；跨平台合成时必须替换或隐藏这些元素，不能保留错误平台的快捷键。创建窗口的保存位置是实际操作系统路径，不能直接把 Windows 路径放进 macOS 或 Linux 成品。采集应使用自有、无敏感数据的演示资料，并为目标平台准备明确的演示路径层；若不能可靠定位并替换路径、平台专属文案或图标，则该场景停止生成，不能发布错误画面。创建格式列表还依平台过滤，必须选用三平台均支持且一致的 ZIP 场景。

## 标题区域参数

以下值为逻辑坐标，转换时统一乘以 1.5 并按最终边界取整；不改产品组件尺寸。

| 窗口 | 已确认的实现依据 | 转换要求 |
| --- | --- | --- |
| Windows 主窗口 | 标题高 48，右侧三个按钮各宽 46，图标 18；标签和品牌由 `ArchiveTabs.qml` 布局。 | 重建完整标题区或保留 Windows 原区，右侧依次为最小化、最大化、关闭。 |
| Ubuntu 主窗口 | 标题高 48，右侧间距 6，三个按钮各宽 36、圆形底直径 28；主窗圆角 10。 | 使用仓库的 `WindowCaptionButton.qml` 和现有浅／深色图标、颜色，重新布局设置按钮与标签。 |
| macOS 主窗口 | 标题高 48；品牌左坐标约 78.057，首个标签约 180.589。原生三按钮在左侧，中心由 `MacTitlebar.mm` 对齐到标题高度中线。 | 重建完整标题区并按原生测量放置按钮，不能仅把红黄绿覆盖在 Windows 品牌上。 |
| 创建等操作窗口 | `OperationWindow.qml` 使用原生窗口装饰，当前请求标题栏与关闭按钮，未默认请求最小化或最大化。 | 独立处理操作窗口，区分窗口边框和客户区，不给不具备的操作伪造可用按钮。 |

Windows／Ubuntu 主窗口的品牌和标签起始位置由 QML 布局动态计算，标签数量、文字、字号和右侧控件会影响可用宽度；生成器应依据当前 QML/视觉参数重排，不应把某张截图的整条标题栏平移到另一平台。macOS 按钮具体横坐标、尺寸及配色由 AppKit 和系统外观决定，不能仅由逻辑截图宽度推算。可在 Mac 上编译并运行仓库的独立测量探针，不读取桌面内容：

```sh
mkdir -p build/marketing-probe
clang -fobjc-arc -framework Cocoa scripts/measure-macos-marketing-titlebar.m -o build/marketing-probe/titlebar
build/marketing-probe/titlebar
```

一次 macOS 27.2.1 的本机探针中，三个按钮初始横坐标分别为 9、32、55，均为 14 × 14；操作窗口的后两个按钮不可用。该坐标以客户区为参照，操作窗口按钮位于客户区上方时纵坐标为负。探针记录 AppKit 初始按钮几何，主窗口最终纵向中心还须按 `MacTitlebar.mm` 的实际布局测量；它不证明按钮像素、系统主题或其他系统版本的外观。平台图形资源应依据项目自有控件或经核对的本机系统参考制作，记录采样平台、外观和版本；系统外观变化时重测，不把单次测量硬编码为所有 macOS 版本的原生事实。

## 后续代码与交付接口

1. 标准化来源回执，保留源平台、程序身份、提交、DPR、语言、场景、PNG 原图、窗口参考图和各自摘要。所有输入先完成校验，再生成新目录，不覆盖原图。处理后的图片明确标记源平台、目标平台及 `cross-platform-composite`，记录每个标题区与演示路径的转换参数、模板版本和摘要。
2. 依据窗口类型生成目标标题区域，处理按钮位置、标签和设置的重排、圆角及边框；对创建窗口单独处理其原生装饰和演示路径。超出模板能力、缺少测量或存在遮挡时拒绝输出。保留每张图标题区外的原始像素，只有登记的路径替换区域例外。
3. 将转换结果作为宣传示意图接入现有平台素材生成器；扩展校验与清单，使合成图不能通过原生截图校验，也不能被标记为原生截图。每平台按语言与场景输出图片和融合图，并保留原始来源及转换回执。
4. 分别检查十种语言和四个场景的内容完整性、尺寸、无敏感路径、原图区外像素一致、标题布局与目标参数、合成来源和哈希；用自有合成夹具测试错误输入、遮挡、超限和目标目录已存在等失败情况。另将每平台至少一组结果与对应平台的原生窗口参考图比较；这项参考比对不是为每个语言重复平台验收。
5. 完整生成并检查后，按[最新版同步](marketing-archive.md)原位更新 Google Drive 各平台目录，保留无关文件，最后更新清单与校验文件。仅在三平台十语言四场景齐备时替换完整截图集合。

macOS 和 Linux 导出器可用 `--create-client-only` 为操作窗口补绘标题栏；该标题栏是合成图，并在清单记录。主窗口跨平台转换程序和新的十语言截图尚未生成。各项实际完成与证据记录在 [issue #409](https://github.com/xiaodaozhi/xdzip/issues/409)。
