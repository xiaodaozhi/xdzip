# 格式扩展收尾与交接门禁

[English](../../engineering/format-expansion-closeout.md) | 简体中文

本指南说明评估和交付新压缩格式时，如何分别核对实现范围、环境要求与验证证据。格式名称、生成的登记行或一次自读成功，都不能单独证明已经支持。

## 1. 冻结范围台账

开始工作和最终复核时都记录 issue、交付分支和远端 tip。每个候选格式只能使用一种明确状态：

| 状态 | 含义 | 必要证据 |
| --- | --- | --- |
| Admitted | 产品暴露了声明的能力 | codec、runtime、登记表、文档和定向自动化检查 |
| Excluded | 产品决定在本工作包中排除 | issue 与持久范围文档中的决定记录 |
| Blocked | 外部门槛未满足，暂时不能继续 | 门槛、责任方或所需输入，以及缺少的确切证据 |
| Deferred | 有意留到后续工作包 | 后续 issue 或明确的后续里程碑 |

不能因为存在后缀、参考工具、解析器空壳或局部样本就提升候选状态。负载读取、创建、修改、执行和安装能力必须分别声明。

## 2. 在作出结论前核对真实工作树

按下面命令逐项执行并检查输出，不能只看简短状态标记：

```text
git status --short --branch
git diff --name-status
git diff --cached --name-status
git diff --check
```

每个标为修改的路径都要查看实际 diff。如果文本 diff 为空，再用 `git hash-object` 比较工作副本对象，用 `git rev-parse HEAD:<path>` 比较提交对象，判断是否只是换行符或文件状态缓存噪声。保留真实的无关改动，但要列出确切路径；不能把只有状态标记的文件说成待提交实现。

提交前把暂存路径与范围台账核对。提交后查看 `git show --stat --summary HEAD`，再用 `git ls-remote origin refs/heads/<branch>` 核对远端 tip。

## 3. 预检真实环境

长批次运行前先检查：

- 产品自有原生 worker 存在于测试和部署入口实际使用的路径；
- 只有需要真实 worker 的命令才设置 `XDZIP_NATIVE_CODEC` 和 `XDZIP_NATIVE_CODEC_WORKER`，并记录选中的路径和摘要；
- 命令使用的编译器及平台工具在同一个 shell 中可用，Windows PE 依赖检查包括 `dumpbin`；
- 原生 worker 使用的临时目录对测试身份私有且可写；
- 参考工具和夹具存在、版本固定，并与产品二进制分开标识。

每项前提都标为 `PASS`、`IGNORED`、`BLOCKED` 或 `NOT RUN`。缺少可选夹具不能算通过；没有经过真实 worker 的测试不能报告为 worker 路径通过。

## 4. 运行最小但完整的验证矩阵

按变更范围选择矩阵，并把命令和结果保留在 issue 或本地证据中：

1. codec 单元测试和畸形输入测试；
2. 配置真实 worker 的 runtime 定向测试；
3. 配置 worker 的 runtime 完整库测试；
4. 登记表生成、格式清单和来源门禁检查；
5. 文档链接和生成输出检查；
6. 使用平台依赖工具的 CLI 与部署审计；
7. 只有 issue 或契约要求时才执行跨平台或人工验收。

把产品回归与工具缺失、夹具缺失、ACL 失败和平台不可用分开。`ignored`、`skipped`、`not run` 或环境失败不能改写成通过数量。

## 5. 按一个顺序完成交接

先完成实现和检查，再执行：

1. 只提交范围内的源码、测试和持久文档；
2. 推送交付分支并核对远端提交；
3. 在 issue 追加最终范围、证据、排除项和剩余门槛；
4. 用五段短内容汇报：已完成、已排除、仍阻塞、自动化证据、下一项需要用户决定的事项；
5. 只有所有者确认具体的已推送结果后，才合并 `main`。

issue 评论和汇报不得包含凭据、完整本机路径、锁屏状态或临时环境原始细节。正式发行批准仍是独立决定。

## 6. 中断后恢复

恢复工作时先重读 issue 最新评论、分支和远端 tip，再将当前工作树与上次交付提交比较。复用已有提交和证据，不因换了进程、shell 或模型而重新实现。如果某项已声称的结果无法复现，就降级为 `NOT RUN` 或 `BLOCKED`，直到用完全相同的命令重新执行。
