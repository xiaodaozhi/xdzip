# Security policy

English | [简体中文](SECURITY.zh-CN.md)

Security maintenance prioritizes the [latest stable release](https://github.com/xiaodaozhi/xdzip/releases/latest) on the systems covered by the [support policy](docs/engineering/support-policy.md). Prereleases, development builds and systems outside the support matrix have no separate maintenance commitment. The project has no fixed response time or service-level agreement.

Use GitHub's private [Report a vulnerability](https://github.com/xiaodaozhi/xdzip/security/advisories/new) entry. If it is unavailable, contact the owner through an established private channel. Keep vulnerability samples, credentials, private paths and user files out of public issues, PRs and release comments.

Include the affected version or commit, platform, smallest reproduction, expected and actual behavior, and impact. Include only redacted logs or owned, redistributable samples. The maintainer will triage reports as capacity permits and coordinate disclosure where appropriate.

For the current security boundaries, see [file security](docs/design/file-security.md), [software updates](docs/engineering/software-update.md) and [dependency admission](docs/engineering/dependencies.md).
