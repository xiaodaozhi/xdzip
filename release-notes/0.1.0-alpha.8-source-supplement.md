# xdzip 0.1.0-alpha.8 源码与许可补充材料

本补充材料对应已公开的 `0.1.0-alpha.8`、build 21、源码提交 `e1cd6a3e125d5fcabc85a9f4edb106d013709c89`。它补充原发行中的来源和通知，不改变原有发行附件、更新签名或校验和。原始版本及对应源码包仍可从 [alpha.8 发布页](https://github.com/xiaodaozhi/xdzip/releases/tag/v0.1.0-alpha.8)取得；`xdzip-0.1.0-alpha.8-corresponding-source.tar.gz` 的 SHA-256 为 `95d7e3eac9d457d3e20773fa9b3c71c520cc9e9893343815b3c8c4547020361e`。

## 原版的补充通知与源码

- 原源码包中的七个 Rust vendor 包缺少独立的常见名称通知文件。请同时取得[固定的补充通知目录](https://github.com/xiaodaozhi/xdzip/tree/7497058904fe29fe9728fdf02a72e68d6847d37a/third_party/rust-vendor-notices)和[逐包来源索引](https://github.com/xiaodaozhi/xdzip/blob/7497058904fe29fe9728fdf02a72e68d6847d37a/scripts/rust-vendor-notice-sources.json)。补充目录不改动原 vendor 文件。
- Qt Network 内嵌的 Public Suffix List 对应的[可编辑原始列表和 MPL-2.0 许可](https://github.com/xiaodaozhi/xdzip/tree/8ae6f6ff9a3d3a228256f10124ad2d802ef900e7/third_party/qt-public-suffix-list)随本补充提供。
- Qt Core MIME 数据所用的 [Apache Tika 原始文件、完整 NOTICE 和 OGL-UK-3.0 原文](https://github.com/xiaodaozhi/xdzip/tree/c9454ed8378935dbb15b63bdd044a4b674548b45/third_party/qt-tika-mimetypes)随本补充提供。相关归属包括 Apache Software Foundation 及英国国家档案馆的 PRONOM；完整 Tika NOTICE 包含上游发行的其他声明，不表示其他全部依赖均随 xdzip 分发。
- Qt Core 的区域数据标注为 CLDR 46。固定的 [CLDR 46 common 数据](https://github.com/unicode-org/cldr/tree/e1d37acce5dae468c414172be53b666d58d45be8/common)可用于编辑生成输入，其[上游许可](https://github.com/unicode-org/cldr/blob/e1d37acce5dae468c414172be53b666d58d45be8/LICENSE)可单独查阅。使用 Qt 生成器及[候选 ISO 639-3 表](https://github.com/unicode-org/cldr/blob/e1d37acce5dae468c414172be53b666d58d45be8/tools/cldr-code/src/main/resources/org/unicode/cldr/util/data/iso-639-3.tab)生成的八个文件在忽略换行和生成日期后与原 Qt 源码一致。候选表的 SHA-256 为 `b31ae9d81d34d8e036b1adabcdaf133d0a46b19d91719ffc6cdc3030ebdb55b8`，但这不证明它就是上游历史构建使用的精确输入。ISO 639-3 表未由本项目补充交付，其[上游下载与条款](https://iso639-3.sil.org/code_tables/download_tables)须单独核对。
- 原 Linux 包使用 ICU 73.2，原源码包只包含其许可文本。现补充 [ICU4C 73.2 官方源码归档](https://github.com/unicode-org/icu/releases/download/release-73-2/icu4c-73_2-src.tgz)，SHA-256 为 `818a80712ed3caacd9b652305e01afc7fa167e6f2e94996da44b90c2ab604ce1`；归档内许可与原包所附文本一致。上游版本和许可相符不证明原 SDK 二进制由该归档无补丁构建。
- 该 ICU 发布归档内的数据文件已经生成，进一步提供包含可编辑词典和区域数据的 [ICU 73.2 固定源码树](https://github.com/unicode-org/icu/tree/680f521746a3bd6a86f25f25ee50a62d88b489cf)，以及上游注明用于该版本的 [CLDR 43.1 数据与工具源码树](https://github.com/unicode-org/cldr/tree/37d524354422f46731db74f3bd6b3f46516c3ced)。CLDR 上游树含 ISO 639-3 表，其条款与可转授授权仍需单独核实；本项目新生成的源码子集排除五个相关文件。用固定 ICU 源码树运行上游数据构建流程，生成的数据与原 Linux ICU 数据段及发布归档内数据逐字节一致；源码树仍含上游预生成输入，此结果不声称原 ICU 动态库整体已重现。
- RAR 的有限参考映射保留原 UnRAR 许可，按保守做法在涉及的[旧版 LZ 映射源码](https://github.com/xiaodaozhi/xdzip/blob/b0b3d8f88c1a6a9065acd28f5aab04f5e02e51d2/crates/xdzip-codec-rar/src/legacy_lz15_codes.rs)和[旧版密码映射源码](https://github.com/xiaodaozhi/xdzip/blob/b0b3d8f88c1a6a9065acd28f5aab04f5e02e51d2/crates/xdzip-codec-rar/src/legacy_crypto/permutation.rs)中补充许可第 2 段。[原版源码注释补丁](0.1.0-alpha.8-rar-notice.patch)可下载到本地；在原版项目源码根目录先运行 `git -c core.autocrlf=false -c core.eol=lf apply --check --verbose <补丁路径>`，确认两个文件均显示正在检查而非跳过后，再运行 `git -c core.autocrlf=false -c core.eol=lf apply --verbose <补丁路径>`。补丁只增加源码注释，不改变原版可执行文件；[参考来源与原许可](https://github.com/xiaodaozhi/xdzip/tree/b0b3d8f88c1a6a9065acd28f5aab04f5e02e51d2/third_party/rar-wire-mappings)保留供复核，未加入官方 RAR 引擎源码。映射是否受该条款约束尚无权利人确认，项目按该段限制采取保守处理，不提供 RAR 创建或修改。
- 原包的 Qt 许可说明误称其为私有开发审阅包，且模块列表遗漏 Network。请参阅[更正后的 Qt 说明](https://github.com/xiaodaozhi/xdzip/blob/82e5db0cf1fc7d524be9a2051fa9e649810d0381/third_party/qt/README.md)。Qt 运行库采用 LGPL-3.0 分支，Qt 内嵌第三方组件可能有其他条款；原包中的 LGPL-3.0 和 GPL-3.0 原文仍保留。

## Qt 重建与替换

原源码包包含固定的 Qt 6.8.2 模块归档、应用源码和 Rust vendor。补充材料的[源码构建与替换说明](https://github.com/xiaodaozhi/xdzip/blob/66933a1c4d7c00b37fafa9a64aa0e41f14d2b4b0/docs/engineering/wp12-automation.md#qt-源码与兼容替换)和[重建脚本](https://github.com/xiaodaozhi/xdzip/tree/66933a1c4d7c00b37fafa9a64aa0e41f14d2b4b0/scripts)提供隔离构建、QtCore 替换及验证入口。Windows／Linux 已在自动化环境中对原始便携包副本完成修改版 QtCore 的实际加载、浏览、取消和解压内容核对，详见 [#118](https://github.com/xiaodaozhi/xdzip/issues/118)。Apple Silicon Mac 仍需在本机使用原始 app.zip 验证替换，修改副本后可使用本地 ad-hoc 完整性签名，无需项目私有签名密钥。替换要求接口兼容，不能据此保证任意修改均可运行。

原版 Qt 翻译文件的上游 SPDX 根包没有声明具体许可，源码中的许可规则也不能单独确认为每个翻译文件的授权。[Qt 官方 QUIP 18](https://contribute.qt-project.org/quips/18/)在 2025-03-04 的修订中明确将普通 Qt 翻译文件列为 `LicenseRef-Qt-Commercial OR BSD-3-Clause`。已重建本项目三平台实际翻译目录的 54 份归档内输入，在 Qt 6.8.2 发布树及该修订前的 6.8 维护树、开发树中逐份相同；英语空输入按上游 CMake 生成，未计入这 54 份。BSD-3-Clause 要求保留适用的版权声明、许可条件及免责声明，并限制使用权利人和贡献者名称背书。该说明晚于 6.8.2 发行，且目标文件没有逐文件许可声明，现有证据尚不足以确认其对每份历史文件的追溯授权；详情与剩余核对见 [#53](https://github.com/xiaodaozhi/xdzip/issues/53#issuecomment-6566213456)。

已公开原包的 macOS 上游 SPDX 中有 110 条文件摘要与 61 个实际 SDK 文件不同。官方 SDK 归档与原发行记录的 SDK 输入一致，但原摘要生成后的具体变化尚未证明；源自官方数据并不自动解决该差异。[#53](https://github.com/xiaodaozhi/xdzip/issues/53) 保留逐项证据、剩余平台验收与许可限制。本补充不宣称原版已完成全部许可审查或所有平台人工验收。

## English

This supplement applies to published `0.1.0-alpha.8`, build 21, source revision `e1cd6a3e125d5fcabc85a9f4edb106d013709c89`. It supplements the original release and corresponding-source archive without modifying their assets, signatures or checksums. The original source archive SHA-256 is recorded above.

The links above supply the missing pinned notices for seven Rust vendor packages, the editable Public Suffix List and MPL-2.0 text, and the Apache Tika MIME input, complete upstream NOTICE and OGL-UK-3.0 text. The Tika notice covers more than the components distributed with xdzip. The two RAR source links retain the original UnRAR license paragraph 2 as a conservative notice for limited reference mappings. The [patch for the original source](0.1.0-alpha.8-rar-notice.patch) can be checked and then applied from its project source root using `git -c core.autocrlf=false -c core.eol=lf apply --check --verbose <patch-path>` and `git -c core.autocrlf=false -c core.eol=lf apply --verbose <patch-path>`; verify that both files are checked rather than skipped. The patch changes comments, not the published executable, and does not incorporate the official RAR engine. The rights holder has not confirmed whether the paragraph applies to these mappings; as a precaution, xdzip does not offer RAR creation or modification.

Qt Core locale data identifies CLDR 46. The pinned CLDR `common` data and license linked above provide editable generation inputs. Using Qt's generators and the linked candidate ISO 639-3 table, whose SHA-256 is recorded above, reproduces eight files from the original Qt source after normalizing line endings and generation dates; this does not establish the exact historical input used upstream. The ISO table is not supplied by xdzip; its upstream download page and terms require separate review.

The original Linux package uses ICU 73.2; its source package included the license text but not ICU source. The linked official ICU4C 73.2 source archive has the SHA-256 shown above and contains the same license text. Matching the upstream version and license does not prove the original SDK binaries were built from this archive without patches.

That release archive contains pre-generated ICU data. The additional pinned ICU source tree supplies editable dictionaries and locale data, and the pinned CLDR 43.1 tree supplies the upstream data and tools identified for ICU 73.2. The upstream CLDR tree contains ISO 639-3 tables whose terms and any transferable grant need separate review; newly generated xdzip source subsets omit five such files. Building the data using the pinned ICU tree reproduces both the original Linux ICU data segment and the release archive's pre-generated data byte for byte. The tree still contains upstream pre-generated inputs; this does not establish reproduction of the complete ICU shared libraries.

The corrected Qt notice identifies the actual release and includes Network. Distributed Qt runtime libraries use the LGPL-3.0 option; embedded third-party components may have different terms. The original release includes LGPL-3.0 and GPL-3.0 texts. The linked source-build and replacement instructions describe isolated QtCore substitution. Automated Windows and Linux checks loaded modified QtCore libraries in copies of the original portable packages and verified browsing, cancellation and extracted contents; see [#118](https://github.com/xiaodaozhi/xdzip/issues/118). Original-package substitution remains to be verified on an Apple Silicon Mac, where a local ad-hoc integrity signature can be used without the project signing key. Substitution requires compatible interfaces and arbitrary ABI changes are not guaranteed to work.

The upstream SPDX package for Qt translations does not declare a specific license, and the source license rule alone does not establish a grant for each translation file. In its 2025-03-04 revision, [Qt's QUIP 18](https://contribute.qt-project.org/quips/18/) identifies ordinary Qt translation files as `LicenseRef-Qt-Commercial OR BSD-3-Clause`. The 54 archived inputs used to rebuild the translation catalogs distributed on all three platforms are individually identical in the Qt 6.8.2 release tree and in the 6.8 maintenance and development trees before that revision; the English empty input generated by upstream CMake is not included in the count. BSD-3-Clause requires retention of applicable copyright notices, license conditions and disclaimers, and restricts endorsement using copyright-holder or contributor names. The guidance postdates 6.8.2, and the target files have no individual license declarations; these facts do not establish a retroactive grant for each historical file. See [#53](https://github.com/xiaodaozhi/xdzip/issues/53#issuecomment-6566213456) for the remaining review.

The original macOS upstream SPDX records have 110 checksum differences covering 61 SDK files. Verified official SDK archives match the original release's recorded SDK inputs, but the exact transformation after those SPDX digests remains unresolved.
