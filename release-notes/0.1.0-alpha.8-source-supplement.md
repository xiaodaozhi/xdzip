# xdzip 0.1.0-alpha.8 源码与许可补充材料

本补充材料对应已公开的 `0.1.0-alpha.8`、build 21、源码提交 `e1cd6a3e125d5fcabc85a9f4edb106d013709c89`。它补充原发行中的来源和通知，不改变原有发行附件、更新签名或校验和。原始版本及对应源码包仍可从 [alpha.8 发布页](https://github.com/xiaodaozhi/xdzip/releases/tag/v0.1.0-alpha.8)取得；`xdzip-0.1.0-alpha.8-corresponding-source.tar.gz` 的 SHA-256 为 `95d7e3eac9d457d3e20773fa9b3c71c520cc9e9893343815b3c8c4547020361e`。

xdzip 原创代码版权声明：Copyright © 2026 xiaodaozhi。第三方组件保留各自的版权和许可；本补充不修改原版程序文件或其内嵌信息。

## 原版的补充通知与源码

- 原源码包中的七个 Rust vendor 包缺少独立的常见名称通知文件。请同时取得[固定的补充通知目录](https://github.com/xiaodaozhi/xdzip/tree/7497058904fe29fe9728fdf02a72e68d6847d37a/third_party/rust-vendor-notices)和[逐包来源索引](https://github.com/xiaodaozhi/xdzip/blob/7497058904fe29fe9728fdf02a72e68d6847d37a/scripts/rust-vendor-notice-sources.json)。补充目录不改动原 vendor 文件。
- Qt Network 内嵌的 Public Suffix List 对应的[可编辑原始列表和 MPL-2.0 许可](https://github.com/xiaodaozhi/xdzip/tree/8ae6f6ff9a3d3a228256f10124ad2d802ef900e7/third_party/qt-public-suffix-list)随本补充提供。
- Qt Core MIME 数据所用的 [Apache Tika 原始文件、完整 NOTICE 和 OGL-UK-3.0 原文](https://github.com/xiaodaozhi/xdzip/tree/c9454ed8378935dbb15b63bdd044a4b674548b45/third_party/qt-tika-mimetypes)随本补充提供。相关归属包括 Apache Software Foundation 及英国国家档案馆的 PRONOM；完整 Tika NOTICE 包含上游发行的其他声明，不表示其他全部依赖均随 xdzip 分发。
- Qt Core 的区域数据标注为 CLDR 46。固定的 [CLDR 46 common 数据](https://github.com/unicode-org/cldr/tree/e1d37acce5dae468c414172be53b666d58d45be8/common)可用于编辑生成输入，其[上游许可](https://github.com/unicode-org/cldr/blob/e1d37acce5dae468c414172be53b666d58d45be8/LICENSE)可单独查阅。Qt 区域数据生成器引用由 [SIL](https://iso639-3.sil.org/) 维护的 ISO 639-3 代码表；原 Qt 生成数据的 347 条语言代码条目与[候选表](https://github.com/unicode-org/cldr/blob/e1d37acce5dae468c414172be53b666d58d45be8/tools/cldr-code/src/main/resources/org/unicode/cldr/util/data/iso-639-3.tab)的对应字段逐条一致。使用 Qt 生成器及该候选表生成的八个文件在忽略换行和生成日期后与原 Qt 源码一致。候选表的 SHA-256 为 `b31ae9d81d34d8e036b1adabcdaf133d0a46b19d91719ffc6cdc3030ebdb55b8`，但这不证明它就是上游历史构建使用的精确输入。ISO 639-3 表未由本项目补充交付，其[上游下载与条款](https://iso639-3.sil.org/code_tables/download_tables)须单独核对。
- 原 Linux 包使用 ICU 73.2，原源码包只包含其许可文本。现补充 [ICU4C 73.2 官方源码归档](https://github.com/unicode-org/icu/releases/download/release-73-2/icu4c-73_2-src.tgz)，SHA-256 为 `818a80712ed3caacd9b652305e01afc7fa167e6f2e94996da44b90c2ab604ce1`；归档内许可与原包所附文本一致。上游版本和许可相符不证明原 SDK 二进制由该归档无补丁构建。
- 该 ICU 发布归档内的数据文件已经生成，进一步提供包含可编辑词典和区域数据的 [ICU 73.2 固定源码树](https://github.com/unicode-org/icu/tree/680f521746a3bd6a86f25f25ee50a62d88b489cf)，以及上游注明用于该版本的 [CLDR 43.1 数据与工具源码树](https://github.com/unicode-org/cldr/tree/37d524354422f46731db74f3bd6b3f46516c3ced)。CLDR 上游树含 ISO 639-3 表，其条款与可转授授权仍需单独核实；本项目新生成的源码子集排除五个相关文件。用固定 ICU 源码树运行上游数据构建流程，生成的数据与原 Linux ICU 数据段及发布归档内数据逐字节一致；源码树仍含上游预生成输入，此结果不声称原 ICU 动态库整体已重现。
- RAR 的有限参考映射保留原 UnRAR 许可，按保守做法在涉及的[旧版 LZ 映射源码](https://github.com/xiaodaozhi/xdzip/blob/b0b3d8f88c1a6a9065acd28f5aab04f5e02e51d2/crates/xdzip-codec-rar/src/legacy_lz15_codes.rs)和[旧版密码映射源码](https://github.com/xiaodaozhi/xdzip/blob/b0b3d8f88c1a6a9065acd28f5aab04f5e02e51d2/crates/xdzip-codec-rar/src/legacy_crypto/permutation.rs)中补充许可第 2 段。[原版源码注释补丁](0.1.0-alpha.8-rar-notice.patch)可下载到本地；在原版项目源码根目录先运行 `git -c core.autocrlf=false -c core.eol=lf apply --check --verbose <补丁路径>`，确认两个文件均显示正在检查而非跳过后，再运行 `git -c core.autocrlf=false -c core.eol=lf apply --verbose <补丁路径>`。补丁只增加源码注释，不改变原版可执行文件；[参考来源与原许可](https://github.com/xiaodaozhi/xdzip/tree/b0b3d8f88c1a6a9065acd28f5aab04f5e02e51d2/third_party/rar-wire-mappings)保留供复核，未加入官方 RAR 引擎源码。映射是否受该条款约束尚无权利人确认，项目按该段限制采取保守处理，不提供 RAR 创建或修改。
- Windows 安装器和便携包含 Microsoft 的 `d3dcompiler_47.dll`、`dxcompiler.dll`、`dxil.dll`；它们不因随 xdzip 分发而改为项目的 Apache-2.0 许可。原包保留 SDK 许可文件 `share/notices/Windows-SDK-graphics/sdk_license.rtf`。[Microsoft REDIST 清单](https://learn.microsoft.com/en-us/legal/windows-sdk/redist)将对应的 x64 文件列为可在符合有效 SDK 许可及附加条件时，原样随 Classic Windows 应用分发。原安装器确认页显示的是 VC++ 运行库协议；SDK 对分发者、外部最终用户和版权声明的条件仍按 [#135](https://github.com/xiaodaozhi/xdzip/issues/135) 核对，本说明不声称历史接收者已接受新条款。
- 原包的 Qt 许可说明误称其为私有开发审阅包，且模块列表遗漏 Network。请参阅[更正后的 Qt 说明](https://github.com/xiaodaozhi/xdzip/blob/82e5db0cf1fc7d524be9a2051fa9e649810d0381/third_party/qt/README.md)。Qt 运行库采用 LGPL-3.0 分支，Qt 内嵌第三方组件可能有其他条款；原包中的 LGPL-3.0 和 GPL-3.0 原文仍保留。

## Qt 重建与替换

原源码包包含固定的 Qt 6.8.2 模块归档、应用源码和 Rust vendor。补充材料的[源码构建与替换说明](https://github.com/xiaodaozhi/xdzip/blob/66933a1c4d7c00b37fafa9a64aa0e41f14d2b4b0/docs/engineering/wp12-automation.md#qt-源码与兼容替换)和[重建脚本](https://github.com/xiaodaozhi/xdzip/tree/66933a1c4d7c00b37fafa9a64aa0e41f14d2b4b0/scripts)提供隔离构建、QtCore 替换及验证入口。Windows／Linux 已在自动化环境中对原始便携包副本完成修改版 QtCore 的实际加载、浏览、取消和解压内容核对，详见 [#118](https://github.com/xiaodaozhi/xdzip/issues/118)。Apple Silicon Mac 本机也已在原始 app.zip 的隔离副本中完成源码构建 QtCore 的加载、受控交互和解压核对，详见[本机记录](https://github.com/xiaodaozhi/xdzip/issues/53#issuecomment-6574172340)；修改副本使用本地 ad-hoc 完整性签名，无需项目私有签名密钥。这些结果不代替真人桌面验收或完整源码许可判断；替换要求接口兼容，不能据此保证任意修改均可运行。

现有 Qt 区域数据还可使用[派生工具](../scripts/derive-qt-locale-code-input.py)，从原 Qt 生成源码取得仅覆盖已有语言的有限查找输入；配合固定 CLDR 46 数据，可重生成原 Qt 的八个相关源码文件，验证允许生成日期和换行差异。该输入不是完整 ISO 639-3 表或历史上游输入，新增语言可能需要另行取得代码；此方法不单独解决授权或完整对应源码问题。

另一条可复现路径使用自行取得的 Ubuntu `iso-codes` 4.16.0-1；[源码交付说明](../docs/engineering/source-delivery.md)给出固定包地址、摘要校验和转换步骤。转换结果与实际用于重建八个 Qt 文件的对照输入一致；项目不分发该包或完整转换结果，包级许可声明不单独证明 SIL 表的再分发权，也不证明它是 Qt 的历史输入。

[修改区域数据及重新编译 QtCore 的步骤](../docs/engineering/wp12-automation.md#修改-qt-区域数据)说明了生成器所需的 `qtbase` 暂存目录、八个生成文件和重新构建方式。自行修改后仍须核对输入许可和替换库的接口兼容性。

原版 Qt 翻译文件的上游 SPDX 根包没有声明具体许可。[Qt 官方 QUIP 18](https://contribute.qt-project.org/quips/18/)在 2025-03-04 明确将普通 Qt 翻译文件列为 `LicenseRef-Qt-Commercial OR BSD-3-Clause`。本项目三平台翻译目录对应的 54 份 Qt 6.8.2 源码输入，与说明更新后的 [Qt 6.8 维护树](https://github.com/qt/qttranslations/tree/b046f9e927d0de7c9c2b8837b5b686bf7b96d3a6)逐份相同；英语空输入按上游 CMake 生成，未计入这 54 份。项目据此对这些输入选择 BSD-3-Clause：原三平台包已附带 `Qt-runtime/license-texts/BSD-3-Clause.txt` 及 Qt 公司和贡献者的概括版权说明。许可原文中的年份和权利人占位符按上游原样保留，不补造逐文件声明。该选择基于 Qt 后来的公开政策及贡献机制，不能证明每份历史文件的单独授权链或其他输入的许可；原 SPDX 的 `NOASSERTION` 不改写，详见 [#53](https://github.com/xiaodaozhi/xdzip/issues/53#issuecomment-6572666231)。

已公开原包的 macOS 上游 SPDX 中有 110 条摘要差异，对应 61 个实际 SDK 文件。[Qt 官方 PySide6 6.8.2 macOS wheel](https://download.qt.io/official_releases/QtForPython/pyside6-essentials/PySide6_Essentials-6.8.2-cp39-abi3-macosx_12_0_universal2.whl) 内的相应文件分别匹配原 SPDX SHA-1，其 SHA-256 为 `abe8446367413b7b56626352e05adc7b15a180956ac9d90e4ee6419c16eab23d`。使用 SDK 已有的签名字节，连同必需的签名命令、链接段大小和对齐变化，可将这 61 个文件逐字节重建为原发行记录所用的 SDK 文件。[复核工具与方法](../docs/engineering/release-candidate.md#许可与来源核对)不证明上游实际使用的历史命令、签名信任或完整许可合规；原 SPDX 和发行资产保持不变。[#53](https://github.com/xiaodaozhi/xdzip/issues/53#issuecomment-6571328466) 保留详细证据和剩余事项。

The Windows installer and portable package include Microsoft's `d3dcompiler_47.dll`, `dxcompiler.dll` and `dxil.dll`; these are not relicensed under xdzip's Apache-2.0 license. The original installer's acceptance page displays the VC++ runtime agreement. SDK conditions concerning distributors, external end users and copyright notices remain under review in [#135](https://github.com/xiaodaozhi/xdzip/issues/135); this supplement does not claim that historical recipients accepted new terms.

Qt Core locale data identifies CLDR 46. The pinned CLDR `common` data and license linked above provide editable generation inputs. Qt's locale-data generator refers to the ISO 639-3 code tables maintained by SIL, linked above. All 347 language-code entries in the original Qt generated data match the corresponding fields in the linked candidate table. Using Qt's generators and that candidate table, whose SHA-256 is recorded above, reproduces eight files from the original Qt source after normalizing line endings and generation dates; this does not establish the exact historical input used upstream. The ISO table is not supplied by xdzip; its upstream download page and terms require separate review.

The [derivation tool](../scripts/derive-qt-locale-code-input.py) can also produce limited lookup input for existing languages from Qt's generated source. Together with the pinned CLDR 46 data, it regenerates the eight related Qt source files allowing generation-date and line-ending differences. This is not the complete ISO 639-3 table or the historical upstream input; adding languages may require separately obtained codes. It does not by itself resolve licensing or complete-corresponding-source obligations.

Another reproducible path uses independently obtained Ubuntu `iso-codes` 4.16.0-1. The [source-delivery instructions](../docs/engineering/source-delivery.md) provide the pinned package URL, hash check and conversion steps. The converted input matches the one actually used to regenerate the eight Qt files. xdzip does not distribute the package or the complete converted table; the package-level license declaration alone establishes neither redistribution rights for the SIL table nor Qt's historical input.

The [locale-data modification and QtCore rebuild steps](../docs/engineering/wp12-automation.md#修改-qt-区域数据) describe the `qtbase` staging directory required by Qt's generators, the eight generated files and the rebuild commands. Review the input licenses and replacement-library interface compatibility after making changes.

The original Linux package uses ICU 73.2; its source package included the license text but not ICU source. The linked official ICU4C 73.2 source archive has the SHA-256 shown above and contains the same license text. Matching the upstream version and license does not prove the original SDK binaries were built from this archive without patches.

That release archive contains pre-generated ICU data. Building the data using the pinned ICU tree reproduces both the original Linux ICU data segment and the release archive's pre-generated data byte for byte. The tree still contains upstream pre-generated inputs; this does not establish reproduction of the complete ICU shared libraries.

The corrected Qt notice identifies the actual release and includes Network. Distributed Qt runtime libraries use the LGPL-3.0 option; embedded third-party components may have different terms.
