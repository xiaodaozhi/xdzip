# xdzip 0.2.0

xdzip **0.2.0，build 27** 是功能更新版本，增加独立命令行客户端，并让 macOS 自定义代理与直连模式支持原生安装更新。

## 本版更新

- **macOS 更新代理**：系统代理、无凭据 HTTP CONNECT／SOCKS5 自定义代理和直连均可用于原生安装更新。feed 与归档共用启动前冻结的网络策略，自定义代理失败不会回退直连，直连明确绕过系统静态代理、PAC 和自动发现。发布签名、TLS、候选身份、任务退出和恢复检查保留。
- **独立 CLI 客户端**：提供 Windows x86_64、macOS Apple Silicon 和 Linux x86_64 命令行包，无需 Qt 或显示会话。支持 `list`、`extract`、`create`、`add`、`test`、`update`、`gui`、`setup`，以及 JSON、非交互模式、密码输入和取消。格式、加密、分卷及写入边界与桌面核心一致，密码不通过命令行参数传入。
- **命令行安装与更新**：桌面包内也带有 CLI，终端入口由用户通过 `setup` 显式启用。独立发行包使用受签名清单保护的管理式更新；源码和开发构建仅检查或下载。桌面 CLI 的更新交接保留应用任务和安装占用屏障，交接成功不等于安装完成。
- 修复 macOS 内置 CLI 元数据位置导致的应用完整性签名失败，将该资源纳入正常 bundle 封装。

## 下载与升级

- 图形界面用户选择对应平台的桌面安装包或便携包；仅使用终端时选择名称以 `xdzip-cli-0.2.0-` 开头的独立包。CLI 命令和安装说明见[命令行契约](https://github.com/xiaodaozhi/xdzip/blob/v0.2.0/docs/engineering/command-line.md)。
- 旧版 macOS 客户端不会因新版本发布而获得新的代理实现。首次取得本版时，若旧客户端自定义代理无法自动安装，请先使用系统代理或从本发布页手动安装。
- 桌面更新与独立 CLI 更新分别提供签名清单，全部发行附件提供 `SHA256SUMS`。已公开旧版本的附件保持不变。

## 支持与验证边界

- 支持范围为受维护的 Windows 11 x86_64、macOS 14 或更新版本 Apple Silicon，以及 Ubuntu 24.04 LTS x86_64、glibc 2.39 或更新版本。桌面 Linux 使用 X11；独立 CLI 不依赖 X11，但需要系统 OpenSSL 3 和 CA 证书。
- macOS 代理与直连变更已在 macOS 15.8.2 arm64 原生 CI 和 macOS 27.2.1 Apple Silicon 本机验证，覆盖实际安装、重启、配置快照、静态代理/PAC 对照、TLS 拒绝和设置恢复。macOS 14 当前没有可用原生环境，**仍未验证**，不以其他系统结果替代。
- CLI 已有三平台原生自动验证。发行工作流另外构建本版本桌面和 CLI 包，执行各平台适用的部署、启动、安装生命周期与 CLI 核验；实际运行和附件复核记录见[发行任务 #260](https://github.com/xiaodaozhi/xdzip/issues/260)。Windows Server CI 不等于 Windows 11 人工验收，本版不新增人工桌面验收声明。
- Windows 安装器未签署发行者证书；macOS 使用 ad-hoc 完整性签名，未使用 Developer ID 或公证，系统可能显示安全提示。更新附件的密码学签名不代替平台发行者签名。
- 发行材料保留适用通知、许可和 SBOM，Sparkle 派生框架的源码、补丁与构建身份单独记录。不生成或上传单独的对应源码压缩包；GitHub 自动提供的标签源码快照不由发行流水线生成或上传。

## English

**xdzip 0.2.0, build 27** adds a standalone command-line client and native macOS installation updates with custom proxies and explicit direct connections.

## Changes

- **macOS update transport**: system proxies, credential-free HTTP CONNECT/SOCKS5 proxies and direct connections support native installation updates. Feed and archive share an immutable policy configured before startup. Custom proxies never fall back to direct; direct mode bypasses static system proxies, PAC and discovery. Signature, TLS, candidate, task-exit and recovery checks remain in force.
- **Standalone CLI**: native Windows x86_64, Apple Silicon macOS and Linux x86_64 packages run without Qt or a display session. Commands include `list`, `extract`, `create`, `add`, `test`, `update`, `gui` and `setup`, with JSON, noninteractive operation, password input and cancellation. Existing format, encryption, split-archive and write limits apply. Passwords are never accepted as command-line arguments.
- **CLI installation and updates**: desktop packages also contain a private CLI; users explicitly enable terminal registration with `setup`. Standalone release packages use managed updates protected by a signed manifest. Source and development builds remain check/download-only. Desktop CLI handoff retains task and installation occupancy barriers; handoff does not mean installation succeeded.
- Fixed bundled macOS CLI metadata placement so it is sealed as a normal bundle resource without blocking application integrity signing.

## Downloads and upgrading

- Choose a desktop installer or portable package for graphical use, or an independent archive starting with `xdzip-cli-0.2.0-` for terminal-only use. See the [CLI contract](https://github.com/xiaodaozhi/xdzip/blob/v0.2.0/docs/engineering/command-line.md) for commands and setup.
- Older macOS clients retain their original updater implementation. If a custom proxy prevents automatic installation, obtain this first supporting version using a system proxy or install it manually from this release.
- Desktop and standalone CLI updates have separate signed manifests. `SHA256SUMS` covers the release attachments; previously published assets remain unchanged.

## Support and verification limits

- Supported targets are serviced Windows 11 x86_64, macOS 14 or later on Apple Silicon, and Ubuntu 24.04 LTS x86_64 with glibc 2.39 or later. Linux desktop uses X11; standalone CLI needs system OpenSSL 3 and CA certificates, without X11.
- The macOS transport changes were verified natively on macOS 15.8.2 arm64 CI and a local Apple Silicon Mac running macOS 27.2.1, including actual installation, restart, frozen settings, static-proxy/PAC controls, TLS rejection and restored system settings. **macOS 14 remains unverified** because no native environment is available; other OS results do not substitute for it.
- CLI has existing native automated evidence on all three platforms. The release workflow separately builds this version's desktop and CLI packages and performs applicable deployment, launch, installation-lifecycle and CLI checks; actual run and attachment verification are recorded in [release issue #260](https://github.com/xiaodaozhi/xdzip/issues/260). Windows Server CI does not constitute manual Windows 11 acceptance. This release adds no new manual desktop acceptance claim.
- The Windows installer has no publisher signature. macOS uses ad-hoc integrity signing without Developer ID or notarization, and system security prompts may appear. Cryptographic update signatures do not replace platform publisher signatures.
- Release materials retain applicable notices, licenses and SBOMs, with separate source, patch and build identities for the derived Sparkle framework. No separate corresponding-source archive is generated or uploaded. GitHub's automatic tag source snapshots are not generated or uploaded by the release pipeline.
