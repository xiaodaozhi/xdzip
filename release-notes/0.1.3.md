# xdzip 0.1.3

xdzip **0.1.3，build 26** 是稳定补丁版本，修复应用归档解压后的目标文件夹名称。

## 本版更新

- 默认创建同名文件夹时，归档名称去掉压缩扩展名后若仍以 `.app` 结尾，会继续去掉该后缀。例如 `Demo.app.zip` 解压到普通的 `Demo` 文件夹，避免 macOS Finder 将外层文件夹误认为损坏的应用。归档内应用的名称、内容和签名不变；不创建同名文件夹时输出路径不变。

## 支持与限制

- Windows 11（受维护版本）x86_64，macOS 14 或更新版本 Apple Silicon，Ubuntu 24.04 LTS x86_64、X11、glibc 2.39 或更新版本。
- Windows 安装器未签署发行者证书；macOS 使用 ad-hoc 完整性签名，未使用 Developer ID 签名或公证。系统可能显示安全提示。
- 本次修复已在 Apple Silicon 本机使用实际 app.zip 验证默认解压、目标预览、文件内容、链接、签名及启动；未执行人工视觉验收，也未将其他平台结果推定为已通过。正式发布工作流的实际打包与验证结果另行记录。
- 发行材料包含适用通知和 SBOM，不附单独的对应源码压缩包；该政策本身不代表所有适用许可义务已自动满足。

## English

**xdzip 0.1.3, build 26** is a stable maintenance release fixing destination folder naming for application archives.

## Changes

- When the default archive-named folder is enabled, a trailing `.app` is removed after the archive extension. For example, `Demo.app.zip` extracts into the ordinary `Demo` folder, preventing macOS Finder from treating the outer folder as a damaged app. The name, contents and signature of the app inside are unchanged; paths are unchanged when the option is disabled.

## Support and limitations

- Windows 11 (supported servicing versions) x86_64, macOS 14 or later on Apple Silicon, and Ubuntu 24.04 LTS x86_64 with X11 and glibc 2.39 or later.
- The Windows installer has no publisher signature. macOS uses ad-hoc integrity signing without Developer ID signing or notarization. System security prompts may appear.
- The fix was verified on an Apple Silicon Mac with an actual app.zip, including default extraction, destination preview, file contents, links, signature and startup. No manual visual acceptance was performed, and results for other platforms are not presumed. Actual release-workflow packaging and validation results are recorded separately.
