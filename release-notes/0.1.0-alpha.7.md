# xdzip 0.1.0-alpha.7

xdzip **0.1.0-alpha.7，build 20**，实验性跨平台候选。本文件是候选的版本专属发布说明，当前没有创建版本标签、草稿或公开 Release。构建、验收与实际交付身份由[候选收尾 #53](https://github.com/xiaodaozhi/xdzip/issues/53)登记。

## 本次能力与修复

- ZIP、TAR/GZIP、7z、RAR、CAB、ISO/UDF 的产品格式与压缩后端迁为项目独立 Rust 实现，共享压缩算法，保留隔离工作进程和既有安全文件提交。官方格式引擎不再进入当前产品构建，历史交付继续保留各自来源义务。
- 7z 支持浏览、解压、测试、创建、密码、文件名加密、固实和编号分卷。普通单文件、未加密 7z 支持受限重建修改，重建工作集上限为 512 MiB。
- RAR 支持受当前契约约束的旧版、RAR5、RAR7、密码、固实和分卷读取。真正 RAR7 algorithm 1 健康压缩流及 6 GiB 逻辑字典已独立验证，产品 worker 仍受 1 GiB 内存预算限制，实际工作集超额会拒绝。
- 新增 CAB Store/MSZip/Quantum/LZX 及分卷读取，新增 ISO9660/Joliet/Rock Ridge/UDF 只读浏览、解压和导出。光盘映像不挂载或执行，结构与可读性检查不宣称逐文件内容认证。
- 支持文件列表右键打开、原生拖出、外部文件拖入后确认添加和包内拖放移动。创建与添加过滤 macOS 元数据，旧文件名编码解析贯通浏览、解压和普通归档修改，添加窗口与共享创建控件同步。
- 关于页支持用户主动检查和安装版更新，生产更新公钥已内置，受保护生产签名及三平台升级自动验收已完成。旧公开客户端若没有内置相同信任根，须先手动安装含公钥版本。
- 修复任务准备占位重复计数与回归测试轮询开销，工作流迁为固定 Node 24 Actions。Windows 程序说明为 `xdzip Archive Manager`，应用文件名及关联身份不变。

## 系统与交付

| 平台 | 候选包型 | 支持范围 |
| --- | --- | --- |
| Windows x86_64 | ZIP、当前用户 EXE 安装器 | 受维护的 Windows 11 |

## 当前验收边界

已完成技术迁移和既有三平台自动化的证据分别见 [#45](https://github.com/xiaodaozhi/xdzip/issues/45)、[#51](https://github.com/xiaodaozhi/xdzip/issues/51)、[#31](https://github.com/xiaodaozhi/xdzip/issues/31) 与 [#52](https://github.com/xiaodaozhi/xdzip/issues/52)，这些历史结果保留各自提交身份。新候选的最终验证状态以 #53 为准，不把此说明文件或版本递增当作验证通过。

原生桌面视觉、物理跨屏、Windows 11 安装许可、Mac 真人系统授权、真实文件管理器的关联／拖放以及旧编码文字人工验收仍需逐项登记，见 #30、#31、#37、#38、#39、#40、#41、#43、#44。新候选的实际包来源与再分发复核未因历史 #4 关闭而自动完成。本候选不代表稳定发行获批。

文件内容预览、百万条磁盘索引与第三方扩展尚未实现。RAR/CAB/ISO/UDF 只读，加密或分卷 7z 不支持修改。其他格式特性、历史编码与资源边界以 README 及工程契约为准。当前不提供 Intel Mac、Windows/Linux ARM64 或 Wayland 支持。

## English

Experimental candidate **0.1.0-alpha.7, build 20**, not yet published. Product archive and compression backends now use independent Rust implementations for ZIP, TAR/GZIP, 7z, RAR, CAB and ISO/UDF while retaining isolated workers, resource budgets and safe host-controlled publication. The release adds 7z creation and restricted rewriting, read-only CAB and optical-image support, genuine RAR7 decoding evidence, archive drag-and-drop, legacy filename decoding and the redesigned add-files window.

7z rewriting is limited to ordinary, unencrypted, unsplit archives and a 512 MiB reconstruction working set. A genuine RAR7 algorithm-1 stream with a 6 GiB logical dictionary has been independently verified while the product worker retains its 1 GiB memory budget; excessive actual working sets are rejected. RAR, CAB, ISO and UDF remain read-only. Optical-image checks establish structure and readability without mounting, executing or claiming per-file payload authentication. Creation and addition filter macOS metadata. Preparation-task counting and polling overhead have also been corrected.

The user-initiated updater embeds production public keys. Protected production signing and native upgrades have passed automation on Windows, Ubuntu and Apple Silicon; older public clients without these trust roots require a manual installation first. Windows process metadata now displays `xdzip Archive Manager`, and workflows use pinned Node 24 Actions.

Six package types target supported Windows 11 x86_64, macOS 14+ arm64 and Ubuntu 24.04 x86_64/X11. Windows installers have no publisher signature; Mac applications use ad-hoc integrity signing without Developer ID or notarization. Update signatures do not establish platform publisher identity. Corresponding source, notices, licenses, SBOMs, rebuild materials and hashes must match the final candidate.

Candidate-specific validation and redistribution review remain tracked in #53. Physical multi-monitor behavior, native visual review, real file-manager associations and transfers, legacy text, Windows license dialogs and Mac human authorization still require recorded acceptance. Existing automated results retain their original commits and do not substitute for these checks or approve stable release. Content preview, million-entry disk indexing and third-party extensions remain future work; documented read-only and resource restrictions continue to apply.
